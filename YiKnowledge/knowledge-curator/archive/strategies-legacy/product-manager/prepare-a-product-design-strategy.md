## Action recommendations

1. **Five dimensions**: requirements + design + validation + governance + measure; no missing dimensions
2. **Business-value driven**: prioritize by efficiency + trust + speed + risk + cost; not empty slogans
3. **Need**: user / scenario / close-loop; do not omit
4. **Design**: information / interaction / visual / close-loop; do not omit
5. **Validate**: usability / test / close-loop; do not omit
6. **Governance**: owner / cadence / review / documentation / drift; do not omit
7. **Measure**: efficiency + trust + speed + risk + cost; do not omit
8. **Not one-shot**: from requirement → design → validation → governance → measure progressively; no skipping
9. **Not report-ized**: reports are only the starting point; not the end
10. **Not empty slogans**: each principle must mark landing evidence; no ambiguity
11. **Versioned**: strategy has versions; evolution is traceable
12. **Link with product-management**: ProductDesign + ProductManagement co-build
13. **Link with product-roadmap**: ProductDesign + ProductRoadmap co-build
14. **Link with product-metrics**: ProductDesign + ProductMetrics co-build
15. **Link with design**: ProductDesign + Design co-build
16. **Link with product-discovery**: ProductDesign + ProductDiscovery co-build
17. **Toolchain**: Figma / Sketch / Adobe XD / Framer / InVision
18. **Publicly accessible**: strategy is accessible to all; not hidden
19. **Regular review**: evolves and updates; not one-shot
20. **First principles**: why ProductDesign is necessary; worst consequence of not doing
21. **Inversion**: how much can be solved by prototype review; if solvable, do not introduce heavy strategy
22. **Second-order thinking**: second-order consequences after strategy (efficiency / trust / speed / risk)
23. **Occam**: ProductDesign simpler is better; cut redundant stages
