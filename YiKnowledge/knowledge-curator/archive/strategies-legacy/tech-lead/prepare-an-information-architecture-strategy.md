## Action recommendations

1. **Five dimensions**: structure + categorization + retrieval + governance + measurement; no missing dimension
2. **Business-value driven**: set priority by growth + trust + speed + risk + cost; no empty slogans
3. **Structure**: hierarchy / depth / breadth / consistency; no leakage
4. **Categorization**: categories / tags / synonyms / antonyms; no leakage
5. **Retrieval / search**: keywords / filters / sort / highlighting; no leakage
6. **Governance**: owner / cadence / review / documentation / drift; no leakage
7. **Measurement**: coverage + adoption + cost + risk + satisfaction; no leakage
8. **Not one-shot**: gradual from structure → categorization → retrieval → governance → measurement; no skipping levels
9. **No report-ism**: navigation is only the start; not the end
10. **No empty slogans**: every principle must mark implementation evidence; no vagueness
11. **Versioned**: strategy is versioned; evolution is traceable
12. **Link with content**: IA + content co-build
13. **Link with content-governance**: IA + content governance co-build
14. **Link with design-system**: IA + design system co-build
15. **Link with user-research**: IA + user research co-build
16. **Link with taxonomy**: IA + taxonomy co-build
17. **Toolchain**: CardSort / TreeTest / OptimalSort / Maze / UserZoom
18. **Publicly discoverable**: strategy is publicly discoverable; not hidden
19. **Regular review**: evolve and update; not one-shot
20. **First principles**: why an information architecture strategy is needed; worst consequence of not doing it
21. **Inversion**: rely on defaults to solve how much; if solvable, do not introduce a heavy strategy
22. **Second-order thinking**: second-order consequences after strategy (growth / trust / speed / risk)
23. **Occam's razor**: information architecture simpler is better; cut redundant layers
