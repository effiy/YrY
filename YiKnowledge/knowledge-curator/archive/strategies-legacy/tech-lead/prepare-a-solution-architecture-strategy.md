## Action recommendations

1. **Five dimensions**: Requirements + solution + landing + governance + measurement; no missing dimension
2. **Business-value driven**: Prioritize by efficiency + trust + speed + risk + cost; not sloganeering
3. **Requirements**: Business / stakeholders / scenarios / constraints; do not omit
4. **Solution**: Selection / architecture / integration / trade-offs; do not omit
5. **Landing**: Phases / team / cadence / retirement; do not omit
6. **Governance**: Owner / cadence / review / documentation / drift; do not omit
7. **Measurement**: Coverage + adoption + cost + risk + satisfaction; do not omit
8. **Not one-shot**: Progressive from requirements → solution → landing → governance → measurement; no skipping
9. **Not report-ized**: Design is only the start; not the end
10. **Not sloganeering**: Every principle must have landing evidence; not vague
11. **Versioned**: Strategy has versions; evolution is traceable
12. **Link with enterprise-architecture**: Solution + enterprise architecture co-build
13. **Link with it-strategy**: Solution + IT co-build
14. **Link with technology**: Solution + technology co-build
15. **Link with application-portfolio**: Solution + application portfolio co-build
16. **Link with cloud**: Solution + cloud co-build
17. **Toolchain**: TOGAF / Sparx EA / ArchiMate / Planview LeanIX / Avolution ADOit
18. **Publicly queryable**: Strategy everyone can look up; not hidden
19. **Periodic review**: Evolution updates; not one-shot
20. **First principles**: Why must solution architecture strategy; worst consequence of not doing it
21. **Inversion thinking**: How much can be solved by default; if solvable do not introduce a heavy strategy
22. **Second-order thinking**: Second-order consequences after strategy (efficiency / trust / speed / risk) 
23. **Occam**: Solution architecture the simpler the better; cut redundant layers
