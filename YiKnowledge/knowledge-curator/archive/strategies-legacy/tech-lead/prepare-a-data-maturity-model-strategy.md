## Action recommendations

1. **Five dimensions**: dimension + level + assessment + governance + measurement; no missing dimension
2. **Business-value driven**: prioritize by efficiency + trust + speed + risk + cost; no empty slogans
3. **Dimension**: strategy / governance / architecture / quality / culture; no leakage
4. **Level**: 1-5 / initial → optimized; no leakage
5. **Assessment**: self-assessment / third-party / persistent; no leakage
6. **Governance**: owner / cadence / review / documentation / drift; no leakage
7. **Measurement**: score + leap + investment + risk + cost; no leakage
8. **Not one-shot**: progress from dimension → level → assessment → governance → measurement; no skipping levels
9. **No report-ism**: scores are only the start; not the end
10. **No empty slogans**: every principle must mark implementation evidence; no vagueness
11. **Versioned**: strategy is versioned; evolution is traceable
12. **Link with data-maturity**: model + maturity co-built
13. **Link with data-strategy**: model + data strategy co-built
14. **Link with data-governance**: model + data governance co-built
15. **Link with data-culture**: model + data culture co-built
16. **Link with analytics-engineering**: model + analytics engineering co-built
17. **Toolchain**: DMM / DCAM / IBM Data Maturity / Gartner Maturity / internal maturity-model
18. **Publicly discoverable**: strategy is publicly discoverable; not hidden
19. **Regular review**: evolve and update; not one-shot
20. **First principles**: why a data maturity model is necessary; worst consequence of not doing it
21. **Inversion**: how much can be solved subjectively; if solvable, do not introduce a heavy strategy
22. **Second-order thinking**: second-order consequence after the strategy (efficiency / trust / speed / risk) 
23. **Occam's razor**: a data maturity model: simpler is better; cut redundant layers
