## Action recommendations

1. **Five dimensions**: concept + relation + rule + governance + measurement; no missing dimension
2. **business-value driven**: prioritize by efficiency + trust + speed + risk + cost; not sloganeering
3. **concept Concept**: class / instance / attribute; do not omit
4. **relation Relation**: hierarchical / related / topology; do not omit
5. **rule Rule**: constraint / inference / consistency; do not omit
6. **governance Governance**: owner / cadence / review / documentation / drift; do not omit
7. **measurement Measure**: coverage + consistency + reuse + risk + cost; do not omit
8. **not one-shot**: from concept → relation → rule → governance → measurement gradual; no skipping
9. **not report-ized**: class count is only the start; not the end
10. **not sloganeering**: every principle must have landing evidence; not vague
11. **versioned**: strategy has versions; evolution is traceable
12. **link with taxonomy**: ontology + taxonomy co-build
13. **link with knowledge-graph**: ontology + knowledge graph co-build
14. **link with data-catalog**: ontology + catalog co-build
15. **link with metadata-management**: ontology + metadata co-build
16. **link with semantic-layer**: ontology + semantic layer co-build
17. **toolchain**: Protégé / OWL / RDF / SPARQL / TopBraid
18. **publicly queryable**: strategy everyone can look up; not hidden
19. **periodic review**: evolution updates; not one-shot
20. **first principles**: why must ontology; worst consequence of not doing
21. **inversion thinking**: how much can be solved by table structure; if solvable don't introduce heavy strategy
22. **second-order thinking**: second-order consequences after strategy (efficiency / trust / speed / risk) 
23. **Occam**: ontology the simpler the better; cut redundant layers
