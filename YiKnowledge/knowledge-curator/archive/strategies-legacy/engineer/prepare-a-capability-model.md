## Action recommendations

1. **five dimensions**: capability + layer + heatmap + governance + measurement; no missing dimension
2. **business-value driven**: prioritize by differentiation + speed + cost + risk + trust; not sloganeering
3. **capability Capability**: strategic / core / supporting / emerging / declining; do not omit
4. **layer Layer**: L1 / L2 / L3 / process / tools; do not omit
5. **heatmap Heatmap**: self-build / buy / joint venture / outsource / automate; do not omit
6. **governance Governance**: owner / cadence / review / documentation / drift; do not omit
7. **measurement Measure**: differentiation + speed + cost + risk + trust; do not omit
8. **not one-shot**: progressive from capability -> layer -> heatmap -> governance -> measurement; no skipping
9. **not report-ized**: reports are only the start; not the end
10. **not sloganeering**: every principle must have landing evidence; not vague
11. **versioned**: strategy has versions; evolution is traceable
12. **links with operating-model**: Capability + Operating co-build
13. **links with org-design**: Capability + Org co-build
14. **links with business-model**: Capability + Business co-build
15. **links with product**: Capability + Product co-build
16. **links with technology**: Capability + Tech co-build
17. **Toolchain**: Aris / LeanIX / Capsifi / Miro / Sparx
18. **publicly queryable**: strategy everyone can look up; not hidden
19. **periodic review**: evolution updates; not one-shot
20. **first principles**: why must Capability Model; worst consequence of not doing it
21. **inversion thinking**: how much can the org chart solve; if solvable, don't introduce a heavy strategy
22. **second-order thinking**: second-order consequences after the strategy (differentiation / speed / cost / risk)
23. **Occam**: Capability Model the simpler the better; cut redundant layers
