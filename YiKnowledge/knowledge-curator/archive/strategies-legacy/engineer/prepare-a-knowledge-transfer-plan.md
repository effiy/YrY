# I want to build a knowledge transfer plan

> **As an** engineer, **I want to** prepare a knowledge transfer plan, **so that** launch is safe.

## Summary

- Knowledge transfer = contract; not just handover
- Explicit + tacit + relationships + tools; no missing dimension
- Staged; not one-shot
- Two-way: outgoing + incoming must both be owners; not one-directional
- Documentation + pairing + shadowing + reverse explanation; not by word of mouth
- Links with project handover + new-hire onboarding + succession plan
- Links with knowledge audit + knowledge-base contribution
- Publicly queryable; not hidden
- Periodic review; evolution updates
- First principles / inversion / second-order / Occam

## Action recommendations

1. **Four dimensions**: explicit + tacit + relationships + tools; no missing dimension
2. **Explicit knowledge**: documentation + code + runbooks; lands into the knowledge base
3. **Tacit knowledge**: decision rationale + historical context + quirks; pair-handoff
4. **Relationships**: stakeholders + upstream/downstream + customers; intro handoff
5. **Tools**: accounts + permissions + documentation locations + runbooks must be handed over
6. **Staged**: documentation → pairing → shadowing → reverse explanation; not one-shot
7. **Reverse explanation**: the incoming side explains back to the outgoing side; verifies understanding
8. **Dual owners**: outgoing + incoming must both be owners; not one-directional
9. **Time budget**: 1-2 weeks, not rushed; not one-shot 1 hour
10. **Pairing execution**: the incoming side follows the outgoing side on tasks; not verbal
11. **Shadow drill**: the incoming side does, the outgoing side reviews; do not take over directly
12. **Checklist**: every dimension must tag a checklist; do not omit
13. **Outgoing-side confirm**: the outgoing side signs off; not verbal
14. **Incoming-side sign-off**: the incoming side signs understanding; not passive
15. **Link with project handover**: handover runs via knowledge transfer
16. **Link with new-hire onboarding**: first month runs knowledge transfer
17. **Link with succession plan**: key roles must run knowledge transfer
18. **Link with knowledge audit**: audit finds gaps, transfer patches them
19. **Link with knowledge-base contribution**: transfer outputs land in the knowledge base
20. **Publicly queryable**: everyone can look up the plan; not hidden
21. **Periodic review**: evolution updates; not one-shot
22. **First principles**: why must transfer; worst consequence of not doing it
23. **Inversion thinking**: how much can documentation solve; if solvable, do not introduce transfer
24. **Second-order thinking**: second-order consequences after transfer (continuity / retention / recruiting / trust)
25. **Occam**: transfer the simpler the better; cut redundant steps
