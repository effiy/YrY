## Action recommendations

1. **Five dimensions**: tree + task + metric + governance + measurement; no missing dimension
2. **Business-value driven**: prioritize by growth + trust + speed + risk + cost; not sloganeering
3. **Tree**: hierarchy / tag / subset / version; do not omit
4. **Task**: find / select / time / feedback; do not omit
5. **Metric**: success / direct-hit / failure / time; do not omit
6. **Governance**: owner / cadence / review / documentation / drift; do not omit
7. **Measurement**: coverage + adoption + cost + risk + satisfaction; do not omit
8. **Not one-shot**: from tree → task → metric → governance → measurement gradual; no skipping
9. **Not report-ized**: IA validation is only the start; not the end
10. **Not sloganeering**: every principle must have landing evidence; not vague
11. **Versioned**: strategy has versions; evolution is traceable
12. **Link with card-sorting**: tree testing + classification co-built
13. **Link with information-architecture**: tree testing + IA co-built
14. **Link with ux-research**: tree testing + UX co-built
15. **Link with usability-testing**: tree testing + usability co-built
16. **Link with design-research**: tree testing + design co-built
17. **Toolchain**: Treejack / UserZoom / Maze / OptimalSort / UsabilityHub
18. **Publicly queryable**: strategy everyone can look up; not hidden
19. **Periodic review**: evolution updates; not one-shot
20. **First principles**: why must a tree testing strategy; worst consequence of not doing
21. **Inversion thinking**: how much can be solved by default; if solvable do not introduce heavy strategy
22. **Second-order thinking**: second-order consequences after strategy (growth / trust / speed / risk)
23. **Occam**: tree testing the simpler the better; cut redundant layers
