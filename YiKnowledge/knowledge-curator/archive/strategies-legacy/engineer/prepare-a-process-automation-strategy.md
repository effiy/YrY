## Action recommendations

1. **Five dimensions**: candidate + design + landing + governance + measurement; no missing dimension
2. **Business-value driven**: prioritize by efficiency + trust + speed + risk + cost; not sloganeering
3. **Candidate**: stable / high-volume / rule-based / high-value; do not omit
4. **Design**: process / exception / monitoring / interface; do not omit
5. **Landing**: development / test / deploy / rollout; do not omit
6. **Governance**: owner / cadence / review / documentation / drift; do not omit
7. **Measure**: coverage + adoption + cost + risk + satisfaction; do not omit
8. **Not one-shot**: progressive from candidate → design → landing → governance → measurement; no skipping
9. **Not report-ized**: robots are only the start; not the end
10. **Not sloganeering**: every principle must have landing evidence; not vague
11. **Versioned**: strategy has versions; evolution is traceable
12. **Link with business-process**: automation + process co-built
13. **Link with process-optimization**: automation + optimization co-built
14. **Link with value-stream**: automation + value stream co-built
15. **Link with operating-model**: automation + operating model co-built
16. **Link with business-architecture**: automation + business architecture co-built
17. **Toolchain**: UiPath / Automation Anywhere / Blue Prism / Microsoft Power Automate / Pega
18. **publicly queryable**: strategy everyone can look up; not hidden
19. **periodic review**: evolution updates; not one-shot
20. **First principles**: why must process automation strategy; worst consequence of not doing
21. **Inversion thinking**: how much can be solved by default; if solvable, don't introduce heavy strategy
22. **Second-order thinking**: second-order consequences after strategy (efficiency / trust / speed / risk)
23. **Occam**: process automation the simpler the better; cut redundant layers
