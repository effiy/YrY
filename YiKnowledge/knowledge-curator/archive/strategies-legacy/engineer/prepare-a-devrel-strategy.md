## Action recommendations

1. **Five dimensions**: audience + content + activity + tooling + measurement; no missing dimension
2. **business-value driven**: set priority by developer count + integration count + API calls + retention; not sloganeering
3. **audience Audience**: indie + enterprise + startup + student + partner; do not omit
4. **content Content**: doc + tutorial + blog + video + sample + OSS; do not omit
5. **activity Event**: meetup + conference + hackathon + webinar + workshop; do not omit
6. **tooling Tooling**: SDK + CLI + playground + sandbox + dashboard + status; do not omit
7. **measurement Measure**: developer count + integration count + API calls + NPS + OSS contribution; do not omit
8. **not one-shot**: progressive from audience → content → activity → tooling → measurement; no skipping
9. **not report-ized**: reports are only the start; not the end
10. **not sloganeering**: every principle must have landing evidence; not vague
11. **versioned**: strategy has versions; evolution is traceable
12. **link with developer-portal**: DevRel + portal co-build
13. **link with community**: DevRel + community co-build
14. **link with content**: DevRel + content co-build
15. **link with partnership**: DevRel + partnership co-build
16. **link with ecosystem**: DevRel + ecosystem co-build
17. **toolchain**: DevRel-Framework / Devpost / Bevy / Meetup / GitHub / Stack Overflow / Discourse / Discord / Slack / Twilio / Stripe / Vercel
18. **publicly queryable**: strategy everyone can look up; not hidden
19. **periodic review**: evolution updates; not one-shot
20. **first principles**: why must DevRel strategy; worst consequence of not doing
21. **inversion thinking**: how much can product itself solve; if solvable don't introduce heavy strategy
22. **second-order thinking**: second-order consequences after strategy (cost / risk / integration / business)
23. **Occam**: DevRel the simpler the better; cut redundant steps
