## Action recommendations

1. **Five dimensions**: portfolio + architecture + evolution + governance + measurement; no missing dimension.
2. **Business-value driven**: prioritize by efficiency + trust + speed + risk + cost; not sloganeering.
3. **Portfolio**: in-house / purchased / SaaS / co-built; do not omit.
4. **Architecture**: layering / patterns / integration / data; do not omit.
5. **Evolve**: modernization / refactor / retirement / exit; do not omit.
6. **Governance**: owner / cadence / review / documentation / drift; do not omit.
7. **Measurement**: coverage + adoption + cost + risk + satisfaction; do not omit.
8. **Not one-shot**: from portfolio → architecture → evolution → governance → measurement, gradual; no skipping.
9. **Not report-ized**: software count is only the start; not the end.
10. **Not sloganeering**: every principle must have landing evidence; not vague.
11. **Versioned**: strategy has versions; evolution is traceable.
12. **Link with application-portfolio**: application + portfolio co-build.
13. **Link with enterprise-architecture**: application + enterprise architecture co-build.
14. **Link with solution-architecture**: application + solution co-build.
15. **Link with it-strategy**: application + IT co-build.
16. **Link with integration**: application + integration co-build.
17. **Toolchain**: Planview LeanIX / Ardoq / SAP / Oracle / ServiceNow SPM.
18. **Publicly queryable**: anyone can look up the strategy; not hidden.
19. **Periodic review**: evolution updates; not one-shot.
20. **First principles**: why must an application strategy; worst consequence of not doing it.
21. **Inversion thinking**: how much can relying on defaults solve; if solvable, do not introduce a heavy strategy.
22. **Second-order thinking**: second-order consequences after the strategy (efficiency / trust / speed / risk).
23. **Occam**: simpler applications are better; cut redundant layers.
