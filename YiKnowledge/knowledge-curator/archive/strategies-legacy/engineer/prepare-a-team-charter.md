# I want to prepare a team charter

> **As an** engineer, **I want to** prepare a team charter, **so that** launch is safe. 

## Summary

- Four charter pieces: behavioral contract + decision mechanism + collaboration convention + values
- Consensus-driven: co-created by all; not written by one person
- Behavioral contract: conventions + feedback mechanism
- Decision mechanism: disagree-and-commit / voting / consensus
- Collaboration convention: meeting / async / time-zone / tool
- Values: 3-5 items; not stacked
- Quarterly review; not written on the wall and forgotten
- Executable; challengeable; not empty talk

## Action recommendations

1. **Four-piece set**: behavioral contract + decision mechanism + collaboration convention + values; no missing piece
2. **Consensus-driven**: co-created by all; not written by one person; not copied from elsewhere
3. **Behavioral contract**: conventions + feedback mechanism; not slogans
4. **Decision mechanism**: disagree-and-commit / voting / consensus; no vagueness
5. **Collaboration convention**: meeting / async / time-zone / tool; explicit
6. **Values**: 3-5 items; not stacked; executable
7. **Quarterly review**: review each quarter; not written on the wall and forgotten
8. **Executable**: each item executable; not empty talk
9. **Challengeable**: can challenge and revise; not dogma
10. **Conflict contingency**: reference the charter during conflict; not by authority
11. **New hire onboarding**: new hires read first; not verbal
12. **Cross-team**: cross-team alignment; not just within team
13. **Tool**: charter implementation tool (wiki / documentation / protocol); not verbal
14. **First principles**: why must there be a charter; worst consequence of not writing
15. **Inversion**: use RACI + Process to see how much can be solved; if solvable, don't introduce a charter
16. **Second-order thinking**: second-order consequences of the charter (behavioral consistency / recruiting / culture / conflict) 
17. **Occam's razor**: charter simpler is better; cut redundant items
