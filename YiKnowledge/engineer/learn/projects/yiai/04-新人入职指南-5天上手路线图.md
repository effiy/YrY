## Day 1｜环境搭建与启动

**目标**：本地成功跑通 YiAi 项目

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 安装 Python 3.10+、pip、MongoDB、Ollama | 60 min | 本地开发环境就绪 |
| ② | 克隆仓库 → `pip install -r requirements.txt` 安装依赖 | 45 min | 依赖安装无报错 |
| ③ | 配置 `.env`（MongoDB URL、Ollama 地址等）→ `python main.py` 启动 | 30 min | 服务启动日志正常 |
| ④ | 访问 `http://localhost:10086/health` 健康检查 + 浏览 API 文档页面 | 15 min | 截图 2 张证明可用 |

**验收 Checklist**：
- [ ] `http://localhost:10086/health` 返回 200 OK
- [ ] `http://localhost:10086/docs` Swagger UI 正常加载
- [ ] `http://localhost:10086/health/observer` 端点可访问
- [ ] 能向 Mentor 复述 YiAi 的 3 个核心功能

---

### Day 1 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| pip 依赖安装失败 | 报 timeout 或版本冲突 | 使用国内镜像 `pip install -i https://pypi.tuna.tsinghua.edu.cn/simple`，或升级 pip 后重试 |
| MongoDB URL 连接不上 | 启动时抛 `ConnectionError` | 检查 `.env` 中 `MONGODB_URL` 格式，确认本地 MongoDB 是否已启动 |
| Ollama 模型未下载 | RAG 相关接口报 500 | 执行 `ollama pull qwen2:7b` 下载基础模型 |
| FSEvents 轮询告警 | macOS 下控制台大量轮询日志 | 设置环境变量 `WATCHFILES_FORCE_POLLING=true` |
| /health/observer 端点异常 | 返回 500 或数据异常 | 检查 APScheduler 任务是否注册，确认 MongoDB collections 已初始化 |

### Day 1 进一步学习路径
1. 通读 `requirements.txt` 了解全部依赖库
2. 尝试用 `curl` 手动调用 `auth/login` 接口拿到 token
3. 熟悉 `scripts/` 目录下的辅助工具脚本

## Day 2｜架构与核心概念

**目标**：读懂项目分层与核心模块

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 精读项目根目录 `CLAUDE.md` 与 `01-架构设计文档` | 90 min | 架构笔记 1 份 |
| ② | 识别 8 大路由模块（execution/auth/system/files/search/knowledge 等）职责 | 60 min | 模块职责对照表 |
| ③ | 追踪一个请求完整链路（如 `search/query` → 路由 → Service → MongoDB/Ollama → 返回） | 90 min | 链路追踪图（手绘或 Mermaid） |
| ④ | 画出 YiAi 整体架构图（至少 3 层：路由层/服务层/数据层） | 60 min | Mermaid 架构图 .md 片段 |

**验收 Checklist**：
- [ ] 能讲清 3 层以上分层（路由 / Service / 数据访问 / 外部集成）
- [ ] 能讲清核心模块 3 个以上（如 RAG、调度、鉴权）
- [ ] 能说出 8 大路由中任意 5 个的功能定位
- [ ] 能画出一张完整请求链路图

---

### Day 2 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| 找不到路由定义入口 | 不知道路由在哪里注册 | 查看 `main.py` 中 `include_router` 注册位置，对应 `app/routers/` 目录 |
| Service 与 Router 对应混乱 | 不知道业务逻辑放哪 | 遵循「路由只做参数校验/格式转换，业务放在 `app/services/`」原则 |
| llama_index RAG 调用关系复杂 | 无法一眼看懂 | 从 `knowledge/query` 路由断点进入，逐层 `step into` |
| APScheduler 任务不触发 | 定时任务未执行 | 检查 `app/core/scheduler.py` 中任务注册，确认启动时 `scheduler.start()` 被调用 |
| Motor 异步连接超时 | 大量 pending 请求 | 检查 MongoDB 连接池配置与网络延迟，必要时调大 `maxPoolSize` |

### Day 2 进一步学习路径
1. 深入阅读 `app/core/` 下的鉴权、配置、调度模块
2. 理解 `llama_index` 在 RAG 管线中的各阶段作用
3. 逐个阅读 8 大路由的 `*.py` 源码 + 对应单元测试

## Day 3｜代码调试与单测

**目标**：独立 Debug 并跑通过现有测试

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 用 VSCode / PyCharm 断点调试 `search/query` 或 `knowledge/ingest` 一条完整链路 | 90 min | 断点截图 + 变量观察记录 |
| ② | 执行 `pytest` / `pytest -cov` 跑全部单测 + `mypy` / `pyright` 类型检查 | 60 min | 测试/类型检查通过截图 |
| ③ | 改一个已有 bug（参考 `projects/yiai/bugs/`）或在核心路径加 1 条结构化日志 | 60 min | bugfix commit / 日志生效截图 |
| ④ | 运行 `scripts/dev_healthcheck.sh` 做端到端自检 | 30 min | 自检全部 PASS 截图 |

**验收 Checklist**：
- [ ] 断点成功进入路由 → Service → DAO 三层核心路径
- [ ] `pytest` 单测 0 失败
- [ ] `mypy` / `pyright` 类型检查 0 错误
- [ ] 日志改动在日志文件 / 控制台中可见

---

### Day 3 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| 断点始终进不去 | 代码热更新未生效 | 关掉 `uvicorn --reload`，手动重启进程后再下断点 |
| pytest fixture 找不到 DB session | 测试启动报 fixture 错误 | 确认 `tests/conftest.py` 被加载，检查 `pytest.ini` / `pyproject.toml` 配置 |
| mypy 报第三方库类型缺失 | 大量 `no attribute` 错误 | 为缺失库安装 `*_stubs`，或在 `mypy.ini` 中 `[mypy-xxx]\nignore_missing_imports = True` |
| 日志文件找不到位置 | 加了日志却没输出 | 查看 `app/core/logging.py`，找 `LOG_PATH` 配置，默认在 `./logs/` |
| motor session 未正确关闭 | 测试后连接泄漏 | 测试用例中使用 async fixture，确保 `yield` 后 `await session.close()` |

### Day 3 进一步学习路径
1. 学习 `pytest-asyncio` 与 `pytest-mock` 的进阶用法
2. 为一个没有单测的 Service 补 2-3 条测试用例
3. 阅读 `scripts/` 目录下的 CI 脚本，理解 CI 如何跑测试

## Day 4｜第一个小功能 / 修改

**目标**：独立完成 1 个可验证的小修改

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 从以下 3 个候选中挑 1 个：(a) 给 `analytics` 加 endpoints 使用数统计 (b) 给 `menus` 新增一条 menu (c) 修复 `projects/yiai/bugs/` 里任一 bug | 120 min | 本地可运行的功能代码 |
| ② | 为本次修改写一份 Dev 文档（含完整 frontmatter）放 `stories/` | 45 min | `stories/<你的修改>.md` |
| ③ | 本地跑 pytest + mypy + 手动 curl 验证功能 | 60 min | 验证截图 3 张以上 |
| ④ | 完成 Code Review Checklist 自检 | 15 min | checklist.md 勾选记录 |

**验收 Checklist**：
- [ ] 修改通过 `pytest` 全部单测
- [ ] 修改通过 `mypy` / `pyright` 类型检查
- [ ] Dev 文档 frontmatter 完整（title/tags/category/created…）
- [ ] 已完成 Code Review Checklist 自检项全部勾选

---

### Day 4 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Dev 文档 frontmatter YAML 语法错误 | 知识扫描报错 | 用 `yamllint` 检查，注意冒号后空格、缩进 2 格 |
| 新增接口没注册到路由 | 调用报 404 | 不要忘记在 `app/routers/__init__.py` 或 `main.py` 中 `include_router` |
| analytics 统计表缺少字段 | 插入报 `ValidationError` | 先检查 Pydantic Model 定义，再同步 MongoDB schema |
| 新增 menu 不显示在 YiVad | 前端读不到数据 | 用 `curl` 先调 `system/menus` 确认后端返回正确，再排查 YiVad 缓存 |
| bugfix 引发回归测试失败 | 新改动让旧测试挂掉 | 先看失败用例的期望行为，确认 bugfix 语义是否真的正确，必要时同步更新单测 |

## Day 5｜PR 准备与跨项目

**目标**：提 PR + 跨项目协作

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 用 Conventional Commits 写 commit message（格式：`<type>(<scope>): <subject>`） | 20 min | 符合规范的 git log |
| ② | 按照仓库 PR / MR 模板提交 PR | 40 min | PR 链接 1 个 |
| ③ | 关联 Issue + 关联至少 1 篇跨项目文档（如 YiVad 相关 Dev 或 YiKnowledge 中的 PRD） | 40 min | PR 描述中含链接 |
| ④ | 准备 10 分钟 Demo（本地演示 + 架构说明）给 Mentor | 60 min | Demo 验收通过 |

**验收 Checklist**：
- [ ] PR 包含自检项勾选（Code Review Checklist）
- [ ] 关联项目知识文件 1 篇以上
- [ ] commit message 符合 Conventional Commits 规范
- [ ] Mentor 验收通过并在 PR 中 Comment / Approve

---

### Day 5 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| commit message 不规范 | CI commitlint 校验挂掉 | 用 `git commit --amend` 修改，严格按照 `feat/fix/docs/test/refactor/chore` 前缀 |
| PR 模板字段没填全 | Reviewer 打回 | 仔细对照仓库 `PULL_REQUEST_TEMPLATE.md`，一项项勾选 |
| 跨项目文档链接 404 | 关联文档不存在 | 使用 **仓库内相对路径**，不要硬编码 GitHub 完整 URL，合并到 main 后再看效果 |
| Demo 现场环境挂了 | 演示当天跑不起来 | 提前一天准备好 `demo_scripts/` 一键启动脚本 + 录制备份 |
| PR 包含无关改动 | 大量和需求无关 diff | 提交前 `git diff --stat` 检查，用 `git add -p` 精确添加，多建分支 |

### Day 5 进一步学习路径
1. 完成 **2 周成长计划**：独立承担 1 个小模块（如 `files` 或 `system`）从需求到上线全流程
2. 完成 **1 月成长计划**：参与 1 次架构评审，能对某个模块的设计提出自己的建议
3. 尝试写一篇 `projects/yiai/stories/` 技术分享，沉淀自己踩过的坑
