# YiAi 架构设计

> 完整架构详见 [engineer/projects/01-项目-YiAi项目.md](../../../projects/01-项目-YiAi项目.md)。本文为快速参考摘要。

## 分层架构

```
server/   → FastAPI 路由 + 中间件（HTTP 层）
services/ → 业务逻辑编排
domain/   → 核心业务逻辑（ai, auth, files, knowledge, rag, rss, state, wework）
data/     → MongoDB 访问层（Motor 异步单例 + Repository）
shared/   → 跨切面（config, response, error_codes, logging, utils）
models/   → Pydantic Schema + 集合名称常量
```

### 各层职责与约束

| 层 | 职责 | 禁止 |
|---|---|---|
| `server/` | HTTP 路由处理、中间件、异常捕获 | 不能直接访问 `data/`，必须通过 `services/` |
| `services/` | 封装 domain 逻辑，提供 routes 调用接口 | 不能包含业务逻辑（业务逻辑在 domain/） |
| `domain/` | 纯业务逻辑，与传输层无关 | 不能导入 `server/` 或 `services/` |
| `data/` | MongoDB CRUD 操作，Motor 异步客户端 | 不能包含业务判断逻辑 |
| `shared/` | 全局工具（配置加载、响应格式、错误码） | 不能导入 `domain/`、`services/`、`server/` |

## 关键数据流

### RPC 通用数据操作

```
YiVad/YiPet POST / { module_name, method_name, parameters }
  → FastAPI 根路由处理器 (src/app.py)
  → 解析 module_name → Python 模块路径
  → 解析 method_name → 可调用对象
  → service.<domain>.<service>.<method>(**parameters)
  → domain 业务逻辑
  → data/repository.py → MongoDB (Motor async)
  → 响应: { code: 0, message: "ok", data: <any> }
```

### AI 聊天 SSE 流式

```
YiVad/YiPet POST / { module_name: "services.ai.chat_service", method_name: "chat" }
  → chat_service.chat(**parameters)
  → domain/ai/chat.py → Ollama/OpenAI/Anthropic 流式调用
  → StreamingResponse(text/event-stream)
  → SSE data: 帧 → 前端增量渲染
```

### 文件双写

```
写入: 磁盘（主）→ MongoDB static_files 集合（尽力备份）
读取: 磁盘优先 → MongoDB 回退
```

## 降级策略

| 故障场景 | 系统行为 | 影响 |
|---|---|---|
| MongoDB 不可用 | 写入快速失败，读取返回空结果 | 所有功能不可用（DB 是唯一数据源） |
| Ollama 不可用 | 聊天端点返回 `ErrorCode.AI_UNAVAILABLE (2001)` | AI 聊天功能不可用，其他功能正常 |
| OSS 不可用 | 文件存储回退到本地磁盘（双写降级为单写） | 文件上传仍可用，缺少异地备份 |
| Auth 中间件禁用 | 所有端点无需认证即可访问（默认状态） | 无影响（开发环境正常配置） |
| Observer 中间件禁用 | 无限流/采样/沙箱保护 | 无影响（开发环境正常配置） |
