## Day 1｜环境搭建与启动

**目标**：本地成功启动 YiPot Tauri 桌面应用

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 安装 Node.js 18+ / pnpm 8+ / Rust stable（rustup）/ macOS Xcode Command Line Tools / WebView2（Windows） | 60 min | `rustc --version` / `pnpm -v` / `node -v` 全部输出正常 |
| ② | 克隆仓库 → `pnpm install` 安装前端依赖 → `cd src-tauri && cargo check` 检查 Rust 依赖 | 60 min | 前端依赖 / Rust crate 下载成功无报错 |
| ③ | 回到项目根 → `pnpm tauri dev` 启动（首次会编译 Rust 10 分钟左右，耐心等待） | 15 min + 编译 10 min | Tauri 窗口正常弹出，无编译错误 |
| ④ | macOS 系统偏好设置 → 隐私与安全性 → 开启「辅助功能权限 / 屏幕录制权限 / 剪贴板权限」→ 测试截图热键 + 翻译窗口 | 45 min | 权限已开，截图热键生效，翻译窗口可打开，截图缓存 `yipot_screenshot_cut.png` 生成 |

**验收 Checklist**：
- [ ] Tauri 桌面窗口正常启动，前端页面正常渲染（无白屏）
- [ ] `http://localhost:1420` 前端 dev server 可访问（dev 模式）
- [ ] `http://localhost:60828` Tauri HTTP 端口监听正常
- [ ] 截图热键能正常工作，翻译窗口能打开，能向 Mentor 复述 3 个核心功能

---

### Day 1 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Rust 首次编译极慢 / 卡死 | `cargo build` 卡在某个 crate 十几分钟 | 更换 Rust 国内源（`~/.cargo/config` 加 tuna / ustc 镜像），首次编译预计 10-20 分钟属于正常 |
| macOS 辅助功能权限开启后仍然无效 | 截图热键按了没反应 | 先关权限再重开，列表里移除 YiPot 再重新添加，重启 App，必要时重启电脑 |
| 截图缓存 `yipot_screenshot_cut.png` 找不到 | 截图完成看不到文件 | 默认路径在 `std::env::temp_dir()` 下，可用 `find /tmp -name "yipot*"` 全局搜 |
| Tauri 窗口白屏 | 启动后窗口一片空白 | 打开 DevTools（dev 模式下 F12 或右键菜单），看前端 `import` 路径错或 Jotai Provider 未挂载 |
| pnpm tauri dev 报 `WebView2 not installed`（Windows） | Windows 启动失败 | 按 Tauri 官方文档安装 Microsoft Edge WebView2 Runtime，Win11 一般自带 |

### Day 1 进一步学习路径
1. 通读 `package.json` + `src-tauri/Cargo.toml` 了解全部依赖和脚本
2. 手动打开 Tauri DevTools，观察前端 console 与 Rust log 两端输出
3. 阅读 `src-tauri/tauri.conf.json` 理解窗口 / 热键 / 权限配置

| ② | 识别 18 个 Tauri Commands、4 类 37 个插件（21 translate / 14 recognize / 1 tts / 2 collection）、全局热键、截图 OCR 流水线、8 大窗口 | 120 min | 核心模块对照表（Commands/Plugins/Hotkeys/Windows 各 1 张） |

### Day 2 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Tauri Invoke 参数对不上 | 前端 `invoke('xxx', {...})` Rust 侧收不到 | 查看 `src-tauri/src/commands.rs` 函数签名参数名必须和 JS 侧对象 key 完全一致，驼峰/下划线注意 serde rename |
| Jotai atom 与 Tauri 状态不同步 | 配置改了 React 侧没刷新 | 用 `useTauriEvent` 监听 Rust `emit` 事件，再 `setAtom` 同步，不要假设 Rust 改了前端自动知道 |
| 37 个插件不知道从哪看源码 | 分不清哪个是内置/哪个是第三方 | 看 `src-tauri/Cargo.toml` dependencies 中的 `yipot-plugin-*` 内部 crate，第三方直接搜 crates.io |
| 全局热键注册冲突 | 启动报 `hotkey already registered` | 查看其他 App 占用了什么键，改 `tauri.conf.json` 中快捷键，或加 `unregister_all` 兜底 |
| 8 大窗口谁是谁分不清 | 不知道哪个窗口对应哪个 URL | 对照 `tauri.conf.json` 中 `windows[]` 数组 label 字段，前端路由 `src/routes/` 对应 label 子目录 |

### Day 2 进一步学习路径

2. 挑 1 个翻译插件 + 1 个 OCR 插件，完整读一遍源码（`yipot-plugin-translate-*`）
3. 逐个查看 8 大窗口对应的 React 页面代码（`src/pages/` / `src/windows/`）

## Day 3｜代码调试与单测

**目标**：独立 Debug 前后端 + 跑通现有测试

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 前端 VSCode Debugger 断点进翻译窗口组件 + Rust CLion/VSCode `lldb` 断点进 `translate()` Command，两端都走到 | 120 min | 前后端断点截图各 1 张 + 变量观察 |
| ② | 前端：`pnpm typecheck` + `pnpm lint` + `pnpm test`；Rust：`cd src-tauri && cargo test --workspace` + `cargo clippy -- -D warnings` | 90 min | 全部检查通过截图（typecheck 0 error / clippy 0 warn） |
| ③ | 从 `bugs/yipot/` 挑 1 个已有的 `unwrap nullsafe` 类 bug，加固修复（加 match / if let / ok_or 处理 None 分支） | 90 min | bugfix commit + 修复前后对比说明 |
| ④ | `pnpm tauri build` 打一个 dmg / msi 安装包（dev 就可，不签名），确认产物能跑 | 30 min + 编译时间 | 安装包生成 + 安装后打开截图 |

**验收 Checklist**：
- [ ] 前端断点成功进入 React 组件 event handler → invoke()；Rust 断点进入对应 Command 函数体
- [ ] `vue-tsc` / `tsc` 0 error；`cargo clippy` 0 error 0 warning（或仅有 pre-existing）
- [ ] `unwrap` 加固：至少修复 1 处 `unwrap()` 为安全处理并通过 `cargo test`
- [ ] `pnpm tauri build` 成功生成安装包文件

---

### Day 3 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Rust `lldb` 断点不触发 | launch.json 配了也进不去 | Tauri dev 模式下要先 `pnpm tauri dev` 启动，再 Attach 到进程，不要用 `cargo run` 直接跑 |
| cargo clippy 报大量 warnings 导致 CI 不过 | 本地没开 `-D warnings` | 严格使用 `cargo clippy --workspace --all-targets -- -D warnings` 作为标准命令，不要自己简化 |
| 修复 unwrap 后引发新的编译错误 | 改了 Option 处理返回类型不匹配 | 按最小改动原则：保留原返回类型，错误分支返回合理默认值或 `return Err(...)` 而不是改函数签名 |
| Tauri build 签名失败（macOS 尤其严重） | 打包报 codesign 错误 | 本地开发用 `pnpm tauri build --debug` 跳过签名，正式签名需要证书（新人不需要） |
| 前端 vitest 报 `window.__TAURI__ is undefined` | 测试环境没 Tauri | 用 vitest `setupFiles` 模拟 `window.__TAURI__.invoke`，参考 `tests/mocks/tauri.ts` |

### Day 3 进一步学习路径
1. 为一个没单测的 Rust plugin 写 2 条 `cargo test` 用例（happy path + error path）
2. 研究 Tauri `Event` 机制，用 `emit` + `listen` 做一次跨窗口通信
3. 阅读 `src-tauri/build.rs` + CI 脚本，理解流水线怎么打包签名发布

### Day 4 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| TTS 暂停按钮前端加了 Rust 侧没对应状态 | 点暂停还继续播 | 如果 TTS 是 Rust 插件内部控制，需要增加「pause_tts」Command + 内部状态机，不要只在前端 set 一个 flag |
| Tooltip 样式在 NextUI 中不显示 | 问号图标 hover 不出提示 | 正确引入 `@nextui-org/tooltip`，注意 `delay` / `placement`，必要时外层包 `div` 让事件冒泡正确 |
| unwrap 加固引发 clippy new warning | 改了代码 clippy 反而多报 | 优先用 `if let Some(x) = ... { } else { }` 或 `.ok_or(...)?`，不要用 `match` 嵌套过深导致 `clippy::collapsible_match` |
| Dev 文档 frontmatter 字段名写错 | 把 `benefit` 写成了 `benefits` | 参考本文件最上方 frontmatter 模板 **逐字段对照**，不要凭记忆 |
| 修改了 Tauri invoke 签名但前端旧缓存还在 | 前端报 `command xxx not found` | `pnpm tauri dev` 模式下，Rust 改了会自动重编，但仍需清 `src-tauri/target/` 缓存并重启 dev |

## Day 5｜PR 准备与跨项目

---

### Day 5 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| 一次 commit 混了 Rust + 前端 + 文档多种改动 | Reviewer 让拆 PR | 用 `git add -p` 精确拆分提交，拆成 3 个 commit：`feat(rust):` + `feat(web):` + `docs:`，一个 PR 可以多 commit 但不要混 scope |
| PR 模板里没贴 clippy 截图 / 验证截图 | 第一轮 Review 必被打回 | 模板里每个「截图：」占位都别空，没有就贴「N/A + 原因」，不要留空 |
| 跨项目链接写死 GitHub URL 导致 404 | 合并到 main 也打不开 | 用仓库根相对路径，如 `../yipet/01-项目-架构设计.md`，不要写 `github.com/xxx/.../blob/main/...` |
| Demo 当天系统权限又失效 | 热键/截图不工作 | 提前 10 分钟开 Demo 机器检查权限，录制备份视频以防万一 |
| PR 包含 `src-tauri/target/` 或 node_modules | diff 体积爆炸 | `.gitignore` 确保忽略 `target/` / `node_modules/`，已提交就 `git rm -r --cached src-tauri/target` |

3. 尝试写一篇 `projects/yipot/stories/` 技术分享，沉淀 Tauri 前后端联调 + unwrap 修复经验
