## Day 1｜环境搭建与启动

**目标**：本地成功加载 YiPet Chrome MV3 扩展

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 安装 Node.js 18+、npm 9+、Chrome 最新版（120+） | 30 min | 本地开发环境就绪 |
| ② | 克隆仓库 → `npm install` 安装依赖 | 45 min | 依赖安装无报错，`node_modules/` 正常生成 |
| ③ | `npm run build`（或 `npm run dev:watch`）构建产物到 `dist/` | 60 min | `dist/` 下 manifest.json + 多入口产物齐全 |
| ④ | 打开 `chrome://extensions` → 开启「开发者模式」→ 加载已解压扩展 → 选择 `dist/` → 测试 Popup 弹出 | 30 min | 截图 3 张（扩展管理页、Popup 页、浮动 Pet） |

**验收 Checklist**：
- [ ] `chrome://extensions` 中 YiPet 已启用，无红色错误角标
- [ ] 浏览器右上角 Popup 点击可正常弹出
- [ ] 打开任意网页，浮动 Pet 在右下角可见
- [ ] 能向 Mentor 复述 YiPet 的 3 个核心功能

### Day 1 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| jsxDEV 残留导致生产构建失败 | `npm run build` 后报 `ReferenceError: React is not defined` | 确保构建命令用 `NODE_ENV=production`，禁用 jsxDEV，或使用 `npm run build:prod` |
| MV3 CSP 策略拦截 inline 脚本 | 控制台报 `Refused to execute inline script` | 不要在 HTML 中写 `<script>...</script>`，所有代码都打包进独立 JS 文件，CSP 在 manifest.json 中放宽需要非常谨慎 |
| `chrome://extensions` 加载后报错 | 「清单文件缺失或不可读取」 | 确认 `dist/manifest.json` 存在且是合法 JSON，不要选到项目根目录而不是 `dist/` |
| 改了代码扩展没更新 | 刷新网页 Pet 没变 | MV3 热更新需要 **在扩展管理页点「刷新」按钮** 或装 `Extension Reloader` 辅助插件，只刷新网页没用 |
| Popup 打开白屏 | 点击图标一片空白 | 打开 F12 Popup DevTools（右键图标→审查弹出内容），看是否 import 路径错或 runtime.lastError |

### Day 1 进一步学习路径
1. 通读 `package.json` 中所有 build 脚本（dev / build / watch / analyze）
2. 查看 `dist/manifest.json` 结构，对比 `manifest.config.ts`（或源文件）
3. 试试 `npm run dev:watch` + 扩展管理页自动刷新，看看开发体验和 build 有何区别

## Day 2｜架构与核心概念

**目标**：读懂项目分层与核心模块

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 精读项目根目录 `CLAUDE.md` + `01-架构设计文档` | 90 min | 架构笔记 1 份 |
| ② | 识别 4 大核心概念：双世界（ISOLATED / MAIN）、四层 API、CDN 80+ 库、NativeMessage 4 入口 | 90 min | 核心概念对照表 |
| ③ | 追踪一个完整链路：点击 Popup 按钮 → Background Service Worker → Content Script → 注入 MAIN 世界 | 90 min | 链路追踪图（手绘或 Mermaid） |
| ④ | 画出 YiPet 4 层架构图 + 多入口（popup/chat/bootstrap/CDN）关系图 | 60 min | Mermaid 架构图 .md 片段 |

**验收 Checklist**：
- [ ] 能讲清「ISOLATED 世界」和「MAIN 世界」的区别以及通信方式
- [ ] 能讲清 3 个以上核心模块（Popup、Chat、浮动 Pet、CDN 注入）
- [ ] 能区分 RPC 中 `filter` 与 `query` 参数用途（filter = 结构化筛选，不是 query）
- [ ] 能画出从 Popup 点击到网页内生效的完整链路

---

### Day 2 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Content Script 读不到 window 变量 | ISOLATED 世界 window 是隔离的 | 读网页全局对象必须走 `window.postMessage` 或 `chrome.scripting.executeScript({world: 'MAIN'})` |
| Background SW 被休眠 | 过一会儿消息收不到 | MV3 Service Worker 空闲 30s 被杀，必须用 `chrome.storage` 持久化 + `chrome.runtime.sendMessage` 触发唤醒 |
| NativeMessage 不通 | 桌面端收不到 / 发不回 | 检查 manifest.json `externally_connectable` + 主机端 native messaging manifest 是否注册到 Chrome |
| CDN 库版本混乱 | 80+ 库不知道引哪个 | 严格看 `src/cdn/registry.ts`（或同类），不要在代码里硬编码 unpkg URL |
| 浮动 Pet z-index 被页面盖住 | Pet 藏在网页元素后面 | 动态读取 `document.body` 下最高 z-index + 1，必要时强制 `z-index: 2147483647` |

### Day 2 进一步学习路径
1. 逐个阅读 `src/entries/` 下 4 个入口（popup/chat/bootstrap/CDN）的入口文件
2. 理解 `src/shim/` 或 `src/bridge/` 下双世界通信桥接层实现
3. 阅读 `src/core/message/` 下消息总线与 RPC 封装

### Day 3 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| 找不到 Background Service Worker DevTools | 不知道怎么调试后台 | 扩展管理页 → YiPet → 「Service Worker (无效)」→ 点一下激活 → 再点「检查视图：Service Worker」 |
| Content Script 断点永远不命中 | 刷新网页也进不去 | 确认 Content Script 已匹配到当前 URL（manifest 的 `matches`），必要时在 Content Script 开头写 `debugger` 语句 |
| vitest 报 `chrome is not defined` | 测试环境没有 chrome API | 用 `vitest` 的 `setupFiles` + `vi.mock('chrome', ...)` mock，参考 `tests/mocks/chrome.ts` |
| MAIN 世界代码调试看不到源码 | 注入的代码 sourcemap 不对 | 注入 MAIN 世界时用 `chrome.scripting.executeScript({... world: 'MAIN', injectImmediately: true})`，确认 sourcemap 一并 build 进去 |
| 改了代码必须手动 Reload 扩展 + 刷网页 | 开发效率极低 | 装「Extension Reloader」浏览器插件，或 `npm run dev:watch` + 自定义 reload 脚本 |

- [ ] 修改通过 `typecheck` 类型检查

---

### Day 4 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| Popup 开关改了状态，Pet 页面没同步 | Popup 和 Content Script 状态不同步 | 必须通过 `chrome.runtime.sendMessage` 广播消息，Content Script 监听后更新 DOM，不要假设共享内存 |
| `/clear` 命令在 MAIN 世界不生效 | 用户在页面聊天框输入命令没反应 | 看输入框是在 ISOLATED（扩展注入）还是 MAIN（原生页面）里，不同世界走不同入口 |
| Pet hover 动画闪一下就停 | transition 没生效就被重置 | 用 `@keyframes` + CSS class 切换，不要频繁改 style inline，必要时用 `requestAnimationFrame` |
| Dev 文档 frontmatter YAML 缩进错误 | 知识扫描解析失败 | 用 yamllint 检查，缩进 2 空格，数组 `- ` 后面必须空格 |
| 新增图片 / 图标 build 后路径 404 | Popup 中图片不显示 | 静态资源统一放 `public/`，代码中用 `chrome.runtime.getURL('/xxx.png')`，不要写相对路径 |

1. 尝试把 P2 小需求扩展成完整 PRD → Dev → Test 三联文档

3. 为快捷命令系统增加 `/help` 命令 + 命令注册机制，做成插件式

## Day 5｜PR 准备与跨项目

**目标**：提 PR + 跨项目协作

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 用 Conventional Commits 写 commit message（格式：`<type>(<scope>): <subject>`） | 20 min | 符合规范的 git log |
| ② | 按照仓库 PR / MR 模板提交 PR | 40 min | PR 链接 1 个 |
| ③ | 关联 Issue + 关联至少 1 篇跨项目文档（如 YiPot / YiAi / YiKnowledge 中相关 PRD 或 Dev） | 40 min | PR 描述中含链接 |
| ④ | 准备 10 分钟 Demo（加载扩展到 Chrome + 现场演示 + 架构说明）给 Mentor | 60 min | Demo 验收通过 |

**验收 Checklist**：
- [ ] PR 包含自检项勾选（Code Review Checklist）
- [ ] 关联项目知识文件 1 篇以上
- [ ] commit message 符合 Conventional Commits 规范
- [ ] Mentor 验收通过并在 PR 中 Comment / Approve

---

### Day 5 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| commit message 不规范 | CI commitlint 挂掉 | `git commit --amend` 修改，严格 `feat/fix/docs/test/refactor/chore` 前缀 |
| PR 把 `dist/` 一起提交了 | diff 体积巨大 | 提交前 `git status` 检查，`.gitignore` 必须忽略 `dist/`，如已 commit 则 `git rm -r --cached dist/` |
| 跨项目链接 404 | 引用 YiPot / YiAi 文档不存在 | 使用仓库相对路径（如 `../yipot/0001-项目-架构设计.md`），不要写绝对 URL |
| Demo 现场 Chrome 扩展加载失败 | 临时环境问题 | 提前准备一台干净的 Chrome Profile，录制备份视频兜底 |
| NativeMessage 跨项目演示失败 | YiPot 没在运行 | 提前把依赖项目一起启动，或准备 mock 数据的分支 |

### Day 5 进一步学习路径

2. 完成 **1 月成长计划**：参与 1 次架构评审，主导 1 个跨浏览器（Firefox/Edge）兼容性改造
3. 尝试写一篇 `projects/yipet/stories/` 技术分享，沉淀 MV3 + 双世界踩坑经验
