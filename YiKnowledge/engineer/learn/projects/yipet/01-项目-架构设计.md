# YiPet 架构设计

> 完整架构详见 [engineer/projects/03-项目-YiPet项目.md](../../../projects/03-项目-YiPet项目.md)。本文为快速参考摘要。

## 双世界边界（核心概念）

YiPet 的架构由 Chrome MV3 的"双世界"执行模型定义——这是理解 YiPet 架构的第一性原理：

```
ISOLATED World (Content Script)           MAIN World (Page Context)
─────────────────────────────────         ─────────────────────────
chrome.runtime.* API 可用                页面 DOM 访问
chrome.storage API 可用                  页面 JS 全局变量 (window)
通过 CustomEvent 与 MAIN 通信            chrome.runtime.* API 不可用
src/content/bootstrap.ts (第一阶段)       src/content/bootstrap.ts (第二阶段)
```

### 通信路径

```
Popup (Vue 3)
  → chrome.tabs.sendMessage({type, payload})
    → Content Script (ISOLATED)
      → CustomEvent
        → Bootstrap (MAIN)
          → 修改宠物 DOM / 打开聊天窗口
```

### 关键约束

- `chrome.runtime.*` 只在 ISOLATED World 可用——在 MAIN 中调用会**静默失败**
- 页面全局变量只在 MAIN World 可见——在 ISOLATED 中不可见
- 两个世界通过 `CustomEvent` 进行通信

## 分层架构

```
Popup UI (Vue 3 + Element Plus 2.14)
Chat Window (Vue 3，独立 Rsbuild 构建入口)
Content Script (ISOLATED → MAIN 桥接)
API Layer (4 层: client → endpoints → types → services)
YiAi Backend (FastAPI :10086)
```

## 四层 API 架构

| 层 | 文件 | 职责 | 示例 |
|---|---|---|---|
| 第 1 层：Client | `api/client.ts` | Fetch 封装 + SSE 流 + 重试 + RPC 信封 | `client.rpc(moduleName, methodName, parameters)` |
| 第 2 层：Endpoints | `api/endpoints.ts` | 路径常量 | `ENDPOINTS.BASE`, `ENDPOINTS.KNOWLEDGE` |
| 第 3 层：Types | `api/types.ts` | 请求/响应接口 | `RpcRequest`, `ChatMessage`, `SessionData` |
| 第 4 层：Services | `api/services/*.ts` | 领域服务类 | `ChatService.stream()`, `SessionService.list()` |

**分层纪律**：不允许跨层调用。组件通过 Service 层调用 API，不直接使用 Client 或 Endpoints。

## CDN 资源注入

YiPet 的 80+ 个第三方库全部本地化存储在 `public/cdn/vendor/` 下，通过 `chrome-extension://` URL 加载。这是 MV3 CSP（`script-src 'self'`）的合规要求——禁止加载远程代码。

### CDN 目录结构
```
public/cdn/
├── utils/api-client.ts     # 基础 fetch 封装（共享）
├── styles/variables.css    # CSS 变量
├── styles/chat.css         # 聊天窗口样式（构建时拼接）
└── vendor/                 # 80+ 第三方库本地副本
```

### CDN 目录作为单一事实来源
`src/content/cdn/catalog.ts` 维护完整的资源清单。新增依赖不仅需要 `npm install`，更需要在此目录中添加条目——否则注入器不会加载该资源。

## 四入口构建

| 入口 | 配置 | 产物 | 运行环境 |
|---|---|---|---|
| Popup | `rsbuild.config.ts` | `dist/popup.html` + `dist/assets/popup.js` | 扩展弹窗 |
| Background | `rsbuild.config.ts` | `dist/assets/background.js` | Service Worker |
| Chat | `rsbuild.config.chat.ts` | `dist/assets/chat.js` | MAIN World 注入 |
| Bootstrap | `rsbuild.config.bootstrap.ts` | `dist/assets/bootstrap.js` | Content Script (双世界) |

**关键陷阱**：聊天窗口入口必须在开发脚本中带 `--mode production` 参数——CDN 加载的是生产版本 React（不含 `jsxDEV`）。

## 数据流

### 聊天消息流
```
用户输入 (ChatInput)
  → ChatController.sendMessage(text)
  → 路由判断: grounded → RagService / agent → AgentService / normal → ChatService
  → ApiClient.stream() → fetch POST YiAi
  → SSE 流式解析 → Chat Store 更新状态
  → Pinia → Vue 响应式重新渲染
```

### Popup 到 Content Script
```
Popup → chrome.tabs.sendMessage() → ISOLATED World → CustomEvent → MAIN World
```

### 跨项目桥接
```
YiPet Chat → 种子化会话数据 → window.open(YiVad URL + session key)
YiPet Chat → BugService.create() → YiAi → MongoDB + YiKnowledge
```
