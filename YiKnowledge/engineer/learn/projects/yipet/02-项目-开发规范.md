# YiPet 开发规范

> 完整规范详见 [engineer/projects/03-项目-YiPet项目.md](../../../projects/03-项目-YiPet项目.md) 和 [YiPet/CLAUDE.md](../../../../YiPet/CLAUDE.md)。以下为快速参考。

## 命名约定

| 范畴 | 规范 | 示例 |
|---|---|---|
| 组件 | PascalCase，每个组件一个文件夹（Vue SFC + 作用域 CSS） | `ChatWindow/`, `ChatInput/` |
| Service | camelCase | `authService.ts`, `chatService.ts` |
| 共享模块 | camelCase | `roles.ts`, `timezone.ts` |
| CSS | 组件同目录，`buildChatCSS()` 拼接 | `ChatWindow/style.css` |

## 关键陷阱（必读）

### 双世界边界

- **`chrome.runtime.*` 只在 ISOLATED World 可用** —— 在 MAIN World 调用会**静默失败**，没有任何错误提示
- **页面全局变量只在 MAIN World 可见** —— ISOLATED World 中访问 `window.YiPet` 返回 undefined
- **调试技巧**：在 ISOLATED World 代码中 `console.log` 出现在 DevTools 的 "Content Script" 上下文，MAIN World 的日志出现在 "top" 上下文

### CDN 目录

- **所有 80+ 第三方库必须在 `CDN_CATALOG` 中注册** —— 同时需要全局存在检查函数。缺少任一项都会导致：要么库不被加载（功能缺失），要么重复加载（冲突）
- **新增依赖的流程**：`npm install` → 复制到 `public/cdn/vendor/` → 在 `src/content/cdn/catalog.ts` 添加条目

### 构建

- **聊天窗口构建必须带 `--mode production`** —— 开发模式下的 JSX 编译器使用 `jsxDEV`，但 CDN 中的 React 是生产版本（不含 `jsxDEV` 导出），不匹配会导致运行时报错
- **4 个独立 Rsbuild 配置文件** —— 每个入口有独立的构建流程，修改构建配置时确保对所有四个入口都进行了测试

### 类型检查

- **`vue-tsc --noEmit` 是唯一的类型检查** —— Rsbuild/SWC 在构建时会**静默剥离类型**，不进行类型检查。始终在提交前运行 `npm run typecheck`
- **TS 严格模式**已启用 —— `strict: true` 在 `tsconfig.json` 中

### RPC 参数契约

| 正确 | 错误 | 上下文 |
|---|---|---|
| `filter` | `query` | `data_service.query_documents` 的过滤参数 |

**为什么容易出错**：`query` 看起来比 `filter` 更自然，但 YiAi 后端的 `_build_filter` 读取的是 `filter` 键。使用 `query` 会被**静默忽略**——没有错误提示，只是返回空结果或全量数据。

## 国际化（i18n）

- 使用 Chrome `chrome.i18n` API
- 消息文件：`_locales/{en,zh_CN}/messages.json`（55+ 键）
- 使用类型化的 `t('key')` 包装函数，**绝不直接使用** `chrome.i18n.getMessage`
- 语言回退链：当前语言 → `en` 源语言 → key 本身

## Lint 与格式化

- ESLint 10 + Prettier 3
- 自动修复：`npm run lint:eslint && npm run lint:prettier`
- 提交前自动检查（lint-staged + husky）

## 测试

- 框架：Vitest 2 + jsdom
- 当前测试数：97+
- 运行：`npm test`

## 组件样式约定

- CSS 与组件同目录放置（不集中管理样式文件）
- 聊天窗口的 CSS 通过 `buildChatCSS()` 函数在构建时拼接为 `dist/cdn/styles/chat.css`
- 使用作用域 CSS 变量（`var(--yp-*)`）进行主题切换
