# 静默吞错误：`.catch(() => {})` 隐藏运行时失败

> 在 YiVad 和 YiPet 代码库中发现多处 `.catch(() => {})` 模式。这些空 catch 块吞掉了所有异常，导致运行时错误完全不可见——功能静默失败，无日志、无提示。

## 影响范围

| 项目 | 文件 | 位置 | 修复 |
|---|---|---|---|
| YiVad | `src/services/sortPersistence.ts:5` | 排序持久化失败静默吞掉 | 添加 `console.warn` 日志 |
| YiVad | `src/stores/modules/aiChat/useConversations.ts:229,246` | 会话删除失败静默吞掉 | 已有错误处理流程，保留 |
| YiPet | `src/chat/stores/chat.ts:566,590,1441` | 上下文/会话加载失败静默 | 部分为 fire-and-forget，保留 |
| YiPet | `src/content/ipc/relay.ts:153` | Token 存储失败静默 | chrome.storage 操作，低风险 |

## 根因

开发者在 Promise 链末尾添加空 catch 以避免未处理的 rejection，但未提供任何错误可见性管道。代码所有者无法知道这些操作是否成功。

## 修复原则

1. **关键数据操作**（排序、持久化）：至少记录 `console.warn`，包含上下文信息
2. **chrome.storage 操作**：`w=0` fire-and-forget 的 chrome.storage 写入可以静默（存储配额超出的风险可接受）
3. **UI 更新**：可以静默，但发出一条 `console.debug`（生产中不显示）

## 检测方法

```bash
# 搜索所有空 catch 块
rg '\.catch\(\(\)\s*=>\s*\{\s*\}\)' --type ts
```

## 修复示例

```typescript
// 修复前：静默失败
items.map(item => updateDocument(coll, item.key, data).catch(() => {}))

// 修复后：错误可见
items.map(item => updateDocument(coll, item.key, data).catch(err => {
  console.warn("[sortPersistence] Failed:", err instanceof Error ? err.message : String(err))
}))
```
