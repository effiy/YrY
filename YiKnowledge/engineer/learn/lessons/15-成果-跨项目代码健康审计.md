# 跨项目代码健康审计 — 63 项修复

> 对 YrY 单体仓库 5 个项目进行的 7 轮系统性代码质量扫描。发现并修复 63 个功能坏味道，跨 TypeScript/Python/Rust/Markdown 四种语言。

## 审计方法论

每轮聚焦不同维度，7 轮覆盖完整的代码质量光谱：

| 轮次 | 焦点 | 典型发现 |
|------|------|----------|
| R1 | 日志与异常可见性 | `print()` 替代 `logging`、空 catch 吞错误 |
| R2 | 数据结构安全 | 脆弱的 dict 访问（IndexError）、frontmatter 格式错误 |
| R3 | 资源管理与 UI 清理 | useEffect 内存泄露、裸 `except: pass` |
| R4 | 框架规范与国际化 | v-for :key 校验、i18n 键对齐、目录命名一致性 |
| R5 | 错误降级链与配置边界 | 三层降级验证、路由守卫循环预防、SPA 重注入 |
| R6 | 并发安全与 XSS 防护 | `asyncio.gather` 异常传播、DOMPurify 使用 |
| R7 | 安全白名单与存储配额 | RPC module allowlist、Tauri 命令错误传播 |

## 关键教训

1. **空 catch 是最隐蔽的 bug** — `.catch(() => {})` 和 `except: pass` 让错误完全不可见。至少记录一条 debug 日志。
2. **frontmatter 是机器可读的配置** — YAML 解析器对格式要求严格，`updated: 2026-09-10---` 缺少换行会导致元数据丢失。
3. **React useEffect 必须清理** — 每次 `addEventListener` 都需要对应的 `return () => removeEventListener`。
4. **目录命名即 API** — 目录名被 `related:` 链接引用，拼写错误会传播到所有链接文件中。
5. **TypeScript 类型错误是硬阻断** — 7 个 TS 错误让 `vue-tsc --noEmit` 失败，阻止构建。

## 自动化检测清单

```bash
# 空 catch 块
rg '\.catch\(\(\)\s*=>\s*\{\s*\}\)' --type ts

# 后端裸 except
rg 'except Exception:' --type py src/

# TODO/FIXME 残留
rg 'TODO|FIXME|HACK' --type ts --type py src/

# frontmatter 格式错误
rg '\d{4}-\d{2}-\d{2}---$' --type md

# useEffect 无 cleanup
rg 'useEffect\(\(\)\s*=>\s*\{[^}]*(addEventListener|setInterval|subscribe)' --type tsx --type jsx
```
