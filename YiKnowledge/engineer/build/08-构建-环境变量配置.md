# 环境变量配置指南

> YrY 的三个项目使用三种不同的配置系统。了解每个系统的加载机制、命名约定和关键变量，可以避免最常见的配置错误——变量名写错导致功能静默失效。

## 各项目配置系统对比

| 项目 | 配置系统 | 文件 | 加载方式 | 变量前缀 |
|------|---------|------|---------|---------|
| YiAi | YAML + pydantic-settings | `config.yaml` | Python 扁平化加载 | 无（YAML 层级结构） |
| YiVad | dotenv + Rsbuild | `.env`, `.env.development`, `.env.production` | Rsbuild 构建时替换 | `RSBUILD_ENV_` |
| YiPet | dotenv + 手动加载 | `.env` | 构建时 define 替换 | 无强制前缀 |

## YiAi — config.yaml

### 配置文件结构

```yaml
# YiAi/config.yaml
server:
  host: "0.0.0.0"
  port: 10086
  reload: true          # 开发模式：true；生产：false

mongodb:
  uri: "mongodb://localhost:27017"
  db_name: "ruiyi"
  pool_size: 10
  max_pool_size: 50

ollama:
  host: "http://localhost:11434"
  model: "qwen2.5:3b"
  timeout: 120           # 推理超时（秒）

middleware:
  auth_enabled: false    # 生产环境建议开启
  auth_token: ""

rag:
  index_dir: "data/rag_store"
  chunk_size: 512
  top_k: 5

knowledge:
  watcher_poll_seconds: 60   # YiKnowledge 扫描间隔
  base_path: "../YiKnowledge"

jwt:
  secret: ""
  algorithm: "HS256"
  expire_minutes: 1440

cors:
  origins: ["*"]         # 生产：限制为具体域名
  allow_any_origin: true
```

### 代码中读取

```python
# YiAi/src/shared/config.py
from pydantic_settings import BaseSettings
from yaml import safe_load

class Settings(BaseSettings):
    # YAML 键名被扁平化：server.port → server_port
    server_port: int = 10086
    mongodb_uri: str = "mongodb://localhost:27017"
    mongodb_db_name: str = "ruiyi"
    ollama_model: str = "qwen2.5:3b"
    middleware_auth_enabled: bool = False
    knowledge_watcher_poll_seconds: int = 60

# 使用
from shared.config import settings
print(settings.server_port)  # 10086
```

### 添加新配置项

```yaml
# 1. 在 config.yaml 中添加
new_feature:
  enabled: true
  max_retries: 3
```

```python
# 2. 在 config.py 的 Settings 类中添加对应字段
class Settings(BaseSettings):
    new_feature_enabled: bool = True
    new_feature_max_retries: int = 3
```

**规则**：YAML 嵌套键用下划线连接——`new_feature.enabled` → `new_feature_enabled`。

## YiVad — dotenv + Rsbuild

### 配置文件

```bash
# YiVad/.env                    # 所有环境加载
# YiVad/.env.development        # pnpm dev 时加载
# YiVad/.env.production         # pnpm build:pro 时加载
# YiVad/.env.test               # pnpm build:test 时加载
```

### 必须的前缀

所有自定义环境变量必须以 `RSBUILD_ENV_` 为前缀——这是 Rsbuild 的安全机制，防止意外暴露敏感变量：

```bash
# YiVad/.env
RSBUILD_ENV_API_URL=http://localhost:10086
RSBUILD_ENV_PORT=8848
RSBUILD_ENV_PUBLIC_PATH=/
RSBUILD_ENV_OPEN=false
RSBUILD_ENV_PROXY="[]"
RSBUILD_ENV_GLOB_APP_TITLE=YiVad
RSBUILD_ENV_ROUTER_MODE=hash
```

### 代码中使用

```typescript
// 编译时替换为字符串字面量
const apiUrl = process.env.RSBUILD_ENV_API_URL;
// 构建后: const apiUrl = "http://localhost:10086";

// ✗ 运行时访问 process.env 在生产构建中不可用
// ✗ 忘记前缀: process.env.API_URL → undefined
// ✗ 在非 Rsbuild 管理的代码中使用（如静态 JSON 文件）
```

### 添加新环境变量

```bash
# 1. .env 中添加
RSBUILD_ENV_NEW_FEATURE_FLAG=true
```

```typescript
// 2. src/typings/global.d.ts 中添加类型声明
declare namespace NodeJS {
  interface ProcessEnv {
    RSBUILD_ENV_NEW_FEATURE_FLAG?: string;
  }
}

// 3. 代码中使用
const isEnabled = process.env.RSBUILD_ENV_NEW_FEATURE_FLAG === 'true';
```

### 常见错误

| 错误 | 原因 | 修复 |
|------|------|------|
| 变量值为 `undefined` | 忘记 `RSBUILD_ENV_` 前缀 | 添加前缀 |
| 构建后变量为字符串 `"undefined"` | `.env` 文件未定义该变量 | 在所有 `.env.*` 文件中添加 |
| 端口冲突 | `RSBUILD_ENV_PORT` 未设置或冲突 | 检查 `lsof -i :8848` |
| 代理不生效 | `RSBUILD_ENV_PROXY` JSON 格式错误 | 验证 JSON：`echo $PROXY \| python3 -m json.tool` |

## YiPet — dotenv + 手动加载

### 配置文件

```bash
# YiPet/.env
API_BASE=http://localhost:10086
YIVAD_URL=http://localhost:8848
```

### 代码中使用

```typescript
// YiPet/src/api/client.ts
const API_BASE = process.env.API_BASE || 'http://localhost:10086';

// 构建时 Rsbuild define 替换为字符串字面量
```

### TypeScript 类型声明

```typescript
// YiPet/env.d.ts
declare namespace NodeJS {
  interface ProcessEnv {
    API_BASE?: string;
    YIVAD_URL?: string;
  }
}
```

## 跨项目变量关系

同一概念在不同项目中的变量名：

| 概念 | YiAi (config.yaml) | YiVad (.env) | YiPet (.env) |
|------|-------------------|-------------|-------------|
| 后端地址 | `server.host` + `server.port` | `RSBUILD_ENV_API_URL` | `API_BASE` |
| AI 模型 | `ollama.model` | — | — |
| 知识库路径 | `knowledge.base_path` | — | — |
| JWT 密钥 | `jwt.secret` | — | — |
| CORS 来源 | `cors.origins` | — | — |

## 安全原则

| 原则 | 实践 |
|------|------|
| 密钥不进仓库 | `.env` 文件加入 `.gitignore`；提供 `.env.example` 模板 |
| 生产密钥兜底 | 代码中为敏感配置提供无默认值——缺少时启动失败 |
| 区分开发/生产 | YiVad 用 `.env.development` / `.env.production` 隔离 |
| 前端不暴露密钥 | 只在前端环境变量中放非敏感配置（API 地址、应用标题等） |

## 快速诊断

```bash
# 检查当前生效的环境变量
# YiAi
python -c "from src.shared.config import settings; print(settings.model_dump())"

# YiVad
grep RSBUILD_ENV_ YiVad/.env

# YiPet
grep -v '^#' YiPet/.env | grep -v '^$'
```

## 反模式

| 反模式 | 正确做法 |
|---|---|
| 在代码中硬编码 URL 和端口 | 使用环境变量或配置文件 |
| 将 `.env` 提交到 Git | `.gitignore` 中包含 `.env`，提供 `.env.example` |
| YiVad 变量忘记 `RSBUILD_ENV_` 前缀 | 始终使用前缀——否则构建时不会替换 |
| 生产配置与开发配置混用 | 使用环境特定的配置文件 |
| 密钥写在 config.yaml 中并提交 | 使用环境变量覆盖 YAML 中的敏感字段 |
