# 性能优化指南

> 性能优化的第一原则：**先测量，再优化。** 没有测量数据的优化是猜测——你可能在优化一个根本不是瓶颈的地方。

## 优先优化什么

按用户感知影响排序：

| 优先级 | 优化方向 | 用户感知 |
|--------|---------|---------|
| 1 | 数据库查询 | 页面加载速度 |
| 2 | API 响应时间 | 操作反馈速度 |
| 3 | 前端渲染 | 交互流畅度 |
| 4 | 包体积 | 首次加载时间 |
| 5 | 内存使用 | 长时间运行稳定性 |

## Python（YiAi）优化

### 异步并发——同时查询多个集合

```python
# ✗ 串行——总耗时 = 查询1 + 查询2 + 查询3
projects = await db["projects"].find(filter1).to_list(100)
issues = await db["issues"].find(filter2).to_list(100)
bugs = await db["bugs"].find(filter3).to_list(100)

# ✓ 并发——总耗时 = max(查询1, 查询2, 查询3)
import asyncio
projects, issues, bugs = await asyncio.gather(
    db["projects"].find(filter1).to_list(100),
    db["issues"].find(filter2).to_list(100),
    db["bugs"].find(filter3).to_list(100),
)
```

异步并发可以将多个独立查询的响应时间从累加降为取最大值。

### 避免 N+1 查询

```python
# ✗ N+1 查询——每个 issue 单独查 project
issues = await db["issues"].find({"status": "active"}).to_list(None)
for issue in issues:
    issue["project"] = await db["projects"].find_one({"_id": issue["project_id"]})

# ✓ 先收集 ID，批量查询
project_ids = [i["project_id"] for i in issues]
projects = await db["projects"].find({"_id": {"$in": project_ids}}).to_list(None)
project_map = {p["_id"]: p for p in projects}
for issue in issues:
    issue["project"] = project_map.get(issue["project_id"])
```

### 限制返回数据量

```python
# ✗ 返回所有字段
result = await db["knowledge_files"].find({"status": "active"}).to_list(None)

# ✓ 只返回需要的字段
result = await db["knowledge_files"].find(
    {"status": "active"},
    {"title": 1, "tags": 1, "category": 1, "_id": 0}
).to_list(None)
```

投影可以显著减少网络传输和内存占用。只查询需要的字段，尤其是当文档较大时。

### LLM 调用优化

```python
# 控制 token 消耗
- 限制上下文长度: 只发送最近 N 条消息，而非完整历史
- 缓存常见响应: 相同 prompt 的响应可以缓存（如系统提示）
- 使用流式响应: 减少用户感知的等待时间
- 超时设置: 防止单次推理占用过长时间
```

## Vue（YiVad）优化

### 大列表虚拟滚动

当列表项超过 100 条时，考虑虚拟滚动而非全量渲染：

```vue
<!-- ✗ 1000 条全部渲染 -->
<div v-for="item in list" :key="item.id">{{ item.name }}</div>

<!-- ✓ 虚拟滚动（只渲染可见区域 + 缓冲区） -->
<!-- 使用 Element Plus 的 el-table-v2 或 vue-virtual-scroller -->
```

### 避免不必要的响应式

```typescript
// ✗ 大数据集标记为响应式（Vue 会为每个属性创建 Proxy）
const largeDataset = ref<Item[]>([...10000 items]);

// ✓ 不需要响应式的大数据集用 shallowRef
const largeDataset = shallowRef<Item[]>([...10000 items]);
// 更新时必须替换整个数组: largeDataset.value = newData
```

### 计算属性 vs 方法

```typescript
// ✗ 模板中调用方法——每次渲染都重新计算
// <div>{{ formatDate(item.date) }}</div>

// ✓ 使用计算属性——结果缓存
const formattedList = computed(() =>
  list.value.map(item => ({
    ...item,
    displayDate: formatDate(item.date),
  }))
);
```

### 组件懒加载

```typescript
// router 中使用动态 import 实现路由级代码分割
const routes = [
  {
    path: '/analytics',
    component: () => import('@/views/analytics/index.vue'),
  },
];
```

## MongoDB 优化

### 索引检查——是否有全表扫描

```javascript
// 在 mongosh 中分析慢查询
db.issues.find({ project_id: "p1", status: "active" }).explain("executionStats");

// 关注 winningPlan:
// IXSCAN (索引扫描) ✓
// COLLSCAN (全表扫描) ✗ → 需要建索引
```

### 常用查询建立索引

```javascript
// 按项目和状态过滤（最常用的查询模式）
db.issues.createIndex({ project_id: 1, status: 1 });

// 按时间排序（列表页默认排序）
db.sessions.createIndex({ updated_at: -1 });

// 文本搜索
db.knowledge_files.createIndex({ title: "text", tags: "text" });
```

### 聚合管道优化

```javascript
// 原则：$match 和 $limit 尽早执行，$lookup 和 $project 晚执行
db.issues.aggregate([
  { $match: { project_id: "p1" } },     // 1. 先用索引过滤
  { $sort: { created_at: -1 } },         // 2. 排序
  { $limit: 20 },                        // 3. 限制数量
  { $lookup: { from: "projects", ... } }, // 4. 最后关联
]);
```

## 性能监控

### 关键指标

| 指标 | 测量方式 | 目标 |
|------|---------|------|
| API 响应时间 (p95) | YiAi 访问日志 | < 500ms |
| 页面首次加载 | Chrome DevTools → Lighthouse | < 3s |
| MongoDB 查询时间 | `.explain("executionStats")` | < 100ms |
| Ollama 推理时间 | YiAi 日志 | < 30s（取决于 prompt 长度） |
| 构建时间 | `time pnpm build` | < 60s |

### 快速性能检查

```bash
# YiAi API 响应时间
time curl -s -X POST http://localhost:10086/ \
  -H "Content-Type: application/json" \

cd YiVad && time pnpm build:dev
```

## 反模式

| 反模式 | 正确做法 |
|---|---|
| 没有测量就优化 | 先用 profiling 工具找到真正的瓶颈 |
| 为所有字段建索引 | 索引有写入成本——只为查询条件建索引 |
| 在循环中 await（Python） | 使用 `asyncio.gather()` 并发执行 |
| 模板中调用方法（Vue） | 换成计算属性或提前处理好数据 |
| 不限制 MongoDB 返回字段 | 使用投影只返回需要的字段 |
