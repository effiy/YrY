## Day 1｜环境搭建与启动

**目标**：本地成功跑通 YiVad 项目

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 安装 Node.js 18+、pnpm 8+ | 30 min | 本地开发环境就绪 |
| ② | 克隆仓库 → `pnpm install` 安装依赖 | 45 min | 依赖安装无报错，`node_modules/` 正常生成 |
| ③ | 配置 `.env`（`RSBUILD_ENV_*` 前缀的 RPC 地址等）→ `pnpm dev` 启动 | 30 min | Rsbuild 编译成功，终端无红色报错 |
| ④ | 浏览器访问 `http://localhost:8848` 登录 + 浏览 Project / Bug 等主菜单 | 30 min | 截图 3 张（登录页、Project 列表、主菜单） |

**验收 Checklist**：
- [ ] `http://localhost:8848` 可访问，页面白屏时间 < 5s
- [ ] 登录流程走通（或 mock 登录），主页面菜单加载完整
- [ ] Project / Bug 任一列表页 ProTable 渲染成功
- [ ] 能向 Mentor 复述 YiVad 的 3 个核心功能

---

### Day 1 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| `RSBUILD_ENV_` 前缀变量未生效 | 读不到 `.env` 中 RPC 地址 | 所有自定义 env 必须以 `RSBUILD_ENV_` 开头，代码中用 `import.meta.env.RSBUILD_ENV_XXX` |
| pnpm install 失败 | 报 peerDependencies 冲突 | 升级 pnpm 到 8.x，或 `pnpm install --no-strict-peer-dependencies` |
| Rsbuild 编译报 vue-tsc 错误 | 启动阶段类型检查挂掉 | 先 `pnpm typecheck` 单独看错误，不要依赖 dev server 报错 |
| RPC 请求 404 / 跨域 | 后端接口调不通 | 确认 YiAi 10086 已启动，检查 `vite.config.ts` / `rsbuild.config.ts` 中 proxy 配置 |
| 动态路由白屏 | 登录后页面一片空白 | 打开 F12 Console，看 `useAuthStore` 中菜单数据是否为空，必要时先 mock 菜单 |

### Day 1 进一步学习路径
1. 通读 `package.json` 了解全部 scripts（dev / build / typecheck / lint 等）
2. 手动打开 F12 Network，观察一次 RPC 请求的 request/response 信封格式
3. 熟悉 Rsbuild DevTools，了解 HMR / 资源面板

## Day 2｜架构与核心概念

**目标**：读懂项目分层与核心模块

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|

| ③ | 追踪一个完整链路：点击 Project 菜单 → 动态路由匹配 → ProTable 发 RPC → YiAi 10086 → 渲染 | 90 min | 链路追踪图（手绘或 Mermaid） |
| ④ | 画出 YiVad 架构图（至少 3 层：视图层 / 状态层 / RPC 层 / 工具层） | 60 min | Mermaid 架构图 .md 片段 |

**验收 Checklist**：
- [ ] 能讲清 3 层以上分层（视图组件 / Pinia Store / RPC Client / Utils）
- [ ] 能讲清核心模块 3 个以上（ProTable、动态路由、权限体系）

- [ ] 能画出从用户点击菜单到表格渲染的完整链路

---

### Day 2 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| ProTable 4 组件搞不清楚 | 分不清哪个是 Search / ToolBar / Table / Pagination | 参考 `src/components/ProTable/` 下 README 或示例页 `src/views/example/protable/` |
| 动态路由注册顺序混乱 | 某些页面刷新后 404 | 查看 `src/router/guards.ts` 中 `addRoute` 逻辑，菜单数据必须在路由匹配前拉完 |
| Pinia Store 持久化失效 | 刷新后登录态丢失 | 检查 `pinia-plugin-persistedstate` 配置，确认 key / storage / paths 正确 |
| v-auth 指令不生效 | 按钮没权限却还显示 | 检查用户 roles / permissions 数据，确认指令从 `useAuthStore().permissions` 取值 |
| RPC filter 与 query 混淆 | 传了参数后端却读不到 | filter = 筛选条件（对象），query = 搜索关键字（字符串），严格区分 |

### Day 2 进一步学习路径
1. 深入阅读 `src/components/ProTable/` 下所有子组件源码
2. 理解 `src/api/` 下 RPC 客户端封装，尝试手写一个新的 request
3. 逐个阅读 `src/views/` 下的业务页面（Project / Bug / Menu 等）

## Day 3｜代码调试与单测

**目标**：独立 Debug 并跑通过现有测试

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 用 Vue DevTools / VSCode Debugger 断点调试 Project 列表 ProTable 渲染完整流程 | 90 min | 断点截图 + 变量观察记录 |
| ② | 执行 `pnpm typecheck` + `pnpm lint` + `pnpm test`（vitest）跑全量检查 | 60 min | 检查通过截图（typecheck 0 error / lint 0 warn / test 0 fail） |
| ③ | 改一个已有 bug（参考 `projects/yivad/bugs/`）或在核心路径加 1 条 `console.debug` / 日志 | 60 min | bugfix commit / 日志生效截图 |
| ④ | 跑一次 `pnpm build` 构建产物，确认无编译错误 | 30 min | `dist/` 目录生成成功截图 |

**验收 Checklist**：
- [ ] 断点成功进入 路由守卫 → Pinia Store → RPC → ProTable 渲染核心路径
- [ ] `vue-tsc` 类型检查 0 错误
- [ ] `eslint` 0 error 0 warning（或仅有 pre-existing）
- [ ] `pnpm build` 成功产出 `dist/`

---

### Day 3 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| vue-tsc 报类型错误但页面能跑 | 「能用但报红」 | 不要忽略，`vue-tsc` 错误 = 真实潜在 bug，优先修类型 |
| vitest 找不到组件 | 测试启动报 `Cannot find module` | 检查 `vitest.config.ts` 中 `alias` 与 `rsbuild.config.ts` 一致 |
| HMR 失效 | 改代码页面不刷新 | 先确认是否改了 `rsbuild.config.ts` / `.env`（需要重启 dev），否则清 `node_modules/.cache` |
| ESLint 规则和个人习惯冲突 | 大量格式报错 | 不要改 `.eslintrc`，按项目规则走，`pnpm lint:fix` 一键修 |
| ProTable 子组件无法断点 | 源码 map 不对 | 确认 `rsbuild.config.ts` 中 `sourcemap` 为 `true`，生产构建才会关 |

### Day 3 进一步学习路径
1. 学习 Vitest + @vue/test-utils 的组件测试写法，给一个简单组件补 2 条单测
2. 研究 Pinia 测试方法，为 auth store 写 1 条用例
3. 阅读 `scripts/` 下 CI 脚本，理解流水线怎么跑 typecheck / lint / test

## Day 4｜第一个小功能 / 修改

**目标**：独立完成 1 个可验证的小修改

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 从以下 3 个候选中挑 1 个：(a) 给 Project 页加一列表头筛选器 (b) 给 Bug 详情页改一个字段显示 (c) 改一个 ProTable Column（如加 formatter 或 tooltip） | 120 min | 本地可运行的功能代码 |
| ② | 为本次修改写一份 Dev 文档（含完整 frontmatter）放 `stories/` | 45 min | `stories/<你的修改>.md` |
| ③ | 本地跑 `pnpm typecheck` + `pnpm lint` + `pnpm test` + 手动页面验证 | 60 min | 验证截图 3 张以上 |
| ④ | 完成 Code Review Checklist 自检 | 15 min | checklist.md 勾选记录 |

**验收 Checklist**：
- [ ] 修改通过 `pnpm typecheck` 类型检查
- [ ] 修改通过 `pnpm lint` + `pnpm test`
- [ ] Dev 文档 frontmatter 完整（title/tags/category/created…）
- [ ] 已完成 Code Review Checklist 自检项全部勾选

---

### Day 4 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| ProTable Column 加筛选器不生效 | 表头点了没反应 | 不要只加 `filters`，还要配合 `onFilter` 或远程模式 `filterMode: 'remote'` 看文档 |
| Bug 详情页字段改了但显示没变化 | 仍然渲染旧值 | 检查 Pinia store 是否缓存了旧详情数据，清缓存或强制 `router.push` 重新拉取 |
| Dev 文档 frontmatter YAML 语法错误 | 知识扫描报错 | 用 yamllint 检查，冒号后空格、缩进 2 格，数组用 `- ` |
| 改了 Column 但 typecheck 报错 | ProTable column 类型不对 | 检查 `import type { ProColumnType }` 是否正确引入，不要用 any |
| 样式在 dev 正常 build 后错乱 | 生产构建样式丢失 | 检查是否使用了 scoped + ::v-deep 却没加正确前缀，确认 CSS Modules 命名 |

## Day 5｜PR 准备与跨项目

**目标**：提 PR + 跨项目协作

| 序号 | 任务内容 | 估计时间 | 交付物 |
|------|----------|----------|--------|
| ① | 用 Conventional Commits 写 commit message（格式：`<type>(<scope>): <subject>`） | 20 min | 符合规范的 git log |
| ② | 按照仓库 PR / MR 模板提交 PR | 40 min | PR 链接 1 个 |
| ③ | 关联 Issue + 关联至少 1 篇跨项目文档（如 YiAi 后端对应 Dev 或 YiKnowledge 中 PRD） | 40 min | PR 描述中含链接 |
| ④ | 准备 10 分钟 Demo（本地演示 + 架构说明）给 Mentor | 60 min | Demo 验收通过 |

**验收 Checklist**：
- [ ] PR 包含自检项勾选（Code Review Checklist）
- [ ] 关联项目知识文件 1 篇以上
- [ ] commit message 符合 Conventional Commits 规范
- [ ] Mentor 验收通过并在 PR 中 Comment / Approve

---

### Day 5 常见坑

| 坑位 | 现象 | 解决方式 |
|------|------|----------|
| commit message 不规范 | CI commitlint 校验挂掉 | 用 `git commit --amend` 修改，严格 `feat/fix/docs/test/refactor/chore` 前缀 |
| PR 模板字段没填全 | Reviewer 打回 | 仔细对照仓库 `PULL_REQUEST_TEMPLATE.md` 逐项勾选 |
| 跨项目文档链接 404 | 关联文档不存在 | 使用仓库内相对路径，不要硬编码 GitHub URL，合并到 main 再检查 |
| Demo 现场 RPC 不通 | 演示当天 YiAi 没启动 | 提前准备 mock 数据版本分支，或带好录制备份 |
| PR 包含 `dist/` / `.env` 等文件 | 把不该提交的文件 push 了 | 提交前 `git status` 检查，`.gitignore` 兜底，必要时 `git rm --cached` 移除 |

### Day 5 进一步学习路径
1. 完成 **2 周成长计划**：独立承担 1 个业务页面（如 Menu / Settings）从需求到上线
2. 完成 **1 月成长计划**：封装 1 个通用业务组件（带单测+文档），参与 ProTable v2 升级讨论
3. 尝试写一篇 `projects/yivad/stories/` 技术分享，沉淀 ProTable 踩坑经验
