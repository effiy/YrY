# 学习路径：竞品分析

> **状态**：草稿 —— 内容已规划，尚待完善。

## 目标受众

工程师、产品经理和高管——需要对竞争对手进行系统性的研究和分析，以指导产品策略和技术选型。

## 竞品分析四步法

### 第一步：识别相关竞品

不要只看直接竞品（功能直接对标的产品）。完整的竞品地图包括：

| 竞品类型 | 定义 | YrY 示例 |
|---|---|---|
| 直接竞品 | 功能直接对标、目标用户重叠 | 其他项目管理 SaaS（Linear、Jira、Notion） |
| 间接竞品 | 解决相同用户需求但方式不同 | 纯知识库工具（Obsidian Publish、GitBook） |
| 替代品 | 用户"目前是怎么做的" | Excel + 邮件管理项目、白板 + 便利贴 |
| 参考品 | 不同领域但有可借鉴的设计或模式 | AI 聊天产品的交互设计、Chrome 扩展的 UI 模式 |

### 第二步：调研方法

| 方法 | 适用场景 | 投入时间 | 产出 |
|---|---|---|---|
| 公开资料研究 | 了解竞品定位、功能、定价 | 2-4 小时 | 功能清单、定位分析 |
| 产品体验拆解 | 深入理解产品细节和交互 | 4-8 小时 | 功能矩阵、UX 分析 |
| 用户评价分析 | 了解竞品的优势和不足 | 2-4 小时 | 用户痛点和期望清单 |
| 专家访谈 | 获取行业深层洞察 | 1-2 周（含安排） | 战略级洞察 |

### 第三步：分析框架

| 框架 | 解决的问题 | 产出物 |
|---|---|---|
| 波特五力模型 | 行业竞争格局 | 行业吸引力评分 |
| 功能矩阵 | 竞品功能覆盖对比 | 功能差异表 |
| 商业模式对比 | 盈利模式和可持续性 | 收入结构分析 |
| SWOT 分析 | 竞品优势和劣势 | 战略定位图 |

### 第四步：归档到知识库

竞品分析的结果分为两部分归档：
- **战略层分析**：归档到 [executiver/industry/](../../../executiver/industry/)
- **功能层分析**：归档到 [producter/strategy/](../../../producter/strategy/)

每份竞品分析报告应包含：
1. 竞品概况（产品定位、目标用户、商业模式）
2. 功能对比矩阵
3. 优劣势分析
4. 对 YrY 产品的启示

## 适用场景速查

| 场景 | 推荐方法 | 投入时间 |
|---|---|---|
| 新项目立项前的市场调研 | 公开资料研究 + 产品体验拆解 | 1-2 天 |
| 季度竞品更新 | 公开资料研究 | 半天 |
| 特定功能对标 | 产品体验拆解 + 功能矩阵 | 半天 |
| 战略级竞争分析 | 全四步 | 1-2 周 |

## 常见错误

| 反模式 | 为什么有问题 | 正确做法 |
|---|---|---|
| 只看直接竞品 | 忽略了替代品和新兴竞争者 | 使用四类竞品分类法扩展视野 |
| 功能点对点对比 | 忽略了竞品的设计哲学和用户心智 | 先理解竞品"为什么这样设计"，再对比功能清单 |
| 一次调研后用一年 | 市场变化快，过时的信息导致错误决策 | 每季度做一次竞品更新，重大变化随时更新 |
| 调研只停留在"看"不用"用" | 公开资料的描述不等于真实体验 | 必须亲手使用竞品，体验完整的用户流程 |
