# 开发工作流指南

> 从启动全栈环境到高效调试的日常开发流程。目标是让你花最少时间在环境问题上，最多时间在业务代码上。

## 全栈启动

### 依赖检查

```bash
# 首次启动前确认
python3 --version    # >= 3.10
node --version       # >= 16.18.0
mongod --version     # 任意 6.x/7.x
ollama --version     # 可选，需要 AI 功能时需要
```

### 启动顺序

必须按此顺序启动——每个服务依赖前一个：

```bash
# 终端 1：MongoDB（如未运行为服务）
mongod --dbpath /usr/local/var/mongodb

# 终端 2：Ollama（如需 AI 功能）
ollama serve

# 终端 3：YiAi 后端
cd YiAi && python main.py
# → 输出: Uvicorn running on http://0.0.0.0:10086

# 终端 4：YiVad 前端
cd YiVad && pnpm dev
# → 输出: Rsbuild Dev Server running on http://localhost:8848

# 终端 5：YiPet 构建监听
cd YiPet && npm run dev  # 或 npm run build -- --watch
```

### 验证全栈连通性

```bash
# 1. YiAi 健康检查
curl http://localhost:10086/health
# → {"status": "healthy", "mongodb": "connected", "ollama": "connected"}

# 2. YiVad 页面可访问
open http://localhost:8848

# 3. RPC 协议可用
curl -X POST http://localhost:10086/ \
  -H "Content-Type: application/json" \
  -d '{"module_name":"services.database.data_service","method_name":"query_documents","parameters":{"cname":"projects","pageNum":1,"pageSize":1}}'
# → {"code": 0, "message": "ok", "data": {...}}
```

## 按项目开发

### 仅改 YiAi（后端）

```bash
cd YiAi
# uvicorn reload: true → 修改 Python 文件后自动重启
# 无需手动重启，等待终端输出 "Reloading..."
# 验证：curl http://localhost:10086/health
```

热重载范围：`src/` 目录下的所有 `.py` 文件。`config.yaml` 修改也触发重载。

### 仅改 YiVad（前端）

```bash
cd YiVad && pnpm dev
# Rsbuild HMR → 修改 Vue/TS/SCSS 文件后浏览器自动更新
# 状态保持：Pinia store 在 HMR 后保持（除非修改 store 文件本身）
# 类型检查（不阻塞 HMR）：pnpm type:check
```

### 仅改 YiPet（扩展）

```bash
cd YiPet
npm run build             # 完整构建
# 或
npm run dev               # watch 模式自动构建

# Chrome 中加载：
# chrome://extensions → 开启"开发者模式" → "加载已解压的扩展程序" → 选择 dist/
# 修改代码后：重新构建 → 在 chrome://extensions 点击刷新按钮
```

### 跨项目修改（最常见场景）

当修改涉及 YiAi + 一个或多个前端：

1. 启动全部服务（4 个终端）
2. 先在 YiAi 修改后端逻辑并验证（curl 或 Swagger UI）
3. 再修改前端调用代码
4. 浏览器中端到端验证
5. 检查 RPC 参数名是否与规范一致

## 开发环境热键

| 场景 | 操作 |
|------|------|
| YiAi 不响应 | 检查终端是否有报错 → `lsof -i :10086` 确认端口 |
| YiVad 白屏 | 检查浏览器控制台 → 确认 `RSBUILD_ENV_API_URL` 指向正确 |
| YiPet 不加载 | `chrome://extensions` → 检查错误 → 重新加载 |
| MongoDB 拒绝连接 | `brew services restart mongodb-community` |
| Ollama 模型不存在 | `ollama pull qwen2.5:3b`（或其他模型） |
| 端口冲突 | `lsof -i :<port>` 找到占用进程 → `kill <pid>` |

## 常见问题排查

### MongoDB 连接失败

```
症状：YiAi 输出 "MongoDB connection failed" 或超时
检查：mongosh --eval "db.runCommand({ping: 1})"
修复：brew services start mongodb-community
      或 mongod --dbpath /usr/local/var/mongodb
```

### Ollama 推理超时

```
症状：AI 聊天卡住，终端输出 timeout
检查：curl http://localhost:11434/api/tags  （列出已加载模型）
修复：ollama pull <model-name>  （如果模型未下载）
     或重启 Ollama：pkill ollama && ollama serve
```

### Python 模块导入错误

```
症状：ImportError: No module named 'xxx'
检查：pip list | grep <package>
修复：pip install -r requirements.txt
```

### 前端构建失败

```
症状：rsbuild 构建报错
检查：node --version（>= 16.18.0）
     pnpm --version（>= 8）
修复：pnpm install（重新安装依赖）
     rm -rf node_modules && pnpm install（清除重装）
```

### RPC 调用返回空数据但应该有数据

```
症状：query_documents 返回 total: 0，但数据库有数据
最常见原因：参数名用了 query 而不是 filter
检查：浏览器 Network 面板 → 请求 Payload → 确认参数名
修复：改为 filter
```

## 高效开发技巧

### 快速数据查询

```bash
# 直接在 MongoDB 中查数据
mongosh ruiyi --eval "db.projects.find({status: 'active'}).limit(3).pretty()"

# 通过 RPC 查询（用于验证 API）
curl -s -X POST http://localhost:10086/ \
  -H "Content-Type: application/json" \
  -d '{"module_name":"services.database.data_service","method_name":"query_documents","parameters":{"cname":"sessions","pageSize":3}}' \
  | python3 -m json.tool
```

### 只重启需要的服务

```bash
# YiAi 改了代码 → 通常自动 reload，如未生效：
# Ctrl+C 终止 → python main.py 重新启动

# YiVad HMR 通常自动生效，如未生效：
# 浏览器手动刷新（Cmd+R）
```

### 使用 Swagger UI

```
浏览器访问 http://localhost:10086/docs
→ 可交互的 API 文档，直接测试端点
→ 用于快速验证后端 API 行为
```

## 反模式

| 反模式 | 正确做法 |
|---|---|
| 不验证后端可用就改前端代码 | 先 `curl localhost:10086/health` 确认后端在线 |
| 同时改 3 个项目且不中间验证 | 每改完一个项目就验证，再改下一个 |
| 修改 Python 代码后不等待热重载 | 等终端输出 "Reloading..." 后再测试 |
| 前端 API 调用报错先怀疑后端 | 先检查 Network 面板确认请求 payload 参数名正确 |
| 全局 `pnpm install` 而非按项目安装 | 每个项目的依赖独立管理，分别 `cd` 进去装 |
