# Mentor 一对一指南

> **适用对象**：所有 Mentor（带新人的工程师/技术负责人）和所有 Mentee（新入职/新角色/新项目成员）。一对一不是状态更新会——是成长辅导和关系建设的专属时间。

---

## 30 / 60 / 90 天三阶段里程碑

| 阶段 | 核心目标 | Mentor 侧重 | 交付物 | 验收标准 |
|---|---|---|---|---|
| **第 1-30 天** | 融入环境、建立信任、跑通第一个闭环 | **倾听 + 消除障碍** | ① 环境搭建完成并跑通 Hello World；② 认识所有团队成员并完成 1:1 介绍；③ 领取第一个小型任务并提交 PR；④ 完成项目架构 1 页笔记 | ① 能独立启动本地开发环境（参考入职文档）；② 至少 3 份 PR 被合并；③ 能画出项目核心模块架构图；④ Mentor 和 Mentee 双向确认"已准备好承担独立任务 |
| **第 31-60 天** | 独立交付、建立节奏、识别成长方向 | **授能 + 提供反馈** | ① 独立承担 1 个完整功能模块的设计与开发；② 完成至少 2 次 Code Review 他人代码；③ 产出 1 份技术选型或设计文档；④ 明确 3 个月成长目标 | ① 按排期独立交付功能并通过测试；② Code Review 评论被采纳 ≥ 2 条；③ 设计文档通过评审；④ 成长目标书面化并纳入行动项跟踪 |
| **第 61-90 天** | 贡献影响力、建立网络、规划长期方向 | **授权 + 拓展视野** | ① 主导 1 次跨团队协作或技术分享；② 参与 1 次 ADR 决策或技术评审；③ 建立至少 2 个跨项目协作关系；④ 更新 6-12 个月职业发展规划 | ① 分享或协作产出可验证的成果；② ADR 或评审中有实质性贡献记录；③ 跨项目联系人 ≥ 2 位能叫出名字并合作过；④ 职业规划书面化，季度 OKR 对齐 |

### 三阶段节奏建议

| 周次 | 建议一对一频率 | 建议时长 | 重点议题 |
|---|---|---|---|
| 第 1-2 周 | **每周 2 次** | 45 分钟 | 环境搭建、人、流程、快速反馈 |
| 第 3-8 周 | **每周 1 次** | 30 分钟 | 任务进展、成长反馈、障碍消除 |
| 第 9-13 周 | **每双周 1 次** | 45 分钟 | 影响力拓展、职业规划、长期目标 |

## 30 个开放式问题清单

> 一对一的核心是提问而非告知。以下问题按四大维度组织，每次一对一挑选 3-5 个深入讨论，不必逐个问完。

### 维度一：成长与发展（1-8）

1. 如果未来三个月你最想掌握的一项技能是什么？为什么是它？
2. 你觉得自己目前最强的能力是什么？在什么场景下它被验证过？
3. 你觉得自己哪个能力如果提升 20%，会给你的产出带来最大变化？
4. 过去一个月，你做过的最有成就感的一件事是什么？
5. 在这家公司，你想成为什么样的人？一年后和三年后的画面是什么样？
6. 你觉得什么样的工作对你来说是"心流"状态？最近一次进入心流是什么时候？
7. 你希望在接下来的一个季度里，承担什么类型的新责任？
8. 如果给你自己过去一个月的表现打分（1-10），你打几分？为什么？那个缺失的分数在哪？

### 维度二：障碍与支持（9-16）

9. 当前工作中，什么事情占用了你最多的时间但产出最少？
10. 有没有什么事情，如果有人帮你清除了，你效率可以翻倍？
11. 在信息、资源、权限这三者中，你觉得哪一项最缺？具体缺什么？
12. 和其他同事协作时，有没有遇到什么摩擦或不顺畅的地方？
13. 最近一次感到沮丧或挫败是什么时候？发生了什么？
14. 你觉得团队的流程（开发/评审/发布）中，哪个环节最需要改善？
15. 有没有什么决定或方向，你觉得不够清晰？具体困惑在哪？
16. 如果明天有一个魔法棒可以改变团队的一件事，你会改变什么？

### 维度三：反馈与认知（17-24）

17. 过去一个月，你收到的最有价值的反馈是什么？它改变了你什么行为？
18. 你希望我（Mentor）在哪方面可以给你更多或更少的支持？
19. 你觉得我做的哪件事对你帮助最大？哪件事其实帮了倒忙？
20. 在团队中，你最佩服谁？为什么佩服他/她？
21. 你觉得别人怎么看你？和你自己认为的有什么不一样？
22. 有没有什么我应该知道但没问你的事？
23. 最近一次你想放弃或者想走是什么时候？是什么让你留下？
24. 如果一个新同事明天入职，你会给TA的三条建议是什么？

### 维度四：职业与意义（25-30）

25. 你工作的动力是什么？是好奇心、影响力、成长、还是别的？
26. 你觉得我们做的事情，对用户/对团队/对行业有意义吗？体现在哪？
27. 你理想中的工作环境是什么样的？我们目前差在哪？
28. 三年后你不想做现在这份工作，大概率是因为什么原因？
29. 除了本职工作，你有没有想探索什么方向？
30. 如果钱和意义，如果只能选一个，你现在选哪个？五年后呢？为什么？

## 行动项跟踪表

> **规则**：每次一对一结束时**必须**产出行动项，下次一对一首先回顾。行动项默认纳入本表。没有行动项的一对一是无效的。

| # | 行动项描述 | 负责人 | Mentor 类型 | 优先级 | 创建日期 | 截止日期 | 状态 | 完成日期 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | {{以动词开头，具体可执行}} | {{Mentee/Mentor/共同}} | 成长/障碍/反馈 | 高/中/低 | YYYY-MM-DD | YYYY-MM-DD | 未开始/进行中/已完成/已取消 | YYYY-MM-DD | {{上下文}} |
| 2 | 例：阅读 YiAi domain/auth 模块代码并产出 1 页架构笔记 | Mentee | 成长 | 高 | | | | | 下次一对一展示 |
| 3 | 例：安排与 @XX 做 YiPot 剪贴板模块的 30 分钟介绍 | Mentor | 障碍 | 中 | | | | | 本周内完成 |
| 4 | 例：Code Review 时给出更多正反馈前先说明预期 | Mentor | 反馈 | 中 | | | | | 持续 2 周后复盘 |

### 行动项的 SMART 原则

每条行动项必须满足：

- **S**pecific（具体）：不写"提升代码质量"，写"阅读 008-运行-CodeReview指南.md 并在下个 PR 中实践 3 条规则"
- **M**easurable（可衡量）：完成有明确的判断标准
- **A**chievable（可达成）：在截止日期前现实可完成
- **R**elevant（相关）：和成长目标或当前工作相关
- **T**ime-bound（有时限）：必须有截止日期

## 一对一的标准议程（推荐结构）

> 这是每次 30 分钟一对一的时间分配建议：

| 时间 | 环节 | 主导方 | 内容 |
|---|---|---|---|
| 0-3 分钟 | 破冰 + 回顾行动项 | Mentee 先讲 | 回顾上次行动项完成情况，未完成的讨论原因并调整 |
| 3-10 分钟 | Mentee 议程 | Mentee | Mentee 带来的 2-3 个话题（工作、成长、障碍） |
| 10-20 分钟 | Mentor 输入 + 反馈 | Mentor | Mentor 的观察、反馈、对成长建议 |
| 20-27 分钟 | 深度话题 | 双方 | 从 30 问中选 1-2 个深入聊 |
| 27-30 分钟 | 行动项 + 收尾 | 双方 | 写行动项、定下次时间、确认无遗漏 |

### 绝对禁忌

1. ❌ **不要变成状态更新会**：状态更新在站会或异步工具里做
2. ❌ **不要 Mentor 一个人说 25 分钟**：Mentor 说话占比 ≤ 40%，Mentee 占比 ≥ 60%
3. ❌ **不要跳过行动项回顾**：上次说的话不算数，下次没人当真
4. ❌ **不要取消或推迟一对一**：优先级等同于客户会议——除非真的紧急
5. ❌ **不要只有"最近怎么样？""挺好的。"的空话对话：永远追问具体事例

## 三阶段里程碑检查清单（供 Mentor 自查）

### 30 天检查（✅ 通过才能进入下一阶段）

- [ ] 本地开发环境能独立跑起来，跑过完整的 Hello World → 真实功能
- [ ] 和团队所有人有过至少 5 分钟单独对话
- [ ] 合并过 ≥ 3 个 PR，其中至少 1 个不是 typo 修复
- [ ] 能画出项目核心模块的架构草图（3 个模块以上）
- [ ] 明确知道找谁问什么问题（不只是找 Mentor 一个人）
- [ ] Mentee 敢在公开场合（站会/评审）发过一次言

### 60 天检查

- [ ] 独立完成过 ≥ 1 个功能从需求到上线的完整闭环
- [ ] Code Review 过别人的代码，评论被采纳
- [ ] 写过 ≥ 1 份设计文档或技术选型说明
- [ ] 有书面的 3 个月具体成长目标（不是"提升技术"这种空话）
- [ ] Mentee 主动发起过 ≥ 1 次一对一议程

### 90 天检查

- [ ] 在团队或跨团队做过 ≥ 1 次分享或主导协作
- [ ] 参与过 ≥ 1 次技术评审并有实质性发言
- [ ] 有 ≥ 2 个跨项目的协作关系（不是只和 Mentor 说话）
- [ ] 有书面的 6-12 个月职业规划，和 Mentor 对齐过
- [ ] Mentee 对下季度想承担的新责任有明确的想法

## 常见问题 FAQ

**Q: Mentee 很内向，一对一总是说"没什么想聊的"怎么办？**
A: 不要问开放式的"最近怎么样？"，从 30 问里挑具体的问题，比如"上周你合并的那个 PR，你觉得最有挑战的部分是什么？"，从具体事件切入。也可以让 Mentee 提前 24 小时准备议程，邮件或文档都行。

**Q: Mentor 和 Mentee 职级相同（平级带教）怎么办？**
A: 平级带教的核心是"经验差"而非"职级差"。提前对齐：Mentor 负责分享经验、提供反馈、连接资源；不负责绩效评估。反馈的开场可以说"我分享下我踩过的坑，你挑有用的听"。

**Q: 90 天后还需要继续一对一吗？**
A: 当然需要，但形式可以变。90 天后转为常规的每双周成长对话，焦点从"融入"转向"持续成长和影响力建设"。推荐每季度有一次 60 分钟的深度成长复盘。
