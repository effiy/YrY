# 安全数据迁移

> **适用时机**：任何 Schema 变更、数据转换或集合重构。数据迁移是风险最高的操作——一个错误可能导致数据损坏或丢失。

## 迁移安全五原则

| 原则 | 含义 | YrY 示例 |
|---|---|---|
| **向后兼容** | 旧代码能读新数据，新代码能读旧数据 | 添加字段时给默认值，不改变已有字段的类型 |
| **可回滚** | 每次迁移都有经过测试的回滚方案 | 迁移前备份集合，保留旧字段直到验证期结束 |
| **在副本上测试** | 在类生产数据上测试，再接触生产 | 使用 `mongodump` 备份恢复到测试库 |
| **有监控** | 跟踪进度、错误和性能影响 | 打印迁移进度百分比、错误收集、耗时记录 |
| **增量执行** | 小批次操作，避免锁整个集合 | 批次大小 100-500，使用 `batch_size` |

## 四阶段迁移流程

### 阶段一：准备

#### 1.1 备份数据

```bash
# MongoDB 备份
mongodump --uri="mongodb://localhost:27017/ruiyi" --out=/backup/$(date +%Y%m%d)

# 验证备份
mongorestore --dry-run --dir=/backup/20260910/ruiyi
```

#### 1.2 在副本上测试

```python
# 恢复备份到测试数据库 → 执行迁移脚本 → 验证数据完整性
# 确认无误后再接触生产数据
```

#### 1.3 编写迁移脚本

```python
# YiAi 数据迁移模式
import asyncio
from data.database import MongoDB

async def migrate_sessions_add_status_field():
    """为所有没有 status 字段的会话添加默认值。"""
    db = MongoDB.get_db()
    collection = db["sessions"]

    # 统计待迁移文档数
    total = await collection.count_documents({"status": {"$exists": False}})
    print(f"待迁移文档数: {total}")

    if total == 0:
        print("无数据需要迁移。")
        return

    # 批次大小 100，避免内存占用过大
    batch_size = 100
    migrated = 0

    cursor = collection.find({"status": {"$exists": False}}).batch_size(batch_size)

    async for doc in cursor:
        await collection.update_one(
            {"_id": doc["_id"]},
            {"$set": {"status": "active" if doc.get("messages") else "empty"}}
        )
        migrated += 1
        if migrated % batch_size == 0:
            print(f"已迁移 {migrated}/{total}（{migrated*100//total}%）")

    print(f"迁移完成: 共更新 {migrated} 条文档。")

# 运行: python -m scripts.migrate_sessions
```

### 阶段二：执行迁移

#### 2.1 在低流量窗口执行

YiAi 的迁移安排在低流量时段（开发环境：任何时间；生产环境：周末或深夜）。

#### 2.2 实时监控

```python
import time

start = time.time()
# ... 迁移循环 ...
elapsed = time.time() - start
print(f"迁移完成 耗时 {elapsed:.1f} 秒（{migrated/elapsed:.1f} 条/秒）")
```

#### 2.3 错误收集

```python
errors = []
try:
    await collection.update_one(...)
except Exception as e:
    errors.append({"doc_id": doc["_id"], "error": str(e)})

if errors:
    print(f"错误: {len(errors)} 条文档迁移失败:")
    for err in errors[:10]:  # 显示前 10 条
        print(f"  {err['doc_id']}: {err['error']}")
```

### 阶段三：验证

#### 3.1 计数检查

```python
total = await collection.count_documents({})
migrated = await collection.count_documents({"status": {"$exists": True}})
unmigrated = total - migrated

assert unmigrated == 0, f"{unmigrated} 条文档未迁移！"
print(f"全部 {total} 条文档迁移成功。")
```

#### 3.2 抽样检查

```python
import random

sample = await collection.aggregate([
    {"$match": {"status": {"$exists": True}}},
    {"$sample": {"size": 10}}
]).to_list(10)

for doc in sample:
    assert "status" in doc
    assert doc["status"] in ("active", "empty", "archived")
    print(f"  ✓ {doc.get('key', doc['_id'])}: status={doc['status']}")
```

### 阶段四：清理

#### 4.1 验证期后删除旧字段

迁移后至少等待 **1 周**再删除旧字段——留出足够时间发现和修复问题。

```python
# 稳定运行 1 周后
await collection.update_many(
    {"old_field": {"$exists": True}},
    {"$unset": {"old_field": ""}}
)
```

#### 4.2 记录迁移日志

```markdown
| 日期 | 迁移内容 | 集合 | 文档数 | 耗时 | 已回滚？ |
|---|---|---|---|---|---|
| 2026-09-10 | 为 sessions 添加 status 字段 | sessions | 1,234 | 45s | 否 |
```

## 回滚策略

### 迁移前

```python
# 保存迁移前状态
backup = await collection.find({"status": {"$exists": False}}).to_list(None)
# 如果迁移失败，从备份恢复
```

### 迁移中

如果错误率超过阈值（如 > 1%），中止迁移并回滚：

```python
if len(errors) / total > 0.01:
    print(f"错误: {len(errors)/total*100:.1f}% 失败率。正在回滚。")
    # 从备份恢复
    return
```

## MongoDB 专项注意事项

| 注意事项 | 建议 |
|---|---|
| 大集合（> 100K 文档） | 使用批次处理（每批 100-500 文档） |
| 索引字段 | 在迁移前创建索引，而非迁移中 |
| Write Concern | 生产迁移使用 `w: "majority"` |
| Read Concern | 使用 `readConcern: "majority"` 避免脏读 |
| Oplog 压力 | 迁移期间监控 oplog 窗口，防止 oplog 溢出 |

## 适用场景

| 场景 | 迁移类型 | 特殊考虑 |
|---|---|---|
| 添加新字段 | 非破坏性，定义默认值即可 | 最简单的迁移，回滚只需删除新字段 |
| 修改字段类型 | 破坏性，需要两阶段迁移 | 先添加新字段（新类型）→ 验证期 → 删除旧字段 |
| 拆分集合 | 破坏性，需要数据复制 | 先创建新集合 → 复制数据到新集合 → 验证期 → 删除旧集合 |
| 删除数据 | 不可逆，必须双重确认 | 先标记（soft delete）→ 验证期（至少 30 天）→ 物理删除 |

## 反模式

| 反模式 | 为什么失败 | 正确做法 |
|---|---|---|
| 不备份就迁移 | 数据丢失不可逆 | 迁移前始终备份 |
| 在 1M+ 文档上一次性迁移 | 锁整个集合；阻塞写入 | 按 100-500 文档批次处理 |
| 没有验证步骤 | 迁移"成功"但数据错误 | 验证计数、抽样检查、检查不变量 |
| 立即删除旧字段 | 后续发现问题无法回滚 | 等待至少 1 周再删除旧字段 |
