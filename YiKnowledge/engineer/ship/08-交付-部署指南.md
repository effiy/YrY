# 部署指南

> 每个 YrY 项目的生产部署步骤和检查清单。所有部署都应该是可重复、可验证、可回滚的。

## 部署前检查清单（所有项目通用）

- [ ] 所有 CI 门禁通过（lint、类型检查、测试、安全审计）
- [ ] `main`/`master` 分支代码已通过 Code Review
- [ ] 数据库迁移脚本已准备并在副本上验证
- [ ] 环境变量和密钥已配置（不在代码仓库中）
- [ ] 回滚方案已确认（上一个可工作版本已知）
- [ ] 依赖审计通过（`pip-audit` / `npm audit` 无高危漏洞）
- [ ] 通知相关方（团队频道发布部署公告）

## YiAi（FastAPI 后端）部署

### 方式一：直接部署（开发/小型生产）

```bash
# 1. 拉取最新代码
cd /opt/YrY && git pull origin main

# 2. 安装/更新依赖
cd YiAi && pip install -r requirements.txt

# 3. 运行数据迁移（如有）
python -m scripts.migrate_xxx

# 4. 重启服务
# 如果使用 systemd
sudo systemctl restart yiai

# 如果手动启动
pkill -f "uvicorn src.app:app"
nohup uvicorn src.app:app --host 0.0.0.0 --port 10086 --workers 4 &

# 5. 健康检查
curl http://localhost:10086/health
# 期望: {"status": "healthy", "mongodb": "connected"}
```

### 方式二：Docker 部署（推荐）

```dockerfile
# YiAi/Dockerfile
FROM python:3.12-slim

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY src/ src/
COPY config.yaml .

EXPOSE 10086
CMD ["uvicorn", "src.app:app", "--host", "0.0.0.0", "--port", "10086", "--workers", "4"]
```

```bash
# 构建和启动
docker build -t yiai:latest .
docker run -d --name yiai \
  -p 10086:10086 \
  -v /opt/YrY/YiKnowledge:/app/../YiKnowledge:ro \
  --restart unless-stopped \
  yiai:latest
```

### uvicorn 生产参数建议

| 参数 | 建议值 | 说明 |
|------|--------|------|
| `--workers` | `4` | CPU 核心数 × 1-2 |
| `--limit-concurrency` | `1000` | 最大并发连接数 |
| `--limit-max-requests` | `10000` | 每个 worker 处理 N 个请求后重启（防内存泄漏） |
| `--timeout-keep-alive` | `5` | Keep-alive 超时（秒） |

### 健康检查端点

```bash
# 基础健康检查
curl http://localhost:10086/health
# → {"status": "healthy", "mongodb": "connected", "ollama": "connected"}

# Observer 健康检查（含更多细节）
curl http://localhost:10086/health/observer
```

### 回滚

```bash
# 回滚到上一个可工作的 git tag
git checkout v1.2.0
sudo systemctl restart yiai
# 或重新构建 Docker 镜像
docker build -t yiai:v1.2.0 . && docker stop yiai && docker run ... yiai:v1.2.0
```

## YiVad（Vue 前端）部署

### 构建

```bash
cd YiVad

# 安装依赖（使用 lockfile 保证可重现）
pnpm install --frozen-lockfile

# 类型检查
pnpm type:check

# 生产构建
pnpm build:pro
# 产物在 dist/ 目录
```

### 方式一：静态文件托管（推荐）

```bash
# 将 dist/ 上传到 OSS 或 CDN
# 阿里云 OSS 示例:
ossutil cp -r dist/ oss://yivad-static/ --meta "Cache-Control:max-age=86400"

# 例外：index.html 不缓存
ossutil cp dist/index.html oss://yivad-static/index.html --meta "Cache-Control:no-cache"
```

### 方式二：Nginx 反向代理

```nginx
server {
    listen 80;
    server_name yivad.example.com;

    root /opt/YrY/YiVad/dist;
    index index.html;

    # SPA 路由——所有路径回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # API 代理到 YiAi
    location /api/ {
        proxy_pass http://localhost:10086/;
        proxy_set_header Host $host;
    }
}
```

### 部署后验证

```bash
# 1. 检查 index.html 可访问
curl -s https://yivad.example.com/ | head -5

# 2. 检查 JS/CSS 资源加载（200 状态码）
curl -s -o /dev/null -w "%{http_code}" https://yivad.example.com/assets/js/app-xxxx.js
# 期望: 200

# 3. 检查 API 连通性
curl -X POST https://yivad.example.com/api/ \
  -H "Content-Type: application/json" \
  -d '{"module_name":"services.database.data_service","method_name":"query_documents","parameters":{"cname":"projects","pageSize":1}}'
# 期望: {"code":0,...}
```

### 回滚

```bash
# OSS: 重新上传上一个版本的 dist/
ossutil cp -r oss://yivad-static-backup/v1.2.0/ oss://yivad-static/

# Nginx: 切换到上一个版本的 dist 目录
ln -sfn /opt/releases/yivad-v1.2.0 /opt/YrY/YiVad/dist
```

## YiPet（Chrome 扩展）部署

### 构建

```bash
cd YiPet

# 生产构建
npm run build
# 产物在 dist/ 目录

# 验证构建产物完整性
ls dist/manifest.json dist/popup/ dist/chat/ dist/cdn/ dist/bootstrap/
```

### 发布到 Chrome Web Store

```bash
# 1. 打包为 zip
cd dist && zip -r ../yipet-$(node -p "require('../package.json').version").zip . && cd ..

# 2. 上传到 Chrome Web Store 开发者控制台
# https://chrome.google.com/webstore/devconsole

# 3. 更新商店页面描述、截图和版本说明
```

### 发布前检查

- [ ] Manifest 版本号已递增
- [ ] 权限声明最小化（仅声明实际使用的权限）
- [ ] CSP 配置正确（`script-src 'self'`）
- [ ] 所有 CDN vendor 在 catalog 中注册
- [ ] 在 Chrome 扩展管理页面测试加载 `dist/` 目录无错误
- [ ] 所有 API 端点指向生产环境 YiAi（非 localhost）

### 回滚

Chrome Web Store 不支持自动回滚——在开发者控制台手动发布上一个版本的包。

## 环境对比

| 配置项 | 开发环境 | 生产环境 |
|--------|---------|---------|
| YiAi 端口 | `10086` | `10086` |
| YiVad 端口 | `8848` | Nginx → 静态文件 |
| YiPet API 基址 | `http://localhost:10086` | `https://api.your-domain.com` |
| MongoDB | `localhost:27017` | 生产 MongoDB 实例 |
| CORS | `origins: ["*"]` | 限制为具体域名 |
| Auth | 默认关闭 | 建议开启 |
| uvicorn workers | 1（reload 模式） | 4（生产模式） |
| Ollama | 本地 | 本地或云 API |

## 反模式

| 反模式 | 正确做法 |
|---|---|
| 在开发服务器上直接 `git pull && pnpm dev` | 走完整的构建 → 部署流程 |
| 部署前不运行数据迁移 | 先迁移数据，再部署新代码 |
| 没有回滚方案就部署 | 记录上一个可工作的版本号或 git tag |
| 生产环境使用 `["*"]` CORS | 限制为具体域名 |
| 跳过部署后验证 | 用 curl 验证关键端点可用 |
