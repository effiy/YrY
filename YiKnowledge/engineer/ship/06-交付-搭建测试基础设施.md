# 搭建测试基础设施

> **适用时机**：当 YrY 项目目前没有测试，或现有测试套件不可靠时。测试基础设施是所有质量工作的基石。

## YrY 测试现状

| 项目 | 框架 | 状态 | 测试数 | 覆盖率 |
|---|---|---|---|---|
| YiAi | pytest 8 + pytest-asyncio + httpx | 活跃 | 76+ | shared/ 模块 92%+ |
| YiVad | Vitest | 无测试 | 0 | 0% |
| YiPet | Vitest 2 + jsdom 29 | 活跃 | 97 | 有限（config/ + shared/） |

### 测试优先级评估

| 项目 | 最需要测试的模块 | 原因 |
|---|---|---|
| YiAi (shared/) | 已完成 | 工具函数和错误处理是纯函数，测试成本低、收益高 |
| YiAi (services/) | services/database/data_service.py | RPC 数据操作是核心路径，参数名错误会导致静默 Bug |
| YiVad | api/modules/ 下的 RPC 请求封装 | 验证请求形状（`filter`/`target_file` 参数）和响应处理 |
| YiPet | api/services/ 下的领域服务 | SessionService 和 DatabaseService 的过滤参数验证 |

## YiAi —— pytest 配置

### 配置文件

```toml
# pyproject.toml
[tool.pytest.ini_options]
pythonpath = ["src"]
testpaths = ["tests"]
addopts = "-v --cov=src --cov-report=term-missing --cov-report=html"
markers = [
    "slow: 慢速测试（使用 '-m \"not slow\"' 排除）",
    "integration: 需要运行中服务的集成测试",
]
```

### 测试目录结构

```
YiAi/tests/
├── conftest.py           # 共享 fixtures
├── test_utils.py         # 纯函数测试（token 估算、文本清洗）
├── test_error_codes.py   # 错误码枚举测试
├── test_response.py      # 响应包装器测试
├── test_exceptions.py    # 异常测试
├── test_config.py        # 配置加载测试
└── test_integration/     # 集成测试（需要 YiAi 运行）
    ├── test_repository.py
    └── test_api.py
```

### 关键测试模式

#### 纯函数测试

```python
# tests/test_utils.py
from shared.utils import estimateTokens, cleanText

def test_estimate_tokens_english():
    """英文文本的 token 估算：按空格分词。"""
    assert estimateTokens("Hello world") == 2

def test_estimate_tokens_chinese():
    """中文文本的 token 估算：每个字符约 1 个 token。"""
    assert estimateTokens("你好世界") == 4

def test_estimate_tokens_mixed():
    """中英文混合文本。"""
    assert estimateTokens("Hello 你好") == 3

def test_clean_text_strips_whitespace():
    """清理前后空格。"""
    assert cleanText("  hello  ") == "hello"

def test_clean_text_empty_string():
    """空字符串应返回空字符串。"""
    assert cleanText("") == ""
```

#### 错误码测试

```python
# tests/test_error_codes.py
from shared.error_codes import ErrorCode

def test_error_code_values_are_unique():
    """错误码的值必须唯一。"""
    values = [e.value for e in ErrorCode]
    assert len(values) == len(set(values))

def test_success_code_is_zero():
    """成功码必须为 0。"""
    assert ErrorCode.SUCCESS.value == 0
```

#### 异步测试

```python
# tests/test_repository.py
import pytest
from data.repository import query_documents

@pytest.mark.asyncio
async def test_query_documents_with_filter():
    """查询带过滤条件的文档。"""
    result = await query_documents("test", filter={"status": "active"})
    assert "list" in result
    assert "total" in result

@pytest.mark.integration
@pytest.mark.asyncio
async def test_query_documents_integration():
    """集成测试：需要 MongoDB 运行。"""
    result = await query_documents("sessions", pageSize=5)
    assert result["total"] >= 0
```

## YiPet —— Vitest 配置

### 配置文件

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';
import path from 'path';

export default defineConfig({
  resolve: {
    alias: { '@': path.resolve(__dirname, 'src') },
  },
  test: {
    environment: 'jsdom',
    include: ['tests/**/*.test.ts'],
  },
});
```

### 关键测试模式

```typescript
// tests/config/data.test.ts
import { describe, it, expect } from 'vitest';
import { DEFAULTS } from '@/config/defaults';

describe('DEFAULTS', () => {
  it('应该有一个有效的模型配置', () => {
    expect(DEFAULTS.MODEL).toBe('qwen3.5');
  });

  it('每个颜色选项应该有 value、label 和 gradient 字段', () => {
    DEFAULTS.COLORS.forEach(color => {
      expect(color).toMatchObject({
        value: expect.any(String),
        label: expect.any(String),
        gradient: expect.any(String),
      });
    });
  });

  it('皮肤颜色不应该有重复的 value', () => {
    const values = DEFAULTS.COLORS.map(c => c.value);
    expect(new Set(values).size).toBe(values.length);
  });
});
```

## CI 集成

```yaml
# .github/workflows/test.yml（示例）
name: Test
on: [push, pull_request]
jobs:
  test-yiai:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: '3.12' }
      - run: pip install -r requirements.txt
      - run: cd YiAi && python -m pytest tests/ -v --cov=src

  test-yipet:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '22' }
      - run: cd YiPet && npm ci && npm test
```

## 覆盖率阈值（目标）

| 级别 | 阈值 | 何时适用 |
|---|---|---|
| 最低 | > 0% | 第一个测试添加后 |
| 基础 | > 50% | 核心工具函数已覆盖 |
| 良好 | > 80% | 主要路径已覆盖 |
| 优秀 | > 90% | 边界情况已覆盖 |

**YiAi 目标**：shared/ 90%+，services/ 70%+
**YiPet 目标**：config/、shared/、utils/ 80%+
**YiVad 目标**：先从 > 0% 开始

## 测试策略：优先测试什么

遵循"测试金字塔"原则，从底向上构建：

| 层级 | 类型 | 数量 | 速度 | 可靠性 | YrY 示例 |
|---|---|---|---|---|---|
| 底层 | 单元测试 | 大量 | 毫秒级 | 最高 | 测试 `estimateTokens()`、`cleanText()` |
| 中层 | 服务/集成测试 | 适量 | 秒级 | 高 | 测试 `data_service.query_documents()` |
| 顶层 | 端到端测试 | 少量 | 分钟级 | 最低 | 测试完整 RPC 请求-响应流程 |

## 适用场景

| 场景 | 推荐测试类型 | 优先级 |
|---|---|---|
| 新工具函数 | 单元测试（纯函数最容易测试） | 高——函数写完立即测试 |
| 修改 API 端点 | 集成测试（验证请求-响应形状） | 高——防止 RPC 参数名回归 |
| 新 UI 组件 | 组件测试（快照 + 交互） | 中——视觉变更频繁时可延后 |
| 跨项目 RPC 变更 | 契约测试（前端请求形状 vs 后端期望） | 高——这是最常见 Bug 的源头 |

## 反模式

| 反模式 | 为什么失败 | 正确做法 |
|---|---|---|
| 只测试 Happy Path | 边界情况在生产中引发 Bug | 每个函数至少添加 1 个错误场景和 1 个边界场景 |
| 无 CI 集成 | 测试腐烂；没人本地运行 | 在 CI 中添加测试步骤；破坏测试的 PR 阻止合并 |
| 追求 100% 覆盖率 | 测试变得脆弱；测试实现细节而非行为 | 目标 80% 覆盖；关注行为而非实现 |
| 慢测试在主测试套件中 | CI 耗时 20+ 分钟；团队不再等待 | 拆分快速单元测试（< 5s）和慢速集成测试；每次 push 只跑快速测试 |
