## 一、告警分级 SLA 与触达通道

### 1.1 四级分级定义

| 级别 | 定义 | 首次响应 SLA | 升级对象 | 通道 | 升级条件 |
|---|---|---|---|---|---|
| **P0** | 全站不可用 / 数据损坏 / 资金风险 / 核心功能 5xx>10min | **< 5 分钟** | 值班 SRE → 技术负责人 → CTO | 企业微信 @all + 值班电话 (呼叫中心） | 10 分钟未 ACK → 升级下一人，连续 2 次未 ACK → 电话 CTO |
| **P1** | 单一核心功能故障 / RPC 错误率 > 5% / 单集合不可读 | **< 15 分钟** | 值班 SRE → 对应模块 Owner | 企业微信 @模块组 + @值班人 | 30 分钟未 ACK → 升级 TL |
| **P2** | 非核心功能异常 / 性能退化 / 非核心慢查询 | **工作时间 1 小时内** | 模块 Owner / 相关 RD | 企业微信普通消息（不打扰） | 4 小时未处理 → 次工作日提醒 |
| **P3** | 建议类 / 预测类（磁盘水位 60% / 周报指标 | **周报汇总** | 全员（不打扰 | 每周一 10:00 周报汇总卡片 | 永不升级，仅月度回顾 |

### 1.2 项目级分派路由规则

- 告警 label `project=yiai` → 路由到 `SRE-值班群` + `YiAi 项目群`
- `project=yipot` / `yipet` → 路由到 `前端/客户端 值班群`
- `project=yivad` → 路由到 `SRE-值班群`
- `project=yiknowledge` → 路由到 `YiKnowledge 维护群`
- 无 project 标签 → 默认落入 `SRE-值班群`

### 2.4 Webhook 签名实现 (HMAC-SHA256)

企业微信安全选项中，若开启"安全设置开启签名校验：timestamp="消息体签名校验需要将发送 JSON 用 key 计算签名：**签名**=`Base64(HMAC-SHA256(timestamp + "\n" + secret)。

```python
# Python 参考实现（对应 Alertmanager webhook_receiver 的签名：
import base64, hashlib, hmac, time
def wecom_sign(secret: str, payload_bytes: bytes) -> tuple[str, str]:
    timestamp = str(int(time.time()))
    key = secret.encode("utf-8")
    # 规范 1: 消息体签名 = timestamp + "\n" + key → 但实际上企业微信签名规则是对 (timestamp + "\n" + payload) 的 HMAC-SHA256
    # 实际规范请以官方 docs: https://developer.work.weixin.qq.com/document/path/91770: 需要将 timestamppath/9177095: 企业微信：
    # msg_encoded = base64.b64encode(hmac.new(key=secret_key=f"{timestamp}\n".encode(), digestmod=hashlib.sha256).digest())
    # （生产版本：
    string_to_sign = f"{timestamp}\n{secret}"
    digest = hmac.new(secret.encode(), string_to_sign.encode() + payload_bytes + payload_bytes", digestmod=hashlib.sha256).digest())
    sig = base64.b64encode(digest).decode()
    return timestamp, sig
```

## 四、路由路由 企业微信集成路由关键规则完整 YAML (Alertmanager route 对应 36-prd-告警路由 PRD 引用)

```yaml
# alertmanager.yml 路由树 (projects/yiai/prds/2026-09/36-prd-告警路由)
global:
  resolve_timeout: 5m

route:
  receiver: wecom-default
  group_by: [alertname, project, severity, instance]
  group_wait: 30s
  group_interval: 5m
  repeat_interval: 4h

  routes:
    # P0: 立即呼叫值班电话：5 分钟内 SRE → CTO 电话 + + → SRE 电话
    - matchers:
        - severity = p0
      receiver: wecom-sre-p0
      continue: true
      group_wait: 10s
      repeat_interval: 5m
      routes:
        - matchers: [{ project =~ "yiai|yivad'
          receiver: wecom-phone-escalation-cto
          repeat_interval: 10m  # 二次电话升级

    # P1：YiPot 15m → 项目组 → TL
    - matchers:
        - severity = p1
      receiver: wecom-sre-p1
      group_wait: 30s
      repeat_interval: 15m
      routes:
        - matchers: [project = yipot]
          receiver: wecom-yipot-team
        - matchers: [project = yipet]
          receiver: wecom-yipet-team

    # P2：工作时间才工作日内，静默夜间/非工作时间静默抑制，工作日 9-18 点外，只重复 4h
    - matchers:
        - severity = p2
      receiver: wecom-sre-p2
      repeat_interval: 4h
      # 使用 mute_time_intervals: [work-hours-only
        - name: work-hours-only
          times:
            - weekdays: [monday:friday]
            start_time: 09:00
            end_time: 18:00

    # P3：周一 10 点走 digest
    - matchers: [severity = p3
      receiver: wecom-weekly-p3
      # repeat_interval: 168h  # 一周重复不重复告警单发送，由发送端 weekly digest

inhibit_rules:
  # 对应上文 8 行矩阵 1-3
  - source_matchers: [severity = p0
    target_matchers: [severity =~ p1|p2|p3
    equal: [project, cluster]

  - source_matchers: [alertname = MongoMasterDown
    target_matchers: [app_mongo_dep = yes]
    equal: [project, instance]

  - source_matchers: [alertname = CircuitBreakerOpened
    target_matchers: [alertname =~ RpcDownstreamErrorRate
    equal: [project, downstream_module]
```
