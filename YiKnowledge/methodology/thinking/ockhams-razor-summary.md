# 奥卡姆剃刀（Occam's Razor）

## 1. 模型定义

14 世纪 William of Ockham 提出：**如无必要，勿增实体**（Entities should not be multiplied without necessity）。

直白说：解释同一现象，假设最少的版本胜出。

## 2. 适用场景

- 多个假设都能解释现象时
- 调试根因、A/B 异常归因
- 系统设计选型（避免过度设计）
- 决策时优先简单方案
- 学术与日常判断

## 3. 使用步骤

1. **列出所有候选解释**
2. **数每个解释所需假设**
3. **优先考虑假设最少的解释**
4. **不要锁死**：剃刀是工具不是铁律；证据能推翻简单假设时，复杂假设胜出
5. **持续验证**：用证据不断调整

## 4. 案例

### 服务异常归因

- 解释 A：网络抖动
- 解释 B：上游服务部署
- 解释 C：分布式系统中复杂竞态
- 解释 D：宇宙射线 bit flip

奥卡姆剃刀：先看 A 与 B（单假设），排除后才考虑 C；不看证据就上 D 是反智。

### 产品数据下跌

- 解释 A：新版本回归
- 解释 B：外部节假日
- 解释 C：复杂用户行为变化
- 解释 D：算法黑盒

按剃刀先查 A 与 B，证据不支撑再上 C / D。

### 系统设计

- 简单方案：一个队列 + worker
- 复杂方案：分布式调度 + 多级队列 + 优先级
- 剃刀：流量未到瓶颈前先用简单方案

## 5. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 简化到失真 | 复杂真相被简化掉 | 剃刀是工具不是结论 |
| 不看证据强行简化 | "应该是简单的" | 必须验证假设 |
| 反剃刀 | "既然简单的不对，一定复杂" | 复杂也需证据 |
| 当铁律用 | 拒绝复杂真相 | 剃刀只是先验偏好 |

## 6. 反例：何时不该用

- 现象本质就复杂（量子物理、生物系统）
- 简单假设已被证伪
- 复杂假设有强证据支撑

## 7. 关联思维模型

- 第一性原理：拆基础事实，避免冗余假设（与奥卡姆一致）
- 反向思考：先把不必要的剔除
- 二阶思维：复杂问题的二级后果
- Strong Opinions, Loosely Held：简单假设为起点，证据推翻时换

## 8. 工程中的"KISS / YAGNI"原则

- KISS（Keep It Simple, Stupid）：奥卡姆在工程上的体现
- YAGNI（You Aren't Gonna Need It）：不为未来可能的需求做设计

工程实践中：

- 不预先抽象（Three similar lines 优于 early abstraction）
- 不为假想需求加配置
- 不为不可能场景加 fallback

## 9. 落地要点

- 决策记录写"为什么选简单方案"
- 复杂方案出现时要求强证据
- 调试时先看简单假设再上复杂
- 系统设计有意识避免过度工程
