# 反向思考（Inversion）

## 1. 模型定义

反向思考：与其问"如何达成目标"，不如问"如何确保失败"。把要避免的列出，反向构造行动原则。

源于斯多葛学派（Seneca、Marcus Aurelius）与 Stoic negative visualization，被 Charlie Munger 推广："告诉我我会死在哪里，我就不去那里"——Jacobi 的"始终反过来想"（invert, always invert）。

## 2. 适用场景

- 目标模糊或风险高，正面思考无从下手
- 决策有强不对称损失（错了损失大）
- 长期项目，避免慢性死亡
- 团队陷入"积极讨论"却不行动

## 3. 使用步骤

1. **明确目标**：要达成什么？
2. **反向问**：要怎么才能失败？
3. **列失败路径**：穷举失败可能（注意力 / 资源 / 协作 / 时间）
4. **倒置为行动原则**：失败路径的反面 = 行动清单
5. **设计护栏**：把失败路径设为红线，触线即停

## 4. 案例

### 项目成功

- 反向：项目失败的可能
  - 需求不清晰
  - 关键人员流失
  - 工期估算过乐观
  - 上游依赖延期
  - 没有验收标准
- 行动原则：
  - 需求评审通过才开发
  - 关键人员备份
  - 工期加 1.5x buffer
  - 上游契约明确 SLA
  - 验收标准写在 PRD

### 个人成长

- 反向：如何确保 5 年后还是平庸
  - 不读书
  - 不复盘
  - 不维护人脉
  - 拒绝承担新责任
- 行动原则：每天读、每周复盘、月度联系旧同事、季度主动接活

### YiAi BRD 上线

- 反向：BRD 生成系统上线失败的可能
  - 幻觉率高于 20%，客户投诉
  - 多语言术语漂移
  - 推理服务超时
  - 用户不会用
- 行动原则：faithfulness 监控 + 术语表锁定 + 推理服务隔离 + 用户引导

## 5. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 只反向不正向 | 知道不要什么，不知要什么 | 正反结合 |
| 列了失败不改 | 反向思考变成仪式 | 每条失败转行动 |
| 失败路径太笼统 | "管理不好" | 拆到可观察的动作 |
| 一次列完不再更新 | 新失败模式未发现 | 季度复审 |

## 6. 与其他思维模型关系

- 第一性原理（正向拆基础事实）↔ 反向思考（反向避免失败）：互补
- 二阶思维：反向想"长期后果"，二阶推演"二级效应"
- Pre-mortem：反向思考的应用形式（假设已失败，倒推根因）

## 7. Pre-mortem 流程（反向思考的应用）

1. 假设项目已经失败（6 个月后）
2. 团队每人写下失败原因（5 分钟）
3. 合并汇总，按频率与影响排序
4. 优先处理 top 3 风险
5. 季度复审，更新风险列表
