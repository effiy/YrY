# OKR 设计指南

## 1. 框架来源

Objectives and Key Results，Andy Grove 在 Intel 提出，John Doerr 在 Google 推广（1999）。核心命题：**目标（O）激发动力，关键结果（KR）可衡量。**

- O = qualitative, aspirational, time-bound
- KR = quantitative, measurable, verifiable

## 2. 核心原则

| 原则 | 含义 |
|---|---|
| 鼓舞 | O 不是 KPI，要激发团队 |
| 可衡 | KR 必须有数字 |
| 限制数 | 3-5 O，每 O 3-5 KR |
| 透明 | 全公司可见，互相查看 |
| 不绑绩效奖金 | OKR 完不成不影响薪资，否则失激励 |
| Stretch | KR 应有挑战，70% 完成即优秀 |
| 双向 | 公司→部门→个人，自上而下 + 自下而上 |

## 3. 实施步骤

### 季度节奏

| 时点 | 事项 |
|---|---|
| 季前 2 周 | 公司 O 起草 |
| 季前 1 周 | 部门 / 个人 OKR 拉通对齐 |
| 季初 | OKR 锁定并公开 |
| 季中（4-6 周） | Mid-quarter check，进度 0-100% 标注 |
| 季末 | 自评 + 同行评议 |
| 季后 | 复盘，定下季方向 |

### O 写作规范

```
✅ "建立行业内最可信的 BRD 生成能力"
✅ "让客户在 10 分钟内拿到可发版的 BRD"
❌ "提升 BRD 质量"（无方向）
❌ "完成 BRD v2 项目"（描述动作，不是目标）
```

### KR 写作规范

```
✅ "BRD 首稿生成时长 P50 ≤ 3 分钟"
✅ "客户首次接受率 ≥ 70%"
✅ "多语言术语一致性（人工抽检）≥ 95%"
❌ "大幅提升生成速度"
❌ "BRD 模块完成度 100%"（KR 是结果不是动作）
```

### 自评打分

- 1.0 = 完全达成
- 0.7 = 良好（标准 stretch 目标）
- 0.5 = 部分达成
- 0.3 = 显著不足
- 0.0 = 未开始

目标：平均分 0.6-0.7；长期 0.9+ 说明目标太保守。

## 4. 输入 / 输出工件

- 输入：公司战略、上季度复盘、用户反馈
- 输出：OKR 文档（每团队一份），公开可查
- 模板：[OKR 模板](../../resources/templates/okr-template.md)（待补）

## 5. 适用场景与边界

**适用**：

- 中大型团队需要方向对齐
- 探索型工作（创新、试错）
- 远期目标与近期任务脱节

**不适用**：

- 强执行型工作（运营、运维）
- 强合规要求（医疗、金融）的 KPI 部分
- 早期小团队（5 人以内，直接口头对齐）

## 6. 与其他框架对比

| 框架 | 性质 | 适合 |
|---|---|---|
| OKR | 拉伸 + 自主 | 中大型、创新 |
| KPI | 必达 + 绩效 | 强执行、合规 |
| North Star | 单一聚焦 | 全公司对齐 |
| SMART | 任务级 | 个人目标设定 |

OKR 与 KPI 不互斥：OKR 管创新与拓展，KPI 管底线与合规。

## 7. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| KR 全是动作完成度 | "完成 BRD 项目 100%" | 改成结果指标 |
| 100% 完成才算成功 | KR 太保守不敢 stretch | 设 stretch，0.7 即优秀 |
| 绑绩效奖金 | 拉伸精神消失 | 与奖金解绑 |
| 不公开 | 跨团队无法对齐 | 全员可查 |
| 季初定后不再看 | 季中调整缺位 | Mid-quarter check |
| KR 太多 | 每 O 7-8 个 KR | 3-5 个上限 |
| 季度孤岛 | 不复盘不迭代 | 季末必复盘，写下季方向 |

## 8. 本团队落地案例

- 团队规模够大后引入，按季度设 O（产品方向）+ KR（关键结果）
- Mid-quarter check 在每月第一周
- 与个人发展计划（IDP）分离：OKR 看团队结果，IDP 看个人成长
