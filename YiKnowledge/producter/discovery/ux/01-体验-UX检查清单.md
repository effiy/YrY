# UX 设计模式与检查清单

> **适用场景**：在任何面向用户的版本发布之前。可用性检查清单应用于每个功能；无障碍检查清单应用于每次发布；视觉设计检查清单应用于每次 UI 变更。

## 为什么需要 UX 检查清单

UX 问题是产品发布后最常见的用户投诉来源。这些问题往往不难修复——难在"没人注意到"。一份结构化的检查清单能将"依赖个人经验"变成"系统化验证"，确保每次发布都达到一致的 UX 质量标准。

三个清单的使用节奏：
- **功能级（每个用户故事完成时）**：运行可用性检查清单
- **发布级（每次版本发布前）**：运行全部三项清单
- **紧急修复级**：至少运行可用性清单中的反馈和表单部分

## 一、可用性检查清单

### 导航

- [ ] 用户能否在首页 3 次点击内完成主要任务？如果某个高频操作需要 5 步，考虑添加快捷入口
- [ ] 当前位置是否清晰标识（面包屑导航、当前菜单高亮）？用户在任何页面都应能回答"我现在在哪"
- [ ] 用户能否回退？返回按钮的行为是否可预测？浏览器返回和页面内返回行为一致
- [ ] 搜索功能是否在每个页面都可见可访问？搜索是用户的"逃生舱"——找不到想要的就去搜索

**为什么重要**：用户对产品的第一印象来自导航。糟糕的导航等于把用户困在迷宫里——就算每个房间都装修精美，用户也会因为找不到出口而离开。

### 反馈

- [ ] 每个操作是否产生即时反馈（加载指示器、Toast 提示、按钮状态变化）？操作无反馈是最常见的"产品像坏了"的原因
- [ ] 超过 500 毫秒的操作是否显示加载状态？人是即时反馈的动物——超过半秒的等待需要视觉确认"系统在工作"
- [ ] 错误信息是否具体且可行动？"连接被拒绝"应翻译为"无法连接到 YiAi 服务。请检查服务是否在端口 10086 上运行。"
- [ ] 成功状态是否确认（绿色对勾、成功 Toast）？成功也需要反馈——没有反馈的保存会让用户反复检查"到底保存了没"

### 表单

- [ ] 必填字段是否用 `*` 标记？不要在用户提交后才告诉 ta 什么没填
- [ ] 校验是否实时（而非仅在提交时）？字段失焦时即校验，避免用户填完一整页后被 5 个红色错误同时轰炸
- [ ] 错误信息是否紧邻出错字段？错误信息浮在页面顶部的模态框里 = 用户需要滚动查找哪里出错了
- [ ] 用户能否在提交前撤消或取消操作？"提交"按钮旁边应该有"取消"或"返回"

### 内容

- [ ] 最重要的信息是否不需要滚动即可看到？（首屏信息密度）
- [ ] 空状态是否有帮助性引导？不是"暂无项目"，而是"暂无项目。创建第一个项目，或从 Demo 开始体验。"
- [ ] 破坏性操作是否受确认对话框保护？删除、清空、不可逆的编辑都需要二次确认

## 二、无障碍检查清单

### 键盘操作

- [ ] 所有可交互元素可通过 Tab 键访问。测试方法：只用键盘（不用鼠标）完成主要操作流程
- [ ] 焦点顺序合理（从左到右、从上到下）。Tab 顺序应与视觉布局一致，不应跳到意外位置
- [ ] 焦点状态可见（可见的轮廓或高亮环）。`outline: none` 是键盘用户的噩梦
- [ ] Esc 关闭模态框、下拉菜单和弹出框。这是用户的"逃生键"——任何时候按下 Esc 都应能退出当前模态
- [ ] Enter/Space 激活按钮和链接。Enter 提交表单，Space 切换复选框

### 屏幕阅读器

- [ ] 所有图片有 `alt` 文字（装饰性图片使用 `aria-hidden`）。功能性图片（图标按钮）的 alt 文本描述功能，而非外观
- [ ] 表单输入框有关联的 `<label>` 元素。`placeholder` 不是 label 的替代品——placeholder 在用户开始输入后就消失了
- [ ] 动态内容变化被播报（`aria-live` 区域）。Toast 通知、加载完成、新消息到达都需要被屏幕阅读器感知
- [ ] 页面有合理的标题层级（h1 → h2 → h3）。不跳级、不把 h1 当样式用。标题层级是屏幕阅读器用户的"目录"

### 视觉

- [ ] 普通文本颜色对比度 ≥ 4.5:1。使用 Chrome DevTools 的 Accessibility 面板检查
- [ ] 信息不只依赖颜色传达（配合图标或文字）。红色边框不能是唯一表示"错误"的方式——色盲用户看不到红色
- [ ] 文本可放大到 200% 不破坏布局。测试方法：浏览器缩放至 200%，检查是否出现水平滚动条或内容截断
- [ ] 尊重 `prefers-reduced-motion` 设置。动效过多的用户应在系统中减少动画

## 三、视觉设计检查清单

### 一致性

- [ ] 间距遵循设计系统（4px/8px 网格）。随意间距积累导致页面看起来"不专业"
- [ ] 排版一致（每页最多 2-3 种字号）。过多的字号变化是设计缺乏系统化的信号
- [ ] 颜色来自设计系统调色板（不使用一次性硬编码色值）。`#f5a623` 在代码中出现 1 次是设计决策，出现 20 次是灾难
- [ ] 图标来自同一图标库（YiVad/YiPet 使用 Ant Design Icons）。混用图标库导致视觉风格不统一

### 响应式

- [ ] 布局在 320px（小手机）到 2560px（大桌面显示器）之间都正常工作
- [ ] 任何支持宽度下都不出现水平滚动条
- [ ] 触控目标 ≥ 44×44px（WCAG 最小标准）。在移动设备上，小于 44px 的按钮极易误触

### YiVad 专属检查

- [ ] ProTable 列响应式适配（小屏幕隐藏低优先级列）。使用 Ant Design 的 `responsive` 属性在 `columns` 中定义断点行为
- [ ] 动态路由面包屑导航正确。测试：在深层页面刷新，面包屑应保持完整
- [ ] 权限控制下隐藏的元素不留空白。`v-auth` 隐藏的按钮不应在布局中留下空洞

### YiPet 专属检查

- [ ] 聊天窗口不超出视口。测试：在 1366x768 笔记本分辨率下，聊天窗口不应超过屏幕高度
- [ ] 弹窗在 Chrome 扩展最小弹出窗口尺寸下可用（宽度约 400px）
- [ ] Content script 注入不破坏宿主页面布局。测试：在常用网站（百度、掘金、GitHub）注入后页面样式无异常
- [ ] 深色模式在弹窗和聊天窗口都生效。测试：在 Chrome 深色主题下，YiPet 应有对应的深色主题

## YrY UX 模式规范

### 加载状态模式

| 模式 | YiVad 实现 | YiPet 实现 |
|---|---|---|
| 页面加载 | ProTable skeleton 骨架屏 | 加载会话列表时显示 Spin |
| 操作进行中 | 按钮 loading 状态 + 禁用重复点击 | 发送按钮禁用 + 旋转动画 |
| AI 流式响应 | 流式文本逐字显示 | 阶段指示器（思考中 → 检索中 → 流式输出中） |
| 空状态 | "暂无数据" + CTA 按钮引导创建 | "暂无会话" + 快速开始提示 |

### 错误状态模式

| 错误类型 | 用户看到的信息 | 用户可执行的操作 |
|---|---|---|
| YiAi 不可达 | "无法连接到服务器。请检查 YiAi 是否在端口 10086 上运行。" | 重试按钮 |
| 网络超时 | "请求超时。请检查您的网络连接。" | 重试按钮 |
| 权限不足 | "您没有访问此页面的权限。" | 返回首页按钮 |
| 表单校验错误 | 字段级红色错误提示（紧邻出错字段） | 修正字段内容 |

### 确认对话框规范

适用于：删除、破坏性编辑、不可逆操作。

设计原则：确认的难度应与后果的严重性成正比。

```
┌─────────────────────────────────────┐
│ ⚠️ 删除项目"SHOP"？                 │
│                                     │
│ 此操作将删除该项目及其所有问题、     │
│ 周期和版本记录。此操作不可撤消。     │
│                                     │
│ 请输入"SHOP"以确认删除：             │
│ [_______________]                   │
│                                     │
│ [取消]              [删除项目]      │
└─────────────────────────────────────┘
```

**使用规则**：
- 确认按钮上使用红色/危险色。按钮文本使用动词（"删除"）而非通用词（"确定"）
- 删除操作要求输入名称确认。对于不可恢复的操作，防止误点击
- 取消按钮始终可用。不给用户"无路可退"的感觉

## 反模式

| 反模式 | 为什么失败 | 修正方法 |
|---|---|---|
| "暂无数据"空状态无引导 CTA | 用户不知道该做什么，离开产品 | 始终包含引导操作："创建你的第一个 X"或"从 Demo 开始" |
| 静默失败（点击无任何反应） | 用户以为产品坏了，反复点击或放弃 | 每个操作产生反馈：成功、失败或加载中。零反馈 = 零信任 |
| 技术错误信息直接暴露给用户 | "ECONNREFUSED 127.0.0.1:10086" 对大多数用户没有意义 | 翻译为用户语言："无法连接到 YiAi 服务。请检查服务是否正在运行。" |
| 模态框打开后焦点管理缺失 | 键盘焦点停留在模态框后面，屏幕阅读器用户被"困住" | 模态框打开时焦点移入模态框内第一个可交互元素；关闭时焦点回到触发元素 |
| 仅用颜色区分状态 | 色盲用户看不到红色错误提示和绿色成功提示的区别 | 颜色 + 图标 + 文字三重传达重要状态信息 |
