# 北极星指标 — 定义与追踪

> **适用场景**：当一个产品需要统一的成功衡量标准时。北极星指标让产品、工程、设计、业务团队朝同一方向努力——它回答"我们做的一切到底是为了什么"。

## 什么是北极星指标

北极星指标（North Star Metric，简称 NSM）是**唯一一个**最能捕捉产品为用户创造的核心价值的指标。它不是收入指标（收入是结果，不是原因）——而是衡量能驱动商业结果的用户行为。

| 是北极星指标 | 不是北极星指标 |
|---|---|
| 日活跃用户数 | 收入（滞后指标）|
| 每天发送的消息数 | 利润率（财务指标）|
| 每周处理的文件数 | 股价（资本市场指标）|
| 每次会话完成的任务数 | 页面浏览量（虚荣指标）|

**为什么只需要一个？** 当团队有两个以上"最重要"的指标时，遇到冲突无法决策。"提高留存"和"提高收入"矛盾时怎么办？单一北极星指标消除了这种矛盾。

## 北极星指标的四项标准

一个好的北极星指标必须满足：

1. **可测量**：能用现有数据追踪。如果需要新建数据采集系统，先评估成本
2. **可行动**：产品团队的能力可以影响它。如果指标主要由市场因素驱动，产品团队无能为力
3. **可理解**：团队中的任何人都能解释这个指标的含义。如果 CEO 和实习生对指标的理解不同，说明定义不够清晰
4. **领先**：预测商业结果，而非仅仅汇报已经发生的结果。北极星指标动，收入跟着动——而不是反过来

## 如何定义北极星指标

### 第一步：一句话描述产品的核心价值

"我们的产品帮助 {{用户}} 实现 {{成果}}。"

| 项目 | 核心价值陈述 |
|---|---|
| **YiVad** | "YiVad 帮助管理员高效管理项目和知识。" |
| **YiAi** | "YiAi 帮助开发者通过统一 API 接入 AI 能力。" |
| **YiPet** | "YiPet 帮助用户在任何网页浏览时获得 AI 辅助。" |

### 第二步：识别最能体现这个价值的用户行为

什么用户行为最能表明他们正在获得价值？

| 产品 | 候选用户行为 | 为什么能体现价值 |
|---|---|---|
| YiVad | 每周活跃管理的项目数 | 项目被活跃管理 = 管理员正在获取价值 |
| YiAi | 每日完成的聊天请求数 | 聊天请求完成 = AI 正在服务用户 |
| YiPet | 每日有知识底座的聊天会话数 | 知识底座的会话 = AI 回答基于真实的 YrY 知识，而非通用答案 |

### 第三步：精确化定义

好的指标定义必须消除歧义。每个人都必须能用同一句话精确描述这个指标。

**示例（YiVad 北极星指标定义）**：
> "每周活跃管理项目数"是指：在最近 7 天内，至少有 1 次问题更新（issue update）或周期变更（cycle change）的项目数量。

这个定义明确了：
- 时间窗口：最近 7 天（滚动窗口，不是自然周）
- 计数方式：去重后的项目数
- 活跃的门槛：至少 1 次操作（issue update 或 cycle change）
- 数据来源：projects 集合，按 `updated_at` 字段筛选

### 第四步：用数据验证

在正式选择北极星指标之前，验证以下问题：

- [ ] **现在能测量吗？** 如果不能，需要什么埋点？成本多高？
- [ ] **与留存相关吗？** 北极星指标高的用户，留存率是否更好？
- [ ] **与商业结果相关吗？** 如果是商业产品，北极星指标高的用户是否更倾向于付费？
- [ ] **难以作弊吗？** 是否能被机器脚本或垃圾行为膨胀？

## 输入指标（撬动北极星的杠杆）

北极星指标是目的地，输入指标是你拉动它前进的杠杆。

| 北极星指标 | 输入指标 |
|---|---|
| YiVad：每周活跃管理项目数 | 每周新建项目数、项目一周留存率、每项目平均问题数、Demo 到正式项目转化率 |
| YiAi：每日完成聊天请求数 | API 正常运行时间、平均响应时间、聊天成功率、模型加载成功率 |
| YiPet：每日有知识底座的聊天会话数 | 知识树覆盖率、RAG 索引新鲜度、范围选择率、附带引用的回答占比 |

## YiVad 北极星指标详细案例

**北极星指标**：每周活跃管理项目数

**精确定义**：在最近 7 天滚动窗口内，至少有 1 次问题更新（issue 状态/指派人变更）或周期变更的项目数量。去重计数。

**当前基准值**：{{N}} 个项目/周（从 `projects` 集合统计，筛选 `updated_at` 在过去 7 天内的去重项目数）

**目标**：6 个月内翻倍

**输入指标监控**：
1. 每周新建项目数 — 从 `projects` 集合统计新创建的文档
2. 项目首周存活率 — 创建后第 7 天仍有活动的项目占比（剔除试了试就走的用户）
3. 每项目平均问题数 — 更多的问题 = 更深的参与度
4. Demo 到正式项目转化率 — 有多少用户从试用 Demo 转变为管理真实项目

## 实践建议

1. **先有数据再定指标**：在定义北极星指标之前，花一周时间探查现有数据。了解你能测量什么，再决定测量什么
2. **指标定义写到 README 级别**：每个人都能复述北极星指标的定义。如果定义只在 PM 脑子里，团队对齐就是幻觉
3. **每周回顾北极星指标的趋势**：在站会或周报中展示，让团队持续感知"我们做的是否在推动核心指标"
4. **警惕指标腐化**：随着产品演化，北极星指标可能需要调整。每季度审视一次：这个指标还能代表产品的核心价值吗？

## 反模式

| 反模式 | 为什么失败 | 正确做法 |
|---|---|---|
| 用收入作为北极星指标 | 收入是滞后指标；产品改动不能直接影响收入。如果收入不动，团队不知道是产品问题还是市场问题 | 使用能驱动收入的用户行为指标。收入是你期望的结果，不是你要优化的输入 |
| 设置多个北极星指标 | "3 个北极星指标" = 没有北极星指标。团队遇到冲突时无法决策 | 选择唯一一个指标。其他所有指标降级为输入指标或辅助指标 |
| 虚荣指标当北极星 | "页面浏览量"容易膨胀（加个弹窗就能涨），但无关于用户价值 | 选择与用户价值和留存强相关的指标。问自己：如果这个指标涨了但用户都没留住，有意义吗？ |
| 没有基准值就开始 | 不知道起点在哪里，也就不知道是否在进步 | 至少收集 4 周数据确定基准值，再设定目标。无基准的 KPI 本质上是在掷骰子 |
| 全团队不知道北极星是什么 | 每个人朝不同方向努力；"成功"有 N 种不同定义 | 北极星指标必须在站会上可见、在周报中追踪、在新人入职时作为产品基础知识介绍 |

## 产品健康仪表盘设计

北极星指标是你最重要的指标——但它不是唯一的指标。产品健康仪表盘将北极星指标及其关键输入指标组织为一页可读的面板，让团队在 30 秒内了解产品健康状况。

### 仪表盘的核心指标（不超过 10 个）

| 类别 | 指标 | 为什么在仪表盘上 | 更新频率 |
|---|---|---|---|
| **北极星** | 每周活跃管理项目数 | 唯一的目标指标 | 周度 |
| **获客** | 周新建项目数 | 北极星指标的前置输入——没有新项目流入，活跃项目数最终会枯竭 | 周度 |
| **激活** | 新建项目首周活跃率 | 新项目是否在"活"——创建了但不用的项目不是真正的获客 | 周度 |
| **留存** | 项目 4 周留存率 | 核心健康信号——项目来了之后是否持续被管理 | 周度 |
| **参与** | 每项目平均问题数 | 活跃深度——项目活跃但只有 1 个问题 vs 有 8 个问题，参与度完全不同 | 周度 |
| **质量** | Bug 修复率 | 如果产品质量在下降，北极星指标的提升可能是虚假的——用户在用但越来越不满 | 周度 |
| **系统** | API 可用率 | 如果系统不可用，所有其他指标都没有意义 | 日度 |

### 告警阈值设置

每个指标设定"警告"和"危险"两条线：

| 指标 | 警告线 | 危险线 | 触发后动作 |
|---|---|---|---|
| 周活跃项目数 | 连续 2 周下降 | 连续 3 周下降或单周下降 ≥ 20% | 危险：立即排查——是获客少了还是留存崩了？ |
| 新建项目首周活跃率 | < 40% | < 25% | 警告：检查新用户引导是否有变更。危险：暂停新功能开发，先修激活 |
| 项目 4 周留存率 | < 50% | < 30% | 危险：产品没有持续价值。回到发现阶段 |
| API 可用率 | < 99% | < 97% | 危险：立即通知 YiAi 团队排查 |

### 仪表盘的使用节奏

| 频率 | 谁看 | 做什么 |
|---|---|---|
| 每日 | PM + 技术负责人 | 扫一眼系统健康指标（API 可用率）。只在有告警时深入 |
| 每周 | 全团队 | 站会上展示北极星指标趋势 + 任意一个告警指标。讨论：我们这周做的事在推动这些指标吗？ |
| 月度 | PM + 干系人 | 月度战略同步中展示完整仪表盘。讨论趋势、意外变化、需要决策的取舍 |
| 季度 | 全员 + 高管 | 季度回顾中展示。讨论：北极星指标是否需要调整？告警阈值是否仍然合理？ |

### 仪表盘维护

- **指标不超过 10 个**：如果觉得需要加第 11 个，先删一个不重要的。仪表盘的目的是聚焦——15 个指标的仪表盘等于没有仪表盘
- **每个指标有一个负责人**：指标异常时，团队知道找谁。北极星指标由 PM 负责，系统指标由技术负责人负责
- **仪表盘是活文档**：每季度审视一次——有没有不再重要的指标？有没有应该加入的新指标？

### YrY 数据采集现状与建议

| 指标 | 当前可否测量 | 如不可，需要什么 |
|---|---|---|
| 周活跃项目数 | 可——`projects` 集合统计 `updated_at` | — |
| 新建项目首周活跃率 | 可——追踪新建项目 7 天内的活跃行为 | 需要定义"活跃"的精确规则 |
| Bug 修复率 | 可——`bugs` 集合统计状态变更 | — |
| 知识底座会话占比 | 可——`sessions` 集合标记 | 需要确保会话标记字段一致 |
| API 可用率 | 部分可——服务日志分析 | 需要建立健康检查端点和自动化监控 |
| 新用户首周引导完成率 | 不可 | 需要在引导流程中加入事件埋点 |
