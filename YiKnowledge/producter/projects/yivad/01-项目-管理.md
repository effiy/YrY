# YiVad 项目管理

> **作为**产品经理/工程师，**我想要**了解 YiVad 项目管理上下文，**以便**协调跨项目工作并理解当前交付节奏。

## 项目定位

YiVad 是 YrY 仓库的 Vue 3.5 管理后台——基于 Rsbuild 构建的 SPA（单页应用），核心价值主张是"动态路由驱动的数据管理和 AI 辅助工作台"。关键特性：
- ProTable 驱动的数据管理（统一表格模式的增删改查）
- 动态路由 + 按钮级权限控制（`v-auth` 指令）
- aiChat（AI 聊天）和 Agent 模式
- 知识库 + RAG 功能前端
- 文件管理和 Bug 追踪

## 产品愿景

让管理员通过统一的界面高效管理项目、知识和 AI 能力——从数据 CRUD 到 AI 辅助决策，一个平台完成所有管理任务。YiVad 不是"另一个后台管理系统"，而是"越来越了解你项目的 AI 工作台"。

## 关键架构决策

| 决策 | 内容 | 原因 |
|---|---|---|
| ProTable 作为规范表格模式 | 所有数据表格使用 ProTable，禁止直接使用 `el-table` | 统一表格交互：分页、筛选、排序、列配置一致 |
| `v-auth` 指令实现按钮级权限 | 通过 `v-auth` 控制按钮和菜单的可见性，禁止内联 `v-if` | 权限逻辑集中管理，避免散落在各组件中的 condition 判断 |
| AiCR 功能整合到 aiChat | AiCR（AI Code Review）功能作为 aiChat 的一个子模式 | 统一 AI 交互入口，避免功能碎片化 |
| Rsbuild 替代 Vite | 构建工具切换，环境变量前缀改为 `RSBUILD_ENV_*` | 更好的构建性能和开发体验 |

## 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| ProTable 组件过度封装 | 遇到不适用场景时开发效率反而降低 | 保留直接使用 Element Plus 组件的逃生路径，但需在 PRD 中说明原因 |
| 动态路由权限配置错误 | 用户无法访问应有页面或看到不应看到的页面 | 权限配置使用前必须测试；关键路由变更需要 code review |
| YiAi 服务不可用 | 聊天、数据管理、文件管理全部中断 | 前端优雅降级：显示清晰的错误信息和重试按钮 |
| 构建配置升级导致回归 | Rsbuild/Vue 版本升级可能引入兼容性问题 | 升级前在 CI 中运行全量构建验证 |

## 跨项目依赖

- **YiAi**：消费聊天、数据 CRUD、文件管理、知识库、RAG、Agent 服务。YiVad 的所有后端功能依赖 YiAi 运行
- **YiPet**：跨项目桥接——YiPet 通过 session key 跳转到 YiVad 的 aiChat 页面；YiPet 的 bug 报告写入 YiVad 管理的 bugs 集合

### PM 操作指南

**新增页面时**：
1. 确认路由配置（path、name、component、meta 权限信息）
2. 数据表格使用 ProTable 模式，除非在 PRD 中说明例外
3. 权限按钮使用 `v-auth` 指令控制
4. 更新 YiKnowledge 中的菜单配置文档

**新增 AI 功能时**：
1. 确认 YiAi 已提供对应的 RPC 接口（module_name、method_name）
2. 遵循 PRD 中的参数名称契约（`filter` 而非 `query`）
3. AI 交互状态至少覆盖：加载中、流式输出中、完成、错误四种状态
4. 参考 [discovery/ux/01-体验-UX检查清单.md](../discovery/ux/01-体验-UX检查清单.md) 中的 AI 相关 UX 模式

**版本发布前**：
1. 运行 `vue-tsc --noEmit` 确保无类型错误
2. 验证所有动态路由的面包屑导航正确
3. 验证权限控制：用不同角色测试可见菜单和按钮
4. 验证深色模式下所有页面渲染正常
