# 竞品分析方法

> **适用场景**：进入新市场前、定义 MVP 范围时、或当竞品发布了可能改变格局的新功能时。竞品分析的目的不是复制竞品，而是找到他们没做、做不好、或不该做的事。

## 为什么需要系统化的竞品分析

没有方法的竞品分析通常变成两种极端：
- **功能清单对比**：列一张表格，竞品有 X 我们也做 X。这是"追赶清单"不是"分析"
- **主观印象判断**：体验了几个竞品后凭感觉说"他们做得一般"。没有结构化证据

系统化的竞品分析回答三个问题：
1. **竞品在哪里强？** — 哪些是他们的护城河，我们不应该正面进攻
2. **竞品在哪里弱？** — 哪些是他们做不好或不该做的事，这是我们的机会窗口
3. **市场在往哪走？** — 竞品的行为揭示了什么趋势

## 三层分析框架

竞品分析不能只停留在功能对比。从三个层面逐层深入：

```
功能层（表层） → 战略层（中层） → 生态层（深层）
  "他们做了什么"  "他们为什么这么做"  "他们如何阻止别人进入"
```

### 第一层：功能对比矩阵

直接在功能维度做对比。这一步最直观，但也最容易被过度依赖——功能矩阵只是分析的起点，不是终点。

**模板**：

| 功能维度 | 我们 | 竞品 A | 竞品 B | 竞品 C | 差距判断 |
|---|---|---|---|---|---|
| 核心能力 | | | | | 领先/持平/落后 |
| 差异化能力 | | | | | 独有/共有 |
| 体验质量 | | | | | 优于/持平/差于 |
| 集成生态 | | | | | 开放/封闭 |

### 对每个功能维度打分

使用 5 分制，避免"有/没有"的二元判断：

| 分数 | 含义 | 判断标准 |
|---|---|---|
| 5 | 行业领先 | 用户会因为这个功能选他们而不是别人 |
| 4 | 明显优势 | 比大多数竞品做得好 |
| 3 | 持平 | 和竞品差不多，用户不会因为差异而选择 |
| 2 | 明显劣势 | 比大多数竞品差，用户因此流失 |
| 1 | 不可用 | 缺少此功能，成为使用阻碍 |

### 第二层：战略定位分析

功能矩阵只能告诉你"现在差在哪"，战略定位分析才能告诉你"为什么差"和"该不该追"。

使用 **SWOT + 战略意图** 框架：

| 竞品 | 核心目标用户 | 核心价值主张 | 盈利模式 | 战略意图 |
|---|---|---|---|---|
| 竞品 A | | | | 成为平台/守住利基/快速扩张/收割变现 |
| 竞品 B | | | | |
| 我们 | | | | |

**关键洞察**：同质化的功能背后可能是完全不同的战略。竞品 A 免费提供某个功能是因为它在用 VC 的钱抢用户，竞品 B 收费提供同样的功能是因为它追求盈利——功能一样，决策逻辑完全不同。

### 第三层：生态壁垒分析

最深的层面。生态壁垒决定了竞品能否持续保持领先。

| 壁垒类型 | 含义 | 识别信号 | YrY 相关案例 |
|---|---|---|---|
| **数据网络效应** | 用户越多，产品越好 | 竞品的 AI 输出质量随用户量增长显著改善 | YiAi 的 RAG 质量依赖 YiKnowledge 内容量和查询反馈数据 |
| **平台锁定** | 切换成本极高 | 用户的核心工作流深度集成，迁移意味着重来 | YiVad 的项目管理数据积累越多，用户越难迁移 |
| **品牌/社区** | 用户因为社区而非功能选择产品 | 活跃的开源社区、专属论坛、用户自发生产内容 | — |
| **独占资源** | 拥有别人拿不到的资源 | 独占数据源、专利技术、行业认证 | YiKnowledge 的行业售后知识体系 |

## 竞品情报收集

### 一手情报（免费、高价值）

| 方法 | 能获得的信息 | 频率 |
|---|---|---|
| 体验竞品核心流程 | 功能完整度、UX 质量、差异化特性 | 每季度一次深度体验 |
| 阅读竞品更新日志 | 产品迭代节奏、优先级的线索 | 关注竞品博客/RSS |
| 浏览竞品用户评价 | 用户真实痛点、竞品做得差的地方 | 每月一次（Chrome Store、GitHub Issues） |
| 试用竞品 API（如有） | 技术架构、数据模型设计思路 | 竞品发布 API 时 |

### 二手情报（需要验证）

- G2/Capterra 的用户评价（偏向极端好评或差评，需剔除两极取中间）
- 行业报告和融资新闻（揭示战略方向而非产品细节）
- 竞品招聘岗位描述（"急招 LLM 应用开发"说明竞品正在投入 AI 方向）

### 情报收集节奏

```
月度：浏览竞品更新日志 + 用户评价 + 招聘信息
季度：深度体验竞品核心流程，更新竞争态势分析
半年：完整的三层竞品分析 + 战略建议
```

## YrY 竞品分析示例

### YiPet — Chrome AI 扩展竞品分析

| 竞品 | 类型 | 核心优势 | 核心弱点 | 我们的机会 |
|---|---|---|---|---|
| Monica | 通用 AI 助手 | 功能全面（写作、翻译、摘要、搜索）、用户量大 | AI 回答基于通用模型，无行业知识底座；付费墙高 | **知识底座**：YrY 用户可以用自己的知识库提问，而非依赖通用回答 |
| Sider | AI 侧边栏 | 多模型支持、界面美观 | 同质化严重——和 Monica 功能高度重合 | **项目深度集成**：与 YiVad 的数据联动，不只是聊天工具 |
| MaxAI | AI 自动化 | 浏览器自动化能力强 | 学习成本高，面向专业用户 | **零门槛知识库对话**：选中一段文字就能查 YrY 知识库 |

### 关键发现

1. **所有竞品都是"通用 AI 工具"**——没有人做"与特定知识库集成的 AI 助手"。这是 YiPet 的蓝海
2. **竞品的差异化集中在模型数量和 UI**——没有人在差异化"回答的知识来源"。我们的知识底座是竞争壁垒
3. **竞品在向平台化发展**——从单一助手变成集成写作、翻译、搜索的平台。这意味着单点功能容易被平台吞掉

## 实践建议

1. **每季度做一次完整的三层分析**：功能矩阵每季度更新，战略分析每半年深挖。功能对比会过时，但战略理解不会
2. **竞品分析不是一次性的项目**：市场在变化、竞品在迭代、用户在迁移。建立月度情报收集习惯，而不是每年做一次大报告
3. **分析完要有产出**：竞品分析的目标是决策支持——"基于竞品分析，我建议我们做 X 而不是 Y"。没有建议的分析是浪费时间
4. **不要过度分析**：花一周分析 5 个竞品 > 花一个月分析 20 个竞品。竞品分析的边际收益迅速递减——前三个竞品提供 80% 的洞察
5. **关注"不做什么"**：竞品分析最大的价值往往是告诉你什么不该做——"竞品 A 做了 2 年也没做好 X，说明这个方向不值得投入"

## 反模式

| 反模式 | 为什么失败 | 正确做法 |
|---|---|---|
| 功能清单竞赛——"竞品有 X，我们也必须有" | 永远在追赶，永远没有差异化。你不可能在竞品擅长的领域打败竞品 | 找到竞品"不做"或"做不好"的事，而非复制竞品"做了"的事 |
| 只分析直接竞品——"我们只关注同类产品" | 替代方案不一定是同类产品。Excel 是 Asana 的竞品，白板是 Figma 的竞品 | 分析用户当前的"替代方案"（包括非软件方案），而非只看同类产品 |
| 分析完放在文件夹里吃灰 | 花了 2 周做了一份 50 页的竞品报告，但没有人基于它做决策 | 竞品分析最多一页纸。每个发现必须有对应的决策建议 |
| 只看功能不看战略 | "他们的界面比我们好看"——这是战术层发现，不会改变产品方向 | 从功能层下钻到战略层：他们为什么要把这个功能做成免费的？他们在放弃什么？ |
| 信息陈旧——用去年的分析做今年的决策 | AI 产品的迭代速度以周计算，半年前的竞品分析已严重过时 | 月度轻量更新（更新日志 + 用户评价），季度深度体验 |
