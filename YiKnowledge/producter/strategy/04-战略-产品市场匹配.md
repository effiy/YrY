# 产品市场匹配验证

> **适用场景**：当产品已上线并有初始用户，但不确定是应该继续投入、转型方向、还是放弃时。PMF 不是"产品做好了吗"的检查——是"有人在用且离不开吗"的验证。

## 什么是 PMF

产品市场匹配（Product-Market Fit, PMF）是"产品在一个好的市场中，满足了真实的用户需求"。

更接地气的定义：

> **PMF 意味着你的产品在解决一个足够多的人足够在意的问题，以至于他们会主动使用、主动推荐，并且在无法使用时感到不便。**

PMF 是一个光谱，不是二元状态。你不是"有 PMF"或"没有 PMF"——你在从 0 到 1 的光谱上移动。

| 阶段 | 信号 | YrY 示例 |
|---|---|---|
| **问题-方案匹配** | 用户确认你描述的痛点是真实的，且他们愿意尝试解决方案 | YiPet 知识底座：用户说"对，我确实需要基于 YrY 知识库的 AI 回答" |
| **产品-市场匹配** | 用户主动使用、留存稳定、自发推荐 | 知识底座周活跃用户在自然增长，而非依赖推广 |
| **规模化** | 增长可预测、单位经济模型成立 | 知识底座使用率成为 YiPet 的核心增长引擎 |

## 三种 PMF 验证方法

### 方法一：Sean Ellis 测试

问活跃用户一个问题：

> "如果 {{产品}} 明天消失了，你会有什么感受？"
>
> A. 非常失望
> B. 有些失望
> C. 不失望
> D. 已经不用了

**判断标准**：选择"非常失望"的用户 ≥ 40%，说明有 PMF 的初步信号。

**注意事项**：
- 只问**最近使用过核心功能**的用户——不活跃的用户本来就无所谓
- 样本量至少 50 人，低于这个数统计意义不足
- 追问"为什么"——"非常失望"是一回事，知道"失望什么"才能找到产品的核心价值锚点

### 方法二：留存曲线

新用户留存是 PMF 最诚实的信号。用户不会骗你——嘴上说"产品很好"但再也不打开，等于没有 PMF。

**看什么**：新用户队列的周留存曲线是否在某一点**趋于平坦**。

```
周留存率
    │
80% │╲
    │ ╲
40% │  ╲
    │   ╲___________  ← 曲线在这里趋于平坦，说明核心用户留下了
20% │
    └──────────────────→ 周
     W1  W2  W3  W4  W8
```

**判断标准**：
- 曲线持续下滑不趋于平坦 → 用户来了就走，没有 PMF
- 曲线在第 3-4 周趋于平坦且平坦线在 20% 以上 → 有 PMF 信号
- 平坦线低于 10% → 产品对大多数用户没有持续价值

### 方法三：使用深度

用户不仅回来，而且用得越来越深。

| 深度信号 | 测量方式 | YrY 示例 |
|---|---|---|
| 使用频率提升 | 新用户前 4 周的使用频率是否在上升 | 小李第一周用 3 次知识底座，第三周用 8 次 |
| 功能扩展使用 | 用户是否从单一功能扩展到多个功能 | 从只用聊天 → 也用知识树浏览 → 也用范围选择 |
| 自发推荐 | 是否有人在没有激励的情况下主动推荐 | GitHub Issues 中有人提"这个功能很棒，我推荐给团队了" |

## YrY 各项目的 PMF 评估

### YiPet 知识底座功能

| 验证维度 | 当前状态 | PMF 信号 |
|---|---|---|
| 使用频率 | 15% 的会话有知识底座 | 弱——知悉率和使用率仍然低 |
| 留存信号 | 尚需数据 | 需要追踪：第一次用知识底座的用户，第二周还在用吗？ |
| 用户反馈 | 深度用户满意度高（85%） | 强——用了的人觉得好，问题在"用的人太少" |
| 自发推荐 | 内部团队开始主动使用并推荐给同事 | 中——在团队内部有小范围的口碑传播 |

**判断**：YiPet 知识底座功能处于"问题-方案匹配"向"产品-市场匹配"过渡阶段。产品价值已被验证（深度用户满意度高），但触达和激活需要改善（55% 用户从未使用）。

**下一步**：不是增加功能，而是降低首次使用门槛——引导、入口优化、触发场景。

### YiVad 项目管理

| 验证维度 | 当前状态 | PMF 信号 |
|---|---|---|
| 依赖程度 | 核心管理流程依赖 YiVad（项目追踪、问题管理） | 强——没了 YiVad 项目管理就会断裂 |
| 使用频率 | 工作日每天使用 | 强 |
| 功能使用广度 | 集中在 ProTable 数据管理和 Bug 追踪 | 中——核心功能被深度使用，周边功能（文件管理）使用较少 |

**判断**：YiVad 的核心数据管理功能已达到 PMF。挑战不在 PMF，在"如何让用户从功能使用扩展到平台依赖"。

### YiAi API

| 验证维度 | 当前状态 | PMF 信号 |
|---|---|---|
| 依赖程度 | YiVad 和 YiPet 都依赖 YiAi | 强——系统级依赖 |
| 使用频率 | 持续调用 | 强 |
| "非常失望"测试 | 如果 YiAi 不可用，YiVad 和 YiPet 的聊天/数据/AI 功能全部瘫痪 | 极强 |

**判断**：YiAi 作为基础设施已达到 PMF。下一步关注点不在 PMF，在 API 稳定性、性能和扩展性。

## 转型 vs 坚持 —— 决策框架

当你怀疑 PMF 时，如何判断是继续投入还是转型方向？

### 问自己三个问题

**1. 有部分用户在深度使用吗？**

- 有 → 问题不在产品本身，在触达和激活。优化入门体验而非重构产品
- 没有 → 产品可能没解决真问题。需要回到用户研究验证问题是否存在

**2. 用户流失的主要原因是"不需要"还是"不好用"？**

| 流失原因 | 含义 | 行动 |
|---|---|---|
| "不需要" | 问题不是真问题，或不值得用工具解决 | 转型——回到问题发现阶段 |
| "不好用" | 问题是真的，但你的方案没做好 | 坚持——优化体验和功能 |

**3. 有没有一个能让我们在 30 天内验证的关键假设？**

如果你不能想到一个可以在 30 天内验证的假设，说明你对"为什么没有 PMF"不够清楚。先做用户研究搞清楚"用户到底卡在哪"，再决定是坚持还是转型。

### 转型类型

| 转型类型 | 含义 | 示例 |
|---|---|---|
| 用户群体转型 | 同一产品，换了目标用户 | 原本面向所有开发者的工具，发现用最深的是售后团队 → 聚焦售后场景 |
| 问题转型 | 同一用户群体，换了要解决的问题 | 用户说"我想要更好的搜索"，但实际痛点是不知用什么关键词搜 → 从"优化搜索算法"转到"引导式检索" |
| 技术转型 | 用了不合适的方案解决真实问题 | 用复杂的 Multi-Agent 解决一个单 Agent 就能做好的事 → 降级到简单方案再验证 |
| 渠道转型 | 产品没问题，但用户不知道怎么用 | 知识底座功能有价值（深用户满意度高），但 55% 用户不知道它存在 → 重点放在引导和激活而非功能开发 |

## PMF 不是终点

PMF 之后不等于"可以放慢节奏"。PMF 验证了你找对了方向——但保持 PMF 需要持续的产品演进。

**PMF 存续的三项条件**：
1. 用户的需求没有变（或变了你跟上了）
2. 竞品没有提供更好的替代方案
3. 你的产品体验在持续改善而非退化

即使是 YiAi 这样已达到 PMF 的产品，如果 API 稳定性持续退化，PMF 也会丧失——用户不是永远忠诚的。

## 实践建议

1. **PMF 验证不是一次性的**：市场在变、用户在变、竞品在变。季度性回顾 PMF 信号——上季度的 PMF 不保证本季度仍然成立
2. **定量数据 + 定性访谈交叉验证**：留存数据告诉你"用户在离开"，但只有用户访谈能告诉你"为什么离开"。数据给信号，访谈给原因
3. **早期产品关注留存而非增长**：在验证 PMF 之前推增长，等于往漏水的桶里倒水。先修桶（达到 PMF），再灌水（做增长）
4. **警惕虚假 PMF 信号**：增长来自推广而非需求、用户使用是替代方案匮乏而非你的方案好、高 NPS 但用户群极小。这些短期信号可能掩盖长期的 PMF 缺失

## 反模式

| 反模式 | 为什么失败 | 正确做法 |
|---|---|---|
| 没有 PMF 就开始做增长——"先把用户拉进来再说" | 漏水的桶——拉进来的用户不留下，增长的每一分钱都在浪费 | 先验证 PMF（留存曲线趋于平坦），再投入增长预算 |
| Sean Ellis 测试只问不追——"40% 非常失望，我们有 PMF！" | 不知道用户"为什么失望"——是核心功能缺失还是某个边缘场景 | 追问：你最失望哪些功能会消失？为什么？答案揭示了产品的价值锚点 |
| 用总量指标代替留存指标——"总用户数在增长所以 PMF 没问题" | 总量掩盖了留存问题。每周新增 100 用户但 99 个离开——总量看起来在涨，实际上在烧钱 | 看新用户队列的留存曲线，而非总量趋势 |
| 仅凭直觉判断 PMF——"我觉得用户在需要我们" | 直觉 = 确认偏差。你只会注意到支持你信念的信号 | 用量化方法交叉验证：Sean Ellis 测试 + 留存曲线 + 使用深度。三者共识 > 个人直觉 |
| 一次 PMF 验证后就不再审视——"我们 6 个月前就有 PMF 了" | PMF 可以被侵蚀：竞品上线了更好的方案、用户需求变了、你的质量下降了 | 每季度用 30 分钟回顾三个信号：依赖度（用户离不开吗）、推荐度（用户在推荐吗）、使用深度（用得更多还是更少） |
