# 会话列表加载时使用 pageSize:200 无游标分页

## 现象

`chat/stores/chat.ts` 的 `_loadSessions` 方法使用硬编码的 `pageSize: 200` 加载会话列表：

```typescript
const res = await _sessions.list({ pageSize: 200 });
```

当用户跨多个项目页面使用时（每个页面创建一个会话），会话数可能超过 200。超出部分的会话无法在侧边栏中看到，且无任何"加载更多"或分页提示。

## 根因分析

- 200 条会话对于 Chrome 扩展来说通常是足够的"上限"
- 但小米用户跨大量页面聊天的场景下可能不够
- 没有游标分页或"加载更多"机制，用户感知不到有更多会话

## 涉及文件

- `src/chat/stores/chat.ts:322` — `pageSize: 200` 硬编码

## 修复方案

1. 实现基于游标的分页：首次加载 50 条，滚动到底部时自动加载下一页
2. 或在侧边栏底部显示"加载更多"按钮
3. 显示总数提示：`Showing 200 of 350 sessions`


## 影响范围

**影响模块**：`src/chat/stores/chat.ts` 会话列表加载逻辑。
**影响用户**：当用户跨多个项目页面使用扩展后，会话数可能超过 200，超出部分的会话在侧边栏中不可见且无任何提示。
**影响范围**：聊天窗口的会话侧边栏，影响重度用户（跨页面使用 200+ 会话）。
## 预防措施

| 层面 | 措施 | 责任人 |
|------|------|--------|
| 架构 | 所有列表加载默认支持分页或虚拟滚动 | 架构师 |
| 代码 | pageSize 通过常量配置管理，不硬编码在业务逻辑中 | 开发者 |
| 代码 | 列表底部显示加载状态和"加载更多"触发机制 | 开发者 |
| 体验 | 显示总数提示（如"已显示 200/350 条会话"） | 开发者 |


## 经验教训

硬编码的分页大小是"乐观假设"的典型例子——假设会话数永远不会超过某个值。在数据量不确定的场景中，始终应实现分页或虚拟滚动，并在达到上限时给用户明确提示。
