# chat/index.ts 中扩展根路径解析依赖脚本 src 属性

## 现象

`src/chat/index.ts:23` 通过解析当前脚本的 `src` 属性来确定扩展根路径：

```typescript
// chat/index.ts — 通过 script src 解析扩展根路径
const EXT_ROOT = (() => {
  const script = document.currentScript as HTMLScriptElement | null;
  if (script?.src) {
    const u = new URL(script.src);
    return u.origin + u.pathname.replace(/\/assets\/chat\..*\.js$/, '');
  }
  return '';
})();
```

这种解析方式脆弱：
- 如果 Rsbuild 构建配置更改了输出文件名格式，正则不再匹配
- 如果聊天 bundle 路径深度变化，截取逻辑也会出错
- `document.currentScript` 在 `defer` 或 `async` 脚本中可能为 null

## 根因分析

- Content script 在 MAIN 世界中运行，无法访问 `chrome.runtime.getURL()`
- 需要知道扩展根路径来解析角色图片等静态资源 URL
- 当前实现是"可用但脆弱"的妥协方案

## 涉及文件

- `src/chat/index.ts:23-29` — EXT_ROOT 解析逻辑

## 修复方案

1. 通过 content script（ISOLATED 世界）预计算资源 URL 并通过 CustomEvent 传递给 MAIN 世界
2. 或使用 `window.__YIPET_CDN_ROOT__` 全局变量，在构建时注入
3. 在 Rsbuild 配置中使用 `define` 注入扩展根路径常量


## 影响范围

**影响模块**：`src/chat/index.ts` 中的 EXT_ROOT 解析逻辑。
**影响用户**：当 Rsbuild 构建配置变更（如输出文件名格式、目录结构）时，路径解析可能失败，导致角色图片等静态资源加载 404。
**影响范围**：MAIN World 中所有需要扩展根路径的静态资源 URL 解析。
## 预防措施

| 层面 | 措施 | 责任人 |
|------|------|--------|
| 架构 | 通过 Content Script（ISOLATED World）预计算资源 URL，通过 IPC 传递给 MAIN World | 架构师 |
| 构建 | 在 Rsbuild 配置中使用 `define` 注入扩展根路径常量 | DevOps |
| 代码 | 避免从脚本 URL 解析路径信息——这是脆弱的启发式方法 | 开发者 |


## 经验教训

从脚本 `src` 属性解析路径是一种启发式方法，依赖构建输出格式的内部实现细节。当构建工具升级或配置变更时，这种解析很容易失效。构建时的环境变量注入是更可靠的选择——路径在编译时确定，不依赖运行时上下文。
