# popup 的 connect 服务 ping 间隔未适配节电模式

## 现象

`popup/services/connection.ts` 的 `ping()` 函数以固定间隔检查 content script 的连接状态，但在笔记本电脑的节电模式下（`navigator.getBattery()` 或 `prefers-reduced-data`），频繁的 ping 会浪费电量。

## 根因分析

- Popup 是短生命周期的（用户打开即关闭），ping 影响有限
- 但 Chat 窗口可长时间保持打开，定时 ping 会阻止浏览器进入节电状态

## 涉及文件

- `src/popup/services/connection.ts` — ping 逻辑

## 修复方案

Popup 关闭时停止 ping，Chat 窗口不可见时增加 ping 间隔。考虑 `document.visibilityState` 检测。


## 影响范围

**影响模块**：`src/background/index.ts` 中的心跳保活逻辑。
**影响用户**：固定间隔的心跳不考虑用户是否活跃，在用户长时间不使用扩展时（如夜间），心跳仍消耗 CPU 和电量。
**影响范围**：所有启用了 Service Worker 心跳保活的用户。
## 预防措施

| 层面 | 措施 | 责任人 |
|------|------|--------|
| 代码 | 根据用户活跃状态动态调整心跳间隔（活跃时 20 秒，空闲时 5 分钟） | 开发者 |
| 代码 | 利用 `chrome.idle` API 检测用户空闲状态 | 开发者 |
| 代码 | 用户空闲超过 15 分钟后停止心跳，恢复时重新启动 | 开发者 |
| 性能 | 评估心跳对电池寿命的影响 | DevOps |


## 经验教训

Service Worker 的心跳保活是一把双刃剑——它改善了响应速度，但增加了功耗。动态调整心跳间隔（活跃时高频、空闲时低频或停止）是兼顾体验和功耗的最佳策略。`chrome.idle` API 是实现这一策略的关键。
