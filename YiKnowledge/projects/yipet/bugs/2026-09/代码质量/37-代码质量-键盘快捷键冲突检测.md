# 缺少 manifest.json 中 commands 快捷键的冲突检测

## 现象

`manifest.json` 定义了两个全局快捷键，但未检查这些快捷键是否与其他已安装扩展冲突：

```json
"commands": {
  "toggle-pet": { "suggested_key": { "default": "Ctrl+Shift+P", "mac": "Command+Shift+P" } },
  "open-chat": { "suggested_key": { "default": "Ctrl+Shift+X", "mac": "Command+Shift+X" } }
}
```

`Ctrl+Shift+P` 在某些浏览器中是"隐私模式新窗口"的默认快捷键。`Ctrl+Shift+X` 可能与 Vimium、Dark Reader 等流行扩展冲突。

## 根因分析

- Chrome 在安装扩展时不会警告快捷键冲突——最后注册的扩展获得快捷键
- 没有运行时检测快捷键是否被覆盖的机制

## 涉及文件

- `manifest.json:27-40` — commands 定义

## 修复方案

1. 运行时使用 `chrome.commands.getAll()` 检查快捷键是否被正确注册
2. 在 popup 或 options 页面显示当前快捷键状态
3. 提供备用快捷键组合


## 影响范围

**影响模块**：`manifest.json` 中的 `commands` 配置。
**影响用户**：当 YiPet 的键盘快捷键与其他扩展或浏览器内置快捷键冲突时，用户可能无法使用某个功能。
**影响范围**：所有键盘快捷键（`Ctrl+Shift+X` 切换宠物、`Ctrl+Shift+Z` 打开聊天窗口）。
## 预防措施

| 层面 | 措施 | 责任人 |
|------|------|--------|
| 配置 | 提供备选快捷键方案，用户可在 `chrome://extensions/shortcuts` 中自定义 | 开发者 |
| 代码 | 检测快捷键是否被其他扩展占用，并给出提示 | 开发者 |
| 体验 | 键盘快捷键冲突时提供可视化提示和配置入口 | 开发者 |


## 经验教训

Chrome 扩展的键盘快捷键是全局资源，多个扩展可能使用相同的快捷键组合。虽然 Chrome 允许用户在 `chrome://extensions/shortcuts` 中自定义，但多数用户不知道这个功能。在扩展中主动提示冲突并提供配置引导是更好的体验。
