# chat/index.ts 中扩展入口缺少 DOM 挂载失败处理

## 现象

`src/chat/index.ts` 的 Vue 应用挂载逻辑缺少对挂载目标元素缺失的错误处理：

```typescript
// chat/index.ts — 挂载 Vue 应用到 #yipet-chat-root
const chatRoot = document.getElementById('yipet-chat-root');
if (!chatRoot) return;  // 仅检查是否存在，无错误日志

const app = createApp(ChatWindow);
app.use(createPinia());
app.mount('#yipet-chat-root');  // 无 .mount() 的异常处理
```

如果因 CSP 限制、DOM 竞争条件或 CDN 加载失败导致 Vue 应用挂载失败，错误不可见（控制台可能有异常但用户无感知）。

## 根因分析

- `app.mount()` 在以下情况会失败：重复挂载、选择器无匹配、组件初始化异常
- 没有 `try/catch` 包裹或错误回调
- 聊天窗口是扩展的核心功能，挂载失败应降级通知用户

## 涉及文件

- `src/chat/index.ts:83-90` — Vue 应用挂载

## 修复方案

```typescript
try {
  app.mount('#yipet-chat-root');
} catch (e) {
  console.error('[YiPet Chat] Mount failed:', e);
  // 降级：在 document.body 上显示错误提示
}
```


## 影响范围

**影响模块**：聊天窗口挂载（`mount()`）方法。
**影响用户**：如果初始化过程中 API 调用失败（如加载会话列表），聊天窗口可能处于半初始化状态——部分功能可用、部分不可用，且无错误提示。
**影响范围**：所有聊天窗口的初始化和状态恢复流程。
## 预防措施

| 层面 | 措施 | 责任人 |
|------|------|--------|
| 代码 | `mount()` 方法中所有异步操作包裹 try-catch | 开发者 |
| 代码 | 初始化失败时应显示明确的错误状态和重试按钮 | 开发者 |
| 代码 | 区分关键初始化失败（聊天不可用）和非关键失败（部分功能降级） | 开发者 |
| 体验 | 加载失败时显示友好的错误提示，而非空白窗口 | 开发者 |


## 经验教训

初始化阶段的错误处理是最容易被忽视的——开发者倾向于假设初始化总是成功。但网络请求、存储读取、DOM 操作在初始化阶段同样可能失败。优雅的初始化失败处理是用户体验的底线。
