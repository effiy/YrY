# 状态管理: 标签页后台隐藏后 Pinia Store 状态未冻结，导致 SSE 流中断、UI 卡死及消息丢失

## 1. 概述

### 1.1 漏洞摘要

YiPet 聊天窗口的 Pinia Store (`src/chat/stores/chat.ts`) 对标签页可见性变化**完全无感知**。当用户将标签页切到后台超过 Chrome 的节流阈值（5 分钟）后，SSE 流式读取循环中的 `reader.read()` Promise 被浏览器挂起，`setTimeout`/`setInterval` 被节流到最低 1 分钟间隔，导致：

1. **流式消息不完整** — `isProcessing` 保持 `true`，实际 SSE 连接已断开
2. **UI 卡死** — 发送按钮灰色不可点击，用户必须刷新页面
3. **消息丢失** — 已接收但未持久化的 token 在标签页恢复时无法恢复
4. **会话列表过期** — 未从 `chrome.storage` 重新加载，可能显示其他标签页已删除的会话

### 1.2 风险评级

| 维度 | 评级 | 依据 |
|------|------|------|
| **严重度** | Major | 用户体验严重受损，聊天窗口卡死，必须刷新页面 |
| **可利用性** | 必然触发 | 标签页后台 5 分钟+ 必定触发，Chrome 节流行为确定 |
| **影响范围** | 所有用户 | 任何切换标签页超过 5 分钟的用户 |
| **数据损失** | 中 | 断连后未持久化的流式 token 丢失，但历史消息不受影响 |
| **检测难度** | 低 | 用户可感知（UI 卡死），但根因隐蔽（Chrome 节流机制） |

## 2. 技术背景

### 2.1 Chrome 后台标签页节流策略

Chrome 为节省资源，对后台标签页实施渐进式节流：

| 后台时间 | 节流行为 | 受影响的 API |
|----------|---------|------------|
| 0–5 分钟 | 正常运行 | 不受影响 |
| **5 分钟+** | `setTimeout`/`setInterval` 最小间隔 **1 分钟** | 所有定时器几乎停止 |
| **10 分钟+** | 标签页可能被**完全冻结**（Page Lifecycle: `frozen`） | 所有 JS 执行暂停，网络请求中断 |
| 恢复时 | 冻结的标签页触发 `resume` 事件 | `pageshow` 的 `persisted` 为 `true` |

**关键影响**：YiPet 聊天窗口的多个流程依赖定时器和网络 I/O：

- SSE 流式读取循环：`reader.read()` 返回 Promise，后台时网络活动被节流，Promise 可能长时间不 resolve
- Token 批量缓冲：如有 `setTimeout` 控制的批量刷新，后台时被延迟到 1 分钟+
- 消息持久化：`_persistMessages()` 调用 `_sessions.update()`（网络请求），后台时可能失败

### 2.2 Chrome Page Lifecycle API

```
foreground → 用户切换标签页 → background (定时器节流)
                                    │
                              5 分钟后: 定时器严重节流
                                    │
                             10 分钟后: frozen (JS 完全暂停)
                                    │
                         用户切回标签页 → resume → foreground
```

两个关键事件：

- `visibilitychange` — 标签页可见性变化时触发（`document.hidden` 切换）
- `pageshow`/`pagehide` — 页面从 BFCache 恢复/进入时触发（`event.persisted` 指示是否来自缓存）

### 2.3 YiPet 当前架构

聊天状态管理位于 `src/chat/stores/chat.ts`（Pinia Store，约 1972 行）：

```
ChatWindow.vue (Vue 3)
    ↕
useChatStore (Pinia reactive state)
    ├── _runStream() — 普通/知识库聊天流式循环
    ├── _runAgentStream() — Agent 工具调用流式循环
    ├── _persistMessages() — 消息持久化到后端
    └── mount() — 初始化（加载会话、恢复状态）
    ↕
ApiClient (src/api/client.ts)
    └── stream() — SSE 流式读取，STREAM_TIMEOUT_MS = 600s
```

**当前缺失**：整个链路中无任何 `visibilitychange`、`pagehide` 或 `pageshow` 监听器。

## 3. 根因分析

### 3.1 直接原因

**Pinia Store 对标签页生命周期无感知**。`src/chat/stores/chat.ts` 中：

- `mount()` 方法（line 1454）仅加载持久化状态和会话列表，不注册任何可见性监听器
- `_runStream()` 和 `_runAgentStream()` 中无超时保护，`reader.read()` 挂起时无恢复机制
- `_persistMessages()` 在 `finally` 块中调用，但后台标签页中此代码可能延迟执行

### 3.2 代码分析

**问题 1 — SSE 读取无单次超时保护**（`src/api/client.ts:219`）：

```typescript
// client.ts:218-220 — 当前实现
while (true) {
  const { done, value } = await reader.read();
  // ⚠️ reader.read() 在后台标签页中可能挂起数分钟
  // 无单次读取超时，仅有一个 10 分钟的整体超时
  if (done) break;
  // ...
}
```

**问题 2 — `finally` 块在后台标签页中延迟执行**（`src/chat/stores/chat.ts:968-998`）：

```typescript
// chat.ts:968-998 — _runStream 的 finally 块
} finally {
  state.isProcessing = false;     // ⚠️ 后台时此行可能数分钟后才执行
  state.streamingType = '';
  state.streamingPhase = '';
  state.streamingTargetTimestamp = null;
  _abortController = null;
  // ...
  _persistMessages();             // ⚠️ 网络请求在后台时可能失败
  setTimeout(() => scrollToBottom(true), 50); // ⚠️ 被节流到 1 分钟+
}
```

**问题 3 — 无可见性变化时的状态检查**（`src/chat/stores/chat.ts`）：

```typescript

    await _findOrCreateSession();

  // ❌ 缺失: document.addEventListener('visibilitychange', ...)
}
```

### 3.3 失败链路

```
用户发送消息，SSE 流式进行中
  │  state.isProcessing = true
  │  reader.read() 循环读取 token
  │
  ├─ 用户切换标签页（t=0）
  │   Chrome 标签页进入后台
  │   0-5 分钟: 正常运行，token 继续累积
  │
  ├─ 5 分钟后（t=5min）
  │   Chrome 节流启动
  │   reader.read() Promise 挂起（网络活动被节流）
  │   setTimeout 最小间隔 1 分钟
  │   _persistMessages() 网络请求可能失败/超时
  │
  ├─ 10 分钟后（t=10min）
  │   Chrome 可能冻结标签页
  │   所有 JS 执行暂停
  │   SSE 底层 TCP 连接可能已超时断开
  │
  └─ 用户切回标签页（t=10min+）
      ├─ 标签页恢复
      ├─ reader.read() 的 Promise 可能 resolve（返回陈旧数据）或 reject
      ├─ finally 块执行: state.isProcessing = false
      ├─ 但消息可能不完整（流中断时未捕获异常）
      │
      └─ 用户看到:
          • isProcessing 仍为 true（finally 未及时执行）
          • 发送按钮灰色不可点击
          • 最后一条消息显示一半的 AI 回复
          • 会话列表可能过期
```

### 3.4 受影响的状态字段

| 状态字段 | 正常值 | 后台卡死时的值 | 影响 |
|---------|--------|-------------|------|
| `state.isProcessing` | `false` | **`true`** | 发送按钮灰色，无法发送新消息 |
| `state.streamingType` | `''` | **`'send'`/`'regenerate'`** | 状态指示器显示错误的操作类型 |
| `state.streamingPhase` | `''` | **`'streaming'`** | 状态指示器卡在"流式传输中" |
| `state.messages[last].streaming` | `false` | **`true`** | 消息气泡显示加载动画 |
| `state.messages[last].content` | 完整文本 | **不完整文本** | 用户看到一半的 AI 回复 |
| `state.sessions` | 最新列表 | **可能过期** | 多标签页场景下数据不一致 |

## 4. 修复方案

### 4.1 分层修复策略

```
┌─────────────────────────────────────────────────────────────┐
│ Layer 1: 可见性监听 — 感知标签页隐藏/恢复                      │
│ Layer 2: SSE 读取超时 — 单次 read() 超时保护                  │
│ Layer 3: 状态自愈 — 恢复时自动检测并修复过期状态                │
│ Layer 4: 数据同步 — 恢复时从 chrome.storage 重新加载            │
│ Layer 5: 优雅降级 — 标记中断消息，恢复用户操作能力              │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 Layer 1: 可见性监听

```typescript
// src/chat/stores/chat.ts — 在 mount() 中注册

const STALE_THRESHOLD_MS = 60_000; // 1 分钟后认为状态可能过期
let _lastVisibleTime = Date.now();
let _hiddenTimer: ReturnType<typeof setTimeout> | null = null;

function _onVisibilityChange(): void {
  if (document.hidden) {
    _onTabHidden();
  } else {
    _onTabVisible();
  }
}

function _onTabHidden(): void {
  _lastVisibleTime = Date.now();

  // 启动后台超时定时器：如果后台超过 CHROME_THROTTLE_THRESHOLD，
  // 主动中止 SSE 流以触发 finally 清理
  const CHROME_THROTTLE_THRESHOLD = 4.5 * 60 * 1000; // 4.5 分钟（在 Chrome 5 分钟节流前）
  _hiddenTimer = setTimeout(() => {
    if (state.isProcessing && document.hidden) {
      // 主动中止 SSE 流，触发 finally 块执行清理
      _abortController?.abort();
      _abortController = null;
    }
  }, CHROME_THROTTLE_THRESHOLD);
}

async function _onTabVisible(): void {
  // 清除后台超时定时器
  if (_hiddenTimer) {
    clearTimeout(_hiddenTimer);
    _hiddenTimer = null;
  }

  const hiddenDuration = Date.now() - _lastVisibleTime;

  // 短时间隐藏（< 阈值）：无需处理
  if (hiddenDuration < STALE_THRESHOLD_MS) {
    return;
  }

  // 长时间隐藏：检查并修复过期状态
  await _recoverFromBackground(hiddenDuration);
}

async function _recoverFromBackground(hiddenDuration: number): Promise<void> {
  // 1. 处理卡住的流式状态
  if (state.isProcessing) {
    const lastMsg = state.messages[state.messages.length - 1];
    if (lastMsg?.type === 'pet' && lastMsg.streaming) {
      lastMsg.streaming = false;
      lastMsg.error = true;
      lastMsg.aborted = true;
      // 不覆盖已有内容，但标记为可能不完整
      if (!lastMsg.content.endsWith('\n\n> ⚠️')) {
        lastMsg.content += '\n\n> ⚠️ Response interrupted — tab was backgrounded for ' +
          Math.round(hiddenDuration / 1000) + 's. [Retry](/retry)';
      }
    }
    state.isProcessing = false;
    state.streamingType = '';
    state.streamingPhase = '';
    state.streamingTargetTimestamp = null;
    _abortController = null;
  }

  // 2. 重新加载会话列表（可能在其他标签页中被修改）
  await _loadSessions();

  // 3. 触发 UI 更新
  state.scrollTick++;
}
```

```typescript
// src/api/client.ts — 在 stream() 中增加单次读取超时

const READ_TIMEOUT_MS = 30_000; // 单次读取超时 30 秒

async function* stream(
  path: string,
  body?: unknown,
  signal?: AbortSignal,
): AsyncGenerator<StreamChunk> {
  // ... 现有初始化 ...

  while (true) {
    // ✅ 单次读取超时保护
    let readResult: ReadableStreamReadResult<Uint8Array>;
    try {
      readResult = await Promise.race([
        reader.read(),
        new Promise<never>((_, reject) =>
          setTimeout(() => reject(new Error('SSE read timeout')), READ_TIMEOUT_MS)
        ),
      ]);
    } catch (err) {
      if ((err as Error).message === 'SSE read timeout') {
        yield { done: true, error: 'SSE stream read timeout — connection may be stalled' };
        return;
      }
      throw err;
    }

    const { done, value } = readResult;
    if (done) break;
    // ... 现有处理 ...
  }
}
```

### 4.4 Layer 3: 状态自愈

```typescript
// src/chat/stores/chat.ts — 新增 store action

/** 检测并修复所有可能的过期状态 */
function validateAndRepairState(): string[] {
  const issues: string[] = [];

  // 检查 isProcessing 是否已卡住超过 5 分钟
  if (state.isProcessing) {
    const lastMsg = state.messages[state.messages.length - 1];
    const lastTs = lastMsg?.timestamp || 0;
    if (Date.now() - lastTs > 5 * 60 * 1000) {
      issues.push('isProcessing stuck for >5min');
      state.isProcessing = false;
      state.streamingType = '';
      state.streamingPhase = '';
      if (lastMsg?.streaming) {
        lastMsg.streaming = false;
        lastMsg.error = true;
      }
    }
  }

  // 检查 streaming 消息是否已过期
  const streamingMsg = state.messages.find((m) => m.streaming);
  if (streamingMsg && Date.now() - streamingMsg.timestamp > 10 * 60 * 1000) {
    issues.push('streaming message stuck for >10min');
    streamingMsg.streaming = false;
    streamingMsg.error = true;
  }

  return issues;
}
```

```typescript
// src/chat/stores/chat.ts — 恢复时从 chrome.storage 重新加载

async function _syncFromStorage(): Promise<void> {
  if (typeof chrome === 'undefined' || !chrome.storage?.local) return;

  try {
    // 重新加载所有持久化设置
    const result = await chrome.storage.local.get([
      'sidebarWidth', 'sidebarCollapsed', 'knowledgeGrounded',
      'ragScope', 'ragScopeIsFile', 'promptHistory',
      'chatColorIndex',

      state.knowledgeGrounded = result.knowledgeGrounded;
    }
    if (typeof result.ragScope === 'string') {
      state.ragScope = result.ragScope;
    }
    // ... 其他字段
  } catch { /* storage unavailable */ }
}
```

### 4.7 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 过期阈值 | 60 秒 | 覆盖绝大多数标签页切换场景，误判成本低 |
| 后台主动中止 | 4.5 分钟 | 在 Chrome 5 分钟节流前主动中止，确保 finally 块执行 |
| SSE 单次读取超时 | 30 秒 | 正常 SSE 流每 50-200ms 有数据，30 秒无数据必为异常 |
| 过期处理 | 标记错误 + 可重试 | 不自动重连（避免浪费 token），让用户决定 |
| 状态恢复 | 从 chrome.storage 重新加载 | 多标签页场景下状态可能被其他标签页修改 |
| 整体流超时 | 保持 10 分钟 | 与 YiVad ragService 一致，覆盖长回复场景 |

### 9.2 Google Chrome 定时器节流详细说明

Chrome 88+ 对后台标签页的定时器节流策略：

- **密集型节流**（Intensive Throttling）：标签页隐藏 **5 分钟**后，`setTimeout`/`setInterval` 的最小间隔被限制为 **1 分钟**
- **冻结**（Freezing）：标签页隐藏 **10 分钟+** 且满足条件（无音频播放、无 WebSocket、无 IndexedDB 事务等）时，Chrome 可能完全冻结标签页
- **BFCache**（Back-Forward Cache）：部分页面在导航离开时会被存入 BFCache，恢复时触发 `pageshow` 事件（`event.persisted === true`）

YiPet 受影响的关键路径：

| 路径 | 使用的 API | 受节流影响 |
|------|----------|:---:|
| SSE 流式读取 | `reader.read()` (Promise) | 是 — 网络活动被节流 |
| 消息持久化 | `_sessions.update()` (fetch) | 是 — 网络请求被延迟 |
| 滚动节流 | `setTimeout` 控制 `scrollTick` | 是 — 定时器被限制到 1 分钟 |
| 确认超时 | `_confirmationTimer` (setTimeout 120s) | 是 — 后台时可能不触发 |
| 压缩提示 | `_compactionTimer` (setTimeout 8s) | 是 — 后台时延迟 |
