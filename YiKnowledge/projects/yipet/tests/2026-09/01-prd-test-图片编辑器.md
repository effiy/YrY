## 一、测试范围与目标

### 1.1 在范围内

| 范围 | 内容 |
|------|------|
| 21 个算法模块 | 基础调整 7 + 高级调整 5 + 几何变换 5 + 装饰 3 + 信息 1 |
| 核心渲染管线 | `renderingPipeline`、`colorSpace`、`histogramCalculator`、`imageLoader` |
| 3 个 Web Worker | histogram、clahe、saturation |
| 9 个 Vue 组件 | 编辑器容器/工具面板/滑块/预设/直方图/分割视图/裁剪/曲线/导出 |
| 4 个 Composables | `useImageEditor`、`useRenderingPipeline`、`useWorkerPool`、`usePresets` |
| 非破坏性编辑 | 始终从 original ImageData 副本开始 |
| 颜色空间正确性 | RGB↔HSL↔Lab 往返误差 < 1 色差值 |

### 1.2 不在范围内

| 排除项 | 原因 |
|--------|------|
| WebP/AVIF 导出 | DEV §13 列为功能缺口 |
| 批量图片处理 | 依赖独立的批量操作基础设施 |
| 跨设备预设同步 | DEV §13 列为技术债 |
| ICC Profile 颜色管理 | DEV §13 列为技术债 |

## 五、单元测试 — 算法模块

### 5.1 基础调整（7 个工具）

| 编号 | 用例 | 输入 | 预期 |
|------|------|------|------|
| UT-BC-01 | 亮度 +50 | 中灰像素(128,128,128) | 输出(178,178,178)：128+50=178 |
| UT-BC-02 | 亮度 -50 | 中灰像素(128,128,128) | 输出(78,78,78)：128-50=78 |
| UT-BC-03 | 对比度 2.0 | 中灰像素(128,128,128) | 输出(128,128,128)：中灰不变 |
| UT-BC-04 | 对比度 2.0 暗像素 | (64,64,64) | 输出(0,0,0)：(64-128)×2+128=0 |
| UT-BC-05 | clamp 上限保护 | 亮度+200 | 输出 ≤ 255 全部通道 |
| UT-BC-06 | clamp 下限保护 | 亮度-200 | 输出 ≥ 0 全部通道 |
| UT-CE-01 | 全局直方图均衡 | 低对比度图片 | 输出像素分布更均匀（std dev 增大） |
| UT-CE-02 | CLAHE tileSize=8 | 1080p 图片 | 无块边界伪影（双线性插值生效） |
| UT-SAT-01 | 饱和度 +50 | 红色像素(200,50,50) | HSL-S 增加，H 保持不变 |
| UT-SAT-02 | 自然饱和度 | 灰色像素(128,128,128) | 变化 < 高饱和像素的变化（(1-S)² 加权生效） |
| UT-WB-01 | Gray World 白平衡 | 偏黄图片 | R_avg≈G_avg≈B_avg（各通道均值趋于相等） |
| UT-WB-02 | White Patch 白平衡 | 含白色区域图片 | 白色区域像素趋向(255,255,255) |
| UT-CT-01 | 色温 3200K→6500K | 暖色图片 | 蓝色通道增益增加，红色通道增益降低 |
| UT-CT-02 | LUT 预计算 81 档 | 初始色温 2000K | `buildKelvinLUT` 返回 3 个 Uint8Array[256] |
| UT-LV-01 | 色阶黑场 50 | (25,128,230) | 25→0：(25-50)/(255-50)×255 映射到 0 |
| UT-LV-02 | 色阶白场 200 | (25,128,230) | 230→255：230/200×255 clamp 到 255 |
| UT-CV-01 | Catmull-Rom LUT 生成 | 3 个控制点 | LUT 曲线为 C1 连续（无折线拐点） |
| UT-CV-02 | 曲线通过所有控制点 | 控制点(64,192)、(128,128)、(192,64) | LUT[64]=192, LUT[128]=128, LUT[192]=64 |

<a id="sec-11"></a>
## 十一、缺陷分级

| 级别 | 定义 | 示例 |
|------|------|------|
| S0 — 阻断 | 编辑器无法加载或核心功能完全不可用 | 图片编辑器白屏、所有工具滑块无响应 |
| S1 — 严重 | 核心工具功能异常 | 亮度调整无效、导出图片全黑、裁剪后图片损坏 |
| S2 — 一般 | 单个工具边界情况 | 极端色温值（2000K/40000K）下 LUT 计算错误 |
| S3 — 轻微 | 体验问题 | 滑块拖动非平滑动画、预设名称截断 |
| S4 — 建议 | 优化建议 | 触控支持、预设拖拽排序 |

## 十二、自动化现状与缺口

### 12.1 自动化覆盖

| 模块 | 状态 | 用例数 | 说明 |
|------|------|--------|------|
| 算法单元测试（21 个工具） | 待扩展 | 当前 5，目标 45+ | 当前仅 5 个通用 TC，需按 §5 扩展至每个工具 2-4 个用例 |
| 渲染管线单元测试 | 待扩展 | 当前 0，目标 7 | 非破坏性编辑、参数合并、颜色空间往返精度 |
| Worker 集成测试 | 待实施 | 0 → 4 | jsdom 不支持 Worker，需 Vitest `pool: 'threads'` |
| 组件测试 | 待实施 | 0 → 12 | jsdom 环境，Canvas mock |
| chrome.storage 集成测试 | 待实施 | 0 → 3 | mock `chrome.storage.local` API |
| E2E 场景 | 手动验证 | 3 个场景 | Playwright 可自动化但需 Chrome 扩展测试环境 |

### 12.2 阻塞项

| # | 阻塞项 | 影响 | 解除条件 |
|---|--------|------|---------|
| 1 | Canvas API mock（jsdom 不支持 Canvas） | 组件测试和集成测试无法验证像素渲染 | 使用 `canvas` npm 包 mock，或切换到 `happy-dom` + `vitest-canvas-mock` |
| 2 | Web Worker mock（jsdom 不支持 Worker） | Worker 集成测试无法执行 | Vitest `pool: 'threads'` 或 `vitest-webworker` 插件 |
| 3 | chrome.storage API mock | 预设持久化测试无法执行 | `vitest-chrome` 或手动 mock |
