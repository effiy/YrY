# OpenSpec 工作流标准

> Claude Code 在 OpenSpec 项目中的行为规范。

---

## 一、Subagent 协作

| 阶段 | 模式 | 拆分策略 |
|------|------|----------|
| Proposal | 并行搜索 | 同时启动多个 Explore 子代理搜索代码模式、API、i18n、权限 |
| Design | 主代理独做 | 决策性强，不拆子代理 |
| Apply | 混合 | 无依赖的 task 并行实现，有依赖的串行 |
| Verify | 并行检查 | 同时启动子代理检查 i18n/规范一致性 |
| Land | 主代理独做 | 回写+commit 步骤短 |

## 二、代码质量（强制执行）

**动手前先思考**：列出假设，逐条验证。有更简单的方案则提出来。

**只写被要求的东西**：不要加没被要求的功能。200行能50行完成则重写。

**精准改动**：只改必要的，匹配现有风格，不改进无关代码。

**lint + typecheck 通过才算成功**。TypeScript 项目使用 ESLint + vue-tsc/tsc。

**禁止非通用性改动**：不写只适配特定输入值的逻辑，校验外部数据，处理边界情况。

## 三、上下文管理

**OpenSpec 阶段隔离**：所有阶段均由用户手动触发，不自动进入下一阶段。

**重构前清死代码**：未使用的 import/export 先删掉，单独提交，再做重构。

## 四、大规模任务处理

**200 行以上修改或显著架构变更必须走 OpenSpec**。

## 五、工具限制与编辑安全

**搜索要全**：用 Grep 搜内容，用 Glob 搜文件名。

**禁止脚本改文件**：修改源码文件只能使用内置编辑工具。

**不主动推送**：除非用户明确要求。

**中文回复**：用中文回复用户。
