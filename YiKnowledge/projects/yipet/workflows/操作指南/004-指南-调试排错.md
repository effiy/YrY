# 调试与排错指南

> YiPet Chrome 扩展调试完整指南：多环境控制台、常见问题诊断、IPC 消息追踪、性能分析、存储检查。

## 一、调试环境入口

YiPet 运行在 4 个独立环境中，每个有独立的 DevTools：

| 环境 | 打开方式 | 查看内容 |
|------|----------|----------|
| **Service Worker** | `chrome://extensions/` → 扩展卡片 → "Service Worker" | 后台日志、消息路由、快捷键处理 |
| **Content Script** | 页面 F12 → Console → 左上角下拉选 "Content Script" 上下文 | IPC 消息、注入日志、CDN 加载 |
| **Popup** | 右键扩展图标 → "检查弹出内容" | 皮肤中心日志、配置读写 |
| **MAIN World** | 页面 F12 → Console（默认 top frame） | 聊天逻辑、API 调用、Vue 组件 |

## 二、快速诊断命令

```js
window.__YIPET_LOADED__                              // 注入状态
document.querySelector("#yipet-chat-root")           // Vue 挂载点
window.__YIPET_CHAT_STORE__?.messages                // Chat Store
chrome.storage.local.get(null, console.log)          // 持久化数据（ISOLATED 上下文）
chrome.storage.local.clear()                         // 重置
```

## 三、常见问题排查

### 扩展不加载

**症状**：`chrome://extensions/` 显示错误

**排查步骤**：
1. 检查 `dist/` 目录是否存在：`ls YiPet/dist/`
2. 验证 `manifest.json` 格式：`cat dist/manifest.json | python3 -m json.tool`
3. 查看错误详情（扩展卡片上的红色错误提示）
4. 清除重建：`rm -rf dist && npm run build`

### 宠物不显示

**症状**：页面无浮动宠物

**排查链路**：
1. `window.__YIPET_LOADED__` → 检查 Content Script 是否注入
2. Network 面板过滤 `cdn/` → 检查 CDN 资源是否加载（找 404）
3. Content Script 控制台 → 查看 `[Bootstrap]` 日志
4. Service Worker 控制台 → 查看消息处理日志
5. `document.querySelector("#yipet-chat-root")` → 检查 DOM 挂载点

### 聊天窗口不响应

**症状**：Ctrl+Shift+X 无反应，或窗口打开但无法发送消息

**排查步骤**：
1. 确认 YiAi 运行：`curl http://localhost:10086/health`
2. Service Worker 控制台 → 检查快捷键事件
3. Content Script 控制台 → 检查 `chrome.runtime.onMessage` 日志
4. MAIN World 控制台 → 检查 `chatStore.isProcessing` 是否卡住
5. Network 面板 → 检查 `/` POST 请求（RPC 信封）

### API 调用失败

**症状**：消息发送失败，返回错误

**排查步骤**：
1. `curl http://localhost:10086/` → 验证 YiAi 可达
2. 检查 `RSBUILD_API_BASE` 环境变量
3. Service Worker 控制台 → Network 标签查看请求
4. 检查参数名：`filter`（非 `query`）、`target_file`（非 `path`）
5. 检查 Token：`chrome.storage.session.get('apiToken', console.log)`

### 热更新不生效

**症状**：修改代码后刷新无变化

**解决**：
1. 确认 `npm run dev`（watch 模式）
2. `chrome://extensions/` → 点击刷新按钮
3. 刷新目标页面
4. 如仍不生效：检查构建输出是否有 error

## 四、IPC 消息追踪

在 Content Script（ISOLATED World）控制台追踪跨世界消息：

```js
// 监听所有 chrome.runtime.onMessage
const orig = chrome.runtime.onMessage.addListener;
// 在 relay.ts 中添加: console.debug('[IPC]', msg.action, msg)

// 监听 CustomEvent（MAIN World）
window.addEventListener('yipet:visibilityChanged', (e) => {
  console.debug('[IPC MAIN] visibilityChanged', e.detail);
});
window.addEventListener('yipet:chatToggled', (e) => {
  console.debug('[IPC MAIN] chatToggled', e.detail);
});
```

## 五、存储检查

```js
// ISOLATED World 上下文
chrome.storage.local.get(null, console.log)     // 所有数据
chrome.storage.local.getBytesInUse(null, console.log)  // 配额使用量
chrome.storage.session.get('apiToken', console.log)    // Token

// 查看特定键
chrome.storage.local.get(['role', 'color', 'sessions', 'chatVisible'], console.log)
```

## 六、网络请求追踪

- **Service Worker 发起的请求**：`chrome://extensions/` → SW → Network 标签
- **Content Script 发起的请求**：页面 F12 → 选择 Content Script 上下文 → Network
- **MAIN World 发起的请求**：页面 F12 → Network（默认上下文）

## 七、构建问题

```bash
# 清除所有缓存和产物
rm -rf dist node_modules .rsbuild
npm install && npm run build

# 检查 Node 版本
node --version  # 需要 >= 16.18.0

# 类型检查
npm run typecheck

# 查看详细构建日志
npm run build -- --debug
```

## 八、性能分析

- **注入耗时**：Content Script 控制台记录 `[Bootstrap]` 时间戳
- **消息渲染**：MAIN World → Performance 标签 → 录制发送消息过程
- **存储写入**：`chrome.storage.local.set()` 耗时 > 10ms 需关注
- **SW 唤醒**：Service Worker 控制台记录 `onMessage` 到 `sendResponse` 耗时
