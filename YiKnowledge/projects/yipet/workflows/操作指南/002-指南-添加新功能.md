# 添加新功能

> 标准流程：功能类型判定 → 涉及的代码层 → 步骤清单 → 提交前检查。

## 速查：改动什么文件？

| 我要... | 修改/创建这些文件 |
|---------|------------------|
| 调一个新后端接口 | `api/types.ts` + `api/services/<Domain>Service.ts` + `api/index.ts` |
| 加一个聊天组件 | `chat/components/<Name>.vue` + `ChatWindow.vue` 引入 |
| 加一个 Popup 控件 | `popup/components/<Name>.vue` + `App.vue` 引入 |
| 改聊天状态逻辑 | `chat/stores/chat.ts`（Chat Store Actions） |
| 加一个 IPC 消息类型 | `shared/ipc/messages.ts` + `content/ipc/relay.ts` + `background/index.ts` |
| 加一个 Composable | `chat/composables/use<Name>.ts` + 组件中 import |
| 加国际化文本 | `public/_locales/en/messages.json` + `zh_CN/messages.json` + `shared/i18n/` MessageKey |
| 加 CDN 资源 | `public/cdn/vendor/` + `content/cdn/catalog.ts` CDN_CATALOG |
| 改 Chrome 权限 | `manifest.json` permissions/host_permissions |

## 一、功能类型判定

不同功能涉及不同代码层，先确定类型：

| 功能类型 | 涉及的层 | 复杂度 | 示例 |
|----------|----------|:---:|------|
| 新 API 调用 | `api/types.ts` + `api/services/` | 低 | 新增后端数据查询 |
| 聊天增强 | API + Chat Store + UI 组件 | 中 | 新聊天模式/消息操作 |
| Popup 功能 | `popup/components/` + `chrome.storage` | 中 | 设置页、快速操作 |
| 页面交互 | Content Script + MAIN World + DOM | 高 | 宠物新动画/页面注入 |
| 跨世界通信 | CS + SW + IPC Relay | 高 | 后台同步、通知 |

## 二、开发步骤

### 步骤 1：API 层（如需新接口）

- `src/api/types.ts` — 添加请求/响应类型
- `src/api/services/<Domain>Service.ts` — Service 类（构造注入 ApiClient）
- `src/api/index.ts` — `createApiServices` 注册

**关键约束**：参数名 `filter`（非 `query`）、`target_file`（非 `path`）、`cname`（非 `collection_name`）。优先复用 `DatabaseService` 通用 CRUD。

### 步骤 2：状态管理

| 功能范围 | 方案 |
|----------|------|
| 聊天相关 | 添加到 `chat/stores/chat.ts`（Chat Store） |
| Popup 独立 | `popup/stores/` 新建 Store |
| Content Script | `chrome.storage.local` + IPC 同步 |

**模式**：异步操作管理 `loading`/`error` 状态、`try/finally` 确保清理。

### 步骤 3：UI 组件

| 环境 | 位置 | 注意 |
|------|------|------|
| Chat Window | `src/chat/components/` | 通过 `useChatStore()` 访问状态 |
| Popup | `src/popup/components/` | 适配 400×500 最大尺寸 |
| Content Script | `src/content/` | CSS 前缀 `yipet-`、z-index ≤ 2147483646 |

**每个组件处理三种状态**：loading / empty / error。

### 步骤 4：双世界注册（如需 IPC）

- Content Script → `src/content/ipc/relay.ts` 添加消息处理
- Service Worker → `src/background/index.ts` 添加消息处理
- 消息类型 → `src/shared/ipc/messages.ts` 判别联合

### 步骤 5：安全审查

| 检查项 | 说明 |
|--------|------|
| innerHTML | 不直接从外部数据设置 |
| postMessage 验证 | `event.source === window` + IPC_SECRET |
| Token 安全 | 不存 sync，不经过消息通道 |
| CSP 合规 | 无远程代码、无 eval、无内联脚本 |
| 权限声明 | manifest.json 最小权限 |

### 步骤 6：验证

```bash
npm run typecheck   # tsc --noEmit 零错误
npm run build       # 多入口构建成功
npm test            # 所有测试通过
```

手动验证：至少 3 个不同页面（SPA、静态页、HTTPS）、Service Worker + Content Script 控制台无错误。

## 三、文件模板速查

```
# API 层（如需）
src/api/types.ts                          # 修改：添加类型
src/api/services/<Domain>Service.ts       # 新建：Service 类
src/api/index.ts                          # 修改：注册

# 状态管理
src/chat/stores/chat.ts                   # 修改：Chat Store（聊天功能）

# UI
src/chat/components/<Name>.vue            # 新建：Chat 组件
src/popup/components/<Name>.vue           # 新建：Popup 组件

# 双世界（如需）
src/content/ipc/relay.ts                  # 修改：消息处理
src/background/index.ts                   # 修改：消息处理
src/shared/ipc/messages.ts                # 修改：消息类型
```

## 四、提交前检查清单

- [ ] `typecheck` + `build` + `test` 全部通过
- [ ] 参数名遵循 RPC 契约
- [ ] API 调用通过 ApiClient（非直接 fetch）
- [ ] Chat 组件通过 Store Actions 操作状态
- [ ] Content Script CSS 使用 `yipet-` 前缀
- [ ] postMessage 有来源验证
- [ ] 处理 loading/empty/error 三种状态
- [ ] 组件卸载清理 AbortSignal 和事件监听
- [ ] 3 个以上不同页面验证通过
