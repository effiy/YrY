# 添加新功能

> 在 YiPet Chrome 扩展中添加新功能的完整 6 步标准流程。覆盖功能类型判定、API 层、Chat Store、双世界组件开发、权限与安全、测试验证的端到端指南。

## 前置条件

- 阅读 [YiPet/CLAUDE.md](../../CLAUDE.md) 了解项目约束和双世界执行模型
- 阅读 [RPC 协议规范](../../specs/开发规范/01-规范-API规范.md) 了解 API 层架构
- 理解 Chrome 扩展的双世界执行模型：Content Script（ISOLATED 世界）← IPC → Service Worker（后台）
- Node.js >= 18，Chrome >= 100

---

## 一、功能类型判定

不同功能类型涉及不同的项目层，先确定你的功能属于哪一类：

| 功能类型 | 涉及的层 | 典型示例 | 复杂度 |
|----------|----------|----------|--------|
| 新 API 调用 | API 层（types + endpoints + services） | 新增后端数据查询 | 低 |
| 聊天增强 | API + Chat Store + UI 组件 | 添加新的聊天模式/角色 | 中 |
| 弹窗功能 | Popup 组件 + chrome.storage | 设置页、快速操作面板 | 中 |
| 内容脚本交互 | Content Script + MAIN 世界 Bootstrap + DOM 注入 | 页面内宠物新动画/交互 | 高 |
| 跨世界通信 | Content Script + Service Worker + IPC | 后台同步、通知、下载 | 高 |

---

## 三、步骤详解

### 步骤 1：类型与服务定义

```typescript
// src/api/types.ts — 添加请求/响应接口

/** 查询功能列表参数 — 注意使用 filter 而非 query */
export interface MyFeatureQueryParams {
  filter?: Record<string, unknown>;
  page?: number;
  page_size?: number;
}

/** 功能列表项 */
export interface MyFeatureItem {
  key: string;
  name: string;
  status: "active" | "inactive" | "archived";
  created_at: string;
  updated_at: string;
}

/** 分页响应 */
export interface MyFeatureListResponse {
  list: MyFeatureItem[];
  total: number;
  page: number;
  page_size: number;
}
```

```typescript
// src/api/services/myFeatureService.ts — 服务类

import { ApiClient } from "../ApiClient";
import type {
  MyFeatureQueryParams,
  MyFeatureListResponse,
  MyFeatureItem,
} from "../types";

class MyFeatureService {
  private client: ApiClient;

  constructor() {
    this.client = new ApiClient();
  }

  /** 查询功能列表 */
  async queryFeatures(
    params: MyFeatureQueryParams
  ): Promise<MyFeatureListResponse> {
    return this.client.rpcCall("services.my_feature.my_feature_service", "query_my_features", {
      cname: "my_features",
      filter: params.filter ?? {},   // ← filter，非 query
      page: params.page ?? 1,
      page_size: params.page_size ?? 20,
    });
  }

  /** 创建功能 */
  async createFeature(payload: Record<string, unknown>): Promise<MyFeatureItem> {
    return this.client.rpcCall("services.my_feature.my_feature_service", "create_my_feature", {
      cname: "my_features",
      document: payload,
    });
  }

  /** 批量删除 */
  async deleteFeatures(keys: string[]): Promise<{ deleted_count: number }> {
    return this.client.rpcCall("services.my_feature.my_feature_service", "delete_my_features", {
      cname: "my_features",
      keys,
    });
  }
}

export const myFeatureService = new MyFeatureService();
```

**关键约束：**
- 所有 RPC 调用必须通过 `ApiClient.rpcCall()`，禁止直接 `fetch()`
- 参数名严格遵守 RPC 契约表（`filter` 非 `query`、`cname` 非 `collection_name`）
- `ApiClient` 自动处理 Token 注入、错误码转换、超时重试

### 步骤 2：API 端点（如需新端点路径）

通常情况下新功能复用现有 RPC 信封路径（`POST /`），不需要新增端点。仅在需要非 RPC 端点时添加：

```typescript
// src/api/endpoints.ts
export const ENDPOINTS = {
  // 现有端点...
  MY_FEATURE_EXPORT: "/my-feature/export",  // 非 RPC 端点
} as const;
```

### 步骤 3：Store / Controller

根据功能范围决定状态管理方式：

| 决策条件 | 方案 |
|----------|------|
| 聊天相关功能 | 添加到 Chat Store（`src/chat/store.ts`） |
| 弹窗独立功能 | 在 `src/popup/stores/` 创建新 Store |
| 内容脚本状态 | 通过 `chrome.storage.local` + IPC 同步 |

```typescript
// src/stores/myFeatureStore.ts
import { defineStore } from "pinia";
import { ref } from "vue";
import { myFeatureService } from "@/api/services/myFeatureService";
import type { MyFeatureItem } from "@/api/types";

export const useMyFeatureStore = defineStore("myFeature", () => {
  const items = ref<MyFeatureItem[]>([]);
  const total = ref(0);
  const loading = ref(false);
  const error = ref<string | null>(null);

  async function fetchItems(params: { filter?: Record<string, unknown>; page?: number; page_size?: number }) {
    loading.value = true;
    error.value = null;
    try {
      const res = await myFeatureService.queryFeatures(params);
      items.value = res.list;
      total.value = res.total;
    } catch (e) {
      error.value = e instanceof Error ? e.message : "加载失败";
      throw e;
    } finally {
      loading.value = false;
    }
  }

  async function deleteItems(keys: string[]) {
    const { deleted_count } = await myFeatureService.deleteFeatures(keys);
    items.value = items.value.filter((i) => !keys.includes(i.key));
    total.value -= deleted_count;
  }

  return { items, total, loading, error, fetchItems, deleteItems };
});
```

import { onMounted } from "vue";

#### 4.2 内容脚本组件（Content Script World）

内容脚本中的 Vue 组件需要特殊处理——它运行在 ISOLATED 世界中，CSS 隔离于宿主页面：

```vue
<!-- src/content/components/PetFeature.vue -->
<script setup lang="ts">
import { ref, onMounted, onUnmounted } from "vue";
import { sendToMain } from "@/content/ipc";

const props = defineProps<{
  petId: string;
  position: { x: number; y: number };
}>();

const isVisible = ref(false);

// 通过 IPC 向 Service Worker 请求数据
async function loadFeatureData() {
  const data = await sendToMain("getFeatureData", { petId: props.petId });
  return data;
}

// 向 MAIN 世界注入脚本（如需要宿主页面 API）
function injectMainWorld(action: string, params: unknown) {
  window.postMessage({
    source: "yipet-content",
    action,
    params,
  }, "*");
}

onMounted(() => {
  isVisible.value = true;
});

onUnmounted(() => {
  // 清理 DOM 注入和事件监听
});
</script>

<template>
  <div
    v-if="isVisible"
    class="yipet-feature"
    :style="{ left: position.x + 'px', top: position.y + 'px' }"
  >
    <!-- 宠物交互 UI —— 使用 Shadow DOM 样式隔离 -->
  </div>
</template>

<style scoped>
/* 使用唯一的类名前缀避免与宿主页面 CSS 冲突 */
.yipet-feature {
  position: fixed;
  z-index: 2147483646; /* Chrome 扩展最大安全 z-index */
  pointer-events: auto;
  /* 使用 CSS contain 限制重绘范围 */
  contain: layout style paint;
}
</style>
```

### 步骤 6：安全审查

Chrome 扩展有独特的安全风险，添加新功能时必须检查：

| 检查项 | 说明 | 风险等级 |
|--------|------|----------|
| innerHTML 使用 | 禁止从外部数据直接设置 innerHTML | CRITICAL |
| postMessage 来源验证 | 必须检查 event.origin 和 event.source | CRITICAL |
| chrome.storage 敏感数据 | 不在 storage 中存储 token/密钥明文 | HIGH |
| CSP 合规 | 确认 content_security_policy 允许新资源 | HIGH |
| 跨世界 IPC 校验 | Token/身份凭证不过 IPC 通道传输 | MEDIUM |
| 资源加载 | CDN 资源使用 integrity hash | MEDIUM |

```typescript
// 正确：postMessage 来源验证
window.addEventListener("message", (event) => {
  // 验证消息来源是当前窗口
  if (event.source !== window) return;
  // 验证消息来自我们自己的代码
  if (event.data?.source !== "yipet-content") return;
  // 安全处理消息
  handleMessage(event.data);
});

// 错误：不验证来源
window.addEventListener("message", (event) => {
  // 任意网页都可以发送消息！
  handleMessage(event.data);
});
```

## 四、检查清单（提交前）

### API 层
- [ ] 类型定义在 `src/api/types.ts` 中
- [ ] 服务类继承 `ApiClient`（非直接 `fetch`）
- [ ] RPC 参数名使用 `filter`（非 `query`）、`cname`（非 `collection_name`）

### 状态管理
- [ ] Store 使用 `defineStore` Setup 语法
- [ ] 异步操作管理 loading/error 状态
- [ ] chrome.storage 读写有 try/catch 错误处理

### 双世界
- [ ] Content Script 代码不访问 `window` 宿主属性（使用 MAIN 世界 Bootstrap）
- [ ] Service Worker 消息处理有超时机制
- [ ] IPC 消息类型定义清晰（`onMessage` / `sendToMain` 类型安全）

### UI
- [ ] 内容脚本 CSS 使用唯一前缀（避免与宿主页面冲突）
- [ ] 弹窗组件适配 400×500 最大尺寸
- [ ] z-index 使用安全值（2147483646 及以下）

### 安全
- [ ] 无 `innerHTML` 直接设置外部数据
- [ ] `postMessage` 有来源验证
- [ ] `chrome.storage` 无明文敏感数据

### 验证
- [ ] `npm run typecheck` 零错误
- [ ] `npm run build` 成功
- [ ] Service Worker + Content Script 控制台无错误
- [ ] 至少 3 个不同页面（SPA、静态页、HTTPS）验证通过

## 五、常见反模式

| 反模式 | 正确做法 | 原因 |
|--------|----------|------|
| 在 Content Script 中使用 `window.location` | 通过 `postMessage` 从 MAIN 世界获取 | ISOLATED 世界无法访问宿主 window |
| `document.querySelector` 使用通用选择器 | 使用以 `yipet-` 为前缀的唯一选择器 | 避免与宿主页面 DOM 冲突 |
| `chrome.storage.local.set` 不处理 `runtime.lastError` | 始终检查 `chrome.runtime.lastError` | 存储满时静默失败 |
| Content Script 直接 `fetch()` | 通过 `ApiClient` 或 IPC → SW → ApiClient | 统一错误处理、Token 注入、超时 |
| Popup 中直接 import 重依赖 | 弹窗 bundle 独立，不引入非必要依赖 | Popup 每次打开重新渲染 |
| MutationObserver 不 `disconnect` | `onUnmounted` 中调用 `disconnect()` | 内存泄漏 |
| z-index 使用 999999 | 使用 2147483646 | Chrome 最大安全值 |
