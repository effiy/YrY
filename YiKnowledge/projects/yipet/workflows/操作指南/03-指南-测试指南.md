# 测试指南

> YiPet Chrome 扩展测试策略：Vitest 单元测试、Chrome API Mock、测试分层、E2E 策略、CI 配置。

## 一、测试金字塔

```
        /\
       /E2E\         少量，覆盖核心流程（Playwright + Chrome）
      /------\
     /集成测试\       中等，跨模块交互（ApiClient + YiAi）
    /----------\
   / 单元测试 \      大量，纯逻辑（Vitest + jsdom）
  /--------------\
```

## 二、测试分层与策略

| 层 | 框架 | 模拟 | 覆盖目标 |
|----|------|------|----------|
| 单元 | Vitest + jsdom | chrome API mock | Store、ApiClient、IPC Relay、工具函数 |
| 集成 | Vitest + jsdom + mock fetch | 真实 ApiClient 逻辑 | API 调用链、跨模块交互 |
| E2E | Playwright + Chromium | 无（真实浏览器） | 注入 → 聊天 → 配置切换 |

**jsdom 不可测试**：Service Worker 生命周期、Content Script 注入、CSP 验证、真实 storage 性能、键盘快捷键冲突。这些需 Playwright 或手动验证。

## 三、Chrome API Mock

```typescript
// tests/mocks/chrome.ts — 全局注入
Object.defineProperty(globalThis, 'chrome', {
  value: {
    storage: {
      local: { get: vi.fn(), set: vi.fn(), remove: vi.fn(), clear: vi.fn() },
    },
    runtime: {
      getURL: vi.fn(p => `chrome-extension://test/${p}`),
      sendMessage: vi.fn(),
      onMessage: { addListener: vi.fn(), removeListener: vi.fn() },
    },
    tabs: { query: vi.fn(), sendMessage: vi.fn() },
    i18n: { getMessage: vi.fn(k => k) },
  },
  writable: true,
});
```

## 四、关键测试场景

| 模块 | 必测场景 |
|------|----------|
| Chat Store | 初始状态、空消息拒绝、isProcessing 并发防护、会话创建/切换/删除、流式错误恢复 |
| ApiClient | RPC 信封组装、HTTP 错误处理、业务错误码、网络错误、AbortError 静默 |
| IPC Relay | 缺少 `__yipet` 标记拒绝、签名不匹配拒绝、5s 过期拒绝、合法消息接受 |
| Bootstrap | `__YIPET_LOADED__` 短路、重复注入防护 |

## 五、测试命令

```bash
npm test                    # 单元测试
npm test -- --coverage      # 带覆盖率
npm test -- --watch         # 监听模式
npm test -- tests/api/      # 特定目录
npm run typecheck           # 类型检查
```

## 六、覆盖率目标

| 模块 | 目标 |
|------|------|
| `api/` | ≥ 80% |
| `stores/` | ≥ 80% |
| `content/ipc/` | ≥ 90% |
| `popup/components/` | ≥ 60% |
| `shared/utils/` | ≥ 85% |

## 七、CI 流水线

```yaml
# steps: checkout → npm ci → typecheck → lint → test --coverage → build
```

## 八、约束

**必须遵守**：新增功能必须有对应单测、ApiClient 请求/响应类型测试、IPC Relay 安全测试、提交前 `npm test` 通过。

**禁止**：测试中硬编码时间（用 `vi.useFakeTimers`）、真实网络请求、跳过类型检查提交。
