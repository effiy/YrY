# 错误处理模式

> YiPet 错误处理：分层处理（ApiClient → Store → Component → Bootstrap）、重试策略、降级方案、用户反馈、错误恢复。

**核心原则**：错误对用户可见（不静默）、提供恢复路径（重试/降级/刷新）、分层处理各有职责、非关键失败不阻塞核心功能。

**相关文档**：[API 架构](./05-规范-API架构与规范.md) · [Chat Store](../功能模式/01-模式-ChatStore状态管理.md)

## 一、错误分类

### 按严重度

| 级别 | 定义 | 处理 |
|------|------|------|
| **Critical** | 扩展不可用 | 错误横幅 + 刷新提示 |
| **Major** | 核心功能不可用 | 自动重试 + 错误提示 |
| **Minor** | 功能受损可继续 | 降级运行 + 控制台警告 |
| **Trivial** | 视觉瑕疵 | 静默 |

### 按层级

| 层 | 职责 | 错误类型 |
|----|------|----------|
| ApiClient | HTTP 通信 | 网络错误、超时、HTTP 错误码、业务错误码 → `ApiResponse{ok:false}` |
| Chat Store | 业务逻辑 | 状态不一致、并发冲突 → 状态回滚 + 错误标记 |
| Component | UI 渲染 | 渲染异常 → 错误边界 + 降级 UI |
| Bootstrap | 注入流程 | 资源加载失败 → 重试 + 降级 |

## 二、分层策略

### ApiClient 层

不抛异常，所有错误通过 `ApiResponse<T>` 表示。调用方检查 `ok` 字段。

### Store 层

保留 AbortError 身份（用户取消静默），其他错误标记消息 `error` + `retryable`，finally 中清理 `isProcessing` + 持久化。

### Component 层

每个数据组件处理 loading/empty/error 三态。错误状态显示用户可理解的消息 + 重试按钮。

### Bootstrap 层

关键资源失败 → 放弃注入、清除 `__YIPET_LOADED__` 允许重试。非关键资源失败 → 降级运行（如无 Bootstrap 仍可用聊）。

## 三、重试策略

| 错误场景 | 重试 | 理由 |
|----------|:---:|------|
| 网络错误（fetch 抛出） | ✓ | 网络波动 |
| HTTP 4xx/5xx | ✗ | 重试无效 |
| 业务错误（code ≠ 0） | ✗ | 业务逻辑错误 |
| 请求超时 | ✗ | 直接返回 |
| AbortError | ✗ | 用户取消 |

重试方式：线性退避 `baseMs * (attempt + 1)`，仅 base client 层处理，默认不启用。

## 四、降级层级

| 级别 | 场景 | 表现 |
|------|------|------|
| 0 | 全部正常 | 所有功能可用 |
| 1 | 非关键资源失败 | 无 UI 组件库/样式，核心功能可用 |
| 2 | 后端不可达 | 自动重试 + 错误提示 + 本地缓存降级 |
| 3 | 致命错误 | 错误横幅 + 刷新提示 |

## 五、用户反馈

| 类型 | 场景 | UI |
|------|------|-----|
| Toast | 操作成功/失败 | 右上角弹出，3s 消失 |
| 内联错误 | 消息发送失败 | 气泡内错误横幅 + 重试按钮 |
| 横幅 | 扩展加载失败 | 右下角黄色横幅 |
| 状态指示 | 重连/加载中 | Loading + 文字 |
| 空状态 | 无数据 | EmptyState 组件 |

**错误消息指南**：用户可理解的语言（非技术术语）、明确下一步操作、不暴露内部细节。

| 技术错误 | 用户消息 |
|----------|----------|
| `TypeError: Failed to fetch` | "网络连接失败，请检查网络后重试" |
| `HTTP 401` | "登录已过期，请刷新页面重新登录" |
| `QuotaExceededError` | "存储空间不足，请清理浏览器数据" |
| `SSE stream closed` | "AI 回复中断，请重试" |

## 六、错误恢复

| 场景 | 自动恢复 | 手动恢复 |
|------|----------|----------|
| 网络恢复 | SSE 自动重连（最多 3 次） | 重试按钮 |
| API 恢复 | 指数退避重试 | 重试按钮 |
| Token 过期 | — | 刷新页面登录 |
| 资源加载 | 重试 3 次 | 刷新页面 |

## 七、反模式

| 反模式 | 正确做法 | 原因 |
|--------|----------|------|
| 静默吞错误 | 至少 `console.error` + 用户提示 | 用户不知道出问题 |
| 技术错误消息 | "网络连接失败" 非 "ENOTFOUND" | 用户无法理解 |
| 所有错误都重试 | 401/403/404 不重试 | 浪费资源 |
| 无降级方案 | 非关键失败降级运行 | 核心功能可用 |
| 错误状态不清理 | 成功后清除 | 用户困惑 |

## 八、约束

**必须遵守**：错误对用户可见、消息用用户语言、区分可重试/不可重试、关键失败显示横幅、非关键失败降级、组件卸载清理错误状态。

**禁止**：静默吞错误、暴露技术细节、对不可重试错误重试、错误状态永久残留、跳过 ApiClient 错误处理层。
