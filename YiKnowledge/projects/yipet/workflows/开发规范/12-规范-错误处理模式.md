# Pattern: 错误处理

> YiPet 错误处理完整模式：错误分类、重试策略、降级方案、用户反馈、错误恢复、全局错误边界、反模式。

## 概述

YiPet 作为浏览器扩展，运行在不可控的页面环境中，需要处理多种错误场景：网络中断、API 不可用、资源加载失败、跨世界通信失败、存储配额超限、Chrome API 异常等。

**核心原则**：
- 错误应对用户可见（不静默失败）
- 提供恢复路径（重试、降级、刷新）
- 分层处理（ApiClient、Store、Component 各有职责）
- 不阻塞核心功能（降级优先）

- [API 规范](./开发规范/01-API规范.md)

## 一、错误分类

### 按严重度

| 严重度 | 定义 | 示例 | 处理方式 |
|--------|------|------|----------|
| **Critical** | 扩展完全不可用 | 关键资源加载失败、Token 泄露 | 显示错误横幅 + 刷新提示 |
| **Major** | 核心功能不可用 | API 不可达、SSE 断连、SW 消息丢失 | 自动重试 + 错误提示 |
| **Minor** | 功能受损但可继续 | 参数名错误、非关键资源加载失败 | 降级运行 + 控制台警告 |
| **Trivial** | 视觉瑕疵 | 样式异常、动画卡顿 | 静默处理 |

### 按层级

| 层级 | 负责 | 错误类型 | 处理方式 |
|------|------|----------|----------|
| ApiClient | HTTP 通信 | 网络错误、超时、HTTP 错误码、业务错误码 | 重试 + 错误映射 |
| Chat Store（Pinia）| 业务逻辑 | 状态不一致、操作冲突、数据校验失败 | 状态回滚 + 错误标记 |
| Component | UI 渲染 | 渲染异常、Prop 类型错误 | 错误边界 + 降级 UI |
| Bootstrap | 注入流程 | 资源加载失败、DOM 注入失败 | 重试 + 用户提示 |

## 二、分层错误处理

### Layer 1: ApiClient 层

```typescript
// ApiClient 返回统一的 ApiResponse，不抛出异常
interface ApiResponse<T> {
  ok: boolean;       // true = 成功
  status: number;    // HTTP 状态码（0 = 网络错误）
  data: T;           // 业务数据
  error?: string;    // 错误消息（ok=false 时）
}

// RPC 调用 — 解包 YiAi 信封 {code, message, data}
async function rpc<T>(moduleName, methodName, parameters, signal): Promise<ApiResponse<T>> {
  try {
    const response = await fetch(url, { body: JSON.stringify({ module_name, method_name, parameters }) });
    const json = await response.json();
    return unwrapEnvelope<T>(json, response.status);
  } catch (err) {
    if ((err as Error).name === 'AbortError') {
      return { ok: false, status: 0, data: null, error: 'Request timed out or was aborted' };
    }
    return { ok: false, status: 0, data: null, error: (err as Error).message || 'Network error' };
  }
}

// 信封解包
function unwrapEnvelope<T>(json: unknown, httpStatus: number): ApiResponse<T> {
  if (json && typeof json === 'object' && 'code' in json) {
    const envelope = json as { code: number; message: string; data: T };
    return {
      ok: envelope.code === 0,
      status: httpStatus,
      data: envelope.data as T,
      error: envelope.code !== 0 ? envelope.message : undefined,
    };
  }
  return { ok: httpStatus >= 200 && httpStatus < 300, status: httpStatus, data: json as T };
}
```

**关键设计决策**：ApiClient 不抛出异常，所有错误通过 `ApiResponse.ok === false` 表示。调用方通过检查 `ok` 字段判断成功/失败，无需 try/catch。

### Layer 2: Store 层

```typescript
// Chat Store（Pinia）中的错误处理 + 状态回滚
async function sendMessage(text: string): Promise<void> {
  if (isProcessing.value) {
    console.warn("[ChatStore] 消息发送中，拒绝并发发送");
    return;
  }

  try {
    isProcessing.value = true;
    streamingType.value = "send";

    const stream = api.client.stream('/rag-chat', body, streamAbort.signal);
    for await (const chunk of stream) {
      if (chunk.done) {
        if (chunk.error) handleError(chunk.error);
        break;
      }
      appendToken(chunk.data);
    }
  } catch (err) {
    // 区分 AbortError（用户取消）vs 真实错误
    if ((err as Error).name === 'AbortError') return;
    const lastMsg = messages.value[messages.value.length - 1];
    if (lastMsg?.type === 'pet') {
      lastMsg.error = (err as Error).message || '发生未知错误';
      lastMsg.aborted = true;
    }
  } finally {
    isProcessing.value = false;
    streamingType.value = '';
    streamingPhase.value = '';
    await _persistSession();
  }
}
```

## 三、重试策略

### 线性退避（Base Client）

```typescript
// public/cdn/utils/api-client.ts — 仅网络错误时重试
async function request<T>(method, path, body?, signal?, attempt = 0): Promise<ApiResponse<T>> {
  try {
    const response = await fetch(url, init);
    // HTTP 错误不重试，直接返回 ApiResponse
    return { ok: response.ok, status: response.status, data, error: ... };
  } catch (err) {
    // 仅 fetch 抛出的网络错误触发重试
    if (retry && attempt < retry.maxRetries) {
      await new Promise((r) => setTimeout(r, retry.baseMs * (attempt + 1)));
      return request<T>(method, path, body, signal, attempt + 1);
    }
    return { ok: false, status: 0, data: null, error: (err as Error).message };
  }
}
```

**重试要点**：
- **仅重试网络错误**（fetch 抛出），不重试 HTTP 错误状态码
- **线性退避**：`baseMs * (attempt + 1)`，默认 `baseMs = 1000`
- **默认不启用**：仅当 `config.retry` 传入时才重试
- Extension client 的 `rpc` 方法不额外重试

### 可重试 vs 不可重试

| 错误场景 | 是否重试 | 理由 |
|----------|----------|------|
| 网络错误（fetch 抛出） | 是（base client） | 网络波动，短暂恢复 |
| HTTP 4xx/5xx | 否 | 重试无效，需修复请求或等待服务恢复 |
| 业务错误（`code !== 0`） | 否 | 业务逻辑错误，重试无效 |
| 请求超时（AbortController） | 否 | Extension client 直接返回错误 |
| `AbortError`（用户取消） | 否 | 用户主动取消 |

## 四、降级策略

### 降级层级

```
Level 0: 完全可用（所有功能正常）
  └── Level 1: 部分降级（非关键资源失败）
      ├── Bootstrap 等 UI 库加载失败 → 聊天窗口仍可用（无 UI 组件库）
      ├── 宠物样式加载失败 → 宠物仍显示（默认样式）
      └── 知识库缓存失效 → 重新从后端加载
  └── Level 2: 核心降级（后端不可达）
      ├── YiAi 不可达 → 自动重试 + 错误提示
      ├── SSE 断连 → 自动重连 + 断点续传
      └── 会话加载失败 → 使用 chrome.storage 本地缓存
  └── Level 3: 致命错误（扩展不可用）
      ├── Vue 运行时加载失败 → 显示错误横幅 + 刷新提示
      ├── Content Script 注入失败 → 清除标志 + 允许重试
      └── chrome.storage 不可用 → 提示用户检查扩展权限
```

### 降级实现

```typescript
interface DegradationState {
  level: 0 | 1 | 2 | 3;
  failedResources: string[];
  canRetry: boolean;
}

class DegradationManager {
  private state: DegradationState = { level: 0, failedResources: [], canRetry: true };

  reportFailure(resource: string, critical: boolean): void {
    this.state.failedResources.push(resource);

    if (critical) {
      this.state.level = Math.max(this.state.level, 3) as DegradationState["level"];
    } else if (this.state.level < 2) {
      this.state.level = 1;
    }
  }

  getDegradationBanner(): string | null {
    switch (this.state.level) {
      case 1: return "部分功能不可用，核心功能正常";
      case 2: return "AI 服务暂时不可用，正在重试...";
      case 3: return "扩展加载失败，请刷新页面";
      default: return null;
    }
  }
}
```

## 五、用户反馈模式

### 反馈类型

| 类型 | 场景 | UI 组件 | 持续时间 |
|------|------|---------|----------|
| Toast 通知 | 操作成功/失败 | 右上角弹出 | 3 秒自动消失 |
| 内联错误 | 消息发送失败 | 消息气泡内错误横幅 | 直到用户操作 |
| 横幅提示 | 扩展加载失败 | 页面右下角黄色横幅 | 直到页面刷新 |
| 状态指示 | 重连中/加载中 | Loading 动画 + 文字 | 操作完成时消失 |
| 空状态 | 无数据 | EmptyState 组件 | 永久（直到有数据） |

### 错误消息指南

- 使用用户能理解的语言（非技术术语）
- 提供明确的下一步操作（重试/刷新/检查网络）
- 区分临时错误和永久错误
- 不暴露内部实现细节（如 API 路径、错误堆栈）

| 技术错误 | 用户消息 |
|----------|----------|
| `TypeError: Failed to fetch` | "网络连接失败，请检查网络后重试" |
| `HTTP 401 Unauthorized` | "登录已过期，请刷新页面重新登录" |
| `QuotaExceededError` | "存储空间不足，请清理浏览器数据" |
| `SSE stream closed` | "AI 回复中断，请重试" |

## 六、全局错误边界

### Vue 错误边界

```vue
<!-- ErrorBoundary.vue -->
<script setup lang="ts">
import { ref, onErrorCaptured } from "vue";

const error = ref<Error | null>(null);

onErrorCaptured((err, instance, info) => {
  error.value = err as Error;
  console.error("[ErrorBoundary]", err, info);
  return false; // 阻止错误继续传播
});

function retry(): void {
  error.value = null;
}
</script>

<template>
  <div v-if="error" class="error-boundary">
    <h3>出现了一些问题</h3>
    <p>{{ error.message }}</p>
    <button @click="retry">重试</button>
    <button @click="() => location.reload()">刷新页面</button>
  </div>
  <slot v-else />
</template>
```

## 七、错误恢复

### 恢复策略

| 场景 | 自动恢复 | 手动恢复 | 恢复后行为 |
|------|----------|----------|-----------|
| 网络恢复 | 自动重连 SSE | — | 从断点继续流式响应 |
| API 恢复 | 指数退避重试 | 重试按钮 | 重新发送请求 |
| Token 过期 | — | 刷新页面 → 重新登录 | 恢复所有功能 |
| 资源加载失败 | 重试 3 次 | 刷新页面 | 重新注入 |
| 存储配额恢复 | 自动清理缓存 | 手动清理 | 恢复持久化写入 |

### 恢复状态追踪

```typescript
interface RecoveryState {
  attempt: number;
  maxAttempts: number;
  lastAttemptTime: number;
  strategy: "automatic" | "manual";
  recovered: boolean;
}

class RecoveryTracker {
  private recoveries = new Map<string, RecoveryState>();

  track(id: string, maxAttempts: number): void {
    this.recoveries.set(id, {
      attempt: 0,
      maxAttempts,
      lastAttemptTime: Date.now(),
      strategy: "automatic",
      recovered: false,
    });
  }

  canRetry(id: string): boolean {
    const state = this.recoveries.get(id);
    if (!state) return false;
    return state.attempt < state.maxAttempts && !state.recovered;
  }

  markRecovered(id: string): void {
    const state = this.recoveries.get(id);
    if (state) state.recovered = true;
  }

  switchToManual(id: string): void {
    const state = this.recoveries.get(id);
    if (state) state.strategy = "manual";
  }
}
```

## 八、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 静默吞掉错误 | `try { ... } catch {}` | 至少 `console.error` + 用户提示 | 用户不知道出了问题 |
| 错误消息不友好 | `throw new Error("ENOTFOUND")` | 返回 `ApiResponse` 带 `error: "网络连接失败"` | 用户无法理解 |
| 不区分可重试错误 | 所有错误都重试 | 401/403/404 不重试 | 无效重试浪费资源 |
| 无降级方案 | CDN 加载失败 → 整个注入失败 | 非关键资源失败 → 降级运行 | 核心功能可用 |
| 错误状态不清理 | 错误提示永久显示 | 成功操作后清除错误状态 | 用户困惑 |
| 不记录错误上下文 | `console.error(error.message)` | `console.error("[ApiClient]", { url, status, body }, error)` | 难以排查 |

## 九、约束

### 必须遵守
- 所有错误必须对用户可见（不静默失败）
- 错误消息使用用户能理解的语言
- 区分可重试和不可重试错误
- 关键资源失败 → 显示错误横幅
- 非关键资源失败 → 降级运行
- SSE 断连 → 自动重连（最多 3 次）
- 组件卸载时清理错误状态

### 禁止
- 不静默吞掉错误（空 catch 块）
- 不向用户暴露技术细节（堆栈、API 路径）
- 不对不可重试错误进行重试（401/403/404）
- 不让错误状态永久残留
- 不跳过 ApiClient 的错误处理层
