# 项目规范

> YiPet 编码规范、命名约定、代码质量门禁、提交规范、文件组织、TypeScript 规则、代码审查清单。

## 一、组件风格

```vue
<script setup lang="ts">
// src/chat/components/ExampleComponent/index.vue
import { ref, computed } from "vue";
import type { Message } from "@/chat/types";

interface Props {
  data?: Message;
  isEdit?: boolean;
}

const props = withDefaults(defineProps<Props>(), { isEdit: true });
const emit = defineEmits<{
  (event: "update", value: Message): void;
}>();

const loading = ref(false);

const isDisabled = computed(() => !props.isEdit);

function handleClick() {
  loading.value = true;
  // ...
}
</script>

<template>
  <div class="example-component">
    <!-- 模板内容 -->
  </div>
</template>

<style lang="scss" scoped>
.example-component { /* 样式 */ }
</style>
```

### 编码规则

| 领域 | 标准 | 反模式 |
|------|------|--------|
| 组件风格 | `<script setup lang="ts">` + Composition API | Options API、Class 组件 |
| Props | `defineProps<{...}>()` 泛型 + `withDefaults` | `PropTypes`、运行时类型检查 |
| 状态管理 | Pinia Store + 操作分发 | 组件内直接调用 API |
| 样式 | `scoped` SCSS，BEM 命名 | 内联样式（动态值除外）、全局样式污染 |
| Element Plus | `el-*` 组件，图标从 `@element-plus/icons-vue` 导入 | 自定义同名的 el- 类名 |
| 路径导入 | 跨模块使用 `@/` 别名，同级使用相对路径 | 深层相对路径 `../../../` |
| 类型导入 | 仅类型使用 `import type`，值和类型混合使用 `import { x, type Y }` | 运行时导入类型 |

## 二、命名约定

| 约定 | 适用范围 | 示例 |
|------|----------|------|
| PascalCase | 组件、类型/接口、Service 类 | `ChatWindow`, `MessageBubble`, `ApiClient`, `BugService` |
| camelCase | 函数、变量、Store 操作 | `sendMessage`, `currentSessionId`, `useChatStore` |
| kebab-case | CSS 类名、文件路由 | `.chat-window`, `.mb-token-chip` |
| UPPER_SNAKE_CASE | 常量、枚举值 | `DEFAULT_MODEL`, `MIN_HEIGHT`, `INPUT_RATE_PER_1K` |
| snake_case | RPC 信封字段（与 YiAi 后端契约） | `module_name`, `method_name`, `target_file` |

### 文件命名

| 文件类型 | 命名规则 | 示例 |
|----------|----------|------|
| Vue 组件 | PascalCase 目录 + `index.vue` | `ChatWindow/index.vue` |
| 组件样式 | 与组件同名 + `scoped` | `ChatWindow/index.vue`（`<style scoped>`） |
| Store | camelCase | `stores/chat.ts` |
| 类型文件 | camelCase | `types.ts` |
| API Service | PascalCase + `Service` | `ChatService.ts`, `KnowledgeService.ts` |
| API 核心 | camelCase | `client.ts`, `endpoints.ts` |
| 工具函数 | camelCase | `datetime.ts`, `url.ts` |
| 配置文件 | camelCase | `catalog.ts`, `injector.ts` |
| 入口文件 | camelCase | `bootstrap.ts` |

## 三、TypeScript 规则

### 类型定义

```typescript
// 接口用于对象形状
interface ChatState {
  messages: Message[];
  currentSessionId: string | null;
  isProcessing: boolean;
  knowledgeGrounded: boolean;
}

// 类型别名用于联合类型、交叉类型
type StreamingType = "send" | "regenerate" | "resend";
type ApiResponse<T> = { code: number; message: string; data: T };

// 枚举用于有穷值的常量集合
enum BugSeverity {
  CRITICAL = "critical",
  MAJOR = "major",
  MINOR = "minor",
  TRIVIAL = "trivial"
}
```

### 类型安全

```typescript
// 使用 const 断言获得字面量类型
const ALLOWED_MESSAGE_TYPES = ["DISCUSS_PAGE", "OPEN_CHAT", "SUBMIT_BUG"] as const;

// 使用类型收窄避免 as 断言
function processValue(value: string | number) {
  if (typeof value === "string") {
    return value.toUpperCase(); // 此处 value 自动收窄为 string
  }
  return value.toFixed(2); // 此处 value 自动收窄为 number
}

// 使用 ?? 和 ?. 安全访问
const pageTitle = pageInfo?.title ?? "Unknown Page";

// Store 操作使用明确类型签名
interface ChatOperations {
  sendMessage(text: string): Promise<void>;
  stopSending(): void;
  selectSession(id: string): void;
}
```

### 禁止模式

| 禁止 | 替代方案 | 原因 |
|------|----------|------|
| `any` | `unknown` + 类型收窄 | `any` 关闭类型检查 |
| `as` 类型断言 | 类型收窄 | `as` 绕过类型检查 |
| `@ts-ignore` | 修复类型错误 | 掩盖真实问题 |
| 隐式 `any` 参数 | 显式类型注解 | 丢失类型安全 |
| `!` 非空断言 | `?.` 或 `??` 安全检查 | 运行时可能抛出错误 |

## 七、架构约束

### 必须遵守

- **4-Tier API 架构** — 所有 API 调用通过 ApiClient → Endpoints → Types → Services 层
- **禁止直接 fetch** — 不绕过 ApiClient 直接调用 fetch
- **RPC 信封格式** — 使用 `{ module_name, method_name, parameters }` 格式
- **参数名契约** — 使用 `filter`（非 `query`）、`target_file`（非 `path`）、`cname`（非 `collection_name`）
- **双世界边界** — MAIN World 不调用 chrome.* API，ISOLATED World 不操作页面 DOM
- **Pinia Store 模式** — 聊天状态通过 Pinia store 管理
- **就近放置 CSS** — 组件 CSS 与组件同目录
- **MV3 CSP 合规** — 所有 vendor 库本地化，无远程代码加载

### 禁止

- 不在组件中直接调用 `fetch` 或操作 chrome.storage
- 不在 API Service 层之外组装 RPC 信封
- 不在 MAIN World 代码中调用 `chrome.runtime.*` API
- 不在 ISOLATED World 代码中直接操作页面 DOM
- 不使用 `any` 类型（除非有充分理由并注释说明）
- 不为单次使用创建抽象层
- 不添加未要求的功能
- 不使用 `eval` 或 `new Function`（MV3 CSP 禁止）

## 八、双世界执行模型规范

### 8.1 世界边界

Chrome MV3 Content Script 运行在两个隔离的 JavaScript 世界中：

```
MAIN World (宿主页面环境)
  ├── 访问宿主页面 window 全局变量
  ├── 操作宿主页面 DOM（同一 DOM 树，不同 JS 上下文）
  ├── 加载外部 CDN 资源（Vue、Element Plus 等）
  ├── 禁止：chrome.* API、extension resources
  └── 通信：window.postMessage → ISOLATED World

ISOLATED World (Content Script 环境)
  ├── 访问 chrome.* API（runtime、storage、tabs）
  ├── 发起网络请求（fetch → YiAi 后端）
  ├── 管理扩展状态
  ├── 禁止：宿主页面 JS 变量、CDN 全局变量
  └── 通信：window.postMessage → MAIN World
```

### 8.2 跨世界 IPC 通信模式

```typescript
// ISOLATED World → MAIN World
// content/bootstrap.ts（ISOLATED World）
export function injectMainWorld(config: PetConfig) {
  window.postMessage(
    {
      source: "yipet-isolated",
      action: "initPet",
      payload: config,
      __signature: IPC_SECRET,
      __timestamp: Date.now(),
    },
    "*" // 同窗口内通信，不跨域
  );
}

// MAIN World → ISOLATED World
// cdn/main-bootstrap.ts（MAIN World 动态注入）
window.addEventListener("message", (event) => {
  // 安全验证
  if (event.source !== window) return;
  if (!event.data?.__yipet) return;
  if (event.data?.__signature !== IPC_SECRET) return;
  if (Date.now() - event.data?.__timestamp > 5000) return; // 5 秒过期

  // 安全处理消息
  handleIsolatedMessage(event.data);
});
```

### 8.3 双世界编码规则

| 规则 | 适用世界 | 违反后果 |
|------|----------|----------|
| 不在 MAIN 世界调用 `chrome.runtime.sendMessage()` | MAIN | TypeError: chrome is not defined |
| 不在 MAIN 世界使用 `chrome.runtime.getURL()` | MAIN | 资源 404 |
| 不在 ISOLATED 世界访问 `window.myAppData` | ISOLATED | undefined（两个世界的 window 属性不共享） |
| DOM 操作在两世界均可进行 | 两者 | 注意避免竞争条件 |
| 通过 `postMessage` 传递的数据必须可序列化 | 两者 | DataCloneError |

## 九、Chrome 扩展安全规范

### 9.1 CSP 合规

```json
// manifest.json — Content Security Policy
{
  "content_security_policy": {
    "extension_pages": "script-src 'self'; object-src 'self'"
  }
}
```

**禁止项（MV3 CSP 强制）：**
- ❌ `eval()`、`new Function()`、`setTimeout(string)`
- ❌ 内联 `<script>` 标签（nonce-based 除外）
- ❌ 加载远程 JS 文件（CDN 第三方库需本地化）
- ❌ `javascript:` URL

**CDN 库本地化处理：**
```typescript
// 所有外部依赖通过 npm 安装，打包到 dist/
// 不通过 CDN 动态加载 JS 文件
import { marked } from "marked";           // ✓ npm 包
// <script src="https://cdn.jsdelivr.net/npm/marked@18"> // ✗ 被 CSP 阻止
```

### 9.2 敏感数据处理

```typescript
// 正确：使用 chrome.storage.local（扩展隔离存储）
await chrome.storage.local.set({
  sessionKey: sessionKey,      // Token 存储
  userPreferences: preferences,
});

// 错误：使用 localStorage（与宿主页面共享）
localStorage.setItem("sessionKey", sessionKey);  // 可能被宿主页面读取

// 正确：敏感数据加密后存储
import { encrypt } from "@/utils/crypto";
await chrome.storage.local.set({
  sessionKey: encrypt(sessionKey),
});
```

### 9.3 host_permissions 规范

```json
// manifest.json — 最小化主机权限
{
  "host_permissions": [
    "http://localhost:10086/*",    // 开发环境 YiAi 后端
    "https://api.example.com/*"    // 生产环境 YiAi 后端
    // 不添加 <all_urls>，除非宠物需要在所有页面显示
  ]
}
```

使用 `activeTab` 替代 `<all_urls>` 以减少权限范围（如适用）。

## 十、Chrome 扩展性能规范

### 10.1 Content Script 性能约束

| 约束 | 说明 | 阈值 |
|------|------|------|
| 注入时间 | 不应阻塞宿主页面加载 | < 50ms |
| CSS 注入 | 动画使用 `transform`/`opacity`，触发 Composite 而非 Layout | — |
| DOM 监听 | MutationObserver 使用 `subtree: false` 或限定范围 | — |
| 空闲检查 | 非活动标签页冻结动画和网络请求 | 5 秒无活动 |

### 10.2 Service Worker 生命周期规范

```typescript
// Service Worker 随时可能被 Chrome 终止
// 必须持久化所有重要状态

// 正确：状态写入 storage
async function handleMessage(message: Message) {
  const state = await chrome.storage.local.get("appState");
  // 处理消息
  await chrome.storage.local.set({ appState: updatedState });
}

// 错误：依赖内存状态
let inMemoryState = {};  // SW 重启后丢失！
```

### 10.3 内存使用限制

| 资源 | 限制 | 降低使用策略 |
|------|------|-------------|
| Storage | 10 MB（local） | LRU 清理旧会话、压缩存储 |
| Service Worker 内存 | ~100 MB | 避免大对象缓存 |
| Content Script 内存 | 共享宿主页面配额 | 及时清理 observer/event listener |
