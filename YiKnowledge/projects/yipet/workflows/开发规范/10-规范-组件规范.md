# 组件规范

> YiPet Vue 3 组件体系完整规范：Chat Window 组件群、Popup 组件群、Floating Pet 渲染组件、组件文件组织、Props/Emits 约定、Pinia Store 集成模式、跨世界组件通信、反模式。

## 一、组件体系总览

### 2.4 ChatInput（输入框）

多行输入组件，支持发送和停止两种状态：

```vue
<script setup lang="ts">
import { ref, computed } from "vue";

const props = defineProps<{
  disabled: boolean;
  isProcessing: boolean;
}>();

const emit = defineEmits<{
  send: [text: string];
  stop: [];
}>();

const text = ref("");
const textareaRef = ref<HTMLTextAreaElement>();

const canSend = computed(() => text.value.trim().length > 0 && !props.isProcessing);

function handleSend(): void {
  if (!canSend.value) return;
  emit("send", text.value.trim());
  text.value = "";
}

function handleKeydown(e: KeyboardEvent): void {
  if (e.key === "Enter" && !e.shiftKey) {
    e.preventDefault();
    handleSend();
  }
}
</script>

<template>
  <div class="chat-input">
    <textarea
      ref="textareaRef"
      v-model="text"
      :disabled="disabled"
      placeholder="输入消息... (Enter 发送, Shift+Enter 换行)"
      rows="3"
      @keydown="handleKeydown"
    />
    <div class="input-actions">
      <button v-if="isProcessing" class="btn-stop" @click="emit('stop')">
        停止
      </button>
      <button v-else class="btn-send" :disabled="!canSend" @click="handleSend">
        发送
      </button>
    </div>
  </div>
</template>
```

### 2.5 组件与 Store 集成模式

所有 Chat Window 组件通过 `useChatStore()` 直接访问 Pinia Store：

```typescript
// 组件中使用 Pinia Store
import { useChatStore } from "../stores/chat";
import { storeToRefs } from "pinia";

const chatStore = useChatStore();
// 解构响应式状态
const { messages, isProcessing, sessions } = storeToRefs(chatStore);

// 调用 Actions
chatStore.sendMessage("Hello");
chatStore.selectSession("abc123");
```

**关键规则**：
- 组件不直接修改 Store 状态，所有变更通过 Actions 完成
- 使用 `storeToRefs()` 解构状态以保持响应性
- Pinia 自动追踪依赖，无需手动订阅/取消订阅

## 四、Floating Pet 渲染组件

### 4.1 架构

Floating Pet 是纯 DOM 渲染，不依赖 Vue 框架：

```
overlay.ts（MAIN World）
  │
  ├── DOM 渲染层
  │   ├── 皮肤环（CSS gradient 光环动画）
  │   ├── 角色图片（精灵图/帧动画）
  │   └── CSS 动画效果（思考中、说话中）
  │
  ├── 动画状态机
  │   ├── idle → active → thinking → speaking → idle
  │   └── 每个状态有独立的帧动画
  │
  ├── 交互层
  │   ├── hover → 工具提示气泡
  │   ├── click → 打开聊天窗口
  │   ├── drag → 移动宠物位置
  │   └── double-click → 切换角色动作
  │
  └── 状态同步
      ├── 监听 yipet:roleChanged 事件 → 更新皮肤
      ├── 监听 yipet:colorChanged 事件 → 更新颜色
      └── 监听 yipet:chatToggled 事件 → 显隐切换
```

### 4.2 动画状态

| 状态 | 触发条件 | 动画效果 | 循环 |
|------|----------|----------|------|
| `idle` | 无操作 5s 后 | 缓慢呼吸、偶尔眨眼、随机动作 | 循环 |
| `active` | 鼠标悬停 | 抬头、摇尾巴、期待表情 | 悬停期间 |
| `thinking` | SSE 流式阶段 | 思考气泡、头部倾斜 | 流式期间 |
| `speaking` | 消息完成 | 嘴巴张合、点头 | 3s 后回 idle |
| `sleeping` | 无操作 30s 后 | 闭眼、蜷缩、zzZ 气泡 | 直到交互 |

### 4.3 位置持久化

```typescript
interface PetPosition {
  x: number;  // 百分比 0-100
  y: number;  // 百分比 0-100
}

async function savePosition(pos: PetPosition): Promise<void> {
  await chrome.storage.local.set({ petPosition: pos });
}

async function loadPosition(): Promise<PetPosition> {
  const result = await chrome.storage.local.get("petPosition");
  return result.petPosition || { x: 80, y: 50 };
}
```

## 六、组件书写约定

### 标准 Vue 3 组件模板

```vue
<script setup lang="ts">
import { ref, computed, onMounted, onUnmounted } from "vue";

// Props 定义（泛型形式）
const props = defineProps<{
  title: string;
  disabled?: boolean;
}>();

// Emits 定义（泛型形式）
const emit = defineEmits<{
  submit: [data: string];
  cancel: [];
}>();

// 本地状态
const loading = ref(false);
const error = ref<string | null>(null);

// 计算属性
const canSubmit = computed(() => !props.disabled && !loading.value);

// 生命周期
onMounted(() => {
  // 初始化
});

onUnmounted(() => {
  // 清理（取消订阅、取消请求）
});
</script>

<template>
  <div class="component-name">
    <!-- 模板内容 -->
  </div>
</template>

<style scoped>
/* Co-located 样式，使用 scoped 避免污染 */
.component-name {
  /* ... */
}
</style>
```

### 核心约定

| 约定 | 说明 |
|------|------|
| `<script setup lang="ts">` | 强制使用 Composition API + TypeScript |
| 泛型 Props/Emits | `defineProps<{ ... }>()` / `defineEmits<{ ... }>()` |
| `<style scoped>` | 所有组件样式使用 scoped，避免跨组件污染 |
| Co-located 样式 | 样式与组件在同一 `.vue` 文件中 |
| Store 响应式访问 | 组件通过 `useChatStore()` + `storeToRefs()` 访问状态，Vue 自动追踪依赖并清理 |
| 错误状态 | 组件需处理 loading/empty/error 三种状态 |

## 七、跨世界组件通信

### 消息流向

```
Popup（扩展弹窗）
  │ chrome.tabs.sendMessage(tabId, { action: 'setRole', role: 'cat' })
  ▼
ISOLATED World（Content Script — relay.ts）
  │ chrome.runtime.onMessage.addListener → 处理 action
  │ dispatchSecureEvent('yipet:roleChanged', { role, color })
  ▼
MAIN World（Chat Window + Floating Pet）
  │ window.addEventListener('yipet:roleChanged', handler)
  │ IPC_SECRET 签名 + 时间戳验证（5s 过期）
  ▼
更新皮肤/聊天头部/系统提示词
```

### 组件中发送 IPC 消息

```typescript
// 在 Popup 组件中 — 通过 chrome.tabs.sendMessage
async function changeRole(roleId: string): Promise<void> {
  await chrome.storage.local.set({ role: roleId });
  const tabs = await chrome.tabs.query({});
  for (const tab of tabs) {
    if (tab.id) {
      chrome.tabs.sendMessage(tab.id, {
        action: "setRole",
        role: roleId,
      });
    }
  }
}

// 在 Content Script (relay.ts) 中 — 通过 dispatchSecureEvent
function dispatchSecureEvent<T>(name: string, detail: T): void {
  window.dispatchEvent(new CustomEvent(name, {
    detail: {
      __yipet: true,
      __signature: IPC_SECRET,
      __timestamp: Date.now(),
      data: detail,
    },
  }));
}

// 在 MAIN World 组件中 — 监听安全事件
window.addEventListener('yipet:roleChanged', ((e: CustomEvent) => {
  const { __yipet, __signature, __timestamp, data } = e.detail || {};
  if (!__yipet || __signature !== IPC_SECRET) return;
  if (Date.now() - __timestamp > 5000) return;
  applyRole(data.role);
}) as EventListener);
```

## 九、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 组件中直接调用 ApiClient | `fetch(url, ...)` 在 `.vue` 中 | 通过 Chat Store Actions | 破坏状态管理，难以追踪 |
| 在 MAIN World 组件中调用 chrome API | `chrome.storage.local.get()` 在 `.vue` 中 | 通过 IPC Relay 请求 | MAIN World 无 chrome API |
| 直接修改 Store 状态 | `chatStore.messages.push(msg)` | 通过 `chatStore.sendMessage()` | 破坏单一数据源 |
| 硬编码颜色/尺寸 | `style="color: #667eea"` | 使用 CSS 变量响应角色配置 | 皮肤切换失效 |
| 不处理 SSE 中断 | 组件卸载后 SSE 连接未断开 | 使用 AbortSignal + onUnmounted 清理 | 资源泄漏 |
| 在 Popup 中操作页面 DOM | `document.querySelector(".pet")` | 通过 `chrome.tabs.sendMessage` 通知 Content Script | 弹窗隔离 |

## 十、约束

### 必须遵守
- 使用 `<script setup lang="ts">` 语法
- 组件样式使用 `<style scoped>`
- Props/Emits 使用泛型形式
- 组件通过 Store Actions 操作状态，不直接修改 state
- SSE 流式请求使用 AbortSignal，组件卸载时取消
- SSE 流式请求使用 AbortSignal，组件卸载时取消
- 处理 loading/empty/error 三种状态

### 禁止
- 不在组件中直接调用 ApiClient 或 fetch
- 不在 MAIN World 组件中调用 chrome.* API
- 不在组件中直接修改 state 对象
- 不用 Options API
- 不忘记清理订阅和请求
- 不硬编码颜色、尺寸和 API 地址
