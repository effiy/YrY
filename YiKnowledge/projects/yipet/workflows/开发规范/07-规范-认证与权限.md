# 认证与权限

> YiPet 认证体系：Token 管理、chrome.storage 持久化、跨世界认证传递、Session Key 桥接到 YiVad、Bug 报告认证、安全约束、Token 刷新、权限模型。

## 一、认证架构

```
用户登录 YiVad
  │ POST /auth/login { username, password }
  │ YiAi 验证 → bcrypt 密码比对 → JWT 签发
  │ 返回 { token: "eyJ...", user: { id, username, role } }
  ▼
YiVad 写入 localStorage
  │ 键: "YiWeb.apiToken.v1"
  │ 值: "eyJ..."  (原始 JWT，不含 Bearer 前缀)
  │
  ▼
YiPet 读取 Token（Content Script relay.ts）
  │ chrome.storage.session.get('apiToken') → 优先
  │ localStorage.getItem('YiWeb.apiToken.v1') → 迁移降级
  │ 找到后提升到 chrome.storage.session
  │
  ▼
Token 传递到 MAIN World
  │ 通过 <script> 标签的 dataset.apiToken 属性
  │ chat/index.ts 读取 dataset.apiToken → createApiServices({ token })
  │
  ▼
ApiClient 注入 Token
  │ 构造时接收 token，注入 X-Token Header
  │
  ▼
YiAi Backend 验证 Token
  │ AuthMiddleware → jwt.decode(token, secret)
  │ 返回 200 → 正常响应，注入 request.state.user
  │ 返回 401 → Token 过期/无效，清除并提示
```

### 认证模式

YiPet 本身不处理用户登录，而是依赖 YiVad 完成认证后共享 Token：

| 模式 | 说明 | 配置 |
|------|------|------|
| 开发模式 | YiAi `auth_enabled: false`，所有端点公开 | Token 可选 |
| 生产模式 | YiAi `auth_enabled: true`，JWT 强制验证 | Token 必须 |

## 二、Token 管理

### 存储机制

Token 使用 `chrome.storage.session`（安全存储，不会同步到云端）：

```typescript
// src/content/ipc/relay.ts — Token 读取与传递
// 1. 优先从 chrome.storage.session 读取
chrome.storage.session.get('apiToken').then((result) => {
  let token = String(result.apiToken || '').trim();

  // 2. 降级：从 localStorage 迁移（YiVad 遗留）
  if (!token) {
    try {
      token = (localStorage.getItem('YiWeb.apiToken.v1') || '').trim();
      if (token) {
        chrome.storage.session.set({ apiToken: token }).catch(() => {});
      }
    } catch { /* localStorage unavailable */ }
  }

  // 3. 通过 dataset 传递给 MAIN World
  if (token) chatEl.dataset.apiToken = token;
});
```

### ApiClient 注入

ApiClient 在构造时接收 token，不主动读取存储：

```typescript
// src/api/client.ts
export function createApiClient(config: ApiClientConfig & { token?: string }): ApiClient {
  const token = (config.token || '').trim();
  if (token) authHeaders['X-Token'] = token;
  // ...
}

// src/chat/index.ts — MAIN World 入口
const API_TOKEN = dataset.apiToken || '';
const api = createApiServices({ baseUrl: API_BASE, token: API_TOKEN });
```

### Token 生命周期

| 事件 | 行为 | 触发者 |
|------|------|--------|
| 用户登录 YiVad | YiVad 写入 token 到 `localStorage`（键 `YiWeb.apiToken.v1`） | YiVad |
| YiPet Content Script 启动 | 从 `chrome.storage.session` 读取，降级到 `localStorage`，提升到 session 存储 | YiPet relay.ts |
| Token 传递到 MAIN World | 通过 `<script>` 标签 `dataset.apiToken` 属性 | YiPet relay.ts |
| ApiClient 发起请求 | 使用构造时注入的 token，设置 `X-Token` Header | YiPet ApiClient |
| 后端返回 401 | ApiClient 返回 `ApiResponse{ok:false, status:401}`，调用方处理 | YiPet ApiClient |

## 三、跨世界认证传递

### 认证信息流

```
YiVad（Vue 3 SPA，端口 8848）
  │ 用户登录
  │ localStorage.setItem('YiWeb.apiToken.v1', 'eyJ...')
  ▼
localStorage（页面存储）
  │ YiVad 写入，YiPet Content Script 可读取
  │
  ▼
YiPet Content Script（ISOLATED World）
  │ relay.ts: chrome.storage.session.get('apiToken')
  │           → 降级 localStorage.getItem('YiWeb.apiToken.v1')
  │           → 提升到 chrome.storage.session.set({ apiToken })
  │
  │ relay.ts: chatEl.dataset.apiToken = token
  │           → 通过 <script> 标签 dataset 传递到 MAIN World
  ▼
YiPet Chat（MAIN World）
  │ chat/index.ts: API_TOKEN = dataset.apiToken
  │ createApiServices({ baseUrl: API_BASE, token: API_TOKEN })
  │ ApiClient 在构造时注入 X-Token Header
```

### 存储键

| 键 | 存储位置 | 写入者 | 读取者 | 说明 |
|----|----------|--------|--------|------|
| `apiToken` | `chrome.storage.session` | YiPet relay.ts | YiPet relay.ts | JWT 认证 Token（安全存储） |
| `YiWeb.apiToken.v1` | `localStorage` | YiVad | YiPet relay.ts（迁移降级） | YiVad 遗留格式 |
| `petRole` | `chrome.storage.local` | YiPet relay.ts | YiPet Popup/Chat | 角色选择 |
| `petColorTheme` | `chrome.storage.local` | YiPet relay.ts | YiPet Popup/Chat | 主题颜色 |

## 四、Session Key 桥接（YiPet → YiVad）

### 桥接流程

```
YiPet Chat Window
  │ 用户点击 "在 YiVad aiChat 中打开"
  │
  ├── 1. 通过 SessionService.create 创建会话
  │     ├── 植入页面上下文作为第一条系统消息
  │     ├── 标签: ["from:<url>", "source:YiPet", "project:<detected>"]
  │     └── 获取 session key (UUID)
  │
  ├── 2. window.open 打开 YiVad
  │     http://localhost:8848/#/aiChat?session=<key>
  │
  ▼
YiVad aiChat 页面
  │ onMounted 读取 ?session=<key>
  │ 调用 SessionService.getByKey(key) 加载会话
  │ 页面上下文已随会话消息植入
```

### 每条消息桥接

```typescript
// src/chat/stores/chat.ts
async function openMessageInYiVad(timestamp: number): Promise<void> {
  const msg = messages.value.find(m => m.timestamp === timestamp);
  if (!msg) return;

  // 对于宠物回复，包含前置用户问题
  const contextMessages = msg.role === "pet"
    ? [_findPrecedingUserMessage(timestamp), msg].filter(Boolean)
    : [msg];

  if (contextMessages.length === 0) return;

  // 通过 SessionService 植入会话
  const sessionKey = await api.session.upsert({
    messages: contextMessages.map(m => ({
      role: m.role === "pet" ? "assistant" : "user",
      content: m.content,
    })),
    tags: [
      "via:per-message-bridge",
      "source:YiPet",
      `from:${window.location.href}`,
    ],
    title: `YiPet → ${msg.content.slice(0, 60)}${msg.content.length > 60 ? "..." : ""}`,
  });

  // 打开 YiVad aiChat
  window.open(
    `http://localhost:8848/#/aiChat?session=${sessionKey}`,
    "_blank"
  );
}

function _findPrecedingUserMessage(timestamp: number): Message | null {
  const idx = messages.value.findIndex(m => m.timestamp === timestamp);
  if (idx <= 0) return null;
  // 向前查找最近一条用户消息
  for (let i = idx - 1; i >= 0; i--) {
    if (messages.value[i].role === "user") {
      return messages.value[i];
    }
  }
  return null;
}
```

## 五、Bug 报告认证

### 提交流程

```
YiPet BugReportDialog
  │ 用户填写 Bug 信息（标题、描述、严重程度、截图）
  │
  ├── 1. KnowledgeService.writeEntryMarkdown
  │     POST /  body: { module_name: "services.knowledge.knowledge_service",
  │                      method_name: "write_entry_markdown",
  │                      parameters: { target_file, content } }
  │     → 写入 YiKnowledge/lessons/failures/bugs/<key>.md
  │
  ├── 2. DataService.createDocument
  │     POST /  body: { module_name: "services.database.data_service",
  │                      method_name: "create_document",
  │                      parameters: { cname: "bugs", data: {...} } }
  │     → 写入 MongoDB bugs 集合
  │
  │ 所有请求通过 ApiClient 携带 X-Token Header
  │
  ▼
YiAi Backend
  │ AuthMiddleware → 验证 X-Token
  │ → 文件双写：磁盘（主） + MongoDB static_files（备份）
  │ → MongoDB bugs 集合
```

### Bug 报告数据模型

```typescript
interface BugReport {
  title: string;
  description: string;
  url: string;           // 发现页面 URL
  browser: string;       // navigator.userAgent
  severity: "critical" | "high" | "medium" | "low";
  steps?: string;        // 复现步骤
  expectedBehavior?: string;
  actualBehavior?: string;
  screenshots?: string[]; // Data URL
}

async function submitBugReport(bug: BugReport): Promise<void> {
  const api = createApiServices(API_BASE);

  const bugKey = `${Date.now()}-${bug.title.toLowerCase().replace(/[^a-z0-9]+/g, "-").slice(0, 50)}`;
  const targetFile = `engineer/learn/lessons/failures/bugs/${bugKey}.md`;

  // 1. 写入知识库
  await api.knowledge.writeEntryMarkdown({
    target_file: targetFile,
    content: formatBugMarkdown(bug),
  });

  // 2. 写入 MongoDB
  await api.data.createDocument("bugs", {
    title: bug.title,
    description: bug.description,
    url: bug.url,
    browser: bug.browser,
    severity: bug.severity,
    status: "open",
    reporter: "YiPet",
    project: detectProject(bug.url),
    created_at: new Date().toISOString(),
    updated_at: new Date().toISOString(),
  });
}
```

## 六、安全约束

### 存储安全

| 措施 | 说明 | 实现 |
|------|------|------|
| Token 仅存 `chrome.storage.session` | 会话级安全存储，不持久化到磁盘 | `chrome.storage.session` |
| Token 不存 `chrome.storage.local` | 避免持久化泄露 | — |
| Token 迁移提升 | 从 `localStorage` 读取后立即提升到 `chrome.storage.session` | `relay.ts` |
| Token 通过 dataset 传递 | 不通过 postMessage 传递敏感数据 | `relay.ts` → `chat/index.ts` |
| 敏感数据不存 sync | `chrome.storage.sync` 同步到云端，仅用于非敏感配置 | 仅存 `role`、`color` 等非敏感项 |

### 通信安全

| 措施 | 说明 | 实现位置 |
|------|------|----------|
| 消息来源验证 | IPC 验证 `event.source === window` + `IPC_SECRET` 签名 | `content/ipc/relay.ts` |
| CustomEvent 安全分发 | `dispatchSecureEvent` 使用 `crypto.randomUUID()` 签名 | `content/ipc/relay.ts` |
| 不通过 postMessage 传递 Token | Token 通过 dataset 属性传递，不经过消息通道 | `content/ipc/relay.ts` |
| X-Token 而非 Authorization | 使用自定义 Header 避免与页面自身认证冲突 | `api/client.ts` |

### 权限最小化

```json
// manifest.json
{
  "permissions": [
    "storage",
    "activeTab",
    "commands"
  ],
  "host_permissions": [
    "http://localhost:10086/*"
  ]
}
```

| 权限 | 用途 | 最小化理由 |
|------|------|-----------|
| `storage` | chrome.storage（Token + 配置持久化） | 仅 local，不使用 sync |
| `activeTab` | 当前标签页访问 | 不使用 `<all_urls>` |
| `commands` | 键盘快捷键 | 仅 2 个命令 |
| `host_permissions` | YiAi 后端通信 | 仅 localhost:10086 |

## 七、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 在 MAIN World 读 Token | `chrome.storage.session.get("apiToken")` 在 chat.ts 中 | 通过 dataset 属性从 Content Script 传递 | MAIN World 无 chrome API |
| URL 参数传递 Token | `window.open(\`/chat?token=${token}\`)` | 使用 dataset 属性 + Session Key 桥接 | Token 泄露到浏览器历史和日志 |
| 日志输出 Token | `console.log("Token:", token)` | 不输出 Token 到日志 | Token 泄露 |
| Token 存 localStorage | `localStorage.setItem("token", token)` 作为主存储 | 使用 `chrome.storage.session` 作为主存储 | 页面 JS 可访问，XSS 风险 |
| Token 存 sync | `chrome.storage.sync.set({ token })` | 使用 `chrome.storage.session` | 同步到云端，泄露风险 |
| 不验证 IPC 签名 | `window.addEventListener("message", handler)` | 验证 `IPC_SECRET` 签名 + `event.source === window` | 恶意页面可伪造消息 |
| 不处理 401 | 忽略 `code === 401` | 返回 `ApiResponse{ok:false}` 由调用方处理 | 后续请求全部失败 |

## 八、约束

### 必须遵守
- Token 通过 `chrome.storage.session` 存储（键 `apiToken`），不存 `chrome.storage.local`
- Token 从 ISOLATED World 通过 `dataset` 属性传递到 MAIN World
- ApiClient 在构造时接收 token，不主动读取存储
- 跨世界通信不通过 postMessage 传递 Token（仅通过 dataset 属性）
- IPC 消息必须验证 `IPC_SECRET` 签名
- MAIN World 不直接访问 chrome.storage（通过 dataset 接收数据）

### 禁止
- 不在 MAIN World 中读取或操作 chrome.storage
- 不在 URL 参数中传递 Token
- 不在日志中输出 Token 内容（包括 console.log、错误堆栈）
- 不将 Token 写入 `chrome.storage.sync`（云端同步风险）
- 不通过 window.postMessage 传递 Token 到 MAIN World
- 不将 Token 以 `chrome.storage.local` 作为主存储
