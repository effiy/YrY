# 状态管理模式

> YiPet 跨世界状态管理：Chat Store（Pinia）单一数据源、chrome.storage 持久化、跨世界状态同步、多标签页一致性、状态恢复。

**相关文档**：[Chat Store](../功能模式/01-模式-ChatStore状态管理.md) · [IPC 通信](../架构设计/06-架构-IPC跨世界通信.md)

## 一、状态分布

```
MAIN World: Chat Store（Pinia）— 聊天状态（messages, sessions, UI）
ISOLATED World: Content Script — 注入状态（__YIPET_LOADED__）、IPC 队列
Service Worker: 命令分发状态、快捷键状态
Popup: usePopupStore（Pinia）— 配置状态（role, color, model）
```

## 二、状态分类

| 分类 | 示例 | 持久化 | 跨世界同步 | 多标签页 |
|------|------|:---:|:---:|:---:|
| 聊天状态 | messages, sessions | ✓ | 否 | 否（独立） |
| 配置状态 | role, color, model | ✓ | 是（广播） | 是 |
| UI 状态 | sidebarCollapsed, chatVisible | ✓ | 否 | 否（独立） |
| 注入状态 | __YIPET_LOADED__ | 否 | 否 | 否 |
| 认证状态 | token | ✓（session） | 是 | 是 |

## 三、持久化策略

| 数据 | 写入时机 | 方式 | 降级 |
|------|----------|------|------|
| 会话消息 | 每条消息完成后 | 后端优先，storage 备份 | `backup_` 键 |
| 会话列表 | 会话变更时 | chrome.storage | — |
| 用户配置 | 每次变更时 | chrome.storage | — |
| UI 状态 | 每次变更时 | chrome.storage | — |
| 知识库缓存 | 首次加载后 | chrome.storage（`cache_` 前缀） | 重新加载 |

**存储键前缀**：无前缀（配置/UI）、`session_`（会话数据）、`backup_`（降级备份）、`cache_`（缓存）。

## 四、跨世界状态同步

配置变更流程：
```
Popup 修改 → chrome.storage.local.set
  → chrome.tabs.sendMessage(tabId, { action: 'setRole', role })
  → ISOLATED: chrome.runtime.onMessage → dispatchSecureEvent
  → MAIN: window.addEventListener → 更新 Chat Store → Vue 响应式更新 UI
```

## 五、多标签页一致性

**最终一致性模型**：每个标签页独立 Chat Store 实例，配置变更通过广播同步，会话数据以后端（YiAi）为准。

| 场景 | 策略 |
|------|------|
| 配置变更 | 即时广播所有标签页 |
| 会话创建 | 后端优先持久化 |
| 会话切换 | 标签页独立（可看不同会话） |
| 冲突处理 | 本地 `updatedAt` vs 存储版本，保留最新 |

## 六、状态恢复

启动恢复优先级：配置状态 → UI 状态 → 会话列表 → 上次会话（含消息加载）。

Service Worker 终止后自动唤醒，从 chrome.storage 恢复全部状态。

## 七、状态重置

| 场景 | 重置 | 保留 |
|------|------|------|
| 切换角色 | 系统提示词、皮肤 | 会话数据、配置 |
| 清除数据 | 所有会话、消息 | 角色/颜色/模型 |
| 扩展更新 | 无（状态迁移） | 全部 |
| 浏览器清除 | 全部 storage | 无 |

## 八、反模式

| 反模式 | 正确做法 | 原因 |
|--------|----------|------|
| 直接修改 Store | 通过 Actions | 破坏单一数据源 |
| 内存状态不持久化 | 后端 + storage | SW 终止丢失 |
| 绕过广播修改 | Popup → 广播 | 其他标签页不同步 |
| 忽略存储配额 | 写入前检查 + 清理缓存 | 写入静默失败 |
| 不处理存储错误 | try/catch + 降级 | 无感知失败 |

## 九、约束

**必须遵守**：Chat Store 是唯一数据源、配置变更通过 Popup 广播、所有持久化用 `chrome.storage.local`、写入前检查配额、标签页恢复重新加载状态。

**禁止**：组件直接修改 Store、MAIN World 直接调 `chrome.storage`、依赖内存状态、绕过广播机制、忽略存储写入错误。
