# Pattern: 状态管理

> YiPet 跨世界状态管理完整模式：Chat Store（Pinia）单一数据源、chrome.storage 持久化、跨世界状态同步、Popup 状态广播、多标签页状态一致性、状态恢复、反模式。

## 概述

YiPet 的状态分布在三个独立运行环境中（MAIN World、ISOLATED World、Service Worker），需要解决跨世界状态同步、持久化恢复、多标签页一致性等问题。

**核心挑战**：
- Chrome MV3 Service Worker 非持久化（空闲 30s 终止）
- MAIN World 和 ISOLATED World 状态隔离
- 多标签页场景下状态一致性
- 状态变更需要广播到所有标签页

**相关规范**：
- [Chat Store 模式](./功能模式/01-ChatStore模式.md)
- [核心模块](./架构设计/05-核心模块.md)
- [扩展架构](./架构设计/02-扩展架构.md)

## 一、状态架构

### 状态分布

```
┌─ MAIN World ─────────────────────────────────────────┐
│  Chat Store（Pinia，单一数据源）                      │
│  ├── messages, sessions, currentSessionId             │
│  ├── knowledgeGrounded, ragScope, ragSources          │
│  ├── sidebarCollapsed, sidebarView, chatVisible       │
│  └── pageInfo, contextEnabled, model, role, color     │
│                                                        │
│  持久化 → chrome.storage.local（通过 IPC）              │
├─ ISOLATED World ─────────────────────────────────────┤
│  Content Script                                       │
│  ├── 注入状态（__YIPET_LOADED__）                     │
│  └── IPC Relay 消息队列                              │
│                                                        │
│  持久化 → chrome.storage.local（直接访问）              │
├─ Service Worker ──────────────────────────────────────┤
│  Background                                           │
│  ├── 命令分发状态                                     │
│  └── 快捷键状态                                       │
│                                                        │
│  持久化 → chrome.storage.local（直接访问）              │
├─ Popup ───────────────────────────────────────────────┤
│  usePopupStore（Pinia，独立 Vue 应用）                  │
│  ├── state: role, color, model, visible, size          │
│  └── 通过 ChromeService.sendMessage 广播变更            │
│                                                        │
│  持久化 → chrome.storage.local（直接访问）              │
└──────────────────────────────────────────────────────┘
```

### 状态分类

| 分类 | 示例 | 持久化 | 跨世界同步 | 多标签页同步 |
|------|------|--------|-----------|-------------|
| 聊天状态 | messages, sessions | chrome.storage + YiAi | 否（仅 MAIN World） | 否（每个标签页独立） |
| 配置状态 | role, color, model, language | chrome.storage | 是（Popup → 所有标签页） | 是（广播） |
| UI 状态 | sidebarCollapsed, chatVisible | chrome.storage | 否（仅 MAIN World） | 否（每个标签页独立） |
| 注入状态 | __YIPET_LOADED__ | 否（内存） | 否（仅 ISOLATED World） | 否（每个标签页独立） |
| 认证状态 | token | chrome.storage | 是（Popup → 所有标签页） | 是（广播） |

## 二、单一数据源模式

### Chat Store（Pinia）作为单一数据源

```typescript
// Chat Store 是聊天状态唯一可信来源
export const useChatStore = defineStore("yipet-chat", () => {
  const messages = ref<Message[]>([]);
  const sessions = ref<Session[]>([]);
  const currentSessionId = ref<string | null>(null);
  // ... 40+ 响应式状态字段

  // 所有状态变更通过 Actions
  function sendMessage(text: string) { /* ... */ }
  function selectSession(id: string) { /* ... */ }

  return { messages, sessions, currentSessionId, sendMessage, selectSession };
});
```

**关键规则**：
- 组件通过 `useChatStore()` + `storeToRefs()` 读取响应式状态
- 所有状态变更通过 Store Actions 完成
- Pinia 自动追踪依赖，无需手动订阅/取消订阅

## 三、chrome.storage 持久化

### 存储键命名规范

| 前缀 | 用途 | 示例 |
|------|------|------|
| 无前缀 | 配置和 UI 状态 | `role`, `color`, `chatVisible` |
| `session_` | 会话数据 | `session_abc123` |
| `backup_` | 降级备份 | `backup_session_abc123` |
| `cache_` | 缓存数据 | `cache_knowledge_tree` |

### 持久化封装

```typescript
// src/shared/storage/state.ts
// Per-Tab 状态（宠物可见性、大小、角色、颜色、模型）
export async function getTabState(tabId: number): Promise<PetGlobalState> {
  const result = await chrome.storage.local.get(GLOBAL_STATE_KEY);
  const map = (result[GLOBAL_STATE_KEY] as TabStateMap) || {};
  return map[tabId] || {};
}

export async function setTabState(tabId: number, patch: Partial<PetGlobalState>): Promise<PetGlobalState> {
  const result = await chrome.storage.local.get(GLOBAL_STATE_KEY);
  const map = (result[GLOBAL_STATE_KEY] as TabStateMap) || {};
  const current = map[tabId] || {};
  const updated = { ...current, ...patch };
  map[tabId] = updated;
  await chrome.storage.local.set({ [GLOBAL_STATE_KEY]: map });
  return updated;
}

// 用户偏好（主题、字号、功能开关）
export async function getPrefs(): Promise<UserPrefs> {
  const result = await chrome.storage.local.get(PREFS_KEY);
  return { ...DEFAULT_PREFS, ...((result[PREFS_KEY] as UserPrefs) || {}) };
}

export async function setPrefs(patch: Partial<UserPrefs>): Promise<UserPrefs> {
  const current = await getPrefs();
  const updated = { ...current, ...patch };
  await chrome.storage.local.set({ [PREFS_KEY]: updated });
  return updated;
}
```

### 持久化策略

| 数据 | 写入时机 | 写入方式 | 降级方案 |
|------|----------|----------|----------|
| 会话消息 | 每条消息完成后 | 后端优先，chrome.storage 备份 | `backup_` 键降级 |
| 会话列表 | 会话变更时 | chrome.storage | 无 |
| 用户配置 | 每次变更时 | chrome.storage | 无 |
| UI 状态 | 每次变更时 | chrome.storage | 无 |
| 知识库缓存 | 首次加载后 | chrome.storage（`cache_` 前缀） | 重新加载 |

## 四、跨世界状态同步

### 配置变更广播

```
Popup（用户修改配置）
  │ 1. chrome.storage.local.set({ pet_global_state: { [tabId]: { role, color, model } } })
  │ 2. chrome.tabs.sendMessage(tabId, { action: 'setRole', role: validated })
  ▼
Content Script（当前标签页）
  │ chrome.runtime.onMessage.addListener
  │ dispatchSecureEvent('yipet:roleChanged', { role, color })
  ▼
MAIN World（Chat Window + Floating Pet）
  │ window.addEventListener('yipet:roleChanged', handler)
  │ IPC_SECRET 签名 + 时间戳验证（5s 过期）
  │ 更新 Chat Store 状态（role/color/model）
  │ 更新 Floating Pet 皮肤
  │ 更新聊天头部信息
```

### 广播实现

```typescript
// src/popup/services/chrome.ts
export function createChromeService(tabRef: TabRef, storageKey: string): ChromeService {
  return {
    sendMessage(msg: unknown) {
      if (!tabRef.current?.id) return Promise.resolve(null);
      return chrome.tabs.sendMessage(tabRef.current.id, msg).catch((err: Error) => {
        console.warn('[YiPet Popup] sendMessage failed:', err.message);
        return null;
      });
    },
    // ...
  };
}

// src/popup/stores/popup.ts — 使用示例
function updateRole(role: string) {
  const validated = validateRole(role);
  send({
    msg: { action: 'setRole', role: validated },
    okMsg: t('notifyRoleChanged', validated),
    optimistic: { role: validated },
  });
}
```

### 状态同步消息类型

| 消息 | 方向 | 触发时机 | 载荷 |
|------|------|----------|------|
| `{ action: 'setRole' }` | Popup → Content Script | 角色/颜色变更 | `{ role: string }` |
| `{ action: 'setColor' }` | Popup → Content Script | 颜色变更 | `{ color: number }` |
| `{ action: 'setVisibility' }` | Popup → Content Script | 显隐切换 | `{ visible: boolean }` |
| `{ action: 'toggleChat' }` | Popup → Content Script | 快捷键切换聊天 | — |
| `{ action: 'changeSize' }` | Popup → Content Script | 宠物大小变更 | `{ size: number }` |
| `{ action: 'extensionUpdated' }` | SW → Content Script | 扩展更新 | `{ previousVersion, currentVersion }` |

## 五、多标签页一致性

### 一致性模型

YiPet 采用**最终一致性**模型：
- 每个标签页有独立的 Chat Store 实例
- 配置变更通过广播同步到所有标签页
- 会话数据通过后端（YiAi）作为真实数据源

### 一致性场景

| 场景 | 策略 | 说明 |
|------|------|------|
| 配置变更 | 即时广播 | Popup 修改 → 广播到所有标签页 |
| 会话创建 | 后端优先 | 创建后立即持久化到后端 |
| 会话切换 | 标签页独立 | 不同标签页可查看不同会话 |
| 消息发送 | 标签页独立 | 每个标签页独立发送消息 |
| 会话删除 | 后端优先 | 删除后其他标签页需重新加载 |

### 冲突处理

```typescript
// 标签页恢复时重新加载会话列表
async function _reloadSessionsFromStorage(): Promise<void> {
  const result = await chrome.storage.local.get("sessions");
  const storedSessions = result.sessions || [];

  // 合并策略：保留本地会话的未保存消息，更新元数据
  const merged = storedSessions.map((stored: Session) => {
    const local = sessions.value.find(s => s.id === stored.id);
    if (local && local.updatedAt > stored.updatedAt) {
      return local; // 本地版本更新，保留本地
    }
    return stored; // 存储版本更新，使用存储
  });

  sessions.value = merged;
}
```

## 六、状态恢复

### 完整恢复流程

```typescript
async function restoreState(): Promise<void> {
  // 1. 恢复配置状态
  const config = await chrome.storage.local.get([
    "role", "color", "model", "language", "petVisible"
  ]);
  role.value = config.role || "cat";
  color.value = config.color || "blue";
  model.value = config.model || "qwen3.5";
  language.value = config.language || "zh_CN";
  petVisible.value = config.petVisible ?? true;

  // 2. 恢复 UI 状态
  const ui = await chrome.storage.local.get([
    "sidebarCollapsed", "sidebarWidth", "sidebarView",
    "chatVisible", "knowledgeGrounded", "ragScope"
  ]);
  sidebarCollapsed.value = ui.sidebarCollapsed ?? false;
  sidebarWidth.value = ui.sidebarWidth || 280;
  sidebarView.value = ui.sidebarView || "sessions";
  chatVisible.value = ui.chatVisible ?? false;
  knowledgeGrounded.value = ui.knowledgeGrounded || false;
  ragScope.value = ui.ragScope || "";

  // 3. 恢复会话列表
  const sessionsData = await chrome.storage.local.get("sessions");
  sessions.value = sessionsData.sessions || [];

  // 4. 恢复上次会话
  const currentSession = await chrome.storage.local.get("currentSessionId");
  if (currentSession.currentSessionId) {
    currentSessionId.value = currentSession.currentSessionId;
    await selectSession(currentSession.currentSessionId);
  }

  // Vue 响应式系统自动追踪状态变更，无需手动 _emit
}
```

## 七、状态重置

### 重置场景

| 场景 | 重置内容 | 保留内容 |
|------|----------|----------|
| 切换角色 | 系统提示词、宠物皮肤 | 会话数据、配置 |
| 清除数据 | 所有会话、消息 | 角色/颜色/模型配置 |
| 扩展更新 | 无（状态迁移） | 全部保留 |
| 浏览器清除 | 全部 chrome.storage | 无 |

## 八、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 直接修改 Store 状态 | `chatStore.messages.push(msg)` | `chatStore.sendMessage(text)` | 破坏单一数据源 |
| 内存状态不持久化 | 仅在内存中保存会话 | `_persistSession()` 写入后端 + chrome.storage | SW 终止后丢失 |
| 绕过广播直接修改 | 标签页中直接修改 `color` | 通过 Popup 修改 → 广播到所有标签页 | 其他标签页不同步 |
| 忽略存储配额 | 不检查 `getBytesInUse` | 写入前检查 + 配额超限时清理缓存 | 存储满后写入静默失败 |
| 不处理存储错误 | `chrome.storage.local.set()` 无 catch | try/catch + 降级处理 | 写入失败无感知 |
| 多标签页无冲突处理 | 两个标签页同时修改同一会话 | 后端作为真实数据源，标签页恢复时合并 | 数据不一致 |

## 九、约束

### 必须遵守
- Chat Store（Pinia）是聊天状态的唯一数据源
- 配置变更通过 Popup 触发，广播到所有标签页
- 所有持久化数据使用 `chrome.storage.local`
- 写入存储前检查配额，超限时清理缓存
- 标签页恢复时重新加载配置和会话列表

### 禁止
- 不在组件中直接修改 Store 状态
- 不在 MAIN World 中直接调用 `chrome.storage` API
- 不依赖内存状态（SW 可随时终止）
- 不绕过广播机制在标签页中直接修改配置
- 不忽略存储写入错误
