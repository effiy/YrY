# 认证与权限

> YiPet 认证体系：Token 管理、chrome.storage 持久化、跨世界认证传递、Session Key 桥接 YiVad、Bug 报告认证。

**相关文档**：[API 架构](./05-规范-API架构与规范.md) · [IPC 通信](../架构设计/06-架构-IPC跨世界通信.md)

## 一、认证架构

YiPet 本身不处理登录，依赖 YiVad 完成认证后共享 Token：

```
YiVad 登录 → localStorage('YiWeb.apiToken.v1') → YiPet CS 读取
  → 提升到 chrome.storage.session('apiToken')
  → 通过 <script> dataset 传递到 MAIN World
  → ApiClient 构造时注入 X-Token Header
  → YiAi AuthMiddleware 验证
```

| 模式 | 说明 |
|------|------|
| 开发模式 | YiAi `auth_enabled: false`，Token 可选 |
| 生产模式 | YiAi `auth_enabled: true`，JWT 强制验证 |

## 二、Token 管理

| 键 | 存储位置 | 写入者 | 读取者 |
|----|----------|--------|--------|
| `apiToken` | `chrome.storage.session` | YiPet relay.ts | YiPet relay.ts |
| `YiWeb.apiToken.v1` | `localStorage`（降级） | YiVad | YiPet relay.ts（迁移） |

**传递链路**：ISOLATED World（relay.ts）读取 token → 通过 `<script> dataset.apiToken` → MAIN World（chat/index.ts）→ createApiServices({ token })

**生命周期**：不主动刷新，YiAi 返回 401 时 `ApiResponse{ok:false}` 由调用方处理。

## 三、跨世界认证传递

**Token 不经过消息通道**：通过 `<script> dataset` 属性从 ISOLATED 传递到 MAIN，避免 postMessage 被页面脚本拦截。

**存储安全**：
- 主存储 `chrome.storage.session`（会话级，不持久化磁盘）
- 降级从 `localStorage` 迁移后立即提升
- 不使用 `chrome.storage.sync`（云端同步风险）
- 不通过 URL 参数传递

## 四、Session Key 桥接（YiPet → YiVad）

**安全模式**：使用 `BridgeService` 创建一次性 token（替代 URL 参数传递 sessionKey）：

```
用户点击 "在 YiVad 中讨论"
  → BridgeService.createToken(sessionId) → 获取一次性 token
  → window.open(`http://localhost:8848/#/aiChat?token=${token}`)
  → YiVad: BridgeService.exchangeToken(token) → 获取 session_id
```

**讨论当前页面**：提取 `pageInfo`（标题/URL/描述/关键词）→ 作为系统消息植入会话 → YiVad 加载即可看到完整上下文。

## 五、Bug 报告认证

双写模式：`KnowledgeService.writeEntryMarkdown`（→ YiKnowledge markdown）+ `DataService.createDocument`（→ MongoDB bugs 集合）。所有请求通过 ApiClient 携带 X-Token。

## 六、安全约束

| 措施 | 说明 |
|------|------|
| Token 仅存 session | `chrome.storage.session`，不持久化磁盘 |
| 不存 local/sync | 避免持久化泄露和云端同步 |
| Token 经 dataset 传递 | 不经过 postMessage |
| X-Token（非 Authorization） | 避免与页面自身认证冲突 |

## 七、反模式

| 反模式 | 正确做法 | 原因 |
|--------|----------|------|
| MAIN World 读 Token | dataset 属性传递 | 无 chrome API |
| URL 参数传 Token | dataset + Session Key | Token 泄露到历史 |
| Token 存 sync | `chrome.storage.session` | 云端泄露 |
| 不验证 IPC 签名 | IPC_SECRET + 时间戳 | 恶意伪造 |

## 八、约束

**必须遵守**：Token 存 `chrome.storage.session`（键 `apiToken`）、通过 dataset 传递到 MAIN、ApiClient 构造时注入不主动读取、不通过 postMessage 传递 Token。

**禁止**：MAIN World 读 chrome.storage、URL 参数传 Token、日志输出 Token、Token 存 sync/local。
