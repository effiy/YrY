# 组件规范

> YiPet Vue 3 组件体系：Chat Window 组件群（20+）、Popup 组件群（6）、Floating Pet 渲染。组件文件组织、Props/Emits 约定、Store 集成、跨世界通信。

## 一、组件分布

YiPet 组件分布在三个独立运行环境中：

| 环境 | 入口 | 框架 | 数量 | 说明 |
|------|------|------|------|------|
| Chat Window | `src/chat/` | Vue 3 | 20+ | MAIN World 注入的聊天 SPA |
| Popup | `src/popup/` | Vue 3 | 6 | 扩展弹窗皮肤中心 |
| Floating Pet | `src/content/rendering/` | 原生 DOM | 1 | MAIN World 宠物渲染 |

## 三、组件书写约定

```vue
<script setup lang="ts">
// 强制 Composition API + TypeScript
const props = defineProps<{ title: string; disabled?: boolean }>();
const emit = defineEmits<{ submit: [data: string]; cancel: [] }>();
// 处理 loading/empty/error/data 四种状态，onUnmounted 清理
</script>
```

**核心约定**：

| 约定 | 说明 |
|------|------|
| `<script setup lang="ts">` | 强制 Composition API + TypeScript |
| 泛型 Props/Emits | `defineProps<{...}>()` / `defineEmits<{...}>()` |
| `<style scoped>` | 所有组件样式 scoped |
| Store 访问 | `useChatStore()` + `storeToRefs()` 访问响应式状态 |
| 三态处理 | 每个数据组件处理 loading/empty/error |

## 四、组件与 Store 集成

```typescript
// Chat Window 组件通过 Pinia 访问状态
const chatStore = useChatStore();
const { messages, isProcessing } = storeToRefs(chatStore);
chatStore.sendMessage("Hello");  // 通过 Actions 操作，不直接修改状态
```

**规则**：组件不直接修改状态，所有变更通过 Store Actions。使用 `storeToRefs()` 解构保持响应性。Pinia 自动追踪依赖和清理。

## 五、Popup 组件群

```
App.vue（根组件）
├── AppHeader.vue（渐变头部 + 状态指示器）
├── PetPreview.vue（实时宠物预览 + 大小滑块）
├── RolePicker.vue（角色选择器，2 列卡片网格）

├── AppFooter.vue（版本信息 + 链接）

```

**数据流**：`用户选择 → App.vue 更新本地状态 → chrome.storage.local.set → chrome.tabs.sendMessage（所有标签页） → Content Script → dispatchSecureEvent → MAIN World 更新皮肤`

## 六、Floating Pet（DOM 渲染）

纯 DOM 操作，不依赖 Vue。5 个动画状态：

| 状态 | 触发 | 动画 |
|------|------|------|
| `idle` | 无操作 5s | 呼吸、眨眼、随机动作 |
| `active` | 鼠标悬停 | 抬头、摇尾巴 |
| `thinking` | SSE 流式阶段 | 思考气泡、头部倾斜 |
| `speaking` | 消息完成 | 嘴巴张合、点头（3s 后回 idle） |
| `sleeping` | 无操作 30s | 闭眼、蜷缩、zzZ 气泡 |

动画使用 CSS `@keyframes` + class toggle，9 种预设动画。位置持久化到 `chrome.storage.local`（`petPosition: { x, y }` 百分比）。

## 七、跨世界组件通信

```
Popup → chrome.tabs.sendMessage → ISOLATED World（relay.ts）
  → dispatchSecureEvent(CustomEvent + IPC_SECRET) → MAIN World
  → window.addEventListener → 更新 Chat Store / Floating Pet
```

## 八、反模式

| 反模式 | 正确做法 | 原因 |
|--------|----------|------|
| 组件中直接 fetch | 通过 Chat Store Actions | 破坏状态管理 |
| MAIN World 调 chrome API | 通过 IPC Relay | 无 chrome API |
| 直接修改 Store 状态 | 通过 Store Actions | 破坏单一数据源 |
| 硬编码颜色/尺寸 | CSS 变量 + 角色配置 | 皮肤切换失效 |
| 不处理 SSE 中断 | AbortSignal + onUnmounted | 资源泄漏 |
| Popup 中操作页面 DOM | chrome.tabs.sendMessage | 弹窗隔离 |

## 九、约束

**必须遵守：**
- `<script setup lang="ts">` 语法
- `<style scoped>` 样式隔离
- Props/Emits 泛型形式
- 组件通过 Store Actions 操作状态
- SSE 流式请求 AbortSignal，组件卸载时取消
- 处理 loading/empty/error 三种状态

**禁止：**
- 不在组件中直接调用 ApiClient 或 fetch
- 不在 MAIN World 组件中调用 chrome.* API
- 不用 Options API
- 不忘记清理订阅和请求
