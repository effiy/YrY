# 国际化

> YiPet 国际化体系：chrome.i18n API、消息文件结构、语言检测与回退链、MessageKey 类型安全、占位符与复数、新增语言指南、manifest 国际化、最佳实践。

## 一、国际化架构

```
public/_locales/
├── en/
│   └── messages.json    # 英文源语言（完整，所有键的基准）
└── zh_CN/
    └── messages.json    # 中文翻译（完整，与 en 键一一对应）

src/shared/
├── i18n.ts              # getMessage 封装 + 回退链 + 类型安全
└── utils/
    └── format.ts        # 日期/数字/货币本地化格式化
```

### 架构原则

- **英文为源语言**：`en/messages.json` 是基准，所有新键先在此添加
- **中文为翻译**：`zh_CN/messages.json` 与英文键一一对应
- **类型安全**：`MessageKey` 联合类型确保编译时检查
- **渐进回退**：zh_CN → en → key 原始值

## 二、chrome.i18n API

### 基础 API

| API | 说明 | 返回值 |
|-----|------|--------|
| `chrome.i18n.getMessage(key)` | 获取指定 key 的翻译文本 | `string`（未找到返回 `""`） |
| `chrome.i18n.getMessage(key, substitutions)` | 带占位符替换的翻译 | `string` |
| `chrome.i18n.getAcceptLanguages()` | 获取浏览器接受语言列表 | `Promise<string[]>` |
| `chrome.i18n.getUILanguage()` | 获取 Chrome UI 语言 | `string`（如 `"zh-CN"`） |
| `chrome.i18n.detectLanguage(text)` | 检测文本语言 | `Promise<DetectLanguageResult>` |

### 封装层

```typescript
// src/shared/i18n/index.ts — 实际封装
import { lookupMessage } from './messages';

export function t(key: MessageKey, substitutions?: string | string[]): string {
  // 优先使用运行时缓存（支持用户选择的语言）
  const cached = lookupMessage(key, undefined, substitutions);
  if (cached) return cached;

  // 回退到 Chrome 内置 i18n（浏览器 UI 语言）
  return chrome.i18n.getMessage(key, substitutions) || key;
}
```

**回退链**：运行时缓存（`lookupMessage`）→ `chrome.i18n.getMessage`（浏览器 UI 语言）→ key 原始值

### 在 Vue 组件中使用

```typescript
// 全局注入
app.config.globalProperties.$t = t;

// 模板中使用
<span>{{ $t("popupTitle") }}</span>
<input :placeholder="$t('chatInputPlaceholder')" />

// 脚本中使用
import { t } from "@/shared/i18n";
const label = t("notifyRoleChanged");
```

## 三、消息文件结构

### messages.json 格式

```json
{
  "appName": {
    "message": "YiPet"
  },
  "appDescription": {
    "message": "Your gentle browser companion"
  },
  "popupSubtitle": {
    "message": "Choose your companion's look"
  },
  "chatInputPlaceholder": {
    "message": "Type a message..."
  },
  "sendButton": {
    "message": "Send"
  },
  "contextEnabled": {
    "message": "Page context enabled"
  },
  "knowledgeGrounded": {
    "message": "Knowledge grounded"
  }
}
```

### 消息属性

| 属性 | 必需 | 说明 |
|------|------|------|
| `message` | 是 | 翻译文本 |
| `description` | 推荐 | 描述该消息的用途，帮助翻译者理解上下文 |
| `placeholders` | 否 | 占位符定义（用于动态内容替换） |

### 占位符

```json
{
  "welcomeMessage": {
    "message": "Hello, $NAME$! Welcome to $APP$.",
    "description": "Welcome message shown on first launch",
    "placeholders": {
      "name": {
        "content": "$1",
        "example": "User"
      },
      "app": {
        "content": "$2",
        "example": "YiPet"
      }
    }
  },
  "itemCount": {
    "message": "You have $COUNT$ item(s)",
    "description": "Shows count of items in a list",
    "placeholders": {
      "count": {
        "content": "$1",
        "example": "5"
      }
    }
  }
}
```

使用：

```typescript
t("welcomeMessage", ["User", "YiPet"])
// → "Hello, User! Welcome to YiPet."

t("itemCount", ["5"])
// → "You have 5 item(s)"
```

### 占位符注意事项

- 占位符名使用大写字母和下划线：`$NAME$`, `$COUNT$`
- `$1`, `$2` 等数字占位符按 `t(key, substitutions)` 的数组顺序替换
- 占位符区分大小写：`$NAME$` 和 `$name$` 是不同的
- 如果占位符替换值缺失，原样保留 `$NAME$`

## 四、语言检测与回退链

### 检测逻辑

```typescript
// src/shared/i18n.ts
export type SupportedLocale = "en" | "zh_CN";

export function detectLocale(): SupportedLocale {
  const uiLang = chrome.i18n.getUILanguage();

  // 中文变体统一为 zh_CN
  if (uiLang.startsWith("zh")) return "zh_CN";

  // 默认英文
  return "en";
}

export function getLocaleDisplayName(locale: SupportedLocale): string {
  const names: Record<SupportedLocale, string> = {
    en: "English",
    zh_CN: "简体中文",
  };
  return names[locale];
}
```

### 回退链

```
用户语言（chrome.i18n.getUILanguage()）
  │
  ├── zh* → zh_CN/messages.json
  │     键存在？
  │       → 返回翻译文本
  │     键不存在？
  │       → chrome.i18n.getMessage 返回 ""
  │       → 封装层 t() 返回 key 原始值
  │       → 开发模式下 console.warn 提示
  │
  └── 其他语言 → en/messages.json
        键存在？
          → 返回翻译文本
        键不存在？
          → 返回 key 原始值
```

### 回退行为表

| 场景 | chrome.i18n 行为 | t() 封装行为 |
|------|-----------------|-------------|
| 语言文件存在，键存在 | 返回翻译文本 | 返回翻译文本 |
| 语言文件存在，键不存在 | 返回 `""` | 返回 key 原始值 + 开发模式 warn |
| 语言文件不存在 | 回退到 en 源语言 | 返回 en 翻译或 key 原始值 |
| 占位符替换值不足 | 原样保留 `$NAME$` | 原样保留 |
| 占位符替换值多余 | 忽略多余值 | 忽略多余值 |

- 新增键时 `MessageKey` 联合类型提醒开发者

## 七、manifest 国际化

```json
// manifest.json
{
  "name": "__MSG_appName__",
  "description": "__MSG_appDescription__",
  "default_locale": "en"
}
```

Chrome 自动根据 `default_locale` 和用户语言选择对应的 `_locales/<lang>/messages.json` 中的 `appName` 和 `appDescription`。

## 八、新增内容指南

### 添加新语言

1. 在 `public/_locales/` 下创建语言目录（如 `ja/`）
2. 复制 `en/messages.json` 作为模板
3. 翻译所有 `message` 字段（保留 `placeholders` 结构）
4. 添加 `description` 字段帮助翻译者理解上下文
5. 在 `SupportedLocale` 类型中添加新语言
6. 在 `detectLocale()` 中添加语言检测逻辑

### 添加新消息键

1. 在 `en/messages.json` 中添加英文源文本（含 `description`）
2. 在 `zh_CN/messages.json` 中添加中文翻译
3. 在 `MessageKey` 类型联合中添加新键
4. 使用 `t("newKey")` 在代码中引用

### 命名约定

| 约定 | 示例 | 说明 |
|------|------|------|
| 驼峰命名 | `sendButton`, `chatInputPlaceholder` | JavaScript 风格 |
| 按功能分组前缀 | `popup*`, `chat*`, `notify*`, `action*`, `status*`, `bugReport*` | 便于查找和组织 |
| 描述性命名 | `notifySessionBranched`（非 `notify1`） | 自文档化 |
| 布尔值用形容词 | `contextEnabled`（非 `isContextEnabled`） | 简洁 |
| 避免缩写 | `actionDelete`（非 `actDel`） | 可读性 |

## 九、最佳实践

### 文本组织

- 将长文本拆分为短句，每个短句一个键
- 避免在翻译文本中拼接 HTML 标签（使用占位符或组件）
- 避免在翻译文本中使用 `\n` 换行（使用多个键或 CSS 控制）

### 翻译质量

- 英文源语言必须完整且语法正确
- 中文翻译使用简体中文，保持专业语气
- 按钮文本使用动词（Send、Cancel、Confirm）
- 状态文本使用进行时或形容词（Thinking...、Done）

### 开发流程

- 新增功能时同步添加 i18n 键，不事后补
- 删除功能时同步删除对应的 i18n 键
- 修改已有键的语义时，新增键并废弃旧键（不修改已有键的 `message` 以改变语义）
- 每个 PR 检查 `en/messages.json` 和 `zh_CN/messages.json` 的键是否一一对应

## 十、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 硬编码文本 | `<button>Send</button>` | `<button>{{ $t("sendButton") }}</button>` | 无法国际化 |
| 消息文件中用 HTML | `"message": "Click <a href='#'>here</a>"` | 使用占位符 `$LINK_START$here$LINK_END$` | 安全风险，翻译困难 |
| 键名无意义 | `"msg1": { "message": "..." }` | `"notifySessionExported": { ... }` | 不可维护 |
| 键名不一致 | `"send_btn"` + `"recvButton"` | 统一驼峰 + 功能前缀 | 查找困难 |
| 修改已有键语义 | 将 `"sendButton"` 从 "Send" 改为 "Submit" | 新增 `"submitButton"` 键，废弃旧键 | 其他语言翻译过时 |
| 删除 en 键但保留 zh_CN | 只删除 `en/messages.json` 中的键 | 同步删除所有语言文件中的键 | 翻译孤立 |
| 不添加 description | `"message": "Send"` 无 description | `"description": "Button label for sending a chat message"` | 翻译者不理解上下文 |

## 十一、约束

### 必须遵守
- 所有用户可见文本使用 `t("key")`，不硬编码文本
- 英文 `en/messages.json` 是源语言，必须完整且先行
- 新键先在 `en/messages.json` 中添加，再添加其他语言
- 消息键使用驼峰命名，按功能分组前缀（`popup*`, `chat*`, `notify*`, `action*`, `status*`）
- 每个消息键添加 `description` 字段说明用途
- `MessageKey` 类型与 `en/messages.json` 保持同步

### 禁止
- 不在模板中硬编码中文/英文文本
- 不在消息文件中使用 HTML 标签（使用占位符替代）
- 不删除 `en/messages.json` 中的键（可能被其他语言回退依赖）
- 不修改已有键的语义（如需变更，新增键并废弃旧键）
- 不创建无 `description` 的消息键
- 不在翻译文本中使用 `\n` 换行符
