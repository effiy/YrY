# YiPet 架构概览

> Chrome MV3 扩展的整体架构导航。详细设计见各专项文档。

**专项文档**：[扩展架构](./02-架构-扩展架构.md) · [双世界模型](./03-架构-双世界执行模型.md) · [核心模块](./05-架构-核心模块.md) · [IPC 通信](./06-架构-IPC跨世界通信.md) · [CDN 注入](./07-架构-CDN资源注入.md) · [API 架构](../开发规范/05-规范-API架构与规范.md)

## 一、技术栈

| 类别 | 选型 | 版本 | 说明 |
|------|------|------|------|
| 框架 | Vue 3 | 3.5.x | Composition API，Chat Window + Popup |
| 语言 | TypeScript | 5.x | strict 模式 |
| 构建 | Rsbuild | 1.x | 5 个独立入口 |
| UI 库 | Element Plus | 2.14.x | Popup + Chat Window |
| 状态 | Pinia | 4.x | Setup Store 模式 |
| 测试 | Vitest | 2.x | jsdom 环境 |
| 后端 | YiAi | FastAPI :10086 | RPC 信封协议 |

## 二、整体架构

```
┌─ Popup（Vue 3，皮肤中心）────────────────────────────┐
│  角色/颜色/模型选择 → chrome.storage                   │
├─ Background Service Worker ──────────────────────────┤
│  命令分发 + 消息路由 + chrome.storage                 │
├─ Content Script（ISOLATED World）─────────────────────┤
│  bootstrap.ts → CDN 注入 → IPC 消息转发               │
├─ Chat Window（Vue 3，MAIN World 注入）────────────────┤
│  Chat Store（Pinia）→ ApiClient → YiAi Backend         │
├─ Floating Pet（MAIN World DOM）───────────────────────┤
│  overlay.ts → 皮肤环 + 角色图片 + 动画                 │
└──────────────────────────────────────────────────────┘
```

### 组件职责速查

| 组件 | 运行环境 | 框架 | 职责 |
|------|---------|------|------|
| Popup | 扩展弹窗 | Vue 3 + Element Plus | 皮肤选择、角色切换、模型配置 |
| Service Worker | 后台 | 原生 TS | 命令分发、消息路由、快捷键 |
| Content Script | ISOLATED World | 原生 TS | CDN 注入、IPC 转发、状态管理 |
| Chat Window | MAIN World | Vue 3 + Element Plus | AI 聊天、消息展示、20+ 组件 |
| Floating Pet | MAIN World | 原生 DOM | 皮肤环渲染、角色动画、交互 |

## 三、数据流

```
用户操作 → Chat Store（Pinia）→ ApiClient → fetch → YiAi :10086
                                                         │
Popup 配置 → chrome.storage ←→ Content Script ←→ Service Worker
                │                    │
                └── MAIN World（CustomEvent + IPC_SECRET）
```

**聊天消息直连**：MAIN World → ApiClient → YiAi（不经过 IPC，减少延迟）
**Chrome API 操作**：MAIN World → dispatchSecureEvent → IPC Relay → SW → Chrome API

## 四、双世界执行（Dual-World）

Chrome MV3 扩展在两个隔离 JS 世界中运行：

| 世界 | 可用 API | 职责 |
|------|---------|------|
| **ISOLATED** | `chrome.runtime`, `chrome.storage`, CORS 豁免 | 消息转发、CDN 注入、bootstrap |
| **MAIN** | DOM, `window`, 无 `chrome.*` | Chat Window（Vue 3）、Floating Pet |

通信：`Popup → chrome.tabs.sendMessage → ISOLATED → dispatchSecureEvent(CustomEvent + IPC_SECRET) → MAIN`

详见 [双世界执行模型](./03-架构-双世界执行模型.md) 和 [IPC 通信](./06-架构-IPC跨世界通信.md)。

## 五、4-Tier API 层

```
Layer 1: ApiClient — fetch 封装、RPC 信封、SSE 解析、错误处理
Layer 2: Endpoints — 路径常量集中管理
Layer 3: Types — 请求/响应类型定义
Layer 4: Services — 8 个领域服务类（Chat, Session, Database, Knowledge, Rag, Bug, Auth, WeWork）
```

详见 [API 架构与规范](../开发规范/05-规范-API架构与规范.md)。

## 六、多入口构建

| 入口 | 配置文件 | 输出 | 约束 |
|------|----------|------|------|
| popup | `rsbuild.config.ts` | `dist/popup.html` | 独立 HTML |
| background | `rsbuild.config.ts` | `dist/assets/background.js` | 单文件，禁代码分割 |
| chat | `rsbuild.config.chat.ts` | `dist/assets/chat.js` | 禁文件名哈希 |
| cdn | `rsbuild.config.cdn.ts` | `dist/cdn/` | 独立 chunk |
| bootstrap | `rsbuild.config.bootstrap.ts` | `dist/assets/bootstrap.js` | 单文件，< 50KB |

详见 [构建部署](../流程规范/05-流程-构建部署.md)。

## 七、Chrome MV3 约束

| 约束 | 处理 |
|------|------|
| SW 非持久化（空闲 30s 终止） | 状态持久化到 chrome.storage |
| 禁止远程代码执行 | 所有代码预打包到 dist/ |
| 禁止 eval | 编译时处理所有动态逻辑 |
| Content Script 隔离 | window.postMessage + IPC_SECRET |
| storage 配额 | local 无限制，大数据优先 |

## 八、设计原则

- **关注点分离**：Content Script 只做转发，SW 只做命令分发，Chat Window 独立 SPA 可单独测试
- **类型安全**：TypeScript strict，所有 API 请求/响应明确定义类型
- **降级优先**：外部依赖有降级方案，非关键资源失败不阻塞核心功能
- **双世界隔离**：MAIN 不调 chrome.*，ISOLATED 不操作页面 DOM

## 九、约束

**必须遵守：**
- 所有 API 调用通过 ApiClient
- Content Script 和 SW 状态分离，通过消息通信
- 使用 chrome.storage 持久化（非内存变量）
- 参数名 `filter`（非 `query`）、`target_file`（非 `path`）
- 注入前检查 `__YIPET_LOADED__` 防重复

**禁止：**
- MAIN World 中使用 chrome.* API
- 绕过 ApiClient 直接 fetch
- 动态加载外部 JS（MV3 CSP）
- 硬编码 API 地址
