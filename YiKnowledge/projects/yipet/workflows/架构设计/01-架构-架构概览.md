## 四、双世界执行（Dual-World）

Chrome MV3 扩展在两个隔离的 JavaScript 世界中运行：

| 世界 | 运行环境 | API 可用 | 职责 |
|------|---------|---------|------|
| **ISOLATED World** | Content Script | `chrome.runtime`, `chrome.storage` | 消息转发、DOM 注入、bootstrap |
| **MAIN World** | 页面注入 | DOM, `window`, 无 `chrome.*` | Chat Window（Vue 3）、Floating Pet（DOM） |

### 跨世界通信

```
MAIN World（聊天窗口）
  │ 用户操作
  │ → dispatchSecureEvent('yipet:...', { ... })  （CustomEvent + IPC_SECRET）
  ↓
ISOLATED World（Content Script）
  │ 监听 chrome.runtime.onMessage（Popup → CS，action-based）
  │ 监听 CustomEvent（MAIN → CS，IPC_SECRET 验证）
  │ → chrome.runtime.sendMessage({ action: ... })
  ↓
Background Service Worker
  │ 处理消息，调用 chrome.* API
  │ → chrome.storage, chrome.tabs, chrome.runtime
  ↓
响应回传
  │ chrome.runtime.sendMessage → Content Script
  │ → dispatchSecureEvent → MAIN World
```

### 跨世界消息类型

| 消息方向 | 通道 | 消息格式 | 说明 |
|----------|------|----------|------|
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'setRole', role: string }` | 角色/颜色/模型变更 |
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'toggleChat' }` | 切换聊天窗口 |
| Content Script → MAIN | `dispatchSecureEvent` (CustomEvent) | `yipet:visibilityChanged` / `yipet:chatToggled` | 安全事件分发 |
| Content Script → SW | `chrome.runtime.sendMessage` | `{ action: 'DISCUSS_PAGE', data }` | 页面讨论请求 |
| SW → Content Script | `chrome.tabs.sendMessage` | `{ action: 'TOGGLE_PET' }` / `{ action: 'OPEN_CHAT' }` | 快捷键命令 |

## 五、4-Tier API 层

```
Layer 1: ApiClient（fetch 封装）
  ├── 请求拦截：注入 Token、Content-Type
  ├── RPC 信封：{ module_name, method_name, parameters }
  ├── SSE 流式：解析 text/event-stream
  ├── 错误处理：指数退避重试 + 状态码映射
  └── 响应解析：StandardResponse → 业务数据

Layer 2: Endpoints（路径常量）
  ├── API_BASE, RPC_ENDPOINT, SSE_ENDPOINT
  └── 所有端点路径集中管理

Layer 3: Types（请求/响应类型）
  ├── RpcRequest, RpcResponse<T>
  ├── 各服务的请求/响应接口
  └── SSE 事件类型

Layer 4: Services（领域服务类）
  ├── ChatService, SessionService, DataService
  ├── KnowledgeService, RagService
  └── 每个 Service 封装一个后端领域
```

### API 调用流程

```
Service.method(params)
  → ApiClient.post(endpoint, rpcEnvelope)
  → fetch(url, { method: "POST", headers, body })
  → 响应拦截器：检查 code → 错误处理/重试
  → 返回业务数据
```

### ApiClient 实现

```typescript
// src/api/client.ts
class ApiClient {
  private baseUrl: string;
  private token: string | null;

  constructor(baseUrl: string) {
    this.baseUrl = baseUrl;
  }

  setToken(token: string | null) {
    this.token = token;
  }

  async post<T>(endpoint: string, body: Record<string, any>): Promise<T> {
    const headers: HeadersInit = {
      "Content-Type": "application/json",
    };
    if (this.token) {
      headers["X-Token"] = this.token;
    }

    const response = await fetch(`${this.baseUrl}${endpoint}`, {
      method: "POST",
      headers,
      body: JSON.stringify(body),
    });

    const data = await response.json();

    if (data.code !== 0) {
      return { ok: false, status: response.status, data: null, error: data.message };
    }

    return data.data as T;
  }

  async streamChat(
    payload: ChatPayload,
    onChunk: (text: string) => void,
    onDone: () => void,
    signal?: AbortSignal
  ): Promise<void> {
    const response = await fetch(`${this.baseUrl}/`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "X-Token": this.token || "",
      },
      body: JSON.stringify({
        module_name: "services.ai.chat_service",
        method_name: "chat",
        parameters: payload,
      }),
      signal,
    });

    const reader = response.body?.getReader();
    const decoder = new TextDecoder();
    let buffer = "";

    while (true) {
      const { done, value } = await reader!.read();
      if (done) { onDone(); break; }

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split("\n");
      buffer = lines.pop() || "";

      for (const line of lines) {
        if (line.startsWith("data: ")) {
          const data = line.slice(6);
          if (data === "[DONE]") { onDone(); return; }
          try {
            const parsed = JSON.parse(data);
            if (parsed.data?.message) onChunk(parsed.data.message);
          } catch { /* skip malformed */ }
        }
      }
    }
  }
}
```

### 服务层示例

```typescript
// src/api/services/chatService.ts
class ChatService {
  constructor(private client: ApiClient) {}

  async sendMessage(
    messages: ChatMessage[],
    onChunk: (text: string) => void,
    signal?: AbortSignal
  ): Promise<void> {
    return this.client.streamChat(
      {
        model: "qwen2.5",
        messages: messages.map(m => ({ role: m.role, content: m.content })),
        stream: true,
      },
      onChunk,
      () => {}, // onDone
      signal
    );
  }
}
```

## 六、多入口构建

YiPet 使用 Rsbuild 多入口构建，每个入口有独立的配置文件：

| 入口 | 配置文件 | 输出 | 运行环境 | 约束 |
|------|----------|------|----------|------|
| popup | `rsbuild.config.ts` | `dist/popup.html` + `popup.js` | 扩展弹窗 | 无特殊约束 |
| background | `rsbuild.config.ts` | `dist/assets/background.js` | Service Worker | 禁用代码分割 |
| chat | `rsbuild.config.chat.ts` | `dist/assets/chat.js` | MAIN World 注入 | 禁用文件名哈希 |
| cdn | `rsbuild.config.cdn.ts` | `dist/cdn/` | 按需注入 | 输出 Vue + Element Plus |
| bootstrap | `rsbuild.config.bootstrap.ts` | `dist/assets/bootstrap.js` | Content Script | 禁用代码分割 |

### 构建约束

| 约束 | 说明 | 原因 | 影响入口 |
|------|------|------|----------|
| 文件名哈希 | 禁用 | MV3 manifest 引用固定文件名 | 所有 |
| 代码分割 | 禁用 | Service Worker 需要单文件 | background, bootstrap |
| 自动导入 | Element Plus 组件 + Vue API | unplugin-auto-import | chat, popup |
| 构建元数据 | 自动生成 `dist/build-meta.json` | 版本追踪 | 所有 |

## 七、注入流程

```
页面加载
  → Content Script（bootstrap.ts）注入到 ISOLATED World
  → 检查 window.__YIPET_LOADED__（防止重复注入）
  → 注入 CDN 资源（Vue, Element Plus, 样式）
  → 创建 MAIN World 脚本标签
  → MAIN World 初始化：
    ├── Chat Window（Vue 3 SPA）
    └── Floating Pet（DOM overlay）
  → Floating Pet 渲染到页面 DOM
```

### 注入实现

```typescript
// src/content/bootstrap.ts
const YIPET_LOADED_KEY = "__YIPET_LOADED__";

async function inject(): Promise<void> {
  // 防止重复注入
  if ((window as any)[YIPET_LOADED_KEY]) return;
  (window as any)[YIPET_LOADED_KEY] = true;

  // 注入 CDN 资源
  await injectStyles(chrome.runtime.getURL("cdn/styles/variables.css"));
  await injectStyles(chrome.runtime.getURL("cdn/styles/chat.css"));
  await injectScript(chrome.runtime.getURL("cdn/vendor/vue@3.5.13/vue.global.prod.js"));
  await injectScript(chrome.runtime.getURL("cdn/vendor/bootstrap@5.2.3/js/bootstrap.bundle.min.js"));

  // 注入 Chat Window（含 Floating Pet 渲染）
  await injectScript(chrome.runtime.getURL("assets/chat.js"));
}

function injectScript(src: string): Promise<void> {
  return new Promise((resolve, reject) => {
    const script = document.createElement("script");
    script.src = src;
    script.onload = () => resolve();
    script.onerror = () => reject(new Error(`Failed to load: ${src}`));
    (document.head || document.documentElement).appendChild(script);
  });
}

inject().catch(console.error);
```

## 九、Chrome MV3 约束

| 约束 | 影响 | 处理方式 |
|------|------|----------|
| Service Worker 生命周期 | 非持久化，空闲时被终止 | 状态持久化到 chrome.storage |
| 禁止远程代码执行 | 不能动态加载外部 JS | 所有代码预打包到 dist/ |
| Manifest V3 声明 | 权限和 host 声明式配置 | manifest.json 精确声明 |
| chrome.storage 配额 | 10MB（sync）/ 无限制（local） | 大数据使用 local |
| 禁止 eval | 不能用 `new Function()` | 编译时处理所有动态逻辑 |
| Content Script 隔离 | 不能直接访问页面 JS 变量 | 通过 window.postMessage 通信 |

## 十一、降级策略

| 场景 | 处理 | 恢复方式 |
|------|------|----------|
| YiAi 不可达 | API 客户端指数退避重试（1s → 2s → 4s → ... max 30s） | YiAi 恢复后自动连接 |
| CDN 资源已加载 | 全局存在检查短路（`window.__YIPET_LOADED__`） | 跳过重复注入 |
| 存储配额超限 | 非关键数据写入静默失败，关键数据降级到 localStorage | 用户清理存储 |
| 语言消息缺失 | 回退 en → key 原始值 | 更新语言包 |
| Chrome MV3 不支持 | 检测 `chrome.runtime` 可用性，优雅降级 | 提示用户升级浏览器 |
| Content Script 注入失败 | 重试 3 次，间隔 500ms | 页面刷新后重试 |
| SSE 连接中断 | 自动重连（最多 3 次，指数退避） | 连接恢复后继续 |

## 十二、设计原则

### 关注点分离
- **Content Script**：只负责消息转发和 DOM 注入，不包含业务逻辑
- **Service Worker**：只负责命令分发和 chrome API 调用，不直接操作 DOM
- **Chat Window**：独立 Vue 3 SPA，不依赖 chrome API，可独立测试
- **Floating Pet**：纯 DOM 操作，不依赖 Vue，轻量级渲染

### 类型安全
- TypeScript strict 模式
- 所有 API 请求/响应定义明确类型
- 4 层 API 架构，每层有明确的类型边界

### 降级优先
- 所有外部依赖（YiAi、CDN）都有降级方案
- 存储配额超限不阻塞核心功能
- 语言文件缺失有回退链

### 双世界隔离
- MAIN World 不能使用 chrome.* API
- ISOLATED World 不能直接操作页面 DOM
- 跨世界通信仅通过 postMessage + chrome.runtime.sendMessage

## 十三、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 在 MAIN World 中使用 chrome.* | `chrome.storage.local.get()` 在 chat.ts 中 | 通过 postMessage 转发到 ISOLATED World | MAIN World 无 chrome API |
| 绕过 ApiClient | `fetch(url, ...)` 直接在组件中 | 使用 `ApiClient.post()` 或 Service 方法 | 失去 Token 注入和错误处理 |
| 动态加载外部 JS | `import(url)` 动态加载 | 所有代码预打包 | MV3 禁止远程代码 |
| 混用双世界状态 | Content Script 和 Service Worker 共享变量 | 通过 chrome.storage 或消息传递 | 两个世界隔离 |
| 硬编码 API 地址 | `fetch("http://localhost:10086")` | 使用 `RSBUILD_API_BASE` 环境变量 | 不可配置 |
| 忽略重复注入 | 不检查 `__YIPET_LOADED__` | 注入前检查全局标志 | 多次注入导致错误 |
| 不处理 SSE 中断 | 用户关闭页面后 SSE 连接未断开 | 使用 AbortSignal 取消 | 资源泄漏 |

## 十四、约束

### 必须遵守
- 所有 API 调用通过 ApiClient，不直接使用 fetch
- Content Script 和 Service Worker 状态分离，通过消息通信
- 使用 chrome.storage 持久化状态（非内存变量）
- 构建禁用文件名哈希和代码分割
- 参数名使用 `filter`（非 `query`）、`target_file`（非 `path`）
- 注入前检查 `__YIPET_LOADED__` 防止重复注入
- SSE 流式请求必须处理中断（AbortSignal）

### 禁止
- 不在 MAIN World 中使用 chrome.* API
- 不绕过 ApiClient 直接调用 fetch
- 不动态加载外部 JS（MV3 CSP 限制）
- 不混用 Content Script 和 Service Worker 状态
- 不硬编码 API 地址和配置
- 不忽略 SSE 请求的取消清理
