# 核心模块

> YiPet 核心模块详解：Chat Store（Pinia）状态管理、Popup 皮肤中心、Bootstrap 双世界注入、IPC 跨世界通信、CDN 资源加载器、Background Service Worker、Floating Pet 渲染引擎。

## 一、模块总览

| 模块 | 文件 | 运行环境 | 框架 | 职责 |
|------|------|----------|------|------|

## 二、Chat Store（聊天状态管理）

### 架构模式

Chat Store 是聊天窗口的单一状态源，使用 **Pinia Store（Composition API）** 模式：

```
用户操作（UI 组件）
  │ 调用 chatStore.sendMessage(text)
  ▼
Pinia Chat Store（响应式状态 + 操作）
  │ 通过 reactive() 更新状态 → Vue 自动追踪依赖
  │ 调用 ApiClient → YiAi Backend
  ▼
Vue 组件（ChatWindow, ChatMessages, ChatInput...）
  │ 通过 storeToRefs() 解构响应式状态
  │ 状态变更 → Vue 响应式重渲染
```

### 状态管理

```typescript
// src/chat/types.ts
interface ChatState {

interface Message {
  id: string;
  role: "user" | "pet" | "system";
  content: string;
  timestamp: number;
  model?: string;
  sources?: RagSource[];
  toolCalls?: ToolCall[];
  error?: string;
}

interface Session {
  id: string;
  title: string;
  model: string;
  messageCount: number;
  createdAt: number;
  updatedAt: number;
  tags?: string[];
}
```

> 注：状态通过 `reactive()` 包裹，Vue 自动追踪依赖。组件通过 `useChatStore()` + `storeToRefs()` 消费。无需手动订阅/发布机制。

### 核心操作

| 操作 | 签名 | 说明 |
|------|------|------|
| `sendMessage` | `(text: string) => Promise<void>` | 发送消息，触发 SSE 流式聊天 |
| `stopSending` | `() => void` | 中止当前流式请求 |
| `selectSession` | `(id: string) => Promise<void>` | 切换会话，加载历史消息 |
| `createSession` | `(opts?: CreateSessionOpts) => Promise<string>` | 创建新会话 |
| `deleteSession` | `(id: string) => Promise<void>` | 删除会话 |
| `renameSession` | `(id: string, title: string) => Promise<void>` | 重命名会话 |
| `toggleKnowledgeGrounded` | `() => void` | 切换知识库增强模式 |
| `setRagScopeFromNode` | `(path: string, isFile: boolean) => void` | 设置 RAG 检索范围 |
| `exportCurrentSessionMarkdown` | `() => void` | 导出会话为 Markdown 文件 |
| `branchFromMessage` | `(timestamp: number) => Promise<void>` | 从指定消息分叉新会话 |
| `summarizeCurrentSession` | `() => Promise<void>` | 生成会话摘要 |
| `autoGenerateSessionTitle` | `(opts?: AutoTitleOpts) => Promise<void>` | 自动生成会话标题 |
| `regenerateMessage` | `(timestamp: number) => Promise<void>` | 重新生成指定消息 |
| `editMessage` | `(timestamp: number, content: string) => Promise<void>` | 编辑消息并重新发送 |

### 流式处理流程

```
sendMessage(text)
  │
  ├── 1. 推送提示词到历史 (pushPromptHistory)
  ├── 2. 添加用户消息到 state.messages
  ├── 3. 添加空的宠物消息占位
  ├── 4. 设置 isProcessing = true, streamingType = "send"
  │
  ├── 5. 构建消息列表
  │     ├── 系统提示词（角色定义 + 页面上下文）
  │     ├── 历史消息（最近 N 轮）
  │     └── 当前用户消息
  │
  ├── 6. 判断聊天模式
  │     ├── knowledgeGrounded && ragScopeIsFile
  │     │     → RagService.streamFileChat({ target_file, question })
  │     │     → 对单个知识文件进行 RAG 聊天
  │     ├── knowledgeGrounded && !ragScopeIsFile
  │     │     → RagService.streamChat({ messages, scope, category })
  │     │     → 对目录范围进行 RAG 检索聊天
  │     └── 普通模式
  │           → ChatService.streamWithCallback({ messages, model, system })
  │           → 直接 LLM 聊天（无 RAG）
  │
  ├── 7. SSE 流式处理
  │     ├── onToken(text) → 追加到宠物消息 content（Vue 响应式自动更新）
  │     ├── onThinking() → streamingPhase = "thinking"
  │     ├── onRetrieving() → streamingPhase = "retrieving"
  │     ├── onStreaming() → streamingPhase = "streaming"
  │     ├── onSources(sources) → 更新 ragSources
  │     ├── onToolCall(call) → 追加 toolCalls 到消息
  │     ├── onDone() → 标记消息完成，更新 ragSources
  │     └── onError(err) → 消息标记 error，显示重试按钮
  │
  └── 8. finally
        ├── isProcessing = false
        ├── streamingType = ""
        ├── streamingPhase = ""
        ├── 持久化会话 (sessions.upsert)
        ├── 自动生成标题（如果是新会话的首条消息）
        └── Vue 响应式系统自动更新 UI
```

### 持久化策略

| 数据 | 存储位置 | 键名 | 序列化 |
|------|---------|------|--------|
| 会话列表 | chrome.storage.local | `sessions` | JSON |
| 当前会话 ID | chrome.storage.local | `currentSessionId` | string |
| 知识库开关 | chrome.storage.local | `knowledgeGrounded` | boolean |
| RAG 范围 | chrome.storage.local | `ragScope` | string |
| 侧边栏宽度 | chrome.storage.local | `sidebarWidth` | number |
| 提示词历史 | chrome.storage.local | `promptHistory` | JSON |
| 聊天可见性 | chrome.storage.local | `chatVisible` | boolean |

### Vue 集成

组件通过 Pinia `useChatStore()` + `storeToRefs()` 直接消费：

```typescript
// src/chat/components/ChatWindow.vue
import { useChatStore } from '@/chat/stores/chat';
import { storeToRefs } from 'pinia';

const chatStore = useChatStore();
const { isProcessing, messages, chatVisible } = storeToRefs(chatStore);

// 调用操作
chatStore.sendMessage('Hello');

// 响应式状态自动追踪，无需手动订阅
```

### 数据流

```

  │

  │
```

## 四、Bootstrap（双世界注入）

### 注入流程

```
页面加载
  │ manifest.json content_scripts 匹配 URL 模式
  │ "matches": ["<all_urls>"]
  ▼
Content Script（bootstrap.ts）注入到 ISOLATED World
  │
  ├── 1. 检查 window.__YIPET_LOADED__
  │     已加载 → 短路退出（日志记录）
  │     未加载 → 继续
  │
  ├── 2. 注入 CDN 资源（CSS 并行优先，JS 顺序加载）
  │     ├── cdn/styles/variables.css（CSS 变量）
  │     ├── cdn/styles/chat.css（聊天组件样式）
  │     ├── cdn/styles/pet.css（宠物皮肤样式）
  │     ├── cdn/vendor/vue@3.5.13/（Vue 3 运行时）
  │     ├── cdn/vendor/bootstrap@5.2.3/（UI 框架）
  │     └── cdn/utils/index.js（API 客户端 + 工具函数）
  │
  ├── 3. 设置全局标志
  │     window.__YIPET_LOADED__ = true
  │
  ├── 4. 创建 MAIN World 脚本标签
  │     const script = document.createElement("script")
  │     script.src = chrome.runtime.getURL("assets/chat.js")
  │     script.onload = () => { /* 初始化完成 */ }
  │     script.onerror = () => { /* 错误记录，继续加载后续资源 */ }
  │     document.documentElement.appendChild(script)
  │
  ├── 5. 创建 Floating Pet 渲染标签
  │     const script = document.createElement("script")
  │     script.src = chrome.runtime.getURL("assets/chat.js")
  │     document.documentElement.appendChild(script)
  │
  ▼
MAIN World 初始化
  │
  ├── 6. 挂载 Chat Window（Vue 3 SPA）
  │     createApp(ChatWindow).mount("#yipet-chat-root")
  │     ├── 初始化 Chat Store（Pinia 状态管理）
  │     ├── 从 chrome.storage 恢复会话状态（通过 IPC）
  │     ├── 注册全局快捷键监听
  │     └── 初始化 IPC Relay（MAIN World 侧）
  │
  └── 7. 渲染 Floating Pet
        overlay.render(document.body)
        ├── 创建 DOM 元素（position: fixed, pointer-events: none）
        ├── 加载角色图片（从 chrome.runtime.getURL）
        ├── 启动 idle 动画循环（CSS animation + requestAnimationFrame）
        └── 绑定事件监听（hover, click, drag）
```

### 注入约束

| 约束 | 处理 | 说明 |
|------|------|------|
| 重复注入 | `window.__YIPET_LOADED__` 全局检查短路 | 同一页面生命周期内只注入一次 |
| 注入失败 | 异常被捕获并跳过，加载继续 | 非 VUE/api-client 资源失败不阻塞注入 |
| VUE/api-client 失败 | `loadJS` reject → `injectAll` catch 继续 | 后续 JS 资源仍会尝试加载 |
| 已加载资源 | `loaded` Map 检查短路重复注入 | 全局存在性检查（`window[global]`）也防止重复 |
| 页面 CSP 限制 | 使用 `chrome.runtime.getURL` 获取扩展内资源 | 满足 MV3 CSP 合规 |
| 页面已有 Vue | 扩展自带 Vue 3 运行时，不依赖页面 | 通过 CDN 注入，隔离运行 |

## 五、IPC Relay（跨世界通信）

### 消息桥接架构

```
┌─ MAIN World ───────────────────────────────────────────┐
│  chat/ + overlay.ts                                     │
│    │ 需要 chrome API 时                                  │
│    │ 通过 dispatchSecureEvent 发送 CustomEvent           │
│    │ dispatchSecureEvent('yipet:discussPage', {url})     │
│    ▼                                                     │
├─ ISOLATED World ───────────────────────────────────────┤
│  content/ipc/relay.ts                                  │
│    │ chrome.runtime.onMessage.addListener(handler)       │
│    │ 处理 Popup 发来的 action 消息                       │
│    │ dispatchSecureEvent (CustomEvent + IPC_SECRET)      │
│    │ IPC_SECRET 签名验证                              │
│    │ chrome.runtime.sendMessage({ action, ... })         │
│    ▼                                                     │
├─ Service Worker ───────────────────────────────────────┤
│  background/index.ts                                    │
│    │ chrome.runtime.onMessage.addListener(handler)       │
│    │ 处理 action 命令 → chrome.tabs / chrome.storage     │
│    ▼                                                     │
└─ Chrome Browser API ───────────────────────────────────┘
```

### 消息流向

| 消息方向 | 通道 | 消息格式 | 说明 |
|----------|------|----------|------|
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'setRole', role: string }` | 角色/颜色/模型变更 |
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'toggleChat' }` | 切换聊天窗口 |
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'setColor', color: string }` | 颜色变更 |
| Popup → Content Script | `chrome.tabs.sendMessage` | `{ action: 'setModel', model: string }` | 模型变更 |
| ISOLATED → MAIN | `dispatchSecureEvent` (CustomEvent) | `yipet:chatToggled` / `yipet:roleChanged` / `yipet:colorChanged` | 安全事件分发 |
| Content Script → SW | `chrome.runtime.sendMessage` | `{ action: 'DISCUSS_PAGE', data }` | 页面讨论请求 |
| SW → Content Script | `chrome.tabs.sendMessage` | `{ action: 'toggleVisibility' }` / `{ action: 'toggleChat' }` / `{ action: 'extensionUpdated', ... }` | 快捷键广播 + 更新通知 |

### 完整实现

```typescript
// content/ipc/relay.ts
const IPC_SECRET = crypto.randomUUID();

function dispatchSecureEvent<T>(name: string, detail: T): void {
  window.dispatchEvent(new CustomEvent(name, {
    detail: {
      __yipet: true,
      __signature: IPC_SECRET,
      __timestamp: Date.now(),
      data: detail,
    },
  }));
}

// 监听 Popup 消息
chrome.runtime.onMessage.addListener((msg: PopupToContent, _sender, sendResponse) => {
  switch (msg.action) {
    case 'setRole':
      _petRole = validateRole(msg.role);
      applyRole(_petRole);
      persist();
      sendResponse({ success: true, role: _petRole });
      break;
    case 'toggleChat':
      dispatchSecureEvent('yipet:chatToggled', {});
      sendResponse({ success: true });
      break;
    // ... 其他 action
  }
  return true;
});
```

### 加载策略

| 资源类型 | 加载时机 | 加载方式 | 失败处理 |
|----------|---------|---------|----------|
| 样式文件 | Bootstrap 阶段（优先） | `<link>` 标签注入 | 降级：无样式，功能可用 |
| Vue 3 运行时 | Bootstrap 阶段 | `<script>` 标签注入 | 失败则 catch 继续，后续资源仍加载 |
| api-client (utils/index.js) | Bootstrap 阶段 | `<script>` 标签注入 | 失败则 catch 继续，后续资源仍加载 |
| Bootstrap 等 UI 库 | Bootstrap 阶段 | `loadByKey` 按需加载 | 失败不影响其他资源加载 |

### 加载器实现

```typescript
// src/content/cdn/injector.ts
export function createInjector(baseUrl: string): CdnInjector {
  const loaded = new Map<string, boolean>();

  function loadByKey(key: string): Promise<boolean> | boolean {
    const entry = catalogByKey[key];
    if (!entry) { console.warn(`Unknown resource: "${key}"`); return false; }
    // 全局存在性检查短路重复注入
    if (entry.global && (window as any)[entry.global] !== undefined) {
      return entry.type === 'js' ? Promise.resolve(false) : false;
    }
    return entry.type === 'js' ? loadJS(entry.path) : loadCSS(entry.path);
  }

  async function injectAll(): Promise<void> {
    // CSS 优先（并行）
    for (const entry of CDN_CATALOG) {
      if (entry.type === 'css') loadCSS(entry.path);
    }
    // JS 串行（保证依赖顺序）
    for (const entry of CDN_CATALOG) {
      if (entry.type === 'js') {
        try { await loadJS(entry.path); } catch { /* continue */ }
      }
    }
  }

  return { loadJS, loadCSS, loadByKey, injectAll };
}
```

```typescript
// src/background/index.ts
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  switch (message.action) {
    case "DISCUSS_PAGE": {
      // 将页面上下文转发到聊天窗口
      chrome.tabs.sendMessage(sender.tab!.id!, {
        action: "OPEN_CHAT_WITH_CONTEXT",
        data: message.data,
      });
      break;
    }

    case "TOGGLE_PET": {
      // 切换宠物显隐，广播到当前标签页
      chrome.tabs.query({ active: true, currentWindow: true }, ([tab]) => {
        if (tab?.id) {
          chrome.tabs.sendMessage(tab.id, { action: "TOGGLE_PET" });
        }
      });
      break;
    }

    case "GET_STORAGE": {
      chrome.storage.local.get(message.key, (result) => {
        sendResponse(result[message.key]);
      });
      return true;  // 保持消息通道开放（异步响应）
    }

    case "SET_STORAGE": {
      chrome.storage.local.set({ [message.key]: message.value }, () => {
        sendResponse({ success: true });
      });
      return true;
    }
  }
});

// 快捷键处理
chrome.commands.onCommand.addListener(async (command) => {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
  if (!tab?.id) return;

  switch (command) {
    case "toggle-pet":
      chrome.tabs.sendMessage(tab.id, { action: "TOGGLE_PET" });
      break;
    case "open-chat":
      chrome.tabs.sendMessage(tab.id, { action: "OPEN_CHAT" });
      break;
  }
});

// 安装/更新时初始化
chrome.runtime.onInstalled.addListener(async (details) => {
  if (details.reason === "install") {
    // 设置默认配置
    await chrome.storage.local.set({
      role: "cat",
      color: "blue",
      model: "qwen3.5",
      petVisible: true,
      language: "zh_CN",
      petPosition: { x: 80, y: 50 },
    });
  }
});
```

## 十、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 组件中直接调用 ApiClient | `fetch(url, ...)` 在 Vue 组件中 | 通过 Chat Store Actions | 破坏状态管理，难以追踪 |
| 在 MAIN World 调用 chrome API | `chrome.storage.local.get()` 在 chat.ts 中 | 通过 IPC Relay 请求 | MAIN World 无 chrome API |
| 绕过 CDN Injector 注入脚本 | 在 bootstrap 中直接 `createElement("script")` | 使用 `createInjector` + `loadByKey` 统一管理 | 失去重复检测和错误处理 |
| 直接修改 Store 状态 | `chatStore.state.messages.push(msg)` | 通过 Store Actions（如 `sendMessage()`） | 破坏 Pinia 响应式追踪 |
| 不处理 SSE 中断 | 用户关闭页面后连接未断开 | 使用 AbortSignal + onUnmounted 清理 | 资源泄漏 |
| 硬编码角色配置 | 角色定义散落在多个文件中 | 集中在 `data.ts` 的 `ROLES` 数组中 | 难以维护 |
| 不验证 postMessage 来源 | `window.addEventListener("message", fn)` 无验证 | 使用 `dispatchSecureEvent` 的 `IPC_SECRET` + 时间戳验证 | 安全风险 |

## 十一、约束

### 必须遵守
- Chat Store（Pinia）是聊天状态的唯一数据源，组件不直接修改状态
- 所有 API 调用通过 ApiClient，组件通过 Store Actions 间接调用
- 跨世界通信必须通过 IPC Relay，不在 MAIN World 中调用 chrome.* API
- CDN 资源加载前检查 `window.__YIPET_LOADED__` 防止重复注入
- 持久化数据使用 `chrome.storage.local`，不使用 `localStorage`
- 组件通过 Store Actions 操作状态，Pinia 自动追踪依赖并清理
- SSE 流式请求使用 AbortSignal 管理，组件卸载时取消

### 禁止
- 不在组件中直接调用 ApiClient（通过 Store Actions 操作）
- 不在 MAIN World 代码中调用 `chrome.runtime.*` API
- 不在 ISOLATED World 代码中直接操作页面 DOM
- 不绕过 CDN Injector 直接创建 `<script>` 标签
- 不混用 ISOLATED 和 MAIN World 的状态
- 不直接修改 Chat Store 的响应式状态
- 不忘记在组件卸载时清理 AbortSignal 和事件监听
