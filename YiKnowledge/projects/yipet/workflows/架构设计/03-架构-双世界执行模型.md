# 双世界执行模型

> Chrome MV3 扩展的核心架构——Content Script (ISOLATED World) 与 MAIN World 的双上下文执行模型。涵盖 IPC 协议、安全验证、消息生命周期、调试策略。

## 一、架构概览

```
┌────────────────────────────────────────────────────┐
│  Popup（Vue 3，独立窗口，每次打开重新渲染）         │
│  chrome.tabs.sendMessage ←→ Content Script          │
│  chrome.storage.local（读写用户配置）                │
├────────────────────────────────────────────────────┤
│  Content Script（ISOLATED World — manifest 声明）    │
│  ✓ chrome.runtime、chrome.storage、chrome.tabs      │
│  ✓ 跨域 fetch（CORS 豁免）                          │
│  ✓ extension URL 资源加载                           │
│  ✗ 宿主页面 window 全局变量                         │
│  ✗ 宿主页面 JS 对象（Vue/React 实例）               │
├────────────────────────────────────────────────────┤
│  postMessage 通道（security: IPC_SECRET + timestamp） │
├────────────────────────────────────────────────────┤
│  Bootstrap（MAIN World — 动态注入 <script>）         │
│  ✓ 宿主页面 window 全局变量                         │
│  ✓ 宿主页面 DOM 操作                                │
│  ✓ CDN 资源加载（Vue, Element Plus）                │
│  ✗ chrome.runtime.* 全部 API                        │
│  ✗ extension URL（chrome-extension://）              │
└────────────────────────────────────────────────────┘
```

## 二、双世界能力边界

| 能力 | ISOLATED World | MAIN World | 说明 |
|------|:---:|:---:|------|
| `chrome.runtime.sendMessage` | ✓ | ✗ | ISOLATED 独有 |
| `chrome.runtime.onMessage` | ✓ | ✗ | ISOLATED 独有 |
| `chrome.runtime.getURL` | ✓ | ✗ | 加载扩展内置资源 |
| `chrome.storage.local` | ✓ | ✗ | 扩展隔离存储 |
| `fetch`（跨域） | ✓ | ✗ | ISOLATED 有 CORS 豁免 |
| `window.postMessage` | ✓ | ✓ | 唯一可用的跨世界通道 |
| `document.createElement('script')` | ✓ | ✓ | DOM 操作两世界均可 |
| `document.querySelector` | ✓ | ✓ | 同一 DOM 树，两世界均可操作 |
| 宿主页面 `window.myData` | ✗ | ✓ | 两个世界的 window 属性不共享 |
| 宿主页面 `Vue`/`React` 实例 | ✗ | ✓ | MAIN 世界独有 |
| `eval` / `new Function` | ✗ | ✗ | MV3 CSP 禁止 |

## 三、IPC 协议

### 3.1 消息格式

```typescript
// ISOLATED → MAIN 消息格式
interface IsolatedToMainMessage {
  source: "yipet-isolated";       // 消息来源标记
  action: string;                  // 操作类型（setRole, toggleChat 等）
  payload: Record<string, unknown>; // 操作数据
  __signature: string;             // 安全签名（IPC_SECRET）
  __timestamp: number;             // 消息时间戳（防重放）
}

// MAIN → ISOLATED 消息格式
interface MainToIsolatedMessage {
  source: "yipet-main";
  action: string;
  payload: Record<string, unknown>;
  __signature: string;
  __timestamp: number;
}
```

### 3.2 ISOLATED → MAIN 通信

```typescript
// content/isolated/ipc.ts — ISOLATED World 中的发送函数
const IPC_SECRET = crypto.randomUUID(); // 扩展安装时生成，持久化到 storage

export function dispatchToMain(action: string, payload: Record<string, unknown>): void {
  const message: IsolatedToMainMessage = {
    source: "yipet-isolated",
    action,
    payload,
    __signature: IPC_SECRET,
    __timestamp: Date.now(),
  };

  window.postMessage(message, "*"); // 同窗口内通信，origin 检查由接收端完成
}
```

### 3.3 MAIN → ISOLATED 通信

```typescript
// cdn/main-bootstrap.ts — MAIN World 中的发送函数
function dispatchToIsolated(action: string, payload: Record<string, unknown>): void {
  window.postMessage(
    {
      source: "yipet-main",
      action,
      payload,
      __signature: IPC_SECRET, // 通过 dataset 从 ISOLATED 传递
      __timestamp: Date.now(),
    },
    "*"
  );
}
```

### 3.4 消息安全验证（接收端）

```typescript
// 两世界使用相同的验证逻辑
function isValidMessage(event: MessageEvent): boolean {
  // 1. 来源验证：仅接受同窗口的消息
  if (event.source !== window) return false;

  // 2. 结构验证：必须有 source 标记
  const data = event.data;
  if (!data?.source || typeof data.source !== "string") return false;

  // 3. 来源标记验证
  const expectedSource =
    data.source === "yipet-isolated" || data.source === "yipet-main";
  if (!expectedSource) return false;

  // 4. 签名验证：防伪造
  if (data.__signature !== IPC_SECRET) {
    console.warn("[YiPet IPC] 签名验证失败：可能的安全攻击");
    return false;
  }

  // 5. 时间戳验证：5 秒过期，防重放攻击
  const elapsed = Date.now() - data.__timestamp;
  if (elapsed < 0 || elapsed > 5000) {
    console.warn("[YiPet IPC] 消息过期或时间异常:", elapsed);
    return false;
  }

  return true;
}

window.addEventListener("message", (event) => {
  if (!isValidMessage(event)) return;
  handleMessage(event.data);
});
```

## 四、完整消息流

### 4.1 Popup → Content Script → MAIN（配置变更）

```
Popup（Vue 3 组件）
  │ chrome.tabs.sendMessage(tabId, { action: 'setRole', role: 'cat', color: 'blue' })
  │
  ▼
Content Script — ISOLATED World
  │ chrome.runtime.onMessage.addListener((msg, sender, sendResponse) => {
  │   if (msg.action === 'setRole') {
  │     dispatchToMain('roleChanged', { role: msg.role, color: msg.color });
  │     sendResponse({ success: true });
  │   }
  │ })
  │
  ▼
Bootstrap — MAIN World
  │ window.addEventListener('message', (e) => {
  │   if (!isValidMessage(e)) return;
  │   if (e.data.action === 'roleChanged') {
  │     const { role, color } = e.data.payload;
  │     petInstance.setRole(role);
  │     petInstance.setColor(color);
  │     // 更新 DOM
  │     renderPet(); // Vue 响应式更新
  │   }
  │ })
```

### 4.2 MAIN → Content Script → Popup（用户触发页面讨论）

```
Bootstrap — MAIN World
  │ // 用户点击宠物 UI 中的按钮
  │ dispatchToIsolated('discussPage', {
  │   url: window.location.href,
  │   title: document.title,
  │ })
  │
  ▼
Content Script — ISOLATED World
  │ window.addEventListener('message', (e) => {
  │   if (!isValidMessage(e)) return;
  │   if (e.data.action === 'discussPage') {
  │     // 转发给 Popup
  │     chrome.runtime.sendMessage({
  │       action: 'DISCUSS_PAGE',
  │       data: e.data.payload,
  │     });
  │   }
  │ })
  │
  ▼
Popup 或 Service Worker
  │ chrome.runtime.onMessage.addListener((msg) => {
  │   if (msg.action === 'DISCUSS_PAGE') {
  │     // 打开 YiVad AI 聊天页面
  │     openYiVadChat(msg.data);
  │   }
  │ })
```

## 五、CDN 资源注入

### 5.1 注入流程

```
Content Script（ISOLATED）
  │
  ├── 1. 检查是否需要注入（__YIPET_LOADED__ 标记）
  │     └── 已注入 → 短路返回
  │
  ├── 2. 注入 CDN CSS（ISOLATED World 可直接操作 DOM）
  │     const link = document.createElement("link");
  │     link.href = chrome.runtime.getURL("cdn/styles/pet.css");
  │     document.head.appendChild(link);
  │
  ├── 3. 注入 CDN Vendor JS（ISOLATED World 创建 <script>）
  │     const vueScript = document.createElement("script");
  │     vueScript.src = chrome.runtime.getURL("cdn/vendor/vue.global.prod.js");
  │     document.head.appendChild(vueScript);
  │     // 这些脚本在 MAIN World 执行
  │
  └── 4. 注入 Bootstrap（MAIN World）
        const bootstrapScript = document.createElement("script");
        bootstrapScript.src = chrome.runtime.getURL("cdn/bootstrap.js");
        bootstrapScript.dataset.ipcSecret = IPC_SECRET;
        bootstrapScript.dataset.apiBase = apiBaseUrl;
        document.head.appendChild(bootstrapScript);
```

### 5.2 注入时机

| 页面类型 | 注入时机 | 策略 |
|----------|----------|------|
| 静态 HTML 页面 | `document_idle`（DOM 加载完成） | 标准注入 |
| SPA（Vue/React） | `document_idle` + `MutationObserver` | 监听 app root 出现后再注入 |
| 动态路由 | `MutationObserver` + URL 变化监听 | 路由切换时重新评估是否需要注入 |
| iframe 页面 | 仅顶层窗口注入 | `window.top === window.self` 检查 |

## 六、常见问题排查

### 问题 1：宠物不显示（MAIN World 初始化失败）

```javascript
// 在浏览器控制台中（确保选择了正确的 JS 上下文）
// 1. 检查 Bootstrap 是否加载
console.log(window.__YIPET_LOADED__); // 应为 true

// 2. 检查 Vue 实例
console.log(document.querySelector("#yipet-root")); // 应存在 DOM 元素

// 3. 检查 CDN 资源
// Network 面板 → 过滤 "cdn/" → 查找 404
```

### 问题 2：Popup 配置变更后宠物不响应

```
排查链路：
1. Popup → chrome.tabs.sendMessage 是否成功（Runtime.lastError）
2. Content Script onMessage 是否收到（ISOLATED 控制台日志）
3. dispatchToMain 是否触发（window.postMessage 调用）
4. MAIN World message listener 是否收到（MAIN 控制台日志）
5. 签名和时间戳是否通过验证
```

### 问题 3：跨域 fetch 失败

- ISOLATED World 有 CORS 豁免（Content Script 声明）
- 确保在 manifest.json 中声明了对应的 `host_permissions`
- MAIN World 的 fetch 受宿主页面 CSP 限制

## 七、硬约束

- MAIN World 代码**禁止**调用 `chrome.runtime.*`——由 ISOLATED Content Script 代理
- ISOLATED World 代码**推荐**通过 `dispatchToMain` 让 MAIN World 操作 DOM（而非直接操作）
- 跨世界通信必须使用安全验证（签名 + 时间戳）
- IPC_SECRET 在扩展安装时生成，通过 `chrome.storage.local` 持久化
- `window.postMessage` 的 `targetOrigin` 使用 `"*"`（同窗口通信，接收端做来源验证）
- 所有 vendor 库（Vue, Element Plus 等）通过 npm 安装后打包到 `cdn/vendor/`，通过 `chrome.runtime.getURL` 加载
- 禁止使用 `eval`、`new Function`、内联 `<script>`（MV3 CSP）
