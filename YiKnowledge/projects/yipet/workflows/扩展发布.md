# 扩展发布流程

> 本文档定义 YiPet Chrome 扩展的发布流程，包括版本号更新、构建、打包、上传 Chrome Web Store 的完整步骤。

---

## 一、发布前检查清单

### 1.1 代码质量

- [ ] `npm run typecheck` 通过（TypeScript strict mode 类型检查）
- [ ] `npm run build` 成功（Rsbuild 多入口构建）
- [ ] `npm test` 所有测试通过
- [ ] `npm run lint` 无错误（Biome lint）
- [ ] 所有用户可见文本使用 `t()` 国际化
- [ ] `en/messages.json` 和 `zh_CN/messages.json` 的 key 一致

### 1.2 功能验证

- [ ] 弹出窗口 (popup) 正常工作
- [ ] Chat 窗口在所有目标页面正常加载
- [ ] 浮动宠物覆盖层渲染正常
- [ ] 知识库树浏览器正常
- [ ] RAG 接地对话功能正常
- [ ] SSE 流式对话正常
- [ ] 跨项目桥接（YiVad、Bug 上报）正常
- [ ] 皮肤切换（颜色、角色）正常
- [ ] 会话持久化正常（重启浏览器后会话仍在）

### 1.3 兼容性

- [ ] Chrome 最新稳定版
- [ ] Chrome 最新 Beta 版（可选）
- [ ] 目标网站页面兼容性（YiVad、YiAi、外部网站）

## 二、版本号更新

### 2.1 更新 manifest.json

```json
// manifest.json
{
  "manifest_version": 3,
  "name": "__MSG_appName__",
  "version": "1.3.0",     // 更新此字段
  "description": "__MSG_appDescription__",
  // ...
}
```

### 2.2 版本号规则

遵循语义化版本（SemVer）：`{major}.{minor}.{patch}`

| 变更类型 | 版本号 | 示例 |
|---------|--------|------|
| 重大架构变更 / 不兼容更新 | Major +1 | `1.2.0` → `2.0.0` |
| 新功能（向后兼容） | Minor +1 | `1.2.0` → `1.3.0` |
| Bug 修复（向后兼容） | Patch +1 | `1.2.0` → `1.2.1` |

### 2.3 更新 package.json

```json
// package.json
{
  "version": "1.3.0"      // 与 manifest.json 保持一致
}
```

## 三、构建流程

### 3.1 构建命令

```bash
# 1. 清理旧的构建产物
rm -rf dist/

# 2. 安装依赖（确保最新）
npm ci

# 3. 类型检查
npm run typecheck

# 4. 运行测试
npm test

# 5. 生产构建
npm run build
```

### 3.2 构建产物

```
dist/
├── manifest.json          # 扩展清单
├── popup/                 # 弹出窗口
│   ├── index.html
│   ├── index.js
│   └── index.css
├── chat/                  # Chat 窗口
│   ├── index.html
│   └── index.js
├── background/            # Service Worker
│   └── index.js
├── content/               # 内容脚本
│   └── bootstrap.js
├── cdn/                   # CDN 资源
│   ├── utils/
│   │   └── api-client.js
│   ├── vendor/            # 第三方库
│   └── styles/
│       ├── variables.css
│       └── chat.css
├── _locales/              # 国际化
│   ├── en/
│   │   └── messages.json
│   └── zh_CN/
│       └── messages.json
└── assets/                # 静态资源（图标等）
```

### 3.3 构建验证

```bash
# 检查 dist/ 目录结构
ls -la dist/
ls -la dist/popup/
ls -la dist/chat/
ls -la dist/background/
ls -la dist/content/
ls -la dist/cdn/

# 验证 manifest.json
cat dist/manifest.json | python3 -m json.tool

# 验证文件大小（不应有异常大的文件）
du -sh dist/*
```

## 四、打包

### 4.1 创建 .zip 包

```bash
# 进入 dist/ 目录，打包所有文件
cd dist/
zip -r ../yipet-v1.3.0.zip ./*
cd ..
```

### 4.2 验证 .zip 包

```bash
# 检查包大小
ls -lh yipet-v1.3.0.zip

# 检查包内容
unzip -l yipet-v1.3.0.zip | head -30

# 确保 manifest.json 在根目录
unzip -l yipet-v1.3.0.zip | grep manifest.json
```

**注意**：Chrome Web Store 要求 `.zip` 包的根目录直接包含 `manifest.json`，不要有多余的父目录。

## 五、Chrome Web Store 上架

### 5.1 开发者控制台

1. 访问 [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole)
2. 选择 YiPet 扩展
3. 进入 "Package" 页面

### 5.2 上传新版本

1. 点击 "Upload new package"
2. 选择 `yipet-v1.3.0.zip` 文件
3. 等待上传完成和自动审核

### 5.3 填写更新信息

**Store listing 页面更新**：

- **Description**: 如需更新扩展描述
- **Screenshots**: 如有 UI 变更，更新截图
- **Category**: 保持不变（通常为 "Productivity"）

**What's new（更新说明）**：

用简洁的英文描述本次更新的内容：

```
Version 1.3.0:
- Added session export as markdown
- Added per-message token cost display
- Added session summary generation
- Added branch-from-message functionality
- Added drag-and-drop knowledge file to chat
- Improved chat window resize handles
- Fixed session filter parameter name (query -> filter)
```

### 5.4 提交审核

1. 点击 "Submit for review"
2. 确认所有必填字段已填写
3. 确认隐私政策链接有效（如需要）
4. 确认权限声明准确
5. 提交审核

### 5.5 审核时间

| 类型 | 预计时间 |
|------|---------|
| 常规审核 | 1-3 个工作日 |
| 快速审核 | 数小时（limited quota，仅紧急情况） |

## 七、Hotfix 紧急发布

### 7.1 流程

```
1. 从 master 切出 hotfix 分支
2. 修复 bug
3. 更新 manifest.json 版本号（patch +1）
4. 合入 dev → 本地验证
5. 合入 test → 打包测试
6. 验证通过 → 打包 .zip → 上传 Chrome Web Store
7. 申请快速审核（如紧急）
8. 审核通过后，hotfix → master 打 tag → 回汇
```

### 7.2 快速审核

Chrome Web Store 提供有限的快速审核配额：

1. 在 Developer Dashboard 中，上传新版本后
2. 在 "Submit for review" 时选择 "Request fast review"
3. 填写紧急原因（如 "Critical bug fix: CSP violation causing extension crash"）

**注意**：快速审核配额有限，仅用于紧急线上问题修复。

## 八、回滚流程

### 8.1 回滚步骤

如果新版本有严重问题需要回滚：

1. 在 Chrome Web Store Developer Dashboard 中
2. 找到上一个稳定版本的 `.zip` 包
3. 重新上传稳定版本
4. 提交审核（或使用快速审核）

### 8.2 代码回滚

```bash
# 从 master 历史 tag 切出修复分支
git checkout v1.2.0
git checkout -b hotfix/rollback-1.3.0

# 修复问题
# ...

# 更新版本号（如 v1.3.1）
# 按 hotfix 流程发布
```

## 十、常见问题

### Q: 扩展审核被拒怎么办？

A: 查看审核反馈邮件，根据指出的问题修改后重新提交。常见原因：
- 权限声明过于宽泛（需说明用途）
- 隐私政策不完整
- 使用了被禁止的 API
- manifest.json 格式错误

### Q: 版本号更新后，已安装用户如何更新？

A: Chrome 会定期检查已安装扩展的更新（通常每 5 小时），用户也可以手动在 `chrome://extensions/` 页面点击 "Update" 触发更新。

### Q: 如何测试生产构建？

A: 在 Chrome `chrome://extensions/` 页面，开启 "Developer mode"，点击 "Load unpacked"，选择 `dist/` 目录加载未打包扩展进行测试。加载的是 `dist/` 目录，与生产构建产物一致。

### Q: .zip 包大小限制？

A: Chrome Web Store 对扩展包大小限制为 500 MB（实际上远小于此限制即可）。YiPet 通常保持在 5 MB 以内。如果包体积过大，检查是否有未压缩的 vendor 库或未使用的资源。<!-- 注意：不要使用 `[` 或 `]` 字符，因为文件名中不能包含这些字符。 -->

## 十一、发布命令速查

```bash
# 完整发布流程
npm run typecheck && npm test && npm run build

# 打包
cd dist && zip -r ../yipet-v$(node -p "require('../package.json').version").zip ./* && cd ..

# 验证包
unzip -l yipet-v*.zip | grep manifest.json

# 打 tag（发布审核通过后）
git checkout master
git merge release
git tag v$(node -p "require('./package.json').version")
git push origin master --tags

# 回汇
git checkout release && git merge master && git push origin release
git checkout test && git merge master && git push origin test
git checkout dev && git merge master && git push origin dev
```
