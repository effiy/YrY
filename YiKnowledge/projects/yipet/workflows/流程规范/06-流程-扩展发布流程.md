# 扩展发布流程

> YiPet Chrome Web Store 发布完整流程。分支策略详见 [分支管理规范](./01-流程-分支管理规范.md)，构建详见 [构建部署](./05-流程-构建部署.md)。

## 一、发布前检查清单

### 代码质量
- [ ] `npm run typecheck` 通过
- [ ] `npm run build` 成功
- [ ] `npm test` 全部通过
- [ ] `npm run lint:eslint` 无错误
- [ ] `en/messages.json` 和 `zh_CN/messages.json` key 一致

### 功能验证
- [ ] Popup、Chat Window、Floating Pet 正常
- [ ] SSE 流式对话、RAG 接地对话正常
- [ ] 跨项目桥接（YiVad、Bug 上报）正常
- [ ] 皮肤切换、会话持久化正常
- [ ] Chrome 最新稳定版兼容

## 二、版本号更新

SemVer：`{major}.{minor}.{patch}`。同步更新 `manifest.json` 和 `package.json`。

| 变更 | 版本 | 示例 |
|------|------|------|
| 重大架构/不兼容 | Major +1 | `1.2.0` → `2.0.0` |
| 新功能（向后兼容） | Minor +1 | `1.2.0` → `1.3.0` |
| Bug 修复 | Patch +1 | `1.2.0` → `1.2.1` |

## 三、构建与打包

```bash
npm run typecheck && npm test && npm run build
cd dist && zip -r ../yipet-v$(node -p "require('../package.json').version").zip ./* && cd ..
unzip -l yipet-v*.zip | grep manifest.json  # 验证 manifest.json 在根目录
```

**注意**：`.zip` 根目录直接包含 `manifest.json`，不要多余父目录。包大小限制 500MB（YiPet 通常 < 5MB）。

## 四、Chrome Web Store 上架

1. [Developer Dashboard](https://chrome.google.com/webstore/devconsole) → 选择扩展 → "Package"
2. "Upload new package" → 选择 `.zip`
3. 填写 "What's new"（英文更新说明）
4. "Submit for review"

**审核时间**：常规 1-3 工作日，快速审核数小时（limited quota，仅紧急情况）。

### 权限用途说明（审核必需）

| 权限 | 用途说明 |
|------|----------|
| `storage` | Store user preferences and chat sessions locally |
| `activeTab` | Access current tab only when user clicks extension icon |
| `scripting` | Inject pet companion UI and chat interface into pages |
| `<all_urls>` | Pet companion needs to appear on any webpage |

### 审核常见拒因

| 拒因 | 解决 |
|------|------|
| 权限过于宽泛 | `activeTab` 替代 `<all_urls>`（如适用） |
| 未说明权限用途 | Privacy 页面逐项填写 |
| 远程代码执行 | 所有代码预打包到扩展内 |
| 隐私政策缺失 | 提供有效 URL |

## 五、分阶段发布（Staged Rollout）

| 阶段 | 比例 | 持续 | 观察 |
|------|------|------|------|
| 金丝雀 | 5% | 24h | 错误率、卸载率、反馈 |
| 扩大 | 20% | 24h | 错误率对比、性能 |
| 半数 | 50% | 12h | 确认无回归 |
| 全量 | 100% | — | 持续监控 |

**回滚信号**：错误率 > 2x 基准、卸载率 > 1.5x 基准、差评单日 > 3 条、新增 CSP/CORS 报错。

## 六、发布后

```bash
# 审核通过后
git checkout master && git merge release
git tag v$(node -p "require('./package.json').version")
git push origin master --tags

# 回汇
git checkout release && git merge master && git push origin release
git checkout test && git merge master && git push origin test
git checkout dev && git merge master && git push origin dev
```

## 七、Hotfix 紧急发布

1. `master` 切 `hotfix/` 分支
2. 修复 → 更新 patch 版本号 → 合入 dev → 验证
3. 合入 test → 打包测试
4. 打包 `.zip` → 上传 Chrome Web Store
5. 申请快速审核 → 通过后 → 合入 master 打 tag → 回汇

## 八、回滚

Dashboard 中找到上一稳定版本 `.zip` → 重新上传。代码侧从 master 历史 tag 切出修复分支按 hotfix 流程处理。

## 九、CI/CD 自动化

```yaml
# tag push → version check → npm ci → typecheck + lint + test → build → package zip → upload artifact → create release
```

发布命令速查：
