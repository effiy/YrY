Chrome DevTools Memory 面板 + `performance.memory` API。

| 指标 | 阈值 |
|------|------|
| JS Heap | < 50MB |
| DOM Nodes | < 500 |
| Event Listeners | < 200 |

## 一、需求背景

来源 PRD：57-架构设计-内存快照泄漏追踪.md

### 用户痛点

1. **无自动化快照采集——依赖开发者手动操作**：高
1. **Detached DOM 节点无追踪——聊天窗口关闭后 DOM 可能未释放**：中
1. **无快照对比能力——单次快照无法判断是否泄漏**：中

## 二、功能实现

| 功能 | 实现方案 |
|------|----------|
| 指标 | 阈值 |
| JS Heap | < 50MB |
| DOM Nodes | < 500 |
| Event Listeners | < 200 |
| 内存增长(10min) | < 5MB |
| 步骤 | 任务 |
| 1 | Composable 核心逻辑开发与单元测试 |
| 2 | UI 组件开发 + Popup/Side Panel 集成 |

## 三、关键技术决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | 纯前端浏览器 API 实现 | 无需服务端依赖，响应 < 50ms，离线可用 |
| 2 | 独立 Vue 3 Composable 封装 | 单一职责，可复用于 Popup + Side Panel |

## 四、实施步骤
