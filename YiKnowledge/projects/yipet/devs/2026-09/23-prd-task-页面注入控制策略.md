## 一、方案概述

用户可控制 YiPet 在哪些页面注入：全部页面/仅特定域名/排除特定域名。

### 注入策略

| 策略 | 配置 | 默认 |
|------|------|------|
| 全部页面 | — | ✅ |
| 白名单 | 域名列表 | — |
| 黑名单 | 排除域名 | chrome://, edge:// |

### 配置存储

```typescript
interface InjectionPolicy {
  mode: "all" | "whitelist" | "blacklist";
  domains: string[];  // 白名单或黑名单域名
}
// 存储：chrome.storage.local
```

## 一、需求背景

来源 PRD：23-架构设计-页面注入控制策略.md

### 用户痛点

1. **`GLOBAL_BLOCKLIST` 正则 `bank**：mil` 匹配过于宽泛——误拦截了 `github.com` 和 `gomovies.com`
1. **`GLOBAL_BLOCKLIST` 和 `UX_BLOCKLIST` 为硬编码数组——无法通过远程配置更新（如 CWS 新增审核要求）**：0.25
1. **`shouldInject` 每次调用都遍历所有正则数组——高频页面（SPA 路由切换）可能有性能开销**：0.125
