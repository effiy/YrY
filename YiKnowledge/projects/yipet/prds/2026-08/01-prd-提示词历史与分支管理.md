# YP-08-01: 聊天核心功能 — 提示词历史与分支管理

> 需求编号：YP-08-02 · 优先级：P0 · 人天：4.0d · 状态：已完成
> 依赖：YP-07-03（聊天框架搭建）、YP-08-01（API Services 就绪）

---

## 一、背景

七月迭代后 YiPet 具备基础聊天能力（消息收发、SSE 流式渲染），但对比 YiVad aiChat，缺失以下会话体验功能：

| 缺失 | 严重度 | 用户影响 | 案例 |
|------|--------|----------|------|
| 无提示词历史 | 中 | 重复输入相同内容 | 用户想重试稍作修改的 prompt，需重新完整输入 |
| 会话无有意义标题 | **高** | 侧边栏无法区分会话 | 20+ 个 "新会话"，逐一打开才能找到目标，耗时 2min |
| 无会话分支 | 中 | 无法从历史消息分叉 | 讨论到一半想换个方向，只能从头开始 |
| 无搜索过滤 | 中 | 会话增多后查找困难 | 50+ 会话后，找到特定对话几乎不可能 |
| 无导出 | 低 | 有价值对话无法留存 | 技术讨论结果只能截屏保存 |
| 无消息操作 | 中 | 无法编辑/删除/重生成 | 发错消息只能将错就错 |

---

## 二、用户故事

| ID | 用户 | 需求 | 价值 | 优先级 |
|----|------|------|------|--------|
| US-01 | 所有用户 | ArrowUp/Down 快速调出之前发送的提示词 | 重复使用或修改 prompt 时无需重新输入 | P1 |
| US-02 | 所有用户 | 会话列表自动显示有意义的标题 | 一眼区分不同会话 | **P0** |
| US-03 | 所有用户 | 在会话列表中搜索关键词 | 快速定位目标会话 | P1 |
| US-04 | 所有用户 | 按收藏/今天/本周过滤会话列表 | 缩小查找范围 | P1 |
| US-05 | 所有用户 | 从任意历史消息分叉创建新的独立会话 | 保持分叉点之前的上下文，换个方向继续讨论 | P2 |
| US-06 | 所有用户 | 编辑/删除已发送的消息 | 纠正错误输入 | P1 |
| US-07 | 所有用户 | 重新生成 AI 回复 | 对不满意回复重新尝试 | P1 |
| US-08 | 所有用户 | 导出完整对话为 Markdown 文件 | 留存或分享有价值的讨论 | P2 |

## 三、功能需求

### FR-01: 提示词历史

| 属性 | 描述 |
|------|------|
| 触发 | 输入框为空或光标在行首时按 ArrowUp → 调出上一条历史；ArrowDown → 下一条 |
| 存储 | 最近 100 条提示词，localStorage 持久化 |
| 浏览面板 | 工具栏按钮打开弹窗：搜索框 + 最近 3 条快捷芯片 + 完整列表（可复制/删除） |
| 清空 | 支持一键清空全部历史（含确认弹窗） |

### FR-02: 自动会话标题

| 属性 | 描述 |
|------|------|
| 生成策略 | 会话创建后，首条用户消息的前 30 字符作为标题 |
| 手动编辑 | SessionEditDialog 支持修改标题 |
| 显示规则 | 无消息时显示 "New chat"，有消息时显示自动生成的标题 |

### FR-03: 会话搜索与过滤

| 属性 | 描述 |
|------|------|
| 搜索 | 侧边栏顶部搜索框，实时客户端模糊匹配 title（不区分大小写） |
| 过滤 | 标签切换：全部 / 收藏 / 今天 / 本周 |
| 行为 | 搜索结果不改变排序（收藏优先 → 时间倒序），仅过滤不匹配项 |

### FR-04: 会话分支

| 属性 | 描述 |
|------|------|
| 创建 | 从任意历史用户消息分叉 → 创建新会话，`messages` 包含分叉点及之前的全部消息 |
| 分支信息 | 记录 `parentMessageId` 和分支点 `messageId` 供可视化使用 |
| 切换 | 分支作为独立会话出现在侧边栏，切换无感知 |
| 可视化 | 分支列表中标识父会话和分支点消息预览 |

### FR-05: 消息操作增强

| 操作 | 适用消息 | 行为 |
|------|----------|------|
| 复制全文 | AI 消息 | 一键写入剪贴板 → "Copied" 反馈 |
| 编辑 | 用户消息 | 内联编辑 → 持久化 |
| 删除 | 所有消息 | 从列表移除 → 持久化（不可恢复） |
| 重新生成 | AI 消息 | 清空 → 保留上下文重新 SSE 流式 |

### FR-06: 会话导出

| 属性 | 描述 |
|------|------|
| 格式 | Markdown：标题 + 创建时间 + 每条消息的角色标签 + 时间戳 + 内容 |
| 触发 | ChatToolbar 导出按钮 → 生成 Blob → `a.click()` 下载 |
| 文件名 | `{会话标题}.md`（特殊字符替换为下划线） |

## 四、非功能需求

| 类别 | 指标 | 目标 |
|------|------|------|
| 性能 | 提示词历史加载 | < 10ms（localStorage 读） |
| 性能 | 搜索过滤响应 | < 50ms（客户端过滤） |
| 存储 | 提示词历史上限 | 100 条（超出 FIFO） |
| 存储 | localStorage 增量 | < 50KB |

## 五、验收标准

| # | 关联 US | Given | When | Then |
|---|---------|-------|------|------|
| AC-01 | US-01 | 曾发送 "分析 Q3 Bug 趋势" | 空输入框按 ArrowUp | 输入框显示完整文本，光标在末尾 |
| AC-02 | US-01 | 提示词历史面板打开 | 搜索框输入 "Bug" | 仅显示包含 "Bug" 的条目 |
| AC-03 | US-02 | 首条消息 "Q3 Roadmap 进度" | 会话创建 | 标题自动设为 "Q3 Roadmap 进度" |
| AC-04 | US-03 | 10 个会话，含 "Roadmap" | 搜索框输入 "road" | 仅显示匹配会话，知识树同步过滤 |
| AC-05 | US-04 | 从第 5 条消息分叉 | 点击 "Branch from here" | 新会话出现，含前 5 条消息，可独立继续对话 |
| AC-06 | US-05 | 用户消息已发送 | 点击编辑 → 修改 → 保存 | 消息内容更新 + 持久化 |
| AC-07 | US-06 | AI 回复不满意 | 点击重新生成 | 回复清空 → 保留上下文重新流式 → 新回复覆盖 |
| AC-08 | US-07 | 会话有 10 条消息 | 点击导出 | 下载 .md 文件，含完整对话格式 |
