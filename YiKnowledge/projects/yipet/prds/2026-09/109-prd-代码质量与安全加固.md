# YP-09-109: 代码质量与安全加固

> **PRD 版本**：v1.0 · **状态**：已完成

---

## 1. 背景

YiPet 经过多轮功能迭代（即时翻译、皮肤中心、会话管理、RAG 集成、跨项目桥接等），代码量快速增长至 110+ 源文件。快速迭代过程中积累了一些技术债务：

- **存储持久化不一致**：`_persistSetting` 写入键带 `yipet:` 前缀，但 `_loadPersistedState` 读取时无前缀，导致 6 项用户设置（侧边栏宽度、窗口位置、颜色主题等）在浏览器重启后丢失
- **安全漏洞**：Mermaid `securityLevel: loose` 允许任意 HTML 执行；`decodeHTMLEntities` 使用 `innerHTML` 存在 XSS 风险
- **API 路径错误**：`relay.ts` 硬编码 `apiBase` 为 `localhost:8848/api`（YiVad 前端端口）而非 `localhost:10086`；`useConversationCompact` 绕过 ApiClient 直接 `fetch('/')`
- **代码质量问题**：死代码、双重序列化、类型不完整等

本任务对全代码库进行系统性审计，修复 14 个已识别缺陷，并补充 11 篇专业 bug 报告。

## 3. 用户问题

- **目标用户**：YiPet 的所有用户
- **问题陈述**：用户在使用过程中遇到设置不持久化（窗口位置重置、侧边栏宽度丢失、颜色主题丢失）、潜在安全风险（LLM 生成的 Mermaid 代码可能执行脚本）、会话压缩功能在第三方页面完全无效等问题
- **证据**：强证据 — 代码审查确认了所有 14 个缺陷的根因；138 个单元测试全部通过验证修复无误

## 4. 解决方案

### 存储持久化修复（7 处）

核心问题：`_persistSetting(key, value)` 自动为键名添加 `yipet:` 前缀后写入 `chrome.storage.local`，但 `_loadPersistedState()` 读取时未使用前缀。

修复：统一 `_loadPersistedState` 中所有读键名为 `yipet:` 前缀版本，并将 `windowState` 键名修正为 `chatWindowState`。

### 安全加固（2 处）

1. **Mermaid**：`securityLevel: 'loose'` → `'strict'`，HTML 标签自动转义
2. **decodeHTMLEntities**：`div.innerHTML` → `textarea.innerHTML`，利用 textarea 的纯文本语义避免 XSS

### API 路径修正（2 处）

1. **relay.ts**：`apiBase` 从 `localhost:8848/api` 改为 `localhost:10086`，直接指向 YiAi 后端
2. **useConversationCompact**：注入 `rpcCall` 依赖，通过 ApiClient 发送压缩请求，不再裸用 `fetch('/')`

### 代码质量改进（3 处）

1. CDN `loadCSS` 移除死代码 `onload` 回调
2. `injectServices` 类型签名补充 `dashboard` 和 `client` 参数
3. `bootstrap.ts` 移除 3 处双分号，`chat/types.ts` 移除未使用导入，`i18n/index.ts` 移除重复键

## 6. 风险与权衡

| 风险 | 缓解 |
|------|------|
| 存储键名变更导致已有用户设置丢失 | `_persistSetting` 始终使用 `yipet:` 前缀写入，旧数据从未被正确持久化，无迁移影响 |
| `relay.ts` apiBase 变更影响已有开发环境 | 新值 `localhost:10086` 与 `chat/index.ts` 默认值一致，且更直接（不依赖 YiVad 代理） |
| compaction 重构引入新 bug | 通过现有 138 个测试 + `npm run build` 验证无回归 |
