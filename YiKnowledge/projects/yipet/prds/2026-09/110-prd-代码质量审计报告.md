## 4. 关键发现深度分析

### 4.1 存储持久化断裂（B01–B03, 7 个子缺陷）

**根因**：两条独立的代码路径存在键名约定不一致。

1. **写入路径** (`_persistSetting`): 自动为所有键添加 `yipet:` 前缀 → `chrome.storage.local.set({ 'yipet:sidebarWidth': 320 })`
2. **读取路径** (`_loadPersistedState`): 未添加前缀 → `chrome.storage.local.get(['sidebarWidth'])`

两条路径的键名不匹配导致所有通过 `_persistSetting` 存储的设置无法恢复。影响范围：

| 设置 | 写入键 | 读取键（修复前） | 用户感知 |
|------|--------|-----------------|----------|
| 侧边栏宽度 | `yipet:sidebarWidth` | `sidebarWidth` | 每次打开恢复默认 320px |
| 侧边栏折叠 | `yipet:sidebarCollapsed` | `sidebarCollapsed` | 每次打开侧边栏展开 |
| 窗口位置 | `yipet:chatWindowState` | `windowState` | 窗口回到默认位置 |
| 颜色主题 | `yipet:chatColorIndex` | `chatColorIndex` | 颜色主题重置 |
| 自定义颜色 | `yipet:chatCustomColor` | `chatCustomColor` | 自定义色丢失 |
| 提示词历史 | `yipet:promptHistory` | `promptHistory` | 历史清空 + 双重序列化 |

**修复**：统一 `_loadPersistedState` 中所有读键为 `yipet:` 前缀的括号表示法 (`result['yipet:key']`)，修正 `windowState` 为 `chatWindowState`。

### 4.2 Compaction 绕过 ApiClient（B10, Critical）

**根因**：`useConversationCompact.ts` 的 `callCompactApi` 函数直接使用 `fetch('/')` 发送 RPC 请求，完全绕过 ApiClient 层。在 MAIN 世界聊天中（运行于任意页面），`fetch('/')` 命中当前页面的 origin 而非 YiAi 后端。

**影响链**：
```
用户长聊 → token 超 6000 → 自动压缩 → fetch('https://第三方页面/')
→ 404/无响应 → 压缩失败 → 会话继续增长 → 上下文窗口溢出
```

**修复**：注入 `rpcCall` 依赖到 `ConversationCompactDeps`，通过 `getClient().rpc()` 走标准 ApiClient → RPC 信封路径。

### 4.3 安全漏洞（B04–B05）

**Mermaid (B04)**：`securityLevel: 'loose'` 允许图表中嵌入任意 HTML/JS。LLM 生成的 Mermaid 代码不受信任——攻击者可通过提示词注入构造恶意图表。

**decodeHTMLEntities (B05)**：使用 `div.innerHTML = html` 解析 HTML 实体。虽然 `<script>` 标签在 innerHTML 赋值时不执行，但 `<img onerror>` 等事件处理器在特定条件下可能触发。

**修复**：Mermaid 改为 `strict` 模式；`decodeHTMLEntities` 改用 `<textarea>` 进行纯文本语义解析。

## 7. 建议

1. **存储持久化**：考虑将 `_persistSetting` 的 `yipet:` 前缀逻辑显式化（如重命名为 `_persistYipetSetting`），避免未来新增开发者再次引入前缀不一致问题
2. **ApiClient 调用规范**：添加 lint 规则禁止模块级 `fetch()` 直接调用，强制走 ApiClient 路径
3. **安全性**：将 `securityLevel: 'strict'` 设为 Mermaid 初始化的强制默认值，在 code review checklist 中增加 XSS 检查项
4. **死代码**：在下一个大版本中清理 `enums/index.ts` 和 `createPopupConfig`，或明确标记为 deprecated
5. **测试增强**：为 chrome.storage 读写一致性添加单元测试（使用 mock），防止存储键名回归
