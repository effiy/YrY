<a id="sec-4"></a>
## 四、PRD 文档结构

每个 PRD 文件遵循标准结构（参考 [PRD 模板](../模板/00-模板-需求文档.md)）：

```
1. 背景 — 业务背景、核心挑战
2. 现状与目标 — 改造前/后、能力全景 (Mermaid)、MV3 约束
3. 需求范围 — 范围内/外（标注 MV3 限制）
4. 功能需求 — FR-01 到 FR-0N + 双世界职责表
5. 非功能需求 — 安全 (CSP)、性能、MV3 兼容性
6. 设计决策 — 选项对比、选择理由
7. 验收标准 — 逐条可验证 AC
8. 风险与缓解 — 风险矩阵、回滚策略
9. 后续演进 — 技术债登记
10. 关联需求 — 开发方案、测试用例
```

<a id="sec-5"></a>
## 五、YiPet 特定约束

| 约束 | 说明 |
|------|------|
| MV3 平台 | Service Worker 非持久化、禁止远程代码、CSP 限制 |
| 双世界 | Content Script (ISOLATED) vs MAIN World |
| chrome.storage | local 10MB 配额，数据需序列化 |
| 4-Tier API | ApiClient → Endpoints → Types → Services |
