# YP-09-18: 聊天消息导出与数据可移植性 — Markdown/JSON 格式导出

> 需求编号：YP-09-18 · 优先级：P2 · 人天：0.5d · 状态：需求已编写

## 背景

用户与 AI 的聊天内容具有长期价值——技术讨论、设计决策、调试记录。当前无导出机制，聊天数据锁定在 YiPet 存储中。Chrome Web Store 对用户数据可移植性有隐性要求。

---

## 一、目标架构

```typescript
// YiPet/src/chat/services/exportService.ts

interface ExportOptions {
  format: 'markdown' | 'json';
  includeMetadata: boolean;     // 包含时间戳/模型/会话信息
  includeRagSources: boolean;   // 包含 RAG 来源引用
  dateRange?: { start: Date; end: Date };
}

class ChatExportService {
  /** 导出当前会话。 */
  exportSession(session: ChatSession, options: ExportOptions): string {
    switch (options.format) {
      case 'markdown': return this._toMarkdown(session, options);
      case 'json': return this._toJson(session, options);
    }
  }

  private _toMarkdown(session: ChatSession, opts: ExportOptions): string {
    const lines: string[] = [];

    // 头部——会话元信息
    if (opts.includeMetadata) {
      lines.push(`# ${session.title || 'YiPet Chat Session'}`);
      lines.push(`> 日期: ${new Date(session.createdAt).toISOString().slice(0, 10)}`);
      lines.push(`> 模型: ${session.model || 'default'}`);
      lines.push(`> 消息数: ${session.messages.length}`);
      if (session.tags?.length) {
        lines.push(`> 标签: ${session.tags.join(', ')}`);
      }
      lines.push('');
      lines.push('---');
    }

    // 消息体
    for (const msg of session.messages) {
      const role = msg.role === 'user' ? '**You**' : '**YiPet**';
      const time = opts.includeMetadata
        ? ` *(${new Date(msg.timestamp).toLocaleString()})*` : '';

      lines.push(`### ${role}${time}`);
      lines.push('');
      lines.push(msg.content);
      lines.push('');

      // RAG 来源
      if (opts.includeRagSources && msg.sources?.length) {
        lines.push('<details><summary>📚 知识来源</summary>');
        lines.push('');
        for (const src of msg.sources) {
          lines.push(`- [${src.title}](${src.path}) (相关性: ${(src.score * 100).toFixed(0)}%)`);
        }
        lines.push('');
        lines.push('</details>');
        lines.push('');
      }
    }

    return lines.join('\n');
  }

  private _toJson(session: ChatSession, opts: ExportOptions): string {
    const exportData: any = {
      version: '1.0',
      exportedAt: new Date().toISOString(),
      session: {
        id: session.id,
        title: session.title,
        url: session.url,
        messages: session.messages.map(msg => ({
          role: msg.role,
          content: msg.content,
          timestamp: msg.timestamp,
          ...(opts.includeRagSources && msg.sources
            ? { sources: msg.sources } : {}),
        })),
        ...(opts.includeMetadata ? {
          model: session.model,
          tags: session.tags,
          createdAt: session.createdAt,
          messageCount: session.messages.length,
        } : {}),
      },
    };
    return JSON.stringify(exportData, null, 2);
  }

  /** 触发浏览器下载。 */
  async download(filename: string, content: string, mimeType: string) {
    const blob = new Blob([content], { type: mimeType });
    const url = URL.createObjectURL(blob);
    const a = document.createElement('a');
    a.href = url;
    a.download = filename;
    a.click();
    URL.revokeObjectURL(url);
  }

  /** 导出并下载当前会话。 */
  async exportAndDownload(session: ChatSession, options: ExportOptions) {
    const ext = options.format === 'markdown' ? 'md' : 'json';
    const filename = `yipet-${session.title || 'chat'}-${Date.now()}.${ext}`;
    const content = this.exportSession(session, options);
    const mimeType = options.format === 'markdown'
      ? 'text/markdown' : 'application/json';
    await this.download(filename, content, mimeType);
  }
}
```

## 二、导出格式对比

| 格式 | 适用场景 | 可读性 | 可重新导入 | 体积 |
|------|----------|--------|-----------|------|
| **Markdown** | 人类阅读、知识库归档、PR 讨论 | 最高 | 否 | ~消息数 × 500B |
| **JSON** | 数据备份、跨工具迁移、程序处理 | 低 | 是 | ~消息数 × 1KB |

## 三、测试规格

#### Scenario: Markdown 导出——包含元数据
- **Given** 会话有 3 条消息, title="API 设计讨论"
- **When** `exportSession(session, {format: 'markdown', includeMetadata: true})`
- **Then** 输出以 `# API 设计讨论` 开头
- **And** 包含 `> 模型:`, `> 消息数: 3`
- **And** 每条消息有 `### **You**` 或 `### **YiPet**` 标题

#### Scenario: Markdown 导出——包含 RAG 来源
- **Given** 消息有 `sources: [{title: "限流设计.md", path: "...", score: 0.92}]`
- **When** 导出 `includeRagSources: true`
- **Then** 输出包含 `<details><summary>📚 知识来源</summary>`
- **And** 包含 `[限流设计.md](...) (相关性: 92%)`

#### Scenario: JSON 导出——可重新解析
- **Given** 会话有 3 条消息
- **When** `exportSession(session, {format: 'json'})`
- **Then** 输出是合法 JSON，`JSON.parse` 不抛异常
- **And** `exportData.version = "1.0"`, `exportData.session.messages.length = 3`

#### Scenario: 文件下载触发
- **Given** 导出内容 "test markdown content"
- **When** `download("test.md", content, "text/markdown")`
- **Then** 触发浏览器下载，文件名 "test.md"

#### Scenario: 空会话导出
- **Given** 会话 `messages: []`
- **When** 导出 Markdown
- **Then** 输出仅包含头部元数据（如有），无消息体

## 重构后发现的回归问题

| # | 问题 | 发现场景 | 根因 | 修复方式 |
|---|------|---------|------|---------|
| 1 | 文件名包含会话标题中的特殊字符时 `download` 失效——系统文件保存对话框不弹出 | 会话标题为 "API 设计: 限流 & 认证" → `filename = "yipet-API 设计: 限流 & 认证-1734567890.md"` → `:` 和 `&` 在文件名中非法 → `a.download` 赋值无效 → 浏览器静默忽略下载 | 文件名未经过滤直接使用会话标题——Windows/macOS 对文件名有字符限制（`:` `/` `\` `*` `?` `"` `<` `>` `|` 等） | 增加文件名清洗函数：`sanitizeFilename(title)` 将非法字符替换为 `-`，连续多个 `-` 合并为一个，首尾去除 `-` |
| 2 | 导出长会话（500+ 条消息）时 `_toMarkdown` 的 `lines.join('\n')` 导致内存占用过高——浏览器 Tab 崩溃 | 用户导出 500 条消息的会话 → `_toMarkdown` 遍历所有消息 → `lines` 数组累积 500+ 个字符串 → `join('\n')` 创建 ~500KB 字符串 → `Blob` 构造函数再次复制 → 内存翻倍 ~1MB | 500 条消息的 Markdown 导出本身不应导致 OOM（~500KB），但若消息内容包含大量代码块/RAG 来源，单条消息可达 50KB → 总字符串 25MB → `Blob` 复制后 50MB → 在内存受限的 Content Script 环境中可能触发 OOM | 改为流式导出——使用 `Blob` 的 `new Blob(parts)` 构造（`parts` 为字符串数组，`Blob` 构造函数不复制字符串），或将导出逻辑移至 Service Worker（独立进程，内存限制更宽松） |
| 3 | JSON 导出中 `session.messages` 的 `timestamp` 字段可能为 `undefined`——旧版本消息无 `timestamp` 字段 | 用户从 v1.0 升级到 v1.1（YP-09-14 迁移后）→ 旧消息的 `timestamp` 字段在迁移中被正确添加 → 但存在边缘情况：迁移失败的会话消息仍使用旧格式 `{sender, text}` → `toJSON` 访问 `msg.timestamp` 为 `undefined` | `_toJson` 中 `timestamp: msg.timestamp` 未提供 fallback——`msg.timestamp` 为 `undefined` 时 JSON 输出 `"timestamp": null` 但不影响导出 | 在 `_toJson` 中增加 `timestamp: msg.timestamp ?? msg.createdAt ?? session.createdAt` 三级 fallback |
| 4 | `URL.revokeObjectURL` 在 `a.click()` 后立即调用——但浏览器可能尚未完成下载 | `download` 函数中 `a.click()` → `URL.revokeObjectURL(url)` → 部分浏览器（Firefox）在 `click` 事件处理完成前就撤销了 Blob URL → 下载失败 | `click()` 触发异步下载流程，`revokeObjectURL` 同步执行——在 Firefox 中下载可能尚未开始 | 将 `revokeObjectURL` 延迟到 `setTimeout(() => URL.revokeObjectURL(url), 1000)` 或使用 `a.addEventListener('click', () => setTimeout(() => revoke, 0))` |

## 设计决策记录

### D-01: Markdown + JSON 双格式导出

**状态**: 已采纳
**背景**: 用户导出聊天数据有两种典型场景：人类阅读（知识归档、PR 讨论、笔记）和程序处理（数据备份、跨工具迁移、批量分析）。单一格式无法同时满足两种需求。
**决策**: 同时支持 Markdown 和 JSON 两种导出格式。Markdown 面向人类阅读（带标题、角色标识、时间戳），JSON 面向程序处理（结构化、可重新解析、含版本标识）。
**理由**: Markdown 可读性最高，适合直接粘贴到 GitHub Issues、Notion、Obsidian 等知识管理工具；JSON 保留完整数据结构，支持未来重新导入或跨工具迁移；两种格式共享同一 `exportSession` 入口，仅在转换层有差异。
**影响**: Markdown 导出中 RAG 来源使用 `<details>` 折叠避免文件过长；JSON 导出包含 `version: "1.0"` 标识以支持未来的格式迁移；Markdown 导出不支持重新导入（需额外开发导入功能）；消息中的 `tool_calls` 卡片当前两种格式均未处理（仅导出 `role: 'user' | 'assistant'` 的消息）。

### D-02: RAG 来源折叠（`<details>` 标签）

**状态**: 已采纳
**背景**: AI 回复中的 RAG 来源引用（知识库文件路径、相关性分数）对用户有参考价值，但全部展开会显著增加导出文件长度（每条消息可能引用 3-5 个来源，每个来源一行）。
**决策**: 在 Markdown 导出中使用 HTML `<details><summary>` 标签折叠 RAG 来源。折叠默认关闭，用户点击展开查看。格式为 `[标题](路径) (相关性: 92%)`。
**理由**: `<details>` 标签在 GitHub、VS Code、Obsidian 等主流 Markdown 渲染器中均支持；折叠默认关闭避免了导出文件过长（50 条消息的 RAG 来源全部展开可能增加 200+ 行）；相关性百分比（`(score * 100).toFixed(0)`）提供了直观的参考价值排序。
**影响**: 在纯文本 Markdown 阅读器中 `<details>` 标签会显示为原始 HTML（不影响可读性，仅失去折叠效果）；JSON 导出中 RAG 来源作为 `sources` 数组保留完整结构；若消息无 `sources` 字段，折叠块不输出。

### D-03: Blob URL + a.click() 触发浏览器下载

**状态**: 已采纳
**背景**: 导出内容需要在浏览器中触发文件下载。Content Script 的隔离世界限制了对 `chrome.downloads` API 的直接访问（需通过 Service Worker 中继）。
**决策**: 使用 `Blob` + `URL.createObjectURL` + `<a>.click()` 触发浏览器下载。`Blob` 构造函数支持 `parts` 数组（不复制字符串），`a.click()` 触发浏览器原生下载对话框。
**理由**: `a.click()` 是 Content Script 中触发下载的最简单方式，无需通过 SW 中继；`Blob` 构造函数接受字符串数组不复制数据，避免大文件导出时的内存翻倍问题；`URL.revokeObjectURL` 在 `setTimeout` 延迟后调用（兼容 Firefox 异步下载）。
**影响**: 在严格 CSP 的页面中 `a.click()` 可能被阻止，需考虑通过 `chrome.runtime.sendMessage` 将下载委托给 SW（使用 `chrome.downloads` API）；`URL.revokeObjectURL` 需延迟 1s 调用（Firefox 中 `click` 事件处理完成前撤销 URL 会导致下载失败）；文件名需经过 `sanitizeFilename` 处理（去除 `:` `/` `\` `*` `?` `"` `<` `>` `|` 等非法字符）。

### D-04: 文件名安全清洗（跨平台兼容）

**状态**: 已采纳
**背景**: 会话标题可能包含操作系统文件名中的非法字符（如 `API 设计: 限流 & 认证`），直接用作文件名会导致下载失败（浏览器静默忽略）。
**决策**: 实现 `sanitizeFilename(title)` 函数：将非法字符（`:` `/` `\` `*` `?` `"` `<` `>` `|`）替换为 `-`，连续多个 `-` 合并为一个，首尾去除 `-`。文件名格式为 `yipet-{sanitizedTitle}-{timestamp}.{ext}`。
**理由**: 字符替换 + 合并 + 首尾去除的三步清洗确保文件名在所有主流 OS（Windows/macOS/Linux）上合法；保留时间戳确保同名会话的多次导出不会互相覆盖；`yipet-` 前缀便于用户在下载目录中识别扩展导出文件。

**影响**: 清洗后的文件名可能与原会话标题差异较大（如 `API 设计: 限流 & 认证` 变为 `API-设计-限流-认证`），但可读性仍然保留；会话标题为空时使用默认名称 `chat`；文件名长度未做限制（Windows 最大路径 260 字符，但文件名本身通常远小于此限制）。
