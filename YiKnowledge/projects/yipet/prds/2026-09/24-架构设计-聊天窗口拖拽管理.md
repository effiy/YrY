# YP-09-17: 聊天窗口拖拽与窗口管理 — 多显示器与边界约束

> 需求编号：YP-09-17 · 优先级：P2 · 人天：0.5d · 状态：需求已编写

## 背景

YiPet 聊天窗口支持自由拖拽和调整大小，但当前实现存在体验缺陷：窗口可拖出屏幕外、无吸附边缘、多显示器环境下位置计算基于主显示器坐标、无最小尺寸约束导致窗口可缩到不可用状态。

---

## 一、目标架构

```typescript
// YiPet/src/chat/composables/useWindowDrag.ts

interface DragBounds {
  minX: number; minY: number; maxX: number; maxY: number;
  minWidth: number; minHeight: number;
  snapThreshold: number;  // 吸附阈值 (px)
}

export function useWindowDrag(chatWindowRef: Ref<HTMLElement>) {
  const position = reactive({ x: 100, y: 100 });
  const size = reactive({ width: 400, height: 600 });
  const isDragging = ref(false);
  const isResizing = ref(false);

  // 多显示器兼容——基于 screen.availLeft/availTop 计算全局边界
  const getScreenBounds = (): DragBounds => ({
    minX: (window.screen as any).availLeft ?? 0,
    minY: (window.screen as any).availTop ?? 0,
    maxX: ((window.screen as any).availLeft ?? 0) + window.screen.availWidth,
    maxY: ((window.screen as any).availTop ?? 0) + window.screen.availHeight,
    minWidth: 320,    // 聊天窗口最小宽度
    minHeight: 400,   // 聊天窗口最小高度
    snapThreshold: 10, // 10px 吸附
  });

  const clampPosition = (x: number, y: number) => {
    const bounds = getScreenBounds();
    x = Math.max(bounds.minX, Math.min(x, bounds.maxX - size.width));
    y = Math.max(bounds.minY, Math.min(y, bounds.maxY - 50)); // 保留 50px 标题栏可见
    return { x, y };
  };

  const clampSize = (w: number, h: number) => {
    const bounds = getScreenBounds();
    return {
      width: Math.max(bounds.minWidth, Math.min(w, bounds.maxX - position.x)),
      height: Math.max(bounds.minHeight, Math.min(h, bounds.maxY - position.y)),
    };
  };

  // 边缘吸附——接近屏幕边缘时自动吸附
  const snapToEdge = (x: number, y: number) => {
    const bounds = getScreenBounds();
    const snap = bounds.snapThreshold;

    if (Math.abs(x - bounds.minX) < snap) x = bounds.minX;
    if (Math.abs(x + size.width - bounds.maxX) < snap) x = bounds.maxX - size.width;
    if (Math.abs(y - bounds.minY) < snap) y = bounds.minY;
    if (Math.abs(y + size.height - bounds.maxY) < snap) y = bounds.maxY - size.height;

    return { x, y };
  };

  // 双击标题栏——窗口在预设位置间切换
  const presetPositions = [
    { x: 100, y: 100 },              // 默认
    { x: (window.screen.availWidth - size.width) / 2,
      y: (window.screen.availHeight - size.height) / 2 },  // 居中
    { x: window.screen.availWidth - size.width - 20, y: 100 },  // 右上
  ];
  let currentPreset = 0;

  const cyclePreset = () => {
    currentPreset = (currentPreset + 1) % presetPositions.length;
    const preset = presetPositions[currentPreset];
    Object.assign(position, clampPosition(preset.x, preset.y));
  };

  // 持久化位置
  const savePosition = async () => {
    await chrome.storage.local.set({
      'yipet:chatWindow': { ...position, ...size },
    });
  };

  const restorePosition = async () => {
    const saved = (await chrome.storage.local.get('yipet:chatWindow'))
      ['yipet:chatWindow'];
    if (saved) {
      Object.assign(position, clampPosition(saved.x, saved.y));
      Object.assign(size, clampSize(saved.width, saved.height));
    }
  };

  return {
    position, size, isDragging, isResizing,
    clampPosition, clampSize, snapToEdge, cyclePreset,
    savePosition, restorePosition,
  };
}
```

## 三、测试规格

#### Scenario: 窗口不拖出屏幕边界
- **Given** 屏幕宽度 1920px, 窗口宽度 400px
- **When** 拖拽窗口到 x=1600
- **Then** `clampPosition` 将 x 限制在 `1920-400=1520` 以内

#### Scenario: 多显示器——副屏左侧
- **Given** 副屏的 `screen.availLeft = -1920`, 主屏 `availLeft = 0`
- **When** 拖拽窗口到副屏 `x=-1800`
- **Then** `getScreenBounds().minX = -1920`, 窗口可放入副屏

#### Scenario: 窗口最小尺寸约束
- **Given** `minWidth=320, minHeight=400`
- **When** 调整窗口到 `200×200`
- **Then** `clampSize` 返回 `320×400`

#### Scenario: 边缘吸附——接近左边缘
- **Given** `snapThreshold=10`
- **When** 拖拽窗口到 x=5
- **Then** `snapToEdge` 将 x 设为 0（吸附到左边缘）

#### Scenario: 双击标题栏循环预设位置
- **Given** 窗口在默认位置 (100, 100)
- **When** 双击标题栏
- **Then** 窗口移动到居中位置
- **When** 再次双击
- **Then** 窗口移动到右上位置
- **When** 再次双击
- **Then** 窗口回到默认位置

#### Scenario: 位置持久化与恢复
- **Given** 上次关闭时窗口在 (200, 300), 400×600
- **When** 重新打开聊天窗口
- **Then** `restorePosition()` 恢复到 (200, 300), 400×600

## 四、代码审查检查清单

- [ ] `getScreenBounds()` 使用 `screen.availLeft/availTop` 而非假设主屏从 0 开始
- [ ] 窗口至少保留 50px 标题栏在屏幕内（可拖回）

- [ ] `restorePosition()` 校验保存的位置仍在屏幕范围内
- [ ] 预设位置数量 3（避免循环过多）

## 重构后发现的回归问题

| # | 问题 | 发现场景 | 根因 | 修复方式 |
|---|------|---------|------|---------|
| 1 | 多显示器拔插后 `restorePosition` 恢复到已不存在的屏幕坐标——窗口不可见且无法拖回 | 用户在外接显示器（副屏 `availLeft = -1920`）上使用聊天窗口 → 拔出外接显示器 → 重新打开聊天窗口 → `restorePosition` 恢复 x=-1800 → 窗口在不可见的屏幕区域 | `restorePosition` 仅调用 `clampPosition`，但 `clampPosition` 的 `getScreenBounds()` 在单显示器时返回 `minX=0` → 窗口被 clamp 到 x=0, y=100 的默认位置 —— 等等，这应该是正确的。但实际问题是 `screen.availLeft` 在拔出显示器后可能仍返回旧值（Chrome bug）或用户快速插拔时 `screen` 对象未更新 | 在 `restorePosition` 中增加二次校验：恢复后检查窗口是否在可视区域内（`window.screenX` 和 `window.screen.availWidth`），若不可见则重置到默认位置 `(100, 100)` |
| 2 | 拖拽过程中 `savePosition` 的 debounce 300ms 在拖拽结束时未触发最后一次保存 | 用户拖拽窗口到新位置 → 释放鼠标 → 300ms 内关闭聊天窗口 → `savePosition` 的 debounce 回调未执行 → 新位置丢失 | 标准的 debounce 仅延迟执行，不保证在组件销毁前触发。窗口关闭时 Vue 组件卸载 → debounce 的 `setTimeout` 被清除 | 在 `useWindowDrag` 的 `onUnmounted` 生命周期中调用 `savePosition` 的 flush 方法（立即执行最后一次 debounced 调用），确保位置在窗口关闭前保存 |
| 3 | 边缘吸附在窗口调整大小时未触发——窗口可被调整到屏幕外 | 用户从右下角调整窗口大小 → 拖拽到屏幕边缘外侧 → `clampSize` 限制大小但 `snapToEdge` 未在 resize 事件中调用 | `snapToEdge` 仅在拖拽（`mousemove`）时调用，未在 resize（`mousedown` on resize handle + `mousemove`）时调用 | 在 resize 的 `mousemove` handler 中增加 `snapToEdge` 调用，或在 `mouseup` 时统一调用 `snapToEdge` + `clampPosition` |
| 4 | 双击标题栏循环预设位置时，窗口在 `cyclePreset` 中直接修改 `position` 对象——Vue 响应式未触发更新 | 双击标题栏 → `cyclePreset` 执行 → `Object.assign(position, clampPosition(...))` → 但 `position` 是 `reactive` 对象，`Object.assign` 应触发响应式更新。实际问题是 `clampPosition` 返回的 `{x, y}` 与当前位置相同（窗口已在预设位置附近）→ `Object.assign` 无实际变更 → Vue 跳过更新 | `cyclePreset` 的 `Object.assign` 在值未变化时 Vue 不触发渲染——但位置确实变了（用户在预设位置之间移动） | 在 `cyclePreset` 中增加过渡动画（CSS `transition: left 0.3s, top 0.3s`），让用户感知到位置变化——即使值在 `Object.assign` 后重复设置 |

## 设计决策记录

### D-01: screen.availLeft/availTop 多显示器坐标系统

**状态**: 已采纳
**背景**: 聊天窗口的拖拽边界计算需要支持多显示器环境。传统方案假设主屏从坐标 (0,0) 开始，导致副屏（如左侧副屏 `availLeft = -1920`）上的窗口无法正确定位。
**决策**: 使用 `window.screen.availLeft` 和 `window.screen.availTop` 作为全局坐标系原点，结合 `window.screen.availWidth` 和 `window.screen.availHeight` 计算各显示器的可用区域边界。`getScreenBounds()` 返回基于当前显示器可用区域的 `DragBounds`。
**理由**: `screen.availLeft/availTop` 是 Web API 中唯一能获取多显示器布局的接口，Chrome 在所有平台上正确报告这些值；基于可用区域（排除任务栏/Dock）而非屏幕总尺寸，避免窗口被系统 UI 遮挡。
**影响**: 多显示器拔插后 `screen` 对象可能未及时更新（Chrome bug），需在 `restorePosition` 中增加二次校验——恢复后检查窗口是否在可视区域内，若不可见则重置到默认位置；窗口位置持久化仅存储 `{x, y, width, height}`，不包含屏幕信息（避免泄露显示器布局）。

### D-02: 10px 阈值边缘吸附

**状态**: 已采纳
**背景**: 用户拖拽窗口到屏幕边缘附近时，手动对齐到像素级精度困难。边缘吸附是桌面操作系统的标准交互模式。
**决策**: 采用 10px 吸附阈值——当窗口边缘距离屏幕边界 < 10px 时，自动吸附到边界。吸附在拖拽（`mousemove`）和调整大小（resize `mousemove`）时均触发，在 `mouseup` 时统一调用 `snapToEdge` + `clampPosition` 确保最终位置正确。
**理由**: 10px 是桌面 OS 的常见吸附阈值（macOS 窗口吸附约 10-15px，Windows Snap 约 20px），用户体验自然；吸附在拖拽和 resize 时均触发，保持交互一致性。
**影响**: 需在 resize 的 `mousemove` handler 中增加 `snapToEdge` 调用（回归风险：原实现仅在拖拽时触发吸附）；吸附触发后位置值可能重复（`Object.assign` 在值未变化时 Vue 跳过渲染），需配合 CSS `transition: left 0.3s, top 0.3s` 让用户感知到吸附效果。

### D-03: 双击标题栏循环预设位置

**状态**: 已采纳
**背景**: 用户需要快速将聊天窗口移动到常用位置（默认、居中、右上），手动拖拽效率低。双击标题栏是桌面窗口管理器的标准交互。
**决策**: 预设 3 个位置（默认 (100,100)、居中、右上），双击标题栏循环切换。`cyclePreset()` 在 3 个预设间循环，每次调用 `clampPosition` 确保预设位置在当前屏幕范围内。
**理由**: 3 个预设覆盖了最常见的窗口位置需求（默认/居中/不遮挡主要内容）；双击标题栏是用户熟悉的交互模式（macOS 双击标题栏最小化，Windows 双击最大化）；循环切换而非单次切换提供了更多选择。
**影响**: 预设位置使用绝对坐标而非屏幕百分比，在 4K 显示器上可能不理想（右上预设 `x: screenWidth - width - 20` 在 4K 上过于靠右），可改为百分比计算；多 Tab 场景下各 Tab 的聊天窗口共享 `yipet:chatWindow` key，最后关闭的 Tab 覆盖其他 Tab 的位置（应改为按 Tab ID 分 key）；`cyclePreset` 需配合过渡动画（CSS transition）让用户感知位置变化。

### D-04: chrome.storage.local 持久化 + debounce 防抖

**状态**: 已采纳
**背景**: 聊天窗口位置需在浏览器重启后恢复，且拖拽过程中频繁写入 storage 会触发配额限制（每分钟最多 120 次写入）。
**决策**: 窗口位置（`{x, y, width, height}`）持久化到 `chrome.storage.local` 的 `yipet:chatWindow` key。拖拽过程中使用 300ms debounce 控制写入频率，`savePosition` 在拖拽结束时通过 `onUnmounted` 的 flush 方法确保最后一次位置被保存。
**理由**: 300ms debounce 在拖拽体验（实时保存）和 storage 配额（120 次/分钟）之间取得平衡——连续拖拽 10 秒产生约 33 次写入，远低于配额限制；`onUnmounted` flush 确保窗口关闭前最后一次位置不丢失。

**影响**: `restorePosition` 恢复时需校验保存的位置仍在屏幕范围内（多显示器拔插后旧坐标可能不可见）；多个 Tab 的聊天窗口共享同一 key 导致位置覆盖；`chrome.storage.local.set` 在 MV3 SW 中通过 IPC 执行，每次写入约 5-10ms 延迟。
