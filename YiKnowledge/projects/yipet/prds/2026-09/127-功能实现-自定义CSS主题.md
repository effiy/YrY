# YP-09-120: 自定义CSS主题 — 用户自定义CSS变量、Shadow DOM主题注入、预设主题库、主题导入导出、站点级主题覆盖、无障碍对比度校验

> 需求编号：YP-09-120 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YP-09-26（主题系统）、YP-09-38（Shadow DOM 样式隔离增强）

## 背景

### 问题陈述

YiPet 当前主题系统（YP-09-26）仅支持固定的几套内置主题（浅色/深色），用户无法自定义聊天窗口和宠物浮层的视觉风格。这导致：

1. **个性化受限**：用户只能从预设主题中选择，无法调整颜色、字体、圆角等细节，与"宠物伴侣"的个性化定位不符
2. **视觉疲劳**：长时间使用固定配色方案，用户容易产生视觉疲劳，缺乏新鲜感
3. **品牌统一困难**：企业用户希望将宠物浮层配色与公司品牌色对齐，但当前不支持
4. **无障碍缺失**：现有主题未检查对比度，部分配色组合对色弱/低视力用户不友好
5. **站点适配不足**：同一套主题在深色网页和浅色网页上表现不一致，部分页面主题与网页背景融为一体

**核心矛盾**：在 Shadow DOM 隔离的样式体系下，提供用户可自定义的 CSS 主题系统，既要保证样式隔离不破坏页面，又要支持灵活的主题定制和跨站点差异化。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 用户无法自定义视觉风格，个性化体验差 | 中 | 用户希望将聊天窗口改为粉色系，但只能选深色/浅色 |
| 2 | 主题在不同网页上表现不一致 | 高 | 深色主题在深色背景网页上文字不可见 |
| 3 | 部分主题色对比度不足，无障碍体验差 | 中 | 浅灰文字在白色背景上难以辨认 |
| 4 | 无法分享自定义主题给他人 | 低 | 用户设计了一套好看的主题想分享给朋友 |
| 5 | 企业用户无法对齐品牌色 | 低 | 公司内部使用需要统一品牌视觉 |

### 挑战

| 挑战 | 说明 |
|------|------|
| Shadow DOM 样式注入 | CSS 变量必须穿透 Shadow DOM 边界，同时保持样式隔离 |
| 实时预览性能 | 编辑 CSS 变量时需要即时反映到聊天窗口和宠物浮层，不能有闪烁 |
| 对比度自动检测 | 需要实时计算颜色对比度（WCAG 标准），校验文字/背景组合 |
| 站点级覆盖 | 不同域名需要独立的主题配置，配置管理复杂度增加 |
| 主题兼容性 | 自定义主题必须兼容明暗模式切换，且不破坏现有布局 |

## 二、设计决策

### 决策 1：主题编辑器位置 — Popup 面板 vs 独立设置页 vs 聊天窗口内嵌

| 选项 | 空间 | 操作便捷性 | 实时预览 | 复杂度 |
|------|------|------------|----------|--------|
| Popup 面板 | 小（300x400） | 高 | 需传递到 content | 中 |
| 独立设置页（options page） | 大 | 中 | 需传递到 content | 低 |
| 聊天窗口内嵌 | 大 | 高 | 直接 | 高 |

**选择：独立设置页（options page）为主，聊天窗口内嵌快捷入口。** 设置页提供完整的编辑器空间（全屏），适合复杂编辑操作。聊天窗口内嵌一个快捷入口（"自定义主题"按钮），点击后打开设置页并定位到当前站点主题。Popup 空间太小不适合编辑器。

### 决策 2：CSS 变量编辑方式 — 可视化表单 vs 代码编辑器 vs 两者兼有

| 选项 | 上手难度 | 灵活性 | 实现复杂度 | 错误率 |
|------|----------|--------|------------|--------|
| 可视化表单（颜色选择器+滑块） | 低 | 中（仅预设变量） | 中 | 低 |
| 代码编辑器（直接写 CSS） | 高 | 高（任意 CSS） | 低 | 高 |
| 两者兼有 | 低 | 高 | 高 | 低 |

**选择：两者兼有。** 默认展示可视化表单（颜色选择器、边框圆角滑块、字体大小调节），满足 90% 用户需求。提供"高级模式"切换到代码编辑器，支持直接编写 CSS 变量覆盖和额外样式规则。两个编辑器双向同步——表单修改自动更新代码，代码修改解析后回填表单。

### 决策 3：主题存储格式 — 纯 CSS 变量 vs JSON 配置 vs 两者兼有

| 选项 | 体积 | 可移植性 | 可读性 | 安全性 |
|------|------|----------|--------|--------|
| 纯 CSS 变量文本 | 极小 | 高（直接可用） | 中 | 需过滤 |
| JSON 配置对象 | 小 | 中（需解析） | 高 | 高 |
| 两者兼有（JSON + 编译后的 CSS） | 小 | 高 | 高 | 高 |

**选择：JSON 配置对象存储，导出时同时生成 CSS 变量文本。** JSON 方便程序化处理（对比度检查、站点覆盖匹配），导出时附加编译后的 CSS 变量文本便于直接使用。存储结构包含 `variables`（变量键值对）、`meta`（名称、作者、标签）、`cssOverrides`（高级模式额外 CSS）。

### 决策 4：站点级覆盖匹配策略 — 精确匹配 vs 通配符 vs 正则

| 选项 | 灵活度 | 性能 | 用户理解成本 | 实现复杂度 |
|------|--------|------|-------------|------------|
| 精确域名匹配 | 低 | 高 | 低 | 低 |
| 通配符匹配（*.example.com） | 中 | 高 | 中 | 中 |
| 正则表达式 | 高 | 中 | 高 | 中 |

**选择：精确域名匹配 + 通配符支持。** 默认精确匹配当前域名，支持 `*.example.com` 通配符覆盖所有子域名。通配符优先级低于精确匹配。正则表达式过于复杂，用户理解成本高，且存在 ReDoS 风险。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 编辑器位置 | Popup 面板 | 独立设置页 | 聊天窗口内嵌 | **独立设置页 + 快捷入口** | 空间充足，操作便捷 |
| 编辑方式 | 可视化表单 | 代码编辑器 | 两者兼有 | **两者兼有** | 兼顾新手和高级用户 |
| 存储格式 | 纯 CSS | JSON 配置 | 两者兼有 | **JSON + 导出CSS** | 程序化处理友好 |
| 站点匹配 | 精确匹配 | 通配符 | 正则表达式 | **精确 + 通配符** | 安全且够用 |

### 4.2 主题管理器

```typescript
// src/content/theme/ThemeManager.ts (新增)

class ThemeManager {
  private storage: ThemeStorage;
  private currentTheme: ThemeConfig | null = null;
  private shadowRoot: ShadowRoot;
  private styleElement: HTMLStyleElement;

  constructor(shadowRoot: ShadowRoot) {
    this.shadowRoot = shadowRoot;
    this.styleElement = document.createElement('style');
    this.styleElement.id = 'yipet-theme-variables';
    this.shadowRoot.appendChild(this.styleElement);
  }

  /**
   * 初始化：加载主题配置并注入到 Shadow DOM
   */
  async init(): Promise<void> {
    this.storage = await this.loadStorage();
    const hostname = window.location.hostname;

    // 查找站点级覆盖
    const override = this.findSiteOverride(hostname);
    const themeId = override?.themeId || this.storage.activeThemeId;

    // 加载主题
    const theme = this.storage.themes.find(t => t.meta.id === themeId);
    if (theme) {
      await this.applyTheme(theme);
    }

    // 监听系统暗色模式切换
    if (this.storage.autoDarkMode) {
      this.watchSystemColorScheme();
    }
  }

  /**
   * 应用主题：注入 CSS 变量到 Shadow DOM
   */
  async applyTheme(theme: ThemeConfig): Promise<void> {
    this.currentTheme = theme;

    // 执行对比度检查
    const contrastWarnings = this.checkContrast(theme);
    if (contrastWarnings.length > 0) {
      this.reportContrastWarnings(contrastWarnings);
    }

    // 构建 CSS 变量声明
    const cssText = this.buildVariableCSS(theme.variables);

    // 注入到 Shadow DOM 根节点
    this.styleElement.textContent = `
      :host {
        ${cssText}
      }
      ${theme.cssOverrides}
    `;

    // 更新宿主页面的宠物浮层（如果可见）
    this.updatePetOverlay(theme.variables);
  }

  /**
   * 构建 CSS 变量声明字符串
   */
  private buildVariableCSS(vars: ThemeVariables): string {
    const mapping: Record<keyof ThemeVariables, string> = {
      primary: '--yp-primary',
      primaryHover: '--yp-primary-hover',
      primaryLight: '--yp-primary-light',
      bgPrimary: '--yp-bg-primary',
      bgSecondary: '--yp-bg-secondary',
      bgTertiary: '--yp-bg-tertiary',
      textPrimary: '--yp-text-primary',
      textSecondary: '--yp-text-secondary',
      textTertiary: '--yp-text-tertiary',
      borderColor: '--yp-border-color',
      borderLight: '--yp-border-light',
      success: '--yp-success',
      warning: '--yp-warning',
      error: '--yp-error',
      info: '--yp-info',
      radiusSm: '--yp-radius-sm',
      radiusMd: '--yp-radius-md',
      radiusLg: '--yp-radius-lg',
      radiusFull: '--yp-radius-full',
      fontSizeXs: '--yp-font-size-xs',
      fontSizeSm: '--yp-font-size-sm',
      fontSizeMd: '--yp-font-size-md',
      fontSizeLg: '--yp-font-size-lg',
      fontSizeXl: '--yp-font-size-xl',
      shadowSm: '--yp-shadow-sm',
      shadowMd: '--yp-shadow-md',
      shadowLg: '--yp-shadow-lg',
      spacingXs: '--yp-spacing-xs',
      spacingSm: '--yp-spacing-sm',
      spacingMd: '--yp-spacing-md',
      spacingLg: '--yp-spacing-lg',
      spacingXl: '--yp-spacing-xl',
      petSize: '--yp-pet-size',
      petBubbleBg: '--yp-pet-bubble-bg',
      petBubbleText: '--yp-pet-bubble-text',
      petAnimationSpeed: '--yp-pet-animation-speed',
    };

    return Object.entries(mapping)
      .map(([key, cssVar]) => {
        const value = vars[key as keyof ThemeVariables];
        return `${cssVar}: ${value};`;
      })
      .join('\n        ');
  }

  /**
   * WCAG 2.1 AA 对比度检查
   * 普通文字: 4.5:1, 大文字: 3:1
   */
  private checkContrast(theme: ThemeConfig): string[] {
    const warnings: string[] = [];

    const pairs = [
      { fg: theme.variables.textPrimary, bg: theme.variables.bgPrimary, label: '主文字/主背景' },
      { fg: theme.variables.textSecondary, bg: theme.variables.bgPrimary, label: '次文字/主背景' },
      { fg: theme.variables.textPrimary, bg: theme.variables.bgSecondary, label: '主文字/次背景' },
      { fg: theme.variables.primary, bg: theme.variables.bgPrimary, label: '主色/主背景' },
      { fg: '#ffffff', bg: theme.variables.primary, label: '白色文字/主色按钮' },
    ];

    for (const pair of pairs) {
      const ratio = this.calculateContrastRatio(pair.fg, pair.bg);
      if (ratio < 4.5) {
        warnings.push(`${pair.label}: 对比度 ${ratio.toFixed(1)}:1 (需要 >= 4.5:1)`);
      }
    }

    return warnings;
  }

  /**
   * 计算两个颜色的 WCAG 对比度
   */
  private calculateContrastRatio(hex1: string, hex2: string): number {
    const luminance1 = this.getRelativeLuminance(hex1);
    const luminance2 = this.getRelativeLuminance(hex2);
    const lighter = Math.max(luminance1, luminance2);
    const darker = Math.min(luminance1, luminance2);
    return (lighter + 0.05) / (darker + 0.05);
  }

  private getRelativeLuminance(hex: string): number {
    const rgb = this.hexToRgb(hex);
    const [r, g, b] = [rgb.r, rgb.g, rgb.b].map((c) => {
      const s = c / 255;
      return s <= 0.03928 ? s / 12.92 : Math.pow((s + 0.055) / 1.055, 2.4);
    });
    return 0.2126 * r + 0.7152 * g + 0.0722 * b;
  }

  private hexToRgb(hex: string): { r: number; g: number; b: number } {
    const result = /^#?([a-f\d]{2})([a-f\d]{2})([a-f\d]{2})$/i.exec(hex);
    if (!result) return { r: 0, g: 0, b: 0 };
    return {
      r: parseInt(result[1], 16),
      g: parseInt(result[2], 16),
      b: parseInt(result[3], 16),
    };
  }

  /**
   * 查找站点级主题覆盖
   */
  private findSiteOverride(hostname: string): SiteThemeOverride | undefined {
    // 1. 精确匹配优先
    const exact = this.storage.siteOverrides.find(o => o.domain === hostname && o.enabled);
    if (exact) return exact;

    // 2. 通配符匹配
    for (const override of this.storage.siteOverrides) {
      if (!override.enabled) continue;
      if (override.domain.startsWith('*.')) {
        const suffix = override.domain.slice(1); // .example.com
        if (hostname.endsWith(suffix) || hostname === override.domain.slice(2)) {
          return override;
        }
      }
    }

    return undefined;
  }

  /**
   * 导出主题为 JSON 文件
   */
  exportTheme(themeId: string): string {
    const theme = this.storage.themes.find(t => t.meta.id === themeId);
    if (!theme) throw new Error('Theme not found');

    return JSON.stringify({
      ...theme,
      exportedCSS: this.buildVariableCSS(theme.variables),
    }, null, 2);
  }

  /**
   * 从 JSON 导入主题
   */
  importTheme(json: string): ThemeConfig {
    const parsed = JSON.parse(json);

    // 验证必要字段
    if (!parsed.variables || !parsed.meta) {
      throw new Error('Invalid theme JSON: missing variables or meta');
    }

    const theme: ThemeConfig = {
      meta: {
        ...parsed.meta,
        id: parsed.meta.id || this.generateId(),
        isPreset: false,
        createdAt: parsed.meta.createdAt || Date.now(),
        updatedAt: Date.now(),
      },
      variables: parsed.variables,
      cssOverrides: parsed.cssOverrides || '',
    };

    // 避免重复，如果已存在同名主题则覆盖
    const existingIndex = this.storage.themes.findIndex(
      t => t.meta.id === theme.meta.id
    );
    if (existingIndex >= 0) {
      this.storage.themes[existingIndex] = theme;
    } else {
      this.storage.themes.push(theme);
    }

    this.saveStorage();
    return theme;
  }

  /**
   * 设置站点级主题覆盖
   */
  setSiteOverride(domain: string, themeId: string): void {
    const existing = this.storage.siteOverrides.find(o => o.domain === domain);
    if (existing) {
      existing.themeId = themeId;
      existing.enabled = true;
    } else {
      this.storage.siteOverrides.push({ domain, themeId, enabled: true });
    }
    this.saveStorage();
  }

  /**
   * 重置为默认主题
   */
  resetToDefault(): void {
    const defaultTheme = this.getPresetTheme('default-light');
    this.storage.activeThemeId = defaultTheme.meta.id;
    this.saveStorage();
    this.applyTheme(defaultTheme);
  }

  private getPresetTheme(presetId: string): ThemeConfig {
    return PRESET_THEMES.find(t => t.meta.id === presetId)!;
  }

  private async loadStorage(): Promise<ThemeStorage> {
    const result = await chrome.storage.local.get('yipet_theme_storage');
    return result.yipet_theme_storage || this.getDefaultStorage();
  }

  private async saveStorage(): Promise<void> {
    await chrome.storage.local.set({ yipet_theme_storage: this.storage });
  }

  private generateId(): string {
    return crypto.randomUUID();
  }

  private getDefaultStorage(): ThemeStorage {
    return {
      themes: PRESET_THEMES,
      activeThemeId: 'default-light',
      siteOverrides: [],
      autoDarkMode: true,
    };
  }
}
```

**THEN** 浏览器下载一个 JSON 文件，包含完整的 variables 和 meta
**AND** JSON 文件包含 `exportedCSS` 字段（编译后的 CSS 变量文本）
**WHEN** 用户 B 点击"导入 JSON"并选择该文件
**THEN** 主题被正确导入到用户 B 的主题列表
**AND** 用户 B 可以应用该主题

### 场景 4：站点级主题覆盖

**GIVEN** 用户设置了全局主题为"浅色默认"
**WHEN** 用户在 `github.com` 上打开聊天窗口，设置该站点覆盖为"深色默认"
**WHEN** 用户访问 `github.com` 任意页面
**THEN** 聊天窗口自动应用深色主题
**WHEN** 用户访问 `google.com`（未设置覆盖）
**THEN** 聊天窗口应用全局默认的浅色主题
**WHEN** 用户设置 `*.example.com` 覆盖为"森林"主题
**THEN** `a.example.com` 和 `b.example.com` 均应用森林主题

### 场景 5：对比度校验与警告

**GIVEN** 用户在主题编辑器中修改配色
**WHEN** 用户设置主文字色为 `#C0C4CC`（浅灰），主背景为 `#FFFFFF`（白色）
**THEN** 对比度指示器显示"3.0:1 — 不通过（需 >= 4.5:1）"
**AND** UI 显示警告提示"主文字/主背景对比度不足"
**WHEN** 用户修改文字色为 `#303133`（深灰）
**THEN** 对比度指示器显示"8.5:1 — 通过 AAA"
**AND** 警告消失

### 场景 6：主题重置为默认

**GIVEN** 用户自定义了多套主题，当前应用"我的橙色主题"
**WHEN** 用户点击"重置为默认"
**THEN** 当前主题切换为"浅色默认"
**AND** 所有预设主题不受影响
**AND** 自定义主题保留在列表中（不删除）
**AND** 站点覆盖配置保留

## 七、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 用户编写的 CSS 覆盖规则破坏 Shadow DOM 布局 | 中 | 高 | 高级模式 CSS 限制在 `:host` 和预定义选择器范围内，禁止使用 `display: none`、`position: fixed` 等危险属性 |
| CSS 变量注入时产生 FOUC（无样式内容闪烁） | 中 | 中 | 在 Shadow DOM 创建时同步注入变量，使用 `requestAnimationFrame` 确保首帧渲染前完成 |
| chrome.storage.local 10MB 主题存储超限 | 低 | 中 | 每套主题 < 5KB，限制自定义主题数量上限为 50 套（约 250KB），超限提示删除旧主题 |
| 导入的 JSON 文件包含恶意 CSS（如 `url()` 外链） | 低 | 高 | 导入时过滤 `url()` 引用、`@import` 规则、`expression()` 等危险 CSS 函数 |
| 站点通配符匹配性能问题 | 低 | 低 | 站点覆盖数量少（通常 < 20），通配符匹配复杂度 O(n)，无需优化 |
| 对比度检查器与 WebAIM 结果不一致 | 低 | 中 | 使用 WCAG 2.1 标准公式，单元测试覆盖已知颜色对（黑白、红绿等），与 WebAIM 对比验证 |

## 九、设计决策记录

### D-01：主题编辑器交互模式

- **问题**：如何让用户编辑 CSS 变量——可视化表单还是代码编辑器
- **选项**：纯可视化表单、纯代码编辑器、两者兼有（表单+高级模式）
- **选择**：两者兼有，默认表单模式
- **理由**：90% 用户仅需修改颜色和圆角，可视化表单（颜色选择器、滑块）满足需求。剩余 10% 高级用户通过代码编辑器直接编辑 CSS 变量和额外规则。两个编辑器双向同步，降低切换成本。

### D-02：CSS 变量注入策略

- **问题**：自定义 CSS 变量如何注入到 Shadow DOM
- **选项**：注入到 `:host` 根节点、注入到每个组件内部、使用 CSSStyleSheet.replaceSync
- **选择**：注入到 `:host` 根节点，通过单个 `<style>` 标签
- **理由**：CSS 自定义属性（变量）继承自 `:host`，所有子组件自动继承。单个 `<style>` 标签便于替换（整个替换而非逐条更新），实现原子性主题切换。

### D-03：站点覆盖优先级

- **问题**：多个覆盖规则匹配同一域名时如何确定优先级
- **选项**：最后添加的优先、通配符优先、精确匹配优先
- **选择**：精确匹配 > 通配符匹配（最长的通配符优先）> 全局默认
- **理由**：精确匹配代表用户明确意图，应优先。通配符中 `*.a.example.com` 比 `*.example.com` 更具体，应优先。全局默认作为兜底。

### D-04：主题市场策略

- **问题**：是否提供社区主题市场功能
- **选项**：仅本地导入导出、通过 YiAi 后端分享、集成第三方主题平台
- **选择**：首期仅本地导入导出，二期通过 YiAi 后端实现主题分享
- **理由**：主题市场涉及审核、版权、安全等复杂问题，投入产出比低。本地导入导出已满足核心分享需求。YiAi 后端可作为轻量级主题分享中心（类似 Gist），无需完整市场功能。

## 回归问题预测

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | CSS 变量注入时机过早，Shadow DOM 尚未完全初始化，导致变量未生效，聊天窗口显示浏览器默认样式 | ThemeManager.init() 在 Shadow DOM `connectedCallback` 之前调用，`:host` 选择器尚未挂载 | 在 Shadow DOM 的 `connectedCallback` 生命周期中调用 `applyTheme()`，确保 DOM 就绪后再注入变量 |
| 2 | 用户导入的 JSON 主题文件中 `cssOverrides` 包含 `display: none !important` 等规则，导致聊天窗口或宠物浮层完全不可见 | 高级模式 CSS 未做属性白名单过滤，用户或第三方主题可能包含破坏性规则 | 实现 CSS 属性白名单过滤器，仅允许颜色、字体、边距、圆角、阴影等视觉属性，禁止 `display`、`position`、`visibility`、`z-index` 等布局属性 |
| 3 | 站点覆盖启用后，用户在 `mail.google.com` 和 `calendar.google.com` 之间切换时，主题频繁切换导致闪烁 | 每次导航到同域不同页面时都重新执行主题匹配和注入，即使主题未变化 | 缓存当前域名和已应用的主题 ID，仅在域名变化或主题 ID 变化时才重新注入 |
| 4 | 对比度检查器对 `currentColor`、`inherit`、`transparent` 等 CSS 关键字无法计算，导致检查结果为 N/A 或报错 | 对比度计算函数仅处理 hex 格式，未处理 CSS 关键字和特殊值 | 扩展 `hexToRgb` 支持 CSS 颜色关键字解析（使用 `canvas` 的 `fillStyle` 获取计算后的 rgb 值），对 `transparent` 使用父级背景色 |
| 5 | 用户同时打开多个标签页，在一个标签页修改主题后，其他标签页的主题未同步更新，出现不一致 | 主题变更仅通过 `chrome.storage.local` 持久化，未使用 `chrome.storage.onChanged` 监听跨标签页同步 | 在 ThemeManager 中监听 `chrome.storage.onChanged` 事件，检测到 `yipet_theme_storage` 变更时自动重新加载主题 |
| 6 | 预设主题的 `petAnimationSpeed` 在用户自定义主题中被设置为 `0` 或 `5.0`，导致动画完全停止或过快闪烁 | 动画速度变量未做范围限制，允许任意值 | 在 `buildVariableCSS` 中对 `petAnimationSpeed` 值做范围限制，clamp 到 `[0.5, 2.0]`，超出范围自动修正并提示用户 |
