## 背景

### 业务背景

用户在 YiPet 聊天侧边栏中，点击 Knowledge/Stories/Bugs 标签页下的条目时会创建或打开一个对应的聊天会话。当前实现仅在 `pageContent` 中存储文件内容，但**未通过 `ctx:` 标签将文件注册为会话的上下文文件**。导致用户打开 Context 面板时看不到任何关联文件——必须手动拖放或搜索添加。

### 核心挑战

| 挑战 | 影响 | 说明 |
|------|------|------|
| 上下文面板为空 | 用户打开 Context 面板看不到关联文件 | `createSessionFrom*` 未添加 `ctx:` tag，parseToTree 无法解析 |
| pageContent 格式不对 | 即使有内容，Context 面板也无法正确解析 | 原始内容未按 `## path\n\ncontent` 格式存储 |

---

<a id="sec-1"></a>
## 一、现状与目标

### 1.1 改造前

- `createSessionFromKnowledgeFile`: 存储 `pageContent: content`，tags 仅有 `['source:YiKnowledge', 'from:path']`
- `createSessionFromStory`: 存储 `pageContent: content`，tags 无 `ctx:` 标记
- `createSessionFromBug`: 存储 markdown 表格到 `pageContent`，tags 无 `ctx:` 标记

### 1.2 改造后

- 三者的 session 创建时均添加对应文件的 `ctx:` tag
- Knowledge 和 Story 的 `pageContent` 格式化为 `## path\n\ncontent`
- Bug 的 `ctx:` tag 指向 `bug.contentPath`（知识库文件路径）
- 重新打开已有会话时，也补充 `ctx:` tag

### 1.3 行为变化

| 操作 | 改造前 | 改造后 |
|------|--------|--------|
| 点击 Knowledge 文件创建/打开会话 → 打开 Context 面板 | 面板为空 | 面板显示该文件，含路径和内容 |
| 点击 Story 创建/打开会话 → 打开 Context 面板 | 面板为空 | 面板显示 story.md 文件 |
| 点击 Bug 创建/打开会话 → 打开 Context 面板 | 面板为空 | 面板显示 bug 的知识库文件路径 |

---

## 二、用户场景

### 2.1 Knowledge 文件

```
1. 用户打开 YiPet 聊天框
2. 切换到 Knowledge 标签页
3. 点击某个知识文件（如 lessoons/failures/bugs/xxx.md）
4. 聊天框创建/打开对应会话
5. 用户点击工具栏 Context 按钮 → 看到该文件已在上下文列表中
```

### 2.2 Story

```
1. 切换到 Stories 标签页
2. 点击某个项目需求故事
3. 会话创建后，Context 面板自动包含 story.md
```

### 2.3 Bug

```
1. 切换到 Bugs 标签页
2. 点击某个 Bug 条目
3. 会话创建后，Context 面板显示 bug 的知识库文件路径
```
