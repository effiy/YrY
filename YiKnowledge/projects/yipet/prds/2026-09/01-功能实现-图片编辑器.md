## 一、概述

### 1.1 问题总览

YiPet 用户在处理聊天中的图片时，几乎所有编辑操作都需要导出到外部工具（Photoshop、在线工具、系统预览）完成后再导回。典型的"保存 → 打开外部工具 → 编辑 → 导出 → 重新上传"流程需要 4-5 步操作，每次耗时 30-60 秒。核心矛盾：浏览器内置 Canvas 2D API 具备像素级处理能力，但 YiPet 当前仅实现了基础的截图和滤镜功能，缺少一个完整的图片编辑工具链。

用户面临的核心痛点按频率排列：

1. **裁剪/旋转/翻转**（频率最高）：手机照片方向错误、需要裁剪适配社交媒体
2. **亮度/对比度/饱和度**（频率高）：曝光不当、色彩平淡的照片需要基础调色
3. **白平衡/色温**（频率中）：室内灯光偏黄、阴天偏蓝导致毛色失真
4. **高级增强**（频率中低）：去雾、暗角、径向滤镜等创意和专业需求
5. **装饰和信息**（频率中低）：边框、箭头标注、EXIF 查看

### 1.3 共享设计原则

1. **非破坏性编辑**：所有工具始终从原始 ImageData 开始计算，调整参数合并为单次遍历，避免增量修改导致的累积误差（如 RGB↔HSL 浮点舍入）
2. **归一化坐标**：选区/滤镜位置使用 0~1 比例坐标（非像素坐标），独立于显示尺寸，缩放后选区不偏移
3. **统一渲染管线**：`原始图加载 → ImageData 提取 → 参数快照合并 → LUT 生成(可选) → 逐像素单次遍历(调整+统计) → ImageData 写回 → Canvas putImageData → toBlob 导出`
4. **性能优先**：大图(>2MP)预览降采样到显示分辨率，导出时全分辨率后台处理；Web Worker 异步处理直方图/CLAHE；掩膜缓存
5. **实时预览 60fps**：所有滑块拖动使用 requestAnimationFrame 节流，选区编辑时叠加层与像素渲染分离
6. **颜色空间正确性**：对比度/饱和度/白平衡/暗角等操作在合适的颜色空间执行（HSL/Lab/亮度通道），避免色相偏移
7. **参数范围约束**：所有滑块有明确物理/数学范围限制，极端值有保护（clamp/soft clip/降级）

## 二、基础调整

### 2.1 亮度对比度 (224)

**核心算法**：
- 亮度使用加性调整：`newPixel = pixel + brightness`，范围 -100~100（对应 -255~255 像素值变化）
- 对比度以中灰 128 为中心乘性调整：`newPixel = (pixel - 128) * contrast + 128`，范围 0.5~2.0
- 两者组合：`newPixel = clamp((pixel - 128) * contrast + 128 + brightness, 0, 255)`

**设计决策记录**：
- D-01 像素调整方式选择 ImageData 逐像素（而非 CSS filter 或 Canvas filter）：CSS filter 无法导出、无法获取直方图；Canvas filter 虽 GPU 加速但无法提取直方图且不兼容曲线调整。ImageData 方案在 1080p 下仅需 2-5ms，直方图可在同次遍历中附带计算（零额外开销）
- D-02 直方图使用渲染时附带计算（一次遍历完成调整+统计）：调整时必须遍历所有像素，直方图计算也需要遍历所有像素，两者合并在同次遍历中完成，仅增加 4 次 `Uint32Array[value]++` 操作（R/G/B/Luma），额外开销可忽略
- D-03 曲线调节选择 Catmull-Rom 样条：贝塞尔曲线控制点不在曲线上不直观，分段线性产生折线拐点不自然。Catmull-Rom 保证曲线通过用户放置的每一个控制点，C1 连续，所见即所得
- D-04 分割视图使用 CSS clip-path 叠加两个 Canvas：Canvas 裁剪方案需要额外像素操作（render→clip→render），CSS clip-path 在两个已渲染好的 Canvas 叠加层上仅通过 CSS 属性控制可见区域，GPU 合成层处理，拖拽时仅更新 CSS 变量，不触发重绘或回流

**架构组件**：
- `BrightnessContrastController`：核心控制器，loadImage/applyAdjustments/applyAutoLevels/reset/export
- `HistogramCalculator`：256 级 RGB+Luma 四通道直方图，maxCount 归一化
- `AutoLevelsEngine`：累积直方图 0.5% 和 99.5% 分位点计算，色阶拉伸
- `CurveEngine`：Catmull-Rom 样条 + 256 级 LUT 查表映射
- `CompareViewManager`：CSS clip-path 分割视图，分割线可拖拽

**类型定义**：
```typescript
interface BrightnessContrastParams { brightness: number; contrast: number; }
interface CurvePoint { x: number; y: number; }
interface CurveConfig { enabled: boolean; points: CurvePoint[]; channel: 'rgb'|'red'|'green'|'blue'; }
interface HistogramData { red: Uint32Array; green: Uint32Array; blue: Uint32Array; luma: Uint32Array; maxCount: number; totalPixels: number; }
interface AutoLevelsResult { blackPoint: number; whitePoint: number; applied: boolean; }
```

**预设**：提亮+20、提亮+40、加对比(1.3)、去雾(+10,+1.4)、柔和(+5,0.9)、原始(0,1.0)

**性能**：

|------|---------|-----------|
| 加载+初始直方图 | <30ms | <150ms |
| 亮度/对比度调整+直方图 | <5ms | <30ms |

### 2.2 对比度增强 (256)

**核心算法**：
- 全局直方图均衡：累积分布函数(CDF)拉伸，裁剪两端各 0.5% 像素
- CLAHE 自适应均衡：tileSize=8×8，clipLimit=3.0，分块做直方图均衡+clipLimit 裁剪，双线性插值消除块边界
- 阴影/高光恢复：亮度掩码 + 高斯模糊(半径30px，可调 10-50px)，暗部提亮 + 亮部压暗
- 所有操作仅处理亮度通道(Y = 0.299R + 0.587G + 0.114B)，按比例映射回 RGB 保持色相

**设计决策记录**：
- D-01 选择全局+CLAHE 双模式(非单一算法)：全局直方图均衡适合整体对比度不足，CLAHE 适合局部纹理增强(毛发/草地/织物)，两者可组合
- D-02 阴影/高光使用亮度掩码+高斯模糊(非双边滤波)：双边滤波 O(n*r²) 对 4K 图片需数秒，高斯模糊+亮度掩码在合理半径下光晕可控
- D-03 预览降采样+导出全分辨率：预览降采样到显示分辨率(≤2MP)，CLAHE 在此分辨率 <100ms；导出时全分辨率后台处理
- D-04 前后对比使用滑动对比+并排对比可选：默认滑动对比(拖拽分割线)，最直观；可切换到并排模式适合全景对比

**CLAHE 核心流程**：
```
1. 将图像分割为 tileSize×tileSize 块(默认 8×8)
2. 每块独立做直方图均衡 + clipLimit 裁剪(超出部分均匀分配到所有 bin)
3. 计算每块的 CDF 映射表(256级)
4. 对每个像素，使用其相邻 4 个 tile 的映射表做双线性插值
```

**性能**：
| 操作 | 1920×1080 | 说明 |
|------|-----------|------|
| 直方图分析 | <2ms | O(n) 单次遍历 |
| 全局对比度拉伸 | <5ms | LUT 查表映射 |
| CLAHE 处理 | <80ms | 8×8 tile,256 个分块 |
| 阴影恢复 | <40ms | 高斯模糊占主耗时 |
| 一键全管线 | <150ms | 分析+拉伸+CLAHE+阴影 |
| 降采样预览(800×600) | <50ms | 实时拖动无延迟 |

**文件变更**：histogram-analyzer.ts + clahe-processor.ts + contrast-stretcher.ts + shadow-highlight.ts + auto-enhancer.ts + 3 个 Vue 组件 = ~35KB

### 2.3 饱和度调整 (258)

**核心算法**：
- RGB ↔ HSL 颜色空间转换：标准算法，6 种色相分支，Delta 处理灰度(S=0)
- 全局饱和度：`S' = S * (1 + amount/100)`，-100=黑白，0=原图，+100=双倍
- 自然饱和度：`S' = S + strength * (1-S)² * 0.5`，低饱和度获得更多增强
- 分色饱和度：8 通道(红/橙/黄/绿/青/蓝/紫/洋红)，每个覆盖 45° 色相，相邻 15° 重叠过渡带

**设计决策记录**：
- D-01 选择 HSL 空间(非 HSV)："Saturation=0 灰度，Saturation=1 纯色"与用户直觉一致。HSV 的 S 依赖 Value，降低 S 同时改变感知亮度
- D-02 逆平方加权自然饱和度 `(1-S)²`：n=2 在低饱和度(S=0.2, gain=1+0.64*strength)和高饱和度(S=0.8, gain=1+0.04*strength)之间提供 16 倍增益差，自然保护肤色
- D-03 8 通道 45° 范围 + 15° 过渡：覆盖全部 360°，过渡带做线性交叉淡化避免硬切换色带
- D-04 始终从原始 ImageData 计算：RGB→HSL→RGB 浮点舍入误差约 1/255，增量修改 10 次可能累积到 >3 RGB 值

**色域裁剪警告**：超出 sRGB 色域(R/G/B 负值或 >255)的像素在预览中用红色半透明覆盖层标记，可开关。类似 Lightroom 的"显示高光剪切"。

**性能**：
| 操作 | 1920×1080 |
|------|-----------|
| RGB→HSL 全图 | <12ms |
| HSL→RGB 全图 | <10ms |
| 全管线(含分色+色域检查) | <30ms |
| 降采样预览(800×600) | <8ms |

**文件变更**：color-space.ts + saturation-processor.ts + gamut-checker.ts + saturation-panel.vue + color-wheel.vue + clipping-overlay.vue = ~30KB

### 2.4 白平衡校正 (257)

**核心算法**：
- Gray World：假设场景平均反射率为灰色，`gain = avgGray / avgChannel`，对色彩丰富场景效果好
- White Patch：假设最亮像素为白色，`gain = maxVal / maxChannel`，对有高光场景效果好
- 自动选择：根据色彩方差和亮度分布计算置信度(0~1)，选择高置信度算法，两者都低时混合输出或提示手动调整

**设计决策记录**：
- D-01 Gray World + White Patch 双算法自动选择：GW 在单色场景失效(大面积蓝天/草地)，WP 在暗图失效，两者互补。两次 O(n) 遍历，几乎不影响性能
- D-02 色温→RGB 使用 Tanner Helland 算法：基于黑体辐射 Planckian Locus 近似拟合，分三段(Red: temp≤66/temp>66, Green: 同, Blue: temp≥66/temp≤19/其他)，误差 <1%
- D-03 白点取样 5×5 区域平均(非单像素)：单像素受传感器噪声影响大(偏差 10 RGB 值)，5×5 区域 25 像素平均降低噪声，保持足够空间精度
- D-04 预设光照：日光 5500K/阴天 6500K/阴影 7500K/钨丝灯 3200K/荧光灯 4000K/闪光灯 5500K，场景图标+名称+色温值

**Tanner Helland 算法(Kelvin→RGB)**：
```typescript
// 简化公式（完整版见源码）
temp = kelvin / 100
// Red:   temp≤66 → 255, temp>66 → 329.698727446 * (temp-60)^(-0.1332047592)
// Green: temp≤66 → 99.4708025861*ln(temp) - 161.1195681661, temp>66 → 288.1221695283 * (temp-60)^(-0.0755148492)
// Blue:  temp≥66 → 255, temp≤19 → 0, 其他 → 138.5177312231*ln(temp-10) - 305.0447927307
```

**性能**：自动白平衡 1080p < 10ms（两次 O(n) 遍历）；色温滑块预览 < 10ms（仅增益应用）

**文件变更**：white-balance.ts + kelvin-rgb.ts + white-point-sampler.ts + apply-gains.ts + white-balance-panel.vue + kelvin-slider.vue + white-point-cursor.vue = ~28KB

### 2.5 色温色调 (272)

**核心算法**：预计算 2000K-10000K LUT（100K 步进，共 81 档），每档存储归一化 RGB 增益（G=1 基准）。运行时线性插值查表。色调通过 tint 参数(-100~+100)影响 RGB 增益实现品红-绿轴调整。

**设计决策记录**：
- D-01 Tanner Helland 近似算法：2000K-10000K 使用范围内精度 <1%，无需 CIE XYZ 矩阵转换，计算量极小
- D-02 G 通道归一化基准：Bayer 传感器中 G 通道信噪比最高，作为基准最小化噪点放大，与人眼对亮度敏感特性一致（G 贡献 59% 亮度）
- D-03 色温范围 2000K-10000K：覆盖烛光/日出到蓝天/深阴影，超出范围在摄影中极少出现
- D-04 6 标准预设 + 10 用户自定义：日光(5500K)/阴天(6500K,tint+10)/阴影(7500K,tint+10)/钨丝灯(2850K)/荧光灯(4000K,tint-20)/闪光灯(5500K)，chrome.storage 持久化
- D-05 自动白平衡使用 Gray World + 增益反推开尔文：遍历 81 项 LUT 找最接近匹配，查找 <0.5ms

**色调实现**：
```
品红(+tint): finalRGain *= (1 + tint*0.3/100), finalGGain *= (1 - tint*0.2/100), finalBGain *= (1 + tint*0.3/100)
绿色(-tint): 反向操作
G 通道作为归一化基准 = 1.0，R 和 B 增益相对 G 计算
```

**性能**：LUT 查表 <0.01ms；逐像素增益 1080p <3ms；AWB <3ms；总内存 ~4KB(LUT+预设)

**文件变更**：white-balance-engine.ts(重写) + wb-presets.ts + wb-panel.vue = ~20KB

### 2.6 色阶调整 (268)

**核心算法**：输入/输出色阶 + 伽马中间调，256 级 LUT 映射。
```
公式: output = outputBlack + (outputWhite - outputBlack) * ((input - inputBlack) / (inputWhite - inputBlack)) ^ (1/gamma)
```

**设计决策记录**：
- D-01 LUT 映射默认方案 + WebGL Shader 可选降级：256 级 LUT 对 8-bit 图片精度足够，性能敏感场景使用 WebGL Shader，不支持 WebGL 时回退到 LUT
- D-02 直方图使用 Web Worker 全分辨率计算：大图(4000px)直方图耗时 >100ms，Worker 异步处理不阻塞主线程；Worker 不可用时降采样到 2000px 等效
- D-03 滑块直方图叠加 + 数值输入双同步：黑场/白场/中间调滑块直接渲染在直方图上，同时提供精确数值输入框
- D-04 自动色阶使用自适应裁剪(默认 0.1%)：与 Photoshop 一致，对 12MP 图片约 12000 像素被裁剪，足够排除噪点
- D-05 伽马滑块使用对数刻度：伽马 0.5(变亮)和 2.0(变暗)在视觉上对称，对数刻度使滑块在 1.0 两侧对称分布
- D-06 RGB 三通道独立 LUT + RGB 复合通道可切换：默认 RGB 复合(三通道联动)降低门槛，专业用户可切换到独立通道修正偏色

### 2.7 曲线调整 (259)

**核心算法**：Catmull-Rom 样条插值生成 256 级 LUT，控制点驱动任意非线性色调映射。默认调整亮度通道(Luminance)，可选 R/G/B 分通道独立曲线。

**Catmull-Rom 插值公式**：
```
给定 4 个控制点 P0,P1,P2,P3，参数 t∈[0,1]：
y = 0.5 * ((2*P1.y) + (-P0.y+P2.y)*t + (2*P0.y-5*P1.y+4*P2.y-P3.y)*t² + (-P0.y+3*P1.y-3*P2.y+P3.y)*t³)
```

**设计决策记录**：
- D-01 Catmull-Rom 样条(非贝塞尔)：贝塞尔曲线控制点不一定在曲线上，用户直觉"我点的点应该在曲线上"。Catmull-Rom 通过所有控制点，C1 连续，与 Photoshop/GIMP 默认曲线工具算法一致
- D-02 256 级 LUT 预计算+查表：LUT 生成仅 256 次 Catmull-Rom 插值(<0.5ms)，应用时 O(n) Uint8Array 索引(1080p <5ms)。逐像素插值需每像素计算 Catmull-Rom，1080p 约 15ms，差异 3x
- D-03 默认亮度通道曲线(非直接 RGB)：对 R/G/B 三通道分别应用同一曲线会导致色相偏移(改变 RGB 比例)。亮度通道(Y=0.299R+0.587G+0.114B)保持色相和饱和度不变，与 Lightroom"参数曲线"一致
- D-04 8 个内置预设：线性/S 曲线/交叉冲印/褪色/反转片/提亮阴影/压暗高光/扁平。预设也是教学工具：加载预设后观察控制点布局，学习"如何放置控制点"

**曲线编辑器 UI**：
- 256×256 Canvas 渲染
- 背景：2×2 灰度棋盘格(辅助观察亮度)
- 半透明直方图叠加(灰色填充)
- 分区着色：阴影(左下 85×85)和高光(右上 85×85)半透明标记

- Catmull-Rom 样条曲线(蓝色 2px)
- 控制点：白色圆点+蓝色描边，可拖拽/双击删除/空白处点击添加
- 端点(0,0)和(255,255)不可删除

**预设曲线库**：

| 线性 | [(0,0),(255,255)] | 恢复默认 |
| S 曲线 | [(0,0),(64,48),(192,207),(255,255)] | 增强对比度 |

## 三、高级调整

### 3.1 曝光调整 (269)

**核心算法**：
- EV 补偿：`pixel * 2^EV`，EV ∈ [-5.0, +5.0]，步进 0.01
- Soft Clip：在阈值(默认 0.9)以上使用二次衰减 `1 - (excess/maxExcess)² * 0.5`，避免硬裁剪造成的色相偏移
- 高光恢复：亮度压缩 S 曲线 `compressed = threshold + (1-threshold) * normalized / (normalized + (1-normalized)*(1+factor))`
- 阴影填充：自适应增益 `1 + shadowStrength * (1 - luminance/0.5) * 2`，仅暗部(lum<0.5)生效
- 阴影降噪：3×3 中值滤波，仅暗部(lum/255 < 0.3)应用

**设计决策记录**：
- D-01 EV 补偿使用幂律变换 + Soft Clip：`pixel * 2^EV` 是摄影曝光的物理模型，Soft Clip 解决极端 EV 值的硬裁剪，与 Lightroom 行为一致
- D-02 高光恢复：通道重建(1-2 通道裁剪) + 亮度压缩(3 通道全裁剪)混合策略
- D-03 包围曝光 1 EV 步进可配置：5 档预览覆盖 -2 到 +2 EV，提供 1/3, 1/2, 1, 2 EV 选项
- D-04 降噪 3×3 中值滤波：仅暗部(lum<0.3)应用，边缘像素跳过(不扩展边界)

**包围曝光预览**：生成 5 张不同 EV 的缩略图（-2/-1/0/+1/+2），点击任一缩略图将 EV 设为对应值。

**Soft Clip 公式**：
```typescript
if (value <= threshold) return value;
const excess = value - threshold;
const compressed = threshold + excess * (1 - Math.pow(excess / (1.0-threshold), 2) * 0.5);
return Math.min(compressed, 1.0);
```

**性能**：三参数合并遍历 1080p <5ms；中值滤波降噪 <8ms；包围曝光 5 张 200px <10ms

**文件变更**：exposure-engine.ts + exposure-panel.vue + bracketing-preview.vue = ~20KB

### 3.2 自然饱和度 (270)

**核心算法**：
- Adobe-style Vibrance：`gain = 1 + vibrance_amount * (1 - saturation)²`
- 肤色保护：HSV 范围 H[6°,38°], S[0.15,0.75], V[0.3,0.95]；肤色区域增益衰减到 30%
- 深色皮肤亮度自适应：lum < 0.4 时放宽饱和度下限到 0.08
- 逐色增强：6 色(红 0°/橙 30°/黄 60°/绿 120°/蓝 240°/紫 285°) + 高斯权重重叠(sigma=25°)

**设计决策记录**：
- D-01 肤色保护增益衰减 70%：Adobe Lightroom Vibrance 对肤色保护约 70-80%即增益×0.2-0.3。完全保护会使肤色与周围颜色不协调，30% 增益允许微弱增强保持整体一致性
- D-02 非线性指数 n=2：n=2 在低/高饱和度间提供 16 倍增益差。n=3 增益差过大(64 倍)导致低饱和区域过度增强
- D-03 固定 HSV 肤色范围 + 亮度自适应：无需 ML 依赖，覆盖浅色到深色皮肤
- D-04 HSL 色彩空间：与完整饱和度调整(258)保持一致，灰度像素(S=0)跳过所有调整

**肤色检测条件**：
```
H ∈ [6°, 38°]
S ∈ [0.15, 0.75]（深色皮肤: lum<0.4→S>0.08）
V ∈ [0.30, 0.95]
```

**逐色高斯权重**：
```typescript
const sigma = 25; // 高斯标准差
weight = exp(-(angleDiff²) / (2*sigma²)); // 色相环360°环绕距离
// 6 个颜色中心插值加权平均
```

**性能**：全图处理 1080p(Worker) <25ms；灰度像素跳过节省约 15%；6 色滑块预览 <16ms（LUT 缓存逐色增益）

**文件变更**：vibrance-engine.ts + vibrance-panel.vue + vibrance-worker.ts = ~22KB

### 3.3 去雾工具 (271)

**核心算法**：
- 大气散射模型：`J = (I - A) / max(t, t0) + A`（I:雾图, J:清晰图, A:大气光, t:透射率, t0:最小透射率 0.1）
- 简化模型：`t = 1 - dehazeStrength * minChannel / max(A)`（无暗通道）
- 完整 DCP：暗通道 15×15 最小值滤波 → `t = 1 - omega * darkChannel/255`，omega=0.95
- 大气光估计：取暗通道 Top 0.1% 最亮像素在原图中的最大值，限制在上半部(天空区域)
- 清晰度 Clarity：大半径(~50px) Box Blur ×3 近似高斯模糊，USM 差值 + 中间调抛物线 mask
- 纹理 Texture：小半径(~3px) USM 增强表面细节，不应用中间调 mask

**设计决策记录**：
- D-01 简化大气散射 + DCP 可选：默认简化模型(性能好)，高级模式启用完整 DCP
- D-02 暗通道 Patch 15×15（DCP 原论文推荐）：更大 patch 去雾更强但光晕更明显，更小 patch 保留边缘但去雾不足
- D-03 最小透射率 t0=0.1（DCP 论文推荐）：t0 越小恢复越强但噪点越多，0.1 在保留远景细节和抑制噪点间平衡
- D-04 清晰度中间调 mask = `1 - (2*L-1)²`（抛物线）：中间灰度附近权重最大，高光和阴影抑制，模拟 Lightroom Clarity
- D-05 处理顺序：先去雾后清晰度（清晰度在恢复的图片上优化纹理）
- D-06 Box Blur ×3 近似高斯模糊：比真正的 2D 高斯模糊快 3-5 倍，效果差异肉眼不可见

**饱和度补偿**：`comp = 1 - dehazeStrength * 0.3`，去雾越强饱和度补偿越多（因去雾本身增加感知饱和度）

**性能**：
| 操作 | 1080p | 说明 |
|------|-------|------|
| 暗通道 15×15 | ~30ms | 每像素 225 次比较 |
| 大气光估计 | ~35ms | 暗通道 + Top 0.1% 排序 |
| 简化去雾 | ~8ms | 仅散射公式 |
| 完整 DCP | ~65ms | 暗通道+大气光+散射 |
| 清晰度 Box Blur ×3(50px) | ~25ms | 3 次 O(n) 水平+垂直 |
| 纹理 Box Blur ×3(3px) | ~3ms | 小半径 |

**文件变更**：dehaze-engine.ts + clarity-engine.ts + dehaze-panel.vue + dehaze-worker.ts = ~30KB

### 3.4 暗角效果 (273)

**核心算法**：
- 椭圆形暗角掩膜：椭圆方程 `sqrt(dx²/a² + dy²/b²)`，圆度(Roundness)控制长宽比 `a/b = 1 + roundness/100`
- Smoothstep 羽化：`smoothstep(edge0, edge1, t) = t² * (3 - 2t)`，S 形曲线两端斜率趋近于 0
- 中点(Midpoint)偏移：`(dist - midOffset) / (1 - midOffset)`，控制暗角起始位置
- 高光优先模式：亮度 L = 0.2126R + 0.7152G + 0.0722B，仅降低 L 通道，保持 RGB 色彩比例(R/L, G/L, B/L)
- L³ 保护函数：`highlightFactor = 1 - highlightProtection * L³`，保护集中在极高光(L>0.7)

**设计决策记录**：
- D-01 高光优先为默认模式：与 Lightroom 4+ 一致，对含有天空/灯光等明亮边缘的照片最自然
- D-02 椭圆方程 `sqrt(x²/a² + y²/b²)`：计算简单高效，圆度参数直接控制长宽比
- D-03 L³ 保护函数：三次函数使保护主要集中在 L>0.7，对 L=0.5 的中亮像素保护很弱，避免误保护
- D-04 掩膜缓存：仅 Feather/Roundness/Midpoint/尺寸变化时重建(1080p <5ms)，强度和模式变化命中缓存(<6ms 应用)
- D-05 黑色暗角(压暗边缘 95% 场景) + 白色暗角(提亮边缘模拟漏光)

**掩膜参数映射**：
| 参数 | 范围 | 默认 | 说明 |
|------|------|------|------|
| Amount | -100~+100 | 0 | 负=黑色暗角，正=白色暗角 |
| Feather | 0~100 | 50 | 0=硬边，100=从中心开始过渡 |
| Roundness | -100~+100 | 0 | 负=水平椭圆，正=垂直椭圆，0=正圆 |
| Midpoint | 0~100 | 50 | 0=靠近中心，100=靠近边缘 |

**性能**：

|------|-------|

### 3.5 径向滤镜 (274)

**核心算法**：
- 椭圆选区：计算像素到椭圆边界的符号距离(梯度近似)，smoothstep 羽化
- 渐变直线选区：计算像素到渐变线的垂直距离(叉积)，smoothstep 羽化
- 内/外独立参数：innerParams 和 outerParams 各含 brightness/contrast/saturation
- 多滤镜叠层：顺序应用(滤镜 2 基于滤镜 1 的输出)，模拟 Photoshop 图层模型
- 归一化坐标(0~1比例)：选区位置独立于显示/缩放尺寸

**设计决策记录**：
- D-01 椭圆+渐变直线双型：覆盖 95% 局部调整场景，共用同一蒙版计算管线(仅距离计算函数不同)
- D-02 内/外独立调整：最常用场景"内部提亮主体+外部压暗背景"必需，若仅单侧需创建两个滤镜
- D-03 smoothstep 羽化(非高斯模糊)：GPU 着色器标准羽化函数，S 形曲线在两端斜率趋近于 0，视觉自然
- D-04 顺序应用(非权重平均)：模拟真实光学滤镜叠加，滤镜 2 基于滤镜 1 的输出而非原始图片
- D-05 选区叠加层与像素渲染层分离：拖拽时仅更新线框(<2ms/帧)，松手后触发像素渲染(<40ms)

**椭圆距离计算**：
```typescript
// 将像素转换到椭圆本地坐标系(反向旋转)
lx = dx*cos(-rotation) - dy*sin(-rotation)
ly = dx*sin(-rotation) + dy*cos(-rotation)
// 椭圆方程: (lx/rx)² + (ly/ry)² = 1
eq = (lx²)/(rx²) + (ly²)/(ry²)
// 梯度近似距离
distPixels = sqrt((lx-lx/√eq)² + (ly-ly/√eq)²) / max(rx,ry)
// 正数=内部，负数=外部
return eq<=1 ? distPixels : -distPixels
```

| 操作 | 1080p | 4K |
|------|-------|-----|
| 单滤镜蒙版计算 | <5ms | <25ms |
| 单滤镜像素混合 | <5ms | <25ms |
| 3 滤镜叠加 | <20ms | <100ms |
| 5 滤镜叠加 | <35ms | <180ms |
| 选区拖拽(仅线框) | <2ms | <5ms |

**文件变更**：types.ts(3KB) + FeatherCalculator.ts(5KB) + RadialFilterRenderer.ts(6KB) + 4 个 Vue 组件(10KB) + useRadialFilter.ts(2KB) = ~26KB

### 4.1 裁剪工具 (206)

**核心能力**：拖拽裁剪框、宽高比预设(1:1/4:3/16:9/自由)、旋转(90°/翻转)、缩放控制、圆角/圆形裁剪输出、实时预览。

- D-04 导出前实时预览裁剪区域尺寸和文件大小预估

**架构组件**：CropBox(拖拽交互+宽高比锁定+把手渲染)、CropRenderer(Canvas 九参数 drawImage）、CropExporter(PNG透明/JPEG填充导出)

**文件变更**：CropBox.ts + CropRenderer.ts + CropExporter.ts + CropTool.vue = ~10KB

### 4.2 旋转工具 (225)

**核心能力**：90°/180°/270° 快速旋转按钮（累积角度模式）、自由角度滑块(-45°~45°, 0.1° 精度)、拉直工具(用户手动画参考线 → atan2 计算角度 → 自动旋转)、旋转后自动裁剪空白区域（最大内接矩形）。

**背景与现状**：旋转是第二常用的图片操作。手机拍摄方向错误是最常见场景。Canvas `ctx.rotate()` 一行代码实现旋转，但旋转后的裁剪、居中、背景填充需大量代码。

**设计决策记录**：
- D-01 90° 倍数使用 Canvas rotate + drawImage（非维度交换）：GPU 加速，GPU 重采样质量极高，视觉无损
- D-02 外接矩形渲染 + 可选自动裁剪：`newW = w*|cosθ| + h*|sinθ|`, `newH = w*|sinθ| + h*|cosθ|`，默认自动裁剪开启
- D-03 拉直工具手动画线（非霍夫变换）：霍夫变换+Canny边缘检测远超0.2d预算。`atan2(y2-y1, x2-x1)` ≈ 30行代码
- D-04 PNG 透明 + JPEG 可选背景色：JPEG 不支持 alpha 通道，旋转后空白区域需填充
- D-05 快速旋转使用累积角度模式：点两次"右转90°" = 180°

**最大内接矩形公式**：
```
angle % 90 === 0 → 跳过（无需裁剪）
否则: iw = (w·cos - h·sin) / (cos² - sin²), ih = (h·cos - w·sin) / (cos² - sin²)
```

**架构组件**：RotationController(角度状态+渲染)、QuickRotateEngine(90°/180°/270°)、FreeAngleEngine(外接矩形+三角函数)、AutoCropEngine(最大内接矩形+drawImage裁剪)、StraightenTool(Canvas拖拽画线+atan2)

**性能**：90°快速<3ms；自由角度1080p<50ms；自动裁剪<10ms

**文件变更**：types.ts(2KB) + RotationController.ts(5KB) + 4 Vue组件(7KB) + useImageRotate.ts(2KB) = ~16KB

### 4.3 镜像翻转 (223)

**核心能力**：水平翻转(左右镜像)、垂直翻转(上下镜像)、180° 旋转、EXIF Orientation 正确处理（先"取消"浏览器自动旋转再应用用户翻转）。

**背景与现状**：前置摄像头自拍默认镜像（文字左右颠倒）、扫描文档颠倒。CSS `transform: scaleX(-1)` 可视觉翻转但无法导出。

**设计决策记录**：
- D-01 Canvas scale + translate 补偿：水平翻转后 X 轴反转，需 `ctx.translate(-width, 0)` 移回可见区域
- D-02 EXIF Orientation 三步处理：(1)读取标签 (2)反向旋转"取消"浏览器旋转 (3)应用用户翻转
- D-03 180° = 水平+垂直，结果等价
- D-04 翻转不改变 Canvas 尺寸（不同于自由角度旋转）

**架构组件**：FlipController(水平/垂直/180° Canvas scale变换+translate补偿+EXIF反处理)

**性能**：所有翻转 1080p <5ms（纯GPU Canvas变换，无像素遍历）

### 4.4 尺寸调整 (210)

**核心能力**：像素模式(输入目标宽高)、百分比模式(10%-200% 滑块)、预设模式(24 种预设分 5 类)、宽高比锁定(默认锁定可解锁)、阶梯缩放(缩小>50%时)、批量调整+ZIP 下载。

**背景与现状**：各平台对图片尺寸有严格要求（Instagram 1080×1080, Twitter 1200×675等），手动计算耗时。预设尺寸是最有价值的功能。

**24 种预设尺寸**：

| 分类 | 数量 | 示例 |
|------|------|------|
| 社交媒体 | 8 | Instagram帖子1080×1080/快拍1080×1920, Twitter 1200×675, LinkedIn 1200×627, Facebook 1200×630, 微信朋友圈1080×1080, YouTube缩略图1280×720, B站封面1146×717 |
| 缩略图 | 3 | 300×200, 400×300, 800×600 |
| 图标 | 6 | 16×16, 32×32, 48×48, 128×128, 256×256, 512×512 |
| 证件照 | 2 | 一寸295×413(25×35mm@300dpi), 二寸413×579(35×49mm@300dpi) |
| 通用 | 3 | 720p 1280×720, 1080p 1920×1080, 4K 3840×2160 |

**设计决策记录**：
- D-01 三模式(像素+百分比+预设)：预设价值最高——一键选择常用尺寸
- D-02 宽高比默认锁定可解锁：90%场景需保持宽高比
- D-03 阶梯缩放(缩小>50%时)：每次缩小50%直到接近目标→最后精确缩放。理论优势：高频信息在每步50%缩小中保留
- D-04 放大上限200%：Canvas插值无法恢复细节，超出提示"建议使用专业工具"
- D-05 适配模式 contain/cover/fill/exact
- D-06 批量串行+requestAnimationFrame让出主线程：每张之间 `await new Promise(r => requestAnimationFrame(r))`

**阶梯缩放算法**：
```
while (currentW/2 > targetW && currentH/2 > targetH):
  currentW = floor(currentW/2), currentH = floor(currentH/2)
  halfCanvas.drawImage(currentCanvas, 0, 0, currentW, currentH) // 每次50%
finalCanvas.drawImage(halfCanvas, 0, 0, targetW, targetH) // 最后精确缩放
```

**性能**：缩小50%<55ms；阶梯缩放(4K→200px)<110ms；批量10张<1s

**文件变更**：types.ts(6KB) + ResizeEngine.ts(4KB) + AspectRatioCalculator.ts(2KB) + 5Vue(10KB) + useImageResizer.ts(2KB) = ~25KB

### 4.5 圆角工具 (220)

**核心能力**：独立四角半径控制(tl/tr/br/bl)、圆形/椭圆一键转换、实时预览、透明 PNG 导出（不可用 JPEG）。

**背景与现状**：圆角是最常用的图片美化操作。CSS `border-radius` 在网页中简单，但导出需 Canvas `clip()`。头像需要圆形，社交媒体卡片需要圆角矩形。

**设计决策记录**：

- D-05 半径预设 4/8/12/16/24px

**架构组件**：RoundCornerRenderer(Path2D roundRect + clip + drawImage + toBlob PNG)

**性能**：圆角渲染 1080p <5ms（纯 Canvas GPU 路径裁剪）

**文件变更**：RoundCornerRenderer.ts + RoundCornerTool.vue = ~8KB

## 五、装饰

### 5.1 边框添加 (222)

**核心能力**：边框宽度(1-50px)/颜色/样式(实线 solid/虚线 dash/点线 dot)、内外边框模式、阴影效果(shadowBlur/shadowOffset/shadowColor)、内边距、圆角边框选项。

**背景与现状**：边框添加是最常用的图片美化手段之一。CSS `border` 在网页中很简单，但在图片编辑中需要 Canvas 绘制。当前外部工具仅支持实线边框，缺少虚线/阴影。

**设计决策记录**：
- D-01 外边框模式扩大画布、内边框模式覆盖边缘：`newW = originalW + (borderWidth + padding) * 2`（外框）
- D-02 虚线使用 `ctx.setLineDash([dashLength, gapLength])`
- D-03 阴影使用 Canvas `ctx.shadowBlur/shadowColor/shadowOffset`
- D-04 绘制顺序：阴影(最底层) → 边框 → 内边距区域填充 → 图片(最上层)
- D-05 圆角边框复用圆角工具(220)的 roundRect 路径：边框路径 = roundRect 路径，仅用 stroke 而非 clip

**架构组件**：BorderRenderer(边框计算+setLineDash+shadow+roundRect路径绘制)

### 5.2 透明度调整 (221)

**核心能力**：全局透明度滑块(0%-100%)、透明背景创建(JPEG→透明PNG)、渐变透明度(线性/径向方向可控)、棋盘格预览、强制 PNG 导出。

**背景与现状**：透明度调整用于水印、叠加层、UI 元素。CSS `opacity` 仅视觉不可导出。JPEG 无 alpha 通道，需先"创建"透明背景。

**设计决策记录**：
- D-01 全局透明度：`ctx.globalAlpha` 或 ImageData alpha 通道逐像素修改
- D-02 JPEG→透明PNG：绘制到 Canvas → 背景色像素设置 alpha=0
- D-03 渐变透明度：根据像素位置(线性: px/w, 径向: sqrt((dx/cx)²+(dy/cy)²))计算 alpha mask
- D-04 棋盘格背景(CSS `background-image` 或第二层 Canvas)用于预览透明程度
- D-05 强制 PNG 导出：JPEG 无 alpha，透明区域变黑
- D-06 透明度预设 25%/50%/75%

**架构组件**：TransparencyController(全局/渐变alpha操作+棋盘格预览+PNG导出)

### 5.3 添加箭头 (236)

**核心能力**：箭头样式(直线/曲线/双箭头)、颜色尺寸可配、文字标签附着、撤销重做、标注图片导出（不含选区叠加层）。

**背景与现状**：箭头标注是图片标注的原子操作。用户截图后想用箭头指出按钮、菜单、错误信息——但当前 YiPet 完全无此能力。Canvas 上的箭头涉及几何计算(三角形顶点旋转)、交互状态管理(拖拽创建/选中编辑)和渲染优化(抗锯齿)。

**设计决策记录**：
- D-01 箭头三角形：atan2 计算线条末端方向角 → 旋转三角形三个顶点 → 绘制三角形(填充色+描边)
- D-02 曲线箭头：三次贝塞尔曲线 `ctx.bezierCurveTo(cp1x,cp1y, cp2x,cp2y, ex,ey)`，两个控制点可拖拽调整曲率
- D-03 文字标签：定位在起点/中点/终点(用户可选)，自动偏移避开箭头线(沿法线方向偏移)
- D-04 撤销/重做：状态栈模式——每个操作(创建/移动/修改/删除)JSON序列化入栈，撤销=pop+应用前一状态
- D-05 多箭头共存：点击选中(判断当前坐标到所有箭头线段的距离 < 8px)、拖拽移动、双击编辑属性
- D-06 导出标注图片：toBlob 前将箭头绘制层合成到图片 Canvas 上

**箭头三角形几何**：
```typescript
angle = atan2(endY-startY, endX-startX)
// 三角形顶点(以end为原点，angle方向为正)
tipR = endX + headLength * cos(angle)    // 不需计算(已在end)
leftX = endX - headLength * cos(angle) + headWidth * cos(angle + PI/2)
leftY = endY - headLength * sin(angle) + headWidth * sin(angle + PI/2)
rightX = endX - headLength * cos(angle) - headWidth * cos(angle + PI/2)
rightY = endY - headLength * sin(angle) - headWidth * sin(angle + PI/2)
// 三角形: (endX,endY), (leftX,leftY), (rightX,rightY)
```

**架构组件**：ArrowDrawer(atan2几何+bezierCurveTo+Canvas绘制)、ArrowStateManager(增删改+JSON序列化撤销栈)、TextLabelRenderer(文字定位+法线偏移+渲染)

## 六、信息查看器

### 6.1 图片信息查看器 (226)

**核心能力**：统一信息仪表盘(尺寸/文件大小/格式/色深/DPI/百万像素)、完整 EXIF 展示(相机/镜头/光圈/快门/ISO/焦距/GPS)、256 级颜色直方图(RGB+Luma)、压缩比计算、一键复制信息(纯文本和Markdown双格式)。

**背景与现状**：聊天中的图片包含大量"隐藏"信息——EXIF相机参数、GPS位置、DPI分辨率——但当前完全不可见。用户需保存文件到本地→右键属性查看，流程断裂。浏览器无原生 EXIF API，需二进制手动解析。

**EXIF 解析架构**：
- 二进制手动解析 JPEG/TIFF/WebP 文件头部（浏览器无原生 EXIF API）
- 支持 GPS 坐标双格式：度分秒（50°53'42.12"N）和十进制（50.895033°）
- DPI/分辨率合并读取：JFIF 头部(APP0标记)有 DPI，EXIF tiff 标签(IFD0)也有——不一致时标注两者的值
- MakerNote(制造商注释)：佳能/尼康/索尼等厂商特定格式，基础支持常见标签
- 图片格式自动检测：JPEG(0xFFD8)、PNG(0x89504E47)、WebP(RIFF...WEBP)、GIF(GIF89a/GIF87a)

**直方图**：复用 224 亮度对比度的 HistogramCalculator，256 级 RGB+Luma 四通道，Canvas 渲染为柱状图

**压缩比计算**：
```
rawSize = width * height * (bitDepth/8) * 3  // 未压缩的RGB像素数据
compressionRatio = rawSize / fileSize
// 例：1080p JPEG 文件 200KB → rawSize=6.22MB → ratio≈31:1
```

**可复制信息格式**：
- 纯文本：`尺寸: 1920×1080 | 大小: 2.3 MB | 格式: JPEG | ISO: 400 | 光圈: f/2.8 | 快门: 1/250s | GPS: 31.2304°N, 121.4737°E`
- Markdown：表格化的完整参数(基本信息表+EXIF表+GPS信息表)，适合粘贴到文档/Issue

**架构组件**：ImageInfoCollector(尺寸/格式/色深/DPI聚合+压缩比)、EXIFParser(完整EXIF+MakerNote+GPS双格式)、HistogramRenderer(256级Canvas柱状图Chart)、InfoClipboard(纯文本/Markdown双格式+系统剪贴板API)

**文件变更**：ImageInfoCollector.ts + EXIFParser.ts + HistogramRenderer.ts + InfoClipboard.ts + ImageInfoViewer.vue = ~18KB

**EXIF 解析**：
- 二进制手动解析(浏览器无原生 EXIF API)
- 支持 GPS 坐标双格式：度分秒(50°53'42.12"N) 和十进制(50.895033°)
- DPI/分辨率合并读取：JFIF 头部(APP0)有 DPI，EXIF tiff 标签(IFD0)也有，不一致时标注

**可复制信息**：
- 纯文本格式：尺寸、大小、格式、色深、ISO、光圈、快门、焦距、GPS
- Markdown 格式：表格化的完整参数，适合粘贴到文档

**架构组件**：ImageInfoCollector(尺寸/格式/色深/DPI 聚合 + 压缩比)、EXIFParser(完整 EXIF + MakerNote + GPS)、HistogramRenderer(256 级 Chart)、InfoClipboard(纯文本/Markdown 格式化 + 复制到系统剪贴板)

## 七、共享架构模式

### 7.1 通用像素处理管线

```
原始 ImageData（仅从原始图片创建一次，后续始终从此读取）
    ↓
参数快照（所有滑块参数合并为单个配置对象，requestAnimationFrame 时快照化）
    ↓
LUT 生成（可选——曲线/色阶/白平衡预计算 256 级映射表，仅参数变化时重建）
    ↓
逐像素单次遍历（合并所有调整：亮度→对比度→饱和度→...，在同一个 for 循环中完成）
    ↓
附带统计（直方图/色域检查等在同次遍历中计算，零额外遍历开销）
    ↓
ImageData 写回 + Canvas putImageData（渲染到预览 Canvas）
    ↓
toBlob 导出（异步，PNG Quality=1.0 或 JPEG Quality=0.92）
```

### 8.4 跨工具处理顺序约定

当多个工具组合使用时，固定管线顺序（前序调整影响后续调整的输入）：

```
白平衡(WB 257/272) → 曝光(EV 269) → 色阶(268) → 曲线(259) → 对比度增强(256) → 饱和度(258) → 自然饱和度(270)
```

此顺序确保：先校正色彩基础(白平衡) → 再调整全局亮度(曝光/色阶) → 然后精细色调映射(曲线) → 然后局部对比度(CLAHE) → 最后调整色彩鲜艳度(饱和度/自然饱和度)

几何变换(裁剪/旋转/翻转/尺寸/圆角)在像素调整前或后进行均可，取决于用户需求。装饰层(边框/箭头)在最后应用。

### 8.5 通用风险评估

| 风险 | 影响工具 | 概率 | 影响 | 缓解措施 |
|------|---------|------|------|----------|
| 4K 图片内存峰值 >200MB | 全部 | 中 | 高 | 预览必降采样到 2K；导出串行处理；大图限制输入 3K |
| 多工具叠加时处理顺序冲突 | 256/257/258/259/269 | 高 | 中 | 固定管线顺序(见 8.4)；始终从原始图重新计算非增量修改 |
| Canvas 8-bit 精度色带(banding) | 259/268/258 | 中 | 中 | 256 级 LUT 对 8-bit 图片精度足够；极端场景加 2px 抖动 |
| Web Worker Transferable 数据传输延迟 | 256/268/270 | 低 | 低 | 使用 Transferable 对象零拷贝(ownership 转移) |
| RGB↔HSL 浮点累积误差 | 258/270 | 中 | 中 | 始终从原始 ImageData 计算(非增量)；每次从 clean 数据重跑管线 |
| 滑块拖动事件洪水(60次/秒) | 全部 | 高 | 低 | requestAnimationFrame 节流，仅取最后一帧值 |
| Canvas toBlob 在不同浏览器行为差异 | 全部导出 | 低 | 中 | 统一 toBlob('image/png') ；避免浏览器特定优化参数 |
| 图片元数据丢失(EXIF/ICC Profile) | 全部导出 | 高 | 低 | EXIF 解析(226)后可选项重新注入；ICC 暂不支持 |

## 十三、代码审查检查清单（通用）

以下为所有工具共享的通用代码审查项：

- [ ] ImageData 始终从原始图片创建——不基于上次处理结果迭代
- [ ] 所有逐像素操作中 clamp 到 [0,255]——使用 Math.round 非 floor
- [ ] 64-bit 浮点 → 8-bit 整数转换使用 Math.round（非截断）
- [ ] Canvas 渲染使用 ctx.save/restore 包裹变换——防止矩阵累积
- [ ] 大图(>2MP)预览路径使用降采样——导出路径使用全分辨率
- [ ] requestAnimationFrame 节流滑块事件——仅取最后一帧值
- [ ] 所有临时 Canvas 在操作完成后 remove()——防止 DOM 游离节点
- [ ] Web Worker 使用 Transferable 对象——零拷贝传输
- [ ] LUT 重建仅在参数变化时触发——参数指纹比对
- [ ] 边界情况：全黑图、全白图、单像素图、单色图处理正确
- [ ] 非方形图片宽高分离计算
- [ ] 导出后 Canvas 状态恢复——不影响后续编辑
- [ ] TypeScript 严格模式——所有 ImageData 索引有类型保护
- [ ] 管线处理顺序固定：WB→曝光→色阶→曲线→对比度→饱和度
- [ ] 颜色空间转换后灰度像素(R=G=B)S保持为0
- [ ] 所有归一化坐标(0~1)使用实际宽高转换
- [ ] 掩膜/缓存失效条件完整（参数/尺寸/裁剪等触发点）
- [ ] Alpha 通道在所有像素操作中保持不变（除非明确调整透明度）
- [ ] 导出格式：有透明区域仅允许PNG，无透明区域可选PNG/JPEG
- [ ] 极端参数值(亮度±100/对比度0.5~2.0/EV±5等)有合理保护
- [ ] 滑块数值与内部参数范围一致（UI显示值与实际计算值对应）

## 十四、统一回滚策略

每个工具的回滚策略遵循三级降级模型：

### 功能级回滚
所有工具均可独立关闭/隐藏入口——不影响其他工具的正常使用。工具面板有重置按钮——一键恢复到原始图片状态。

### 代码级回滚
每个工具的服务层和 UI 层代码独立——删除对应目录和组件即可完全移除。共享模块（直方图分析器、颜色空间转换器、LUT引擎等）仅在被该模块唯一使用者才可删除。
