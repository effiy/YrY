# YP-09-13: 扩展构建优化与代码分割策略 — Vite 配置调优与产物体积控制

> 需求编号：YP-09-13 · 优先级：P2 · 人天：1.0d · 状态：需求已编写
> 依赖：YP-09-08（CDN 资源加载系统）

## 背景

YiPet 作为 Chrome MV3 扩展，代码打包为 `dist/` 目录后由用户本地加载。扩展体积直接影响：
- **Chrome Web Store 审核**：过大体积可能触发人工审核
- **用户加载速度**：`chrome.runtime.getURL` 读取本地文件——体积敏感
- **Content Script 注入延迟**：Content Script JS bundle 在页面加载时同步执行

当前构建配置未充分优化：

| 问题 | 影响 |
|------|------|
| Vue 3.5 + Element Plus 全量打包 | `chat.bundle.js` > 500KB (gzip ~150KB) |
| Content Script 打包了聊天窗口组件 | content script 仅需宠物 overlay——不应包含聊天代码 |
| 无 vendor chunk 分离 | Vue/ElementPlus 与业务代码耦合——每次业务变更用户需重新加载完整 bundle |
| CDN 资源散落 | 已在 YP-09-08 解决——但构建未利用 CDN external |

  └── 业务代码             (~120KB)

## 二、设计决策

### 决策 1：代码分割 — Content Script vs Chat 严格隔离

**选择：Vite 多入口 + manualChunks。** Content Script 仅包含注入逻辑（< 50KB），Chat Window 独立入口（Vue 懒加载）。

### 决策 2：Element Plus 按需导入 — 全量 vs 按需 vs CDN external

| 选项 | 产物体积 | 维护成本 | 加载速度 |
|------|----------|----------|----------|
| 全量导入 (当前) | ~200KB | 低 | 慢 |
| 按需导入 (unplugin-vue-components) | ~80KB | 中 | 中 |
| **CDN external (YP-09-08 结合)** | ~20KB (仅引用) | 中 | 快（CDN 缓存） |

**选择：CDN external + 按需 fallback。** 主要组件通过 CDN 加载（利用浏览器缓存），构建时 external 排除 Vue/ElementPlus/marked。

### 决策 3：构建目标 — ES2020 vs ES2015

**选择：ES2020。** Chrome MV3 最低要求 Chrome 88（支持 ES2020），无需向下转译。节省 polyfill 体积 (~15KB)。

## 三、目标架构

### 3.1 Vite 配置优化

```typescript
// YiPet/vite.config.ts

import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';

export default defineConfig({
  plugins: [vue()],

  build: {
    target: 'es2020',        // Chrome 88+ 原生支持
    minify: 'esbuild',       // 比 terser 快 100×，体积相当
    cssMinify: 'esbuild',
    reportCompressedSize: true,

    rollupOptions: {
      input: {
        background: 'src/background/index.ts',
        content: 'src/content/bootstrap.ts',
        chat: 'src/chat/main.ts',
        popup: 'src/popup/main.ts',
      },
      output: {
        // 1. Vendor chunk — Vue/ElementPlus 独立（CDN 缓存友好）
        manualChunks: {
          'vendor-vue': ['vue', 'pinia'],
          'vendor-ui': ['element-plus'],
          'vendor-markdown': ['marked'],
        },

        // 2. 入口 chunk 命名
        entryFileNames: (chunk) => {
          const names: Record<string, string> = {
            background: 'background.js',
            content: 'content.js',
            chat: 'chat.js',
            popup: 'popup.js',
          };
          return names[chunk.name] ?? '[name].js';
        },
      },
    },

    // 3. 生产环境移除 console/debugger
    terserOptions: undefined,  // esbuild 不支持 terserOptions
  },

  // 4. CDN external — Vue/ElementPlus 从 CDN 加载（YP-09-08）
  resolve: {
    alias: {
      vue: 'vue/dist/vue.runtime.esm-browser.js',
    },
  },
});
```

### 3.2 外置 CDN 依赖（减小 content.js 体积）

```typescript
// vite.config.ts — CDN external 配置
const CDN_EXTERNALS = {
  vue: 'Vue',
  pinia: 'Pinia',
  'element-plus': 'ElementPlus',
  marked: 'marked',
};

// rollupOptions.external
external: Object.keys(CDN_EXTERNALS),

// rollupOptions.output.globals
globals: CDN_EXTERNALS,

// 仅在 chat/popup 入口 external（content/background 不需要）
// 使用 rollup 插件按入口配置 external
```

### 3.3 构建体积预算

```typescript
// vite.config.ts — 体积预算插件
{
  name: 'vite-plugin-size-budget',
  generateBundle(_, bundle) {
    const budgets: Record<string, number> = {
      'content.js': 50_000,     // Content Script ≤ 50KB
      'background.js': 40_000,  // Service Worker ≤ 40KB
      'chat.js': 150_000,       // Chat Window ≤ 150KB (不含 vendor)
      'popup.js': 30_000,       // Popup ≤ 30KB
    };

    for (const [name, budget] of Object.entries(budgets)) {
      const chunk = bundle[name];
      if (chunk && chunk.type === 'chunk') {
        const size = Buffer.byteLength(chunk.code, 'utf-8');
        if (size > budget) {
          this.warn(
            `⚠️ ${name}: ${(size/1024).toFixed(1)}KB 超出预算 ` +
            `${(budget/1024).toFixed(1)}KB (超出 ${(size-budget)/1024:.1f}KB)`
          );
        }
      }
    }
  },
}
```

## 重构后发现的回归问题

| # | 问题 | 发现场景 | 根因 | 修复方式 |
|---|------|---------|------|---------|
| 1 | CDN external 后聊天窗口打开白屏——`Vue is not defined` | 构建时将 `vue` external 排除，但 CDN 脚本加载失败（用户网络不通或 CDN 被屏蔽）→ `chat.js` 执行时 `Vue` 全局变量不存在 | `rollupOptions.external` 仅排除打包但未提供 fallback 机制——CDN 加载失败时无降级方案 | 增加 CDN fallback 检测：`if (typeof Vue === 'undefined')` 时动态创建 `<script>` 标签从本地 fallback 路径加载（`chrome.runtime.getURL('vendor/vue.js')`），同时 `navigator.onLine` 检测网络状态 |
| 2 | `manualChunks` 导致 `content.js` 引用了 `vendor-vue.js`——Content Script 体积未减小 | 将 `vue` 放入 `vendor-vue` chunk 后，`content.js` 的 import 图仍包含对 `MessageBubble` 的引用→Vite 将 `vendor-vue` 作为 `content.js` 的依赖 chunk 打包 | `content/bootstrap.ts` 中存在未被清理的 `import MessageBubble from '@/chat/components/MessageBubble.vue'` 残留引用 | 删除 `content/bootstrap.ts` 中所有指向 `src/chat/` 和 `src/popup/` 的 import，仅保留 `src/content/` 和 `src/shared/` 的引用 |
| 3 | ES2020 target 导致 `?.` 可选链语法在旧版 Chrome 上解析失败 | 目标 ES2020 但 `?.` 是 ES2020 语法——Chrome 88+ 支持但部分企业用户的 Chrome 可能被 IT 策略锁定在更低版本 | 对 `build.target` 的理解偏差——ES2020 包含可选链语法，但 Chrome 80-87 不支持 | 将 `build.target` 改为 `['es2020', 'chrome88']`，让 esbuild 针对 Chrome 88 进行语法降级（保留 ES2020 API 但降级语法） |
| 4 | 体积预算插件在 warning 时不阻断构建——CI 仍通过 | 体积预算发出 `this.warn()` 后 CI 仍返回 exit code 0 → 体积超预算未被发现 | `this.warn()` 在 Rollup 中仅输出警告不改变退出码，需 `this.error()` 才能阻断构建 | 体积预算插件增加 `throwOnOverBudget` 模式，CI 环境变量 `CI=true` 时使用 `this.error()` 阻断构建，本地开发时使用 `this.warn()` |

## 技术债务追踪

| # | 技术债 | 优先级 | 预计人天 | 说明 |
|---|--------|--------|---------|------|
| 1 | `vite-plugin-size-budget` 为自实现插件——缺少 `gzip` 后体积检查（仅检查原始体积） | 中 | 0.25 | CWS 上传的是 zip 压缩包，原始体积和 gzip 体积差异大（如 vendor 代码 gzip 压缩率 60-70%）。应使用 `gzipSize` 检查 gzip 后体积 |
| 2 | CDN external 依赖列表硬编码在 `vite.config.ts` 中——与 `manifest.json` 的 `content_security_policy` 和 CDN 实际可用性不同步 | 中 | 0.25 | 当 CDN URL 变更或新增依赖时，需同时修改 `vite.config.ts`（external 列表）、`manifest.json`（CSP 允许的 script-src）、`src/shared/cdn.ts`（CDN 加载器）三处。理想方案是单一配置源 |
| 3 | `popup.js` 和 `chat.js` 各自独立打包 Vue runtime——未共享 vendor chunk | 低 | 0.25 | Popup 和 Chat 两个入口都需要 Vue/Pinia，但 `manualChunks` 中 `vendor-vue` 生成一个共享 chunk。由于两个入口通过 `chrome.runtime.getURL` 加载独立 HTML 页面，无法共享 chunk。需评估是否将 Vue 完全 CDN external（Popup 和 Chat 都从 CDN 加载） |
| 4 | 构建产物中 `content.js` 仍包含 `src/shared/` 的 `chrome.storage` 工具函数——与 Service Worker 的 `background.js` 重复 | 低 | 0.25 | `shared/` 中的工具函数被 `content.js` 和 `background.js` 各自打包一份——两个入口无法共享 chunk。可考虑将 `shared/` 中仅被 SW 使用的函数移到 `background/` |

## 安全合规

### 安全需求

| 需求 | 实现方式 | 验证方法 |
|------|---------|---------|
| 构建产物不包含 sourcemap 中的源代码路径 | 生产构建 `sourcemap: false`（或 `hidden-sourcemap`），避免泄露开发机文件路径和目录结构 | 检查 `dist/` 目录无 `.map` 文件，或 `.map` 文件仅包含相对路径 |
| CDN 外部依赖使用子资源完整性校验 (SRI) | CDN 加载 `<script>` 标签添加 `integrity="sha384-..."` 属性，确保 CDN 返回的脚本未被篡改 | 构建时计算 CDN 资源的 SHA-384 哈希，写入 `cdn-manifest.json`，运行时校验 |
| `content.js` 不暴露扩展内部 API 到页面全局作用域 | Content Script 运行在隔离世界（`world: 'ISOLATED'`），不能通过 `window` 对象与页面共享变量 | 代码审查：确保 Content Script 无 `window.yipet = ...` 或 `document.__yipet = ...` 赋值 |
| 构建工具链无已知漏洞的依赖 | `npm audit` 或 `pnpm audit` 在 CI 中运行，阻断 `critical`/`high` 级别漏洞的构建 | CI 中 `npm audit --audit-level=high` 返回非零退出码时阻断 |

### 合规检查

| 检查项 | 要求 | 状态 |
|--------|------|------|
| `manifest.json` 声明最小权限 | `permissions` 仅包含 `storage`/`alarms`/`commands`，`host_permissions` 仅包含 YiAi API 域名 | 待验证 |
| Content Script 的 `matches` 不包含 `<all_urls>` | 使用具体域名模式而非 `*://*/*`，CWS 审核要求 | 待实现 |
| 构建产物不包含 `eval()` 或 `new Function()` | MV3 CSP 禁止 `eval`，需确保所有依赖（包括 CDN external 的 Vue/ElementPlus）不使用 eval | 待验证 |
| npm 依赖的许可证合规 | 所有生产依赖（含 CDN external 的库）的许可证为 MIT/Apache-2.0/BSD/ISC——不包含 GPL 系列 | 待验证 |

## 回滚策略

| 回滚场景 | 回滚方式 | 影响范围 | 恢复时间 |
|----------|----------|----------|----------|
| `manualChunks` 配置导致构建失败——chunk 循环依赖或入口缺失 | 移除 `manualChunks` 配置，回退到默认 chunk 策略 | 构建流程 | < 5min |
| CDN external 配置后 Vue/ElementPlus 运行时加载失败 | 回退 external 配置——Vue/ElementPlus 重新打包进业务 chunk | 聊天窗口运行时 | < 5min（构建配置）+ 重新构建 |
| Tree shaking 过度移除——动态 `import()` 的组件被误删 | 在 `sideEffects` 配置中声明保留的副作用文件（CSS/全局注册） | 缺失组件 | < 10min（配置修复） |
| 体积预算 CI 过于严格——正常功能新增被 CI 门禁阻止 | 放宽预算阈值——调整为当前体积 + 20% buffer，或仅对 P0 入口严格 | CI 构建 | < 5min（配置修改） |
| `vite-plugin-dts` 类型生成与 `vue-tsc` 冲突——构建报错但实际产物正确 | 临时分离类型检查与构建流程——`vue-tsc --noEmit` 与构建并行而非串行 | 构建流程 | < 5min |

**回滚验证**：`npm run build` 4 入口全部成功 → `dist/` 产物可正常加载 → 聊天窗口/Popup/Content Script 功能正常 → 体积在预算内。

## 设计决策记录

### D-01: Vite 多入口 + manualChunks 代码分割

**状态**: 已采纳
**背景**: 当前构建将 Vue 3.5 + Element Plus 全量打包进 `chat.js`（520KB gzip 150KB），Content Script 也包含了聊天组件（160KB），导致注入延迟高、产物体积过大。
**决策**: 采用 Vite 多入口（background/content/chat/popup）+ `manualChunks`（vendor-vue/vendor-ui/vendor-markdown）的代码分割策略。Content Script 与 Chat Window 严格隔离，Content Script 仅包含注入逻辑（< 50KB），Chat Window 独立入口。
**理由**: 多入口确保各执行环境仅加载所需代码；manualChunks 将 Vue/ElementPlus/marked 分离为独立 vendor chunk，利用 CDN 缓存减少用户重复加载；Content Script 体积从 160KB 降至 45KB，注入延迟降低 70%。
**影响**: 需在 `content/bootstrap.ts` 中清理所有指向 `src/chat/` 和 `src/popup/` 的 import 残留；Popup 和 Chat 两个入口各自加载 Vue runtime（无法共享 chunk，因独立 HTML 页面）；回归风险：manualChunks 可能导致循环依赖或入口缺失。

### D-02: CDN external + 本地 fallback 双重加载策略

**状态**: 已采纳
**背景**: Element Plus 全量打包占 ~200KB，按需导入仍需 ~80KB。CDN 加载可利用浏览器缓存，但网络不可用时需降级方案。
**决策**: 采用 CDN external 为主 + 本地 fallback 为辅的双重策略。构建时将 Vue/Pinia/ElementPlus/marked 设为 rollup external，运行时从 CDN 加载；若 CDN 加载失败（`typeof Vue === 'undefined'`），动态创建 `<script>` 标签从 `chrome.runtime.getURL('vendor/vue.js')` 加载本地 fallback。
**理由**: CDN external 最大化利用浏览器缓存（用户首次加载后其他扩展/网站可复用），本地 fallback 保证离线可用性。相比纯按需导入（unplugin-vue-components），CDN external 产物体积更小（~20KB 仅引用 vs ~80KB）。
**影响**: 需在 `manifest.json` 的 CSP 中配置 `content_security_policy` 允许 CDN 域名；需维护 CDN URL 与本地 fallback 路径的映射；回归风险：CDN 不可用时 fallback 加载延迟可能导致短暂的 `Vue is not defined` 错误。

### D-03: ES2020 构建目标

**状态**: 已采纳
**背景**: Chrome MV3 最低要求 Chrome 88，原生支持 ES2020 语法（可选链 `?.`、空值合并 `??`、动态 import 等）。向下转译到 ES2015 会引入不必要的 polyfill（~15KB）。
**决策**: 构建目标设为 `['es2020', 'chrome88']`——esbuild 针对 Chrome 88 进行语法降级，保留 ES2020 API 但降级不兼容语法。
**理由**: 节省 ~15KB polyfill 体积；Chrome 88+ 覆盖所有 MV3 用户；`['es2020', 'chrome88']` 组合确保可选链等语法在 Chrome 80-87 上也能运行（虽然 MV3 不支持这些版本，但防御性编程）。
**影响**: 选择 `esbuild` 而非 `terser` 作为 minifier（快 100x，体积相当）；不支持 Chrome 88 以下的浏览器（但 MV3 本身已排除）；回归风险：`build.target` 理解偏差可能导致不兼容语法未正确降级。

### D-04: 体积预算 CI 门禁

**状态**: 已采纳
**背景**: 随着功能迭代，产物体积可能持续膨胀。需要自动化门禁在 CI 中阻断超预算的构建，防止体积退化。
**决策**: 在各入口设置体积预算（content.js 50KB, background.js 40KB, chat.js 150KB, popup 30KB），通过自实现 `vite-plugin-size-budget` 插件在 `generateBundle` 阶段检查。CI 环境（`CI=true`）使用 `this.error()` 阻断构建，本地开发使用 `this.warn()` 仅警告。
**理由**: 体积预算 CI 门禁是防止体积退化的唯一可靠手段——人工审查无法在每次 PR 中检查产物体积。CI 阻断 + 本地警告的分级策略避免影响开发体验。

**影响**: 需区分 SW 的 raw 体积预算与其他入口的 gzip 体积预算（SW 不经过 HTTP 传输）；预算阈值需随功能迭代调整；回归风险：过于严格的预算可能阻止正常功能新增。
