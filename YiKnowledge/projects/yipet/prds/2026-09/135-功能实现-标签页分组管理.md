# YP-09-128: 标签页分组管理 — chrome.tabGroups API、AI 智能分组建议、分组命名着色、保存恢复会话、跨窗口搜索、重复标签检测、内存用量显示、批量操作

> 需求编号：YP-09-128 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YP-09-24（右键菜单集成）、YP-09-31（多标签页同步）、YP-09-119（书签与网页收藏管理）

## 背景

### 问题陈述

YiPet 当前仅作为聊天伴侣存在，未利用 Chrome 扩展的标签页管理能力。用户在浏览过程中积累大量标签页，面临严重的标签页管理问题：

1. **标签页混乱**：用户打开 50+ 标签页后，标签栏拥挤不堪，无法区分不同主题/项目的标签页，查找目标标签页耗时
2. **上下文丢失**：关闭浏览器后，之前分组的标签页无法恢复，用户需要手动重新打开和排列
3. **重复标签页浪费**：用户经常无意中打开多个相同 URL 的标签页（如多个 GitHub Issues 页面），浪费内存和注意力
4. **内存压力**：大量标签页消耗内存，但用户不知道哪些标签页占用最多资源，无法做出关闭决策
5. **跨窗口管理困难**：标签页分散在多个窗口中，用户难以全局搜索和批量操作

**核心矛盾**：在 Chrome 扩展的权限模型下，利用 `chrome.tabs` 和 `chrome.tabGroups` API 实现标签页管理功能，既要提供强大的分组/搜索/批量操作能力，又要最小化权限请求，避免用户因权限过大而拒绝安装。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 50+ 标签页无法高效导航 | 高 | 用户在进行多项目研究时打开大量标签页，标签栏变成小图标，完全无法区分 |
| 2 | 浏览器重启后工作上下文丢失 | 高 | 用户下班关闭浏览器，第二天无法恢复昨天的工作标签页分组 |
| 3 | 重复标签页浪费内存 | 中 | 用户从不同入口打开了 3 个相同的 Jira 页面，占用 3 倍内存 |
| 4 | 无法判断哪些标签页可以关闭 | 中 | 用户想释放内存但不知道哪些标签页占用最大，只能随机关闭 |
| 5 | 标签页分散在多个窗口 | 中 | 用户有 3 个浏览器窗口，想找一个标签页但记不清在哪个窗口 |

### 挑战

| 挑战 | 说明 |
|------|------|
| 权限最小化 | `chrome.tabGroups` 需要 `tabGroups` 权限，需在安装时明确告知用户用途 |
| AI 分组准确度 | AI 根据页面标题/URL 推断分组主题，准确度取决于页面元数据质量 |
| 内存数据获取 | `chrome.processes` API 已废弃，需使用 `chrome.system.memory` 或性能 API 估算 |
| 分组恢复时机 | 保存的标签组恢复时需要处理 URL 失效、页面需要登录等问题 |
| 跨窗口操作 | 标签页移动/分组涉及窗口间通信，需处理异步操作和错误状态 |
| 性能影响 | 标签页搜索和分组操作需要遍历所有标签页（可能 100+），需优化查询性能 |

## 二、设计决策

### 决策 1：管理面板位置 — Popup 面板 vs 独立页面 vs 侧边栏

| 选项 | 空间 | 操作便捷性 | 与标签页交互 | 实现复杂度 |
|------|------|------------|-------------|------------|
| Popup 面板 | 小（300x400） | 高（点击图标即开） | 中（需切换焦点） | 中 |
| 独立标签页（chrome-extension://） | 大 | 中（需切换标签页） | 低（离开当前页面） | 低 |
| 侧边栏（sidePanel API） | 大 | 高（始终可见） | 高（同屏操作） | 高 |

**选择：侧边栏（sidePanel API）为主，Popup 为快捷入口。** Chrome 114+ 支持 `sidePanel` API，侧边栏固定在浏览器左侧，提供完整的标签页管理视图，用户可以同时看到标签页列表和当前浏览页面。Popup 作为快捷入口（显示最近分组和搜索框），点击后打开侧边栏。对于不支持 sidePanel 的旧版本，降级为独立标签页。

### 决策 2：AI 分组策略 — 基于页面内容 vs 基于标题/URL vs 混合方案

| 选项 | 准确度 | 性能 | 隐私 | 实现复杂度 |
|------|--------|------|------|------------|
| 基于页面内容（注入 content script 提取文本） | 高 | 低（需等待页面加载） | 低（读取页面内容） | 高 |
| 基于标题/URL（仅用元数据） | 中 | 高（即时） | 高（不读内容） | 低 |
| 混合方案（标题优先，可选内容分析） | 高 | 中 | 中 | 中 |

**选择：基于标题/URL 为主，可选内容分析。** 默认使用标签页标题和 URL 进行 AI 分组（通过 YiAi 后端），隐私友好且即时。用户可对特定标签页触发"深度分析"（提取页面正文前 500 字），获得更准确的分组建议。90% 的场景下标题和 URL 已足够（如 `github.com` → 开发、`docs.google.com` → 文档）。

### 决策 3：分组保存格式 — 仅 URL 列表 vs 完整快照 vs 混合方案

| 选项 | 恢复效果 | 存储大小 | 隐私 | 实现复杂度 |
|------|----------|----------|------|------------|
| 仅 URL 列表 | 中（需重新加载） | 极小（< 1KB） | 高 | 低 |
| 完整快照（含页面截图和标题） | 好 | 大（每页 > 100KB） | 低 | 高 |
| 混合方案（URL + 标题 + 可选截图） | 好 | 中（每页 < 5KB） | 中 | 中 |

**选择：混合方案。** 保存分组时记录每个标签页的 URL、标题、favicon URL 和分组元数据（名称、颜色、折叠状态）。可选截图功能（默认关闭）供用户手动触发生成缩略图。恢复时打开 URL 并恢复标题作为参考，页面内容由浏览器重新加载。

### 决策 4：重复标签页检测策略 — 精确 URL vs 规范化 URL vs 语义相似度

| 选项 | 准确度 | 性能 | 误报率 | 实现复杂度 |
|------|--------|------|--------|------------|
| 精确 URL 匹配 | 高（但漏掉参数化 URL） | 高 | 低 | 低 |
| 规范化 URL（去参数/去 hash） | 中 | 高 | 中 | 中 |
| 语义相似度（标题 + URL 相似度） | 高 | 中 | 低 | 高 |

**选择：精确 URL + 规范化 URL 双重检测。** 第一轮：精确 URL 匹配（如 `https://example.com/page`），标记为完全重复。第二轮：规范化 URL 匹配（去除 query string 和 hash），标记为疑似重复。例如 `github.com/issues/1` 和 `github.com/issues/1?tab=comments` 被标记为疑似重复。语义相似度方案需要额外的 AI 调用，性价比低。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 管理面板位置 | Popup 面板 | 独立标签页 | 侧边栏 | **侧边栏 + Popup 快捷入口** | 始终可见，操作便捷 |
| AI 分组策略 | 页面内容 | 标题/URL | 混合方案 | **标题/URL 为主** | 隐私友好，即时高效 |
| 分组保存格式 | 仅 URL | 完整快照 | 混合方案 | **URL + 标题 + 元数据** | 体积小，恢复效果好 |
| 重复检测策略 | 精确 URL | 规范化 URL | 语义相似度 | **精确 + 规范化双重检测** | 准确且高效 |

### 3.3 AI 分组建议流程

```
                    ┌──────────────┐
```

```typescript
class TabGroupService {
  /**
   * 获取所有标签页（含分组信息）
   */
  async getAllTabs(): Promise<TabInfo[]> {
    const tabs = await chrome.tabs.query({});
    const groups = await chrome.tabGroups.query({});

    const groupMap = new Map(groups.map(g => [g.id, g]));

    return tabs.map(tab => ({
      id: tab.id!,
      title: tab.title || '无标题',
      url: tab.url || '',
      favIconUrl: tab.favIconUrl || '',
      windowId: tab.windowId,
      groupId: tab.groupId ?? -1,
      active: tab.active,
      audible: tab.audible || false,
      muted: tab.mutedInfo?.muted || false,
      pinned: tab.pinned,
      discarded: tab.discarded,
      lastAccessed: tab.lastAccessed || 0,
      memoryEstimate: this.estimateMemory(tab),
    }));
  }

  /**
   * 创建标签页分组
   */
  async createGroup(tabIds: number[], options: {
    title?: string;
    color?: chrome.tabGroups.ColorEnum;
  }): Promise<number> {
    // 将标签页移动到同一窗口（如果分散在不同窗口）
    const firstTab = await chrome.tabs.get(tabIds[0]);
    for (const tabId of tabIds.slice(1)) {
      await chrome.tabs.move(tabId, {
        windowId: firstTab.windowId,
        index: -1,
      });
    }

    // 创建分组
    const groupId = await chrome.tabs.group({
      tabIds,
      createProperties: { windowId: firstTab.windowId },
    });

    // 设置分组属性
    if (options.title || options.color) {
      await chrome.tabGroups.update(groupId, {
        title: options.title,
        color: options.color,
      });
    }

    return groupId;
  }

  /**
   * 更新分组属性
   */
  async updateGroup(groupId: number, updates: {
    title?: string;
    color?: chrome.tabGroups.ColorEnum;
    collapsed?: boolean;
  }): Promise<void> {
    await chrome.tabGroups.update(groupId, updates);
  }

  /**
   * 取消分组（保留标签页）
   */
  async ungroup(groupId: number): Promise<void> {
    await chrome.tabs.ungroup(groupId);
  }

  /**
   * 将标签页添加到分组
   */
  async addToGroup(tabIds: number[], groupId: number): Promise<void> {
    const group = await chrome.tabGroups.get(groupId);
    for (const tabId of tabIds) {
      await chrome.tabs.move(tabId, { windowId: group.windowId, index: -1 });
    }
    await chrome.tabs.group({ tabIds, groupId });
  }

  /**
   * 从分组中移除标签页
   */
  async removeFromGroup(tabIds: number[]): Promise<void> {
    await chrome.tabs.ungroup(tabIds);
  }

  /**
   * 获取所有分组信息
   */
  async getAllGroups(): Promise<TabGroupInfo[]> {
    const groups = await chrome.tabGroups.query({});
    const tabs = await chrome.tabs.query({});

    return groups.map(group => ({
      id: group.id,
      title: group.title || '未命名分组',
      color: group.color,
      collapsed: group.collapsed,
      tabIds: tabs.filter(t => t.groupId === group.id).map(t => t.id!),
      windowId: group.windowId,
    }));
  }

  /**
   * 估算单个标签页的内存用量
   * chrome.processes API 已废弃，使用启发式估算
   */
  private estimateMemory(tab: chrome.tabs.Tab): number {
    // 基础内存估算（基于页面类型加权）
    let base = 50; // MB

    const url = tab.url || '';

    // 视频/流媒体页面内存更大
    if (/youtube\.com|netflix\.com|bilibili\.com|twitch\.tv/.test(url)) {
      base = 200;
    } else if (/docs\.google\.com|notion\.so|confluence/.test(url)) {
      base = 150; // 富文本编辑器
    } else if (/github\.com|gitlab\.com/.test(url)) {
      base = 80;
    } else if (/twitter\.com|x\.com|reddit\.com/.test(url)) {
      base = 100; // 无限滚动页面
    }

    // 已丢弃的标签页内存占用极低
    if (tab.discarded) {
      base = 5;
    }

    return base;
  }
}
```

### 4.3 重复标签页检测器

```typescript
// src/background/DuplicateDetector.ts (新增)

class DuplicateDetector {
  /**
   * 检测重复标签页
   */
  detectDuplicates(tabs: TabInfo[]): DuplicateGroup[] {
    const duplicates: DuplicateGroup[] = [];
    const seen = new Map<string, TabInfo[]>();

    // 第一轮：精确 URL 匹配
    for (const tab of tabs) {
      const key = tab.url;
      if (!seen.has(key)) {
        seen.set(key, []);
      }
      seen.get(key)!.push(tab);
    }

    for (const [url, tabList] of seen) {
      if (tabList.length > 1) {
        duplicates.push({
          normalizedUrl: url,
          tabs: tabList,
          type: 'exact',
        });
      }
    }

    // 第二轮：规范化 URL 匹配（去除 query string 和 hash）
    const normalized = new Map<string, TabInfo[]>();
    for (const tab of tabs) {
      const normalizedUrl = this.normalizeUrl(tab.url);
      if (!normalized.has(normalizedUrl)) {
        normalized.set(normalizedUrl, []);
      }
      normalized.get(normalizedUrl)!.push(tab);
    }

    for (const [url, tabList] of normalized) {
      if (tabList.length > 1) {
        // 检查是否已被精确匹配覆盖
        const alreadyCovered = duplicates.some(
          d => this.normalizeUrl(d.normalizedUrl) === url && d.type === 'exact'
        );
        if (!alreadyCovered) {
          duplicates.push({
            normalizedUrl: url,
            tabs: tabList,
            type: 'normalized',
          });
        }
      }
    }

    return duplicates;
  }

  /**
   * 规范化 URL（去除 query string 和 hash）
   */
  private normalizeUrl(url: string): string {
    try {
      const parsed = new URL(url);
      parsed.search = '';
      parsed.hash = '';
      return parsed.toString();
    } catch {
      return url;
    }
  }

  /**
   * 关闭重复标签页（保留最近访问的）
   */
  async closeDuplicates(duplicates: DuplicateGroup[]): Promise<number> {
    let closedCount = 0;
    for (const group of duplicates) {
      // 按最后访问时间排序，保留最近的一个
      const sorted = [...group.tabs].sort((a, b) => b.lastAccessed - a.lastAccessed);
      const toClose = sorted.slice(1); // 保留第一个

      for (const tab of toClose) {
        await chrome.tabs.remove(tab.id);
        closedCount++;
      }
    }
    return closedCount;
  }
}
```

```typescript
class AIGroupingService {
  private apiBase = 'http://localhost:10086';

  /**
   * 请求 AI 分组建议
   */
  async suggestGroups(tabs: TabInfo[]): Promise<AIGroupingSuggestion[]> {
    // 构建标签页列表（仅发送标题和域名，保护隐私）
    const tabList = tabs.map(t => ({
      title: t.title,
      domain: this.extractDomain(t.url),
    }));

    const prompt = `你是一个浏览器标签页管理助手。请将以下标签页按主题分组。
每个标签页给出了标题和域名。请返回 JSON 格式的分组建议，每组包含：
- name: 分组名称（中文，简短的，如"开发"、"文档"、"新闻"、"社交"、"购物"）
- color: 建议颜色（"grey", "blue", "red", "yellow", "green", "pink", "purple", "cyan", "orange"）
- domainPatterns: 该分组包含的域名列表

标签页列表:
${tabList.map((t, i) => `${i + 1}. [${t.domain}] ${t.title}`).join('\n')}

请返回 JSON 数组格式（不要包含其他文字）:
[{"name": "...", "color": "...", "domainPatterns": ["..."]}]`;

    const response = await fetch(this.apiBase, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        module_name: 'services.ai.chat_service',
        method_name: 'chat',
        parameters: {
          messages: [{ role: 'user', content: prompt }],
          stream: false,
        },
      }),
    });

    const result = await response.json();
    const aiResponse = result.data?.content || '[]';

    // 解析 AI 返回的 JSON
    const suggestions = this.parseAIResponse(aiResponse, tabs);
    return suggestions;
  }

  /**
   * 解析 AI 返回的分组建议
   */
  private parseAIResponse(
    response: string,
    tabs: TabInfo[]
  ): AIGroupingSuggestion[] {
    try {
      // 提取 JSON（去除可能的 markdown 代码块包装）
      const jsonMatch = response.match(/\[[\s\S]*\]/);
      if (!jsonMatch) return [];

      const rawSuggestions = JSON.parse(jsonMatch[0]);

      return rawSuggestions.map((s: any) => {
        // 将 domainPatterns 匹配到实际的 tabIds
        const matchingTabs = tabs.filter(tab =>
          s.domainPatterns?.some((pattern: string) =>
            tab.url.includes(pattern)
          )
        );

        return {
          name: s.name || '未命名分组',
          color: s.color || 'grey',
          tabIds: matchingTabs.map(t => t.id),
          confidence: matchingTabs.length > 0 ? 0.8 : 0.3,
        };
      });
    } catch {
      console.error('[YiPet] AI 分组建议解析失败');
      return [];
    }
  }

  private extractDomain(url: string): string {
    try {
      return new URL(url).hostname;
    } catch {
      return url;
    }
  }
}
```

```typescript
// src/background/GroupPersistence.ts (新增)

class GroupPersistence {
  private storageKey = 'yipet_saved_groups';

  /**
   * 保存当前所有分组
   */
  async saveAllGroups(): Promise<SavedGroup[]> {
    const tabService = new TabGroupService();
    const groups = await tabService.getAllGroups();
    const allTabs = await tabService.getAllTabs();

    const savedGroups: SavedGroup[] = groups.map(group => ({
      id: this.generateId(),
      name: group.title,
      color: group.color,
      createdAt: Date.now(),
      collapsed: group.collapsed,
      tabs: group.tabIds.map(tabId => {
        const tab = allTabs.find(t => t.id === tabId)!;
        return {
          url: tab.url,
          title: tab.title,
          favIconUrl: tab.favIconUrl,
          savedAt: Date.now(),
        };
      }),
    }));

    await this.saveToStorage(savedGroups);
    return savedGroups;
  }

  /**
   * 获取所有已保存的分组
   */
  async getSavedGroups(): Promise<SavedGroup[]> {
    const result = await chrome.storage.local.get(this.storageKey);
    return result[this.storageKey] || [];
  }

  /**
   * 删除已保存的分组
   */
  async deleteSavedGroup(groupId: string): Promise<void> {
    const groups = await this.getSavedGroups();
    const filtered = groups.filter(g => g.id !== groupId);
    await this.saveToStorage(filtered);
  }

  /**
   * 恢复已保存的分组
   */
  async restoreGroup(groupId: string): Promise<void> {
    const groups = await this.getSavedGroups();
    const group = groups.find(g => g.id === groupId);
    if (!group) throw new Error('未找到保存的分组');

    const tabService = new TabGroupService();

    // 打开所有标签页
    const tabIds: number[] = [];
    for (const savedTab of group.tabs) {
      const tab = await chrome.tabs.create({
        url: savedTab.url,
        active: false,
      });
      if (tab.id) tabIds.push(tab.id);
    }

    // 创建分组
    if (tabIds.length > 0) {
      await tabService.createGroup(tabIds, {
        title: group.name,
        color: group.color,
      });

      if (group.collapsed) {
        // 获取刚创建的分组并折叠
        const tabs = await chrome.tabs.query({});
        const firstTab = tabs.find(t => tabIds.includes(t.id!));
        if (firstTab?.groupId) {
          await chrome.tabGroups.update(firstTab.groupId, { collapsed: true });
        }
      }
    }
  }

  private async saveToStorage(groups: SavedGroup[]): Promise<void> {
    await chrome.storage.local.set({ [this.storageKey]: groups });
  }

  private generateId(): string {
    return crypto.randomUUID();
  }
}
```

**WHEN** 用户点击"AI 智能分组"按钮
**THEN** 系统收集所有标签页的标题和域名，发送到 YiAi 后端
**AND** 侧边栏显示加载动画"AI 分析中..."

## 七、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| `chrome.tabGroups` API 在部分 Chrome 版本不可用 | 低 | 高 | 检测 API 可用性，不可用时隐藏分组功能，仅提供搜索和重复检测 |
| `sidePanel` API 仅 Chrome 114+ 支持 | 中 | 中 | 降级方案：使用独立标签页（`chrome-extension://` 页面）作为管理面板 |
| 用户拒绝 `tabGroups` 权限 | 中 | 高 | 分组功能不可用，但搜索、重复检测、内存显示等不依赖 tabGroups 的功能仍可用 |
| AI 分组建议不准确（分组名称不符合预期） | 中 | 中 | 允许用户预览和调整 AI 建议后再应用，支持手动重命名和调整分组 |
| 恢复分组时 URL 失效（页面已删除或需要登录） | 中 | 中 | 恢复时显示 URL 列表预览，用户可取消失效的 URL，仅恢复可访问的页面 |
| 大量标签页（200+）时侧边栏渲染性能差 | 低 | 中 | 使用虚拟滚动（virtual-scroll）渲染标签页列表，搜索和过滤在前端内存中完成 |

## 八、回滚策略

| 场景 | 回滚操作 | 影响 |
|------|----------|------|
| tabGroups API 导致浏览器异常 | 移除 `tabGroups` 权限，禁用分组功能 | 分组管理不可用，其他功能正常 |
| 侧边栏渲染性能问题 | 降级为 Popup 面板模式（仅显示搜索和基础列表） | 分组卡片的可视化效果丢失 |
| AI 分组建议服务不可用 | 隐藏 AI 分组按钮，仅保留手动分组 | 智能分组不可用，手动分组正常 |
| 分组保存数据损坏 | 清空保存的分组数据，提示用户重新保存 | 历史保存的分组丢失 |
| 批量操作误关闭重要标签页 | 为批量关闭操作提供撤销功能（30s 内可恢复） | 无 |

## 九、设计决策记录

### D-01：管理面板 UI 形式

- **问题**：标签页管理面板使用什么 UI 形式——Popup、独立标签页还是侧边栏
- **选项**：Popup 面板（空间小）、独立标签页（需切换）、侧边栏（sidePanel API）
- **选择**：侧边栏（sidePanel API）为主，Popup 为快捷入口
- **理由**：侧边栏固定在浏览器左侧，提供完整的管理视图，用户可同时查看标签页列表和当前页面。Chrome 114+ 支持，旧版本降级为独立标签页。Popup 提供快捷入口（搜索框 + 最近分组），点击后打开侧边栏。

### D-02：AI 分组数据隐私

- **问题**：AI 分组是否需要发送页面内容到 YiAi 后端
- **选项**：发送完整页面内容、仅发送标题和 URL、不发送任何数据
- **选择**：仅发送标题和域名（不发送完整 URL 路径和页面内容）
- **理由**：标题和域名已足够 AI 判断主题分类（如 `github.com` → 开发、`docs.google.com` → 文档）。不发送完整 URL 保护用户隐私（避免泄露具体文档路径、Issue 编号等）。不发送页面内容避免隐私风险和处理延迟。

### D-03：内存用量估算方法

- **问题**：如何获取标签页的内存用量——使用已废弃的 API 还是估算
- **选项**：`chrome.processes` API（已废弃）、`performance.memory` API（仅 JS 堆）、启发式估算
- **选择**：启发式估算（基于页面类型 + 是否丢弃状态）
- **理由**：`chrome.processes` 在 Chrome 68+ 已废弃不可用。`performance.memory` 仅报告 JS 堆大小，不包含 DOM、图片、Worker 等内存。启发式估算（50-200MB/页，根据页面类型加权）提供相对排序参考，虽不精确但足够用户判断"哪些标签页占用最多"。

### D-04：分组保存的存储策略

- **问题**：保存的分组数据存储在哪里，如何处理容量限制
- **选项**：`chrome.storage.local`、`chrome.storage.sync`、IndexedDB
- **选择**：`chrome.storage.local`（10MB 容量），最多保存 20 个分组快照
- **理由**：每个分组快照约 2-5KB（含 URL、标题、favicon），20 个快照 < 100KB，远低于 10MB 限制。`chrome.storage.sync` 容量太小（100KB）且不需要跨设备同步（分组与当前设备标签页状态相关）。IndexedDB 过于复杂，`chrome.storage.local` 足够简单。

## 回归问题预测

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | 跨窗口创建分组时，标签页从原窗口移动到目标窗口后，用户在原窗口的标签页顺序被打乱，原本相邻的标签页被分散 | `chrome.tabs.move` 将标签页移动到目标窗口末尾（`index: -1`），未保留原窗口的相对顺序 | 在移动标签页前记录原窗口的标签页顺序，移动到目标窗口时按顺序指定 `index` 参数，确保分组标签页在目标窗口中连续排列 |
| 2 | AI 分组建议返回后，部分标签页被分配到错误的分组（如 Stack Overflow 被分配到"文档"而非"开发"），用户确认后需要手动调整 | AI 仅根据域名判断，`stackoverflow.com` 可能被归类为"问答"或"文档"而非"开发" | AI 分组建议展示为可编辑的预览，每个分组内的标签页支持拖拽调整，用户确认前可自由修改分组分配 |
| 3 | 用户保存分组后，关闭了部分标签页再恢复分组，所有标签页被重新打开，导致与现有标签页重复（URL 相同） | 恢复分组时未检查当前标签页中是否已存在相同 URL，直接创建新标签页 | 恢复分组前先检查当前标签页的 URL 列表，已存在的 URL 不重复打开，仅在分组中关联已有标签页 |
| 4 | 侧边栏在 Service Worker 被浏览器回收后（idle 状态），打开侧边栏时 TabGroupService 重新初始化，但之前的标签页监听器未恢复，导致侧边栏数据不更新 | Service Worker 生命周期结束时会丢失内存中的事件监听器，重新初始化时仅恢复了静态数据，未恢复动态监听 | 在 Service Worker 的 `chrome.runtime.onConnect` 事件中重新注册 `chrome.tabs.onCreated`、`onRemoved`、`onUpdated` 等监听器，确保每次侧边栏连接时数据监听器处于活跃状态 |
| 5 | 内存估算显示某标签页占用 200MB，用户关闭该标签页后系统内存仅释放 50MB，用户对估算准确性产生怀疑 | 启发式估算基于页面类型（如 YouTube = 200MB），但实际内存占用受缓存、扩展、页面内容等因素影响，估算值与实际值偏差大 | 在内存估算旁添加说明文字"估算值，仅供参考"，并将估算值显示为范围（如"100-200MB"）而非精确值，管理用户预期 |
| 6 | 批量静音操作后，部分标签页的静音状态未更新（UI 显示静音但实际仍在播放音频），用户需要逐个手动静音 | `chrome.tabs.update` 的 `muted` 参数对某些页面（如使用 Web Audio API 的页面）不生效，`mutedInfo.muted` 状态与实际不符 | 批量静音时同时调用 `chrome.tabs.update(tabId, { muted: true })` 和检查更新后的 `mutedInfo.muted` 状态，对于静音失败的标签页提供单独提示和手动操作建议 |
