# YP-09-123: AI 页面摘要 — 一键智能摘要、三级摘要粒度、Readability.js 内容提取、关键点提取、摘要缓存、会话分享、语言感知

> 需求编号：YP-09-123 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YP-09-42（上下文感知菜单）、YP-09-99（右键菜单集成）

## 背景

### 问题陈述

YiPet 用户在浏览网页时，经常需要快速了解页面内容而不必阅读全文。当前用户只能手动阅读全文或复制内容到聊天中让 AI 总结，操作繁琐且无法自动识别页面语言、提取关键信息。这导致：

1. **阅读效率低**：用户面对长篇文章或技术文档，需要大量时间阅读，缺乏快速获取核心信息的手段
2. **操作割裂**：用户需要手动选择、复制页面内容，粘贴到聊天窗口，再输入"请总结这篇文章"——多步操作打断阅读流
3. **摘要粒度单一**：无法根据需求选择简短摘要（一句话）或详细摘要（分段要点），缺乏灵活性
4. **重复摘要浪费**：同一页面在会话期间多次请求摘要，每次都重新调用 AI，浪费 token 和等待时间
5. **摘要信息孤岛**：生成的摘要无法自动关联到聊天会话上下文，用户需要手动复制粘贴

**核心矛盾**：在浏览器扩展的安全限制下，如何高效提取页面正文内容，通过 AI 生成多粒度摘要，同时缓存结果避免重复请求，并将摘要无缝融入聊天上下文。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 长文章阅读效率低，用户需要手动总结 | 高 | 用户阅读 5000 字技术文章，想知道核心观点 |
| 2 | 摘要操作步骤多，打断阅读流 | 中 | 用户需要选中全文 → 复制 → 打开聊天 → 粘贴 → 输入总结指令 |
| 3 | 同一页面重复摘要浪费资源 | 中 | 用户在会话中多次返回同一页面，每次都需要重新生成摘要 |
| 4 | 摘要与聊天上下文脱节 | 中 | AI 生成的摘要无法直接作为聊天上下文引用 |
| 5 | 英文页面用中文摘要不准确 | 中 | 英文技术文档用中文摘要时，术语翻译不准确 |

### 挑战

| 挑战 | 说明 |
|------|------|
| 页面内容提取质量 | 不同网页结构差异大，正文提取不准确会直接影响摘要质量。需要可靠的正文提取库 |
| 摘要粒度控制 | 三种粒度（简短/标准/详细）需要不同的 prompt 策略，确保输出符合预期长度和结构 |
| 缓存策略设计 | 需要判断页面内容是否变化，避免缓存过期页面。会话内缓存与跨会话缓存策略不同 |
| 语言检测与适配 | 需要准确检测页面主要语言，生成语言匹配的摘要，同时支持用户偏好语言覆盖 |
| 跨世界通信 | Content Script 提取内容，Service Worker 或 Popup 调用 AI 服务，需要可靠的数据传输 |

## 二、设计决策

### 决策 1：内容提取方案 — Readability.js vs 自定义提取器 vs DOM 遍历

| 选项 | 提取准确度 | 体积 | 维护成本 | 跨页面兼容性 |
|------|-----------|------|----------|-------------|
| Readability.js | 高（Firefox 阅读模式同款） | ~45KB | 低（开源社区维护） | 高（处理各种页面结构） |
| 自定义提取器 | 中 | ~10KB | 高（需持续适配） | 中（需要大量规则） |
| DOM 遍历 | 低 | ~5KB | 中 | 低（特殊结构无法处理） |

**选择：Readability.js（@mozilla/readability）。** Readability.js 是 Firefox 阅读模式的核心引擎，经过多年验证，能准确提取绝大多数网页的正文内容。体积约 45KB（gzip 后约 15KB），通过动态 import 懒加载，不影响扩展启动性能。作为备选，当 Readability.js 提取失败时，降级为 `document.body.innerText` 的前 10000 字符。

### 决策 2：摘要粒度方案 — 简短/标准/详细三种粒度

| 选项 | 简短 (brief) | 标准 (standard) | 详细 (detailed) |
|------|-------------|-----------------|-----------------|
| 输出长度 | 1-2 句话 | 1 个段落 | 分段要点 + 小标题 |
| Token 消耗 | ~100-200 | ~300-500 | ~800-1500 |
| 生成速度 | 1-2s | 2-4s | 4-8s |
| 适用场景 | 快速浏览 | 了解概况 | 深度阅读替代 |

**选择：三种粒度全部支持，默认 "标准"。** 用户在不同场景下对摘要的需求不同。简短摘要适合快速浏览（如社交媒体分享的文章），标准摘要适合日常阅读，详细摘要适合技术文档和研究报告。默认使用标准粒度，用户可在设置中修改默认粒度。

### 决策 3：摘要缓存策略 — 会话内缓存 vs 跨会话持久化缓存

| 选项 | 缓存时长 | 存储 | 内容变化检测 | 实现复杂度 |
|------|----------|------|-------------|-----------|
| 会话内缓存 | 当前会话 | 内存 Map | 不需要 | 低 |
| 跨会话缓存 | 7 天 | chrome.storage.local | 需要（URL + 内容指纹） | 中 |
| 不缓存 | 无 | 无 | 不需要 | 低 |

**选择：会话内缓存（内存 Map）+ 可选手动刷新。** 同一会话内用户多次访问同一页面时，直接返回缓存的摘要，避免重复请求 AI。不跨会话缓存的原因：页面内容可能已更新，缓存摘要可能过时。用户可通过"刷新摘要"按钮强制重新生成。缓存键为 `URL + 摘要粒度`。

### 决策 4：语言检测方案 — 页面语言检测 vs 用户偏好 vs 混合

| 选项 | 准确性 | 用户体验 | 实现复杂度 |
|------|--------|----------|-----------|
| 页面语言检测 | 高 | 摘要语言与页面一致 | 低 |
| 用户偏好设置 | 最高 | 用户可选择偏好语言 | 低 |
| 混合（页面检测 + 用户偏好） | 最高 | 默认页面语言，可切换 | 中 |

**选择：混合方案（页面语言检测 + 用户偏好覆盖）。** 默认使用页面语言生成摘要，保持摘要与原文语言一致。用户在设置中可配置"始终使用中文摘要"偏好，覆盖页面语言检测。语言检测使用 `document.documentElement.lang` 优先级高于内容检测。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 内容提取 | Readability.js | 自定义提取器 | DOM 遍历 | **Readability.js** | 准确度最高，社区维护 |
| 摘要粒度 | 仅标准 | 简短+标准 | 简短+标准+详细 | **三种粒度** | 覆盖不同场景需求 |
| 缓存策略 | 会话内缓存 | 跨会话缓存 | 不缓存 | **会话内缓存** | 避免过期内容，内存开销小 |
| 语言检测 | 页面语言 | 用户偏好 | 混合 | **混合** | 默认准确，可手动覆盖 |

### 4.2 内容提取器

```typescript
// src/content/summarization/ContentExtractor.ts (新增)

import { Readability } from '@mozilla/readability';
import { PageContent } from '../../types/summarization';

class ContentExtractor {
  private readabilityModule: typeof Readability | null = null;

  /**
   * 提取当前页面正文内容
   */
  async extractContent(): Promise<PageContent> {
    try {
      // 动态加载 Readability.js（懒加载）
      if (!this.readabilityModule) {
        const module = await import('@mozilla/readability');
        this.readabilityModule = module.Readability;
      }

      // 克隆 document 避免修改原始 DOM
      const documentClone = document.cloneNode(true) as Document;
      const reader = new this.readabilityModule(documentClone);
      const article = reader.parse();

      if (article && article.textContent && article.textContent.length > 100) {
        return this.buildPageContent(article);
      }

      // 降级方案：使用 body 文本
      return this.fallbackExtract();
    } catch (error) {
      console.warn('[ContentExtractor] Readability failed, using fallback:', error);
      return this.fallbackExtract();
    }
  }

  /**
   * 生成内容指纹（用于缓存验证）
   */
  generateFingerprint(content: PageContent): string {
    // 取前 1000 字符 + 标题的 hash
    const sample = content.title + content.content.slice(0, 1000);
    return this.simpleHash(sample);
  }

  /**
   * 检测页面语言
   */
  detectLanguage(): string {
    // 优先级：html lang 属性 > meta 标签 > 内容检测
    const htmlLang = document.documentElement.lang;
    if (htmlLang) return htmlLang.split('-')[0];

    const metaLang = document.querySelector('meta[http-equiv="content-language"]')
      ?.getAttribute('content');
    if (metaLang) return metaLang.split('-')[0];

    // 简单启发式：检测中文字符比例
    const text = document.body.innerText.slice(0, 1000);
    const chineseChars = (text.match(/[\u4e00-\u9fff]/g) || []).length;
    if (chineseChars / text.length > 0.1) return 'zh';

    return 'en';
  }

  /**
   * 提取元数据
   */
  extractMetadata(): Partial<PageContent> {
    const meta = {
      byline: this.getMetaContent('author'),
      publishedDate: this.getMetaContent('article:published_time')
        || this.getMetaContent('date'),
      siteName: this.getMetaContent('og:site_name'),
      tags: this.extractTags(),
    };
    return meta;
  }

  // --- 私有方法 ---

  private buildPageContent(article: any): PageContent {
    const meta = this.extractMetadata();
    return {
      title: article.title || document.title,
      url: window.location.href,
      content: article.textContent.trim(),
      excerpt: article.excerpt || article.textContent.slice(0, 200),
      length: article.textContent.length,
      byline: article.byline || meta.byline || null,
      siteName: article.siteName || meta.siteName || null,
      dir: article.dir || null,
      lang: this.detectLanguage(),
      publishedDate: meta.publishedDate || null,
    };
  }

  private fallbackExtract(): PageContent {
    const body = document.body.innerText.slice(0, 10000);
    return {
      title: document.title,
      url: window.location.href,
      content: body,
      excerpt: body.slice(0, 200),
      length: body.length,
      byline: null,
      siteName: null,
      dir: null,
      lang: this.detectLanguage(),
      publishedDate: null,
    };
  }

  private getMetaContent(name: string): string | null {
    const meta = document.querySelector(`meta[name="${name}"], meta[property="${name}"]`);
    return meta?.getAttribute('content') || null;
  }

  private extractTags(): string[] {
    const keywords = this.getMetaContent('keywords');
    if (keywords) return keywords.split(',').map(t => t.trim()).slice(0, 5);
    return [];
  }

  private simpleHash(str: string): string {
    let hash = 0;
    for (let i = 0; i < str.length; i++) {
      const char = str.charCodeAt(i);
      hash = ((hash << 5) - hash) + char;
      hash = hash & hash; // Convert to 32bit integer
    }
    return hash.toString(36);
  }
}
```

### 4.3 摘要管理器

```typescript
// src/content/summarization/SummaryManager.ts (新增)

class SummaryManager {
  private cache: Map<string, SummaryCacheEntry> = new Map();
  private extractor: ContentExtractor;
  private apiClient: ApiClient;
  private readonly MAX_CACHE_SIZE = 20;

  /**
   * 生成页面摘要（带缓存）
   */
  async summarize(
    level: SummaryLevel = 'standard',
    language: SummaryLanguage = 'auto',
    forceRefresh = false
  ): Promise<PageSummary> {
    // 1. 提取页面内容
    const content = await this.extractor.extractContent();
    const fingerprint = this.extractor.generateFingerprint(content);

    // 2. 检查缓存
    const cacheKey = this.buildCacheKey(content.url, level);
    if (!forceRefresh) {
      const cached = this.cache.get(cacheKey);
      if (cached && cached.summary.contentFingerprint === fingerprint) {
        cached.hitCount++;
        return cached.summary;
      }
    }

    // 3. 确定摘要语言
    const resolvedLanguage = language === 'auto'
      ? content.lang || 'zh'
      : language;

    // 4. 调用 AI 生成摘要
    const response = await this.callAISummary({
      content,
      level,
      language: resolvedLanguage,
      includeKeyPoints: true,
    });

    // 5. 构建摘要对象
    const summary: PageSummary = {
      id: this.generateId(),
      url: content.url,
      level,
      content: response.summary,
      language: resolvedLanguage,
      keyPoints: response.keyPoints,
      generatedAt: Date.now(),
      contentFingerprint: fingerprint,
      sourceContentLength: content.length,
      tokenCount: response.tokenUsage.total,
    };

    // 6. 写入缓存
    this.cache.set(cacheKey, {
      url: content.url,
      level,
      summary,
      createdAt: Date.now(),
      hitCount: 0,
    });

    // 7. 清理过期缓存（LRU）
    this.evictCache();

    return summary;
  }

  /**
   * 获取页面关键点（不生成完整摘要）
   */
  async getKeyPoints(): Promise<PageKeyPoints> {
    const content = await this.extractor.extractContent();
    const response = await this.callAIKeyPoints(content);
    return response;
  }

  /**
   * 分享摘要到聊天会话
   */
  async shareSummaryToChat(
    summary: PageSummary,
    sessionId: string
  ): Promise<void> {
    const message = this.formatSummaryAsMessage(summary);
    await this.apiClient.sendMessage({
      sessionId,
      content: message,
      type: 'page_summary',
      metadata: {
        url: summary.url,
        level: summary.level,
        summaryId: summary.id,
      },
    });
  }

  /**
   * 检查缓存状态
   */
  getCacheStatus(url: string): {
    brief: boolean;
    standard: boolean;
    detailed: boolean;
  } {
    return {
      brief: this.cache.has(this.buildCacheKey(url, 'brief')),
      standard: this.cache.has(this.buildCacheKey(url, 'standard')),
      detailed: this.cache.has(this.buildCacheKey(url, 'detailed')),
    };
  }

  /**
   * 清除指定页面缓存
   */
  clearCache(url: string): void {
    ['brief', 'standard', 'detailed'].forEach(level => {
      this.cache.delete(this.buildCacheKey(url, level as SummaryLevel));
    });
  }

  // --- 私有方法 ---

  private async callAISummary(request: SummaryRequest): Promise<SummaryResponse> {
    const levelPrompts = {
      brief: '用1-2句话总结以下内容的核心结论，简洁明了：',
      standard: '用一段话（约150字）总结以下内容的主要观点和关键信息：',
      detailed: '对以下内容进行详细总结，使用分段要点形式，每个要点配小标题，包含核心论点、论据和结论：',
    };

    const prompt = `${levelPrompts[request.level]}

语言要求：使用${request.language === 'zh' ? '中文' : '英文'}回复。

${request.includeKeyPoints ? '同时提取以下信息：主题、作者、日期、标签、核心论点列表。' : ''}

页面标题：${request.content.title}
页面来源：${request.content.siteName || '未知'}
页面内容：
${request.content.content.slice(0, 8000)}`;

    const response = await this.apiClient.rpcCall('services.ai.summarization.summarize', {
      prompt,
      level: request.level,
      maxTokens: request.level === 'brief' ? 200 : request.level === 'standard' ? 500 : 1500,
    });

    return {
      summary: response.summary,
      keyPoints: response.keyPoints || {
        mainTopic: '',
        author: null,
        date: null,
        tags: [],
        arguments: [],
      },
      language: request.language,
      tokenUsage: response.tokenUsage || { prompt: 0, completion: 0, total: 0 },
    };
  }

  private async callAIKeyPoints(content: PageContent): Promise<PageKeyPoints> {
    const response = await this.apiClient.rpcCall('services.ai.summarization.keypoints', {
      content: content.content.slice(0, 5000),
      title: content.title,
    });
    return response.keyPoints;
  }

  private buildCacheKey(url: string, level: SummaryLevel): string {
    return `${url}::${level}`;
  }

  private formatSummaryAsMessage(summary: PageSummary): string {
    return `📄 **页面摘要** (${summary.level === 'brief' ? '简短' : summary.level === 'standard' ? '标准' : '详细'})

${summary.content}

---
📌 主题: ${summary.keyPoints.mainTopic || '未知'}
${summary.keyPoints.author ? `👤 作者: ${summary.keyPoints.author}` : ''}
${summary.keyPoints.date ? `📅 日期: ${summary.keyPoints.date}` : ''}
🔗 来源: ${summary.url}`;
  }

  private evictCache(): void {
    if (this.cache.size <= this.MAX_CACHE_SIZE) return;

    // LRU 淘汰：删除最旧的条目
    const entries = Array.from(this.cache.entries());
    entries.sort((a, b) => a[1].createdAt - b[1].createdAt);
    const toRemove = entries.slice(0, entries.length - this.MAX_CACHE_SIZE);
    toRemove.forEach(([key]) => this.cache.delete(key));
  }

  private generateId(): string {
    return `summary_${Date.now()}_${Math.random().toString(36).slice(2, 9)}`;
  }
}
```

## 九、设计决策记录

### D-01：内容提取库选择

- **问题**：如何在浏览器扩展中准确提取页面正文内容
- **选项**：Readability.js、自定义 DOM 遍历提取器、cheerio 等第三方库
- **选择**：Readability.js（@mozilla/readability）
- **理由**：Readability.js 是 Firefox 阅读模式的核心引擎，经过数百万网页验证，提取准确率 > 90%。体积约 45KB（gzip 15KB），通过动态 import 懒加载不影响扩展启动性能。提供降级方案（body.innerText）确保极端情况下仍可用。

### D-02：摘要粒度设计

- **问题**：应该提供几种摘要粒度，如何平衡灵活性和复杂度
- **选项**：仅一种（标准）、两种（简短+标准）、三种（简短+标准+详细）
- **选择**：三种粒度（简短/标准/详细）
- **理由**：用户在不同场景下对摘要的需求差异显著。简短摘要（1-2 句）适合快速浏览，标准摘要（1 段）适合日常阅读，详细摘要（分段要点）适合深度阅读替代。三种粒度覆盖了主要使用场景，且通过不同 prompt 和 maxTokens 控制，实现复杂度可控。

### D-03：缓存策略设计

- **问题**：摘要是否需要缓存，缓存的粒度和失效策略
- **选项**：不缓存、会话内缓存、跨会话持久化缓存
- **选择**：会话内缓存（内存 Map，LRU 淘汰，最大 20 条）
- **理由**：同一会话内用户可能多次访问同一页面，缓存可避免重复 AI 调用。不跨会话缓存的原因：页面内容可能已更新，且跨会话缓存的失效检测（内容指纹比对）增加复杂度。用户可通过"刷新"按钮强制更新。内存 Map 查找 < 50ms，20 条缓存 < 100KB 内存，开销可忽略。

### D-04：语言检测策略

- **问题**：摘要应该使用什么语言生成
- **选项**：始终使用页面语言、始终使用用户偏好语言、混合（页面语言 + 用户偏好覆盖）
- **选择**：混合方案（页面语言检测 + 用户偏好覆盖）
- **理由**：默认使用页面语言生成摘要符合直觉（英文文章用英文摘要，中文文章用中文摘要）。提供用户偏好设置（如"始终使用中文"）覆盖默认行为，满足跨语言阅读需求。语言检测优先级：html lang 属性 > meta 标签 > 内容启发式检测，准确率 > 95%。

## 回归问题预测

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | Readability.js 在 SPA 页面（如 React/Vue 应用）中提取内容为空，因为 document.cloneNode 克隆的是初始 DOM，动态渲染的内容未被包含 | SPA 页面的内容通过 JavaScript 动态渲染，Readability.js 在解析时可能尚未渲染完成 | 在提取前等待 2s 并使用 MutationObserver 检测 DOM 变化，内容稳定后再提取。或在 document.readyState === 'complete' 后延迟提取 |
| 2 | 摘要缓存使用 URL 作为键，但同一 URL 的页面内容可能因登录状态、A/B 测试等动态变化，导致缓存命中时返回过期摘要 | 动态页面（如社交媒体 feed、个性化推荐）相同 URL 可能展示不同内容 | 缓存键中加入内容指纹（前 1000 字符 + 标题的 hash），内容变化时自动失效缓存。用户可手动刷新 |
| 3 | 浮动摘要按钮的 `position: fixed` 在使用了 CSS `transform` 或 `filter` 的父元素中，定位相对于该父元素而非视口，导致按钮位移到错误位置 | CSS `position: fixed` 的包含块规则：当祖先元素有 transform/filter/perspective 时，fixed 相对于该祖先定位 | 使用 Shadow DOM 隔离样式，或在 body 直接插入按钮元素。定期检测按钮位置是否异常，自动修正 |
| 4 | 语言检测基于 html lang 属性，但部分网站 lang 属性设置错误（如中文网站 lang="en"），导致摘要语言与用户预期不符 | 网站开发者未正确设置 lang 属性，或使用了默认模板语言 | 语言检测加入内容启发式分析（中文字符比例 > 10% 判定为中文），作为 lang 属性的校验。用户可手动切换摘要语言 |
| 5 | 详细摘要的 prompt 指令较长，加上页面内容，可能超出 AI 模型的上下文窗口，导致摘要被截断或生成不完整 | 详细摘要 prompt 约 200 字 + 页面内容 8000 字 = 8200 字，部分模型上下文窗口较小 | 根据模型上下文窗口动态调整内容截取长度。详细摘要模式下，content 截取前 6000 字（而非 8000 字），为 prompt 和输出留出空间 |
| 6 | 用户在生成摘要过程中切换标签页，Content Script 的异步 AI 调用可能仍在执行，但页面已不可见，摘要结果无处展示 | 浏览器标签页切换时 Content Script 仍在运行，异步请求完成后无法更新已隐藏的 UI | 在 AI 调用前记录当前 tabId，响应返回时检查当前激活标签页是否匹配。不匹配时仅写入缓存，不渲染 UI |
