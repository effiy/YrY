# YiPet/YiPot 跨项目翻译分析数据桥接 — 需求规格

> 编号：YP-09-238 · 优先级：P2 · 工时：~0.4d · 状态：已完成

> **文档职责**：定义 YiPet 接入 YiAi 翻译分析数据的 API 层需求，统一三项目（YiVad/YiPet/YiPot）的 RPC 契约。

---

## 一、背景

### 现状

YiVad 管理后台已实现完整的翻译分析仪表盘（TranslationAnalytics.vue），包含 5 KPI + 3 ECharts 图表 + Provider 排名。YiPot 桌面端已接入 `getAnalytics`、`getProviderHealth`、`getHourlyTrend` 等 7 个分析方法。YiPet 浏览器扩展仅有基础的 `translate`、`feedback`、`getProviderRecommend` 3 个方法，缺少分析和实时能力。

### 数据流现状

```
YiVad :8848 ──→ YiAi :10086 ──→ MongoDB（翻译记录 + 记忆缓存）
YiPot (Tauri) ──→ YiAi :10086 ──→ 同上
YiPet (Chrome) ──→ YiAi :10086 ──→ 同上
```

三个项目均通过 YiAi RPC 信封通信，但 API 方法覆盖度不均衡：

| RPC 方法 | YiVad | YiPot | YiPet（修改前） | YiPet（修改后） |
|----------|-------|-------|----------------|----------------|
| `translate` | - | ✅ | ✅ | ✅ |
| `translation_analytics` | ✅ | ✅ | ❌ | ✅ |
| `provider_health` | ✅ | ✅ | ❌ | ✅ |
| `hourly_trend` | ✅ | ✅ | ❌ | ✅ |
| `provider_breakdown` | ✅ | ✅ | ❌ | ✅ |
| `translation_memory_stats` | ✅ | ✅ | ❌ | ✅ |
| `provider_recommend` | ✅ | ✅ | ✅ | ✅ |
| `translation_feedback` | ✅ | ✅ | ✅ | ✅ |
| `translate_stream` | - | ✅ | ❌ | ✅ |

---

## 二、功能需求

### FR-1: Translation Analytics API

**文件**：`YiPet/src/api/services/translation.ts`

新增方法 `getAnalytics(days?)`，调用 `translation_analytics` RPC，返回翻译总量、语言分布。

### FR-2: Provider Health API

新增方法 `getProviderHealth(hours?)`，调用 `provider_health` RPC，返回各 Provider 成功率、健康状态、记忆缓存条目、反馈统计。

### FR-3: Hourly Trend API

新增方法 `getHourlyTrend(days?)`，调用 `hourly_trend` RPC，返回小时级翻译量趋势数据。

### FR-4: Provider Breakdown API

新增方法 `getProviderBreakdown(days?)`，调用 `provider_breakdown` RPC，返回各 Provider 调用次数和成功次数。

### FR-5: Translation Memory Stats API

新增方法 `getMemoryStats()`，调用 `translation_memory_stats` RPC，返回缓存总量、语言分布、Provider 分布。

### FR-6: SSE Streaming Translation

新增 `translateStream()` 异步生成器，调用 `translate_stream` RPC，通过 SSE 实时返回翻译文本分块。

### FR-7: Provider Health Widget

**文件**：`YiPet/src/popup/components/ProviderHealth.vue`（新增）

在 YiPet Popup 中新增翻译引擎健康卡片，60s 自动刷新，展示：
- 健康/降级/宕机 Provider 数量
- 记忆缓存条目数
- 反馈 👍 率
- Top 5 Provider 列表（名称、成功率、调用次数）

---

## 三、数据一致性保证

### RPC 契约统一

三个项目使用相同的 RPC 端点和方法名：

```typescript
// 三项目一致的调用模式
MODULE = 'services.translation.translate_service'
// 方法名: translation_analytics | provider_health | hourly_trend |
//          provider_breakdown | translation_memory_stats | provider_recommend
```

### 类型定义一致

所有项目的返回类型从 YiAi 透传，不进行客户端转换。Provider 健康状态使用统一的 `'healthy' | 'degraded' | 'down'` 枚举。

### 实时性保证

- YiVad: 30s 轮询（TranslationAnalytics toggle）
- YiPet: 60s 轮询（ProviderHealth widget）
- YiPot: 按需调用（翻译前查询）
