## 1. 图片瘦脸工具 (YP-09-280)

### 背景

用户在发布照片前经常需要微调面部轮廓——瘦脸、大眼、鼻部塑形是最常见的人像美化需求。手机 APP 的美颜功能普及——但浏览器端缺乏像素级的液化工具。

### 问题陈述

1. **脸型轮廓不理想**: 拍摄角度导致脸部显得宽大，需要局部收缩脸颊
2. **眼睛大小不对称**: 需要放大眼睛 (大眼效果)
3. **鼻部塑形**: 鼻翼宽大、鼻梁不够挺拔——需要局部调整
4. **无浏览器端液化工具**: 桌面端只能依赖 Photoshop 的液化工具

### 核心设计

**液化工具类型**:

| 工具 | 操作 | 笔刷行为 |
|------|------|---------|
| 推 (Push) | 沿拖动方向推动像素 | 笔刷中心向前推动，边缘渐变衰减 |
| 捏 (Pinch) | 向内收缩像素 | 笔刷半径内像素向中心收缩 |
| 膨胀 (Bloat) | 向外扩张像素 | 笔刷半径内像素向外膨胀 |
| 恢复 (Restore) | 恢复原始像素 | 笔刷区域像素还原到初始状态 |

**笔刷参数**: 大小 (10-200px)、强度 (0-100%)、硬度 (0-100%)、密度 (1-5)

**液化算法**: 基于网格变形 (Mesh Warp)——在图片上覆盖 NxN 网格 → 笔刷拖动时移动周围网格点 → 双线性插值重采样 → 得到液化后的图片

**撤销/重做**: 全分辨率 ImageData 快照，限制 20 步

**核心类型**:


**液化笔刷算法**:

```typescript
class LiquifyEngine {
  // 推工具: 移动笔刷中心邻域像素
  pushBrush(cx: number, cy: number, dx: number, dy: number, radius: number, strength: number): void {
    for (grid points within radius) {
      // 距离衰减权重 = 1 - dist/radius (线性) 或 (1 - (dist/radius)²) (二次)
      const weight = 1 - Math.sqrt((px-cx)² + (py-cy)²) / radius;
      if (weight > 0) {
        grid.point.x += dx * weight * strength;
        grid.point.y += dy * weight * strength;
      }
    }
  }
  
  // 捏工具: 向内移动
  pinchBrush(cx: number, cy: number, radius: number, strength: number): void {
    for (grid points within radius) {
      const dist = distance(grid.point, {x: cx, y: cy});
      const weight = Math.exp(-dist * dist / (2 * radius * radius)); // 高斯权重
      const shift = strength * weight * radius * 0.1;
      grid.point.x = cx + (grid.point.x - cx) * (1 - shift / dist);
      grid.point.y = cy + (grid.point.y - cy) * (1 - shift / dist);
    }
  }

  // 膨胀工具: 向外移动 (与捏相反)
  bloatBrush(cx: number, cy: number, radius: number, strength: number): void {
    // 与 pinch 方向相反
    for (grid points within radius) {
      const shift = strength * weight * radius * 0.1;
      grid.point.x = cx + (grid.point.x - cx) * (1 + shift / dist);
      grid.point.y = cy + (grid.point.y - cy) * (1 + shift / dist);
    }
  }
}
```

## 2. 图片红眼移除 (YP-09-277)

### 背景

闪光灯拍摄的人像照片经常出现红眼现象——瞳孔呈现红色而非自然的黑色/棕色。传统处理需要 Photoshop 的红眼工具或专业的照片编辑软件。

### 问题陈述

1. **红眼检测**: 需要自动识别照片中人眼区域的红眼像素
2. **精确修正**: 仅修改瞳孔红色区域——保留虹膜和巩膜
3. **眼神光保留**: 保持眼睛中的高光反射——使眼睛看起来自然有神
4. **手动修正**: 自动检测不完全时——用户手动框选眼睛区域

### 核心设计

**自动检测**: 基于红色像素阈值检测——在肤色区域中寻找高红色饱和度的圆形区域

**检测算法**: 遍历像素 → 红色通道明显高于绿色和蓝色 (R > G+20 && R > B+20) → 形态学开运算去除噪点 → 圆形度检测 (面积/周长² 接近 1/(4π)) → 标记为红眼候选区域

**修正算法**: 红眼区域内 → 将红色像素转为深色 (降低 R 通道 → 平均 G+B 通道值) → 保留原始亮度 → 保持瞳孔自然黑色

**眼神光保留**: 检测瞳孔中心最亮的像素群 (高光点) → 修正时跳过这些像素 → 眼神光不变

**手动模式**: 用户拖拽框选单只眼睛 → 仅处理框选区域

**核心类型**:

```typescript

  detectRedEyes(imageData: ImageData): EyeRegion[] {
    // 1. 红色像素掩码: R > G + 20 && R > B + 20 && R > 100
    // 2. 形态学开运算 (去除孤立噪点)
    // 3. 连通区域分析 → 保留圆形度高 (> 0.7) 的区域
    // 4. 过滤: 半径在 5-50px 范围内
    return eyeRegions;
  }

  correctRedEye(imageData: ImageData, eye: EyeRegion, strength: number): void {
    for (pixels in eye region) {
      if (isRedPixel(pixel)) {
        // 去红: R 通道 = 平均(G, B)
        const newR = (pixel.g + pixel.b) / 2;
        // 保持亮度
        const originalLuminance = 0.299 * pixel.r + 0.587 * pixel.g + 0.114 * pixel.b;
        const newLuminance = 0.299 * newR + 0.587 * pixel.g + 0.114 * pixel.b;
        const luminanceRatio = originalLuminance / newLuminance;
        pixel.r = newR * luminanceRatio * strength + pixel.r * (1 - strength);
      }
    }
  }
}
```

## 3. 图片皮肤平滑 (YP-09-278)

### 背景

人像照片中皮肤的毛孔、细纹、斑点在近距离拍摄下非常明显。用户希望在不损失皮肤纹理的前提下实现自然的磨皮效果——避免"塑料感"的过度平滑。

### 问题陈述

1. **皮肤区域识别**: 需要精确定位皮肤区域——避免平滑了头发、衣物、背景
2. **纹理保留**: 双边滤波在平滑同时保留边缘——毛孔质感不丢失
3. **强度控制**: 从轻度柔焦到深度磨皮——用户根据需求调节
4. **对比预览**: 左右分屏——原图 vs 磨皮后直观对比

### 核心设计

**皮肤检测**: 基于颜色范围的肤色掩码

**皮肤掩码算法**: RGB → YCbCr 空间 → 肤色范围: 80 < Cb < 120, 133 < Cr < 170 → 形态学闭运算 (填充细小空隙) → 边缘羽化 (5px 高斯模糊)

**磨皮算法**: 双边滤波 (Bilateral Filter)——同时考虑空间邻近度和颜色相似度

**双边滤波公式**: 输出像素 = Σ(邻域像素 × 空间权重 × 颜色权重) / Σ(空间权重 × 颜色权重)
- 空间权重 = exp(-(dx² + dy²) / (2 × sigmaSpace²))
- 颜色权重 = exp(-(Δr² + Δg² + Δb²) / (2 × sigmaColor²))

**参数控制**:
- sigmaSpace (1-20): 空间范围，越大平滑范围越大
- sigmaColor (10-100): 颜色容差，越大越模糊
- 强度 (0-100): 原图与滤波结果的混合权重

**掩码限制**: 双边滤波仅应用于皮肤掩码内的像素——非皮肤区域保持原始像素

**分屏对比**: 垂直分割线可拖动——左半原图/右半磨皮 ——同步缩放

**核心类型**:


**双边滤波实现**:

```typescript
class SkinSmoother {
  generateSkinMask(imageData: ImageData): Float32Array {
    const mask = new Float32Array(imageData.width * imageData.height);
    for (each pixel) {
      const [y, cb, cr] = rgbToYCbCr(r, g, b);
      if (cb >= 80 && cb <= 120 && cr >= 133 && cr <= 170) {
        mask[i] = 1.0;
      }
    }
    // 形态学闭运算 + 高斯羽化边缘
    return morphologicalClose(mask);
  }

  bilateralFilter(imageData: ImageData, mask: Float32Array, sigmaSpace: number, sigmaColor: number): ImageData {
    const radius = Math.ceil(sigmaSpace * 3);  // 3σ 原则
    const result = new ImageData(imageData.width, imageData.height);
    for (each pixel in mask where mask > 0) {
      let sumR = 0, sumG = 0, sumB = 0, sumW = 0;
      for (neighbor pixels within radius) {
        const spatialWeight = Math.exp(-(dx*dx + dy*dy) / (2 * sigmaSpace * sigmaSpace));
        const colorDist = (Δr*Δr + Δg*Δg + Δb*Δb);
        const colorWeight = Math.exp(-colorDist / (2 * sigmaColor * sigmaColor));
        const weight = spatialWeight * colorWeight;
        sumR += nr * weight; sumG += ng * weight; sumB += nb * weight; sumW += weight;
      }
      result[pixel] = { r: sumR/sumW, g: sumG/sumW, b: sumB/sumW };
    }
    return result;
  }

  applyStrength(original: ImageData, filtered: ImageData, mask: Float32Array, strength: number): ImageData {
    // output = original * (1-s) + filtered * s
    const s = strength / 100;
    for (each pixel in skin region) {
      result.r = original.r * (1-s) + filtered.r * s;
      result.g = original.g * (1-s) + filtered.g * s;
      result.b = original.b * (1-s) + filtered.b * s;
    }
  }
}
```

## 4. 图片牙齿美白 (YP-09-279)

### 背景

微笑照片中牙齿偏黄影响美观。需要自动识别牙齿区域并进行自然的美白处理——避免"过度漂白"的不自然效果。

### 问题陈述

1. **牙齿区域定位**: 在微笑状态下自动检测牙齿所在的局部区域
2. **颜色修正**: 降低黄色饱和度——增加亮度——而非简单去色
3. **自然外观**: 保留牙齿的立体感和光泽——避免纯白假牙效果
4. **精确调整**: 牙齿边界清晰——美白不溢出到嘴唇和牙龈

### 核心设计

**微笑/牙齿检测**: 基于人脸关键点 ——使用 face-api.js 或 MediaPipe Face Mesh 检测嘴唇关键点 → 口腔内部矩形区域 → 在此区域内检测白色像素连通区域作为牙齿候选

**牙齿区域提取**: 嘴部关键点 → 内唇轮廓 → 框出口腔区域 → 白色阈值 (HSL L > 0.5, S < 0.3) → 保留最大连通区域

**美白算法**: HSL 空间操作——提升 L (Lightness) + 降低 S (Saturation) → 去黄增白

**美白公式**:
- Lnew = Lold + (1 - Lold) × strength / 100
- Snew = Sold × (1 - strength / 200)
- H 保持不变 (保留原始色相，不偏蓝)

**自然外观保护**: 牙齿边缘区域渐变过渡 → 美白强度随像素接近边缘递减 → 避免"贴白片"效果

**手动修正**: 画笔工具 → 手动画出牙齿区域 → 补充自动检测遗漏的区域

**核心类型**:


**牙齿美白算法**:

```typescript
class TeethWhitening {
  detectTeeth(imageData: ImageData, faceLandmarks: FaceLandmarks): TeethRegion {
    // 1. 从人脸关键点提取嘴部区域
    const mouthPoints = faceLandmarks.getMouth();
    const mouthRect = boundingBox(mouthPoints);
    
    // 2. 在嘴部区域内找白色连通区域
    const whiteMask = detectWhitePixels(imageData, mouthRect);
    
    // 3. 保留最大连通区域作为牙齿
    const teethRegion = largestComponent(whiteMask);
    
    return { mask: teethRegion, bounds: mouthRect };
  }

  whitenTeeth(imageData: ImageData, teeth: TeethRegion, strength: number): ImageData {
    const s = strength / 100;
    for (pixels in teeth region) {
      // RGB → HSL
      const hsl = rgbToHsl(pixel.r, pixel.g, pixel.b);
      
      // 去黄增白
      hsl.l = hsl.l + (1 - hsl.l) * s * 0.6;  // 提升亮度，上限 1.0
      hsl.s = hsl.s * (1 - s * 0.5);           // 降低饱和度
      
      // HSL → RGB
      const newRgb = hslToRgb(hsl);
      
      // 边缘渐变过渡
      const edgeFactor = edgeDistance(pixel, teeth.mask);
      pixel.r = mix(pixel.r, newRgb.r, edgeFactor);
      pixel.g = mix(pixel.g, newRgb.g, edgeFactor);
      pixel.b = mix(pixel.b, newRgb.b, edgeFactor);
    }
    return imageData;
  }
}
```

## 7. 图片相似度搜索 (YP-09-287)

### 背景

用户本地/浏览器中的图片逐渐积累——大量相似或重复图片占用空间。需要相似度搜索来发现重复、查找相似图片、清理冗余。

### 问题陈述

1. **重复图片检测**: 找到完全相同的图片 (不同文件名/分辨率)
2. **相似图片查找**: 找到视觉上相似的图片 (编辑版本、不同尺寸)
3. **去重辅助**: 标记重复/相似组 → 用户选择保留/删除
4. **性能**: 大量图片 (数百张) 的相似度计算在浏览器端可行

### 核心设计

**感知哈希 (Perceptual Hash)**: 多层哈希策略

| 哈希算法 | 大小 | 速度 | 适用于 |
|---------|------|------|--------|
| aHash (平均哈希) | 8x8 = 64 bit | 极快 | 初筛 |
| pHash (感知哈希/DCT) | 32x32 | 快 | 精确匹配 |
| dHash (差异哈希) | 9x8 = 64 bit | 极快 | 缩放/裁剪不变性 |
| wHash (小波哈希) | 8x8 | 中 | 旋转/裁剪鲁棒性 |

**相似度计算**: 汉明距离 (Hamming Distance) — 两个哈希值不同 bit 的数量

**搜索流程**: 用户选择一张参考图片 → 计算其多个哈希值 → 与图片库中所有图片的哈希值比较汉明距离 → 按距离排序 → 显示相似图片 (辅以缩略图)

**去重分组**: 遍历所有图片 → 两两比较 → 汉明距离 < 阈值 (如 5) 的归为一组 → 显示重复组 → 用户选择每组保留哪张

**增量索引**: 图片库哈希值缓存到 IndexedDB → 新图片加入时仅计算新图片的哈希值 → 与缓存比较

**核心类型**:

```typescript

  phash: string;    // 64-bit hex
  dhash: string;    // 64-bit hex
}

interface SimilarityResult {

  thumbnailUrl: string;

}

  images: SimilarityResult[];

```

**pHash DCT 算法**:

```typescript
class PerceptualHasher {
  computePHash(imageData: ImageData): string {
    // 1. 缩放至 32x32
    // 2. 转灰度
    // 3. DCT (2D 离散余弦变换)
    // 4. 取左上角 8x8 (低频分量)
    // 5. 计算中位数
    // 6. 每个像素 > 中位数 → 1, 否则 → 0
    // 7. 转为 64-bit hex 字符串
    return hash;
  }

  hammingDistance(hash1: string, hash2: string): number {
    let distance = 0;
    for (let i = 0; i < hash1.length; i++) {
      const xor = parseInt(hash1[i], 16) ^ parseInt(hash2[i], 16);
      distance += bitCount(xor);
    }
    return distance;
  }

  findSimilar(queryHash: string, candidates: ImageHash[], threshold: number): SimilarityResult[] {
    return candidates
      .map(c => ({ ...c, distance: this.hammingDistance(queryHash, c.phash) }))
      .filter(c => c.distance < threshold)
      .sort((a, b) => a.distance - b.distance);
  }
}
```

## 10. 图片批量优化报告 (YP-09-302)

### 背景

批量优化 (YP-09-288) 和批量压缩 (YP-09-289) 完成后——用户需要一份详细的报告来了解优化效果。

### 问题陈述

1. **逐张统计**: 每张图片的优化前后大小、节省量、节省百分比
2. **总计统计**: 总数量、总原始大小、总优化后大小、总节省量、平均节省率
3. **优化建议记录**: 哪些建议被应用——哪些被跳过
4. **前后对比画廊**: 可浏览所有优化前后对比
5. **报告导出**: PDF 或 CSV 格式——便于存档或分享

### 核心设计

**统计计算**:

```
总文件数: 20
总原大小: 45.2 MB
优化后: 8.3 MB
总节省: 36.9 MB (81.6%)
平均节省: 1.85 MB/张
最大节省: 5.2 MB (photo_001.jpg)
最小节省: 0.1 MB (icon.png)
```

**报告内容**:
1. 抬头: 生成时间、图片总数、工具版本
2. 汇总面板: 总节省量 + 节省百分比 + 平均节省
3. 逐张明细表格: 文件名 | 原大小 | 优化后 | 节省 | 应用的建议
4. 优化建议分布饼图: 压缩/格式转换/尺寸/元数据建议占比
5. 节省量 Top 10

**前后对比画廊**: 垂直排列 → 每张图片上方原图/下方优化后 (或左右) → 单击放大查看

**PDF 导出**: 使用 jsPDF 库生成 PDF → 包含汇总、表格、画廊缩略图

**CSV 导出**: 纯数据导出——文件名,原大小(bytes),优化后大小(bytes),节省(bytes),节省%,应用建议

### 核心类型

```typescript
interface OptimizationReport {
  generatedAt: string;
  totalFiles: number;
  totalOriginalSize: number;
  totalOptimizedSize: number;
  totalSavings: number;
  totalSavingsPercent: number;
  averageSavingsPerFile: number;
  maxSavingFile: { name: string; savings: number };
  fileDetails: FileDetail[];
}

interface FileDetail {
  fileName: string;
  originalSize: number;
  optimizedSize: number;
  savings: number;
  savingsPercent: number;
  appliedSuggestions: string[];
  thumbnailBefore: string;      // data URL
  thumbnailAfter: string;
}
```

|------|------|------|
| `src/image-optimize/ReportGenerator.ts` | 新增 | 报告生成器 |
| `src/image-optimize/PdfExporter.ts` | 新增 | PDF 导出 (jsPDF) |
| `src/components/tools/OptimizationReport.vue` | 新增 | 优化报告展示页面 |

### 测试规格

- 统计正确: 20 张优化 → 报告总节省 = 各张节省之和 → 平均 = 总/20
- Top 10: 按节省量排序 → 第一行节省最多
- 画廊浏览: 点击任一张 → 放大查看前后对比
- PDF 导出: 点击导出 PDF → 文件包含汇总表 + 10 张图
- CSV 导出: 点击导出 CSV → Excel/Numbers 打开 → 数据完整

## 11. 图片质量评分 (YP-09-303)

### 背景

需要客观、量化的图片质量评估——用于批量筛选、自动淘汰低质量图片、质量监控。

### 问题陈述

1. **多维度评分**: 清晰度、噪点、曝光、色彩、压缩伪影 ——综合评定
2. **加权总分**: 各维度按权重加权——不同场景权重不同
3. **质量等级**: 将分数映射为直观的等级 (优秀/良好/一般/较差)
4. **改进建议**: 针对低分维度——给出具体改进建议

### 核心设计

**六维评分模型**:

| 维度 | 检测算法 | 分数范围 | 权重 |
|------|---------|---------|------|
| 清晰度 | Laplacian 方差 (复用 YP-09-283) | 0-100 | 25% |
| 噪点 | 局部方差分析 (复用 YP-09-284) | 0-100 | 20% |
| 曝光 | 亮度直方图均衡度 | 0-100 | 20% |
| 色彩 | 色彩和谐度 + 饱和度分布 (复用 YP-09-286) | 0-100 | 15% |
| 压缩伪影 | JPEG blocking artifacts 检测 | 0-100 | 10% |
| 构图 | 三分法/黄金螺旋评分 (复用 YP-09-285) | 0-100 | 10% |

**曝光评分算法**: 亮度直方图分析 → 过暗区域 (< 50) 和过曝区域 (> 230) 像素占比 → 正常曝光区域占比 → 加权评分

**压缩伪影检测**: 8x8 块边界差分 → JPEG 块效应程度 → 归一化为 0-100

**加权总分**: Score = Σ(dimension_score × weight) where Σ(weight) = 1.0

**质量等级**:
- 优秀 (Excellent): 85-100 — 适合打印/出版
- 良好 (Good): 70-84 — 适合网页展示
- 一般 (Fair): 50-69 — 可用但有改善空间
- 较差 (Poor): < 50 — 建议重拍或替换

**改进建议**:

| 低分维度 | 建议 |
|---------|------|
| 清晰度 < 60 | 使用 USM 锐化 (amount 50-100%) |
| 噪点 > 60 | 使用降噪工具 (双边滤波 sigma 5-10) |
| 曝光 < 50 | 调整亮度/对比度或直方图均衡 |
| 色彩 < 50 | 调整饱和度或使用色彩分析建议的调色方案 |
| 压缩伪影 > 50 | 使用更高质量的原始图片 |
| 构图 < 50 | 使用智能裁剪工具 (三分法/黄金比例) |

**批量评分**: 多张图片逐一评分 → 排序 → 标记低分图片 → 批量淘汰建议

### 核心类型

```typescript
interface QualityScore {
  total: number;                 // 0-100 加权总分
  grade: 'excellent' | 'good' | 'fair' | 'poor';
  dimensions: {
    sharpness: number;          // 0-100
    noise: number;              // 0-100 (越低越好, 显示时反转)
    exposure: number;           // 0-100
    color: number;              // 0-100
    compression: number;        // 0-100 (越低越好, 显示时反转)
    composition: number;        // 0-100
  };
  suggestions: QualitySuggestion[];
  evaluatedAt: string;
}

interface QualitySuggestion {
  dimension: string;
  score: number;
  threshold: number;
  actionType: 'sharpen' | 'denoise' | 'adjust-exposure' | 'adjust-color' | 'recompress' | 'recrop';
  description: string;
  recommendedTool: string;      // 推荐使用的 YiPet 工具名称
}
```

**曝光评分算法**:

```typescript
class QualityScorer {
  evaluateExposure(imageData: ImageData): number {
    const histogram = computeLuminanceHistogram(imageData);
    const totalPixels = imageData.width * imageData.height;
    
    // 暗部 (< 50) 和亮部 (> 230) 像素占比
    const darkPct = sum(histogram[0..50]) / totalPixels;
    const brightPct = sum(histogram[230..255]) / totalPixels;
    const midPct = 1 - darkPct - brightPct;
    
    // 理想: 中间调占大部分，暗部和亮部有分布但不极端
    let score = 100;
    if (darkPct > 0.3) score -= (darkPct - 0.3) * 150;  // 过暗扣分
    if (brightPct > 0.3) score -= (brightPct - 0.3) * 150;  // 过曝扣分
    if (darkPct < 0.05 && brightPct < 0.05) score -= 15;  // 对比度不足
    
    return Math.max(0, Math.min(100, score));
  }

  evaluateJpegArtifacts(imageData: ImageData): number {
    // 8x8 块边界检测
    // 计算水平/垂直方向块边界的差分
    // 差分越显著 → 块效应越严重 → 分数越低
    const blockSize = 8;
    let edgeDiff = 0;
    
    for (each 8x8 block) {
      edgeDiff += abs(pixel[blockEdge] - pixel[blockEdge + 1]);
      edgeDiff += abs(pixel[inner] - pixel[inner + 1]);
    }
    
    const artifactRatio = edgeDiff / totalPixels;
    // artifactRatio 0→100分, 10→0分
    return Math.max(0, 100 - artifactRatio * 10);
  }
}
```

## 整体架构

### 共享模块

以下为 M05 工具集公用的基础设施:

- **人脸检测**: `src/face/FaceDetector.ts` — face-api.js / MediaPipe 封装——被瘦脸、红眼、美肤、美白、人脸标记共享

```
face-api.js / MediaPipe
  ├── 瘦脸工具 (人脸关键点 → 液化网格初始化)

  └── 相似度搜索 (哈希计算 + 汉明距离匹配)

  └── 批量在线压缩 (服务端编码器)
```

## 共享风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| face-api.js 模型加载慢 | 中 | 中 | 首次使用时后台预加载 (web worker)，显示加载进度 |
| 人脸检测在侧脸/遮挡时失败 | 高 | 低 | 提供手动框选/画笔修正作为补充 |
| 双边滤波大图性能差 | 中 | 中 | 限制处理分辨率 (max 1920px)，分块并行处理 |
| YiAi 压缩服务不可用 | 中 | 高 | 降级到浏览器端 Canvas toBlob + 用户提示 |
| 感知哈希碰撞 (不同图片误判为相似) | 低 | 低 | 多哈希交叉验证 + 相似度阈值可调 |
| 大量图片的批量处理卡死浏览器 | 中 | 中 | 串行处理 + requestIdleCallback + 10 张批次间隔 |
| 人脸数据隐私 | 高 | 中 | 人脸特征仅存储 128 维向量 (不可逆推出原图) + 本地存储不上传 |

## 代码审查统一检查清单

- [ ] 人脸检测: 支持多张人脸同时检测——按置信度排序
- [ ] 液化工具: 网格变形时双线性插值——无锯齿
- [ ] 红眼移除: 仅修改红色像素——不误伤嘴唇/红衣服
- [ ] 皮肤平滑: 双边滤波仅应用于皮肤掩码内——头发/背景不受影响
- [ ] 牙齿美白: HSL 空间操作——不过曝——边缘渐变
- [ ] 智能裁剪: 自动推荐方案可接受/调整——不强制应用
- [ ] 人脸标记: 特征向量存储不带原始图像数据
- [ ] 相似度搜索: 多哈希交叉验证——汉明距离阈值可配置
- [ ] 批量处理: 显示实时进度 + 支持取消 + 错误不中断
- [ ] PDF 导出: 不支持图片过大——分页正确
- [ ] 质量评分: 六个维度独立计算——加权公式正确
- [ ] 所有工具: 撤销/重做 + 重置原图
