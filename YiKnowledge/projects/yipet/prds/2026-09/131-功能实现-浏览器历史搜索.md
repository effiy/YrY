# YP-09-124: 浏览器历史搜索 — chrome.history 语义搜索、AI 历史洞察、时间/域名/频次过滤、最近访问、隐私保护、历史书签

> 需求编号：YP-09-124 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YP-09-119（书签与网页收藏管理）、YP-09-99（右键菜单集成）

## 背景

### 问题陈述

YiPet 用户在日常浏览中积累了大量的浏览历史，但浏览器的默认历史搜索功能仅支持基于 URL 和标题的关键词匹配，无法理解用户的自然语言查询意图。用户在寻找"上周看过的那篇关于 React 状态管理的文章"时，只能凭借模糊记忆逐个翻阅历史记录。这导致：

1. **搜索效率低**：浏览器默认历史搜索仅支持精确关键词匹配，用户需要记住 URL 或标题中的确切词汇
2. **语义理解缺失**：用户无法用自然语言描述要找的内容（如"那个讲 React hooks 和 Vue composables 对比的文章"）
3. **历史记录碎片化**：浏览历史散落在不同的时间点和域名下，缺乏统一的管理和洞察视图
4. **隐私顾虑**：用户不希望浏览历史数据被发送到远程服务器处理，但又渴望 AI 增强的搜索能力
5. **历史价值未被挖掘**：浏览历史中蕴含了用户的知识脉络和兴趣变化，但完全未被利用

**核心矛盾**：在严格保护用户隐私（历史数据不离开本地）的前提下，如何提供超越关键词匹配的智能历史搜索体验，同时通过 AI 提供历史浏览洞察。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 找不到之前浏览过的页面，只能凭记忆翻找 | 高 | 用户想找回上周看过的技术文章，但不记得标题 |
| 2 | 关键词搜索匹配不到语义相关的结果 | 高 | 搜索"状态管理"，不匹配标题为"React 数据流方案"的页面 |
| 3 | 历史记录分散，无法按主题浏览 | 中 | 用户想回顾"最近一个月关于 AI 的所有浏览记录" |
| 4 | 隐私顾虑导致不敢使用 AI 历史搜索 | 中 | 用户担心浏览历史被上传到远程服务器 |
| 5 | 浏览历史中的好内容无法快速保存 | 中 | 用户在历史中发现好文章，但没有快速保存到书签的入口 |

### 挑战

| 挑战 | 说明 |
|------|------|
| 隐私与智能的平衡 | 要提供语义搜索，需要理解页面内容，但不能将历史数据发送到远程服务器 |
| chrome.history API 限制 | 仅返回 URL、标题、访问时间、访问次数，不包含页面内容，语义搜索需要额外获取页面内容 |
| 本地嵌入模型 | 需要在浏览器中运行轻量级文本嵌入模型，用于语义相似度计算 |
| 历史数据量 | 用户可能有数万条历史记录，全量处理面临性能挑战 |
| 实时性与准确性 | 需要在实时搜索响应和语义理解准确度之间取得平衡 |

## 二、设计决策

### 决策 1：语义搜索方案 — 本地嵌入 vs 远程 AI vs 混合

| 选项 | 隐私 | 准确性 | 速度 | 实现复杂度 |
|------|------|--------|------|-----------|
| 本地嵌入（Transformers.js） | 完全本地 | 中 | 快（首次加载慢） | 中 |
| 远程 AI（YiAi 后端） | 需上传数据 | 高 | 取决于网络 | 低 |
| 混合（本地关键词 + 远程 AI） | 部分隐私 | 高 | 中 | 高 |
| 仅关键词匹配 | 完全本地 | 低 | 快 | 低 |

**选择：本地嵌入（Transformers.js）+ 远程 AI 可选。** 默认使用本地嵌入模型进行语义搜索，所有历史数据在本地处理，不上传服务器。提供"AI 增强搜索"选项（明确用户授权后），将匿名化的查询向量发送到后端进行更精准的语义匹配。用户可在设置中控制是否启用远程 AI 搜索。

### 决策 2：嵌入模型选择 — all-MiniLM-L6-v2 vs bge-small-zh vs 多语言模型

| 选项 | 体积 | 中文支持 | 英文支持 | 推理速度 |
|------|------|----------|----------|----------|
| all-MiniLM-L6-v2 | ~23MB | 一般 | 优秀 | 快 |
| bge-small-zh | ~24MB | 优秀 | 一般 | 快 |
| multilingual-e5-small | ~30MB | 好 | 好 | 中 |

**选择：multilingual-e5-small（通过 Transformers.js）。** 中国用户的中文浏览历史和中英文混合页面需要多语言支持。multilingual-e5-small 在中文和英文上都表现良好，体积约 30MB（ONNX 量化后约 15MB），通过 Service Worker 缓存，首次加载后持久化。

### 决策 3：历史数据索引策略 — 全量索引 vs 增量索引 vs 懒加载索引

| 选项 | 首次加载 | 搜索速度 | 存储开销 | 实时性 |
|------|----------|----------|----------|------|
| 全量索引 | 慢（数万条） | 快 | 高 | 差 |
| 增量索引 | 快 | 快 | 中 | 好 |
| 懒加载索引 | 快 | 慢 | 低 | 好 |

**选择：增量索引（最近 30 天全量 + 更早的按需索引）。** 首次加载时索引最近 30 天的历史记录（通常 500-2000 条），旧记录在用户滚动或搜索时按需索引。搜索结果分为"最近 30 天"和"更早记录"两个区域。IndexedDB 存储嵌入向量，每条记录约 1.5KB（384 维 float32）。

### 决策 4：AI 历史洞察方案 — 本地分析 vs 远程 AI vs 不提供

| 选项 | 隐私 | 洞察质量 | 实现复杂度 |
|------|------|----------|-----------|
| 本地分析（规则 + 统计） | 完全本地 | 中 | 低 |
| 远程 AI（匿名化统计） | 部分隐私 | 高 | 中 |
| 不提供 | 完全本地 | 无 | 无 |

**选择：本地分析（规则 + 统计）为主，远程 AI 可选。** 默认提供本地生成的历史洞察（最常访问的域名、浏览时间分布、主题趋势），不涉及页面内容分析。用户可授权后，将匿名化的域名统计和访问频率数据发送到后端，获取 AI 生成的个性化洞察（如"你最近对前端性能优化很感兴趣"）。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 语义搜索 | 本地嵌入 | 远程 AI | 混合 | **本地嵌入 + 远程可选** | 隐私优先 |
| 嵌入模型 | MiniLM | bge-small-zh | multilingual-e5 | **multilingual-e5** | 中英文兼顾 |
| 索引策略 | 全量 | 增量 | 懒加载 | **增量索引** | 性能与全面性平衡 |
| AI 洞察 | 本地规则 | 远程 AI | 不提供 | **本地 + 远程可选** | 隐私优先，可扩展 |

```typescript
interface HistoryEntry {
```

### 4.2 历史索引器

```typescript
// src/sw/HistoryIndexer.ts (新增)

import { pipeline, env } from '@xenova/transformers';

class HistoryIndexer {
  private embedder: any = null;
  private db: IDBDatabase | null = null;
  private readonly DB_NAME = 'yipet_history';
  private readonly MODEL_NAME = 'Xenova/multilingual-e5-small';
  private readonly BATCH_SIZE = 50;
  private isIndexing = false;

  /**
   * 初始化嵌入模型
   */
  async initialize(): Promise<void> {
    // 配置 Transformers.js 使用 Service Worker 缓存
    env.cacheHost = 'https://huggingface.co';
    env.useBrowserCache = true;

    this.embedder = await pipeline('feature-extraction', this.MODEL_NAME);
    this.db = await this.openDB();
  }

  /**
   * 增量索引：索引最近 30 天的历史记录
   */
  async indexRecent(): Promise<number> {
    const thirtyDaysAgo = Date.now() - 30 * 24 * 60 * 60 * 1000;
    const items = await this.searchHistory({
      text: '',
      startTime: thirtyDaysAgo,
      maxResults: 5000,
    });

    let indexed = 0;
    for (let i = 0; i < items.length; i += this.BATCH_SIZE) {
      const batch = items.slice(i, i + this.BATCH_SIZE);
      const indexedBatch = await this.indexBatch(batch);
      indexed += indexedBatch;
    }

    return indexed;
  }

  /**
   * 语义搜索历史
   */
  async semanticSearch(query: HistorySearchQuery): Promise<HistorySearchResult[]> {
    // 1. 生成查询向量
    const queryEmbedding = await this.embed(query.text);

    // 2. 获取候选历史记录
    const items = await this.getHistoryItems(query.filter);

    // 3. 获取已索引的嵌入向量
    const embeddings = await this.getEmbeddings(items.map(i => i.id));

    // 4. 计算余弦相似度
    const results: HistorySearchResult[] = [];
    for (const item of items) {
      const emb = embeddings.find(e => e.historyId === item.id);
      if (!emb) continue;

      const score = this.cosineSimilarity(queryEmbedding, emb.vector);
      results.push({
        entry: item,
        score,
        matchType: 'semantic',
      });
    }

    // 5. 排序 + 截断
    return results
      .sort((a, b) => b.score - a.score)
      .slice(0, query.filter.maxResults);
  }

  /**
   * 混合搜索：语义 + 关键词
   */
  async hybridSearch(query: HistorySearchQuery): Promise<HistorySearchResult[]> {
    const [semanticResults, keywordResults] = await Promise.all([
      this.semanticSearch(query),
      this.keywordSearch(query),
    ]);

    // 合并结果，语义和关键词都匹配的加权
    const merged = new Map<string, HistorySearchResult>();

    for (const r of semanticResults) {
      merged.set(r.entry.id, r);
    }

    for (const r of keywordResults) {
      const existing = merged.get(r.entry.id);
      if (existing) {
        existing.score = existing.score * 0.6 + r.score * 0.4;
        existing.matchType = 'both';
      } else {
        merged.set(r.entry.id, r);
      }
    }

    return Array.from(merged.values())
      .sort((a, b) => b.score - a.score)
      .slice(0, query.filter.maxResults);
  }

  /**
   * 关键词搜索（使用 chrome.history API）
   */
  async keywordSearch(query: HistorySearchQuery): Promise<HistorySearchResult[]> {
    const items = await this.searchHistory({
      text: query.text,
      startTime: this.getStartTime(query.filter.timeRange),
      maxResults: query.filter.maxResults * 2,
    });

    return items.map(item => ({
      entry: item,
      score: this.calculateKeywordScore(item, query.text),
      matchType: 'keyword' as const,
    }));
  }

  /**
   * 获取最近访问的页面
   */
  async getRecentVisits(count = 20): Promise<HistoryEntry[]> {
    const items = await this.searchHistory({
      text: '',
      startTime: 0,
      maxResults: count,
    });
    return items.map(this.normalizeHistoryItem);
  }

  /**
   * 生成历史洞察
   */
  async generateInsights(type: 'daily' | 'weekly' | 'monthly'): Promise<HistoryInsight> {
    const timeRange = {
      daily: 24 * 60 * 60 * 1000,
      weekly: 7 * 24 * 60 * 60 * 1000,
      monthly: 30 * 24 * 60 * 60 * 1000,
    };

    const startTime = Date.now() - timeRange[type];
    const items = await this.searchHistory({ text: '', startTime, maxResults: 10000 });

    // 统计分析
    const domainCount = new Map<string, number>();
    const hourCount = new Map<number, number>();

    for (const item of items) {
      const domain = new URL(item.url).hostname;
      domainCount.set(domain, (domainCount.get(domain) || 0) + 1);
      const hour = new Date(item.lastVisitTime).getHours();
      hourCount.set(hour, (hourCount.get(hour) || 0) + 1);
    }

    const topDomains = Array.from(domainCount.entries())
      .sort((a, b) => b[1] - a[1])
      .slice(0, 10)
      .map(([domain, count]) => ({ domain, count }));

    let peakHour = 0;
    let maxCount = 0;
    hourCount.forEach((count, hour) => {
      if (count > maxCount) { maxCount = count; peakHour = hour; }
    });

    const topTopics = this.inferTopics(items);

    return {
      type,
      totalVisits: items.length,
      uniqueDomains: domainCount.size,
      topDomains,
      topTopics,
      peakHour,
      trendDescription: this.generateTrendDescription(topDomains, topTopics),
      generatedAt: Date.now(),
    };
  }

  /**
   * 从历史记录保存到书签
   */
  async bookmarkHistory(request: HistoryBookmarkRequest): Promise<void> {
    await chrome.bookmarks.create({
      parentId: await this.findOrCreateFolder(request.folder || '来自历史'),
      title: request.entry.title,
      url: request.entry.url,
    });
  }

  /**
   * 清除历史记录（带确认）
   */
  async clearHistory(filter: Partial<HistoryFilter>): Promise<number> {
    // 仅清除指定过滤条件的历史
    const items = await this.getHistoryItems(filter as HistoryFilter);
    const urls = items.map(i => i.url);
    await chrome.history.deleteUrl({ url: urls[0] }); // 逐条删除
    // 也有 chrome.history.deleteRange 用于批量时间范围删除
    return urls.length;
  }

  // --- 私有方法 ---

  private async searchHistory(params: {
    text: string;
    startTime?: number;
    endTime?: number;
    maxResults: number;
  }): Promise<chrome.history.HistoryItem[]> {
    return new Promise((resolve) => {
      chrome.history.search(params, (results) => resolve(results));
    });
  }

  private async embed(text: string): Promise<Float32Array> {
    const output = await this.embedder(`query: ${text}`, {
      pooling: 'mean',
      normalize: true,
    });
    return new Float32Array(output.data);
  }

  private async indexBatch(items: chrome.history.HistoryItem[]): Promise<number> {
    const texts = items.map(item => `${item.title} ${item.url}`);
    const embeddings = await this.embedder(texts, {
      pooling: 'mean',
      normalize: true,
    });

    const tx = this.db!.transaction('embeddings', 'readwrite');
    const store = tx.objectStore('embeddings');

    for (let i = 0; i < items.length; i++) {
      const vector = new Float32Array(embeddings[i].data);
      store.put({
        historyId: items[i].id,
        vector,
        text: texts[i],
        createdAt: Date.now(),
      });
    }

    await tx.done;
    return items.length;
  }

  private cosineSimilarity(a: Float32Array, b: Float32Array): number {
    let dotProduct = 0;
    let normA = 0;
    let normB = 0;
    for (let i = 0; i < a.length; i++) {
      dotProduct += a[i] * b[i];
      normA += a[i] * a[i];
      normB += b[i] * b[i];
    }
    return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB));
  }

  private getStartTime(timeRange: HistoryFilter['timeRange']): number | undefined {
    if (typeof timeRange === 'object') return timeRange.start;
    const ranges: Record<string, number> = {
      today: Date.now() - 24 * 60 * 60 * 1000,
      '7days': Date.now() - 7 * 24 * 60 * 60 * 1000,
      '30days': Date.now() - 30 * 24 * 60 * 60 * 1000,
      all: 0,
    };
    return ranges[timeRange] || 0;
  }

  private normalizeHistoryItem(item: chrome.history.HistoryItem): HistoryEntry {
    return {
      id: item.id,
      url: item.url || '',
      title: item.title || '',
      lastVisitTime: item.lastVisitTime || 0,
      visitCount: item.visitCount || 0,
      typedCount: item.typedCount || 0,
      domain: item.url ? new URL(item.url).hostname : '',
    };
  }

  private calculateKeywordScore(item: chrome.history.HistoryItem, query: string): number {
    const title = (item.title || '').toLowerCase();
    const url = (item.url || '').toLowerCase();
    const q = query.toLowerCase();
    const qWords = q.split(/\s+/);

    let score = 0;
    if (title.includes(q)) score += 1.0;
    if (url.includes(q)) score += 0.5;

    for (const word of qWords) {
      if (title.includes(word)) score += 0.3;
      if (url.includes(word)) score += 0.2;
    }

    return Math.min(score, 1.0);
  }

  private inferTopics(items: chrome.history.HistoryItem[]): string[] {
    // 简单的域名到主题映射
    const domainTopics: Record<string, string> = {
      'github.com': '开发',
      'stackoverflow.com': '编程',
      'zhihu.com': '问答',
      'juejin.cn': '前端',
      'docs.python.org': 'Python',
      'developer.mozilla.org': 'Web 开发',
    };

    const topicCount = new Map<string, number>();
    for (const item of items) {
      try {
        const domain = new URL(item.url).hostname;
        for (const [d, topic] of Object.entries(domainTopics)) {
          if (domain.includes(d)) {
            topicCount.set(topic, (topicCount.get(topic) || 0) + 1);
          }
        }
      } catch {}
    }

    return Array.from(topicCount.entries())
      .sort((a, b) => b[1] - a[1])
      .slice(0, 5)
      .map(([topic]) => topic);
  }

  private generateTrendDescription(
    domains: Array<{ domain: string; count: number }>,
    topics: string[]
  ): string {
    if (topics.length === 0) return '暂无足够数据生成趋势描述';
    return `最近主要浏览了 ${topics.slice(0, 3).join('、')} 相关的内容，访问最多的网站是 ${domains[0]?.domain || '未知'}`;
  }

  private async openDB(): Promise<IDBDatabase> {
    return new Promise((resolve, reject) => {
      const request = indexedDB.open(this.DB_NAME, 1);
      request.onupgradeneeded = () => {
        const db = request.result;
        if (!db.objectStoreNames.contains('embeddings')) {
          const store = db.createObjectStore('embeddings', { keyPath: 'historyId' });
          store.createIndex('createdAt', 'createdAt', { unique: false });
        }
      };
      request.onsuccess = () => resolve(request.result);
      request.onerror = () => reject(request.error);
    });
  }

  private async getHistoryItems(filter: HistoryFilter): Promise<HistoryEntry[]> {
    const items = await this.searchHistory({
      text: '',
      startTime: this.getStartTime(filter.timeRange),
      maxResults: 5000,
    });

    let filtered = items.map(this.normalizeHistoryItem);

    // 域名过滤
    if (filter.domains.length > 0) {
      filtered = filtered.filter(item =>
        filter.domains.some(d => item.domain.includes(d))
      );
    }

    if (filter.excludeDomains.length > 0) {
      filtered = filtered.filter(item =>
        !filter.excludeDomains.some(d => item.domain.includes(d))
      );
    }

    // 最小访问次数过滤
    if (filter.minVisitCount > 1) {
      filtered = filtered.filter(item => item.visitCount >= filter.minVisitCount);
    }

    return filtered;
  }

  private async getEmbeddings(historyIds: string[]): Promise<HistoryEmbedding[]> {
    const db = this.db!;
    const tx = db.transaction('embeddings', 'readonly');
    const store = tx.objectStore('embeddings');

    const results: HistoryEmbedding[] = [];
    for (const id of historyIds) {
      const emb = await new Promise<HistoryEmbedding | undefined>((resolve) => {
        const request = store.get(id);
        request.onsuccess = () => resolve(request.result);
        request.onerror = () => resolve(undefined);
      });
      if (emb) results.push(emb);
    }

    await tx.done;
    return results;
  }

  private async findOrCreateFolder(name: string): Promise<string> {
    return new Promise((resolve) => {
      chrome.bookmarks.search({ title: name }, (results) => {
        const folder = results.find(r => r.url === undefined);
        if (folder) {
          resolve(folder.id);
        } else {
          chrome.bookmarks.create({ title: name }, (created) => {
            resolve(created.id);
          });
        }
      });
    });
  }
}
```

## 七、风险与缓解

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Transformers.js 嵌入模型加载失败（网络问题或 HuggingFace 不可用） | 中 | 高 | 降级为关键词搜索模式，功能完全可用但无语义搜索。模型缓存到 Service Worker 后无需网络 |
| 嵌入模型体积过大（约 30MB），首次下载耗时长 | 中 | 中 | 使用 ONNX 量化版本（约 15MB），在扩展安装时后台下载。显示下载进度。Service Worker 缓存持久化 |
| 大量历史记录（> 10000 条）索引耗时过长，影响浏览器性能 | 中 | 中 | 增量索引：仅索引最近 30 天。分批处理（每批 50 条），使用 requestIdleCallback 在空闲时执行 |
| chrome.history API 在某些受管设备上被企业策略禁用 | 低 | 高 | 检测 API 可用性，不可用时提示用户"历史搜索功能不可用，请检查浏览器管理策略" |
| 语义搜索冷启动：用户首次使用时无索引，搜索体验差 | 中 | 中 | 扩展安装后立即后台索引最近 30 天历史。首次搜索时显示"正在建立索引..."提示，同时提供关键词搜索作为降级 |
| 嵌入向量存储占用 IndexedDB 大量空间（每条 1.5KB * 5000 条 = 7.5MB） | 中 | 低 | 30 天以上的索引自动清理。用户可手动清除索引。存储空间告警（> 50MB）时提示用户 |

## 八、回滚策略

| 场景 | 回滚操作 | 影响 |
|------|----------|------|
| Transformers.js 导致 Service Worker 崩溃 | 禁用嵌入模型，降级为纯关键词搜索 | 语义搜索不可用，关键词搜索正常 |
| 嵌入模型下载失败率高 | 扩展包内置轻量级关键词匹配，不依赖外部模型 | 语义搜索不可用 |
| IndexedDB 嵌入向量存储异常 | 清除嵌入向量存储，重建索引 | 语义搜索暂时不可用，重建期间仅关键词搜索 |
| chrome.history API 权限被拒绝 | 隐藏历史搜索功能入口，提示用户检查扩展权限 | 功能不可用 |
| 内存占用过高（索引大量历史） | 减少索引范围为最近 7 天，降低批处理大小 | 搜索范围缩小 |

## 九、设计决策记录

### D-01：语义搜索实现方案

- **问题**：如何在浏览器扩展中实现语义历史搜索，同时保护用户隐私
- **选项**：本地嵌入模型（Transformers.js）、远程 AI（YiAi 后端）、混合方案
- **选择**：本地嵌入模型（Transformers.js）+ 远程 AI 可选
- **理由**：浏览历史是用户最敏感的数据之一，必须优先保护隐私。Transformers.js 的 multilingual-e5-small 模型（ONNX 量化后约 15MB）可在浏览器中高效运行，生成 384 维嵌入向量，余弦相似度计算 < 1ms。远程 AI 作为可选增强，需用户明确授权，仅发送匿名化查询向量。

### D-02：嵌入模型选择

- **问题**：选择哪个嵌入模型，如何平衡体积、准确性和多语言支持
- **选项**：all-MiniLM-L6-v2（英文优秀）、bge-small-zh（中文优秀）、multilingual-e5-small（多语言）
- **选择**：multilingual-e5-small
- **理由**：YiPet 用户主要浏览中文和英文页面，需要多语言嵌入模型。multilingual-e5-small 在中文和英文上均有良好表现，且体积适中（ONNX 量化后约 15MB）。通过 Service Worker 缓存持久化，首次加载后无需重复下载。

### D-03：历史索引策略

- **问题**：如何高效索引大量历史记录，同时保证搜索实时性
- **选项**：全量索引（所有历史）、增量索引（最近 30 天）、懒加载索引（按需）
- **选择**：增量索引（最近 30 天全量 + 更早的按需）
- **理由**：最近 30 天的历史记录是用户最常搜索的（通常 500-2000 条），全量索引这部分数据可在 1-2 分钟内完成。更早的记录通过按需索引覆盖，用户滚动到"更早记录"区域时触发索引。30 天以上的嵌入向量自动清理，控制 IndexedDB 存储 < 10MB。

### D-04：隐私保护策略

- **问题**：如何在提供 AI 增强功能的同时，保护用户浏览历史隐私
- **选项**：全部本地处理、全部远程处理、可选远程增强
- **选择**：默认全部本地处理，用户可选远程 AI 增强
- **理由**：隐私是历史搜索功能的核心约束。默认所有处理（嵌入计算、向量检索、洞察生成）在本地完成，浏览历史数据不离开浏览器。远程 AI 增强作为可选功能，需用户明确操作授权，且仅发送匿名化查询向量（不含具体 URL 或标题）。清晰展示隐私设置，让用户完全掌控数据流向。

## 回归问题预测

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | Transformers.js 在 Service Worker 中加载 ONNX 模型时，由于 SW 内存限制导致模型加载失败或 OOM 崩溃 | Service Worker 的内存限制通常比主线程更严格（约 100-200MB），大型模型可能超出限制 | 使用 ONNX 量化模型（约 15MB），在 SW 启动时分批加载模型权重。监控 SW 内存使用，超过阈值时降级为关键词搜索 |
| 2 | 嵌入模型首次下载超时（HuggingFace CDN 在国内访问较慢），用户等待时间过长，导致搜索功能无法使用 | HuggingFace CDN 在国内部分地区访问速度慢或被阻断 | 配置模型下载镜像（如 hf-mirror.com），显示下载进度。超时 30s 后自动降级为关键词搜索。后续重试时使用断点续传 |
| 3 | chrome.history.search 在某些情况下返回空结果（如隐私模式浏览记录、已清除的历史），但语义搜索的嵌入向量未同步清理，导致搜索结果包含已删除的页面 | 用户清除浏览器历史后，IndexedDB 中的嵌入向量未同步删除，搜索结果中出现"幽灵记录" | 定期（每天）清理 IndexedDB 中不存在于 chrome.history 中的嵌入向量。搜索结果渲染前验证 URL 是否仍可访问 |
| 4 | 历史洞察中的主题推断基于域名到主题的简单映射，但同一域名可能包含多种主题内容（如 github.com 包含前端、后端、AI 等多个主题），导致洞察不准确 | 域名到主题的映射过于粗糙，无法反映同一域名下内容的多样性 | 增加基于页面标题的关键词提取，辅助主题推断。提供"主题不准确？"反馈入口，收集用户纠正数据 |
| 5 | 用户在搜索时切换标签页，Service Worker 的异步搜索回调仍执行，但 Popup 已关闭，搜索结果无处展示或导致状态不一致 | Popup 关闭时异步搜索请求仍在执行，回调时无法更新 UI | 搜索请求带上 requestId，Popup 关闭时取消对应的搜索请求。搜索结果写入 store，Popup 重新打开时展示最新结果 |
| 6 | 嵌入向量存储的 IndexedDB 在浏览器清理缓存时被删除，导致所有已索引的嵌入向量丢失，需要重新索引 | 浏览器清理缓存时可能删除扩展的 IndexedDB 数据，用户不明所以 | 检测 IndexedDB 是否为空（但 chrome.history 有数据），自动触发重建索引。显示"正在重建搜索索引..."提示 |
