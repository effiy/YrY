## 概述

本需求文档合并了 YiPet 浏览器扩展中的 18 个图片高级编辑工具，涵盖图层管理、AI 抠图、背景替换、元数据编辑、几何变形、超分辨率放大、水印去除、频率域处理、通道操作、阈值/边缘检测、直方图处理、质量评估与图像分析等完整的高级图片编辑能力。

所有工具基于浏览器端 Canvas API 实现，部分 AI 功能通过 YiAi 后端 RPC 调用 Ollama 模型，遵循 YiPet 的 API 分层架构。

## 1. 图片分层编辑器 (YP-09-255)

### 背景

当前 YiPet 图片编辑器是扁平化的——所有编辑操作直接作用在原始图片上，无法撤销单个操作，无法调整元素叠加顺序，无法独立控制透明度。需要引入基于图层的非破坏性编辑系统。

### 核心设计

**图层存储模型**: 独立图层模型。每层独立存储渲染数据，图层面板直接操作任意层，撤销/重做通过图层历史快照实现。

**混合模式**: 支持 15 种混合模式——11 种 Canvas `globalCompositeOperation` 原生模式 + 4 种手动实现 (hue/saturation/color/luminosity)。

**图层数量**: 上限 10 层——覆盖典型场景 (1 背景 + 2 图片 + 2 文字 + 1 边框 + 1 贴纸 + 1 调整层)。

**核心类型**:

```typescript
type LayerType = 'background' | 'image' | 'text' | 'frame' | 'sticker' | 'adjustment';
type BlendMode = 'normal' | 'multiply' | 'screen' | 'overlay' | 'darken' | 'lighten' | 'color-dodge' | 'color-burn' | 'hard-light' | 'soft-light' | 'difference' | 'exclusion' | 'hue' | 'saturation' | 'color';

interface Layer {
  id: string; name: string; type: LayerType; visible: boolean; locked: boolean;
  opacity: number; blendMode: BlendMode; order: number;
  content: LayerContent; transform: LayerTransform;
  _thumbnail?: ImageData; _dirty: boolean;
}

interface LayerState {
  layers: Layer[]; activeLayerId: string | null; canvasWidth: number; canvasHeight: number;
  history: LayerSnapshot[]; historyIndex: number; maxHistorySize: number;
}
```

**LayerManager 核心方法**: addLayer / removeLayer / duplicateLayer / moveLayer / updateLayer / mergeVisible / flatten / undo / redo / getLayerThumbnail

**增量渲染**: 脏标记 (_dirty) 系统——仅重绘变化的图层，10 层合成 < 50ms。

**撤销/重做**: 图层参数快照 (JSON)，每次 < 10KB，最多 50 步历史。

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/types/layer.ts` | 新增 | 图层类型定义 |
| `src/services/layer-manager.ts` | 新增 | 图层管理器 (CRUD + 渲染 + 撤销) |
| `src/components/layer-panel.vue` | 新增 | 图层面板 UI |

### 测试规格

- 创建多个图层: 4 层，顺序一致
- 图层可见性切换: 独立隐藏/显示
- 图层顺序调整: 拖拽排序，渲染顺序正确
- 图层透明度 + 混合模式: 0.5 透明度 + multiply 混合正确
- 合并/展平: mergeVisible 排除隐藏层，flatten 包含所有层
- 撤销/重做: 3 次撤销 → 初始状态，3 次重做 → 最终状态

## 2. 图片背景移除 (YP-09-235)

### 背景

用户在制作产品图、证件照、社交媒体素材时需要移除图片背景，但 YiPet 完全没有背景移除能力。需要 AI 抠图 + 手动修饰的实现。

### 核心设计

**AI 抠图双方案**:
- **主力**: YiAi 后端 RPC 调用 (SAM/U2Net 模型)，精度最高
- **降级**: 浏览器端 ONNX Runtime WebGL (RMBG-1.4)，离线可用
- **兜底**: 简单色差法 (对白底产品图效果可接受)

**RPC 调用流程**: 客户端压缩图片 ≤ 2000px → `POST / RPC: remove_background.remove({ image: base64 })` → YiAi 运行分割模型 → 返回 Alpha 蒙版 base64

**手动修饰**: 保留/移除双画笔，画笔硬度 0-100%

**边缘优化**: 羽化 (高斯模糊)、膨胀/腐蚀 (形态学操作)、Alpha Matting (可选)

**背景替换**: 纯色合成 + 图片背景合成 (cover/contain/stretch)

**导出**: PNG (透明背景) / JPEG (合成白色背景) / WebP

**核心类型**:

```typescript
interface AlphaMask {
  data: Uint8ClampedArray;  // 0-255 灰度，0=背景, 255=主体
  width: number; height: number;
  method: 'ai' | 'manual';
  confidence?: Float32Array;
}
```

**关键算法**: `featherMask()` (高斯模糊蒙版), `dilateOrErodeMask()` (形态学膨胀/腐蚀), `applyMaskToImage()` (蒙版 → 透明背景), `compositeSolidBg()` / `compositeImageBg()` (背景替换合成)

## 3. 图片背景替换 (YP-09-281)

### 背景

背景替换是证件照制作、电商产品展示、社交媒体创作的核心需求。需要浏览器端主体检测 + 多类型背景替换的一体化工具。

### 核心设计

**主体检测策略**: 颜色对比度 + 边缘检测 (Canny) + 形态学操作，无 ML 模型依赖

**四种背景类型**:
- **纯色** (solid): 证件照/产品照，预设白/蓝/红 + 自定义取色器
- **渐变** (gradient): 水平/垂直/对角线方向
- **图片** (image): 自定义背景图，cover/contain/stretch fit
- **模糊** (blur): 原图高斯模糊，隐私保护

**绿幕抠图**: 自动检测绿色占比 > 40% → 切换到 HSV 颜色键控模式，溢出抑制消除绿色反光

**边缘精细化**: 简单羽化 (默认) + Alpha Matting (可选)

**核心类型**:

```typescript
type BackgroundType = 'solid' | 'gradient' | 'image' | 'blur';
type BackgroundConfig = SolidBackground | GradientBackground | ImageBackground | BlurBackground;

interface ForegroundMask {
  width: number; height: number;
  data: Float32Array;  // 0-1 alpha
  generatedBy: 'auto' | 'chroma-key' | 'manual';
  confidence: number;
}

interface ChromaKeyConfig {
  targetColor: { h: number; s: number; v: number };
  hueTolerance: number; saturationTolerance: number; valueTolerance: number;
  spillSuppression: boolean; spillStrength: number;
}
```

**ChromaKeyer 算法**: RGB → HSV → 色相环绕距离 → 容差判定，溢出抑制将绿色反射向品红偏移

**BackgroundCompositor**: 渲染四种背景 → `output = foreground * alpha + background * (1 - alpha)`

## 4. 图片元数据编辑 (YP-09-242)

### 背景

浏览器端可读取 EXIF 但无法写入——Canvas toBlob 丢弃所有元数据。需要实现 JPEG 二进制级别的元数据编辑。

### 核心设计

**实现方案**: piexifjs 读写 EXIF + 自定义 JPEG 段重组器

**JPEG 文件结构解析**: SOI → APP0/JFIF → APP1/EXIF → APP13/IPTC → DQT → SOF → DHT → SOS → 图像数据 → EOI

**支持字段**:
- EXIF: Artist, Copyright, Make, Model, DateTimeOriginal, DateTimeDigitized, GPS
- IPTC 核心 5 字段: 标题/描述/作者/版权/关键词

**格式范围**: 仅 JPEG (80% 场景覆盖)，PNG/WebP 后续迭代

**GPS 编辑**: 编辑坐标 (DD/DMS 转换) + 一键移除，不集成地图

**核心类 MetadataEditor**:

```typescript
class MetadataEditor {
  async editJPEGMetadata(sourceBuffer: ArrayBuffer, fields: MetadataFields): Promise<ArrayBuffer>
  async removeGPS(sourceBuffer: ArrayBuffer): Promise<ArrayBuffer>
  private parseJPEGSegments(data: Uint8Array): JPEGSegment[]
  private extractEXIF(data, segments): any
  private extractIPTC(data, segments): any
  private mergeEXIFFields(exifData, fields): any
  private mergeIPTCFields(iptcData, fields): Record<number, string>
  private rebuildJPEG(source, segments, newExifData, newIptcData): ArrayBuffer
  private decimalToDMS(decimal: number): [number, number][][]
}
```

**JPEG 重组流程**: 遍历段 → 定位 APP1/APP13 → 替换新数据 → 更新段长度和偏移 → 重组 ArrayBuffer

## 6. 图片变形工具 (YP-09-266)

### 背景

图片需要透视矫正、仿射变换、网格变形、液化效果等几何变换——但 YiPet 当前仅有基础旋转。需要像素级变形工具。

**典型场景**:
1. 仰拍建筑物 → 梯形变形 → 透视变换恢复正视效果
2. 人像精修 → 脸部微调/身材修饰 → 液化工具推/捏
3. 书页弯曲 → 非均匀矫正 → 网格变形局部调整
4. 创意变形 → 旋转/缩放/倾斜组合 → 仿射变换

**挑战**: 透视变换像素映射产生锯齿 (需双线性/双三次插值)，液化大笔刷实时预览性能，全分辨率 ImageData 快照内存管理

### 核心设计

**四种变形模式**:

1. **透视变换**: 3x3 单应矩阵，四角自由拖动，双线性/双三次插值
2. **仿射变换**: 旋转/缩放/平移/剪切，拖动控制柄交互
3. **网格变形**: NxM 控制点网格 (默认 5x5)，自由拖动变形
4. **液化工具**: 推 (push)/捏 (pinch)/膨胀 (bloat)，可调笔刷大小/强度/硬度

**透视变换数学**: 使用 3x3 单应矩阵 H，给定 4 个对应点 → 解线性方程组 → H 矩阵 → 逆向映射 (目标坐标 → 源坐标) → 插值采样。

**仿射变换数学**: 2x3 矩阵 `[a b c; d e f]`→ `x' = a*x + b*y + c; y' = d*x + e*y + f`，6 自由度 → 3 对不共线点求解。

**变换插值**: 双线性插值 (4 邻域，默认) + 双三次插值 (16 邻域，高质量选项)。双三次使用 Catmull-Rom 样条核。

**液化交互**:
- 推 (Push): 沿鼠标拖动方向移动像素
- 捏 (Pinch): 笔刷半径内像素向中心收缩 (Gaussian 权重衰减)
- 膨胀 (Bloat): 笔刷半径内像素向外膨胀 (与 Pinch 方向相反)
- 恢复 (Restore): 笔刷区域内像素恢复为原始值

**撤销/重做**: 全分辨率 ImageData 快照，限制 20 步，每步 ~4MB (1920x1080 RGBA)，总计 ~80MB 内存预算。

**性能优化**: 液化大笔刷 → requestAnimationFrame 节流 → 每帧仅重绘变化区域 → OffscreenCanvas 双缓冲

- 透视矫正: 拍摄倾斜的矩形门框 → 拖动四角 → 门框变为正矩形 → 垂直线平行
- 仿射变换: 旋转 45° + 缩放 0.8 → 预览反映变换 → 应用后像素准确
- 网格变形: 拖动网格控制点 → 局部区域跟随变形 → 未拖动区域保持原样
- 液化推: 笔刷拖动 → 像素沿轨迹移动 → 边缘柔和无硬切
- 液化捏: 笔刷点击鼻翼 → 像素向内收缩 → 左右对称操作一致
- 撤销/重做: 5 步液化 → 撤销 5 次 → 回到原始图片

### 回归问题预测

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | 透视变换后图片边缘出现黑边 | 逆向映射超出源图范围 → 未处理边界像素 | 透视矫正后检查四边 → 无黑边或透明区域 |
| 2 | 液化笔刷在图片边缘附近触发错误 | 笔刷中心接近边缘时邻域采样越界 | 在图片边缘使用液化工具 → 验证无异常 |
| 3 | 网格变形控制点拖出 canvas 范围 | 控制点无边界限制 → 变形结果扭曲 | 控制点拖动到边缘 → 验证被限制在画布内 |
| 4 | 快速连续笔刷导致帧跳过 → 变形不连贯 | requestAnimationFrame 节流导致中间帧丢失 | 快速连续涂抹 → 验证变形连续无跳跃

## 7. 图片放大工具 (YP-09-239)

### 背景

用户需要放大低分辨率图片——老照片修复、网页小图放大、截图文字放大。简单 CSS/Canvas 缩放模糊不堪，需要 AI 超分辨率 + 传统插值双重方案。

**典型场景**:
1. 老照片修复: 200x200 旧照片 → 800x800 打印 → 直接拉伸模糊
2. 网页小图: 50x50 缩略图 → 放大查看细节 → 浏览器原生缩放仅像素插值
3. 截图文字: 12px UI 标签文字 → 放大阅读 → 需要智能锐化
4. 头像/Logo: 64x64 → 高清版本 → bicubic 放大后仍不够清晰

**关键挑战**: AI 模型推理需要 GPU/后端，大图处理耗时，放大后无法直观对比原图。

### 核心设计

**双方案**:
- **AI 超分辨率**: YiAi 后端 RPC 调用 (ESRGAN/Real-ESRGAN)，2x/4x 放大
- **传统插值降级**: bicubic / lanczos 插值，纯前端，离线可用

**bicubic 插值算法**: 使用 4x4 像素邻域，Catmull-Rom 样条核，对每个目标像素在源图中计算 16 个邻域点的加权平均。

**lanczos 插值算法**: 使用更大的核 (a=2 时 4x4 采样窗，a=3 时 6x6 采样窗)，`L(x) = sinc(x) × sinc(x/a) for |x| < a else 0`，提供比 bicubic 更锐利的放大效果。

**细节增强**: AI 放大后应用 USM (Unsharp Mask) 锐化 → 创建高斯模糊副本 → `sharpened = original + (original - blurred) × amount` → amount 默认 50%，radius 1-3px

**前后缩放对比**: 分屏垂直分割线 → 左侧原图/右侧放大结果 → 同步缩放和平移 (两个 canvas 的 transform 保持一致)

**裁剪预览**: 用户框选感兴趣区域 → 仅放大该区域 → 避免处理整张 4000x3000 超大图

**后端 RPC 调用**: 图片压缩 ≤ 2000px → `POST / RPC: super_resolution.upscale({ image: base64, scale: 2|4 })` → 返回放大后图片 base64

| `YiPet/src/components/tools/ImageUpscaler.vue` | 新增 | 放大工具主界面 |

- AI 2x 放大: 低分辨率人脸 → YiAi super_resolution → 2x 放大后脸部细节恢复 → 清晰度明显提升

## 8. 图片水印去除 (YP-09-228)

### 背景

分享图片常带有社交媒体水印、截图工具水印或不想要的文字。浏览器端没有 AI 修复算法，提供三种有限但实用的方法。

**典型场景**:
1. 社交媒体水印: 小红书/抖音图片底部自动加水印
2. 截图工具水印: 免费工具右下角品牌水印
3. 不需要的文字: 图片上多余标注文字
4. 角落 Logo: 裁剪直接去除是最佳方案

**局限性**: 不支持大面积/中心水印智能去除，不替代 Photoshop 内容感知填充。UI 中必须明确声明功能边界，管理用户预期。

### 核心设计

**三种去水印方法**:

1. **修复涂抹** (Healing Brush): 在水印边界采样周围像素 → 加权平均 (距水印越近权重越高) → 填充水印区域。适合背景单一、纯色水印。

2. **仿制图章** (Clone Stamp): 用户 Alt+点击选择源区域 → 涂抹目标区域 → 源点和笔刷相对位置保持固定 → 逐像素复制。适合有纹理的背景。

3. **裁剪去除** (Crop): 直接裁剪掉含水印的边缘区域，最快最简单，但会损失图片尺寸。

**修复涂抹算法详解**:
1. 用户涂抹目标区域 (水印区域)
2. 沿目标区域边界采样周围像素 (band width = brush radius)
3. 对边界的每个源像素，计算到目标区域内部的距离
4. 目标区域每个像素 = 边界像素的加权平均 → weight = 1 / distance²
5. 边缘混合: 修复区域边缘与周围像素做 alpha 渐变 (2-5px transition)

**仿制图章交互**:
1. 按住 Alt → 鼠标变为十字取色器 → 点击选择源点
2. 松开 Alt → 鼠标变回笔刷 → 涂抹目标区域
3. 源点和笔刷相对位置保持固定 (源点跟随笔刷移动)
4. 笔刷大小和硬度可调 → 硬度 < 50% 时边缘羽化

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/watermark-removal.ts` | 新增 | 修复涂抹 + 仿制图章算法 |
| `src/components/tools/WatermarkRemover.vue` | 新增 | 水印去除主界面 |

- 修复涂抹: 纯色背景上的小文字 → 涂抹区域被填充为背景色 → 无明显痕迹

## 9. 图片直方图匹配 (YP-09-264)

### 背景

直方图匹配将源图灰度分布变换为目标图分布——实现色调风格统一。多张照片因不同拍摄条件颜色不一致，需要自动化色调匹配。手动调整亮度/对比度/饱和度只能做线性变换——无法实现参考图直方图那种非线性的色调映射。

**核心算法**: 计算源图直方图 → 计算源图 CDF → 计算参考图 CDF → 对源图每个亮度值，在参考图 CDF 中找到最接近的 CDF 值对应的亮度值 → 建立像素映射 LUT (Look-Up Table) → 逐像素应用 LUT。这是经典的直方图规定化 (Histogram Specification) 算法。

### 核心设计

**匹配模式**:
- **参考图匹配**: 用户选择参考图 → 计算双方 CDF → 查找映射函数 → 逐像素映射
- **预设分布**: 正态分布/均匀分布/对数正态——一键标准化，无需参考图
- **颜色迁移**: 仅在 L*a*b* 颜色空间的 L 通道做匹配 (保留 a*/b* 颜色信息)

**通道处理**: 支持 RGB 三通道分别匹配 (每个通道独立 CDF 映射) + 仅亮度通道匹配 (保持色相/饱和度)

**直方图可视化**: 匹配前后直方图对比 + CDF 曲线叠加显示。直方图使用 Canvas 柱状图，CDF 使用线图叠加在同一 chart 上。

**预设分布公式**:
- 均匀分布: PDF(x) = 1/256, CDF(x) = x/256
- 正态分布: PDF(x) = N(128, 40²), CDF 通过误差函数 erf 计算
- 对数正态: PDF(x) = 1/(xσ√2π) × exp(-(ln(x)-μ)²/(2σ²))

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/histogram-match.ts` | 新增 | 直方图匹配引擎 + CDF 映射 |
| `src/components/tools/HistogramMatch.vue` | 新增 | 直方图匹配面板 + 直方图可视化 |

### 测试规格

- 参考图匹配: 选中偏暖参考图 → 应用到偏冷源图 → 源图色调变暖 → 两张图色调风格一致
- 均匀分布: 对比度低的灰蒙蒙照片 → 均匀分布 → 对比度显著增强 → 直方图趋于平直
- 颜色迁移: 仅 L 通道匹配 → 颜色信息保留 → 色调统一但原图色彩不变
- 直方图对比: 匹配后 → 查看前后直方图 → CDF 曲线明显靠近参考图 CDF
- 通道独立匹配: RGB 分别匹配 → 可能产生色偏 → 用户可选切换到 L 通道模式

## 10. 图片频率域处理 (YP-09-265)

### 背景

频率域处理可以对图片进行频域滤波——去除周期性噪声、选择性平滑/锐化。空间域的卷积操作在频率域转化为简单的乘法运算，处理速度更快且可视化直观。

**典型场景**:
1. 印刷品扫描 → 摩尔纹去除 → 陷波滤波器
2. 老照片 → 扫描线/网格去除 → 频率域掩蔽
3. 选择性锐化 → 高通滤波器增强高频 → 边缘更清晰
4. 平滑降噪 → 低通滤波器抑制高频噪声

### 核心设计

**FFT 实现**: 基于 2D Cooley-Tukey FFT 算法，支持 2 的幂尺寸 (不足时 zero-padding)。复杂度 O(N log N)。

**2D FFT 分解**: `FFT2D(image) = FFT_rows(FFT_columns(image))`，先对每行做 1D FFT，再对每列做 1D FFT。

**滤波器类型和数学定义**:

| 滤波器 | 类型 | 频域传递函数 H(u,v) |
|--------|------|-------------------|
| 理想低通 | LPF | H = 1 if D ≤ D0 else 0 |
| Butterworth 低通 | LPF | H = 1 / (1 + (D/D0)^(2n)) |
| Gaussian 低通 | LPF | H = exp(-D² / (2×D0²)) |
| 理想高通 | HPF | H = 1 if D > D0 else 0 |
| Butterworth 高通 | HPF | H = 1 / (1 + (D0/D)^(2n)) |
| Gaussian 高通 | HPF | H = 1 - exp(-D² / (2×D0²)) |
| 带通 | BPF | H = HPF₁ × LPF₂ (D0₁ < D < D0₂) |
| 陷波 | Notch | H = 1 - Gaussian_band(x-x0, y-y0) |

其中 D = √(u² + v²)，D0 = 截止频率，n = 阶数

**频域可视化**: 对数振幅谱 → `log(1 + |F(u,v)|)`，中心化 (fftshift——低频移到中心)，0-1 归一化后作为灰度图显示。

**滤波器设计 UI**: 在频谱图上绘制矩形/圆形/环形选区 → 选区内为保留区域 (1.0)，选区外衰减 (Gaussian 过渡)

**处理流程**: 图片 → 转灰度 → 取 2 的幂尺寸 → FFT → 频谱显示 → 应用滤波器 → IFFT → 裁剪回原始尺寸

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/fft.ts` | 新增 | 2D FFT/IFFT 实现 + fftshift |
| `src/utils/image/frequency-filters.ts` | 新增 | 各类型频域滤波器 |
| `src/components/tools/FrequencyDomain.vue` | 新增 | 频率域处理面板 + 频谱显示 |

### 测试规格

- FFT/IFFT 保真度: 图片 → FFT → IFFT → 与原始像素差 < 1 (浮点舍入误差)
- 理想低通: D0=30 → 高频噪声被抑制 → 图片变平滑 → 无明显振铃 (但可能有)
- Gaussian 低通: D0=30 → 平滑效果 → 无振铃 → 比理想低通更自然
- 高通滤波: D0=50 → 边缘被增强 → 平坦区域变暗
- 陷波滤波器: 含摩尔纹图片 → 在频谱图中标记周期性亮点 → 陷波后 → 摩尔纹消失
- 频谱可视化: FFT 后 → 显示对数振幅谱 → 中心亮度最高 (低频能量大)

### 核心设计

**通道选择器面板**: 按钮组，选中通道高亮，多选时叠加显示

**通道作为蒙版**: 任意通道可导出为 Alpha 蒙版 → 直接用于背景移除 (YP-09-235) 或阈值处理 (YP-09-261)

## 12. 图片阈值处理 (YP-09-261)

### 背景

阈值处理将灰度图二值化——用于文档扫描增强 (去除背景/增强文字)、蒙版创建 (前景/背景分离)、图像分割。自动阈值算法 (Otsu) 可以无需人工调整阈值。

### 核心设计

**阈值模式**:
- **全局二值化**: 滑块设置阈值 0-255，`if (pixel > threshold) 255 else 0`
- **自适应阈值**: 局部 NxN 窗口内的均值或高斯加权均值作为每个像素的阈值。`if (pixel > localMean - C) 255 else 0`，C 为偏移常量 (默认 2)
- **Otsu 自动阈值**: 最大化类间方差的自动阈值。遍历 0-255 → `σ² = w₁ × w₂ × (μ₁-μ₂)²` → 选择最大化 σ² 的阈值
- **反向阈值**: 黑白反转，`if (pixel > threshold) 0 else 255`
- **截断阈值**: 高于阈值截断为阈值 `min(pixel, threshold)`，低于保持不变

**应用模式**:
- **灰度输出**: 二值化结果作为灰度图直接显示
- **蒙版应用**: 二值化结果作为 Alpha 蒙版应用到原图 → `output = original × mask/255`

**直方图辅助**: Canvas 绘制灰度直方图 → 红色竖线叠加当前阈值位置 → 帮助用户判断最佳阈值点 (两峰之间的谷底)

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/threshold.ts` | 新增 | 全局/自适应/Otsu/反向/截断阈值 |
| `src/components/tools/ThresholdPanel.vue` | 新增 | 阈值处理面板 + 直方图 |

### 测试规格

- Otsu 文档扫描: 白底黑字文档 → Otsu → 自动找到最佳阈值 → 文字清晰/背景纯白
- 自适应阈值: 光照不均的文本 → 全局 (128) 效果差 → 自适应 15x15 窗口 → 各区域文字清晰
- 蒙版应用: 二值化人像 → 白=人/黑=背景 → 应用蒙版 → 人像保留/背景透明
- 反向阈值: 白底黑图 → 反向 → 黑底白图 → 适合特定视觉效果
- 直方图辅助: 双峰直方图 → 阈值线显示在谷底位置 → 用户微调节省时间

## 13. 图片边缘检测 (YP-09-262)

### 背景

边缘检测是图像分析的基础——用于轮廓提取、图像分割辅助、风格化效果。不同算法侧重不同: Sobel 快速简单，Canny 精细但计算量大。

### 核心设计

**检测算法**:

| 算法 | 类型 | 核大小 | 特点 |
|------|------|--------|------|
| Sobel | 一阶导数 | 3x3 | Gx/Gy 分别计算水平/垂直梯度，G = √(Gx²+Gy²) |
| Prewitt | 一阶导数 | 3x3 | 类似 Sobel，权重均匀 (无中心加权) |
| Laplacian | 二阶导数 | 3x3/5x5 | 检测零交叉点 (zero-crossing)，各向同性 |
| Canny | 多级 | 自适应 | 高斯平滑 → 梯度 → 非极大值抑制 → 双阈值 → 滞后跟踪 |

**Sobel 核**:
```
Gx = [[-1,0,1],[-2,0,2],[-1,0,1]]
Gy = [[-1,-2,-1],[0,0,0],[1,2,1]]
```
梯度幅值: `|G| = √(Gx² + Gy²)`，方向: `θ = atan2(Gy, Gx)`

**Canny 算法流程**:
1. 高斯平滑 (sigma=1.4) 去噪
2. Sobel 计算梯度和方向
3. 非极大值抑制 (NMS): 沿梯度方向，保留局部最大值，抑制非边缘
4. 双阈值: 高阈值 (如 100) 标记强边缘，低阈值 (如 30) 标记弱边缘
5. 滞后跟踪: 弱边缘像素若与强边缘连通 (8-neighbor) 则保留，否则丢弃

**边缘可视化**:
- **灰度边缘**: 梯度幅值作为灰度值 → 白=强边缘/黑=无边缘
- **边缘方向彩色编码**: 0°/45°/90°/135° 方向 → 映射为 4 种颜色 → 直观展示边缘方向分布
- **边缘叠加**: 边缘 50% 透明度叠加到原图 → 同时看到原图内容和检测边缘

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/edge-detection.ts` | 新增 | Sobel/Prewitt/Laplacian/Canny |
| `src/components/tools/EdgeDetection.vue` | 新增 | 边缘检测面板 + 算法选择 |

### 测试规格

- Sobel: 含清晰边缘图片 → Gx 显示垂直边缘 → Gy 显示水平边缘 → 合成梯度完整
- Canny vs Sobel: 同一图片 → Canny 边缘更细更连续 → Sobel 边缘更粗
- 方向编码: 选取方向编码 → 水平边缘红色/垂直蓝色 → 方向分布一目了然
- 边缘叠加: 边缘叠加到原图 → 调整透明度 → 0% 仅原图 / 100% 仅边缘
- Canny 双阈值: 调高高阈值 → 边缘减少/更可靠 → 调低低阈值 → 边缘增加/弱边缘被加入

## 14. 图片直方图均衡 (YP-09-263)

### 背景

直方图均衡是自动对比度增强的经典方法——尤其适合曝光不足/过度的照片。CLAHE (自适应直方图均衡) 解决了全局均衡的过增强问题。

### 核心设计

**均衡模式**:
- **全局均衡**: `g(x,y) = CDF[f(x,y)] × 255`，将最暗像素映射到 0，最亮映射到 255。缺点: 噪声区域被过度增强。
- **CLAHE** (Contrast Limited Adaptive Histogram Equalization): 将图片分为 NxN tiles (默认 8x8) → 每 tile 局部均衡 → clip limit 限制对比度 (裁剪超出直方图 bin 上限的部分，均匀分配) → 双线性插值消除 tile 边界块效应。
- **LAB 亮度均衡**: 仅对 LAB 空间的 L 通道做均衡 → 保留 a*/b* 颜色信息 → 避免色彩偏移。

**直方图展示**:
- **合成直方图**: RGB 三通道叠加 (半透明)，快速了解整体曝光
- **分通道直方图**: R/G/B 三个独立柱状图，分析各通道分布
- **累积直方图 (CDF)**: 叠加累计分布曲线 → 直线=均匀曝光/弯曲=过度曝光
- **导出直方图数据**: CSV (256 行) 或 JSON → 用于外部分析

**CLAHE 参数**: tile size (4/8/16/32)，clip limit (1-10，建议 3-4)

**算法**: 全局: `s = T(r) = (L-1) ∫₀ʳ pᵣ(w) dw`，离散化为 `sₖ = (L-1) × Σⱼ₌₀ᵏ nⱼ/N`。CLAHE: 分块 → 各块局部均衡 → clip limit 裁剪 → 双线性插值

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/histogram-equalize.ts` | 新增 | 全局/CLAHE 均衡算法 |
| `src/utils/image/histogram-chart.ts` | 新增 | 直方图 Canvas 可视化 |
| `src/components/tools/HistogramEqualize.vue` | 新增 | 直方图均衡面板 |

### 测试规格

- 全局均衡: 暗照片 → 直方图集中在低值 → 均衡后拉伸到 0-255 → 对比度明显增强
- CLAHE vs 全局: 含天空(亮)和地面(暗)的照片 → 全局: 天空过曝 → CLAHE: 天空和地面都增强
- LAB 亮度: 仅均衡 L 通道 → 色彩不变 → 不会出现全局均衡的荒诞色调
- Tile 边界消除: CLAHE tile=8 → 放大 400% → 观察 tile 边界 → 双线性插值后无明显分块
- Clip limit 效果: clip=1 → 过度增强/噪声放大 → clip=5 → 均衡温和自然

## 15. 图片清晰度评估 (YP-09-283)

### 背景

批量照片需要快速筛选清晰/模糊图片，手动逐张检查效率低。自动化清晰度评分可以根据客观量化指标判断图片是否可用。

### 核心设计

**多算法评分**:

| 算法 | 原理 | 权重 | 数学定义 |
|------|------|------|---------|
| Laplacian 方差 | Laplacian 卷积 → 像素方差 | 40% | Var(L∗I)，其中 L = [[0,1,0],[1,-4,1],[0,1,0]] |

**评分输出**:
- 0-100 分 (越高越清晰)
- 等级: 优秀 (90+) / 良好 (70-90) / 一般 (50-70) / 模糊 (30-50) / 极模糊 (< 30)
- 各算法分项得分 + 加权总分 + 评估耗时

**批量评估**: 多图逐一评分 → 按清晰度排序 → 过滤低于阈值 → 标记红色/黄色/绿色

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/sharpness.ts` | 新增 | Laplacian/Brenner/FFT 算法 |
| `src/components/tools/SharpnessEval.vue` | 新增 | 清晰度评估面板 + 批量排序 |

### 测试规格
- 高清照片: 锐利对焦 → 得分 90+ → 优秀等级
- 运动模糊: 慢快门 → 得分 30-50 → 模糊等级 → 建议重拍
- 三算法一致性: 三算法得分趋势一致 → 无矛盾 (一张图不应同时高 Laplacian 低 FFT)
- 批量排序: 10 张混合质量 → 按分排序 → 清晰的在前面

## 16. 图片噪点评估 (YP-09-284)

### 背景

高 ISO 照片、低光环境拍摄存在明显噪点。需要自动检测噪点水平并提供有针对性的降噪建议。

### 核心设计

**评估方法**: 局部方差分析——将图片分成 8x8 块 → 每块计算灰度方差 → 对平坦块 (方差最小) 的方差取平均 → 平坦区域的方差主要由噪声贡献 = 噪点水平估计

**噪点类型区分**:
- **亮度噪点**: 灰度通道方差 (Y = 0.299R+0.587G+0.114B)
- **色度噪点**: LAB 空间 a*/b* 通道方差 → 体现色彩噪声

**评分输出**:
- 噪点水平 0-100 (越高越严重，反转显示: 100-噪点分=清晰度)
- 等级: 无噪点 (0-15) / 轻微 (15-30) / 中度 (30-50) / 明显 (50-70) / 严重 (70+)
- 等效 ISO 估计: 基于噪点水平的 ISO 范围 (如 噪点 20→ISO 200-400，噪点 60→ISO 3200-6400)
- 降噪建议: 根据噪点类型和水平的针对性建议

**降噪建议映射**:
- 轻微亮度噪点 → 轻度高斯模糊 (sigma 0.5-1.0)
- 中度量噪+色噪 → 双边滤波 (sigmaColor 30/sigmaSpace 5)
- 严重噪点 → 非局部均值降噪 (NLM) 或建议使用外部降噪工具
- 仅色噪 → LAB 空间 a/b 通道降噪 → L 通道保留细节

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/noise-eval.ts` | 新增 | 局部方差 + LAB 通道噪点评估 |
| `src/components/tools/NoiseEval.vue` | 新增 | 噪点评估面板 + 降噪建议 |

### 测试规格
- 低 ISO 照片: ISO 100 → 噪点分 < 15 → 无噪点等级
- 高 ISO 照片: ISO 6400 → 噪点分 > 50 → 明显等级 → 建议降噪
- 亮噪 vs 色噪: 一张亮噪为主 → 评估正确 → 建议空间域降噪 / 色噪为主 → 建议 LAB 降噪
- 平坦 vs 纹理: 天空区域检测噪点 vs 草地纹理 → 天空噪点高/草地方差大但不是噪点 → 正确区分

## 17. 图片构图分析 (YP-09-285)

### 背景

用户拍摄的照片构图不尽如人意。客观的构图评估可以帮助裁剪改善——如将主体移到三分线交点。

### 核心设计

**四维度评分**:

| 维度 | 检测方法 | 权重 | 评分逻辑 |
|------|---------|------|---------|
| 三分法 | 显著性区域中心与三分线交点距离 | 35% | 距离 ≤ 10% 画布宽 → 满分；距离 > 20% → 0 |
| 黄金螺旋 | 对数螺旋端点与显著区域距离 | 20% | 距螺旋终点 5% 内 → 满分 |
| 对称性 | 水平翻转差分 | 25% | 平均绝对差 < 10 → 满分 |
| 水平线 | Hough 直线检测倾斜角度 | 20% | 角度偏差 < 1° → 满分 |

**三分法检测**: Saliency detection → 显著性热力图 → 找到 4 个显著区域的中心 → 计算与 4 个三分线交点 (0.33,0.33)/(0.66,0.33)/(0.33,0.66)/(0.66,0.66) 的最小欧氏距离 → 归一化为 0-100

**黄金螺旋**: 画布上绘制对数螺旋 `r = a × e^(bθ)`，b = ln(φ)/(π/2) → 螺旋终点在画布中的位置固定 → 计算显著区域中心与终点的距离

**对称性**: 水平翻转 → |原图 - 翻转图| → 均方误差 (MSE) → 归一化 → 评分 = 100 - MSE×100

**水平线**: Canny 边缘 → HoughLinesP → 找 10 条最长的水平线段 (±10° 内) → 计算加权平均倾斜角度 (按段长度加权) → |角度| < 0.5° → 100 分

**输出**: 0-100 总分 + 各维度分项 + 构图等级 + 改进建议 + 辅助线叠加 (三分线/黄金螺旋/水平线)

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/composition-analysis.ts` | 新增 | 三分法/螺旋/对称/水平线检测 |
| `src/components/tools/CompositionAnalysis.vue` | 新增 | 构图分析面板 + 辅助线 |

### 测试规格
- 三分法构图: 人物在右上三分线交点 → 三分法得分 > 80 → 总体评分良好
- 中心构图: 主体严格居中 → 三分法得分 < 30 → 对称性得分 > 80 (对称构图也是有效构图)
- 倾斜地平线: 地平线倾斜 5° → 水平线得分 < 40 → 建议旋转校正

## 18. 图片色彩分析 (YP-09-286)

### 背景

用户需要了解图片的色彩构成、主色调、色彩和谐度，用于调色参考、品牌色提取、色彩方案设计。

### 核心设计

**色彩仪表盘**:

| 维度 | 检测方法 | 权重 |
|------|---------|------|
| 主色提取 | K-means (k=5) 聚类 + 按像素占比排序 | 30% |
| 色彩和谐度 | 6 种和谐规则匹配 + 色相分布评分 | 30% |
| 饱和度分布 | HSL S 通道直方图 + 过饱和/欠饱和比例 | 25% |
| 色温估计 | Gray World / White Patch 白平衡假设 | 15% |

**主色提取详解** (K-means, k=5):
1. 均匀采样: 每 10px 取一个像素 (减少计算量)
2. 转 LAB 空间 (感知均匀，距离有物理意义)
3. K-means 聚类: 初始化 5 个中心 (均匀分布) → 分配 → 更新 → 迭代至收敛 (10 次 or ΔE < 1)
4. 每个聚类: 中心 LAB → RGB → HEX → 像素占比
5. 按占比排序 → 显示 5 色色板+占比百分比

**色彩和谐度** (6 种和谐规则):
1. 互补 (Complementary): 两色相位差 180° ± 10°
2. 类似 (Analogous): 三色相位差 30° ± 10° 连续
3. 三角 (Triadic): 三色相位差 120°± 10°
4. 分裂互补 (Split-Complementary): 基色 + 互补色 ± 30°
5. 矩形 (Tetradic-Rectangle): 四色相位差 60° 交替
6. 单色 (Monochromatic): 同一色相，不同饱和度和亮度

匹配度 = Σ(每个规则的主色匹配分数) → 最优匹配规则作为和谐度评分

**饱和度分布**: 每个像素 HSL S → 10 桶直方图 (0.0-0.1, ... , 0.9-1.0) → 低饱和 (< 0.2) 和高饱和 (> 0.8) 占比 → 评分

**色温估计**: Gray World 假设: avg(R)=avg(G)=avg(B) → 计算 R/G/B 三通道均值 → 偏差: R>B (偏暖), B>R (偏冷) → 色温 = a×(R-B) 经验公式

**输出**: 综合色彩评分 0-100 + 5 色主色色板 + 和谐规则匹配结果 + 饱和度直方图 + 色温估计 (冷/暖/中性)

### 文件清单

| 文件 | 操作 | 说明 |
|------|------|------|
| `src/utils/image/color-analysis.ts` | 新增 | K-means/和谐度/饱和度/色温分析 |
| `src/components/tools/ColorAnalysis.vue` | 新增 | 色彩分析仪表盘 |

### 测试规格
- 主色提取: 蓝色天空+绿色草地照片 → 前 2 主色为蓝和绿 → 占比 > 50%
- 互补色和谐: 蓝/橙配色图片 → 检测为互补和谐 → 和谐度 > 70
- 饱和度: 鲜艳图片 → 高饱和占比 > 40% → 色彩评分中等 (过饱和扣分)
- 色温: 日光照片 → 中性/微暖 → 钨丝灯 → 明显偏暖 → 荧光灯 → 偏冷

| 2 | 多个 APP1 段只修改了第一个 | 某些相机写入 2 个 APP1 段(EXIF+XMP) | 检查段列表 → 所有 APP1 段都被处理 |
| 3 | Unicode 中文在 IPTC 中乱码 | IPTC 默认 Latin-1 → 中文需 UTF-8 | 中文标题 → 验证 Adobe Bridge 中正确显示 |
| 4 | GPS 微调后 N/S/E/W Ref 标签错误 | 用户输入负坐标时 → Ref 设反 | 测试四象限坐标 → 验证 Ref 正确 |
| 5 | piexifjs 写入后 JPEG 质量下降 | 重新编码导致双重压缩 | 使用 piexif.insert 而非重新编码 |

### 分析工具 (YP-09-283/284/285/286)

| # | 预测问题 | 原因 | 验证方法 |
|---|---------|------|---------|
| 1 | 清晰度评估: 平滑渐变天空误判为模糊 | Laplacian 方差低 (渐变无边缘) → 得分低 | 分块评估 + 排除低纹理区域 + 仅评估有纹理的区域 |
| 2 | 噪点评估: 纹理丰富区域误判为噪点 | 草地/布料纹理方差大 → 与噪声方差混淆 | 频率域辅助: 纹理=低频/噪声=高频 → 区分 |
| 3 | 构图分析: 留白构图误判为失败 | 简约构图无显著区域 → 三分法得分低 | 增加"留白构图"判断 → 检测负空间占比 → 留白 > 40% 时跳过三分法 |
| 4 | 色彩分析: K-means 对渐变主色不稳定 | 随机初始化导致每次聚类结果略有不同 | K-means++ 初始化 → 固定 seed → 结果可复现 |

### 跨工具设计决策

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 图片格式支持范围 | 仅 JPEG | JPEG+PNG | 全格式 | JPEG+PNG (按工具不同) | 元数据编辑仅 JPEG，像素操作支持 PNG |

| UI 模式 | 单工具独占 | 多工具叠加 | 工具组合 | 单工具独占 | 同一图片只有一个工具激活编辑 |

### 关键数学模型选择

| 操作 | 可选算法 | 选择 | 理由 |
|------|---------|------|------|
| 图像缩放 | Nearest/Bilinear/Bicubic/Lanczos | Bicubic(默认)+Lanczos | 质量与速度的最优平衡 |

| 降噪 | 高斯/双边/NLM | 双边滤波 | 保持边缘 + 去除噪声的最优平衡 |

### 通用交互模式

- **工具切换**: 同一图片在不同工具间切换时保留编辑状态 (无副作用的工具可并行，有副作用的显示提示)
- **撤销/重做**: Ctrl+Z / Ctrl+Shift+Z 全局快捷键——所有编辑工具统一
- **导出**: Ctrl+S 保存/导出——所有工具统一快捷键
- **重置**: 每个工具独立的"重置原图"按钮——颜色醒目 (橙色/红色)
- **帮助**: 每个工具有 ? 按钮 → 弹出工具使用说明和技巧

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Canvas 大图操作内存溢出 | 中 | 高 | 限制图片 ≤ 50MP，超大图自动缩放，处理完成释放 ArrayBuffer |
| YiAi 后端不可用 | 中 | 高 | 所有 AI 功能提供纯前端降级方案 |
| 浏览器兼容性差异 | 低 | 中 | 检测 OffscreenCanvas/ImageBitmap 支持，降级到 Canvas 2D |
| 多工具并行操作冲突 | 低 | 中 | 同一图片只允许一个工具激活编辑，其他工具只读预览 |
| JPEG 二进制操作损坏文件 | 中 | 高 | 写入前备份原始文件，修改后验证可读 |
