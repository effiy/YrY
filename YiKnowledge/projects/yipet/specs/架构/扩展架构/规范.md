# Spec: Extension Architecture

## Overview

本规范定义了 YiPet Chrome MV3 扩展的架构约定，包括双世界执行上下文、内容脚本注入、ISOLATED <-> MAIN 消息传递、chrome.storage 使用、CSP 合规等。

---

## 双世界执行架构

### 执行上下文对比

| 属性 | ISOLATED 世界 | MAIN 世界 |
|------|--------------|----------|
| 运行环境 | Content Script 沙箱 | 页面 JavaScript 上下文 |
| JavaScript 上下文 | 独立，与页面 JS 隔离 | 与页面 JS 共享 |
| DOM 访问 | 有限（可访问但不可靠） | 完整 DOM 访问 |
| `chrome.runtime.*` | 可用 | 不可用 |
| `chrome.storage.*` | 可用 | 不可用 |
| `chrome.runtime.getURL` | 可用 | 不可用 |
| 页面全局变量 | 不可访问 | 可访问 |
| `window` 对象 | 独立的 `window` 代理 | 真实的页面 `window` |

### 核心文件

```
src/content/
├── bootstrap.ts           # 双世界入口：ISOLATED 世界运行 + 自注入 MAIN 世界
├── cdn/
│   ├── catalog.ts         # CDN 资源注入清单（单一数据源）
│   └── injector.ts        # 资源注入器（<script>/<link> 标签注入）
├── ipc/
│   └── messages.ts        # ISOLATED <-> MAIN 消息传递
├── rendering/
│   └── overlay.ts         # 浮动宠物覆盖层渲染（MAIN 世界）
└── state/                 # 页面级状态管理
```

## 注入流程

### 完整注入时序

```
1. Service Worker (background/index.ts)
    │
    ├── 页面加载时触发 chrome.scripting.executeScript
    │   注入 src/content/bootstrap.ts 到 ISOLATED 世界
    │
    ▼
2. bootstrap.ts 在 ISOLATED 世界执行
    │
    ├── 注册 chrome.runtime.onMessage 监听器
    │   处理来自 popup 和 service worker 的消息
    │
    ├── 通过 chrome.runtime.getURL 解析 CDN 资源路径
    │   将 chrome-extension:// 路径映射为实际 URL
    │
    ├── 创建 <script> 标签，将自身代码注入 MAIN 世界
    │   (自注入模式：bootstrap.ts 在 ISOLATED 运行后，
    │    再以 <script> 标签注入到页面 DOM)
    │
    ▼
3. bootstrap.ts 在 MAIN 世界执行
    │
    ├── 检测 chrome.runtime 是否可用（判断执行世界）
    │   ├── 可用 → ISOLATED 世界，执行步骤 2
    │   └── 不可用 → MAIN 世界，执行步骤 3
    │
    ├── 加载 CDN 资源（React、Ant Design 等）
    │   通过 injector.ts 注入 <script> 和 <link> 标签
    │
    ├── 初始化 IPC 通信
    │   监听来自 ISOLATED 世界的 CustomEvent
    │
    ├── 渲染浮动宠物覆盖层 (overlay.ts)
    │
    └── 初始化 Chat 窗口 (ChatWindow)
```

### 代码示例

```typescript
// src/content/bootstrap.ts
// 通过检测 chrome.runtime 判断当前执行世界
if (typeof chrome !== 'undefined' && chrome.runtime) {
  // ISOLATED 世界
  initIsolatedWorld()
} else {
  // MAIN 世界
  initMainWorld()
}

function initIsolatedWorld() {
  // 1. 注册消息监听
  chrome.runtime.onMessage.addListener(handleMessage)

  // 2. 解析 CDN 路径
  const cdnScripts = getCDNScripts()

  // 3. 自注入到 MAIN 世界
  const script = document.createElement('script')
  script.src = chrome.runtime.getURL('content/bootstrap.js')
  script.dataset.cdnScripts = JSON.stringify(cdnScripts)
  document.documentElement.appendChild(script)
}

function initMainWorld() {
  // 1. 注入 CDN 资源
  const cdnScripts = JSON.parse(
    document.currentScript?.dataset?.cdnScripts || '[]'
  )
  injectCDNResources(cdnScripts)

  // 2. 初始化 IPC
  initIPC()

  // 3. 渲染 UI
  renderOverlay()
  renderChatWindow()
}
```

## ISOLATED <-> MAIN 消息传递

### 消息方向

```
Popup (React)
    │
    ▼ chrome.tabs.sendMessage(tabId, { type, payload })
ISOLATED world (content script)
    │ chrome.runtime.onMessage 监听
    │
    ├── 需要 DOM 操作 → 转发到 MAIN 世界
    │   └── window.postMessage({ type, payload }, '*')
    │
    ├── 需要 chrome.* API → 在 ISOLATED 直接处理
    │
    ▼
MAIN world
    │ window.addEventListener('message', ...)
    │
    ├── 执行业务逻辑（DOM 操作、渲染）
    │
    └── 需要回调 → 通过 CustomEvent 返回
        └── window.dispatchEvent(new CustomEvent('yipet:response', { detail }))
```

### 消息类型

```typescript
// ISOLATED -> MAIN 消息
type IsolatedToMainMessage =
  | { type: 'TOGGLE_PET'; payload: { visible: boolean } }
  | { type: 'UPDATE_SKIN'; payload: { role: string; color: string } }
  | { type: 'TOGGLE_CHAT'; payload: { open: boolean } }
  | { type: 'APPLY_THEME'; payload: { colors: ThemeColors } }

// MAIN -> ISOLATED 消息
type MainToIsolatedMessage =
  | { type: 'CHAT_STATE_CHANGED'; payload: Partial<ChatState> }
  | { type: 'PET_CLICKED'; payload: { x: number; y: number } }
  | { type: 'SESSION_CREATED'; payload: { key: string; title: string } }
```

### 消息传递模式

```typescript
// ISOLATED 世界 -> MAIN 世界
function sendToMain(message: IsolatedToMainMessage) {
  window.postMessage({ source: 'yipet-isolated', ...message }, '*')
}

// MAIN 世界监听 ISOLATED 消息
window.addEventListener('message', (event) => {
  if (event.source !== window) return
  if (event.data?.source !== 'yipet-isolated') return
  handleIsolatedMessage(event.data)
})

// MAIN 世界 -> ISOLATED 世界
function sendToIsolated(message: MainToIsolatedMessage) {
  window.dispatchEvent(
    new CustomEvent('yipet:from-main', { detail: message })
  )
}

// ISOLATED 世界监听 MAIN 消息
window.addEventListener('yipet:from-main', (event) => {
  const message = (event as CustomEvent).detail
  // 使用 chrome.runtime.sendMessage 转发到 popup/service worker
  chrome.runtime.sendMessage(message)
})
```

## chrome.storage 使用

### 存储区域

| 存储类型 | 用途 | 容量 | 持久化 |
|---------|------|------|--------|
| `chrome.storage.local` | 扩展状态、用户配置、会话数据 | 10 MB（可申请更多） | 永久 |
| `chrome.storage.sync` | 跨设备同步配置 | 100 KB | 永久 + 同步 |
| `chrome.storage.session` | 浏览器会话期间数据 | 10 MB | 会话结束清除 |

### 使用模式

```typescript
// src/shared/state.ts — 统一状态读写封装

// 读取
async function getFromStorage<T>(key: string): Promise<T | null> {
  const result = await chrome.storage.local.get(key)
  return result[key] ?? null
}

// 写入
async function setToStorage<T>(key: string, value: T): Promise<void> {
  await chrome.storage.local.set({ [key]: value })
}

// 删除
async function removeFromStorage(key: string): Promise<void> {
  await chrome.storage.local.remove(key)
}

// 监听变化
chrome.storage.onChanged.addListener((changes, areaName) => {
  if (areaName === 'local') {
    for (const [key, { oldValue, newValue }] of Object.entries(changes)) {
      handleStorageChange(key, oldValue, newValue)
    }
  }
})
```

### 存储键约定

| 键名 | 内容 | 读写位置 |
|------|------|---------|
| `sidebarWidth` | 侧边栏宽度 | ChatController |
| `knowledgeGrounded` | 知识库接地开关 | ChatController |

## CSP 合规

### MV3 CSP 要求

Chrome MV3 扩展必须满足以下 CSP 约束：

| 禁止 | 原因 | 替代方案 |
|------|------|---------|
| 远程脚本加载 | 安全策略 | 本地化所有 vendor 库 |
| `eval()` / `new Function()` | 代码执行风险 | 使用静态代码 |
| 内联 `<script>` 标签 | CSP 禁止 | 外部脚本文件 |
| 远程样式加载 | 安全策略 | 本地化样式文件 |

### 合规实践

```typescript
// ✅ 正确：本地化 vendor 库
// public/cdn/vendor/ 存放所有第三方库
// 通过 chrome.runtime.getURL 加载

// ✅ 正确：外部脚本文件
const script = document.createElement('script')
script.src = chrome.runtime.getURL('cdn/vendor/react.js')
document.head.appendChild(script)

// ❌ 错误：远程 CDN
// <script src="https://cdn.jsdelivr.net/npm/react@18/umd/react.production.min.js"></script>

// ❌ 错误：内联脚本
// <script>console.log('inline')</script>

// ❌ 错误：eval
// eval('console.log("hello")')
```

### CDN 资源目录

```
public/cdn/
├── utils/
│   └── api-client.ts      # 共享 HTTP 客户端（MAIN 世界可用）
├── vendor/                # 第三方库（本地化）
│   ├── react.js
│   ├── react-dom.js
│   ├── antd.js
│   └── ...
└── styles/
    ├── variables.css      # 设计变量
    └── chat.css           # Chat 串联样式（构建时生成）
```

## Constraints

### MUST

- 所有 `chrome.runtime.*` 调用仅限于 ISOLATED 世界
- MAIN 世界代码不能调用 `chrome.runtime.getURL`
- ISOLATED 和 MAIN 之间只能通过消息传递通信
- 所有 vendor 库必须本地化存放于 `public/cdn/vendor/`
- CDN 资源路径必须通过 `chrome.runtime.getURL` 在 ISOLATED 世界解析
- 使用 `chrome.storage.local` 作为主要持久化存储
- 注入前检查全局存在性，避免重复注入

### MUST NOT

- 不要在 MAIN 世界代码中调用 chrome API
- 不要在 ISOLATED 世界直接操作页面 DOM
- 不要加载远程 CDN 资源
- 不要使用 `eval()` 或 `new Function()`
- 不要使用内联 `<script>` 标签
- 不要使用 `chrome.storage.sync` 存储大容量数据（上限 100KB）

### 生命周期阶段

```
                    ┌─────────────┐
                    │  已安装      │
                    │  (Installed) │
                    └──────┬──────┘
                           │ chrome.runtime.onInstalled

                    ┌─────────────┐

                    └──────┬──────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
       ┌──────────┐ ┌──────────┐ ┌──────────┐
       │  运行中   │ │  空闲中   │ │  已终止   │
       │ (Running) │ │  (Idle)  │ │(Terminated)│
       └─────┬────┘ └─────┬────┘ └─────┬────┘
             │            │            │
             │  事件触发   │   30s 无活动 │  浏览器回收
             └────────────┴────────────┘
```

### 唤醒机制

```typescript
// Service Worker 唤醒模式
// src/background/index.ts

// 1. 监听安装事件
chrome.runtime.onInstalled.addListener((details) => {
  if (details.reason === 'install') {
    // 首次安装：初始化默认配置
    chrome.storage.local.set({
      config: DEFAULT_CONFIG,
      installedAt: Date.now(),
    })
  } else if (details.reason === 'update') {
    // 扩展更新：执行数据迁移
    migrateStorageData(details.previousVersion)
  }
})

// 2. 保持 Service Worker 活跃
// 问题：Service Worker 在 30 秒无活动后自动终止
// 解决：通过 chrome.alarms 定期唤醒，维持长连接

const KEEP_ALIVE_INTERVAL = 20 // 秒，小于 30 秒的终止阈值

// 注册定期唤醒
chrome.alarms.create('keepAlive', {
  periodInMinutes: KEEP_ALIVE_INTERVAL / 60,
})

chrome.alarms.onAlarm.addListener((alarm) => {
  if (alarm.name === 'keepAlive') {
    // 执行轻量级操作，保持 SW 活跃
    updateConnectionStatus()
  }
})

// 3. 优雅关闭
// 在 SW 即将终止前保存状态
self.addEventListener('beforeunload', () => {
  // 保存未完成的任务
  pendingTasks.forEach(task => saveTaskToStorage(task))
})
```

### 生命周期事件处理

```typescript
// 生命周期事件处理模式
class ServiceWorkerLifecycle {
  private pendingConnections = new Set<chrome.runtime.Port>()

  // 建立长连接（port 方式）
  connectPort(port: chrome.runtime.Port): void {
    this.pendingConnections.add(port)

    port.onDisconnect.addListener(() => {
      this.pendingConnections.delete(port)
    })
  }

  // 检查 SW 是否存活
  async isAlive(): Promise<boolean> {
    try {
      const response = await chrome.runtime.sendMessage({ type: 'PING' })
      return response === 'PONG'
    } catch {
      return false
    }
  }

  // 等待 SW 就绪
  async waitForReady(timeout = 5000): Promise<void> {
    const start = Date.now()
    while (Date.now() - start < timeout) {
      if (await this.isAlive()) return
      await new Promise(resolve => setTimeout(resolve, 200))
    }
    throw new Error('Service Worker 未能在超时时间内就绪')
  }
}
```

### 状态持久化恢复

```typescript
// SW 终止后恢复状态
// 问题：SW 终止后内存中的状态全部丢失
// 解决：关键状态持久化到 chrome.storage，重启时恢复

const SW_STATE_KEY = 'swState'

interface SWState {
  lastActiveAt: number
  activeTabId: number | null
  injectedTabs: Set<number>  // 已注入内容脚本的标签页
  pendingRequests: string[]  // 未完成的请求 ID
}

class SWStateManager {
  private state: SWState

  // 恢复状态
  async restore(): Promise<void> {
    const result = await chrome.storage.local.get(SW_STATE_KEY)
    if (result[SW_STATE_KEY]) {
      const saved = result[SW_STATE_KEY]
      this.state = {
        ...saved,
        injectedTabs: new Set(saved.injectedTabs),
      }
    } else {
      this.state = this._createInitialState()
    }
  }

  // 持久化状态
  async persist(): Promise<void> {
    await chrome.storage.local.set({
      [SW_STATE_KEY]: {
        ...this.state,
        injectedTabs: Array.from(this.state.injectedTabs),
      },
    })
  }

  private _createInitialState(): SWState {
    return {
      lastActiveAt: Date.now(),
      activeTabId: null,
      injectedTabs: new Set(),
      pendingRequests: [],
    }
  }
}
```

## 消息传递性能优化

### Transferable Objects

在传递大量数据时（如消息列表、知识库树），使用 Transferable Objects 避免数据拷贝开销。

```typescript
// 使用 Transferable Objects 传递大数据
// 传统方式：数据被拷贝，内存加倍
function sendLargeData(data: ArrayBuffer): void {
  chrome.runtime.sendMessage({
    type: 'LARGE_DATA',
    payload: data,  // ❌ 数据被拷贝
  })
}

// Transferable 方式：零拷贝传递
function sendLargeDataTransferable(data: ArrayBuffer): void {
  const port = chrome.runtime.connect({ name: 'data-channel' })
  port.postMessage({ type: 'LARGE_DATA' }, [data])  // ✅ 零拷贝
}

// 在消息通道中使用 Transferable
class MessageChannelOptimized {
  private port: chrome.runtime.Port

  sendWithTransferable<T>(message: T, transferables: Transferable[]): void {
    this.port.postMessage(message, transferables)
  }
}
```

### 消息批处理

```typescript
// 消息批处理：合并频繁的小消息
class MessageBatcher {
  private batch: Message[] = []
  private timer: ReturnType<typeof setTimeout> | null = null
  private readonly BATCH_DELAY = 16 // ms，约 60fps

  enqueue(message: Message): void {
    this.batch.push(message)

    if (!this.timer) {
      this.timer = setTimeout(() => this.flush(), this.BATCH_DELAY)
    }
  }

  private flush(): void {
    if (this.batch.length === 0) return

    // 合并为一条消息
    const merged: BatchedMessage = {
      type: 'BATCHED',
      payload: this.batch,
    }

    chrome.runtime.sendMessage(merged)
    this.batch = []
    this.timer = null
  }
}

// 用于高频更新的场景（如 SSE streaming token）
const tokenBatcher = new MessageBatcher()
onToken((text) => {
  tokenBatcher.enqueue({ type: 'TOKEN', text })
})
```

### 消息大小限制

| 消息类型 | 大小限制 | 策略 |
|---------|---------|------|
| `chrome.runtime.sendMessage` | 64 MB (JSON) | 大数据使用 Transferable |
| `chrome.storage.local.set` | 10 MB (总配额) | 分片存储，使用 IndexedDB |
| `window.postMessage` | 无硬性限制 | 大数据使用结构化克隆 |

### 消息优先级

```typescript
// 带优先级的消息队列
type MessagePriority = 'high' | 'normal' | 'low'

interface PrioritizedMessage {
  type: string
  payload: unknown
  priority: MessagePriority
}

class PriorityMessageQueue {
  private queues = {
    high: [] as PrioritizedMessage[],
    normal: [] as PrioritizedMessage[],
    low: [] as PrioritizedMessage[],
  }

  enqueue(message: PrioritizedMessage): void {
    this.queues[message.priority].push(message)
    this.processNext()
  }

  private processNext(): void {
    // 高优先级优先处理
    const queue = this.queues.high.length > 0 ? this.queues.high
      : this.queues.normal.length > 0 ? this.queues.normal
      : this.queues.low

    if (queue.length === 0) return

    const message = queue.shift()!
    this.send(message).then(() => this.processNext())
  }

  private async send(message: PrioritizedMessage): Promise<void> {
    chrome.runtime.sendMessage(message)
  }
}
```

## 内容脚本注入时机策略

### 注入时机对比

| 时机 | `run_at` | 优点 | 缺点 | 适用场景 |
|------|---------|------|------|---------|
| `document_start` | 页面开始加载 | 最早注入，无闪烁 | DOM 可能未就绪 | 需要尽早拦截页面事件 |
| `document_end` | DOM 就绪 | 平衡时机 | 页面可能已渲染部分内容 | **默认选择** |
| `document_idle` | 页面完全加载 | 所有资源就绪 | 最晚注入，用户可见延迟 | 非关键功能 |

### 动态注入策略

```typescript
// 策略 1：静态声明 + 动态注入混合
// manifest.json 中声明 document_end 基础注入
// 特定页面通过 chrome.scripting.executeScript 动态注入

// 策略 2：按需延迟注入
// 用户点击扩展图标时才注入 UI 组件
chrome.action.onClicked.addListener(async (tab) => {
  if (!tab.id) return

  // 检查是否已注入
  const isInjected = await checkInjected(tab.id)
  if (isInjected) {
    // 已注入，直接切换可见性
    chrome.tabs.sendMessage(tab.id, { type: 'TOGGLE_CHAT' })
    return
  }

  // 未注入，执行注入
  await chrome.scripting.executeScript({
    target: { tabId: tab.id },
    files: ['content/bootstrap.js'],
  })

  // 等待注入完成后初始化
  await waitForContentScriptReady(tab.id)
  chrome.tabs.sendMessage(tab.id, { type: 'INIT_CHAT' })
})

// 策略 3：条件注入
// 仅在特定 URL 模式注入增强功能
const ENHANCED_URLS = [
  '*://github.com/*',
  '*://gitlab.com/*',
  '*://*.notion.so/*',
]

chrome.tabs.onUpdated.addListener((tabId, changeInfo, tab) => {
  if (changeInfo.status !== 'complete' || !tab.url) return

  const needsEnhanced = ENHANCED_URLS.some(pattern =>
    new RegExp(pattern.replace(/\*/g, '.*')).test(tab.url!)
  )

  if (needsEnhanced) {
    chrome.scripting.executeScript({
      target: { tabId },
      files: ['content/enhanced.js'],
    })
  }
})
```

```typescript
// 安全等待 DOM 就绪的工具函数
function waitForDOMReady(
  selectors: string[],
  timeout = 5000
): Promise<Element[]> {
  return new Promise((resolve, reject) => {
    const start = Date.now()

    const check = () => {
      const elements = selectors.map(s => document.querySelector(s))
      const allReady = elements.every(el => el !== null)

      if (allReady) {
        resolve(elements as Element[])
      } else if (Date.now() - start > timeout) {
        reject(new Error(`DOM 元素未在 ${timeout}ms 内就绪: ${selectors}`))
      } else {
        requestAnimationFrame(check)
      }
    }

    check()
  })
}

// 使用示例
```

## 扩展更新流程

### 版本迁移

```typescript
// 扩展更新时的数据迁移
const MIGRATIONS: Record<string, (currentVersion: string) => Promise<void>> = {
  // 从 1.0 迁移到 1.1
  '1.0': async (currentVersion) => {
    // 迁移 session 数据格式
    const result = await chrome.storage.local.get('sessions')
    const oldSessions = result.sessions || []

    const newSessions = oldSessions.map((s: LegacySession) => ({
      id: s.key || crypto.randomUUID(),
      key: s.key,
      title: s.title,
      messages: s.messages || [],
      createdAt: s.createdAt || new Date().toISOString(),
      updatedAt: s.updatedAt || new Date().toISOString(),
    }))

    await chrome.storage.local.set({ sessions: newSessions })
  },

  // 从 1.1 迁移到 1.2
  '1.1': async (currentVersion) => {
    // 迁移配置格式
    const result = await chrome.storage.local.get('config')
    const oldConfig = result.config

    const newConfig = {
      ...oldConfig,
      ragScope: oldConfig.ragScope || '',
      ragScopeIsFile: oldConfig.ragScopeIsFile || false,
      knowledgeGrounded: oldConfig.knowledgeGrounded ?? true,
    }

    await chrome.storage.local.set({ config: newConfig })
  },
}

// 在 onInstalled 中执行迁移
chrome.runtime.onInstalled.addListener(async (details) => {
  if (details.reason === 'update') {
    const previousVersion = details.previousVersion || '0.0'
    const currentVersion = chrome.runtime.getManifest().version

    // 按版本顺序执行迁移
    const versions = Object.keys(MIGRATIONS).sort()
    for (const version of versions) {
      if (compareVersions(version, previousVersion) > 0
        && compareVersions(version, currentVersion) <= 0) {
        console.log(`[Migration] 执行迁移: ${version}`)
        await MIGRATIONS[version](currentVersion)
      }
    }

    // 记录迁移完成
    await chrome.storage.local.set({
      lastMigratedVersion: currentVersion,
      lastMigratedAt: Date.now(),
    })
  }
})
```

## Iframe 隔离 Chat 窗口

### 架构设计

Chat 窗口使用 iframe 隔离，解决以下问题：

1. **样式隔离**：Chat 窗口的 CSS 不与宿主页面冲突
2. **CSP 隔离**：Chat 窗口有独立的 CSP 策略
3. **JS 隔离**：Chat 的 React 运行时与宿主页面 JS 完全隔离

```typescript
// iframe 创建与通信
class ChatIframeManager {
  private iframe: HTMLIFrameElement | null = null
  private chatOrigin: string

  constructor(chatOrigin: string) {
    this.chatOrigin = chatOrigin
  }

  // 创建 Chat iframe
  createChatIframe(container: HTMLElement): void {
    this.iframe = document.createElement('iframe')

    // 设置 iframe 属性
    this.iframe.id = 'yipet-chat-iframe'
    this.iframe.src = chrome.runtime.getURL('chat/index.html')
    this.iframe.style.cssText = `
      position: fixed;
      bottom: 80px;
      right: 20px;
      width: 420px;
      height: 600px;
      border: none;
      border-radius: 12px;
      box-shadow: 0 8px 32px rgba(0, 0, 0, 0.12);
      z-index: 2147483646;
      background: #fff;
    `
    this.iframe.allow = 'clipboard-write'

    container.appendChild(this.iframe)

    // 监听 iframe 消息
    window.addEventListener('message', this._handleIframeMessage)
  }

  // 向 iframe 发送消息
  sendToChat(message: unknown): void {
    this.iframe?.contentWindow?.postMessage(
      { source: 'yipet-main', ...message as object },
      this.chatOrigin
    )
  }

  // 处理来自 iframe 的消息
  private _handleIframeMessage = (event: MessageEvent): void => {
    // 验证消息来源
    if (event.origin !== this.chatOrigin) return
    if (event.data?.source !== 'yipet-chat') return

    switch (event.data.type) {
      case 'CHAT_READY':
        // Chat 窗口已就绪，发送初始数据
        this.sendToChat({
          type: 'INIT_CHAT',
          pageInfo: this._getPageInfo(),
          config: this._getConfig(),
        })
        break

      case 'OPEN_YIVAD':
        // 跨项目桥接
        window.open(event.data.url, '_blank')
        break

      case 'CLOSE_CHAT':
        this.destroyChatIframe()
        break
    }
  }

  // 销毁 Chat iframe
  destroyChatIframe(): void {
    window.removeEventListener('message', this._handleIframeMessage)
    this.iframe?.remove()
    this.iframe = null
  }

  private _getPageInfo() {
    return {
      url: window.location.href,
      title: document.title,
      hostname: window.location.hostname,
      pathname: window.location.pathname,
    }
  }

  private _getConfig() {
    return {} // 从 chrome.storage 读取
  }
}
```


## 反模式

### 错误：在 MAIN 世界直接使用 chrome.runtime API

```typescript
// ❌ 反模式：MAIN 世界调用 chrome API
const url = chrome.runtime.getURL('icons/pet.png')  // 抛出 ReferenceError
chrome.storage.local.get('config')                   // 抛出 ReferenceError
```

**问题**：MAIN 世界与页面共享 JavaScript 上下文，无法访问 `chrome.runtime.*` API。

**正确做法**：通过 ISOLATED 世界的消息传递间接获取数据。

### 错误：Service Worker 中执行长时间运行的任务

```typescript
// ❌ 反模式：Service Worker 中长时间阻塞
chrome.runtime.onMessage.addListener(async (message, sender, sendResponse) => {
  const result = await heavyComputation()  // 可能导致 SW 被终止
  sendResponse(result)
  return true
})
```

**问题**：Service Worker 在 30 秒无活动后被终止，长时间任务可能导致处理中断。

**正确做法**：将重量级计算委托给主线程（通过内容脚本），SW 仅做路由和协调。

### 错误：注入脚本时不检查已注入状态

```typescript
// ❌ 反模式：重复注入
chrome.tabs.onUpdated.addListener((tabId, changeInfo) => {
  if (changeInfo.status === 'complete') {
    chrome.scripting.executeScript({
      target: { tabId },
      files: ['content/bootstrap.js'],  // 每次页面刷新都注入，导致重复
    })
  }
})
```

**问题**：每次页面刷新都注入脚本，导致重复注入，UI 叠加。

**正确做法**：注入前检查全局存在性标记，或使用 `chrome.scripting.getRegisteredContentScripts`。

### 错误：消息传递无来源验证

```typescript
// ❌ 反模式：不验证消息来源
window.addEventListener('message', (event) => {
  handleMessage(event.data)  // 可能接收恶意页面的消息
})
```

**问题**：任何页面都可以通过 `window.postMessage` 发送消息，无来源验证可能导致安全漏洞。

**正确做法**：验证 `event.origin` 和 `event.data.source`，使用白名单机制。
