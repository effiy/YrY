# Spec: API Conventions

## Overview

本规范定义了 YiPet API 的四层架构、文件组织、ApiClient 类、RPC 信封、SSE 流式处理等约定。

---

## 四层架构

```
┌──────────────────────────────────────────────────────┐
│ 第 4 层：领域服务 (src/api/services/*.ts)              │
│                                                       │
│ AuthService   ChatService   SessionService            │
│ KnowledgeService   RagService   BugService            │
│ DatabaseService   AgentService   WeWorkService        │
│                                                       │
│ 每个服务类通过构造函数注入 ApiClient 实例               │
│ 负责将领域操作翻译为 RPC 调用                          │
├──────────────────────────────────────────────────────┤
│ 第 3 层：类型定义 (src/api/types.ts)                   │
│                                                       │
│ 所有请求/响应接口的单一数据源                          │
│ 类型定义供第 4 层和调用方消费                          │
│ 类型绝不导入第 4 层的服务                              │
├──────────────────────────────────────────────────────┤
│ 第 2 层：路径常量 (src/api/endpoints.ts)               │
│                                                       │
│ 按域分组的 API 路径常量                                │
│ CHAT、DATA、AGENT、AUTH、SESSION、KNOWLEDGE、RAG ...  │
│ 路径常量供第 4 层服务引用                              │
├──────────────────────────────────────────────────────┤
│ 第 1 层：HTTP 客户端 (src/api/client.ts)               │
│                                                       │
│ ApiClient 类                                          │
│ 基类：public/cdn/utils/api-client.ts                   │
│ 扩展：开发日志 + SSE 流式解析                          │
│ 功能：fetch 封装 + 自动重试 + 错误提取 + AbortController│
│ 第 4 层之外的代码绝不直接调用 fetch                     │
└──────────────────────────────────────────────────────┘
```

### 层级规则

| 规则 | 说明 |
|------|------|
| 不跨层调用 | 服务层使用 client + endpoints + types，绝不直接调用 fetch |
| 单向依赖 | types 不导入 services；client 不导入 services |
| 构造函数注入 | 每个服务类通过构造函数接收 `ApiClient` 实例 |
| 工厂聚合 | `createApiServices(config)` 统一创建所有服务实例 |

## ApiClient 类

### 基类来源

`src/api/client.ts` 继承自 `public/cdn/utils/api-client.ts`，后者提供：

- `fetch` 封装（自动拼接 base URL）
- 指数退避重试机制
- 统一错误提取
- `AbortController` 支持

### 扩展功能

```typescript
// src/api/client.ts
class ApiClient extends BaseApiClient {
  // 开发模式日志注入
  private logger: Logger

  // SSE 流式处理
  async stream<T>(params: StreamParams): Promise<StreamResult<T>>
  // 解析 text/event-stream 响应
  // 每行 data: {...} 触发 onChunk 回调
  // data: {"done": true} 触发 onDone 回调
  // 错误时触发 onError 回调
  // 支持 AbortController 取消
}
```

### SSE 流式协议

```
POST /  body: { module_name, method_name, parameters: { model, messages, stream: true } }
    │
    ▼ 响应头: Content-Type: text/event-stream
    │
    ├── data: {"data": {"message": "Hello"}}\n\n
    ├── data: {"data": {"message": " world"}}\n\n
    ├── data: {"data": {"message": "!"}}\n\n
    └── data: {"done": true}\n\n
```

## RPC 信封

### 请求格式

所有 API 调用使用统一的 RPC 信封：

```typescript
interface RpcRequest {
  module_name: string   // "services.<domain>.<service>"
  method_name: string   // "<method>"
  parameters: object    // 方法特定参数
}

interface RpcResponse<T> {
  code: number          // 0 = 成功
  message: string       // "ok" 或错误信息
  data: T               // 响应数据
}
```

### 服务映射

| 服务 | module_name | 常用方法 |
|------|-------------|---------|
| Chat | `services.ai.chat_service` | `chat` |
| 数据 CRUD | `services.database.data_service` | `query_documents`, `create_document`, `update_document`, `delete_document` |
| 会话 | `services.database.data_service` | `query_documents` (cname: "sessions") |
| Agent | `services.ai.agent_service` | `run`, `stop` |

```typescript
    messages: ChatMessage[]
    model: string
    system?: string
    images?: string[]
    onToken: (text: string) => void
    onDone: () => void
    onError: (err: Error) => void

      method_name: 'chat',

        messages: params.messages,
        stream: true,
        system: params.system,
        images: params.images,
      },
      onChunk: (data) => {
        if (data.data?.message) {
          params.onToken(data.data.message)
        }
      },
      onDone: params.onDone,
      onError: params.onError,
      signal: params.signal,
    })
  }
}
```

## Constraints

### MUST

- 所有 API 调用必须通过 `src/api/` 四层架构
- 第 4 层服务必须通过构造函数注入 `ApiClient`
- 第 3 层类型绝不导入第 4 层服务
- 第 1 层 client 绝不导入第 4 层服务
- 使用 `filter` 参数名而非 `query`
- 使用 `createApiServices(config)` 工厂创建服务
- SSE 流式调用使用 `ApiClient.stream()` 方法
- 支持 `AbortController` 取消

### MUST NOT

- 不要在任何层直接调用 `fetch`
- 不要跳过任何层（组件 -> 服务 -> client -> fetch）
- 不要使用 `any` 类型定义请求/响应
- 不要在 API 文件中编写业务逻辑
- 不要硬编码 API 路径
- 不要在服务中创建新的 `ApiClient` 实例

## SSE 流式高级模式

### 中断与重连

SSE 连接在 Chrome 扩展上下文中有两个特殊场景：Service Worker 休眠和页面关闭。ApiClient 需要处理这些场景下的中断与重连。

```typescript
// SSE 流式中断与重连模式
interface StreamReconnectConfig {
  maxRetries: number            // 最大重连次数，默认 3
  retryDelay: number            // 初始重连延迟（ms），默认 1000
  backoffMultiplier: number     // 退避乘数，默认 2
  resumeFromChunk: number       // 断点续传：从第 N 个 chunk 恢复
  onReconnectAttempt: (attempt: number) => void
  onReconnectFailed: (error: Error) => void
}

// 使用示例
await this.client.stream({
  module_name: 'services.ai.chat_service',
  method_name: 'chat',
  parameters: { messages, stream: true },
  onChunk: (data) => { /* 处理数据 */ },
  onDone: () => { /* 完成 */ },
  onError: (err) => { /* 错误 */ },
  signal: abortController.signal,
  reconnect: {
    maxRetries: 3,
    retryDelay: 1000,
    backoffMultiplier: 2,
    onReconnectAttempt: (attempt) => {
      console.warn(`SSE 重连尝试 ${attempt}/3`)
    },
    onReconnectFailed: (error) => {
      console.error('SSE 重连失败，请求已中止')
    },
  },
})
```

### 重连策略决策树

```
SSE 连接中断
    │
    ├── 错误类型 = AbortError（用户主动取消）
    │   └── 不重连，标记 aborted: true
    │
    ├── 错误类型 = NetworkError（网络中断）
    │   ├── 已接收 chunk 数 > 0 → 断点续传重连
    │   └── 已接收 chunk 数 = 0 → 完整重试
    │
    ├── 错误类型 = TimeoutError（超时）
    │   └── 指数退避重连（最多 3 次）
    │
    └── 错误类型 = ServerError（5xx）
        └── 不重连，展示错误信息
```

### 断点续传实现

```typescript
// 断点续传：记录已接收的 chunk 数量，重连时传递给后端
private async _streamWithReconnect(params: StreamParams): Promise<void> {
  let chunkCount = 0
  let retryCount = 0

  const doStream = async (): Promise<void> => {
    try {
      await this._rawStream({
        ...params,
        parameters: {
          ...params.parameters,
          // 传递断点信息给后端（如果后端支持）
          resume_from_chunk: chunkCount > 0 ? chunkCount : undefined,
        },
        onChunk: (data) => {
          chunkCount++
          params.onChunk(data)
        },
        onDone: params.onDone,
        onError: async (err) => {
          if (err.name === 'AbortError') {
            params.onError(err)
            return
          }
          if (retryCount < (params.reconnect?.maxRetries ?? 0)) {
            retryCount++
            const delay = (params.reconnect?.retryDelay ?? 1000)
              * Math.pow(params.reconnect?.backoffMultiplier ?? 2, retryCount - 1)
            params.reconnect?.onReconnectAttempt?.(retryCount)
            await new Promise(resolve => setTimeout(resolve, delay))
            return doStream()
          }
          params.reconnect?.onReconnectFailed?.(err)
          params.onError(err)
        },
        signal: params.signal,
      })
    } catch (err) {
      params.onError(err as Error)
    }
  }

  await doStream()
}
```

## 请求重试与指数退避

### 扩展上下文特殊性

Chrome 扩展的 Service Worker 可能在任意时刻被浏览器终止，因此请求重试需要比普通 Web 应用更保守的策略。

```typescript
// 请求重试配置
interface RetryConfig {
  maxRetries: number            // 最大重试次数，默认 3
  baseDelay: number             // 基础延迟（ms），默认 500
  maxDelay: number              // 最大延迟（ms），默认 10000
  backoffMultiplier: number     // 退避乘数，默认 2
  jitter: boolean               // 是否添加随机抖动，默认 true
  retryableStatuses: number[]   // 可重试的 HTTP 状态码，默认 [408, 429, 500, 502, 503, 504]
}

// 指数退避实现
private async _fetchWithRetry<T>(
  url: string,
  options: RequestInit,
  retryConfig: RetryConfig
): Promise<T> {
  let lastError: Error | null = null

  for (let attempt = 0; attempt <= retryConfig.maxRetries; attempt++) {
    try {
      const response = await fetch(url, options)

      // 不可重试的状态码直接抛出
      if (!retryConfig.retryableStatuses.includes(response.status)) {
        return this._extractData<T>(response)
      }

      // 可重试的状态码，记录错误
      lastError = new Error(`HTTP ${response.status}: ${response.statusText}`)
    } catch (err) {
      lastError = err as Error
      // 网络错误（TypeError: Failed to fetch）总是可重试的
    }

    if (attempt < retryConfig.maxRetries) {
      // 计算延迟：baseDelay * multiplier^attempt
      let delay = retryConfig.baseDelay
        * Math.pow(retryConfig.backoffMultiplier, attempt)

      // 上限
      delay = Math.min(delay, retryConfig.maxDelay)

      // 抖动：在 [delay * 0.5, delay * 1.5] 范围内随机
      if (retryConfig.jitter) {
        delay = delay * (0.5 + Math.random())
      }

      await new Promise(resolve => setTimeout(resolve, delay))
    }
  }

  throw lastError || new Error('Max retries exceeded')
}
```

### 重试白名单

| 请求类型 | 重试策略 | 原因 |
|---------|---------|------|
| `GET` 查询 | 最多 3 次，指数退避 | 幂等操作，可安全重试 |
| `POST` 创建 | 最多 1 次，仅网络错误 | 非幂等，需避免重复创建 |
| SSE 流式 | 最多 3 次，断点续传 | 流式数据可从中断点恢复 |
| 知识库写入 | 不重试 | 文件写入不可重试 |

## 离线队列模式

### 架构设计

Chrome 扩展在 Service Worker 休眠后无法发送请求，离线队列确保用户操作不会丢失。

```typescript
// 离线队列管理器
interface OfflineQueueItem {
  id: string                    // 唯一标识
  moduleName: string            // RPC module_name
  methodName: string            // RPC method_name
  parameters: object            // 请求参数
  createdAt: number             // 创建时间戳
  retryCount: number            // 已重试次数
  maxRetries: number            // 最大重试次数
  priority: 'high' | 'normal' | 'low'
}

class OfflineQueueManager {
  private queue: OfflineQueueItem[] = []
  private processing = false
  private readonly STORAGE_KEY = 'offlineQueue'

  // 将请求加入离线队列
  async enqueue(item: Omit<OfflineQueueItem, 'id' | 'createdAt' | 'retryCount'>): Promise<void> {
    const queueItem: OfflineQueueItem = {
      ...item,
      id: crypto.randomUUID(),
      createdAt: Date.now(),
      retryCount: 0,
    }
    this.queue.push(queueItem)
    await this._persistQueue()
  }

  // 网络恢复时重放队列
  async replayQueue(): Promise<ReplayResult> {
    if (this.processing) return { success: 0, failed: 0, pending: this.queue.length }
    this.processing = true

    const results = { success: 0, failed: 0, pending: 0 }
    const remaining: OfflineQueueItem[] = []

    // 按优先级排序
    const sorted = [...this.queue].sort((a, b) => {
      const priorityOrder = { high: 0, normal: 1, low: 2 }
      return priorityOrder[a.priority] - priorityOrder[b.priority]
    })

    for (const item of sorted) {
      try {
        await this.client.post({
          module_name: item.moduleName,
          method_name: item.methodName,
          parameters: item.parameters,
        })
        results.success++
      } catch (err) {
        if (item.retryCount < item.maxRetries) {
          item.retryCount++
          remaining.push(item)
        }
        results.failed++
      }
    }

    this.queue = remaining
    this.processing = false
    await this._persistQueue()
    return results
  }

  // 持久化队列到 chrome.storage
  private async _persistQueue(): Promise<void> {
    await chrome.storage.local.set({ [this.STORAGE_KEY]: this.queue })
  }

  // 恢复队列
  async restoreQueue(): Promise<void> {
    const result = await chrome.storage.local.get(this.STORAGE_KEY)
    this.queue = result[this.STORAGE_KEY] || []
  }
}
```

### 网络状态监听

```typescript
// 监听网络状态变化，自动触发队列重放
class NetworkMonitor {
  private queueManager: OfflineQueueManager

  constructor(queueManager: OfflineQueueManager) {
    this.queueManager = queueManager
  }

  start(): void {
    // 监听 online 事件
    window.addEventListener('online', () => {
      console.log('[NetworkMonitor] 网络已恢复，开始重放离线队列')
      this.queueManager.replayQueue()
    })

    // 监听 offline 事件
    window.addEventListener('offline', () => {
      console.log('[NetworkMonitor] 网络已断开，请求将进入离线队列')
    })

    // 定期健康检查（Service Worker 可用）
    if ('serviceWorker' in navigator) {
      setInterval(() => {
        if (navigator.onLine) {
          this.queueManager.replayQueue()
        }
      }, 30000) // 每 30 秒检查一次
    }
  }
}
```

## API 速率限制处理

### 响应头解析

```typescript
// 速率限制响应头
interface RateLimitHeaders {
  remaining: number      // X-RateLimit-Remaining: 剩余请求数
  reset: number          // X-RateLimit-Reset: 重置时间戳（秒）
  limit: number          // X-RateLimit-Limit: 总配额
  retryAfter?: number   // Retry-After: 建议等待时间（秒）
}

// 解析速率限制头
private _parseRateLimitHeaders(response: Response): RateLimitHeaders | null {
  const remaining = response.headers.get('X-RateLimit-Remaining')
  const reset = response.headers.get('X-RateLimit-Reset')
  const limit = response.headers.get('X-RateLimit-Limit')

  if (!remaining || !reset || !limit) return null

  return {
    remaining: parseInt(remaining, 10),
    reset: parseInt(reset, 10),
    limit: parseInt(limit, 10),
    retryAfter: response.headers.get('Retry-After')
      ? parseInt(response.headers.get('Retry-After')!, 10)
      : undefined,
  }
}
```

### 预先节流

```typescript
// 请求节流器：在扩展上下文中限制并发请求数
class RequestThrottle {
  private pending = new Map<string, Promise<unknown>>()
  private maxConcurrent: number

  constructor(maxConcurrent = 3) {
    this.maxConcurrent = maxConcurrent
  }

  async throttle<T>(key: string, fn: () => Promise<T>): Promise<T> {
    // 同名请求去重（同一 key 的请求共享结果）
    if (this.pending.has(key)) {
      return this.pending.get(key) as Promise<T>
    }

    // 并发限制
    while (this.pending.size >= this.maxConcurrent) {
      await Promise.race(this.pending.values())
    }

    const promise = fn().finally(() => {
      this.pending.delete(key)
    })

    this.pending.set(key, promise)
    return promise
  }
}

// 使用示例
const throttle = new RequestThrottle(3)
await throttle.throttle('knowledge-scan', () => this._api.knowledge.scan())
```

## Cache-First 策略

### chrome.storage 缓存层

```typescript
// 缓存优先读取策略
interface CacheStrategy {
  key: string                   // chrome.storage key
  ttl: number                   // 生存时间（ms），默认 5 分钟
  staleWhileRevalidate: boolean // 是否在后台刷新过期缓存
}

class CachedApiClient extends ApiClient {
  private cache = new Map<string, { data: unknown; timestamp: number }>()

  async getWithCache<T>(params: {
    url: string
    query?: Record<string, string>
    cache: CacheStrategy
  }): Promise<T> {
    const cacheKey = `${params.url}:${JSON.stringify(params.query || {})}`

    // 1. 检查内存缓存
    const memCached = this.cache.get(cacheKey)
    if (memCached && Date.now() - memCached.timestamp < params.cache.ttl) {
      return memCached.data as T
    }

    // 2. 检查 chrome.storage 缓存
    const storageCached = await this._getStorageCache<T>(params.cache.key)
    if (storageCached && Date.now() - storageCached.timestamp < params.cache.ttl) {
      // 命中缓存，更新内存缓存
      this.cache.set(cacheKey, { data: storageCached.data, timestamp: storageCached.timestamp })
      return storageCached.data
    }

    // 3. 缓存未命中，发起网络请求
    const data = await this.get<T>(params.url, params.query)

    // 4. 更新缓存
    const entry = { data, timestamp: Date.now() }
    this.cache.set(cacheKey, entry)
    await this._setStorageCache(params.cache.key, entry)

    return data
  }

  async getStaleWhileRevalidate<T>(params: {
    url: string
    query?: Record<string, string>
    cache: CacheStrategy
  }): Promise<T> {
    const cacheKey = `${params.url}:${JSON.stringify(params.query || {})}`

    // 立即返回过期缓存（如果有）
    const staleData = await this._getStorageCache<T>(params.cache.key)

    // 后台刷新
    if (!staleData || Date.now() - staleData.timestamp >= params.cache.ttl) {
      this.get<T>(params.url, params.query).then(data => {
        const entry = { data, timestamp: Date.now() }
        this.cache.set(cacheKey, entry)
        this._setStorageCache(params.cache.key, entry)
      }).catch(() => {
        // 静默失败，不影响用户
      })
    }

    return staleData?.data as T
  }

  private async _getStorageCache<T>(key: string): Promise<{ data: T; timestamp: number } | null> {
    const result = await chrome.storage.local.get(`cache:${key}`)
    return result[`cache:${key}`] || null
  }

  private async _setStorageCache(key: string, entry: { data: unknown; timestamp: number }): Promise<void> {
    await chrome.storage.local.set({ [`cache:${key}`]: entry })
  }
}
```

### 缓存策略矩阵

| 数据类型 | 缓存策略 | TTL | 原因 |
|---------|---------|-----|------|
| 知识库树 | Stale-While-Revalidate | 5 分钟 | 变化频率低，可接受短暂过期 |
| RAG 分类 | Cache-First | 10 分钟 | 静态数据 |
| 会话列表 | Cache-First | 1 分钟 | 需要较快反映新会话 |
| 消息列表 | Network-First | 无缓存 | 必须实时 |
| 角色配置 | Cache-First | 1 小时 | 几乎不变 |
| Bug 列表 | Stale-While-Revalidate | 2 分钟 | 可接受短暂延迟 |

## 反模式

### 错误：在内容脚本中直接使用 fetch 绕过四层架构

```typescript
// ❌ 反模式：绕过 API 层
const response = await fetch('http://localhost:10086/', {
  method: 'POST',
  body: JSON.stringify({ module_name: 'services.ai.chat_service', method_name: 'chat' }),
})
```

**问题**：丢失了重试、错误处理、日志、离线队列等所有 ApiClient 能力。

**正确做法**：始终通过 `createApiServices()` 工厂获取服务实例。

### 错误：同步阻塞等待网络响应

```typescript
// ❌ 反模式：Service Worker 中同步等待
const response = await fetch(url)  // 如果 Service Worker 被终止，请求丢失
```

**问题**：Service Worker 可能在 await 期间被终止，请求结果丢失。

**正确做法**：使用离线队列 + 重放机制，确保请求不丢失。

### 错误：忽略 AbortController 清理

```typescript
// ❌ 反模式：组件卸载时不清理 AbortController
useEffect(() => {
  const controller = new AbortController()
  ctrl.sendMessage(text)  // controller 未被传递
  // 组件卸载时未调用 controller.abort()
}, [])
```

**问题**：组件卸载后 SSE 流仍在继续，造成内存泄漏和状态更新错误。

**正确做法**：在 `useEffect` 清理函数中调用 `controller.abort()`。

### 错误：缓存未设置 TTL 导致数据永久过期

```typescript
// ❌ 反模式：缓存无过期时间
await chrome.storage.local.set({ knowledgeTree: data })
// 永远不更新，用户看到的数据可能过时数天
```

**问题**：缓存数据永不过期，用户无法看到最新数据。

**正确做法**：始终设置 TTL，定期清理过期缓存。
