# 项目架构摘要

## 一、技术栈概览

### 核心框架与库

| 类别 | 技术选型 | 版本 |
|------|---------|------|
| 运行时 | Chrome Extension Manifest V3 | - |
| UI 框架 | React 18 (函数组件 + Hooks) | 18.3 |
| 组件库 | Ant Design | 5.21 |
| 开发语言 | TypeScript（strict mode） | 5.5 |
| 构建工具 | Rsbuild（多入口） | 1.0 |
| 包管理 | npm | - |
| 状态管理 | useSyncExternalStore（无 Redux/Pinia） | - |
| 国际化 | chrome.i18n API（en + zh_CN） | - |
| 代码规范 | Biome（替代 ESLint + Prettier） | 2.5 |
| 测试框架 | Vitest + jsdom | 2 / 29 |

### 开发工具链

- **代码规范**: Biome 2.5（格式化 + lint 一体化）
- **类型检查**: `tsc --noEmit`
- **测试**: Vitest 2 + jsdom 29
- **国际化**: chrome.i18n（`public/_locales/<lang>/messages.json`）
- **构建**: Rsbuild 多入口（popup、chat、CDN utils、bootstrap）

## 三、双世界执行架构

### 3.1 执行上下文

YiPet 在 Chrome MV3 中运行于两个隔离的执行世界：

| 世界 | 运行环境 | 可用 API | 职责 |
|------|---------|---------|------|
| **ISOLATED** | Content Script 沙箱 | `chrome.runtime.*`, `chrome.storage.*` | 与扩展后台通信、存储管理 |
| **MAIN** | 页面 JavaScript 上下文 | 页面 DOM、`window`、`document` | 页面 UI 渲染、CDN 资源加载 |

### 3.2 注入流程

```
Service Worker (background/)
    │
    ▼ chrome.scripting.executeScript
Content Script (ISOLATED world)
    │ src/content/bootstrap.ts
    │
    ├── 1. 注册 chrome.runtime.onMessage 监听器
    ├── 2. 通过 chrome.runtime.getURL 解析 CDN 资源路径
    ├── 3. 将 CDN 资源路径注入页面 DOM
    │
    ▼ 自注入 <script> 标签
MAIN world
    │
    ├── 加载 CDN 资源（React、Ant Design 等）
    ├── 渲染浮动宠物覆盖层 (overlay.ts)
    ├── 渲染 Chat 窗口 (ChatWindow)
    │
    ▼ ISOLATED <-> MAIN 通信
CustomEvent (window.postMessage 风格)
    ├── ISOLATED → MAIN: 通过 CustomEvent 转发 chrome.runtime 消息
    └── MAIN → ISOLATED: 通过 window.postMessage 回调
```

### 3.3 双世界边界规则

| 规则 | 说明 |
|------|------|
| `chrome.runtime.*` 仅 ISOLATED 可用 | MAIN 世界代码不能调用 `chrome.runtime.getURL` 等 API |
| DOM 操作仅 MAIN 世界执行 | ISOLATED 世界不能直接操作页面 DOM |
| 消息传递通过 CustomEvent | ISOLATED 和 MAIN 之间只能通过事件通信 |
| CDN 资源路径在 ISOLATED 解析 | `chrome.runtime.getURL` 将 `chrome-extension://` 路径注入 MAIN 世界 |

## 四、CDN 资源注入

### 4.1 注入目录

CDN 资源目录 (`src/content/cdn/catalog.ts`) 是注入清单的单一数据源：

```typescript
// CDN_CATALOG 数组定义所有需要注入到 MAIN 世界的资源
// 每个条目包含：id、path（相对于 public/cdn/）、type（script/style）
```

### 4.2 注入机制

1. **bootstrap.ts** 在 ISOLATED 世界解析 `chrome.runtime.getURL` 路径
2. **injector.ts** 将资源以 `<script>` 或 `<link>` 标签注入页面 DOM
3. 注入前检查全局存在性（`global-existence check`），已存在则跳过
4. 所有 vendor 库本地化存放于 `public/cdn/vendor/`，满足 MV3 CSP 合规

### 4.3 资源类型

| 类别 | 路径 | 内容 |
|------|------|------|
| 工具库 | `public/cdn/utils/api-client.ts` | 共享 HTTP 客户端基类 |
| 样式 | `public/cdn/styles/variables.css` | CSS 设计变量 |
| 样式 | `public/cdn/styles/chat.css` | Chat 组件串联样式（buildChatCSS 生成） |
| Vendor | `public/cdn/vendor/` | 第三方库（React、Ant Design 等） |

## 五、API 层架构

### 5.1 四层架构

```
┌─────────────────────────────────────┐
│ 第 4 层：领域服务 (services/*.ts)     │
│ AuthService, ChatService,            │
│ SessionService, KnowledgeService ... │
│ 构造函数注入 ApiClient                │
├─────────────────────────────────────┤
│ 第 3 层：类型定义 (types.ts)          │
│ 请求/响应接口，单一数据源             │
├─────────────────────────────────────┤
│ 第 2 层：路径常量 (endpoints.ts)      │
│ 按域分组的 API 路径常量              │
├─────────────────────────────────────┤
│ 第 1 层：HttpClient (client.ts)      │
│ ApiClient 类：fetch + 重试 +         │
│ 错误提取 + SSE 流式 + 开发日志       │
│ 基类：public/cdn/utils/api-client.ts │
└─────────────────────────────────────┘
```

### 5.2 跨项目协议

所有 API 调用使用统一的 RPC 信封：

```json
POST /  body: {
  "module_name": "services.<domain>.<service>",
  "method_name": "<method>",
  "parameters": { ... }
}
response: { "code": 0, "message": "ok", "data": <any> }
```

### 5.3 关键参数名称契约

| 正确 | 错误 | 上下文 |
|------|------|--------|
| `filter` | `query` | `data_service.query_documents` 参数 |
| `target_file` | `path` | `/read-file`, `/write-file` 端点 |
| `cname` | `collection_name` | `data_service` 集合参数 |

## 六、Chat 控制器

### 6.1 状态管理

使用 React 18 的 `useSyncExternalStore` 实现外部状态订阅：

```
ChatController (单例)
    │
    ├── state: ChatState (内部可变状态)
    ├── listeners: Set<() => void> (订阅者集合)
    │
    ├── getState(): ChatState (快照读取)
    ├── subscribe(listener): () => void (订阅/取消订阅)
    │
    ├── actions: { sendMessage, stopSending, ... }
    │   └── 每个 action 修改 state 后调用 _emit() 通知所有订阅者
    │
    └── useSyncExternalStore(ctrl.subscribe, ctrl.getState)
        └── React 组件自动在 state 变化时重渲染
```

### 6.2 SSE 流式对话

```
User 输入消息
    │
    ▼ sendMessage(text)
    │
    ├── 1. 追加 user message 到 state.messages
    ├── 2. 追加空 assistant message（streaming: true）
    ├── 3. _emit() 通知 UI 更新
    │
    ▼ _runStream(messages)
    │
    ├── knowledgeGrounded === true
    │   ├── ragScopeIsFile → RagService.streamFileChat({target_file, question})
    │   └── !ragScopeIsFile → RagService.streamChat({messages, scope})
    │
    ├── knowledgeGrounded === false
    │   └── ChatService.streamWithCallback({messages, onToken, onDone, onError})
    │
    ▼ ApiClient.stream()
    │
    ├── POST /  body: { module_name, method_name, parameters: { model, messages, stream: true } }
    ├── 解析 SSE: data: {"data": {"message": "..."}}\n\n
    │
    ▼ onToken(chunk)
    │   └── 追加 text 到当前 assistant message.content
    │       └── _emit() → React 重渲染
    │
    ▼ onDone()
        └── 设置 streaming: false, 持久化会话
```

## 九、设计原则

### 9.1 一致性

- 所有 API 调用遵循四层架构
- 所有组件使用 co-located CSS
- 所有用户可见文本使用 chrome.i18n
- 所有时间戳使用 UTC ISO 8601 存储

### 9.2 可维护性

- TypeScript strict mode 保证类型安全
- 领域驱动的 API 服务划分
- 清晰的关注点分离（API、类型、组件、状态）
- 单一职责原则

### 9.3 CSP 合规

- 无远程代码加载
- 无 `eval` 调用
- 无内联脚本
- 所有 vendor 库本地化

### 9.4 优雅降级

| 条件 | 降级策略 |
|------|---------|
| YiAi 后端不可达 | ApiClient 指数退避重试，返回类型化错误 |
| CDN 资源已加载 | 全局存在性检查，跳过重复注入 |
| Chrome Storage 配额超限 | 静默失败，开发模式输出警告日志 |
| 语言 key 缺失 | 回退到 en 源语言 -> 回退到 key 本身 |
