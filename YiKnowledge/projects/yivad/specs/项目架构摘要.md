## 三、状态与存储管理方案

### 3.1 Pinia 状态管理

YiVad 使用 Pinia 4 搭配 `pinia-plugin-persistedstate` 进行状态持久化。所有 Store 均采用 setup-function 语法。

**全局 Stores** (`src/stores/modules/`):

| Store | 用途 | 持久化 |
|-------|------|--------|
| `global.ts` | 应用配置：布局模式、主题色、暗色主题、语言 | localStorage |
| `user.ts` | 用户认证信息：token、用户详情 | localStorage |
| `auth.ts` | 权限信息：菜单列表、按钮权限列表 | - |
| `tabs.ts` | 标签页状态 | - |
| `keepAlive.ts` | 页面缓存状态 | - |
| `aiChat.ts` | AI 聊天状态：SSE 流式传输、Agent 循环、确认机制 | - |
| `knowledge.ts` | 知识库状态 | - |
| `knowledgeTree.ts` | 知识库树状态 | - |
| `rag.ts` | RAG 检索状态 | - |
| `story.ts` | Story 状态 | - |
| `bug.ts` | Bug 状态 | - |
| `issue.ts` | Issue 状态 | - |
| `project.ts` | 项目状态 | - |
| `module.ts` | 模块状态 | - |
| `page.ts` | 页面状态 | - |
| `rss.ts` | RSS 状态 | - |

### 3.2 持久化方案

使用 `pinia-plugin-persistedstate`，对 `global` 和 `user` Store 进行 localStorage 持久化：

```typescript
// src/stores/index.ts
import { createPinia } from "pinia";
import piniaPluginPersistedstate from "pinia-plugin-persistedstate";

const pinia = createPinia();
pinia.use(piniaPluginPersistedstate);
export default pinia;
```

### 3.3 Store 书写规范

```typescript
// Stores 使用 setup-function 语法
export const useGlobalStore = defineStore("yivad-global", () => {
  const isDark = ref(false);
  const language = ref("zh");
  // ...
  return { isDark, language };
```

## 四、API 请求封装

### 4.1 RequestHttp 类 (`src/api/index.ts`)

YiVad 使用自定义 `RequestHttp` 类封装 Axios，提供统一的请求拦截和响应处理：

- **自动 Token 注入**：请求拦截器从 `useUserStore` 获取 token 并注入 `Authorization` Header
- **全屏 Loading**：默认显示全屏加载动画，可通过 `{ loading: false }` 关闭
- **请求去重**：通过 `AxiosCanceler` 自动取消重复请求，可通过 `{ cancel: false }` 关闭
- **统一错误处理**：登录过期自动跳转登录页；业务错误码自动弹出消息提示
- **超时/网络错误**：专门的错误提示和处理

### 4.2 RPC 信封协议

所有跨项目 API 调用使用统一的 RPC 信封格式：

```
POST /  body: {
  "module_name": "services.<domain>.<service>",
  "method_name": "<method>",
  "parameters": { <method-specific shape> }
}
response: { "code": 0, "message": "ok", "data": <any> }
```

### 4.3 API 模块文件模式 (`src/api/modules/*.ts`)

每个 API 模块文件导出领域相关的服务函数，内部调用 `http.post("", { module_name, method_name, parameters })`：

```typescript
import http from "@/api/index";

// 通用 RPC 调用
export function callService<T>(module: string, method: string, params: Record<string, any> = {}): Promise<YiAiEnvelope<T>> {
  const payload = { module_name: module, method_name: method, parameters: params };
  return http.post<T>("", payload, { cancel: false });
}

// 文档查询
export function queryDocuments<T>(params: QueryDocumentsParams): Promise<YiAiEnvelope<QueryDocumentsData<T>>> {
  return callService<QueryDocumentsData<T>>("services.database.data_service", "query_documents", params);
}
```

### 4.4 关键参数名约定

| 正确 | 错误 | 上下文 |
|------|------|--------|
| `filter` | `query` | `data_service.query_documents` 参数 |
| `target_file` | `path` | `/read-file`, `/write-file` 接口 |
| `cname` | `collection_name` | `data_service` 集合名称参数 |

## 五、路由配置

### 5.1 路由特点

- **模式**：Hash 模式 (`createWebHashHistory()`)
- **动态路由**：从后端菜单 API 加载，失败时降级到 `src/assets/json/authMenuList.json`
- **权限守卫**：全局前置守卫检查 token、加载菜单、添加动态路由
- **标签页缓存**：通过 `keepAlive` Store 管理页面缓存

### 5.2 路由结构

```typescript
// src/routers/index.ts
const router = createRouter({
  history: routerMode[mode](), // hash 或 history
  routes: [...staticRouter, ...errorRouter],
  strict: false,
  scrollBehavior: () => ({ left: 0, top: 0 })
});

// 全局前置守卫
router.beforeEach(async (to, from) => {
  // 1. NProgress 进度条
  // 2. 设置 document.title
  // 3. 登录页检查：已登录则跳转首页
  // 4. 白名单路由直接放行
  // 5. 无 token 则跳转登录页
  // 6. 无菜单列表则请求后端菜单 API 并添加动态路由
  // 7. 存储 routeName 用于按钮权限过滤
});
```

### 5.3 路由元信息

| 元信息字段 | 说明 |
|------------|------|
| `meta.icon` | 菜单和面包屑图标 |
| `meta.title` | 路由标题（document.title 和菜单名称） |
| `meta.activeMenu` | 详情页高亮对应菜单 |
| `meta.isLink` | 外部链接 |
| `meta.isHide` | 是否在菜单中隐藏 |
| `meta.isFull` | 是否全屏 |
| `meta.isAffix` | 是否在标签页中固定（如首页） |
| `meta.isKeepAlive` | 是否缓存页面 |

## 六、组件设计

### 6.1 组件分类

| 组件类型 | 技术选型 | 使用场景 |
|---------|---------|---------|
| Vue SFC | `<script setup lang="ts">` + Composition API | 绝大多数页面和组件 |
| 全局组件 | 在 `src/components/index.ts` 注册 | 跨页面复用的通用组件 |

### 6.2 ProTable 表格组件（标准表格模式）

ProTable 是 YiVad 的标准表格组件，**新表格页面必须使用 ProTable**，不直接使用 `el-table`。

ProTable 的核心特性：
- 接收 `columns` 配置数组和 `requestApi` 请求函数
- 自动处理分页（`pageNum`、`pageSize`、`total`）
- 支持搜索表单（通过 `searchCol` 配置）
- 支持选择列（`isSelected`）
- 支持枚举格式化（`enum` 配置）
- 支持自定义渲染（`render` 函数）

### 6.3 ECharts 图表组件

通过 `src/components/ECharts/` 封装，提供统一的图表初始化和配置接口。

### 6.4 SearchForm 搜索表单

`src/components/SearchForm/` 提供搜索表单组件，支持：
- 表单项配置数组
- 重置和搜索按钮
- 与 ProTable 联动

### 6.5 上传与富文本

- **Upload 组件** (`src/components/Upload/`)：文件上传，支持图片/文件上传
- **WangEditor** (`src/components/WangEditor/`)：富文本编辑器封装

### 6.6 布局组件

四套布局模式共享 Header / Menu / Footer / Tabs 组件：

| 布局模式 | 目录 | 说明 |
|----------|------|------|
| 纵向布局 | `LayoutVertical/` | 侧边栏垂直菜单 |
| 经典布局 | `LayoutClassic/` | 顶部导航 + 侧边栏 |
| 横向布局 | `LayoutTransverse/` | 顶部导航 |
| 分栏布局 | `LayoutColumns/` | 分栏式菜单 |

## 八、权限控制

### 8.1 权限模型

YiVad 的权限控制包含两个层面：

1. **菜单权限**：后端返回菜单列表，前端动态添加路由
2. **按钮权限**：通过 `v-auth` 指令控制按钮级别的显示/隐藏

### 8.2 v-auth 指令

```typescript
// src/directives/modules/auth.ts
const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding;
    const authStore = useAuthStore();
    const currentPageRoles = authStore.authButtonListGet[authStore.routeName] ?? [];
    if (value instanceof Array && value.length) {
      const hasPermission = value.every(item => currentPageRoles.includes(item));
      if (!hasPermission) el.remove();
    } else {
      if (!currentPageRoles.includes(value)) el.remove();
    }
  }
};
```

### 8.3 使用方式

```vue
<!-- 单个权限 -->
<el-button v-auth="'add'">新增</el-button>

<!-- 多个权限（全部满足才显示） -->
<el-button v-auth="['add', 'edit']">操作</el-button>
```

## 九、设计原则

### 一致性

所有页面遵循相同的组件模式：
- 表格页使用 ProTable
- 搜索使用 SearchForm
- 按钮权限使用 v-auth 指令
- 国际化使用 Vue-i18n 模块化语言文件

### 可复用性

- 公共组件在 `src/components/` 中统一管理
- 自定义 Hook 在 `src/hooks/` 中提取共享逻辑
- API 模块在 `src/api/modules/` 中按领域划分

### 可维护性

- 功能域划分清晰的页面目录
- 关注点分离（API、类型、组件、Store）
- 全局守卫统一处理认证和权限

### 可扩展性

- 四套布局模式共用组件
- 动态路由支持按需加载
- 国际化模块化支持新语言扩展
