## 核心组件详解

### ProTable 表格组件

ProTable 是 YiVad 的标准表格组件，**所有新表格页面必须使用 ProTable**，不直接使用 `el-table`。

**核心特性**：
- 通过 `columns` 配置数组定义表格列
- 通过 `requestApi` 传入请求函数，自动处理分页
- 支持搜索表单（通过 `searchCol` 配置搜索项）
- 支持选择列（`isSelected` 属性）
- 支持枚举格式化（`enum` 配置字典数据）
- 支持自定义渲染（`render` 函数）

**基本使用**：

```vue
<template>
  <ProTable
    :columns="columns"
    :requestApi="getTableData"
    :isSelected="true"
    :searchCol="searchCol"
  />
</template>

<script setup lang="ts">
import { ref } from "vue";
import ProTable from "@/components/ProTable/index.vue";

const columns = [
  { prop: "name", label: "名称", width: 200 },
  { prop: "status", label: "状态", enum: statusDict },
  {
    prop: "action",
    label: "操作",
    render: (scope) => {
      return h("el-button", { onClick: () => handleEdit(scope.row) }, "编辑");
    }
  }
];

const getTableData = (params: any) => {
  return queryDocuments({ ...params });
};
</script>
```

| 布局模式 | 组件目录 | 说明 |

## 组件书写约定

### 标准模板

```vue
<script setup lang="ts">
import { ref, computed, onMounted } from "vue";

// Props 定义
const props = withDefaults(
  defineProps<{
    data?: any;
    isEdit?: boolean;
  }>(),
  {
    isEdit: true
  }
);

// Emits 定义
const emit = defineEmits<{
  (event: "update", value: any): void;
}>();

// 本地状态
const loading = ref(false);

// 计算属性
const isDisabled = computed(() => !props.isEdit);

// 生命周期
onMounted(() => {
  // 初始化
});

// 暴露给父组件
defineExpose({
  validate: async () => { /* ... */ }
});
</script>

<template>
  <div class="component-name">
    <!-- 模板内容 -->
  </div>
</template>

<style lang="scss" scoped>
.component-name {
  /* 样式 */
}
</style>
```

### 组件通信模式

| 模式 | 场景 | 示例 |
|------|------|------|
| Props & Events | 父子组件通信 | `defineProps` + `defineEmits` |
| Template Refs | 父调用子方法 | `ref.value.validate()` |
| defineExpose | 子暴露给父 | `defineExpose({ formRef, validate })` |
| Pinia Store | 跨组件共享状态 | `useGlobalStore()` |

## ProTable 高级特性

### 虚拟滚动（大数据量优化）

当表格数据量超过 1000 行时，启用虚拟滚动以优化渲染性能：

```vue
<template>
  <ProTable
    :columns="columns"
    :requestApi="getTableData"
    :virtualScroll="true"
    :virtualScrollItemSize="48"
    :virtualScrollHeight="600"
  />
</template>

<script setup lang="ts">
const columns: ProTable.Column[] = [
  // virtualScroll 模式下，每列必须设置固定 width
  { prop: "name", label: "名称", width: 200 },
  { prop: "status", label: "状态", width: 120 }
];
</script>
```

**虚拟滚动配置**：

| 属性 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `virtualScroll` | `boolean` | `false` | 是否启用虚拟滚动 |
| `virtualScrollItemSize` | `number` | `48` | 每行高度（像素） |
| `virtualScrollHeight` | `number` | `600` | 可视区域高度（像素） |
| `virtualScrollThreshold` | `number` | `100` | 数据量超过此值自动启用虚拟滚动 |

### 列固定与列拖拽

```vue
<template>
  <ProTable
    :columns="columns"
    :columnDraggable="true"
  />
</template>

<script setup lang="ts">
const columns: ProTable.Column[] = [
  { prop: "name", label: "名称", width: 200, fixed: "left" },
  { prop: "status", label: "状态", width: 120 },
  // 操作列固定在右侧
  { prop: "action", label: "操作", width: 200, fixed: "right" }
];
</script>
```

**列固定规则**：
- 首列（选择列）自动固定在左侧
- 操作列固定在右侧（`fixed: "right"`）
- 固定列必须设置 `width`，否则列宽会抖动
- 启用列拖拽时，固定列不可拖拽

### 表格导出

ProTable 支持导出当前数据为 CSV 或 Excel：

```vue
<template>
  <ProTable
    ref="tableRef"
    :columns="columns"
    :requestApi="getTableData"
    :exportConfig="exportConfig"
  />
</template>

<script setup lang="ts">
const exportConfig = {
  enable: true,           // 启用导出
  fileName: "数据导出",   // 导出文件名
  format: "csv",          // 导出格式: "csv" | "xlsx"
  columns: ["name", "status", "createTime"], // 导出列（默认全部）
  maxRows: 10000,         // 最大导出行数
  beforeExport: () => {
    // 导出前回调：可修改导出数据
    return true; // 返回 false 取消导出
  }
};

// 手动触发导出
const handleExport = () => {
  tableRef.value?.exportTable();
};
</script>
```

## 组件懒加载

### defineAsyncComponent 异步组件

对于体积大或不常显示的组件，使用 `defineAsyncComponent` 进行懒加载：

```vue
<script setup lang="ts">
import { defineAsyncComponent } from "vue";
import Loading from "@/components/Loading/index.vue";
import ErrorMessage from "@/components/ErrorMessage/index.vue";

// 基础用法
const MarkdownPreview = defineAsyncComponent(
  () => import("@/components/MarkdownPreview/index.vue")
);

// 完整配置：加载状态 + 错误处理 + 超时
const AiChatBox = defineAsyncComponent({
  loader: () => import("@/components/AiChatBox/index.vue"),
  loadingComponent: Loading,       // 加载时显示
  errorComponent: ErrorMessage,    // 加载失败时显示
  delay: 200,                      // 延迟显示加载组件（毫秒）
  timeout: 10000,                  // 超时时间（毫秒）
  suspensible: true,               // 是否可被 <Suspense> 控制
  onError(error, retry, fail, attempts) {
    // 自定义重试逻辑
    if (attempts <= 3) {
      retry();  // 自动重试
    } else {
      fail();   // 放弃重试，显示错误组件
    }
  }
});
</script>

<template>
  <Suspense>
    <AiChatBox />
    <template #fallback>
      <Loading />
    </template>
  </Suspense>
</template>
```

### 懒加载决策指南

| 场景 | 是否懒加载 | 原因 |
|------|-----------|------|
| 路由页面 | 始终懒加载 | 减小首屏打包体积 |
| 对话框/抽屉组件 | 懒加载 | 用户不触发则不加载 |
| 图表组件 | 懒加载 | ECharts 体积大，按需加载 |
| 富文本编辑器 | 懒加载 | WangEditor 体积大，编辑页才需要 |
| 表格/表单 | 不懒加载 | 核心交互，几乎每次都用 |
| 布局组件 | 不懒加载 | 全局使用，首屏必需 |

## 错误边界模式

YiVad 中通过对特定组件添加错误边界，防止子组件错误导致整个页面崩溃：

```vue
<!-- src/components/ErrorBoundary/index.vue -->
<script setup lang="ts">
import { ref, onErrorCaptured } from "vue";

const error = ref<Error | null>(null);
const hasError = ref(false);

onErrorCaptured((err: Error, instance, info) => {
  error.value = err;
  hasError.value = true;
  console.error("[ErrorBoundary]", err, info);
  return false; // 阻止错误继续向上传播
});

const retry = () => {
  hasError.value = false;
  error.value = null;
};
</script>

<template>
  <div v-if="hasError" class="error-boundary">
    <el-result icon="error" title="组件加载异常" :sub-title="error?.message">
      <template #extra>
        <el-button type="primary" @click="retry">重试</el-button>
      </template>
    </el-result>
  </div>
  <slot v-else />
</template>
```

```vue
<!-- 使用示例 -->
<template>
  <ErrorBoundary>
    <ECharts :options="complexChartOptions" />
  </ErrorBoundary>
</template>
```

## Teleport 使用

YiVad 中 Teleport 用于将组件内容渲染到 DOM 树的其他位置：

### 对话框/抽屉 Teleport 到 body

```vue
<template>
  <!-- 将弹窗渲染到 body 下，避免被父元素 overflow: hidden 裁剪 -->
  <Teleport to="body">
    <el-dialog
      v-model="visible"
      title="编辑"
      width="800px"
      :close-on-click-modal="false"
    >
      <EditForm :data="currentData" @success="visible = false" />
    </el-dialog>
  </Teleport>
</template>
```

### 通知/全局消息

```vue
<template>
  <!-- 将通知渲染到 #notifications 容器 -->
  <Teleport to="#notifications">
    <Transition name="slide">
      <div v-if="showNotification" class="notification">
        {{ notificationMessage }}
      </div>
    </Transition>
  </Teleport>
</template>
```

**Teleport 使用规则**：

| 场景 | 目标选择器 | 说明 |
|------|-----------|------|
| 对话框 | `to="body"` | 避免被 overflow 或 z-index 限制 |
| 抽屉 | `to="body"` | 同上 |
| 全屏遮罩 | `to="body"` | 确保覆盖整个视口 |
| 通知消息 | `to="#notifications"` | 统一的消息容器 |
| 右键菜单 | `to="body"` | 跟随鼠标位置 |

## provide/inject 深度组件树

对于深层嵌套的组件树，使用 `provide/inject` 避免 prop 逐层传递（prop drilling）：

### 提供者组件

```typescript
// 父组件：提供上下文
import { provide, ref, readonly, type InjectionKey } from "vue";

// 定义注入 Key（类型安全）
interface ProjectContext {
  projectId: Ref<string>;
  projectName: Ref<string>;
  canEdit: ComputedRef<boolean>;
  refresh: () => Promise<void>;
}

export const PROJECT_CONTEXT_KEY: InjectionKey<ProjectContext> = Symbol("ProjectContext");

const projectId = ref("proj-001");
const projectName = ref("示例项目");

provide(PROJECT_CONTEXT_KEY, {
  projectId: readonly(projectId),
  projectName: readonly(projectName),
  canEdit: computed(() => authStore.hasPermission("edit")),
  refresh: async () => { /* ... */ }
});
```

### 消费者组件

```typescript
// 深层子组件：注入上下文
import { inject } from "vue";
import { PROJECT_CONTEXT_KEY } from "../parent";

const context = inject(PROJECT_CONTEXT_KEY);

if (!context) {
  throw new Error("ProjectContext 未提供，请确保在正确的父组件下使用");
}

// 使用上下文
const { projectId, projectName, canEdit, refresh } = context;
```

### provide/inject 使用场景

| 场景 | 推荐方式 | 原因 |
|------|----------|------|
| 父子组件（1-2 层） | Props + Emits | 简单直接，数据流清晰 |
| 祖先-后代组件（3 层以上） | provide/inject | 避免 prop drilling |
| 跨组件共享状态 | Pinia Store | 全局状态，非组件树局部 |
| 表单上下文 | provide/inject | 表单是多层嵌套组件树 |
| 主题/语言 | Pinia Store | 全局切换，非组件树局部 |

## 边界情况

### 组件渲染边界

| 边界情况 | 处理方式 | 说明 |
|----------|----------|------|
| 组件数据为空 | 使用 `v-if` + 空状态组件，不直接渲染空表格/空列表 | 给用户明确的状态提示 |
| 组件数据加载失败 | 使用 ErrorBoundary 包裹，显示错误信息 + 重试按钮 | 局部错误不影响整个页面 |
| 组件 props 未传入 | 使用 `withDefaults` 设置默认值 | 防止 undefined 导致的运行时错误 |
| 组件被多次实例化 | 每个实例独立状态，使用 `key` 区分不同实例 | 避免状态污染 |
| 组件在 keep-alive 中 | 使用 `onActivated`/`onDeactivated` 替代 `onMounted`/`onUnmounted` | 缓存组件不会触发 mount/unmount |
| 动态组件切换 | 使用 `<component :is="...">` + `<KeepAlive>` | 切换时保留组件状态 |
| SSR 相关 | 使用 `onMounted` 包裹浏览器 API 调用 | YiVad 是 CSR 应用，但应保持兼容性 |
| 大列表渲染 | 启用 ProTable 虚拟滚动 + 分页 | 避免 DOM 节点过多导致卡顿 |

### ProTable 边界

| 边界情况 | 处理方式 |
|----------|----------|
| 表格数据为空 | 显示 `el-empty` 空状态，提示"暂无数据" |
| 请求失败 | 显示错误信息 + 重试按钮，不替换已有数据 |
| 分页参数异常 | 使用 `Math.max(1, pageNum)` 确保页码 >= 1 |
| 搜索条件为空 | 发送空 filter 对象，后端返回全部数据 |
| 固定列 + 横向滚动 | 固定列在滚动时保持可见，需设置 `width` |
| 列配置过多 | 使用 `columnDraggable` 让用户自定义列宽 |

## 反模式

### 不要这样做

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 直接使用 el-table | `<el-table :data="list">` 替代 ProTable | 使用 `<ProTable :columns="columns" :requestApi="api" />` | ProTable 统一了分页、搜索、选择、权限等逻辑 |
| 不设置组件 key | `<MyComponent v-if="type === 'A'" />` 切换时复用 | `<MyComponent :key="type" v-if="..." />` | 强制重建组件，避免状态残留 |
| 在模板中硬编码文本 | `<el-button>新增</el-button>` | `<el-button>{{ $t("common.add") }}</el-button>` | 国际化缺失，文本散落 |
| 在代码中硬编码权限 | `v-if="userStore.role === 'admin'"` | `v-auth="'add'"` | 权限逻辑分散，难以维护 |
| 使用 Options API | `data() { return {} }, methods: {}` | `<script setup lang="ts">` + Composition API | 违反项目约定，类型推导更弱 |
| 深层 prop 传递 | 父组件通过多层 props 传递数据 | 使用 provide/inject 或 Pinia Store | prop drilling 难以维护 |
| 不清理事件/定时器 | `setInterval` 或 `addEventListener` 不清理 | 使用 `onBeforeUnmount` 清理 | 内存泄漏 |
| 大组件不拆分 | 单个组件超过 500 行 | 提取子组件和 Composables | 可维护性差，难以测试 |
| 为不同布局 fork 组件 | 为每个布局复制 Header/Menu/Footer/Tabs | 共享基础组件，通过 props 差异化 | 代码重复，bug 修复需要同步 |
| 不使用懒加载 | 所有组件在首屏加载 | 路由页面懒加载，大组件用 defineAsyncComponent | 首屏加载慢 |
| 固定列不设 width | `{ prop: "name", fixed: "left" }` 没有 width | `{ prop: "name", fixed: "left", width: 200 }` | 列宽抖动，布局错乱 |
