# Spec: API Conventions

## 概述

本规范定义了 YiVad 的 API 请求封装、文件组织、命名规范、函数签名等约定。所有 API 调用必须通过 `src/api/index.ts` 中的 `RequestHttp` 类，不直接使用 Axios。

## RequestHttp 封装

### 核心配置

```typescript
// src/api/index.ts
import axios from "axios";
import { showFullScreenLoading, tryHideFullScreenLoading } from "@/components/Loading/fullScreen";

class RequestHttp {
  service: AxiosInstance;

  public constructor(config: AxiosRequestConfig) {
    this.service = axios.create(config);

    // 请求拦截器：自动注入 Token + 全屏 Loading + 请求去重
    this.service.interceptors.request.use(
      (config: CustomAxiosRequestConfig) => {
        config.loading ??= true;
        config.loading && showFullScreenLoading();
        // 注入 Authorization Header
        config.headers.set("Authorization", `Bearer ${userStore.token}`);
        return config;
      }
    );

    // 响应拦截器：统一错误处理 + 登录过期跳转
    this.service.interceptors.response.use(
      (response) => {
        config.loading && tryHideFullScreenLoading();
        // 登录过期处理
        if (data.code == ResultEnum.OVERDUE) {
          userStore.setToken("");
          router.replace(LOGIN_URL);
        }
        return data;
      }
    );
  }
}
```

## RPC 信封格式

YiVad 与 YiAi 后端通信使用统一的 RPC 信封协议：

```typescript
// POST /
{
  "module_name": "services.<domain>.<service>",
  "method_name": "<method>",
  "parameters": { <method-specific shape> }
}

// 响应
{
  "code": 0,
  "message": "ok",
  "data": <any>
}
```

### 通用 RPC 调用函数

```typescript
// src/api/modules/dataService.ts
import http from "@/api/index";

export function callService<T = any>(
  module: string,
  method: string,
  params: Record<string, any> = {},
  timeout?: number
): Promise<YiAiEnvelope<T>> {
  const payload: ServicePayload = {
    module_name: module,
    method_name: method,
    parameters: params
  };
  // RPC 调用为幂等请求，关闭自动去重
  return http.post<YiAiEnvelope<T>>("", payload, { cancel: false, ...(timeout ? { timeout } : {}) });
}
```

## SSE 流式请求处理

YiVad 中 AI 聊天和 Agent 服务使用 SSE（Server-Sent Events）流式传输。SSE 请求有以下特殊处理模式：

### SSE 请求封装

```typescript
// src/api/modules/chatService.ts
export async function streamChat(
  payload: ChatPayload,
  onChunk: (text: string) => void,
  onDone: () => void,
  onError: (err: Error) => void,
  signal?: AbortSignal
): Promise<void> {
  const token = useUserStore().token;
  const baseUrl = import.meta.env.RSBUILD_API_BASE || "http://localhost:10086";

  try {
    const response = await fetch(`${baseUrl}/`, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${token}`
      },
      body: JSON.stringify({
        module_name: "services.ai.chat_service",
        method_name: "chat",
        parameters: payload
      }),
      signal  // 支持 AbortController 取消
    });

    if (!response.ok) {
      throw new Error(`SSE 连接失败: ${response.status}`);
    }

    const reader = response.body?.getReader();
    if (!reader) throw new Error("不支持流式读取");

    const decoder = new TextDecoder();
    let buffer = "";

    while (true) {
      const { done, value } = await reader.read();
      if (done) {
        onDone();
        break;
      }

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split("\n");
      buffer = lines.pop() || "";

      for (const line of lines) {
        if (line.startsWith("data: ")) {
          const data = line.slice(6);
          if (data === "[DONE]") {
            onDone();
            return;
          }
          try {
            const parsed = JSON.parse(data);
            if (parsed.content) {
              onChunk(parsed.content);
            }
          } catch {
            // 非 JSON 文本直接作为内容
            onChunk(data);
          }
        }
      }
    }
  } catch (err: any) {
    if (err.name === "AbortError") {
      // 用户主动取消，不触发错误回调
      return;
    }
    onError(err);
  }
}
```

### SSE 断线重连策略

```typescript
// 自动重连 Hook
export function useSseReconnect(
  streamFn: (signal: AbortSignal) => Promise<void>,
  options: {
    maxRetries?: number;     // 最大重试次数，默认 3
    retryDelay?: number;     // 重试延迟（毫秒），默认 2000
    backoffMultiplier?: number; // 退避乘数，默认 2
  } = {}
) {
  const { maxRetries = 3, retryDelay = 2000, backoffMultiplier = 2 } = options;
  const retryCount = ref(0);
  const isReconnecting = ref(false);
  const abortController = ref<AbortController>();

  const start = async () => {
    abortController.value = new AbortController();
    try {
      await streamFn(abortController.value.signal);
    } catch (err) {
      if (retryCount.value < maxRetries) {
        isReconnecting.value = true;
        retryCount.value++;
        const delay = retryDelay * Math.pow(backoffMultiplier, retryCount.value - 1);
        await new Promise(resolve => setTimeout(resolve, delay));
        isReconnecting.value = false;
        await start();
      }
    }
  };

  const abort = () => {
    abortController.value?.abort();
  };

  return { start, abort, retryCount, isReconnecting };
}
```

## 请求重试模式

对于网络不稳定或临时性后端错误，YiVad 使用请求重试模式：

```typescript
// src/api/helper/retry.ts
interface RetryConfig {
  maxRetries?: number;      // 最大重试次数，默认 3
  retryDelay?: number;      // 基础延迟（毫秒），默认 1000
  backoffMultiplier?: number; // 退避乘数，默认 2
  retryOnStatus?: number[]; // 触发重试的 HTTP 状态码，默认 [502, 503, 504]
  onRetry?: (attempt: number, error: any) => void; // 重试回调
}

export async function withRetry<T>(
  requestFn: () => Promise<T>,
  config: RetryConfig = {}
): Promise<T> {
  const {
    maxRetries = 3,
    retryDelay = 1000,
    backoffMultiplier = 2,
    retryOnStatus = [502, 503, 504],
    onRetry
  } = config;

  let lastError: any;

  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      return await requestFn();
    } catch (error: any) {
      lastError = error;
      const status = error?.response?.status;

      // 只有可重试的状态码才重试
      if (status && !retryOnStatus.includes(status)) {
        throw error;
      }

      if (attempt < maxRetries) {
        const delay = retryDelay * Math.pow(backoffMultiplier, attempt);
        onRetry?.(attempt + 1, error);
        await new Promise(resolve => setTimeout(resolve, delay));
      }
    }
  }

  throw lastError;
}

// 使用示例
const data = await withRetry(
  () => queryDocuments({ cname: "projects", filter: {} }),
  { maxRetries: 2, retryDelay: 1000 }
);
```

## 请求去重与 AbortController

YiVad 使用 `AxiosCanceler` 管理请求去重，核心机制：

```typescript
// src/api/helper/axiosCancel.ts
import type { AxiosRequestConfig, Canceler } from "axios";
import axios from "axios";

export class AxiosCanceler {
  private pendingMap: Map<string, Canceler> = new Map();

  // 生成请求唯一标识
  private getPendingKey(config: AxiosRequestConfig): string {
    const { method, url, params, data } = config;
    return [method, url, JSON.stringify(params), JSON.stringify(data)].join("&");
  }

  // 添加待处理请求
  addPending(config: AxiosRequestConfig): void {
    // 请求前移除已有相同请求（去重）
    this.removePending(config);

    const key = this.getPendingKey(config);
    config.cancelToken = new axios.CancelToken(cancel => {
      if (!this.pendingMap.has(key)) {
        this.pendingMap.set(key, cancel);
      }
    });
  }

  // 移除并取消请求
  removePending(config: AxiosRequestConfig): void {
    const key = this.getPendingKey(config);
    const cancel = this.pendingMap.get(key);
    if (cancel) {
      cancel(`${key} 请求被取消`);
      this.pendingMap.delete(key);
    }
  }

  // 移除所有待处理请求（用于路由切换时清理）
  removeAllPending(): void {
    this.pendingMap.forEach(cancel => cancel());
    this.pendingMap.clear();
  }
}

// 路由切换时取消所有待处理请求
router.beforeEach(() => {
  axiosCanceler.removeAllPending();
});
```

## 批量操作模式

YiVad 中批量操作（批量删除、批量更新）使用以下模式：

```typescript
// src/api/modules/batchService.ts
import http from "@/api/index";
import { ElMessage } from "element-plus";

/** 批量操作请求 */
export interface BatchOperationParams {
  collection: string;
  ids: string[];
  operation: "delete" | "update" | "archive";
  data?: Record<string, any>;  // 更新时的数据
}

/** 批量操作结果 */
export interface BatchOperationResult {
  success: number;
  failed: number;
  errors: Array<{ id: string; error: string }>;
}

/**
 * 执行批量操作（并发控制 + 错误收集）
 * @param params - 批量操作参数
 * @param concurrency - 并发数，默认 5
 */
export async function executeBatchOperation(
  params: BatchOperationParams,
  concurrency: number = 5
): Promise<BatchOperationResult> {
  const { collection, ids, operation, data } = params;
  const result: BatchOperationResult = { success: 0, failed: 0, errors: [] };

  // 分批并发执行
  for (let i = 0; i < ids.length; i += concurrency) {
    const batch = ids.slice(i, i + concurrency);
    const promises = batch.map(async (id) => {
      try {
        if (operation === "delete") {
          await http.post("", {
            module_name: "services.database.data_service",
            method_name: "delete_document",
            parameters: { cname: collection, key: { _id: id } }
          }, { cancel: false });
        } else if (operation === "update") {
          await http.post("", {
            module_name: "services.database.data_service",
            method_name: "update_document",
            parameters: { cname: collection, key: { _id: id }, data }
          }, { cancel: false });
        }
        result.success++;
      } catch (error: any) {
        result.failed++;
        result.errors.push({ id, error: error?.message || "未知错误" });
      }
    });
    await Promise.allSettled(promises);
  }

  return result;
}

// 使用示例
const handleBatchDelete = async (ids: string[]) => {
  const result = await executeBatchOperation({
    collection: "projects",
    ids,
    operation: "delete"
  });

  if (result.failed > 0) {
    ElMessage.warning(`删除完成：成功 ${result.success} 条，失败 ${result.failed} 条`);
  } else {
    ElMessage.success(`成功删除 ${result.success} 条记录`);
  }
};
```

## 乐观更新模式

对于需要即时反馈的操作（如切换状态、点赞），使用乐观更新模式：

```typescript
// src/hooks/useOptimisticUpdate.ts
import { ref } from "vue";

export function useOptimisticUpdate<T extends Record<string, any>>(
  updateApi: (data: T) => Promise<any>,
  options: {
    onSuccess?: () => void;
    onError?: (error: any, previousData: T) => void;
    rollbackDelay?: number;
  } = {}
) {
  const isUpdating = ref(false);
  const error = ref<string | null>(null);

  const execute = async (newData: T, previousData: T) => {
    isUpdating.value = true;
    error.value = null;

    try {
      await updateApi(newData);
      options.onSuccess?.();
    } catch (err: any) {
      error.value = err?.message || "操作失败";
      // 回滚到之前的数据
      options.onError?.(err, previousData);
    } finally {
      isUpdating.value = false;
    }
  };

  return { execute, isUpdating, error };
}

// 使用示例：状态切换
const handleToggleStatus = async (row: ProjectItem) => {
  const previousStatus = row.status;
  const newStatus = row.status === "active" ? "inactive" : "active";

  // 乐观更新 UI
  row.status = newStatus;

  await optimisticUpdate.execute(
    { ...row, status: newStatus },
    { ...row, status: previousStatus }
  );
};
```

## 文件上传与进度

YiVad 中文件上传使用 `el-upload` 组件配合自定义上传逻辑：

```typescript
// src/api/modules/upload.ts
import http from "@/api/index";
import type { UploadProgressEvent } from "@/api/interface";

export interface UploadFileParams {
  file: File;
  collection?: string;    // 关联的集合名称
  documentId?: string;    // 关联的文档 ID
  onProgress?: (percent: number) => void;
}

export interface UploadFileResult {
  fileId: string;
  fileName: string;
  fileSize: number;
  url: string;
}

/**
 * 上传文件（带进度回调）
 * 大文件使用 FormData 直接上传，小文件使用 RPC 信封
 */
export async function uploadFile(params: UploadFileParams): Promise<UploadFileResult> {
  const { file, collection, documentId, onProgress } = params;

  // 大文件（> 5MB）使用 FormData 直传
  if (file.size > 5 * 1024 * 1024) {
    const formData = new FormData();
    formData.append("file", file);
    if (collection) formData.append("collection", collection);
    if (documentId) formData.append("documentId", documentId);

    const { data } = await http.post<UploadFileResult>("/upload", formData, {
      headers: { "Content-Type": "multipart/form-data" },
      onUploadProgress: (progressEvent: UploadProgressEvent) => {
        if (onProgress && progressEvent.total) {
          const percent = Math.round((progressEvent.loaded * 100) / progressEvent.total);
          onProgress(percent);
        }
      }
    });
    return data;
  }

  // 小文件使用 Base64 编码通过 RPC 传输
  return new Promise((resolve, reject) => {
    const reader = new FileReader();
    reader.onload = async () => {
      try {
        const base64 = (reader.result as string).split(",")[1];
        const { data } = await http.post<UploadFileResult>("", {
          module_name: "services.file.upload_service",
          method_name: "upload_base64",
          parameters: {
            file_name: file.name,
            file_data: base64,
            content_type: file.type,
            collection,
            document_id: documentId
          }
        }, { cancel: false });
        resolve(data);
      } catch (err) {
        reject(err);
      }
    };
    reader.onerror = reject;
    reader.readAsDataURL(file);
  });
}
```

## 边界情况

### 网络异常处理

| 边界情况 | 处理方式 | 说明 |
|----------|----------|------|
| 网络断开 | `RequestHttp` 响应拦截器捕获 `Network Error`，弹出"网络连接失败"提示 | 不自动重试，由用户手动触发 |
| 请求超时 | 根据端点类型设置不同超时时间（`TIMEOUT_CONFIG`），超时后弹出"请求超时"提示 | 查询类 15s，上传类 120s |
| 并发请求过多 | `AxiosCanceler` 自动取消重复请求，仅保留最新一次 | 防止用户快速点击导致的请求堆积 |
| 路由切换时请求未完成 | 路由守卫中调用 `axiosCanceler.removeAllPending()` 取消所有待处理请求 | 防止旧页面数据污染新页面 |
| Token 过期 | 响应拦截器检测 `ResultEnum.OVERDUE`，清除 token 并跳转登录页 | 静默处理，不弹出错误提示 |
| 后端 500 错误 | 响应拦截器统一弹出"服务器错误"提示 | 不自动重试 |
| 后端 502/503/504 | 使用 `withRetry` 包装，自动重试最多 3 次 | 退避策略：1s → 2s → 4s |
| 请求被用户取消 | `AbortError` 静默处理，不触发错误回调 | 用于 SSE 停止生成、组件卸载清理 |

### 并发请求竞态条件

```typescript
// 防止搜索输入时的竞态条件
let searchRequestId = 0;

const handleSearch = async (keyword: string) => {
  const requestId = ++searchRequestId;
  const result = await searchApi(keyword);

  // 只处理最新请求的响应
  if (requestId === searchRequestId) {
    searchResults.value = result;
  }
};
```

## 反模式

### 不要这样做

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 直接使用 axios/fetch | `const res = await axios.get("/api/data")` | `import http from "@/api/index"; await http.get("/api/data")` | 绕过了 RequestHttp 的拦截器、Token 注入、Loading 管理 |
| 硬编码 API 路径 | `http.post("/api/v1/projects", data)` | 在 `src/api/modules/` 中定义服务函数，使用 `@/api` 路径别名 | 路径变更时需要修改多处 |
| 在 API 文件中写业务逻辑 | 在 `dataService.ts` 中处理数据格式转换 | 业务逻辑放在组件或 Store 中，API 层只负责请求 | 关注点分离，API 层应保持纯粹 |
| 忽略请求取消 | 组件卸载后请求回调仍修改状态 | 使用 `onBeforeUnmount` 清理，或使用 `AbortController` | 导致"已卸载组件状态更新"警告 |
| 在循环中逐个请求 | `for (const id of ids) { await deleteApi(id); }` | 使用 `executeBatchOperation` 并发执行 | 性能差，用户等待时间长 |
| 参数名使用 `query` | `queryDocuments({ query: {...} })` | `queryDocuments({ filter: {...} })` | 后端 422 错误，参数名必须用 `filter` |
| 参数名使用 `path` | `readFile({ path: "/file.md" })` | `readFile("/file.md")` 或 `readFile({ target_file: "/file.md" })` | 后端 422 错误，参数名必须用 `target_file` |
| 不处理 SSE 中断 | 用户关闭页面后 SSE 连接未断开 | 使用 `onBeforeUnmount(() => abortController.abort())` | 资源泄漏，服务器继续推送数据 |

## 约束

### 必须遵守

- API 文件必须放在 `src/api/modules/` 目录
- 所有 API 调用必须通过 `RequestHttp` 实例（`import http from "@/api/index"`）
- 请求参数和返回值必须定义类型（不使用 `any`）
- RPC 调用使用 `callService` 或对应的领域服务函数
- 文件读写使用 `target_file` 参数名（不是 `path`）
- 数据查询使用 `filter` 参数名（不是 `query`）
- SSE 流式请求必须处理 `AbortError`，组件卸载时取消请求
- 批量操作使用 `executeBatchOperation` 模式，控制并发数
- 大文件上传使用 FormData + 进度回调，小文件使用 Base64 + RPC
- 网络不稳定场景使用 `withRetry` 包装请求

### 禁止

- 不要在组件或 Store 中直接 `import axios` 或调用 `fetch`
- 不要硬编码 API 路径
- 不要在 API 文件中编写业务逻辑
- 不要使用 `path` 作为文件路径参数名
- 不要使用 `query` 作为查询参数名
- 不要在循环中逐个执行批量操作
- 不要忽略 SSE 请求的取消清理
- 不要对所有请求使用相同的超时时间
