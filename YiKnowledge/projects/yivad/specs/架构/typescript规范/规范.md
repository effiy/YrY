# Spec: TypeScript Type Conventions

## 概述

本规范定义了 YiVad 项目中 TypeScript 类型的命名规范、文件组织、类型推导模式等约定。YiVad 使用 TypeScript strict 模式，`vue-tsc --noEmit` 必须通过。

## 类型文件结构

### 文件位置

| 类型用途 | 文件位置 | 说明 |
|----------|----------|------|
| 全局类型声明 | `src/typings/globals.d.ts` | 全局模块声明、Window 扩展 |
| Rsbuild 环境类型 | `src/rsbuild-env.d.ts` | 环境变量类型 |
| API 接口类型 | `src/api/interface/index.ts` | 通用接口类型（ResultData 等） |
| YiAi 接口类型 | `src/api/interface/yiweb.ts` | RPC 信封、聊天消息等 YiAi 类型 |
| Store 类型 | `src/stores/interface/` | Store 状态类型 |
| Hooks 类型 | `src/hooks/interface/` | Hook 相关类型 |
| 枚举常量 | `src/enums/` | HTTP 状态码、请求方法等枚举 |

## 类型命名规范

### 基础命名模式

| 后缀 | 用途 | 示例 |
|------|------|------|
| `Props` | 组件 Props 类型 | `ProTableProps`, `UploadProps` |
| `Params` | 请求参数类型 | `QueryDocumentsParams`, `ChatParams` |
| `Data` | 响应数据类型 | `QueryDocumentsData`, `ChatData` |
| `State` | Store 状态类型 | `GlobalState`, `AuthState` |
| `Result` | 接口返回结果 | `ResultData<T>` |

### 接口命名

```typescript
// 使用 PascalCase，无 I 前缀
export interface QueryDocumentsParams {
  cname: string;
  filter?: Record<string, any>;
  pageNum?: number;
  pageSize?: number;
}

// Store 状态接口
export interface AuthState {
  authButtonList: Record<string, string[]>;
  authMenuList: MenuItem[];
  routeName: string;
}
```

### 类型别名

```typescript
// 联合类型
type LayoutMode = "vertical" | "classic" | "transverse" | "columns";

// 函数类型
type RequestApi = (params: any) => Promise<any>;

// 泛型类型
type YiAiEnvelope<T> = {
  code: number;
  message: string;
  data: T;
};
```

## 类型定义模式

### 组件 Props

```typescript
// 使用 defineProps 的泛型形式
const props = withDefaults(
  defineProps<{
    data?: ProjectData;
    isEdit?: boolean;
    loading?: boolean;
  }>(),
  {
    isEdit: true,
    loading: false
  }
);
```

### 组件 Emits

```typescript
// 使用 defineEmits 的泛型形式
const emit = defineEmits<{
  (event: "update", value: ProjectData): void;
  (event: "delete", id: string): void;
  (event: "close"): void;
}>();
```

### Store 类型


## 严格模式

YiVad 的 `tsconfig.json` 启用 strict 模式，意味着：

- `strict: true` 涵盖所有严格检查
- `noImplicitAny`: 禁止隐式 any
- `strictNullChecks`: 严格空值检查
- `strictFunctionTypes`: 严格函数类型

### 处理空值

```typescript
// 使用可选链
const name = project?.detail?.name;

// 使用空值合并
const displayName = name ?? "未知";

// 使用类型守卫
if (data !== null && data !== undefined) {
  // data 被推断为具体类型
}
```

## 约束

### 必须遵守

- 使用 `interface` 定义对象类型，使用 `type` 定义联合类型/别名
- 类型命名使用 `PascalCase`
- 仅作为类型使用时，使用 `import type` 导入
- 每个字段和接口添加 JSDoc 注释说明用途
- Props 和 Emits 使用泛型形式（`defineProps<{...}>()`）
- 组件 Ref 明确指定类型（如 `ref<FormInstance>()`）

### 禁止

- 不要使用 `I` 前缀（如 `IProject`）
- 不要使用 `any` 类型（除非有充分理由）
- 不要省略必需的 JSDoc 注释
- 不要在类型文件中编写业务逻辑
