# Spec: Auth Conventions

## 概述

本规范定义了 YiVad 的权限控制体系，包括菜单权限（动态路由）和按钮权限（v-auth 指令）。权限数据从后端菜单 API 获取，前端通过 Pinia Store 管理权限状态。

## 权限模型

YiVad 的权限控制分为两个层面：

1. **菜单权限**：控制用户可以看到哪些菜单页面，通过后端返回菜单列表动态生成路由
2. **按钮权限**：控制页面内按钮级别的操作权限，通过 `v-auth` 指令控制

## 权限数据流

```
用户登录 → 后端返回 token
  ↓
路由守卫 → 请求后端菜单 API（getAuthMenuListApi）
  ↓
authStore 存储菜单列表（authMenuList）
  ↓
initDynamicRouter() → 根据菜单列表动态添加路由
  ↓
路由守卫 → 请求按钮权限 API（getAuthButtonListApi）
  ↓
authStore 存储按钮权限列表（authButtonList）
  ↓
页面组件 → v-auth 指令根据 routeName 过滤按钮
```

## Auth Store

### Store 定义

```typescript
// src/stores/modules/auth.ts
export const useAuthStore = defineStore("yivad-auth", {
  state: (): AuthState => ({
    // 按钮权限列表：{ [routeName]: string[] }
    authButtonList: {},
    // 菜单权限列表：原始菜单树
    authMenuList: [],
    // 当前页面路由名，用于按钮权限过滤
    routeName: ""
  }),
  getters: {
    // 按钮权限列表
    authButtonListGet: state => state.authButtonList,
    // 原始菜单数据
    authMenuListGet: state => state.authMenuList,
    // 处理后的侧边栏菜单（过滤 isHide==true 的项，排序）
    showMenuListGet: state => sortMenuTree(getShowMenuList(state.authMenuList)),
    // 扁平化菜单列表（用于添加动态路由）
    flatMenuListGet: state => getFlatMenuList(state.authMenuList),
    // 面包屑导航列表
    breadcrumbListGet: state => getAllBreadcrumbList(state.authMenuList)
  },
  actions: {
    async getAuthButtonList() {
      const { data } = await getAuthButtonListApi();
      this.authButtonList = data;
    },
    async getAuthMenuList() {
      const { data } = await getAuthMenuListApi();
      this.authMenuList = data;
    },
    async setRouteName(name: string) {
      this.routeName = name;
    }
  }
});
```

### 菜单降级策略

当后端菜单 API 不可用时，路由守卫会降级到 `src/assets/json/authMenuList.json` 静态菜单数据。

## v-auth 指令

### 指令定义

```typescript
// src/directives/modules/auth.ts
import { useAuthStore } from "@/stores/modules/auth";

const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding;
    const authStore = useAuthStore();
    const currentPageRoles = authStore.authButtonListGet[authStore.routeName] ?? [];

    if (value instanceof Array && value.length) {
      // 数组模式：所有权限都满足才显示
      const hasPermission = value.every(item => currentPageRoles.includes(item));
      if (!hasPermission) el.remove();
    } else {
      // 字符串模式：单个权限满足即显示
      if (!currentPageRoles.includes(value)) el.remove();
    }
  }
};
```

### 使用方式

```vue
<template>
  <!-- 单个权限 -->
  <el-button v-auth="'add'">新增</el-button>

  <!-- 多个权限（全部满足才显示） -->
  <el-button v-auth="['add', 'edit']">批量操作</el-button>

  <!-- 结合其他指令 -->
  <el-button v-auth="'delete'" type="danger">删除</el-button>
</template>
```

### 权限判断机制

1. 路由守卫在每次路由切换时调用 `authStore.setRouteName(to.name)`
2. `v-auth` 指令的 `mounted` 钩子中，根据 `authStore.routeName` 查找当前页面的按钮权限列表
3. 如果按钮权限值（字符串或数组）不在当前页面的权限列表中，则移除该 DOM 元素

## 动态菜单

### 菜单数据格式

后端返回的菜单数据为树形结构，每个菜单项包含：

```typescript
interface MenuItem {
  path: string;        // 路由路径
  name: string;        // 路由名称（同时用于按钮权限过滤）
  component: string;   // 视图文件路径
  meta: {
    icon: string;      // 菜单图标
    title: string;     // 菜单标题
    isHide: boolean;   // 是否在菜单中隐藏
    isKeepAlive: boolean; // 是否缓存
    isAffix: boolean;  // 是否固定在标签页
    isLink: string;    // 外部链接
  };
  children?: MenuItem[]; // 子菜单
}
```

```typescript

    // 2. 获取按钮权限

      // 降级逻辑

      // 添加路由
    });
  } catch (error) {
    // 降级到静态菜单
  }
};
```

## 权限检查

### 在组件中检查权限

```typescript
import { useAuthStore } from "@/stores/modules/auth";

const authStore = useAuthStore();
// 当前页面的按钮权限列表
const pagePermissions = authStore.authButtonListGet[authStore.routeName] ?? [];
```

### 在模板中使用

```vue
<template>
  <!-- 使用 v-auth 指令（推荐） -->
  <el-button v-auth="'add'">新增</el-button>

  <!-- 通过手动判断（不推荐，除非需要复杂逻辑） -->
  <el-button v-if="pagePermissions.includes('add')">新增</el-button>
</template>
```

## 约束

### 必须遵守

- 按钮权限控制使用 `v-auth` 指令，不手动写 `v-if` 判断权限
- 权限数据从后端 API 获取，前端不硬编码权限列表
- 菜单降级时使用静态 JSON 文件，确保应用可正常访问

### 禁止

- 不要在组件内硬编码权限标识字符串
- 不要在 `v-if` 中直接判断权限（使用 `v-auth` 指令）
- 不要在前端修改权限数据（权限由后端控制）
