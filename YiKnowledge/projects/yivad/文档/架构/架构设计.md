# 架构设计

## 整体架构

YiVad 是一个 Vue 3.5 SPA，采用分层架构模式：

```
┌─────────────────────────────────────────────────────────┐
│  Views (页面组件)                                        │
│  home/ aiChat/ project/ issue/ kanban/ roadmap/ ...     │
├─────────────────────────────────────────────────────────┤
│  Components (30+ 可复用组件) + Hooks (7 组合式函数)       │
│  ProTable/ ECharts/ AiChatBox/ EntityBreadcrumb/ ...    │
├─────────────────────────────────────────────────────────┤
│  Stores (16 Pinia Setup Stores)                          │
│  aiChat/ global/ user/ auth/ project/ knowledge/ ...    │
├─────────────────────────────────────────────────────────┤
│  API Modules (30 领域服务函数)                            │
│  dataService/ chatService/ agentService/ fileService/... │
├─────────────────────────────────────────────────────────┤
│  RequestHttp (Axios 封装)                                │
│  Interceptors/ Canceler/ Error Mapping/ RPC Envelope    │
├─────────────────────────────────────────────────────────┤
│  YiAi Backend (FastAPI :10086)                           │
└─────────────────────────────────────────────────────────┘
```

## 核心数据流

### 表格数据获取 (ProTable)

```
View 定义 columns + requestApi
  → api/modules/<domain>.ts → callService("services.database.data_service",
                                          "query_documents",
                                          { cname, filter, pageNum, pageSize })
  → http.post → YiAi data_service → _build_filter(query_params)
  → MongoDB find().sort().skip().limit()
  → { list, total, pageNum, pageSize, totalPages }
  → ProTable 渲染 rows + Pagination
```

ProTable 是标准表格模式，封装了分页、搜索、排序、选择、导出等功能。所有列表页面统一使用 ProTable，禁止直接使用 `el-table`。

### AI 聊天 (SSE 流式传输)

```
aiChat store → streamChat(payload, onChunk, onDone, onError)
  → fetch POST /  body: { module_name: "services.ai.chat_service",
                          method_name: "chat",
                          parameters: { model, messages, stream: true } }
  → YiAi FastAPI → StreamingResponse(text/event-stream)
  → 逐行解析 SSE (data: {...}\n\n)
  → onChunk(text) → 追加到消息列表
  → onDone() → 持久化会话 + 自动转发到 WeCom
  → onError(err) → 错误提示
```

### Agent 模式 (Pi 风格循环)

```
aiChat store → streamAgentChat(payload, onEvent, onDone)
  → fetch POST /agent/chat
  → Agent 循环:
    turn_start → tool_call → confirmation_required
    → tool_execution_start → tool_execution_end → turn_end
    → (重复直到 max_turns 或 stop=completed)
  → agent_end
```

Agent 特性：
- **确认门控** — 写操作需用户确认，支持聊天输入批准/拒绝
- **模型切换** — 弱模型停滞时自动升级到更强模型
- **预算感知** — 剩余轮次不足时提醒模型压缩步骤
- **断连检测** — 客户端断开时自动中止 Agent 运行
- **Follow-up** — 运行中排队消息，Agent 停止后自动执行
- **Steer** — 运行中实时重定向 Agent 行为

## 多布局系统

四种布局模式共享同一套 Header/Menu/Footer/Tabs 组件：

| 布局 | 特点 |
|------|------|
| Vertical | 左侧垂直菜单，经典后台布局 |
| Classic | 顶部导航 + 左侧菜单 |
| Transverse | 顶部横向菜单 |
| Columns | 分栏式菜单，适合深层级 |

## RPC 协议

所有发往 YiAi 的请求使用统一信封：

```
POST /  body: {
  "module_name": "services.<domain>.<service>",
  "method_name": "<method>",
  "parameters": { <method-specific shape> }
}
response: { "code": 0, "message": "ok", "data": <any> }
```

关键参数名约定：

| 正确 | 错误 | 上下文 |
|------|------|--------|
| `filter` | `query` | `data_service.query_documents` |
| `target_file` | `path` | `/read-file`, `/write-file` |
| `cname` | `collection_name` | `data_service` 集合参数 |

## 降级策略

| 场景 | 行为 |
|------|------|
| 菜单 API 不可用 | 回退到 `authMenuList.json` 静态菜单 |
| Token 过期 | 401 拦截器重定向到登录页，清除 user/auth stores |
| 构建/类型检查失败 | `vue-tsc --noEmit` 阻止构建；commit hooks 阻止提交 |
| SSE 流中断 | 消息标记 `aborted=true`；持久化写入部分内容；跳过 WeCom 自动转发 |
| 浏览器不支持 (IE) | 构建目标仅现代浏览器，ES module 输出 |
