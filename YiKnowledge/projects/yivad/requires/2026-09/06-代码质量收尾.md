### 3.3 消费者改动

> **⚠️ 2026-09-04 缺陷修复**：原方案使用非 scoped `<style lang="scss">` + `@use "@/views/project/styles/markdown-preview"` 导致 SFC 编译失败。
> **根因**：Rsbuild 的 SCSS 处理器（`@rsbuild/plugin-sass` + `additionalData`）在非 scoped 样式块中无法正确解析 `@/` 路径别名，导致 `@use` 静默失败，Vue SFC 编译产物为 `{}`，浏览器报 `Component is missing template or render function: Object`。
> **修复**：放弃 `@use` + `@include` 方案，改为在 scoped 样式块中使用 `:deep(.do-desc-preview)` 内联 markdown 样式。`markdown-preview.scss` 文件保留供后续 Rsbuild 配置修复后使用。

**DetailOverview.vue（scoped 样式块内 `:deep()` 方案）：**

## 7. 实现注意事项

### 7.1 类型迁移顺序（关键）

类型迁移必须按以下顺序，不可打乱：

```
1. 先扩展 types.ts — 追加所有新类型、常量、工具函数（此时旧定义仍存在，不会破坏现有代码）
2. 再更新消费者 — 逐个文件将导入路径从旧位置改为 types.ts，每改一个文件运行 vue-tsc
3. 最后删除旧定义 — 确认所有引用已迁移后，删除各文件中的内联定义
```

每步完成后运行 `vue-tsc --noEmit` 确保类型正确。**不要一次性改完再验证**——分批迁移，分批验证。

### 7.2 roleTagType 提取影响范围

`roleTagType` 在 `detail.vue` 和 `index.vue` 中各自定义了一份完全相同的实现。提取到 `src/utils/role.ts` 后，两处均改为统一导入。

注意 `index.vue` 中可能以不同名称或内联方式使用，需逐一确认：

```bash
# 搜索所有 roleTagType 或角色标签相关的内联实现
grep -rn "role.*tag\|tagType\|roleTagType" src/views/project/ --include="*.vue" --include="*.ts"
```

### 7.3 markdown 样式迁移验证

从 `detail.vue` 删除非 scoped 样式后，需确认以下位置的 markdown 渲染不受影响：
- `DetailOverview.vue` — README.md 预览区
- `DetailDocs.vue` — CLAUDE.md 预览

两处均通过 `@include markdown-preview` 引入样式，确保渲染一致。

### 7.4 KnowledgePreviewDialog 样式独立性

`KnowledgePreviewDialog` 可能依赖 `detail.vue` 的全局 markdown 样式。需在删除前确认：

```bash
grep -rn "KnowledgePreviewDialog" src/views/project/ --include="*.vue"
grep -rn "markdown\|\.preview" src/components/KnowledgePreviewDialog.vue 2>/dev/null
```

若该组件已有独立样式，则无需处理。否则需同步引入 `markdown-preview` mixin。

### 7.5 风险矩阵

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 类型迁移导致类型错误 | 中 | 低 | 分步迁移，每步 vue-tsc 验证 |
