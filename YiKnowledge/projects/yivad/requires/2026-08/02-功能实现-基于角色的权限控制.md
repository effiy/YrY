# 基于角色的权限控制 (RBAC)

> 需求编号：YV-08-01-9 · 优先级：P0 · 人天：8.0d · 状态：已完成
> 依赖：无

## 权限模型对照（前后端统一）

| 含义 | 字段/标识 | 说明 |
|------|----------|------|
| 菜单权限 | `authMenuList` | 后端返回的菜单树，前端据此注册动态路由 + 渲染侧边栏 |
| 按钮权限 | `authButtonList` | 按路由名分组的按钮权限码列表，`{ [routeName]: string[] }` |
| 权限粒度 | 路由级 / 按钮级 | 路由级：动态注册路由；按钮级：`v-auth` 指令控制 DOM |
| 权限存储 | Pinia state + 后端 API | 前端每次路由跳转时重新获取；后端持久化菜单/按钮配置 |
| 降级策略 | 本地 JSON 兜底 | 后端不可用时，fallback 到 `authMenuList.json` + `authButtonList.json` |

权限模型为「用户 → 后端分配的菜单树 + 按钮列表」，权限码按路由名分组，`v-auth` 指令按当前路由名查找对应按钮权限。

## 背景

当前 YiVad 仅区分登录/未登录，所有登录用户拥有相同权限，无法满足外部用户（供应商、合作伙伴）接入的合规要求。需实现细粒度权限控制，支持按钮级和路由级权限管控。

本需求分两阶段实施，均已实现：
- **第一阶段（已实现）**：菜单驱动的动态路由 + 按钮权限指令，后端 API 控制菜单和按钮可见性
- **第二阶段（已实现）**：角色管理页面、用户角色分配、审计日志、权限码常量体系

## 一、动态路由（已实现）

### 1.1 路由守卫流程

`src/routers/index.ts:53-85` — 路由守卫 `beforeEach` 完整流程：

```
用户访问任意页面
  ├── NProgress.start()
  ├── 设置 document.title
  ├── 访问登录页 → token 存在则跳回首页，否则 resetRouter()
  ├── 路由白名单 → 直接放行
  ├── 无 token → 重定向到登录页
  ├── authMenuList 为空 → initDynamicRouter() → 重新跳转当前路由
  └── 存储 routeName 到 authStore（用于按钮权限过滤）
```

### 1.2 动态路由初始化

`src/routers/modules/dynamicRouter.ts:16-62` — `initDynamicRouter()` 核心逻辑：

```typescript
export const initDynamicRouter = async () => {
  const userStore = useUserStore();
  const authStore = useAuthStore();

  try {
    // 1. 获取菜单列表和按钮权限列表
    await authStore.getAuthMenuList();
    await authStore.getAuthButtonList();

    // 2. 菜单为空 → 提示无权限 → 跳转登录页
    if (!authStore.authMenuListGet.length) {
      ElNotification({ title: "No Permission", ... });
      userStore.setToken("");
      router.replace(LOGIN_URL);
      return Promise.reject("No permission");
    }

    // 3. 遍历扁平菜单，逐个 addRoute
    authStore.flatMenuListGet.forEach(item => {
      item.children && delete item.children;
      if (item.component && typeof item.component == "string") {
        // 通过 viewsGlob 映射解析组件路径
        const resolved = modules["/src/views" + item.component + ".vue"];
        if (!resolved) return; // 组件文件不存在时跳过
        item.component = resolved;
      }
      // isFull → 全屏路由；否则 → 注册到 layout 下
      if (item.meta.isFull) {
        router.addRoute(item as unknown as RouteRecordRaw);
      } else {
        router.addRoute("layout", item as unknown as RouteRecordRaw);
      }
    });
  } catch (error) {
    // 请求失败 → 清除 token → 跳转登录页
    userStore.setToken("");
    router.replace(LOGIN_URL);
    return Promise.reject(error);
  }
};
```

### 1.3 路由重置

`src/routers/index.ts:42-48` — 退出登录时清除所有动态路由：

```typescript
export const resetRouter = () => {
  const authStore = useAuthStore();
  authStore.flatMenuListGet.forEach(route => {
    const { name } = route;
    if (name && router.hasRoute(name)) router.removeRoute(name);
  });
};
```

## 二、按钮权限指令 v-auth（已实现）

### 2.1 指令实现

`src/directives/modules/auth.ts` — 8 行核心逻辑：

```typescript
const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding;
    const authStore = useAuthStore();
    const currentPageRoles = authStore.authButtonListGet[authStore.routeName] ?? [];
    if (value instanceof Array && value.length) {
      // 数组：所有权限码都满足才显示
      const hasPermission = value.every(item => currentPageRoles.includes(item));
      if (!hasPermission) el.remove();
    } else {
      // 单值：权限码在列表中即显示
      if (!currentPageRoles.includes(value)) el.remove();
    }
  }
};
```

### 2.2 指令注册

`src/directives/index.ts` — 通过 Vue 插件统一注册，与其他 7 个指令（copy、waterMarker、draggable、debounce、throttle、longpress、sticky）一起安装：

```typescript
const directivesList: { [key: string]: Directive } = {
  auth, copy, waterMarker, draggable, debounce, throttle, longpress, sticky
};
```

### 2.3 指令用法

| 用法 | 示例 | 说明 |
|------|------|------|
| 单权限码 | `v-auth="'add'"` | 当前路由有 `add` 权限时显示 |
| 多权限码（全部满足） | `v-auth="['add', 'delete']"` | 所有权限码都满足才显示 |
| 无权限行为 | — | `el.remove()` 直接移除 DOM 元素 |

### 2.4 权限判断逻辑

```
v-auth="'add'"
  → useAuthStore().authButtonListGet → { [routeName]: string[] }
  → authStore.routeName → 当前路由名（由 router.beforeEach 设置）
  → currentPageRoles = authButtonListGet[routeName] ?? []
  → 'add' in currentPageRoles ? 显示 : el.remove()
```

### 2.5 useAuthButtons Hook

`src/hooks/useAuthButtons.ts` — 将按钮权限列表转为布尔 map，方便在 `<script>` 中使用：

```typescript
export const useAuthButtons = () => {
  const route = useRoute();
  const authStore = useAuthStore();
  const authButtons = authStore.authButtonListGet[route.name as string] || [];

  const BUTTONS = computed(() => {
    let currentPageAuthButton: { [key: string]: boolean } = {};
    authButtons.forEach(item => (currentPageAuthButton[item] = true));
    return currentPageAuthButton;
  });

  return { BUTTONS };
};

// 用法：const { BUTTONS } = useAuthButtons();
//       BUTTONS.value.add === true → 显示添加按钮
```

## 1. v-auth 指令实现 (`src/directives/modules/auth.ts`)

### 1.1 核心逻辑

指令仅在 `mounted` 钩子中执行，`el.remove()` 直接移除 DOM 元素。无权限时不渲染，而非 `display:none` 或 `disabled`。

```typescript
const auth: Directive = {
  mounted(el: HTMLElement, binding: DirectiveBinding) {
    const { value } = binding;
    const authStore = useAuthStore();
    const currentPageRoles = authStore.authButtonListGet[authStore.routeName] ?? [];
    if (value instanceof Array && value.length) {
      const hasPermission = value.every(item => currentPageRoles.includes(item));
      if (!hasPermission) el.remove();
    } else {
      if (!currentPageRoles.includes(value)) el.remove();
    }
  }
};
```

### 1.2 权限数据来源

```
authButtonListGet (Pinia getter)
  ← authButtonList (state)
    ← getAuthButtonListApi() → GET /auth/buttons
      → 成功：后端返回 { [routeName]: string[] }
      → 失败：authButtonList.json 兜底

routeName (state)
  ← router.beforeEach → authStore.setRouteName(to.name)
```

### 1.3 与 useAuthButtons 的配合

`v-auth` 指令用于**模板中**直接控制 DOM，`useAuthButtons` 用于 **`<script>` 中**判断权限：

```typescript
// 模板中 — v-auth 指令
<el-button v-auth="'add'">Add</el-button>

// 脚本中 — useAuthButtons Hook
const { BUTTONS } = useAuthButtons();
if (BUTTONS.value.add) { /* 执行添加逻辑 */ }
```

## 2. 动态路由注册 (`src/routers/modules/dynamicRouter.ts`)

### 2.1 组件解析

通过 `viewsGlob` 映射（构建时由 `build/views-glob-plugin.ts` 生成）将菜单中的组件路径字符串解析为实际的 Vue 组件：

```typescript
const modules = viewsGlob as Record<string, () => Promise<any>>;

// 菜单项 component = "/system/menuMange/index"
// → modules["/src/views" + "/system/menuMange/index" + ".vue"]
// → () => import("/src/views/system/menuMange/index.vue")
```

### 2.2 路由注册策略

| 条件 | 注册方式 | 说明 |
|------|---------|------|
| `meta.isFull === true` | `router.addRoute(item)` | 全屏页面（如数据大屏），不嵌套在 layout 中 |
| 其他 | `router.addRoute("layout", item)` | 嵌套在 layout 路由下，共享侧边栏/顶栏 |
| 组件文件不存在 | `return`（跳过） | 避免注册无法解析的路由 |
| `redirect && !component` | `delete item.component` | 菜单组标题，仅重定向，无实际组件 |

### 2.3 错误处理

| 场景 | 行为 |
|------|------|
| 菜单列表为空 | `ElNotification` 提示无权限 → 清除 token → 跳转登录页 |
| API 请求失败 | 清除 token → 跳转登录页 |
| 组件文件不存在 | 跳过该路由（不注册），不阻断其他路由 |

## 3. 权限 Store (`src/stores/modules/auth.ts`)

### 3.1 数据流

```
登录成功

    → initDynamicRouter()
```

## 4. 路由守卫 (`src/routers/index.ts`)

### 4.1 beforeEach 完整流程

```
router.beforeEach(async (to, from) => {
  1. NProgress.start()
  2. 设置 document.title
  3. 访问登录页？
     ├─ token 存在 → return from.fullPath（已登录，跳回来源页）
     └─ token 不存在 → resetRouter() → 放行
  4. 路由白名单？ → 直接放行
  5. 无 token？ → return { path: LOGIN_URL, replace: true }
  6. authMenuList 为空？ → await initDynamicRouter() → return { ...to, replace: true }
  7. authStore.setRouteName(to.name) → 放行
})
```

### 4.2 白名单路由

由 `ROUTER_WHITE_LIST` 常量配置（`src/config/index.ts`），包含登录页等无需权限的静态路由。

### 4.3 错误页面路由

`errorRouter` 包含 403 页面，在 `createRouter` 时即注册为静态路由，不依赖动态路由加载。

## 实现注意事项

### 权限码设计原则

- 当前权限码按路由名分组（`{ [routeName]: string[] }`），非全局 `{module}:{action}` 格式
- 第二阶段统一为 `{module}:{action}` 格式时，需保持 `v-auth` 指令接口不变，仅修改 store 内部判断逻辑
- 新增页面时同步更新 `authMenuList.json` 和 `authButtonList.json` 兜底数据

### 降级策略

- 后端 API 不可用时，前端仍可通过本地 JSON 渲染完整菜单
- 本地 JSON 数据需与后端菜单配置保持同步，避免不一致
- 降级模式下所有按钮权限均可用（本地 JSON 包含完整权限码）

### 边界情况

| 场景 | 处理方式 |
|------|---------|
| 菜单组件文件不存在 | `initDynamicRouter` 中 `return` 跳过，不阻断其他路由 |
| 用户无任何菜单权限 | `ElNotification` 提示 + 跳转登录页 |
| API 请求失败 | 清除 token + 跳转登录页 |
| 权限数据加载失败 | 降级到本地 JSON |
| 路由名无对应按钮权限 | `currentPageRoles = []`，所有按钮隐藏 |

### 与后端协作

- 前端 `v-auth` 仅为 UI 层控制，后端必须对每个接口做权限校验
- 菜单和按钮权限由后端 API 返回，前端不做权限计算
- 权限变更：管理员修改后，用户下次路由跳转时自动重新加载
