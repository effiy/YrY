## 一、业务概述

### 1.1 业务背景

YiVad 在经过七月迭代完成 AI Chat 迁移、构建系统升级和知识库集成后，八月迭代聚焦于工程化能力提升：组件提取复用、测试基础设施搭建、主题系统建设、权限控制体系实现。

### 1.2 业务目标

- 消除跨页面重复代码，建立组件化体系
- 建立测试基础设施，保障代码质量
- 支持暗色主题，提升用户体验
- 实现细粒度权限控制，满足合规要求

### 1.3 适用对象

- 内部开发团队成员
- 未来可能接入的外部用户（RBAC 合规）

### 1.4 系统范围

- YiVad 前端 SPA
- YiAi 后端（权限数据）

## 二、目标架构

### 组件化架构

```
业务页面 (issue/project/knowledge)
  └── ProTable (通用表格)
        ├── SearchForm (内置搜索表单)
        ├── ElTable + ElPagination
        └── useTableData / useTableSelection (composables)
  └── Upload (通用上传)
        └── ElUpload + 模板下载 + 文件校验
```

### 权限架构

```
登录 → loadPermissions() → Pinia permission store
  ├── 路由守卫 → 动态路由注册 (router.addRoute)
  ├── 菜单过滤 → 侧边栏动态渲染
  └── v-auth 指令 → 按钮显隐/禁用控制
```

## 四、风险矩阵

## 五、设计决策记录

| 决策 | 选项 A | 选项 B | 选择 | 理由 |
|------|--------|--------|------|------|
| 测试框架 | Vitest | Jest | Vitest | 与 Vite 生态一致，配置简单，速度快 |
| 主题方案 | CSS 变量 | SCSS 变量 | CSS 变量 | 运行时切换，无需重新编译 |
| 权限粒度 | 路由+按钮 | 路由+按钮+数据 | 路由+按钮 | 数据级权限后期扩展 |
| 组件通信 | Props/Emits | provide/inject | Props/Emits | 单向数据流，可追踪，易调试 |
