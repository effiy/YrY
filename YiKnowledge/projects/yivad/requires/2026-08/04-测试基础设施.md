# 技术方案

## 1. Vitest 配置

### `vitest.config.ts`

```ts
import { resolve } from "node:path";
import { defineConfig } from "vitest/config";
import vue from "@vitejs/plugin-vue";
import vueJsx from "@vitejs/plugin-vue-jsx";

const rootDir = __dirname;

export default defineConfig({
  plugins: [vue(), vueJsx()],
  test: {
    environment: "jsdom",
    setupFiles: [resolve(rootDir, "tests/setup.ts")],
    globals: true,
    env: {
      RSBUILD_ENV_ROUTER_MODE: "hash",
      RSBUILD_ENV_API_URL: "http://localhost:10086",
      RSBUILD_ENV_GLOB_APP_TITLE: "YiVad",
    },
  },
  resolve: {
    alias: {
      "@": resolve(rootDir, "src"),
      "@yivad/views-glob": resolve(rootDir, "tests/mocks/viewsGlob.ts"),
    },
  },
})
```

| 配置项 | 值 | 说明 |
|--------|-----|------|
| `globals` | `true` | 无需显式 import `describe`/`it`/`expect` |
| `environment` | `jsdom` | 模拟浏览器 DOM API |
| `setupFiles` | `tests/setup.ts` | 全局 Mock、插件注册 |
| `resolve.alias` | `@/` → `src/`，`@yivad/views-glob` → mock | 与 Rsbuild 配置保持一致 |
| `plugins` | `vue()` + `vueJsx()` | SFC + TSX 编译 |
| `env` | `RSBUILD_ENV_*` 变量 | 模拟 Rsbuild 环境变量 |

### `package.json` 脚本

```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest",
    "test:coverage": "vitest run --coverage"

}
```

| 脚本 | 命令 | 用途 |
|------|------|------|
| `test` | `vitest run` | CI / 一次性运行 |
| `test:watch` | `vitest` | 开发时 watch 模式 |
| `test:coverage` | `vitest run --coverage` | 生成覆盖率报告 |

## 3. 初期测试覆盖清单

### 3.1 API 模块测试

**`tests/unit/requestHttp.test.ts`**

| 测试用例 | 测试要点 |
|----------|---------|
| `post()` 组装 RPC 请求体 | `module_name`/`method_name`/`parameters` 正确传递 |
| 响应拦截器 — code=0 成功 | 返回 `data` 字段 |
| 响应拦截器 — code≠0 失败 | 抛出错误或返回错误信息 |
| 请求拦截器 — token 注入 | 请求头携带 Authorization |
| 网络异常处理 | fetch 失败时的错误处理 |

```ts
import { describe, it, expect, vi, beforeEach } from 'vitest'
import { RequestHttp } from '@/api/requestHttp'

describe('RequestHttp', () => {
  beforeEach(() => {
    vi.restoreAllMocks()
  })

  it('should assemble RPC envelope correctly', async () => {
    global.fetch = vi.fn().mockResolvedValue({
      json: () => Promise.resolve({ code: 0, message: 'ok', data: { result: 'success' } }),
    })

    const result = await RequestHttp.post({
      moduleName: 'services.ai.chat_service',
      methodName: 'chat',
      parameters: { prompt: 'hello' },
    })

    expect(global.fetch).toHaveBeenCalledWith(
      expect.any(String),
      expect.objectContaining({
        body: expect.stringContaining('"module_name":"services.ai.chat_service"'),
      })
    )
    expect(result).toEqual({ result: 'success' })
  })
})
```

## 实现注意事项

### Pinia Store 测试

Store 测试需要 `setActivePinia(createPinia())` 初始化。API 调用相关的 store 需 mock `@/api/modules/*` 的返回值，使用 `vi.mock()` 拦截：

```ts
import { setActivePinia, createPinia } from 'pinia'

beforeEach(() => {
  setActivePinia(createPinia())
})

vi.mock('@/api/modules/issue', () => ({
  getIssueList: vi.fn().mockResolvedValue({ data: [] }),
}))
```

### Element Plus 组件测试

使用 `@vue/test-utils` 测试 ProTable 等子组件时，需在 `tests/setup.ts` 中全局注册 Element Plus 组件，或在测试中 `stub: true` 跳过子组件渲染：

```ts
// 方式一：全局注册（setup.ts）
import ElementPlus from 'element-plus'
config.global.plugins = [ElementPlus]

// 方式二：测试中 stub
mount(ProTable, {
  global: { stubs: { ElTable: true, ElPagination: true } },
})
```

### 与现有构建流程的关系

- `build:dev` / `build:test` / `build:pro` 已有 `vue-tsc` 前置，本次不调整
- `vitest` 独立于 Rsbuild 构建流程，无需修改 `rsbuild.config.ts`

### Mock 策略

| 场景 | 方式 | 说明 |
|------|------|------|
| API 调用 | `vi.mock('@/api/modules/*')` | 拦截模块级导出 |
| 路由 | `vi.mock('vue-router')` | 或使用 `createRouter` + `createWebHistory` 创建真实路由 |
| Pinia store | `setActivePinia(createPinia())` | 每个测试独立 store 实例 |
| 浏览器 API | `tests/setup.ts` 全局 mock | `matchMedia`、`ResizeObserver` 等 |
