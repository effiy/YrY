# YV-09-101-TEST: ProTable 数据竞态条件修复 — 测试方案

---

## 测试环境

| 配置项 | 值 |
|--------|-----|
| 浏览器 | Chrome 最新版 |
| 后端 | YiAi :10086 |
| 数据库 | MongoDB（含 500+ issues 测试数据） |
| 工具 | Chrome DevTools Network 节流 |

---

## 测试用例

### TC-1: 快速翻页——数据正确性

| 项 | 内容 |
|----|------|
| **前置条件** | Issue 列表页，共 10+ 页数据 |
| **步骤** | 1. 确认当前在第 1 页<br>2. 快速连续点击"下一页" 5 次（间隔 <100ms） |
| **期望** | 1. 最终显示第 6 页数据<br>2. 页码指示器显示 "6"<br>3. 无中间闪烁或数据跳变 |
| **实际** | ✅ 正确显示第 6 页数据 |

### TC-2: 弱网环境——排序一致性

| 项 | 内容 |
|----|------|
| **前置条件** | DevTools Network → 节流至 Slow 3G |
| **步骤** | 1. 点击 "Status" 列头排序<br>2. 立即点击 "Priority" 列头排序<br>3. 立即点击 "Created" 列头排序 |
| **期望** | 1. 最终显示按 "Created" 排序<br>2. 排序箭头指向 "Created" 列<br>3. 无排序状态不一致 |
| **实际** | ✅ 最终排序状态正确 |

### TC-3: 错误不传播

| 项 | 内容 |
|----|------|
| **前置条件** | Issue 列表页 |
| **步骤** | 1. 触发快速翻页（page=2, page=3）<br>2. 在 page=2 请求飞行期间，关闭 MongoDB 连接<br>3. 立即恢复 MongoDB 连接<br>4. page=3 请求正常返回 |
| **期望** | 1. 表格显示 page=3 数据<br>2. 不显示 page=2 的错误提示<br>3. 表格状态正常 |
| **实际** | ✅ page=2 错误被丢弃 |

### TC-4: 多表格隔离

| 项 | 内容 |
|----|------|
| **前置条件** | 同时打开 Bug 列表（Tab A）和 Issue 列表（Tab B） |
| **步骤** | 1. 在 Tab A 快速翻 Bug 列表<br>2. 切换到 Tab B 快速翻 Issue 列表 |
| **期望** | 1. Bug 列表的翻页不受 Issue 列表影响<br>2. Issue 列表的翻页不受 Bug 列表影响<br>3. 两个表格的 `_reqSeq` 独立计数 |
| **实际** | ✅ 互相隔离（闭包变量天然隔离） |

### TC-5: 搜索输入竞态

| 项 | 内容 |
|----|------|
| **前置条件** | 任意 ProTable + SearchForm 页面 |
| **步骤** | 1. 在搜索框中输入 "a" (慢速响应)<br>2. 立即输入 "ab"<br>3. 立即输入 "abc" |
| **期望** | 1. 表格显示搜索 "abc" 的结果<br>2. 不显示搜索 "a" 或 "ab" 的结果 |
| **实际** | ✅ 仅显示最新搜索词结果 |

### TC-6: 自动刷新 + 手动操作竞态

| 项 | 内容 |
|----|------|
| **前置条件** | FileAlertsDashboard（30s 自动轮询） |
| **步骤** | 1. 等待轮询自动触发<br>2. 在轮询响应返回前手动切换 Project 下拉 |
| **期望** | 1. 表格显示手动选择 Project 的结果<br>2. 轮询结果不覆盖手动选择 |
| **实际** | ✅ 手动选择优先于旧轮询 |
