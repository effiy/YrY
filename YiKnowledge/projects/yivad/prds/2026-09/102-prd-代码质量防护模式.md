# YV-09-102: 代码质量防护模式

> 从 17 个 bug 中提炼的 6 大防护模式 + 代码审查检查清单。

---

## 六大防护模式

### 模式 1: 竞态守卫 (Stale Response Guard)

**根因 Bug**: #17 — useTable 快速翻页数据错乱

**模式**:
```typescript
let _seq = 0;
async function fetchData(params: Params) {
  const seq = ++_seq;
  const result = await api(params);
  if (seq !== _seq) return; // 丢弃陈旧响应
  applyResult(result);
}
```

**适用**: 任何"最新请求结果才有意义"的异步操作（表格、搜索、图表数据切换）

**检查**: 代码审查时，查找 `await` 后直接 `xxx.value = result` 的赋值模式

---

### 模式 2: 模板函数名校验 (Template Function Name Check)

**根因 Bug**: #1 — `fmtTime` undefined（模板调用 `fmtTime`，脚本定义 `formatTime`）

**模式**:
```typescript
// 模板中使用函数前，检查脚本中的函数名精确匹配
// ✅ 一致
<span>{{ fmtTime(ts) }}</span>  ←→  function fmtTime(ts: number): string

// ✗ 不一致——运行时报错
<span>{{ fmtTime(ts) }}</span>  ←→  function formatTime(ts: number): string
```

**检查**: 代码审查时，搜索模板中的 `{{ fn(` / `@click="fn"` / `:prop="fn(` 并交叉引用脚本定义

---

### 模式 3: KeepAlive 副作用守卫 (KeepAlive Side-Effect Guard)

**根因 Bug**: #13 — Grid 组件 activate/deactivate 循环增加重复 resize 监听器

**模式**:
```typescript
let _guard = false;
function addEffect() {
  if (_guard) return;
  window.addEventListener("resize", handler);
  _guard = true;
}
function removeEffect() {
  if (!_guard) return;
  window.removeEventListener("resize", handler);
  _guard = false;
}
onMounted(() => addEffect());
onActivated(() => addEffect());    // 幂等——第二次调用无害
onDeactivated(() => removeEffect());
onUnmounted(() => removeEffect());
```

**检查**: 代码审查时，检查同时使用 `onMounted` + `onActivated` 的组件是否有副作用守卫

---

### 模式 4: localStorage Key 校验 (Storage Key Verification)

**根因 Bug**: #14 — SSE 通知从 `"user-store"` 读 token，但 Pinia store 使用 `"yivad-user"`

**模式**:
```typescript
// ✅ 使用 Pinia persisted state key 常量
const raw = localStorage.getItem("yivad-user");

// ✅ 或从共享模块导入
import { getYiAiToken } from "@/config/yiAi";
const token = getYiAiToken();

// ✗ 硬编码字符串可能与 store 配置不一致
const raw = localStorage.getItem("user-store");
```

**检查**: 代码审查时，搜索 `localStorage.getItem(` 并验证 key 与 `piniaPersistConfig(id)` 参数一致

---

### 模式 5: v-model 路径限制 (v-model Path Constraint)

**根因 Bug**: #4 — `v-model="configComponent.data_source?.metrics?.[0]"` 使用可选链

**模式**:
```typescript
// ✅ 使用 computed getter/setter 替代复杂路径
const kpiValue = computed({
  get: () => config.value?.data_source?.metrics?.[0],
  set: (val) => {
    if (!config.value) return;
    // ... safe path initialization ...
    config.value.data_source.metrics[0] = val;
  }
});
// 模板: v-model="kpiValue"
```

**检查**: 代码审查时，搜索 `v-model=` 中是否包含 `?.` 或复杂表达式

---

### 模式 6: PollTimer Ref 化 (Timer as Ref)

**根因 Bug**: #15 — `let pollTimer` 在模板中不可访问（非响应式变量）

**模式**:
```typescript
// ✅ ref — 在模板中可访问 + onUnmounted 可清理
const pollTimer = ref<ReturnType<typeof setInterval> | null>(null);

// ✗ 普通变量 — 模板中不可访问、需在闭包中访问
let pollTimer: ReturnType<typeof setInterval> | null = null;
```

**检查**: 代码审查时，检查 `let xxxTimer` 是否需要在模板中引用；如需要，改为 `ref`

## 代码审查检查清单

使用此清单作为 PR review 的标准检查项：

### 类型安全
- [ ] `vue-tsc --noEmit` 零错误
- [ ] 无 `@ts-ignore` 注释（每个必须附带理由说明）
- [ ] `catch` 的参数使用 `e: unknown` 而非 `e: any`
- [ ] 无 `v-model` 使用可选链或复杂表达式

### 内存管理
- [ ] 所有 `setInterval` 在 `onUnmounted`/`onBeforeUnmount` 中有对应 `clearInterval`
- [ ] 所有 `addEventListener` 有对应 `removeEventListener`
- [ ] KeepAlive 组件中 `onActivated` 的副作用有幂等守卫
- [ ] 模板中使用的 timer 变量是 `ref` 而非 `let`

### 异步安全
- [ ] `await` 后直接赋值响应式变量的代码有竞态守卫
- [ ] `confirm()` 从 `@/hooks/useConfirmAction` 导入（非 `window.confirm`）
- [ ] `import` 语句在文件顶部（非底部）

### 数据一致性
- [ ] `localStorage` key 与 Pinia `persist(id)` 参数一致
- [ ] API 响应中 `res.code !== 0` 有错误处理
- [ ] 乐观更新的操作有 rollback 逻辑

### 生产质量
- [ ] 无条件 `console.log` 被 `if (import.meta.env.DEV)` 包裹
- [ ] 无 `void` 表达式用于抑制未使用变量（应删除死代码）
- [ ] CSS 无选择器外的孤立属性块

### 认证安全
- [ ] 所有 fetch 调用使用 `yiAiAuthHeaders()` 或通过 `RequestHttp` 类
- [ ] Token 从正确 Pinia store key 读取
