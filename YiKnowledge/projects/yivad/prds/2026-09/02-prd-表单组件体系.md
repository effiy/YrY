## 一、背景与问题陈述

### 1.1 问题清单

YiVad 当前的表单系统基于 Element Plus 基础表单组件，缺少系统化的验证框架、数据持久化机制和高级交互能力：

| # | 问题 | 严重度 | 用户影响 |
|---|------|--------|----------|
| 1 | **验证分散重复** — 每个表单独立实现验证逻辑，无统一框架 | 高 | 代码重复、验证规则不一致、维护困难 |
| 2 | **无自动保存** — 意外关闭页面数据丢失 | 高 | 用户花费数十分钟填写的数据瞬间丢失 |
| 3 | **复杂表单体验差** — 无向导分步、无字段依赖、无条件逻辑 | 中 | 20+ 字段表单杂乱，用户填写意愿低 |
| 4 | **文件上传简陋** — 无进度显示、无预览、无断点续传 | 中 | 大文件上传体验差 |
| 5 | **缺少高级字段类型** — 无富文本、签名、地图选点、加密字段 | 中 | 特定场景（合同签署、位置选择、敏感信息）无法满足 |
| 6 | **无协作能力** — 无多人编辑、无字段锁定 | 低 | 团队共同填写表单时冲突频繁 |
| 7 | **无离线支持** — 网络不稳定时无法继续工作 | 中 | 移动办公场景体验差 |
| 8 | **无访问控制** — 所有用户看到的表单字段相同 | 低 | 不同角色需要不同字段的场景无法满足 |

### 1.2 现状基线

| 维度 | 现状 |
|------|------|
| 验证方式 | 各表单独立实现，无统一框架 |
| 数据持久化 | 无自动保存，页面关闭即丢失 |
| 复杂表单 | 无向导、无依赖、无条件逻辑 |
| 文件上传 | 基础上传，无断点续传、无预览 |
| 协作 | 无实时协作、无字段锁定 |
| 离线 | 无离线支持 |

<a id="sec-2"></a>
## 二、目标与非目标

### 2.1 目标

1. **数据不丢失**：自动保存 + 草稿恢复 + 崩溃恢复三重保障。
2. **验证统一**：声明式验证框架，一处定义、全局复用。
3. **渐进复杂**：简单表单快速填写；复杂表单通过向导、依赖、条件逻辑降低认知负担。
4. **安全可控**：敏感字段客户端加密；字段级访问控制。
5. **协作与离线**：实时协作光标 + IndexedDB 离线存储 + 在线同步。

### 2.2 非目标

| 非目标 | 说明 |
|--------|------|
| 替换 Element Plus 表单组件 | 本次为**增量增强**，Element Plus 表单组件保持不变 |
| 表单设计器 | 不做可视化拖拽表单设计器（属独立需求 YV-09-XX） |
| 审批工作流引擎 | 不做审批流程引擎（属 YV-09-XX） |
| 后端表单服务 | 不做独立的表单后端服务，复用 YiAi 既有 RPC 通道 |

## 三、设计原则

1. **验证统一** — 声明式验证框架，一处定义、全局复用
2. **数据不丢失** — 自动保存 + 草稿恢复 + 崩溃恢复三重保障
3. **渐进复杂** — 简单表单快速填写；复杂表单通过向导、依赖、条件逻辑降低认知负担
4. **安全可控** — 敏感字段客户端加密；字段级访问控制
5. **协作与离线** — 实时协作光标 + IndexedDB 离线存储 + 在线同步
6. **特殊场景覆盖** — 签名、地图、富文本、批量输入等专业需求

| <a id="fr-1-2"></a>FR-1.2 | 异步验证 | 支持异步验证函数（如检查用户名唯一性），返回 `Promise<boolean|string>` |

| <a id="fr-1-5"></a>FR-1.5 | 验证错误展示 | 行内错误消息、字段红色边框、表单顶部摘要（"请修正 X 个错误"）、提交失败自动滚动到首个错误 |

**内置验证规则：**

| 规则 | 说明 | 示例 |
|------|------|------|
| `required` | 必填 | `{ required: true, message: '名称不能为空' }` |
| `minLength` | 最小长度 | `{ minLength: 3, message: '至少 3 个字符' }` |
| `maxLength` | 最大长度 | `{ maxLength: 100, message: '不超过 100 个字符' }` |
| `pattern` | 正则匹配 | `{ pattern: /^[a-zA-Z0-9_]+$/, message: '仅允许字母数字下划线' }` |
| `email` | 邮箱格式 | `{ email: true, message: '邮箱格式错误' }` |
| `url` | URL 格式 | `{ url: true, message: 'URL 格式错误' }` |
| `numeric` | 数字类型 | `{ numeric: true, message: '请输入数字' }` |
| `min` | 最小值 | `{ min: 0, message: '不能小于 0' }` |
| `max` | 最大值 | `{ max: 100, message: '不能大于 100' }` |
| `integer` | 整数 | `{ integer: true, message: '请输入整数' }` |
| `dateFormat` | 日期格式 | `{ dateFormat: 'YYYY-MM-DD', message: '日期格式错误' }` |
| `custom` | 自定义函数 | `{ custom: (v) => v !== 'admin', message: '用户名已被占用' }` |

|------|------|----------|
| <a id="fr-12-1"></a>FR-12.1 | 离线架构 | Service Worker 缓存应用 shell+表单页面；IndexedDB 存储表单数据+草稿+同步队列 |
| <a id="fr-12-2"></a>FR-12.2 | 在线同步 | 网络恢复自动同步；FIFO 顺序提交；冲突检测（服务端版本 vs 本地版本） |
| <a id="fr-12-3"></a>FR-12.3 | 离线指示器 | 顶部横幅"当前离线"→"已恢复在线，正在同步..."→"同步完成"（3s 消失）→"同步失败，X 条待同步"+重试 |
| <a id="fr-12-4"></a>FR-12.4 | 提交队列 | IndexedDB 存储队列（表单数据+提交时间+重试次数）；最大重试 3 次，超过标记失败 |

### 5.13 数据持久化（FR-13）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| <a id="fr-13-1"></a>FR-13.1 | 多层持久化 | 自动保存（IndexedDB 防抖 2s）/ 草稿保存（IndexedDB 手动）/ 崩溃恢复（IndexedDB 节流 1s）/ 多标签同步（BroadcastChannel） |
| <a id="fr-13-2"></a>FR-13.2 | 草稿管理 | 草稿列表（名称/表单类型/修改时间/步骤进度）；打开/删除草稿；导出/导入草稿（JSON）；30 天过期自动清理 |

### 5.14 提交进度与重试（FR-14）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| <a id="fr-14-1"></a>FR-14.1 | 提交进度 | 多步骤进度：验证中→上传中（文件计数）→提交中→处理中→完成（勾号动画）；预计剩余时间；支持后台提交 |
| <a id="fr-14-2"></a>FR-14.2 | 重试策略 | 网络错误指数退避（1s/2s/4s）；5xx 间隔 5s；4xx 不重试显示错误；最大 3 次；全部失败后手动重试按钮 |

### 5.15 访问控制（FR-15）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| <a id="fr-15-1"></a>FR-15.1 | 表单级权限 | 查看/编辑/提交/审批/管理五种权限 |
| <a id="fr-15-2"></a>FR-15.2 | 字段级权限 | 每个字段可配置谁可查看/编辑；无查看权限不显示；无编辑权限显示只读（灰色背景） |
| <a id="fr-15-3"></a>FR-15.3 | 只读模式 | 全局只读（审批查看）；字段级只读（特定角色部分字段）；视觉区分（灰色背景、不可点击） |
| <a id="fr-15-4"></a>FR-15.4 | 权限变更审计 | 记录变更（谁/何时/从 A 到 B）；审计日志可查看 |

### 5.16 表单数据导入导出（FR-16）

| 编号 | 需求 | 验收标准 |
|------|------|----------|
| <a id="fr-16-1"></a>FR-16.1 | 数据导入 | 支持 CSV/JSON/Excel 上传、剪贴板粘贴、URL 获取；自动检测格式编码；字段映射→预览（前10行）→验证→重复处理→执行 |
| <a id="fr-16-2"></a>FR-16.2 | 数据导出 | CSV/Excel/JSON/PDF 四种格式；字段选择、日期筛选、匿名化脱敏、定时导出配置 |

## 六、非功能需求

<a id="nfr-1"></a>

### 6.1 安全性（NFR-1）

| 目标 | 要求 |
|------|------|
| XSS 防护 | 富文本输出经 DOMPurify 净化；服务端二次净化 |

| 敏感数据 | 敏感字段默认遮罩；导出默认排除加密字段 |

### 6.2 性能（NFR-2）

| 场景 | 目标 |
|------|------|
| 表单首屏渲染 | < 500ms（含 20 字段） |
| 自动保存延迟 | 用户停止输入后 2s 触发，保存完成 < 100ms |
| 离线同步 | 网络恢复后 < 5s 开始同步 |
| IndexedDB 读写 | < 50ms |
| 大文件上传 | 支持 5MB 分片，单文件最大 500MB |

## 七、依赖与约束

### 7.1 上游依赖

| 依赖 | 类型 | 说明 |

| Element Plus 表单组件 | 内部 | 本次为增量增强，基础表单组件不变 |

### 7.2 约束

- **禁止前端直连 MongoDB**，数据操作一律经 RPC 信封。
- **参数名契约**：collection 参数为 `cname`，查询条件为 `filter`，文件路径为 `target_file`。
- **TypeScript 严格模式**，`vue-tsc --noEmit` 必须通过。
- 所有用户可见文本必须国际化。

<a id="sec-8"></a>
## 八、需求风险
| 风险 | 概率 | 影响 | 等级 | 缓解措施 | 应急预案 |
|------|------|------|------|----------|----------|
| IndexedDB 容量超限 | 中 | 中 | 中 | 监控使用量；LRU 清理旧草稿；提示用户清理 | 降级为 localStorage（5MB 限制） |
| WebSocket 连接不稳定 | 中 | 中 | 中 | 自动重连（指数退避）；心跳检测 | 降级为"刷新获取最新" |
| Service Worker 缓存过旧 | 低 | 高 | 中 | 版本号控制；每次加载检查更新 | 强制刷新绕过缓存 |
| 离线数据同步冲突 | 中 | 中 | 中 | 服务端版本号；三路合并 | 用户手动选择保留哪个版本 |
| 客户端密钥丢失 | 低 | 高 | 高 | 密钥导出备份提示；密码保护的密钥恢复 | 数据永久无法解密（需明确告知用户风险） |
| 实时协作并发写入冲突 | 中 | 低 | 低 | 字段级锁定 + LWW 策略 | 版本历史恢复 |
| 富文本编辑器 XSS | 低 | 高 | 高 | 输出时 HTML 净化（DOMPurify）；服务端二次净化 | 降级为纯文本显示 |
| 签名数据被篡改 | 低 | 高 | 高 | 签名 + 时间戳哈希存证 | 签名验证失败标记 |
| Service Worker 注册失败 | 低 | 中 | 低 | 渐进增强：SW 失败不影响基本功能 | 离线功能不可用，在线功能正常 |
| 文件上传分片服务器异常 | 中 | 中 | 中 | 分片上传幂等性设计；已上传分片可复用 | 告知用户重新上传 |
