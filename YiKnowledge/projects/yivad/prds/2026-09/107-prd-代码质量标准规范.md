# YiVad 代码质量标准规范

> 版本 1.0 | 2026-09-23 | 基于 18 个真实 bug 提炼

---

## 一、编译时标准 (P0 — 阻断构建)

### 1.1 TypeScript 严格检查

```bash
vue-tsc --noEmit  # 必须 0 errors
```

违反此标准的构建**不得合入**主分支。

### 1.2 类型安全戒律

| 规则 | 错误示例 | 正确示例 |
|------|----------|----------|
| 模板函数名必须与脚本一致 | `{{ fmtTime(x) }}` 但定义 `formatTime` | 保持一致的命名 |
| v-model 禁止可选链 | `v-model="obj?.prop"` | 使用 computed getter/setter |
| catch 参数用 `unknown` | `catch (e)` 或 `catch (e: any)` | `catch (e: unknown)` |
| confirm 从 hook 导入 | 使用全局 `window.confirm()` | `import { confirm } from "@/hooks/useConfirmAction"` |
| import 在文件顶部 | import 在 600+ 行底部 | 所有 import 在顶部 |

## 二、内存安全标准 (P1)

### 2.1 事件监听器生命周期

```
规则: 每个 addEventListener 必须在 onUnmounted/onBeforeUnmount 中有对应的 removeEventListener
```

### 2.2 计时器管理

```
规则: 模板中引用的 timer 必须是 ref (非 let)
规则: 每个 setInterval/setTimeout 必须在 onUnmounted 中有对应的 clearInterval/clearTimeout
```

### 2.3 KeepAlive 守卫

```
规则: 同时使用 onMounted + onActivated 注册副作用时，必须有幂等守卫
模式: let _guard = false; if (_guard) return; 副作用; _guard = true;
```

---

## 三、异步安全标准 (P1)

### 3.1 竞态条件防护

```
规则: await 后直接赋值响应式变量的 async 函数必须实现竞态守卫
模式: const seq = ++_reqSeq; 结果 = await api(); if (seq !== _reqSeq) return;
```

### 3.2 API 响应校验

```
规则: 所有 API 响应的 res.data 访问前必须检查 res.code === 0
规则: RPC module_name + method_name 组合必须在后端有对应实现
```

---

## 四、生产质量标准 (P2)

### 4.1 控制台清洁

```
规则: 所有 console.log 必须包裹在 if (import.meta.env.DEV) 中
规则: console.error 可保留（通过统一 error reporter）
```

### 4.2 代码卫生

```
规则: 禁止 void 表达式抑制未使用变量 — 应删除死代码
规则: CSS 中禁止选择器外的孤立属性块
规则: 导入但未使用的 composable 应立即删除
```

---

## 五、数据安全标准 (P2)

### 5.1 localStorage Key

```
规则: localStorage key 必须与 Pinia persist(id) 参数一致
规则: 禁止硬编码 store key 字符串 — 通过共享模块读取
```

### 5.2 认证头

```
规则: 所有直接 fetch 调用必须使用 yiAiAuthHeaders() 或通过 RequestHttp
规则: Token 从 Pinia store 读取，禁止直接操作 localStorage
```

---

## 六、文档标准 (P3)

### 6.1 需求追踪

```
规则: 所有 P0/P1 bug 修复必须有对应的 PRD → Dev → Test 文档链
规则: bug 文档必须放在 YiKnowledge/projects/yivad/bugs/ 对应分类目录
```

### 6.2 Frontmatter 完整性

```
规则: 所有知识文档的 frontmatter 必须包含 title, tags, category, created, updated, source, type, status
规则: project 文档使用中文 type 值（需求/bug/task/test/spec）
```

## 七、标准合规矩阵

| 标准 | 检查方式 | 阻断级别 |
|------|----------|----------|
| TypeScript 严格 | `vue-tsc --noEmit` | 构建阻断 |
| ESLint | `pnpm lint:eslint` | 提交阻断 (lint-staged) |
| 内存安全 | 代码审查 | PR 阻断 |
| 异步安全 | 代码审查 + 竞态守卫模式检查 | PR 阻断 |
| 生产质量 | `grep "console.log" dist/` (CI) | 构建警告 |
| 数据安全 | 代码审查 | PR 阻断 |
| 文档完整性 | 代码审查 | PR 建议 |
