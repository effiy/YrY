# YV-09-101: ProTable 数据竞态条件修复

> 修复 `useTable` 基础设施中的并发异步响应丢序问题。影响全部 19 个 ProTable 页面的数据一致性。

---

## 背景

`useTable.getTableList()` 是 YiVad 所有表格页面的底层数据获取函数。当用户快速切换页码、搜索或排序时，多个 API 调用并发发出，但响应的到达顺序不一定等于发出顺序。后到达的旧响应会覆盖先到达的新响应——导致表格显示错误数据。

### 问题场景

```
时间线：
t1: 用户点击"下一页" → getTableList(page=2) 发出请求 A
t2: 用户再次点击"下一页" → getTableList(page=3) 发出请求 B
t3: 请求 B 响应到达（快）→ tableData = [page3 数据] ✓
t4: 请求 A 响应到达（慢）→ tableData = [page2 数据] ✗ 覆盖!
```

### 影响范围

`useTable` 是 ProTable 的底层钩子，被以下页面直接或间接依赖：

| 页面 | 表格 |
|------|------|
| Bug 列表 | ProTable + Bug 数据 |
| Issue 列表 | ProTable + Issue 数据 |
| 项目列表 | ProTable + 项目数据 |
| 模块列表 | ProTable + 模块数据 |
| 菜单管理 | ProTable + 菜单树 |
| 通知中心 | ProTable + 通知 |
| 知识库 | ProTable + 文件列表 |
| 系统日志 | ProTable + 审计日志 |
| 字典管理 | ProTable + 字典项 |
| ... 共 19 个功能模块 | |

### 为什么 Axios Cancel 机制不适用

RPC 调用设置了 `cancel: false`（因为多个并行的独立查询（如同页面的多表加载）共享相同的 RPC 端点 URL，axios cancel 会误杀这些合理并发）。

## 验收标准

### AC-1: 快速翻页数据正确性
- **Given** 一个 ProTable 页面有 >100 条数据
- **When** 用户快速连续点击"下一页" 3 次
- **Then** 最终显示的表格数据对应第 4 页（初始在第 1 页）
- **And** 无闪烁或中间状态可见

### AC-2: 弱网环境验证
- **Given** DevTools Network 节流至 Slow 3G
- **When** 快速切换排序字段 3 次
- **Then** 表格排序结果与最后一次选择的排序字段一致

### AC-3: 不增加额外请求
- **Given** 正常翻页操作
- **When** 触发 3 次 getTableList
- **Then** 发送 3 个 API 请求（不因去重减少）
- **And** 仅使用最后一次响应的数据更新状态

### AC-4: 错误不传播
- **Given** 请求 A 正在飞行中
- **When** 请求 B 发出后请求 A 失败
- **Then** 请求 A 的错误不覆盖请求 B 的成功响应
- **And** 表格显示请求 B 的数据

### AC-5: 类型安全
- **Given** 项目已通过 vue-tsc
- **When** 执行 `npx vue-tsc --noEmit`
- **Then** 0 个 TypeScript 错误

## 非功能需求

- **可维护性**：修改仅涉及 `src/hooks/useTable.ts` 一个文件，无 API 变更
- **性能**：序列号检查是 O(1) 整数比较，不增加可观测的性能开销
- **向后兼容**：所有现有调用者无需修改，`_reqSeq` 是内部实现细节
