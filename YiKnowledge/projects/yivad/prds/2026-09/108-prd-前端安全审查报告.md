# YiVad 前端安全审查报告

> 审查日期：2026-09-23 | 范围：YiVad 全部前端代码

---

## 一、XSS 防护 (Cross-Site Scripting)

### 1.1 v-html 使用 (25 文件, 36 处)

| 风险评估 | 结论 |
|----------|------|
| Markdown 渲染 | ✅ 所有实例通过 `DOMPurify` 净化 (`useMarkdown.ts`) |
| 搜索高亮 | ✅ `highlightSuggestion` 通过 `escapeHtml` 预处理 |
| 知识预览 | ✅ 服务端 frontmatter 解析，无用户注入路径 |
| Mermaid 图表 | ⚠️ `securityLevel: "loose"` — 如接受不可信 markdown 输入有风险 |

### 1.2 建议

| # | 建议 | 优先级 |
|---|------|--------|
| 1 | Mermaid securityLevel 改为 `"strict"`（如不需要 HTML 标签） | P2 |
| 2 | 添加 CSP header `script-src 'self'` 到生产 Nginx 配置 | P2 |

## 二、CSRF 防护

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 所有 API 调用通过 JSON body | ✅ | RPC 信封 + JSON content-type — 天然防 CSRF |
| Token 通过 Header 传递 | ✅ | `Authorization: Bearer <jwt>` 不使用 Cookie |
| 无 Cookie-based session | ✅ | localStorage + JWT token |

**结论**：当前认证架构（JWT + Bearer header + JSON body）天然免疫 CSRF。

---

## 三、认证安全

| 检查项 | 状态 | 说明 |
|--------|------|------|
| Token 存储 | ✅ | localStorage（Pinia persisted state） |
| 401 拦截器 | ✅ | 自动清除 stores → 重定向登录 |
| SSE Token 传递 | ✅ | `yiAiAuthHeaders()` 统一管理（#12 修复） |
| Token 过期处理 | ⚠️ | 无自动 refresh — 依赖 401 拦截重定向 |
| CORS | ✅ | YiAi `access-control-allow-origin: *`（auth disabled 时无影响） |

### 建议

| # | 建议 | 优先级 |
|---|------|--------|
| 3 | 实现 Token 自动 refresh（避免用户频繁重新登录） | P2 |
| 4 | YiAi CORS 收窄到具体域名（启用 auth 后） | P2 |

## 四、数据保护

| 检查项 | 状态 | 说明 |
|--------|------|------|
| 无硬编码密钥 | ✅ | 搜索 `password|secret|api.key|token=` 无发现 |
| localStorage 敏感数据 | ⚠️ | `yivad-user` 存储 JWT token（可被 XSS 读取） |
| 表单加密传输 | ✅ | `useTableExport.encryptContent` 使用 AES-GCM |
| IndexedDB 草稿 | ⚠️ | `useAutoSave` 存储未加密表单数据 |

### 建议

| # | 建议 | 优先级 |
|---|------|--------|
| 5 | 考虑 HttpOnly cookie 存储 token（防 XSS 读取） | P3 |
| 6 | IndexedDB 草稿加密（与导出同级别的 AES-GCM） | P3 |
