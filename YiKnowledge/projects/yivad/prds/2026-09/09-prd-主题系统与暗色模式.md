## 一、背景与问题陈述

### 1.1 问题清单

YiVad 作为管理后台，用户在不同光照环境中使用，缺少主题系统导致以下问题：

| # | 问题 | 严重度 | 用户影响 |
|---|------|--------|----------|
| 1 | **无暗色模式** — 夜间使用时白色界面刺眼 | 高 | 长时间使用疲劳，夜间工作效率低 |
| 2 | **无主题定制** — 不同团队无法适配品牌色 | 中 | 管理后台外观千篇一律 |
| 3 | **图表颜色不统一** — ECharts/Mermaid 图表与全局主题不协调 | 中 | 仪表盘和文档页面视觉割裂 |
| 4 | **主题不持久** — 刷新后主题丢失 | 中 | 每次进入需重新设置 |

### 1.2 现状基线

| 维度 | 现状 |
|------|------|
| 暗色模式 | 无，仅亮色 |
| 图表主题 | 无统一主题系统，各图表使用默认配色 |
| 主题定制 | 无，仅固定品牌色 |
| 持久化 | 无 |

<a id="sec-2"></a>
## 二、目标与非目标

### 2.1 目标

1. **暗色模式**：一键切换亮/暗，Element Plus 组件、自定义样式、图表全局跟随。
2. **图表主题**：ECharts（4 套预设）+ Mermaid（15 套），与全局主题联动。
3. **主题定制**：可视化主题配置面板（主色/圆角/暗色开关）。
4. **持久化**：主题偏好跨会话保持。

### 2.2 非目标

| 非目标 | 说明 |
|--------|------|
| 多主题市场 | 不做类似于 VS Code 的主题市场，仅支持预设 + 手动自定义 |
| 布局切换 | 不改变导航/侧栏/页脚的布局结构 |
| CSS 变量全覆盖 | 不覆盖第三方组件库的内部样式变量 |

<a id="sec-6"></a>
## 六、依赖与约束

### 6.1 上游依赖

| 依赖 | 类型 | 说明 |
|------|------|------|
| Element Plus 2.x | 外部 | CSS 变量暗色方案 |
| ECharts 6.x | 外部 | registerTheme / setOption 主题注入 |
| Mermaid | 外部 | theme 配置项，通过 mermaidThemes.ts 封装 |
| localStorage | 平台 | 主题偏好持久化 |

### 6.2 约束

- **禁止 hack Element Plus 内部样式**，必须通过官方 CSS 变量覆盖。
- **图表主题与全局主题解耦**，图表可独立设置主题。
- **TypeScript 严格模式**，`vue-tsc --noEmit` 必须通过。

<a id="sec-7"></a>
## 七、需求风险

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| Element Plus CSS 变量覆盖不完整 | 中 | 中 | 使用官方 dark 变量集；缺失覆盖以 CSS patch 补充 |
| ECharts 主题与暗色模式冲突 | 低 | 中 | 亮/暗各一套默认，用户可手动覆盖 |
| Mermaid 主题渲染异常 | 低 | 低 | 15 套主题均由算法 auto-derive，参数化生成 |
| localStorage 配额不足 | 低 | 低 | 主题配置 < 1KB，远低于 5MB 限制 |
