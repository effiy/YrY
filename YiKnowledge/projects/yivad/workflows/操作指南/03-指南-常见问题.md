# 常见问题排查

> 开发中高频遇到的问题及解决方案。按类型分为：环境、构建、运行时、RPC、权限、类型。

## 一、环境问题

### pnpm install 失败

```bash
# 症状：ERR_PNPM_NO_MATCHING_VERSION 或 lockfile 冲突
rm -rf node_modules pnpm-lock.yaml
pnpm install

# 如果仍失败，检查 Node 版本
node --version  # 需 ≥ 18
```

### 端口 8848 已被占用

```bash
lsof -i :8848 | grep LISTEN
kill -9 <PID>
# 或指定其他端口：
RSBUILD_PORT=8849 pnpm dev
```

### 热更新不生效

| 场景 | 解决 |
|------|------|
| 修改 `.vue` / `.ts` 无效 | Rsbuild HMR 自动生效，检查浏览器控制台是否有编译错误 |
| 修改路由配置无效 | 路由变更需手动刷新页面（HMR 不会重新注册路由） |
| 修改环境变量无效 | 重启 `pnpm dev` |
| 修改 `rsbuild.config.ts` 无效 | 重启 `pnpm dev` |

### `Error: Cannot find module '@yivad/views-glob'`

这是 Rsbuild 虚拟模块，仅在构建时存在。IDE 报错可忽略，或用 `// @ts-ignore` 抑制类型检查。

## 二、构建问题

### `vue-tsc --noEmit` 报错

```bash
# 获取完整错误列表
pnpm typecheck 2>&1 | head -50

# 常见原因及修复：
# - "Property 'x' does not exist" → 检查 Props/Emits 类型定义
# - "Cannot find module"       → 检查导入路径
# - "Type 'x' is not assignable" → 检查泛型参数
```

### 构建产物过大

```bash
# 分析构建产物
pnpm build:pro
ls -lh dist/

# 常见优化：
# - 检查是否有大型库被全量引入（如 moment.js）
# - 路由懒加载检查：确认非首屏路由使用 () => import()
# - ECharts 按需引入而非全量
```

### `module_name` 报 404 或 500

检查 RPC 信封格式：

```json
// 正确的请求体
{
  "module_name": "services.database.data_service",
  "method_name": "query_documents",
  "parameters": {
    "cname": "projects",
    "filter": { "status": "active" }
  }
}

// ❌ 错误：module_name 拼写错误
// "services.database.data_services"   → 多了个 s
// "services.database.dataService"     → 用了驼峰
```

## 三、运行时问题

### 页面白屏/空白

排查顺序：

1. **浏览器控制台** → 是否有 JS 错误？
2. **Network 面板** → `/auth/menu/list` 是否 200？
3. **Vue DevTools** → 路由是否注册？Pinia Store 是否有数据？
4. **清除 localStorage** → 刷新重新登录

### 表格数据不更新

| 原因 | 检查方法 | 修复 |
|------|----------|------|
| 参数名用了 `query` | Network → Request Payload | 改为 `filter` |
| `cname` 与集合名不一致 | 对照 MongoDB 集合名 | 修正 `cname` |
| 没调 `refresh()` | 组件中搜索/操作后是否触发 | 添加 `refresh()` 调用 |
| 响应被拦截器吞掉 | Console → 是否有 `ElMessage.error` | 检查后端返回的 `code` |

### 弹窗关闭后再打开有上次的校验提示

```typescript
// 在弹窗关闭时重置表单
watch(visible, (val) => {
  if (!val) formRef.value?.resetFields();
});
// 或
<el-dialog v-model="visible" @closed="formRef?.resetFields()">
```

### 搜索后翻页重置了但数据不对

`useTable` 内置了搜索时页码重置逻辑。如果自定义了搜索表单，确保：

```typescript
function handleSearch() {
  search.value = { ...searchParams };  // useTable 自动重置 pageNum
  // 不要手动设置 pagination.current = 1
}
```

### `[object Object]` 出现在表格中

原因：`_id` 是 MongoDB ObjectId 对象而非字符串。

修复：在 Store 或 API 层序列化：

```typescript
list.value = data.list.map(item => ({
  ...item,
  _id: typeof item._id === "object" ? item._id.$oid || String(item._id) : item._id,
}));
```

## 四、RPC 调用问题

### 后端返回空列表，明明应该有数据

检查 Network 面板中的 Request Payload，确认：
- `filter` 而非 `query`（最常见的 bug）
- `cname` 拼写与后端 MongoDB 集合名一致
- `pageNum` 从 1 开始（非 0）

### `POST / 422 (Unprocessable Entity)`

通常原因：
- `module_name` 或 `method_name` 拼写错误
- 缺少必填参数
- 参数类型不匹配（如 `pageNum` 传了字符串）

### SSE 流式聊天无响应

```bash
# 1. 检查 YiAi 后端是否运行
curl http://localhost:10086/health

# 2. 检查 Ollama 是否运行
curl http://localhost:11434/api/tags

# 3. 浏览器 Network → 找到 POST / 请求 → EventStream 标签
#    确认有 data: 帧返回
```

## 五、权限问题

### 菜单为空

1. 确认 `/auth/menu/list` 返回数据
2. 检查 `authMenuList.json` 兜底文件是否有效
3. 清除 localStorage → 刷新重新登录
4. 检查 YiAi 中 MongoDB `menus` 集合是否有数据

### `v-auth` 不生效

```typescript
// 检查 authButtonList 中是否有对应权限码
const authStore = useAuthStore();
console.log(authStore.authButtonListGet);
// v-auth="'project:create'" 需要 authButtonList 中存在 'project:create'

// 常见原因：权限码不匹配（大小写、分隔符）
// 后端: "project.create"  前端: "project:create"  → 不匹配
```

### 401 后页面不跳转登录页

检查 `RequestHttp` 响应拦截器是否被覆盖，确认：

```typescript
// src/api/index.ts
if (error.response?.status === 401) {
  useUserStore().setToken("");
  // 确保导入了 router 实例
  router.replace(LOGIN_URL);
}
```

## 六、类型问题

### `Property 'x' does not exist on type '{}'`

```typescript
// ❌ 错误：未声明类型
const data = ref({});
data.value.name;  // Error

// ✅ 正确：声明类型
interface Item { name: string }
const data = ref<Item>({ name: "" });
```

### `Type 'string | undefined' is not assignable to type 'string'`

```typescript
// ❌ 错误：没处理 undefined
const title = props.item.meta.title;  // meta 可能为 undefined

// ✅ 正确：可选链 + 默认值
const title = props.item?.meta?.title ?? "";
```

## 七、国际化问题

### 切换语言后部分文本不变

- 检查是否硬编码中文（用 `rg '"([^"]*[\u4e00-\u9fa5][^"]*)"' src/` 搜索）
- 检查是否在顶层作用域调用了 `t()`
- 使用 `computed(() => t("key"))` 而非 `const label = t("key")`

### 翻译缺失控制台报 `[intlify] Not found`

- 开发环境 `missingWarn: true` 会在控制台打印缺失的键
- 确认 `zh.ts` 和 `en.ts` 有相同的键结构
- 检查模块是否已在 `languages/modules/index.ts` 中注册

## 八、Git 问题

### Husky hooks 不执行

```bash
# 重新初始化 husky
npx husky init
# 或在 .husky/ 目录确认 pre-commit 文件存在
ls -la .husky/
```

### commitlint 报错

确保提交信息格式：`<type>(<scope>): <description>`

```
✅ feat(project): add delete button
❌ add delete button           # 缺少 type
❌ feat:add delete button       # 缺少空格
❌ FEAT(project): add button    # type 必须小写
```
