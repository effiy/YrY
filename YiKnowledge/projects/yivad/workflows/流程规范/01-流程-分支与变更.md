# 分支与变更

> 分支管理规范和变更落地工作流。

## 分支策略

| 分支 | 用途 |
|------|------|
| `main` | 生产就绪代码，仅通过 PR/MR 合并 |
| `claude/*` | 功能/修复分支（默认前缀） |

**规则：**
- 从 `main` 拉出特性分支
- 分支命名：`claude/<简短描述>`，使用 kebab-case
- 一个分支聚焦一个功能或修复
- 合并前确保 `vue-tsc --noEmit` 通过

## 变更落地工作流

```
1. 明确需求 → 确认范围和验收标准
2. 拉分支   → git checkout -b claude/<feature> main
3. 编码     → 遵循代码约定，更新 CLAUDE.md 如需
4. 自检     → pnpm typecheck && pnpm lint && pnpm test
5. 提交     → pnpm commit（Conventional Commits）
6. PR/合并  → 描述变更内容和测试说明
```

## 冲突处理

- 优先从 `main` merge 而非 rebase（保留提交历史）
- 解决冲突后重新验证 `pnpm typecheck`
- 冲突涉及关键模块（路由、Store）时通知相关开发者
