# 异步数据获取与竞态条件防护规范

> 适用场景：ProTable 数据获取、搜索建议、图表数据切换、任何异步状态更新。

---

## 一、核心问题

异步响应到达顺序不等于请求发出顺序。后发出的请求可能先返回，先发出的请求可能后返回——如果不加保护，陈旧响应会**覆盖**最新数据。

```
请求 A(page=2) ──────────────────────→ 响应 A(慢)
请求 B(page=3) ────────→ 响应 B(快)
                                    ↓
                         错误：A 覆盖 B，显示第 2 页
```

## 二、标准解法：序列号守卫

```typescript
let _seq = 0;

async function fetchData(params: Params) {
  const seq = ++_seq;           // 1. 请求前递增序列号
  const result = await api(params);  // 2. 异步等待
  if (seq !== _seq) return;     // 3. 检查是否仍是最新请求
  applyResult(result);          // 4. 安全更新状态
}
```

**关键特性**：
- `_seq` 是模块级闭包变量（非 ref），每个 composable 实例独立
- 序列号检查是 O(1) 整数比较，零性能开销
- 同时保护成功和错误分支

## 三、常见反模式

| 反模式 | 问题 | 修复 |
|--------|------|------|
| 直接 `data.value = await api()` | 无竞态保护 | 添加序列号守卫 |
| `debounce(api, 300)` | 增加 300ms 延迟 | 序列号方案零延迟 |
| `AbortController` 全局取消 | 影响其他并行请求 | 仅用于可独立取消的请求 |

## 四、检查清单

- [ ] 所有 `await` 后直接修改响应式状态的 async 函数有序列号守卫
- [ ] 序列号在 `try` 和 `catch` 分支中均检查
- [ ] `_seq` 是普通变量（非 ref），避免响应式追踪开销
- [ ] 不同 composable 实例的 `_seq` 自然隔离（闭包特性）
