# 代码约定

> 组件风格、命名、TypeScript、导入顺序、Store 模式、反模式 —— 所有代码必须遵守的基线规则。

## 一、组件风格

仅使用 `<script setup lang="ts">`，禁止 Options API。

```vue
<script setup lang="ts">
// 正确：Composition API + <script setup>
import { ref, computed } from "vue";

interface Props {
  projectId: string;
  editable?: boolean;
}

const props = withDefaults(defineProps<Props>(), {
  editable: false,
});

const emit = defineEmits<{
  (e: "update", payload: { id: string; data: Record<string, unknown> }): void;
}>();

const data = ref<Item[]>([]);
const loading = ref(false);
</script>

<template>
  <div class="page-container">
    <!-- 模板 -->
  </div>
</template>

<style lang="scss" scoped>
@import "@/styles/var.scss";
</style>
```

**规则：**
- Props 使用泛型声明：`defineProps<{...}>()`
- Emits 使用泛型声明：`defineEmits<{...}>()`
- 样式使用 `<style lang="scss" scoped>`，变量来自 `src/styles/var.scss`
- 复杂逻辑抽取为 composables（`src/hooks/`）

## 二、命名约定

| 格式 | 适用范围 | 示例 |
|------|----------|------|
| PascalCase | 组件、类型、接口 | `ProjectList`, `TableColumn`, `UserInfo` |
| camelCase | composables、变量、函数、Store 模块、API 模块 | `useAuthButtons`, `queryDocuments`, `pageNum` |
| kebab-case | CSS 类名、文件路由、目录 | `page-container`, `/project/list` |
| UPPER_SNAKE_CASE | 常量、枚举值 | `APP_TITLE`, `LOGIN_URL`, `PERMISSIONS.PROJECT_VIEW` |
| snake_case | 后端 YiAi（Python） | `chat_service`, `query_documents` |

**文件命名：**

| 文件类型 | 命名规则 | 示例 |
|----------|----------|------|
| 页面组件 | kebab-case 目录 + `index.vue` | `project/list/index.vue` |
| 公共组件 | PascalCase | `ProTable.vue`, `PermissionMatrix.vue` |
| Store 模块 | camelCase | `auth.ts`, `project.ts` |
| API 模块 | camelCase + `Service` 后缀 | `projectService.ts` |
| Composable | `use` + PascalCase | `useTable.ts`, `useAuthButtons.ts` |
| 类型定义 | PascalCase 目录 | `api/interface/Project.ts` |

## 三、TypeScript 规则

**类型声明：**
- 对象形状优先使用 `interface`，联合/交叉类型使用 `type`
- 禁止 `any`，用 `unknown` + 类型收窄替代
- 禁止 `as` 类型断言，用类型收窄替代
- 禁止 `@ts-ignore`、非空断言 `!`
- 仅类型导入使用 `import type { ... }`

```typescript
// 正确：interface 定义对象形状
interface ProjectItem {
  id: string;
  name: string;
  status: ProjectStatus;
  createdAt: string;
}

// 正确：type 定义联合类型
type ProjectStatus = "active" | "archived" | "draft";

// 正确：类型收窄替代 as
function getStatus(item: unknown): ProjectStatus {
  if (typeof item === "object" && item !== null && "status" in item) {
    const { status } = item as { status: unknown };
    if (typeof status === "string" && ["active", "archived", "draft"].includes(status)) {
      return status as ProjectStatus;
    }
  }
  throw new Error("Invalid project item");
}

// 错误：使用 any
function getStatus(item: any): string {
  return item.status; // 无类型安全
}
```

**安全访问：**
```typescript
// 正确：使用可选链和空值合并
const title = item?.meta?.title ?? "未命名";
const list = response?.data?.list ?? [];

// 错误：深层访问无保护
const title = item.meta.title; // item 或 meta 可能为 null
```

## 四、导入顺序

```
1. Vue 核心          (vue, vue-router, vue-i18n, pinia)
2. 第三方 UI/工具     (element-plus, echarts, axios)
3. Stores            (@/stores/modules/*)
4. API 模块           (@/api/modules/*)
5. Hooks / Utils     (@/hooks/*, @/utils/*)
6. 组件               (@/components/*)
7. 类型导入           (import type { ... })
8. 样式               (@/styles/*)
```

```typescript
// 示例
import { ref, computed, onMounted } from "vue";
```

## 五、Store 模式

使用 Setup Store 语法（`defineStore` + composition API）：

```typescript
// stores/modules/project.ts
import { defineStore } from "pinia";
import { ref, computed } from "vue";
import { queryDocuments, createDocument } from "@/api/modules/dataService";

export const useProjectStore = defineStore("yivad-project", () => {
  // 状态
  const list = ref<ProjectItem[]>([]);
  const loading = ref(false);
  const currentPage = ref(1);

  // 派生
  const activeCount = computed(() => list.value.filter(p => p.status === "active").length);

  // 动作
  async function fetchList(params: QueryParams) {
    loading.value = true;
    try {
      const { data } = await queryDocuments(params);
      list.value = data.list;
    } finally {
      loading.value = false;
    }
  }

  return { list, loading, currentPage, activeCount, fetchList };
});
```

**Store 约束：**
- Store 禁止直接导入 `axios`/`fetch`，必须通过 `@/api/modules/*`
- 状态变更仅通过 store 动作，不在组件中直接修改 `store.list = [...]`
- 持久化使用 `pinia-plugin-persistedstate`

## 六、Composable 模式

```typescript
// hooks/useTable.ts
import { ref, reactive } from "vue";
import type { PageParams, TableItem } from "@/api/interface";

interface UseTableOptions {
  requestApi: (params: PageParams) => Promise<{ data: { list: TableItem[]; total: number } }>;
  defaultParams?: Partial<PageParams>;
}

export function useTable(options: UseTableOptions) {
  const tableData = ref<TableItem[]>([]);
  const loading = ref(false);
  const pagination = reactive({ current: 1, pageSize: 20, total: 0 });
  const search = ref<Record<string, unknown>>({});

  async function refresh() {
    loading.value = true;
    try {
      const { data } = await options.requestApi({
        pageNum: pagination.current,
        pageSize: pagination.pageSize,
        filter: search.value,
        ...options.defaultParams,
      });
      tableData.value = data.list;
      pagination.total = data.total;
    } finally {
      loading.value = false;
    }
  }

  return { tableData, loading, pagination, search, refresh };
}
```

**Composable 约束：**
- 文件名以 `use` 开头
- 单一职责，一个 hook 做一件事
- 返回值使用解构（保持响应性）
- 不直接操作 DOM

## 七、错误处理

```typescript
// API 层：错误由 RequestHttp 拦截器统一处理
// 组件层：仅处理 UI 相关的错误恢复
async function handleDelete(id: string) {
  try {
    await deleteDocument({ cname: "projects", key: { id } });
    ElMessage.success("删除成功");
    await refresh();
  } catch {
    // 错误提示已由拦截器处理，此处仅恢复 UI 状态
    loading.value = false;
  }
}
```

**规则：**
- RequestHttp 拦截器统一处理 401（清凭据 + 跳登录页）和网络错误
- 业务错误（`code !== 0`）由拦截器统一 `ElMessage.error`
- 组件中 try/catch 仅用于恢复本地 UI 状态，不再重复弹提示

## 八、硬约束

| 约束 | 说明 |
|------|------|
| 页面表格必须用 `ProTable` | 禁止直接使用 `el-table` |
| Store 禁止直接导入 `axios`/`fetch` | 必须通过 `@/api/modules/*` |
| 权限判断必须用 `v-auth` 指令 | 禁止 `v-if` 内联权限判断 |
| 模板文本必须用 `$t()` 国际化 | 禁止硬编码中文 |
| API 调用必须通过 `RequestHttp` | 禁止直接 `axios` 或 `fetch` |
| RPC 参数名用 `filter` | 非 `query`（后端静默忽略） |

## 九、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| Options API | `export default { data() {...}, methods: {...} }` | `<script setup lang="ts">` | 项目统一 Composition API |
| 组件内直接调 axios | `import axios from "axios"; axios.post(...)` | `import { queryDocuments } from "@/api/modules/dataService"` | 绕过拦截器和 RPC 信封 |
| 内联权限判断 | `v-if="authStore.buttons.includes('add')"` | `v-auth="'add'"` | 权限逻辑分散，不可维护 |
| 硬编码文本 | `<span>项目管理</span>` | `<span>{{ $t("nav.project") }}</span>` | 国际化不可切换 |
| 使用 `any` | `function handle(data: any)` | `function handle(data: unknown)` + 类型收窄 | 丢失类型安全 |
| `as` 类型断言 | `(data as ProjectItem).name` | 类型收窄或 zod 校验 | 绕过编译期检查 |
| Store 中直接操作 DOM | `document.querySelector(...)` | 通过 ref 或 composable 返回数据 | 破坏响应式 + 不可测试 |
| Props 解构丢失响应性 | `const { title } = props` | `const title = computed(() => props.title)` 或 `toRefs(props)` | 丢失响应式追踪 |
