# 活动时间轴组件开发模式

> `ActivityTimeline.vue` + `useActivityTimeline.ts` 的完整架构模式 — 适用于需要从多数据源聚合、筛选、分组并以时间轴形式展示的场景。

## 一、架构概览

```
DetailOverview.vue (父组件, 974 行)
  │
  ├── useProjectDetail()          ← 数据注入层（allIssues/allBugs/allModules/knowledgeFiles）
  │
  └── <ActivityTimeline           ← 组件（154 行）
        :all-issues :all-bugs :all-modules :knowledge-files
        :project-key :filter-date-str :now
        :loading :last-updated :updated-ago
        @refresh @item-click
      />
        │
        └── useActivityTimeline()  ← Composable（374 行）
              ├── overviewActivity    — 4 数据源 → ActivityItem[]
              ├── filteredActivity    — 类型筛选
              ├── activityGroups      — 日期分组
              ├── activityFilters     — 筛选标签计数
              ├── activitySummary     — 今日摘要
              └── 辅助函数             — icon/fresh/tooltip/togglePreview
```

**核心原则**：Composable 负责数据逻辑，Component 负责渲染。父组件只传原始数据，不传派生状态。

## 二、Composable 接口

```ts
// useActivityTimeline.ts
export interface ActivityTimelineInput {
  allIssues: Ref<Issue[]>;           // 需求列表
  allBugs: Ref<BugDocument[]>;       // 缺陷列表
  allModules: Ref<Module[]>;         // 模块列表
  knowledgeFiles: Ref<KnowledgeFileEntry[]>;  // 知识文件
  projectKey: ComputedRef<string>;   // 当前项目 key
  filterDateStr: ComputedRef<string>; // 日期筛选（空=全部）
  now: ComputedRef<number>;          // 当前时间戳（响应式，用于相对时间计算）
}

export function useActivityTimeline(input: ActivityTimelineInput) {
  // 返回 activityTypeFilter、overviewActivity、filteredActivity、
  // activityFilters、activitySummary、activityEmptyText、activityGroups、
  // expandedPreviews、togglePreview、isActivityFresh、
  // activityTypeIcon、activityTooltip、activityColor
}

export type UseActivityTimelineReturn = ReturnType<typeof useActivityTimeline>;
```

## 三、数据流

```
YiAi RPC (轮询 30s)
  → useProjectDetail (ref 更新)
    → props 传递到 ActivityTimeline
      → computed(() => props.xxx) 包裹为 ComputedRef
        → useActivityTimeline(input)
          → overviewActivity (computed)
            ├── 需求: allIssues.filter(issue_type="requirement").slice(0,20)
            ├── 缺陷: allBugs.slice(0,10)
            ├── 模块: allModules.slice(0,10)
            └── 文档: knowledgeFiles.filter(project prefix).slice(0,15)
          → sort by updatedAt desc → slice(0,30)
          → filteredActivity (按 activityTypeFilter)
          → activityGroups (按日期分组: Today/Yesterday/YYYY-MM-DD · DoW)
          → DOM 渲染
```

**切片策略**：各数据源独立 `.slice()` 限制，避免单一数据源过载。最终合并后 `.slice(0,30)` 上限。

## 四、组件接口

```html
<ActivityTimeline
  :all-issues="allIssues"           <!-- Issue[] -->
  :all-bugs="allBugs"               <!-- BugDocument[] -->
  :all-modules="allModules"         <!-- Module[] -->
  :knowledge-files="knowledgeFiles" <!-- KnowledgeFileEntry[] -->
  :project-key="project?.key || ''" <!-- string -->
  :filter-date-str="filterDateStr"  <!-- string ("" = all) -->
  :now="now"                        <!-- number (epoch ms, reactive) -->
  :loading="loading"                <!-- boolean -->
  :last-updated="lastUpdated"       <!-- number (epoch ms) -->
  :updated-ago="updatedAgo"         <!-- string ("5m ago") -->
  @refresh                          <!-- 点击刷新按钮 -->
  @item-click="handleActivityClick" <!-- 点击时间轴条目 -->
/>
```

**设计决策**：传原始数据而非派生状态。组件内部调用 `useActivityTimeline` 管理自身状态，实现完全自治。

## 五、扩展新活动类型

### 添加新数据源

1. 在 `ActivityTimelineInput` 中添加新的 `Ref<NewType[]>`
2. 在 `overviewActivity` computed 中添加 `.forEach()` 构建 `ActivityItem[]`
3. 在 `activityColor()` 中添加颜色映射
4. 在 `activityTypeIcon()` 中添加图标映射
5. 在 `activityFilters` 中添加筛选标签
6. 父组件传递新 prop

### 添加新活动动作

只需在对应数据源的 `actionKey` 映射中添加 `status → i18n key` 条目：

```ts
const actionKey: Record<string, string> = {
  new_status: "activity.newAction",  // → t("project.overview.activity.newAction")
};
```

### 添加新筛选维度

在 `activityTypeFilter` 的联合类型和 `activityFilters` 数组中添加新维度。

## 六、动画体系

| 动画 | 触发条件 | 关键帧 | 时长 |
|------|---------|--------|------|
| `timeline-enter` | 筛选切换（`:key` 变化） | opacity 0→1 + translateY 6→0 | 0.25s |
| `item-enter` | 条目挂载 | opacity 0→1 + translateX -8→0 | 0.3s |
| `fresh-pulse` | 条目 < 5min 内更新 | box-shadow 0→6px→0 (currentColor) | 2s infinite |

**错峰延迟**：`animationDelay: i * 0.04s`，形成自顶向下的瀑布流入场效果。

## 八、已知约束

| 约束 | 原因 | 影响 |
|------|------|------|
| 需求上限 20 条 | `reqIssues.slice(0, 20)` | 大量需求时可能遗漏 |
| 文档上限 15 条 | `knowledgeFiles.slice(0, 15)` | 同上 |
| 总上限 30 条 | `activity.slice(0, 30)` | 超 30 条活动时截断 |
| 无虚拟滚动 | 时间轴非列表，分组结构复杂 | 30 条以内性能无忧 |
| `now` 需响应式 | 依赖 `useNow(30_000)` 更新相对时间 | 父组件必须传 ComputedRef |
| 日期比较用 UTC | `toISOString().slice(0,10)` 直接比较 | 跨时区一致，但不支持本地日期语义 |
