# 项目架构

> 目录结构、路由系统、状态管理 —— 架构层面的设计决策和约束。

## 分层架构

```
Views（页面）→ Components（组件）→ Hooks（逻辑）
                                    → Stores（状态）
RequestHttp（HTTP 封装）→ YiAi :10086（RPC 信封）→ MongoDB
```

## 目录结构

```
src/
├── api/           RequestHttp + 接口类型 + 领域服务模块
├── components/    55 个可复用组件（ProTable 是核心）
├── views/         28 个功能域页面
├── stores/        25 个 Pinia 模块
├── hooks/         63 个 composables
├── routers/       动态路由 + 权限守卫
├── languages/     i18n（zh-CN, en-US）
├── styles/        全局 SCSS + 主题变量
├── directives/    10 个自定义指令
└── utils/         工具函数
```

## 路由系统

- Hash 模式（`createWebHashHistory`）
- 后端菜单 API → 权限树 → `router.addRoute` 动态注册
- 菜单 API 不可用时回退 `authMenuList.json`
- 401 拦截器 → 清除 stores → 重定向登录页
- 路由组件使用懒加载

## 状态管理

Pinia setup-function 语法，按域拆分：

```
全局状态         — 用户、权限、主题、语言、侧边栏
业务状态         — AI 对话、知识库、项目管理
页面状态         — 标签页、KeepAlive 缓存
```

**原则：**
- 一个 Store 一个业务域，不做万能 Store
- Store 暴露方法而非直接暴露 mutable state
- 异步操作统一管理 loading/error 状态
- 持久化用 `pinia-plugin-persistedstate`
