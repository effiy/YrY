# rsbuild.config.ts 中 source.alias 可能有未使用的别名

## 现象

`rsbuild.config.ts` 配置了路径别名（`@/` → `src/`），但未验证所有配置的别名是否在代码中实际使用：

```typescript
source: {
  alias: {
    "@": "./src",
    "@yivad/views-glob": "./build/views-glob-plugin.ts", // 构建时虚拟模块
  }
}
```

`views-glob-plugin.ts` 中的虚拟模块映射有对应的 import（`dynamicRouter.ts:10`），但如果插件输出格式变化，类型检查可能不会捕获。

此外 `vitest.config.ts` 中单独配置了 mock（`tests/mocks/viewsGlob.ts`），与真实构建产物可能不同步。

## 根因分析

- 别名配置在三处独立维护：rsbuild.config、tsconfig.json、vitest.config
- 没有自动化检查确保别名一致性

## 涉及文件

- `rsbuild.config.ts` — 构建别名
- `tsconfig.json` — 类型检查别名
- `vitest.config.ts` — 测试别名
- `build/views-glob-plugin.ts` — 自定义插件
- `tests/mocks/viewsGlob.ts` — 测试 mock

## 修复方案

添加构建时验证步骤检查别名与实际文件路径的一致性。

## 预防措施

- 别名在所有配置文件中保持一致，使用共享的基础配置

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- **别名配置的三份维护是漂移的根源**：rsbuild、tsconfig paths、vitest resolve.alias 各自维护相同的别名映射。添加一个新别名需要在三处同步。应使用单一来源（tsconfig paths）+ 自动派生（rsbuild/vitest 从中读取）消除漂移
- **自定义虚拟模块的测试 mock 同步**：`@yivad/views-glob` 在构建时指向真实插件、测试时指向 mock。两者的输出格式需要 snapshot 测试来保证一致性
