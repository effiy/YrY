# CSS 中使用 `split-map-join` 模式而非 Sass 颜色函数

## 现象

`KanbanCard.vue:163` 使用 JavaScript 的 `split-map-join` 模式处理颜色字符串，而非使用 SCSS 或 CSS 颜色函数：

```typescript
const severityBg = computed(() => {
  const clean = severityColor.value.replace('#', '');
  return hexToRgba(severityColor.value, 0.12);
});
```

`hexToRgba` 在 `utils/color.ts` 中手工实现：
```typescript
function hexToRgb(str: any) {
  let hexs: any;
  // 手动解析 hex → rgb
}
```

这与现代 CSS 的 `color-mix()` 或 `rgb(from ...)` 相比低效。浏览器已原生支持 rgba 处理，无需在 JavaScript 中转换颜色。

## 根因分析

- ECharts 配置需要 rgba 颜色字符串
- 开发者选择在 JS 中手工转换 hex → rgba
- CSS 自定义属性配合 `color-mix(in srgb, ...)` 可以消除 JS 转换

## 涉及文件

- `utils/color.ts` — 手工颜色转换
- `views/kanban/KanbanCard.vue` — 背景色计算

## 修复方案

使用 CSS 自定义属性 + `opacity` 或 `color-mix()` 替代 JS 颜色计算：
```css
background: color-mix(in srgb, var(--severity-color) 12%, transparent);
```

## 预防措施

- 颜色处理优先使用 CSS 原生方案，避免 JS 中的颜色解析
