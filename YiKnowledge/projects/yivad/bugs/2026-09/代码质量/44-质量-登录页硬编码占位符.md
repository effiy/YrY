# 登录页面 placeholder 和按钮文本未国际化

## 现象

`views/login/index.vue` 中的表单占位符和 `SearchMenu.vue` 的搜索框占位符使用硬编码英文：

```vue
<!-- login/index.vue — 硬编码英文 -->
<el-input placeholder="Username" />
<el-input placeholder="Password" />

<!-- Header/SearchMenu.vue — 硬编码英文 -->
<el-input placeholder="Search menus: supports menu name and path" />
```

而在其他已国际化的组件中，placeholder 使用 `:placeholder="$t('key')"` 绑定：

```vue
<!-- 已国际化示例 -->
<el-input :placeholder="$t('aiChat.inputPlaceholder')" />
```

## 根因分析

- 登录页面在 i18n 完整建立前开发
- 登录是挂载前的独立页面（不需要路由守卫），容易遗漏
- 与 bug #24、#25、#33、#35 同属 i18n 覆盖不全的系列问题

## 涉及文件

- `views/login/index.vue:6,9` — Username/Password placeholder
- `layouts/components/Header/components/SearchMenu.vue:8` — 搜索框 placeholder
- `views/search/index.vue:21` — 全局搜索 placeholder

## 修复方案

在语言包中添加登录相关的 i18n 键：
```json
{
  "login.username": "Username / 用户名",
  "login.password": "Password / 密码",
  "search.menuPlaceholder": "Search menus / 搜索菜单"
}
```

## 预防措施

- 全局搜索所有 `placeholder=`（非 `:placeholder=`）确保国际化

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- **登录页是 i18n 盲区**：登录页在路由守卫之外（未登录状态），i18n 初始化在登录之后。如果登录页本身需要国际化，i18n 必须作为独立模块在应用挂载前初始化，而非依赖路由守卫
- **`placeholder=` vs `:placeholder=` 的区别**：静态属性 `placeholder="Username"` 传递字面字符串，`:placeholder="$t('key')"` 才传递表达式结果。这是 Vue 模板中最常见的 i18n 遗漏模式
