# 构建产物中包含了 3 个 hot-update 文件

## 现象

YiPet 的 `dist/assets/` 目录中包含 3 个 Rsbuild HMR (Hot Module Replacement) 的 `.hot-update.js` 文件：

```
index.f3bcd92eca1f5f27.hot-update.js  (30KB)
index.f49ab3937c706bc1.hot-update.js  (11KB)
index.fbf848554e5278d0.hot-update.js  (4KB)
```

这些文件是 Rsbuild 开发服务器在 HMR 更新时生成的，不应出现在 `npm run build`（生产构建）的输出中。它们的存在表明构建配置或缓存未正确清理。

## 根因分析

- 开发构建（`npm run dev`）与生产构建（`npm run build`）共享 `dist/` 目录
- 执行 `npm run build` 前未清理旧的开发产物
- Rsbuild 的 `output.cleanDistPath` 可能未启用

## 涉及文件

- `dist/assets/*.hot-update.js` — 不应存在的文件
- `rsbuild.config.ts` — 缺少 `cleanDistPath` 配置

## 修复方案

1. 启用 `output.cleanDistPath: true` 在构建前自动清理
2. 或 `npm run build` 前执行 `rm -rf dist/`
3. 将 build 脚本改为 `"build": "rm -rf dist && rsbuild build"`

## 预防措施

- 构建脚本必须在构建前清理输出目录

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- 此类问题属于常见开发疏忽，可通过静态分析和自动化检查提前发现
- 建议将典型问题模式记录到团队知识库，避免重复踩坑
- 代码审查应重点关注此类边界情况
