# AutoImport 生成的类型文件包含大量未使用的类型声明

## 现象

`typings/auto-imports.d.ts`（93 行）声明了 Vue/Pinia/Element Plus 等所有可能的自动导入类型，但实际代码中仅使用了其中约 30%：

```typescript
// auto-imports.d.ts — 93 行，包含未使用的类型
const EffectScope: typeof import('vue').EffectScope     // 未使用
const getCurrentScope: typeof import('vue').getCurrentScope  // 未使用
```

## 涉及文件

- `src/typings/auto-imports.d.ts`

## 修复方案

配置 `unplugin-auto-import` 仅生成项目中实际使用的 API 的类型声明。

## 预防措施

定期审查自动生成的类型文件，移除未使用的声明。

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- 此类问题属于常见开发疏忽，可通过静态分析和自动化检查提前发现
- 建议将典型问题模式记录到团队知识库，避免重复踩坑
- 代码审查应重点关注此类边界情况
