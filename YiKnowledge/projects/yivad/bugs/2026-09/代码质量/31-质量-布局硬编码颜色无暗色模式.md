# 布局组件中云标签行内样式使用硬编码像素值

## 现象

`LayoutTransverse` 和 `LayoutColumns` 的 SCSS 中使用大量硬编码的像素值和颜色覆盖，缺乏响应式变量：

```scss
// LayoutTransverse/index.scss
color: #ffffff !important;
background-color: var(--el-color-primary) !important;
border-bottom-color: var(--el-color-primary) !important;

// LayoutColumns/index.scss
width: 0 !important;
border-right: none !important;
```

这些布局样式使用 `!important` 强制覆盖 Element Plus 默认样式，且硬编码 `#ffffff` 而非使用主题变量。切换到暗色主题时，`#ffffff` 白色文字在白色背景上不可见。

## 根因分析

- Element Plus 的布局组件（`el-menu`）默认样式与 YiVad 的布局设计不完全匹配
- 开发者使用 `!important` + 硬编码值快速覆盖
- 缺乏主题感知的 CSS 变量体系
- 暗色模式下硬编码的 `#ffffff` 会导致对比度问题

## 涉及文件

- `layouts/LayoutTransverse/index.scss` — 6 处硬编码
- `layouts/LayoutColumns/index.scss` — 4 处硬编码
- `assets/iconfont/iconfont.scss` — 字体强制覆盖

## 修复方案

1. 将硬编码颜色替换为 Element Plus CSS 变量（`var(--el-color-white)`、`var(--el-menu-text-color)` 等）
2. 通过 Element Plus 的暗色模式变量自动适配主题切换
3. 布局宽度/边距使用 SCSS 变量统一管理

## 预防措施

- SCSS 中禁止硬编码主题相关颜色
- 所有颜色必须通过 CSS 变量间接引用

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）
