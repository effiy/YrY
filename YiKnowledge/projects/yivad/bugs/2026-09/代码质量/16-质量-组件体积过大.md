# 大文件组件拆分优化

## 优化总览

| 文件 | 优化前 | 优化后 | 缩减 | 策略 |
|------|--------|--------|------|------|
| `LlamaIndexPanel/index.vue` | 4556 | **174** | 96% | Tab 组件拆分 |
| `ChatToolbar/index.vue` | 3217 | **1809** | 44% | Composable 提取 |
| `rssManager.vue` | 2689 | **2510** | 7% | Composable 提取 |
| `useKnowledgeBase.ts` | 1693 | 1693 | — | 待优化 |
| `aiChat.ts` store | 1489 | 1489 | — | 待优化 |

**总计**：移除了 4569 行内联逻辑，新增 5 个模块化文件。

---

## 1. LlamaIndexPanel — 4556 → 174 行（96%）

**问题**：单个 SFC 包含 Query、Index、Decompose、History 四个 Tab 的全部逻辑（2091 行 `<script>` + 1830 行 `<template>` + 632 行 `<style>`）。

**策略**：拆分为 4 个独立 Tab 组件 + 共享 composable。每个 Tab 拥有独立的内部状态和 API 调用，`index.vue` 仅负责 Tab 切换、Scope 管理和文件预览弹窗。

**拆分产物**：

| 文件 | 行数 | 职责 |
|------|------|------|
| `index.vue` | 174 | Tab 切换 + Scope 管理 + 文件预览 |
| `RagQueryTab.vue` | 521 | Query Tab：语义搜索 + 评分结果 |
| `RagIndexTab.vue` | 599 | Index Tab：索引状态 + 重建 |
| `RagDecomposeTab.vue` | 348 | Decompose Tab：SubQuestionQueryEngine |
| `RagHistoryTab.vue` | ~2500 | History Tab：检索历史 + 分析 charts |
| `useRagScope.ts` | 58 | Scope/Context 文件管理 |
| `useRagFormat.ts` | — | 格式化工具函数 |

**架构**：配置覆盖通过 `queryTabRef.seedOverrides()` 显式传递，避免隐式耦合。

---

## 2. ChatToolbar — 3217 → 1809 行（44%）

**问题**：Skills 面板（Pin 管理、排序模式、Sparklines）、MCP 工具发现/执行、内联参数编辑器、遥测统计全部内联在单个 SFC 中（~1500 行 `<script>`）。

**策略**：提取 `useSkillsMcp` composable，封装所有 Skills/MCP/遥测逻辑。Composable 自包含依赖（`useAiChatStore`、`MCP_SERVERS`、`listMcpTools`），通过 100+ 变量解构暴露给模板。

**拆分产物**：

| 文件 | 行数 | 职责 |
|------|------|------|
| `index.vue` | 1809 | Toolbar 布局 + Prompt 历史 + 事件分发 + 模板 |
| `useSkillsMcp.ts` | 1547 | Skills 面板 + MCP 工具 + 内联执行 + 遥测 |

**关键设计决策**：
- Composable 自行导入 `useAiChatStore`（Pinia 单例模式，多处导入安全）
- `pinLegend` 的 `useSparkLegendToggle` 在 composable 内部调用一次，解构为 `pinLegendCollapsed`/`togglePinLegend`
- 模板通过批量解构访问所有变量，无需逐一手动传递 props

---

## 3. rssManager — 2689 → 2510 行（7%）

**策略**：提取简报分析图表和计数动画。

**拆分产物**：

| 文件 | 行数 | 职责 |
|------|------|------|
| `useRssBriefing.ts` | 190 | 5 种 ECharts 图表配置 + `loadBriefing`/`loadDailyVolume` |
| `useCountUp.ts` | 21 | 通用 `requestAnimationFrame` 缓动计数动画 |

`useRssBriefing` 接收 `briefingItems` 等 Ref 参数，通过依赖注入模式与组件通信，无隐式耦合。

`useCountUp` 位于 `src/hooks/`，可被任意组件复用。

---

## 待优化

### useKnowledgeBase（1693 行）

单个 composable 包含 50+ 个 computed、20+ 个方法，建议拆分：
- `useKnowledgeFilters` — 过滤方法 + 排序 + 分页（~260 行）
- `useKnowledgeCharts` — ECharts 图表 computed 选项（~150 行）
- `useKnowledgeDrill` — 图表点击钻取（~60 行）

### aiChat Store（1489 行）

单个 Pinia store 管理消息、工具、上下文、会话、SSE 流控，建议用 Pinia composition API 拆分为可组合的 store 片段。

---

## 预防措施

- 组件行数上限 300–500 行，超限触发 code review
- 新功能优先提取为独立组件或 composable
- 可复用逻辑放入 `src/hooks/`，领域逻辑放入对应 `composables/` 目录
- 图表配置从页面组件提取到领域 composable，接受 Ref 参数实现依赖注入

## 影响范围

- **影响组件**：LlamaIndexPanel、ChatToolbar、rssManager
- **影响用户**：无功能变更，纯代码组织优化
- **API 契约**：无影响
- **其他项目**：无影响（仅 YiVad）
