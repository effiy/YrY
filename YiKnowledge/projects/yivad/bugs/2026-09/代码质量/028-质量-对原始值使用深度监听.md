# watch 布尔值数组使用了不必要的 deep: true

## 现象

`KnowledgeChatPanel.vue` 对布尔 ref 数组使用了 `deep: true` 监听，完全无效且增加开销：

```typescript
// KnowledgeChatPanel.vue:139
watch([ragEnabled, webSearchEnabled], () => saveSettings(), { deep: true });
```

`ragEnabled` 和 `webSearchEnabled` 均为 `ref<boolean>`，其值是不可变的原始类型（`true`/`false`）。`deep: true` 对原始类型无任何效果，但会导致 Vue 在每次回调前执行不必要的深度遍历检查。

其他合理使用 `deep: true` 但可优化的场景：
- `TopicListPage.vue:507` — `watch(columns, ..., { deep: true })` 监听整个列配置数组
- `useRssReadStar.ts:28-29` — `watch(readKeys/starredKeys, ..., { deep: true })` 监听 Set
- `ProTable/index.vue:208` — `watch(() => props.initParam, ..., { deep: true })` 可改用 `() => ({...props.initParam})`

## 根因分析

- 开发者习惯性地给 `watch` 添加 `{ deep: true }` 而不评估数据类型
- 对原始类型（string、number、boolean）的 ref 使用 deep 是完全浪费
- Vue 3 文档明确说明 `deep` 仅对嵌套对象/数组有意义

## 涉及文件

- `views/aiChat/components/KnowledgeChatPanel.vue:139` — 布尔数组 deep watch
- `components/TopicListPage/index.vue:507` — 列配置 deep watch
- `hooks/useRssReadStar.ts:28-29` — Set deep watch
- `components/ProTable/index.vue:208` — initParam deep watch

## 修复方案

1. `KnowledgeChatPanel`：移除 `{ deep: true }`
2. `TopicListPage`：仅监听 `columns.length` 和关键配置字段
3. `useRssReadStar`：Set 本身不需要 deep，移除
4. `ProTable`：使用 getter 返回浅拷贝触发变更检测

## 预防措施

- ESLint 规则标记对原始类型 ref 使用 `deep: true` 的 watch

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- **`deep: true` 对原始类型完全无效**：`ref<boolean>` 的值是不可变原始类型，`deep: true` 只会增加不必要的遍历开销而不会有任何功能差异。Vue 文档明确说明 `deep` 仅对嵌套对象有意义
- **习惯性添加 `deep: true` 是性能债务**：开发者可能从某处复制了 `{ deep: true }` 模板而不理解其含义。这 4 处无效的 `deep` 虽然单次开销微乎其微，但反映了「不理解就复制」的编码习惯
