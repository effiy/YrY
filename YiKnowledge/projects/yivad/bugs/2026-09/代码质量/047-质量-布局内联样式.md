# layouts 组件中使用内联 style 属性绑定

## 现象

`layouts/components/Main/index.vue:35` 使用 `<router-view>` 的内联样式绑定：

```vue
<router-view v-slot="{ Component, route }">
  <component :is="Component" :key="route.fullPath" />
</router-view>
```

多个布局组件将样式直接写在模板的 `:style` 绑定中，而非提取到 `<style scoped>` 块。内联样式无法利用 CSS 预处理器、无法被 Stylelint 检查、优先级高于 CSS 文件难以覆盖。

## 根因分析

- 布局组件需要根据状态动态调整样式（如侧边栏折叠、全屏模式）
- 开发者使用 `:style="{ marginLeft: ... }"` 动态计算值

## 涉及文件

- `layouts/components/Main/index.vue` — 内联样式
- `layouts/components/` — 多个布局组件

## 修复方案

使用 CSS 自定义属性：
```vue
<div :style="{ '--sidebar-width': isCollapse ? '64px' : '200px' }">
```
```scss
.main-content {
  margin-left: var(--sidebar-width);
}
```

## 预防措施

- 动态样式优先使用 CSS 自定义属性，限制内联 `:style`

## 影响范围

- **影响组件/页面**：详见描述章节
- **影响用户**：所有用户
- **是否影响 API 契约**：否
- **是否影响其他前端项目**：否（仅 YiVad）

## 经验教训

- **CSS 自定义属性作为动态样式桥梁**：`:style="{ '--sidebar-width': isCollapse ? '64px' : '200px' }"` 可以让 JS 状态驱动 CSS，同时保持样式在 `<style scoped>` 块内、可被 Stylelint 检查。这比直接写 `:style="{ marginLeft: '...' }"` 更可维护
- **布局组件的样式特殊性**：布局组件确实需要根据交互状态（折叠/展开/全屏）动态调整尺寸，不能用纯静态 CSS。关键是选择一个规范的动态样式方案（CSS 变量或 CSS class 切换）并统一使用
