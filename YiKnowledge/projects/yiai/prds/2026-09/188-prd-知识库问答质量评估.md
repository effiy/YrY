# 知识库问答质量评估

## 背景

当前 RAG 问答缺乏系统化的质量评估机制：
- 无法量化回答是否忠实于知识库来源
- 无法评估检索结果与问题的相关性
- 无法判断回答是否完整覆盖了检索到的信息
- 无法追踪质量变化趋势

## 用户故事

- 作为知识库管理员，我希望了解 RAG 回答的质量水平
- 作为开发者，我希望知道哪些类型的查询 RAG 表现不佳
- 作为产品经理，我希望看到质量趋势以判断 RAG 优化效果

## 功能需求

1. **忠实度评估**：LLM-as-judge 判断回答是否基于检索来源（0-1 评分）
2. **相关性评估**：检索结果与查询的语义相似度评分
3. **完整性评估**：回答是否覆盖所有检索到的关键信息
4. **综合评分**：三项加权平均（忠实度 50% + 相关性 30% + 完整性 20%）
5. **质量仪表盘**：7 天趋势图 + 低质量查询列表
6. **每日聚合**：rag_quality_daily 集合存储每日统计

## 非功能需求

- 评估延迟 < 2s（异步执行，不阻塞回答返回）
- 每日聚合在凌晨 2:00 执行

## 验收标准

- [ ] 忠实度/相关性/完整性三维评分
- [ ] 仪表盘展示 7 天趋势折线图
- [ ] 单次回答下方显示质量卡片
