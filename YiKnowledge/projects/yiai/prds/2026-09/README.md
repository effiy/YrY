## 四、文档规范

### 4.1 文件命名

```
{序号}-需求-{描述}.md

正确示例：
  05-需求-RAG引擎.md
  106-需求-监控与告警体系.md
  163-需求-多Agent编排框架.md

错误示例：
  rag-engine.md            — 缺少中文描述和序号前缀
  05-RAG引擎.md            — 缺少"需求"标识段
  05_需求_RAG引擎.md       — 使用下划线而非连字符
```

- 序号与 `prd_task_id` 中的数字一致（`YA-09-{序号}`）
- 描述使用中文，简洁概括需求主题
- 仅连字符（`-`）分隔，禁止下划线

### 4.2 PRD 标准结构

每个标准 PRD 文件按 11 节组织：

| 节 | 内容 | 关键产出 |
|----|------|----------|
| 1. 背景 | 业务背景、核心挑战 | 问题陈述 |
| 2. 现状与目标 | 改造前/后对比、能力全景（Mermaid）、边界定义 | 目标状态图 |
| 3. 需求范围 | 明确范围内/外 | 范围边界表 |
| 4. 功能需求 | FR-01 至 FR-0N | 可追溯的功能条目 |
| 5. 领域模型 | 数据模型、状态机、实体关系 | ER 图 / 状态图 |
| 6. 非功能需求 | 安全、性能、可用性、可观测性 | NFR 检查清单 |
| 7. 设计决策 | 方案对比矩阵、选择理由 | ADR 记录 |
| 8. 验收标准 | 逐条可验证的 AC | 测试用例骨架 |
| 9. 风险与缓解 | 风险矩阵、回滚策略 | 风险登记册 |
| 10. 后续演进 | 技术债登记、下期规划 | 技术债条目 |
| 11. 关联需求 | 依赖、开发方案、测试用例 | 追溯链接 |
