# 流式响应缓存与重放

## 背景

当前每次 LLM 请求都重新推理，即使相同问题被重复询问：
- 相同对话中重复生成浪费计算资源
- 多个用户同时问相同问题各自调 LLM
- Regenerate 操作完全重新推理

## 用户故事

- 作为用户，当我重新生成相同问题的回答时，希望更快返回
- 作为开发者，我希望减少重复 LLM 调用以降低成本
- 作为用户，我不希望因缓存而影响流式输出的体验

## 功能需求

1. **SSE Chunk 记录**：记录每个 chunk 的内容和时间戳
2. **缓存键生成**：messages hash + model + params 去重
3. **并发去重**：相同请求正在处理时共享 promise
4. **时序重放**：按原始 chunk 间隔重放，保持流式体验
5. **TTL + LRU**：1 小时 TTL，最大 100 条目

## 非功能需求

- 缓存命中率 > 20%
- 重放时序偏差 < 50ms
- 缓存条目内存占用 < 50MB

## 验收标准

- [ ] 相同请求第二次走缓存
- [ ] 缓存重放逐字速度与原始一致
- [ ] TTL 过期自动清除
- [ ] 前端显示"(cached)"提示
