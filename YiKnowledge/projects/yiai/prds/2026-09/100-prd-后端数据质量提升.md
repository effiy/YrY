# YA-100: 后端数据质量提升

## 一、需求背景

### 问题 1：Issue/Bug 状态值大小写混用

YiAi 数据库中 `issues` 和 `bugs` 集合的 `status` 字段存在大小写混用：
- `done` / `Done`
- `todo` / `To Do`  
- `in_progress` / `In Progress`
- `in_review` / `Review`

**影响**：
- 6 个服务文件各自维护状态常量列表（代码重复）
- 前端 YiVad 首页需通过 `STATUS_MERGE` 映射兼容（硬编码 workaround）
- MongoDB 聚合查询需同时包含大小写变体（`["done", "Done", "closed", "Closed", ...]`）

### 问题 2：Dashboard 数据依赖轮询

YiVad 首页通过 `useHomeData` 每 60 秒轮询一次 YiAi countDocuments，无服务端推送机制。高频数据（如活跃 issue 数、今日完成数）无法实时反映变化。

## 二、解决方案

### R1：共享状态常量模块

创建 `src/shared/status.py` 作为唯一状态数据源：
- `Status` 类定义所有 canonical 状态值（小写）
- `normalize_status()` / `normalize_status_list()` 处理遗留大小写兼容
- `is_closed()` / `is_active()` 判断函数
- 6 个服务文件迁移到统一导入

### R2：Dashboard 实时 SSE 端点

创建 `src/server/routes/dashboard/live.py`：
- `GET /dashboard/live`：SSE 端点，每 5s 推送 KPI
- `GET /dashboard/live-snapshot`：REST 单次快照

## 三、验收标准

- [x] 6 个服务文件不再包含自定义状态常量列表
- [x] `normalize_status` 正确映射所有遗留变体
- [x] `/dashboard/live` 返回 SSE text/event-stream
- [x] `/dashboard/live-snapshot` 返回完整 KPI JSON
- [x] 无 MongoDB 连接时优雅降级（返回 0 值）
- [x] pytest 561 passed
