# YA-09-16: 服务健康检查与就绪探针 — 生产部署可观测性增强

> 需求编号：YA-09-16 · 优先级：P2 · 人天：0.5d · 状态：需求已编写

## 背景

YiAi 当前缺少标准健康检查端点。FastAPI 默认无 `/health` 端点，部署到容器环境（Docker/Kubernetes）时无法进行存活探测和就绪探测。生产环境需要三个级别的健康检查：存活（liveness）、就绪（readiness）、详细诊断（debug）。

---

## 一、目标架构

```python
# YiAi/src/server/health.py

from fastapi import APIRouter, HTTPException
from motor.motor_asyncio import AsyncIOMotorClient
import time, psutil

router = APIRouter(tags=["health"])

# 健康状态缓存（避免每次探测都查 MongoDB/Ollama）
_health_cache: dict = {}
CACHE_TTL = 5  # 秒


@router.get("/health/live")
async def liveness():
    """存活探针——仅检查进程是否存在。K8s livenessProbe 用。"""
    return {"status": "alive", "uptime": time.time() - _start_time}


@router.get("/health/ready")
async def readiness():
    """就绪探针——检查关键依赖是否可用。K8s readinessProbe 用。"""
    now = time.monotonic()
    if _health_cache.get('ready_checked', 0) > now - CACHE_TTL:
        return _health_cache['ready_result']

    checks = {}
    healthy = True

    # MongoDB 连接检查
    try:
        await db.command('ping')
        checks['mongodb'] = 'ok'
    except Exception as e:
        checks['mongodb'] = f'error: {e}'
        healthy = False

    # Ollama 检查
    try:
        async with httpx.AsyncClient() as client:
            resp = await client.get(f"{settings.OLLAMA_BASE_URL}/api/tags", timeout=5)
        checks['ollama'] = 'ok' if resp.status_code == 200 else f'status {resp.status_code}'
    except Exception as e:
        checks['ollama'] = f'error: {e}'
        healthy = False

    result = {"status": "ready" if healthy else "not_ready", "checks": checks}
    _health_cache['ready_checked'] = now
    _health_cache['ready_result'] = result

    if not healthy:
        raise HTTPException(503, detail=result)
    return result


@router.get("/health/debug")
async def debug():
    """详细诊断——内存/连接池/活跃请求统计。仅内部运维使用。"""
    mongo_pool = db.client.topology_description

    return {
        "process": {
            "pid": os.getpid(),
            "memory_mb": psutil.Process().memory_info().rss / 1024 / 1024,
            "cpu_percent": psutil.Process().cpu_percent(),
            "threads": psutil.Process().num_threads(),
        },
        "mongodb": {
            "pool_size": getattr(db.client, 'max_pool_size', None),
            "topology": str(mongo_pool),
        },
        "agent": {
            "semaphore_available": agent_semaphore._value,
            "active_agents": 3 - agent_semaphore._value,
        },
        "cache": {
            "prompt_templates": len(prompt_manager._cache),
            "tool_cache_hit_rate": tool_cache.hit_rate if tool_cache else None,
        },
    }
```

## 三、测试规格

### Requirement: 三级健康检查端点

#### Scenario: 存活探针始终返回成功
- **Given** YiAi 进程正在运行
- **When** `GET /health/live`
- **Then** HTTP 200, `{"status": "alive", "uptime": <seconds>}`

#### Scenario: 就绪探针——所有依赖正常
- **Given** MongoDB ping 成功, Ollama API 返回 200
- **When** `GET /health/ready`
- **Then** HTTP 200, `{"status": "ready", "checks": {"mongodb": "ok", "ollama": "ok"}}`

#### Scenario: 就绪探针——MongoDB 不可用
- **Given** MongoDB 连接断开
- **When** `GET /health/ready`
- **Then** HTTP 503, `checks.mongodb` 包含 "error:"
- **And** `status` = "not_ready"

#### Scenario: 就绪探针——Ollama 不可用
- **Given** Ollama 服务未启动
- **When** `GET /health/ready`
- **Then** HTTP 503, `checks.ollama` 包含 "error:"
- **And** `status` = "not_ready"

#### Scenario: 就绪探针缓存
- **Given** 上一次 ready 检查在 3 秒前 (CACHE_TTL=5)
- **When** `GET /health/ready`
- **Then** 返回缓存结果，不重新检查 MongoDB/Ollama

#### Scenario: 详细诊断返回完整信息
- **Given** YiAi 正常运行
- **When** `GET /health/debug`
- **Then** 返回 `process` (pid/memory/cpu/threads), `mongodb` (pool_size/topology), `agent` (semaphore/active), `cache` (templates/hit_rate)

#### Scenario: 详细诊断——生产环境访问控制
- **Given** 请求未携带运维 Token
- **When** `GET /health/debug`
- **Then** HTTP 403（生产环境中 `/health/debug` 需要认证）

## 四、Kubernetes 集成配置

```yaml
# deployment.yaml
spec:
  containers:
  - name: yiai
    ports:
    - containerPort: 10086
    livenessProbe:
      httpGet:
        path: /health/live
        port: 10086
      initialDelaySeconds: 10    # 应用启动 10s 后开始探测
      periodSeconds: 30           # 每 30s 探测一次
      timeoutSeconds: 5           # 探测超时
      failureThreshold: 3         # 连续 3 次失败 → 重启 Pod
    readinessProbe:
      httpGet:
        path: /health/ready
        port: 10086
      initialDelaySeconds: 5     # 应用启动 5s 后开始探测
      periodSeconds: 10           # 每 10s 探测一次
      timeoutSeconds: 5
      failureThreshold: 2         # 连续 2 次失败 → 移出 Service
    startupProbe:
      httpGet:
        path: /health/ready
        port: 10086
      initialDelaySeconds: 0
      periodSeconds: 5
      failureThreshold: 30        # 最多等待 150s (5s × 30) 启动
```

### 探针行为矩阵

| 探针 | 用途 | 失败后果 | 探测频率 | 超时 | 失败阈值 | 成功阈值 |
|------|------|----------|----------|------|----------|----------|
| **startupProbe** | 应用启动完成检测 | 不重启（等待启动完成） | 5s | 5s | 30 | 1 |
| **livenessProbe** | 进程存活检测 | 重启 Pod | 30s | 5s | 3 | 1 |
| **readinessProbe** | 服务就绪检测 | 移出 Service (不重启) | 10s | 5s | 2 | 1 |

## 五、代码审查检查清单

- [ ] `/health/live` 不检查外部依赖（纯进程状态）
- [ ] `/health/ready` 检查 MongoDB 和 Ollama 可用性
- [ ] `/health/ready` 有 5s 缓存避免每 10s 探测都查数据库
- [ ] `/health/debug` 有访问控制（生产环境需 Token）
- [ ] K8s livenessProbe 的 `failureThreshold` ≥ 3 (避免误重启)
- [ ] K8s readinessProbe 的 `periodSeconds` ≥ 10 (避免过于频繁)
- [ ] `startupProbe` 配置足够等待 Ollama 模型加载 (150s)
- [ ] 健康检查端点不记录到审计日志（避免噪音）
- [ ] `psutil` 依赖添加到 `requirements.txt`

## 六、可观测性

| 指标 | 采集方式 | 告警阈值 | 说明 |
|------|----------|----------|------|
| 就绪探针失败次数 | K8s Events | 5 分钟内 > 3 次 | 表示依赖服务 (MongoDB/Ollama) 不稳定 |
| 存活探针失败次数 | K8s Events | > 0 即告警 (Pod 重启) | 应用崩溃或无响应 |
| 就绪探针延迟 (P95) | `health.py` 内置计时 | > 2s | MongoDB/Ollama 响应变慢 |
| 内存使用趋势 | `/health/debug` → Prometheus | 单日增长 > 50MB | 可能存在内存泄漏 |
| Agent Semaphore 耗尽 | `/health/debug` → `available=0` | 持续 > 5 分钟 | 所有 Agent 实例忙碌 |

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
