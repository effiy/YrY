# YA-101: 翻译引擎智能推荐

## 一、需求背景

YiPet（Chrome 扩展）在调用 YiAi 翻译服务时，需要选择翻译引擎。当前无智能选择能力——用户要么手动选择引擎，要么使用默认配置。

**核心问题**：翻译引擎的可用性和质量是实时变化的（API 限流、服务故障、响应延迟），用户无法实时感知哪个引擎当前最佳。

## 二、解决方案

### `provider_recommend` RPC 方法

路径：`services.translation.translate_service.provider_recommend`

**输入**：
```json
{ "from_lang": "en", "to_lang": "zh", "limit": 5 }
```

**输出**：
```json
{
  "recommended": "openai",
  "providers": [
    { "name": "openai", "success_rate": 0.98, "status": "healthy", "total": 245 },
    { "name": "google", "success_rate": 0.95, "status": "healthy", "total": 180 },
    { "name": "deepl", "success_rate": 0.72, "status": "degraded", "total": 95 }
  ],
  "healthy_count": 2, "degraded_count": 1, "down_count": 0
}
```

**排名算法**：
1. 状态层级优先：healthy (3) > degraded (2) > down (1)
2. 同层级按成功率降序
3. 数据来源：近 24h `translation_records` MongoDB 聚合

### 消费方

| 项目 | 集成方式 | 用途 |
|------|---------|------|
| YiVad | TranslationAnalytics 面板 | 运维监控 — 实时排名展示 |
| YiPet | `getProviderRecommend()` API | 用户选中文本翻译 — 自动选择最佳引擎 |

## 三、跨项目数据流

```
YiAi MongoDB translation_records (实时写入)
  → provider_recommend RPC (24h 聚合 + 排名)
    ├── YiVad TranslationAnalytics → 监控面板
    └── YiPet translateSelection → 智能引擎选择
```

## 四、验收标准

- [x] `provider_recommend` RPC 返回正确的排名
- [x] 排名按状态层级 + 成功率降序
- [x] YiVad TranslationAnalytics 展示排名面板
- [x] YiPet `getProviderRecommend` API 已添加
- [x] 无数据时优雅降级（返回空列表）
