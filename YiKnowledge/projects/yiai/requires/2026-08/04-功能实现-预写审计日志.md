### 功能概述

实现 Write-Ahead Audit Log 机制，记录每一次数据写入操作（actor + timestamp + operation + before/after），满足合规审计要求。生产环境数据迁移前必须完成。

### 技术实现

#### 审计日志模型

```python
class AuditLog:
    log_id: str          # 唯一日志 ID
    timestamp: datetime  # 操作时间
    actor: str           # 操作人 (username / system)
    operation: str       # 操作类型: CREATE / UPDATE / DELETE
    collection: str      # 目标集合
    document_key: str    # 文档唯一键
    before: dict | None  # 操作前数据（CREATE 时为 None）
    after: dict | None   # 操作后数据（DELETE 时为 None）
    changes: dict | None # 变更字段 diff（UPDATE 时）
    ip_address: str      # 操作 IP
    user_agent: str      # 客户端信息
```

#### 实现策略

- **Write-Ahead**：在数据写入 MongoDB 之前，先写入审计日志
- **MongoDB 集合**：`audit_logs`（独立集合，与业务数据分离）
- **异步写入**：审计日志写入不阻塞主流程（使用 Motor 异步驱动）
- **不可变性**：审计日志只追加，不可修改或删除

#### 审计范围

| 操作 | 审计内容 |
|------|----------|
| `insert_document` | after 数据（完整文档） |
| `update_document` | before/after 数据 + changes diff |
| `delete_document` | before 数据（完整文档） |
| `write_file` | target_file + content hash |
| 权限变更 | actor + target_user + old_role + new_role |

#### 数据保留策略

- 审计日志保留 90 天（可配置）
- 超过保留期的日志自动归档（可选）
- 归档日志存储于 `audit_logs_archive` 集合或导出为 JSON 文件

#### 查询接口

- RPC 路由：`services.audit.audit_service.query_audit_logs`
- 查询参数：
  ```json
  {
    "filter": {
      "actor": "username",
      "collection": "issues",
      "operation": "UPDATE",
      "start_time": "2026-08-01T00:00:00Z",
      "end_time": "2026-08-31T23:59:59Z"
    },
    "limit": 50,
    "offset": 0
  }
  ```
- 权限：仅 admin 角色可查询审计日志

#### 性能考量

- 审计日志写入 < 5ms（异步，不阻塞主流程）
- 审计日志写入失败不阻塞数据写入（best-effort + 错误告警）
- 审计日志集合按月分片（可选）

### 关联模块

- 后端服务：`services/audit/audit_service.py`
- 数据模型：`domain/audit/`
- 数据服务：`services/database/data_service.py`（拦截写入操作）
- 配置：`config.yaml` (audit 配置段)

### 验收标准

1. 所有数据写入操作（INSERT/UPDATE/DELETE）有审计记录
2. 审计日志包含 actor + timestamp + before/after 数据
3. 审计日志不可修改或删除
4. 审计日志查询接口可用，支持按 actor/collection/时间 过滤
5. 审计日志写入不阻塞主流程（异步）
6. 通过合规审计审查
