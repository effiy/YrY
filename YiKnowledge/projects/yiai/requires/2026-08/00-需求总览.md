# 一、业务概述

## 1.1 业务背景

YiAi 在七月迭代完成 RAG 引擎和 Knowledge Watcher 后，八月迭代聚焦于 AI 能力升级（BRD Agent、Multi-Provider LLM）、工程质量提升（Pytest 覆盖率）和基础设施完善（审计日志、GraphQL 网关）。

## 1.2 业务目标

- 构建基于知识库的 BRD Agent，辅助产品需求分析
- 抽象 LLM Provider 层，支持多种模型服务
- 扩展测试覆盖范围，提升代码质量和可靠性
- 实现审计日志机制，满足合规要求
- 探索 GraphQL 网关层，提供类型安全的 API

## 1.3 适用对象

- YiVad / YiPet 前端（AI Chat、Agent 功能）
- 产品经理（BRD Agent 辅助需求分析）
- 合规审计（审计日志）

## 1.4 系统范围

- YiAi FastAPI 后端
- MongoDB（审计日志集合）
- Ollama / OpenAI / Anthropic（LLM Provider）
- YiKnowledge（BRD Agent 知识源）

# 二、功能详情

## 2.1 BRD Agent (需求 1)

RAG 驱动的产品需求分析 Agent，支持文档对比和方案推荐。基于 YiKnowledge 知识库进行上下文检索，辅助产品经理撰写和评审 PRD。

## 2.2 Multi-Provider LLM (需求 2)

抽象 LLM Provider 层，统一接口支持多种模型服务：

| Provider | 模型 | 用途 |
|----------|------|------|
| Ollama | qwen2.5, nomic-embed-text | 本地推理 + Embedding |
| OpenAI | gpt-4o, text-embedding-3 | 云端推理 |
| Anthropic | claude-sonnet-4-6 | 云端推理 |

## 2.3 测试覆盖率 (需求 3)

扩展 Pytest 测试覆盖范围，覆盖 shared/data/domain 模块，目标行覆盖率 70%+。

## 2.4 审计日志 (需求 7)

Write-Ahead Audit Log 机制，记录所有数据写入操作（MongoDB collection 级别），满足合规要求。

## 2.5 GraphQL 联邦层 (需求 6)

为 RPC envelope 提供类型安全的 GraphQL 接口，支持 Strawberry GraphQL + Federation。
