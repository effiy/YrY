# 一、业务概述

## 1.1 业务背景

YiAi 作为 YrY monorepo 的唯一后端，需要为所有前端（YiVad、YiPet）提供 AI 检索能力。七月迭代聚焦于 RAG（Retrieval-Augmented Generation）检索引擎的构建和 YiKnowledge 知识库的自动同步机制。

## 1.2 业务目标

- 构建基于 llama_index 的 RAG 检索引擎，支持混合检索和多种查询增强特性
- 实现 Knowledge Watcher 自动同步机制，将 YiKnowledge 文件树同步至 MongoDB

## 1.3 适用对象

- YiVad 前端（知识库 RAG 检索页面）
- YiPet 扩展（Chat 窗口 RAG 检索）
- YiAi BRD Agent（知识库驱动）

## 1.4 系统范围

- YiAi FastAPI 后端
- MongoDB（knowledge_files 集合）
- llama_index（向量索引 + 检索引擎）
- Ollama（LLM 推理 + Embedding）

# 二、功能详情

## 2.1 RAG Module — Hybrid Retrieval Engine (需求 4)

基于 llama_index 构建 RAG 检索引擎，实现混合检索和多种查询增强特性。

### 核心架构

| 组件 | 说明 |
|------|------|
| 向量检索 | nomic-embed-text 向量化，FAISS 索引 |
| BM25 检索 | 关键词匹配，与向量检索结果融合 |
| LLM 重排序 | cross-encoder 对候选文档二次排序 |
| 内联引用 | 答案中嵌入来源引用标记 |
| HyDE | 查询前生成假设文档增强检索 |
| 句子窗口检索 | 检索句子级片段，返回窗口上下文 |

### API 端点

| 接口 | 说明 |
|------|------|
| `POST /rag-query` | 一次性检索，返回排序后的文档片段 |
| `POST /rag-chat` | SSE 流式聊天，基于检索结果生成回答 |
| `POST /rag-file-chat` | 单文件 SSE 流式聊天 |
| `POST /rag-status` | 索引状态查询 |
| `POST /rag-build` | 触发索引重建 |

## 2.2 Knowledge Watcher (需求 5)

apscheduler 每 5 秒轮询 YiKnowledge 文件树，解析 frontmatter 同步至 MongoDB `knowledge_files` 集合。

| 特性 | 说明 |
|------|------|
| 轮询间隔 | 5 秒 |
| 变更检测 | 文件 mtime + content hash |
| 同步策略 | 增量更新（新增/修改/删除） |
| 元数据解析 | YAML frontmatter 提取 title/tags/category/status 等 |
