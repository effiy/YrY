# Pattern: Agent Loop

## Overview

Agent 循环是 YiAi 的核心 AI 交互模式，实现了多轮 LLM 推理、工具调用、确认门控和 SSE 流式事件推送。Agent 循环遵循 Pi 风格设计，支持模型切换、任务续接、断连检测和多重容错机制。

**相关规范**：
- [API 规范](../../架构/api规范/规范.md) -- SSE 流式响应和错误码
- [认证规范](../../架构/认证规范/规范.md) -- Agent 安全控制
- [领域服务模式](../domain-service/spec.md) -- 工具注册和执行

## Agent 循环架构

### 整体流程

```
POST /agent/chat  { messages, model, max_turns, system?, tools? }
  |
  v
Agent.run() 循环
  ┌─────────────────────────────────────────────────────┐
  │  turn_start                                        │
  │  -> LLM 推理 (Ollama/OpenAI/Anthropic)              │
  │  -> 解析响应 (text + tool_calls)                    │
  │  -> 工具调用:                                       │
  │    tool_execution_start                            │
  │    -> 确认门控 (写操作需用户确认)                     │
  │    -> 执行工具 (ToolRegistry.execute)               │
  │    tool_execution_end                              │
  │  -> turn_end (总结本轮)                             │
  │  -> 循环直到 stop=completed 或 max_turns            │
  └─────────────────────────────────────────────────────┘
  -> agent_end { stop_reason, turns, trajectory }
```

### 核心数据结构

```python
@dataclass
class AgentConfig:
    model: str                          # 当前模型
    max_turns: int = 10                 # 最大轮次
    system: Optional[str] = None        # 系统提示
    tools: Optional[List[dict]] = None  # 可用工具定义
    model_fallback: Optional[List[str]] = None  # 模型回退列表
    llm_max_retries: int = 2            # LLM 重试次数
    max_tool_result_chars: int = 6000   # 工具结果最大字符数
    confirmation_timeout: int = 120     # 确认超时 (秒)

@dataclass
class ToolCall:
    id: str                             # 工具调用 ID
    name: str                           # 工具名称
    arguments: dict                     # 工具参数

@dataclass
class ToolResult:
    name: str                           # 工具名称
    content: Any                        # 工具返回内容
    error: Optional[str] = None         # 错误信息
```

## SSE 事件类型

### 完整事件流

```
data: {"type":"turn_start","turn":1}

data: {"type":"tool_call","tool":"db_list","args":{"cname":"menus"}}

data: {"type":"confirmation_required","tool":"db_create","confirmation_id":"t1:tool_0","args":{...}}

data: {"type":"tool_execution_start","tool":"db_create"}

data: {"type":"tool_execution_end","tool":"db_create","result":{...}}

data: {"type":"turn_end","summary":"已完成菜单创建"}

data: {"type":"agent_end","stop_reason":"completed","turns":3}
```

### 事件类型清单

| 事件 | 说明 | 触发时机 |
|------|------|---------|
| `turn_start` | 新一轮开始 | 每轮开始时 |
| `tool_call` | 模型发起工具调用 | 模型返回 tool_calls |
| `confirmation_required` | 需要用户确认 | 写操作工具调用前 |
| `tool_execution_start` | 工具开始执行 | 确认通过后/读操作直接执行 |
| `tool_execution_end` | 工具执行完毕 | 工具执行完成后 (含 blocked/skipped) |
| `turn_end` | 本轮结束 | 每轮结束时 |
| `agent_end` | Agent 循环结束 | 循环正常/异常终止 |
| `model_switch` | 模型自动切换 | 模型停滞时切换 |
| `error` | 错误事件 | LLM 调用失败等异常 |

## 工具注册与执行

### ToolRegistry

```python
# domain/ai/tools.py
class ToolRegistry:
    """工具注册表"""

    def __init__(self):
        self._tools: Dict[str, dict] = {}

    def register(self, name: str, func: callable, schema: dict):
        """注册工具"""
        self._tools[name] = {
            "func": func,
            "schema": schema,
            "requires_confirmation": schema.get("requires_confirmation", False)
        }

    def get_definitions(self) -> List[dict]:
        """获取工具定义的 JSON Schema 列表 (给 LLM)"""
        return [t["schema"] for t in self._tools.values()]

    async def execute(self, call: ToolCall, on_event: callable = None) -> ToolResult:
        """执行工具调用"""
        tool = self._tools.get(call.name)
        if not tool:
            return ToolResult(name=call.name, error=f"Unknown tool: {call.name}")

        # 参数校验
        validation_error = _validate_arguments(call, tool["schema"])
        if validation_error:
            return ToolResult(name=call.name, error=validation_error)

        # 执行
        try:
            result = await tool["func"](**call.arguments)
            return ToolResult(name=call.name, content=result)
        except Exception as e:
            return ToolResult(name=call.name, error=str(e))

def get_tool_registry() -> ToolRegistry:
    """获取工具注册表单例"""
    registry = ToolRegistry()

    # 注册通用数据工具
    registry.register("db_list", db_list, {
        "name": "db_list",
        "description": "列出集合中的文档",
        "parameters": {...},
        "requires_confirmation": False
    })

    registry.register("db_create", db_create, {
        "name": "db_create",
        "description": "创建文档",
        "parameters": {...},
        "requires_confirmation": True  # 写操作需要确认
    })

    # ... 更多工具
    return registry
```

### 参数校验

```python
def _validate_arguments(call: ToolCall, schema: dict) -> Optional[str]:
    """校验工具参数，返回错误信息或 None"""
    required = schema.get("parameters", {}).get("required", [])
    properties = schema.get("parameters", {}).get("properties", {})

    # 检查必填参数
    for field in required:
        if field not in call.arguments:
            return f"Missing required parameter: {field}"

    # 检查参数类型
    for key, value in call.arguments.items():
        if key in properties:
            expected_type = properties[key].get("type")
            if expected_type == "string" and not isinstance(value, str):
                return f"Parameter {key} should be string, got {type(value).__name__}"
            elif expected_type == "object" and not isinstance(value, dict):
                return f"Parameter {key} should be object, got {type(value).__name__}"
            elif expected_type == "array" and not isinstance(value, list):
                return f"Parameter {key} should be array, got {type(value).__name__}"

    return None
```

## 确认门控

### 门控流程

```
工具调用 (requires_confirmation=True)
  |
  v
发出 confirmation_required 事件
  |
  v
等待用户确认 (120s 超时)
  |
  ├── approved -> 执行工具 -> tool_execution_end
  ├── rejected -> 跳过工具 -> tool_execution_end (error: "Rejected by user")
  ├── timeout  -> 跳过工具 -> tool_execution_end (error: "Confirmation timed out")
  └── blocked  -> 跳过工具 -> tool_execution_end (error: "Blocked: identical call...")
```

### 确认实现

```python
async def _wait_for_confirmation(
    session_id: str,
    confirmation_id: str,
    timeout: int = 120
) -> str:
    """
    等待用户确认

    Returns: "approved" | "rejected" | "timeout"
    """
    store = _get_confirmation_store(session_id)

    start = time.time()
    while time.time() - start < timeout:
        decision = store.get(confirmation_id)
        if decision is not None:
            del store[confirmation_id]
            return decision
        await asyncio.sleep(0.5)

    # 超时
    del store[confirmation_id]
    return "timeout"

# 确认端点
@router.post("/agent/confirm")
async def confirm(request: Request, data: dict):
    """处理用户确认"""
    session_id = data["session_id"]
    confirmation_id = data["confirmation_id"]
    approve = data.get("approve", False)

    store = _get_confirmation_store(session_id)
    store[confirmation_id] = "approved" if approve else "rejected"

    return StandardResponse.success({"status": "ok"})
```

### 拒绝记忆

```python
# 模块级拒绝记忆
_session_rejections: Dict[str, List[str]] = {}
_MAX_SESSION_REJECTIONS = 20

def _call_signature(call: ToolCall) -> str:
    """生成调用签名: tool_name|json_args"""
    return f"{call.name}|{json.dumps(call.arguments, sort_keys=True, ensure_ascii=False)}"

def _remember_rejection(session_id: str, call: ToolCall):
    """记录拒绝"""
    if session_id not in _session_rejections:
        _session_rejections[session_id] = []
    _session_rejections[session_id].append(_call_signature(call))
    if len(_session_rejections[session_id]) > _MAX_SESSION_REJECTIONS:
        _session_rejections[session_id].pop(0)

def _is_rejected_call(session_id: str, call: ToolCall) -> bool:
    """检查是否已被拒绝"""
    return _call_signature(call) in _session_rejections.get(session_id, [])
```

## 容错机制

### 1. LLM 重试

```python
async def _stream_llm_response(messages, config, tools):
    """LLM 调用带重试"""
    for attempt in range(config.llm_max_retries + 1):
        try:
            async for chunk in runtime.stream_chat(messages, tools=tools):
                yield chunk
            return  # 成功
        except Exception as e:
            if attempt < config.llm_max_retries:
                wait = 2 ** attempt  # 指数退避
                logger.warning(f"LLM retry {attempt + 1}/{config.llm_max_retries} after {wait}s: {e}")
                await asyncio.sleep(wait)
            else:
                raise  # 重试耗尽
```

### 2. 模型切换

当弱模型停滞时，自动切换到更强模型：

```python
# 触发条件:
# 1. 叙述但不执行工具 (narrate-and-stop)
# 2. 连续 nudge 耗尽

if _model_escalated or not config.model_fallback:
    break  # 不切换

fallback_model = config.model_fallback[0]
config.model = fallback_model
config.model_fallback = config.model_fallback[1:]
_model_escalated = True

yield {"type": "model_switch", "from": old_model, "to": fallback_model}
```

### 3. 预算感知

在接近 max_turns 时提醒模型压缩步骤：

```python
def _budget_warning(turn_index: int, max_turns: int, warn_leftover: int = 3) -> str:
    """接近轮次上限时注入预算警告"""
    remaining = max_turns - turn_index
    if remaining <= warn_leftover and not _budget_injected:
        _budget_injected = True
        return (
            f"[BUDGET] 本次运行最多 {max_turns} 轮，当前第 {turn_index} 轮，"
            f"还剩 {remaining} 轮。压缩非必要步骤；若不够完成，"
            f"明确说还差哪些，方便用户回复「继续」"
        )
    return ""
```

### 4. 旋转检测

检测连续 3 次相同观察，防止模型陷入循环：

```python
def _advance_spin_state(prev_sig, run_sigs, obs, threshold=3):
    """检测重复观察"""
    if prev_sig == obs and obs:  # 相同且非空
        run_sigs += 1
        if run_sigs >= threshold:
            # 触发 nudge
            return True, 0
    else:
        run_sigs = 0
    return False, run_sigs
```

### 5. 结果裁剪

超大工具结果自动裁剪，防止上下文溢出：

```python
def _bound_tool_result(name: str, content: Any, max_chars: int = 6000) -> str:
    """裁剪工具结果"""
    text = json.dumps(content, ensure_ascii=False, default=str)
    if len(text) <= max_chars:
        return text

    head = text[:int(max_chars * 0.7)]
    tail = text[-int(max_chars * 0.22):]
    omitted = len(text) - len(head) - len(tail)
    return (
        f"{head}\n\n... [result truncated for context: {len(text)} chars, "
        f"~{omitted} chars omitted] ...\n\n{tail}"
    )
```

### 6. 断连检测

```python
async def _watch_disconnect(http_request: Request, abort_event: asyncio.Event):
    """监听客户端断开"""
    while not abort_event.is_set():
        try:
            message = await asyncio.wait_for(http_request._receive(), timeout=1.0)
            if message.get("type") == "http.disconnect":
                abort_event.set()
                break
        except asyncio.TimeoutError:
            continue
```

## 任务续接 (Resume)

### 续接流程

```
max_turns_reached
  |
  v
前端提示: "回复「继续」可接着完成"
  |
  v
用户发送 "继续"
  |
  v
POST /agent/chat { messages: [...], resume: true, task_text: "原任务" }
  |
  v
Agent 加载之前的 agent_messages (含 tool_results)
  |
  v
注入 [RESUME] 标记: "已执行的工具: db_create, db_update -- 请勿重复执行"
  |
  v
从上次中断处继续执行
```

### 续接实现

```python
async def agent_chat_stream(request: AgentChatRequest):
    """Agent 聊天流 (支持续接)"""

    agent_messages = [{"role": "system", "content": system_prompt}]

    if request.resume:
        # 恢复之前的 agent_messages
        saved = load_session_history(request.session_id)
        if saved:
            agent_messages = saved
            # 注入续接标记
            agent_messages.append({
                "role": "system",
                "content": f"[RESUME] 已执行工具: {', '.join(executed_tools)} -- 请勿重复执行"
            })

    # 继续执行
    agent = Agent(config=config)
    async for event in agent.run(agent_messages):
        yield event
```

## 任务完整性检查

Agent 循环在结束前执行多项任务完整性检查：

### 1. 无写入检查 (no-write nudge)

如果零次写入执行 + 最后一条用户消息是任务请求 -> 注入 `[TASK]` nudge

### 2. 命名工具检查 (named-tool checkpoint)

如果任务文本中命名的工具从未执行 -> 注入 `[TASK]` nudge 命名缺失工具

### 3. 计数感知检查 (count-aware gap)

如果任务要求创建 N 个但只创建了 M 个 (M < N) -> 注入 `[TASK]` nudge

### 4. 完整性检查 (completeness checkpoint)

如果任务文本中命名的工具部分未执行 -> 注入 `[TASK]` nudge

## 工具执行超时处理

### 超时配置

```python
# domain/ai/tools.py
import asyncio

class ToolRegistry:
    """工具注册表：支持超时控制"""

    def __init__(self):
        self._tools: Dict[str, dict] = {}
        # 工具级超时配置 (秒)
        self._timeouts = {
            "db_list": 10,          # 数据库查询 10s
            "db_create": 10,        # 数据库写入 10s
            "db_update": 10,
            "db_delete": 10,
            "file_read": 15,        # 文件读取 15s
            "file_write": 30,       # 文件写入 30s
            "web_search": 20,       # 网络搜索 20s
            "code_execute": 30,     # 代码执行 30s
            "rag_query": 15,        # RAG 检索 15s
            "default": 30,          # 默认 30s
        }

    async def execute(self, call: ToolCall, on_event: callable = None) -> ToolResult:
        """执行工具调用，带超时控制"""
        tool = self._tools.get(call.name)
        if not tool:
            return ToolResult(name=call.name, error=f"Unknown tool: {call.name}")

        timeout = self._timeouts.get(call.name, self._timeouts["default"])

        try:
            # 使用 asyncio.wait_for 实现超时
            result = await asyncio.wait_for(
                tool["func"](**call.arguments),
                timeout=timeout
            )
            return ToolResult(name=call.name, content=result)
        except asyncio.TimeoutError:
            logger.warning(f"工具 {call.name} 执行超时 ({timeout}s)")
            return ToolResult(
                name=call.name,
                error=f"工具执行超时 ({timeout}s)，请简化操作或分步执行"
            )
        except Exception as e:
            logger.error(f"工具 {call.name} 执行失败: {e}")
            return ToolResult(name=call.name, error=str(e))
```

### 分级超时策略

| 工具类型 | 超时 | 原因 |
|---------|------|------|
| 数据库读操作 | 10s | 索引查询应在毫秒级完成 |
| 数据库写操作 | 10s | 写入通常很快 |
| 文件读取 | 15s | 大文件可能需要更长时间 |
| 文件写入 | 30s | 含双写备份 |
| 网络搜索 | 20s | 外部 API 调用 |
| 代码执行 | 30s | 代码可能有计算量 |
| RAG 检索 | 15s | 向量检索 + 混合检索 |
| LLM 推理 | 120s | 长时间推理任务 |

### 反模式

**不要这样做** -- 工具无超时，无限等待：

```python
# 错误：工具执行无超时，可能永久阻塞 Agent 循环
async def execute(self, call: ToolCall):
    result = await tool["func"](**call.arguments)
    # 若 LLM 推理卡住，Agent 循环永远无法继续
    return ToolResult(name=call.name, content=result)
```

## 并行工具执行

### 并行执行策略

当 LLM 返回多个独立的工具调用时，可以并行执行以提高效率：

```python
async def _execute_tools_parallel(
    calls: List[ToolCall],
    registry: ToolRegistry,
    on_event: callable
) -> List[ToolResult]:
    """并行执行多个独立的工具调用"""

    # 分析依赖关系：db_read 和 file_read 可并行
    independent, dependent = _classify_tool_calls(calls)

    results = []

    # 第一阶段：并行执行独立调用
    if independent:
        tasks = [
            registry.execute(call, on_event)
            for call in independent
        ]
        for call in independent:
            yield {"type": "tool_execution_start", "tool": call.name, "parallel": True}

        parallel_results = await asyncio.gather(*tasks, return_exceptions=True)

        for call, result in zip(independent, parallel_results):
            if isinstance(result, Exception):
                result = ToolResult(name=call.name, error=str(result))
            results.append(result)
            yield {
                "type": "tool_execution_end",
                "tool": call.name,
                "result": result.content if result.error is None else None,
                "error": result.error
            }

    # 第二阶段：串行执行有依赖的调用
    for call in dependent:
        yield {"type": "tool_execution_start", "tool": call.name}
        result = await registry.execute(call, on_event)
        results.append(result)
        yield {
            "type": "tool_execution_end",
            "tool": call.name,
            "result": result.content if result.error is None else None,
            "error": result.error
        }

    return results

def _classify_tool_calls(calls: List[ToolCall]) -> tuple[List[ToolCall], List[ToolCall]]:
    """分类工具调用：独立调用 vs 有依赖调用"""
    independent = []
    dependent = []
    write_names = set()

    for call in calls:
        # 写操作不能并行（可能有数据依赖）
        if call.name in ("db_create", "db_update", "db_delete", "file_write"):
            dependent.append(call)
            write_names.add(call.name)
        else:
            independent.append(call)

    return independent, dependent
```

### 并行执行约束

| 约束 | 说明 |
|------|------|
| 只读操作可并行 | `db_list`, `file_read`, `web_search` 等 |
| 写操作串行执行 | 避免数据竞争和死锁 |
| 最大并行数 | 默认 5 个，防止资源耗尽 |
| 同集合操作串行 | 避免对同一集合的并发修改 |

### 反模式

**不要这样做** -- 所有工具调用强制串行：

```python
# 错误：3 个独立的 db_list 调用串行执行
for call in tool_calls:
    result = await registry.execute(call)
    # 3 次查询 = 3 * 平均延迟，而非 max(3 次延迟)
```

## 工具结果缓存

### 缓存策略

相同的工具调用在同一 Agent 会话内应缓存结果，避免重复查询：

```python
# domain/ai/tool_cache.py
import hashlib
import json
import time
from collections import OrderedDict

class ToolResultCache:
    """Agent 会话内工具结果缓存"""

    def __init__(self, max_size: int = 50, ttl: int = 60):
        self._cache = OrderedDict()
        self._max_size = max_size
        self._ttl = ttl  # 60 秒过期

    def _cache_key(self, call: ToolCall) -> str:
        """生成缓存键：tool_name + sorted args hash"""
        args_str = json.dumps(call.arguments, sort_keys=True, ensure_ascii=False)
        return f"{call.name}|{hashlib.md5(args_str.encode()).hexdigest()}"

    def get(self, call: ToolCall) -> Optional[ToolResult]:
        """获取缓存结果"""
        key = self._cache_key(call)
        entry = self._cache.get(key)
        if not entry:
            return None

        if time.time() - entry["cached_at"] > self._ttl:
            del self._cache[key]
            return None

        self._cache.move_to_end(key)
        return entry["result"]

    def set(self, call: ToolCall, result: ToolResult):
        """缓存结果"""
        key = self._cache_key(call)

        if len(self._cache) >= self._max_size:
            self._cache.popitem(last=False)

        self._cache[key] = {
            "result": result,
            "cached_at": time.time()
        }

    def invalidate(self, cname: str = None):
        """使缓存失效：写操作后清除相关缓存"""
        if cname:
            # 清除特定集合的缓存
            keys_to_remove = [
                k for k in self._cache
                if cname in k
            ]
            for k in keys_to_remove:
                del self._cache[k]
        else:
            self._cache.clear()
```

### 缓存使用

```python
# 在工具执行时使用缓存
async def execute(self, call: ToolCall, cache: ToolResultCache = None) -> ToolResult:
    """执行工具调用，优先使用缓存"""
    # 读操作可缓存，写操作不缓存
    if call.name in ("db_list", "db_get", "file_read", "rag_query"):
        if cache:
            cached = cache.get(call)
            if cached:
                logger.info(f"工具结果缓存命中: {call.name}")
                return cached

    result = await self._execute_internal(call)

    # 缓存读操作结果
    if call.name in ("db_list", "db_get", "file_read", "rag_query") and cache:
        cache.set(call, result)

    # 写操作后清除相关缓存
    if call.name in ("db_create", "db_update", "db_delete") and cache:
        cname = call.arguments.get("cname")
        cache.invalidate(cname)

    return result
```

## 上下文窗口优化

### Token 估算

```python
# domain/ai/context.py
def estimate_tokens(text: str) -> int:
    """估算文本的 Token 数量
    
    中文: ~1.5 字符/token
    英文: ~4 字符/token
    代码: ~3 字符/token
    """
    # 简易估算：按字符数 / 3
    return len(text) // 3

def estimate_messages_tokens(messages: list) -> int:
    """估算消息列表的总 Token 数"""
    total = 0
    for msg in messages:
        content = msg.get("content", "")
        if isinstance(content, str):
            total += estimate_tokens(content)
        elif isinstance(content, list):
            # 多模态消息
            for part in content:
                if isinstance(part, dict) and part.get("type") == "text":
                    total += estimate_tokens(part.get("text", ""))
    return total
```

### 上下文窗口管理

```python
class ContextManager:
    """上下文窗口管理"""

    def __init__(self, model_max_tokens: int = 8192, reserved_for_response: int = 2048):
        self.model_max_tokens = model_max_tokens
        self.reserved_for_response = reserved_for_response
        self.max_input_tokens = model_max_tokens - reserved_for_response

    def fit_messages(self, messages: list, system_prompt: str = "") -> list:
        """裁剪消息列表以适应上下文窗口"""
        system_tokens = estimate_tokens(system_prompt)
        available = self.max_input_tokens - system_tokens - 500  # 预留 500 for tool defs

        # 从最新消息开始保留
        fitted = []
        total_tokens = 0

        for msg in reversed(messages):
            msg_tokens = estimate_tokens(str(msg.get("content", "")))
            if total_tokens + msg_tokens > available:
                break
            fitted.insert(0, msg)
            total_tokens += msg_tokens

        if len(fitted) < len(messages):
            logger.warning(
                f"上下文窗口裁剪: {len(messages)} 条 -> {len(fitted)} 条 "
                f"({total_tokens}/{available} tokens)"
            )

        return fitted

    def should_compress(self, messages: list) -> bool:
        """检查是否需要压缩消息历史"""
        total = estimate_messages_tokens(messages)
        return total > self.max_input_tokens * 0.8  # 超过 80% 时压缩
```

### 优化策略

| 策略 | 说明 | 优先级 |
|------|------|--------|
| 结果裁剪 | 工具结果超过 6000 字符自动裁剪 | 高 |
| 历史压缩 | 旧消息压缩为摘要 | 高 |
| 消息裁剪 | 超出上下文时从旧到新裁剪 | 中 |
| 工具定义精简 | 只发送当前场景需要的工具 | 低 |
| 系统提示词优化 | 精简 system prompt | 中 |

### 反模式

**不要这样做** -- 忽略上下文窗口限制：


### 成本记录

```python
# domain/ai/cost_tracker.py
@dataclass
class CostRecord:
    model: str
    prompt_tokens: int
    completion_tokens: int
    tool_calls: int
    turns: int
    duration_ms: float
    estimated_cost_usd: float

class CostTracker:
    """LLM 调用成本追踪"""

    # 模型价格 (USD / 1M tokens)
    PRICING = {
        "qwen3:7b": {"prompt": 0.1, "completion": 0.1},
        "qwen3:14b": {"prompt": 0.2, "completion": 0.2},
        "qwen3:72b": {"prompt": 0.8, "completion": 0.8},
        "deepseek-r1:7b": {"prompt": 0.1, "completion": 0.1},
        "gpt-4o": {"prompt": 2.5, "completion": 10.0},
        "claude-sonnet-4-20250514": {"prompt": 3.0, "completion": 15.0},
    }

    def __init__(self):
        self._records: List[CostRecord] = []

    def record(self, model: str, prompt_tokens: int, completion_tokens: int,
               tool_calls: int, turns: int, duration_ms: float):
        """记录一次调用的成本"""
        pricing = self.PRICING.get(model, {"prompt": 0, "completion": 0})
        prompt_cost = (prompt_tokens / 1_000_000) * pricing["prompt"]
        completion_cost = (completion_tokens / 1_000_000) * pricing["completion"]

        record = CostRecord(
            model=model,
            prompt_tokens=prompt_tokens,
            completion_tokens=completion_tokens,
            tool_calls=tool_calls,
            turns=turns,
            duration_ms=duration_ms,
            estimated_cost_usd=prompt_cost + completion_cost
        )
        self._records.append(record)
        return record

    def get_session_summary(self) -> dict:
        """获取会话成本摘要"""
        if not self._records:
            return {"total_cost_usd": 0, "total_tokens": 0, "total_calls": 0}

        return {
            "total_cost_usd": sum(r.estimated_cost_usd for r in self._records),
            "total_prompt_tokens": sum(r.prompt_tokens for r in self._records),
            "total_completion_tokens": sum(r.completion_tokens for r in self._records),
            "total_tool_calls": sum(r.tool_calls for r in self._records),
            "total_turns": self._records[-1].turns,
            "total_duration_ms": sum(r.duration_ms for r in self._records),
            "records": [asdict(r) for r in self._records],
        }
```

### 流式返回工具结果

对于长时间运行的工具，通过 SSE 实时推送中间结果：

```python
async def execute_with_streaming(
    self, call: ToolCall, on_event: callable
) -> ToolResult:
    """执行工具，流式返回中间结果"""

    tool = self._tools.get(call.name)
    if not tool:
        return ToolResult(name=call.name, error=f"Unknown tool: {call.name}")

    # 支持流式的工具类型
    if call.name in ("code_execute", "web_search", "rag_query", "file_read"):
        return await self._execute_streaming(call, tool, on_event)
    else:
        return await self._execute_simple(call, tool)

async def _execute_streaming(self, call: ToolCall, tool: dict, on_event: callable) -> ToolResult:
    """流式执行工具"""
    chunks = []
    try:
        async for chunk in tool["func"](**call.arguments):
            chunks.append(chunk)
            # 推送中间结果
            if on_event:
                await on_event({
                    "type": "tool_stream",
                    "tool": call.name,
                    "chunk": chunk,
                })
    except Exception as e:
        return ToolResult(name=call.name, error=str(e))

    return ToolResult(name=call.name, content="".join(chunks))
```

## Constraints

### MUST

- 写操作必须经过确认门控
- 工具调用前必须校验参数类型和必填项
- 确认 ID 必须每轮唯一 (使用 `t{turn_index}:{call.id}` 格式)
- 拒绝记忆必须基于调用签名 (tool_name + sorted args)
- SSE 流必须设置 `text/event-stream` media_type
- 断连检测必须使用 ASGI receive channel 监听
- 工具执行必须有超时控制
- 并行工具执行需要区分读写操作

### MUST NOT

- 不要在确认门控中跳过写操作
- 不要在工具结果中泄露敏感信息
- 不要在 Agent 循环中阻塞主线程
- 不要绕过 ToolRegistry 执行工具
- 不要在续接时重复执行已完成的写入操作
- 不要缓存写操作结果
- 不要忽略上下文窗口限制
