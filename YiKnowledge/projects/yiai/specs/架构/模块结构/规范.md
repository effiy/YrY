# Spec: Module Structure

## Overview

本规范定义了 YiAi 项目的模块分层结构、各层职责边界、`__init__.py` 公共 API 导出规则和模块命名约定。

---

## 分层架构

### 四层模型

```
server/     (HTTP 层)      -- 路由、中间件、异常处理
services/   (服务层)       -- 业务编排、参数校验
domain/     (领域层)       -- 核心业务逻辑
data/       (数据层)       -- MongoDB 访问、仓库模式
shared/     (共享层)       -- 配置、响应、错误码、工具函数
```

### 依赖方向

```
server/ -> services/ -> domain/ -> data/ -> shared/
                     -> shared/
```

**单向依赖**：上层依赖下层，下层不依赖上层。`shared/` 是最底层，不依赖任何业务层。

---

## 各层职责详解

### server/ -- HTTP 层

**职责**：处理 HTTP 请求/响应、路由分发、中间件、异常处理

**目录结构**：
```
server/
├── middleware.py       # 认证中间件 (header_verification_middleware)
├── errors.py           # 全局异常处理器
├── mcp_server.py       # MCP 协议服务
└── routes/             # 20 个路由模块
    ├── about.py
    ├── agent.py
    ├── auth.py
    ├── files.py
    ├── execution.py
    # ... 等
```

**约束**：
- 路由函数只做参数提取和响应格式化，不写业务逻辑
- 通过 `services/` 层调用业务功能
- 不直接导入 `domain/` 或 `data/` 模块

### services/ -- 服务层

**职责**：封装 domain 逻辑，提供 routes 调用的统一接口，参数校验，业务编排

**目录结构**：
```
services/
├── ai/
│   └── chat_service.py      # ChatService
├── database/
│   ├── data_service.py      # DataService (通用 CRUD)
│   └── session_service.py   # SessionService
├── execution/
│   └── executor.py          # ExecutionService
├── knowledge/
│   └── knowledge_service.py # KnowledgeService
├── rag/
│   └── rag_service.py       # RagService
├── rss/
│   ├── feed_service.py      # FeedService
│   └── rss_scheduler.py     # RSS 调度器
└── storage/
    └── oss_client.py        # OSS 客户端
```

**约束**：
- 可以导入 `domain/`、`data/`、`shared/`
- 不导入 `server/`
- 每个 service 类封装一个领域的所有方法

### domain/ -- 领域层

**职责**：核心业务逻辑，与框架无关

**目录结构**：
```
domain/
├── ai/              # AI 聊天 + Agent 循环
│   ├── __init__.py
│   ├── chat.py      # 聊天服务
│   ├── agent.py     # Agent 循环 (Pi 风格)
│   ├── tools.py     # 工具注册 + 执行
│   └── data_tools.py # 通用数据工具
├── auth/            # 认证 (JWT + bcrypt)
├── execution/       # 通用模块执行
├── files/           # 文件操作
│   ├── __init__.py  # 公共 API: read_file, write_file, delete_file 等
│   ├── local.py     # 本地文件操作
│   ├── storage.py   # OSS 存储操作
│   └── paths.py     # 路径处理
├── knowledge/       # 知识库管理
│   ├── scanner.py   # 文件树扫描 + frontmatter 解析
│   ├── watcher.py   # apscheduler 轮询循环
│   └── writer.py    # Markdown 写回
├── rag/             # RAG 检索引擎
│   ├── engine.py    # rag_query, rag_chat_stream
│   ├── indexer.py   # get_kb_index, build_file_index
│   ├── settings.py  # RAG 设置
│   └── paths.py     # 路径工具
├── rss/             # RSS 聚合
├── search/          # 全局搜索
├── state/           # 状态记录 CRUD
└── wework/          # 企业微信消息
    ├── __init__.py  # 公共 API: send_message
    └── client.py
```

**约束**：
- 可以导入 `data/`、`shared/`
- 不导入 `server/`、`services/`
- 有公共 API 的模块必须通过 `__init__.py` 导出

### data/ -- 数据层

**职责**：MongoDB 访问、仓库模式、会话存储、状态存储

**目录结构**：
```
data/
├── database.py       # MongoDB 单例 (Motor async)
├── repository.py     # 通用数据仓库
├── sessions.py       # 会话数据操作
├── store.py          # 状态存储
└── seeds/            # 种子数据
    ├── menus.json
    ├── users.json
    ├── projects.json
    # ... 等
```

**约束**：
- 可以导入 `shared/`
- 不导入 `server/`、`services/`、`domain/`
- `MongoDB` 是线程安全的单例

### shared/ -- 共享层

**职责**：配置、响应封装、错误码、异常、日志、工具函数

**目录结构**：
```
shared/
├── config.py         # 配置 (YamlConfigSettingsSource)
├── response.py       # 响应封装 (StandardResponse)
├── error_codes.py    # 错误码枚举 (ErrorCode)
├── exceptions.py     # 业务异常 (BusinessException)
├── logging.py        # 日志配置
└── utils.py          # 通用工具函数
```

**约束**：
- 不依赖任何业务层模块
- 所有模块都可导入 `shared/`

## `__init__.py` 公共 API 导出

### 有 `__init__.py` 的 domain 模块

部分 domain 模块通过 `__init__.py` 定义公共 API 表面：

```python
# domain/files/__init__.py
from .local import read_file, write_file, delete_file
from .storage import upload_image

__all__ = [
    "read_file",
    "write_file",
    "delete_file",
    "rename_file",
    "delete_folder",
    "rename_folder",
    "upload_image",
]
```

```python
# domain/wework/__init__.py
from .client import send_message

__all__ = ["send_message"]
```

### 调用方使用公共 API

```python
# 正确：通过 __init__.py 导入
from domain.files import read_file, write_file

# 错误：直接导入内部模块
from domain.files.local import read_file  # 不要这样做
```

### 导出规则

| 规则 | 说明 |
|------|------|
| 有 `__init__.py` 的模块 | 调用方必须使用 `__init__.py` 的导出，不能直接导入内部文件 |
| 无 `__init__.py` 的模块 | 按需导入具体文件，如 `from domain.ai.agent import Agent` |
| `__all__` 列表 | 明确声明公共 API，作为模块的合同 |

## 模块命名约定

### 文件命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块文件 | snake_case | `chat_service.py`, `error_codes.py` |
| 路由文件 | snake_case | `agent.py`, `knowledge.py` |
| 测试文件 | test_前缀 + snake_case | `test_utils.py`, `test_error_codes.py` |
| 目录 | snake_case | `domain/ai/`, `services/database/` |

### 类命名

| 类型 | 规范 | 示例 |
|------|------|------|
| Service 类 | PascalCase + Service 后缀 | `ChatService`, `DataService` |
| 异常类 | PascalCase + Exception/Error 后缀 | `BusinessException` |
| 枚举类 | PascalCase | `ErrorCode` |
| 数据类 | PascalCase | `StandardResponse`, `ErrorInfo` |

### 函数命名

| 类型 | 规范 | 示例 |
|------|------|------|
| 公共函数 | snake_case | `read_file`, `query_documents` |
| 私有函数 | _前缀 + snake_case | `_build_filter`, `_resolve_service` |
| 异步函数 | async def | `async def get_item()` |

## 新增模块指南

### 新增 domain 模块

1. 在 `domain/` 下创建目录，如 `domain/notification/`
2. 创建 `__init__.py` 定义公共 API（如有多个内部文件）
3. 实现核心业务逻辑，只依赖 `data/` 和 `shared/`
4. 在 `services/` 下创建对应的 service 封装
5. 在 `server/routes/` 下创建路由模块（如需暴露 HTTP 端点）
6. 在 `app.py` 中注册路由

### 新增 service 模块

```python
# services/notification/notification_service.py
from domain.notification import send_notification
from shared.exceptions import BusinessException
from shared.error_codes import ErrorCode

class NotificationService:
    """通知服务"""

    async def send(self, user_id: str, message: str):
        """发送通知"""
        if not user_id:
            raise BusinessException(ErrorCode.INVALID_PARAMS, "user_id is required")
        return await send_notification(user_id, message)
```

### 新增路由模块

```python
# server/routes/notification.py
from fastapi import APIRouter, Request
from services.notification.notification_service import NotificationService
from shared.response import StandardResponse

router = APIRouter()
notification_service = NotificationService()

@router.post("/notification/send")
async def send_notification(request: Request, data: dict):
    """发送通知"""
    result = await notification_service.send(
        user_id=data.get("user_id"),
        message=data.get("message")
    )
    return StandardResponse.success(result)
```

## Constraints

### MUST

- 路由不直接调用 `data/` 层，必须通过 `services/`
- domain 模块不导入 `server/` 或 `services/`
- 有 `__init__.py` 的 domain 模块，调用方必须使用其公共 API
- 新模块遵循 snake_case 命名
- 私有函数使用 `_` 前缀
- 异步函数使用 `async/await`

### MUST NOT

- 不要在 `domain/` 中导入 `server/`
- 不要在 `data/` 中导入 `domain/` 或 `services/`
- 不要在 `shared/` 中导入任何业务层模块
- 不要绕过 `__init__.py` 直接导入 domain 内部文件
- 不要创建循环依赖
