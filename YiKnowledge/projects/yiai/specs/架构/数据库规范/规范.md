# Spec: Database Conventions

## Overview

本规范定义了 YiAi 的 MongoDB 数据访问约定，包括单例模式、Motor 异步驱动、Repository 仓库模式、`_build_filter` 查询构建、集合命名规范以及文件双写持久化策略。

## MongoDB 单例模式

### 设计模式

`MongoDB` 类使用线程安全的单例模式，全局只有一个数据库连接实例：

```python
# data/database.py
class MongoDB:
    _instance: Optional['MongoDB'] = None
    _lock: threading.Lock = threading.Lock()
    _client: Optional[AsyncIOMotorClient] = None
    _db = None
    _initialized: bool = False

    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:
                    cls._instance = super(MongoDB, cls).__new__(cls)
        return cls._instance
```

### 全局实例

```python
# 在 data/database.py 底部导出
db = MongoDB()  # 全局单例
```

### 初始化

```python
# 在 app.py 生命周期中初始化
from data.database import db

@asynccontextmanager
async def lifespan(app: FastAPI):
    # 启动时
    await db.initialize()
    yield
    # 关闭时
    await db.close()
```

### 单例方法

```python
class MongoDB:
    # 基础 CRUD
    async def find_one(self, collection: str, query: dict) -> Optional[dict]
    async def find_many(self, collection: str, query: dict, **kwargs) -> List[dict]
    async def insert_one(self, collection: str, document: dict) -> str
```


### _build_filter 查询构建

```python
def _build_filter(query_params: dict) -> dict:
    """
    将 HTTP 参数转为 Mongo 查询条件

    支持的操作符:
    - 精确匹配: key: value
    - 模糊匹配: key_like: value -> {"$regex": value, "$options": "i"}
    - 大于等于: key_gte: value -> {"$gte": value}
    - 小于等于: key_lte: value -> {"$lte": value}
    - 范围: key: [start, end] -> {"$gte": start, "$lte": end}
    - 列表: key: [v1, v2] -> {"$in": [v1, v2]}
    """
    filter_dict = {}
    for key, value in query_params.items():
        if value is None or value == "":
            continue
        # 处理 _like 后缀
        if key.endswith("_like"):
            real_key = key[:-5]
            filter_dict[real_key] = {"$regex": value, "$options": "i"}
        # 处理 _gte/_lte 后缀
        elif key.endswith("_gte"):
            real_key = key[:-4]
            filter_dict[real_key] = filter_dict.get(real_key, {})
            filter_dict[real_key]["$gte"] = value
        elif key.endswith("_lte"):
            real_key = key[:-4]
            filter_dict[real_key] = filter_dict.get(real_key, {})
            filter_dict[real_key]["$lte"] = value
        # 处理列表值
        elif isinstance(value, list):
            filter_dict[key] = {"$in": value}
        # 默认精确匹配
        else:
            filter_dict[key] = value
    return filter_dict
```

```python
_SEED_SPECS = [

async def _seed_collection_if_empty(cname: str, fname: str, lookup_field: str):

    count = await db.db[cname].count_documents({})
```

## 文件双写持久化

### 双写策略

```
POST /write-file {target_file, content}
   │
   ├── 1. 写入本地磁盘 (主存储)
   │     成功: 继续
   │     失败: 返回错误，终止
   │
   └── 2. best-effort upsert 到 MongoDB static_files 集合 (备份)
         成功: 静默
         失败: 记录日志，不抛出异常
```

### 双写实现模式

```python
# domain/files/local.py
async def write_file(target_file: str, content: str, is_base64: bool = False):
    """写入文件: 磁盘主存储 + MongoDB 备份"""

    # 1. 主存储: 写入磁盘 (失败则整体失败)
    file_path = _resolve_path(target_file)
    os.makedirs(os.path.dirname(file_path), exist_ok=True)

    if is_base64:
        content = base64.b64decode(content)

    with open(file_path, "w", encoding="utf-8") as f:
        f.write(content)

    # 2. 备份: best-effort upsert 到 MongoDB
    try:
        await db.update_one(
            "static_files",
            {"file_path": target_file},
            {"$set": {
                "file_path": target_file,
                "content": content,
                "updated_at": datetime.now(timezone.utc)
            }},
            upsert=True
        )
    except Exception as e:
        logger.warning(f"Failed to backup file to MongoDB: {e}")
        # 不抛出异常，磁盘已写入成功

    return {"file_path": target_file, "status": "ok"}
```

### 双写降级

| 场景 | 行为 |
|------|------|
| 磁盘写入成功 + MongoDB 可用 | 双写完整 |
| 磁盘写入成功 + MongoDB 不可用 | 仅磁盘写入（降级），日志记录 |
| 磁盘写入失败 | 整体失败，不尝试 MongoDB 备份 |

## MongoDB 聚合管道模式

### 聚合管道规范

Motor 的 `aggregate()` 方法返回 `AsyncIOMotorCommandCursor`，需要遍历消费：

```python
async def aggregate(self, collection: str, pipeline: List[dict]) -> List[dict]:
    """执行聚合管道，返回完整结果列表"""
    cursor = self.db[collection].aggregate(pipeline)
    results = []
    async for doc in cursor:
        results.append(doc)
    return results
```

### 常用聚合模式

#### 分组统计

```python
# 按状态统计 issue 数量
pipeline = [
    {"$match": {"project_id": "proj-001"}},
    {"$group": {
        "_id": "$status",
        "count": {"$sum": 1},
        "avg_priority": {"$avg": "$priority"}
    }},
    {"$sort": {"count": -1}}
]
results = await db.aggregate("issues", pipeline)
```

#### 关联查询 ($lookup)

```python
# 项目 + 负责人信息关联
pipeline = [
    {"$match": {"status": "active"}},
    {"$lookup": {
        "from": "users",
        "localField": "owner_key",
        "foreignField": "key",
        "as": "owner"
    }},
    {"$unwind": {"path": "$owner", "preserveNullAndEmptyArrays": True}},
    {"$project": {
        "name": 1, "status": 1,
        "owner_name": "$owner.name",
        "owner_avatar": "$owner.avatar"
    }}
]
results = await db.aggregate("projects", pipeline)
```

#### 多维度聚合 ($facet)

```python
# 同时获取多个维度的聚合结果
pipeline = [
    {"$facet": {
        "by_status": [
            {"$group": {"_id": "$status", "count": {"$sum": 1}}}
        ],
        "by_priority": [
            {"$group": {"_id": "$priority", "count": {"$sum": 1}}}
        ],
        "total": [
            {"$count": "count"}
        ]
    }}
]
results = await db.aggregate("issues", pipeline)
# -> {"by_status": [...], "by_priority": [...], "total": [{"count": 100}]}
```

#### 时间序列聚合

```python
# 按日期分组统计
from datetime import datetime, timedelta

pipeline = [
    {"$match": {
        "created_at": {"$gte": datetime.utcnow() - timedelta(days=30)}
    }},
    {"$group": {
        "_id": {
            "$dateToString": {"format": "%Y-%m-%d", "date": "$created_at"}
        },
        "count": {"$sum": 1}
    }},
    {"$sort": {"_id": 1}}
]
results = await db.aggregate("chat_records", pipeline)
```

#### 关键词搜索 ($text)

```python
# 需要先创建文本索引: db.issues.createIndex({title: "text", description: "text"})
pipeline = [
    {"$match": {"$text": {"$search": "登录失败"}}},
    {"$addFields": {"score": {"$meta": "textScore"}}},
    {"$sort": {"score": -1}},
    {"$limit": 20}
]
results = await db.aggregate("issues", pipeline)
```

### 聚合管道性能规则

| 规则 | 说明 |
|------|------|
| `$match` 前置 | 尽早过滤，减少后续处理的数据量 |
| `$project` 精简 | 只保留后续阶段需要的字段 |
| 避免 `$unwind` 大数组 | 大数组展开会成倍增加文档数 |
| 使用索引覆盖 | `$match` 和 `$sort` 阶段应使用索引 |
| 限制 `$lookup` | 关联查询代价高，考虑嵌入替代 |

### 反模式

**不要这样做** -- 在内存中做聚合，而非用 MongoDB 管道：

```python
# 错误：将所有数据加载到内存后做 Python 聚合
all_docs = await db.find_many("issues", {})
status_count = {}
for doc in all_docs:
    status_count[doc["status"]] = status_count.get(doc["status"], 0) + 1
# 100 万条文档 = 内存爆炸

# 正确：用 MongoDB 聚合管道
pipeline = [{"$group": {"_id": "$status", "count": {"$sum": 1}}}]
results = await db.aggregate("issues", pipeline)
```

**不要这样做** -- 嵌套 `$lookup` 替代数据嵌入：

```python
# 错误：过度关联查询
pipeline = [
    {"$lookup": {"from": "users", ...}},
    {"$lookup": {"from": "projects", ...}},
    {"$lookup": {"from": "labels", ...}},
    # 3 次关联查询，性能极差
]
# 考虑：在 domain 层做 3 次简单查询，或使用嵌入文档
```

## 索引策略

### 索引设计原则

```python
# 索引创建脚本 (放在 data/migrations/ 目录)
async def create_indexes():
    """启动时创建索引，使用 background=True 避免阻塞"""

    # 1. 高频查询字段：单字段索引
    await db.db["users"].create_index("key", unique=True, background=True)
    await db.db["sessions"].create_index("session_id", unique=True, background=True)

    # 2. 复合查询：复合索引（等值在前，排序在后）
    await db.db["issues"].create_index(
        [("project_id", 1), ("status", 1), ("created_at", -1)],
        background=True
    )

    # 3. 文本搜索：文本索引
    await db.db["issues"].create_index(
        [("title", "text"), ("description", "text")],
        background=True
    )

    # 4. 排序优化：覆盖查询字段的索引
    await db.db["chat_records"].create_index(
        [("session_id", 1), ("created_at", -1)],
        background=True
    )

    # 5. TTL 索引：自动过期
    await db.db["sessions"].create_index(
        "expires_at",
        expireAfterSeconds=0,
        background=True
    )
```

### 索引命名规范

```python
# 显式命名索引，便于管理和调试
await db.db["issues"].create_index(
    [("project_id", 1), ("status", 1), ("created_at", -1)],
    name="idx_project_status_created",
    background=True
)
```

### 索引使用检查

```python
async def _get_query_plan(cname: str, query: dict, sort: list = None):
    """检查查询执行计划，验证索引使用"""
    explain_cmd = {"find": cname, "filter": query}
    if sort:
        explain_cmd["sort"] = sort

    plan = await db.db.command("explain", explain_cmd, verbosity="executionStats")
    return plan["executionStats"]

# 使用
plan = await _get_query_plan("issues", {"project_id": "proj-001", "status": "open"})
# 检查 plan["stage"] 是否为 "IXSCAN" (索引扫描) 而非 "COLLSCAN" (全表扫描)
```

### 索引维护策略

| 操作 | 时机 | 命令 |
|------|------|------|
| 创建索引 | 应用启动时 | `create_index(background=True)` |
| 查看索引 | 按需 | `db.issues.list_indexes()` |
| 删除无用索引 | 定期审查 | `db.issues.drop_index("index_name")` |
| 重建索引 | 索引碎片化 | `db.issues.reIndex()` |
| 慢查询分析 | 持续监控 | `db.setProfilingLevel(1, {slowms: 100})` |

### 反模式

**不要这样做** -- 无索引全表扫描：

```python
# 错误：project_id 上没有索引，每次查询扫描全表
docs = await db.find_many("issues", {"project_id": "proj-001"})
# 100 万条文档 = 每次查询扫描 100 万次

# 正确：先创建索引
await db.db["issues"].create_index("project_id", background=True)
```

**不要这样做** -- 创建过多无用索引：

```python
# 错误：每个字段一个索引，写入性能急剧下降
for field in ["status", "priority", "type", "label", "assignee", "reporter"]:
    await db.db["issues"].create_index(field, background=True)
# 每次写入需要更新 6 个索引，写入延迟翻倍
```

## 查询优化

### 投影 (Projection)

```python
# 只返回需要的字段，减少网络传输和内存开销
# 排除敏感字段
user = await db.find_many(
    "users",
    {"role": "developer"},
    projection={"password": 0, "secret_key": 0}
)

# 只包含必要字段
issue_titles = await db.find_many(
    "issues",
    {"project_id": "proj-001"},
    projection={"title": 1, "status": 1, "_id": 0}
)
```

### 提示 (Hint)

```python
# 当查询优化器选择错误索引时，强制使用指定索引
docs = await db.db["issues"].find(
    {"project_id": "proj-001", "status": "open"}
).hint("idx_project_status_created").to_list(length=100)
```

### 查询优化检查清单

| 检查项 | 操作 |
|--------|------|
| 是否使用索引 | 检查 `explain()` 输出中 `stage` 字段 |
| 是否返回过多字段 | 使用 `projection` 限制返回字段 |
| 是否跳过太多文档 | 大 `skip` 改用游标分页 |
| 是否使用 `$regex` 前缀匹配 | 用 `^keyword` 而非 `keyword`，前者可用索引 |
| 是否在结果集上排序 | 排序字段应包含在查询索引中 |
| 是否使用 `countDocuments` | 优于 `estimatedDocumentCount`（精确度要求时） |

### 反模式

**不要这样做** -- 不限制返回字段：

```python
# 错误：返回整个文档（含 Markdown 正文等大字段）
docs = await db.find_many("knowledge_files", {"status": "published"})
# 每个文档 50KB+，100 条 = 5MB 传输

# 正确：只返回需要的字段
docs = await db.find_many(
    "knowledge_files",
    {"status": "published"},
    projection={"title": 1, "tags": 1, "category": 1, "updated": 1}
)
```

## 事务模式

### 何时使用事务

MongoDB 事务适用于需要原子性保证的多文档操作。YiAi 中大多数操作为单文档 CRUD（已天然原子），仅在以下场景需要事务：

| 场景 | 操作 | 原因 |
|------|------|------|
| 用户注册 | 创建 user + 初始化 profile + 创建默认设置 | 3 个集合必须同时成功 |
| 项目归档 | 更新 project 状态 + 归档所有关联 issues | 级联操作需要一致性 |
| 知识库重建 | 删除旧索引 + 写入新索引 + 更新元数据 | 重建过程不可部分完成 |

### 事务实现

```python
async def transactional_operation():
    """事务操作示例"""
    async with await db.client.start_session() as session:
        async with session.start_transaction():
            try:
                # 操作 1: 创建用户
                await db.db["users"].insert_one(
                    {"key": "new_user", "name": "新用户"},
                    session=session
                )

                # 操作 2: 创建关联 profile
                await db.db["profiles"].insert_one(
                    {"user_key": "new_user", "settings": {}},
                    session=session
                )

                # 操作 3: 创建默认设置
                await db.db["user_settings"].insert_one(
                    {"user_key": "new_user", "theme": "light"},
                    session=session
                )

                # 全部成功，事务自动提交
            except Exception as e:
                # 任何失败，事务自动回滚
                logger.error(f"事务失败，已回滚: {e}")
                raise BusinessException(ErrorCode.DATA_STORE_FAIL, "操作失败，已回滚")
```

### 事务约束

| 约束 | 说明 |
|------|------|
| 副本集要求 | 需要 MongoDB 副本集（非 standalone） |
| 超时限制 | 默认 60s，超时自动回滚 |
| 不适用场景 | 单文档操作不需要事务（MongoDB 单文档操作天然原子） |
| 性能影响 | 事务持有锁，避免在事务中执行耗时操作 |

### 反模式

**不要这样做** -- 在不需要事务的场景使用事务：

```python
# 错误：单文档更新不需要事务
async with session.start_transaction():
    await db.db["users"].update_one(
        {"key": "admin"},
        {"$set": {"name": "新名称"}},
        session=session
    )
# 单文档更新天然原子，事务只是增加开销

# 正确：直接更新
await db.update_one("users", {"key": "admin"}, {"$set": {"name": "新名称"}})
```

## 数据迁移脚本模式

### 迁移脚本结构

```python
# data/migrations/001_add_user_avatar_field.py
"""
迁移: 为 users 集合添加 avatar 默认字段
日期: 2026-09-02
作者: claude
状态: 已执行
"""

import logging
from data.database import db

logger = logging.getLogger(__name__)

MIGRATION_ID = "001"
DESCRIPTION = "为 users 集合添加 avatar 默认字段"

async def up():
    """执行迁移"""
    logger.info(f"开始迁移 {MIGRATION_ID}: {DESCRIPTION}")

    result = await db.db["users"].update_many(
        {"avatar": {"$exists": False}},
        {"$set": {"avatar": "default_avatar.png"}}
    )

    logger.info(f"迁移 {MIGRATION_ID} 完成: 更新 {result.modified_count} 条文档")
    return result.modified_count

async def down():
    """回滚迁移"""
    logger.info(f"回滚迁移 {MIGRATION_ID}")

    result = await db.db["users"].update_many(
        {"avatar": "default_avatar.png"},
        {"$unset": {"avatar": ""}}
    )

    logger.info(f"回滚 {MIGRATION_ID} 完成: 更新 {result.modified_count} 条文档")
    return result.modified_count

async def verify():
    """验证迁移结果"""
    count = await db.db["users"].count_documents({"avatar": {"$exists": False}})
    assert count == 0, f"仍有 {count} 条文档缺少 avatar 字段"
    return True
```

### 迁移执行器

```python
# data/migrations/runner.py
import importlib
import logging

logger = logging.getLogger(__name__)

MIGRATION_LIST = [
    "data.migrations.001_add_user_avatar_field",
    "data.migrations.002_create_chat_indexes",
    "data.migrations.003_normalize_status_values",
]

async def run_migrations():
    """按顺序执行所有未执行的迁移"""
    # 检查 migration 状态集合
    executed = set()
    async for doc in db.db["migrations"].find({}):
        executed.add(doc["migration_id"])

    for migration_path in MIGRATION_LIST:
        migration_id = migration_path.split(".")[-1].split("_")[0]

        if migration_id in executed:
            logger.info(f"迁移 {migration_id} 已执行，跳过")
            continue

        module = importlib.import_module(migration_path)

        try:
            await module.up()
            await module.verify()
            # 记录迁移状态
            await db.db["migrations"].insert_one({
                "migration_id": migration_id,
                "description": module.DESCRIPTION,
                "executed_at": datetime.now(timezone.utc),
                "status": "success"
            })
        except Exception as e:
            logger.error(f"迁移 {migration_id} 失败: {e}")
            await db.db["migrations"].insert_one({
                "migration_id": migration_id,
                "description": module.DESCRIPTION,
                "executed_at": datetime.now(timezone.utc),
                "status": "failed",
                "error": str(e)
            })
            raise
```

### 迁移规范

| 规则 | 说明 |
|------|------|
| 幂等性 | `up()` 和 `down()` 必须可重复执行 |
| 验证 | 每次迁移后调用 `verify()` 检查结果 |
| 回滚 | 提供 `down()` 回滚逻辑 |
| 记录 | 迁移记录存储在 `migrations` 集合 |
| 顺序 | 迁移按编号顺序执行，不可跳过 |
| 文档 | 每个迁移文件头部包含迁移说明 |

### 反模式

**不要这样做** -- 手动执行 MongoDB 命令修改 schema：

```python
# 错误：直接连 MongoDB 执行命令，无记录无回滚
# $ mongo
# > db.users.updateMany({}, {$set: {avatar: "default.png"}})
# 无法追踪谁在何时做了什么修改
```

```python
# 使用 find_one_and_update 保证原子性
async def atomic_increment(cname: str, key: str, field: str, amount: int = 1):
    """原子递增，避免并发写入冲突"""
    result = await db.db[cname].find_one_and_update(
        {"key": key},
        {"$inc": {field: amount}},
        return_document=True
    )
    return result
```

### 大文档处理

```python
# 超过 16MB 的文档无法存储
MAX_DOC_SIZE = 16 * 1024 * 1024  # 16MB

def check_doc_size(document: dict) -> bool:
    """检查文档大小是否超过 MongoDB 限制"""
    size = len(json.dumps(document, ensure_ascii=False, default=str).encode("utf-8"))
    if size > MAX_DOC_SIZE:
        raise BusinessException(
            ErrorCode.INVALID_PARAMS,
            f"文档大小 {size / 1024 / 1024:.1f}MB 超过 MongoDB 16MB 限制"
        )
    return True
```

## Constraints

### MUST

- 所有 MongoDB 操作通过 `db` 单例进行
- 使用 `repository.query_documents()` 进行分页查询
- 分页查询参数使用 `filter`（不是 `query`）
- 集合参数使用 `cname`（不是 `collection_name`）
- 种子数据只在集合为空时导入
- 文件写入使用双写模式（磁盘 + MongoDB 备份）
- MongoDB 备份写入失败时记录日志但不阻塞主流程

### MUST NOT

- 不要直接创建新的 `AsyncIOMotorClient` 实例
- 不要在路由中直接操作 MongoDB
- 不要在 `_build_filter` 外手动构建 Mongo 查询条件
- 不要使用 `query` 作为 `filter` 的替代参数名
- 不要在种子数据导入时删除已有数据
