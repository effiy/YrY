# Spec: API Conventions

## Overview

本规范定义了 YiAi 后端的 API 协议、路由组织、SSE 流式响应和错误处理约定。YiAi 使用两种 API 模式：RPC 信封（通用 CRUD + 服务调用）和 RESTful 端点（文件、认证、Agent 等）。

---

## RPC 信封协议

### 协议定义

所有 YiVad/YiPet 的通用服务调用使用统一 RPC 信封：

**请求格式：**

```json
POST / {
  "module_name": "services.database.data_service",
  "method_name": "query_documents",
  "parameters": {
    "cname": "projects",
    "filter": { "status": "active" },
    "pageNum": 1,
    "pageSize": 20
  }
}
```

**响应格式：**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [...],
    "total": 100,
    "pageNum": 1,
    "pageSize": 20,
    "totalPages": 5
  }
}
```

### RPC 分发器

根路由 `/` 作为 RPC 分发器，解析 `module_name` 和 `method_name` 定位到对应的 service 方法：

```python
# 分发逻辑
POST /  body: { module_name, method_name, parameters }
  -> _resolve_service(module_name)
  -> getattr(service, method_name)(**parameters)
  -> StandardResponse(code=0, message="ok", data=result)
```

### RPC 方法清单

#### data_service (通用 CRUD)

| method_name | 说明 | 关键参数 |
|-------------|------|---------|
| `query_documents` | 分页查询文档 | `cname`, `filter`, `pageNum`, `pageSize`, `orderBy`, `orderType`, `fields`, `excludeFields` |
| `create_document` | 创建文档 | `cname`, `data` |
| `update_document` | 更新文档 | `cname`, `key`, `data` |
| `delete_document` | 删除文档 | `cname`, `key` |
| `get_document` | 获取单个文档 | `cname`, `key` |

#### chat_service (AI 聊天)

| method_name | 说明 |
|-------------|------|
| `chat` | AI 聊天 (SSE 流式) |
| `chat_rag` | RAG 增强聊天 |
| `get_models` | 获取可用模型列表 |

#### session_service (会话管理)

| method_name | 说明 |
|-------------|------|
| `create_session` | 创建会话 |
| `get_session` | 获取会话 |
| `list_sessions` | 会话列表 |
| `update_session` | 更新会话 |
| `delete_session` | 删除会话 |

#### knowledge_service (知识库)

| method_name | 说明 |
|-------------|------|
| `scan_knowledge` | 扫描知识库 |
| `read_file` | 读取知识文件 |
| `write_file` | 写入知识文件 |
| `list_files` | 文件列表 |

#### rag_service (RAG 检索)

| method_name | 说明 |
|-------------|------|
| `query` | RAG 检索 |
| `chat` | RAG 聊天 |
| `build_index` | 构建索引 |
| `decompose_question` | 子问题分解 |

### 关键参数名约定

| 正确 | 错误 | 上下文 |
|------|------|--------|
| `filter` | `query` | `data_service.query_documents` |
| `target_file` | `path` | `/read-file`, `/write-file` |
| `cname` | `collection_name` | `data_service` 集合参数 |

**注意**：这些参数名不匹配曾导致真实 Bug -- 后端静默忽略 `query`，对 `path` 返回 422。

## SSE 事件流模式

### 流式事件协议

YiAi 的 SSE 事件遵循标准 SSE 协议，每行以 `data: ` 前缀，以 `\n\n` 结束：

```python
# 标准 SSE 事件格式
data: {"type":"event_name","payload":{...}}\n\n
```

### 事件命名规范

| 类型 | 命名模式 | 示例 |
|------|---------|------|
| 生命周期 | `<noun>_<verb>` | `turn_start`, `turn_end`, `agent_end` |
| 工具调用 | `tool_<action>` | `tool_call`, `tool_execution_start`, `tool_execution_end` |
| 用户交互 | `<noun>_<state>` | `confirmation_required`, `connection_lost` |
| 系统事件 | 简明描述 | `error`, `model_switch`, `heartbeat` |

### 流式错误处理

SSE 流中的错误不应中断流，而是通过 `error` 事件传递：

```python
async def event_generator():
    try:
        async for event in agent.run(request):
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
    except BusinessException as e:
        yield f"data: {json.dumps({'type': 'error', 'code': e.error_code.business, 'message': e.detail})}\n\n"
    except asyncio.CancelledError:
        yield f"data: {json.dumps({'type': 'error', 'code': 499, 'message': '客户端断开连接'})}\n\n"
    except Exception as e:
        logger.error(f"SSE 流异常: {e}", exc_info=True)
        yield f"data: {json.dumps({'type': 'error', 'code': 5000, 'message': '服务器内部错误'})}\n\n"
    finally:
        yield f"data: {json.dumps({'type': 'stream_end', 'done': True})}\n\n"
```

### 心跳保持

长时间无事件的 SSE 流应发送心跳保持连接活跃：

```python
async def _heartbeat_generator(interval: int = 15):
    """每 15s 发送心跳，防止代理超时"""
    while True:
        await asyncio.sleep(interval)
        yield f": heartbeat\n\n"  # SSE 注释格式，客户端忽略

async def event_generator():
    heartbeat_task = asyncio.create_task(_heartbeat_consumer())
    try:
        async for event in agent.run(request):
            yield f"data: {json.dumps(event, ensure_ascii=False)}\n\n"
    finally:
        heartbeat_task.cancel()
```

### 流式响应头配置

```python
return StreamingResponse(
    event_generator(),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "Connection": "keep-alive",
        "X-Accel-Buffering": "no",      # 禁用 Nginx 缓冲
        "Content-Encoding": "none",      # 禁用压缩（实时性优先）
        "Access-Control-Allow-Origin": "*",
    }
)
```

### 反模式

**不要这样做** -- 在 SSE 流中直接返回非流式响应：

```python
# 错误：在 StreamingResponse 中返回单个 JSON
async def bad_stream():
    result = await some_service.do_work()
    yield f"data: {json.dumps(result)}\n\n"
    # 缺少事件类型，前端无法区分事件类型

# 错误：用普通 JSON 响应替代 SSE 流
@router.post("/agent/chat")
async def chat(request: Request, data: dict):
    result = await agent.run_sync(data)  # 阻塞等待全部完成
    return StandardResponse.success(result)  # 用户等待超时
```

**不要这样做** -- 在 SSE 流中抛出未捕获异常导致连接断开：

```python
# 错误：异常会中断整个流，客户端收到不完整的响应
async def bad_stream():
    async for event in agent.run(request):
        yield f"data: {json.dumps(event)}\n\n"
    # 若 agent.run() 抛出异常，流直接中断，客户端收到空响应
```

## 请求超时模式

### 超时配置分层

```python
# 不同端点配置不同超时策略
TIMEOUT_CONFIG = {
    # 快速端点：3s 超时
    "health": 3.0,
    "auth/login": 5.0,
    "data/query": 10.0,

    # 慢端点：30s 超时
    "file/upload": 30.0,
    "rag/build_index": 60.0,
    "knowledge/scan": 30.0,

    # SSE 流：无超时（由客户端控制）
    "agent/chat": None,
    "ai/chat": None,
}

def get_timeout(route: str) -> Optional[float]:
    return TIMEOUT_CONFIG.get(route, 10.0)  # 默认 10s
```

### 超时中间件

```python
# server/middleware.py
from fastapi import Request
import asyncio

async def timeout_middleware(request: Request, call_next):
    """全局超时中间件"""
    route = request.url.path.lstrip("/")
    timeout = get_timeout(route)

    if timeout is None:
        # SSE 流，不设超时
        return await call_next(request)

    try:
        return await asyncio.wait_for(call_next(request), timeout=timeout)
    except asyncio.TimeoutError:
        return StandardResponse.fail(
            ErrorCode.SERVER_ERROR,
            f"请求超时 ({timeout}s)，请重试"
        )
```

### 反模式

**不要这样做** -- 全端点统一超时：

```python
# 错误：快速端点和慢端点使用相同超时
@app.middleware("http")
async def timeout_middleware(request, call_next):
    return await asyncio.wait_for(call_next(request), timeout=30)
    # 健康检查等待 30s 无意义，文件上传 30s 可能不够
```

## 重试与指数退避

### 重试策略

```python
import asyncio
from tenacity import (
    retry, stop_after_attempt, wait_exponential,
    retry_if_exception_type
)

# 网络层重试：MongoDB / Ollama 连接瞬态故障
@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=1, max=10),
    retry=retry_if_exception_type((ConnectionError, TimeoutError)),
)
async def call_ollama_with_retry(prompt: str, model: str):
    """Ollama 调用带指数退避重试"""
    async with httpx.AsyncClient(timeout=60.0) as client:
        response = await client.post(
            f"{settings.ollama_base_url}/api/generate",
            json={"model": model, "prompt": prompt, "stream": False}
        )
        return response.json()

# 业务层重试：LLM 调用
async def _stream_llm_response(messages, config, tools):
    """LLM 调用带指数退避重试"""
    for attempt in range(config.llm_max_retries + 1):
        try:
            async for chunk in runtime.stream_chat(messages, tools=tools):
                yield chunk
            return
        except Exception as e:
            if attempt < config.llm_max_retries:
                wait = min(2 ** attempt, 30)  # 1s, 2s, 4s, 8s, ... 上限 30s
                logger.warning(f"LLM 重试 {attempt + 1}/{config.llm_max_retries}，等待 {wait}s: {e}")
                await asyncio.sleep(wait)
            else:
                raise
```

### 重试决策表

| 错误类型 | 是否重试 | 退避策略 | 最大次数 |
|---------|---------|---------|---------|
| 连接超时 (ConnectionError) | 是 | 指数退避 1s-10s | 3 |
| 服务不可用 (503) | 是 | 指数退避 1s-30s | 3 |
| 速率限制 (429) | 是 | 使用 Retry-After 头 | 1 |
| 参数错误 (400) | 否 | -- | 0 |
| 认证失败 (401) | 否 | -- | 0 |
| 数据不存在 (404) | 否 | -- | 0 |
| 服务器错误 (500) | 是 | 指数退避 1s-10s | 2 |

### 反模式

**不要这样做** -- 对所有错误无差别重试：

```python
# 错误：400 重试毫无意义，只会浪费资源
@retry(stop=stop_after_attempt(3))
async def bad_retry():
    response = await client.post(url, json=data)
    response.raise_for_status()  # 400 也会重试
```

## 速率限制

### 速率限制头

```python
# 响应头
X-RateLimit-Limit: 100        # 窗口内最大请求数
X-RateLimit-Remaining: 85     # 窗口内剩余请求数
X-RateLimit-Reset: 1697424000 # 窗口重置时间 (Unix timestamp)
Retry-After: 60               # 限流后建议重试等待秒数
```

### 基于令牌桶的速率限制

```python
import time
from collections import defaultdict

class RateLimiter:
    """令牌桶速率限制器"""

    def __init__(self, rate: int = 100, window: int = 60):
        self.rate = rate          # 窗口内最大请求数
        self.window = window      # 时间窗口 (秒)
        self._buckets: dict = defaultdict(lambda: {"tokens": rate, "reset_at": 0})

    async def check(self, key: str) -> bool:
        """检查是否允许请求，返回 (allowed, headers)"""
        now = time.time()
        bucket = self._buckets[key]

        # 新窗口：重置令牌
        if now >= bucket["reset_at"]:
            bucket["tokens"] = self.rate
            bucket["reset_at"] = now + self.window

        if bucket["tokens"] > 0:
            bucket["tokens"] -= 1
            return True

        return False

    def get_headers(self, key: str) -> dict:
        """获取速率限制响应头"""
        bucket = self._buckets[key]
        remaining = max(0, bucket["tokens"])
        reset_at = int(bucket["reset_at"])

        headers = {
            "X-RateLimit-Limit": str(self.rate),
            "X-RateLimit-Remaining": str(remaining),
            "X-RateLimit-Reset": str(reset_at),
        }

        if remaining == 0:
            headers["Retry-After"] = str(int(reset_at - time.time()))

        return headers

# 使用
rate_limiter = RateLimiter(rate=100, window=60)

@router.get("/example/items")
async def list_items(request: Request):
    client_ip = request.client.host
    if not await rate_limiter.check(client_ip):
        headers = rate_limiter.get_headers(client_ip)
        return JSONResponse(
            status_code=429,
            content={"code": 1003, "message": "请求过于频繁，请稍后重试", "data": None},
            headers=headers
        )
    # ... 正常处理
```

### 反模式

**不要这样做** -- 在内存中存储限流状态（重启丢失，多进程不同步）：

```python
# 错误：单进程内存存储，重启丢失，多 worker 间不同步
rate_cache = {}  # 仅适用于单进程开发环境
```

## 分页：游标 vs 偏移

### 偏移分页（当前默认）

适用于数据量稳定、总页数可预知的场景：

```python
# 请求
{
    "pageNum": 1,
    "pageSize": 20
}

# 响应
{
    "list": [...],
    "total": 100,
    "pageNum": 1,
    "pageSize": 20,
    "totalPages": 5
}
```

### 游标分页（推荐大数据量场景）

适用于实时数据流、无限滚动场景：

```python
# 请求
{
    "cursor": "eyJfaWQiOiI2N2U5...",  # 上一页最后一条的 _id (base64)
    "pageSize": 20
}

# 响应
{
    "list": [...],
    "nextCursor": "eyJfaWQiOiI2N2Vh...",  # 下一页游标
    "hasMore": true
}

# 实现
async def cursor_paginate(cname: str, cursor: str = None, pageSize: int = 20):
    query = {}
    if cursor:
        try:
            last_id = base64.b64decode(cursor).decode()
            query["_id"] = {"$gt": ObjectId(last_id)}
        except Exception:
            raise BusinessException(ErrorCode.INVALID_PARAMS, "无效的游标参数")

    docs = await db.find_many(cname, query, limit=pageSize + 1)
    has_more = len(docs) > pageSize
    if has_more:
        docs = docs[:pageSize]

    next_cursor = None
    if has_more and docs:
        next_cursor = base64.b64encode(str(docs[-1]["_id"]).encode()).decode()

    return {"list": docs, "nextCursor": next_cursor, "hasMore": has_more}
```

### 分页模式选择

| 场景 | 推荐模式 | 原因 |
|------|---------|------|
| 管理后台表格 | 偏移分页 | 需要总页数、页码跳转 |
| 实时 Feed 流 | 游标分页 | 数据持续增长，偏移不可靠 |
| 搜索列表 | 偏移分页 | 需要总数 |
| 无限滚动 | 游标分页 | 性能最优，无重复/遗漏 |
| 导出全量 | 不适用分页 | 异步任务 + 文件下载 |

### 反模式

**不要这样做** -- 大数据量下使用大偏移分页：

```python
# 错误：skip(100000) 在 MongoDB 中性能极差
docs = await db.find_many("issues", {}, skip=100000, limit=20)
# 应使用游标分页或基于索引的范围查询
```

## 批量操作模式

### 批量创建

```python
# services/database/data_service.py
class DataService:
    async def batch_create(self, cname: str, documents: list, chunk_size: int = 100) -> dict:
        """批量创建文档，自动分批处理
        
        Returns:
            {"total": 250, "succeeded": 248, "failed": 2, "details": [...]}
        """
        if not documents:
            raise BusinessException(ErrorCode.INVALID_PARAMS, "documents 不能为空")

        total = len(documents)
        succeeded = 0
        failed = 0
        details = []

        for i in range(0, total, chunk_size):
            chunk = documents[i:i + chunk_size]
            try:
                ids = await db.insert_many(cname, chunk)
                succeeded += len(ids)
                details.append({"chunk": i // chunk_size, "status": "ok", "count": len(ids)})
            except Exception as e:
                failed += len(chunk)
                details.append({"chunk": i // chunk_size, "status": "error", "error": str(e)})
                logger.error(f"批量创建分片 {i // chunk_size} 失败: {e}")

        return {"total": total, "succeeded": succeeded, "failed": failed, "details": details}
```

### 批量更新

```python
async def batch_update(self, cname: str, updates: list, chunk_size: int = 100) -> dict:
    """批量更新文档，使用 bulk_write 提升性能
    
    updates: [{"key": "id1", "data": {"status": "done"}}, ...]
    """
    if not updates:
        raise BusinessException(ErrorCode.INVALID_PARAMS, "updates 不能为空")

    operations = []
    for item in updates:
        operations.append(
            UpdateOne(
                {"key": item["key"]},
                {"$set": item["data"]}
            )
        )

    result = await db.db[cname].bulk_write(operations, ordered=False)
    return {
        "matched": result.matched_count,
        "modified": result.modified_count,
        "upserted": len(result.upserted_ids)
    }
```

### 批量删除

```python
async def batch_delete(self, cname: str, keys: list) -> dict:
    """批量删除文档"""
    if not keys:
        raise BusinessException(ErrorCode.INVALID_PARAMS, "keys 不能为空")

    result = await db.db[cname].delete_many({"key": {"$in": keys}})
    return {"deleted": result.deleted_count}
```

### 反模式

**不要这样做** -- 逐条循环操作大量数据：

```python
# 错误：1000 条数据 = 1000 次网络往返
for item in documents:
    await db.insert_one("items", item)

# 正确：使用 insert_many 或 bulk_write
await db.insert_many("items", documents)
```

## 文件上传/下载流式传输

### 流式上传（大文件）

```python
from fastapi import UploadFile, File
from pathlib import Path

@router.post("/files/upload/stream")
async def upload_file_stream(request: Request, file: UploadFile = File(...)):
    """流式上传大文件，分块写入磁盘"""
    file_path = Path(settings.upload_dir) / file.filename

    # 使用流式读取，不将整个文件加载到内存
    chunk_size = 1024 * 1024  # 1MB 分块
    total_size = 0
    max_size = 100 * 1024 * 1024  # 100MB 上限

    file_path.parent.mkdir(parents=True, exist_ok=True)

    with open(file_path, "wb") as f:
        while chunk := await file.read(chunk_size):
            total_size += len(chunk)
            if total_size > max_size:
                file_path.unlink(missing_ok=True)
                raise BusinessException(ErrorCode.INVALID_PARAMS, "文件大小超过 100MB 限制")
            f.write(chunk)

    return StandardResponse.success({
        "filename": file.filename,
        "size": total_size,
        "path": str(file_path),
    })
```

### 流式下载（大文件）

```python
from fastapi.responses import StreamingResponse

@router.get("/files/download/{filename}")
async def download_file(filename: str):
    """流式下载大文件"""
    file_path = Path(settings.upload_dir) / filename

    if not file_path.exists():
        raise BusinessException(ErrorCode.DATA_NOT_FOUND, "文件不存在")

    def file_iterator():
        chunk_size = 1024 * 1024  # 1MB
        with open(file_path, "rb") as f:
            while chunk := f.read(chunk_size):
                yield chunk

    return StreamingResponse(
        file_iterator(),
        media_type="application/octet-stream",
        headers={
            "Content-Disposition": f"attachment; filename=\"{filename}\"",
            "Content-Length": str(file_path.stat().st_size),
        }
    )
```

### 反模式

**不要这样做** -- 将整个文件读入内存：

```python
# 错误：500MB 文件会耗尽服务器内存
with open(file_path, "rb") as f:
    content = f.read()  # 整个文件读入内存
return Response(content=content)
```

## 边界情况

### 空请求体处理

```python
@router.post("/example/items")
async def create_item(request: Request, data: dict = None):
    """处理空请求体"""
    if data is None:
        raise BusinessException(ErrorCode.INVALID_REQUEST, "请求体不能为空")
    # ...
```

### 空列表/空结果处理

```python
# 正确：空列表返回空，不是 null
result = await repository.query_documents(cname="projects", filter=filter)
# -> {"list": [], "total": 0, "pageNum": 1, "pageSize": 20, "totalPages": 0}

# 错误：不要返回 null
# -> {"list": null, "total": 0}  # 前端解构崩溃
```

### Unicode / 特殊字符处理

```python
# 正确：使用 ensure_ascii=False 保留中文

def sanitize_input(data: dict) -> dict:
    """清理输入数据中的控制字符"""

        if isinstance(value, str):
```

### 路由设计约束

## SSE 流式响应

### Agent 聊天 SSE 事件类型

```
POST /agent/chat
Response: text/event-stream

data: {"type":"turn_start","turn":1}

data: {"type":"tool_call","tool":"db_list","args":{...}}

data: {"type":"confirmation_required","tool":"db_create","confirmation_id":"t1:tool_0"}

data: {"type":"tool_execution_start","tool":"db_create"}

data: {"type":"tool_execution_end","tool":"db_create","result":{...}}

data: {"type":"turn_end","summary":"..."}

data: {"type":"agent_end","stop_reason":"completed","turns":3}
```

### SSE 事件类型说明

| 事件类型 | 说明 | 关键字段 |
|---------|------|---------|
| `turn_start` | 新一轮开始 | `turn` |
| `tool_call` | 模型发起工具调用 | `tool`, `args` |
| `confirmation_required` | 写操作需要用户确认 | `tool`, `confirmation_id` |
| `tool_execution_start` | 工具开始执行 | `tool` |
| `tool_execution_end` | 工具执行完毕 | `tool`, `result`, `error` |
| `turn_end` | 本轮结束 | `summary` |
| `agent_end` | Agent 循环结束 | `stop_reason`, `turns` |
| `model_switch` | 模型自动切换 | `from`, `to` |
| `error` | 错误事件 | `error` |

## 响应格式

### StandardResponse

```python
# shared/response.py
class StandardResponse:
    @staticmethod
    def success(data: Any = None) -> dict:
        return {"code": 0, "message": "ok", "data": data}

    @staticmethod
    def fail(error_code: ErrorCode, detail: str = None) -> dict:
        return {
            "code": error_code.business,
            "message": detail or error_code.message,
            "data": None
        }
```

## Constraints

### MUST

- 所有 RPC 调用必须使用 `{module_name, method_name, parameters}` 信封
- 参数名必须使用 `filter`（不是 `query`）、`target_file`（不是 `path`）、`cname`（不是 `collection_name`）
- 路由文件必须放在 `server/routes/` 目录
- 路由函数必须使用 `StandardResponse` 返回
- 业务异常必须使用 `BusinessException` 抛出
- SSE 流式响应必须设置 `text/event-stream` media_type
- Agent 写操作必须经过确认门控

### MUST NOT

- 不要在路由中直接操作 MongoDB
- 不要绕过 service 层调用 domain 模块
- 不要使用 `query` 作为 `filter` 的替代参数名
- 不要使用 `path` 作为 `target_file` 的替代参数名
- 不要在 SSE 流中混用 `text/plain` 响应
- 不要在路由中捕获通用异常（由全局异常处理器统一处理）
