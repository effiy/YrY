# YA-09-91: API 版本化路由灰度 — 测试规格

> 来源 PRD：[95-需求-API版本化路由灰度.md](../../prds/2026-09/95-需求-API版本化路由灰度.md)
> 需求编号：YA-09-91 · 优先级：P2 · 人天：0.5d

> **文档职责**：本文档定义**怎么验证**（VERIFY），不含产品目标与实现方案。

---

## 一、测试范围与策略

### 1.1 测试范围

| 模块 | 测试重点 | 层级 |
|------|---------|------|
| VersionedRouter | URL 路径版本化 `/v1/rpc` `/v2/rpc` 共存 | 单元 |
| 灰度分发引擎 | Canary(5%) -> Rolling(30%) -> Full(100%) 三阶段 | 单元 |
| 阶段推进条件 | P95 延迟无劣化 + 错误率无上升自动推进 | 单元 |
| sticky routing | 同一用户始终路由到同一版本 | 单元 |
| 版本废弃通知 | v1 返回 `410 Gone` + 迁移指引 | 集成 |
| 快速回滚 | `X-API-Version` Header 或流量权重调整 | 集成 |

### 1.2 测试策略

| 层级 | 框架 | 覆盖内容 | 占比 |
|------|------|---------|------|
| 单元测试 | pytest | 版本路由、灰度权重分配、sticky routing、阶段推进 | 70% |
| 集成测试 | pytest + httpx | 端到端版本路由、回滚、废弃通知 | 30% |

---

## 二、测试数据与前置条件

| 组件 | 要求 |
|------|------|
| 多版本 RPC handler | v1 和 v2 分别注册不同的 handler（返回不同 version 字段） |
| 灰度配置 | `canary_weight=0.05`, `rolling_weight=0.3`, `full_weight=1.0` |
| 流量统计 | `version_stats` 字典：按版本统计请求数 |
| 1000 个模拟 session_id | 用于分布验证 |

---

## 三、测试用例

### 3.1 URL 路径版本化（4 条）

| 编号 | 用例 | 步骤 | 预期 | 优先级 |
|------|------|------|------|--------|
| UT-VR-01 | v1 路由正确 | `POST /v1/rpc` | 路由到 v1 handler，`response.version = "1.0"` | P0 |
| UT-VR-02 | v2 路由正确 | `POST /v2/rpc` | 路由到 v2 handler，`response.version = "2.0"` | P0 |
| UT-VR-03 | 未版本化路由降级 | `POST /rpc`（无版本前缀） | 路由到默认版本（最新稳定版） | P1 |
| UT-VR-04 | 不存在版本 404 | `POST /v99/rpc` | 返回 404 Not Found | P1 |

### 3.2 灰度分发（4 条）

| 编号 | 用例 | 步骤 | 预期 | 优先级 |
|------|------|------|------|--------|
| UT-CA-01 | Canary 5% 分发 | 1000 个请求，canary 阶段 | 约 50 个路由到 v2，950 个到 v1（误差 ±2%） | P0 |
| UT-CA-02 | Rolling 30% 分发 | 1000 个请求，rolling 阶段 | 约 300 个路由到 v2，700 个到 v1（误差 ±3%） | P0 |
| UT-CA-03 | Full 100% 分发 | 1000 个请求，full 阶段 | 全部路由到 v2 | P0 |
| UT-CA-04 | 阶段切换零中断 | canary -> rolling 切换时 | 无 5xx 错误，无请求丢失 | P1 |

### 3.3 Sticky Routing（2 条）

| 编号 | 用例 | 步骤 | 预期 | 优先级 |
|------|------|------|------|--------|
| UT-ST-01 | 同用户同版本 | 同一 session_id 连续 10 次请求 | 全部路由到同一版本 | P0 |
| UT-ST-02 | 不同用户可不同版本 | 两个不同 session_id 在 canary 阶段 | 一个可能到 v1，另一个可能到 v2 | P1 |

### 3.4 阶段推进条件（2 条）

| 编号 | 用例 | 步骤 | 预期 | 优先级 |
|------|------|------|------|--------|
| UT-PR-01 | 指标合格自动推进 | P95 延迟无劣化 + 错误率无上升 | 30 分钟后自动推进到下一阶段 | P0 |
| UT-PR-02 | 指标不合格阻止推进 | P95 延迟劣化 > 10% 或错误率上升 | 灰度暂停，告警发送 | P0 |

## 四、边界与异常测试

### 4.1 边界场景（3 条）

| 编号 | 场景 | 输入 | 预期 |
|------|------|------|------|
| BE-01 | 灰度权重为 0 | traffic_split=0 | 所有流量到 v1，v2 零请求 |
| BE-02 | 快速回滚 | 从 rolling 直接切回 0% | 所有流量立即回 v1，无请求中断 |
| BE-03 | 客户端指定版本 | `X-API-Version: 2.0` Header | 路由到指定版本，忽略灰度权重 |

### 4.2 异常场景（3 条）

| 编号 | 场景 | 触发条件 | 预期 |
|------|------|---------|------|
| EX-01 | v2 handler 异常 | v2 handler 抛出未捕获异常 | 仅 v2 流量受影响，v1 正常工作 |
| EX-02 | 灰度配置无效 | `traffic_split=1.5`（> 1.0） | 自动 cap 到 1.0，记录 WARNING |
| EX-03 | 版本废弃通知 | v1 请求返回 410 | 响应含 `message: "v1 已废弃，请升级到 v2"` + migration guide URL |

## 五、回归测试（2 条）

| 编号 | 回归场景 | 验证方法 |
|------|---------|---------|
| RG-01 | 灰度不影响非灰度端点 | 健康检查、静态资源等非 RPC 端点不受灰度影响 |
| RG-02 | 快速回滚后数据一致 | 回滚后 v1 和 v2 的数据无冲突，无脏数据 |

## 七、覆盖率缺口

| 缺口 | 原因 | 建议 |
|------|------|------|
| 灰度长期运行稳定性 | 需要数小时的实际流量 | 生产金丝雀部署后监控 |
| v1/v2 数据兼容性转换层 | 数据格式差异需真实数据 | 补充数据迁移测试 |
| 多级灰度同时运行 | 多个实验同时灰度的场景 | 需设计冲突解决策略 |
