# YA-09-232: LLM推理调度优化 — 测试规格

> **文档职责**：本文档定义**怎么验证**（VERIFY），覆盖优先级队列（P0-P3）、抢占式调度、负载感知路由、批处理合并（batching）、GPU 显存感知调度。

> 来源 PRD：[227-需求-LLM推理调度优化.md](../../prds/2026-09/227-需求-LLM推理调度优化.md)
> 需求编号：YA-09-232 · 优先级：P2 · 人天：0.3d

---

<a id="sec-1"></a>
## 一、测试范围与策略

| 层级 | 框架 | 覆盖内容 | 占比 |
|------|------|---------|------|
| 单元测试 | pytest | PriorityQueue 调度顺序、PreemptiveScheduler 抢占逻辑、BatchMerger 合并策略 | 45% |
| 集成测试 | pytest + httpx | RPC 优先级传递、多模型负载路由、GPU 显存限制下的调度行为 | 35% |
| 性能测试 | pytest-benchmark | 批处理合并延迟节省、优先级等待时间对比 | 20% |

**测试目标**：P0 请求优先于 P2 > 95%、抢占延迟 < 100ms、批处理合并吞吐提升 > 30%、GPU OOM 避免率 100%。

---

<a id="sec-2"></a>
## 二、测试数据与前置条件

**测试数据**：`tests/fixtures/scheduling/` 下 100 个模拟推理请求（含不同优先级、不同预估 token 数、不同模型需求）。

**前置条件**：YiAi ModelRuntime 多模型已注册（至少 2 个），GPU 显存监控可用。

---

<a id="sec-3"></a>
## 三、测试用例

| # | 场景 | 输入 | 步骤 | 预期结果 | 优先级 |
|---|------|------|------|----------|--------|
| 1 | P0 优先于 P2 | P2 先到达，P0 后到达 | 调度选择 | P0 先于 P2 执行，P2 等待 | P0 |
| 2 | 同优先级 FIFO | 3 个 P1 请求先后到达 | 调度顺序 | 按到达时间顺序执行（FIFO） | P0 |
| 3 | 抢占式调度 | P2 正在执行，P0 到达 | P0 抢占 | 暂停 P2（保存状态），执行 P0，P0 完成后恢复 P2 | P1 |
| 4 | 负载感知路由 | Model A 队列 5 个/Model B 队列 1 个 | 新请求路由 | 新请求路由到 Model B（负载低），不排队 | P1 |
| 5 | 批处理合并 | 5 个短请求同时到达 | batch_merge | 合并为 1 个 batch 推理，延迟总和 < 5x 单独推理 | P0 |
| 6 | GPU 显存感知调度 | 当前 GPU 已用 22/24 GB，新请求需 4GB | 调度检查 | 请求排队等待（不 OOM），直到显存释放 | P1 |
| 7 | 优先级反转防护 | P2 持有资源，P0 等待 P2 释放 | 优先级继承 | P2 临时提升到 P0，快速释放资源 | P2 |
| 8 | 请求超时取消 | P1 请求排队 > 30s | 超时处理 | 请求被取消，返回超时错误，释放队列位置 | P1 |
| 9 | 调度统计 | 100 请求调度完成 | GET /scheduler/stats | 返回: 平均等待时间/优先级分布/抢占次数/批处理命中率 | P1 |
| 10 | 批处理大小限制 | 20 个请求同时到达 | batch_merge(max_batch=8) | 最多 8 个合并为一个 batch，其余排队 | P2 |

<a id="sec-4"></a>
## 四、边界与异常测试

| # | 场景 | 输入 | 预期结果 |
|---|------|------|----------|
| E1 | 空队列调度 | 队列为空 | 调度器 idle，不抛异常 |
| E2 | 所有模型 GPU 显存不足 | 3 个模型均显存 < 500MB | 请求全部排队，不 OOM，返回"等待资源"提示 |
| E3 | 抢占恢复后状态一致 | P2 被抢占 3 次 | 每次恢复后推理结果与未抢占时一致 |
| E4 | 极高优先级请求连续到达 | 100 个 P0 连续 | 不饿死低优先级请求（max_consecutive 限制） |

## 五、回归测试

| # | 场景 | 验证方法 |
|---|------|----------|
| R1 | 添加新模型不影响已有调度策略 | 注册新模型后，已有优先级/批处理策略不变 |
