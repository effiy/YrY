# YA-09-100: 数据库备份与恢复 — 测试规格

> 来源 PRD：[104-需求-数据库备份与恢复](../../prds/2026-09/104-需求-数据库备份与恢复)

## 一、测试范围与策略

### 1.1 测试范围

| 模块 | 测试重点 | 层级 |
|------|---------|------|
| MongoDB 备份脚本 | `mongodump` 全量备份、增量备份、压缩存储 | 单元 |
| 时间点恢复 | 从备份恢复 + oplog 回放到指定时间点 | 单元 |
| 备份验证 | 备份文件完整性校验（MD5）、可恢复性验证 | 单元 |
| 灾备演练 | 恢复流程自动化、RPO/RTO 指标验证 | 集成 |
| 定时调度 | apscheduler 定时备份任务 | 集成 |

### 1.2 测试策略

| 层级 | 框架 | 覆盖内容 | 占比 |
|------|------|---------|------|
| 单元测试 | pytest + mongomock | 备份逻辑、恢复逻辑、完整性校验 | 60% |
| 集成测试 | pytest + docker-compose (MongoDB) | 真实备份/恢复流程、RPO/RTO | 40% |

| 组件 | 要求 |

| 测试 MongoDB 实例 | `mongodb://localhost:27018/test_backup`（独立实例） |

| 备份存储 | `tests/fixtures/backup/` 目录 |

## 三、测试用例

### 3.1 核心功能验证

| 编号 | 用例 | 步骤 | 预期 | 优先级 |
|------|------|------|------|--------|
| UT-BK-01 | 全量备份 | 执行 `backup_full()` | 备份文件生成，含 8 个集合的 BSON 文件 | P0 |
| UT-BK-02 | 备份文件完整性校验 | 备份完成后验证 MD5 | MD5 校验通过 | P0 |
| UT-BK-03 | 从备份恢复 | 清空数据库 -> `restore_from_backup()` | 数据恢复，文档数与备份前一致 | P0 |
| UT-BK-04 | 时间点恢复 | 备份后新增 10 条数据 -> 恢复到备份后时间点 | 新增数据保留，备份后删除的数据恢复 | P1 |
| UT-BK-05 | 增量备份 | 全量备份后数据变更 -> `backup_incremental()` | 仅备份变更的文档 | P1 |
| UT-BK-06 | 备份压缩 | 500MB 数据备份 | 压缩后 < 150MB（gzip level 6） | P1 |
| UT-BK-07 | RPO 验证 | 最后一笔写入到备份完成间隔 | < 1 小时（P0 集合） | P0 |
| UT-BK-08 | RTO 验证 | 恢复开始到服务可用间隔 | < 30 分钟 | P0 |
| UT-BK-09 | 备份不影响正常读写 | 备份期间并发读写 | 备份耗时增加 < 5%，读写无阻塞 | P1 |
| UT-BK-10 | 备份失败告警 | 模拟磁盘满导致备份失败 | 发送企微告警，记录审计日志 | P1 |

## 四、边界与异常测试

### 4.1 边界场景

| 编号 | 场景 | 输入 | 预期 |
|------|------|------|------|
| BE-01 | 空数据库备份 | 部分集合为空 | 仅备份非空集合，不报错 |
| BE-02 | 超大集合备份 | sessions 集合 5GB | 分片备份，单文件 < 500MB |
| BE-03 | 备份文件重名 | 同一分钟执行两次备份 | 自动添加时间戳后缀避免覆盖 |
| BE-04 | 恢复时数据库非空 | 目标库有数据时 restore | 提示"目标数据库非空"，需 `--drop` 确认 |

### 4.2 异常场景

| 编号 | 场景 | 触发条件 | 预期 |
|------|------|---------|------|
| EX-01 | 磁盘空间不足 | 备份路径剩余空间 < 备份文件大小 | 备份前检查空间，不足时告警 |
| EX-02 | 备份文件损坏 | 恢复时 BSON 文件非法 | 恢复失败，明确报错文件路径 |
| EX-03 | mongodump 不可用 | PATH 中无 mongodump | 脚本退出并提示"请安装 mongodb-database-tools" |
