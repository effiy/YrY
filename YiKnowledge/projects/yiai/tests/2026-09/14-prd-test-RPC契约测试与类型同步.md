<a id="sec-scope"></a>
## 一、测试范围与策略

### 1.1 测试分层

| 层级 | 描述 | 工具 | 覆盖目标 |
|------|------|------|---------|
| L1 单元测试 | 签名解析、类型映射、契约文件生成 | pytest + inspect | Python 函数签名提取、TS 类型生成、JSON Schema 输出 |
| L2 集成测试 | CI 契约检查流水线 | pytest + subprocess + git | pre-commit hook、CI 契约一致性、跨项目类型文件同步 |

### 1.2 契约同步流程

```
Python Service 方法签名
  → inspect.signature() 提取参数
  → 参数名 + 类型 → JSON Schema 契约文件
  → 生成 TypeScript 类型定义 (.d.ts)
  → pre-commit hook 检测漂移
  → CI 流水线校验一致性
```

### 1.3 常见漂移案例

| Python 参数 | 错误 TS 调用 | CI 检测 |
|------------|-------------|---------|
| `filter: dict` | `{query: {...}}` | 参数名不匹配 → CI 失败 |
| `target_file: str` | `{path: "/data"}` | 参数名不匹配 → CI 失败 |
| `cname: str` | `{collection_name: "bugs"}` | 参数名不匹配 → CI 失败 |

## 三、详细测试用例

### 3.1 Python 签名导出

| ID | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
|----|---------|---------|---------|---------|--------|
| TC-CT-01 | 函数签名参数提取 | sample_service_methods | 1. `inspect.signature(query_documents)`<br>2. 提取参数名和类型 | `{cname: str, filter: dict, pageNum: int, pageSize: int}` | P0 |
| TC-CT-02 | 必填/可选参数区分 | query_documents (cname 必填，其他可选) | 1. 提取参数<br>2. 检查 required 标记 | cname.required=True，其他 required=False | P1 |
| TC-CT-03 | 默认值提取 | pageNum=1, pageSize=10 | 1. 提取默认值<br>2. 检查契约输出 | 默认值正确记录在契约中 | P2 |
| TC-CT-04 | 类型注解映射 | Python type → JSON Schema type | 1. str → "string"<br>2. int → "integer"<br>3. dict → "object"<br>4. list → "array" | 类型映射正确 | P1 |
| TC-CT-05 | 无类型注解降级 | 参数无 type hint | 1. 缺省为 "any"<br>2. 日志 INFO | 类型标记为 "any"，不报错 | P2 |

## 四、边界与异常测试

| ID | 用例名称 | 输入/场景 | 预期行为 | 优先级 |

<a id="sec-gaps"></a>
## 七、覆盖缺口

| 缺口 | 影响 | 建议 |
|------|------|------|
| YiPet TypeScript 调用检测 | CI 仅检测 YiVad，未覆盖 YiPet | 将 YiPet 源码也加入 CI 契约检查范围 |
| 响应类型契约 | 仅检查请求参数，不检查响应结构 | 添加响应 data 字段的 JSON Schema 契约 |
| 跨项目类型文件同步 | 生成 .d.ts 后需手动复制到前端项目 | 添加自动同步机制（symlink 或 CI artifact） |
| Pydantic 迁移后自动导出 | 未来迁移 Pydantic 后的契约生成 | 添加 Pydantic model → JSON Schema 导出测试 |
