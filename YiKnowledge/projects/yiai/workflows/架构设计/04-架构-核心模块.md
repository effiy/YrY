## 二、应用工厂（src/app.py）

`create_app()` 函数按固定顺序初始化，**顺序不可调换**：

```
1. setup_logging()                    — 配置日志格式和级别
2. 注册异常处理器                      — BusinessException → StandardResponse
3. 注册中间件（CORS, Auth, Observer）  — 按顺序注册
4. 注册 19 个路由模块                  — server/routes/*.py
5. 挂载 MCP 服务                      — /mcp/*
6. 挂载静态文件                       — static/
7. lifespan 生命周期管理               — 启动/关闭钩子
```

### 应用工厂实现

```python
# src/app.py
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from contextlib import asynccontextmanager

def create_app() -> FastAPI:
    """FastAPI 应用工厂"""

    @asynccontextmanager
    async def lifespan(app: FastAPI):
        # 启动
        await db.connect(config.mongodb.uri, config.mongodb.db_name)
        await seed_database()
        await create_indexes()
        if config.knowledge.watcher_enabled:
            start_knowledge_watcher()
        if os.path.exists("data/rag_store/docstore.json"):
            preload_rag_index()
        yield
        # 关闭
        stop_knowledge_watcher()
        await db.disconnect()

    app = FastAPI(
        title="YiAi",
        version="1.0.0",
        lifespan=lifespan
    )

    # 异常处理器
    app.add_exception_handler(BusinessException, business_exception_handler)
    app.add_exception_handler(Exception, global_exception_handler)

    # 中间件（顺序不可变）
    app.add_middleware(CORSMiddleware, allow_origins=config.cors.origins)
    if config.observer.enabled:
        app.add_middleware(ObserverMiddleware)
    if config.middleware.auth_enabled:
        app.add_middleware(AuthMiddleware)

    # 路由注册
    app.include_router(execution.router)     # RPC 分发器 /
    app.include_router(auth.router)          # /auth/*
    app.include_router(files.router)         # /files/*, /read-file, /write-file
    app.include_router(knowledge.router)     # /knowledge/*
    app.include_router(rag.router)           # /rag/*
    app.include_router(search.router)        # /search/*
    app.include_router(health.router)        # /health
    # ... 其余 12 个路由模块（包括 metrics、bridge 等）

    return app

app = create_app()
```

### 生命周期管理

```
启动（lifespan startup）:
  → init MongoDB（Motor async client，pool_size=10）
  → seed 种子数据（menus, users, projects, issues, bugs, modules, pages, cycles, releases, labels, dict_*）
  → create indexes（为常用查询字段创建索引）
  → init RSS 系统（注册定时抓取任务）
  → init Knowledge Watcher（apscheduler 每 60s 轮询）
  → preload RAG 索引（从磁盘加载 VectorStoreIndex）

关闭（lifespan shutdown）:
  → shutdown Knowledge Watcher（取消 apscheduler 任务）
  → shutdown RSS 系统（取消定时任务）
  → close MongoDB connection（关闭连接池）
```

## 三、模块执行器（src/domain/execution/executor.py）

受控模块执行器，负责验证白名单、解析参数、调用目标函数：

```python
# src/domain/execution/executor.py
class ModuleExecutor:
    """受控模块执行器 — 白名单验证 + 参数解析 + 同步/异步调用"""
    
    async def execute(self, module_name: str, method_name: str, parameters: dict) -> dict:
        # 1. 白名单验证 — module_name 必须在 EXEC_ALLOWLIST 中
        # 2. 动态导入 — importlib.import_module(module_name)
        # 3. 参数解析 — 支持 dict 和 JSON string
        # 4. 调用目标函数 — async 函数直接 await，sync 函数用 asyncio.to_thread
        # 5. 结果记录 — 集成 SkillRecorder 和 ReentrancyGuard
```

### 核心特性

| 特性 | 说明 |
|------|------|
| 白名单机制 | `EXEC_ALLOWLIST` 从 `config.yaml` 的 `module_allowlist` 加载 |
| 参数解析 | 支持 dict 或 JSON string，自动转换 |
| 同步/异步兼容 | inspect 检测函数类型，sync 函数包装为 `asyncio.to_thread` |
| Observer 集成 | 可选的 ReentrancyGuard 防重入，SkillRecorder 记录执行轨迹 |
| 日志截断 | 参数和结果超过 500 字符自动截断 |

### 核心数据结构

```python
@dataclass
class ToolDefinition:
    name: str                              # 唯一标识（如 web_search）
    description: str                       # 给 LLM 看的描述
    parameters: dict                       # JSON Schema 参数定义
    execute: Callable[..., Awaitable[dict]] # async 执行函数
    requires_confirmation: bool = False    # 是否需要用户确认

@dataclass
class ToolCall:
    id: str                                # 调用 ID
    name: str                              # 工具名
    arguments: dict                        # 解析后的参数

@dataclass
class ToolResult:
    call_id: str
    name: str
    content: str                           # 执行结果文本
    error: Optional[str] = None
    duration_ms: float = 0
    details: Any = None
    terminate: bool = False                # Pi: 提示在此工具批次后停止
```

## 六、RAG 引擎（src/domain/rag/engine.py）

混合检索引擎，组合向量检索和 BM25 关键词检索：

```python
async def rag_query(
    query: str,
    top_k: int = 5,
    scope: str | None = None,  # 文件/文件夹过滤
    use_hyde: bool = True,     # HyDE 查询增强
    use_rerank: bool = False   # LLM Rerank
) -> RagResult:
    """RAG 检索：返回相关文档片段 + 引用编号"""
```

### 检索流程

```
用户查询
  → HyDE 查询增强（可选）：用 LLM 生成假设文档
  → 混合检索：向量相似度 + BM25 关键词
  → LLM Rerank（可选）：二阶段重排序
  → Sentence Window：返回周围窗口上下文
  → 内联引用编号：[Source 1], [Source 2], ...
  → 返回结果
```

### RAG 配置

| 配置项 | 默认值 | 说明 | 调优建议 |
|--------|--------|------|----------|
| `rag.embed_model` | `nomic-embed-text` | Embedding 模型 | 中文内容可考虑 `bge-m3` |
| `rag.chunk_size` | `512` | 分块大小（tokens） | 长文档增大，短文档减小 |
| `rag.chunk_overlap` | `40` | 分块重叠（tokens） | 约 10% 的 chunk_size |
| `rag.top_k` | `3` | 返回片段数 | 精度优先增大，速度优先减小 |
| `rag.hybrid_search` | `true` | 混合检索开关 | 推荐开启 |
| `rag.use_rerank` | `true` | LLM Rerank 开关 | 高精度需求开启 |
| `rag.use_hyde` | `true` | HyDE 增强开关 | 短查询场景开启 |

## 七、知识库监视器（src/domain/knowledge/watcher.py）

```python
# apscheduler 每 60s 轮询 YiKnowledge 目录树
from apscheduler.schedulers.asyncio import AsyncIOScheduler

scheduler = AsyncIOScheduler()
scheduler.add_job(
    scan_knowledge_base,
    trigger="interval",
    seconds=60,  # 可配置：knowledge.watcher_poll_seconds
    id="knowledge_watcher"

```

### 扫描流程

```
YiKnowledge Markdown 文件树
  → 遍历目录树，收集所有 .md 文件
  → 与 MongoDB knowledge_files 集合对比
  → 检测变更：新增（disk - db）、修改（mtime > scanned_at）、删除（db - disk）
  → 解析 YAML frontmatter（title, tags, category, status, ...）
  → 提取正文内容
  → Upsert 到 MongoDB
  → 触发 RAG 索引增量更新
```

### 变更检测策略

| 检测类型 | 方法 | 时间复杂度 | 说明 |
|----------|------|-----------|------|
| 新增文件 | 目录树遍历 vs MongoDB 已有记录 | O(n) | 新文件路径不在 MongoDB 中 |
| 修改文件 | 文件 mtime vs MongoDB `scanned_at` 字段 | O(n) | mtime 更新则重新解析 |
| 删除文件 | MongoDB 记录 vs 目录树 | O(n) | 文件路径在 MongoDB 中但磁盘上不存在 |

## 九、认证模块（src/domain/auth/）

JWT + bcrypt 认证，支持两种模式：

| 模式 | 配置 | 行为 | 适用场景 |
|------|------|------|----------|
| 开发模式 | `auth_enabled: false` | 所有端点公开，无需认证 | 本地开发 |
| 生产模式 | `auth_enabled: true` | X-Token 头部验证，JWT 签发/验证 | 生产环境 |

### Token 生命周期

```
登录成功 → bcrypt 验证密码 → PyJWT 签发 Token（含 user_id, role, exp）
  → 返回 { token, user }
  → 后续请求携带 X-Token 请求头
  → header_verification_middleware 验证 Token
  → 提取 user 信息 → 注入 request.state.user
  → Token 过期（默认 1440 分钟）→ 需刷新或重新登录
```

## 十一、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| 初始化顺序错误 | 先注册路由再注册中间件 | 严格按 CORS → Auth → Observer → 路由顺序 | 中间件不生效 |
| 路由中直接操作 MongoDB | 路由中 `await db.find_one(...)` | 路由 → Service → Repository → MongoDB | 分层破坏 |
| 推测性扩展 | 给 MongoDB 单例添加未使用的方法 | 仅在调用者需要时扩展 | 死代码 |
| 生命周期中遗漏清理 | 启动时注册定时任务，关闭时不取消 | 启动时注册的都在关闭时清理 | 资源泄漏 |
| Agent 工具无确认门控 | 写操作直接执行 | 标记 `requires_confirmation=True` | 安全风险 |

## 十二、约束

### 必须遵守
- 应用工厂初始化顺序不可调换
- 所有异步操作使用 async/await
- 错误处理使用 ErrorCode 枚举 + BusinessException
- API 响应使用 StandardResponse 统一信封
- Domain 层不导入 server/
- 启动时注册的资源在关闭时清理

### 禁止
- 不在 routes 中直接调用 data/ 层
- 不混用同步和异步代码
- 不推测性地扩展 MongoDB 单例
- 不在 __init__.py 之外暴露内部实现
- 不跳过 Agent 写操作的确认门控
