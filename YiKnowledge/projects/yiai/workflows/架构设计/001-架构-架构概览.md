# 架构概览

> YiAi 是 YrY 单体仓库的唯一后端（FastAPI，端口 10086），为 YiVad 和 YiPet 提供统一的 RPC 服务。

## 一、技术定位

| 属性 | 值 |
|------|-----|
| 项目类型 | FastAPI 后端服务 |
| 端口 | 10086（可通过 `config.yaml` 的 `server.port` 配置） |
| 运行时 | Python 3.10+（uvloop 加速） |
| 数据库 | MongoDB（Motor async driver，连接池 pool_size=10, max_pool_size=50） |
| LLM 推理 | Ollama（自托管）+ DeepSeek（OpenAI 兼容）+ Anthropic |
| RAG 引擎 | llama_index（混合检索：向量 + BM25，可选 HyDE + Rerank） |
| 消费者 | YiVad（Vue 3.5 SPA）+ YiPet（Chrome MV3 扩展） |
| 通信协议 | RPC 信封 `{module_name, method_name, parameters}` |

## 二、目录结构

```
YiAi/src/
├── app.py                  # FastAPI 应用工厂 + 生命周期管理
├── shared/                 # 共享层（14 个文件，零业务依赖）
│   ├── config.py           # pydantic-settings + YAML 配置
│   ├── response.py         # StandardResponse 统一信封 + ORJSONResponse
│   ├── error_codes.py      # ErrorCode 枚举
│   ├── exceptions.py       # BusinessException
│   ├── logging.py          # 日志配置
│   ├── cache.py + cache_keys.py  # 缓存层（Redis/内存回退）
│   ├── circuit_breaker.py  # 时间窗口熔断器
│   ├── metrics.py          # Prometheus 指标
│   ├── migration.py + migration_helpers.py  # 数据迁移
│   ├── runtime.py          # 运行时优化（uvloop 等）
│   ├── sse_utils.py        # SSE 格式化工具（orjson）
│   └── utils.py            # 通用工具函数
├── models/                 # Pydantic 模型 + 集合名常量
│   ├── __init__.py         # 模型预编译（model_rebuild）
│   ├── schemas.py          # 请求/响应 Schema
│   └── collections.py      # MongoDB 集合名常量
├── middleware/              # 中间件（auth）
├── server/                 # HTTP 层
│   ├── middleware.py        # AuthMiddleware, BodySizeLimit, GracefulShutdown, RequestId, ResponseTime
│   ├── gzip_middleware.py   # FastGZipMiddleware (zlib level 1)
│   ├── errors.py           # 全局异常处理器
│   ├── mcp_server.py       # MCP 协议服务端
│   └── routes/             # 21 个路由模块 + 1 个 dashboard 子包
├── services/               # 服务层 — 编排业务逻辑
├── domain/                 # 领域层 — 11 个子包（核心业务逻辑）
└── data/                   # 数据层 — MongoDB 单例 + Repository
```

## 三、分层架构

```
server/routes/  →  services/  →  domain/  →  data/  →  shared/
   HTTP 层         编排层        业务层      持久层      共享层
```

**导入规则**：server 可导入 services/shared；services 可导入 domain/data/shared；domain 可导入 data/shared；data 仅导入 shared；shared 零依赖。

## 四、请求生命周期

```
HTTP Request
  → FastGZipMiddleware (zlib level 1, >= 512 bytes)
  → BodySizeLimitMiddleware
  → ResponseTimeMiddleware (X-Response-Time-Ms)
  → RequestIdMiddleware (X-Request-ID)
  → CORS
  → AuthMiddleware（可选）
  → GracefulShutdownMiddleware (inflight 计数)
  → 路由匹配
  → RPC 分发器（execution.py）：module_name.method_name → 动态导入
  → services 参数校验 → domain 业务逻辑 → data MongoDB 操作
  → ORJSONResponse {code, message, data}
```

启动顺序（lifespan）：runtime 优化 → MongoDB 连接 → 种子数据 upsert → 缓存初始化 → Knowledge Watcher → 备份调度器 → 缓存预热（menus、knowledge scan、RAG 预加载、热模块预导入、Ollama 预连接）。

## 五、RPC 分发

`POST /` body: `{module_name, method_name, parameters}` → `execution.py` 动态路由到对应 service 方法。支持 `POST /batch` 并发 RPC 调用。

核心 RPC 模块：`data_service`（CRUD）、`chat_service`（SSE 聊天）、`knowledge_service`（知识库）、`rag_service`（RAG 检索）、`rss.feed_service`（RSS）、`bridge_service`（YiPet→YiVad）。

## 六、Agent 循环

```
turn_start → LLM 推理 → tool_call → [confirmation_required(120s)] → tool_execution → turn_end → 循环 → agent_end
```

特性：确认门控、拒绝记忆（20 条）、模型自动升级、预算感知、旋转检测、断连检测（CancelledError → 保存 → 清理）、结果裁剪（6000 字符）。

## 七、RAG 管道

```
YiKnowledge/*.md → Knowledge Watcher(60s 轮询) → MongoDB knowledge_files → llama_index(向量+BM25) → [HyDE] → [Rerank] → top_k 结果
```

配置开关：`rag.hybrid_search`、`rag.use_hyde`、`rag.use_rerank`、`rag.chunk_size`(512)、`rag.top_k`(5)。

## 八、降级策略

| 场景 | 行为 |
|------|------|
| MongoDB 不可用 | 写入失败，读取空 |
| Ollama 不可用 | 返回 AI_UNAVAILABLE |
| RAG 索引缺失 | 返回空，提示构建 |
| Agent 模型停滞 | 自动切换 fallback |
| 熔断器打开 | 快速失败，冷却期后重试 |

## 九、关键约束

- 统一信封 `{code, message, data}`，使用 `ORJSONResponse`
- 参数名：`filter`（非 `query`）、`target_file`（非 `path`）、`cname`（非 `collection_name`）
- 文件双写：磁盘（主）+ MongoDB（备份）
- 分层不妥协：server 不调 data，domain 不调 server
- 所有外部 I/O 使用 `asyncio.timeout` 包装
- 安全配置通过环境变量覆盖，禁止硬编码默认值
