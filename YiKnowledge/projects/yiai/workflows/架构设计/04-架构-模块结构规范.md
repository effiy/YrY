# 模块结构规范

> **读完你将能够**：掌握 YiAi 各层职责边界和模块组织规则

## 一、分层模型

```
server/routes/     HTTP 层 — 路由、中间件、异常处理
services/          服务层 — 业务编排、参数校验
domain/            领域层 — 核心业务逻辑
data/              数据层 — MongoDB 访问、仓库模式
shared/            共享层 — 配置、响应、错误码、工具函数
```

**单向依赖**：server → services → domain → data → shared。下层绝不依赖上层。

## 二、各层职责

### server/routes/（20 个模块）
路由函数只做参数提取和响应格式化，通过 `services/` 调用业务。不直接导入 `domain/` 或 `data/`。

### services/（17 个模块）
封装 domain 逻辑，进行参数校验和业务编排。可导入 `domain/`、`data/`、`shared/`，不导入 `server/`。

### domain/（11 个模块）
核心业务逻辑，与框架无关。可导入 `data/`、`shared/`，不导入 `server/` 或 `services/`。

### data/
MongoDB 单例 + Repository + sessions。可导入 `shared/`，不导入上层。

### shared/
配置、StandardResponse、ErrorCode、BusinessException、日志。零业务依赖，所有模块可导入。

## 三、__init__.py 导出规则

多文件的 domain 模块必须通过 `__init__.py` 导出公共 API：

```python
# domain/files/__init__.py
from .local import read_file, write_file, delete_file
from .storage import upload_image
__all__ = ["read_file", "write_file", "delete_file", "upload_image"]

# 调用方：通过 __init__.py 导入
from domain.files import read_file
# 禁止：from domain.files.local import read_file
```

## 四、命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块文件 | snake_case | `chat_service.py` |
| Service 类 | PascalCase + Service | `ChatService` |
| 路由文件 | snake_case | `agent.py` |
| 测试文件 | test_ + snake_case | `test_agent.py` |
| 私有函数 | _ 前缀 | `_build_filter` |

## 五、新增模块流程

1. `domain/<name>/` — 核心逻辑，`__init__.py` 导出
2. `services/<name>_service.py` — 参数校验 + 编排
3. `server/routes/<name>.py` — HTTP 路由
4. `app.py` — `include_router`
5. `tests/` — 单元测试
