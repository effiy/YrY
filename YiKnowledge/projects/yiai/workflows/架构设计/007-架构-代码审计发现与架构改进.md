# ADR: YiAi Bug 修复中发现的架构模式与反模式

## 1. 已识别反模式

### AP1: 裸异常替代 BusinessException

**发现频率**：6 处（已全部修复）

```python
# ✗ 反模式：RPC 调度器无法识别
raise ValueError("notification_id is required")

# ✓ 正确模式
raise BusinessException(ErrorCode.INVALID_PARAMS, message="notification_id is required")
```

**根因**：开发者未意识到 RPC 调度器通过 `except BusinessException` 区分业务异常和系统异常。裸 `ValueError`/`Exception` 会被全局处理器捕获并返回 `code: 9999`，导致客户端无法区分错误类型。

**治理**：新增 RPC 服务方法的 code review 检查项 — 所有显式 raise 必须使用 `BusinessException` 或 `ErrorCode` 枚举。

### AP2: 魔法数字替代枚举

**发现频率**：2 处（已修复）

```python
# ✗ 反模式
return {"code": 1001, "message": "...", "data": None}

# ✓ 正确模式
return {"code": ErrorCode.BUSINESS_ERROR.business, "message": "...", "data": None}
```

### AP3: 硬编码状态集

**发现频率**：1 处（已修复）

```python
# ✗ 反模式：与 shared/status.py 不一致
DONE_STATUSES = {"closed", "resolved", "done"}

# ✓ 正确模式
from shared.status import CLOSED_STATUSES, normalize_status_list
normalize_status_list(CLOSED_STATUSES)  # 含 4 种状态 + 8 种遗留变体
```

### AP4: 每次请求创建新客户端

**发现频率**：2 处（已修复）

```python
# ✗ 反模式：无连接池复用
client = AsyncOpenAI(api_key=..., base_url=...)

# ✓ 正确模式：模块级单例
_openai_client = None
def _get_openai_client():
    global _openai_client
    if _openai_client is None:
        _openai_client = AsyncOpenAI(...)
    return _openai_client
```

### AP5: 废弃 API 使用

**发现频率**：15 处（已修复）

```python
# ✗ 反模式（Python 3.12+ DeprecationWarning）
datetime.utcnow()

# ✓ 正确模式
datetime.now(timezone.utc)
```

## 2. 已识别正确模式

### GP1: 路径遍历防护

`domain/files/path_ops.py` 和 `domain/knowledge/scanner.py` 中的路径解析函数统一使用 `..` 检测 + `os.path.commonpath` 容器校验 + `os.path.realpath` 规范化。此三层防护有效阻止了目录遍历攻击。

### GP2: 熔断器模式

`shared/circuit_breaker.py` 实现的时间窗口熔断器（CLOSED → OPEN → HALF_OPEN），集成到 `LLMProviderRouter`。O(1) 状态检查，失败计数自动过期。

### GP3: RAG 检索去重

`domain/rag/context_builder.py` 实现了三层去重：文本签名去重 → 跨文件重叠过滤 → 知识库-Web 结果交叉去重。每层均使用词级 Jaccard 相似度，阈值可配置。

### GP4: 错误码分层设计

`shared/error_codes.py` 的 `ErrorCode` 枚举按千位分层：1xxx 客户端、2xxx AI、3xxx 文件、4xxx 认证、5xxx 服务端。每个 `ErrorCode` 成员同时携带 HTTP 状态码和业务错误码。

## 3. 架构建议

### 3.1 CI 门禁增强

```yaml
# 建议添加到 CI pipeline
- name: Error code uniqueness
  run: python -m pytest tests/unit/shared/test_error_codes.py::TestErrorCode::test_all_business_codes_unique -v
- name: No bare ValueError in RPC services  
  run: grep -rn "raise ValueError" src/domain/ src/services/ && exit 1 || exit 0
- name: No deprecated utcnow()
  run: grep -rn "\.utcnow()" src/ && exit 1 || exit 0
```

### 3.2 可选依赖管理

当前 `observer` 包为可选依赖但未被声明。建议添加 `pyproject.toml` extras：

```toml
[project.optional-dependencies]
observer = ["yi-observer>=0.1.0"]
```

### 3.3 测试覆盖扩展

当前覆盖空白领域：

| 模块 | 现状 | 建议 |
|------|------|------|
| `openai_compat.py` | 0 测试 | 至少覆盖 `/v1/chat/completions` 和 `/v1/models` |
| `notification_service.py` | 0 测试 | 覆盖 CRUD + SSE 流 |
| `mcp.py` | 0 测试 | 覆盖 `_extract_content` 各种输入类型 |
| `export_service.py` | 0 测试 | 覆盖 create + status 流程 |
| `search.py` | 0 测试 | 覆盖 SSRF 防护边界值 |
