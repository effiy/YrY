# 模块结构规范

> YiAi 各层职责边界和模块组织规则。模块数量与 `src/` 当前代码保持一致。

## 一、分层模型

```
server/routes/     HTTP 层 — 路由、中间件、异常处理
services/          服务层 — 业务编排、参数校验（模块级函数为主）
domain/            领域层 — 核心业务逻辑（与框架无关）
models/            数据模型层 — Pydantic Schema + 集合名常量
data/              数据层 — MongoDB 单例 + Repository 模块函数
shared/            共享层 — 配置、响应、错误码、工具函数（零业务依赖）
```

**单向依赖**：server → services → domain → data → shared。下层绝不依赖上层。

## 二、各层职责与规模

### server/routes/（21 个路由模块 + dashboard 子包）
| 模块 | 说明 |
|------|------|
| `execution.py` | RPC 分发器（`POST /` + `POST /batch`） |
| `about.py`, `auth.py`, `backup.py`, `bridge.py` | 服务信息、认证、备份、桥接 |
| `debug.py` | 调试端点（性能/熔断器/inflight） |
| `files.py` | 文件读写/上传（双写策略） |
| `health.py` | 健康检查（liveness/readiness） |
| `knowledge.py`, `rag.py` | 知识库、RAG 检索 |
| `maintenance.py` | 系统维护（缓存清理） |
| `mcp.py`, `metrics.py` | MCP 协议、Prometheus 指标 |
| `notification.py` | 通知 SSE 流 |
| `openai_compat.py` | OpenAI 兼容 API |
| `search.py` | 全局搜索 + 对话压缩 |
| `state.py` | 状态记录 CRUD |
| `system.py` | 系统管理（菜单/字典） |
| `users.py`, `wework.py` | 用户管理、企业微信 |
| `dashboard/` | 8 个子模块（ai/health/knowledge/organization/performance/rag/rss/service） |

路由只做参数提取和响应格式化（`success()`/`fail()`），业务逻辑通过 `services/` 调用。

### services/（17 个服务模块）
```
ai/ (chat_service, llm_provider, model_runtime, compaction)
alert/, analytics/ (aggregator, collector, query_engine)
audit/, backup/ (backup_service, scheduler)
bridge_service.py, code_health_service.py
custom_fields/, database/ (data_service)
export/, knowledge/, milestone/
notification/, rag/, report/
rss/ (feed_service, rss_scheduler), tags/
```

职责：参数校验 + 调用 domain + 业务编排。**模块级函数为主**，非 class（少数复杂服务除外）。

### domain/（11 个领域模块）
```
ai/ (Agent 循环、工具注册 core/builtin/mcp)
audit/ (审计装饰器、日志模型)
auth/ (JWT + bcrypt)
execution/ (通用模块执行器)
files/ (文件管理 local + storage + paths)
knowledge/ (知识库扫描 + watcher 轮询)
rag/ (RAG 引擎 + 索引构建)
rss/ (RSS 抓取 + 调度器)
search/ (全局搜索 + Wikipedia 回退)
state/ (状态记录 + TTL 管理)
wework/ (企业微信客户端)
```

核心业务逻辑，与 FastAPI 框架无关。不导入 `server/` 或 `services/`。

### shared/（14 个文件）
```
config.py (pydantic-settings + YAML)
response.py (success/fail/ORJSONResponse)
error_codes.py (ErrorCode 枚举)
exceptions.py (BusinessException)
logging.py, utils.py, sse_utils.py
cache.py + cache_keys.py (Redis/内存双后端)
circuit_breaker.py (时间窗口熔断器)
metrics.py (Prometheus 指标)
migration.py + migration_helpers.py
runtime.py (uvloop + asyncio 调试)
```

零业务依赖，所有模块可导入。

### data/（4 个文件 + seeds/）
```
database.py (MongoDB 单例 + 慢查询监控 + 写关注分级)
repository.py (模块级 query_documents + 其他 CRUD)
sessions.py (会话数据操作)
chat_records.py (聊天记录操作)
seeds/ (14 个 JSON 种子文件，upsert 策略)
```

## 三、__init__.py 导出规则

多文件的 domain 模块必须通过 `__init__.py` 导出公共 API：

```python
# domain/files/__init__.py — 实际代码
from .local import read_file, write_file, delete_file, rename_file
from .local import delete_folder, rename_folder
from .storage import upload_image

# 调用方：通过 __init__.py 导入
from domain.files import read_file
# 禁止：from domain.files.local import read_file
```

## 四、命名约定

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块文件 | snake_case | `chat_service.py`, `error_codes.py` |
| Service 函数 | snake_case（模块级函数） | `query_documents()`, `scan_knowledge()` |
| 路由文件 | snake_case | `execution.py`, `knowledge.py` |
| 测试文件 | `test_` + snake_case | `test_utils.py` |
| 私有函数 | `_` 前缀 | `_build_sort_list`, `_write_concern` |

**注意**：YiAi 的 service 层使用**模块级函数**而非 class（`data_service.query_documents()` 而非 `DataService().query_documents()`）。

## 五、新增模块流程

1. `domain/<name>/` — 核心逻辑，`__init__.py` 导出公共 API
2. `services/<name>/` — 参数校验 + 编排（模块级函数）
3. `server/routes/<name>.py` — HTTP 路由（APIRouter + success/fail）
4. `app.py` — `app.include_router(<name>.router)`
5. `tests/` — pytest 测试
