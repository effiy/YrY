# OpenSpec 工作流标准

> Claude Code 在 OpenSpec 项目中的行为规范。

---

## 一、Subagent 协作

| 阶段 | 模式 | 拆分策略 |
|------|------|----------|
| Proposal | 并行搜索 | 同时启动多个 Explore 子代理搜索代码模式、API、已有模块 |
| Design | 主代理独做 | 决策性强，不拆子代理 |
| Apply | 混合 | 识别 tasks.md 中无依赖关系的 task 组并行实现，有依赖的串行 |
| Verify | 并行检查 | 同时启动子代理检查规范一致性/接口契约 |
| Land | 主代理独做 | 回写+commit 步骤短，拆子代理没收益 |

规则：
- 子代理只做搜索和确定的子任务，不做架构决策
- 并行子代理的结果由主代理综合判断
- 有依赖关系的 task 必须串行，不能强行并行

## 二、代码质量（强制执行）

**动手前先思考**：列出假设，逐条验证。复杂任务如有多种解释则都列出来，如有更简单的方案则提出来。

**每步有可验证的退出条件**：多步骤任务先列计划，动手后循环验证直到成功。

**只写被要求的东西**：不要加"灵活"、"可配置"、单次使用的抽象。

**精准改动**：只改必要的，改完清理自己造成的垃圾。匹配现有风格。

**lint + typecheck 通过才算成功**。Python 项目使用 ruff + mypy。

**禁止非通用性改动**：
- 不写只适配特定输入值的逻辑
- 假设所有外部数据都有效 → 必须校验类型/范围/null
- 处理数据时考虑边界情况（空值、异常值、边界值）
- 禁止魔法数字 → 用常量或枚举
- 禁止隐式成功假设 → 异步/外部操作必须处理失败情况
- 禁止资源泄漏假设 → 文件/连接/cursor 等使用后必须释放

## 三、上下文管理

**OpenSpec 阶段隔离**：所有阶段均由用户手动触发，不自动进入下一阶段。

**重构前清死代码**：未使用的 import/变量 先删掉，单独提交，再做重构。

## 四、大规模任务处理

**200 行以上修改或显著架构变更必须走 OpenSpec**：代码改动超过 200 行、或涉及新增服务/API 契约/数据模型重构时，禁止直接修改，必须通过 OpenSpec 工作流。

## 五、工具限制与编辑安全

**搜索要全**：用 Grep 搜内容，用 Glob 搜文件名。两者缺一不可。

**禁止脚本改文件**：修改源码文件只能使用内置编辑工具。格式化工具（ruff fmt）除外。

**不主动推送**：除非用户明确要求，否则不推送代码。

**中文回复**：用中文回复用户。
