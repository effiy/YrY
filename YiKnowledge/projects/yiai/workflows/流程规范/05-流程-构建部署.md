# 构建部署

> uvicorn/Gunicorn 部署、Docker 容器化、CI/CD 流水线、配置管理、健康检查、性能优化。

## 一、启动方式

### 开发环境

```bash
# 热重载模式（默认）
python main.py
# 等效于：
uvicorn src.app:app --host 0.0.0.0 --port 10086 --reload
```

### 生产环境

```bash
# 多 worker 模式
uvicorn src.app:app --host 0.0.0.0 --port 10086 --workers 4

# 使用 Gunicorn（推荐）
gunicorn src.app:app -w 4 -k uvicorn.workers.UvicornWorker -b 0.0.0.0:10086

# 使用 Gunicorn + 配置文件
gunicorn src.app:app -c gunicorn.conf.py
```

---

## 二、启动配置

### uvicorn 配置

```yaml
# config.yaml
server:
  host: "0.0.0.0"
  port: 10086
  reload: true                  # 开发模式热重载

uvicorn:
  limit_concurrency: 1000       # 最大并发连接数
  limit_max_requests: 10000     # 每个 worker 最大请求数
  timeout_keep_alive: 5         # Keep-Alive 超时（秒）
```

### Gunicorn 配置（gunicorn.conf.py）

```python
# gunicorn.conf.py
import multiprocessing

bind = "0.0.0.0:10086"
workers = multiprocessing.cpu_count() * 2 + 1
worker_class = "uvicorn.workers.UvicornWorker"
timeout = 120                   # SSE 流式传输需要长超时
keepalive = 5
max_requests = 10000
max_requests_jitter = 1000
```

## 三、启动流程

```
main.py
  → uvicorn.run("src.app:app", host, port, reload)
    → src/app.py: create_app()
      → setup_logging()              # 配置日志格式和级别
      → 注册异常处理器                # BusinessException → StandardResponse
      → 注册 Observer 中间件（可选）   # 限流/采样/深度防护
      → 注册 20 个路由模块            # server/routes/*.py
      → 配置 CORS 中间件              # origins: ["*"]
      → 配置 Auth 中间件（可选）       # header_verification_middleware
      → 挂载 MCP 服务                 # /mcp/*
      → 挂载静态文件                  # static/
      → lifespan:
        → 初始化 MongoDB              # Motor async client
        → 导入种子数据                # data/seeds/*.json
        → 初始化 RSS 系统             # 注册定时抓取任务
        → 初始化 Knowledge Watcher    # apscheduler 每 60s 轮询
        → 预加载 RAG 索引             # 从 MongoDB 构建 VectorStoreIndex
```

## 六、Docker 部署

```dockerfile
# Dockerfile
FROM python:3.12-slim

WORKDIR /app

# 安装依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制源码
COPY src/ ./src/
COPY config.yaml .

# 暴露端口
EXPOSE 10086

# 启动命令
CMD ["uvicorn", "src.app:app", "--host", "0.0.0.0", "--port", "10086", "--workers", "4"]
```

```bash
# 构建镜像
docker build -t yiai:latest .

# 运行容器
docker run -d \
  -p 10086:10086 \
  -v $(pwd)/data:/app/data \
  -v $(pwd)/../YiKnowledge:/app/YiKnowledge \
  -e MONGODB_URI="mongodb://host.docker.internal:27017" \
  --name yiai \
  yiai:latest
```

### Docker Compose

```yaml
# docker-compose.yml
version: "3.8"
services:
  mongodb:
    image: mongo:7
    ports:
      - "27017:27017"
    volumes:
      - mongo_data:/data/db

  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama_data:/root/.ollama

  yiai:
    build: .
    ports:
      - "10086:10086"
    depends_on:
      - mongodb
      - ollama
    environment:
      - MONGODB_URI=mongodb://mongodb:27017
    volumes:
      - ./data:/app/data
      - ../YiKnowledge:/app/YiKnowledge

volumes:
  mongo_data:
  ollama_data:
```

## 七、CI/CD 流水线（GitLab CI 示例）

```yaml
# .gitlab-ci.yml
stages:
  - check
  - test
  - build
  - deploy

lint:
  stage: check
  script:
    - cd YiAi
    - pip install ruff
    - ruff check src/

type-check:
  stage: check
  script:
    - cd YiAi
    - pip install -r requirements.txt
    - python -c "import src.app"

test:
  stage: test
  script:
    - cd YiAi
    - pip install -r requirements.txt
    - python -m pytest tests/ -v --cov=src --cov-report=term --cov-fail-under=80
  coverage: '/TOTAL.*\s+(\d+%)$/'

build-image:
  stage: build
  only:
    - master
  script:
    - docker build -t yiai:${CI_COMMIT_SHORT_SHA} .
    - docker tag yiai:${CI_COMMIT_SHORT_SHA} registry.example.com/yiai:${CI_COMMIT_SHORT_SHA}
    - docker push registry.example.com/yiai:${CI_COMMIT_SHORT_SHA}

deploy-prod:
  stage: deploy
  only:
    - master
  when: manual
  script:
    - docker pull registry.example.com/yiai:${CI_COMMIT_SHORT_SHA}
    - docker stop yiai || true
    - docker rm yiai || true
    - docker run -d --name yiai -p 10086:10086 registry.example.com/yiai:${CI_COMMIT_SHORT_SHA}
```

## 九、性能优化

| 优化 | 说明 | 配置 |
|------|------|------|
| 多 Worker | 利用多核 CPU | `--workers 4` |
| 连接池 | MongoDB 连接复用 | `pool_size=10, max_pool_size=50` |
| Keep-Alive | 复用 HTTP 连接 | `timeout_keep_alive: 5` |
| 最大并发 | 限制并发连接数 | `limit_concurrency: 1000` |
| Worker 重启 | 防止内存泄漏 | `max_requests: 10000` |

## 十、常见部署问题

### 启动后无法访问

```bash
# 检查端口监听
lsof -i :10086

# 检查防火墙
# macOS: System Preferences → Security → Firewall
# Linux: sudo ufw status
```

### MongoDB 连接超时

- 检查 `config.yaml` 中 `mongodb.uri` 配置
- 确保 MongoDB 服务已启动
- Docker 中使用 `host.docker.internal` 替代 `localhost`

### Worker 内存泄漏

- 设置 `max_requests` 定期重启 worker
- 使用 `max_requests_jitter` 避免同时重启
- 监控内存使用情况

### SSE 流式传输中断

- 确保 Nginx 反向代理配置了 `proxy_read_timeout` 足够大
- 检查客户端是否主动断开连接
