# 编码规范

> YiAi 编码规范、模块分层、命名约定、代码质量、错误处理、API 设计原则。

## 一、模块分层

```
server/routes/   ← HTTP 层，不直接访问 data/
      ↓
services/        ← 服务层，封装 domain 供 routes 调用
      ↓
domain/          ← 业务逻辑层，不导入 server/
      ↓
data/            ← 数据访问层，MongoDB 操作
      ↓
shared/          ← 跨模块共享（config, response, error_codes, utils）
```

### 分层规则

| 层 | 可以导入 | 禁止导入 |
|----|----------|----------|
| `server/` | `services/`, `shared/` | `data/`（直接） |
| `services/` | `domain/`, `data/`, `shared/` | `server/` |
| `domain/` | `data/`, `shared/` | `server/` |
| `data/` | `shared/` | `domain/`, `server/`, `services/` |
| `shared/` | —（零依赖） | 所有业务模块 |

## 二、命名约定

| 约定 | 适用范围 | 示例 |
|------|----------|------|
| snake_case | 文件、函数、变量 | `chat_service.py`, `query_documents`, `page_num` |
| PascalCase | 类、Pydantic 模型 | `StandardResponse`, `BusinessException`, `MongoDB` |
| UPPER_SNAKE_CASE | 常量、枚举值 | `SUCCESS`, `OVERDUE`, `AI_UNAVAILABLE` |
| 双下划线前缀 | 模块内部私有 | `_build_filter`, `_resolve_service` |

### 文件命名

| 文件类型 | 命名规则 | 示例 |
|----------|----------|------|
| 路由模块 | snake_case | `auth.py`, `agent.py`, `knowledge.py` |
| 领域模块 | snake_case | `chat.py`, `scanner.py`, `watcher.py` |
| 服务模块 | snake_case + `_service` | `chat_service.py`, `data_service.py` |
| 数据模块 | snake_case | `database.py`, `repository.py` |
| 工具模块 | snake_case | `utils.py`, `error_codes.py` |
| 测试文件 | `test_` + snake_case | `test_agent.py`, `test_config.py` |

## 三、代码风格

### 异步优先

```python
# 正确：使用 async/await
async def query_documents(cname: str, filter: dict | None = None) -> dict:
    result = await db.find_many(cname, filter or {})
    return result

# 错误：混用同步/异步
def query_documents(cname: str, filter: dict | None = None) -> dict:
    result = db.find_many_sync(cname, filter or {})  # 不存在同步方法
    return result
```

### 类型注解

```python
# 正确：完整的类型注解
async def create_document(cname: str, data: dict[str, Any]) -> dict[str, Any]:
    ...

# 错误：缺少类型注解
async def create_document(cname, data):
    ...
```

### 错误处理

```python
# 正确：使用 ErrorCode + BusinessException
from src.shared.error_codes import ErrorCode
from src.shared.exceptions import BusinessException

if not document:
    raise BusinessException(ErrorCode.NOT_FOUND, "文档不存在")

# 错误：返回原始错误信息
if not document:
    return {"error": "文档不存在"}
```

### 响应封装

```python
# 正确：使用 StandardResponse
from src.shared.response import StandardResponse

@router.get("/items")
async def get_items():
    items = await service.get_items()
    return StandardResponse.success(items)

# 错误：返回原始字典
@router.get("/items")
async def get_items():
    items = await service.get_items()
    return {"data": items}
```

## 四、API 设计原则

### 路由处理函数

```python
# server/routes/example.py
from fastapi import APIRouter, Request
from src.shared.response import StandardResponse

router = APIRouter()

@router.get("/example")
async def get_example(request: Request):
    """获取示例数据"""
    # 1. 参数提取（从 request 或 query params）
    # 2. 调用 service 层
    # 3. 封装响应
    result = await example_service.get_data()
    return StandardResponse.success(result)
```

### Service 层

```python
# services/example/example_service.py
from src.domain.example import ExampleDomain

class ExampleService:
    def __init__(self):
        self.domain = ExampleDomain()

    async def get_data(self) -> dict:
        # 1. 参数校验
        # 2. 调用 domain 层
        # 3. 格式化响应
        return await self.domain.fetch_data()
```

### Domain 层

```python
# domain/example/core.py
from src.data.repository import query_documents

class ExampleDomain:
    async def fetch_data(self) -> dict:
        # 核心业务逻辑
        return await query_documents(cname="example")
```

## 六、自约束

### 必须遵守

- **Domain 层拥有业务逻辑** — Routes 不直接调用 `data/`
- **公共 API 通过 `__init__.py` 导出** — 调用者使用重新导出，而非内部文件
- **MongoDB 单例只按需扩展** — 不推测性地添加方法
- **参数名称是合同** — `filter` 不是 `query`，`target_file` 不是 `path`
- **所有异步操作使用 async/await** — 不混用同步/异步
- **错误处理使用 ErrorCode + BusinessException** — 统一错误码管理

### 禁止

- 不在 routes 中直接调用 `data/` 层
- 不混用同步和异步代码
- 不在 `__init__.py` 之外暴露内部实现
- 不破坏 RPC 信封协议
- 不推测性地扩展 MongoDB 单例
- 不在 domain 层导入 `server/`


### 测试命名

```python
# 测试函数命名：test_<功能>_<场景>_<预期>
def test_query_documents_with_filter_returns_filtered_results():
    ...

def test_query_documents_empty_collection_returns_empty_list():
    ...

    ...
```

### 覆盖率目标

| 模块 | 目标覆盖率 | 理由 |
|------|-----------|------|
| `shared/` | >= 90% | 被所有层依赖，错误影响面大 |
| `data/` | >= 80% | 数据访问层，直接影响数据正确性 |
| `domain/` | >= 70% | 核心业务逻辑，需要重点覆盖 |
| `services/` | >= 70% | 业务编排层，需覆盖参数校验和异常路径 |

## 八、异步编程模式

### 异步函数定义

```python
# 正确：所有 I/O 操作使用 async/await
async def fetch_user(user_id: str) -> dict[str, Any]:
    user = await db.find_one("users", {"user_id": user_id})
    if not user:
        raise BusinessException(ErrorCode.NOT_FOUND, "用户不存在")
    return user

# 错误：在 async 函数中使用同步阻塞调用
async def fetch_user(user_id: str):
    user = pymongo.find_one(...)  # 阻塞事件循环
    return user
```

### 并发执行

```python
# 正确：使用 asyncio.gather 并发执行独立任务
async def load_dashboard_data(user_id: str) -> dict:
    projects, issues, bugs, sessions = await asyncio.gather(
        repo.query("projects", {"owner": user_id}),
        repo.query("issues", {"assignee": user_id}),
        repo.query("bugs", {"reporter": user_id}),
        repo.query("sessions", {"user_id": user_id}),
    )
    return {
        "projects": projects["total"],
        "issues": issues["total"],
        "bugs": bugs["total"],
        "sessions": sessions["total"],
    }

# 错误：串行等待，浪费时间
async def load_dashboard_data(user_id: str) -> dict:
    projects = await repo.query("projects", {"owner": user_id})
    issues = await repo.query("issues", {"assignee": user_id})
    bugs = await repo.query("bugs", {"reporter": user_id})
    sessions = await repo.query("sessions", {"user_id": user_id})
    return {...}
```

### 超时控制

```python
import asyncio

# 正确：为外部调用设置超时
async def call_external_api(url: str) -> dict:
    try:
        async with asyncio.timeout(10):  # 10 秒超时
            async with aiohttp.ClientSession() as session:
                async with session.get(url) as resp:
                    return await resp.json()
    except asyncio.TimeoutError:
        raise BusinessException(ErrorCode.AI_UNAVAILABLE, "外部服务超时")

# 错误：没有超时保护，可能无限等待
async def call_external_api(url: str) -> dict:
    async with aiohttp.ClientSession() as session:
        async with session.get(url) as resp:
            return await resp.json()
```

### 后台任务

```python
# 正确：使用 asyncio.create_task 启动后台任务
async def send_notification(user_id: str, message: str):
    """发送通知——不阻塞主流程"""
    asyncio.create_task(_do_send(user_id, message))

async def _do_send(user_id: str, message: str):
    try:
        await wework_client.send(user_id, message)
    except Exception as e:
        logger.error(f"通知发送失败: {e}")

# 错误：在主流程中 await 非关键任务
async def create_issue(data: dict):
    issue_id = await repo.insert("issues", data)
    await send_notification(data["assignee"], "新 issue")  # 阻塞主流程
    return issue_id
```

## 九、依赖注入模式

### 构造函数注入（推荐）

```python
# 正确：通过构造函数注入依赖
class DataDomain:
    def __init__(self, repository: Repository):
        self._repo = repository

class DataService:
    def __init__(self, domain: DataDomain):
        self._domain = domain

# 错误：在类内部创建依赖实例
class DataDomain:
    def __init__(self):
        self._repo = Repository(db)  # 硬编码依赖，无法测试

class DataService:
    def __init__(self):
        self._domain = DataDomain()  # 硬编码依赖
```

### 应用工厂装配

```python
# src/app.py
def create_app() -> FastAPI:
    # 1. 数据层
    repository = Repository(db)

    # 2. 领域层（注入 repository）
    data_domain = DataDomain(repository)
    chat_domain = ChatDomain(ollama_runtime, data_domain)

    # 3. 服务层（注入 domain）
    data_service = DataService(data_domain)
    chat_service = ChatService(chat_domain)

    # 4. 注册到 app.state
    app.state.data_service = data_service
    app.state.chat_service = chat_service

    return app
```

### 路由中获取依赖

```python
# 正确：通过 request.app.state 获取
@router.post("/data")
async def handle_data(request: Request, payload: RpcRequest):
    service = request.app.state.data_service
    return await service.query_documents(**payload.parameters)

# 错误：在路由中直接创建实例
@router.post("/data")
async def handle_data(payload: RpcRequest):
    domain = DataDomain(Repository(db))  # 每次请求创建新实例
    service = DataService(domain)
    return await service.query_documents(**payload.parameters)
```

## 十、配置管理

### 配置加载

```python
# 正确：使用 pydantic-settings 加载配置
from pydantic_settings import BaseSettings, SettingsConfigDict
from yaml import safe_load

class Settings(BaseSettings):
    model_config = SettingsConfigDict(yaml_file="config.yaml")

    mongodb_uri: str = "mongodb://localhost:27017"
    mongodb_db_name: str = "ruiyi"
    ollama_base_url: str = "http://localhost:11434"
    jwt_secret_key: str
    jwt_expire_hours: int = 24

    @classmethod
    def from_yaml(cls, path: str) -> "Settings":
        with open(path) as f:
            data = safe_load(f)
        return cls(**data)

settings = Settings.from_yaml("config.yaml")
```

### 配置访问

```python
# 正确：通过 Settings 实例访问
from src.shared.config import settings

class MongoDB:
    async def connect(self):
        await self.client.connect(
            settings.mongodb_uri,
            settings.mongodb_db_name,
        )

# 错误：直接读取环境变量或硬编码
class MongoDB:
    async def connect(self):
        uri = os.environ.get("MONGO_URI", "mongodb://localhost:27017")
        await self.client.connect(uri, "ruiyi")
```

## 十一、日志规范

### 日志级别使用

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| DEBUG | 开发调试信息 | 函数参数、中间变量值 |
| INFO | 关键业务流程 | 服务启动、索引构建、API 调用 |
| WARNING | 需关注但不影响运行 | 配置缺失使用默认值、重试操作 |
| ERROR | 错误但可恢复 | API 调用失败、文件读取异常 |
| CRITICAL | 严重错误需立即处理 | 数据库连接断开、服务不可用 |

### 日志格式

```python
# 正确：使用结构化日志
import logging

logger = logging.getLogger(__name__)

async def create_document(cname: str, data: dict) -> str:
    logger.info("Creating document collection=%s", cname)
    try:
        doc_id = await repo.insert(cname, data)
        logger.info("Document created id=%s collection=%s", doc_id, cname)
        return doc_id
    except Exception as e:
        logger.error("Failed to create document collection=%s error=%s", cname, e)
        raise

# 错误：使用 print 或不提供上下文
async def create_document(cname, data):
    print("creating...")
    return await repo.insert(cname, data)
```

## 十二、异常处理模式

### 异常层级

```
Exception
  └── BusinessException (业务异常基类)
        ├── AuthException (认证失败, 401)
        ├── ForbiddenException (权限不足, 403)
        ├── NotFoundException (资源不存在, 404)
        ├── ConflictException (资源冲突, 409)
        └── ValidationException (参数校验失败, 2)
```

### 异常抛出

```python
# 正确：使用具体异常类
async def delete_document(cname: str, key: dict) -> int:
    doc = await repo.find_one(cname, key)
    if not doc:
        raise NotFoundException(f"文档不存在: {cname}/{key}")
    return await repo.delete(cname, key)

# 错误：使用通用异常
async def delete_document(cname, key):
    doc = await repo.find_one(cname, key)
    if not doc:
        raise Exception("文档不存在")  # 无法区分错误类型
```

### 异常处理

```python
# 正确：只捕获可处理的异常
async def safe_rag_query(query: str) -> dict:
    try:
        return await rag_query(query)
    except ConnectionError:
        logger.warning("RAG service unavailable, returning empty")
        return {"results": [], "fallback": True}
    # 不捕获 Exception，让未预期的异常向上传播

# 错误：捕获所有异常
async def safe_rag_query(query: str) -> dict:
    try:
        return await rag_query(query)
    except Exception:  # 吞掉所有异常，包括 bug
        return {"results": []}
```

## 十三、MongoDB 操作规范

### 查询模式

```python
# 正确：使用 Repository 方法
async def get_active_projects() -> list[dict]:
    return await repo.find_many("projects", {"status": "active"})

# 错误：直接使用 Motor
async def get_active_projects():
    cursor = db.projects.find({"status": "active"})
    return await cursor.to_list(None)
```

### ObjectId 处理

```python
# 正确：返回前序列化 ObjectId
async def query_documents(cname: str, filter: dict) -> dict:
    docs = await repo.find_many(cname, filter)
    for doc in docs:
        if "_id" in doc:
            doc["_id"] = str(doc["_id"])  # ObjectId → str
    return docs

# 错误：直接返回 ObjectId
async def query_documents(cname, filter):
    docs = await repo.find_many(cname, filter)
    return docs  # _id 是 ObjectId，JSON 序列化失败
```

### 分页限制

```python
# 正确：限制 pageSize 范围
async def query_documents(cname: str, page_size: int = 20) -> dict:
    if page_size < 1:
        page_size = 1
    if page_size > 100:
        page_size = 100
    return await repo.query(cname, page_size=page_size)

# 错误：不限制 pageSize
async def query_documents(cname: str, page_size: int = 20) -> dict:
    return await repo.query(cname, page_size=page_size)  # 可能 pageSize=10000
```

## 十四、代码审查清单

### 提交前自查

| 检查项 | 说明 | 工具 |
|--------|------|------|
| 分层导入 | 不跨层导入（domain/ → server/） | 人工审查 |
| 异步一致性 | 所有 I/O 操作使用 async/await | ruff + 人工 |
| 类型注解 | 所有公共函数有完整类型注解 | ruff |
| 错误处理 | 使用 ErrorCode + BusinessException | 人工审查 |
| 响应封装 | 使用 StandardResponse 包装 | 人工审查 |
| 参数校验 | pageSize 等参数有范围限制 | 人工审查 |
| ObjectId 序列化 | 返回前转为字符串 | 人工审查 |
| 日志规范 | 使用 logger 而非 print | ruff |
| 测试覆盖 | 新功能有对应测试 | pytest-cov |

### 审查常见问题

| 问题 | 频率 | 建议 |
|------|------|------|
| 参数名不一致 | 高 | 使用 `filter` 而非 `query`，`target_file` 而非 `path` |
| 混用同步/异步 | 中 | 统一使用 async/await |
| 缺少类型注解 | 中 | 所有公共函数添加类型注解 |
| 错误信息不明确 | 低 | 错误信息包含上下文（collection name, key 等） |
| 日志信息不足 | 低 | 关键操作记录 INFO 日志，包含操作参数 |
