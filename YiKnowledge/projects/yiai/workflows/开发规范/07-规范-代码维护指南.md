# YiAi 代码维护指南

> 基于 2026-09-23 全量代码审计（25 个缺陷修复）提炼的维护规则。

## 1. 必检清单 — 新增/修改代码前

### 1.1 错误码使用

```
□ 新增 ErrorCode 成员前，运行 test_all_business_codes_unique 确认无冲突
□ RPC 服务方法中使用 BusinessException，不使用裸 ValueError/Exception
□ RPC 响应字典中的 code 字段使用 ErrorCode.{NAME}.business，不使用魔法数字
```

### 1.2 状态常量

```
□ Issue/Bug 状态使用 shared.status.Status 类常量
□ MongoDB 查询中的状态过滤使用 normalize_status_list() 兼容遗留数据
□ 不在服务层定义本地 DONE_STATUSES/OPEN_STATUSES 等硬编码集合
```

### 1.3 日期时间

```
□ 使用 datetime.now(timezone.utc)，不使用 datetime.utcnow()（Python 3.12+ 已废弃）
□ from datetime import 导入需包含 timezone
□ 时间戳比较使用 timezone-aware datetime 对象
```

### 1.4 HTTP 客户端

```
□ Provider/Runtime 中使用模块级或实例级共享客户端，不每次创建新连接
□ 参考模式：_get_http_client() 或 _get_openai_client()
□ 应用关闭时在 lifespan 中清理客户端
```

### 1.5 路径安全

```
□ 文件读写操作前调用 resolve_safe() 或 _resolve_project_path() 进行路径遍历防护
□ Web 请求外部 URL 前检查 SSRF（调用 _is_private_url()）
□ 不直接拼接用户输入到 os.path/os.system 调用
```

### 1.6 可选依赖

```
□ 可选包（observer 等）的导入包裹在 try/except ImportError 中
□ 可选特性默认值设为 False（observer_enabled: False）
□ 添加 pyproject.toml extras 声明可选依赖
```

## 3. 常见修复模式

### ValueError → BusinessException

```python
# Before
raise ValueError("notification_id is required")

# After
from shared.error_codes import ErrorCode
from shared.exceptions import BusinessException
raise BusinessException(ErrorCode.INVALID_PARAMS, message="notification_id is required")
```

### 硬编码状态集 → shared.status

```python
# Before
DONE = {"closed", "resolved", "done"}
filter = {"status": {"$in": list(DONE)}}

# After
from shared.status import CLOSED_STATUSES, normalize_status_list
filter = {"status": {"$in": normalize_status_list(CLOSED_STATUSES)}}
```

### 每次创建客户端 → 模块级共享

```python
# Before
client = AsyncOpenAI(api_key=..., base_url=...)

# After
_openai_client = None
def _get_openai_client():
    global _openai_client
    if _openai_client is None:
        _openai_client = AsyncOpenAI(api_key=..., base_url=...)
    return _openai_client
```
