# 领域服务模式

> 领域服务模式是 YiAi 的核心架构模式。每个业务领域封装在 `domain/` 下，通过 `services/` 对外暴露，由 `server/routes/` 调用。所有示例来自 `src/` 实际代码。

## 一、架构层次

```
server/routes/xxx.py          # HTTP 层：参数提取 + 调用 service + 响应格式化
        ↓
services/xxx/xxx_service.py   # 服务层：参数校验 + 调用 domain + 业务编排
        ↓
domain/xxx/
  __init__.py                 # 公共 API 导出（多文件模块必需）
  core.py / scanner.py / ...  # 核心业务逻辑
        ↓
data/repository.py            # 数据访问层：模块级函数
data/database.py              # MongoDB 单例
```

**实际分层示例**（domain/knowledge/）：

```
domain/knowledge/
  __init__.py        → 导出 init_knowledge_watcher, shutdown_knowledge_watcher, scan_knowledge
  scanner.py         → 目录树遍历 + frontmatter 解析
  watcher.py         → apscheduler 轮询循环
  writer.py          → Markdown 写回 + MongoDB upsert

services/knowledge/
  knowledge_service.py → 包装 domain/knowledge 的公共 API

server/routes/
  knowledge.py       → HTTP 端点（/knowledge-scan, /knowledge-read ...）
```

## 二、Domain 模块

### 简单模块（单文件，无需 __init__.py）
```
domain/auth/     → core.py        # JWT + bcrypt
domain/rss/      → feed.py + scheduler.py
domain/state/    → recorder.py + service.py
```

### 复杂模块（多文件，必须通过 __init__.py 导出）
```python
# domain/files/__init__.py — 实际代码
from .local import read_file, write_file, delete_file, rename_file
from .local import delete_folder, rename_folder
from .storage import upload_image

# domain/wework/__init__.py — 实际代码
from .client import send_message
```

**规则**：调用方导入 `domain/files`，不能直接导入 `domain/files/local.py`。

## 三、Service 层

Service 层是**模块级函数**，不是 Class（除少数复杂服务外）：

```python
# services/knowledge/knowledge_service.py — 实际模式
async def scan_knowledge() -> list[dict]:
    """扫描知识库目录树"""
    from domain.knowledge import scan_knowledge as _scan
    return await asyncio.to_thread(_scan)

async def read_knowledge_file(target_file: str) -> dict:
    """读取知识文件"""
    # 参数校验 → 调用 domain → 格式化返回
    ...
```

**职责**：参数校验 → 调用 domain 函数 → 格式化响应。不写核心业务逻辑，不直接操作 MongoDB（database.py 单例除外，仅限 data_service 内部使用）。

## 四、Route 注册

Route 使用 `APIRouter`，响应使用 `success()` / `fail()`：

```python
# server/routes/knowledge.py — 实际模式
from fastapi import APIRouter
from shared.response import success, fail
from shared.error_codes import ErrorCode

router = APIRouter()

@router.post("/knowledge-scan")
async def knowledge_scan():
    try:
        tree = await knowledge_service.scan_knowledge()
        return success(data=tree, cache_ttl=60)
    except Exception as e:
        logger.error(f"Knowledge scan failed: {e}")
        return fail(ErrorCode.INTERNAL_ERROR, str(e))

# app.py 注册
from server.routes import knowledge
app.include_router(knowledge.router, tags=["Knowledge"])
```

**规则**：路由只做参数提取和响应格式化，不写业务逻辑，不直接调 data/ 层。

## 五、完整示例：新增领域模块的 6 步流程

```
1. domain/new_feature/__init__.py  →  导出公共 API
2. domain/new_feature/core.py      →  核心业务逻辑
3. services/new_feature/           →  包装 domain API（参数校验 + 编排）
4. server/routes/new_feature.py    →  HTTP 端点（APIRouter + success/fail）
5. app.py                          →  app.include_router(...)
6. tests/                          →  pytest（conftest.py fixtures）
```

**检查清单**：
- [ ] domain 只导入 `data/` + `shared/`，不导入 `server/` 或 `services/`
- [ ] Service 不导入 `server/`
- [ ] 多文件的 domain 模块通过 `__init__.py` 导出
- [ ] Route 只调 Service，不调 domain 或 data
- [ ] 响应使用 `success()` / `fail()`
- [ ] 错误使用 `BusinessException(ErrorCode.XXX, "detail")`

## 六、约束

- Domain 只依赖 `data/` + `shared/`，不导入 `server/` 或 `services/`
- Service 不导入 `server/`，不直接操作 MongoDB（通过 domain 或 data_service）
- 多文件的 domain 模块必须通过 `__init__.py` 导出公共 API
- 响应统一使用 `success()` / `fail()`，不使用 `StandardResponse.success()`（该方法不存在）
- 错误处理统一使用 `BusinessException(ErrorCode.XXX, "detail")`
