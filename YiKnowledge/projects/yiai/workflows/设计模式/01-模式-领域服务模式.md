# 领域服务模式

> **读完你将能够**：掌握 Domain → Service → Route 三层实现模式

> 领域服务模式是 YiAi 的核心架构模式。每个业务领域封装在 `domain/` 下，通过 `services/` 对外暴露，由 `server/routes/` 调用。

## 一、架构层次

```
server/routes/example.py     # HTTP 层：参数提取 + 响应格式化
        ↓
services/example_service.py  # 服务层：参数校验 + 业务编排
        ↓
domain/example/
  __init__.py                # 公共 API 导出
  core.py                    # 核心业务逻辑
        ↓
data/repository.py           # 数据访问层：MongoDB CRUD
```

## 二、Domain 模块

### 简单模块（单文件）
```
domain/auth/
└── auth.py          # JWT + bcrypt 逻辑
```

### 复杂模块（多文件 + __init__.py）
```python
# domain/files/__init__.py
from .local import read_file, write_file, delete_file
from .storage import upload_image

__all__ = ["read_file", "write_file", "delete_file", "upload_image"]
```

**规则**：多文件的 domain 模块必须通过 `__init__.py` 导出公共 API，调用方不能直接导入内部文件。

## 三、Service 层

```python
# services/example/example_service.py
class ExampleService:
    async def create_item(self, data: dict) -> dict:
        if not data.get("name"):
            raise BusinessException(ErrorCode.INVALID_PARAMS, "name is required")
        return await do_something(data)  # 调用 domain

    async def list_items(self, filter: dict = None, pageNum=1, pageSize=20) -> dict:
        return await repository.query_documents("items", filter=filter,
                                                 pageNum=pageNum, pageSize=pageSize)
```

**职责**：参数校验 → 调用 domain → 格式化响应。不写核心业务逻辑，不直接操作 MongoDB。

## 四、依赖注入

```python
class MyFeatureDomain:
    def __init__(self, repository: Repository = None):
        self._repo = repository or Repository("my_features")

# 测试时注入 mock
service = ExampleService(repository=mock_repository)
```

**好处**：可测试（注入 mock）、解耦（依赖接口）、清晰（构造函数声明依赖关系）。

## 五、Route 注册

```python
# server/routes/notification.py
from fastapi import APIRouter, Request
router = APIRouter()

@router.post("/notification/send")
async def send(request: Request, data: dict):
    result = await notification_service.send(data.get("user_id"), data.get("message"))
    return StandardResponse.success(result)

# app.py
app.include_router(notification.router)
```

**规则**：路由只做参数提取和响应格式化，不写业务逻辑，不直接调 data/ 层。

## 六、完整示例：新增通知模块

```
1. domain/notification/__init__.py  →  导出 send_notification
2. domain/notification/sender.py    →  核心逻辑（调 data/ 层）
3. services/notification_service.py →  参数校验 + 编排
4. server/routes/notification.py    →  HTTP 路由
5. app.py                           →  include_router
6. tests/domain/test_notification.py →  单元测试
```

## 七、约束

- Domain 只依赖 `data/` + `shared/`，不导入 `server/` 或 `services/`
- Service 不导入 `server/`，不直接操作 MongoDB
- 多文件的 domain 模块必须通过 `__init__.py` 导出
- 依赖通过构造函数注入，不用全局变量
