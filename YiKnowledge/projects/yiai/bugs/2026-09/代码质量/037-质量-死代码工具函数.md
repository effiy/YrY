# generate_random_string 和 generate_md5 定义但未被调用

## 现象

`src/shared/utils.py` 中两个工具函数在代码库中无任何调用方：

```python
def generate_md5(text: str) -> str:
    """Generate MD5 hash of string"""
    return hashlib.md5(text.encode('utf-8').hexdigest())

def generate_random_string(length: int = 8, chars: str = string.ascii_letters + string.digits) -> str:
    """Generate random string of specified length"""
    return ''.join(random.choice(chars) for _ in range(length))
```

搜索 `generate_random_string` 和 `generate_md5` 的结果显示它们仅在定义处出现，未被项目中的任何文件导入或调用。

此外，`generate_random_string` 使用 `random.choice` 而非 `secrets.choice`——即使被启用在安全场景中也是不安全的。

## 根因分析

- 早期开发者添加了通用的工具函数但项目中从未需要它们
- 没有常规的死代码清理流程
- 函数定义存在于共享模块中，容易误导新开发者

## 涉及文件

- `src/shared/utils.py:50-56` — `generate_md5` + `generate_random_string`

## 修复方案

删除这两个函数。如需随机 ID 生成，使用 `uuid.uuid4()`；如需哈希，使用 `hashlib.sha256` 并注明用途。

## 预防措施

- 定期运行 `vulture` 或 `dead` 检测未使用的 Python 代码

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
