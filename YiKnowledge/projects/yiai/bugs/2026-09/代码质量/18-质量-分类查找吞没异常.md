# _lookup_source_category 和 _get_enabled_sources 吞没异常无法区分空结果与数据库错误

## 现象

`src/domain/rss/feed.py` 的 `_lookup_source_category` 和 `src/domain/rss/scheduler.py` 的 `_get_enabled_sources` 使用 `except Exception` 捕获所有异常并返回表示"无数据"的默认值，导致调用方无法区分"查询结果为空"和"数据库查询失败"两种截然不同的场景。

`_lookup_source_category`（`feed.py:447-457`）：
```python
async def _lookup_source_category(url: str) -> Optional[str]:
    try:
        await db.initialize()
        seeds = db.db[settings.collection_seeds]
        doc = await seeds.find_one({"url": url}, {"category": 1, "_id": 0})
        cat = doc.get("category") if doc else None
        return cat if (cat and "/" in cat) else None
    except Exception as e:
        logger.warning(f"Failed to look up source category for {url}: {e}")
        return None  # 数据库错误和"无分类配置"返回相同的 None
```

`_get_enabled_sources`（`scheduler.py:101-120`）：
```python
async def _get_enabled_sources(self) -> List[Dict[str, Any]]:
    try:
        await db.initialize()
        collection = db.db[settings.collection_seeds]
        filter_dict = { ... }
        cursor = collection.find(filter_dict, {'_id': 0})
        sources = [doc async for doc in cursor]
        return sources
    except Exception as e:
        logger.error(f"Failed to get RSS source list: {str(e)}", exc_info=True)
        return []  # 数据库错误返回空列表，与"无 RSS 源"相同
```

## 根因分析

虽然两个函数都有日志记录（符合之前的修复），但调用方无法根据返回值编程判断是否存在数据库问题：

1. `_lookup_source_category` 返回 `None` 时，调用方无法知道是"seeds 集合中没有该 URL 的 category 配置"还是"MongoDB 连接失败"
2. `_get_enabled_sources` 返回空列表 `[]` 时，调用方无法知道是"没有启用任何 RSS 源"还是"数据库查询失败"

对于 `_get_enabled_sources`，`parse_all_sources` 中的调用处：
```python
sources = await self._get_enabled_sources()
if not sources:
    return {
        'total_sources': 0,
        'success_count': 0,
        'failed_count': 0,
        'results': []
    }
```
数据库错误被当作"无源可解析"处理，RSS 定时任务静默跳过，运维无法发现数据库异常。

## 涉及文件

- `src/domain/rss/feed.py:447-457` — `_lookup_source_category` 函数
- `src/domain/rss/scheduler.py:101-120` — `_get_enabled_sources` 方法

## 修复方案

两种方案：

**方案 A（推荐）：让异常向上传播**
```python
async def _lookup_source_category(url: str) -> Optional[str]:
    await db.initialize()
    seeds = db.db[settings.collection_seeds]
    doc = await seeds.find_one({"url": url}, {"category": 1, "_id": 0})
    cat = doc.get("category") if doc else None
    return cat if (cat and "/" in cat) else None
```
调用方自行处理异常，区分"无数据"和"出错"。

**方案 B：返回带状态的结果对象**
```python
@dataclass
class LookupResult:
    found: bool
    value: Optional[str] = None
    error: Optional[str] = None
```
但会增加调用方的代码复杂度。

推荐方案 A——让数据库层的异常自然向上传播，由上层（调度器、路由）统一处理。

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
