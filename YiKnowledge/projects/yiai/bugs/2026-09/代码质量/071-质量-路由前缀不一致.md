# 多个路由文件中的 router 前缀定义不一致

## 现象

路由文件中 `APIRouter` 的 `prefix` 参数定义不一致——部分路由在 router 级别定义 prefix，部分依赖 `app.include_router(prefix=...)`：

```python
# state.py — router 级别定义 prefix
router = APIRouter(prefix="/state", tags=["State"])

# rag.py — 无 prefix，依赖 app.include_router
router = APIRouter()
```

## 涉及文件

- `server/routes/` 下 16 个路由文件

## 修复方案

统一在 router 级别定义 prefix 或在 app.include_router 中定义，不要混用。

## 预防措施

新路由定义遵循统一的 prefix 约定。

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
