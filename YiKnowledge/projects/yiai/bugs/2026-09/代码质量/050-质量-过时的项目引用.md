# 废弃的 YiWeb/YiPett 路径仍存在于白名单和工具引用中

## 现象

`src/domain/ai/tools.py:359` 的 `_ALLOWED_ROOTS` 白名单中包含已废弃的项目路径：

```python
_ALLOWED_ROOTS = ["../YiKnowledge", "../YiVad", "../YiPet", "../YiAi", "../YiWeb", "../YiPett"]
```

- `YiWeb` — 已重命名为 YiVad
- `YiPett` — 已重命名为 YiPet（多一个 `t`）

此外，`src/shared/exceptions.py:8` 引用了错误的异常处理文档链接，`domain/ai/tools.py` 的多处注释（`#noqa`）引用了已被修复但未移除的标记。

## 根因分析

- 项目经历过多次重命名（YiWeb → YiVad, YiPett → YiPet）
- 白名单从未被审计和更新
- 过时引用在运行时虽然被解析为绝对路径，但目录不存在，Agent 工具无法访问

## 涉及文件

- `src/domain/ai/tools.py:359` — `YiWeb`、`YiPett` 残留
- `src/shared/exceptions.py:8` — 过时的注释引用

## 修复方案

1. 从 `_ALLOWED_ROOTS` 中移除 `YiWeb` 和 `YiPett`
2. 搜索并替换所有 `YiWeb`、`YiPett` 的引用
3. 确认无其他废弃项目名称的残留

## 预防措施

- 项目重命名时，同步搜索并替换所有代码引用

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
