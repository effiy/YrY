# 缺少 Startup Probe 和 Readiness Probe 健康检查

## 现象

`server/routes/health.py` 的 `/observer-health` 端点返回 Observer 组件的状态，但缺少 Kubernetes 标准的 startup/liveness/readiness 端点：

```python
# 现有的健康检查 — 仅 Observer 状态
@router.get("/observer-health")
async def observer_health():
    ...
```

没有标准的 `/healthz`（liveness）、`/readyz`（readiness）、`/startup` 端点。

## 根因分析

- 目前通过 `python main.py` 单进程部署，未使用容器编排
- 但 CLAUDE.md 部署架构已规划生产环境

## 涉及文件

- `src/server/routes/health.py` — 缺少标准健康检查端点

## 修复方案

添加：
```python
@router.get("/healthz")  # liveness: 进程存活即可
@router.get("/readyz")   # readiness: MongoDB + Ollama 连接状态
```

## 预防措施

- 健康检查端点应遵循 Kubernetes 标准命名

## 影响范围

- **影响模块**：待补充
- **涉及文件**：
- `src/server/routes/health.py`
- **是否影响 API 契约**：否
- **是否影响其他项目（YiVad/YiPet）**：否
- **用户感知**：待确认

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
