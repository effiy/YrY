# 硬编码的运维参数应移至 config.yaml

## 现象

多个模块将外部服务 URL、超时时间、缓存 TTL、缓冲区大小等运维参数硬编码为模块级常量，无法通过 `config.yaml` 或环境变量覆盖。

涉及的硬编码值：

| 文件 | 常量 | 硬编码值 | 类型 |
|------|------|---------|------|
| `server/routes/search.py` | `_JINA_URL` | `https://r.jina.ai/` | 外部服务 URL |
| `server/routes/search.py` | `_FETCH_TIMEOUT` | `15.0` | 超时 |
| `server/routes/search.py` | `_FETCH_MAX_BYTES` | `512 * 1024` | 大小限制 |

| `server/routes/search.py` | `_FETCH_OUTPUT_MAX_CHARS` | `8000` | 大小限制 |

## 根因分析

项目使用 `config.yaml` + `pydantic-settings` 作为配置系统，但大量运维参数仍然以模块级常量的方式硬编码。这导致：

1. 切换环境（开发/测试/生产）时无法通过配置覆盖这些值
2. 外部服务 URL 变更需要修改代码并重新部署
3. 性能调优（如缓冲区大小、并发数）需要修改代码
4. 不符合项目已有的配置管理模式

## 修复方案

将运维相关的硬编码值迁移到 `config.yaml` 和 `Settings` 类中：

1. 在 `config.yaml` 中按模块添加对应的配置节
2. 在 `src/shared/config.py` 的 `Settings` 类中添加对应的 `Field` 定义
3. 各模块通过 `settings.xxx` 读取，保留模块级常量作为默认值但改为从 `settings` 取值

示例（search 模块）：
```yaml
# config.yaml
search:
  jina_url: "https://r.jina.ai/"
  fetch_timeout: 15.0
  fetch_max_bytes: 524288
  fetch_output_max_chars: 8000
  cache_ttl_seconds: 300
```

```python
# shared/config.py
search_jina_url: str = Field("https://r.jina.ai/", validation_alias="search_jina_url")
search_fetch_timeout: float = Field(15.0, validation_alias="search_fetch_timeout")
```

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
