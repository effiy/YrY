# code-quality: code_health_service.py 使用歧义变量名 l

## 现象

ruff 检查报 E741（ambiguous variable name）错误：

```
src/services/code_health_service.py:160:35: E741 Ambiguous variable name: `l`
src/services/code_health_service.py:163:54: E741 Ambiguous variable name: `l`
```

## 复现步骤

1. 运行 `cd YiAi && python -m ruff check src/ --select=E741`
2. 观察歧义变量名

## 预期行为

变量名应具有描述性，避免单字母变量名（除了常见的数学符号如 `i`、`j`、`k`）

## 实际行为

在 `_detect_duplicates` 函数中，`l` 被用作循环变量名来表示代码行。由于 `l` 在某些字体中容易与数字 `1` 混淆，PEP 8 建议避免使用。

## 根因分析

`_detect_duplicates` 函数中的滑动窗口循环使用 `l` 作为行变量：
```python
non_blank = sum(1 for l in window if l.strip())
normalized = "\n".join(_norm_line(l) for l in window)
```

## 修复方案

将 `l` 重命名为 `line`：

```diff
- non_blank = sum(1 for l in window if l.strip())
+ non_blank = sum(1 for line in window if line.strip())
- normalized = "\n".join(_norm_line(l) for l in window)
+ normalized = "\n".join(_norm_line(line) for line in window)
```

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
