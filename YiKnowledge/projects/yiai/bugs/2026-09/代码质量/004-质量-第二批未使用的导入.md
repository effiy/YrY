# code-quality: 第二批未使用 import 和变量清理

## 现象

ruff 检查报 8 个 F401（未使用导入）、1 个 F841（未使用变量）、4 个 W292（文件末尾缺少换行）：

**F401 — 未使用导入:**
| 文件 | 行 | 未使用符号 |
|------|-----|------------|
| `src/domain/ai/tools.py` | 672 | `subprocess`（局部导入） |
| `src/domain/ai/tools.py` | 1020 | `json as _json`（局部导入） |
| `src/domain/audit/models.py` | 1 | `dataclasses.field` |
| `src/domain/knowledge/scanner.py` | 17 | `typing.Iterable` |
| `src/domain/rag/engine.py` | 12 | `json` |
| `src/server/routes/knowledge.py` | 169 | `re`（局部导入） |
| `src/services/ai/model_runtime.py` | 23 | `functools` |
| `src/services/code_health_service.py` | 9 | `asyncio` |

**F841 — 未使用变量:**
| 文件 | 行 | 变量 |
|------|-----|------|
| `src/domain/knowledge/scanner.py` | 458/464 | `date_str` |

**W292 — 缺少末尾换行:**
| 文件 |
|------|
| `src/services/ai/llm_provider.py` |
| `src/services/audit/audit_service.py` |
| `src/services/database/data_service.py` |
| `src/shared/sse_utils.py` |

## 复现步骤

1. 运行 `cd YiAi && python -m ruff check src/ --select=F401,F841`
2. 观察未使用导入和变量

## 预期行为

所有导入和变量应被实际使用或移除

## 实际行为

8 个导入和 1 个变量赋值在代码中完全未被引用

## 根因分析

这些是重构后残留的死代码：
- `functools` 在 `model_runtime.py` 中可能是早期实现遗留
- `asyncio` 在 `code_health_service.py` 中导入但该模块使用同步模式
- `field` 在 `audit/models.py` 中只有 `dataclass` 和 `asdict` 被使用
- `json` 和 `subprocess` 在 `tools.py` 函数中局部导入但未被使用
- `Iterable` 在 `scanner.py` 中被导入但从未作为类型注解使用
- `re` 在 `knowledge.py` 中导入但正则逻辑已被移除
- `date_str` 在 `scanner.py` 中被赋值但值从未被读取

## 修复方案

移除所有未使用的导入和变量，为缺失换行的文件添加末尾换行

## 影响范围

- **影响模块**：6 个 Python 文件
- **是否影响 API 契约**：否
- **是否影响其他项目**：否

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
