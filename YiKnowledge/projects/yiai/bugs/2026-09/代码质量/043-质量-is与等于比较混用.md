# 项目中 `is` 用于字符串和数字的相等比较

## 现象

Python 中 `is` 比较对象身份（内存地址），`==` 比较值。虽然 CPython 对小整数和短字符串有 intern 优化，但依赖 `is` 做值比较是不可靠的做法。

代码库中有几处使用了 `is` 而非 `==` 进行值比较：

```python
# 多个文件中使用 is None / is not None — 正确（None 是单例）
if params is None:  # 正确

# 但在某些比较中混淆了 is 和 ==
if result.get('success') is True:  # 应使用 ==
```

## 根因分析

- `is None` / `is not None` 是正确的 Python 惯例（PEP 8 推荐）
- 但对 `True`/`False` 和数值使用 `is` 在某些 Python 实现中可能返回意外结果

## 涉及文件

- 多个领域和服务模块

## 修复方案

审计所有 `is` 比较——仅对 `None` 使用 `is`，对其他值使用 `==`。

## 预防措施

- 启用 `ruff` 规则 `F632`（`is` 用于字面量比较）
- 仅 `is None`、`is True` 作为哨兵值使用
