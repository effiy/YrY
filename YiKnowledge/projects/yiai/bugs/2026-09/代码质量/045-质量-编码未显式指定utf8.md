# SSE 编码 .encode() 未显式指定 utf-8

## 现象

3 处 SSE 数据帧编码调用 `.encode()` 未显式指定 UTF-8：

```python
# sse_utils.py:20
return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n".encode()

# openai_compat.py:100
return f"data: {json.dumps(chunk, ensure_ascii=False)}\n\n".encode()

# rag.py:59
return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n".encode()
```

虽然 Python 3 的 `.encode()` 默认使用 UTF-8，但当包含非 ASCII 字符（`ensure_ascii=False` 允许 Unicode）时，隐式编码依赖可能导致不同系统上行为不一致。

## 根因分析

- `ensure_ascii=False` 允许 JSON 输出保留 Unicode 字符（如中文）
- `.encode()` 依赖系统默认编码（在所有主流平台上为 UTF-8）
- 但 Python 文档和 PEP 推荐在 I/O 边界显式指定编码

## 涉及文件

- `src/shared/sse_utils.py:20` — SSE 帧编码
- `src/server/routes/openai_compat.py:100` — OpenAI 兼容 SSE
- `src/server/routes/rag.py:59` — RAG SSE

## 修复方案

```python
return f"data: {json.dumps(payload, ensure_ascii=False)}\n\n".encode("utf-8")
```

## 预防措施

- 所有 `.encode()` 和 `.decode()` 调用必须显式指定编码
