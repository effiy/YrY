# FastAPI app 未配置请求体大小限制

## 现象

`src/app.py` 的 `create_app()` 函数在创建 FastAPI 实例时未设置请求体大小限制。文件上传端点（`/upload-image-to-oss`、`/write-file`）可能接受任意大小的请求体：

```python
app = FastAPI(
    title="YiAi API",
    description="YiPet AI Service API",
    version="1.0.0",
    lifespan=_build_lifespan(...)
)
# 未设置 max_body_size 或 uvicorn 的 limit_max_requests_body_size
```

## 根因分析

- FastAPI 默认无请求体大小限制
- uvicorn 运行时 `main.py` 也未设置 `--limit-max-requests` 等安全参数
- 大文件上传（如图片、base64 编码内容）可能消耗大量内存
- 恶意请求可发送巨大 JSON payload 导致 OOM

## 涉及文件

- `src/app.py:162-167` — FastAPI 实例创建缺少大小限制
- `main.py` — uvicorn 启动参数缺少安全限制

## 修复方案

1. 添加 Starlette `MaximumContentLength` 中间件，限制请求体为 50MB
2. 在 `config.yaml` 中添加 `server.max_body_size_mb` 配置项
3. uvicorn 启动时设置 `--limit-max-requests` 和 `--limit-concurrency`
4. 文件上传端点单独设置合理的大小限制（图片 10MB，文件 50MB）

## 预防措施

- 所有公开 API 必须有请求大小上限
- 上传端点使用 `Depends` 注入大小验证

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
