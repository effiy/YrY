# services/__init__.py 使用 noqa: F401 进行 re-export 不够清晰

## 现象

3 个 service 模块使用 `# noqa: F401` 抑制 linter 告警来实现 re-export：

```python
# services/ai/chat_service.py
from domain.ai.chat import chat, list_ollama_models, OllamaService, classify_error, get_model_info  # noqa: F401
from services.ai.llm_provider import (  # noqa: F401
    get_llm_router, LLMProviderRouter, ChatMessage, ChatResponse,
    ProviderType, OllamaProvider, DeepSeekProvider,
)

# services/database/data_service.py
from data.repository import (  # noqa: F401
    query_documents, create_document, update_document,
    delete_document, upsert_document, ...
)
```

`noqa: F401` 表明这些导入仅用于 re-export（通过 RPC 信封的 `module_name.method_name` 调度）。但这种方式：
- 抑制了真正的未使用导入告警
- 如果底层模块移除了某个函数，linter 不会报错
- 没有 `__all__` 声明，IDE 无法提供准确的自动补全

## 根因分析

- RPC 信封调度机制通过 `importlib.import_module(module_name)` + `getattr(module, method_name)` 动态调用
- Service 模块的 `__init__.py` 仅做 re-export，函数本身未被模块内其他代码使用
- Team 选择 `noqa: F401` 作为"意图性 re-export"的信号

## 涉及文件

- `src/services/ai/chat_service.py:1-10`
- `src/services/database/data_service.py:2+`
- `src/services/rag/rag_service.py` — 类似模式

## 修复方案

1. 将 re-export 替换为显式 `__all__` 声明
2. 或使用变量赋值 `chat = chat` 消除 F401 而无需 noqa
3. 将 RPC 调度路由表独立到 JSON/YAML 配置（替代代码 re-export）

## 预防措施

- 所有 re-export 模块使用显式 `__all__` 而非 `noqa` 抑制

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
