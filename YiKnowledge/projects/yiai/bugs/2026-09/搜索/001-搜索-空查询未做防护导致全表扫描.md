## Description

全局搜索端点（`/search/*`）允许跨集合搜索。如果前端传入空的搜索关键词（`query=""` 或 `query` 参数缺失），后端可能构造出一个空过滤条件的 MongoDB 查询，导致全表扫描。

**场景：**
- 前端搜索框清空时触发搜索请求，`query` 参数为空字符串
- 后端未校验 `query` 是否为空，直接构造 `$regex` 查询
- 空字符串的 `$regex` 匹配所有文档 → 全表扫描
- 如果集合中有大量文档（如 `chat_records` 可能有 10 万+），全表扫描会导致：
  - MongoDB CPU 飙升
  - 查询超时（无 `maxTimeMS` 限制）
  - 其他请求排队等待

**影响范围：** YiVad 全局搜索功能、YiPet 搜索功能。

## Steps to Reproduce

1. 在 YiVad 全局搜索框中输入并快速清空
2. 前端可能发送 `query=""` 的搜索请求
3. 后端执行空字符串的 `$regex` 匹配 → 返回所有文档
4. 检查 MongoDB 慢查询日志——可能看到全表扫描
5. 如果集合很大，请求可能超时

## Expected Result

空查询应被提前拦截，返回空结果或参数校验错误，不执行数据库查询。

## Actual Result

空查询可能触发全表扫描，返回所有文档，消耗大量数据库资源。

## Root Cause

搜索端点缺少输入参数的前置校验——没有检查 `query` 是否为空、过短或过长。

**根本原因：** API 端点的参数校验不完整。RPC 分发器校验了 `module_name` 和 `method_name` 的存在性，但 `parameters` 内部的业务语义校验依赖各服务自行实现。

## Fix

### 1. 搜索端点添加参数校验

```python
# src/server/routes/search.py
MIN_QUERY_LENGTH = 1
MAX_QUERY_LENGTH = 200

@router.post("/search")
async def global_search(request: SearchRequest):
    query = (request.query or "").strip()

    # 空查询防护
    if not query:
        return success(data={"results": [], "total": 0}, message="Empty query")

    # 查询长度限制
    if len(query) < MIN_QUERY_LENGTH:
        return fail(
            error=ErrorCode.INVALID_PARAMS,
            message=f"Query too short (minimum {MIN_QUERY_LENGTH} character)"
        )
    if len(query) > MAX_QUERY_LENGTH:
        return fail(
            error=ErrorCode.INVALID_PARAMS,
            message=f"Query too long (maximum {MAX_QUERY_LENGTH} characters)"
        )

    # 添加 maxTimeMS 限制
    results = await _search_collections(query, max_time_ms=5000)
    return success(data=results)
```

### 2. MongoDB 查询添加超时

```python
async def _search_collection(collection, query: str, max_time_ms: int):
    cursor = collection.find(
        {"$text": {"$search": query}},
        {"score": {"$meta": "textScore"}}
    ).sort([("score", {"$meta": "textScore"})]).limit(100)

    # 设置查询超时
    cursor.max_time_ms(max_time_ms)

    return [doc async for doc in cursor]
```

## Verification

- `query=""` → 返回空结果，不执行数据库查询
- `query="a"` → 返回参数过短错误
- `query="正常搜索词"` → 正常搜索
- `query=<200+字符>` → 返回参数过长错误
- 全表扫描场景 → 5s 超时后自动终止

## Prevention

- **代码层面：** 所有搜索/查询端点 MUST 校验输入参数（非空、长度限制、特殊字符过滤）
- **数据库层面：** 所有动态查询 MUST 设置 `maxTimeMS` 限制
- **监控层面：** 监控慢查询（> 1s）的比例和空查询的请求次数

## 经验教训

1. **根本原因**：开发过程中对边界情况和异常路径的考虑不足是此类问题的共同根因
2. **设计阶段**：在接口设计和模块实现时，应主动考虑异常输入、空值、超时等边界场景
3. **代码审查**：审查时应检查是否存在类似的反模式（如未捕获异常、无超时控制、缺少参数校验等）
4. **测试覆盖**：异常路径的测试覆盖率应与正常路径同等重视
5. **团队分享**：此类问题应在团队周会或技术分享中讨论，形成团队共识
