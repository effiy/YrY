# 多接口并行调度 — 测试方案

### TC-PAR-001: 3 服务并行成功

| 步骤 | 启用 Google + 百度 + DeepL → 翻译 |
| 预期 | 3 个结果全部展示，按优先级排序 |

### TC-PAR-002: 1 个服务超时不影响其他

| 步骤 | 设置 DeepL 为慢速代理 → 翻译 |
| 预期 | Google/百度 正常，DeepL 显示超时错误 |

### TC-PAR-003: 全部失败

| 步骤 | 断开网络 → 翻译 |
| 预期 | 所有服务显示网络错误 |

### TC-PAR-004: 结果排序

| 步骤 | 拖拽调整服务优先级 → 翻译 |
| 预期 | 结果按新优先级排序 |

### TC-PAR-005: AbortController 取消

| 步骤 | 翻译中 → 关闭窗口 |
| 预期 | 所有请求被取消，无内存泄漏 |

## 增强边界与异常测试

### 边界值测试

| 编号 | 测试项 | 输入/场景 | 预期结果 | 优先级 |
|------|--------|----------|---------|--------|
| TC-EDGE-01 | 仅 1 个服务启动 | 仅启用 Google 翻译 | 串行执行，不启动并行调度开销 | P2 |
| TC-EDGE-02 | 所有可用服务同时启用 | 6 个翻译服务全开 | 全部并行发出，结果按优先级合并展示 | P1 |
| TC-EDGE-03 | 同一服务不同语言对并行 | Google en→zh + Google en→ja | 各自独立请求，结果分开展示 | P3 |
| TC-EDGE-04 | 混合启用/禁用状态 | 百度启用 + DeepL 禁用 + Google 启用 | 仅已启用的服务参与并行调度 | P1 |
| TC-EDGE-05 | 翻译文本为空 | 所有并行服务收到空文本 | 前端统一拦截，无请求发出 | P1 |
| TC-EDGE-06 | 结果完全相同 (各服务返回一致) | "Hello" en→zh 所有服务均返回"你好" | 去重展示，折叠相同结果并标注来源 | P2 |
| TC-EDGE-07 | 结果完全冲突 (各服务返回不同) | 歧义句翻译，各服务理解不同 | 全部展示，用户自行选择 | P2 |

### 异常场景测试

| 编号 | 异常场景 | 模拟方式 | 预期行为 | 恢复验证 |
|------|---------|---------|---------|---------|
| TC-ERR-01 | 1 个服务超时，其他正常 | DeepL 超时 + 百度/Google 正常 | DeepL 显示超时错误卡片，其他正常展示 | 下次请求正常 |
| TC-ERR-02 | 全部服务失败 | 断网或所有 API Key 无效 | 每个服务显示对应错误卡片，整体提示"所有翻译服务不可用" | 网络/Key 恢复后正常 |
| TC-ERR-03 | 1 个服务返回垃圾数据 | Mock 服务返回非翻译格式数据 | 该服务显示"解析失败"，其他服务正常 | 不影响其他服务 |
| TC-ERR-04 | 请求中途关闭窗口 (AbortController) | 翻译窗口打开 → 0.5s 后关闭 | 所有 in-flight 请求通过 AbortController.abort() 取消 | 无内存泄漏 |
| TC-ERR-05 | 服务部分 API 未配置 | 百度未配置 Key，Google 可用 | 百度跳过不请求，仅 Google 执行 | 配置百度后参与调度 |
| TC-ERR-06 | 并发连接数达到浏览器限制 | Chrome 6 连接/域名限制下 10+ 请求 | 请求排队，浏览器自动调度，不崩溃 | — |
| TC-ERR-07 | 快速连续触发翻译 (竞态) | 100ms 内触发 3 次翻译 | 前两次请求被 AbortController 取消，仅保留最新 | 最终结果正确 |

## 性能基准测试

| 编号 | 测试场景 | 测量指标 | 基准值 | 劣化阈值 | 测试方法 |
|------|---------|---------|--------|---------|---------|
| TC-PERF-01 | 3 服务并行，首个结果展示 | Time to First Result (TTFR) | ≤ 400ms | > 800ms | 取最快的服务响应 |
| TC-PERF-02 | 3 服务并行，全部结果完成 | Time to All Results (TTAR) | ≤ 1s | > 2s | 等待最慢的服务 |
| TC-PERF-03 | 并行调度开销 (vs 串行) | 调度层额外耗时 | ≤ 5ms | > 20ms | Promise.all 启动到首个请求发出 |
| TC-PERF-04 | AbortController 清理耗时 | abort() → 内存释放 | ≤ 10ms | > 50ms | GC 触发 + 测量 |
| TC-PERF-05 | 6 服务并行内存峰值 | 内存增量 | ≤ 20MB | > 50MB | 翻译 1000 字文本，6 服务全开 |
