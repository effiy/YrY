# 安全加密存储 — 测试方案

> **文档职责**：验证 API Key/Secret 的 AES 加密存储、机器指纹密钥生成、跨机器防解密、日志屏蔽和配置文件安全。

---

## 一、测试层级

```
安全加密存储
├── 加密方案
│   ├── crypto-js AES 加密
│   ├── 机器指纹密钥生成 (hostname + OS + username hash)
│   ├── 仅加密敏感字段 (apiKey/secret)
│   └── 解密过程正确性
├── 存储格式
│   ├── 加密字段标记 (U2FsdGVkX1...)
│   ├── 非敏感字段明文保留
│   └── 配置文件 JSON 结构完整
├── 安全边界
│   ├── 配置文件本地权限
│   ├── HTTP 服务仅 127.0.0.1 绑定
│   ├── 日志不含 API Key
│   └── WebDAV 同步安全性
└── 抗攻击能力
    ├── 配置文件泄露 → 无法解密
    ├── 配置文件复制到其他机器 → 无法解密
    └── 暴力破解抵抗力
```

---

## 二、核心测试用例

### 2.1 加密存储

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-ENC-001 | API Key 加密存储 | 配置百度翻译 Secret → 检查配置文件 | Secret 字段为 AES 加密串 (U2FsdGVkX1...) | P0 |
| TC-ENC-002 | 多服务 Key 全加密 | 配置 5 个翻译/OCR 服务 API Key | 所有敏感字段 (apiKey/secret/SecretKey) 均加密 | P0 |
| TC-ENC-003 | 非敏感字段明文保留 | 配置 → 检查 enable/source/name 字段 | 非敏感字段以明文 JSON 存储 | P1 |
| TC-ENC-004 | 配置文件 JSON 可解析 | 读取配置文件 → JSON.parse() | 加密后仍为有效 JSON | P1 |
| TC-ENC-005 | 空 API Key 不加密 | API Key 留空 → 检查存储 | 空字符串不加密存储 | P2 |
| TC-ENC-006 | 相同的 Key 加密结果不同 | 两次配置相同 Key → 检查两次加密密文 | 每次加密生成不同 IV，密文不同 | P2 |

### 2.2 解密验证

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-DEC-001 | 解密后可用于 API 调用 | 配置加密 → 重启 → 翻译请求 | 解密后 Key 正确，翻译成功 | P0 |
| TC-DEC-002 | 解密失败 → 提示重新配置 | 修改密文 → 启动 | 提示"API Key 解密失败，请重新配置" | P1 |
| TC-DEC-003 | 应用启动自动解密 | 重启 → 检查内存中 Key | 解密仅在内存中，不写回明文到磁盘 | P1 |
| TC-DEC-004 | 批量解密性能 | 解密 30 个加密字段 | 不影响启动速度 (≤ 100ms) | P2 |

### 2.3 机器指纹密钥

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-FP-001 | 密钥基于机器指纹 | 检查加密密钥生成逻辑 | 密钥 = hash(hostname + OS + username) 派生 | P1 |
| TC-FP-002 | 同机器重启密钥一致 | 重启 → 解密成功 | 机器指纹不变，密钥不变 | P0 |
| TC-FP-003 | 配置文件复制到其他机器 | 复制 config 到另一台机器 → 启动 | 解密失败，提示"配置不兼容当前机器" | P0 |
| TC-FP-004 | 修改 hostname 后密钥变化 | 修改 hostname → 重启 | 解密失败 (指纹变化)，需重新配置 Key | P2 |
| TC-FP-005 | 操作系统重装后密钥变化 | 重装 OS → 恢复配置文件 | 解密失败 (指纹变化) | P2 |
| TC-FP-006 | 用户名变更后密钥变化 | 修改用户名 → 配置文件复制 | 解密失败 (指纹变化) | P2 |

### 2.4 日志屏蔽

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-LOG-001 | 日志不含 API Key 明文 | 配置 Key → 启用调试日志 → 翻译 | 日志中无 Key 明文 | P0 |
| TC-LOG-002 | 日志不含加密密文 | 配置 Key → 启用调试日志 | 日志中无加密密文 (避免被复制到其他机器) | P2 |
| TC-LOG-003 | 错误日志不含 Key | API 调用失败 → 检查错误日志 | 错误日志中 Key 被截断为 "baidu_***key" | P1 |
| TC-LOG-004 | 崩溃报告不含 Key | 触发崩溃 → 检查 crash dump/log | crash 输出不含 Key 信息 | P1 |

### 2.5 文件权限

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-PERM-001 | 配置文件 Unix 权限 | ls -la ~/.pot/config.json | 权限 600 (仅用户可读写) | P1 |
| TC-PERM-002 | 配置目录 Unix 权限 | ls -la ~/.pot/ | 权限 700 (仅用户可访问) | P1 |
| TC-PERM-003 | 配置文件 Windows ACL | 检查文件安全属性 | 仅当前用户有 Full Control | P1 |
| TC-PERM-004 | 新创建的配置文件权限 | 删除 config → 重启自动创建 | 新建文件默认 600 | P1 |

## 三、边界与异常测试

### 边界值测试

| 编号 | 测试项 | 输入/场景 | 预期结果 | 优先级 |
|------|--------|----------|---------|--------|
| TC-EDGE-01 | API Key 超长 (4096 字符) | 配置 4096 字符 Key | 正常加密，加密后长度合理 | P3 |
| TC-EDGE-02 | API Key 含特殊字符 | Key 含引号、换行、emoji | 正确加密解密，不截断 | P1 |
| TC-EDGE-03 | API Key 仅数字 | Key = "12345" | 正常加密 | P2 |
| TC-EDGE-04 | 配置文件为空 (只是 {}) | 手动清空配置 | 所有 Key 为空，不尝试解密 | P2 |
| TC-EDGE-05 | 加密字段过多 | 配置 50+ 个加密字段 | 启动解密耗时不可感知 | P2 |
| TC-EDGE-06 | hostname 含 Unicode | 中文/日文机器名 | hash 函数正确处理 Unicode | P2 |
| TC-EDGE-07 | 加密 Key 为 Base64 原始值 | 检查加密前是否额外处理 | Key 加密前不做 Base64 转换 (已是原始值) | P2 |

### 异常场景测试

| 编号 | 异常场景 | 模拟方式 | 预期行为 | 恢复验证 |
|------|---------|---------|---------|---------|
| TC-ERR-01 | 加密库不可用 | 模拟 crypto-js 加载失败 | 回退到 Base64 编码 + 日志警告 | 修复依赖后正常 |
| TC-ERR-02 | 加密过程中断电 | 写入配置文件时断电 | 下次启动配置 JSON 可解析 (原子写入) | 重新配置 Key |
| TC-ERR-03 | 配置文件被外部修改 | 手动修改配置 JSON → 破坏结构 | 检测 JSON 格式错误，提示"配置文件损坏" | 修复 JSON 后正常 |
| TC-ERR-04 | 密文被截断 | 手动截断加密字段 | 解密失败，提示重新配置该 Key | 重新配置后正常 |
| TC-ERR-05 | 机器指纹信息不可用 | hostname 返回空 | 使用备选指纹 (固定盐值) | — |
| TC-ERR-06 | 配置文件读权限丢失 | chmod 000 → 启动 | 创建新配置文件 (默认值) | 恢复权限后可读取旧配置 |
| TC-ERR-07 | 磁盘空间不足写配置 | 磁盘满 → 配置 Key | 提示"配置保存失败，磁盘空间不足" | 清理空间后保存成功 |
| TC-ERR-08 | WebDAV 同步密文到其他机器 | WebDAV 同步配置到另一台 | 另一台机器解密失败 | 每台机器各自配置 Key |

## 五、安全测试

| 编号 | 测试项 | 测试方法 | 预期结果 | 优先级 |
|------|--------|---------|---------|--------|
| TC-SEC-01 | AES 密钥强度 | 检查密钥长度 | ≥ 256 bit | P0 |
| TC-SEC-02 | 加密算法验证 | 已知明文 → 检查密文 | AES-CBC 或 AES-GCM，带随机 IV | P0 |
| TC-SEC-03 | 相同明文不同密文 | 两次加密相同 Key | 密文不同 (随机 IV) | P1 |
| TC-SEC-04 | 配置文件泄露风险 | 复制 config.json 到公开目录 | 文件不包含可解密凭据 (在其他机器上) | P0 |
| TC-SEC-05 | 备份导出不含明文 | 导出配置备份 → 查看 JSON | 备份文件中 Key 仍为加密状态 | P0 |
| TC-SEC-06 | 内存中解密 Key 不落地 | strace/dtrace 监控 | 解密后的明文不写回配置文件 | P1 |
| TC-SEC-07 | 进程内存 dump 保护 | 分析 core dump | 仅运行时内存有明文，不持久化 | P2 |
| TC-SEC-08 | 机器指纹不可逆推导 | 已知密文 + 另一台机器的配置文件 | 无法推导出原始加密密钥 | P1 |
| TC-SEC-09 | 默认配置无预设 Key | 首次安装 → 检查配置文件 | 配置中无硬编码的 API Key | P1 |
| TC-SEC-10 | 频道/社区版无后门 | 检查加密逻辑代码 | 无绕过加密的调试开关或后门 | P1 |
