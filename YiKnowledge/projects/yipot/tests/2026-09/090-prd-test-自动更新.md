# 自动更新 — 测试方案

> **文档职责**：验证自动更新检查、GitHub Release API 版本对比、下载进度、更新器脚本和安装重启流程。

---

## 一、测试层级

```
自动更新系统
├── 更新检查
│   ├── 启动时非阻塞检查
│   ├── GitHub Release API 请求
│   ├── 版本号语义比较
│   └── 无新版本时静默
├── 更新窗口
│   ├── 当前版本 vs 最新版本
│   ├── 更新日志展示
│   ├── 下载进度条
│   └── 安装并重启按钮
├── 更新器脚本
│   ├── updater.mjs — 下载 + 替换 + 重启
│   ├── updater-for-fix-runtime.mjs — macOS 修复
│   └── 二进制替换逻辑
└── 平台差异
    ├── macOS .dmg 更新
    ├── Windows .msi 更新
    └── Linux .deb/.AppImage 更新
```

---

## 二、核心测试用例

### 2.1 更新检查

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-CHK-001 | 启动时非阻塞检查 | 启动 Pot → 检查启动耗时 | check_update 异步执行，不增加启动时间 | P1 |
| TC-CHK-002 | 无新版本静默 | GitHub Release 版本 = 当前版本 | 无弹窗，无通知，静默通过 | P1 |
| TC-CHK-003 | 发现新版本提示 | GitHub Release 版本 > 当前版本 | 弹窗提示"发现新版本 vX.Y.Z"，显示更新日志 | P1 |
| TC-CHK-004 | 版本号语义比较 | v1.2.3 vs v1.2.4 → 正确识别后者更新 | 正确判断版本先后 | P1 |
| TC-CHK-005 | pre-release 忽略 | GitHub 发布 pre-release (v2.0.0-beta) | 默认忽略预发布版本 | P2 |
| TC-CHK-006 | 手动检查更新 | 设置 → 点击"检查更新" | 立即发起检查请求 | P2 |
| TC-CHK-007 | 检查间隔限制 | 10 秒内连续点击"检查更新" | 防抖，限制检查频率 | P3 |

### 2.2 更新窗口

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-WND-001 | 更新窗口内容 | 点击"更新" → 检查窗口 | 显示当前版本、最新版本、更新日志 | P1 |
| TC-WND-002 | 更新日志 Markdown 渲染 | 检查日志显示 | 正确地渲染列表/标题/链接 | P2 |
| TC-WND-003 | 下载进度显示 | 点击"下载" → 观察进度条 | 百分比递增，有速度显示 | P1 |
| TC-WND-004 | 下载完成后按钮变化 | 下载完成 → 检查按钮 | "下载"变为"安装并重启" | P1 |
| TC-WND-005 | 更新窗口关闭 | 下载中 → 点击关闭 | 提示"下载将取消"确认 | P2 |
| TC-WND-006 | 安装并重启 | 下载完成 → 点击"安装并重启" | 应用关闭，更新器启动，新版本启动 | P1 |
| TC-WND-007 | 更新窗口不可重复打开 | 更新窗口已打开 → 再次点击检查 | 聚焦已有窗口 | P3 |

### 2.3 更新器脚本

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-UPD-001 | macOS 更新流程 | macOS → 下载 .dmg → 安装 | 旧版应用替换为新版，重启后版本更新 | P1 |
| TC-UPD-002 | Windows 更新流程 | Windows → 下载 .msi → 安装 | 旧版覆盖安装为新版 | P1 |
| TC-UPD-003 | Linux 更新流程 | Linux → 下载 .deb → 安装 | 包管理器更新或直接替换 | P1 |
| TC-UPD-004 | macOS "damaged" 修复 | macOS → 安装后提示已损坏 | updater-for-fix-runtime.mjs 执行，清除隔离属性 | P2 |
| TC-UPD-005 | 二进制替换原子性 | 安装过程中 Kill 进程 | 不会出现半替换状态 (先备份再替换) | P1 |
| TC-UPD-006 | 更新失败回滚 | 下载包损坏 → 尝试安装 | 保留旧版不损坏，提示重新下载 | P1 |

### 2.4 平台差异

| 编号 | 测试项 | 步骤 | 预期结果 | 优先级 |
|------|--------|------|---------|--------|
| TC-PLT-001 | macOS 更新源 | 检查更新 URL | 从 GitHub Release 下载 universal-apple-darwin .dmg | P1 |
| TC-PLT-002 | Windows 更新源 | 检查更新 URL | 从 GitHub Release 下载 x64 .msi | P1 |
| TC-PLT-003 | Linux AppImage 更新 | AppImage → 检查更新 | 下载新 AppImage 替换 | P2 |
| TC-PLT-004 | Linux deb 更新 | deb 安装 → 检查更新 | 提示通过包管理器更新 | P2 |

## 三、边界与异常测试

### 边界值测试

| 编号 | 测试项 | 输入/场景 | 预期结果 | 优先级 |
|------|--------|----------|---------|--------|
| TC-EDGE-01 | 版本号含字母后缀 | v2.0.0-alpha.1 vs v2.0.0 | 字母后缀版本 < 正式版 | P2 |
| TC-EDGE-02 | 版本号跳跃多个大版本 | v1.0.0 → v5.0.0 | 仍提示更新，下载大版本包 | P2 |
| TC-EDGE-03 | 版本号格式异常 | 非标准 semver (如 "latest") | 忽略或报错，不崩溃 | P2 |
| TC-EDGE-04 | 更新包超大 (2GB) | GitHub Release 包含超大包 | 进度正常显示，内存不爆炸 | P3 |
| TC-EDGE-05 | 更新日志超长 | 发布版含 500+ 行 changelog | 窗口可滚动，不截断 | P2 |
| TC-EDGE-06 | GitHub API 返回空 release | 仓库无任何 release | 静默，无更新 | P3 |
| TC-EDGE-07 | 安装包与当前系统不匹配 | 下载 macOS 包 → Windows 上尝试安装 | 拒绝安装，提示平台不匹配 | P2 |
| TC-EDGE-08 | 同名文件冲突 | updater 替换时目标文件被锁定 | 提示重启后继续 | P2 |

### 异常场景测试

| 编号 | 异常场景 | 模拟方式 | 预期行为 | 恢复验证 |
|------|---------|---------|---------|---------|
| TC-ERR-01 | GitHub API 不可达 | 断网或 DNS 屏蔽 github.com | 启动时检查失败静默，手动检查提示"无法连接" | 网络恢复后正常 |
| TC-ERR-02 | GitHub API 限流 (403) | 短时间大量检查请求 | 提示"检查过于频繁"，等待后重试 | 等待后正常 |
| TC-ERR-03 | 更新下载中断 | 下载 50% 断网 | 提示"下载失败"，支持断点续传或重试 | 恢复网络后重新下载成功 |
| TC-ERR-04 | 更新下载速度极慢 | 限速网络 (< 50KB/s) | 显示进度但速度慢，不卡死 UI | 无 |
| TC-ERR-05 | 磁盘空间不足 | 剩余 < 安装包大小 | 下载前检查空间，提示"磁盘空间不足" | 清理后重试 |
| TC-ERR-06 | 安装包 hash 校验失败 | 下载中篡改文件 | 校验失败，拒绝安装，提示重新下载 | 重新下载成功 |
| TC-ERR-07 | 更新器被防病毒拦截 | Windows Defender 隔离 updater.exe | 提示"更新程序被拦截，请加入白名单" | 解除拦截后正常 |
| TC-ERR-08 | macOS 更新后首次启动缓慢 | macOS 首次打开新版本 | Gatekeeper 验证 + 启动，不卡死 | 仅首次慢 |
| TC-ERR-09 | 更新过程中应用被杀 | Kill Pot 进程 → updater 仍在运行 | updater 独立完成替换，下次启动为新版 | 正常启动为新版 |

## 四、性能基准测试

| 编号 | 测试场景 | 测量指标 | 基准值 | 劣化阈值 | 测试工具 |
|------|---------|---------|--------|---------|---------|
| TC-PERF-01 | 更新检查 API 耗时 | GitHub Release API 请求 | ≤ 3s | > 10s | 含网络延迟 |
| TC-PERF-02 | 更新检查不阻塞启动 | 启动到可交互时间差 | ≤ 100ms 影响 | > 500ms | 对比启用/禁用自动检查 |
| TC-PERF-03 | 下载速度 | 100MB 更新包下载 | GitHub CDN 正常速率 | < 100KB/s | 网络稳定环境 |
| TC-PERF-04 | 安装替换时间 | 关闭到新版本启动 | ≤ 30s | > 2min | macOS/Windows/Linux |
| TC-PERF-05 | 更新窗口渲染 | 窗口打开到内容显示 | ≤ 500ms | > 1s | 含 changelog 解析 |
| TC-PERF-06 | 启动时更新检查内存 | check_update 内存增量 | ≤ 5MB | > 20MB | 对比检查前后 |

## 五、安全测试

| 编号 | 测试项 | 测试方法 | 预期结果 | 优先级 |
|------|--------|---------|---------|--------|
| TC-SEC-01 | 更新清单 HTTPS | 抓包检查更新请求 | 仅 HTTPS 请求 GitHub API | P0 |
| TC-SEC-02 | 下载包 HTTPS | 抓包检查下载请求 | 仅 HTTPS 下载更新包 | P0 |
| TC-SEC-03 | 更新包签名校验 | 篡改签名 → 安装 | 拒绝安装 | P0 |
| TC-SEC-04 | 更新包 hash 校验 | 比对下载后 SHA256 | 不匹配拒绝安装 | P0 |
| TC-SEC-05 | 不允许降级攻击 | 服务端返回低版本 | 忽略低版本更新 | P1 |
| TC-SEC-06 | 更新器不请求多余权限 | 检查 updater 所需权限 | 仅文件读写 + 进程管理权限 | P2 |
| TC-SEC-07 | 更新过程中配置文件不丢失 | 更新 → 检查 ~/.pot/ 配置 | 配置文件完整保留 | P1 |
| TC-SEC-08 | GitHub Release API 鉴权 | 公共仓库无需 token | 不泄露任何 token | P1 |
