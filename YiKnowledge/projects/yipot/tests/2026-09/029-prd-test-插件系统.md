# 插件与服务系统 — 测试方案

> **文档职责**：本文档定义插件架构 (翻译/OCR/TTS/生词本四类) 和服务配置管理的完整验证方案。

---

## 测试分层

| 层级 | 工具 | 覆盖 |
|------|------|------|
| L1 单元 | Vitest | 插件接口规范校验、info.ts 解析 |
| L2 集成 | Vitest + Tauri mock | 插件安装/卸载/启用流程、配置注册 |
| L3 E2E | 手动测试 | 完整插件生命周期、拖拽排序 |
| L4 平台兼容 | 真机测试 | macOS/Windows/Linux 插件目录与加载 |

---

## 一、插件架构核心用例

### TC-PLUG-01: 内置插件校验

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 启动 Pot，打开设置页 | — |
| 2 | 查看翻译插件列表 | 12 个内置翻译插件全部显示 (百度/腾讯/阿里/Google/DeepL/OpenAI/有道/Caiyun/Bing/Papago/LibreTranslate/火山) |
| 3 | 查看 OCR 插件列表 | 4 个 OCR 插件显示 (百度精准/百度通用/合合信息/系统 OCR) |
| 4 | 查看 TTS 插件列表 | 3 个 TTS 插件显示 (百度/腾讯/Azure) |
| 5 | 查看生词本插件列表 | 2 个插件显示 (Anki/欧路词典) |

### TC-PLUG-02: 插件接口规范 (info.ts + index.jsx + Config.jsx)

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 按规范创建翻译插件 (含 info.ts) | — |
| 2 | info.ts 包含 name/version/author/type | 解析正确 |
| 3 | 拖拽插件目录到设置页 | 安装成功，自动注册到翻译服务列表 |
| 4 | Config.jsx 渲染 | 配置界面自动出现在设置页中 |

### TC-PLUG-03: 插件安装/卸载

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 安装第三方翻译插件 A | 插件 A 出现在服务列表，状态"已启用" |
| 2 | 禁用插件 A | 插件 A 状态变为"已禁用"，翻译时跳过 |
| 3 | 重新启用插件 A | 插件 A 状态恢复"已启用" |
| 4 | 卸载插件 A | 提示"是否同时删除配置数据？" |
| 5 | 确认卸载 | 插件 A 从列表中移除，配置清理 |

### TC-PLUG-04: 插件隔离性

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 安装插件 B (故意注入异常代码) | — |
| 2 | 触发翻译 | 插件 B 报错但不影响其他插件 |
| 3 | 检查其他翻译插件结果 | 正常返回结果 |

## 二、服务配置管理用例

### TC-CONFIG-01: 服务实例独立配置

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 为百度翻译配置 API Key "key-a" | 百度翻译配置保存 |
| 2 | 为 Google 翻译配置 API Key "key-b" | Google 翻译配置独立保存 |
| 3 | 重启 Pot | 两个 API Key 均正确恢复 |

### TC-CONFIG-02: 多账号切换 (同服务多实例)

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 为百度翻译创建实例"个人账号"，填入 Key-A | 实例创建成功 |
| 2 | 为百度翻译创建实例"公司账号"，填入 Key-B | 两个实例均显示 |
| 3 | 翻译时选择"个人账号" | 使用 Key-A 调用 |
| 4 | 翻译时选择"公司账号" | 使用 Key-B 调用 |

### TC-CONFIG-03: 服务优先级拖拽排序

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 在设置页看到翻译服务列表 (百度第1, Google第2) | 当前排序正确显示 |
| 2 | 拖拽 Google 到第 1 位 | 排序变更为 Google第1, 百度第2 |
| 3 | 重启 Pot | 排序持久化，Google 仍为第1位 |
| 4 | 翻译时并行查询 | 结果按新优先级排序展示 |

### TC-CONFIG-04: 禁用服务不参与并行查询

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 启用百度、Google、有道翻译 | 3 个服务均启用 |
| 2 | 禁用 Google 翻译 | Google 置灰不可用 |
| 3 | 触发翻译 | 仅百度+有道参与并行，Google 跳过 |

## 三、边界与异常测试

| 编号 | 异常场景 | 模拟方式 | 预期行为 | 恢复验证 |
|------|---------|---------|---------|---------|
| TC-ERR-01 | 插件缺少 info.ts | 创建仅有 index.jsx 的插件目录 | 安装失败，提示"插件格式不正确：缺少 info.ts" | 补全 info.ts 后安装成功 |
| TC-ERR-02 | 插件版本不兼容 | info.ts 声明 `minAppVersion: "3.1.0"`，当前 3.0.7 | 提示"插件要求 Pot >= v3.1.0" | 升级 Pot 后安装成功 |
| TC-ERR-03 | 同名插件已安装 | 安装与已有插件同名的插件 | 提示"插件已安装，是否覆盖？" | 覆盖后旧版本备份 |
| TC-ERR-04 | info.ts JSON 格式错误 | info.ts 含语法错误 | 安装失败，显示具体错误行号 | 修复后安装成功 |
| TC-ERR-05 | API Key 为空时查询 | 某翻译服务未配置 API Key | 该服务跳过查询，自动置灰 | 配置 Key 后恢复 |
| TC-ERR-06 | 卸载插件配置残留 | 卸载插件时不勾选删除配置 | 配置保留 30 天 | 30 天内重新安装恢复配置 |
| TC-ERR-07 | 拖拽排序原子性 | 拖拽过程中取消 | 排序回滚到拖拽前状态 | 仅在确认后持久化 |

## 四、性能基准测试

| 编号 | 测试场景 | 测量指标 | 基准值 | 劣化阈值 | 测试方法 |
|------|---------|---------|--------|---------|---------|
| TC-PERF-01 | 单插件加载时间 | 动态 import 耗时 | ≤ 100ms | > 200ms | 动态 import 计时 |
| TC-PERF-02 | 设置页插件列表渲染 (20 插件) | 首屏渲染 | ≤ 200ms | > 500ms | React Profiler |
| TC-PERF-03 | 插件安装包大小 | 不含语言包 | ≤ 500KB | > 1MB | 构建产物检查 |
| TC-PERF-04 | 新增翻译插件时间 | 有 API 文档时 | ≤ 3 分钟 | > 5 分钟 | 开发者实测 |
| TC-PERF-05 | 配置持久化延迟 | 修改到写盘 | ≤ 50ms | > 100ms | 修改配置→检查磁盘 |

## 五、安全测试

| 编号 | 测试项 | 测试方法 | 预期结果 | 优先级 |
|------|--------|---------|---------|--------|
| TC-SEC-01 | 第三方插件 API Key 加密 | 安装带 API Key 的第三方插件后检查磁盘 | Key 与核心服务的 Key 共用 AES-256 加密方案 | P0 |
| TC-SEC-02 | 插件沙箱限制 | 安装恶意插件尝试访问文件系统 | 网络/文件系统访问受 Tauri CSP 限制 | P1 |
| TC-SEC-03 | 插件卸载清理 | 卸载插件后检查磁盘残留 | 所有插件文件和配置完全清除 | P1 |
