# 剪切板监听状态使用字符串布尔值比较

---

## 一、现象

> **一句话描述**：`ClipboardMonitorEnableWrapper` 使用 `Mutex<String>` 存储布尔状态，通过 `contains("true")` 判断是否启用，类型不安全且易出错。

---

## 二、复现步骤

1. 查看 `src-tauri/src/clipboard.rs:5` — `pub struct ClipboardMonitorEnableWrapper(pub Mutex<String>)`
2. 查看 `src-tauri/src/main.rs:124-126` — 初始化时使用 `clipboard_monitor.to_string()`
3. 查看 `src-tauri/src/clipboard.rs:14` — 判断逻辑 `clipboard_monitor.contains("true")`

---

## 三、根因分析

**问题代码**：

```rust
// clipboard.rs:5
pub struct ClipboardMonitorEnableWrapper(pub Mutex<String>);

// clipboard.rs:14
if clipboard_monitor.contains("true") {

// main.rs:124-126
app.manage(ClipboardMonitorEnableWrapper(Mutex::new(
    clipboard_monitor.to_string(),  // bool → String 转换
)));
```

**根因**：最初设计时可能因跨线程共享的便利性使用了 `String`，但布尔状态应用 `bool` 类型表达。`contains("true")` 无法区分 `"truexxx"` 等边界情况。

---

## 四、修复方案

将 `Mutex<String>` 改为 `Mutex<bool>`：

**修复后**：

```rust
// clipboard.rs
pub struct ClipboardMonitorEnableWrapper(pub Mutex<bool>);

if *enabled { ... }  // 直接布尔判断

// main.rs
app.manage(ClipboardMonitorEnableWrapper(Mutex::new(clipboard_monitor)));
```
