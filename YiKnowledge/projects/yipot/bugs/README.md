## Bug 生命周期

```
发现 Bug
  │
  ▼
[待确认] ───── 提交 Bug Report (使用模板)
  │
  │ 维护者复现确认
  ▼
[已确认] ───── 分配优先级 (P0/P1/P2/P3) 和处理人
  │
  │ 开发修复
  ▼
[修复中] ───── 开发分支修复 + 测试
  │
  │ PR 合并到 dev
  ▼
[已修复] ───── 等待版本发布
  │
  │ 版本发布
  ▼
[已发布] ───── 在 Release Notes 中标记修复
  │
  │ 验证修复 + 7天无复发
  ▼
[已关闭] ───── 归档到 bug 分类目录

侧路径:
[待确认] → [不予处理]  不修（wontfix）/ 不可复现 / 设计如此
[已确认] → [不予处理]  评估后决定不修
```

## 状态工作流详解

| 当前状态 | 可流转到 | 触发条件 | 操作人 |
|---------|---------|---------|--------|
| 待确认 | 已确认 | 维护者成功复现 | 维护者 |
| 待确认 | 不予处理 | 不可复现/设计如此/重复 | 维护者 |
| 已确认 | 修复中 | 开始开发 | 开发者 |
| 已确认 | 不予处理 | 评估后不修 | 维护者 |
| 修复中 | 已修复 | PR 已合并到 dev | 开发者 |
| 已修复 | 已发布 | 版本正式发布 | 维护者 |
| 已发布 | 已关闭 | 7天无复发 + 用户确认 | 维护者 |

## 严重程度与响应SLA

| 级别 | 响应时间 | 修复目标 | 说明 |
|------|---------|---------|------|
| P0 阻断 | 4小时内 | 24小时（hotfix） | 核心功能完全不可用 |
| P1 严重 | 24小时内 | 下个版本 | 主要功能受影响 |
| P2 一般 | 7天内 | 2个版本内 | 次要功能异常 |
| P3 轻微 | 无强制 | 随便修 | UI瑕疵、体验问题 |

## Bug 报告指南

### 好的 Bug 报告包含

1. **精确的标题**: `[平台] [模块] 简短描述`
   - 好: `[macOS] 截图OCR翻译后结果窗口不弹出`
   - 差: `翻译功能坏了`

2. **最小复现步骤**: 列表形式，每一步可执行
   - 好:
     1. 打开 Pot
     2. 选中一段中文文本
     3. 按 Ctrl+Shift+Q（截图翻译快捷键）
     4. 框选截图区域
     5. 观察结果窗口
   - 差: 选中文本翻译不行

3. **预期 vs 实际行为**: 清晰对比
   - 预期: 弹出翻译窗口显示翻译结果
   - 实际: 截图正常，窗口未弹出，无任何提示

4. **环境信息**: 完整（见模板的环境信息部分）

5. **日志附件**: 相关日志文件（路径见[调试排错](../workflows/操作指南/03-指南-调试排错.md#六日志位置)）

### 不好的 Bug 报告特征

- 标题模糊（"有问题"、"不能用"）
- 无复现步骤（"有时候会这样"）
- 无环境信息（不同平台表现可能完全不同）
- 包含主观评价（"这个设计太烂了"——bug报告不是产品讨论）
- 混合多个问题（一个report只描述一个问题）

### Bug 报告自检清单

提交前请确认：
- [ ] 搜索了已有 Bug（避免重复报告）
- [ ] 使用了 Bug 模板
- [ ] 包含了操作系统版本和 Pot 版本
- [ ] 列出了详细的复现步骤
- [ ] 描述了预期行为和实际行为
- [ ] 描述了问题频率（always/sometimes/once）
- [ ] 附上了相关日志（如有）
- [ ] 附上了截图/录屏（如有）
