# YP-09-S03: 剪切板监听与自动化

> 需求编号：YP-09-S03 · 优先级：P1 · 人天：1.0d · 状态：已完成

## 背景

剪切板监听模式允许用户无需按快捷键，复制文本后自动翻译，提升阅读外文资料的效率。

## 需求

### Rust 剪切板监控

`clipboard.rs` — 后台线程轮询剪切板：

```rust
// ClipboardMonitor 定期检查剪切板内容
// 内容变化 → 触发前端翻译事件
pub fn start_clipboard_monitor(app_handle: &AppHandle) { ... }
```

### 功能要点

- 一键开启/关闭监听
- 监听状态持久化（`clipboard_monitor` 配置项）
- 仅监听文本内容，忽略图片/文件
- 去重检测：相同内容不重复翻译

### 前端交互

- 翻译窗口顶部显示监听状态指示灯
- 点击指示灯切换监听状态
- 监听模式下的翻译结果实时更新

## 验收标准

- [ ] 开启监听后复制文本自动翻译
- [ ] 关闭监听后不再触发翻译
- [ ] 相同内容不重复翻译
- [ ] 重启应用后监听状态保持
- [ ] 不监听图片/文件剪切板内容

## 用户画像与使用场景

### 典型用户

| 画像 | 角色 | 核心诉求 | 使用频率 |
|------|------|---------|---------|
| 外文资料连续阅读者 | 浏览大量英文网页/PDF | 连续复制多段文本，自动翻译无需反复按快捷键 | 日均 30+ 次触发 |
| 批量翻译者 | 翻译大量文档段落 | 开启监听后专注阅读，翻译自动完成 | 单次任务 50+ 次 |

### 使用场景

1. **连续阅读模式**: 用户在 Safari 阅读长英文文章 → 开启剪切板监听 → 每复制一段，Pot 自动翻译 → 期望: 不打断阅读心流，翻译结果实时更新
2. **临时关闭**: 用户复制密码/敏感信息 → 暂时关闭监听 → 再开启 → 期望: 一键切换，状态指示清晰
3. **跨应用复制**: 用户从 PDF 复制 → 切换回浏览器 → 翻译结果已在 Pot 窗口显示 → 期望: 无需切换窗口查看翻译

## 边界条件与异常处理

| 输入条件 | 分类 | 预期行为 | 降级策略 |
|---------|------|---------|---------|
| 剪切板内容 > 5000 字符 | 边界 | 截断至 5000，翻译截断部分 | 与划词翻译截断策略一致 |
| 剪切板为富文本/HTML | 边界 | 提取纯文本内容后翻译 | 忽略格式标签 |
| 连续快速复制（< 100ms 间隔） | 边界 | 取最后一次复制内容，防抖处理 | 300ms 防抖 |
| 剪切板权限未授予 | 异常 | macOS 提示"需要辅助功能权限" | — |
| Rust 剪切板监控线程 panic | 异常 | 自动重启监控线程 | 最多重启 3 次，失败提示用户 |
| 监听中 Pot 窗口关闭 | 边界 | 监听状态持久化，下次启动恢复 | — |

## 各平台剪切板行为差异

| 平台 | 剪切板 API | 轮询间隔 | 文本获取 | 限制 |
|------|-----------|---------|---------|------|
| macOS | NSPasteboard (via Rust) | 500ms | changeCount 变化检测 | 辅助功能权限可能需要 |
| Windows | GetClipboardData (via Rust) | 500ms | ClipboardSequenceNumber 变化检测 | 无特殊限制 |
| Linux (X11) | x11-clipboard (via Rust) | 500ms | selection owner 变化检测 | X11 剪切板机制 (3 个 selection) |
| Linux (Wayland) | wl-clipboard / wlr-data-control | 500ms | 通过协议监听 | 需要 compositor 支持 |

### 平台特殊处理

- **macOS**: 辅助功能权限未授权时，监听功能禁用
- **Linux X11**: 同时监听 PRIMARY (选中) 和 CLIPBOARD (Ctrl+C) 两个 selection
- **Linux Wayland**: 部分 compositor 无剪切板协议支持，功能可能不可用
- **Windows**: UWP 应用可能无法获取剪切板文本（沙箱限制）
