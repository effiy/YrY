# YiPot 划词翻译软件 — 全面需求总览

> 需求编号：YP-09-M01 · 版本：v3.0.7 · 平台：Windows / macOS / Linux

> **文档职责**：本文档定义**要做什么、为什么做、做到什么程度算完成**（WHAT / WHY），不含实现方案与测试用例。

## 0. 文档概述

YiPot（Pot）是一款跨平台的划词翻译桌面应用，基于 Tauri 框架构建，使用 React 作为前端、Rust 作为系统后端。支持多接口并行翻译、OCR 文字识别、语音合成和生词本导出，并通过插件系统实现服务扩展。

### 核心能力矩阵

| 板块 | 核心能力 | 优先级 |
|------|---------|--------|
| 翻译引擎 | 划词翻译、输入翻译、剪切板监听、多接口并行 | P0 |
| 文字识别 | 截图 OCR、截图翻译、系统 OCR 集成 | P0 |
| 语音合成 | 多接口 TTS、朗读翻译结果 | P1 |
| 生词本 | Anki/欧路词典导出、词汇收藏 | P1 |
| 插件系统 | 翻译/OCR/TTS/生词本插件扩展 | P1 |
| 桌面集成 | 全局快捷键、系统托盘、窗口管理、开机启动 | P0 |
| 国际化 | 20+ 语言支持、RTL 布局 | P2 |
| 数据管理 | 配置备份恢复、WebDAV/阿里云同步 | P2 |

<a id="sec-1"></a>
## 一、翻译引擎（FR-1）

### 1.1 划词翻译

- 鼠标选中任意应用中的文本
- 按下全局快捷键触发翻译
- 弹出翻译结果浮窗，显示原文与译文
- 支持多接口并行查询，结果并排展示

### 1.2 输入翻译

- 快捷键呼出翻译窗口
- 手动输入或粘贴待翻译文本
- 支持语言自动检测
- 按 Enter 触发翻译

### 1.3 剪切板监听模式

- 在翻译面板上启动剪切板监听
- 复制任意文本自动触发翻译
- 无需额外快捷键操作

### 1.4 多接口并行翻译

- 同时查询多个翻译服务
- 结果以选项卡或并排方式展示
- 支持的接口包括：百度、腾讯、阿里、Google、DeepL、OpenAI 等 20+

<a id="sec-2"></a>
## 二、文字识别（FR-2）

### 2.1 截图 OCR

- 快捷键触发截图模式
- 框选屏幕任意区域
- 调用 OCR 服务识别文字
- 识别结果可复制或二次翻译

### 2.2 截图翻译

- 截图后直接对识别文字进行翻译
- 支持在 OCR 结果上叠加翻译

### 2.3 系统 OCR 集成

- macOS: 使用系统 Vision 框架
- Windows: 使用 Windows OCR API
- 离线可用，无需网络

## 七、产品愿景与市场定位

### 7.1 产品愿景

> **让每个人在任何应用中、用任何语言、以任何方式获取信息时，翻译都像呼吸一样自然。**

YiPot 的使命是成为桌面翻译的"瑞士军刀"——不绑定任何单一翻译服务商，不限定任何使用场景（文字/图片/语音），不强制任何付费模式。用户拥有完全的控制权：选择服务、配置快捷键、定制外观、保护隐私。

**核心设计哲学：**

| 原则 | 含义 | 对手的反例 |
|------|------|-----------|
| **服务商中立** (Vendor Agnostic) | 不绑定翻译引擎，用户自选服务、自带 API Key | DeepL Desktop 仅支持自家引擎 |
| **场景全覆盖** (Omni-Scenario) | 文字/图片/语音三种输入形态全支持 | Bob 不支持 TTS；沙拉查词不支持 OCR |
| **开源透明** (Open Source) | 代码完全开放，隐私可审计，无遥测 | 市面多数竞品闭源，用户无法验证隐私承诺 |
| **插件可扩展** (Plugin-Extensible) | 翻译/OCR/TTS/生词本四大类插件，社区贡献 | 沙拉查词仅支持翻译接口扩展 |
| **跨平台一致** (Cross-Platform) | Windows/macOS/Linux 功能对等，体验一致 | Bob 仅 macOS；DeepL Desktop 不完整支持 Linux |

### 7.2 市场定位

YiPot 占据桌面翻译工具矩阵中的**开源全能型**象限：

```
                功能广度
                   ▲
      Bob        ─│─  YiPot ← 本产品
   (macOS 精品)   │  (开源全能)
                   │
  ─────────────────┼──────────────────→ 服务商开放度
                   │
  沙拉查词          │  DeepL Desktop
  (浏览器扩展)      │  (厂商绑定)
                   │
```

**竞品对比总表：**

| 维度 | YiPot | Bob | 沙拉查词 | DeepL Desktop | CopyTranslator | Immersive Translate |
|------|-------|-----|---------|---------------|----------------|---------------------|
| **价格** | 免费开源 | 免费 (macOS) | 免费开源 | 免费+订阅 | 免费开源 | 免费+订阅 |
| **平台** | Win/Mac/Linux | 仅 macOS | 浏览器扩展 | Win/Mac | Win/Mac/Linux | 浏览器扩展 |
| **翻译引擎数** | 20+ (插件可扩) | 10+ | 8+ | 仅 DeepL | 5+ | 10+ |
| **OCR** | 系统+云 OCR | 系统+云 OCR | 无 | 无 | 无 | 无 |
| **TTS** | 多接口 | 系统 TTS | 无 | 无 | 无 | 无 |
| **离线翻译** | Ollama+系统OCR | 系统 OCR | 无 | 仅付费版 | 无 | 无 |
| **插件系统** | 4 类插件 | 有限扩展 | 接口扩展 | 无 | 无 | 有限 |
| **全局快捷键** | 4 组可自定义 | 4 组 | 依赖浏览器 | 2 组 | 3 组 | 依赖浏览器 |
| **生词本** | Anki+欧路导出 | 无 | 生词本 | 无 | 无 | 无 |
| **剪切板监听** | 支持 | 支持 | 浏览器内 | 支持 | 核心功能 | 浏览器内 |
| **开机启动** | 支持 | 支持 | 不适用 | 支持 | 支持 | 不适用 |
| **隐私** | 完全本地，开源可审计 | 闭源 | 开源 | 闭源，遥测 | 开源 | 闭源 |
| **国际化** | 22 种语言 | 中文为主 | 中英 | 有限 | 中英 | 10+ |
| **社区生态** | 插件市场 | 社区小 | 社区活跃 | 无 | 社区小 | 社区活跃 |

### 7.3 差异化优势总结

1. **唯一同时支持 OCR + TTS + 生词本的开源桌面翻译工具**——竞品最多覆盖其中 1-2 项
2. **唯一支持 Linux 的完整功能翻译工具**——多数竞品放弃 Linux 或功能残缺
3. **插件架构使翻译能力无上限**——任何 API 翻译服务均可由社区快速接入，不依赖核心团队
4. **离线能力矩阵**：系统 OCR + Ollama 本地 LLM 翻译 = 真正离线可用的完整翻译链

## 八、用户旅程地图

### 8.1 旅程一：首次使用 (First-Time User)

```
阶段:   发现        获取        安装        授予权限      首次翻译      形成习惯
       ────→      ────→      ────→      ────→        ────→        ────→
```

| 阶段 | 用户行为 | 触点 | 用户想法 | 情绪 | 痛点 | 机会点 |
|------|---------|------|---------|------|------|--------|
| **发现** | 在 GitHub Trending/V2EX/知乎看到 YiPot 推荐 | GitHub Release 页 | "又一个翻译工具？有什么特别？" | 好奇→怀疑 | 竞品太多，难以区分 | README 用动图展示核心功能 10 秒抓住注意力 |
| **获取** | 访问 Release 页面，选择对应平台安装包 | GitHub Release / 官网 | "Windows 版在哪？怎么这么多文件？" | 轻度困惑 | 多平台文件混杂，非技术用户不知选哪个 | 提供平台自动检测 + 一键下载按钮 |
| **安装** | 下载 .dmg/.msi/.AppImage，拖拽安装 | 操作系统安装器 | "不会有病毒吧？" | 轻度焦虑 | macOS 未签名提示"无法验证开发者" | 提供代码签名 + 安装引导，告知用户如何信任 |
| **授予权限** | 首次启动 → 系统弹出辅助功能/屏幕录制权限请求 | macOS 隐私设置 / Windows UAC | "为什么要这些权限？" | 警惕 | 用户不理解权限用途而拒绝，导致功能不可用 | 权限引导页解释每个权限的用途 + 截图指引 |
| **首次翻译** | 选中一段英文 → 按下默认快捷键 → 看到翻译弹窗 | 翻译浮窗 | "真的能用了！还挺快" | 惊喜→满意 | 如果网络不好或没配 API Key，翻译失败 | 预置免费接口（如 Google 翻译免 Key）+ 失败友好提示 |
| **形成习惯** | 2-3 天内多次使用 → 决定保留 | 系统托盘 | "每天都要用，开机自启吧" | 依赖 | 忘记设置开机启动，次日需要手动打开 | 首次使用第 3 次后，托盘气泡提醒"设置开机启动？" |

**首次使用关键指标：**
- 从下载到首次成功翻译 ≤ 5 分钟
- 权限授予成功率 ≥ 85%（有引导 vs 无引导对比）
- 次日留存率 ≥ 40%

```
时间线:  开机        上午工作       午休        下午工作       下班

```

| 阶段 | 用户行为 | 触点 | 用户期望 | 情绪 | 潜在中断 | 恢复策略 |

## 十、边界条件与异常处理总览

### 10.1 系统级边界条件矩阵

以下边界条件跨越多个功能模块，是架构设计中需统一处理的系统级问题。

| 编号 | 边界条件 | 影响模块 | 当前行为 | 期望行为 | 严重程度 | 处理状态 |
|------|---------|---------|---------|---------|---------|---------|
| E-01 | **首次启动 - 无任何配置** | 全模块 | 使用默认配置，翻译服务列表为空 | 显示引导页，自动检测系统语言→预填源/目标语言，预启用"Google 翻译(免费)"作为默认接口 | 中 | 部分实现 |

| E-03 | **所有翻译服务不可用** (无网络+无已配置服务) | FR-1 | 翻译失败，显示错误 | 明确提示"无可用翻译服务" + 建议检查网络 + 提示配置离线翻译(Ollama) + 不显示空白窗口 | 高 | 需改善 |
| E-04 | **网络恢复后的服务状态** | FR-1, FR-3 | 各服务独立重试，无统一协调 | 网络恢复事件触发一次服务可用性探测，批量恢复失败的服务状态 | 中 | 未实现 |

| E-06 | **OS 锁屏→解锁** | FR-5 | 解锁后快捷键正常工作 (Windows/macOS)，Wayland 可能失效 | 同 E-05 处理逻辑 | 中 | 需验证 |

### 10.2 权限缺失的渐进式降级

当用户未授予某项权限时，系统应优雅降级而非完全不可用：

```
权限检查流程图:

辅助功能权限 (划词取词)
  ├── 已授予 → 划词翻译正常工作
  └── 未授予 → 降级方案:
        ├── 剪切板监听模式 仍可用 (用户手动复制)
        ├── 输入翻译 仍可用 (打开窗口手动输入)
        └── 首次使用提示权限 + 后续托盘定期提醒

屏幕录制权限 (截图 OCR)
  ├── 已授予 → 截图 OCR 正常工作
  └── 未授予 → 降级方案:
        ├── 提示用户使用系统截图工具 → 剪切板读取
        └── 翻译 (非 OCR) 功能完全不收影响

全局快捷键权限
  ├── 正常 → 所有快捷键可用
  └── 冲突/被占用 → 降级方案:
        ├── 托盘菜单手动触发各功能
        ├── 剪切板监听替代划词翻译
        └── 冲突检测提示 → 引导修改快捷键
```

### 10.3 翻译请求失败的分级处理

| 失败类型 | 重试策略 | 用户体验 | 日志级别 |
|---------|---------|---------|---------|
| 网络超时 (≥ 5s) | 同接口重试 1 次,间隔 2s | "请求超时，正在重试..." → 还是失败 → "网络不稳定，已切换到备用接口" | WARN |
| HTTP 4xx (鉴权失败) | 不重试 | "API Key 无效，请在偏好设置中更新" + 跳转按钮 | ERROR |
| HTTP 429 (限流) | 退避重试 3 次: 1s, 2s, 4s | "请求过于频繁，稍后重试" → 3 次后 → "今日请求次数已达上限" | WARN |
| HTTP 5xx (服务端错误) | 切换备用接口 (不重试同接口) | 其他并行接口的结果正常展示，静默丢弃异常接口 | ERROR |
| 响应解析失败 | 不重试 | 同 HTTP 5xx 处理 | ERROR |
| DNS 解析失败 | 不重试 | "无法连接翻译服务，请检查网络" | ERROR |

## 十一、平台差异化需求

### 11.1 平台差异根源分析

YiPot 基于 Tauri 框架，理论上"一套代码、多端运行"。但系统层能力差异（取词API、OCR API、快捷键机制、窗口管理）决定了以下功能必须按平台实现。

| 差异根因 | Windows | macOS | Linux (X11) | Linux (Wayland) |
|---------|---------|-------|-------------|-----------------|
| **取词 API** | UI Automation / 剪贴板 | Accessibility API (AXUIElement) | X11 Selection/Clipboard | 无原生 API，需 XWayland 桥接 |
| **系统 OCR** | Windows.Media.OCR (WinRT) | Vision Framework (VNRecognizeText) | Tesseract (系统包) | Tesseract (系统包) |
| **系统 TTS** | SAPI5 / WinRT Speech | AVSpeechSynthesizer | speech-dispatcher | speech-dispatcher |
| **全局快捷键** | RegisterHotKey (Win32) | CGEvent / Carbon | X11 GrabKey | wlr-foreign-toplevel / 不稳定 |
| **窗口置顶** | WS_EX_TOPMOST | NSWindow.level = .floating | _NET_WM_STATE_ABOVE | 协议支持但不一致 |
| **系统托盘** | Shell_NotifyIcon | NSStatusBar | libappindicator / StatusNotifier | StatusNotifier |
| **开机启动** | 注册表 Run key / Startup 文件夹 | LaunchAgent plist | autostart .desktop | autostart .desktop |
| **安装格式** | .msi / .exe (NSIS/WiX) | .dmg (签名+公证) | .AppImage / .deb / .rpm | .AppImage / .deb / .rpm |
| **休眠管理** | WM_POWERBROADCAST | NSWorkspace.sleepNotification | logind / systemd-inhibit | logind / systemd-inhibit |

### 11.2 功能可用性矩阵

| 功能 | Windows 10+ | macOS 11+ | Linux (X11) | Linux (Wayland) | 备注 |

### 11.3 平台特定功能

| 平台 | 独占功能 | 原因 |
|------|---------|------|
| **macOS** | 系统 OCR 质量最高 (Vision 框架中英文识别优秀) | Apple 在 Vision 框架投入大，识别准确率优于 Windows OCR 和 Tesseract |
| **macOS** | 划词取词稳定性最好 | Accessibility API 成熟，所有应用默认支持 |
| **Windows** | UI Automation 可获取更丰富的文本上下文 | 可扩展实现"整句翻译"而非仅"选中词" |
| **Windows** | 触摸屏/手写笔优化 | Surface 等设备场景 |
| **Linux (X11)** | 完全控制窗口行为 (置顶/无边框等) | X11 协议灵活，不受 compositor 限制 |
| **Linux** | 通过包管理器安装 (.deb/.rpm) | 用户习惯 + 自动依赖管理 |
| **Linux (Wayland)** | 安全隔离更强 (应用间无法随意读取剪贴板) | Wayland 的安全模型 —— 这是限制也是特性 |

| **并行翻译** | Parallel Translation | 同时向多个翻译服务发送同一请求，并将所有结果并排或分选项卡展示。目的：对比不同服务的翻译质量，选择最优结果。 | FR-1.4 |
| **浮窗** | Popup Window / Floating Window | 翻译结果显示的弹出式窗口。特征：始终置顶、不抢夺键盘焦点、鼠标跟随定位、可拖拽。区别于主窗口（偏好设置）。 | FR-5.3 |
| **系统 OCR** | System OCR / Offline OCR | 使用操作系统内置的 OCR 能力（macOS Vision / Windows OCR API / Tesseract）进行文字识别，不需要网络连接。优点是隐私+离线可用，缺点是准确率通常低于云 OCR。 | FR-2.3 |
