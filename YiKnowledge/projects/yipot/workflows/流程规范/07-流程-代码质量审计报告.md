## 一、命名约定

### 1.1 `getServiceSouceType` 拼写错误

- **文件**：`src/utils/service_instance.ts:13`
- **影响**：42 个调用点，17 个文件
- **建议**：下个主版本统一重命名为 `getServiceSourceType`
- **风险**：无运行时影响；大规模重命名应作为独立 PR

### 1.2 `whetherPluginService` 命名不直观

- **文件**：`src/utils/service_instance.ts:21`
- **建议**：重命名为 `isPluginService` 符合布尔函数命名惯例

## 二、安全

### 2.1 `invoke_plugin.js` 使用 `eval()` 执行插件代码

- **文件**：`src/utils/invoke_plugin.js:35`
- **机制**：插件 `.potext` 文件中的 `main.js` 经 `readTextFile` 读入后直接 `eval()`
- **风险**：插件拥有完整应用权限（文件系统、网络、数据库）
- **现状**：此为 Pot 插件系统设计决策，与上游一致
- **缓解**：插件安装前需用户手动确认；插件来源应为可信渠道

### 2.2 API Key 明文存储

- **文件**：`tauri-plugin-store` 配置持久化
- **机制**：所有服务 API Key（OpenAI/DeepL/Baidu 等）存储在 `~/.config/com.pot-app.desktop/config.json` 明文 JSON
- **风险**：本地文件访问即可获取所有 API Key
- **现状**：已知限制（Bug #004），YiAi 后端集成可缓解（Key 存储在服务端）
- **建议**：使用平台密钥链（macOS Keychain / Windows Credential Manager / Linux libsecret）

---

## 三、架构

### 3.1 `env.js` 异步初始化空窗期

- **文件**：`src/utils/env.js`
- **机制**：`osType`/`arch`/`osVersion`/`appVersion` 作为 `export let` 变量，`initEnv()` 异步赋值
- **风险**：模块级导入方在 `initEnv()` 完成前读取到空字符串 `""`
- **现状**：`main.jsx` 保证 `initEnv()` 在 React 挂载前完成，20 个导入方均为组件内延迟读取，暂时安全
- **建议**：迁移为 `once_cell` 模式或 React Context

### 3.2 多窗口模块级状态模式

`Translate`/`Recognize` 窗口使用模块级变量（`blurTimeout`/`blurUnlisten`）共享窗口生命周期状态。在 Tauri 中每个窗口标签对应独立 webview，模式合理。但若未来支持同标签多实例（如多翻译窗口），需重构为组件级状态。
