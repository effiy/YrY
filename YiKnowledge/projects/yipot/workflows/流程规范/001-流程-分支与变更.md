# 分支与变更管理

> Git 分支策略、提交规范、PR 流程。

## 一、分支策略

```
main          — 稳定发布分支
  └── dev     — 开发分支
       └── feature/xxx  — 功能分支
       └── fix/xxx      — 修复分支
       └── release/x.x  — 发布分支
```

### 分支命名

| 类型 | 格式 | 示例 |
|------|------|------|
| 功能 | `feature/{描述}` | `feature/add-deepl-support` |
| 修复 | `fix/{描述}` | `fix/screenshot-macos-crash` |
| 发布 | `release/{版本}` | `release/3.0.8` |
| 热修复 | `hotfix/{描述}` | `hotfix/api-key-leak` |

## 二、提交规范

使用 Conventional Commits：

```
<type>(<scope>): <description>

[optional body]
```

### Type 类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat(translate): add DeepL service plugin` |
| `fix` | Bug 修复 | `fix(ocr): correct baidu accurate result parsing` |
| `docs` | 文档更新 | `docs(readme): update installation guide` |
| `style` | 代码格式 | `style: format with prettier` |
| `refactor` | 重构 | `refactor(hotkey): extract shortcut manager` |
| `perf` | 性能优化 | `perf(translate): parallel service calls` |
| `test` | 测试 | `test: add ocr service unit tests` |
| `chore` | 构建/工具 | `chore(deps): update tauri to 1.6.8` |
| `ci` | CI/CD | `ci: add linux arm64 build` |

### Scope 范围

| Scope | 说明 |
|-------|------|
| `translate` | 翻译功能 |
| `ocr` | OCR 功能 |
| `tts` | 语音合成 |
| `hotkey` | 快捷键 |
| `window` | 窗口管理 |
| `tray` | 系统托盘 |
| `config` | 配置管理 |
| `backup` | 备份功能 |
| `server` | HTTP 服务 |
| `i18n` | 国际化 |
| `theme` | 主题 |
| `build` | 构建系统 |

## 三、PR 流程

1. 从 `dev` 创建功能分支
2. 开发 + 自测
3. 提交 PR 到 `dev`
4. Code Review
5. 合并到 `dev`
6. 发布时合并 `dev` → `main` → 打 tag

### PR 描述模板

```markdown
## Summary
Brief description of changes.

## Changes
- Change 1
- Change 2

## Testing
- [ ] Tested on macOS
- [ ] Tested on Windows
- [ ] Tested on Linux

## Screenshots
(if UI changes)
```

## 四、版本号管理

格式: `MAJOR.MINOR.PATCH`

- **MAJOR**: 重大架构变更
- **MINOR**: 新功能添加
- **PATCH**: Bug 修复

同步更新：
- `package.json` → `version`
- `src-tauri/Cargo.toml` → `package.version`
- `src-tauri/tauri.conf.json` → `package.version`

## 补充：Code Review 检查清单

### 架构层面

- [ ] 变更是否遵循了项目架构模式（React → Tauri Bridge → Rust）
- [ ] 新增功能是否需要新窗口（如有，是否评估了内存开销）
- [ ] 是否有不必要的 Rust 模块依赖增加
- [ ] 是否引入了新的 npm/cargo 依赖（如有，评估体积和安全性）

### 功能正确性

- [ ] 翻译服务插件: 返回格式符合 `TranslateResult` 类型
- [ ] OCR 服务插件: 是否正确处理 base64 图片输入
- [ ] Rust command: 返回 `Result<T, String>` 格式
- [ ] 快捷键: 是否检查了与现有快捷键的冲突
- [ ] 窗口: 是否处理了多显示器/DPI缩放场景
- [ ] 配置: 读写是否正确处理了默认值和迁移

### 代码质量

- [ ] TypeScript: 无 `any` 类型，类型导出清晰
- [ ] React: 使用函数组件 + Hooks，无 class 组件
- [ ] Rust: 无 `unwrap()` 在生产代码中（使用 `?` 或 `map_err`）
- [ ] 错误处理: 用户可见的错误有明确的提示信息
- [ ] 日志: 关键路径有合适的日志级别（info/warn/error）

### 安全

- [ ] 无硬编码 API Key/Secret（通过 `needs` 配置传入）
- [ ] 无 eval() / new Function() 等动态代码执行
- [ ] 外部 fetch 请求 URL 是硬编码的服务商地址（非用户输入拼接）
- [ ] 文件操作路径做了基本校验（无路径遍历风险）

### 性能

- [ ] `useEffect` 依赖数组正确（无无限循环风险）
- [ ] 大对象（base64图片）使用后及时释放
- [ ] 列表渲染使用了合适的 key
- [ ] Rust 长时间操作使用了 `#[tauri::command(async)]`

### 测试

- [ ] 新插件: 有基本的信息结构验证
- [ ] 关键逻辑: 有单元测试（如翻译解析、OCR结果处理）
- [ ] 平台相关: 跨平台进行了差异化测试

### 文档

- [ ] CHANGELOG 条目已添加（如 applicable）
- [ ] 新增配置项有文档说明
- [ ] 新增服务在源码索引中已记录

## 补充：合并策略

### 合并方式选择

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| **Squash and Merge** | 功能分支（默认） | 干净的主分支历史 | 丢失分支内的细粒度提交 |
| **Rebase and Merge** | 修复分支（单提交） | 线性历史，无合并commit | 无法追溯PR中的讨论 |
| **Create a Merge Commit** | 多开发者协作分支 | 保留完整分支拓扑 | 历史较乱 |

**推荐策略**:
- `feature/*` → **Squash and Merge** (默认)
- `fix/*` → **Rebase and Merge** (单提交修复)
- `release/*` → **Create a Merge Commit** (保留拓扑以便追溯)
- `hotfix/*` → **Squash and Merge** (紧急修复需简洁)

### 合并前检查

```
合并条件（所有必须满足）:
├── CI 全部通过 (lint + typecheck + build)
├── 至少 1 个 Approve（核心模块需 2 个）
├── 无未解决的 Review 评论
├── 与 base 分支无冲突
└── 分支已同步 base 分支的最新提交

合并时机:
├── 周一至周四: 任意时间（周五下午避免合并大型 PR）
├── 临近发布: 仅合并 P0/P1 修复 → release 分支
└── 紧急修复: hotfix 分支直接合入 main，同步回 dev
```

### 分支保护规则

| 分支 | 保护规则 |
|------|---------|
| `main` | 禁止直接推送；PR 必须通过 review；CI 必须通过；必须 squash merge |
| `dev` | 禁止直接推送；PR 建议 review；CI 必须通过 |
| `release/*` | 创建时从 dev 分支；仅 cherry-pick P0/P1 修复 |
| `feature/*` | 无特殊保护；鼓励早期 PR draft |
| `hotfix/*` | 从 main 分支创建；合并回 main + dev |
