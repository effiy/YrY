# 调试排错

> 常见问题排查指南。包括快捷键、翻译、OCR、窗口、构建等问题。

## 一、快捷键问题

### 快捷键不生效

1. 检查是否有其他应用占用了相同的快捷键
2. 查看日志：快捷键注册成功的日志为 `Registered global shortcut: ...`
3. 检查 `config` 中快捷键配置是否为空（空 = 未注册）
4. macOS：检查辅助功能权限是否已授权
5. Linux：检查是否安装了 `libayatana-appindicator`

### 快捷键冲突

```
日志: Failed to register global shortcut: ...
→ 在设置页修改快捷键
→ 或关闭占用该快捷键的其他应用
```

## 二、翻译问题

### 翻译无响应

1. 检查网络连接
2. 检查 API Key 是否正确配置
3. 检查代理设置（如有）
4. 查看日志中的 HTTP 错误

### 特定服务不可用

1. 检查该服务的 API Key 是否过期
2. 检查配额是否用完
3. 查看该服务的 API 状态页

### Ollama 本地翻译不可用

```bash
# 检查 Ollama 是否运行
curl http://localhost:11434/api/tags

# 确保模型已下载
ollama list
```

## 三、OCR 问题

### 系统 OCR 不可用

- **macOS**: 需要 macOS 10.15+
- **Windows**: 需要 Windows 10+，需安装对应语言包
- **Linux**: 系统 OCR 不可用，使用 Tesseract.js 替代

### 截图异常

- macOS: 使用系统 `screencapture` 命令
- Win/Linux: 使用自定义截图窗口（全屏 + 选区）
- 截图失败查看 `screenshot.rs` 日志

## 四、窗口问题

### 翻译窗口不显示

1. 检查快捷键是否已注册
2. 检查是否有文本被选中
3. 查看 `window.rs` → `translate_window()` 日志

### 窗口位置异常

1. 删除窗口位置配置（`translate_window_position_x/y`）
2. 下次打开将使用默认位置

### macOS 窗口无阴影

- 检查 `set_shadow` 调用（非 Linux 平台自动设置）

## 五、构建问题

### Rust 编译失败

```bash
# 清理缓存
cargo clean
cargo build

# 更新依赖
cargo update
```

### pnpm 安装失败

```bash
# 清理并重装
rm -rf node_modules pnpm-lock.yaml
pnpm install
```

### macOS 签名失败

```bash
# 检查证书
security find-identity -v -p codesigning
```

## 六、日志位置

| 平台 | 路径 |
|------|------|
| macOS | `~/Library/Logs/com.pot-app.pot/` |
| Windows | `%APPDATA%/com.pot-app.pot/logs/` |
| Linux | `~/.local/share/com.pot-app.pot/logs/` |

1. 操作系统版本
2. Pot 版本号
3. 相关日志文件
4. 问题复现步骤
5. 截图/录屏

## 补充：更多排错场景

### 翻译结果为空但API返回正常

**根因**: 翻译插件的响应解析路径错误。

```javascript
// 调试步骤
// 1. 在 index.jsx 中临时输出 raw 响应
export default async function translate(text, from, to, options) {
  const response = await fetch(API_URL, { /* */ });
  const data = await response.json();
  console.log("RAW RESPONSE:", JSON.stringify(data, null, 2)); // 临时调试行
  return {
    text: data.translation, // 检查这个路径是否正确！
    // ...
  };
}

// 2. 对比API文档，确认字段路径
// 百度翻译: data.trans_result[0].dst
// 有道翻译: data.translation[0]
// DeepL: data.translations[0].text
// OpenAI: data.choices[0].message.content
```

### 应用启动闪退

排查顺序：
1. **检查日志**: 查看平台特定日志文件（见"日志位置"）
2. **检查环境**: `RUST_BACKTRACE=full pnpm tauri dev` 获取完整堆栈
3. **检查配置文件**: 删除 `config.json` 重试（可能是损坏的配置）
4. **检查依赖**: `pnpm install && cargo build` 确认所有依赖正常
5. **排查平台特定**:
   - macOS: 检查 `spctl --assess --verbose /Applications/Pot.app`（Gatekeeper状态）
   - Windows: 检查事件查看器 → Windows日志 → 应用程序
   - Linux: `ldd ./target/release/pot | grep "not found"` 检查缺失的 .so 文件

### 截图黑屏/白屏

| 平台 | 常见原因 | 解决方案 |
|------|---------|---------|
| macOS | 屏幕录制权限未授权 | 系统偏好设置 → 隐私与安全性 → 屏幕录制 → 添加 Pot |
| macOS | M芯片外接显示器兼容性 | 更新到最新版 Tauri 1.6.x+ |
| Windows | DPI缩放设置为>100% | `window.rs` 中做DPI感知适配 |
| Windows | 多个GPU（核显+独显） | 在显卡控制面板中将Pot指定到独显 |
| Linux | Wayland下截图黑屏 | 切换到X11或使用 `grim` 替代方案 |
| Linux | 没有 `xdg-desktop-portal` | `sudo apt install xdg-desktop-portal-gtk` |

### 剪贴板相关

```
剪贴板读取为空
├── macOS: 检查系统偏好设置 → 辅助功能权限
├── Linux: 检查是否在 Wayland 下（xclip 不支持 Wayland 剪贴板）
│   └── 替代: wl-clipboard
└── 所有平台: 检查是否在其他应用"独占"剪贴板时读取

剪贴板图片粘贴失败
├── 检查图片格式兼容性（PNG/JPEG 支持最好）
├── 检查图片大小（>50MB 的图片可能导致问题）
└── Linux: 需要安装 xclip 或 wl-clipboard
```

### Ollama 相关

```
Ollama 连接失败
├── 确认 Ollama 正在运行: curl http://localhost:11434/api/tags
├── 确认模型已下载: ollama list
├── 检查防火墙: 确保 11434 端口未被阻止
├── 确认模型支持翻译任务:
│   ├── 推荐: qwen2.5, llama3, gemma2
│   └── 不推荐: 纯 code 模型（如 codellama）
└── 超时调整: 默认60s，大模型首次推理可能超时
```

### NextUI 样式异常

```
NextUI 样式未加载
├── 确认 tailwind.config.js 中 NextUI plugin 已配置
├── 确认 main.jsx 中导入了 NextUIProvider
├── 检查是否覆盖了 NextUI 的 CSS 变量
└── 确认 @nextui-org/react 版本与 tailwindcss 版本兼容

RTL 布局异常（阿拉伯语/希伯来语）
├── 确认 html[dir="rtl"] 已设置
├── NextUI 2.4 已知问题: Select 组件 RTL 箭头偏移
└── 自定义 CSS: [dir="rtl"] .class { /* 翻转 */ }
```

## 补充：诊断脚本

将以下脚本保存为 `scripts/diagnose.sh`，运行后可自动收集诊断信息。

```bash
#!/bin/bash
# YiPot 诊断脚本 - 收集系统和应用信息用于 Bug 报告
OUTPUT_FILE="pot-diagnosis-$(date +%Y%m%d-%H%M%S).txt"

echo "=== YiPot Diagnosis Report ===" > $OUTPUT_FILE
echo "Generated: $(date)" >> $OUTPUT_FILE
echo "" >> $OUTPUT_FILE

# 系统信息
echo "--- System Info ---" >> $OUTPUT_FILE
echo "OS: $(uname -s)" >> $OUTPUT_FILE
echo "Arch: $(uname -m)" >> $OUTPUT_FILE

if [[ "$OSTYPE" == "darwin"* ]]; then
    echo "macOS: $(sw_vers -productVersion 2>/dev/null)" >> $OUTPUT_FILE
    echo "Xcode: $(xcodebuild -version 2>/dev/null | head -1)" >> $OUTPUT_FILE
elif [[ "$OSTYPE" == "linux-gnu"* ]]; then
    echo "Distro: $(cat /etc/os-release 2>/dev/null | grep PRETTY_NAME)" >> $OUTPUT_FILE
    echo "DE: $XDG_CURRENT_DESKTOP" >> $OUTPUT_FILE
    echo "Session: $XDG_SESSION_TYPE" >> $OUTPUT_FILE
    echo "Display: $DISPLAY" >> $OUTPUT_FILE
fi

echo "" >> $OUTPUT_FILE

# 依赖版本
echo "--- Dependencies ---" >> $OUTPUT_FILE
echo "Node: $(node --version 2>/dev/null)" >> $OUTPUT_FILE
echo "pnpm: $(pnpm --version 2>/dev/null)" >> $OUTPUT_FILE
echo "Rust: $(rustc --version 2>/dev/null)" >> $OUTPUT_FILE
echo "Cargo: $(cargo --version 2>/dev/null)" >> $OUTPUT_FILE
echo "" >> $OUTPUT_FILE

# 环境检查
echo "--- Environment Check ---" >> $OUTPUT_FILE
echo "RUST_LOG: ${RUST_LOG:-not set}" >> $OUTPUT_FILE
echo "TAURI_DEBUG: ${TAURI_DEBUG:-not set}" >> $OUTPUT_FILE

# macOS 特定
if [[ "$OSTYPE" == "darwin"* ]]; then
    echo "" >> $OUTPUT_FILE
    echo "--- macOS Permissions ---" >> $OUTPUT_FILE
    echo "Accessibility: $(sqlite3 /Library/Application\ Support/com.apple.TCC/TCC.db "SELECT allowed FROM access WHERE client='com.pot-app.pot' AND service='kTCCServiceAccessibility'" 2>/dev/null || echo 'check manually')" >> $OUTPUT_FILE
fi

# 应用日志（最近50行）
echo "" >> $OUTPUT_FILE
echo "--- App Logs (last 50 lines) ---" >> $OUTPUT_FILE
if [[ "$OSTYPE" == "darwin"* ]]; then
    LOG_DIR="$HOME/Library/Logs/com.pot-app.pot"
elif [[ "$OSTYPE" == "linux-gnu"* ]]; then
    LOG_DIR="$HOME/.local/share/com.pot-app.pot/logs"
else
    LOG_DIR="$APPDATA/com.pot-app.pot/logs"
fi

if [ -d "$LOG_DIR" ]; then
    find "$LOG_DIR" -name "*.log" -type f -exec tail -50 {} \; >> $OUTPUT_FILE 2>/dev/null
else
    echo "No log directory found at $LOG_DIR" >> $OUTPUT_FILE
fi

# Ollama 状态
echo "" >> $OUTPUT_FILE
echo "--- Ollama Status ---" >> $OUTPUT_FILE
curl -s http://localhost:11434/api/tags 2>/dev/null >> $OUTPUT_FILE || echo "Ollama not running" >> $OUTPUT_FILE

echo "" >> $OUTPUT_FILE
echo "Report saved to: $OUTPUT_FILE"
echo "Please attach this file to your bug report."
```

使用方式：
```bash
chmod +x scripts/diagnose.sh
./scripts/diagnose.sh
# 将生成的 txt 文件附到 Bug 报告中
```
