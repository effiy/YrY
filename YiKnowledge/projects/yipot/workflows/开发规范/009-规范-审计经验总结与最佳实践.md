# YiPot 审计经验总结与最佳实践

> 基于 16 轮代码审计、~135 个缺陷修复的经验提炼。适用 YiPot 及 YrY 单体仓库其他项目。

---

## 一、缺陷模式分类

### 1.1 Rust — unwrap/expect panic（占比 65%）

**模式**：`.unwrap()` / `.expect()` 在错误路径直接 panic。

```rust
// ❌ 反模式
let config = config_dir().unwrap();
let value = store.get("key").unwrap().as_str().unwrap();

// ✅ 推荐
let config = match config_dir() {
    Some(v) => v,
    None => { warn!("..."); return Err(...) }
};
let value = store.get("key")
    .and_then(|v| v.as_str())
    .unwrap_or("");
```

**自动化**：`cargo clippy -- -W clippy::unwrap_used`

### 1.2 JavaScript — config 解构无默认值（占比 20%）

**模式**：`options.config` 未传入时解构 `undefined`。

```js
// ❌ 反模式 (21 个翻译引擎 + 15 个 OCR 引擎中存在)
const { config } = options;
const { apiKey } = config;  // TypeError if config undefined

// ✅ 推荐
const { config = {} } = options;
const { apiKey } = config;  // undefined, no crash
```

**自动化**：ESLint `no-unused-vars` + TypeScript `strictNullChecks`

### 1.3 React — 模块级状态（占比 8%）

**模式**：`let timer = null` / `let unlisten = null` 在模块作用域。

```jsx
// ❌ 反模式 (Translate/Recognize/Updater/General/Backup 中存在)
let blurTimeout = null;

// ✅ 推荐
function Component() {
    const blurTimeoutRef = useRef(null);
    // ...
}
```

### 1.4 事件监听器 — 未清理（占比 5%）

**模式**：`listen()` 返回值未保存，useEffect 无 cleanup。

```jsx
// ❌ 反模式
useEffect(() => {
    listen('event', handler);
}, []);

// ✅ 推荐
useEffect(() => {
    const unlisten = listen('event', handler);
    return () => { unlisten.then(f => f()); };
}, []);
```

### 1.5 API 响应 — null safety（占比 5%）

**模式**：深层嵌套访问无保护。

```js
// ❌ 反模式
result[0].translations[0].text

// ✅ 推荐
result?.[0]?.translations?.[0]?.text
```

## 二、自动化检查建议

| 层级 | 工具 | 规则 | 覆盖 |
|------|------|------|------|
| Rust | `cargo clippy` | `-W clippy::unwrap_used` | unwrap panic |
| Rust | `cargo check` | 默认 | 编译错误 |
| JS | ESLint | `no-undef` (App.jsx warn bug) | 未定义引用 |
| JS | ESLint | `prefer-const` (let → const) | 不可变声明 |
| TS | `tsc --noEmit` | `strictNullChecks` | config null |
| Build | `pnpm build` | Vite/esbuild | 语法错误 |
| i18n | 自定义脚本 | key 完整性检查 | 缺失翻译 |
| CI | GitHub Actions | 以上全部 | 每次 PR |

## 三、新增服务/引擎检查清单

新增翻译/OCR 引擎时，验证以下项：

- [ ] `config` 使用默认值解构：`const { config = {} } = options`
- [ ] `config` 中敏感字段（apiKey/token/secret）存储安全
- [ ] API 响应使用可选链访问：`data?.field?.nested`
- [ ] 网络请求包裹 try/catch 或使用 `.catch()`
- [ ] 流式响应正确清理 reader
- [ ] info.ts 中 `icon` 使用普通字符串（非模板字符串）
- [ ] Config.jsx 中密码字段使用 `type='password'`
