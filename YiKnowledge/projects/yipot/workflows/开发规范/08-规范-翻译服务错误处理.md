# YiPot 翻译服务错误处理指南

> 基于第六/七轮审计发现的通用模式，适用于现有 21 个翻译引擎及未来新增引擎。

---

## 一、核心原则

1. **永不信任 API 响应格式。** 第三方 API 可能返回空数组、缺失字段、类型变化。
2. **Config 永远使用默认值解构。** `const { config = {} } = options;`
3. **所有深层访问使用可选链。** `obj?.prop?.nested` 而非 `obj.prop.nested`

## 二、标准模板

```js
export async function translate(text, from, to, options = {}) {
    // 1. Config 安全解构
    const { config = {} } = options;
    const { apiKey, model = 'default' } = config;

    // 2. 必填校验
    if (!apiKey) {
        throw 'Please configure API key';
    }

    // 3. API 调用
    let res;
    try {
        res = await fetch(url, { /* ... */ });
    } catch (e) {
        throw `Network error: ${e.message || e}`;
    }

    // 4. 响应解析 — 使用可选链 + 类型守卫
    if (!res.ok) {
        throw `Http Error: ${res.status}`;
    }

    const data = res.data;
    if (!data || typeof data !== 'object') {
        throw 'Unexpected API response format';
    }

    // 5. 提取结果 — 全部可选链
    const result = data?.translations?.[0]?.text;
    if (!result) {
        throw 'No translation in response';
    }
    return result;
}
```
