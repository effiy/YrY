# 代码约定

> React 函数组件、Rust Tauri 命令、服务插件模式 —— 所有代码必须遵守的基线规则。

## 一、React 组件规范

仅使用函数组件 + Hooks，禁止 class 组件。

```jsx
// 正确：函数组件 + Hooks
import { useState, useEffect } from "react";

export default function TranslateWindow({ text, onClose }) {
  const [result, setResult] = useState(null);

  useEffect(() => {
    if (text) translate(text);
  }, [text]);

  return <div>{result}</div>;
}
```

### 组件命名

| 类型 | 约定 | 示例 |
|------|------|------|
| 窗口组件 | PascalCase | `Translate`, `Recognize`, `Config` |
| 页面组件 | PascalCase | `GeneralPage`, `HotkeyPage` |
| 子组件 | PascalCase | `SourceArea`, `TargetArea` |
| Hooks | camelCase + use 前缀 | `useConfig`, `useVoice` |

### 状态管理

使用 Jotai 原子化状态：

```jsx
import { atom, useAtom } from "jotai";

const translateResultAtom = atom(null);

function useTranslateResult() {
  const [result, setResult] = useAtom(translateResultAtom);
  return { result, setResult };
}
```

## 二、Rust 代码规范

### Tauri Command

```rust
#[tauri::command]
pub fn my_command(param: String) -> Result<String, String> {
    // 实现
    Ok("result".into())
}
```

### 模块命名

| 约定 | 示例 |
|------|------|
| snake_case 文件 | `clipboard.rs`, `system_ocr.rs` |
| snake_case 函数 | `get_selected_text()`, `start_server()` |
| PascalCase 结构体 | `StringWrapper`, `ClipboardMonitor` |

### 错误处理

```rust
use crate::error::AppError;

fn fallible_operation() -> Result<(), AppError> {
    // ? 操作符自动传播错误
    let config = read_config()?;
    Ok(())
}
```

## 三、服务插件模式

每个服务插件由 3 个文件组成：

```
services/{type}/{provider}/
├── info.ts    — 元信息（id, name, type, languages, configurable, needs）
├── index.jsx  — 核心逻辑（默认导出异步函数）
└── Config.jsx — 配置界面（React 组件）
```

### info.ts 模板

```typescript
export const info = {
  id: "provider_id",
  name: "服务名称",
  type: "translate" | "recognize" | "tts" | "collection",
  languages: ["auto", "zh", "en"],
  configurable: true,
  needs: [
    { name: "apiKey", message: "API Key" },
    { name: "secretKey", message: "Secret Key" }
  ]
};
```

### index.jsx 模板

```typescript
export default async function service(input, from, to, options) {
  const response = await fetch(API_URL, { /* ... */ });
  return { text: response.result, from, to };
}
```

## 四、导入顺序

```jsx
// 1. React 核心
import React, { useState, useEffect } from "react";

// 2. Tauri API
import { invoke } from "@tauri-apps/api/tauri";
import { appWindow } from "@tauri-apps/api/window";

// 3. 第三方库
import { useAtom } from "jotai";
import { useTranslation } from "react-i18next";

// 4. 项目内部
import { useConfig } from "../hooks";
import { store } from "../utils/store";
```

## 五、禁止事项

| 禁止 | 原因 |
|------|------|
| React class 组件 | 统一使用函数组件 + Hooks |
| 直接操作 DOM | 使用 React ref |
| `any` 类型 | 使用明确的 TypeScript 类型 |
| 硬编码 API Key | 必须通过配置管理 |
| 在 render 中调用 `invoke` | 使用 useEffect 或事件处理 |
| 阻塞主线程的 Rust 命令 | 使用 `#[tauri::command(async)]` |

## 补充：反模式详解

### 1. 从 Tauri Command 返回值滥用 `String`

```rust
// 错误：返回 JSON 字符串让前端手动解析
#[tauri::command]
fn get_config() -> String {
    let config = read_config();
    serde_json::to_string(&config).unwrap()
    // 前端需要 JSON.parse() 两次——invoke 返回时已自动序列化一次
}

// 正确：返回强类型结构体，Tauri 自动序列化
#[derive(Serialize)]
struct Config { theme: String, language: String }

#[tauri::command]
fn get_config() -> Result<Config, String> {
    let config = read_config();
    Ok(config)
}
```

### 2. Jotai atom 过度拆分

```javascript
// 错误：为每个字段单独创建 atom，导致分散的状态和重复渲染
const translateFromAtom = atom("auto");
const translateToAtom = atom("zh");
const translateTextAtom = atom("");

// 正确：相关状态合并到组合atom，使用 selector atom 提取部分状态
const translateStateAtom = atom({ from: "auto", to: "zh", text: "" });
const translateFromAtom = atom(get => get(translateStateAtom).from);
```

### 3. 在组件内直接操作剪贴板时未考虑 Tauri 异步特性

```javascript
// 错误：同步思维，Tauri invoke 是异步的
function copyToClipboard(text) {
  invoke("copy_to_clipboard", { text });
  // 此时 invoke 可能还没完成！
  showNotification("已复制");  // 可能显示在操作完成之前
}

// 正确：await invoke 完成后再执行后续操作
async function copyToClipboard(text) {
  await invoke("copy_to_clipboard", { text });
  showNotification("已复制");
}
```

### 4. 服务插件中直接修改全局状态

```javascript
// 错误：插件修改全局 atom，破坏插件隔离性
export default async function translate(text, from, to, options) {
  const result = await fetchApi(text, from, to, options);
  // 不要在这里调用 setTranslateResult() 或其他全局状态修改
  return result; // 只返回结果，由调用方决定如何使用
}
```

## 补充：代码审查检查清单

### React/TypeScript 检查

- [ ] 组件是否使用函数组件 + Hooks（无 class 组件）
- [ ] 是否有显式 TypeScript 类型（无 `any`）
- [ ] `useEffect` 依赖数组是否正确（无不完整的依赖或多余的依赖）
- [ ] 是否在 render 中调用了 `invoke`（应使用 useEffect 或事件处理）
- [ ] Jotai atom 粒度是否合理（避免过度拆分）
- [ ] 导入顺序是否符合规范（React → Tauri → 第三方 → 内部）

### Rust 检查

- [ ] `#[tauri::command]` 函数是否返回 `Result<T, String>`（而非裸类型）
- [ ] 是否使用了 `#[tauri::command(async)]`（如长时间运行）
- [ ] 错误处理是否使用 `AppError` 类型（而非裸 `String`）
- [ ] 文件命名是否是 `snake_case`
- [ ] 是否有不必要的 `#[allow(dead_code)]` 标注

### 服务插件检查

- [ ] 三文件（`info.ts`、`index.jsx`、`Config.jsx`）是否齐全
- [ ] `info.ts` 中 `needs` 字段是否与实际代码使用的配置项一致
- [ ] `index.jsx` 返回格式是否符合对应类型规范（TranslateResult/OcrResult等）
- [ ] `Config.jsx` 是否处理了 `config` 初始为空对象的情况
- [ ] API Key 是否通过 `options` 传入（无硬编码）
