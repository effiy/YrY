# 插件开发

> 如何为 YiPot 开发新的服务插件。包括插件结构、接口规范、配置界面、调试方法。

## 一、插件类型与目录

| 类型 | 目录 | 核心功能 |
|------|------|---------|
| 翻译 | `services/translate/{name}/` | 文本翻译 |
| OCR | `services/recognize/{name}/` | 图片文字识别 |
| TTS | `services/tts/{name}/` | 文字转语音 |
| 生词本 | `services/collection/{name}/` | 词汇导出 |

## 二、必需文件

每个插件包含 3 个文件：

```
services/translate/my_service/
├── info.ts    — 插件元信息（必需）
├── index.jsx  — 核心逻辑（必需）
└── Config.jsx — 配置界面（可选，configurable: true 时必需）
```

## 三、info.ts 规范

```typescript
export const info = {
  // 唯一标识符（snake_case）
  id: "my_service",

  // 显示名称
  name: "我的翻译服务",

  // 插件类型
  type: "translate", // "translate" | "recognize" | "tts" | "collection"

  // 支持的语言列表
  languages: ["auto", "zh", "en", "ja", "ko"],

  // 是否需要配置界面
  configurable: true,

  // 配置项定义
  needs: [
    { name: "apiKey", message: "API Key", required: true },
    { name: "apiUrl", message: "自定义 API 地址", required: false },
    { name: "model", message: "模型名称", required: false }
  ],

  // 可选：额外信息
  extra: {
    homepage: "https://example.com",
    docs: "https://example.com/docs"
  }
};
```

## 四、index.jsx 规范

### 翻译插件

```typescript
export default async function translate(
  text: string,     // 待翻译文本
  from: string,     // 源语言代码
  to: string,       // 目标语言代码
  options: Record<string, any>  // 配置项（来自 needs）
): Promise<TranslateResult> {
  // 1. 构造请求
  const response = await fetch(options.apiUrl || API_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      q: text,
      from: from,
      to: to,
      appKey: options.apiKey
    })
  });

  // 2. 解析响应
  const data = await response.json();

  // 3. 返回标准结果
  return {
    text: data.translation,      // 译文（必需）
    from: data.detected_from,    // 检测到的源语言
    to: to,                       // 目标语言
    phonetics: data.phonetic,    // 音标（可选）
    explains: data.explains,     // 词典释义（可选）
    raw: data                     // 原始响应（可选，用于调试）
  };
}
```

## 六、注册到系统

插件放在对应目录后，系统自动发现并加载：

1. 构建时：Vite 扫描 `services/` 目录
2. 运行时：`service_instance.ts` 管理所有服务实例
3. 设置页：自动生成配置表单

## 补充：插件测试策略

### 测试分层

| 层 | 范围 | 框架 | 覆盖率目标 |
|----|------|------|-----------|
| 单元 | `index.jsx` 核心逻辑（mock fetch） | Vitest + msw | 80%+ |
| 集成 | `info.ts` 元信息验证 | Vitest + 自定义断言 | 100%（结构化验证） |
| 端到端 | 真实API调用（需API Key） | 手动测试 + 日志 | 每个服务≥3个用例 |
| 平台 | 跨平台基础功能验证 | CI多平台构建 | 100%平台覆盖 |

### 插件单元测试示例

```javascript
// services/translate/my_service/__tests__/index.test.js
import { describe, it, expect, vi } from "vitest";
import translate from "../index.jsx";

describe("my_service translate", () => {
  it("returns correct TranslateResult shape", async () => {
    // Mock fetch 返回服务标准响应
    global.fetch = vi.fn().mockResolvedValue({
      json: () => Promise.resolve({
        translation: "你好",
        detected_source: "en",
        phonetic: "nǐ hǎo"
      })
    });

    const result = await translate("hello", "auto", "zh", { apiKey: "test" });
    
    // 验证返回结构
    expect(result).toHaveProperty("text", "你好");
    expect(result).toHaveProperty("from", "en");
    expect(result).toHaveProperty("to", "zh");
  });

  it("handles API error gracefully", async () => {
    global.fetch = vi.fn().mockRejectedValue(new Error("Network error"));
    
    // 插件应抛出可读的错误信息
    await expect(translate("hello", "auto", "zh", { apiKey: "test" }))
      .rejects.toThrow();
  });
});
```

### info.ts 验证测试

```javascript
// __tests__/info.test.js
import { info } from "../info";

describe("plugin info", () => {
  it("has required fields", () => {
    expect(info.id).toBeTruthy();
    expect(info.name).toBeTruthy();
    expect(["translate", "recognize", "tts", "collection"]).toContain(info.type);
    expect(info.languages).toBeInstanceOf(Array);
    expect(info.languages.length).toBeGreaterThan(0);
  });

  it("has matching needs and config usage", () => {
    // needs 中的字段名应与 Config.jsx 和 index.jsx 中使用的 key 一致
    if (info.configurable) {
      expect(info.needs).toBeInstanceOf(Array);
      info.needs.forEach(need => {
        expect(need.name).toMatch(/^[a-zA-Z][a-zA-Z0-9_]*$/);
      });
    }
  });
});
```

## 补充：插件分发流程

### 社区贡献插件

```
1. 开发者 fork pot-desktop 仓库
     ↓
2. 在 services/ 下创建插件目录（三文件）
     ↓
3. 本地测试（pnpm tauri dev）
     ↓
4. 提交 PR 到 dev 分支
     ↓
5. CI 自动检查（lint + 类型检查 + info.ts 验证）
     ↓
6. 人工 Code Review（重点: API Key硬编码、网络请求、返回格式）
     ↓
7. 合并 → 下个版本发布时自动包含
```

### 插件审核要点

| 检查项 | 说明 | 必须 |
|--------|------|------|
| 无硬编码 API Key | `needs` 中定义，`options` 获取 | 是 |
| 无外部网络请求到非API域名 | 检查 fetch URL 是否为服务商官方地址 | 是 |
| 返回格式符合类型定义 | TranslateResult / OcrResult 等 | 是 |
| 错误处理完善 | 网络错误/服务错误有合理的提示信息 | 是 |
| Config.jsx 最少可用 | 至少支持 API Key 输入 | 是 |
| info.ts 字段完整 | id/name/type/languages/configurable/needs | 是 |

### 插件发布后维护

- 服务商 API 变更 → 插件作者或社区成员提 PR 更新
- 服务商停止服务 → 插件标记为 `deprecated`，6个月后从主仓库移除
- 安全漏洞 → 紧急移除+通知用户手动升级，同时评估是否需要版本号机制
