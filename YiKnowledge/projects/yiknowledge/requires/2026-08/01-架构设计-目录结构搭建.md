### 功能概述

建立 YiKnowledge 知识库的目录结构和角色边界体系，基于软件交付流水线（Requirements → Decisions → Design+Build → Quality+Release → Operate+Learn）组织 7 个角色目录 + 1 个项目知识中心。

### 技术实现

#### 角色目录设计

| 角色 | 流水线阶段 | 核心职责 |
|------|-----------|----------|
| `executiver/` | 业务策略（跨阶段） | 企业战略、行业分析、组织目标 |
| `producter/` | 1. 需求 | PRD、用户故事、优先级框架 |
| `leader/` | 2. 决策 | ADR 存档、架构决策、容量规划 |
| `engineer/` | 3. 设计构建 | 架构模式、开发实践、经验教训 |
| `srer/` | 4. 质量发布 + 5. 运营学习 | 可观测性、事件响应、发布流程 |
| `aier/` | AI 赋能（跨阶段） | AI 基础、方法论、平台、ML |
| `curator/` | 知识治理（元层） | 治理流程、模板、归档、图表 |

#### 目录层级约束

- 最多 3 层：`role/problem-domain/file.md`
- 文件命名：kebab-case，禁止下划线和数字
- 每个角色目录有 `README.md`（概述）和 `INDEX.md`（导航）

#### 跨领域索引

- **SECURITY.md**：聚合供应链安全、应用安全、风险、事件响应、合规
- **COLLABORATION.md**：聚合团队流程、会议、知识共享、入职、PM
- **ENGINEERING.md**：聚合架构、质量、数据、工具、经验教训

#### 项目知识中心

- `projects/` 目录容纳 4 个项目的 bugs/issues/文档/demos
- 各项目独立 `requires/` 目录按月份组织

### 关联模块

- 架构文档：`docs/架构/架构设计.md`、`目录结构.md`、`角色边界.md`
- 治理文档：`docs/治理/知识治理.md`
- 规范文档：`docs/规范/知识管理规范.md`

### 验收标准

1. 7 个角色目录 + 1 个项目知识中心创建完成
2. 每个角色目录有 README.md 和 INDEX.md
3. 3 个跨领域索引（SECURITY/COLLABORATION/ENGINEERING）创建完成
4. 目录层级不超过 3 层
5. 文件命名符合 kebab-case 规范
