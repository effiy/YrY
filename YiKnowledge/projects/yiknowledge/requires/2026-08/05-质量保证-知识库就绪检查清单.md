### 功能概述

制定知识库就绪检查清单，确保每条新增知识在入库前通过质量检查。10 项检查覆盖角色归属、命名规范、元数据完整性、内容质量和可发现性。

### 技术实现

#### 检查清单（10 项）

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 角色归属 | 内容属于哪个角色目录？参考角色边界决策树 |
| 2 | 文件命名 | 是否符合 kebab-case 规范？禁止下划线和数字 |
| 3 | frontmatter 完整性 | 必填字段是否齐全？`title/tags/category/created/updated/source/type/status` |
| 4 | tags 质量 | 是否 3-5 个精准标签？非泛化标签 |
| 5 | lifecycle 状态 | 是否设置正确？（inbox/triage/active/参考/archive） |
| 6 | 外部内容审查 | 外部来源内容是否设置 `review_cycle` 和 `last_verified`？ |
| 7 | 正文结构 | 是否包含 Summary / Core viewpoints / Key information / Action recommendations？ |
| 8 | 重复检查 | 是否与已有内容重复？ |
| 9 | 索引更新 | 是否更新了角色 INDEX.md？ |
| 10 | 导航可达 | 前端导航是否可发现该内容？ |

#### 检查清单执行

- 新增知识文件时，作者自查 10 项
- 策展人 (Curator) 每季度抽查
- CI 自动化检查（可选）：校验 frontmatter 必填字段

#### 自动化检查脚本

```bash
# 检查缺失 frontmatter 必填字段
rg -L "^title:" YiKnowledge/**/*.md
rg -L "^tags:" YiKnowledge/**/*.md
rg -L "^category:" YiKnowledge/**/*.md

# 检查文件名规范（下划线、数字）
find YiKnowledge -name "*_*" -o -name "*[0-9]*.md"

# 检查 lifecycle 状态分布
rg "^lifecycle:" YiKnowledge -c --no-filename | sort -t: -k2
```
