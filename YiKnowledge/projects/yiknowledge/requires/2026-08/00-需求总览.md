# 一、业务概述

## 1.1 业务背景

YiKnowledge 作为团队知识库，是 YrY monorepo 的共享知识层。它既服务于人类（文档查阅），也服务于 AI（YiAi BRD Agent 的 RAG 数据源）。八月迭代聚焦于知识库基础设施的全面建设。

## 1.2 业务目标

- 建立结构化的知识库目录体系，覆盖软件交付全流程
- 制定统一的元数据规范，提升 RAG 检索质量
- 建立知识治理流水线，确保知识库长期健康
- 实现 YiAi 与 YiKnowledge 的深度集成，支撑 AI 检索
- 建立项目知识中心，统一管理跨项目 issue 和 PRD

## 1.3 适用对象

- 团队成员（人类知识查阅）
- YiAi BRD Agent（AI RAG 检索）
- 知识库策展人（治理维护）

## 1.4 系统范围

- YiKnowledge 知识库（Markdown 文件树）
- YiAi 后端（Knowledge Watcher、RAG 引擎）
- MongoDB（知识文件索引）

# 二、功能详情

## 2.1 知识库目录架构 (需求 1)

建立基于软件交付流水线的 7 角色目录 + 1 项目知识中心。

| 角色 | 阶段 | 职责 |
|------|------|------|
| `executiver/` | 业务策略 | 企业战略、行业分析、组织目标 |
| `producter/` | 需求发现 | PRD、用户研究、竞品分析 |
| `leader/` | 技术决策 | 架构决策、技术选型、风险管控 |
| `engineer/` | 工程实现 | 代码规范、架构模式、质量保障 |
| `aier/` | AI 工程 | AI 方法论、平台工具、ML 实践 |
| `srer/` | 运维保障 | 事件响应、可观测性、发布管理 |
| `curator/` | 知识治理 | 模板规范、归档管理、质量检查 |

## 2.2 元数据标准 (需求 2)

统一的 YAML Frontmatter 规范，支持 RAG 检索优化。

## 2.3 知识治理 (需求 3)

生命周期管理、治理角色划分、就绪检查清单、定期维护机制。

## 2.4 AI 集成 (需求 4)

Knowledge Watcher 文件监听、MongoDB 索引同步、llama_index RAG 引擎、混合检索。

## 2.5 质量保障 (需求 5)

10 项就绪检查清单，自动化检查脚本，前置质量门禁。

## 2.6 项目知识中心 (需求 6)

7 项目统一 issue 管理，PRD 归档，MongoDB 同步，跨项目检索。
