### 功能概述

建立 `projects/` 项目知识中心，为 4 个项目（YiVad、YiAi、YiPet、YiKnowledge）提供统一的 issue 管理和 PRD 归档能力，实现跨项目知识的结构化存储和检索。

### 技术实现

#### 项目知识中心结构

```
projects/
├── README.md              # 项目知识中心概述
├── INDEX.md               # 项目导航索引
├── yivad/                 # YiVad 管理后台
│   └── requires/          # 按月份组织的需求/issue 文件
├── yiai/                  # YiAi 后端
│   └── requires/
├── yipet/                 # YiPet Chrome 扩展
│   └── requires/
├── yiknowledge/           # YiKnowledge 知识库
│   ├── requires/
│   ├── 文档/
    └── demos/
```

#### Issue 文件标准格式

每个 issue 文件包含：
- **YAML frontmatter**：`title`、`tags`、`status`、`priority`、`issue_type`、`assignee`、`estimate_points`、`prd_month`、`prd_task_id` 等
- **基本信息表**：需求编号、项目、代码仓库、功能模块、优先级、人天、状态
- **功能概述**：简要描述需求目标
- **技术实现**：详细的技术方案和实现细节
- **关联模块**：相关的代码模块和文件路径
- **验收标准**：可验证的完成标准

#### MongoDB 同步

- Issue 通过 RPC envelope 同步至 MongoDB `issues` 集合
- Issue key 格式：`{project_key}-{prd_task_id}`
- 支持 delete + re-create 模式更新（`update_document` 需要 key 字段）

#### PRD 文件

- 每个月份目录包含 `prd.md` 聚合当月所有 issue
- PRD 格式：业务概述 → 功能清单 → 功能性需求详述 → 全局性需求 → 开发排期

### 关联模块

- 项目知识中心：`projects/README.md`、`projects/INDEX.md`
- 各项目 requires 目录：`projects/{project}/requires/YYYY-MM/`
- MongoDB 集合：`issues`

### 验收标准

1. 7 个项目均建立 `requires/` 目录结构
2. Issue 文件格式统一，frontmatter 完整
3. 每个月份有对应的 `prd.md` 聚合文件
4. MongoDB 同步正常，issue 数据完整
5. 知识库检索可发现所有项目 issue
