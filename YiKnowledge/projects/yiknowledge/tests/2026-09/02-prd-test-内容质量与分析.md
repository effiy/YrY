## 一、测试范围与目标

### 1.1 在范围内（24 个子需求，8 个功能域）

| 功能域 | 模块 | 关键测试点 |
|--------|------|----------|
| 审核工作流 | 状态机/检查清单/分配/通知 | 5 状态转换、15 项自动检查、负载均衡、企微通知 |
| 可读性分析 | Flesch 中文/句子复杂度/词汇难度 | HSK 等级分布、句子长度分布、技术文档加权 |
| 质量评分 | 7 维度加权评分 | 权重总和=1.0、各维度 0-100、幂等性 |
| 信息分析 | 信息密度/情感/受众匹配 | 实体密度、情感极性、目标受众偏离检测 |
| 去重 | SimHash/同义检测 | 64-bit 指纹确定性、汉明距离阈值、全量比对 |
| 术语一致性 | 术语变体检测/术语表 | 模糊匹配 0.8、非标准变体提示、代码块排除 |
| 安全合规 | 安全分类/合规/版权/行业标准 | 4 级分类、规则兜底、License 检测 |
| 统计仪表盘 | 聚合/趋势/排行 | 评分分布、领域对比、时间趋势 |

|--------|------|

| 主观题自动评分 | DEV §8 列为功能缺口 |

<a id="sec-4"></a>
## 四、单元测试 — 审核工作流

| 编号 | 用例 | 输入 | 预期 |
|------|------|------|------|
| UT-RV-01 | 合法状态转换 draft→in_review | `transition("file.md", "in_review")` | 成功，返回 ReviewEvent |
| UT-RV-02 | 合法状态转换 in_review→approved | `transition("file.md", "approved")` | 成功 |
| UT-RV-03 | 非法状态转换 draft→published | `transition("file.md", "published")` | 拒绝，抛出 InvalidTransitionError |
| UT-RV-04 | 非法状态转换 archived→draft | `transition("file.md", "draft")` | 拒绝（归档不可逆） |
| UT-RV-05 | 审核检查清单 15 项全部通过 | 符合规范的完整文档 | `ChecklistResult.passed=15, failed=0` |
| UT-RV-06 | 检查清单：frontmatter 缺失 | 缺少 title 字段 | `failed` 包含 "frontmatter_complete" |
| UT-RV-07 | 检查清单：死链检测 | 文档含 `http://nonexistent.example.com` | `failed` 包含 "links_valid" |
| UT-RV-08 | 检查清单：标题跳跃 | H1 → H3 缺 H2 | `failed` 包含 "heading_hierarchy" |
| UT-RV-09 | 审核人分配负载均衡 | 5 个文件同时提交审核 | 审核人分布均匀（每人 ≤ 2 个） |
| UT-RV-10 | 审核通知 5 分钟内去重 | 同一文件 2 分钟内 2 次相同状态变更 | 仅发送 1 条通知 |

<a id="sec-5"></a>
## 五、单元测试 — 可读性与质量评分

| 编号 | 用例 | 输入 | 预期 |
|------|------|------|------|
| UT-RD-01 | Flesch 中文：短文 | 100 字简单句（HSK 1-2 级词汇） | 评分 > 70（易读） |
| UT-RD-02 | Flesch 中文：技术文档 | 含代码块和公式的架构设计文档 | 评分 < 50（较难，代码/公式加权降低） |
| UT-RD-03 | 句子复杂度：短句为主 | 平均句长 < 20 字 | `hard_sentences` 占比 < 10% |
| UT-RD-04 | 句子复杂度：长句为主 | 平均句长 > 50 字 | `hard_sentences` 占比 > 50% |
| UT-RD-05 | 词汇难度：HSK 等级分布 | 技术术语为主的文档 | HSK 6 级 + 超纲词占比高 |
| UT-QS-01 | 质量评分 7 维度 | 完整合规的文档 | 综合评分 > 80 |
| UT-QS-02 | 质量评分：权重总和 | 任意文档 | 7 维度权重总和 = 1.0 |
| UT-QS-03 | 质量评分幂等性 | 同一文档两次评分 | 结果一致 |
| UT-QS-04 | 质量评分：过期文档 | updated 为 1 年前 | freshness 维度评分 < 30 |
| UT-IA-01 | 信息密度：高密度 | 含表格/列表/代码的文档 | `facts_per_k` > 10 |
| UT-IA-02 | 情感分析：技术文档 | 客观描述的架构文档 | `polarity ≈ 0, subjectivity < 0.2` |
| UT-IA-03 | 受众匹配：目标读者 "engineer" | 技术术语丰富的文档 | `match_score` > 0.8 |

<a id="sec-6"></a>
## 六、单元测试 — 去重与一致性

| 编号 | 用例 | 输入 | 预期 |
|------|------|------|------|
| UT-DD-01 | SimHash 确定性 | 同一文档两次计算 | 64-bit 指纹完全一致 |
| UT-DD-02 | SimHash 局部修改不敏感 | 原文 vs 修改一个段落 | 汉明距离 ≤ 3 |
| UT-DD-03 | SimHash 完全不同文档 | 架构文档 vs 故障复盘 | 汉明距离 > 10 |
| UT-DD-04 | 去重阈值判定 | 汉明距离 2 | 判定为重复 |
| UT-DD-05 | 去重阈值判定 | 汉明距离 5 | 判定为非重复 |
| UT-DD-06 | 短文档阈值放宽 | < 500 字文档，汉明距离 4 | 阈值放宽到 5，判定为非重复 |
| UT-TC-01 | 术语一致性：标准术语 | 文档使用 "RAG" | 无警告（已在术语表中） |
| UT-TC-02 | 术语一致性：非标准变体 | 文档使用 "搜寻增强生成" | 警告：建议替换为 "检索增强生成" |
| UT-TC-03 | 术语一致性：代码块排除 | 代码块中的术语变体 | 不触发警告 |
| UT-TC-04 | 术语模糊匹配 0.8 阈值 | "检所" vs "检索"（编辑距离 1，相似度 > 0.8） | 匹配成功 |

## 九、端到端场景

### 场景 1：完整审核流程

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 作者提交文档 draft→in_review | 状态变更，审核人自动分配 |
| 2 | 审核人收到企微通知 | 通知含文件路径和审核链接 |
| 3 | 审核面板执行 15 项检查清单 | 逐项显示通过/失败，死链和标题跳跃被检出 |
| 4 | 审核人填写审查意见 → 批准 in_review→approved | 状态变更，作者收到通过通知 |
| 5 | 作者发布 approved→published | 文档在知识库可见 |

### 场景 2：全库质量扫描

| 步骤 | 操作 | 验证点 |
|------|------|--------|
| 1 | 触发全库质量扫描 | 800+ 文件扫描 < 30s |
| 2 | 查看统计仪表盘 | 评分分布图、领域对比、Top 问题 |
| 3 | 点击低分文档（<50） | 查看各维度分解，定位问题（如 freshness 过低） |
| 4 | 查看术语一致性报告 | 非标准术语变体列表，一键替换 |
