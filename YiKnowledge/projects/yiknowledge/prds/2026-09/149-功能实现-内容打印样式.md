# YK-09-182: 内容打印样式 — 干净打印布局、分页控制、目录生成、页眉页脚、QR码、打印预览

> 需求编号：YK-09-182 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YK-09-35（打印样式与PDF导出——本需求是对早期打印样式的全面增强，复用基础打印 CSS 框架）

## 背景

### 问题陈述

YiKnowledge 知识库文章在屏幕阅读体验良好——但用户需要在纸质或 PDF 上阅读和存档时——浏览器的默认打印效果极差：

1. **打印布局混乱**：侧边栏、导航栏、页脚、评论区全部打印——占据50%以上纸张空间——核心内容被挤压
2. **无分页控制**：代码块在页边界被截断——标题与内容分离（标题在上一页底——内容在下一页顶）——表格被截断
3. **链接不可追溯**：文中链接在打印后失去 URL 信息——读者无法追溯引用来源
4. **无元数据标识**：打印页无标题、作者、日期——离线阅读时不清楚文章来源和版本
5. **无目录导航**：长文章打印后无目录——读者无法快速定位章节——翻阅效率低
6. **移动端不友好**：A4 宽度在手机屏幕上无法预览——用户不知道打印效果——只能先打印再确认

**核心矛盾**：屏幕阅读和打印阅读是完全不同的媒介——屏幕友好的布局（侧边栏/导航/交互元素）对打印是噪音。目标是提供 `@media print` 优化的打印样式——生成打印目录——添加元数据——最大化纸张上的内容可读性。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 打印浪费纸张 | 高 | 5 页文章——打印出 12 页——7 页是导航和侧边栏 |
| 2 | 代码/表格截断 | 高 | 代码块在页底被切成两半——后半部分在下一页——无法阅读 |
| 3 | 链接不可追溯 | 中 | 打印文档中的"详见 API 文档"链接——纸质上无法访问 |
| 4 | 无来源标识 | 中 | 存档 3 个月后——不记得文章的来源和版本 |
| 5 | 长文无导航 | 中 | 50 页技术文档——打印后无目录——查找章节困难 |
| 6 | 打印前无法预览 | 高 | 打印出来才发现问题——浪费纸和时间 |

### 挑战

| 挑战 | 说明 |
|------|------|
| CSS print 媒体查询 | 隐藏非内容元素——调整布局为 A4——字体大小——行距——边距 |
| 分页控制 | page-break-before/after/inside——孤儿行/widow 行——避免标题在页底 |

| 打印预览 | 提供打印预览模式——模拟 A4 布局——在屏幕上展示打印效果 |

## 二、设计决策

### 决策 1：打印样式实现方式 — 纯 CSS vs CSS + JS 增强 vs CSS + JS + 独立打印模板

| 选项 | 灵活性 | 复杂度 | 兼容性 |
|------|--------|--------|--------|
| A: 纯 CSS @media print | 低——受限于 CSS 能力 | 低 | 最佳——所有浏览器 |
| B: CSS + JS 增强（TOC生成/QR码/打印预览） | 高——可计算页码/生成内容 | 中 | 好——JS 打印增强已普遍支持 |
| C: CSS + JS + 独立打印模板（新窗口渲染） | 最高——完全控制 | 高——需要独立渲染管线 | 中——新窗口弹窗可能被拦截 |

**选择：B（CSS @media print + JS 增强——TOC 生成 + 页码计算 + QR 码 + 打印预览模式）。** 纯 CSS 无法生成 TOC 目录（需要扫描标题 DOM）、显示 QR 码（需要 URL 编码生成图片）、计算页码（需要知道内容高度和 A4 页高）。JS 增强可以在用户触发打印前，动态生成这些内容。不选择独立打印模板——因为需要双倍维护渲染逻辑。

### 决策 2：分页控制策略 — 自动 vs 手动标记 vs 混合

| 选项 | 精确度 | 维护成本 | 适应性 |
|------|--------|---------|--------|
| A: 自动——基于元素类型自动添加分页规则 | 中——规则通用但非完美 | 低——全局 CSS 规则 | 好——所有文章适用 |
| B: 手动标记——作者在 markdown 中标记分页 | 高——完全控制 | 高——每篇文章需维护 | 差——历史文章无标记 |
| C: 混合——自动全局规则 + 特殊元素手动标记 | 高——覆盖大多数场景 | 中——大部分自动+少量手动 | 最好 |

**选择：C（混合——CSS 自动分页规则 + markdown 块级属性 `{.page-break-before}` 手动标记）。** 自动规则处理通用场景：h2 前分页（`page-break-before: always`）、代码块和表格不可跨页（`page-break-inside: avoid`）、避免标题在页底（`orphans: 3`）。手动标记处理特殊情况——当作者明确知道某处需要分页时——在 markdown 块级属性中添加 `{.page-break-before}`。

### 决策 3：打印目录(TOC)位置 — 仅首页 vs 独立页 vs 内联

| 选项 | 纸张占用 | 导航效果 | 实现 |
|------|---------|---------|------|
| A: 仅首页——目录放在文章标题下方 | 省纸——不额外占页 | 中——翻阅时不可见 | 低 |
| B: 独立页——目录独占首页（或前N页） | 多占1页 | 好——单独翻阅 | 中 |
| C: 内联——目录在文章内容中浮动 | 不单独占页 | 差——被内容包围 | 低 |

**选择：B（独立页——目录独占首页——文章正文从第 2 页开始）。** 独立目录页最符合纸质文档习惯——读者先看目录了解结构——确定感兴趣章节——再翻到对应页。目录包含：文章标题、版本信息、目录树（h2/h3 层级）、对应页码。类似书籍或 PDF 白皮书的目录页——专业且实用。

### 决策 4：QR 码位置 — 首页 vs 末页 vs 页眉 vs 不生成

| 选项 | 视觉美观 | 实用性 | 空间占用 |
|------|---------|--------|---------|
| A: 首页——title 下方 | 中 | 好——一眼看到 | 小——首页有空间 |
| B: 末页——文档末尾 | 好——不干扰正文 | 中——需要翻到末页 | 小 |
| C: 页眉/页脚——每页出现 | 差——重复冗余 | 高——随时可扫 | 每页占用 |
| D: 不生成 | — | 差 | 无 |

**选择：A + B（首页+末页各一个 QR 码——首页为小型徽章式——末页为大尺寸）。** 首页 QR 码在文章标题右侧——小尺寸（2cm×2cm）——扫码回到线上版本。末页 QR 码大尺寸（4cm×4cm）——下方文字"扫描二维码查看最新版本"。QR 码不放在页眉——每页重复浪费墨水——且页眉空间应留给标题/页码。

### 4.2 核心代码：TOC 页码生成器

```typescript
// src/composables/usePrintEnhancer.ts

interface TOCEntry {
  id: string;
  level: number; // 2 = h2, 3 = h3
  text: string;
  pageNumber: number;
  children: TOCEntry[];
}

class PrintEnhancer {
  private articleEl: HTMLElement | null = null;
  private A4_HEIGHT_PX = 1122; // A4 297mm × 3.78px/mm (96dpi)
  private PAGE_MARGIN_PX = 80; // 上下边距

  /** 生成打印目录 */
  generateTOC(articleEl: HTMLElement): TOCEntry[] {
    this.articleEl = articleEl;
    const headings = articleEl.querySelectorAll('h2, h3');
    const toc: TOCEntry[] = [];
    const stack: TOCEntry[] = [];

    for (const heading of headings) {
      const level = parseInt(heading.tagName[1]);
      const entry: TOCEntry = {
        id: heading.id || '',
        level,
        text: heading.textContent || '',
        pageNumber: this.estimatePageNumber(heading),
        children: [],
      };

      if (level === 2) {
        toc.push(entry);
        stack.length = 0;
        stack.push(entry);
      } else if (level === 3 && stack.length > 0) {
        stack[stack.length - 1].children.push(entry);
      }
    }

    return toc;
  }

  /** 估算元素所在页码 */
  private estimatePageNumber(el: Element): number {
    if (!this.articleEl) return 1;

    const articleRect = this.articleEl.getBoundingClientRect();
    const elRect = el.getBoundingClientRect();
    const offsetFromTop = elRect.top - articleRect.top;

    // TOC 首页占一整页
    const tocPageOffset = this.A4_HEIGHT_PX - this.PAGE_MARGIN_PX * 2;
    const contentOffset = offsetFromTop + tocPageOffset;

    return Math.max(2, Math.ceil(contentOffset / (this.A4_HEIGHT_PX - this.PAGE_MARGIN_PX * 2)));
  }

  /** 生成 QR 码（使用 Canvas——避免外部依赖） */
  generateQRCode(url: string, size: number = 200): string {
    // 简化实现——使用 qrcode 库或 API
    // 实际使用: QRCode.toDataURL(url, { width: size })
    return `https://api.qrserver.com/v1/create-qr-code/?size=${size}x${size}&data=${encodeURIComponent(url)}`;
  }

  /** 渲染打印目录到 DOM */
  renderTOC(toc: TOCEntry[], container: HTMLElement): void {
    const html = `
      <div class="print-toc" style="page-break-after: always;">
        <h1>目录</h1>
        ${this.renderTOCEntries(toc)}
        <div class="print-qr-small" style="margin-top: 30pt; text-align: center;">
          <img src="${this.generateQRCode(window.location.href, 150)}"
               width="75" height="75" alt="QR">
          <p style="font-size: 8pt; color: #999;">扫描回到线上版本</p>
        </div>
      </div>
    `;
    container.insertAdjacentHTML('afterbegin', html);
  }

  private renderTOCEntries(entries: TOCEntry[]): string {
    return entries.map(e => `
      <div class="toc-item" style="display: flex; justify-content: space-between;
        margin-left: ${(e.level - 2) * 20}pt; padding: 4pt 0;">
        <span>${e.text}</span>
        <span style="color: #999;">${e.pageNumber}</span>
      </div>
      ${e.children.length > 0 ? this.renderTOCEntries(e.children) : ''}
    `).join('');
  }
}
```

## 九、设计决策记录

### D-01：CSS + JS 增强——非独立打印模板

**上下文**：打印功能通过 @media print CSS 还是独立打印窗口实现。

**决策**：@media print CSS 控制打印布局——JS 增强生成 TOC/QR 码/页眉页脚。

**理由**：独立打印窗口需要维护另一套渲染逻辑——且弹窗可能被浏览器拦截。@media print 在用户触发 window.print() 时，浏览器自动应用打印样式——无需额外渲染。JS 增强在打印前执行——动态生成 TOC 和 QR 码插入 DOM——打印完成后移除临时元素——不污染页面。

### D-02：独立目录页——首页

**上下文**：打印目录放在首页还是内联在正文中。

**决策**：目录独占首页——正文从第 2 页开始。

**理由**：纸质文档标准做法——目录单独一页——读者翻开封面的第一页就是目录。如果目录内联在正文中——读者需要翻好几页才能找到——体验差。独立目录页后跟正文——结构清晰——符合纸质书和 PDF 白皮书的排版习惯。

### D-03：首页+末页双 QR 码

**上下文**：QR 码放置位置。

**决策**：首页小型 QR 码（标题旁）——末页大型 QR 码（正文后+说明文字）。

**理由**：首页 QR 码方便快速扫码——不占用太多空间。末页 QR 码在文档结尾——读者读完后再回头扫码——尺寸大些方便识别。两个 QR 码指向同一 URL——互为冗余。不放在页眉/页脚——避免每页重复印刷 QR 码——浪费墨水且视觉累赘。

### D-04：页码估算而非精确计算

**上下文**：TOC 中的页码如何计算。

**决策**：基于元素位置和 A4 页面高度估算页码——误差 ±1 页。

**理由**：精确页码计算需要考虑字体的具体字形度量（glyph metrics）——不同操作系统/浏览器字体渲染不同——无法完全精准。估算误差 ±1 页在纸质文档中是可接受的——实际上许多 PDF 生成工具也有类似误差。TOC 中标注"约 3 页"而非"3 页"——管理预期。打印预览模式中的页码更精确（因为实际渲染了 A4 尺寸）。

| # | 预测问题 | 触发条件 | 检测方式 |

| 1 | 打印后页面残留 TOC/QR 临时元素——视觉污染 | 打印完成后清理逻辑未执行——或 JS 错误中断清理 | finally 块中清理——使用标记 class——检查所有 `.print-temp` 元素是否移除 |
