# YK-09-07: 知识检索反馈闭环 — 用户反馈收集与检索质量持续优化

> 需求编号：YK-09-07 · 优先级：P1 · 人天：2.0d · 状态：需求已编写
> 依赖：YK-09-04（RAG 检索质量监控）

## 背景

YK-09-04 建立了 RAG 检索质量监控（空结果告警 + 维度检测），解决了"检索系统是否故障"的问题。但未解决"检索结果是否相关"的问题——系统可以返回非空结果，但结果可能与用户意图不匹配。

当前 RAG 检索缺少**用户反馈闭环**：
- BM25 + 向量混合检索的 `alpha` 权重是固定值（0.7 BM25 + 0.3 向量），未根据实际检索效果调优
- 标签过滤的权重和策略无数据支撑
- 检索结果排序仅依赖混合分数，无用户点击/采纳信号
- 知识文件质量评分（见 00-需求总览 §0.7）未与检索效果关联

**目标**：建立用户反馈收集 → 检索质量分析 → 参数自动调优的闭环。

---

## 一、现状分析

### 1.1 当前检索质量信号

```
RAG 检索（BM25 + 向量混合）
  │
  ├── 可观测信号（YK-09-04 已实现）
  │   ├── 检索结果数
  │   ├── 空结果率
  │   ├── 检索延迟
  │   └── 维度不匹配告警
  │
  └── 缺失信号（本次补充）
      ├── 用户点击了哪个结果（采纳信号）
      ├── 用户对检索结果满意度（显式反馈）
      ├── 结果与查询的相关性（隐式反馈）
      ├── 检索结果对 LLM 生成的贡献度（溯源分析）
      └── 不同检索策略的 A/B 对比效果
```

### 1.2 反馈信号类型

| 信号类型 | 采集方式 | 信号强度 | 噪声 | 实现复杂度 |
|----------|----------|----------|------|-----------|
| **显式反馈**：用户 👍/👎 评分 | UI 按钮（thumbs up/down） | 高（直接意图） | 低 | 低 |
| **隐式反馈**：用户点击结果 | 点击事件追踪 | 中（点击≠满意） | 中 | 低 |
| **采纳反馈**：LLM 引用了结果 | 溯源分析（source tracking） | 高（实际使用） | 低 | 中 |
| ** dwell time**：结果停留时长 | 页面停留计时 | 中 | 高（需去噪） | 中 |
| **复制/保存行为**：用户复制了片段 | 剪贴板事件 | 高（明确意图） | 低 | 低 |

### 1.3 反馈数据流

```
用户 RAG 查询 "微服务架构最佳实践"
  │
  ├── RAG 检索返回 Top-5 结果
  │   [0] "微服务设计模式" (score: 0.92) ← 用户点击 ✅
  │   [1] "分布式系统架构" (score: 0.87)
  │   [2] "API Gateway 实践" (score: 0.81)
  │   [3] "服务间通信模式" (score: 0.76)
  │   [4] "容器化部署指南" (score: 0.71) ← 用户 👎 ❌
  │
  ├── LLM 生成回答 → 引用 [0] 和 [2] 作为来源
  │
  ├── 用户点击 [0] 查看原文（采纳信号）
  ├── 用户对回答 👍（显式正面反馈）
  └── 用户对来源 [4] 👎（显式负面反馈）
        │
        ▼
反馈收集 → 分析 → 调优
  ├── [0] 质量评分 +0.01（采纳信号）
  ├── [4] 质量评分 -0.02（负面反馈）
  ├── BM25 alpha: 0.70 → 0.72（BM25 top-1 更常被采纳）
  └── 标签过滤权重: "微服务" +0.005, "架构" +0.003
```

### 1.4 改造前 API 依赖

| # | 接口 | 说明 | 反馈能力 |
|---|------|------|----------|
| 1 | `rag.rag_query` | RAG 检索 | 返回结果列表，无反馈通道 |
| 2 | `rag.rag_chat` | SSE 流式 RAG 聊天 | 返回来源，无反馈通道 |
| 3 | `data_service.query_documents` | 知识检索 | 无反馈通道 |

> 改造前 3 个 RAG 接口均无反馈收集能力，检索质量优化依赖于人工抽查和直觉判断。

## 二、设计决策

### 决策 1：反馈收集方式 — 显式 vs 隐式 vs 混合

| 选项 | 数据质量 | 数据量 | 用户负担 |
|------|----------|--------|----------|
| 纯显式（👍/👎) | 高 | 低（< 5% 用户会反馈） | 有（需点击） |
| 纯隐式（点击/停留/复制） | 中 | 高 | 无 |
| **混合（显式+隐式）** | 高 | 中-高 | 低 |

**选择：混合收集。** 隐式信号（点击、来源引用）作为主要数据源（量大、无负担），显式信号（👍/👎）作为高质量标注数据（量少、精度高）。两者互补。

### 决策 2：反馈存储 — MongoDB 独立集合 vs 嵌入检索日志

| 选项 | 查询效率 | 数据一致性 | 扩展性 |
|------|----------|-----------|--------|
| 独立集合 `rag_feedback` | 高（专用查询） | 中（需关联检索日志） | 高 |
| 嵌入检索日志 | 中 | 高（原子写入） | 低 |

**选择：独立集合 `rag_feedback` + 关联 `query_id`。** 存储结构化反馈数据，支持按查询/文档/用户维度分析。

### 决策 3：质量评分更新 — 实时 vs 批量

| 选项 | 反馈延迟 | 系统负载 | 稳定性 |
|------|----------|----------|--------|
| 实时更新 | 低（秒级） | 高（每次反馈触发） | 中（可能振荡） |
| 批量更新（每小时） | 中（小时级） | 低（定时批处理） | 高（平滑更新） |

**选择：批量更新（每小时）+ 指数移动平均。** 避免实时更新导致的评分振荡。EMA 平滑短期波动，保留长期趋势。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选择 | 理由 |
|------|--------|--------|------|------|
| 反馈收集 | 显式 | 混合 | **混合** | 显式精准+隐式量大，互补 |
| 存储方案 | 独立集合 | 嵌入日志 | **独立集合** | 专用查询，灵活扩展 |
| 评分更新 | 实时 | 批量 | **批量+EMA** | 平滑更新，避免振荡 |

## 三、目标架构

### 3.1 反馈收集 API

```python
# YiAi/src/services/rag/feedback_service.py

from dataclasses import dataclass
from enum import Enum

class FeedbackType(str, Enum):
    EXPLICIT_LIKE = "explicit_like"        # 👍 用户主动点赞
    EXPLICIT_DISLIKE = "explicit_dislike"  # 👎 用户主动点踩
    CLICK_THROUGH = "click_through"        # 用户点击结果查看原文
    SOURCE_CITED = "source_cited"          # LLM 引用此来源
    COPIED_SNIPPET = "copied_snippet"      # 用户复制了片段
    DWELL_TIME_LONG = "dwell_time_long"    # 停留 > 30s
    SKIPPED = "skipped"                    # 用户跳过（未查看）

@dataclass
class RagFeedback:
    query_id: str           # RAG 查询唯一 ID
    document_path: str      # 知识文件路径
    feedback_type: FeedbackType
    user_id: str | None     # 匿名反馈时为空
    score: float            # 正/负信号强度 (-1.0 ~ +1.0)
    timestamp: float        # Unix timestamp

class FeedbackService:
    """RAG 检索反馈收集与质量评分更新。"""

    SIGNAL_WEIGHTS = {
        FeedbackType.EXPLICIT_LIKE: 1.0,
        FeedbackType.EXPLICIT_DISLIKE: -1.0,
        FeedbackType.CLICK_THROUGH: 0.3,
        FeedbackType.SOURCE_CITED: 0.5,
        FeedbackType.COPIED_SNIPPET: 0.7,
        FeedbackType.DWELL_TIME_LONG: 0.2,
        FeedbackType.SKIPPED: -0.1,
    }

    async def collect(self, feedback: RagFeedback) -> None:
        """收集一条 RAG 检索反馈。"""
        weighted_score = feedback.score * self.SIGNAL_WEIGHTS[feedback.feedback_type]
        await db.rag_feedback.insert_one({
            **feedback.__dict__,
            "weighted_score": weighted_score,
        })

    async def update_quality_scores(self) -> dict:
        """批量更新知识文件质量评分（每小时执行）。"""
        # 1. 聚合最近 1 小时的反馈
        pipeline = [
            {"$match": {"timestamp": {"$gte": time.time() - 3600}}},
            {"$group": {
                "_id": "$document_path",
                "total_feedback": {"$sum": 1},
                "weighted_sum": {"$sum": "$weighted_score"},
                "explicit_likes": {"$sum": {"$cond": [
                    {"$eq": ["$feedback_type", "explicit_like"]}, 1, 0
                ]}},
                "explicit_dislikes": {"$sum": {"$cond": [
                    {"$eq": ["$feedback_type", "explicit_dislike"]}, 1, 0
                ]}},
            }},
        ]
        aggregates = await db.rag_feedback.aggregate(pipeline).to_list(None)

        # 2. 使用 EMA 更新质量评分
        ema_alpha = 0.1  # 平滑系数
        updates = {}
        for agg in aggregates:
            doc_path = agg["_id"]
            feedback_score = agg["weighted_sum"] / max(agg["total_feedback"], 1)
            # EMA: new_score = alpha * feedback + (1-alpha) * old_score
            old_doc = await db.knowledge_files.find_one({"path": doc_path})
            old_score = old_doc.get("quality_score", 0.5) if old_doc else 0.5
            new_score = ema_alpha * feedback_score + (1 - ema_alpha) * old_score
            updates[doc_path] = round(new_score, 4)

        # 3. 批量写入
        for path, score in updates.items():
            await db.knowledge_files.update_one(
                {"path": path},
                {"$set": {"quality_score": score, "quality_updated_at": time.time()}}
            )

        return {
            "updated_count": len(updates),
            "avg_score_change": round(sum(updates.values()) / max(len(updates), 1), 4),
        }
```

### 3.2 检索参数自动调优

```python
# YiAi/src/domain/rag/tuner.py

class RagParameterTuner:
    """基于反馈数据自动调优 RAG 检索参数。"""

    def __init__(self):
        self.ema_alpha = 0.05  # 参数更新平滑系数

    async def tune_hybrid_weight(self) -> dict:
        """调优 BM25 vs 向量混合权重。

        分析: 比较 BM25 top-1 和向量 top-1 的采纳率，
        调整 alpha 使高采纳率的检索方式获得更高权重。
        """
        # 1. 计算 BM25 和向量检索的采纳率
        pipeline = [
            {"$match": {
                "feedback_type": {"$in": ["click_through", "source_cited", "explicit_like"]},
                "timestamp": {"$gte": time.time() - 86400},  # 最近 24h
            }},
            {"$lookup": {
                "from": "rag_query_logs",
                "localField": "query_id",
                "foreignField": "query_id",
                "as": "query_log",
            }},
            {"$unwind": "$query_log"},
            {"$group": {
                "_id": "$query_log.retrieval_method",  # "bm25" | "vector" | "hybrid"
                "adoption_count": {"$sum": 1},
            }},
        ]
        method_stats = await db.rag_feedback.aggregate(pipeline).to_list(None)

        # 2. 计算采纳率
        stats = {m["_id"]: m["adoption_count"] for m in method_stats}
        bm25_rate = stats.get("bm25", 0) / max(sum(stats.values()), 1)
        vector_rate = stats.get("vector", 0) / max(sum(stats.values()), 1)

        # 3. 更新 alpha（EMA 平滑）
        current_alpha = settings.rag_hybrid_alpha  # 当前值，如 0.70
        target_alpha = bm25_rate / max(bm25_rate + vector_rate, 0.01)
        new_alpha = (self.ema_alpha * target_alpha +
                     (1 - self.ema_alpha) * current_alpha)

        return {
            "current_alpha": current_alpha,
            "target_alpha": round(target_alpha, 4),
            "new_alpha": round(new_alpha, 4),
            "bm25_adoption_rate": round(bm25_rate, 4),
            "vector_adoption_rate": round(vector_rate, 4),
        }
```

### 3.3 前端反馈 UI

```typescript
// YiVad/YiPet RAG 来源展示组件

interface RagSource {
  path: string;
  title: string;
  score: number;
  snippet: string;
}

function RagSourceCard({ source, queryId }: Props) {
  const [feedback, setFeedback] = useState<'like' | 'dislike' | null>(null);

  const handleFeedback = async (type: 'like' | 'dislike') => {
    setFeedback(type);
    await ragFeedbackService.collect({
      query_id: queryId,
      document_path: source.path,
      feedback_type: type === 'like' ? 'explicit_like' : 'explicit_dislike',
      score: type === 'like' ? 1.0 : -1.0,
    });
  };

  const handleClick = async () => {
    await ragFeedbackService.collect({
      query_id: queryId,
      document_path: source.path,
      feedback_type: 'click_through',
      score: 0.3,  // 隐式正信号
    });
  };

  return (
    <div class="rag-source-card" onClick={handleClick}>
      <div class="source-title">{source.title}</div>
      <div class="source-snippet">{source.snippet}</div>
      <div class="source-score">相关性: {(source.score * 100).toFixed(0)}%</div>
      <div class="source-feedback">
        <button class={feedback === 'like' ? 'active' : ''}
                onClick={() => handleFeedback('like')}>👍 有用</button>
        <button class={feedback === 'dislike' ? 'active' : ''}
                onClick={() => handleFeedback('dislike')}>👎 不相关</button>
      </div>
    </div>
  );
}
```

## 六、测试规格

### Requirement: 反馈收集

#### Scenario: 显式正面反馈
- **Given** RAG 查询返回 3 个来源
- **When** 用户点击 👍 按钮
- **Then** `rag_feedback` 写入 `{feedback_type: "explicit_like", weighted_score: 1.0}`

#### Scenario: 隐式点击反馈
- **Given** RAG 来源列表
- **When** 用户点击来源卡片查看原文
- **Then** `rag_feedback` 写入 `{feedback_type: "click_through", weighted_score: 0.3}`

### Requirement: 质量评分更新

#### Scenario: EMA 平滑更新
- **Given** 文档当前质量评分 0.70，最近反馈评分 0.90
- **When** `update_quality_scores()` 执行（`alpha=0.1`）
- **Then** 新评分 = `0.1 * 0.90 + 0.9 * 0.70 = 0.72`

#### Scenario: 无反馈文档保持原评分
- **Given** 文档当前质量评分 0.65，最近 1 小时无反馈
- **When** `update_quality_scores()` 执行
- **Then** 该文档评分保持 0.65（无更新）

### Requirement: 参数调优

#### Scenario: BM25 采纳率更高时提升 alpha
- **Given** BM25 采纳率 70%，向量采纳率 30%
- **When** `tune_hybrid_weight()` 执行
- **Then** `target_alpha` ≈ 0.70（倾向于 BM25）

## 八、风险与缓解

| 风险 | 概率 | 影响 | 等级 | 缓解措施 | 应急预案 |
|------|------|------|------|----------|----------|
| 反馈数据稀疏（< 1% 用户会 👍/👎） | 高 | 中 | 中 | 隐式信号（点击/引用）作为主要数据源，显式信号作为辅助 | 降低 EMA alpha（0.05），减缓评分变化速度 |
| 恶意反馈（用户恶意点 👎） | 低 | 中 | 低 | 单用户对同文档每天最多 3 次显式反馈；IP 级别速率限制 | 人工审查异常文档评分变化 |
| 参数自动调优导致检索质量波动 | 中 | 中 | 中 | EMA 平滑（alpha=0.05），变化很慢；调优日志可审计 | 回滚参数到手动设置值 |
