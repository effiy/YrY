# YK-09-08: 跨项目知识依赖图谱 — 变更影响分析与知识缺口识别

> 需求编号：YK-09-08 · 优先级：P2 · 人天：1.5d · 状态：需求已编写
> 依赖：YK-09-05（项目知识中心完善）

## 背景

YrY 单体仓库包含 4 个项目（YiVad/YiAi/YiPet/YiKnowledge），知识文件散布在 `projects/` 和各角色目录中。当前各项目的知识文件独立维护，缺少以下能力：

1. **变更影响分析**：修改 `YiAi/domain/rag/` 架构决策后，哪些 YiVad/YiPet 的 PRD/需求文件需要同步更新？
2. **知识缺口识别**：YiPet 是否有对应的安全配置文档？YiKnowledge 中是否有各项目共用的错误处理模式？
3. **跨项目追溯**：从 YiVad 的一个 feature request 能否追溯到 YiAi 对应的 API 设计和 YiPet 的集成方案？

800+ 知识文件中隐含了大量跨项目引用——文件内 Markdown 链接、相同的 tags、共享的 `category` 路径前缀。这些信息未被结构化利用。

## 二、设计决策

### 决策 1：图谱构建方式 — 静态解析 vs 运行时追踪 vs 混合

| 选项 | 精度 | 覆盖率 | 维护成本 |
|------|------|--------|----------|
| 静态解析（解析 Markdown 链接 + frontmatter） | 中 | 中（仅显式引用） | 低 |
| 运行时追踪（YiAi API 调用链） | 高 | 高 | 高 |
| **混合（静态为主 + 语义关联）** | 中-高 | 中-高 | 中 |

**选择：静态解析 + tags/category 语义关联。** 显式 Markdown 链接是强依赖（确定性），tags/category 是弱关联（概率性）。两者互补构建完整依赖图谱。

### 决策 2：图谱存储 — 文件内嵌 vs 独立索引 vs 图数据库

| 选项 | 更新延迟 | 查询能力 | 复杂度 |
|------|----------|----------|--------|
| 文件内嵌 (frontmatter `dependencies: [...]`) | 手动更新 | 低 | 低 |
| MongoDB 独立集合 `knowledge_deps` | 秒级（Knowledge Watcher 更新） | 高 | 中 |
| 图数据库 (Neo4j) | 秒级 | 最高 | 高 |

**选择：MongoDB 独立集合。** Knowledge Watcher 扫描时自动解析和更新依赖关系，无需额外基础设施。

### 决策 3：变更影响范围计算 — 仅直接依赖 vs N 跳传递

| 选项 | 精确度 | 计算量 | 误报 |
|------|--------|--------|------|
| 仅直接依赖（1 跳） | 高 | 低 | 低 |
| 2 跳依赖 | 中-高 | 中 | 中 |
| N 跳（全图遍历） | 低 | 高 | 高 |

**选择：1 跳强依赖 + 2 跳弱关联。** Markdown 链接为 1 跳强依赖（必须同步更新），共享 tags/category 为 2 跳弱关联（建议检查）。

### 设计决策记录

| 决策 | 选项 A | 选项 B | 选项 C | 选择 | 理由 |
|------|--------|--------|--------|------|------|
| 构建方式 | 静态解析 | 运行时追踪 | — | **静态+语义** | 知识库本质是静态文件 |
| 存储方案 | 文件内嵌 | MongoDB | Neo4j | **MongoDB** | 与 Knowledge Watcher 集成 |
| 影响范围 | 1 跳 | N 跳 | — | **1+2 跳** | 精准优先，避免告警风暴 |

## 三、目标架构

### 3.1 依赖关系模型

```python
# YiAi/src/domain/knowledge/dependency.py

from dataclasses import dataclass, field
from enum import Enum

class DependencyType(str, Enum):
    EXPLICIT_LINK = "explicit_link"       # Markdown [text](path) 显式链接
    SHARED_TAGS = "shared_tags"           # 相同 tags（≥ 2 个重叠）
    SHARED_CATEGORY = "shared_category"   # 相同 category 前缀
    CODE_REFERENCE = "code_reference"     # CLAUDE.md/comments 中引用
    PARENT_CHILD = "parent_child"         # 父子关系（项目→子需求）

class DependencyStrength(str, Enum):
    STRONG = "strong"     # 显式链接 — 必须同步
    MODERATE = "moderate" # tags 高度重叠 (≥ 3 个) — 建议检查
    WEAK = "weak"         # category 相同 — 可选

@dataclass
class KnowledgeDependency:
    source_file: str           # 源文件路径
    target_file: str           # 目标文件路径
    dep_type: DependencyType
    strength: DependencyStrength
    context: str | None        # 引用上下文（如链接周围的文本）
    created_at: float = field(default_factory=time.time)

class DependencyGraphBuilder:
    """从知识文件构建跨项目依赖图谱。"""

    def build_graph(self, files: list[dict]) -> list[KnowledgeDependency]:
        deps: list[KnowledgeDependency] = []

        for file_a in files:
            for file_b in files:
                if file_a['path'] == file_b['path']:
                    continue

                # 1. 检测显式 Markdown 链接
                link_deps = self._detect_explicit_links(file_a, file_b)
                deps.extend(link_deps)

                # 2. 检测共享 tags
                tag_deps = self._detect_shared_tags(file_a, file_b)
                deps.extend(tag_deps)

                # 3. 检测共享 category
                cat_deps = self._detect_shared_category(file_a, file_b)
                deps.extend(cat_deps)

        return deps

    def _detect_explicit_links(
        self, source: dict, target: dict
    ) -> list[KnowledgeDependency]:
        """检测 Markdown 内部链接 [text](./path/to/file.md)。"""
        import re
        content = source.get('content', '')
        target_path = target['path']
        # 匹配相对路径链接
        pattern = re.compile(r'\[([^\]]*)\]\(([^)]*' +
                           re.escape(target_path.split('/')[-1]) + r')\)')
        matches = pattern.findall(content)
        return [
            KnowledgeDependency(
                source_file=source['path'],
                target_file=target_path,
                dep_type=DependencyType.EXPLICIT_LINK,
                strength=DependencyStrength.STRONG,
                context=m[0],  # 链接文本
            ) for m in matches
        ]

    def _detect_shared_tags(
        self, source: dict, target: dict
    ) -> list[KnowledgeDependency]:
        """检测共享 tags（≥ 2 个重叠）。"""
        source_tags = set(source.get('tags', []))
        target_tags = set(target.get('tags', []))
        overlap = source_tags & target_tags

        if len(overlap) >= 3:
            strength = DependencyStrength.MODERATE
        elif len(overlap) >= 2:
            strength = DependencyStrength.WEAK
        else:
            return []

        return [KnowledgeDependency(
            source_file=source['path'],
            target_file=target['path'],
            dep_type=DependencyType.SHARED_TAGS,
            strength=strength,
            context=f"共享 tags: {', '.join(overlap)}",
        )]
```

### 3.2 变更影响分析 API

```python
# YiAi/src/services/knowledge/knowledge_service.py

async def analyze_change_impact(file_path: str) -> dict:
    """分析修改某个知识文件的影响范围。

    返回受影响文件列表，按依赖强度分组。
    """
    # 1. 查找所有依赖此文件的其他文件（反向依赖）
    reverse_deps = await db.knowledge_deps.find({
        "target_file": file_path,
    }).to_list(None)

    # 2. 查找此文件依赖的外部文件（前向依赖）
    forward_deps = await db.knowledge_deps.find({
        "source_file": file_path,
    }).to_list(None)

    # 3. 按强度分组
    impact = {
        "changed_file": file_path,
        "must_update": [],     # STRONG — 必须同步更新
        "should_review": [],   # MODERATE — 建议检查
        "may_consider": [],    # WEAK — 可选
        "depends_on": [],      # 此文件依赖的外部文件
    }

    for dep in reverse_deps:
        entry = {"file": dep["source_file"], "reason": dep["context"]}
        if dep["strength"] == "strong":
            impact["must_update"].append(entry)
        elif dep["strength"] == "moderate":
            impact["should_review"].append(entry)
        else:
            impact["may_consider"].append(entry)

    for dep in forward_deps:
        impact["depends_on"].append({
            "file": dep["target_file"],
            "reason": dep["context"],
        })

    return impact
```

### 3.3 知识缺口识别

```python
async def identify_knowledge_gaps() -> list[dict]:
    """识别知识库中的缺口。

    规则:
    1. 4 个项目的 bugs/ 目录下 bug 数量与 requirements/ 中的验收标准不匹配
    2. 角色目录中各项目覆盖率不均衡
    3. 孤立文件——无任何依赖关系的文件
    """
    gaps = []

    # 规则 1: 项目 bugs 数量告警
    project_bug_counts = {
        "yivad": 10,
        "yiai": 17,
        "yipet": 4,
        "yiknowledge": 3,
    }
    avg_bugs = sum(project_bug_counts.values()) / len(project_bug_counts)
    for project, count in project_bug_counts.items():
        if count < avg_bugs * 0.5:  # 低于平均值 50%
            gaps.append({
                "type": "insufficient_bug_tracking",
                "project": project,
                "bug_count": count,
                "expected_minimum": int(avg_bugs * 0.5),
                "suggestion": f"{project} bug 追踪不足，建议补充常见缺陷模式",
            })

    # 规则 2: 孤立文件检测
    all_files = await db.knowledge_files.find().to_list(None)
    all_deps = await db.knowledge_deps.distinct("source_file")
    all_deps += await db.knowledge_deps.distinct("target_file")
    all_deps = set(all_deps)

    for file in all_files:
        if file["path"] not in all_deps:
            gaps.append({
                "type": "orphan_file",
                "file": file["path"],
                "suggestion": "文件无任何依赖关系，可能是孤立内容或缺失链接",
            })

    return gaps
```

## 六、测试规格

### Requirement: 依赖图谱构建

#### Scenario: 显式链接依赖
- **Given** `yivad/requirements/00-需求-需求总览.md` 包含 `[RAG 引擎](../yiai/requirements/01-xxx.md)` 链接
- **When** Knowledge Watcher 扫描此文件
- **Then** `knowledge_deps` 写入一条 STRONG 依赖

#### Scenario: 共享 tags 关联
- **Given** 文件 A `tags: [RAG, 混合检索, BM25, llama_index]` 和文件 B `tags: [RAG, 混合检索, 向量搜索, Ollama]`
- **When** 依赖构建器执行
- **Then** 识别 3 个重叠 tags → 写入一条 MODERATE 依赖

### Requirement: 变更影响分析

#### Scenario: 修改被多个文件引用的文件
- **Given** `yiai/requirements/01-RAG引擎.md` 被 5 个文件显式链接
- **When** 调用 `analyze_change_impact('yiai/requirements/01-RAG引擎.md')`
- **Then** `must_update` 包含 5 个文件

#### Scenario: 修改孤立文件
- **Given** 某文件无任何依赖关系
- **When** 调用 `analyze_change_impact(file_path)`
- **Then** `must_update` 和 `should_review` 均为空
