# YK-09-180: 内容代码示例增强 — 复制按钮、行号、行高亮、Diff 语法、标题头、语言徽章、可运行代码片段

> 需求编号：YK-09-180 · 优先级：P2 · 人天：0.3d · 状态：需求已编写
> 依赖：YK-09-26（代码示例验证——复用代码运行时环境）、YK-09-131（代码示例测试——复用测试用例运行逻辑）、YK-09-123（API参考文档生成——代码示例是 API 文档核心元素）

## 背景

### 问题陈述

YiKnowledge 知识库中大量技术文章包含代码示例——架构设计文档中的配置代码、API 文档中的示例请求、工作流中的脚本片段。但当前代码块只做基础的语法高亮——缺乏现代代码文档应有的辅助功能：

1. **无法一键复制代码**：读者需要手动选中代码——Ctrl+C 复制——但长代码块滚动选中容易漏选——体验差——尤其是移动端几乎无法选中完整代码块
2. **无行号**：讨论特定行代码时——只能描述"第几个 if 块后第 3 行"——沟通效率极低——代码评审引用行号时无法定位
3. **无法高亮特定行**：文档说明"注意第 15-18 行"——但代码块无行号和高亮——读者需要挨个数——浪费时间
4. **Diff 展示不直观**：代码变更对比用 +- 前缀的普通代码块展示——没有彩色 diff 红色/绿色背景——难以区分新增和删除
5. **代码块无标题/语言标识**：长文章中多个代码块——读者无法快速区分哪个是 Python、哪个是 YAML——缺少语言徽章和标题

**核心矛盾**：技术文档的核心价值在于代码示例——但当前最基础的代码阅读辅助功能都缺失——读者在"阅读代码"上消耗了不必要的注意力。目标是对代码块进行系统性增强——复制按钮、行号、行高亮、Diff 彩色渲染、代码块标题/语言徽章——让代码在文档中真正"可读、可操作"。

### 影响范围

| # | 影响 | 严重程度 | 典型场景 |
|---|------|----------|----------|
| 1 | 无法一键复制代码 | 高 | 50 行配置代码——手动选中容易漏行——移动端完全无法操作 |
| 2 | 无行号——引用困难 | 高 | 文档说"修改第 23 行的参数"——代码块无行号——读者需要数 |
| 3 | 无法高亮重点行 | 中 | 大段代码中只有 3 行是关键——无法标记——读者需要全文阅读 |
| 4 | Diff 展示不直观 | 中 | 配置变更文档——+- 符号的普通代码块——无法区分增删 |
| 5 | 多语言代码块混乱 | 低 | 文章同时有 Python/JavaScript/YAML 代码块——无法快速区分 |

### 挑战

| 挑战 | 说明 |
|------|------|
| markdown-it fence 增强 | 拦截 fence block 渲染——添加增强 UI——保持 highlight.js 语法高亮 |
| 复制按钮实现 | Clipboard API——复制代码内容——去除行号——成功/失败反馈——超时重置 |
| 行号计算 | 代码行号与内容行对应——折叠代码块时行号正确——滚动超过视口时行号固定 |
| 行高亮语法 | Markdown fence info 扩展语法——如 `python{3,5-8,12}` 指定高亮行——解析+渲染 |
| Diff 渲染 | 识别 diff 语言——语义化着色——新增行绿色背景——删除行红色背景——上下文行灰色 |
| 可运行代码 | 前端运行时嵌入——JavaScript/Python(Brython)代码可执行——安全沙箱 |

## 二、设计决策

### 决策表 1：代码块增强实现方式

| 选项 | 描述 | 优点 | 缺点 | 决策 |
|------|------|------|------|------|
| A: markdown-it fence 重写 | 重写 fence render 规则——输出增强 HTML 结构——CSS 样式和 JS 交互 | 渲染时即生成增强结构——无闪烁 | 需要维护 fence token 到 HTML 的映射逻辑 | ✅ 选中 |
| B: highlight.js 插件 | 通过 highlight.js 插件在语法高亮阶段附加功能 | 复用 highlight.js 生态 | highlight.js 无法生成 DOM 结构——只输出 HTML 字符串——灵活度低 | ❌ |
| C: JS 后处理 | 页面加载后 querySelectorAll('pre code')——动态注入按钮/行号 | 简单——不修改 markdown-it | 闪烁——页面渲染后 DOM 突变——SEO 不友好 | ❌ |

**决策**：选择 A（markdown-it fence 重写）。在 fence render 阶段——输出包含完整 HTML 结构的增强代码块——包括工具栏（复制按钮/语言徽章）、行号列、高亮行背景。Vue 组件在客户端渲染时接管这个 HTML——添加交互逻辑。无 JavaScript 环境下降级为带行号和复制按钮的静态 HTML——按钮为 mailto:// 的假链接——可访问。

### 决策表 2：行高亮语法设计

| 选项 | 描述 | 优点 | 缺点 | 决策 |
|------|------|------|------|------|
| A: fence info 扩展 | `python{3,5-8,12}` ——大括号中指定行号范围 | 简洁——GitHub 风格——社区熟悉 | 解析规则需文档说明 | ✅ 选中 |
| B: HTML 注释标记 | 在代码行末添加 `<!-- highlight -->` | 精确——作者控制 | 侵入代码内容——污染复制结果 | ❌ |
| C: 独立 meta 行 | fence 第一行 `@highlight:3,5-8,12` | 不侵入语言标识 | 非标准——增加语法——不符合直觉 | ❌ |

**决策**：选择 A（fence info 扩展）。格式 ````python{3,5-8,12}` ——紧跟在语言标识后的大括号——GitHub Flavored Markdown 代码块行高亮使用类似语法（`// [!code highlight]` 注释）。简洁——读者和作者都容易理解。解析器按逗号分割——每个元素可以是单个行号或范围 `start-end`——无重叠处理——覆盖合并。

### 决策表 3：复制功能实现

| 选项 | 描述 | 优点 | 缺点 | 决策 |
|------|------|------|------|------|
| A: Clipboard API | navigator.clipboard.writeText——复制纯文本 | 现代标准——异步——不阻塞——支持 Promise | 需要 HTTPS 或 localhost——权限 | ✅ 选中 |
| B: document.execCommand('copy') | 创建 textarea——select——execCommand | 兼容性好——无需权限 | 已废弃——同步阻塞 | ❌——作为 fallback |
| C: 手动选择 | 用户手动选择——无按钮 | 无额外代码 | 体验差——不符合需求 | ❌ |

**决策**：选择 A（Clipboard API 为主——fallback execCommand）。Clipboard API 是现代标准——异步不阻塞——支持 then/catch 处理成功和失败。复制时去除行号——只复制纯代码内容。复制成功后显示"已复制!"提示——1.5s 后自动消失——按钮图标短暂变为对号。HTTP 环境下 fallback 到 execCommand('copy')。

### 决策表 4：可运行代码策略

| 选项 | 描述 | 优点 | 缺点 | 决策 |
|------|------|------|------|------|
| A: Web Worker 沙箱 | 在 Web Worker 中执行 JavaScript——捕获输出 | 安全——不阻塞主线程——超时控制 | 不支持 DOM API——仅纯 JS | ✅ 选中 |
| B: iframe 沙箱 | 创建 sandboxed iframe——注入代码执行 | 更安全——支持 DOM | 跨域限制——通信复杂——Android WebView 问题 | ❌ |
| C: 不实现可运行 | 仅静态展示——不执行 | 简单 | 失去"可运行"的核心体验价值 | ❌ |

**决策**：选择 A（Web Worker 沙箱）。可运行代码仅支持 JavaScript（纯逻辑）——使用 Web Worker 隔离执行——5 秒超时自动终止——console.log 输出捕获到输出面板。不支持 DOM 操作——明确标注"仅支持纯 JavaScript 逻辑——不支持 DOM/BOM API"。HTML/CSS 示例不可运行——但渲染预览通过 iframe srcdoc 展示。Python 通过 Brython 在线解释器——可选集成。

interface CodeBlockConfig {

// 代码行
interface CodeLine {
  number: number;              // 行号——1-based
  content: string;             // 行内容——纯文本
  highlighted: boolean;        // 是否高亮
  diffType?: 'add' | 'remove' | 'context' | 'header'; // diff 行类型
}

// 复制结果
interface CopyResult {
  success: boolean;
  error?: string;
}

// 运行结果
interface RunResult {
  success: boolean;
  output: string;              // stdout/stderr 输出
  error?: string;              // 错误信息
  executionTime: number;       // 执行耗时 ms
  timedOut: boolean;           // 是否超时

interface EnhancedCodeBlockState {
  config: CodeBlockConfig;
  lines: CodeLine[];
  codeText: string;            // 纯代码文本——无行号——用于复制
  isCopied: boolean;           // 复制反馈状态
  isCollapsed: boolean;        // 折叠状态
  isRunning: boolean;          // 运行中状态
  runResult: RunResult | null;
  showOutput: boolean;         // 是否显示输出面板
}

### 4.2 核心代码：fence info 解析器

```typescript
// src/components/EnhancedCodeBlock/fenceParser.ts
export function parseFenceInfo(info: string): CodeBlockConfig {
  const config: CodeBlockConfig = {
    language: '',
    highlightedLines: [],
    runnable: false,
    collapsed: false,
    diffMode: false,
    wrapLines: false,
  };

  if (!info) return config;

  let remaining = info.trim();

  // 处理大括号内行高亮: python{3,5-8,12}
  const highlightMatch = remaining.match(/^(\w+)\{([^}]+)\}(.*)/);
  if (highlightMatch) {
    config.language = highlightMatch[1];
    config.highlightedLines = parseLineRange(highlightMatch[2]);
    remaining = highlightMatch[3].trim();
  } else {
    // 提取语言标识
    const parts = remaining.split(/\s+/);
    config.language = parts[0];
    remaining = parts.slice(1).join(' ');
  }

  // 处理特殊模式和选项: diff, :run, :collapsed, :wrap, title="xxx"
  const options = remaining.split(/\s+/);
  for (const opt of options) {
    if (opt === ':run') {
      config.runnable = true;
    } else if (opt === ':collapsed') {
      config.collapsed = true;
    } else if (opt === ':wrap') {
      config.wrapLines = true;
    } else if (opt.startsWith('title=')) {
      config.title = opt.replace('title=', '').replace(/^["']|["']$/g, '');
    } else if (opt.startsWith('maxHeight=')) {
      config.maxHeight = parseInt(opt.replace('maxHeight=', ''));
    }
  }

  // 特殊语言处理
  if (config.language === 'diff' || config.language === 'patch') {
    config.diffMode = true;
  }

  return config;
}

/** 解析行号范围: "3,5-8,12" → [3, 5, 6, 7, 8, 12] */
function parseLineRange(range: string): number[] {
  const lines: number[] = [];
  const parts = range.split(',').map(p => p.trim());

  for (const part of parts) {
    if (part.includes('-')) {
      const [start, end] = part.split('-').map(Number);
      if (!isNaN(start) && !isNaN(end) && start <= end) {
        for (let i = start; i <= end; i++) lines.push(i);
      }
    } else {
      const num = parseInt(part);
      if (!isNaN(num)) lines.push(num);
    }
  }

  return [...new Set(lines)].sort((a, b) => a - b);
}
```

// src/plugins/markdown/codeBlockPlugin.ts
import MarkdownIt from 'markdown-it';
import hljs from 'highlight.js';

export function codeBlockPlugin(md: MarkdownIt) {
  const defaultFence = md.renderer.rules.fence!;

  md.renderer.rules.fence = function (tokens, idx, options, env, self) {
    const token = tokens[idx];
    const info = token.info || '';
    const content = token.content;

    // 解析 fence info
    const config = parseFenceInfo(info);

    // 语法高亮
    let highlighted: string;
    if (config.language && hljs.getLanguage(config.language)) {
      try {
        highlighted = hljs.highlight(content, {
          language: config.language,
          ignoreIllegals: true,
        }).value;
      } catch {
        highlighted = md.utils.escapeHtml(content);
      }
    } else {
      highlighted = md.utils.escapeHtml(content);
    }

    // 行拆分
    const lines = highlighted.split('\n');
    // 去除末尾空行
    if (lines[lines.length - 1] === '') lines.pop();

    // 生成行 HTML——带行号和高亮
    const linesHtml = lines.map((lineHtml, i) => {
      const lineNum = i + 1;
      const isHighlighted = config.highlightedLines.includes(lineNum);
      const hClass = isHighlighted ? ' highlighted' : '';
      return `<div class="code-line${hClass}" data-line="${lineNum}">
        <span class="line-number">${lineNum}</span>
        <span class="line-content">${lineHtml || ' '}</span>
      </div>`;
    }).join('\n');

    // 构建完整 HTML 结构
    return `<enhanced-code-block
      data-language="${md.utils.escapeHtml(config.language)}"
      data-title="${md.utils.escapeHtml(config.title || '')}"
      data-runnable="${config.runnable}"
      data-collapsed="${config.collapsed}"
      data-diff-mode="${config.diffMode}"
      data-wrap-lines="${config.wrapLines}"
      data-code-text="${md.utils.escapeHtml(content)}"
    >
      ${linesHtml}
    </enhanced-code-block>`;
  };
}

### 4.4 核心代码：可运行代码执行器

```typescript
// src/components/EnhancedCodeBlock/CodeRunner.ts
export class CodeRunner {
  private worker: Worker | null = null;
  private timeout: number;

  constructor(timeout: number = 5000) {
    this.timeout = timeout;
  }

  /** 在 Web Worker 沙箱中执行代码 */
  async run(code: string): Promise<RunResult> {
    const startTime = performance.now();

    // 创建 Worker 脚本
    const workerCode = `
      const console = {
        _output: [],
        log: function(...args) {
          this._output.push(args.map(a => String(a)).join(' '));
        },
        error: function(...args) {
          this._output.push('[Error] ' + args.map(a => String(a)).join(' '));
        },
        warn: function(...args) {
          this._output.push('[Warn] ' + args.map(a => String(a)).join(' '));
        },
      };

      self.onmessage = function(e) {
        console._output = [];
        try {
          const result = eval(e.data);
          if (result !== undefined) {
            console._output.push('=> ' + JSON.stringify(result));
          }
          self.postMessage({ success: true, output: console._output.join('\\n') });
        } catch (err) {
          self.postMessage({ success: false, output: console._output.join('\\n'), error: err.message });
        }
      };
    `;

    const blob = new Blob([workerCode], { type: 'application/javascript' });
    this.worker = new Worker(URL.createObjectURL(blob));

    return new Promise<RunResult>((resolve) => {
      let timedOut = false;

      const timer = setTimeout(() => {
        timedOut = true;
        this.worker?.terminate();
        resolve({
          success: false,
          output: '',
          error: `代码执行超时 (${this.timeout}ms)`,
          executionTime: this.timeout,
          timedOut: true,
        });
      }, this.timeout);

      this.worker!.onmessage = (e) => {
        clearTimeout(timer);
        const { success, output, error } = e.data;
        resolve({
          success,
          output: output || '',
          error,
          executionTime: performance.now() - startTime,
          timedOut: false,
        });
        this.worker?.terminate();
      };

      this.worker!.onerror = (err) => {
        clearTimeout(timer);
        resolve({
          success: false,
          output: '',
          error: err.message,
          executionTime: performance.now() - startTime,
          timedOut: false,
        });
      };

      this.worker!.postMessage(code);
    });
  }

  destroy(): void {
    if (this.worker) {
      this.worker.terminate();
      this.worker = null;
    }
  }
}
```

## 九、设计决策记录

### D-01：markdown-it fence 重写——非 JS 后处理

**上下文**：需要在保持语法高亮的同时添加交互 UI——不能破坏 highlight.js 的输出。

**决策**：重写 markdown-it fence render 规则——在 highlight.js 语法高亮后——进行行拆分——生成 `<enhanced-code-block>` 自定义元素——包含工具栏和行号。

**理由**：在渲染管线中处理——不需要在 DOM 加载后二次遍历——无闪烁——SEO 友好（自定义元素内含完整代码文本）。highlight.js 不感知增强——只负责语法高亮——增强在 hoc 中实现——职责分离。

### D-02：fence info 扩展语法——大括号行高亮

**上下文**：需要在 Markdown 中表达行高亮——但 Markdown 标准 fence 不提供此能力。

**决策**：使用 `python{3,5-8,12}` 语法——在大括号中指定行号范围——紧跟语言标识。

**理由**：语法简洁——一目了然——不污染代码内容。逗号分隔单个行号——减号分隔行范围。解析器使用正则轻松提取——向后兼容——无大括号时行为不变。多个行范围去重合并——超出总行数截断——不报错。

### D-03：Web Worker 沙箱执行——非 iframe

**上下文**：可运行代码需要安全隔离——不能访问主页面 DOM 和存储。

**决策**：使用 Web Worker 执行 JavaScript 代码——通过 Blob URL 创建 worker 脚本——注入 mock console 捕获输出。

**理由**：Web Worker 在独立线程运行——无 DOM 访问——无 window 对象——无 localStorage/cookie。通过 Blob URL 创建——无需额外文件——纯内存运行——用完即销毁。Worker 内 eval 执行代码——捕获 console.log/warn/error 输出——返回给主线程。5 秒超时自动 terminate——防止无限循环。

### D-04：Clipboard API 优先——execCommand fallback

**上下文**：复制功能需要在各种环境下可靠工作——包括 HTTP 开发环境。

**决策**：优先使用 Clipboard API——失败时 fallback 到 execCommand('copy')。

**理由**：Clipboard API 是现代标准——异步——不阻塞 UI。但需要安全上下文（HTTPS/localhost）和用户权限——开发环境（HTTP localhost）可能不可用。execCommand 虽然已弃用——但兼容性好——在 HTTP 环境下仍然有效——成为可靠的 fallback。两个方案都失败时——显示手动选择提示。
