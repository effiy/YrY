## Description

YiAi 的 Knowledge Watcher（`apscheduler` 每 5 秒轮询）在扫描 YiKnowledge 目录时，存在文件写入与扫描的竞态条件。当用户正在写入文件（如 `git checkout`、编辑器自动保存）时，Watcher 恰好扫描到该文件——文件可能为空或内容不完整——导致：
- 文件被标记为 "已索引"（记录到 MongoDB `knowledge_files` 集合）
- 实际内容未被正确解析（frontmatter 缺失或内容为空）
- 后续轮询中，文件 `mtime` 未变化，Watcher 不会重新扫描
- RAG 检索中该文件的内容为空或损坏

**触发条件：**
- 大文件写入时间 > 5 秒（Watcher 轮询间隔）
- `git clone` 或 `git checkout` 大量文件时
- 批量编辑（查找替换）多个文件时

## Steps to Reproduce

1. 创建一个 500KB 的 markdown 文件（模拟大文件写入）
2. 使用 `dd` 命令缓慢写入（模拟慢速磁盘 I/O）：
   ```bash
   dd if=/dev/urandom of=YiKnowledge/engineer/build/large-file.md bs=1024 count=500
   ```
3. 在写入过程中，Knowledge Watcher 可能扫描到部分写入的文件
4. 检查 MongoDB `knowledge_files` 集合——该文件的 `content_hash` 与最终文件内容不匹配
5. RAG 检索该文件——内容为空或不完整

## Expected Result

Knowledge Watcher 应检测文件是否正在被写入（如通过文件锁或 `mtime` 稳定检测），避免扫描未完成写入的文件。

## Actual Result

Knowledge Watcher 在文件写入过程中扫描到部分文件，将其标记为已索引，后续不再更新。

## Root Cause

`watcher.py` 的扫描逻辑未检测文件写入状态：

```python
# domain/knowledge/watcher.py:78 — 修复前
def scan_files(self) -> dict:
    current_files = {}
    for root, _, files in os.walk(self.knowledge_dir):
        for file in files:
            if not file.endswith(".md"):
                continue
            filepath = os.path.join(root, file)
            stat = os.stat(filepath)
            current_files[filepath] = {
                "mtime": stat.st_mtime,
                "size": stat.st_size,
            }
    # 与上次扫描结果对比，mtime 变化即认为文件已修改
    # 未检测文件是否正在被写入
```

**根本原因：** 缺少文件写入稳定性检测。文件 `mtime` 在写入开始时即更新，但文件内容可能尚未完全写入。

## Fix

### 1. 文件写入稳定性检测

```python
# domain/knowledge/watcher.py
import time

FILE_STABLE_WAIT_MS = 500  # 文件 mtime/size 稳定 500ms 后才认为写入完成

def _is_file_stable(self, filepath: str) -> bool:
    """Check if file is stable (not being written to)."""
    try:
        stat1 = os.stat(filepath)
        time.sleep(FILE_STABLE_WAIT_MS / 1000)
        stat2 = os.stat(filepath)
        return (
            stat1.st_mtime == stat2.st_mtime and
            stat1.st_size == stat2.st_size
        )
    except FileNotFoundError:
        return False

def scan_files(self) -> dict:
    current_files = {}
    for root, _, files in os.walk(self.knowledge_dir):
        for file in files:
            if not file.endswith(".md"):
                continue
            filepath = os.path.join(root, file)
            if not self._is_file_stable(filepath):
                logger.debug(f"Skipping unstable file: {filepath}")
                continue
            stat = os.stat(filepath)
            current_files[filepath] = {
                "mtime": stat.st_mtime,
                "size": stat.st_size,
            }
    # ...
```

### 2. 内容校验

```python
# domain/knowledge/parser.py
def parse_knowledge_file(self, filepath: str) -> dict | None:
    with open(filepath, "r") as f:
        content = f.read()

    # 校验 frontmatter 完整性
    if not content.startswith("---"):
        logger.warning(f"File missing frontmatter: {filepath}")
        return None

    try:
        metadata = parse_frontmatter(content)
    except yaml.YAMLError as e:
        logger.warning(f"Frontmatter parse error in {filepath}: {e}")
        return None

    # 校验必需字段
    required_fields = ["title", "tags", "category", "created", "updated", "source", "type", "status"]
    missing = [f for f in required_fields if f not in metadata]
    if missing:
        logger.warning(f"Missing required fields in {filepath}: {missing}")
        return None

    return metadata
```

## Verification

- 大文件写入过程中 → Watcher 跳过该文件（`Skipping unstable file` 日志）
- 文件写入完成后 → 下一次轮询（5s 后）正常扫描并索引
- 批量写入 100 个文件 → 所有文件在写入完成后被正确索引
- 空文件（0 字节）→ 被跳过（`File missing frontmatter` 日志）

## Prevention

- **代码层面：** Knowledge Watcher MUST 在扫描前检测文件稳定性
- **配置层面：** `FILE_STABLE_WAIT_MS` 可配置，默认 500ms
- **监控层面：** 记录被跳过的 "不稳定文件" 数量，若持续增长则表明系统 I/O 瓶颈
- **架构层面：** 考虑使用 `watchdog` 库替代轮询，通过文件系统事件（`IN_CLOSE_WRITE`）检测写入完成
