## 角色责任链

角色在流水线中不是平级的，有明确的上游/下游关系：

```
executiver ──→ producter ──→ leader ──→ engineer ──→ srer
  (why)         (what)       (which)     (how)       (run)

  Business       Product      Tech        Impl        Ops
  strategy       requirements decisions   patterns    procedures
```

| 角色 | 目录 | 管道阶段 | 输出 |
|------|------|---------|------|
| executiver | `executiver/` | 业务战略层 | 市场分析、竞争策略、组织目标 |
| producter | `producter/` | 1. 需求 | PRD、用户故事、优先级 |
| leader | `leader/` | 2. 决策 | ADR、技术选型、容量规划 |
| engineer | `engineer/` | 3. 设计构建 | 架构模式、开发实践、质量安全 |
| srer | `srer/` | 4-5. 发布+运营 | 发布流程、事件响应、可观测性 |
| aier | `aier/` | AI 赋能层 | AI 基础、方法论、平台、ML |
| curator | `curator/` | 治理层 | 生命周期、分类标准、模板 |

## 3 层架构

### 业务战略层 (executiver/)

贯穿整个管道的商业上下文。子目录：`strategy/` (企业战略)、`industry/` (市场趋势)、`roadmap/` (组织目标)、`reading-list/` (学习资源)。

### AI 赋能层 (aier/)

AI 不是独立的管道阶段，而是渗透每个阶段的加速器。子目录：`foundations/` (AI 基础)、`methodology/` (RAG/Agent)、`platform/` (向量库/嵌入模型)、`ml/` (传统 ML)。

### 知识治理层 (curator/)

元层，不产出领域知识，维护知识库的结构和健康。子目录：`governance/` (生命周期)、`diagrams/` (架构图)、`archive/` (已弃用)、`templates/` (模板)。

## AI 检索架构

```
YiKnowledge (Markdown 文件树, 1000+ 文件)
  ↓ apscheduler 每 60s 轮询
YiAi Knowledge Watcher
  ↓ 解析 YAML frontmatter (title/tags/category/roles/benefit/...)
  ↓ 提取正文 (Summary/Core viewpoints/Key info/Action recommendations)
MongoDB knowledge_files 集合
  ↓ llama_index 索引构建 (VectorStoreIndex)
Vector Index (data/rag_store/)
  ↓ 混合检索: 向量相似度 + BM25 关键词
  ↓ 可选 LLM Rerank + HyDE 查询增强 + Sentence Window 检索
  ↓ 内联引用编号
RAG 查询 → YiAi BRD Agent → 用户
```

## 设计原则

1. **角色优先，边界清晰** — 每条知识属于唯一角色目录，多角色覆盖用 frontmatter `roles:`
2. **描述性文件名** — 动词短语 slug，kebab-case，无下划线和数字
3. **外部内容双文件** — `*-original.md` (源文件) + `*-summary.md` (合成)
4. **YAML frontmatter 必填** — 13 个字段作为检索信号
5. **统一正文结构** — Summary / Core viewpoints / Key information / Action recommendations
6. **新鲜度标记** — `last_verified` + `review_cycle`，6 个月未验证标记 `deprecated`
7. **最多 3 层目录** — `role/problem-domain/file.md`
8. **Chip 契约** — 每个管道阶段有明确的 Input chips (从上游消费) 和 Output chips (为下游产出)

## 导航策略

| 方式 | 适用场景 |
|------|---------|
| 管道阶段优先 | 从当前阶段进入对应角色目录 |
| 角色目录 | 按角色索引找到具体问题域 |
| 领域索引 | 跨角色主题 (SECURITY/COLLABORATION/ENGINEERING) |
| 文件名 grep | `rg "^tags:.*keyword" YiKnowledge -l` |
| Frontmatter 扫描 | `head -15 file.md` 快速判断相关性 |
