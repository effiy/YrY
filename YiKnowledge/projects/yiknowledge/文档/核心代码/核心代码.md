# 核心代码

> YiKnowledge 是纯 Markdown 知识库，无运行时代码。本章档描述知识管线的核心流程和治理机制，等同于其他项目的"核心代码"。

## 知识管线

```
写入 (curator/engineer/leader/...)
  ↓ 遵循角色边界决策树
  ↓ kebab-case 文件名，YAML frontmatter 必填
  ↓
YiKnowledge Markdown 文件树
  ↓ apscheduler 每 60s 轮询
  ↓
YiAi Knowledge Watcher
  ↓ 解析 frontmatter + 正文
  ↓
MongoDB knowledge_files 集合
  ↓ llama_index 索引构建
  ↓
Vector Index (data/rag_store/)
  ↓ 混合检索 (向量 + BM25)
  ↓
RAG 查询 → YiAi BRD Agent
```

## 关键模块

| 模块 | 路径 | 核心逻辑 |
|------|------|----------|
| 角色目录 | `{executiver,producter,leader,engineer,srer,aier,curator}/` | 7 个角色，每个角色拥有唯一知识域 |
| 项目知识 | `projects/{yivad,yiai,yipet,yiknowledge}/` | 项目级文档、Bug、Issue、Demo |
| 知识治理 | `curator/治理/` | 生命周期管理、分类标准、就绪清单 |
| 领域索引 | `{engineer,curator}/SECURITY\|COLLABORATION\|ENGINEERING.md` | 跨角色主题聚合 |
| 模板 | `curator/templates/` | 知识文件、ADR、BRD 模板 |
| 存档 | `curator/archive/` | 已弃用内容索引 |

## 知识生命周期

```
Draft → Review → Stable → Deprecated → Archived
  ↓        ↓        ↓         ↓           ↓
 新建     curator  稳定      6个月未     curator
         审核      使用      验证       移入存档
```

## 治理检查点

| 检查点 | 频率 | 工具 |
|--------|------|------|
| 就绪清单 | 每次新增 | `curator/治理/readiness-checklist.md` |
| 新鲜度检查 | 每季度 | `last_verified` + `review_cycle` 字段 |
| 弃用审查 | 每半年 | 未验证 6 个月 → `status: deprecated` |
| 重复检测 | 按需 | `rg "^title:.*" YiKnowledge -l \| sort` |

## Frontmatter 规范

每个知识文件必须包含以下 YAML frontmatter：

| 字段 | 必填 | 说明 |
|------|------|------|
| `title` | 是 | 文件标题 |
| `tags` | 是 | 标签数组 |
| `category` | 是 | 所属分类 |
| `created` | 是 | 创建日期 |
| `updated` | 是 | 最后更新日期 |
| `source` | 是 | 来源 (internal/external) |
| `type` | 是 | 类型 (summary/analysis/参考/howto) |
| `status` | 是 | 状态 (draft/review/stable/deprecated/archived) |
| `lifecycle` | 否 | 生命周期阶段 |
| `review_cycle` | 否 | 审查周期 (weekly/monthly/quarterly) |
| `last_verified` | 否 | 最后验证日期 |
| `roles` | 否 | 适用角色数组 |
| `benefit` | 否 | 知识价值描述 |
| `acceptance_criteria` | 否 | 验收标准 |
| `related` | 否 | 关联文件路径 |

## AI 检索引擎集成

YiAi 的知识库监听器 (`knowledge_watcher`) 通过以下流程将知识库同步到 RAG 检索引擎：

1. **轮询扫描** — `apscheduler` 每 60 秒扫描 `YiKnowledge/` 目录树
2. **Frontmatter 解析** — 提取 YAML 元数据作为检索信号
3. **MongoDB 同步** — 写入 `knowledge_files` 集合
4. **向量索引** — `llama_index` 构建混合索引 (向量 + BM25)
5. **RAG 查询** — BRD Agent 通过 `/rag/*` 端点检索
