# Pattern: Knowledge Entry

> 知识条目创建模式：完整模板、frontmatter 字段、正文结构、生命周期管理、RAG 优化、验证脚本、批量操作、质量评分、反模式。每个知识条目是 Markdown 文件，同时服务于人类查阅和 AI RAG 检索。

## 一、概述

YiKnowledge 中的每个知识条目是一个 Markdown 文件，包含 YAML frontmatter 元数据和结构化正文。知识条目是 RAG 检索的基本单元，frontmatter 字段直接映射为检索信号。

**设计目标**：
- **人类可读**：清晰的标题层级、表格、代码块，便于浏览和查阅
- **AI 可索引**：高信息密度 Summary + 精准 tags + 结构化正文，提升 RAG 检索精度
- **可维护**：完整的生命周期管理，6 个月新鲜度保证

## 二、完整模板

```markdown
---
title: 文件标题
tags: [tag1, tag2, tag3]
category: role/domain
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: internal
type: analysis
status: draft
lifecycle: active
review_cycle: quarterly
last_verified: YYYY-MM-DD
roles: [role1, role2]
benefit: "简短描述"
acceptance_criteria:
  - "可验证的条款"
related:
  - relative/path/to/file.md
---

# 文件标题

> 一句话概述核心内容（高信息密度，用于 RAG 检索）

## Summary
一句话概述核心内容

## Core viewpoints
- 观点 1：详细说明
- 观点 2：详细说明

## Key information
详细的技术信息、数据、配置

## Action recommendations
具体可执行的行动建议

## Anti-patterns（可选）
常见错误和避免方法

## Related links（可选）
- [相关文件](./related-file.md)
- [外部参考](https://example.com)
```

## 三、Frontmatter 字段

### 必填字段（8 个）

| 字段 | 类型 | 说明 | 示例 | 验证规则 |
|------|------|------|------|----------|
| `title` | string | 文件标题（中文） | `"实现 API 接口"` | 非空，建议 5-30 字 |
| `tags` | array | 3-5 个具体标签 | `[api, fastapi, implementation]` | 3 ≤ len ≤ 5，全小写英文 |
| `category` | string | 角色/问题域分类 | `engineer/build` | 格式 `role/domain`，至少两级 |
| `created` | date | 创建日期 | `2026-09-07` | YYYY-MM-DD，无引号 |
| `updated` | date | 最后更新日期 | `2026-09-07` | YYYY-MM-DD，无引号 |
| `source` | string | 来源 | `internal` / `external` | 枚举值 |
| `type` | string | 内容类型 | `analysis` / `howto` / `reference` / `summary` | 枚举值 |
| `status` | string | 内容状态 | `draft` / `review` / `stable` / `deprecated` / `archived` | 枚举值 |

### 可选字段（7 个）

| 字段 | 类型 | 说明 | 示例 | 何时必填 |
|------|------|------|------|----------|
| `lifecycle` | string | 生命周期阶段 | `active` | 建议始终填写 |
| `review_cycle` | string | 审查周期 | `quarterly` | status=stable 时建议填写 |
| `last_verified` | date | 最后验证日期 | `2026-09-07` | status=stable 时必须填写 |
| `roles` | array | 适用角色 | `[leader, engineer]` | 多角色覆盖时必须填写 |
| `benefit` | string | 知识价值描述 | `"为微服务技术选型提供决策参考"` | 建议始终填写 |
| `acceptance_criteria` | array | 验收标准 | `["可通过 curl 调用"]` | type=howto 时建议填写 |
| `related` | array | 关联文件路径 | `[./related-file.md]` | 有明确关联文件时填写 |

### 字段类型枚举

**type（内容类型）**：

| 值 | 说明 | 适用场景 | 正文结构要求 |
|----|------|----------|-------------|
| `analysis` | 分析 | 技术调研、方案对比、决策分析 | 必须有对比数据和结论 |
| `howto` | 操作指南 | 步骤说明、配置指南、操作手册 | 必须有可执行步骤 |
| `reference` | 参考 | API 文档、配置参数、速查表 | 必须有完整参数说明 |
| `summary` | 摘要 | 会议纪要、学习笔记、阅读摘要 | 必须有来源标注 |

**status（内容状态）**：

| 值 | 说明 | RAG 检索 | 生命周期阶段 | 转换条件 |
|----|------|----------|-------------|----------|
| `draft` | 草稿 | 不检索 | inbox | 初始状态 |
| `review` | 审核中 | 不检索 | triage | 提交 curator 审核 |
| `stable` | 稳定 | 正常检索 | active | 审核通过 |
| `deprecated` | 已弃用 | 降低权重 | reference | 6 个月未验证或内容过时 |
| `archived` | 已归档 | 不检索 | archive | curator 移入 archive/ |

## 四、内容结构

### 正文层级规范

```
# 文件标题（H1）
  │
  ├── > 一句话概述（blockquote，高信息密度）
  │
  ├── ## Summary（H2，必填）
  │     一句话概述核心内容，包含关键术语
  │
  ├── ## Core viewpoints（H2，必填）
  │     - 观点 1：详细说明（含数据支撑）
  │     - 观点 2：详细说明
  │
  ├── ## Key information（H2，必填）
  │     详细的技术信息、数据、配置、代码示例
  │
  ├── ## Action recommendations（H2，必填）
  │     具体可执行的行动建议（含命令/步骤）
  │
  ├── ## Anti-patterns（H2，可选）
  │     常见错误和避免方法
  │
  └── ## Related links（H2，可选）
        - 相关文件链接（相对路径）
        - 外部参考链接（完整 URL）
```

### 各章节内容要求

| 章节 | 最低要求 | 优秀标准 | 检查方法 |
|------|----------|----------|----------|
| Summary | 1 句话，包含核心术语 | 2-3 句，高信息密度，含关键词 | 读一遍能否理解文件主题 |
| Core viewpoints | 至少 2 个观点 | 3-5 个观点，每个有数据或示例支撑 | 观点是否可独立验证 |
| Key information | 至少 1 个表格或代码块 | 多维度信息（表格+代码+配置+数据） | 信息是否可直接引用 |
| Action recommendations | 至少 1 个可执行建议 | 3-5 个建议，含命令/步骤/预期结果 | 按建议操作能否成功 |
| Anti-patterns | 至少 2 个反模式 | 4-6 个，含错误示例+正确做法+原因 | 每个反模式是否有对比 |

### 内容质量评分

| 维度 | 权重 | 1 分（不合格） | 3 分（合格） | 5 分（优秀） |
|------|------|--------------|-------------|-------------|
| 准确性 | 30% | 无数据支撑 | 有来源引用 | 多源交叉验证 |
| 完整性 | 25% | 缺 2+ 必填章节 | 4 个必填章节齐全 | 含可选章节，信息丰富 |
| 可操作性 | 20% | 无行动建议 | 有通用建议 | 含命令/代码/预期结果 |
| 时效性 | 15% | last_verified 超 12 个月 | 6 个月内验证 | 3 个月内验证 |
| RAG 友好 | 10% | tags 宽泛，Summary 简短 | 3-5 tags，Summary 含关键词 | benefit 精准，正文结构化 |

# 1. 确定角色和问题域
ROLE="leader"
DOMAIN="decisions"

# 2. 检查目录层级（不超过 3 级）
TARGET_DIR="YiKnowledge/${ROLE}/${DOMAIN}"
if [ $(echo "${TARGET_DIR}" | tr '/' '\n' | wc -l) -gt 3 ]; then
  echo "错误：目录层级超过 3 级"
  exit 1
fi

# 3. 检查文件名（kebab-case，无下划线和数字）

### Python 验证脚本

```python
#!/usr/bin/env python3
"""validate_knowledge.py — 验证知识文件是否符合规范"""

import os
import re
import sys
import yaml
from datetime import datetime, timedelta

REQUIRED_FIELDS = ["title", "tags", "category", "created", "updated", "source", "type", "status"]
VALID_TYPES = {"analysis", "howto", "reference", "summary"}
VALID_STATUSES = {"draft", "review", "stable", "deprecated", "archived"}
VALID_SOURCES = {"internal", "external"}
VALID_ROLES = {"executiver", "producter", "leader", "engineer", "srer", "aier", "curator"}

def parse_frontmatter(content: str) -> tuple[dict | None, str, str | None]:
    """解析 YAML frontmatter，返回 (frontmatter, body, error)"""
    if not content.startswith("---"):
        return None, content, "缺少 frontmatter 分隔符 '---'"
    
    parts = content.split("---", 2)
    if len(parts) < 3:
        return None, content, "frontmatter 格式错误"
    
    try:
        frontmatter = yaml.safe_load(parts[1])
        if not isinstance(frontmatter, dict):
            return None, content, "frontmatter 不是有效的 YAML 映射"
        return frontmatter, parts[2], None
    except yaml.YAMLError as e:
        return None, content, f"YAML 解析错误: {e}"

def validate_file(filepath: str) -> list[str]:
    """验证单个文件，返回错误列表"""
    errors = []
    
    # 1. 文件名检查
    filename = os.path.basename(filepath)
    if not re.match(r'^[a-z][a-z0-9-]*[a-z0-9]\.md$', filename):
        errors.append(f"文件名不符合 kebab-case: {filename}")
    if '_' in filename:
        errors.append(f"文件名包含下划线: {filename}")
    
    # 2. 目录层级检查
    rel_path = os.path.relpath(filepath, "YiKnowledge")
    depth = len(rel_path.split(os.sep))
    if depth > 3:
        errors.append(f"目录层级超过 3 级 (当前 {depth}): {rel_path}")
    
    # 3. 文件大小检查
    size_mb = os.path.getsize(filepath) / (1024 * 1024)
    if size_mb > 10:
        errors.append(f"文件过大 ({size_mb:.1f}MB)，超过 10MB 限制")
    
    # 4. 编码检查
    try:
        with open(filepath, 'r', encoding='utf-8') as f:
            content = f.read()
    except UnicodeDecodeError:
        errors.append("文件编码不是 UTF-8")
        return errors
    
    # 5. Frontmatter 检查
    frontmatter, body, parse_error = parse_frontmatter(content)
    if parse_error:
        errors.append(parse_error)
        return errors
    
    # 6. 必填字段检查
    for field in REQUIRED_FIELDS:
        if field not in frontmatter or frontmatter[field] is None:
            errors.append(f"缺少必填字段: {field}")
    
    # 7. tags 检查
    if "tags" in frontmatter and frontmatter["tags"]:
        tags = frontmatter["tags"]
        if not isinstance(tags, list):
            errors.append("tags 必须是数组")
        else:
            if len(tags) < 3:
                errors.append(f"tags 至少 3 个，当前 {len(tags)} 个")
            if len(tags) > 5:
                errors.append(f"tags 最多 5 个，当前 {len(tags)} 个")
            for tag in tags:
                if not re.match(r'^[a-z][a-z0-9-]*$', str(tag)):
                    errors.append(f"tag 包含中文或大写: {tag}")
    
    # 8. 日期格式检查
    for date_field in ["created", "updated", "last_verified"]:
        if date_field in frontmatter and frontmatter[date_field]:
            val = str(frontmatter[date_field])
            if not re.match(r'^\d{4}-\d{2}-\d{2}$', val):
                errors.append(f"{date_field} 格式错误: {val}，应为 YYYY-MM-DD")
    
    # 9. 枚举值检查
    if frontmatter.get("type") not in VALID_TYPES:
        errors.append(f"type 值无效: {frontmatter.get('type')}")
    if frontmatter.get("status") not in VALID_STATUSES:
        errors.append(f"status 值无效: {frontmatter.get('status')}")
    if frontmatter.get("source") not in VALID_SOURCES:
        errors.append(f"source 值无效: {frontmatter.get('source')}")
    
    # 10. category 格式检查
    category = frontmatter.get("category", "")
    if not re.match(r'^[a-z]+/[a-z-]+$', category):
        errors.append(f"category 格式错误: {category}，应为 role/domain")
    
    # 11. 内容结构检查
    required_sections = ["Summary", "Core viewpoints", "Key information", "Action recommendations"]
    for section in required_sections:
        if f"## {section}" not in body:
            errors.append(f"缺少正文章节: ## {section}")
    
    # 12. 新鲜度检查
    if "last_verified" in frontmatter and frontmatter["last_verified"]:
        try:
            verified_date = datetime.strptime(str(frontmatter["last_verified"]), "%Y-%m-%d")
            if datetime.now() - verified_date > timedelta(days=180):
                errors.append(f"内容超过 6 个月未验证 (last_verified: {frontmatter['last_verified']})")
        except ValueError:
            pass
    
    return errors

def validate_directory(base_dir: str = "YiKnowledge") -> dict:
    """批量验证目录下所有知识文件"""
    results = {"total": 0, "passed": 0, "failed": 0, "files": {}}
    
    for root, dirs, files in os.walk(base_dir):
        # 跳过隐藏目录和归档
        dirs[:] = [d for d in dirs if not d.startswith('.') and d != 'archive']
        
        for f in files:
            if not f.endswith('.md'):
                continue
            filepath = os.path.join(root, f)
            results["total"] += 1
            errors = validate_file(filepath)
            if errors:
                results["failed"] += 1
                results["files"][filepath] = errors
            else:
                results["passed"] += 1
    
    return results

if __name__ == "__main__":
    target = sys.argv[1] if len(sys.argv) > 1 else "YiKnowledge"
    
    if os.path.isfile(target):
        errors = validate_file(target)
        if errors:
            print(f"❌ {target} — {len(errors)} 个错误:")
            for e in errors:
                print(f"  - {e}")
        else:
            print(f"✅ {target} — 验证通过")
    else:
        results = validate_directory(target)
        print(f"总计: {results['total']} 文件")
        print(f"通过: {results['passed']} ✅")
        print(f"失败: {results['failed']} ❌")
        if results["failed"] > 0:
            print("\n失败详情:")
            for filepath, errors in results["files"].items():
                print(f"\n  {filepath}:")
                for e in errors:
                    print(f"    - {e}")
```

## 六、生命周期管理

### 状态流转图

```
                    ┌─────────┐
                    │  draft  │  ← 新建文件
                    └────┬────┘
                         │ 提交 curator 审核
                         ▼
                    ┌─────────┐
                    │ review  │  ← curator 分类审核
                    └────┬────┘
                         │ 审核通过
                         ▼
                    ┌─────────┐
                    │ stable  │  ← 活跃使用，RAG 正常检索
                    └────┬────┘
                         │ 6 个月未验证 或 内容过时
                         ▼
                    ┌──────────┐
                    │deprecated│  ← RAG 降低权重
                    └────┬─────┘
                         │ curator 归档
                         ▼
                    ┌─────────┐
                    │archived │  ← RAG 不检索
                    └─────────┘
```

### 生命周期阶段详解

| 阶段 | status | 触发条件 | 操作 | 审查周期 | RAG 检索 |
|------|--------|----------|------|----------|----------|
| `inbox` | `draft` | 新建文件 | 作者填写 frontmatter + 正文 | — | 不检索 |
| `triage` | `review` | curator 审核 | curator 验证分类、tags、结构 | — | 不检索 |
| `active` | `stable` | 审核通过 | 定期 review，保持新鲜度 | 按 review_cycle | 正常检索 |
| `reference` | `stable` | 不再频繁更新 | 降低 review_cycle 为 yearly | yearly | 正常检索 |
| `archive` | `deprecated` | 6 个月未验证 | 标记为 deprecated，降低权重 | — | 降低权重 |
| `archive` | `archived` | curator 归档 | 移入 curator/archive/ | — | 不检索 |

### 审查周期选择

| 周期 | 适用内容 | 示例 | 过期判定 |
|------|----------|------|----------|
| `weekly` | 快速变化的 API 文档、配置参数 | API 端点文档、环境变量配置 | 2 周未验证 |
| `monthly` | 开发实践、工具链、依赖 | 构建配置、lint 规则、部署流程 | 2 月未验证 |
| `quarterly` | 架构决策、方法论、模式 | ADR、架构模式、设计模式 | 6 月未验证 |
| `yearly` | 基础理论、行业分析、最佳实践 | 设计原则、安全基础、语言特性 | 18 月未验证 |

## 七、RAG 优化策略

### 分块策略与正文结构

llama_index 按 chunk_size=512 tokens 对正文进行分块。良好的正文结构确保每个 chunk 保持语义完整性：

```
❌ 差的分块（大段文字无标题）:
  Chunk 1: "微服务架构是一种软件架构模式...（前 512 tokens）"
  Chunk 2: "...（续）服务间通过 API 通信...（续 512 tokens）"
  → 每个 chunk 缺少上下文，检索精度低

✅ 好的分块（H2/H3 标题分隔）:
  Chunk 1: "## 微服务拆分原则\n- 按业务边界拆分\n- 独立数据库\n..."
  Chunk 2: "## 服务间通信\n- 同步：RPC/gRPC\n- 异步：消息队列\n..."
  → 每个 chunk 是独立的语义单元，检索精度高
```

### 提升检索质量的 7 个技巧

1. **精准标签** — tags 使用 3-5 个具体标签，避免过于宽泛
   - ❌ `tags: [tech, code, dev]`
   - ✅ `tags: [fastapi, middleware, auth, jwt]`

2. **高密度 Summary** — blockquote 和 Summary 章节包含关键术语
   - ❌ `> 这是一个 API 文档`
   - ✅ `> FastAPI 中间件认证实现，支持 JWT + bcrypt，包含 Token 刷新和权限校验`

3. **结构化正文** — 使用清晰的 H2/H3 标题层级，每个 H2 是一个独立语义单元
   - 每个 H2 章节控制在 200-400 tokens，确保分块边界与章节边界对齐

4. **benefit 字段** — 写清楚知识的独特价值，帮助 RAG 判断相关性
   - ❌ 空
   - ✅ `"为微服务框架选型提供完整决策依据，包含性能对比和迁移成本评估"`

5. **关键词覆盖** — 正文中自然包含同义词和相关术语
   - 如写 "认证" 时同时提及 "auth"、"authentication"、"login"、"token"

6. **表格数据** — 对比信息使用表格，向量检索对结构化数据更敏感
   - 技术选型对比、性能数据、配置参数等优先使用表格

7. **代码示例** — 关键实现提供代码片段，BM25 可匹配代码中的 API 名称
   - 代码块使用语言标记（```python、```bash），便于解析

### 检索信号映射

| Frontmatter 字段 | 检索信号 | 权重 | 索引方式 | 说明 |
|------------------|----------|------|----------|------|
| `title` | 标题向量 | 高 | VectorStoreIndex | 标题与查询的语义相似度 |
| `tags` | BM25 关键词 | 高 | BM25 索引 | 标签与查询关键词的精确匹配 |
| `category` | Scope 过滤 | 中 | MongoDB 查询 | 分类限定检索范围 |
| `benefit` | 相关性评估 | 中 | LLM Rerank 输入 | 帮助判断内容与查询的相关性 |
| `status` | 内容过滤 | — | MongoDB 查询 | `draft`/`archived` 不检索 |
| `roles` | 角色过滤 | 低 | MongoDB 查询 | 按角色筛选内容 |
| 正文 `content` | 正文向量 + BM25 | 高 | VectorStoreIndex + BM25 | 全文检索 |

#!/bin/bash
# batch_create.sh — 从 CSV 批量创建知识文件

source: internal
type: ${type}

---

# ${title}

> 一句话概述

## Summary

- 

## Key information


## Action recommendations


EOF

  echo "Created: ${TARGET_DIR}/${filename}.md"
done < "$1"

### 批量更新 frontmatter

```python
#!/usr/bin/env python3
"""batch_update_frontmatter.py — 批量更新 frontmatter 字段"""

import os
import sys
import yaml
from pathlib import Path

def update_frontmatter(filepath: str, updates: dict) -> bool:
    """更新单个文件的 frontmatter，返回是否修改"""
    with open(filepath, 'r') as f:
        content = f.read()
    
    if not content.startswith("---"):
        return False
    
    parts = content.split("---", 2)
    if len(parts) < 3:
        return False
    
    try:
        fm = yaml.safe_load(parts[1])
    except yaml.YAMLError:
        return False
    
    modified = False
    for key, value in updates.items():
        if key not in fm or fm[key] != value:
            fm[key] = value
            modified = True
    
    if not modified:
        return False
    
    new_fm = yaml.dump(fm, allow_unicode=True, default_flow_style=False, sort_keys=False).strip()
    new_content = f"---\n{new_fm}\n---{parts[2]}"
    
    with open(filepath, 'w') as f:
        f.write(new_content)
    
    return True

if __name__ == "__main__":
    # 示例：批量更新 status 从 draft 到 review
    base_dir = sys.argv[1] if len(sys.argv) > 1 else "YiKnowledge"
    updates = {"status": "review", "updated": "2026-09-07"}
    
    count = 0
    for md_file in Path(base_dir).rglob("*.md"):
        if update_frontmatter(str(md_file), updates):
            print(f"Updated: {md_file}")
            count += 1
    
    print(f"Total updated: {count} files")
```

## 十、反模式

| 反模式 | 错误示例 | 正确做法 | 原因 |
|--------|----------|----------|------|
| tags 过于宽泛 | `tags: [tech, code]` | `tags: [fastapi, middleware, auth]` | 无区分度，BM25 匹配精度低 |
| Summary 过于简短 | `"这是一个 API 文档"` | `"FastAPI 中间件认证实现，支持 JWT + bcrypt，包含 token 刷新和权限校验"` | 向量检索相关性低 |
| 正文无标题层级 | 大段文字无 H2/H3 | 使用 H2/H3 组织内容 | 分块索引质量差 |
| benefit 为空 | 不填写 benefit | `"为微服务技术选型提供决策参考"` | RAG 无法判断内容价值 |
| 文件名使用中文 | `RAG混合检索.md` | `rag-hybrid-search.md` | grep/ripgrep 搜索不友好 |
| 文件名使用下划线 | `implement_an_api.md` | `implement-an-api.md` | kebab-case 是 URL 友好格式 |
| 状态不更新 | 内容已过时，status 仍为 `stable` | 更新为 `deprecated` 并设置 `last_verified` | RAG 检索到过时内容 |
| 超过 3 级目录 | `engineer/build/api/fastapi/auth.md` | `engineer/build/fastapi-auth.md` | 路径过长稀释语义信号 |
| 创建空文件 | 只有 frontmatter 无正文 | 至少填写 4 个必填章节 | 浪费索引资源 |
| 日期加引号 | `created: "2026-09-07"` | `created: 2026-09-07` | YAML 解析为字符串 |
| category 缺少层级 | `category: engineer` | `category: engineer/build` | Scope 过滤粒度太粗 |
| 不写 last_verified | status=stable 但不写验证日期 | 填写 `last_verified: 2026-09-07` | 新鲜度检测失效 |

## 十一、约束

### 必须遵守

- 文件命名使用 kebab-case（小写字母 + 连字符），禁止下划线和数字
- 目录层级最多 3 层 — `role/problem-domain/file.md`
- Frontmatter 必填字段完整：`title, tags, category, created, updated, source, type, status`
- 正文至少包含 Summary、Core viewpoints、Key information、Action recommendations 四个章节
- Tags 使用 3-5 个英文小写标签
- 日期使用无引号 `YYYY-MM-DD` 格式
- 文件编码为 UTF-8，换行符为 LF
- 修改内容后更新 `updated` 字段
- status=stable 时必须填写 `last_verified`
- 新增内容前运行验证脚本

### 禁止

- 不使用中文文件名
- 不使用下划线或数字前缀
- 不跳过 frontmatter 必填字段
- 不创建超过 3 层的目录
- 不创建空文件（只有 frontmatter 无正文）
- 不创建超过 10MB 的文件
- 不将文件放在错误的角色目录中
- 不让 status 为 `draft` 或 `archived` 的文件进入 RAG 检索
