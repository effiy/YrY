# YiKnowledge 项目规范

> YiKnowledge（Markdown 知识库）的完整规范体系导航。8 个角色目录、4 个流水线阶段、RAG 数据源。服务于人类文档阅读和 AI（YiAi RAG 引擎）语义检索。

## 一、YiKnowledge 定位

```
YiKnowledge/
  ├── 8 个角色目录（按问题域组织知识）
  │   ├── architect/     — 架构决策与设计
  │   ├── engineer/      — 工程实践与模式
  │   ├── aier/          — AI/RAG 数据工程
  │   ├── qa/            — 质量保证策略
  │   ├── pm/            — 产品管理
  │   ├── designer/      — 设计系统与 UX
  │   └── ...
  │
  ├── 4 个流水线阶段（创建→评审→发布→归档）
  │   ├── inbox/         — 新知识，待评审
  │   ├── triage/        — 质量检查中
  │   ├── active/        — 已发布，可检索
  │   └── archive/       — 内容过时，保留备份
  │
  ├── curator/           — 知识治理工具
  │   └── governance/    — 就绪检查清单、生命周期规则
  │
  └── projects/          — 项目知识中心
      ├── yivad/         — YiVad 项目架构、模式、规范
      ├── yiai/          — YiAi 项目架构、模式、规范
      ├── yipet/         — YiPet 项目架构、模式、规范
      └── INDEX.md       — 项目知识中心索引
```

## 六、关键约束

### MUST（必须）
- 所有文件包含 8 个必需 frontmatter 字段
- 文件名使用 kebab-case，禁止下划线和数字
- 目录层级不超过 3 级：`role/problem-domain/file.md`
- 每条知识属于唯一角色目录
- 内容结构遵循三段式：Summary → Core viewpoints → Key information
- 新文件通过就绪检查清单后再发布

### MUST NOT（禁止）
- 不在文件名中使用下划线或数字
- 不超过 3 级目录层级
- 不创建 `misc/`、`other/` 等模糊分类目录
- 不将同一文件放在多个角色目录中
- 不在 frontmatter 中使用中文 key
- 不在知识文件中包含代码实现（仅文档和模式描述）
