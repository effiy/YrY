# OpenSpec 工作流标准

> Claude Code 在 OpenSpec 项目中的行为规范。

---

## 一、Subagent 协作

| 阶段 | 模式 | 拆分策略 |
|------|------|----------|
| Proposal | 并行搜索 | 同时启动多个 Explore 子代理搜索知识库内容 |
| Design | 主代理独做 | 决策性强，不拆子代理 |
| Apply | 混合 | 无依赖的 task 并行实现，有依赖的串行 |
| Verify | 并行检查 | 同时启动子代理检查 frontmatter/命名规范 |
| Land | 主代理独做 | 回写+commit 步骤短 |

## 二、代码质量（强制执行）

**动手前先思考**：列出假设，逐条验证。

**只写被要求的东西**：不要加没被要求的内容。

**精准改动**：只改必要的，匹配现有风格。

**YiKnowledge 特殊约束**：
- 所有文件必须有 frontmatter
- 文件名 kebab-case，无下划线/数字
- 最多 3 级目录层级

## 三、上下文管理

**OpenSpec 阶段隔离**：所有阶段均由用户手动触发，不自动进入下一阶段。

## 四、大规模任务处理

**200 行以上修改或显著架构变更必须走 OpenSpec**。

## 五、工具限制与编辑安全

**搜索要全**：用 Grep 搜内容，用 Glob 搜文件名。

**禁止脚本改文件**：修改源文件只能使用内置编辑工具。

**不主动推送**：除非用户明确要求。

**中文回复**：用中文回复用户。
