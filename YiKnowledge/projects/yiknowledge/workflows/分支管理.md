# 发布与分支管理规范

> 本文档定义项目的分支策略、环境映射、发布流程。

---

## 一、分支与环境映射

| 分支 | 环境 | 用途 |
|------|------|------|
| `dev` | dev | 开发联调环境 |
| `test` | sit | 系统集成测试环境 |
| `release` | uat | 主迭代 UAT 验证通道 |
| `release-hotfix` | uat | 单独发布 UAT 验证通道 |
| `master` | prod | 生产代码快照（保持分支，不参与构建） |

## 二、分支核心规则

- 功能分支独立合入各环境分支，环境分支之间不存在合并关系
- master 不参与 CI/CD 构建
- 每次 prod 部署后，从对应发布分支合入 master 并打 tag
- 生产发布后，将 master 回汇到 `release` / `test` / `dev`

## 三、正常迭代发布流程

```
feat-A,B,C → dev → test → release → uat验证 → 构建生产镜像 → 部署 prod
                                              ↓
                                     release → master（打 tag）
                                              ↓
                                     master → 回汇 release / test / dev
```

## 四、单独发布（Hotfix）流程

从 `master` 切出 `release-hotfix` → 合入功能分支 → 部署 UAT → 上生产 → 合入 master 打 tag → 回汇

## 五、分支命名规范

| 类型 | 格式 |
|------|------|
| 功能分支 | `issues/[feat\|fix]-[编号]-[描述]-[姓名缩写]` |
| 发布分支 | `release` / `release-hotfix` |
| 生产快照 | `master` |
