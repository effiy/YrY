# YiKnowledge 文件约定 — kebab-case 命名、3 级目录限制、Frontmatter Schema

> YiKnowledge 知识库的所有文件必须遵循严格的命名、目录和 frontmatter 规范。这些规范是 RAG 引擎正确解析和检索知识的基础。

## 文件命名规范

### 核心规则

| 规则 | 说明 | 正确示例 | 错误示例 |
|---|---|---|---|
| kebab-case | 全小写英文，连字符 `-` 分隔 | `knowledge-lifecycle.md` | `KnowledgeLifecycle.md` |
| 无下划线 | 禁止 `_` | `rag-indexing.md` | `rag_indexing.md` |
| 无数字 | 禁止数字 | `readiness-checklist.md` | `checklist-v2.md` |
| 无空格 | 禁止空格 | `file-conventions.md` | `file conventions.md` |
| 中文语义 | 保留在 frontmatter title 中 | `title: 文件约定` | 文件名用中文 |

### 命名模式

```
# 模式：<主题>-<描述>.md
knowledge-lifecycle.md          # 知识生命周期
rag-indexing.md                 # RAG 索引
readiness-checklist.md          # 就绪检查清单
branch-management.md            # 分支管理
monthly-report-workflow.md      # 月报工作流

# 模式：<主题>.md（单一名词）
governance.md                   # 治理
architecture.md                 # 架构
```

### 禁止模式

```
# 禁止：下划线
bad_example.md                  # 错误

# 禁止：数字
file-v2.md                      # 错误
file-2024.md                    # 错误

# 禁止：大写
File-Name.md                    # 错误

# 禁止：空格
File Name.md                    # 错误

# 禁止：中文文件名
文件约定.md                     # 错误
```

## 目录层级约束

### 3 级目录限制

```
# 正确：3 级或更少
YiKnowledge/engineer/architecture/overview.md          # 3 级
YiKnowledge/engineer/learn/projects/yivad.md           # 4 级？不，engineer/learn/projects 是第 3 级
YiKnowledge/engineer/API.md                             # 2 级

# 正确：模式
<role>/<problem-domain>/<file>.md                      # 3 级
<role>/<file>.md                                        # 2 级

# 错误：超过 3 级
YiKnowledge/engineer/learn/projects/yivad/architecture/overview.md  # 5 级，禁止
```

### 目录结构

```
YiKnowledge/
├── MEMORY.md              # 根目录文件，category: root
├── README.md              # 根目录文件，category: root
├── INDEX.md               # 根目录文件，category: root
├── engineer/              # 1 级：角色目录
│   ├── architecture/      # 2 级：问题域
│   │   └── overview.md    # 3 级：文件
│   └── learn/             # 2 级：问题域
│       └── projects/      # 3 级：文件（这是最终文件）
├── curator/               # 1 级：角色目录
│   └── governance/        # 2 级：问题域
│       └── readiness-checklist.md  # 3 级：文件
└── projects/              # 1 级：角色目录
    └── yivad/             # 2 级：项目
        └── specs/         # 3 级：文件
```

## Frontmatter Schema

### 必填字段

| 字段 | 类型 | 说明 | 示例 | 枚举值 |
|---|---|---|---|---|
| `title` | string | 文件标题，中文描述 | `"文件约定"` | — |
| `tags` | array | 标签，3-5 个 | `[yiknowledge, conventions]` | — |
| `category` | string | 分类路径，匹配文件位置 | `projects/yiknowledge/specs` | `root` 或 `<role>/<subdir>` |
| `created` | string | 创建日期 | `2026-09-02` | 格式 `YYYY-MM-DD` |
| `updated` | string | 更新日期 | `2026-09-02` | 格式 `YYYY-MM-DD` |
| `source` | string | 内容来源 | `internal` | `internal` / `url` |
| `type` | string | 内容类型 | `summary` | `summary` / `original` / `template` / `prompt` |
| `status` | string | 内容状态 | `stable` | `draft` / `stable` / `deprecated` |

### 推荐字段

| 字段 | 类型 | 说明 | 示例 | 枚举值 |
|---|---|---|---|---|
| `lifecycle` | string | 生命周期阶段 | `active` | `inbox` / `triage` / `active` / `reference` / `archive` |
| `review_cycle` | string | 评审周期 | `quarterly` | `weekly` / `monthly` / `quarterly` / `yearly` |
| `last_verified` | date | 最后验证日期 | `2026-09-02` | 格式 `YYYY-MM-DD` |
| `roles` | array | 目标角色 | `[curator, engineer]` | `engineer` / `leader` / `producter` / `curator` / `aier` / `srer` / `executiver` |
| `benefit` | string | 读者收益 | `"掌握文件命名规范"` | — |
| `acceptance_criteria` | array | 验收标准 | `["列出所有命名规则"]` | — |
| `related` | array | 相关文件路径 | `[./other-file.md]` | 相对路径 |

### 字段详细说明

#### `category` 字段

`category` 必须与文件的实际目录路径匹配：

```
文件路径：YiKnowledge/engineer/architecture/overview.md
category:  engineer/architecture          # 正确

文件路径：YiKnowledge/MEMORY.md
category:  root                            # 正确（根目录文件）

文件路径：YiKnowledge/curator/governance/readiness-checklist.md
category:  curator/governance              # 正确
```

#### `type` 字段

| 值 | 说明 | 使用场景 |
|---|---|---|
| `summary` | 摘要/总结 | 架构文档、规范、模式说明 |
| `original` | 原创内容 | 分析报告、经验教训 |
| `template` | 模板 | 可复用的模板文件 |
| `prompt` | 提示词 | AI 提示词 |

#### `status` 字段

| 值 | 说明 | 适用阶段 |
|---|---|---|
| `draft` | 草稿 | 内容编写中，尚未发布 |
| `stable` | 稳定 | 已发布，内容成熟 |
| `deprecated` | 废弃 | 内容已过时，不再使用 |

#### `lifecycle` 字段

| 值 | 说明 | 阶段流转 |
|---|---|---|
| `inbox` | 收件箱 | 新创建，待分类 |
| `triage` | 评审中 | 待通过就绪检查 |
| `active` | 活跃 | 已发布，正在维护 |
| `reference` | 参考 | 稳定内容，偶尔查阅 |
| `archive` | 归档 | 已过时，保留备份 |

## 常见错误

### 错误 1：category 与路径不匹配

```yaml
# 错误：文件在 curator/governance/ 但 category 写的是 curator
category: curator

# 正确：category 应与实际路径匹配
category: curator/governance
```

### 错误 2：标签过少或过多

```yaml
# 错误：只有 1 个标签
tags: [yiknowledge]

# 错误：超过 8 个标签
tags: [a, b, c, d, e, f, g, h, i]

# 正确：3-5 个标签
tags: [yiknowledge, conventions, frontmatter]
```

### 错误 3：文件名使用下划线或数字

```yaml
# 错误文件名
knowledge_lifecycle.md
knowledge-v2.md

# 正确文件名
knowledge-lifecycle.md
```

### 错误 4：缺少必填字段

```yaml
# 错误：缺少 source、type、status
---
title: 测试文件
tags: [test]
category: root
created: 2026-09-02
updated: 2026-09-02
---

# 正确：所有 8 个必填字段齐全
---
title: 测试文件
tags: [test, knowledge]
category: root
created: 2026-09-02
updated: 2026-09-02
source: internal
type: summary
status: draft
---
```

## 自动化检查

YiAi 知识监听器会自动检查以下内容：

- 文件名是否符合 kebab-case 规范
- 目录深度是否超过 3 级
- frontmatter 必填字段是否齐全
- `category` 字段是否与文件路径匹配
- 日期格式是否正确

检查不通过的文件会被标记但不会被阻止提交。

## Frontmatter 验证规则

### YAML 类型检查

每个 frontmatter 字段有严格的类型要求，YAML 解析器会验证类型是否正确：

```yaml
# 正确：string 类型用引号包裹（含特殊字符时）
title: "文件约定 — kebab-case 命名规范"
benefit: "掌握文件命名规范"

# 正确：array 类型用方括号
tags: [yiknowledge, conventions, frontmatter]
roles: [curator, 工程师]

# 正确：date 类型用 YYYY-MM-DD 格式（不加引号也是合法的 YAML 字符串）
created: 2026-09-02
updated: 2026-09-02

# 正确：纯字符串字段（无特殊字符时可省略引号）
source: internal
status: stable
type: summary
```

```yaml
# 错误：array 类型用了字符串
tags: yiknowledge              # 应该是 [yiknowledge]
roles: curator                 # 应该是 [curator]

# 错误：字符串类型误用为数组
title: [文件约定]               # 应该是 "文件约定"

# 错误：date 格式不对
created: 2026/09/02            # 应该是 2026-09-02
created: 2026-9-2              # 应该是 2026-09-02（补齐前导零）

# 错误：布尔值误用（frontmatter 中不使用布尔类型）
is_published: true             # 用 status: stable 代替
is_archived: false             # 用 lifecycle: archive 代替
```

### 验证脚本示例

```python
# validate_frontmatter.py — 验证 frontmatter 完整性和正确性
import yaml
import re
from pathlib import Path
from datetime import datetime

REQUIRED_FIELDS = ['title', 'tags', 'category', 'created', 'updated', 'source', 'type', 'status']
VALID_SOURCES = {'internal', 'url'}
VALID_TYPES = {'summary', 'original', 'template', 'prompt'}
VALID_STATUSES = {'draft', 'stable', 'deprecated'}
VALID_LIFECYCLES = {'inbox', 'triage', 'active', 'reference', 'archive'}
VALID_REVIEW_CYCLES = {'weekly', 'monthly', 'quarterly', 'yearly'}
VALID_ROLES = {'engineer', 'leader', 'producter', 'aier', 'srer', 'executiver', 'curator'}

def validate_frontmatter(filepath: str) -> list[str]:
    """验证单个文件的 frontmatter，返回错误列表"""
    errors = []
    content = Path(filepath).read_text(encoding='utf-8')

    # 提取 frontmatter
    match = re.match(r'^---\n(.*?)\n---', content, re.DOTALL)
    if not match:
        return ['缺少 frontmatter 分隔符']

    try:
        fm = yaml.safe_load(match.group(1))
    except yaml.YAMLError as e:
        return [f'YAML 解析错误: {e}']

    if fm is None:
        return ['frontmatter 为空']

    # 检查必填字段
    for field in REQUIRED_FIELDS:
        if field not in fm or fm[field] is None:
            errors.append(f'缺少必填字段: {field}')

    # 类型检查
    if 'tags' in fm and not isinstance(fm['tags'], list):
        errors.append(f'tags 应该是数组类型，当前是 {type(fm["tags"]).__name__}')
    if 'roles' in fm and fm['roles'] is not None and not isinstance(fm['roles'], list):
        errors.append(f'roles 应该是数组类型，当前是 {type(fm["roles"]).__name__}')
    if 'acceptance_criteria' in fm and fm['acceptance_criteria'] is not None and not isinstance(fm['acceptance_criteria'], list):
        errors.append(f'acceptance_criteria 应该是数组类型')
    if 'related' in fm and fm['related'] is not None and not isinstance(fm['related'], list):
        errors.append(f'related 应该是数组类型')

    # 枚举值检查
    if fm.get('source') and fm['source'] not in VALID_SOURCES:
        errors.append(f'source 值无效: {fm["source"]}，有效值: {VALID_SOURCES}')
    if fm.get('type') and fm['type'] not in VALID_TYPES:
        errors.append(f'type 值无效: {fm["type"]}，有效值: {VALID_TYPES}')
    if fm.get('status') and fm['status'] not in VALID_STATUSES:
        errors.append(f'status 值无效: {fm["status"]}，有效值: {VALID_STATUSES}')
    if fm.get('lifecycle') and fm['lifecycle'] not in VALID_LIFECYCLES:
        errors.append(f'lifecycle 值无效: {fm["lifecycle"]}，有效值: {VALID_LIFECYCLES}')
    if fm.get('review_cycle') and fm['review_cycle'] not in VALID_REVIEW_CYCLES:
        errors.append(f'review_cycle 值无效: {fm["review_cycle"]}，有效值: {VALID_REVIEW_CYCLES}')

    # 日期格式检查
    for date_field in ['created', 'updated']:
        if date_field in fm and fm[date_field]:
            try:
                datetime.strptime(str(fm[date_field]), '%Y-%m-%d')
            except ValueError:
                errors.append(f'{date_field} 日期格式错误: {fm[date_field]}，应为 YYYY-MM-DD')

    # updated >= created 检查
    if 'created' in fm and 'updated' in fm and fm['created'] and fm['updated']:
        try:
            c = datetime.strptime(str(fm['created']), '%Y-%m-%d')
            u = datetime.strptime(str(fm['updated']), '%Y-%m-%d')
            if u < c:
                errors.append(f'updated ({fm["updated"]}) 早于 created ({fm["created"]})')
        except ValueError:
            pass  # 日期格式错误已在上面报告

    # tags 数量检查
    if 'tags' in fm and isinstance(fm['tags'], list):
        if len(fm['tags']) < 3:
            errors.append(f'tags 数量不足: {len(fm["tags"])}，建议 3-5 个')
        if len(fm['tags']) > 5:
            errors.append(f'tags 数量过多: {len(fm["tags"])}，建议 3-5 个')

    # category 与路径匹配检查
    if 'category' in fm and fm['category']:
        path_parts = Path(filepath).parent.parts
        # 根目录文件 category 应为 root
        if len(path_parts) <= 1 and fm['category'] != 'root':
            errors.append(f'根目录文件 category 应为 root，当前为 {fm["category"]}')
        # 非根目录文件，category 应匹配路径
        if len(path_parts) > 1 and fm['category'] != 'root':
            expected = '/'.join(path_parts[-2:]) if len(path_parts) >= 2 else path_parts[-1]
            # 简化检查：category 应该包含路径的关键部分
            actual_parts = fm['category'].split('/')
            if actual_parts[-2:] != list(path_parts[-2:]):
                # 不强制报错，因为 category 格式可能不同
                pass

    return errors

# 批量验证
def validate_all(base_dir: str) -> dict:
    """验证目录下所有 .md 文件"""
    results = {}
    for md_file in Path(base_dir).rglob('*.md'):
        errors = validate_frontmatter(str(md_file))
        if errors:
            results[str(md_file)] = errors
    return results
```

## 字符集和编码规则

### 编码要求

| 规则 | 说明 |
|---|---|
| 编码格式 | UTF-8（无 BOM） |
| 字符集 | Unicode，支持中文/英文/特殊符号 |
| 禁止编码 | GBK、GB2312、Latin-1 等非 UTF-8 编码 |
| BOM 标记 | 禁止使用 UTF-8 BOM（`\xEF\xBB\xBF`） |

### 验证方法

```bash
# 检查文件编码是否为 UTF-8
file -I knowledge-file.md
# 输出应为: knowledge-file.md: text/plain; charset=utf-8

# 检查是否有 BOM（BOM 会导致 YAML 解析失败）
hexdump -C knowledge-file.md | head -1
# 如果前 3 字节是 EF BB BF，则包含 BOM，需要移除

# 移除 BOM
sed -i '1s/^\xEF\xBB\xBF//' knowledge-file.md
```

### 特殊字符处理

```yaml
# 正确：使用 Unicode 转义或直接使用中文
title: "文件约定 — kebab-case 命名规范"

# 正确：在 YAML 中使用引号包裹含特殊字符的字符串
benefit: "掌握 kebab-case 命名、3 级目录限制和 frontmatter schema"

# 正确：路径中的特殊字符不需要转义
related:
  - ./file-with-special-chars.md
```

## 行尾约定

### 统一换行符

| 规则 | 说明 |
|---|---|
| 换行符 | LF（`\n`，Unix 风格） |
| 禁止 | CRLF（`\r\n`，Windows 风格） |
| 文件末尾 | 必须以一个空行结束（即以 `\n` 结尾） |

### 检查与修复

```bash
# 检查文件是否包含 CRLF
grep -r $'\r' YiKnowledge/ --include="*.md" -l

# 批量转换 CRLF 为 LF
find YiKnowledge/ -name "*.md" -exec dos2unix {} \;

# 或使用 sed 转换
find YiKnowledge/ -name "*.md" -exec sed -i 's/\r$//' {} \;

# 确保文件末尾有空行
for f in $(find YiKnowledge/ -name "*.md"); do
  sed -i -e '$a\' "$f"
done
```

## 文件大小限制

### 限制规则

| 指标 | 限制 | 说明 |
|---|---|---|
| 单文件最大行数 | 500 行 | 超过应拆分为多个文件 |

## 自动修复脚本

### fix-frontmatter.sh — 一键修复常见问题

```bash
#!/bin/bash
# fix-frontmatter.sh — 自动修复 YiKnowledge 文件的常见问题
# 用法: bash fix-frontmatter.sh [文件路径]

set -e

FIX_FILE="${1:-}"

if [ -z "$FIX_FILE" ]; then
    echo "用法: bash fix-frontmatter.sh <file.md>"
    exit 1
fi

echo "正在修复: $FIX_FILE"

# 1. 移除 BOM
if [ "$(hexdump -C "$FIX_FILE" | head -1 | grep 'ef bb bf')" ]; then
    echo "  [修复] 移除 UTF-8 BOM"
    sed -i '1s/^\xEF\xBB\xBF//' "$FIX_FILE"
fi

# 2. 转换 CRLF 为 LF
if grep -q $'\r' "$FIX_FILE"; then
    echo "  [修复] 转换 CRLF 为 LF"
    sed -i 's/\r$//' "$FIX_FILE"
fi

# 3. 确保文件末尾有空行
if [ -n "$(tail -c 1 "$FIX_FILE")" ]; then
    echo "  [修复] 添加文件末尾空行"
    echo "" >> "$FIX_FILE"
fi

# 4. 检查 frontmatter 是否存在
if ! head -1 "$FIX_FILE" | grep -q '^---$'; then
    echo "  [警告] 缺少 frontmatter 开始分隔符 (---)"
fi

echo "修复完成: $FIX_FILE"
```

### add-missing-frontmatter.py — 补全缺失字段

```python
#!/usr/bin/env python3
"""
add-missing-frontmatter.py — 为缺少 frontmatter 字段的文件添加默认值
用法: python3 add-missing-frontmatter.py <file.md>
"""
import sys
import re
import yaml
from datetime import datetime
from pathlib import Path

DEFAULT_FRONTMATTER = {
    'source': 'internal',
    'type': 'summary',
    'status': 'draft',
    'lifecycle': 'inbox',
    'review_cycle': 'quarterly',
    'last_verified': datetime.now().strftime('%Y-%m-%d'),
}

def add_missing_fields(filepath: str):
    content = Path(filepath).read_text(encoding='utf-8')
    match = re.match(r'^---\n(.*?)\n---', content, re.DOTALL)
    if not match:
        print(f"错误: {filepath} 没有 frontmatter")
        return

    fm_text = match.group(1)
    try:
        fm = yaml.safe_load(fm_text)
    except yaml.YAMLError as e:
        print(f"错误: YAML 解析失败: {e}")
        return

    if fm is None:
        fm = {}

    # 补全缺失字段
    added = []
    for key, value in DEFAULT_FRONTMATTER.items():
        if key not in fm or fm[key] is None:
            fm[key] = value
            added.append(key)

    if not added:
        print(f"无需修复: {filepath}")
        return

    # 重新生成 frontmatter
    new_fm = yaml.dump(fm, allow_unicode=True, default_flow_style=False, sort_keys=False)
    new_content = content.replace(match.group(1), '\n' + new_fm.rstrip(), 1)
    Path(filepath).write_text(new_content, encoding='utf-8')

    print(f"已修复 {filepath}: 添加了 {', '.join(added)}")

if __name__ == '__main__':
    if len(sys.argv) < 2:
        print("用法: python3 add-missing-frontmatter.py <file.md>")
        sys.exit(1)
    add_missing_fields(sys.argv[1])
```

## 关键约定

1. **kebab-case 强制** — 文件名必须全小写英文连字符，无下划线，无数字
2. **3 级目录强制** — 目录深度不超过 3 级
3. **8 个必填字段** — `title`, `tags`, `category`, `created`, `updated`, `source`, `type`, `status`
4. **category 匹配路径** — 必须与实际文件所在目录匹配
5. **tags 3-5 个** — 标签数量适中，便于检索
6. **日期格式** — `YYYY-MM-DD`
7. **中文内容** — 标题和正文使用中文
8. **UTF-8 编码** — 无 BOM，LF 换行符
9. **文件大小** — 单文件不超过 500 行 / 100KB
10. **相对路径引用** — 所有交叉引用使用相对路径，禁止绝对路径和外部 URL
11. **YAML 类型正确** — 数组用 `[]`，字符串用引号（含特殊字符时），日期用 `YYYY-MM-DD`
12. **枚举值合法** — source、type、status、lifecycle、review_cycle 必须使用预定义枚举值
