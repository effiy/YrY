# 模板填充模式

适用于需求明确的场景。逐步引导用户，规范化输入，评分并导出。

逐节推进、进度跟踪、命令和原则详见 SKILL.md 中的共享命令和进度跟踪章节。

## 1. 模板选择

展示两个可用模板：

| 模板 | 文件 | 适用场景 |
|----------|------|----------|
| 标准 BRD | `assets/standard-brd-template.md` | 通用企业 BRD — 11 个章节，包含干系人角色、现状/目标、功能需求/非功能需求、集成 |
| 汽车售后 BRD | `assets/automotive-brd-template.md` | 汽车售后 — 7 个双语章节，包含文档信息、业务背景、场景、国家/领域/系统、业务规则、时间线、验收标准和审批记录 |

选择后，总结模板结构，让用户了解需要填充的内容。

## 2. 逐节工作

展示所有标记为**必填**或**可选**的章节。让用户按任意顺序选择章节。对于每个章节：

1. **解释** — 用通俗的语言说明该章节需要什么。对于标准 BRD，参考 `requirement_description` 和 `min_score`。对于汽车模板，解释每个子节占位符提示的含义。

2. **收集** — 接受自由格式的输入。

3. **规范化** — 重写为清晰、专业的 BRD 文案。不要添加用户未提供的内容——仅为了清晰和完整而重新措辞。

4. **评估** — 对于标准 BRD，按 `min_score` 评分：
   - `>= min_score` → `达标`
   - `>= min_score × 0.7` → `需修订`
   - `< min_score × 0.7` → `未达标`
   - 如果 `min_score` 为 0，跳过评分。

   对于汽车模板，定性评分：`达标`（细节充分）、`需修订`（轻微缺口）、`未达标`（内容不完整）。

5. **给出反馈** — 展示规范化版本及评估结果。如果 `未达标`，说明缺失了什么并请求修订。如果 `需修订`，指出哪些接近达标、哪些需要补充。如果 `达标`，询问是否保存。

## 3. 导出

当用户说"导出 BRD"、"生成 BRD"等时，将所有已保存的章节按所选模板组装为完整的 Markdown 文档。保存为 `BRD_[名称]_[日期].md` 到当前工作目录。
