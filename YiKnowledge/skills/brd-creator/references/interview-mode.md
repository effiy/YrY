# 结构化访谈模式

适用于复杂或模糊的需求。通过结构化对话帮助用户发现他们真正需要什么。

**关键行为：**
- **先理解，后结论** — 将非正式描述翻译为专业术语，征求确认。
- **结构化访谈，而非问卷** — 通过渐进式提问暴露缺口。每轮最多 1-3 个问题。
- **区分知识与确认** — 区分用户确认的事实、知识库参考和合理推断。
- **校准而非评判** — 当发现常见陷阱时，用引导性问题帮助用户校准。

## 第 1 步：需求翻译

当用户首次描述他们的想法时，输出：

```
## 初步分析
### 你的想法
（重述原始描述）
### 初步业务表达
（专业翻译，包含业务对象、目标和场景——不添加规则）
> 以上为初步理解，尚未确认为正式需求。
```

## 第 2 步：需求类型分类

分类并展示选项：
- **小型**（局部变更 / 功能增强）→ "快速草图"：5-6 个主要问题
- **大型**（业务构建 / 系统建设）→ "完整分解"：全部 7 个主要问题

让用户通过 A/B/C/D/E 选项确认。

## 第 3 步：结构化访谈（Q1-Q7）

**每轮最多 1-3 个问题。** 根据需求类型选择要覆盖的问题。

| 编号 | 问题 | 目的 |
|----|----------|---------|
| Q1 | 业务背景与痛点 | 为什么现在要做？ |
| Q2 | 当前流程 | 现在怎么做？谁来做？在哪个系统里做？ |
| Q3 | 现有问题与影响 | 哪里有问题？影响有多大？ |
| Q4 | 目标状态 | 成功的标准是什么？ |
| Q5 | 用户与角色 | 谁使用？谁参与？谁受影响？ |
| Q6 | 范围与影响 | 市场、模块、系统、权限；海外差异；跨部门协调 |
| Q7 | 成功与验收 | 如何判断已完成？ |

**追问规则：** 衍生问题编号为 Q1-1、Q1-2。每个主要问题最多连续追问 2 轮；如果仍未确认，标记为 **[待确认]** 并返回主线。

**提问标准**（完整规范见 `rules/qa-rules.md`）：
- 每个问题必须包含"业务对象 + 动作 + 场景"
- 优先使用选择题；始终附加"其他，请说明"和"不确定 / 待确认"
- 不要问"流程是什么？"这种裸问题——始终包含上下文

## 第 4 步：校准检查

当发现以下信号时，使用引导性问题（而非评判）：

- **方案优先思维** — 用户描述功能而非问题。问："这个功能解决什么问题？当前的痛点是什么？"
- **目标模糊** — 只有"提高效率"而无量化标准。问："用什么指标来判断成功？"
- **缺少用户** — 定义了功能但未分配使用者。问："谁会用这个？在什么场景下？"
- **假设跨市场一致性** — 问："所有市场是否遵循相同的流程？"

如果用户明显很确定，不要强行挑战。

## 第 5 步：海外业务验证（条件触发）

仅在涉及海外/多市场场景时激活。确认：
- 适用市场和分阶段上线策略
- 各国业务流程 / DMS 功能差异
- 语言 / 时区 / 币种本地化需求
- 各国法律和合规要求

## 第 6 步：跨部门对齐检查

确认参与组织及其沟通/同步状态。将未对齐的干系人标记为阻塞项，并指定负责人。

## 第 7 步：流程与泳道确认

确认业务流程后，生成合适的图表：
- **单角色、线性步骤** → `flowchart TD` / `flowchart LR`
- **多角色、基于交接** → 子图泳道（`graph TD` 配合 `subgraph`）
- **系统间数据流** → `sequenceDiagram`

在最终确定前询问"这个图表是否正确表示了流程？"

## 第 8 步：总结与 BRD 输出

生成 BRD 之前，输出需求理解摘要供最终确认。仅在用户确认后才继续。

**KPI 统计口径验证（Q7 中）：** 当用户提到比率/百分比 KPI 时，验证：
- **分子与分母**：两者是否都明确定义？
- **时间单位**："24 小时"是自然日还是工作日？跨国节假日如何处理？
- **部分满足**：部分满足的订单如何归类？
- **逾期分类**：逾期项如何分类？

如果不明确，将 KPI 标记为 **[待确认]**，附注"统计口径偏差风险"。

**访谈退出条件：** 满足以下条件时退出：用户请求 BRD 输出、Q1-Q7 主访谈完成、或用户终止。
