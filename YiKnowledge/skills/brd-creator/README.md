# BRD — 业务需求文档助手

双模式 BRD 助手，帮助创建专业的业务需求文档。覆盖汽车售后领域（DMS、经销商管理、保修、备件、VOC、服务预约）和通用企业场景。

## 快速开始

### 模板填充模式

```
你：我需要写一个经销商服务预约系统的 BRD，需求已经很清楚了。
```

助手展示可用模板，你可以任意选择要处理的章节，按任意顺序进行。每个章节会被规范化并评分。完成后说"导出"即可。

### 结构化访谈模式

```
你：我们海外售后团队最近投诉很多，经销商没有及时跟进客户，满意度一直在下降。帮我看看该怎么处理。
```

助手将你的非正式描述翻译为专业业务术语，然后通过 Q1-Q7 结构化问题引导你——每轮 1-3 个问题。它会识别缺口、挑战假设，并在生成 BRD 之前检查跨部门对齐情况。

## 为什么采用双模式？

单一模式会强制把所有需求塞进同一个形状。清晰的需求适合快速、结构化的模板填充。复杂、模糊的需求需要渐进式的访谈澄清。

**为什么评分？** 评分提供即时、客观的反馈——"功能需求至少需要 10 项，你目前只有 6 项"——在文档到达评审者之前就发现缺口。

**为什么三级信息标记？** **[已确认]**、**[知识库参考]** 和 **[待确认]** 清晰区分了哪些是已确定的、哪些是补充性的、哪些是仍需明确的。这防止了沉默的假设变成 BRD 内容。

**为什么每轮 1-3 个问题？** 访谈模式是对话，不是问卷。限制每轮问题数量让用户保持方向感，防止信息过载。

## 业务领域覆盖

汽车售后全链路：经销商管理、DMS、服务预约、维修、VOC、备件、保修、索赔、技术支持、多市场本地化、总部→区域→国家→经销商多层级协同。不在范围内：整车销售、制造、物流（非售后备件）。
