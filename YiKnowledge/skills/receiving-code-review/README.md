## 接收代码审查反馈 AI 智能体

### 快速开始

```
你的同事：这里应该用 useMemo 优化一下

你：[接收反馈模式]
  验证——这个计算当前渲染 <1ms，加 memo 的实际收益是什么？
  
  [如果确实需要] → 加上并验证性能提升
  [如果不必要] → 解释当前场景下不需要的原因
```

### 为什么需要这个技能？

**为什么不能直接按意见改？**
代码审查反馈需要技术评估——不是所有意见都对。盲目同意和盲目拒绝一样危险。

**为什么不回复「你说得对」？**
表演性同意不增加任何价值。技术确认或直接行动才是正确的回应。

**为什么模糊的意见要一次性问清楚？**
意见之间可能有关联。部分理解 = 错误实现。

### 与其他技能的协作

- **code-review** → receiving-code-review：审查报告产出的 P0-P3 问题由本技能处理
- receiving-code-review → **verification**：修改完成后触发验证
- receiving-code-review 参考 **CLAUDE.md**：修改需遵守 RPC 契约和模块边界
