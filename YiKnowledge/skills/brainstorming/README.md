## 需求澄清与方案探讨 AI 智能体

### 快速开始

```
你：我想给 YiVad 加个搜索功能，但不确定怎么做

助手：[头脑风暴模式]
  先确认几点：搜索范围是全局还是模块内？
  搜索对象是菜单还是数据？需要实时搜索还是异步索引？

  [澄清边界后...]

  两个方案供参考：
  方案 A：前端静态搜索 — 数据量不大，直接过滤已加载数据
  方案 B：后端全文检索 — 通过 YiAi RAG 向量检索做语义搜索

  考虑到 YiVad 数据通过 ProTable 服务端分页加载，方案 A 只能搜当前页...
```

### 为什么先讨论再编码？

**为什么不能直接开始写代码？**
跳过需求澄清直接编码的返工率高达 40-60%。10 分钟的讨论能省下 2 小时返工。

**为什么要提供多个方案而不是推荐一个？**
每个方案有取舍——你比 AI 更了解业务优先级。提供选择让你做决策，而非替你决策。

**为什么产出设计摘要而非直接进入 PRD？**
头脑风暴确认的是方向（选哪条路），PRD 定义的是细节（这条路怎么修）。方向不对，PRD 写得再好也是浪费。

### 与其他技能的协作

- brainstorming → **prd-creator**：方向确认后撰写正式需求文档
- brainstorming → **task-planning**：方向确认后直接进入实现规划
- brainstorming 参考 **YiKnowledge/projects/**：方案设计时查阅现有架构和 PRD
