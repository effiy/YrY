# 三文件模式详细规范

## 设计原理

三文件模式源自 `planning-with-files`（OthmanAdi）的上下文工程实践。其核心洞察是：

> AI 的上下文窗口 = 人脑的短期记忆，文件系统 = 人脑的长期记忆。在长任务中，仅依赖上下文窗口就像只用短期记忆做复杂项目——必然会遗忘和偏离。

### 与普通对话的区别

| 维度 | 普通对话 | 三文件模式 |
|------|---------|-----------|
| 任务状态 | 存在上下文中，压缩后丢失 | 存在文件中，永久可恢复 |
| 调研成果 | 散落在多轮对话中 | 结构化的 findings.md |
| 失败记录 | 可能被后续消息覆盖 | 明确记录在 progress.md |
| 交接能力 | 需要人工重新解释 | 直接读取三文件即可 |
| 方向锚定 | 长任务中易偏离 | task_plan 持续纠正 |

## 文件模板

### task_plan.md

```markdown
# 任务计划：[任务名称]

**创建时间**：YYYY-MM-DD HH:MM
**最后更新**：YYYY-MM-DD HH:MM
**状态**：planning / executing / paused / completed
**目标**：[一句话描述最终交付物]

## 背景

[为什么需要这个任务？关联哪个 PRD 或 Issue？]

## 方案

[选定的技术方案简述，包括关键设计决策]

### 备选方案（已排除）

| 方案 | 排除原因 |
|------|---------|
| [方案 A] | [为什么不选] |

## 执行步骤

- [ ] 1. [步骤描述]
  - 涉及文件：`path/to/file`
  - 预估行数：~N 行
  - 依赖：无 / 步骤 X
- [ ] 2. [步骤描述]
  - ...

## 验收标准

- [ ] [具体的、可验证的标准]
- [ ] [包含验证方式，如「运行 pnpm test 全部通过」]

## 风险登记

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| [描述] | 高/中/低 | [影响描述] | [应对策略] |

## 变更记录

| 时间 | 变更内容 | 原因 |
|------|---------|------|
| [时间] | [变更了什么] | [为什么变更] |
```

### findings.md

```markdown
# 调研发现：[任务名称]

## 2026-09-23 14:30 — [发现标题]

**结论**：[一句话结论]
**类型**：技术验证 / 方案对比 / 约束发现 / 依赖确认

**背景**：[为什么要调研这个]

**证据**：
- [代码路径或测试结果]
- [文档引用]
- [实验数据]

**影响**：[对当前任务的具体影响]

**相关文件**：
- `path/to/file`

**来源**：[内部代码 / 外部文档 / 实验验证 / 用户告知]
```

### progress.md

```markdown
# 执行日志：[任务名称]

## 2026-09-23 14:35 — 步骤 1：[步骤描述]

**状态**：✅ 完成
**耗时**：约 15 分钟

**修改文件**：
- `src/components/ThemeToggle.vue:1-45` — 新建组件，实现三态切换
- `src/stores/theme.ts:12-18` — 添加 `toggleTheme` action

**验证**：
- `vue-tsc --noEmit` 通过
- 手动验证切换开关在浅色/深色/系统三种模式间切换正常

**问题**：无
```

## 反模式

### ❌ 反模式 1：事后再补记录

```
# 错误：完成任务后才一次性补写 progress
## 2026-09-23 16:00 — 全部步骤完成
修改了很多文件，过程比较顺利
```

**后果**：丢失了中间失败和修正的细节，下次遇到类似问题无法参考。

**正确做法**：每完成一步立即记录。

### ❌ 反模式 2：findings 记录推测

```markdown
# 错误
## 发现：Element Plus 可能不支持 CSS 变量

**结论**：应该不支持
```

**后果**：未验证的推测被当作事实，可能误导后续决策。

**正确做法**：只记录已验证的事实，标注验证方式。

### ❌ 反模式 3：task_plan 过于详细或过于粗略

```
# 错误 A：过于粗略
- [ ] 1. 实现暗色模式

# 错误 B：过于详细
- [ ] 1. 在 ThemeToggle.vue 第 3 行添加 import { useTheme } from '@/stores/theme'
```

**正确粒度**：每步是一到三个文件的修改，有明确的完成边界。

## 何时不需要三文件模式

- 单文件、单次对话的小修改（如修复一个拼写错误）
- 纯问答任务（无代码修改）
- 已有明确 spec 且预计 5 分钟内完成的任务

如果任务从简单变为复杂，随时可以升级为三文件模式。
