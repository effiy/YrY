### 为什么采用五维审查？

**为什么不是只检查安全问题？**
安全是必要条件但不是充分条件。代码还需要正确、高效、可维护且与架构一致。五个维度确保全面覆盖。

**为什么每个问题都附带修复方案？**
「这里有问题」不是审查——是抱怨。每个问题附带具体的、可操作的修复代码。

**为什么有 P0-P3 分级？**
不是所有问题都同等重要。分级让开发者知道哪些必须修复、哪些可以后续处理，避免审查阻塞进度。

### 与其他技能的协作

- **code-review** ← task-planning：步骤执行完成后触发审查
- **code-review** → debugging：审查中发现的问题需要深入调试
- **code-review** → issue-creator：非阻塞问题可创建 Issue 跟踪
