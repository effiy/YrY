## 产品需求文档 (PRD) AI 智能体

### 快速开始

直接与 Claude 对话。PRD 技能通过 3 个阶段引导你完成一份完整、可执行的 PRD：

```
你：我需要一份 PRD，为我们的项目管理工具添加任务优先级功能
```

该技能从你的消息中提取上下文，总结其理解，并展示 9 章节的 PRD 结构。如果已经描述了足够的内容，它会直接告诉你，而不是让你重复。你以任意顺序选择章节填充，说「导出」即可生成 `tasks/prd-[功能名称].md`。

### 为什么采用这种方式？

**为什么优先从上下文中提取？**
用户通常在触发消息中描述了功能。该技能会捕获这些信息，而不是让他们重复。尊重用户的注意力。

**为什么规范化但不编造？**
目标是让用户的意图对开发人员或 AI 智能体而言明确且可执行——而不是添加用户未要求的功能。当确实缺少某些内容时，该技能会标记出来而不是猜测。

**为什么要编号用户故事？**
US-001, US-002 等便于在对话、代码和提交中引用。每个故事是一个工作单元，附带可验证的验收标准。

**为什么让用户选择任意章节顺序？**
有些用户想从功能需求开始，有些想从用户故事开始。强制线性顺序会制造摩擦。

**为什么要有 BRD → PRD 衔接？**
当 BRD 存在时，它应该为 PRD 提供信息——引言/目标来自业务背景，用户故事来自业务场景，功能需求来自业务规则等。

### 示例场景

> **用户：** 「我们需要为管理后台添加暗色模式。用户已经要求了好几个月了。主要需求是在页面头部添加一个切换开关，可以在浅色、暗色和跟随系统之间切换。所有现有页面在两种模式下都应该正常工作。」

该技能从上下文中提取：「根据你描述的内容，我已经可以起草引言和目标。你想让我从这些开始吗？」经过 30 分钟的来回交流，用户说「导出」并得到 `tasks/prd-dark-mode.md`。

### 架构

```
prd-creator/
├── SKILL.md                    # 技能本身（9 章节结构 + 导出模板 + BRD→PRD 衔接）
├── README.md                   # 本文件
└── references/
    └── example-prd.md          # 完整示例 PRD（任务优先级系统）
```

9 章节的 PRD 结构在完整性和灵活性之间取得了平衡——必填章节确保一份最小可用的 PRD，可选章节在相关时增加深度。
