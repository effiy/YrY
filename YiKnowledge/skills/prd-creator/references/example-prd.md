# PRD: 任务优先级系统

## 1. 引言/概述

为任务添加优先级等级，让用户能够专注于最重要的事项。任务可标记为高、中、低三个优先级，通过视觉指示器和筛选功能帮助用户高效管理工作负载。

## 2. 目标

- 允许为任意任务分配优先级（高/中/低）
- 提供不同优先级之间清晰的视觉区分
- 支持按优先级筛选和排序
- 新任务默认设为中优先级

## 3. 用户故事

### US-001: 为数据库添加优先级字段
**描述：** 作为开发人员，我需要存储任务优先级，使其在会话之间持久化。

**验收标准：**
- [ ] 为 tasks 表添加 priority 列：'high' | 'medium' | 'low'（默认 'medium'）
- [ ] 成功生成并运行迁移
- [ ] 类型检查通过

### US-002: 在任务卡片上显示优先级指示器
**描述：** 作为用户，我希望一眼就能看到任务优先级，以便知道哪些需要优先关注。

**验收标准：**
- [ ] 每张任务卡片显示带颜色的优先级徽章（红=高，黄=中，灰=低）
- [ ] 无需悬停或点击即可看到优先级
- [ ] 类型检查通过
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-003: 在任务编辑中添加优先级选择器
**描述：** 作为用户，我希望在编辑任务时能更改其优先级。

**验收标准：**
- [ ] 任务编辑弹窗中包含优先级下拉菜单
- [ ] 显示当前优先级为已选中状态
- [ ] 选择变更后立即保存
- [ ] 类型检查通过
- [ ] 使用 dev-browser 技能在浏览器中验证

### US-004: 按优先级筛选任务
**描述：** 作为用户，我希望在专注工作时能筛选任务列表，只查看高优先级项目。

**验收标准：**
- [ ] 筛选下拉菜单，选项：全部 | 高 | 中 | 低
- [ ] 筛选条件持久化到 URL 参数中
- [ ] 无匹配任务时显示空状态提示
- [ ] 类型检查通过
- [ ] 使用 dev-browser 技能在浏览器中验证

## 4. 功能需求

- FR-1: 为 tasks 表添加 `priority` 字段（'high' | 'medium' | 'low'，默认 'medium'）
- FR-2: 在每张任务卡片上显示带颜色的优先级徽章
- FR-3: 在任务编辑弹窗中包含优先级选择器
- FR-4: 在任务列表头部添加优先级筛选下拉菜单
- FR-5: 在每个状态列内按优先级排序（高到中到低）

## 5. 非目标（范围之外）

- 不包含基于优先级的通知或提醒
- 不包含基于截止日期的自动优先级分配
- 不包含子任务的优先级继承

## 6. 设计考量

- 复用现有的徽章组件，使用颜色变体

## 7. 技术考量

- 筛选状态通过 URL 搜索参数管理
- 优先级存储在数据库中，而非计算得出

## 8. 成功指标

- 用户可以在 2 次点击内更改优先级
- 高优先级任务立即显示在列表顶部
- 任务列表性能无退化
