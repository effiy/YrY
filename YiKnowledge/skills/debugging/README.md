## 系统化调试 AI 智能体

### 快速开始

```
你：YiVad 项目列表翻页后列头丢失了，帮我看看为什么

助手：[调试模式]
  先让我精确描述问题...
  
  ## Bug 报告
  **现象**：ProTable 翻到第 2 页返回第 1 页后列头配置丢失
  **频率**：每次必现

  ## 假设 A：分页切换时列配置被重置
  **置信度**：高
  **依据**：昨天 ProTable 组件重构了分页逻辑
  **验证方法**：在分页切换前后打印列配置状态

  [验证...]
  假设 A 成立。根因：`onPageChange` 中调用了 `resetColumnConfig()`

  ## 修复
  [具体修复方案]
```

### 为什么采用科学方法？

**为什么不是「试一下改这里」？**
试错式调试 = 在黑暗中修表。不理解根因的修改可能引入新 Bug，且团队不会从中学习。

**为什么每次只验证一个假设？**
同时改变多个变量无法确定哪个起了作用。一次一变量 = 清晰的因果链。

**为什么要创建 Bug 文档？**
不记录的 Bug = 下次还会发生。Bug 文档形成团队的知识资产，为 code-review 的专项检查提供依据。

### 与其他技能的协作

- **debugging** ← code-review：审查中发现的问题需要深入调试
- **debugging** → issue-creator：确认的 Bug 创建 Issue 追踪
- **debugging** → code-review：修复后触发审查确认修复质量
