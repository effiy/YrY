# 数据库备份与恢复 — MongoDB 数据保护策略

> **适用场景**：搭建数据保护策略时。备份不是目的，能恢复才是。一份从未被验证能成功恢复的备份，不是备份，是心理安慰。

## 备份策略核心原则

| 原则 | 含义 | 没有遵守的后果 |
|---|---|---|
| **3-2-1 规则** | 3 份副本、2 种介质、1 份异地 | 单一故障点即可导致全部数据丢失 |
| **定期验证恢复** | 每季度实际执行一次恢复演练 | 备份文件损坏无人知晓 |
| **自动化** | 备份通过 cron/定时任务自动执行 | 手动备份 = 迟早会忘记 |
| **监控** | 备份失败时应有告警 | 备份静默失败数周才被发现 |

## YrY MongoDB 备份方案

### 备份哪些数据

YrY 的 MongoDB 包含以下需要保护的数据：

| 数据库/集合 | 数据重要性 | 备份频率 | 保留策略 |
|---|---|---|---|
| `yry.sessions` | 高 — 用户聊天记录 | 每日 | 30 天 |
| `yry.menus` | 中 — 菜单配置（可从代码重建） | 每日 | 14 天 |
| `yry.users` | 高 — 用户账号和权限 | 每日 | 30 天 |
| `yry.bugs` | 中 — 缺陷追踪记录 | 每日 | 30 天 |
| `yry.knowledge_files` | 低 — 可从 YiKnowledge 目录重建 | 每周 | 14 天 |
| `yry.static_files` | 中 — 上传的文件 | 每日 | 30 天 |

### 备份类型

| 类型 | 命令 | 优点 | 缺点 | 适用场景 |
|---|---|---|---|---|
| **mongodump 全量** | `mongodump --uri="..." --archive` | 逻辑备份，可选择性恢复 | 大数据库耗时长 | 日常备份（YrY 数据量小，适用） |
| **mongodump 增量** | 配合 oplog 实现 | 节省存储空间和备份时间 | 恢复时需要重放 oplog | 数据量大时使用 |
| **文件系统快照** | `mongod --dbpath` 所在磁盘快照 | 恢复速度快 | 需要文件系统支持 | 对恢复时间要求高的场景 |

**YrY 推荐**：当前数据量小，采用 `mongodump` 全量备份即可。

### 备份脚本

```bash
#!/bin/bash
# /opt/yiai/scripts/backup-mongo.sh
# crontab: 0 2 * * * /opt/yiai/scripts/backup-mongo.sh

BACKUP_DIR="/opt/backups/mongodb"
RETENTION_DAYS=30
MONGO_URI="mongodb://localhost:27017"
DATE=$(date +%Y%m%d-%H%M)
BACKUP_PATH="${BACKUP_DIR}/dump-${DATE}"

mkdir -p "$BACKUP_DIR"

# 执行备份
mongodump --uri="$MONGO_URI" --out="$BACKUP_PATH" 2>&1 | tee -a "${BACKUP_DIR}/backup.log"

# 检查备份是否成功
if [ ${PIPESTATUS[0]} -eq 0 ]; then
  # 压缩备份
  tar -czf "${BACKUP_PATH}.tar.gz" -C "$BACKUP_DIR" "dump-${DATE}"
  rm -rf "$BACKUP_PATH"

  echo "[$(date)] 备份成功: ${BACKUP_PATH}.tar.gz" >> "${BACKUP_DIR}/backup.log"
else
  echo "[$(date)] 备份失败" >> "${BACKUP_DIR}/backup.log"
  # 发送告警（如配置了 Webhook）
  curl -s -X POST "https://open.feishu.cn/open-apis/bot/v2/hook/YOUR_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"msg_type":"text","content":{"text":"P1 告警：MongoDB 备份失败"}}'
  exit 1
fi

# 清理过期备份
find "$BACKUP_DIR" -name "dump-*.tar.gz" -mtime +${RETENTION_DAYS} -delete

# 保留最近一次备份的路径供恢复参考
echo "$BACKUP_PATH.tar.gz" > "${BACKUP_DIR}/latest_backup.txt"
```

## 恢复流程

### 恢复前检查

恢复操作前必须确认：
- [ ] 备份文件完整且可读（`tar -tzf <备份文件>` 无错误）
- [ ] 目标 MongoDB 实例空间足够（备份文件大小的 2-3 倍）
- [ ] 已通知相关人员（恢复期间数据库可能有短暂不可用）

### 全量恢复

```bash
#!/bin/bash
# /opt/yiai/scripts/restore-mongo.sh
# 用法: ./restore-mongo.sh <备份文件路径>

BACKUP_FILE="$1"
RESTORE_DIR="/tmp/mongo-restore-$(date +%Y%m%d-%H%M)"
MONGO_URI="mongodb://localhost:27017"

if [ -z "$BACKUP_FILE" ]; then
  echo "用法: $0 <备份文件.tar.gz>"
  exit 1
fi

# 解压备份
mkdir -p "$RESTORE_DIR"
tar -xzf "$BACKUP_FILE" -C "$RESTORE_DIR"
DUMP_DIR=$(ls -d "$RESTORE_DIR"/dump-*)

# 执行恢复
echo "正在从 ${DUMP_DIR} 恢复到 ${MONGO_URI} ..."
mongorestore --uri="$MONGO_URI" --drop "$DUMP_DIR"

# 验证恢复
if [ $? -eq 0 ]; then
  echo "恢复成功"

  # 验证数据完整性
  mongosh --eval "
    use yry;
    print('sessions 集合文档数: ' + db.sessions.countDocuments());
    print('users 集合文档数: ' + db.users.countDocuments());
    print('menus 集合文档数: ' + db.menus.countDocuments());
  "
else
  echo "恢复失败"
  exit 1
fi

# 清理临时文件
rm -rf "$RESTORE_DIR"
```

### 选择性恢复（只恢复特定集合）

```bash
# 只恢复 sessions 集合
mongorestore --uri="$MONGO_URI" --db=yry --collection=sessions --drop \
  "$DUMP_DIR/yry/sessions.bson"
```

### 恢复到指定时间点（需要 oplog）

```bash
# 条件：备份包含 oplog
mongorestore --uri="$MONGO_URI" --oplogReplay \
  --oplogLimit="2026-09-15T14:00:00Z" "$DUMP_DIR"
```

## YrY 环境配置

### 开发环境

```yaml
备份策略:
  频率: 每日凌晨 2:00
  类型: mongodump 全量
  保留: 7 天
  存储路径: /opt/backups/mongodb/
  监控: 备份失败时打印日志（无告警）
```

### 生产环境（规划中）

```yaml
备份策略:
  频率: 每日凌晨 2:00（全量） + 每小时（oplog 增量）
  类型: mongodump 全量 + oplog 增量
  保留: 全量 30 天，增量 7 天
  异地: 每日同步到 OSS 或异地服务器
  监控: 备份失败时触发 P1 告警
  演练: 每季度从异地备份恢复一次
```

## 备份监控

### 监控检查项

| 检查项 | 方法 | 预期结果 | 异常时操作 |
|---|---|---|---|
| 备份是否按时执行 | 检查最新备份文件时间戳 | < 25 小时前 | 排查 cron 任务和脚本日志 |
| 备份文件大小是否异常 | 对比相邻备份文件大小 | 波动 < 50% | 检查数据是否有大规模删除 |
| 备份日志有无错误 | `grep "失败" backup.log` | 无输出 | 查看具体错误信息并修复 |
| 磁盘空间是否充足 | `df -h $BACKUP_DIR` | 使用率 < 80% | 清理过期备份或扩容 |

### 备份健康检查脚本

```bash
#!/bin/bash
# 检查备份状态

BACKUP_DIR="/opt/backups/mongodb"
LATEST_BACKUP=$(cat "${BACKUP_DIR}/latest_backup.txt" 2>/dev/null)

if [ -z "$LATEST_BACKUP" ] || [ ! -f "$LATEST_BACKUP" ]; then
  echo "错误：未找到最新备份"
  exit 1
fi

# 检查备份年龄
BACKUP_AGE_HOURS=$(( ($(date +%s) - $(stat -f %m "$LATEST_BACKUP")) / 3600 ))
if [ "$BACKUP_AGE_HOURS" -gt 25 ]; then
  echo "警告：最新备份已有 ${BACKUP_AGE_HOURS} 小时"
  exit 1
fi

# 检查备份大小
BACKUP_SIZE_MB=$(stat -f %z "$LATEST_BACKUP" | awk '{print int($1/1024/1024)}')
echo "最新备份: $LATEST_BACKUP (${BACKUP_SIZE_MB}MB, ${BACKUP_AGE_HOURS} 小时前)"
```

## 常见反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 备份从不验证恢复 | 备份文件损坏；需要时发现无法恢复 | 每季度在独立环境中执行一次完整恢复演练 |
| 备份存储在生产服务器本地 | 服务器故障同时丢失数据和备份 | 备份至少复制到另一台机器或云存储（OSS/S3） |
| 没有备份监控 | 备份脚本静默失败数周 | 备份失败时必须有告警通知 |
| 只有全量备份没有增量 | 两次全量备份之间产生的数据无法恢复 | 关键数据使用 oplog 实现增量备份 |
| 备份保留时间太短 | 问题发现晚于保留窗口，需要恢复的备份已被删除 | 至少保留 30 天；季度备份保留 90 天 |
