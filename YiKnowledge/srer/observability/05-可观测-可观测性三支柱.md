# 可观测性三支柱 — 日志、指标、链路追踪

> **适用场景**：为服务搭建可观测性时，或诊断生产问题时。三大支柱为你提供三个不同的系统行为观察视角——每个视角回答不同的问题。

## 三大支柱概览

| 支柱 | 回答什么问题 | 数据形态 | 数据量 | 存储成本 |
|---|---|---|---|---|
| **日志** | 发生了什么？ | 不可变、带时间戳的事件记录 | 高 | 高 |
| **指标** | 多少？多快？ | 数值时间序列数据 | 每个数据点成本低 | 低 |
| **链路追踪** | 时间花在哪里？ | 有向无环图（Span 树）| 中 | 中 |

**类比理解**：
- 日志 = 汽车的行驶记录仪（事后回放，看到底发生了什么）
- 指标 = 汽车的仪表盘（实时了解速度、油量、温度）
- 链路追踪 = 发动机拆解图（精确找到哪个零件慢了）

## 使用决策树

```
你要做什么？
├─ 调试特定错误？ → 日志
│   例："用户 123 遇到 500 错误——堆栈信息是什么？"
│
├─ 检查系统整体健康？ → 指标
│   例："P99 延迟是否超出 SLO？错误率是否飙升？"
│
├─ 定位性能瓶颈？ → 链路追踪
│   例："为什么这个接口慢？哪个服务调用是瓶颈？"
│
└─ 调查未知问题？ → 指标 → 日志 → 链路追踪
    先从指标入手（是否有问题？）→
    深入日志（发生了什么？）→
    跟随链路追踪（发生在哪里？）
```

## 一、日志

### 日志级别与记录内容

| 级别 | 用途 | 示例 | 触发告警 |
|---|---|---|---|
| **ERROR** | 出现问题，需要人工关注 | `数据库连接被拒绝：连接池已耗尽` | 是 |
| **WARN** | 状态异常但未失败 | `Ollama 请求第 3/5 次重试；退避 2 秒` | 可选（频率异常时）|
| **INFO** | 关键业务事件 | `会话已创建：session_id=abc123, user=admin` | 否 |
| **DEBUG** | 详细诊断信息 | `MongoDB 查询：find_one({key: "abc"}) 耗时 12ms` | 否 |

**日志级别配置建议**：
- 开发环境：DEBUG 级别，帮助调试
- 生产环境：INFO 级别，ERROR 和 WARN 自带
- 调试临时问题：动态调整为 DEBUG，问题解决后恢复 INFO

### 结构化日志格式

每行日志应为结构化格式（JSON），并包含以下字段：

```json
{
  "timestamp": "2026-08-24T10:00:00Z",
  "level": "INFO",
  "service": "yi-ai",
  "trace_id": "abc123",
  "message": "聊天请求已完成",
  "duration_ms": 1234,
  "user_id": "admin",
  "model": "qwen3.5"
}
```

**结构化日志的关键字段**：
- `timestamp`：ISO 8601 格式，带时区
- `trace_id`：关联同一请求的跨服务调用链
- `service`：标识日志来源服务
- `duration_ms`：请求耗时（用于后续生成 P95/P99 指标）

### YiAi 日志来源

YiAi 使用 Python 的 `logging` 模块。主要日志来源：

| 来源 | 记录内容 | 输出位置 |
|---|---|---|
| `src/app.py` | 请求生命周期（接收、处理、响应）| stdout |
| `src/domain/ai/agent.py` | Agent 循环：轮次、工具调用、确认 | stdout（带 `[Agent]` 前缀）|
| `src/data/database.py` | MongoDB 操作 | stdout |
| `src/services/ai/chat_service.py` | 聊天请求、Ollama 调用 | stdout |

## 二、指标

### 四大黄金信号

| 信号 | 指标 | 度量方式 | YiAi 示例 |
|---|---|---|---|
| **延迟** | 请求耗时（P50, P95, P99）| Histogram | `chat_request_duration_ms` |
| **流量** | 每秒请求数 | Counter | `chat_requests_total` |
| **错误** | 错误率（5xx / 总请求数）| Counter 组合 | `http_requests_total{status=~"5.."}` |
| **饱和度** | 服务多"满" | Gauge | `db_connection_pool_active`, `ollama_queue_depth` |

**为什么关注 P99 而非平均值**：
- 平均值掩盖了长尾问题——如果 99% 的请求在 100ms 完成，但 1% 的请求要 10 秒，平均值看起来仍然不错
- P99 代表最差的可接受体验，应设为 SLO 的目标值
- 长尾延迟通常意味着资源争抢、GC 暂停等系统性问题

### 指标类型

| 类型 | 行为 | 适用场景 | 示例 |
|---|---|---|---|
| **Counter** | 只增不减 | 计数类指标 | `http_requests_total`, `chat_messages_total` |
| **Gauge** | 可升可降 | 状态类指标 | `db_connection_pool_active`, `memory_usage_bytes` |
| **Histogram** | 分布统计 | 时延分布 | `request_duration_seconds` (产生 P50/P95/P99) |
| **Summary** | 预计算分位数 | 客户端延迟汇总 | 客户端侧延迟统计 |

## 三、链路追踪

### Span 结构

一次完整的链路追踪是由多个 Span 组成的树状结构。每个 Span 代表一个工作单元：

```
Trace: 聊天请求 (500ms)
├─ Span: 解析请求 (2ms)
├─ Span: 从 MongoDB 加载会话 (15ms)
│   └─ Span: find_one 查询 (12ms)
├─ Span: Ollama 聊天推理 (450ms)
│   └─ Span: Token 生成 (448ms)
└─ Span: 保存会话 (8ms)
```

### 需要追踪的操作

- **每个 HTTP 请求入口**——作为 Trace 的根节点
- **每次数据库查询**——定位慢查询
- **每次外部 API 调用**——Ollama 推理、RAG 检索
- **每次重要的内部操作**（耗时超过 10ms）

## YiAi 当前的可观测性

### 现状

YiAi 的可观测性目前处于**最小可用**状态——日志输出到 stdout，无结构化指标，无分布式追踪。

| 能力 | 当前状态 | 是否满足基本运维 |
|---|---|---|
| 日志 | stdout 纯文本输出 | 勉强满足——可看到错误，但无法结构化查询 |
| 指标 | 无 | 不满足——无法量化回答"系统现在是否健康" |
| 链路追踪 | 无 | 不满足——无法定位慢请求的瓶颈 |
| 告警 | 无自动化 | 不满足——依赖人工发现故障 |

### 快速改进路线图

| 序号 | 改进项 | 投入时间 | 收益 | 优先级 |
|---|---|---|---|---|
| 1 | **结构化日志** | 约 30 分钟 | 将 stdout 切换为 JSON 格式，便于后续日志聚合 | 最高 |
| 2 | **请求耗时指标** | 约 1 小时 | 添加中间件追踪 P50/P95/P99 延迟 | 高 |
| 3 | **错误率告警** | 约 2 小时 | 当 5xx 错误率超过 1% 持续 5 分钟时告警 | 高 |
| 4 | **分布式追踪** | 约 1 天 | 在日志中添加 trace_id；跨服务传播 | 中 |

### 目标可观测性架构

```
YiAi (FastAPI)
  │ stdout → JSON 日志 → Grafana Loki
  │ metrics → Prometheus → Grafana 仪表盘
  │ traces → Grafana Tempo
  ▼
MongoDB Atlas → 内置指标 → Atlas 仪表盘
Ollama → 自定义指标导出 → Prometheus
```

## 常见反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 所有日志都设为 DEBUG 级别 | 存储成本爆炸；有效信号被噪声淹没 | 生产环境默认 INFO 级别；DEBUG 仅开发环境使用 |
| 只有指标不设告警 | 漂亮的仪表盘但没人看 | 每个关键指标都应有告警阈值（参照 SLO 定义）|
| 日志中无 trace_id | 调试时无法跨服务关联日志行 | 在每条日志中包含 trace_id 字段 |
| 只用一种支柱 | 每种支柱回答不同的问题；单靠一种不完整 | 日志用于调试，指标用于告警，追踪用于性能分析 |
| 指标只看平均值 | 掩盖尾延迟问题 | 同时追踪 P50、P95、P99；SLO 基于 P99 设定 |
