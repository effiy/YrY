# 反向代理 — Nginx 配置（YiAi）

> **适用场景**：将 YiAi 暴露到 localhost 之外时——SSL 终止、速率限制、静态文件服务或负载均衡。

## 为什么需要反向代理

当前 YiAi 的 uvicorn 直接监听 `0.0.0.0:10086`。对于开发和内部使用，这样足够了。当需要将服务暴露到公网或多个客户端时，反向代理带来的收益包括：

| 能力 | 不使用反向代理 | 使用 Nginx |
|---|---|---|
| **SSL/TLS** | uvicorn 不擅长 | Nginx 原生支持 |
| **速率限制** | 无 | 保护 API 不被滥用 |
| **静态文件** | 无 | Nginx 直接服务静态文件 |
| **SSE 流式传输** | uvicorn 默认配置不优化 | Nginx 可配置缓冲关闭 |
| **负载均衡** | 单进程 | 代理到多个 uvicorn 进程 |

## Nginx 完整配置

```nginx
# /etc/nginx/sites-available/yiai
upstream yiai_backend {
    server 127.0.0.1:10086;
    keepalive 32;
}

server {
    listen 80;
    server_name yi-ai.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name yi-ai.example.com;

    # SSL 配置
    ssl_certificate     /etc/ssl/certs/yiai.crt;
    ssl_certificate_key /etc/ssl/private/yiai.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;

    # 安全响应头
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options DENY;
    add_header X-XSS-Protection "1; mode=block";
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;

    # 速率限制
    limit_req_zone $binary_remote_addr zone=api:10m rate=30r/s;
    limit_req zone=api burst=50 nodelay;

    # 访问日志
    access_log /var/log/nginx/yiai-access.log;
    error_log  /var/log/nginx/yiai-error.log;

    # 静态文件
    location /static/ {
        alias /opt/yiai/static/;
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # API 代理到 uvicorn
    location / {
        proxy_pass http://yiai_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # SSE 流式传输支持（对 YiAi 聊天至关重要）
        proxy_set_header Connection '';
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;  # 10 分钟超时，支持长聊天会话

        # CORS（按需启用）
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods 'GET, POST, OPTIONS';
        add_header Access-Control-Allow-Headers 'Content-Type, X-Token';
    }
}
```

## SSE 流式传输支持

以下三项配置对 YiAi 聊天功能至关重要。没有它们，SSE 流会中断：

```nginx
proxy_set_header Connection '';    # 清除 Connection 头
proxy_buffering off;                # 不缓冲——立即转发每个 chunk
proxy_cache off;                    # 不缓存 SSE 流
proxy_read_timeout 600s;           # 10 分钟超时，支持长聊天会话
```

**SSE 中断的典型现象**：
- 用户看到聊天消息只显示了一半
- 浏览器控制台显示 `EventSource` 连接中断
- 代理超时（默认 60 秒）后流式响应被截断

## 速率限制

| 区域 | 速率 | 突发 | 用途 | 说明 |
|---|---|---|---|---|
| `api` | 30 r/s | 50 | 通用 API 保护 | 对内部工具来说足够宽松 |
| `chat` | 5 r/s | 10 | 聊天接口（资源消耗大）| 聊天接口涉及 Ollama 推理 |
| `static` | 100 r/s | 200 | 静态文件 | 静态资源请求量可以较大 |

```nginx
# 聊天专用速率限制
location /chat {
    limit_req zone=chat:10m rate=5r/s burst=10 nodelay;
    proxy_pass http://yiai_backend;
}
```

**速率限制设计原则**：
- 限制应足够宽松，正常使用不会触发
- 限制应足够严格，单个滥用客户端不能压垮服务
- `burst` 参数允许短时突发流量，避免误伤正常用户

## 负载均衡

```nginx
upstream yiai_backend {
    least_conn;  # 最少连接数算法——适合长连接 SSE 流
    server 127.0.0.1:10086 weight=3 max_fails=3 fail_timeout=30s;
    server 127.0.0.1:10087 weight=1 max_fails=3 fail_timeout=30s;
    keepalive 32;
}
```

| 算法 | 适合场景 | 不适合场景 |
|---|---|---|
| `least_conn` | 长连接服务（SSE 聊天）| 无状态短连接 |
| `ip_hash` | 需要会话保持（有状态服务）| 客户端 IP 变化频繁 |
| `round_robin` | 无状态且请求耗时接近 | 长连接导致负载不均 |

## 健康检查

```nginx
upstream yiai_backend {
    server 127.0.0.1:10086 max_fails=3 fail_timeout=30s;

    # 主动健康检查（仅 Nginx Plus 支持）
    # health_check uri=/health interval=10s fails=3 passes=2;
}
```

对于开源版 Nginx，通过 `max_fails` + `fail_timeout` 实现被动健康检查。

## YiAi 特定配置注意事项

| 考量 | 具体配置 | 原因 |
|---|---|---|
| SSE 流式传输 | `proxy_buffering off; proxy_read_timeout 600s` | 避免聊天流中断 |
| 大文件上传 | `client_max_body_size 100m` | YiAi 支持文件上传功能 |
| RPC POST 请求体 | 默认 `proxy_pass` 支持 | 请求体格式为 `{module_name, method_name, parameters}` |
| YiVad CORS (8848 端口) | `add_header Access-Control-Allow-Origin http://localhost:8848` | YiVad 开发服务器跨域 |
| YiPet CORS (扩展) | `add_header Access-Control-Allow-Origin chrome-extension://*` | Chrome 扩展的跨域请求 |

## 测试与验证

```bash
# 测试反向代理是否正常工作
curl -s https://yi-ai.example.com/health

# 测试 SSE 流经代理是否正常
curl -N https://yi-ai.example.com/ \
  -H "Content-Type: application/json" \
  -H "Accept: text/event-stream" \
  -d '{"module_name":"services.ai.chat_service","method_name":"chat","parameters":{"model":"qwen3.5","messages":[{"role":"user","content":"你好"}],"stream":true}}'

# 测试速率限制是否生效
for i in $(seq 1 100); do
  curl -s -o /dev/null -w "%{http_code}\n" https://yi-ai.example.com/health
done
# 超出速率限制后应返回 429 状态码
```

## 常见反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| SSE 接口开启 `proxy_buffering on` | SSE 消息块被缓冲；用户看不到任何内容，直到流结束 | SSE 端点必须 `proxy_buffering off` |
| 不设置 `proxy_read_timeout` | 默认 60 秒超时会切断长聊天会话 | 聊天接口设置为 600s（10 分钟）|
| 无速率限制 | 单个客户端可以压垮整个 API | 添加速率限制；对内部工具 30 r/s 已足够宽松 |
| SSL 在 uvicorn 层终止 | 性能差；uvicorn 不是 SSL 终止器 | 在 Nginx 终止 SSL；uvicorn 接收纯 HTTP |
| CORS 使用 `*` 通配符 | 安全风险——任何域名都可以发起请求 | 生产环境指定具体允许的域名 |
