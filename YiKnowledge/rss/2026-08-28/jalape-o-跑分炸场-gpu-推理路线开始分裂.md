margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">Transformer 在生成新 Token 时，会把此前 Attention 的 Key 和 Value 保存起来，避免每次重新计算全部历史。上下文越来越长，KV Cache 也跟着增长。Agent 又会不断积累系统 Prompt、工具返回、网页、代码和历史步骤，这些状态可能跟着一个 Session 存在很久。</span></p><section style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a91382514501.png?imageMogr2/quality/90" style="background-color: transparent; width: 100%;" /></section><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">于是调度器不能只看“哪颗芯片现在空闲”，还得考虑“这个请求的数据现在在哪”。如果 Prefill 在一组机器完成，Decode 被迁到另一组机器，KV Cache 也可能跟着跨网络移动。对于长上下文模型，这次搬运本身就会消耗带宽和时间。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">到了这里，推理芯片的价值已经不只来自减少几次计算。它开始围绕一整条数据路径做优化：权重从哪里来、KV Cache 留在哪里、一次 Token 生成需要访问几次 HBM、数据需不需要跨芯片，以及计算单元有多少时间处在等待状态。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">而 NVIDIA 选择的办法，比 Jalapeño 更激进一些——它直接把推理内部拆开了。</span></p><section><section><section style="width: 100%; display: flex; padding: 0px 14px 0px 14px;"><section style="display: flex;"><section><img alt="图片" class="rich_pages wxw-img __bg_gif" src="https://static.leiphone.com/uploads/new/images/20260828/6a91382546237.jpg?imageMogr2/quality/90" style="display: block; height: auto !important; width: 38px !important; background-color: transparent;" /></section><section style="text-align: center;"><p style="font-size: 36px; color: #333333; line-height: 50px;"><strong><span>03</span><span><br /></span></strong></p><h2><span><br /></span></h2><h2><strong><strong style="text-align: center; font-size: 18px; color: rgb(51, 51, 51); line-height: 25px; font-weight: bold; font-family: Optima-Regular, PingFangTC-light;"><strong style="text-align: center; color: rgb(51, 51, 51); line-height: 25px; font-weight: bold; font-family: Arial, Helvetica, sans-serif; font-size: 18px;"><span style="text-align: center; color: #333333; line-height: 25px; font-weight: bold; font-family: Arial, Helvetica, sans-serif; font-size: 18px;">GPU 不再包下整段推理</span><span><br /></span></strong></strong></strong></h2></section></section></section></section></section><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a91382582487.png?imageMogr2/quality/90" style="background-color: transparent; width: 100%;" /></section><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">Groq 的芯片设计也几乎围绕这件事展开。一套 LPX 机架有&nbsp;</span><code><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">256</span></code><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">&nbsp;颗 LPU，加起来只有&nbsp;</span><code><span style="font-size: 15px; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a913825c17bb.png?imageMogr2/quality/90" style="background-color: transparent; width: 100%;" /></section><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">Decode 每一步做的计算有限，又频繁取数据，把数据放得更靠近 ALU，收益会非常直接地反映在下一个 Token 的等待时间上。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">Groq 还进一步减少了动态硬件控制。LPU 是确定性执行架构，指令调度主要由软件提前完成。每颗芯片同时充当处理器和路由器，编译器会一起安排计算资源和网络资源，甚至省掉了传统硬件流控和虚拟通道这类机制。</span></p><section style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a9138260812e.png?imageMogr2/quality/90" style="background-color: transparent; width: 100%;" /></section><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">代价也很明显：这种架构没有 GPU 那么通用，片上 SRAM 又装不下完整的大模型状态。所以 NVIDIA 没有让 Groq 3 独立运行整个模型，而是做了一套更复杂的异构系统。</span></p><section style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a9138263c774.png?imageMogr2/quality/90" style="background-color: transparent; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">这套结构很能说明 AI 芯片分工已经走到了什么程度。它拆的已经不只是“训练芯片”和“推理芯片”，连一次 Decode 里面的不同部分也可以放到不同架构执行。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">不过 NVIDIA 展示的数据也给出了这条路线的边界：当业务只追求总体吞吐，并且能够接受较高延迟时，Rubin GPU 依然很有效率；随着对单用户 Token 速度要求提高，LPX 才逐渐发挥优势，而使用更多 LPU 之后，总体吞吐效率也会下降。</span></p><section style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a91382672399.png?imageMogr2/quality/90" style="background-color: transparent; display: flex; padding: 0px 14px 0px 14px;"><section style="display: flex;"><section><img alt="图片" class="rich_pages wxw-img __bg_gif" src="https://static.leiphone.com/uploads/new/images/20260828/6a913826d851d.jpg?imageMogr2/quality/90" style="display: block; height: auto !important; width: 38px !important; background-color: transparent;" /></section><section style="text-align: center;"><p style="font-size: 36px; color: #333333; line-height: 50px;"><strong><span>04</span><span><br /></span></strong></p><h2><span><br /></span></h2><h2><strong><strong style="text-align: center; font-size: 18px; color: rgb(51, 51, 51); line-height: 25px; font-weight: bold; font-family: Optima-Regular, PingFangTC-light;"><strong style="text-align: center; color: rgb(51, 51, 51); line-height: 25px; font-weight: bold; font-family: Arial, Helvetica, sans-serif; font-size: 18px;"><span style="text-align: center; color: #333333; line-height: 25px; font-weight: bold; font-family: Arial, Helvetica, sans-serif; font-family: Arial, Helvetica, sans-serif;">&nbsp;聚合计算能力，Google 还为它引入 Virgo 网络，把更大范围的训练连接做成专门体系。</span></p><section style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><img class="rich_pages wxw-img" src="https://static.leiphone.com/uploads/new/images/20260828/6a913827d82f4.png?imageMogr2/quality/90" style="background-color: transparent; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">把三条路线放在一起，差异其实很清楚。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">OpenAI 做 Jalapeño，把芯片专用化到 LLM 推理这一层，但保留 Prefill 和 Decode 在同构硬件上的灵活调度；NVIDIA 往下继续拆，让 GPU 和 Groq LPU 分担一次推理里的不同阶段；Google 往上切，把训练和推理直接做成两颗 TPU。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">这几条路线背后并没有神秘的新计算原理，改变的是资源比例。训练希望把更多晶体管投入矩阵计算和大规模互联，因为高 Batch 能把数据搬运成本摊开；低延迟推理需要更高的 HBM 带宽、更大的 SRAM、更好的 KV Cache 局部性和更短的网络路径，因为很多时间花在等待数据上。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">当两类负载需要的“芯片配方”越拉越开，用一颗通用芯片同时照顾它们，效率损失自然会越来越明显。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">这也是为什么这轮硬件竞争里的核心数字正在变化。FLOPS 依然重要，但旁边开始出现&nbsp;</span><code><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">Token</span></code><code><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">s/s/user</span></code><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">、TBT、TTFT、Tokens/kW、HBM 带宽以及网络延迟。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">它们描述的其实是同一件事：算力已经放在那里了，系统能不能持续把数据喂进去，并把生成的 Token 尽快送出来。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">OpenAI、NVIDIA 和 Google 现在选择的分界线还不一样，后面真正会继续变化的，很可能也是这条线应该画在哪里。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">训练和推理可以拆，Prefill 和 Decode 可以拆，Decode 内部的 Attention 与其他计算也可以继续拆。拆得越细，单项效率越容易提高，但资源调度、KV Cache 搬运和跨硬件通信也会变得更复杂。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">因此下一阶段 AI 芯片竞争的难题，或许已经不只是造出一颗更强的芯片。</span></p><p style="text-align: justify; margin: 16px 16px 24px; line-height: 1.75em;"><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;">更难的是决定：</span><strong><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;"><span style="color: #4499E7;">哪些任务值得专门做一颗芯片，哪些任务继续放在同一套硬件里，整套系统的&nbsp;</span></span></strong><strong><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;"><span style="color: #4499E7;">Token</span></span></strong><strong><span style="font-size: 15px; font-family: Arial, Helvetica, sans-serif;"><span style="color: #4499E7;">&nbsp;成本才更低。</span></span></strong></p><p style="text-align: justify;
