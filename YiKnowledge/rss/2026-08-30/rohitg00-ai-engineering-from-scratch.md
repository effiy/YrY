<h3>Use every lesson the same way</h3> 
<ol> 
 <li><strong>Read</strong> <code>docs/en.md</code> and explain the core idea in your own words.</li> 
 <li><strong>Type and build</strong> the important code instead of treating the code block as decoration.</li> 
 <li><strong>Run</strong> the lesson command from the repository root, the directory containing <code>README.md</code> and <code>phases/</code>.</li> 
 <li><strong>Keep evidence</strong>: the command, working directory, exit code, meaningful output, and the artifact you changed or produced.</li> 
 <li><strong>Continue</strong> only when you can explain the output and make one small change without guessing.</li> 
</ol> 
<p>Commands in lesson pages are paths from the repository root unless the lesson explicitly says to change directories. If a lesson offers several languages, run the implementation for the language you are learning.</p> 
<h3>Clone it and produce your first evidence</h3>

<h2>How this works</h2> 
<p>Most AI material teaches in scattered pieces. A paper here, a fine-tuning post there, a flashy agent demo somewhere else. The pieces rarely line up. You ship a chatbot but can't explain its loss curve. You hook a function to an agent but can't say what attention does inside the model that's calling it.</p> 
<p>This curriculum is the spine. 20 phases, 511 lessons, four languages: Python, TypeScript, Rust, Julia. Linear algebra at one end, autonomous swarms at the other. Every algorithm gets built from raw math first. Backprop. Tokenizer. Attention. Agent loop. By the time PyTorch shows up, you already know what it's doing under the hood.</p> 
<p>Each lesson runs the same loop: read the problem, derive the math, write the code, run the test, keep the artifact. No five-minute videos, no copy-paste deploys, no hand-holding. Free, open source, and built to run on your own laptop.</p>

<h2>The toolkit</h2> 
<p>Every lesson produces a reusable artifact. By the end you have:</p> 
<pre><code class="language-text">outputs/
├── prompts/      prompt templates for every AI task
└── skills/       SKILL.md files for AI coding agents
</code></pre> 
<p>Plug them into Claude, Cursor, Codex, OpenClaw, Hermes, or any agent that reads a <a href="http://SKILL.md">SKILL.md</a> / <a href="http://AGENTS.md">AGENTS.md</a> directory. Real tools, not homework.</p> 
<h3>Install course skills into your agent</h3> 
<p>Two skill sets, two installers:</p> 
<p><strong>The learning skills</strong> (<code>start-learning</code>, <code>learn</code>, <code>course-guide</code>, <code>learn-mcp</code>, <code>learn-agent-skills</code>, <code>claude-certification</code>, <code>find-your-level</code>, and <code>check-understanding</code>) live under <a href="https://raw.githubusercontent.com/rohitg00/ai-engineering-from-scratch/main/skills/"><code>skills/</code></a> and install into a supported skill-capable host with one command. Installation needs Node.js and <code>npx</code>, but not a repository clone or Python:</p> 
<pre><code class="language-bash">npx skills add rohitg00/ai-engineering-from-scratch
</code></pre> 
<p><code>skills</code> writes to the host and scope selected during installation, such as <code>.claude/skills/</code>, <code>.cursor/skills/</code>, <code>.codex/skills/</code>, or another supported skills folder. Verify that the selected host discovers that exact destination.</p> 
<p><strong>The lesson artifacts.</strong> The repo ships 396 skills and 99 prompts under <code>phases/**/outputs/</code>; install them via <code>scripts/install_skills.py</code>. Requires cloning the repo. Supports tag filters, dry-runs, and per-agent layouts:</p> 
<pre><code class="language-bash">python3 scripts/install_skills.py &lt;target&gt;                                 # every skill, default --layout skills (nested)
python3 scripts/install_skills.py &lt;target&gt; --layout skills                 # same as above, explicit
python3 scripts/install_skills.py &lt;target&gt; --type all                      # skills + prompts + agents
python3 scripts/install_skills.py &lt;target&gt; --phase 14                      # one phase only
python3 scripts/install_skills.py &lt;target&gt; --tag rag                       # filter by tag
python3 scripts/install_skills.py &lt;target&gt; --layout flat                   # flat files
python3 scripts/install_skills.py &lt;target&gt; --dry-run                       # preview without writing
python3 scripts/install_skills.py &lt;target&gt; --force                         # overwrite existing files
</code></pre> 
<p><code>&lt;target&gt;</code> is the skills directory for your agent (examples: <code>~/.claude/skills/</code>, <code>~/.cursor/skills/</code>, <code>~/.config/openclaw/skills/</code>, <code>.skills/</code>, or any path your agent reads).</p> 
<p>By default the script refuses to overwrite an existing destination and exits with code 1 after listing every colliding path. Use <code>--dry-run</code> to preview collisions or <code>--force</code> to overwrite. Every non-dry-run run writes a <code>manifest.json</code> in the target with the full inventory grouped by type and phase. Pick the layout your agent reads:</p>

<h3>Drop the agent workbench into your own repo</h3> 
<p>The Phase 14 capstone ships a reusable Agent Workbench pack (<a href="http://AGENTS.md">AGENTS.md</a>, schemas, init / verify / handoff scripts). Scaffold it into any repo with:</p> 
<pre><code class="language-bash">python3 scripts/scaffold_workbench.py path/to/your-repo            # full pack + seeds
python3 scripts/scaffold_workbench.py path/to/your-repo --minimal  # skip docs/
python3 scripts/scaffold_workbench.py path/to/your-repo --dry-run  # preview only
python3 scripts/scaffold_workbench.py path/to/your-repo --force    # overwrite
</code></pre> 
<p>You get the seven workbench surfaces wired up, a starter <code>task_board.json</code>, and a fresh <code>agent_state.json</code> at <code>schema_version: 1</code>. From there: edit the task, edit <code>AGENTS.md</code>, run <code>scripts/init_agent.py</code>, hand the contract to your agent. The pack source lives at <code>phases/14-agent-engineering/42-agent-workbench-capstone/outputs/agent-workbench-pack/</code>.</p> 
<h3>Browse the entire course as JSON</h3> 
<p><code>scripts/build_catalog.py</code> walks every phase, every lesson, every artifact on disk and writes <code>catalog.json</code> at the repo root. One file, every course truth.</p> 
<pre><code class="language-bash">python3 scripts/build_catalog.py               # writes &lt;repo&gt;/catalog.json
python3 scripts/build_catalog.py --stdout      # to stdout, do not touch repo
python3 scripts/build_catalog.py --out path/to/file.json
</code></pre> 
<p>The catalog is filesystem-derived, not README-derived, so counts always match what is actually on disk. Use it for site builds, downstream tooling, or to verify the README counts have not drifted. Schema is documented at the top of the script.</p> 
<p>A GitHub Action (<code>.github/workflows/curriculum.yml</code>) rebuilds <code>catalog.json</code> on every PR and fails the build if the committed file is stale. After editing any lesson, run <code>python3 scripts/build_catalog.py</code> and commit the result, or CI will reject the PR. The same workflow runs <code>audit_lessons.py</code> in warn-only mode (so existing drift does not block contributors).</p> 
<h3>Smoke-check every lesson's Python code</h3> 
<p><code>scripts/lesson_run.py</code> byte-compiles every <code>.py</code> file under each lesson's <code>code/</code> directory. Default mode is syntax-check only — no execution, no API keys, no heavy ML deps required. Catches the regressions contributors introduce most often (bad indentation, broken f-strings, stray edits).</p> 
<pre><code class="language-bash">python3 scripts/lesson_run.py                  # syntax-check the whole curriculum
python3 scripts/lesson_run.py --phase 14       # one phase only
python3 scripts/lesson_run.py --json           # JSON report on stdout
python3 scripts/lesson_run.py --strict         # exit 1 if any lesson fails
python3 scripts/lesson_run.py --execute        # actually run, 10s timeout per lesson
</code></pre> 
<p><code>--execute</code> runs each lesson's <code>code/main.py</code> (or the first <code>.py</code> file) with a 10-second timeout. Lessons whose entry file starts with a <code># requires: pkg1, pkg2</code> comment listing non-stdlib deps are skipped with reason <code>needs &lt;deps&gt;</code>. The script is opt-in and not wired into CI.</p> 
<p>Stdlib only, Python 3.10+. Set <code>LINK_CHECK_SKIP=domain1,domain2</code> to override the default skip-list (<code>twitter.com</code>, <code>x.com</code>, <code>linkedin.com</code>, <code>instagram.com</code>, <code>medium.com</code> — domains that aggressively block automated HEAD/GET).</p>
