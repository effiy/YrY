<p style="text-align: left;">终端里干到一半的活，换个窗口就得从头再干一遍。今天，这事结束了。</p><p>就在刚刚，Anthropic 官宣，<strong>Claude Code 桌面端打通了终端会话！</strong><strong>在桌面端敲下</strong><strong> /resume</strong><strong>，历史会话列表就弹出来，点击任意一个之前在 CLI 终端里开过的工作会话，原样拉进桌面接着干。</strong></p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/5d802bab-878e-4734-9cfa-fee0dd579e1d.png?x-bce-process=image/format,f_auto" /></p><p>完整对话记录、代码片段、之前一起理清的来龙去脉，一个不落地跟着搬。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/88c56a3e-1007-42af-8ed6-0b0e00b2e311.png?x-bce-process=image/format,f_auto" /></p><p>更扎眼的是官方演示视频里的那张 Dashboard。</p><p>Claude Code 团队自己的工程师 Lydia Hallie，会话统计 1240 次、162.4M tokens，也就是 <strong>1.624 亿 Token</strong>。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/5d076c9b-1ec7-4c02-88ae-4f801cf62920.gif" /></p><p>开发这个工具的人，自己攒下的会话已经是一笔沉甸甸的资产。</p><p>而在昨夜之前，就连她自己也被跨端的围墙卡着。</p><p><strong>每天都在交的隐形税</strong></p><p>泡在 Claude Code 里的人，都交过这笔税。</p><p>你在终端里起了个活，写到一半走开。下次想换桌面端接着做，前面那一整套对话得重新喂一遍。</p><p>项目结构、试错过的方案、你已经跟它讲好的口径，全部重讲。</p><p>如果这个活已经跑了几十轮对话，重建它的代价往往比继续干还高。</p><p><strong>现在，上下文开始跟着人走，不再钉死在某一个窗口上。</strong></p><p>终端那头其实早就没这个问题。恢复会话的命令一直都有，会话记录就存在本地，随时能拿回来接着干。</p><p>卡住的是桌面端。官方文档写得很清楚，桌面、Web、VS Code 各管各的会话历史，互相看不见。你在终端里干的活，桌面端根本不知道它存在。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/39bdc967-8421-46c8-83c5-28804bc06366.png?x-bce-process=image/format,f_auto" /></p><p>今年 4 月，有人在 GitHub 上正式提了需求：终端能恢复会话，桌面连个选择器都没有，换个端就丢上下文。Claude Code 团队当时也讨论过怎么补，只是没做顺。</p><p>8 月底，官方终于补上了。</p><p>补法很讲究。Claude Code 团队工程师 Lydia Hallie 在官宣半小时后发了一条帖子，把产品逻辑说圆了。</p><p>终端里原本就有 /desktop，命令行可以把当前这个会话交到桌面手上。现在多出来的 /resume 正好相反，<strong>人在桌面端，可以把过去在 </strong><strong>CLI</strong><strong> 里开过的会话捡回来</strong>。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/42482fc5-01a5-442b-96fe-afd1c2706207.png?x-bce-process=image/format,f_auto" /></p><p>一交一捡，两个方向都通了。</p><p>捡回来的会话还是活的。检查点机制照常可用，你依然可以用 /rewind 退回到之前任意一步，不用担心跨端接手会把前面的活改坏。</p><p>Claude Code 的工程师 Anthony Morris 也交代了背后的纠结：团队本来想过更省事的方案，直接把终端会话塞进桌面侧栏，但界面没做到满意，先用 /resume 顶上。</p><p><strong>更理想的方案没砍掉，只是往后排了。</strong></p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/4e082d04-1897-4a7f-928c-d26a7b703121.png?x-bce-process=image/format,f_auto" /></p><p>网友 @ServoReality 说得最准：这事听起来很小，直到你意识到在不同工具之间重建上下文要浪费掉多少时间，/resume 属于那种<strong>无聊但会改变日常使用</strong>的功能。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/df0cedfc-79a6-491a-91c7-81ba6ba7655a.png?x-bce-process=image/format,f_auto" /></p><p>Stripe 设计经理 @krispuckett 反应更直接。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/7f62924b-409e-4c6e-89e9-9d46b46f0234.png?x-bce-process=image/format,f_auto" /></p><p>网友 @Aykutuces 说终端和桌面终于不用二选一了。</p><p style="text-align: center;"><img class="no-alt-img" src="https://img.ithome.com/newsuploadfiles/2026/8/425cb7ea-bf0f-4ac3-856a-4d896169ee7d.png?x-bce-process=image/format,f_auto" /></p><h3>Anthropic 这个月一直在补同一件事</h3><p>把 Anthropic 8 月的更新排在一起看，/resume 不是孤零零冒出来的。</p><p>就在本月，Claude Code 桌面端加了一个自动续跑的功能 —— 额度用完了不用人守着，等额度一恢复，它自己接着干。</p><p>还修了两个 bug：聊太久会话标题会莫名消失，超过 30 天的会话会被自动清掉。</p><p>这条线很明显：<strong>会话不许丢，标题不许丢，等额度的那段时间也不许丢。</strong></p><p>有位博主说得到位，<strong>这是桌面端走向中控台的又一步</strong>。一旦所有会话都能从桌面端找回来，它就不再只是一个聊天窗口了。</p><p>不过目前打通的都是<strong>终端里起的活，</strong>不管是从终端推过去还是从桌面拉过来，会话本身都是在终端里开的。</p><p>在桌面端从零开始的会话呢，目前还搬不回终端。不过，社区已经在追这个能力了。</p><p>但方向已经很清楚了。</p><p>在 Claude Code 这样的工具里，最贵的东西是你和模型一起攒出来的那段上下文。它比任何一个文件都难重建。</p><p>当你跟模型聊出来的那些东西能跟着你走，这就是<strong>一段随时能捡起来的对话</strong>。</p><p>断点续传这个词，我们用了二三十年来传文件。现在它开始传工作了。</p><p><span class="referenceTitle
