<h2>Start From A Video You Already Love</h2> 
<p>Starting from a reference video is often faster than starting from a blank prompt.</p> 
<p>OpenMontage can start from a <strong>YouTube video, Short, Reel, TikTok, or local clip</strong> and turn it into a grounded production plan:</p> 
<ol> 
 <li><strong>Paste a reference video</strong></li> 
 <li><strong>The agent analyzes transcript, pacing, scenes, keyframes, and style</strong></li> 
 <li><strong>You get 2-3 differentiated concepts, an honest tool path, cost estimates, and a sample before full production</strong></li> 
</ol> 
<pre><code class="language-text">"Here's a YouTube Short I love. Make me something like this, but about quantum computing."
</code></pre> 
<p>What you get back is not "best guess prompt spaghetti." You get:</p> 
<ul> 
 <li><strong>What it keeps</strong> from the reference: pacing, hook style, structure, tone</li> 
 <li><strong>What it changes</strong>: topic, visual treatment, angle, narration approach</li> 
 <li><strong>What it will cost</strong> at your target duration, before asset generation starts</li> 
 <li><strong>What it will actually look like</strong> with your currently available tools</li> 
</ul> 
<p>Works with <strong>Claude Code, Cursor, Copilot, Windsurf, Codex</strong> — any AI coding assistant that can read files and run code.</p>

<h2>Watch It Happen — The Backlot Living Storyboard</h2> 
<p>Chat tells you what the agent <em>said</em>. <strong>Backlot shows you what the production is actually doing</strong> — a local board that fills itself in as the pipeline runs. Stages light up, the script lands as a screenplay page, scene cards shimmer while assets generate, and every provider decision and dollar spent is on the wall.</p> 
<p>When a production starts, the agent opens it for you automatically. No setup, no reporting — the board derives everything from the project files the pipeline already writes.</p> 
<p align="center"><img alt="Backlot live board — assets generating" src="https://raw.githubusercontent.com/calesthio/OpenMontage/main/docs/images/backlot/board-live.png" width="920" /></p> 
<p><strong>The storyboard is now a real approval gate.</strong> Asset generation pauses on a scene-by-scene contact sheet — takes, prompts, per-asset cost, quality scores — so you approve the visuals <em>before</em> the render, not after it's too late:</p> 
<p align="center"><img alt="Backlot storyboard — filmstrip with takes and renders" src="https://raw.githubusercontent.com/calesthio/OpenMontage/main/docs/images/backlot/storyboard.png" width="920" /></p> 
<p>Creative gates hold until you answer. The board shows what's waiting and why; you reply in chat:</p> 
<p align="center"><img alt="Backlot script gate — awaiting approval" src="https://raw.githubusercontent.com/calesthio/OpenMontage/main/docs/images/backlot/script-gate.png" width="920" /></p> 
<p>Every production on your machine, live-first, in the library:</p> 
<p align="center"><img alt="Backlot library" src="https://raw.githubusercontent.com/calesthio/OpenMontage/main/docs/images/backlot/library.png" width="920" /></p> 
<pre><code class="language-bash">python -m backlot open                  # the library — every project on disk

<h2>Quick Start</h2> 
<h3>Prerequisites</h3> 
<ul> 
 <li><strong>Python 3.10+</strong> — <a href="https://www.python.org/downloads/">python.org</a></li> 
 <li><strong>FFmpeg</strong> — <code>brew install ffmpeg</code> / <code>sudo apt install ffmpeg</code> / <a href="https://ffmpeg.org/download.html">ffmpeg.org</a></li> 
 <li><strong>Node.js 18+</strong> — <a href="https://nodejs.org/">nodejs.org</a></li> 
 <li><strong>An AI coding assistant</strong> — Claude Code, Cursor, Copilot, Windsurf, or Codex</li> 
</ul> 
<h3>Install &amp; Run</h3> 
<pre><code class="language-bash">git clone https://github.com/calesthio/OpenMontage.git
cd OpenMontage
make setup
</code></pre> 
<p>Open the project in your AI coding assistant and tell it what you want:</p> 
<pre><code>"Make a 60-second animated explainer about how neural networks learn"
</code></pre> 
<p>Or if you want the real-footage path:</p> 
<pre><code class="language-text">"Make a 75-second documentary montage about city life in the rain. Use real footage only, no narration, elegiac tone, with music."
</code></pre> 
<p>That's it. The agent researches your topic with live web search, generates AI images, writes and narrates the script with voice direction, finds royalty-free background music automatically, burns in word-level subtitles, and renders the final video. Before you see anything, the system runs a multi-point self-review — ffprobe validation, frame sampling, audio level analysis, delivery promise verification, and subtitle checks. Every provider selection is scored across 7 dimensions with an auditable decision log. Every creative decision gets your approval.</p> 
<blockquote> 
 <p><strong>No <code>make</code>?</strong> macOS/Linux: <code>python3 -m venv .venv &amp;&amp; source .venv/bin/activate &amp;&amp; python -m pip install -r requirements.txt &amp;&amp; cd remotion-composer &amp;&amp; npm install &amp;&amp; cd .. &amp;&amp; python -m pip install piper-tts &amp;&amp; cp .env.example .env</code></p> 
 <p>Windows PowerShell: <code>py -3 -m venv .venv; .\.venv\Scripts\Activate.ps1; python -m pip install -r requirements.txt; cd remotion-composer; npm install; cd ..; python -m pip install piper-tts; Copy-Item .env.example .env</code></p> 
 <p><strong>Windows:</strong> If <code>npm install</code> fails with <code>ERR_INVALID_ARG_TYPE</code>, use <code>npx --yes npm install</code> instead.</p> 
</blockquote>

<p>OpenMontage picks between Remotion and HyperFrames at proposal time (locked as <code>render_runtime</code>). Remotion is the default for data-driven explainers and anything using the existing React scene stack; HyperFrames is the default for motion-graphics-heavy briefs that express naturally as HTML + GSAP, including the <code>character-animation</code> pipeline's SVG/GSAP rig output. See <code>skills/core/hyperframes.md</code> for the full decision matrix.</p> 
<p><strong>Two free-ish paths:</strong></p> 
<ul> 
 <li><strong>Image-based video:</strong> Piper narrates your script, images provide the visuals, and Remotion animates them into a polished edit.</li> 
 <li><strong>Local character animation:</strong> SVG rigs, pose libraries, GSAP timelines, and HyperFrames render cartoon character acting to <code>projects/&lt;project-name&gt;/renders/final.mp4</code>.</li> 
 <li><strong>Real-footage video:</strong> the documentary montage pipeline builds a CLIP-searchable corpus from <a href="http://Archive.org">Archive.org</a>, NASA, Wikimedia Commons, and optional free-key sources like Pexels and Unsplash, then cuts together actual motion footage into a finished video.</li> 
</ul> 
<p>If you want the second one, prompt for a <strong>documentary montage</strong>, <strong>tone poem</strong>, or <strong>stock-footage collage</strong>, and explicitly say <strong>use real footage only</strong>.</p>

<h2>Why OpenMontage?</h2> 
<p>Most AI video tools give you a single clip from a prompt. OpenMontage gives you an <strong>end-to-end production pipeline</strong> — the same structured process a real production team follows, automated by your AI agent.</p> 
<p>Most "free AI video" stacks quietly mean "animate still images." OpenMontage can do that too, but it can also build a finished video from <strong>real footage</strong> pulled from free/open sources, ranked semantically, edited intentionally, and rendered as a proper timeline.</p> 
<p>Edit your own talking-head footage. Generate a fully animated explainer from scratch. Cut a 2-hour podcast into a dozen social clips. Translate and dub your content into 10 languages. Build a cinematic brand teaser from stock footage and AI-generated scenes. <strong>If a production team can make it, OpenMontage can orchestrate it.</strong></p> 
<ul> 
 <li><strong>10+ production pipelines</strong> — explainers, talking heads, screen demos, cinematic trailers, animations, podcasts, localization, documentary montages, character animation, and more</li> 
 <li><strong>100+ production tools</strong> — spanning video generation, image creation, text-to-speech, music, audio mixing, subtitles, enhancement, and analysis</li> 
 <li><strong>60+ provider integrations</strong> — cloud APIs, local models, stock libraries, open archives, and production runtimes behind one scored selection layer</li> 
 <li><strong>700+ agent skill and production-knowledge files</strong> — pipeline directors, creative techniques, quality checklists, and deep technology knowledge packs that teach the agent how to use every tool like an expert</li> 
 <li><strong>Reference-driven creation</strong> — paste a video you like and the agent turns it into a grounded, differentiated production plan instead of forcing you to invent the perfect prompt from scratch</li> 
 <li><strong>Real-footage documentary creation without paid video models</strong> — build actual edited videos from free/open motion footage and archival sources, not just Ken Burns over images</li> 
 <li><strong>Live web research built in</strong> — before writing a single word of script, the agent runs 15-25+ web searches across YouTube, Reddit, news sites, and academic sources to ground your video in real, current data</li> 
 <li><strong>Both free/local AND cloud providers</strong> — every capability supports open-source local alternatives alongside premium APIs. Use what you have.</li> 
 <li><strong>No vendor lock-in</strong> — swap providers freely. The scored selector ranks every provider across 7 dimensions (task fit, output quality, control, reliability, cost efficiency, latency, continuity) and picks the best match automatically.</li> 
 <li><strong>Production-grade quality gates</strong> — delivery promise enforcement blocks slideshow-looking renders, pre-compose validation catches broken plans before wasting GPU time, and mandatory post-render self-review (ffprobe + frame extraction + audio analysis) ensures the agent never presents garbage. Every provider choice, style decision, and fallback gets logged in an auditable decision trail.</li> 
 <li><strong>Budget governance built in</strong> — cost estimation before execution, spend caps, per-action approval thresholds. No surprise bills.</li> 
</ul>

<h2>How It Works</h2> 
<p>OpenMontage uses an <strong>agent-first architecture</strong>. There is no code orchestrator. Your AI coding assistant IS the orchestrator.</p> 
<pre><code>You: "Make an explainer video about how black holes form"
 |
 v
Agent reads pipeline manifest (YAML) -- stages, tools, review criteria, success gates
 |
 v
Agent reads stage director skill (Markdown) -- HOW to execute each stage
 |
 v
Agent calls Python tools -- scored provider selection ranks every tool across 7 dimensions
 |
 v
Agent self-reviews using reviewer skill -- schema validation, playbook compliance, quality checks
 |
 v
Agent checkpoints state (JSON) -- resumable, with decision log and cost snapshot
 |
 v
Agent presents for your approval -- you stay in control at every creative decision
 |
 v
Pre-compose validation gate -- delivery promise, slideshow risk, renderer governance
 |
 v
Render (Remotion or FFmpeg) -- composition engine matched to visual grammar
 |
 v
Post-render self-review -- ffprobe, frame extraction, audio analysis, promise verification
 |
 v
Final video output -- only if self-review passes
</code></pre> 
<p><strong>Python provides tools and persistence.</strong> All creative decisions, orchestration logic, review criteria, and quality standards live in readable instruction files (YAML manifests + Markdown skills) that you can inspect and customize. Every decision is logged with alternatives considered, confidence scores, and the reasoning behind each choice.</p>

<h2>Architecture</h2> 
<pre><code>OpenMontage/
├── tools/              # 100+ registered production tools (the agent's hands)
│   ├── video/          # 20+ generation providers + compose, stitch, trim
│   ├── audio/          # 10+ speech providers + music, mixing, enhancement
│   ├── graphics/       # 15+ image providers + diagrams, code snippets, math
│   ├── enhancement/    # Upscale, bg remove, face enhance, color grade
│   ├── analysis/       # Transcription, scene detect, frame sampling
│   ├── avatar/         # Talking head, lip sync
│   └── subtitle/       # SRT/VTT generation
│
├── pipeline_defs/      # YAML pipeline manifests (the agent's playbook)
├── skills/             # Markdown skill files (the agent's knowledge)
│   ├── pipelines/      # Per-pipeline stage director skills
│   ├── creative/       # Creative technique skills
│   ├── core/           # Core tool skills
│   └── meta/           # Reviewer, checkpoint protocol
│
├── schemas/            # 20+ JSON Schemas (contract validation)
├── styles/             # Visual style playbooks (YAML)
├── remotion-composer/  # React/Remotion video composition engine
├── lib/                # Core infrastructure (config, checkpoints, pipeline loader)
└── tests/              # Contract tests, QA integration tests, eval harness
</code></pre> 
<h3>Three-Layer Knowledge Architecture</h3> 
<pre><code>Layer 1: tools/ + pipeline_defs/     "What exists" — executable capabilities + orchestration
Layer 2: skills/                     "How to use it" — OpenMontage conventions and quality bars
Layer 3: .agents/skills/             "How it works" — external technology knowledge packs
</code></pre> 
<p>Each tool declares which Layer 3 skills it relies on. The agent reads Layer 1 to know what's available, Layer 2 to know how OpenMontage wants it used, and Layer 3 for deep technical knowledge when needed.</p>

<h2>Production Governance</h2> 
<p>OpenMontage treats video production like real engineering — with quality gates, audit trails, and enforcement at every stage.</p> 
<h3>Quality Gates</h3> 
<ul> 
 <li><strong>Human approval gates are enforced, not suggested</strong> — proposal, script, scene plan, generated assets, and publish all pause for your sign-off. The checkpoint writer rejects a "completed" gated stage without recorded approval, and every superseded checkpoint is archived so the audit trail (including gate transitions) survives revisions. Review happens visually on the <a href="https://raw.githubusercontent.com/calesthio/OpenMontage/main/#watch-it-happen--the-backlot-living-storyboard">Backlot board</a>.</li> 
 <li><strong>Pre-compose validation</strong> — blocks render if the delivery promise is violated (e.g. "motion-led" video with 80% still images), slideshow risk score is critical, or renderer family is missing. Catches broken plans before wasting GPU time.</li> 
 <li><strong>Post-render self-review</strong> — after every render, the runtime runs ffprobe validation, extracts frames at 4 positions to check for black frames and broken overlays, analyzes audio levels for silence and clipping, verifies the delivery promise was honored, and checks subtitle presence. If the review fails, the video is not presented.</li> 
 <li><strong>Slideshow risk scoring</strong> — 6-dimension analysis (repetition, decorative visuals, weak motion, shot intent, typography overreliance, unsupported cinematic claims) prevents "animated PowerPoint" outputs.</li> 
 <li><strong>Source media inspection</strong> — when users supply their own footage, the system probes every file (resolution, codec, audio channels, duration) and builds planning implications before a single creative decision is made. No hallucinating content from filenames.</li> 
</ul> 
<h3>Scored Provider Selection</h3> 
<p>Every tool selection (video generation, image generation, TTS, music) runs through a 7-dimension scoring engine: task fit (30%), output quality (20%), control features (15%), reliability (15%), cost efficiency (10%), latency (5%), continuity (5%). The winning provider and its score are logged in the decision trail with all alternatives considered.</p> 
<p>Selectors normalize loose brief context before scoring. If the agent only knows something like "Pixar-style animated short with character consistency," the selector expands that into scorer-friendly intent and style signals instead of requiring a perfectly pre-shaped <code>task_context</code>.</p> 
<p>Selector outputs also surface the chosen provider's <code>agent_skills</code>, so the agent can immediately read the right Layer 3 provider skill before writing prompts.</p> 
<h3>Decision Audit Trail</h3> 
<p>Every major creative and technical choice — provider selection, style/playbook choice, music track, voice selection, renderer family, any fallback or downgrade — is logged with alternatives considered, confidence scores, and reasoning. The cumulative decision log persists across all stages so you can trace exactly why the output looks the way it does.</p> 
<h3>Budget Controls</h3> 
<ul> 
 <li><strong>Estimate</strong> before execution — see what it will cost</li> 
 <li><strong>Reserve</strong> budget — lock funds before the call</li> 
 <li><strong>Reconcile</strong> after — record actual spend</li> 
 <li><strong>Configurable modes</strong> — <code>observe</code> (track only), <code>warn</code> (log overruns), <code>cap</code> (hard limit)</li> 
 <li><strong>Per-action approval</strong> — pause for confirmation above a threshold (default: $0.50)</li> 
 <li><strong>Total budget cap</strong> — default $10, fully configurable</li> 
</ul> 
<p>No surprise bills. The agent tells you what it will cost before it spends.</p>

<h2>Contributing</h2> 
<p>OpenMontage is built to be extended. The two most common contributions:</p> 
<h3>Adding a New Tool</h3> 
<ol> 
 <li>Create a Python file in the appropriate <code>tools/</code> subdirectory</li> 
 <li>Inherit from <code>BaseTool</code> and implement the tool contract</li> 
 <li>The registry auto-discovers it — no manual registration needed</li> 
 <li>Add a skill file if the tool needs usage guidance</li> 
</ol> 
<h3>Adding a New Pipeline</h3> 
<ol> 
 <li>Create a YAML manifest in <code>pipeline_defs/</code></li> 
 <li>Create stage director skills in <code>skills/pipelines/&lt;your-pipeline&gt;/</code></li> 
 <li>Reference existing tools — or add new ones if needed</li> 
</ol> 
<p>See <code>docs/ARCHITECTURE.md</code> for the full technical reference, <code>docs/PROVIDERS.md</code> for the complete provider guide (setup, pricing, free tiers), and <code>AGENT_GUIDE.md</code> for the agent contract.</p>
