<h2>🎯 Getting Started</h2> 
<h3>Option 1: npx (supported hosts)</h3> 
<p>Install Scientific Agent Skills with a single command:</p> 
<pre><code class="language-bash">npx skills add K-Dense-AI/scientific-agent-skills
</code></pre> 
<p>This is a common standards-based installer for supported Agent Skills hosts, including current versions of <strong>Claude Code</strong>, <strong>Claude Cowork</strong>, <strong>Codex</strong>, <strong>Gemini CLI</strong>, <strong>Google Antigravity</strong>, and <strong>Cursor</strong>. Confirm installation paths and optional metadata behavior in your host's current documentation.</p> 
<h3>Option 2: GitHub CLI (<code>gh skill</code>)</h3> 
<p>If you use the <a href="https://cli.github.com/">GitHub CLI</a> (v2.90.0+), you can install skills with <a href="https://github.blog/changelog/2026-04-16-manage-agent-skills-with-github-cli/"><code>gh skill</code></a>:</p> 
<pre><code class="language-bash"># Browse and install interactively
gh skill install K-Dense-AI/scientific-agent-skills

# Install a specific skill directly
gh skill install K-Dense-AI/scientific-agent-skills scanpy

# Target a specific agent host
gh skill install K-Dense-AI/scientific-agent-skills --agent cursor
gh skill install K-Dense-AI/scientific-agent-skills --agent claude-code
gh skill install K-Dense-AI/scientific-agent-skills --agent codex
gh skill install K-Dense-AI/scientific-agent-skills --agent gemini
</code></pre> 
<p><code>gh skill</code> automatically installs to the correct directory for your agent host and records provenance metadata for supply chain integrity.</p> 
<h4>Version pinning</h4> 
<p>Pin to a specific release tag or commit SHA for reproducible installs:</p> 
<pre><code class="language-bash"># Pin to a release tag
gh skill install K-Dense-AI/scientific-agent-skills --pin v2.64.0

# Pin to a commit SHA
gh skill install K-Dense-AI/scientific-agent-skills --pin abc123def
</code></pre> 
<h4>Keeping skills up to date</h4> 
<pre><code class="language-bash"># Check for updates interactively
gh skill update

# Update all installed skills
gh skill update --all
</code></pre> 
<h3>Option 3: Agent Plugins (Cursor, Codex, and other plugin clients)</h3> 
<p>This repository is a valid <a href="https://agent-plugins.org/">Agent Plugins</a> 1.0.0 package: root <a href="https://raw.githubusercontent.com/K-Dense-AI/scientific-agent-skills/main/plugin.json"><code>plugin.json</code></a> plus Agent Skills under <code>skills/</code>. Clients that support the standard discover every immediate child of <code>skills/</code> that contains a <code>SKILL.md</code>.</p> 
<p><strong>Cursor</strong> — symlink or copy the repo into the local plugins directory, then reload:</p> 
<pre><code class="language-bash">mkdir -p ~/.cursor/plugins/local
ln -s "$(pwd)" ~/.cursor/plugins/local/scientific-agent-skills
</code></pre> 
<p>Restart Cursor or run <strong>Developer: Reload Window</strong>, then confirm the plugin and its skills appear under <strong>Customize</strong>. See <a href="https://cursor.com/docs/plugins">Cursor plugins</a>.</p> 
<p><strong>Codex</strong> — install from a local checkout (confirm the current CLI flag names in Codex docs):</p> 
<pre><code class="language-bash">codex plugins install .
</code></pre> 
<p>Compatible clients (Cursor, Codex, GitHub Copilot, VS Code, Kiro, and others listed at <a href="https://agent-plugins.org/compatible-clients">agent-plugins.org</a>) share the same package layout; installation UX stays client-specific.</p> 
<h3>Other Agent Skills hosts (OpenClaw, NemoClaw, Pi, Hermes, …)</h3> 
<p>Agent hosts differ in install paths, discovery settings, and support for optional frontmatter fields. <code>npx skills add</code> (Option 1) commonly installs into the <code>~/.agents/skills/</code> convention, with project-scoped installs under <code>.agents/skills/</code>; confirm both paths against your host's current documentation. To install manually on a host configured to scan one of those locations:</p> 
<pre><code class="language-bash">git clone https://github.com/K-Dense-AI/scientific-agent-skills.git ~/.agents/skills/scientific-agent-skills   # user-level
git clone https://github.com/K-Dense-AI/scientific-agent-skills.git .agents/skills/scientific-agent-skills      # project-level
</code></pre> 
<p>For Hermes versions that support skill taps, add the repository as a tap:</p> 
<pre><code class="language-bash">hermes skills tap add K-Dense-AI/scientific-agent-skills
</code></pre> 
<p>Every <code>SKILL.md</code> has YAML frontmatter, but legacy and community skills vary in <code>metadata</code> formatting (block or flow style) and optional extension fields. Repository updates must keep <code>metadata.version</code> as a quoted numeric string and pass canonical <code>skills-ref validate ./skills/&lt;skill-name&gt;</code> checks. Hosts may interpret optional metadata and credential prompts differently, so verify behavior on the target host. Because 161 skills add up to a lot of standing context, consider installing a topical subset rather than the whole collection.</p> 
<blockquote> 
 <p><strong>NemoClaw note:</strong> NemoClaw runs agents inside NVIDIA OpenShell with default-deny outbound networking. Skills are discovered and loaded normally, but any skill that needs the network — package installs via <code>uv</code>, or API calls (Exa, Parallel, Benchling, NCBI, Materials Project, …) — only works once the operator pre-approves the relevant domains in the OpenShell TUI.</p> 
</blockquote> 
<p><strong>That's it!</strong> A compatible host can discover the skills from its configured paths and use them when relevant. You can also invoke any skill manually by mentioning the skill name in your prompt.</p>

<h2>⚠️ Security Disclaimer</h2> 
<blockquote> 
 <p><strong>Skills can execute code and influence your coding agent's behavior. Review what you install.</strong></p> 
</blockquote> 
<p>Agent Skills are powerful — they can instruct your AI agent to run arbitrary code, install packages, make network requests, and modify files on your system. A malicious or poorly written skill has the potential to steer your coding agent into harmful behavior.</p> 
<p>We take security seriously. All contributions go through a review process, and we run LLM-based security scans (via <a href="https://github.com/cisco-ai-defense/skill-scanner">Cisco AI Defense Skill Scanner</a>) on every skill in this repository. However, as a small team with a growing number of community contributions, we cannot guarantee that every skill has been exhaustively reviewed for all possible risks.</p> 
<p><strong>It is ultimately your responsibility to review the skills you install and decide which ones to trust.</strong></p> 
<p>We recommend the following:</p> 
<ul> 
 <li><strong>Do not install everything at once.</strong> Only install the skills you actually need for your work.  <li><strong>Read the <code>SKILL.md</code> before installing.</strong> Each skill's documentation describes what it does, what packages it uses, and what external services it connects to. If something looks suspicious, don't install it.</li>

<h3>Testing</h3> 
<p>Every skill that ships <code>scripts/</code> must have a test suite under <code>tests/&lt;skill-name&gt;/</code> and an entry in <code>tests/skill-requirements.toml</code>. This is enforced — <code>tests/_meta</code> fails a pull request that adds bundled tooling without one, and it also runs a repo-wide structural contract over all skills (frontmatter conformance, <code>SKILL.md</code> length, local links resolving, scripts parsing, no shipped bytecode, no hardcoded local paths, <code>--help</code> behavior).</p> 
<pre><code class="language-bash"># Structural contract and coverage guard — seconds, no scientific packages needed
uv run python -m pytest tests/_meta -q

# One skill's suite
uv run --with pytest python -m pytest tests/&lt;skill-name&gt; -q

# Every suite, each in its own throwaway environment
uv run python tests/run_all.py --isolated
</code></pre> 
<p>The <a href="https://github.com/K-Dense-AI/scientific-agent-skills/actions/workflows/skill-tests.yml">Skill Tests</a> workflow runs the contract plus the standard-library-only suites on every pull request; the full <code>--isolated</code> sweep builds ~100 environments and is run locally or on a schedule.</p>

<p><strong>Q: Is this free to use?</strong><br /> A: Yes! This repository is MIT licensed. However, each individual skill has its own license specified in the <code>license</code> metadata field within its <code>SKILL.md</code> file—be sure to review and comply with those terms.</p>

However, individual skills may have different licenses—check the <code>license</code> field in each skill's <code>SKILL.md</code> file to ensure compliance with your intended use.</p> 
<p><strong>Q: Do all skills have the same license?</strong><br /> A: No. Each skill has its own license specified in the <code>license</code> metadata field within its <code>SKILL.md</code> file. These licenses may differ from the repository's MIT License. Users are responsible for reviewing and adhering to the license terms of each individual skill they use.</p> 
<p><strong>Q: How often is this updated?</strong><br /> A: We regularly update skills to reflect the latest versions of packages and APIs. Major updates are announced in release notes.</p> 
<p><strong>Q: Can I use this with other AI models?</strong><br /> A: The core <code>SKILL.md</code> format follows the open <a href="https://agentskills.io/">Agent Skills</a> standard. <h2>📖 Citation</h2> 
<p>If you use Scientific Agent Skills in your research or project, please cite the overall collection and, when relevant, the individual skill or skills that materially supported your work.</p> 
<p>The collection citation helps others find the repository, understand the broader skill ecosystem used in your workflow, and credit the maintenance effort behind Scientific Agent Skills. Individual skill citations give more precise credit for the specific package, database, or workflow guidance your agent used.</p> 
<p>Recommended practice:</p> 
<ul> 
 <li>Always cite <strong>Scientific Agent Skills</strong> using one of the formats below.</li> 
 <li>Also cite each individual skill that directly contributed to your analysis, code, figures, reports, or research workflow.</li> 
 <li>If a skill wraps or documents an external package, database, or platform, cite that upstream project too when your field's norms require it.</li> 
</ul>
