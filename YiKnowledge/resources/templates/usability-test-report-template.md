# 可用性测试报告模板

## 使用场景

可用性测试后写报告。参与者 5-8 人（Nielsen 经验：5 人可发现 80% 问题）。

## 模板正文

```markdown
# {产品/功能} 可用性测试报告

**测试日期**：YYYY-MM-DD
**测试负责人**：{name}
**参与者**：{N} 人（特征：{行业 / 角色 / 经验}）
**测试版本**：{版本 / 原型链接}
**测试方法**：远程 / 现场； moderated / unmoderated

## 1. 测试目标

- 验证假设：{列表}
- 关键任务：{3-5 个任务}
- 成功标准：{每任务的可接受完成率 / 时长}

## 2. 任务清单

| # | 任务 | 期望路径 | 成功标准 |
|---|---|---|---|
| 1 | {task description} | {expected steps} | 80% 完成率 / < 2 分钟 |
| 2 | ... | ... | ... |

## 3. 关键指标

| 任务 | 完成率 | 平均时长 | 错误率 | 满意度（1-7） |
|---|---|---|---|---|
| 1 | X% | Y 秒 | Z% | M |
| 2 | ... | ... | ... | ... |

## 4. 关键发现

### 发现 1：{标题}

- 现象：{观察到的}
- 影响：{对用户 / 业务}
- 严重度：1-5（5 = 阻塞）
- 频率：{N/8 参与者遇到}
- 推荐：{修复建议}

### 发现 2：...

## 5. 按参与者细分

| 参与者 | 任务 1 | 任务 2 | ... | 备注 |
|---|---|---|---|---|
| P1 | ✓ 1m | ✗ 困惑于按钮 | ... | {quote} |
| P2 | ... | ... | ... | ... |

## 6. 用户原话

> "我以为这个按钮是提交，结果它把我带走了"
> "整个流程很顺，但这里我犹豫了 10 秒"
> — P1, 任务 2

## 7. 改进建议（按优先级）

| 优先级 | 建议 | 责任人 | 截止日 |
|---|---|---|---|
| P0 | {修复阻塞问题} | {name} | YYYY-MM-DD |
| P1 | {影响多人} | ... | ... |
| P2 | {优化体验} | ... | ... |

## 8. 与设计假设对比

| 假设 | 验证结果 | 备注 |
|---|---|---|
| "用户会先看左栏" | 否，多数先看中栏 | {quote} |
| ... | ... | ... |

## 9. 后续追踪

- 改进实施后做小规模回测（3-5 人）
- 上线后埋点监控关键任务完成率

## 附：原始数据

- 任务录屏链接
- 笔记
- 访谈转录
```

## 填写规范

| 字段 | 必填 | 规范 |
|---|---|---|
| 测试目标 | 是 | 可衡量 |
| 任务清单 | 是 | 3-5 个核心任务 |
| 关键指标 | 是 | 完成率 / 时长 / 错误率 / 满意度 |
| 关键发现 | 是 | 含严重度 + 频率 |
| 改进建议 | 是 | 优先级 + 责任人 + 截止 |
| 用户原话 | 推荐 | 增强说服力 |

## 严重度分级

| 级 | 含义 | 处置 |
|---|---|---|
| 5 | 阻塞任务完成 | 立刻修 |
| 4 | 多数用户受阻 | 本迭代修 |
| 3 | 部分用户受阻 | 下迭代修 |
| 2 | 小问题 | 可延后 |
| 1 | 表面问题 | 可选 |

## 反模式

- 只列问题不给建议 → 必给改进建议
- 没有用户原话 → 必引述
- 完成率好看但埋点看不到 → 加埋点对照
- 改进无追踪 → 必有责任人与截止
- 一次测试定终身 → 改进后回测
