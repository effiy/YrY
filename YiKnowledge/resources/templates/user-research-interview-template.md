# 用研访谈大纲模板

## 使用场景

产品发现阶段、需求调研、可用性测试前访谈。半结构化访谈，有提纲但允许展开。

## 模板正文

```markdown
# 用户访谈：{研究主题}

**日期**：YYYY-MM-DD
**访谈人**：{name}
**受访者**：{角色 / 行业 / 经验}
**访谈时长**：45-60 分钟
**研究目标**：{1-2 句话}

## 1. 暖场与同意（5 分钟）

- 介绍研究目的与录音 / 笔记用途
- 取得知情同意
- 简单自我介绍 + 让受访者自我介绍

## 2. 背景了解（5-10 分钟）

- 你在公司的角色与日常职责？
- 与 {产品 / 场景} 的接触频率？
- 最近一次使用 / 处理 {场景} 是什么时候？

## 3. 当前工作流（10-15 分钟）

核心问题，半结构化追问。用 5-Why 或 critical incident 法：

- 请描述上次 {场景} 的完整过程
- 在哪个环节最耗时间？
- 在哪个环节最容易出错？
- 哪个环节最让人沮丧？
- 你和谁协作？信息怎么流转？
- 用了什么工具？为什么用这个？

## 4. 痛点与期望（10-15 分钟）

- 如果可以改一件事，你会改什么？
- 现在怎么解决这个问题的？
- 这个问题每年带来多少成本 / 损失？
- 有没有想过换方案？为什么没换？

## 5. 解决方案反馈（10 分钟，可选）

展示原型 / 草图：

- 你第一眼看到什么？
- 你觉得这是给谁用的？
- 你会怎么用？请走一遍
- 哪里你觉得不需要 / 多余？
- 哪里你最想用？
- 价格你会预期多少？

## 6. 收尾（5 分钟）

- 还有什么我没问但你想到的？
- 你愿意后续再聊吗？
- 推荐其他访谈对象？

## 访谈后立即记录

- 受访者特征标签（行业、角色、使用频率）
- 关键洞察（3-5 条）
- 与假设对照的发现
- 待验证的下一步行动
```

## 填写规范

| 字段 | 必填 | 规范 |
|---|---|---|
| 研究目标 | 是 | 1-2 句话，可衡量 |
| 受访者背景 | 是 | 角色 + 行业 + 经验 |
| 当前工作流 | 是 | 用 critical incident |
| 痛点与期望 | 是 | 不引导、不暗示 |
| 解决方案反馈 | 可选 | 仅在原型阶段 |

## 访谈原则

1. **不引导**：问"你觉得怎么样"而不是"你觉得这个功能好不好"
2. **不评判**：受访者说啥都记，不打断不辩论
3. **不解释**：受访者问"这个怎么用" → 反问"你觉得应该怎么用"
4. **5 秒沉默**：问完等 5 秒，受访者会主动补充
5. **具体不抽象**：问"上次具体怎么做的"而非"通常怎么做"
6. **现状而非未来**：用户对未来的预测不准，对现状的描述准
7. **样本 ≥15**：定性访谈至少 15 人覆盖细分

## 记录与编码

- 全程录音（知情同意后）
- 立即写笔记（不靠记忆）
- 编码：把访谈内容按主题编码，找 pattern
- 模式识别：3+ 受访者提到同一痛点 = 信号

## 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 引导提问 | "你不喜欢 X 吗" | 中性问"你如何评价 X" |
| 抽象问题 | "通常你怎么做" | "上次具体怎么做" |
| 状态汇报 | 让用户讲流程 | 让用户演示 |
| 样本不足 | 访谈 3 人下定论 | ≥15 |
| 不记录 | 靠事后回忆 | 录音 + 立即笔记 |
