# 复盘模板

## 使用场景

迭代结束、项目里程碑、事件后复盘。无指责式，关注流程与系统。

## 模板正文

```markdown
# {项目/迭代/事件} 复盘

**日期**：YYYY-MM-DD
**参与者**：{列表}
**复盘类型**：迭代复盘 / 项目复盘 / 事件复盘
**复盘周期**：YYYY-MM-DD ~ YYYY-MM-DD

## 1. 期望 vs 实际

| 维度 | 计划 | 实际 | 差异 |
|---|---|---|---|
| 目标 | {OKR / 关键结果} | {实际完成} | +X% / -X% |
| 工期 | {计划日期} | {实际日期} | +X 天 |
| 资源 | {预算人力} | {实际人力} | +/- |

## 2. 做得好的（Keep）

- {3-5 条，含数据与原因}
- 例：BRD 上线后首日幻觉率 2%，源于评测集 + faithfulness 后处理双保险
- ...

## 3. 做得不好的（Problem）

- {3-5 条，含影响与原因}
- 例：多语言术语漂移率 15%，源于术语表覆盖率不足
- ...

## 4. 根因分析

对每个"做得不好"项做 5-Why：

### Problem 1：{描述}

- Why 1：{原因}
- Why 2：{更深原因}
- Why 3：{更深原因}
- Why 4：{更深原因}
- Why 5：{根本原因}

**根本原因**：{一句话}

## 5. 改进措施（Action）

| # | 改进项 | 责任人 | 截止日 | 验证方式 |
|---|---|---|---|---|
| 1 | {action} | {name} | YYYY-MM-DD | {metric / artifact} |
| 2 | ... | ... | ... | ... |

## 6. 下周期承诺

- {3-5 条，可量化}
- ...

## 7. 复盘结论

- {1-2 句话总结}

## 附：数据与证据

- {链接到指标仪表盘、PR 列表、用户反馈}
```

## 填写规范

| 字段 | 必填 | 规范 |
|---|---|---|
| 日期 | 是 | ISO 格式 |
| 期望 vs 实际 | 是 | 量化 |
| 做得好 / 不好 | 是 | 各 3-5 条 |
| 根因分析 | 是 | 至少 1 项 5-Why |
| 改进措施 | 是 | 责任人 + 截止 + 验证 |
| 下周期承诺 | 是 | 3-5 条 |
| 数据证据 | 推荐 | 链接 |

## 反模式

- 把复盘写成表彰会 → 强制必写不足
- 改进措施无责任人 → 必填
- 改进不跟踪 → 下迭代开始必查上迭代改进完成情况
- 指责个人 → 关注流程与系统
