## 方案概述

说明本方案的目的、适用范围、背景、整体目标和意义。简要介绍业务场景与预期收益，让阅读者在不深入其他章节的情况下也能了解核心价值。可贴需求 PRD 链接。

## 详细设计

### 接口设计

| 序号 | 系统 | 市场 | 接口描述 | 链接 | 新增/更新 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 用户系统 | 区域 A | 用户查询 | 链接 | 更新 | 新增字段 xxx |

规范：
1. 统一使用 API 文档平台进行接口管理。
2. 枚举类字段必须列出所有类型定义；若不同枚举导致传参/返回参有差异，需说明。
3. 非必填字段在不同业务场景的必填性需备注清楚。
4. 强依赖前置接口的字段需标注来源（例：登录接口的验证码来源于验证码发送接口）。
5. 列出异常返回的错误码及含义。

### 时序设计

绘制关键业务流程的时序图，展示调用链路、时序顺序、并发点、同步/异步调用方式。说明性能瓶颈与优化点（工程内部类之间的时序图）。

要求：
1. 时序图需包含所有业务分支与异常返回，便于测试覆盖。
2. 批量数据需说明是循环处理还是单次批量，并说明对性能的影响。
3. 需求更新时，时序图中修改部分标红。
4. 有歧义的复杂业务逻辑、算法等需备注说明。

### 一致性设计（可选）

说明分布式事务方案（SAGA / 补偿 / 最终一致性）、补偿事件格式和触发条件，给出失败场景与恢复步骤。

### 异步 / 事件设计（可选）

列出事件清单、每个事件的 JSON Schema、topic 名称、版本策略、消费语义（至少一次 / 至多一次）、重试与 DLQ 策略与监控指标。

## 数据设计

### 数据模型 / ER 图

提供 ER 图，标注主键 / 外键 / 关系类型及数据所有者。无需标注所有字段，有核心字段、表述清楚表关系即可。整个服务的数据模型链接单独维护。

### 数据模型变更

新增/修改/删除的数据表 DDL，含字段名、类型、长度、默认值、索引、约束。

```sql
CREATE TABLE IF NOT EXISTS `account_encrypt_field_data` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `create_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`)
) ENGINE=InnoDB COMMENT='账号加密字段原始值';

-- 1. 不要在 DDL 中定义 CHARSET=utf8mb4 和 COLLATE=utf8mb4_0900_ai_ci，由 DBA 在整库层面定义
-- 2. 表字段和表名必须添加 COMMENT
```

### 存储方案

分库分表 / 分区策略，索引设计。选型：MySQL / Redis / ES / 大数据。

### 数据字典

为涉及的表字段建立数据字典，明确字段含义、取值范围、单位、业务说明。

### 数据迁移方案

说明迁移策略、脚本、执行步骤、回滚方案。
1. 迁移方式：DRS 同步 / SQL 脚本 / 接口/定时任务；实时迁移 / 停机迁移。
2. 执行时间：上线前还是上线后，影响范围。

## 非功能设计

### 高可用与容灾要求

### 数据埋点

统计 PV/UV 等数据埋点。

## 风险与限制条件

列出可能的风险（技术 / 业务 / 资源）与限制条件，给出应对措施。

1. **业务风险**：业务不明确项，可能影响提测的点。
2. **资源风险**：工作排期，正常排期需要的工作量与实际可行工作量是否一致。
3. **技术风险**：
   - 涉及线程上下文，评估子线程是否依赖使用。
   - 是否高频调用接口，定时任务等是否会大量消耗内存/CPU。
   - 涉及外部调用的，评估调用失败的影响和补偿方案。
   - 技术方案不确定，或需要调研新技术的。
