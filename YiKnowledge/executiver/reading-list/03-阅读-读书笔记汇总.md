# 读书笔记模板

> **作为**高管，**我想要**用统一结构记录读书笔记，**以便**可执行的洞察能系统地蒸馏到知识库中。
>
> **核心理念**：读书笔记不是摘要。摘要是写给自己的（增强记忆），笔记是写给团队和未来自己的（可检索、可操作、可复用）。

## 适用场景

- 精读完一本管理/战略/技术/产品类书籍后
- 读完一篇重要的行业报告或长文
- 参加完高管培训课程后
- 听完关键播客或讲座后

## 字段说明

| 字段 | 是否必填 | 填写指引 |
|---|---|---|
| 作者 | 是 | 全名，重要作者可附上 Wikipedia 或主页链接 |
| 来源 | 是 | 文章填 URL，书籍填 ISBN |
| 阅读日期 | 是 | 完成笔记的日期 |
| 评分 | 是 | 1-5 分制，主观价值评估 |
| 标签 | 是 | 至少包含 [管理/战略/技术/产品] 之一 + 具体主题 |
| 核心观点 | 是 | 一句话，不超过 50 字 |
| 关键章节摘要 | 是 | 表格格式便于扫读，每章必须有精华摘录 |
| 可操作收获 | 是 | 必须具体且与当前团队上下文相关 |
| 精华摘录 | 否 | 只摘录真正有力量或颠覆认知的句子 |
| 蒸馏目标 | 是 | 追踪每个见解蒸馏到知识库的位置 |
| 关联阅读 | 否 | 推荐与本书观点互补或延伸的阅读材料 |

## 使用建议

- **不要拖延蒸馏**：读完就确定每个见解的归属知识叶，不要等"有空再说"。拖延一周以上的蒸馏有 80% 的概率永远不会完成。
- **以行动为导向**：笔记必须产出至少一个本周可执行的行动项。读完书但没有行为改变 = 白读。
- **季度回顾**：每季度浏览过去的读书笔记，发现跨书目的模式。多本书指向同一观点 = 高置信度洞察。
- **无产出则质疑**：如果一本书读完没有任何可执行收获，思考是选书失败还是阅读深度不够。连续三本无产出，重新审视阅读策略。
- **诚实评分**：1-5 分的标准不是"这本书好不好"，而是"这本书对我当前的工作有多大价值"。经典著作如果在错误的时间读，也可以评低分。

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| **写书摘而不是笔记** | 摘要整本书，没有为相关性做过滤 | 只记录与当前团队和目标相关的内容 |
| **无蒸馏** | 写了笔记但从未将见解链接到具体知识叶 | 阅读时就确定蒸馏目标；知识叶应引用读书笔记作为来源 |
| **空洞行动** | "多想想这个"而不是具体的下一步 | 行动必须包含：做什么、谁做、截止时间 |
| **过度摘要** | 逐章抄写而不是提取核心论点 | 每章只用 1-2 句话概括核心论点，不要复述内容 |
| **评分通货膨胀** | 所有书都评 4-5 星 | 诚实评价：这本书对你当前工作的实际价值是多少？ |
| **忽视反面观点** | 只摘录你认同的观点 | 有意识地记录反对或质疑的部分——它们往往更有价值 |

### 跨书洞察

读过的 5 本书中反复出现的模式（高置信度洞察）：

1. **管理杠杆 > 个人产出**：《高产出管理》+《创业维艰》+《加速》共同指向——管理者（和团队）的效能来自于系统能力而非个人英雄主义
2. **战略 = 诊断 + 取舍 + 连贯行动**：《好战略坏战略》+《创业维艰》共同指向——好战略的三个要素，CEO 最难的时刻是坚持取舍
3. **组织设计决定系统设计**：《加速》+《团队拓扑》共同指向——松耦合架构 + 流对齐团队 = 高效能组织
4. **数据驱动的改进 > 直觉驱动的管理**：《加速》+《高产出管理》共同指向——先测量再改进，但不要让测量变成目标
