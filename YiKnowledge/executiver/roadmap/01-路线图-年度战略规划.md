# 年度战略规划

> **作为**高管，**我想要**运行结构化的年度战略规划流程，**以便**组织就下一年度的优先级、资源分配和成功指标达成一致。
>
> **核心原则**：规划不是预测未来，而是让今天的决策为明天的成果做准备。好的规划是"在不确定中建立确定"——确定方向、确定优先级、确定退路。

## 定义

年度战略规划是一个四阶段流程，将战略转化为可执行的计划，包含明确的优先级、资源分配和可衡量的成果。

```
上年度 Q3-Q4                     本年度 Q1-Q4
─────────────────────────────────────────────────────
阶段 1: 战略评审 ──►
阶段 2: 自下而上输入 ──►
阶段 3: 综合与辩论 ──►
阶段 4: 承诺与级联 ──►  执行与季度评审
```

## 适用场景

- 年度规划周期（通常为 Q3–Q4 规划下一年度）
- 重大战略转向需要全面重规划
- 并购后或整合后的统一规划
- 新高管团队建立第一个联合计划
- 融资后需要向投资人呈现结构化计划

## 实践建议

### 规划前的准备工作

在启动阶段 1 之前，确保以下就绪：
- 当年截至当前的业绩数据（OKR 完成情况、收入、客户指标）
- 上年度规划的得失复盘
- 至少一份外部环境扫描（行业报告、竞品动态）
- 核心团队的日程锁定（阶段 1-4 合计需要 12-17 周的持续投入）

### YrY 特定考量

- **三项目协同**：YiVad、YiAi、YiPet 的发展节奏不同，年度规划需分别评估但统一优先级排序
- **AI 行业速度**：AI 领域变化极快，年度规划需要额外的弹性机制（如 10-20% 的未分配资源用于应对突发机会）
- **知识库建设**：YiKnowledge 本身也是战略资产，年度规划应考虑知识库建设的投入

## 设计步骤

### 阶段 1：战略评审（4–6 周）

**目标**：在做出资源配置决策之前，就战略背景达成一致。

| 步骤 | 活动 | 产出 | 负责人 |
|---|---|---|---|
| 1.1 | 评审当前战略文档 | 更新的[战略评估](../strategy/08-战略-产品战略框架.md) | 高管 |
| 1.2 | 评估外部环境 | [波特五力](../strategy/07-战略-波特五力模型.md) + [蓝海战略](../strategy/01-战略-蓝海战略.md) 刷新 | 高管 |
| 1.3 | 评估内部能力 | [VRIO](../strategy/12-战略-VRIO框架.md) + [SWOT](../strategy/10-战略-SWOT分析.md) 刷新 | 技术负责人 |
| 1.4 | 评审当年度业绩 | 实际 vs 计划；哪里做对了，哪里需要改变 | 全体 |
| 1.5 | 确定下年度战略支柱 | 3–5 个战略支柱，每个附 1 段描述 | 高管 |

**战略支柱的要求**：
- 每个支柱必须是定性且有抱负的（如"成为最受信赖的 AI 平台"而非"营收增长 30%"）
- 每个支柱需要明确的范围边界（包含什么，不包含什么）
- 支柱之间不应重叠超过 20%

**门径检查**：领导团队在进入阶段 2 前必须签署战略支柱。

### 阶段 2：自下而上输入（3–4 周）

**目标**：在自上而下分配之前收集团队提案和数据。

| 步骤 | 活动 | 产出 | 负责人 |
|---|---|---|---|
| 2.1 | 团队提交项目提案 | 项目提案含影响估算、资源需求 | 技术负责人 |
| 2.2 | 产品提交路线图草稿 | [Now/Next/Later](../strategy/06-战略-Now-Next-Later路线图.md) 对齐战略支柱 | 产品负责人 |
| 2.3 | 工程提交容量估算 | 下年度可用人周数，按团队划分 | 技术负责人 |
| 2.4 | 财务提供预算框架 | 收入预测、成本目标、投资容量 | 财务 |

**防止的反模式**：不允许团队提交愿望清单。每个项目提案必须映射到至少一个战略支柱。

**提案模板**（团队提交时使用）：

| 字段 | 说明 |
|---|---|
| 项目名称 | 简洁且描述性 |
| 所属战略支柱 | 一对一映射 |
| 预期影响 | 量化的业务或用户指标变化 |
| 资源需求 | 需要多少人、多长时间、什么技能 |
| 置信度 | 影响估算的确定程度（高/中/低） |
| 依赖项 | 依赖哪些其他项目或外部条件 |
| 不做的后果 | 如果这个项目不启动，会发生什么 |

### 阶段 3：综合与辩论（3–4 周）

**目标**：将自上而下的战略与自下而上的提案协调为一个连贯计划。

| 步骤 | 活动 | 产出 | 负责人 |
|---|---|---|---|
| 3.1 | 将所有项目映射到战略支柱 | 项目-支柱映射；识别无映射项目和空白 | 高管 |
| 3.2 | 使用评分框架排优先级 | 排序后的项目列表 | 全体 |
| 3.3 | 运行资源分配情景 | 2–3 个情景（乐观、基准、保守） | 高管 + 财务 |
| 3.4 | 辩论并解决冲突 | 引导式领导会议；决议文档化 | 高管 |
| 3.5 | 产出计划草案 | 年度计划文档草案 | 高管 |

**优先级评分框架**：

| 标准 | 权重 | 描述 | 评分指引 |
|---|---|---|---|
| 战略对齐度 | 30% | 直接支持战略支柱的程度 | 1-5 分：1=间接相关，5=直接落地支柱 |
| 预期影响 | 25% | 收入、成本节约或战略地位改善 | 量化影响并转换为 1-5 分 |
| 置信度 | 15% | 影响估算的确定程度 | 1=纯猜测，5=有历史数据支撑 |
| 可行性 | 15% | 是否具备执行的能力和容量 | 1=需要外部招聘，5=团队可立刻开工 |
| 紧迫性 | 15% | 是否有时间敏感的窗口或截止 | 1=可在未来 2 年任意时间，5=错过 Q1 窗口损失巨大 |

**辩论规则**：
- 用数据开头，不是观点
- 辩论决策，不辩论人
- 不抛弃低优先级项目——明确记录"做了什么、为什么不做、何时重评"
- 每个决议必须有一名负责人

### 阶段 4：承诺与级联（2–3 周）

**目标**：定稿计划并将其级联为团队级 OKR 和预算。

| 步骤 | 活动 | 产出 | 负责人 |
|---|---|---|---|
| 4.1 | 最终领导评审和批准 | 批准的年度计划 | 高管 |
| 4.2 | 级联到团队级 OKR | [组织 OKR](./03-路线图-组织OKR追踪.md) → 团队 OKR | 技术负责人 |
| 4.3 | 分配人员编制和预算 | [编制计划](./02-路线图-人员预算规划.md) | 高管 + 财务 |
| 4.4 | 向全组织沟通 | 全员大会演讲、书面计划、常见问答 | 高管 |
| 4.5 | 设定评审节奏 | 全年 [QBR 日程](./04-路线图-季度业务回顾.md) | 高管 |

**沟通清单**：
- [ ] 全员大会演讲（10-15 分钟核心信息）
- [ ] 书面计划（5-10 页，供细读）
- [ ] 一页摘要（供忙碌的人快速了解）
- [ ] 常见问答（预判至少 10 个问题并回答）
- [ ] 团队 OKR 模板（各团队填写自己的 OKR）

## 核心产出

| 交付物 | 格式 | 受众 | 关键要求 |
|---|---|---|---|
| 年度计划文档 | 5–10 页文档 | 领导层、董事会 | 包含战略支柱、优先项目、资源配置、成功指标 |
| 战略支柱 | 单页 | 全公司 | 每个支柱附一句话解释和边界定义 |
| 优先项目列表 | 电子表格 | 领导层、团队 | 按评分排序，含负责人和时间线 |
| 资源配置 | 编制 + 预算电子表格 | 财务、HR、领导层 | 四桶分配模型输出 |
| 级联 OKR | [OKR 追踪](./03-路线图-组织OKR追踪.md) | 全公司 | 组织 OKR → 团队 OKR 的映射清晰可见 |
| 沟通幻灯片 | 演讲文稿 | 全员大会 | 不超过 15 张幻灯片 |

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 无战略先规划 | 项目按谁喊得响来排优先级 | 阶段 1 不可跳过；无战略 = 无规划 |
| 电子表格驱动规划 | 数字成为目标而不是成果 | 先从战略支柱开始，再分配资源 |
| 无取舍讨论 | 每件事都是"第一优先级" | 阶段 3 辩论必须明确拒绝低优先级项目 |
| 年度计划当作固定合同 | 环境变化，计划必须适应 | 通过 [QBR](./04-路线图-季度业务回顾.md) 做季度调整 |
| 跳过自下而上输入 | 领导层计划脱离一线现实 | 阶段 2 必须执行；团队知道什么是可行的 |
| 规划完成后束之高阁 | 再也没有人看 | QBR 时对照计划评审实际；偏差必须解释 |
