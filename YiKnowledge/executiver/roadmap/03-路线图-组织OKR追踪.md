# 组织级 OKR 追踪

> **作为**高管，**我想要**定义、级联和追踪全组织的 OKR，**以便**每个人都对齐于重要事项以及如何衡量成功。
>
> **核心原则**：OKR 的首要目标是**对齐和抱负**，不是绩效考核。当 OKR 被用于决定奖金时，人们会降低目标以确保达标——这完全违背了 OKR 的初衷。

## 定义

OKR（目标与关键结果）是一个目标设定框架：

- **目标 (Objective)**：定性的、鼓舞人心的目标。回答"我们想去哪里？"
- **关键结果 (Key Results)**：2–5 个量化衡量指标。回答"我们如何知道正在到达？"

```
目标: 成为企业合规领域最受信赖的 AI 平台

  KR1: Q2 前取得 SOC 2 Type II 认证
  KR2: 0 起涉及客户数据暴露的严重安全事件
  KR3: 企业客户 ($100K+ ARR) NPS > 60
  KR4: 发布 12 篇合规相关内容；产生 500 个合格线索
```

### OKR 与 KPI 的区别

| 维度 | OKR | KPI |
|---|---|---|
| 目标 | 改变某事（向上挑战） | 维持某事（健康监控） |
| 时间 | 有明确周期（通常为季度） | 持续进行 |
| 抱负 | 有意的延展目标（70% 置信度） | 基线达标（100% 置信度） |
| 变化 | 每季度变化 | 相对稳定 |
| 用途 | 驱动组织向新方向前进 | 监控业务健康状况 |

## 适用场景

- 将[年度计划](./01-路线图-年度战略规划.md)转化为可衡量目标
- [QBR](./04-路线图-季度业务回顾.md)期间的季度 OKR 设定
- 多团队围绕共享成果对齐
- 董事会/投资人汇报公司业绩
- 早期识别团队目标冲突时的偏差

## 设计步骤

### 步骤 1：设定组织级 OKR（自上而下）

从[年度计划](./01-路线图-年度战略规划.md)中的公司战略支柱出发。每个支柱定义 1 个目标，附带 2–5 个关键结果。

**好目标 (Objective) 的规则**：
- 定性且有抱负（不是"达成 $X 收入"）
- 行动导向（以动词开头）
- 有时间限制（季度周期）
- 可记忆（员工应该能复述出来）
- 范围清晰（包含什么，不包含什么）

**好关键结果 (KR) 的规则**：
- 可衡量，有明确的数值和基线
- 聚焦成果而非产出
- 可实现但有抱负（目标约 70% 置信度）
- 2–5 个 KR 每个目标（3 个是甜点）
- 每个 KR 有明确的数据来源和衡量方式

| 坏的 KR | 好的 KR | 问题 |
|---|---|---|
| "上线新的新手引导"（产出） | "新用户首次价值时间从 3 天降到 1 小时"（成果） | 船出功能不等于产出价值 |
| "提升性能"（模糊） | "p95 API 延迟 < 200ms（当前 450ms）"（具体） | 没有基准线和目标数值 |
| "10 个新客户"（过于安全） | "25 个新企业客户"（有抱负） | 太容易达标失去了延展意义 |
| "用户满意度提升"（无法衡量） | "NPS 从 40 提升到 55+"（可衡量） | 没有定义如何衡量 |
| "完成 AI 功能开发"（活动） | "AI 功能使客服效率提升 30%"（成果） | 开发完成不代表产生了影响 |

### 步骤 2：级联到团队（自下而上对齐）

每个团队定义与组织 OKR 对齐的团队 OKR：

```
组织 OKR (3-5 个目标)
  ├── 团队 A OKR (2-3 个目标)
  ├── 团队 B OKR (2-3 个目标)
  └── 团队 C OKR (2-3 个目标)
```

**对齐而非逐层分解**：团队 OKR 不需要 1:1 映射到组织 OKR。一个团队可能贡献到 2 个组织目标，或一个组织 KR 可能由 2 个团队共同承担。

**对齐缺口检查**：
- 每个组织 KR 是否有至少一个团队在推进？
- 每个团队 OKR 是否连接到至少一个组织目标？
- 是否有团队 OKR 不连接任何组织目标？（可能是不对齐或缺少组织目标）
- 是否有组织 KR 无人认领？（需要分配或确认优先级）

### 步骤 3：定义评分标准

使用 0.0–1.0 评分制，含明确含义：

| 分数 | 含义 | 行动 |
|---|---|---|
| 0.0–0.3 | 显著未达成 | 根因分析：是战略问题、执行问题还是外部因素？ |
| 0.4–0.6 | 有进展但未达标 | 好的进展；延展目标约到合理的野心度 |
| 0.7–0.8 | 达成 | 完成了我们承诺的事情 |
| 0.9–1.0 | 超额完成 | 延展目标不够有野心；下季度校准 |

**甜点区是 0.6–0.8**：如果持续命中 1.0，KR 不够有野心。如果持续命中 0.3，目标不切实际或执行有问题。

### 步骤 4：建立检查节奏

| 节奏 | 活动 | 形式 | 时长 |
|---|---|---|---|
| **每周** | KR 进度更新（仅数值） | 异步：更新跟踪器 | 5 分钟 |
| **双周** | 团队 OKR 站会 | 同步：15 分钟——什么推进了、什么阻塞了、任何风险 | 15 分钟 |
| **每月** | OKR 健康评审 | 30 分钟：在轨/有风险/脱轨评估 | 30 分钟 |
| **每季度** | OKR 评分和回顾 | [QBR](./04-路线图-季度业务回顾.md)：评分、反思、设定下季度 | 半天 |

**每周 KR 更新格式**：
```
KR1: [当前值] / [目标值] — 信心: [高/中/低] — 阻塞: [有/无]
```

### 步骤 5：运行季度 OKR 周期

```
第 1 周:  领导层设定组织 OKR（草稿）
第 2 周:  团队评审并提出团队 OKR
第 3 周:  对齐评审：团队 OKR 是否覆盖组织 OKR？
第 4 周:  定稿并发布 OKR
第 5-12 周: 周异步更新 + 双周站会
第 13 周:  最终评分；QBR 回顾
```

## 核心产出

| 交付物 | 格式 | 受众 | 更新频率 |
|---|---|---|---|
| 组织 OKR（3–5 个目标） | 文档或跟踪器 | 全公司 | 每季度 |
| 团队 OKR（每团队 2–3 个） | 跟踪器 | 团队 | 每季度 |
| OKR 对齐地图 | 团队到组织的对齐图 | 领导层 | 每季度初 |
| 每周 KR 分数 | 仪表盘 | 全公司 | 每周 |
| 季度评分与回顾 | QBR 章节 | 领导层 | 每季度末 |

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| OKR 当作任务清单 | KR 变成"发布功能 X"而非成果衡量的载体 | 每个 KR 必须有数值并衡量成果 |
| OKR 与薪酬挂钩 | 人们为了保奖金而保守设目标 | OKR 是为了对齐和抱负，不是薪酬依据 |
| OKR 太多 | 10 个目标各 5 个 KR = 没有优先级 | 3–5 个组织目标，每个 2–5 个 KR |
| 设定后不管 | 第 1 周设定 OKR，第 13 周才回头看 | 每周异步更新；双周站会 |
| 级联但无对齐 | 团队各写各的 OKR 不看组织 OKR | 步骤 2 的对齐检查是必须执行的 |
| 目标与 KR 混淆 | 目标不是"增加 20% 收入"（那个是 KR） | 目标是定性的方向；KR 是定量的衡量 |
