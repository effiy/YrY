## 规划周期

全年规划活动的节奏安排：

```
Q1 (1-3月)              Q2 (4-6月)              Q3 (7-9月)              Q4 (10-12月)
────────────────────────────────────────────────────────────────────────────────────
1月: Q1 OKR 确认        4月: Q2 OKR 确认        7月: Q3 OKR 确认        10月: Q4 OKR 确认
     Q4 QBR                   Q1 QBR             Q2 QBR                  Q3 QBR
                                                ★ 年度规划启动          年度规划定稿
3月: 年中预算重预测                                              11月: 预算编制确认
    (触发: 收入偏差>20%)                                         12月: 全公司沟通
```

### 战略转向场景

当出现以下信号时，可能需要触发额外的规划周期：

| 信号 | 触发动作 | 使用文档 |
|---|---|---|
| 市场份额变化 > 5% | 重评年度计划 | 年度战略规划 |
| 关键假设不再成立 | 重评战略 + 计划 | 战略框架 → 年度规划 |
| 融资/并购事件 | 全面重规划 | 全部文档 |
| QBR 连续两季度 OKR 偏离 > 30% | 重评计划可行性 | QBR → 年度规划 |

## 角色与使用

| 角色 | 主要使用的文档 | 使用方式 |
|---|---|---|
| CEO / 创始人 | 全部 | 主导年度规划和 QBR，批准预算 |
| COO / 运营负责人 | 年度规划、QBR、OKR 追踪 | 执行规划和季度跟踪 |
| CFO / 财务负责人 | 人员预算规划、QBR（财务数据） | 提供财务框架，监控预算执行 |
| CPO / 产品负责人 | OKR 追踪、QBR（产品部分） | 将组织 OKR 级联到产品团队 |
| CTO / 技术负责人 | OKR 追踪、QBR（技术部分）、预算（技术） | 将组织 OKR 级联到工程团队 |

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 规划完就束之高阁 | 计划与实际脱节 | QBR 时对照计划评审实际，偏差必须解释 |
| 无战略先规划 | 项目按谁嗓门大排优先级 | 先完成 strategy/ 下的战略分析再启动规划 |
| 电子表格驱动 | 数字成为目标而非成果 | 从战略支柱出发，再分配资源 |
| 规划太刚性 | 环境变化但计划不变 | 通过 QBR 做季度纠偏；保留 10-20% 弹性资源 |
| 跳过自下而上输入 | 领导层计划脱离一线 | 年度规划阶段 2 不跳过；团队最知道可行性 |
| OKR 当 KPI | OKR 变成考核工具而非对齐工具 | OKR 是方向性目标，不是绩效考核的全部 |

## 维护

- **月度**：更新 OKR 进度
- **季度**：执行 QBR，更新决策日志
- **年度**：执行完整年度规划流程，归档上年度材料
