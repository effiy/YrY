# 处理监管变更

> **作为**合规负责人，**我想要**应对新发布或变化的监管法规，**以便**我们在执法开始前完成适应，避免罚款、业务中断或市场准入损失。
>
> **核心原则**：监管响应需要"快速启动，妥善完成"。第一份评估应在 48 小时内产出，不是完美的评估，而是对风险的初步判断。等待"了解更多"通常是拖延的借口——监管的不确定性本身就是一种需要管理的风险。

## 适用场景

- 新法规发布，影响你的产品、数据或市场
- 现行法规修订增加新要求
- 行业内出现监管执法或罚款（即使不是针对你）
- 进入新的司法管辖区（新市场 = 新法规）
- 客户或合作伙伴要求合规认证
- 数据保护机构发布新的指南或解释

## 触发条件

- 新法规或修订发布
- 你所在行业出现监管执法行动或罚款（即使不是针对你）
- 新司法管辖区进入（新市场 = 新法规）
- 客户或合作伙伴要求合规认证
- 行业自律组织发布新标准

## 分步操作

### 步骤 1：初步评估（触发后 48 小时内）

回答以下问题：

| 问题 | 行动 |
|---|---|
| 法规是什么？ | 名称、司法管辖区、监管机构、官方编号 |
| 要求什么？ | 3–5 句关键义务总结 |
| 适用于谁？ | 公司规模、行业、数据类型、地理范围 |
| 何时生效？ | 公告日期、执法日期、过渡期 |
| 不合规的后果？ | 处罚：罚款、业务限制、刑事责任 |
| 是否适用于我们？ | 是 / 否 / 可能 — 保守判断；若"可能"，按"是"处理 |

产出：**一页监管简报**（48 小时内与领导层共享）。

### 步骤 2：影响评估（1–2 周内）

组织跨职能团队：法务、工程、产品、安全、数据。

| 领域 | 评估问题 |
|---|---|
| **数据** | 是否影响我们收集、存储或处理的数据？ |
| **产品** | 是否需要产品变更（UX、功能、流程）？ |
| **工程** | 需要什么技术变更？需要多长时间？ |
| **运营** | 什么流程需要变更（支持、事故响应、报告）？ |
| **业务** | 是否影响我们的商业模式、定价或市场准入？ |
| **法务** | 什么文档、政策或合同需要更新？ |

对每个领域，估算：
- **工作量**：所需人周数
- **风险**：截止日期前未完成的影响
- **依赖**：是否有其他事项依赖此项先完成？

### 步骤 3：差距分析（与步骤 2 重叠）

将当前状态与新要求对比：

| 要求 | 当前状态 | 差距 | 严重等级 |
|---|---|---|---|
| 须在 30 天内提供数据可移植 | 无自动导出；人工流程需 45 天 | 须构建自动导出；将周转降至 <30 天 | 高 |
| 须指定数据保护官 | 未指定 DPO | 指定或招聘 DPO | 中 |
| 须对高风险处理做数据保护影响评估 | 无 DPIA 流程 | 创建 DPIA 模板和评审流程 | 中 |

### 步骤 4：适应计划

创建优先路线图：

| 差距 | 行动 | 负责人 | 截止日期 | 工作量 |
|---|---|---|---|---|
| 构建自动数据导出 | 实施数据可移植 API | 工程负责人 | 执法前 60 天 | 4 人周 |
| 指定 DPO | 招聘或内部指定 | 法务负责人 | 执法前 90 天 | 2 人周 |
| 创建 DPIA 流程 | 模板 + 评审工作流 | 合规负责人 | 执法前 30 天 | 1 人周 |

**关键规则**：目标完成期限设为执法日期前至少 30 天。这为测试、意外问题和利益相关方评审留出缓冲。

### 步骤 5：执行与监控

1. **周例会**（适应期间）：对照计划追踪进度
2. **升级路径**：如某项截止日期有风险，立即升级给领导层
3. **证据收集**：记录每项变更——如被审计，你需要这些
4. **外部律师评审**：在执法前让律师评审最终状态
5. **实施后回顾**：执法日期后，回顾哪些做对了、哪些需要改进

### 步骤 6：更新合规基线

适应完成后，更新：
- [数据合规基线](./05-战略-数据合规处理.md) — 新要求现在构成持续合规的一部分
- [数据留存策略](./03-战略-数据留存审查.md) — 如留存期发生了变化
- [战略文档](./08-战略-产品战略框架.md) — 如法规影响战略选择（如市场进入、产品范围）

### 监管清单

**每次监管变更的检查清单**：

- [ ] 48 小时内完成初步评估（一页简报）
- [ ] 通知受影响的所有利益相关方（法务、工程、产品、安全、高管）
- [ ] 2 周内完成影响评估
- [ ] 差距分析已记录并通过风险评级排序
- [ ] 适应计划有明确的负责人和截止日期
- [ ] 至少 30 天缓冲（完成日期早于执法日期）
- [ ] 周例会追踪进度（适应期间）
- [ ] 保留变更和决策的证据
- [ ] 外部律师评审（如需要）
- [ ] 实施后回顾已完成
- [ ] 合规基线已更新

## 决策要点与分支

| 决策点 | 选项 | 指引 |
|---|---|---|
| 法规可能不适用于我们 | 忽略 vs 监控 vs 准备 | 至少做最低限度的准备（理解要求）；保守起见按适用处理 |
| 合规成本 > 该市场的业务价值 | 退市 vs 合规 vs 接受风险 | 若市场边缘化，退出；对于有刑事责任的法规绝不可"接受风险" |
| 多项法规互相冲突 | 遵守最严格的 vs 按辖区分割 | 遵守最严格的，除非可按辖区分割（独立产品/基础设施） |
| 执法日期过于激进 | 最低可行合规 vs 全面合规 | 在截止日期前交付最低可行合规 (MVC)；记录延后项及理由；安排后续 |
| 法规不清晰或在演进中 | 等待清晰 vs 按最可能结果准备 | 按最可能的解释准备；通过行业协会寻求澄清 |

## 阶段核心产出

| 阶段 | 交付物 | 时间线 |
|---|---|---|
| 初步评估 | 一页监管简报 | 48 小时 |
| 影响评估 | 影响报告含工作量估算 | 1–2 周 |
| 差距分析 | 排序的差距列表附风险评级 | 1–2 周 |
| 适应计划 | 路线图含负责人和截止日期 | 2–3 周 |
| 执行 | 已完成的变更含证据 | 按计划 |
| 收尾 | 实施后回顾 + 基线更新 | 执法后 1 周 |

## 反模式与常见陷阱

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| "临近截止再说" | 合规变更总是比预期更久；需要缓冲 | 立即启动；目标执法前 30+ 天完成 |
| 仅律师参与 | 法务识别了要求但无法落地实施 | 跨职能团队，从第一天启动 |
| 镀金合规 | 构建完美方案，明明 MVC 就够 | 问："截止日期前合规的最低要求是什么？" |
| 等竞品被罚再行动 | 第一个被执法的可能就是你们 | 监控执法行动但不等到出事才行动 |
| 无证据痕迹 | 被审计时无法证明合规 | 记录每项变更、决策和评审；所有项标注日期 |
| 忽视员工培训 | 政策改了但人员不知道如何执行 | 列入适应计划的培训环节 |
