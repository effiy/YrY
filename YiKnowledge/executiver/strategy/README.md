# 战略 — 框架目录

> **作为**高管，**我想要**理解每个战略框架的用途和适用场景，**以便**为当前的战略问题选择正确的分析工具。
>
> **核心理念**：框架是思考的脚手架，不是答案的自动售货机。好的框架帮你提出正确的问题；差的使用方式是把框架当作填表练习。

## 快速开始

**第一次来？** 按以下顺序了解：

1. 先看[决策流程](#决策流程) — 确定你需要哪个框架

3. 找到目标框架后，打开对应文件阅读详细步骤
4. 完成后参考[战略栈](#战略栈) — 了解如何将多个框架组合使用

## 决策流程

```
面临战略问题
│
├── 问题是"我们在哪？" ──→ SWOT（快照定位）
│   └── 内部优势是否可持续？ ──→ VRIO
│
├── 问题是"市场怎么样？" ──→ 波特五力（行业结构）
│   └── 有没有无竞争空间？ ──→ 蓝海战略
│
├── 问题是"客户要什么？" ──→ 用户研究 → JTBD → 价值主张画布
│   └── 商业上是否成立？ ──→ 商业模式画布
│
├── 问题是"怎么增长？" ──→ 安索夫矩阵 + 市场进入策略
│   ├── 现有业务是否到顶？ ──→ 第二曲线 + BCG矩阵
│   └── 如何进入市场？ ──→ GTM策略
│
├── 问题是"怎么做产品？" ──→ 产品优先级 (RICE)
│   └── 用户会持续用吗？ ──→ 用户研究（持续发现）
│
├── 问题是"怎么衡量？" ──→ 平衡计分卡 + 单元经济
│   ├── 如何落地执行？ ──→ OKR方法论
│   └── 工程团队效率如何？ ──→ 工程效能度量
│
├── 问题是"用什么技术？" ──→ 技术选型决策 + 自建vs采购
│   └── 技术债怎么管？ ──→ 技术债策略
│
├── 问题是"组织怎么建？" ──→ 7S框架 + 文化设计
│   ├── 人怎么招和留？ ──→ 高管招聘 + 继任规划
│   └── 决策怎么下放？ ──→ 委托授权 + 反馈对话
│
├── 问题是"怎么合作？" ──→ 战略合作 + 谈判框架 + 干系人管理
│
├── 问题是"有什么风险？" ──→ 风险管理 + 情景规划 + 危机沟通
│
├── 问题是"怎么讲故事？" ──→ 战略叙事 + 董事会汇报 + 高管写作
│
└── 问题是"怎么合成？" ──→ 产品战略框架（元框架）
    ├── 按什么顺序做？ ──→ Now/Next/Later 路线图
    ├── 数据和AI策略？ ──→ AI数据策略 + API产品策略
    └── 我能持续多久？ ──→ 可持续节奏
```

## 战略栈

单一框架只提供局部视角。战略栈告诉你如何将多个框架组合成完整的战略图景：

```
层 1: 环境分析（知己知彼）
  SWOT → VRIO → 波特五力
  产出：我们在有吸引力的行业中拥有可持续优势吗？

层 2: 机会识别（去哪竞争）
  蓝海战略 → 安索夫矩阵 → 第二曲线
  产出：增长机会在哪？风险有多大？

层 3: 模式设计（如何取胜）
  价值主张画布 → 商业模式画布
  产出：为谁创造什么价值？如何捕获价值？

层 4: 执行系统（如何落地）
  平衡计分卡 → OKR 方法论 → Now/Next/Later 路线图
  产出：衡量什么？谁负责什么？按什么顺序？

层 5: 战略合成（统一叙事）
  产品战略框架
  产出：一页战略文档，可在 5 分钟内讲清楚
```

**组合原则**：
- 必须：每层至少做一个框架，不能跳层
- 建议：层 1-2 用外部视角（行业+市场），层 3-4 用内部视角（客户+执行）
- 禁止：不完成层 1 直接跳层 5（没有分析基础的战略是拍脑袋）

## 战略生命周期

```
情报收集 ──→ 分析 ──→ 合成 ──→ 执行 ──→ 评审 ──→ 情报收集...
   │            │         │        │        │
   │  industry/ │ strategy/│ strategy/│ roadmap/│ roadmap/
   │  reports/  │ 框架分析  │ 产品战略  │ OKR +   │ QBR
   │  竞品分析   │          │ 框架     │ 路线图   │
```

每个阶段的负责人和节奏：

| 阶段 | 活动 | 所有者 | 节奏 | 产出 |
|---|---|---|---|---|
| 情报收集 | 竞品追踪、行业报告、市场数据 | 高管 + 产品 | 持续 | industry/ 文件更新 |
| 分析 | 单框架分析 | 高管 + 产品 | 按需/季度 | 框架分析文档 |
| 合成 | 多框架综合 | 高管 | 半年/年度 | 产品战略文档 |
| 执行 | OKR + 路线图 | 全员 | 季度 | OKR 评分 + QBR 材料 |
| 评审 | QBR + 年度规划 | 高管 | 季度/年度 | 决策日志 + 新年度计划 |

## 前置条件

使用任何战略框架前，确保以下基础就绪：

### 每个框架都需要的通用前置

- [ ] 清晰的业务边界定义（我们在什么行业？做什么产品？）
- [ ] 当前业务数据（收入、客户数、增长率、市场份额——至少估算值）
- [ ] 关键竞品名单（至少 3-5 个，含直接/间接）

### 按框架类型的前置

| 框架类型 | 额外前置 |
|---|---|
| 分析类（SWOT, VRIO, P5F） | 行业报告、竞品公开数据、内部访谈 |
| 画布类（VP Canvas, BMC） | 客户访谈记录、定价数据、渠道数据 |
| 定位类（蓝海, 安索夫） | 市场地图、客户痛点排序、替代品清单 |
| 执行类（BSC, OKR） | 已批准的年度战略、团队容量数据、历史 KPI |
| 元框架（产品战略） | 至少完成 3 个基础框架的分析 |

### YrY 特定前置

- YiKnowledge 行业情报已刷新（`last_verified` ≤ 1 个月）
- YiAi RAG 可检索到相关竞品和市场信息
- 三项目（YiVad/YiAi/YiPet）当前状态已汇总

## 战略节奏

不同框架有不同的刷新频率。以下是推荐节奏：

```
月度 ──── 竞品扫描、行业动态追踪
季度 ──── SWOT、商业模式画布、OKR 评分、QBR
半年度 ── 波特五力、价值主张、市场趋势复盘
年度 ──── VRIO、蓝海战略、安索夫、第二曲线、平衡计分卡、产品战略框架
事件驱动 ─ 监管变更触发合规评审、重大竞品动作触发竞争重评
```

**触发重评的信号**（任一出现，立即启动框架刷新）：
- 市场份额变化 > 5%
- 新进入者获得 > 10% 市场份额
- 关键客户流失或重大客户获取
- 监管法规重大变化
- 核心技术突破（如新模型能力跃升）
- 融资环境显著变化

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 框架跳跃 | 每个框架浅尝辄止，不做深入分析 | 选对框架后彻底完成，产出可行动的洞察 |
| 分析瘫痪 | 花 3 个月做 8 个框架分析但不决策 | 2 周内产出 3 个行动项，否则分析范围过大 |
| 无视前置条件 | 没有数据就填框架，全是猜测 | 缺失数据先收集；无法获取的标记为假设并计划验证 |
| 框架当目标 | 填完框架就认为战略做完了 | 框架是输入，决策是输出。没有决策的分析是浪费 |
| 孤立使用 | 单个框架给出片面结论 | 按战略栈至少完成一个完整层次 |

## 维护

- **月度**：检查各框架文件的 `last_verified` 时间戳
- **季度**：审查框架速览表，确认所有框架仍适用
- **年度**：根据实际使用频率，评估是否需要新增或归档框架
