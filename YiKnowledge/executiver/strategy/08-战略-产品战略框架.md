# 产品战略框架

> **作为**产品战略家，**我想要**将多个分析框架的输出合成为一个连贯的战略，**以便**组织拥有统一的方向，包含明确的选择、权衡和执行计划。
>
> **核心洞见**：每个战略框架回答一个特定问题。SWOT 告诉你现状，波特五力告诉你在哪竞争，VRIO 告诉你靠什么赢。但如果把每个框架的结论单拿出来用，你会得到一堆矛盾的建议。PSF 的角色是裁判和合成者。

## 定义

产品战略框架 (PSF) 是一个**元框架**——它自身不做分析。相反，它提供了一种结构，将 SWOT、VRIO、波特五力、蓝海战略、价值主张画布和商业模式画布的输出合并为一个连贯的战略文档。

把各个框架想象成诊断工具，PSF 就是治疗方案。

## 适用场景

- 已经运行了 2 个以上分析框架，需要协调它们的结论
- 年度战略刷新周期
- 董事会/投资人战略演讲准备
- 收购后或战略转向后的战略定义
- 多团队（产品、工程、业务）围绕一个方向对齐
- 持续的季度战略重评

## 设计步骤

### 阶段 1：收集输入

收集你应用的每个框架的输出。至少需要：

| 输入 | 来源 | 提取什么 |
|---|---|---|
| 态势审计 | [SWOT](./10-战略-SWOT分析.md) | 前 3 强项、弱项、机会、威胁 |
| 资源优势 | [VRIO](./12-战略-VRIO框架.md) | 具有持续竞争优势的资源 |
| 行业结构 | [波特五力](./07-战略-波特五力模型.md) | 整体吸引力评级 + 关键力量 |
| 市场机会 | [蓝海战略](./01-战略-蓝海战略.md) | 战略布局图 + ERRC 行动 |
| 客户价值 | [价值主张画布](./11-战略-价值主张画布.md) | 前几个客户待办任务 + 产品匹配评估 |
| 商业模式 | [商业模式画布](./02-战略-商业模式画布.md) | 关键假设和验证状态 |
| 组合时机 | [第二曲线](./09-战略-第二曲线.md) | 当前曲线位置 + 转型时机 |

### 阶段 2：识别模式

在所有输入中寻找：

- **收敛**：多个框架指向同一结论的地方？（高置信度——全力以赴）
- **分歧**：框架之间不一致的地方？（需要调查——不要忽视矛盾）
- **空白**：什么重要问题没有被任何框架回答？（需要新框架或一手研究）
- **约束**：什么合规或资源限制构成了战略的边界？

### 阶段 3：做出战略选择

战略的核心是选择**不**做什么。对于每个重大决策领域：

1. 列出考虑的选项
2. 陈述选择的路径和原因
3. 明确陈述拒绝了什么以及为什么
4. 链接回支撑选择的框架证据

**战略选择模板**：
```
决策领域：{{例如：目标客户细分}}
  考虑的选项：{{选项 A, B, C}}
  我们的选择：{{选项 B}}
  理由：{{基于框架 X 和 Y 的证据}}
  拒绝了什么：{{选项 A（原因：市场规模不足），选项 C（原因：不匹配 VRIO 资源）}}
```

### 阶段 4：撰写战略文档

用以下大纲撰写战略文档。每节应引用产生该洞察的具体框架：

```
1. 执行摘要（1 页）
2. 我们为什么存在（使命、愿景、战略支柱）
3. 我们在哪里竞争（行业边界、市场细分）
4. 我们如何赢（VRIO 优势、差异化策略）
5. 我们不做什么（明确的拒绝和边界）
6. 关键假设（如果这些不成立，战略需要重做）
7. 执行路线图（Now / Next / Later）
8. 成功衡量（OKR 和关键指标）
```

### 阶段 5：沟通与对齐

1. 与框架负责人分享草稿
2. 召开战略评审会：阐述选择，不是框架
3. 将分歧记录为假设日志中的风险
4. 发布最终版本并附上评审日期

## YrY 产品战略框架实例

### 当前 YrY 战略的核心选择

| 决策领域 | 我们的选择 | 拒绝了什么 | 框架支撑 |
|---|---|---|---|
| 技术路径 | 自有部署 Ollama，不依赖第三方 LLM API | 使用 OpenAI/Claude API（数据隐私 + 成本） | SWOT（数据控制优势） + 五力（降低 LLM 供应商议价能力） |
| 目标用户 | 内部团队优先，外部推出待验证 | 立即推向外部市场 | BMC（收入模式未验证） + SWOT（内部需求明确） |
| 产品生态 | 三项目协同（Vad + Ai + Pet），知识共享 | 独立项目各自发展 | VRIO（知识库是独特资源） + 蓝海（浏览器扩展 + 知识 RAG 原生） |
| 知识库策略 | 结构化 frontmatter + RAG 优化，核心战略资产 | 自由格式维基（检索效率低） | VRIO（结构化知识是持续优势） + BMC（降低 RAG 成本和提升质量） |

### 当前阶段的关键假设

| 假设 | 置信度 | 如果错了... | 验证方法 |
|---|---|---|---|
| Ollama 能持续满足推理性能需求 | 中 | 需引入云 LLM API，成本显著上升 | 监控延迟和吞吐量，每季度重评 |
| 知识库结构能被 RAG 有效检索 | 中 | 需调整 frontmatter 规范或索引策略 | 定期 RAG 检索质量测试 |
| 浏览器扩展用户愿意使用 AI 助手 | 低 | YiPet 需重新定位 | YiPet 的使用数据分析 |

## 核心产出

- **战略文档**（5–10 页）：所有框架合成为一个叙述
- **单页摘要**：给不会读全文的利益相关方的执行摘要
- **假设日志**：关键赌注和重评触发条件
- **沟通幻灯片**：5–10 张用于全公司对齐

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 框架堆砌等于战略 | 列出 SWOT 条目不等于战略 | 合成为选择；每个框架输出必须映射到一个决策 |
| 委员会共识法 | 平均化冲突观点产生平淡战略 | 呈现证据，做出选择，将不同意见记录为风险 |
| 跳过"我们不做什么" | 没有明确拒绝，团队什么都会追 | 每个战略选择必须有明确的拒绝 |
| 战略是静态文档 | 发布一次，从未回顾 | 在文档中设评审日期；遵循战略节奏 |
| 过度打磨才分享 | 完美主义延迟对齐 | 完成 80% 时分享；基于反馈迭代 |
