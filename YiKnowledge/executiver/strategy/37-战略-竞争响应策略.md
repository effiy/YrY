# 竞争响应策略

> **作为**高管，**我想要**在竞品做出重大动作时基于战略而非情绪做出响应，**以便**不因恐慌而模仿、也不因傲慢而忽视。
>
> **核心洞见**：竞品做了一个动作——你的团队看着你，等你反应。最差的反应是"我们也做一个"（跟随是默认选项，也是最多错的选项）。最好的反应是基于你的战略判断——有时候最好的反击是不反击。

## 竞品动作评估

不是每个竞品动作都需要响应。先用三个过滤器：

### 过滤器 1：这个动作改变竞争格局吗？

| 竞品动作类型 | 通常的威胁等级 | 示例 |
|---|---|---|
| 重大产品架构变更 | 高——可能重新定义品类 | Cursor 从补全到 Agent 模式 |
| 定价大幅降低或免费 | 中高——取决于是否可持续 | 大厂用免费挤占市场 |
| 新功能发布（模仿你） | 中——验证了你方向对 | 竞品复制你的差异化功能 |
| 新功能发布（差异化） | 中——可能开辟新战场 | 竞品做你没想到的事 |
| 融资/并购 | 中——信号而非直接威胁 | 竞品获得大额融资 |
| 市场宣传/PR 动作 | 低——噪音多于信号 | "XXX 宣布..." |
| 高管变动 | 低中——取决于角色 | 核心技术人员离职加入竞品 |

### 过滤器 2：这会影响我们的核心用户吗？

| 如果... | 则... |
|---|---|
| 影响的是我们不服务（也不打算服务）的用户群 | 忽略 |
| 影响的是我们未来打算服务的用户群 | 监控，不急于响应 |
| 影响的是我们当前的核心用户群 | 需要评估响应 |

### 过滤器 3：不响应会怎样？

假设我们不响应的 6 个月后：
- 最好的情况：用户没注意到，或者注意到了但不在乎
- 最坏的情况：核心用户因为缺少这个能力而开始流失
- 最可能的情况：_____

如果最可能的情况是"用户注意到了但不会因此离开"——不需要紧急响应。

## 四种响应策略

| 策略 | 做什么 | 何时使用 | 风险 |
|---|---|---|---|
| **忽略** | 不回应，不改变路线图 | 动作不改变格局、不影响核心用户、或响应的成本>不响应的代价 | 判断失误——其实用户在乎 |
| **监控** | 不改变路线图，但追踪信号 | 动作可能重要但时机未到 | 监控变遗忘——设定期评审点 |
| **吸收** | 将竞品的方向纳入你的路线图（但用自己的方式） | 竞品验证了一个需要被解决的用户问题——但你的解决方案可以不同且更好 | 吸收变成复制——失去差异化 |
| **反击** | 用自己的差异化动作回应 | 核心领域受到直接威胁，且你有独特的反击角度 | 被竞品牵着鼻子走——按对方的节奏打仗 |

### 判断矩阵

| 竞品动作威胁 | 与我方战略一致性 | 建议策略 |
|---|---|---|
| 高 | 高——他们做了我们也该做的事 | **吸收**：用自己的方式做得更好 |
| 高 | 低——他们做的事对我们不重要 | **监控**：除非用户反馈表明更重要 |
| 低 | 高 | **监控**或**吸收**（看时机） |
| 低 | 低 | **忽略** |

### 如何"吸收"而不"复制"

吸收和复制的区别：

- **复制**：竞品做了 X，我们也做 X。结果：你永远是第二。
- **吸收**：竞品做了 X，说明用户需要解决 Y 问题。我们用 Z 方式解决 Y 问题——Z 方式与我们的差异化一致。

**示例**：
- 竞品动作：Cursor 推出 Agent 模式，能自主修改多个文件
- 复制式响应：YrY 也做 Agent 模式
- 吸收式响应：Agent 模式解决的核心问题是"减少从意图到代码的步骤"。YrY 减少这个步骤的方式不是 Agent，而是让用户在做决策时有更好的上下文——减少他们反复修改的次数。投资 RAG 而非 Agent 能力。

## 响应速度的悖论

| 响应速度 | 何时合适 | 风险 |
|---|---|---|
| **即时**（数天-数周） | 竞品动作直接威胁核心业务、用户已经开始询问 | 恐慌响应，产品战略被打乱 |
| **快速**（1-3 月） | 竞品验证了用户需求，你可以在下个周期内吸收 | 仍然可能不够深思熟虑 |
| **常规**（按路线图节奏） | 竞品动作值得吸收，但不需要紧急 | 市场窗口期错失 |
| **延迟**（下个规划周期） | 重要但不紧急的响应 | 团队忘记当初为什么要加这个 |

**原则**：除非核心用户在竞品动作后开始流失，否则不改变当前季度的路线图。最快响应在下个 OKR 周期中体现。

## YrY 竞品响应矩阵

| 竞品 | 近期动作 | 威胁 | 与我方战略一致性 | 建议策略 | 具体行动 |
|---|---|---|---|---|---|
| Cursor | 推出 Agent 模式 | 高 | 低——YrY 不做 IDE | **监控** | 关注开发者社区的反应，但不需要在 Agent 功能上与 Cursor 竞争 |
| Copilot | Workspace 从 Issue 到 PR | 中高 | 中——部分重叠 YrY 全流程叙事 | **吸收** | "从需求到代码"是 YrY 也在做的——但用 RAG+知识库的方式，而非 Workspace 方式 |
| Claude Code | 长时间自主任务 | 中 | 中低——定位不同 | **监控** | 关注自主 Agent 的技术进展，但不急 |
| 新 AI IDE | 进入市场 | 低 | 低 | **忽略** | 除非获得显著市场 traction |
| 大厂免费 AI 工具 | 免费提供部分功能 | 中 | — | **监控** | 如果大厂免费覆盖了 YiPet 的核心场景，需要加速差异化 |

## 竞品响应节奏

| 节奏 | 活动 |
|---|---|
| **每周** | 竞品动态扫描（官方渠道 + 行业媒体） |
| **每月** | 竞品动作评估——是否有需要通过三层过滤器的动作 |
| **每季度** | 竞品响应策略评审——已做出的响应效果如何？需要调整哪些监控级别？ |
| **事件驱动** | 重大竞品动作——48 小时内完成三层过滤器 + 初始响应策略 |

## 核心产出

- 竞品动作过滤评估（三个过滤器 × 每个重大竞品动作）
- 响应策略决策记录（忽略/监控/吸收/反击 + 理由 + 重评日期）
- 竞品监控面板（关键竞品、关注指标、预警阈值）

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 每个竞品动作都跟 | 按对方的节奏打仗，永远被动，差异化消失 | 三层过滤器——大多数竞品动作不值得响应 |
| 傲慢忽视 | "他们不是威胁"——直到他们变成威胁 | 即使选择忽略，也要陈述理由和重评条件 |
| 恐慌响应 | 竞品做了 X，下周就要求团队做 X | 响应进入下一个 OKR 周期——不打乱当前优先级 |
| 降价竞争 | 竞品降价我就降价——这是往底部竞争 | 在价值上竞争，不在价格上竞争 |
| 只关注直接竞品 | 间接和潜在竞品的一步可能比直接竞品的十步更有威胁 | 四级竞品体系：直接/间接/相邻/潜在 |
