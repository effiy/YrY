# 平衡计分卡

> **作为**高管，**我想要**用多维指标体系衡量战略执行，**以便**避免只看财务指标的短视行为，确保长期健康发展。
>
> **核心洞见**：财务指标告诉你过去做了什么，客户和流程指标告诉你现在做得怎么样，学习和成长指标告诉你未来能做什么。只看财务就像开车只看后视镜。

## 定义

平衡计分卡 (BSC) 从四个维度衡量组织绩效：

```
        ┌──────────────┐
        │   财务维度     │
        │  "股东怎么     │
        │   看我们？"    │
        └──────┬───────┘
               │
  ┌────────────┼────────────┐
  │            │            │
  ▼            ▼            ▼
┌────────┐ ┌────────┐ ┌────────┐
│客户维度 │ │流程维度 │ │学习与  │
│"客户怎 │ │"什么流 │ │成长维度 │
│么看我  │ │程必须 │ │"如何持 │
│们？"   │ │卓越？" │ │续改进？"│
└────────┘ └────────┘ └────────┘
```

四个维度之间存在因果链：**学习与成长 → 内部流程 → 客户 → 财务**。更好的员工能力和技术驱动更好的流程，更好的流程带来更好的客户体验，更好的客户体验带来更好的财务结果。

## 适用场景

- 战略规划完成后，需要将战略转化为可衡量指标
- 组织规模扩大，需要系统性的绩效管理
- 发现只关注财务指标导致了短视行为
- 需要向董事会或投资人展示战略执行的全景
- 并购或整合后统一绩效语言

## 设计步骤

### 步骤 1：确定战略主题

从年度战略中提取 3-5 个战略主题。每个主题在四个维度上都有对应的目标。

**示例**：
- 战略主题："成为最受信赖的 AI 平台"
  - 财务：ARR 增长 + 客户终身价值提升
  - 客户：客户满意度 + 客户留存率
  - 流程：系统可用性 + 安全合规
  - 学习：AI 能力建设 + 团队认证

### 步骤 2：为每个维度选择指标

#### 财务维度

| 指标类别 | 示例指标 | 适用阶段 |
|---|---|---|
| 增长 | 收入增长率、新客户获取数、市场占有率 | 早期/增长期 |
| 盈利 | 毛利率、净利润率、单位经济 | 增长期/成熟期 |
| 效率 | 人均收入、资本回报率、现金流 | 成熟期 |
| 价值 | 客户生命周期价值 (LTV)、获客成本 (CAC) | 全阶段 |

**原则**：早期阶段侧重增长指标，成熟阶段侧重效率指标。不要在一个维度堆砌超过 5 个指标。

#### 客户维度

| 指标类别 | 示例指标 | 测量方法 |
|---|---|---|
| 满意度 | NPS、CSAT、客户投诉率 | 定期调研 + 自动收集 |
| 留存 | 客户流失率、续约率、MRR 留存 | 订阅/合同数据 |
| 获取 | 转化率、试用转付费率、获客成本 | CRM + 财务数据 |
| 价值 | 客户健康分、产品使用深度、功能采纳率 | 产品分析 |

**原则**：NPS 是被引用最多的客户指标，但单独使用不足以说明问题。至少搭配一个行为指标（如留存率或使用深度）。

#### 内部流程维度

| 指标类别 | 示例指标 | 适用团队 |
|---|---|---|
| 运营效率 | 周期时间、吞吐量、自动化率 | 运营、工程 |
| 质量 | 缺陷率、返工率、SLA 达成率 | 工程、QA |
| 创新 | 新产品收入占比、从概念到上线的周期 | 产品、工程 |
| 合规 | 审计通过率、安全事件数、合规差距数 | 安全、法务 |

**原则**：流程指标应与客户和财务指标有可验证的因果联系。如果一个流程指标提升了但客户指标没有变化，说明你衡量了错误的东西。

#### 学习与成长维度

| 指标类别 | 示例指标 | 测量方法 |
|---|---|---|
| 人才 | 关键岗位备份率、员工留存率、内部晋升率 | HR 系统 |
| 技能 | 关键技能覆盖率、培训完成率、认证通过率 | 学习管理系统 |
| 技术 | 技术债务比率、基础设施现代化率、自动化覆盖率 | 工程数据 |
| 文化 | 员工敬业度、心理安全感评分、反馈采纳率 | 员工调研 |

**原则**：学习与成长指标是最先行的。如果这个维度的指标恶化，12-18 个月后其他三个维度也会开始恶化。

### 步骤 3：绘制战略地图

将四个维度的目标用因果箭头连接，形成战略地图：

```
学习与成长         内部流程          客户            财务
─────────────────────────────────────────────────────────
AI 工程能力提升 ──→ 模型推理速度 ↑ ──→ 用户体验 ↑ ──→ 客户留存 ↑
    │                                       │
    └──→ 自动化率 ↑ ──→ 运维成本 ↓ ────────→ 毛利率 ↑
```

**验证**：每条因果链上的假设都应该可被数据验证。如果 A 提升了但 B 没有变化，说明因果假设不成立。

### 步骤 4：设定目标和阈值

对每个指标设定：

| 指标 | 当前值 | 目标值 | 黄灯阈值 | 红灯阈值 | 数据来源 |
|---|---|---|---|---|---|
| NPS | 35 | 50 | < 40 | < 30 | 季度调研 |
| 客户流失率 | 5% | < 3% | > 5% | > 8% | 订阅数据 |
| 系统可用性 | 99.5% | 99.9% | < 99.5% | < 99.0% | 监控系统 |

### 步骤 5：建立评审节奏

| 维度 | 评审频率 | 评审人 | 评审内容 |
|---|---|---|---|
| 财务 | 月度 | CFO + CEO | 收入、成本、现金流 vs 预算 |
| 客户 | 月度 | CPO | NPS、留存、关键客户健康 |
| 流程 | 月度 | CTO + COO | 交付效率、质量、事件 |
| 学习 | 季度 | CTO + HR | 技能覆盖、技术债务、敬业度 |
| 全景 | 季度 | 高管团队 | 战略地图评审、阈值触发讨论 |

## 核心产出

- 战略地图（一张图展示四个维度的因果链）
- 指标字典（每个指标的定义、计算方式、数据来源、评审频率）
- 阈值仪表盘（红黄绿灯状态一目了然）
- 季度评审报告

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 指标过多 | 15+ 个指标没人看得过来 | 每个维度 3-5 个，总计不超过 20 个 |
| 无视因果链 | 四个维度假性平衡，没关系 | 用战略地图连接各维度，验证因果假设 |
| 只有 lagging 指标 | 只看到结果，无法提前干预 | 每个维度至少有一个 leading 指标 |
| KPI 当考核 | 指标变成了惩罚工具 | 指标是学习和改进的工具，不是打分的尺子 |
| 设完就不管 | 环境变了指标没变 | 季度评审：指标仍然衡量正确的事吗？ |
| 指标互相矛盾 | 降成本指标和提质量指标冲突 | 战略地图应揭示这种矛盾并在设定时就解决 |
