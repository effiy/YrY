# Second Curve

> **As an** executiver, **I want to** time the transition from our current business to the next growth engine, **so that** we don't wait until decline forces a desperate pivot.

## Definition

The Second Curve model describes the lifecycle of any business, product, or technology as an S-curve:

```
Performance
    ▲
    │                                    ● Second Curve
    │                                 ╱
    │                              ╱
    │         ● First Curve    ╱
    │       ╱               ╱
    │     ╱               ╱
    │   ╱               ╱
    │ ╱       ← Gap → ╱
    └──────────────────────────────► Time
         Growth    Maturity   Decline
```

The key insight: **you must start the second curve while the first curve is still growing**, because the transition takes time and resources. If you wait until the first curve peaks, you're already too late.

## Applicable scenarios

- Revenue growth is slowing in your core business
- A disruptive technology threatens your current model
- Annual portfolio review: where is each product line on its curve?
- Resource allocation: how much to invest in current vs. future business?
- M&A strategy: buy the second curve or build it?

## Design steps

### Step 1: Map current curves

For each product/business line, plot:

| Attribute | How to assess |
|---|---|
| **Current position** | Growth rate, market share trend, customer acquisition cost trend |
| **Curve shape** | Is growth accelerating (early), linear (mid), or decelerating (late)? |
| **Remaining runway** | TAM penetration, use case saturation, competitive intensity |
| **Peak indicators** | Declining growth rate, increasing churn, price pressure, commoditization |

### Step 2: Identify second curve candidates

Sources of potential second curves:

| Source | Example | Tool |
|---|---|---|
| **Adjacent market** | Geographic expansion, new vertical | [Blue Ocean](./blue-ocean.md) |
| **New technology** | AI-native version of existing product | [VRIO](./vrio-framework.md) |
| **Business model innovation** | Subscription → marketplace | [BMC](./business-model-canvas.md) |
| **Customer segment expansion** | Enterprise → SMB, or vice versa | [VPC](./value-proposition-canvas.md) |
| **Value chain move** | Forward/backward integration | [P5F](./porter-five-forces.md) |

### Step 3: Evaluate second curve candidates

Score each candidate:

| Criterion | Weight | Candidate A | Candidate B |
|---|---|---|---|
| Market size (TAM) | 25% | | |
| Competitive advantage (VRIO) | 25% | | |
| Synergy with current business | 15% | | |
| Team and capability fit | 15% | | |
| Time to meaningful revenue | 10% | | |
| Capital required | 10% | | |

### Step 4: Time the transition

The optimal window to start the second curve:

```
Too early ──────► OPTIMAL WINDOW ──────► Too late
   │                    │                      │
   │                    │                      │
First curve            First curve           First curve
still accelerating     growth is strong      growth is flat
but showing signs      but decelerating      or declining
of eventual plateau
```

Inside the window:
- Allocate 10–20% of resources to second curve exploration
- Protect the second curve team from first-curve operational demands
- Use first-curve profits to fund second-curve investment

### Step 5: Manage the portfolio

Classify all products/businesses by curve position:

| Stage | Resource allocation | Management approach |
|---|---|---|
| **First curve — growing** | 70–80% | Optimize, scale, defend |
| **First curve — maturing** | 50–60% | Harvest, reduce cost, maintain |
| **Second curve — exploring** | 10–20% | Protect, experiment, don't optimize too early |
| **Second curve — scaling** | 30–40% | Shift resources from declining first curve |
| **Declining** | 0–5% | Exit or milk, don't reinvest |

## Key outputs

- S-curve map with all products/businesses positioned
- Second curve candidates ranked by evaluation criteria
- Resource allocation recommendation (% split between curves)
- Transition timing recommendation with trigger indicators
- First-curve peak early-warning dashboard

## Anti-patterns

| Anti-pattern | Why it fails | Fix |
|---|---|---|
| Starting too late | By the time the first curve peaks, you lack resources and credibility | Monitor leading indicators of maturity; start exploration at 60–70% of estimated runway |
| Starting too many second curves | Resources spread too thin; none get enough investment | Pick 1–2 second curve candidates; kill the rest |
| Managing second curve like first curve | Second curves need exploration, not optimization | Different KPIs, different team, different governance |
| Abandoning the first curve too early | You need its cash flow to fund the transition | Continue harvesting the first curve; don't starve it |
| Assuming the second curve is just "first curve + AI" | Technology alone rarely creates a new S-curve | Combine technology with business model innovation using [BMC](./business-model-canvas.md) |
