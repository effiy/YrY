# 价值主张画布

> **作为**产品负责人，**我想要**将客户试图完成的任务与我们的产品所提供的内容做映射，**以便**验证产品市场匹配，并优先开发创造真正价值的功能。
>
> **核心洞见**：大多数产品失败的根因不是构建了错误的东西，而是为错误的人构建了正确的东西。价值主张画布迫使你先理解客户，再讨论解决方案。

## 定义

价值主张画布 (VPC) 有两个面：

```
┌──────────────────────────────┬──────────────────────────────┐
│        客户画像              │         价值主张              │
│                              │                              │
│          期望收益            │         收益创造器            │
│            ▲                 │            ▲                 │
│            │                 │            │                 │
│    客户待办任务  ◄──匹配──►  产品和服务                      │
│            │                 │            │                 │
│            ▼                 │            ▼                 │
│          痛点               │         痛点消除器            │
│                              │                              │
└──────────────────────────────┴──────────────────────────────┘
```

- **客户待办任务 (Customer Jobs)**：客户试图完成什么（功能性、社交性、情感性）
- **痛点 (Pains)**：与待办任务相关的坏结果、风险和障碍
- **期望收益 (Gains)**：客户想要的结果和收益（必需、期望、渴望、意外）
- **产品和服务 (Products & Services)**：你提供的产品
- **痛点消除器 (Pain Relievers)**：你的产品如何减轻特定客户痛点
- **收益创造器 (Gain Creators)**：你的产品如何创造特定客户收益

**匹配 (Fit)** 发生在你的痛点消除器解决真实痛点，且收益创造器交付真实收益时。

## 适用场景

- 定义新产品或功能
- 解释为什么一个"应该"有效的功能得不到采用
- 在竞争功能请求之间排优先级
- 竞争定位：你的价值主张在哪方面与众不同？
- 季度评审：客户价值是否变了？
- 竞品分析时的横向价值对比

## 设计步骤

### 步骤 1：填充客户画像

从客户开始，不是从产品开始。使用客户访谈、使用数据和支持工单。

#### 客户待办任务
问："客户试图完成什么？"

| 任务类型 | 示例 |
|---|---|
| **功能性** | "向我的经理发送月度报告" |
| **社交性** | "在团队面前看起来称职" |
| **情感性** | "对数据正确性有信心" |

#### 痛点
问："什么让客户烦恼、沮丧或担忧？"

| 痛点类型 | 示例 |
|---|---|
| **不想要的结果** | "报告编译需要 2 小时" |
| **障碍** | "数据分散在 3 个系统中" |
| **风险** | "害怕给董事会发送错误数字" |

#### 期望收益
问："什么会让客户满意或欣喜？"

| 收益类型 | 示例 |
|---|---|
| **必需** | "报告必须准确" |
| **期望** | "报告应该易读" |
| **渴望** | "报告应该自动生成" |
| **意外** | "报告应该基于趋势建议行动项" |

### 步骤 2：填充价值主张

将你的产品对照客户画像做映射。

#### 产品和服务
列出你的产品提供的一切——不仅功能，还包括服务、集成、支持、文档。

#### 痛点消除器
对客户画像中的每个痛点，描述你的产品如何减轻或消除它。要具体：
- 不好："节省时间" → 好："将报告编译从 2 小时减少到 5 分钟"

#### 收益创造器
对客户画像中的每个期望收益，描述你的产品如何赋能或增强它。

### 步骤 3：评估匹配

为每个痛点消除器和收益创造器评级：

| 评级 | 含义 | 行动 |
|---|---|---|
| ✅ **强匹配** | 直接解决最高优先级痛点/收益，影响可衡量 | 放大——这是核心竞争力 |
| 🔶 **中等匹配** | 解决痛点/收益但影响不明确或次要 | 调查——为什么影响不明确？ |
| ❌ **无匹配** | 不映射到任何客户痛点或收益 | 考虑移除或重新定位 |

如果你有产品/服务无匹配，它们是移除的候选。
如果你有客户痛点/收益无覆盖，它们是机会。

### 步骤 4：排优先级

按以下顺序：
1. **极端**且**频繁**的痛点
2. **必需**且**当前服务不足**的期望收益
3. 其余所有

## YrY 价值主张画布应用

### 对 YiVad 用户的客户画像

| 客户待办任务 | 功能性：在管理后台查看和操作数据 |
|---|---|
| 痛点 | "不同模块数据割裂，切换上下文耗时" |
| 期望收益 | "在一个后台完成所有数据操作" |

### 对 YiPet 用户的客户画像

| 客户待办任务 | 功能性："在浏览网页时不离开当前页面就能获得 AI 帮助" |
|---|---|
| 痛点 | "需要切换到独立 AI 应用，打断工作流" |
| 期望收益 | "浏览器原生就知道我在看什么并能帮助我" |

### 对 YiKnowledge 维护者的客户画像

| 客户待办任务 | 功能性："维护高质量知识库供团队和 AI 使用" |
|---|---|
| 痛点 | "文件多了以后查找困难，不知道内容是否过时" |
| 期望收益 | "结构化 frontmatter + 自动扫描，内容质量和时效一目了然" |

## 核心产出

- 完成的客户画像（待办任务、痛点、期望收益 — 已排优先级）
- 完成的价值主张（产品/服务、痛点消除器、收益创造器）
- 匹配评估，含强/中/无匹配评级
- 差距分析：未覆盖的痛点/收益 → 功能机会
- 过度工程分析：无匹配的产品/服务 → 移除候选

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 从产品侧开始 | 你会将客户需求强套到现有功能上 | 总是先填充客户画像 |
| 模糊的痛点消除器 | "更好的 UX"不是痛点消除器 | 要具体："将 5 步点击流程减到 1 步" |
| 忽视情感/社交任务 | B2B 产品也有情感买家 | 访谈中追问情感背景："什么让你夜不能寐？" |
| 问客户想要什么 | 客户描述的是问题，不是解决方案 | 追问待办任务、痛点和收益；你来设计解决方案 |
| 一刀切的客户画像 | 不同细分有不同的待办任务 | 为每个不同的客户细分创建单独画像 |
