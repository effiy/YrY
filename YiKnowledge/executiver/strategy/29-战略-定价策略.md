# 定价策略

> **作为**高管，**我想要**基于价值而非成本来设计定价策略，**以便**最大化捕获产品创造的价值，同时不阻碍增长。
>
> **核心洞见**：定价是商业模式中最被低估的杠杆。定价提升 1% 通常直接转化为利润提升 10% 以上——因为定价变化不增加任何成本。大多数产品的定价不是太高，而是太低——不是因为慷慨，而是因为恐惧。

## 三种定价基础

| 基础 | 定义 | 优点 | 缺点 |
|---|---|---|---|
| **成本加成** | 成本 × (1 + 利润率) | 简单、确保不亏 | 完全无视用户获得的价值——你可能在低价卖高价价值的东西 |
| **竞品对标** | 以竞品价格为锚点 ± X% | 市场验证过，用户不觉得离谱 | 你变成了价格追随者——竞品定价错了你也跟着错 |
| **价值定价** | 基于用户获得的价值定价 | 最大化捕获价值，最能反映产品真实价值 | 最难做——需要理解用户的价值感知和支付意愿 |

**原则**：用成本加成确保底线（不能长期亏钱卖），用竞品对标了解市场参照，用价值定价设定最终价格。

## 定价模型选择

| 模型 | 适合 | 不适合 | 示例 |
|---|---|---|---|
| **按用户/席位** | 协作工具、SaaS | 用户数波动大的场景 | Slack、Notion |
| **按用量** | API、云服务、AI 推理 | 用量不可预测的场景 | AWS、OpenAI API |
| **分层订阅** | 从个人到企业的完整覆盖 | 功能差异导致用户困惑 | Figma、GitHub |
| **免费增值** | 需要网络效应的产品 | 免费用户成本侵蚀付费用户价值 | Dropbox、Spotify |
| **一次性买断** | 独立工具、不需要持续服务 | 需要持续更新和维护的产品 | Sketch（旧版） |
| **按效果付费** | 价值可直接量化的服务 | 价值难以归因的场景 | 部分广告、销售工具 |
| **混合模式** | 大多数企业产品 | — | 基础订阅 + 超额按用量 |

### 免费增值的设计原则

| 原则 | 说明 |
|---|---|
| **免费层必须有独立价值** | 不是"免费试用 14 天"，是一个长期可用的免费版本 |
| **转换点在价值感知最深处** | 不是随机限制功能，而是用户刚好需要"更多"的时刻 |
| **免费用户必须有传播价值** | 要么变成付费用户，要么带来付费用户——否则是亏本生意 |
| **免费层成本必须可控** | AI 推理成本高的产品，免费层必须设硬性的用量上限 |

## 定价心理和锚定

### 价格锚定

用户不是绝对判断价格贵不贵，而是相对判断——参照你给他们的第一个价格锚点。

| 技巧 | 做法 | 效果 |
|---|---|---|
| **三选项效应** | 提供低价/中价/高价三个选项 | 大多数人选中价——如果只有两个选项，他们会选低价 |
| **标杆选项** | 设一个明显更贵但提供"所有功能"的选项 | 不是为了卖它——是为了让次高价看起来合理 |
| **价格从高到低展示** | 网页/报价单从左到右从贵到便宜 | 用户从高锚点开始思考——"便宜"是相对的感觉 |
| **拆分为小单位** | "每天只需 3 元"而非"每月 99 元" | 降低感知痛苦——虽然总数一样 |

### 免费的力量（及其陷阱）

"免费"不是价格——是根本不同的心理类别。用户对免费和 1 元之间的感知差距远大于 1 元和 10 元之间的差距。

**何时使用免费**：
- 需要网络效应（更多人用 = 产品更好）
- 边际成本接近零（如软件分发）
- 免费用户能转化为口碑传播

**何时不要免费**：
- 边际成本高（如 AI 推理）
- 用户价值高但需要销售转化
- 免费会吸引非目标用户噪音

## 价格测试

不要问用户"你愿意付多少钱"——人会高估自己的支付意愿。用以下方法代替：

| 方法 | 做法 | 可靠性 |
|---|---|---|
| **Van Westendorp 模型** | 问四个问题：太便宜/便宜/贵/太贵分别是多少 | 中（比直接问好，但仍有偏） |
| **A/B 价格测试** | 不同用户看到不同价格，看转化率和收入 | 高 |
| **看实际行为** | 流失用户的付费金额 vs 留存用户 | 极高——行为不说话，只行动 |
| **竞品代理** | 竞品的定价 = 市场已接受的锚点 | 中（竞品可能定价错误） |

### 涨价策略

| 策略 | 做法 | 风险 |
|---|---|---|
| **对新人涨对老人不变** | 新价格仅对新用户生效 | 低——老用户感到被尊重 |
| **涨价值不涨价** | 增加功能同时提价，用户感知是"更值" | 低 |
| **年度涨幅** | 每年固定小幅上涨（如 5%），用户预期内 | 低 |
| **一刀切涨价** | 所有用户同时涨价 | 高——可能引发集体流失 |

## YrY 定价考量

### 当前状态：内部工具

YrY 当前没有对外定价——三个项目都是内部使用。但需要为可能的未来商业化做好准备。

### 未来定价模型建议

| 产品 | 建议模型 | 理由 |
|---|---|---|
| YiAi API（对外） | 按用量 + 免费层 | AI 推理有边际成本，按用量最公平；免费层吸引开发者 |
| YiVad 企业版 | 按席位订阅 | 管理后台的典型定价方式 |
| YiPet | 免费增值 | 扩展的传播价值高，免费层有独立价值 |
| YiKnowledge（公开版） | 免费 + 增值内容 | 知识库公开可吸引用户，增值内容（行业报告）付费 |

### 定价前需要先回答的问题

1. 用户从使用这个产品中获得的可量化经济价值是多少？
2. 现有的替代方案（包括"什么都不用"）的成本是多少？
3. 谁是购买决策者？他们的预算来自哪个部门？
4. 竞品怎么定价？我们的差异化值得溢价吗？

## 核心产出

- 定价模型选择及理由
- 三层价格方案（如有）
- Van Westendorp 调研或 A/B 测试结果
- 涨价策略和沟通计划

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 成本加成定价 | 无视价值——把最有价值的产品卖成白菜价 | 成本是底线，价值是价格 |
| 竞品定价跟从 | 假设竞品定价合理——它们可能也是错的 | 竞品价格是参照，不是答案 |
| 怕涨价 | 通胀在涨、价值在涨、成本在涨——价格不涨等于降价 | 用年度小幅涨价建立预期 |
| 过度细分 | 7 个定价层让用户决策瘫痪 | 3 个选项是最佳设计 |
| 免费层没有转化路径 | 免费用户永远不需要付费 | 在"刚好需要更多"的时刻设转换点 |
