# 干系人管理

> **作为**高管，**我想要**系统性地识别和管理关键的干系人关系，**以便**推动那些不由我直接控制、但依赖多方协作的目标。
>
> **核心洞见**：职级越高，你越少通过"命令"来完成工作，越多通过"影响"来驱动结果。干系人管理不是办公室政治——是在没有直接汇报关系的情况下推动跨组织目标所需的核心能力。

## 干系人识别

### 权力-利益矩阵

将干系人按两个维度分类：

```
        高权力
          │
  满足他们 │ 紧密管理
  (Keep    │ (Manage
  Satisfied)│ Closely)
          │
──────────┼────────── 利益相关度
          │
  监控     │ 保持知情
  (Monitor)│ (Keep Informed)
          │
        低权力
```

| 象限 | 策略 | 沟通频率 | 沟通内容 |
|---|---|---|---|
| **高权力+高利益** | 紧密管理——深度参与、频繁沟通 | 每周或随时 | 关键决策、进展、风险、需要他们做什么 |
| **高权力+低利益** | 满足他们——保护他们的利益，但不过度沟通 | 月度或季度 | 高层摘要、与他们的目标相关的信息 |
| **低权力+高利益** | 保持知情——让他们知道进展，寻求执行层面的输入 | 双周或月度 | 进展更新、近期里程碑 |
| **低权力+低利益** | 监控——不需要主动沟通，但注意状态变化 | 季度或触发式 | 重大变化时通知 |

### YrY 干系人矩阵（示例）

| 干系人 | 权力 | 利益 | 象限 | 策略 |
|---|---|---|---|---|
| 用户/团队（内部） | 高 | 高 | 紧密管理 | 周会、决策透明、优先响应 |
| 投资人/董事会（如有） | 高 | 中 | 满足 | 月度更新、季度董事会 |
| 开源社区（Ollama等） | 中 | 中 | 保持知情 | 关注动态、参与讨论 |
| Chrome Web Store | 高 | 低 | 满足 | 合规跟踪、政策更新关注 |
| 行业分析师/媒体 | 低 | 中 | 监控 | 按需 |

## 影响力策略

在没有汇报关系的情况下推动事情：

### 六种影响力来源

| 来源 | 定义 | 何时使用 | 过度使用的风险 |
|---|---|---|---|
| **专业权威** | "我在这件事上有深度经验" | 需要技术/业务判断时 | 被视为傲慢 |
| **关系信任** | "我们合作过，你信任我的判断" | 需要快速决定时 | 依赖过度，忽视新声音 |
| **数据说服** | "数据指向这个方向" | 有可信数据、有人抵触直觉判断时 | 数据可以被操控 |
| **共同目标** | "这对我们共同在乎的目标有利" | 跨团队协作、资源争夺时 | 目标不真共有 |
| **互惠交换** | "如果这次你支持我，下次我支持你" | 需要短期让步时 | 变成交易关系 |
| **合法权力** | "这是我的职责范围" | 明确在管辖范围内时 | 损害关系，引起抵触 |

**原则**：前三种（专业、关系、数据）是最可持续的影响力来源。后三种（目标、互惠、权力）在特定场景下有效但不能长期依赖。

### 影响力对话结构

在面对无汇报关系的人推动决策时：

```
1. 共同目标
   "我们都想让 YiKnowledge 的 RAG 检索更准，这对 YiVad 和 YiPet 的用户体验都很关键。"

2. 现状和差距
   "目前竞品信息的检索准确率是 70%，但我们发现用户在竞品查询场景下尤其容易失望。"

3. 建议和逻辑
   "我建议 Q4 集中投入 40% 的工程资源做检索优化。原因是竞品窗口期还有 12 个月。"

4. 我需要你做什么
   "我需要你支持这个优先级决策——在 Q4 OKR 讨论中，帮我把这个放在 P0。"

5. 这对你意味着什么
   "如果检索准确率提升，YiPet 的用户体验会直接受益——你们也不用在侧边栏里翻 3 页找相关信息了。"
```

## 干系人冲突处理

### 冲突信号识别

| 信号 | 含义 | 行动 |
|---|---|---|
| 对方开始 CC 更多人 | 他们在建立防御、准备升级 | 主动约 1:1，了解顾虑 |
| 邮件变长、文字变正式 | 对话从解决问题变成保护立场 | 停止邮件往来，面对面或语音沟通 |
| 对方在别的会上提你负责的问题 | 信任在降低 | 私下问"我注意到你在 X 会上提到了 Y——有什么我没做好的吗？" |
| 决策被推到下一层 | 你不具备他们需要的决策权或信任 | 检查：是这个决策需要升级，还是你需要修复信任？ |

### 升级前的检查清单

在将冲突升级给共同上级之前：

- [ ] 我是否已和对方 1:1 直接沟通过？
- [ ] 我是否清晰表达了对方的利益，让对方感到被理解？
- [ ] 我们是否已尝试过第三个选项（既非他的也非我的）？
- [ ] 如果升级，上级可能会怎么决定？这个结果对我来说可接受吗？

## 干系人地图维护

### 每月干系人健康检查

| 干系人 | 上次沟通 | 关系温度 | 风险 | 行动 |
|---|---|---|---|---|
|  | 日期 | 热/暖/冷 | 如果关系变冷会怎样 | 下一步沟通计划和关键信息 |

**温度标准**：
- **热**：会主动找你讨论重要问题，你在决策圈内
- **暖**：定期沟通顺利，你在信息圈内
- **冷**：沟通减少或勉强，对方可能在回避或不满

- 干系人权力-利益矩阵
- 关键干系人的影响力策略
- 月度干系人健康检查
- 冲突升级前的检查清单

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 只管理上级 | 忽视横向和下级干系人——执行力的瓶颈往往在平级 | 画完整的干系人地图 |
| 只在需要时才沟通 | 平时不维护关系，需要时才找人——对方不傻 | 持续投资关系，不要在"取款"前才"存款" |
| 只传达不倾听 | 你的每次沟通都在说服——对方觉得不被理解 | 先问"你怎么看"，再说"我的想法是" |
| 把影响力当操纵 | 短期内可能有效，但信任崩塌后寸步难行 | 影响力的基础是可信度，不是话术 |
| 只有一种影响力策略 | 对所有人用同样的方式——错配 | 因人而异：对上用数据、对平级用共同目标、对下级用专业权威 |
