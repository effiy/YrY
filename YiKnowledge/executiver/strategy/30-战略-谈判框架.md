# 谈判框架

> **作为**高管，**我想要**在合作谈判、合同谈判、资源争夺等场景中获得更好结果，**以便**既保护我方利益，又维系长期关系。
>
> **核心洞见**：谈判不是赢输游戏，是价值创造和价值分配的平衡。最差的谈判不是"输"了——是在分配环节争得太凶，毁了创造环节本来可以共同做大的价值。

## 谈判准备：BATNA 分析

BATNA (Best Alternative To a Negotiated Agreement)：如果谈判破裂，你最好的替代方案是什么。

| 要素 | 定义 | 示例 |
|---|---|---|
| **BATNA** | 谈判破裂后最好的替代方案 | 如果和这个供应商谈不拢，排第二的供应商的报价是多少？ |
| **保留价格** | 你能接受的最差结果（低于此就走） | 最高采购价或最低售价 |
| **目标价格** | 你实际想要达到的理想结果 | 合理但偏高的目标 |
| **ZOPA** | 双方保留价格之间的重叠区域 | 卖方最低 80 万，买方最高 100 万 → ZOPA 是 80-100 万 |

**最重要的谈判原则**：你的 BATNA 越强，你在谈判中的位置越强。提升 BATNA 是谈判前最重要的工作——不是提升话术，是提升你不谈的底气。

## 谈判中的三种策略

### 1. 价值创造（做大蛋糕）

在分配之前，先看能不能一起把蛋糕做大。

| 技巧 | 做法 | 示例 |
|---|---|---|
| **交换不对等的价值** | 你用低成本的让步换对方高价值的东西 | 初创公司付不起高额许可费 → 可以给供应商做案例研究/联合PR |
| **揭示隐藏利益** | 不只说立场，说立场背后的利益 | "我们要 X"是立场，"我们需要 X 是因为它能让我们合规通过审计"是利益 |
| **多议题打包** | 不要把每个议题单独谈——打包一起谈更容易创造交换空间 | 价格 + 付款周期 + 服务范围 + 排他条款一起谈 |

### 2. 价值分配（分蛋糕）

当蛋糕无法再做大的时候，进入分配阶段。

| 技巧 | 做法 | 风险 |
|---|---|---|
| **先出价（锚定）** | 第一个出价的人设定了谈判的心理锚点 | 如果出价太离谱，对方可能直接退出 |
| **退让的节奏** | 第一次退让最大，之后每次减半——暗示你正在接近底线 | 太早退让会让对方觉得还有空间 |
| **沉默** | 出价后沉默，等对方回应。大多数人会因不适而先开口 | 对方可能用沉默反击 |
| **红脸白脸** | 甲方-唱红脸，乙唱白脸（需两人配合） | 太明显会被识破，损害信任 |

### 3. 关系管理

| 技巧 | 做法 |
|---|---|
| **对事不对人** | "这个条款对我们来说有风险"而非"你们太过分了" |
| **命名对方的情绪** | "我理解这个条件让你们觉得不公平"——命名情绪降低对抗 |
| **暂时搁置** | "这个话题我们暂时没法达成一致，先放一边，谈其他议题" |
| **不要庆祝** | 谈判结束后不要在对手面前庆祝——你下次还要和他们打交道 |

## 常见谈判场景

### 合作/合同谈判

| 阶段 | 行动 | 常见错误 |
|---|---|---|
| 准备 | BATNA 分析、议题清单、交换空间识别 | 不准备BATNA——不知道"不谈的后果" |
| 开局 | 建立关系，了解对方的核心利益 | 一开始就给出价格——先收集信息 |
| 探索 | 了解对方的真实利益和约束条件 | 假设对方的立场就是利益 |
| 交换 | 打包议题、创造条件性让步 | 单议题逐一谈——每次都变成零和博弈 |
| 收尾 | 书面确认、明确执行的细节 | 握手就算完——不写入书面的细节等于不存在 |

### 资源/预算谈判（内部）

| 技巧 | 做法 |
|---|---|
| **用公司目标说话** | "给 YiKnowledge 更多资源能让 Q4 的 RAG 目标提前达成"——而非"我们团队人不够" |
| **提供选项** | "如果能给我 2 个人，Q4 能达成 X。如果只有 1 个人，只能达成 Y。你的决定？" |
| **打包** | "如果你支持我的预算，我可以帮你在你的关键目标上提供 Z" |

### 冲突/分歧谈判

| 技巧 | 做法 |
|---|---|
| **区分立场和利益** | 双方站立的"立场"可能是对立的，但背后的"利益"通常不对立 |
| **寻找共同敌人** | 把冲突重新框架为"我们一起对抗这个外部挑战" |
| **升级前的一步** | 在正式升级给老板之前，"如果我们升级，老板可能会怎么决定？那会是我们都能接受的结果吗？" |

## YrY 谈判场景

| 场景 | 类型 | 关键准备 |
|---|---|---|
| 技术供应商选型（如考虑使用付费 API） | 合同谈判 | BATNA：其他供应商报价 + 自建替代方案成本 |
| YiPet Chrome Store 合规沟通 | 政策谈判 | BATNA：了解上诉流程和案例 |
| 内部三项目资源分配 | 资源谈判 | 不争"谁重要"——用 OKR 数据说"哪个投入产出比更高" |
| 可能的未来：投资人条款谈判 | 合同谈判 | BATNA：其他投资意向、不融资的增长计划 |

## 核心产出

- 谈判准备清单（BATNA + 利益分析 + 交换空间）
- 议题打包方案
- 谈判后总结（达成的一致 + 未解决的 + 关系评估）

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 不准备 BATNA | 你不知道底线在哪，容易接受不该接受的条件 | 花 30% 的谈判准备时间在 BATNA 上 |
| 立场谈判 | 各守立场互不退让，谁都不愿意"输" | 区分立场和利益——在利益层面寻找创造性的解决方案 |
| 一开始就亮底牌 | 对方知道你的底线后，所有谈判空间消失 | 用条件性让步："如果你能做 X，我可以在 Y 上让步" |
| 赢了战斗输了关系 | 这次拿到了想要的条件，但对方不再信任你 | 检查：谈判结束后，对方是否愿意再次与你合作？ |
| 口头协议不落纸 | 记忆会不一致——双方都记得"对自己有利的版本" | 24 小时内发出书面确认邮件 |
