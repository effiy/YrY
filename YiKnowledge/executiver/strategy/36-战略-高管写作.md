# 高管写作

> **作为**高管，**我想要**用清晰、简洁、有说服力的文字传达战略和决策，**以便**文字成为我影响力的放大器而非瓶颈。
>
> **核心洞见**：写作不是"把想好的写下来"——写作就是思考。写不清楚通常不是表达问题，是想不清楚。这么说来，写作是高管最诚实的思考质量检测仪。

## 高管写作的核心原则

### BLUF (Bottom Line Up Front)

军事和新闻写作的铁律：**结论在前，背景在后**。

对比：
- 差："最近我们团队做了很多关于用户反馈的分析，发现了一些有趣的数据，经过几周讨论..."（读者在第 3 段才知道你要说什么）
- 好："我们建议 Q4 集中 40% 工程资源投入 YiKnowledge RAG 优化。原因如下：1) ... 2) ..."

**原则**：假设读者随时会停止阅读。他们读到的第一句话必须包含最重要的信息。

### 简洁的强制手段

| 规则 | 说明 |
|---|---|
| **一页原则** | 任何战略文档的第一稿不超过 1 页。如果 1 页说不清楚，不是页数不够——是你还没想清楚 |
| **短句优先** | 超过 30 字的句子拆成两句。长句是读者的迷宫 |
| **每段一个观点** | 段落的第一个句子应该能独立传达整个段落的核心信息 |
| **删掉"我认为"和"我觉得"** | 你的名字在发件人栏——每句话都是你的观点，不需要标注 |
| **数据替代形容词** | "大幅提升"→"提升了 40%"；"显著改善"→"从 3 天缩到 1 天" |
| **主动语态** | "我们决定做 X"而非"X 被决定做"——让谁做的决策一目了然 |

### 三段验证

写完任何重要文档后，用三个标准自检：

1. **5 秒测试**：5 秒内扫读，能否抓到核心信息？（如果不能——BLUF 没做好）
2. **朗读测试**：大声朗读全文，有哪里读起来别扭？（如果能读顺——逻辑没问题）
3. **同事测试**：给一个不了解背景的同事看，问"你觉得我要传达什么"？（如果和你的意图一致——写作成功）

## 常见文档类型的写法

### 决策备忘录

推动一个重大决策时使用的文档。

```
# 决策：{一句话决策描述}

## 建议
{你的推荐方案，1 句话}

## 背景
{读者需要知道的 3-5 个关键事实}

## 选项
| 选项 | 优点 | 风险 | 置信度 |
| A    |      |      | 高/中/低 |
| B    |      |      | 高/中/低 |
| 不决定 |    |      | — |

## 为什么选 A 而不是 B
{分析的核心逻辑，而非数据罗列}

## 如果决定
{下一步是什么，谁在什么时候做什么}

## 如果不决定
{成本是什么，窗口期还有多久}
```

### 战略文档

年度战略或重大战略转向的文档。

```
# {年份/主题}战略

## 一句话战略
{不超过 20 字——用于电梯对话和全员会议的第一句}

## 我们为何改变
{3-5 句话——现状、变化、不改变的代价}

## 战略支柱
{3 个方向，每个附 1 段 + 边界定义}

## 不做的事
{至少 3 项明确放弃的方向}

## 资源分配
| 方向 | 资源占比 | 关键里程碑 | 负责人 |

## 风险与假设
{最大的 3 个风险 + 如果它们发生，我们的退路}
```

### 周报/月报

不是流水账——是给忙碌的读者的摘要。

```
# {团队/公司}周报 — {日期}

## 最重要的 1 件事
{读者如果只能记住一件事，希望ta记住什么}

## 进展（好消息）
- {进展 1} — 影响：{具体影响}
- {进展 2}

## 阻碍（我需要帮助的事）
- {阻碍 1} — 需要谁做什么
- {阻碍 2}

## 下周期待
- {下周最重要的 2-3 件事}
```

### 邮件

| 场景 | 结构 |
|---|---|
| **信息通知** | 标题含决定/结论 → 第一句重复标题 → 2-3 个关键点 → 无行动请求 |
| **请求行动** | 标题含 [Action Required] → 第一句说需要什么 → 为什么 → 截止日期 |
| **升级问题** | 标题含 [Escalation] → 第一句说问题和影响 → 我做了什么 → 我需要你做什么 |
| **会议邀请** | 标题含决策→ 第一句说产出 → 必参者+选参者 → 预读材料链接 |

### 全员公告

- 3 段结构：发生了什么 → 为什么（对我们意味着什么）→ 下一步
- 诚实：坏消息不要裹在好消息里——分开说。好消息单独发，坏消息直说
- 有个人色彩：全员信不是你代表公司——是你以 CEO/高管的身份和团队说话。用"我"而非"管理层认为"

## 写作习惯

### 写作流程

| 阶段 | 时间占比 | 活动 |
|---|---|---|
| **思考和大纲** | 50% | 想清楚：读者是谁？他们需要知道什么？我想让他们做什么？ |
| **初稿** | 25% | 快速写——不修改、不回头、不考虑措辞。目标是"有东西可以改" |
| **修改** | 20% | 删掉 30%——任何不必要的话。检查 BLUF、检查短句、检查数据替代形容词 |
| **最后检查** | 5% | 朗读测试、检查错别字、确认所有链接有效 |

**原则**：不要在写的时候改。写和改是不同的认知模式——切换成本极高。

### 建立写作习惯

| 习惯 | 说明 |
|---|---|
| **写决策日志** | 每个重要决定写 3 句话：决定了什么、为什么、如果什么发生变化会重新考虑 |
| **写下你的思考** | 与其在脑中反复琢磨一个问题，不如写下来——写作迫使你把模糊的直觉变成清晰的逻辑链 |
| **用文字替代会议** | 下次有人让你"开个会同步一下"，先写个文档发过去。如果文档引发需要同步讨论的问题——再开会 |

## 核心产出

- 关键文档的写作模板库
- 决策日志（持续更新）
- 写作习惯（每周至少产出 1 篇需要"写作"而非"打字"的内容）

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 边写边改 | 思维在"创造"和"批判"之间反复切换——两者都做不好 | 先写完，再修改——两个阶段完全分离 |
| 为写而写 | 文档写了没人读——因为没有明确的读者和目的 | 写任何东西前回答：谁读？为什么读？读完要做什么？ |
| 语言膨胀 | 用"利用"、"赋能"、"抓手"等词——语言越空洞，思维越空洞 | 用最日常的词——能说"用"不说"利用"，能说"帮"不说"赋能" |
| 永远不迭代 | 追求"写一篇完美的文档"——拖延 | 先写一版"够好的"发出去——读者的反馈是最好的编辑 |
| 忽略格式 | 大段文字墙——读者直接跳过 | 有标题、有表格、有空行——视觉结构 = 逻辑结构 |
