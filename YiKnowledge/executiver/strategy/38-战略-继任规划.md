# 继任规划

> **作为**高管，**我想要**识别组织的关键人依赖并有计划地降低这些风险，**以便**没有人是不可替代的——包括我自己。
>
> **核心洞见**：小团队最大的风险不是竞品、不是现金流、不是技术——是"关键人"。如果一个人离开会让一个产品线停摆 3 个月，你不是在经营公司——你在经营一个由个人持有的期权。继任规划不是在等人要走的时候才做的——那时已经晚了。

## 关键人识别

### 关键人判断标准

不是按职级判断——按"如果这个人明天离开，什么会断裂"：

| 判断维度 | 问题 | 关键性评分 (1-5) |
|---|---|---|
| **知识垄断** | 有没有只有这个人知道的知识（代码逻辑、架构理由、客户关系细节）？ | |
| **技能垄断** | 有没有只有这个人会的技能（特定技术栈、特定工具链、特定领域）？ | |
| **关系垄断** | 有没有只有这个人维护的外部关系（关键客户、开源社区、合作伙伴）？ | |
| **决策垄断** | 有没有只有这个人能做的决策（无人了解背景、无人有胆量）？ | |
| **恢复时间** | 如果这个人离开，相关产品/功能需要多久才能恢复到之前的产出水平？ | |

**关键人 = 任何在两个以上维度得分 4+ 的人**。

### YrY 关键人风险评估

| 角色 | 知识垄断 | 技能垄断 | 关系垄断 | 决策垄断 | 恢复时间 | 风险等级 |
|---|---|---|---|---|---|---|
| YiAi 核心开发者 | 4 | 4 | 2 | 3 | 2 个月 | 高 |
| YiPet 核心开发者 | 4 | 4 | 1 | 3 | 2 个月 | 高 |
| YiVad 核心开发者 | 3 | 3 | 1 | 2 | 1 个月 | 中 |
| CEO | 5 | 3 | 4 | 5 | 4+ 个月 | 极高 |

## 降低关键人依赖的四种方法

### 1. 文档化（降低知识垄断）

| 行动 | 产出 |
|---|---|
| 关键系统架构决策写 ADR | 架构决策记录——不仅仅写"怎么做"，写"为什么这么做" |
| 隐性知识外化 | "如果我不在，你需要知道的 10 件事"——每个关键人维护一份 |
| 代码注释和 README | 每个模块必须有：它是做什么的、为什么存在、怎么跑起来 |

### 2. 交叉培训（降低技能垄断）

| 方法 | 做法 |
|---|---|
| **结对轮换** | 每季度安排不同的人结对——不只是为了代码质量，是为了知识传播 |
| **非舒适区任务** | 故意把不紧急但重要的任务分配给不熟悉的人——有文档和关键人做后盾 |
| **巴士因子演练** | 模拟："如果 X 明天不在，Y 能不能独立完成 Z？"如果不能——Y 需要培训 |

### 3. 关系转移（降低关系垄断）

| 方法 | 做法 |
|---|---|
| **多点接触** | 任何关键外部关系至少两个内部人参与过沟通 |
| **关系文档** | 关键客户/合作伙伴的联系人、沟通历史、偏好——不被锁在个人的脑子里 |

### 4. 决策权下放（降低决策垄断）

| 方法 | 做法 |
|---|---|
| **决策日志** | 重大决策记录：为什么做、谁做的、替代方案是什么 |
| **决策原则公开** | 写下来"当 X 情况出现时，我们的决策原则是..."——即使你不在，团队能做出与你一致的决策 |

参考 [strategy/20-战略-委托授权框架.md](./20-战略-委托授权框架.md) 的委托等级模型。

## CEO 自身的继任

CEO 最常忽视的继任规划是——自己的。

### CEO 的巴士因子检查

| 如果 CEO 明天离开... | 当前状态 | 行动 |
|---|---|---|
| 有人知道所有关键决策的背景和逻辑吗？ | | 写决策日志 + 定期与第二梯队同步战略讨论 |
| 有人能对接投资人/董事会/关键合作伙伴吗？ | | 关键关系至少引入一名第二梯队参与 |
| 有人能做出战略级决策吗？ | | 让第二梯队参与战略讨论——不等到需要他们的那一刻才曝光 |
| 有人知道钱在哪、合同在哪、密码在哪吗？ | | 维护一本"如果我不在"手册 |

### 小团队 CEO 的特殊考量

在 10 人以下的团队：
- 不可能立刻有一个"可以替代 CEO"的人——这正常
- 重点是**过渡能力**而非**替代能力**：如果有人能维持运营 3 个月，让公司不掉下悬崖，就够
- 如果公司只有 CEO 一个人能融资、能定战略、能对接关键伙伴——不是在创业，是在创造一个以自己为中心的系统

## 继任规划的节奏

| 频率 | 活动 |
|---|---|
| **每月** | 知识文档化进展检查——关键人是否在持续外化知识 |
| **每季度** | 关键人风险评估矩阵更新、巴士因子演练 |
| **每半年** | 继任规划评审——关键角色的备份状态、培训进展 |
| **事件驱动** | 关键人离职风险信号——立即启动加速知识转移 |

### 关键人离职风险预警信号

| 信号 | 紧急程度 |
|---|---|
| 连续 2 次 1:1 中情绪低落或回避未来话题 | 高——私下沟通了解情况 |
| 突然开始大量文档化自己的工作 | 中——可能在准备离开 |
| 对长期项目不再有热情 | 中 |
| 频繁请假或迟到 | 低中——生活变故或面试 |
| 在社交媒体上更新履历或增加行业互动 | 中 |

## 核心产出

- 关键人风险评估矩阵（按五个维度打分）
- 每个关键人的"如果我不在"文档
- 交叉培训和知识转移计划
- 季度巴士因子演练记录

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 只在人要走时才做继任 | 知识转移需要时间——突然离职的交接最多覆盖 30% | 持续做知识外化，而不是临阵磨枪 |
| 以为"我是唯一的" | CEO 自以为不可替代——变成了事实 | CEO 主动培养第二梯队，主动分享决策背景 |
| 只关注技术岗位 | 客户关系、市场洞察、文化传承也是垄断领域 | 覆盖四个垄断维度 |
| 知识文档写了没人维护 | 6 个月前的文档比没文档更危险——给人虚假的安全感 | 每个关键文档有负责人和定期更新机制 |
| 把继任规划等同于"指定接班人" | 早期公司指定一个人接手 CEO——这个人可能 2 年后已经不在了 | 建立系统能力而非依赖特定个人 |
