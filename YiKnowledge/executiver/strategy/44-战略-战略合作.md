# 战略合作与联盟

> **作为**高管，**我想要**系统性地评估、构建和管理战略合作关系，**以便**用有限的资源撬动更大的市场和技术杠杆，同时避免合作变成"签了 MoU 就再也没有后续"的表面关系。
>
> **核心洞见**：好的合作是 1+1=3——双方都能获得自己单独做不出来的价值。坏的合作是 1+1=0.5——双方的管理注意力被消耗、团队被分心、最终什么都没落地。合作失败的首要原因不是合作对象错了，是合作的目标和成功标准从一开始就不清晰。

## 合作类型

| 类型 | 定义 | 深度 | 适用场景 | 示例 |
|---|---|---|---|---|
| **流量/渠道合作** | 互相导流、联合营销 | 浅——低管理成本 | 快速获取新用户 | Chrome Web Store 推广、开源社区合作 |
| **技术集成合作** | API 对接、技术互通 | 中——有技术投入 | 产品能力互补 | YiAi API 被第三方平台集成 |
| **联合产品合作** | 共同开发、联合产品 | 深——高投入高回报 | 创造单方做不出的产品 | 与行业数据供应商联合开发垂直 AI 工具 |
| **股权/合资合作** | 互相持股或成立合资实体 | 最深——战略绑定 | 长期不可逆的战略关系 | 与关键模型供应商的战略绑定 |

## 合作评估框架

### 步骤 1：合作就绪度检查

在接触潜在合作伙伴之前，先检查自己：

| 检查项 | 问题 | 未就绪的信号 |
|---|---|---|
| **产品稳定性** | 合作涉及的产品/API 是否稳定运行 ≥ 3 个月？ | 还在频繁改 API、改架构——合作方集成完你就改了 |
| **对接资源** | 有没有一个人能全职或半职负责这个合作的技术和商务对接？ | "谁有空谁对接"——合作方等不到回应 |
| **合作的价值主张** | 你能一句话说清对方为什么应该跟你合作吗？ | 你自己都讲不清——"我们产品挺好的，合作共赢" |

**原则**：如果三个检查项中有任何一条未就绪——先解决内部问题，再找外部合作。

### 步骤 2：合作方评估

| 维度 | 评估问题 | 红灯信号 |
|---|---|---|
| **战略匹配** | 双方的战略方向是一致的还是可能冲突？ | 合作方的长期战略与你构成竞争——现在的合作是培养未来的对手 |
| **互补性** | 合作带来的能力是你自己做不了的，还是懒得做？ | 你"懒得做"的事，合作方也不会用心做 |
| **投入意愿** | 对方有没有明确的负责人和资源承诺？ | "我们很感兴趣"但没有具体的对接人——这是礼貌的拒绝 |
| **文化匹配** | 双方的工作节奏和决策速度匹配吗？ | 你迭代周期 2 周，对方 6 个月——合作会在等待中死亡 |
| **不对等风险** | 双方体量悬殊吗？较弱的一方会不会被"吃掉"或被弃？ | 你是 10 人公司，对方是 10000 人——你的优先级在对方那儿永远是第 99 位 |

### 步骤 3：定义成功的合作

合作最常见的失败模式：签约那天是合作关系的最高点——之后什么都没有发生。

**合作画布**（合作前双方对齐）：

| 要素 | 你的 | 合作方的 |
|---|---|---|
| 核心目标（一句话） | | |
| 成功 6 个月后什么样子 | | |
| 失败的话什么样子 | | |
| 我们的投入（人/钱/技术） | | |
| 对方需要做的（具体） | | |
| 不可接受的底线 | | |
| 退出条件 | | |

**原则**：如果这份合作画布不能让双方都觉得"值得做"——不要开始合作。握手不产生价值，行动才产生。

## 合作的生命周期

### 阶段 1：探索（1-3 个月）

- 目标：验证合作假设而非构建完整方案
- 形式：小范围试点、PoC、单一场景集成
- 投入：≤ 1 个人 × ≤ 20% 时间
- 退出条件：试点未达双方预期的成功标准

### 阶段 2：构建（3-6 个月）

- 前提：阶段 1 的成功标准达成
- 目标：建立可持续的合作运营
- 形式：正式的技术集成、联合 GTM、定期评审
- 投入：有明确的负责人和资源分配

### 阶段 3：规模化（6-18 个月）

- 前提：阶段 2 证明了合作的商业价值
- 目标：扩大合作范围、探索新领域
- 形式：联合产品、收入分成、更深度的集成

### 阶段 4：演进或退出

- 定期评审（每季度）：合作仍然值得双方的投入吗？
- 演进：拓宽合作范围、加深合作层次
- 退出：优雅地减小范围或结束合作——保留关系，坦诚沟通原因

## 小公司的合作陷阱

YrY 当前阶段最需要警惕的合作陷阱：

| 陷阱 | 描述 | 防御 |
|---|---|---|
| **大公司"礼貌约会"** | 大公司 BD 团队的目标是签 MoU——签完他们的 KPI 就完成了。你的目标是产品落地——签完才刚刚开始 | 不给独家、不投入大量资源、先要求对方证明投入意愿（小试点、指定对接人） |
| **合作当融资** | "和 XX 合作能让投资人觉得我们厉害"——这不是合作的理由 | 合作的价值主张必须不依赖于融资故事 |
| **太多合作分散精力** | 同时推进 5 个合作 = 每个合作都没有深度 | 同一时间最多 2 个活跃合作 |
| **没有退出机制** | 合作变成沉没成本——"我们已经投入这么多了" | 每个合作在开始时设定明确的评审点和退出条件 |

## 核心产出

- 合作画布（双方对齐文档）
- 合作评审日历（季度）
- 合作健康检查（阶段 2+ 的合作）

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 签约 = 成功 | 签约那天应该是最低点——之后才是真正的价值创造 | 签约后 30 天内必须有具体行动产出 |
| 合作无负责人 | "谁有空谁对接"——合作在组织内部成了孤儿 | 每个合作有一个明确的内部 owner |
| 话语权悬殊时签独家 | 小公司给大公司独家——把自己的命运绑在一艘巨轮的一个小舵上 | 不签独家；不确定时要法律顾问审核 |
| 只有高层对话没有执行层对接 | CEO 握手,然后两个团队都不知道该做什么 | 合作启动时,高层定方向 + 执行层定行动计划 |
| 忘记评审 | 合作在自动驾驶中撞墙 | 每季度评审：是否仍然值得？ |
