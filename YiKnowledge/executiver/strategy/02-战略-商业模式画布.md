# 商业模式画布

> **作为**战略家，**我想要**绘制业务如何创造、交付和捕获价值，**以便**识别差距、验证假设和设计商业模式改进。
>
> **核心洞见**：一个伟大的产品不等于一个伟大的商业模式。商业模式画布帮你确保所有 9 个构建块协调一致——如果产品或渠道或收入模式之间有矛盾，画布会比财务模型更早暴露出来。

## 定义

商业模式画布 (BMC) 是一个包含 9 个构建块的可视化框架：

```
┌──────────────────┬──────────────────┬──────────────────────┐
│  关键伙伴        │  关键活动         │  价值主张             │
│                  │                  │                      │
│  谁帮助我们？    │  我们做什么？     │  我们交付什么价值？    │
│                  ├──────────────────┤                      │
│                  │  关键资源         │                      │
│                  │                  │                      │
│                  │  我们需要什么资产？│                     │
├──────────────────┴──────────────────┼──────────────────────┤
│       成本结构                      │     收入来源           │
│                                     │                      │
│  主要成本是什么？                   │  我们如何赚钱？        │
└──────────────────┬──────────────────┴──────────────────────┘
                   │
┌──────────────────┼──────────────────┐
│   客户关系       │   客户细分        │
│                  │                  │
│  我们如何互动？   │  我们的客户是谁？  │
├──────────────────┼──────────────────┤
│     渠道         │                  │
│                  │                  │
│  我们如何触达？   │                  │
└──────────────────┴──────────────────┘
```

## 适用场景

- 设计新业务或产品线
- 评估商业模式转向
- 理解为什么看似好的产品不具商业可行性
- 跨职能团队对齐于业务运作方式
- 投资人路演准备：你能在一页内解释业务吗？
- 分析竞品商业模式的差异

## 设计步骤

### 步骤 1：从客户细分和价值主张开始

这两者是画布的核心。用[价值主张画布](./11-战略-价值主张画布.md)验证这两个块，再填充其余部分。

**客户细分**——你在为谁创造价值？
- 大众市场、利基市场、细分市场、多元化市场、多边平台？
- 列出具体细分，不是"所有人"
- 每个细分要有明确的规模估算

**价值主张**——你解决什么问题？
- 新颖性、性能、定制化、设计、价格、品牌、便利？
- 为每个细分量身定制地说清楚交付的价值

### 步骤 2：填充面向客户的块

**渠道**——如何触达每个细分？
- 认知 → 评估 → 购买 → 交付 → 售后
- 自有 vs 合作伙伴渠道；直接 vs 间接
- 每个阶段的转化率估算

**客户关系**——每个细分期望什么类型的关系？
- 人工协助、自助服务、自动化、社区、共创？
- 获客 vs 留存 vs 升级的侧重

**收入来源**——每个细分如何支付？
- 资产销售、订阅、许可、按用量收费、广告、免费增值？
- 一次性 vs 经常性；固定 vs 动态定价
- 各收入来源占比估算

### 步骤 3：填充基础设施块

**关键资源**——需要什么资产？
- 物理、知识产权、人力、财务？
- 交叉参考 [VRIO](./12-战略-VRIO框架.md) 识别哪些资源是战略性的

**关键活动**——什么必须做得特别好？
- 生产、问题解决、平台/网络管理？
- 这些是让商业模式运转的活动

**关键伙伴**——依赖谁？
- 战略联盟、竞合、合资、供应商关系？
- 为什么合作？优化、降低风险、资源获取？

### 步骤 4：填充财务块

**成本结构**——什么驱动成本？
- 成本驱动 vs 价值驱动？
- 固定成本、可变成本、规模/范围经济？

### 步骤 5：验证假设

每个块在验证之前都是假设。对每个块，问：

| 块 | 验证问题 |
|---|---|
| 客户细分 | 与 10+ 个该细分客户交谈过吗？ |
| 价值主张 | 客户能否在没有提示的情况下说出价值？ |
| 渠道 | 每个渠道的获客成本是多少？ |
| 收入来源 | 支付意愿的证据是什么？ |
| 关键资源 | 这些资源真的是 VRIO 吗？ |
| 关键活动 | 我们确实比竞品做得更好吗？ |
| 关键伙伴 | 如果伙伴失败，备选方案是什么？ |
| 成本结构 | 规模化后的单位经济是多少？ |

### 步骤 6：评估商业模式

| 评估维度 | 问题 |
|---|---|
| **一致性** | 各块是否相互加强？（如自助渠道 + 自动客户关系 + 低成本结构） |
| **差异化** | 模型与竞品不同，还是仅执行得更好？ |
| **可扩展性** | 模型随规模提升还是恶化？ |
| **防御性** | 防止竞品复制此模型的壁垒是什么？ |

## YrY 商业模式画布分析

### YiVad + YiAi + YiPet 的协同商业模式

| 块 | YrY 表现 |
|---|---|
| 价值主张 | 完整 AI 开发生命周期——从知识管理到智能助手到管理后台 |
| 客户细分 | 内部团队（当前阶段）；未来可向外部开发者提供 YiAi API |
| 渠道 | 内部部署；YiPet 通过 Chrome 商店分发 |
| 客户关系 | 内部协作；YiPet 用户通过扩展自服务 |
| 收入来源 | 当前为内部效率工具（节约成本）；未来可 API 收费、企业版授权 |
| 关键资源 | YiKnowledge 知识库（RAG 数据源）、YiAi RPC 协议、MongoDB 数据 |
| 关键活动 | AI 模型推理、RAG 检索优化、三项目 RPC 协议维护 |
| 关键伙伴 | Ollama（开源 LLM）、Chrome Web Store（分发） |
| 成本结构 | 人力 > 算力 > 基础设施；YiAi Ollama 推理是主要可变成本 |

## 核心产出

- 填完的 9 块画布
- 假设登记表含各块验证状态
- 一致性/差异化/可扩展性/防御性评估
- 下一步要测试的最危险假设列表

## 反模式

| 反模式 | 为何失败 | 正确做法 |
|---|---|---|
| 一次填完画布 | 每个块都是猜测，不是假设 | 当作活文档；分多次填充，每次有证据支撑 |
| "所有人"当作客户细分 | 无差异化的价值主张 | 按不同的待办任务、痛点和支付意愿细分 |
| 收入脱离成本现实 | 收入乐观，成本低估 | 自下而上建模单位经济；压力测试假设 |
| 忽视各块间的匹配 | 不一致的模型（如高端价值主张 + 折扣渠道） | 检查内部一致性：每块的选择都会影响其他块 |
| BMC 当成战略 | 画布描述模式，而非战略 | 用[产品战略框架](./08-战略-产品战略框架.md)将 BMC 与其他分析合成 |
| 不更新 | 商业模式随市场变化 | 每季度重评，重大市场变化时立即重评 |
