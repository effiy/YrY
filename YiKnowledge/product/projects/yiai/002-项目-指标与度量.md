# YiAi 项目指标与度量

> **作为** PM / 后端工程师 / Leader，**我想要**一页看懂 YiAi 全部量化指标（北极星、AARRR、SLO、字典 20+），**以便**周会只花 10 分钟过指标趋势就知道「要不要排期修」。

## 北极星指标表

| 北极星指标 | 定义 | 公式 | 谁负责 | 当前值（2026-10-07） | Q4 目标 | 更新频率 |
|---|---|---|---|---|---|---|
| **RAG MRR@5**（Mean Reciprocal Rank @ Top5） | 对 500 条内部标准查询集，YiAi RAG 返回的 Top5 命中文档中，第一个「正确命中」排名的倒数的平均值。衡量「检索第一名相关」的能力 | `MRR@5 = mean( 1 / rank_of_first_relevant )`，对 500 条测试集逐条计算后平均；正确命中标注由 Curator 每两月重标 | 产品 PM + RAG 模块 Owner | 0.58（500 条离线评测基准，建立于 2026-09） | ≥ 0.72 | 每两月全量评测 + 每日对最近 100 条会话采样滚动评测（指标字典 M02） |

## AARRR 五阶段漏斗表

| 漏斗阶段 | 指标名（#1） | 单位 | 计算公式 / 口径 | 阈值（危险 / 警告 / 健康） |
|---|---|---|---|---|
| **获客 Acquisition** | 每周新注册 / 首次触达 YiAi 的应用数（YiVad 新组织 + YiPet 新设备去重） | 个 / 周 | `count(distinct client_id) where first_seen between now-7d and now`；client_id 由前端上报，YiVad=org、YiPet=device、YiPot=安装包 UUID | < 10 危险 / 10~20 警告 / ≥ 30 健康 |
| **获客 Acquisition** | 开发者文档 /health/observer 主动探测成功数 | 次 / 日 | 外部健康探针（未来）或内部监控对 `GET /health/observer` 的成功 HTTP 200 次数 | < 86,400 危险（探针掉线） / ≥ 86,400 次健康 |
| **激活 Activation** | 首次 RAG 检索成功率（新 client_id 第 1 次调用 RAG 引擎返回 code=0 的比例） | % | `count(first_rag_call_code=0) / count(first_rag_call_total)` 按 client_id 去重周汇总 | < 60% 危险 / 60~75% 警告 / ≥ 85% 健康 |
| **激活 Activation** | 单次会话完成度：用户 10 分钟内 ≥ 3 轮交互（消息）的会话占比 | % | `count_sessions_with(interaction_count ≥3) / count_total_sessions`；窗口=10min 无新消息即会话结束 | < 30% 危险 / 30~45% 警告 / ≥ 55% 健康 |
| **留存 Retention** | W7 周留存：第 1 周有调用的 client_id 在第 7 周仍有 ≥ 1 次 RAG/聊天调用 | % | Cohort 分析，按 client_id first_seen 周分组 | < 20% 危险 / 20~35% 警告 / ≥ 45% 健康 |
| **留存 Retention** | 高频使用占比：周调用次数 ≥ 20 次的 client_id 占活跃 client_id 的比例 | % | `count(client_id where weekly_calls ≥ 20) / count(weekly_active_client_id)` | < 10% 危险 / 10~20% 警告 / ≥ 30% 健康 |
| **收入 Revenue**（内部效率等价） | 平均 RAG 查询延迟 P95（越短 = 节省用户时间 = 效率收入） | 毫秒 | `percentile(response_latency_ms, 95) over 24h`，仅统计 rag.* domain | > 3,000ms 危险 / 1,500~3,000ms 警告 / ≤ 800ms 健康 |
| **收入 Revenue**（内部效率等价） | Agent 自主任务完成率（无需人工介入的 Agent 循环达到「完成」态比例） | % | `count(agent_loops where final_status=completed) / count(total_agent_loops)` | < 40% 危险 / 40~65% 警告 / ≥ 80% 健康 |
| **推荐 Referral** | 跨项目桥接采纳率：YiPet → YiVad 跳转 / YiVad 会话中「打开知识文件」行为的次数 | 次 / 日 | `count(event.type in ('pet_to_vad_jump','vad_open_knowledge_file'))` 日汇总 | < 20 危险 / 20~50 警告 / ≥ 100 健康 |
| **推荐 Referral** | 用户「有帮助」点赞率：knowledge_base 对话中 feedback=positive 的比例 | % | `count(chat_feedback where value=positive) / count(chat_feedback_total)`，过滤 knowledge_base=true 会话 | < 40% 危险 / 40~60% 警告 / ≥ 75% 健康 |

## SLO & 告警分级表（3 行 P0/P1/P2）

| 级别 | 场景 | SLO（服务等级目标） | 测量窗口 | 响应人 | 告警渠道 |
|---|---|---|---|---|---|
| **P0** | 主 API 服务可用率（所有 RPC `POST /` + `/health/observer` 聚合） | ≥ 99.5%（月度）。允许每月最多 216 分钟不可用（30d × 1440min × 0.5%） | 滚动 30 天窗口，每 5 分钟采样 | YiAi Owner + 值班 Backend（周轮换） | 飞书 P0 机器人 @所有人 + 短信（参考 36-prd-告警路由 告警分级 → P0 短信通道）；CICD 流水线失败时联动（参考 07-交付-CICD流水线） |
| **P1** | RAG 首包延迟 P95 + MRR@5 滚动周质量 | ① RAG 查询首字节（TTFB）P95 ≤ 1.5s；② MRR@5 滚动周评测 ≥ 0.60，双条件同时满足率 ≥ 95%（周窗口） | 滚动 7 天窗口；MRR@5 采样每日 100 条已标注会话 | RAG 模块 Owner + 产品 PM | 飞书 P1 告警群；未达标时触发周会 Top3 议题（压测基线见 138-prd-压测） |
| **P2** | 非核心 API（RSS 聚合 / 文件元数据写入 / 审计日志）错误率 | 单端点 5xx 比例 ≤ 2%（小时窗口）；审计日志写入延迟 ≤ 5s（中位数） | 滚动 1 小时窗口，每 1 分钟采样 | 对应 Domain 负责人 | 飞书 P2 告警 Bot 通知；每日日报汇总；熔断器降级参考 106-prd-熔断器 |

## 数据质量 SLA（4 条） + 验收 Checklist（3 条）

### 数据质量 SLA 四项

| # | 数据质量维度 | SLA 定义 | 违反后果 | 修复时限 |
|---|---|---|---|---|
| D1 | **准确性**（Accuracy） | 指标 M01~M24 与人工抽样对账误差 ≤ ±1%；MRR@5 人工重标与自动评测偏差 ≤ ±0.02 | 健康看板当日对应指标显示「?」灰色；PM 不得基于该指标做优先级决策 | ≤ 48 工作小时 |
| D2 | **完整性**（Completeness） | 每小时采集周期内，指标丢失行数（空值、-1 占位） ≤ 0.1%；单日总丢失指标点 ≤ 50 | 仪表盘面板「-」灰框；连续 2 小时不完整触发 SLO 数据侧 P2 告警 | ≤ 24 工作小时 |
| D3 | **时效性**（Timeliness） | 全部指标到达仪表盘的端到端延迟 P95 ≤ 15 分钟（产生 → 入仓 → 面板可见）；MRR@5 日采样当日 10:00 前必达 | 面板显示「迟滞 N 分钟」黄牌；≥ 1 小时未更新进入 PM 早会 Top3 | ≤ 2 工作小时（面板不刷新） |
| D4 | **新鲜度**（Freshness） | 采集端埋点代码版本 ≥ 当前发布版本 - 2；MRR@5 全量评测集标注不早于 60 天；指标字典文档 updated_at ≤ 90 天 | 指标旁显示「⚠️ stale」图标；Curator 季度审查时高亮 | ≤ 5 工作天（埋点升级）/ ≤ 2 工作天（字典 updated） |

### 验收 Checklist（3 条）

- [ ] **数据对账**：连续 7 天抽样比对 M01（可用率）、M02（MRR@5）、M07（活跃）三条关键指标，人工/系统差值 ≤ ±1%，D1 满足
- [ ] **故障演练**：模拟采集脚本挂起 2 小时，完整性 D2、时效性 D3 告警正确触发 → 飞书 Bot 推送 → 修复 SLA 时限内面板恢复正常
- [ ] **字典对齐**：指标字典 24 条的「采集点」字段 100% 能在 YiAi 代码或 YiKnowledge PRD 文档中定位到具体文件路径 + 行号（可搜索命中），Curator 抽样 ≥ 10 条全中
