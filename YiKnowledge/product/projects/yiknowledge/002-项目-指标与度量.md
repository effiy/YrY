# YiKnowledge 项目指标与度量

> **作为** PM / 工程师 / Curator / Leader，**我想要**一页看懂 YiKnowledge 全部指标（北极星条目新鲜度 < 30 天、Frontmatter 合规率、模板复用率、策展流水线 5 段 SLA、RAG 知识命中率），**以便**每周一策展巡检 + 每季度审查时 10 分钟过仪表盘就知道「先修哪 10 份文档」。

## 北极星指标表

| 北极星指标 | 定义 | 公式 | 谁负责 | 当前值（2026-10-07 基线） | Q4 目标 | 更新频率 |
|---|---|---|---|---|---|---|
| **条目新鲜度 < 30 天占比** | YiKnowledge 仓库下全部 .md 叶子文档（排除 README / INDEX / 归档目录 archive/）中，Frontmatter `updated` 字段日期距离「当前日期」≤ 30 天的文档条数占总文档数的比例；等同于策展人视角「活跃条目率」 | `新鲜度占比 = count( md_files where updated_at ≥ today - 30d AND NOT path IN (README.md, INDEX.md, */archive/*) ) ÷ count( 全部 md_files 排除同路径 )`；updated 缺失 = 默认「陈旧」计入分母不计入分子；计算脚本：`scripts/freshness_check.sh`（规划中） | Curator 总负责人 + 5 项目 Owner 分工包片 | 45%（2026-10-07 全量扫描基线：~200 份 .md 文档中 90 份 updated 在 9 月后，排除 README/INDEX） | ≥ 80%（2026-12-31 Q4 结束时） | 每周一 10:00 自动快照（Curator 巡检日）+ 每季度审查全量（QBR 前一日） |

## AARRR 五阶段漏斗表（知识生命周期视角：Acquisition=采集/Activation=规范化/Retention=留存/复用=Revenue/推荐=跨项目传播）

| 漏斗阶段（知识语义） | 指标名（#1 / #2） | 单位 | 计算公式 / 口径 | 阈值（危险 / 警告 / 健康） |
|---|---|---|---|---|
| **Acquisition 知识采集入仓** | 每周新增长条目标（按 Frontmatter created 日期 7 天窗口） | 份 / 周 | `count(md where created in [today-7d, today])`；排除模板本身与空壳 COPY | < 5 危险 / 5~15 警告 / ≥ 25 健康（Q4 稳态） |
| **Acquisition 知识采集入仓** | 新建条目模板复用率：使用 curator/templates/ 10 份模板骨架新建的条目 / 新建条目总数 | % | 对比新建条目 Frontmatter 顺序与字段集合与 templates/ 样板一致度 ≥ 80% 即算复用 | < 50% 危险 / 50~80% 警告 / ≥ 90% 健康（01-项目-管理 P0 对齐） |
| **Activation 规范化激活** | Frontmatter 13 字段合规率：title/tags/category/created/updated/source/type/status/lifecycle/review_cycle/roles/benefit/related 全部字段存在且非空（benefit/acceptance_criteria/related 三大必填不能空串） | % | `count(合规) / count(总文档)`；校验规则见 governance/00002-治理-治理规范.md；字段缺失 = 不合规；空数组/空字符串 benefit = 不合规 | < 70% 危险 / 70~95% 警告 / ≥ 98% 健康（01-项目-管理 P0） |
| **Activation 规范化激活** | 就绪检查通过率：通过 governance/00004-治理-就绪检查清单.md 全部 8 项勾选项的条目 / 进入「收件箱 → 分类处理 → 就绪检查」流水线条目的总数 | % | `count(passed_04_checklist) / count(entered_pipeline)`；就绪检查 8 项见 04 文件 | < 40% 危险 / 40~70% 警告 / ≥ 85% 健康 |
| **Retention 知识留存（不老化过时）** | 条目 90 天留存率（lifecycle=active 的条目在 90 天后仍然 status=stable 且 updated ≤ 90 天未被标记 deprecated） | % | Cohort：90 天前 lifecycle=active 文档在今日仍然 active+updated 合格 / 当日 active 数；等价「知识不老化率」 | < 55% 危险 / 55~75% 警告 / ≥ 85% 健康 |
| **Retention 知识留存（不老化过时）** | 僵尸文档率（updated > 180 天 + lifecycle=active + status=stable，无任何引用 linked_from=0）反向指标 | % | 反向越低越好；`count(僵尸文档) / count(total_active)`；僵尸文档 6 个月未更新 + 无任何 related 被引用 | > 15% 危险 / 5~15% 警告 / < 3% 健康 |
| **Revenue 复用价值（被消费）** | YiAi RAG 检索知识命中率：YiAi RAG 引擎 Top5 返回结果中命中 YiKnowledge 路径的文档数 / 总返回数 × 100% | % | 「命中率」= 含 `YiKnowledge/` 前缀的 sources 引用 / 5 × 100%；仅统计 knowledge_base=true 会话 | < 30% 危险 / 30~50% 警告 / ≥ 70% 健康（01-项目-管理 成功指标 4 对齐） |
| **Revenue 复用价值（被消费）** | 策展人复用率：PM/工程师在新建 PRD / ADR 时，related 字段中引用 ≥ 2 篇 YiKnowledge 已存在文档的 PR 比例 | % | `count(prs_new_docs where related_count ≥ 2) / count(all_prs_new_docs)`；Code Review 时 mentor 检查 | < 20% 危险 / 20~50% 警告 / ≥ 70% 健康 |
| **Referral 推荐传播（跨项目）** | 跨项目引用率：一篇 YiKnowledge 文档（如 lessons/09 跨项目 Hub）被 ≥ 2 个不同项目（YiAi/YiVad/YiPet/YiPot/YiKnowledge 自身）在 related 中引用的文档数 / 总文档数 | % | 「被引用来自 2+ 项目」= 引用方 frontmatter category 属性的 2+ 前缀；统计 00002-治理-治理规范.md 等被多项目引用的经典文档 | < 2% 危险 / 2~8% 警告 / ≥ 15% 健康 |
| **Referral 推荐传播（跨项目）** | 新人 Day3 「我找到了答案」满意度：新人入职第 3 天结束时匿名问卷 1-5 分「YiKnowledge 能回答我的 80% 入门问题吗？」≥ 4 分的比例 | % | `count(score ≥ 4) / count(newcomer_survey_responded)`；每批新人入职发一份 3 题问卷 | < 60% 危险 / 60~80% 警告 / ≥ 90% 健康 |
