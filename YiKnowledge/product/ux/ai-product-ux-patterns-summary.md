# AI 产品 UX 模式

## 1. 研究目标

AI 产品输出非确定性、有延迟、可能出错，传统 GUI 模式不适用。归纳常见 UX 模式，便于设计时复用与避雷。

## 2. 关键发现 / 模式清单

### 模式 1：流式输出（Streaming）

- **表现**：token 逐个出现，像打字机
- **价值**：降低感知延迟、显示模型"在思考"
- **陷阱**：
  - 输出过长滚动闪烁 → 限制单次显示 + 暂停后再续
  - 出错时部分输出已显示 → 错误处理明确（保留已输出，标注失败段）
- **实现**：SSE / WebSocket，UI 逐 token append

### 模式 2：思考可视化（Chain-of-Thought Display）

- **表现**：展示模型的中间推理步骤
- **价值**：增加信任、便于调试、教育用户
- **陷阱**：
  - 中间推理泄露敏感 → 过滤 PII 后再展示
  - 思考链过长 → 折叠默认，展开可选
- **实现**：reasoning content 字段独立，UI 区别显示

### 模式 3：工具调用透明化

- **表现**：展示"正在搜索知识库"、"正在执行 SQL"
- **价值**：让用户理解延迟来源、提升信任
- **陷阱**：工具失败不告知用户 → 失败明确反馈
- **实现**：tool call / observation 实时显示，可展开查看参数与结果

### 模式 4：可编辑的输入 + 重生成

- **表现**：用户原 prompt 可点编辑，重生成新回答
- **价值**：迭代优化，减少从零再写
- **陷阱**：编辑后丢失历史 → 保留版本树
- **实现**：每条 message 带 version，编辑创建新分支

### 模式 5：引用与溯源

- **表现**：答案中标注 `[1] [2]`，点击跳转原文
- **价值**：可验证、可信任、RAG 必备
- **陷阱**：引用与内容不对应 → 后处理校验
- **实现**：渲染时把 citation 与 chunk 关联，hover 显示摘要

### 模式 6：渐进式置信度

- **表现**：答案末尾或角标显示置信度
- **价值**：用户知道何时该验证
- **陷阱**：数字幻觉（80% 用户当 100% 看）→ 用"低 / 中 / 高"档
- **实现**：logprob 或自评模型给分

### 模式 7：人在回路（Human-in-the-loop）

- **表现**：关键操作前需用户确认（如发邮件、删除）
- **价值**：防止 LLM 自主执行造成损失
- **陷阱**：确认太多用户疲劳 → 只在敏感操作
- **实现**：工具标注 `requires_confirmation: true`

### 模式 8：明确拒答

- **表现**：模型说"我不知道"或"信息不足"
- **价值**：降低幻觉率、建立信任
- **陷阱**：拒答过度 → 用户失望
- **实现**：system prompt 鼓励拒答 + 监控 false refusal

### 模式 9：反馈与点赞

- **表现**：每条回答有赞 / 踩 / 复制 / 重生成
- **价值**：隐式反馈数据、用户参与感
- **陷阱**：反馈无人看 → 反馈必须进评测集
- **实现**：埋点 + 周报

### 模式 10：异常恢复

- **表现**：网络断、模型超时、内容违规的友好提示
- **价值**：不让用户卡死
- **陷阱**：报错技术化 → 翻译成用户语言 + 给操作建议
- **实现**：错误类型分类，每类配人话提示

## 3. 设计建议

| 建议 | 含义 |
|---|---|
| 流式优先 | 任何 > 2s 的输出都要流式 |
| 思考可见 | 复杂任务展示推理链 |
| 工具透明 | 调用工具要可见可追溯 |
| 引用兜底 | RAG 必须可溯源 |
| 可编辑 | 用户可改 prompt 重来 |
| 可中断 | 流式输出可停止 |
| 反馈闭环 | 用户反馈进数据 |
| 拒答友好 | 拒答时给替代建议 |

## 4. 移动端与桌面端差异

- **移动端**：屏幕小，流式输出避免滚动抖动；引用折叠
- **桌面端**：可同时显示思考链、工具调用、答案
- **跨端**：会话状态同步，编辑历史保留

## 5. 海外用户跨文化差异

- 日本：高延迟容忍，但更重视引用准确
- 欧美：低延迟高期望，流式必备
- 中东：RTL 布局，多语言混排
- 中国：习惯短答案、低幻觉容忍

## 6. 后续追踪

- 每模式上线后跟踪用户行为与满意度
- 季度复盘模式使用率与问题
- 新模式（如多模态交互、语音）持续补充
