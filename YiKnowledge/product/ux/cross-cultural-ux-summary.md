# 海外用户跨文化 UX 差异

## 1. 研究目标

同一产品在不同文化下表现不同。理解跨文化 UX 差异，避免：

- 把本国习惯套到海外
- 把单一市场用户反馈当全球
- 错过本地化机会（非翻译，是体验本地化）

## 2. 关键文化维度（Hofstede 模型）

| 维度 | 含义 | UX 影响 |
|---|---|---|
| Power Distance 权力距离 | 对不平等的接受度 | 高距离文化接受权威推荐，低距离要参与决策 |
| Individualism 集体主义 | 个人 vs 集体 | 个人主义强调个性化推荐，集体主义强调共识与社交证明 |
| Uncertainty Avoidance 不确定性规避 | 对模糊的容忍 | 高规避要清晰指引与 FAQ，低规避接受探索 |
| Long-Term Orientation 长期导向 | 长期 vs 短期 | 长期导向接受延后满足，短期导向要即时反馈 |
| Indulgence 放纵度 | 享乐 vs 克制 | 高放纵度接受娱乐化设计，低放纵度要严肃 |

## 3. 地区差异

### 日本

- 高不确定性规避 → 明确指引、详细 FAQ、错误提示细致
- 高集体主义 → 社交证明、排行榜
- 长期导向 → 接受长流程
- 信任依赖 → 权威背书、引用来源
- 视觉：信息密度高、文本密集

### 北美 / 西欧

- 个人主义强 → 个性化、定制
- 低权力距离 → 平等对话、参与设计
- 低不确定性规避 → 接受探索、空状态友好
- 视觉：留白多、单一焦点

### 中东

- RTL 布局（阿拉伯语、希伯来语）
- 高权力距离 → 权威推荐
- 性别敏感 → 图像选择注意
- 文化禁忌 → 颜色、动物、宗教符号

### 中国

- 高移动端优先 → 信息密度高、快捷功能
- 二维码、微信生态深度集成
- 即时反馈强 → 流式输出、动画
- 社交属性 → 分享、协作功能

### 印度

- 多语言、多文字 → 必须支持本地文字渲染
- 低带宽场景 → 轻量化、压缩
- 价格敏感 → 免费增值模式 UX

### 东南亚

- 移动端为主 → 简化界面
- 多宗教 → 文化符号注意
- 多语言 → 切换流畅

## 4. 关键差异维度

### 文本与翻译

- 直译常失败：隐喻、例子、文化引用
- 文字长度变化：德语比英语长 30%，UI 要容错
- 阅读方向：RTL 国家要镜像
- 数字格式：千分位、小数点、日期格式各异
- 货币：本币种展示

### 颜色与符号

| 文化 | 颜色含义 |
|---|---|
| 中国 | 红喜庆、白丧 |
| 西方 | 白纯洁、黑丧 |
| 印度 | 红喜庆、白丧 |
| 中东 | 绿神圣 |

通用符号也可能文化差异（OK 手势在日本是钱、在法国是零）。

### 输入法

- 中文 / 日文 / 韩文 IME 输入，UX 要支持组合态
- 阿拉伯语 RTL + 双向混排
- 印地语 / 阿拉伯语字体渲染

### 隐私与数据

- 欧盟 GDPR：明确同意、可删
- 美国：相对宽松
- 中国：网络安全法 + 数据出境
- 印度：个人数据保护法

### 支付习惯

- 美国：信用卡
- 中国：微信 / 支付宝
- 欧洲：SEPA、iDEAL、Bancontact
- 印度：UPI
- 日本：便利店支付、Konbini

## 5. 本地化（L10n）vs 国际化（i18n）

| 概念 | 含义 |
|---|---|
| i18n | 工程层准备：可变语言、可变布局、字符编码 |
| L10n | 翻译与本地化：文本、图片、货币、日期 |
| Culturalization | 文化适应：例子、隐喻、符号 |

i18n 是基础，L10n 是表层，文化适应是深层。

## 6. 设计建议

| 建议 | 含义 |
|---|---|
| 文本不写死 | 用变量与翻译文件 |
| 布局灵活 | 不同文字长度变化 |
| 支持 RTL | 用 logical CSS properties（start/end 而非 left/right） |
| 字体多语言 | fallback 字体栈 |
| 输入法兼容 | IME composition 事件 |
| 文化中立图标 | 避免手势、宗教符号 |
| 本地化数字日期 | 用 Intl API |
| 隐私合规 | 按地区不同流程 |
| 支付本地化 | 集成本地主流支付 |

## 7. 评估方法

- 多地区用户访谈
- 本地化翻译质量评估（不只看字面）
- 文化适配度审查（图标、颜色、例子）
- 跨文化可用性测试
- 各地区留存与转化对比

## 8. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 字面翻译 | 隐喻失效 | 文化适应 |
| 单一布局 | 文字溢出 / 留白过多 | 弹性布局 |
| 忽略 RTL | 阿拉伯语乱 | 用 logical properties |
| 颜色冒犯 | 文化冲突 | 本地化颜色 |
| 支付单一 | 海外用户无法付费 | 集成本地支付 |
| 隐私一刀切 | 违反 GDPR 或过度宽松 | 按地区合规 |
| 反馈仅本国 | 当全球用 | 各地区独立收集 |

## 9. 本团队落地案例

- YiAi BRD：多语言生成支持 8+ 语种，RTL 适配阿拉伯语
- 文档布局：用 logical CSS properties，启动时切换
- 货币 / 日期：用 Intl API，按地区格式
- 隐私：欧盟同意流程更严格，中国数据不出境
