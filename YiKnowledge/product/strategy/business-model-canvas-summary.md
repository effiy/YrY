# Business Model Canvas（商业模式画布）

## 1. 框架定义

Alexander Osterwalder（2008）提出，把商业模式拆成九个模块，画在一张图上。核心：**价值主张 + 客户细分 + 收入与成本结构 + 关键资源与活动**。

是描述与诊断商业模式的通用语言，比商业计划书更轻量、更可演化。

## 2. 九个模块

| 模块 | 含义 | 关键问题 |
|---|---|---|
| Customer Segments 客户细分 | 为谁创造价值 | 用户画像、付费方、决策方 |
| Value Propositions 价值主张 | 提供什么独特价值 | 解决什么问题、为何选你 |
| Channels 渠道 | 如何触达客户 | 销售、营销、服务渠道 |
| Customer Relationships 客户关系 | 建立什么关系 | 自助 / 顾问 / 社区 |
| Revenue Streams 收入来源 | 怎么赚钱 | 订阅 / 一次性 / 用量 / 抽成 |
| Key Resources 核心资源 | 必须有什么 | 资产、品牌、数据、人才 |
| Key Activities 核心活动 | 必须做什么 | 生产、研发、平台运营 |
| Key Partnerships 关键伙伴 | 谁是伙伴 / 供应商 | 战略联盟、外包、互补 |
| Cost Structure 成本结构 | 主要成本 | 固定 / 变动、规模 / 范围 |

## 3. 设计步骤

1. **客户细分先行**：谁是付费方与用户
2. **价值主张对照**：每个细分对应一个 VP
3. **收入与成本填上**：算清商业可行性
4. **资源 / 活动 / 伙伴支撑**：上面四模块靠下面三模块支撑
5. **画布一致性**：左右两边是否匹配（"价值-客户-收入"是否闭环）

## 4. 关键产出物

- 1 页画布图（A3 纸或 Figma 模板）
- 每模块 3-5 项要点
- 配套文字版说明

## 5. 适用场景与边界

**适用**：

- 新业务设计 / 老业务诊断
- 战略评审与转型讨论
- 跨团队对齐"我们在做什么生意"

**不适用**：

- 单产品功能讨论（用 JTBD 更直接）
- 早期探索未定型（用 Lean Canvas 更轻）

## 6. 与其他框架对比

| 框架 | 重点 | 适合 |
|---|---|---|
| Business Model Canvas | 整体商业模式 | 描述与诊断 |
| Lean Canvas | 问题-解决方案-指标 | 0→1 创业 |
| Value Proposition Canvas | VP 与客户痛点匹配 | 单产品定位 |
| Porter 五力 | 行业竞争分析 | 战略定位 |

## 7. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 每格列 20 项 | 失焦 | 每格 3-5 项 |
| 价值主张空泛 | "提供卓越体验" | 与客户痛点一一对应 |
| 收入成本不闭环 | 不赚钱生意 | 算单位经济 |
| 画完不更新 | 半年前画布已过时 | 季度复审 |
| 不与团队分享 | 只有高管知道 | 全员可见 |

## 8. AI 产品商业化模式（针对我方场景）

| 模式 | 适用 | 注意 |
|---|---|---|
| 订阅 | 长期高频用户 | 流失监控 |
| 按 token 计费 | API / B2B 开发者 | 单位经济透明 |
| 按席位 | 团队 / 企业 | 防滥用 |
| 一次性 + 服务 | 项目型 B2B | 标准化难 |
| 抽成 | 平台型 | 双边市场冷启动 |
| 广告 | C 端免费 | 隐私合规 |

## 9. 本团队落地案例

- YiAi BRD 智能体商业化模式候选：按席位 + 高用量 token 包
- 价值主张：把海外售后 BRD 生成从数小时压到分钟级
- 关键活动：LLM 推理运维、业务知识库维护、术语表治理
