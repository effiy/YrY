# Now / Next / Later 路线图

## 1. 框架定义

Now / Next / Later 是一种**结果导向**而非时间导向的路线图形式。把规划分三层，按"现在做 / 下一阶段 / 之后"组织，不绑死日期。

起源于产品管理圈对传统 Gantt 路线图（绑死日期）的反思：日期经常错、错后失信任；而功能价值与依赖关系更稳定。

## 2. 三层结构

| 层 | 时间窗（参考） | 内容 | 详略 |
|---|---|---|---|
| Now | 当前迭代 / 本季度 | 已确定、正在做 | 详（功能、负责人、状态） |
| Next | 下一季度 | 已对齐方向、待设计 | 中（价值、目标、依赖） |
| Later | 半年 - 一年 | 战略方向与探索 | 略（机会、假设、信号） |

**关键原则**：Now 之外的项不绑日期。Later 是方向不是承诺。

## 3. 设计步骤

1. **Now**：列出当前迭代确定要交付的功能（有 PRD / 验收标准）
2. **Next**：列出下季度已对齐方向的功能集群（还没设计，但目标明确）
3. **Later**：列出战略方向与假设（如"探索 Agent 跨知识库"）
4. **每项要回答**：
   - 目标（解决什么 / 衡量指标）
   - 假设（什么数据会推翻）
   - 依赖（关键资源 / 上游）
5. **按价值优先级**排（不按时间）
6. **季度复审**：Later 提升到 Next，Next 提升到 Now

## 4. 关键产出物

- 三列布局（Now / Next / Later）的图（一张图能装一页）
- 每项至少 3 字段：目标 / 假设 / 状态
- 公开给团队 + 关键利益相关方

## 5. 适用场景与边界

**适用**：

- 产品方向持续演化
- 利益相关方需要预期管理（不希望承诺死日期）
- 跨团队对齐战略

**不适用**：

- 强合规 / 合同项目（日期已固定）
- 硬件发布（供应链周期长）
- 团队无方向感时（先要战略对齐）

## 6. 与其他形式对比

| 路线图形式 | 适合 | 缺点 |
|---|---|---|
| Gantt 时间线 | 合同、强约束 | 失信快，更新成本高 |
| Now / Next / Later | 产品持续演化 | 不承诺日期，对管理层难交代 |
| Theme-based | 战略主题 | 缺具体功能 |
| Story Map | 用户体验流 | 单产品级 |

## 7. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| Next 与 Later 等同承诺 | 给非承诺项贴日期 | 严格区分"承诺"与"方向" |
| Now 项太多 | 一次塞 20 项 | 限于 5-8 项 |
| 不写假设 | Later 没法验证 | 必填假设与信号 |
| 季度不复审 | Later 永远不动 | 强制复审节奏 |
| 不公开 | 利益相关方拍脑袋要 | 全公司可见 |

## 8. 与 OKR 关系

- OKR 是季度目标与关键结果
- Now / Next / Later 是中长朘认知
- Now 通常对应本季度 OKR 的具体动作
- Next / Later 对应下季度与战略主题

## 9. 本团队落地案例

- 季度末画三列，与 OKR 对齐
- Now：本季度 BRD 生成稳定性、多语言术语表扩展
- Next：下季度 Agent 跨知识库检索、评估体系完善
- Later：跨语言 BRD 一致性保障的端到端方案
