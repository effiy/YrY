# 留存与流失

## 1. 指标定义

留存（Retention）= 一段时间后还在用的用户比例。
流失（Churn）= 留存的反面，1 - retention。

留存是 SaaS / 订阅 / 内容社区最核心指标：比增长更反映产品真实价值。**留存不健康，增长只是漏桶**。

## 2. 留存的类型

| 类型 | 含义 |
|---|---|
| N-Day Retention | 第 N 天回来的用户 / 第 0 天用户数 |
| N-Week / N-Month | 周 / 月维度（长周期产品用） |
| Bracket Retention | 区间留存（如 W1-W4 平均），平滑波动 |
| Rolling Retention | 滚动留存，更复杂但更准 |
| Revenue Retention | 收入留存（付费 / 续费） |
| Logo Retention | 客户数留存（B2B 常用） |
| Net Revenue Retention | 含升级抵消流失，> 100% 表示现有客户增长 |

## 3. 留存曲线类型

```
1. 微笑曲线（健康）：高开 → 下沉 → 平台稳定
   用户留下后形成习惯

2. 持续下降（不健康）：高开 → 持续降 → 趋零
   没找到持续价值

3. 平稳（早期看不出）：水平不动
   使用频率不足，无法判断
```

判断：微笑曲线 + 平台高于 20-30%（B2C）/ 80-90%（B2B）才健康。

## 4. 分群分析

整体留存掩盖真相。必分：

- **按获客渠道**：不同渠道来的用户质量差很大
- **按首次行为**：完成关键动作的留存远高于没完成的
- **按付费 / 试用**：付费留存远高于试用
- **按用户画像**：地域、行业、角色
- **按版本 / 时间**：新版本是否提升留存

## 5. 留存指标公式

### N-Day Retention

$$ R_N = \frac{\text{Day 0 用户中 Day N 还活跃的用户数}}{\text{Day 0 用户数}} $$

### Cohort Retention

按 cohort（同周 / 同月注册用户）追踪，画矩阵：

```
       D1    D7    D14   D30
W1     40%   20%   15%   10%
W2     42%   22%   ...
W3     ...
```

### Revenue Retention (NRR / GRR)

- **GRR**（Gross Revenue Retention）：不含升级，只看流失后剩多少
- **NRR**（Net Revenue Retention）：含升级 + 降级 + 流失，反映现有客户的健康度

NRR > 100% = 现有客户增长抵过流失（SaaS 优秀线）

## 6. 流失分类

| 类型 | 含义 | 处置 |
|---|---|---|
| 主动流失 | 用户主动取消 | 唤醒 / 留存挽留 |
| 静默流失 | 用户不再登录但没取消 | 重新激活 |
| 付费流失 | 取消订阅 | 退出挽留 |
| 使用流失 | 没有使用（但可能仍付费） | 警告 - 即将付费流失 |
| 假流失 | 季节性 / 临时不使用 | 不算流失 |

## 7. 健康阈值

| 产品类型 | 30 日留存 | 90 日留存 | 12 月留存 |
|---|---|---|---|
| C 端工具 | 30-40% | 15-25% | 5-15% |
| 内容社区 | 40-50% | 25-35% | 15-25% |
| SaaS | 60-80% | 50-70% | 70-90% |
| B2B 企业 | 90%+ | 85%+ | 80%+ |

## 8. 提升留存的方法

### 提升 N-Day

- 首次体验（Aha! moment）优化
- 引导用户完成关键动作
- 推送 / 邮件召回
- 降低首次使用门槛

### 提升 N-Month

- 持续价值兑现（功能迭代、内容更新）
- 习惯养成（订阅、定期通知）
- 社区与连接（社交属性）
- 数据锁定（用户沉淀的数据无法迁移）

### 防 B2B 流失

- 健康度评分（用量、工单、SLA）
- 客户成功主动外联
- 季度业务复盘（QBR）

## 9. 与北极星关系

- 留存是北极星的上限天花板
- 增长再多，留存差就是漏桶
- 北极星 + 留存 + LTV/CAC 三个一起看

## 10. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 只看整体留存 | 不分群，掩盖真相 | 按 cohort / 渠道分群 |
| 短期留存当健康 | D1 好不代表 D30 好 | 至少看 D30 |
| 不区分付费 / 试用 | 试用留存 60% 看着好 | 分开看 |
| 流失后才行动 | 太迟 | 健康度评分 + 主动外联 |
| 增长掩盖流失 | DAU 上升但老用户在流失 | 老用户留存单独看 |

## 11. 本团队落地案例

- YiAi BRD：W4 留存目标 60%（B2B），按客户分群
- YiVad：D30 留存目标 25%（C 端工具），按版本对比
- 监控：留存下降 > 5% 触发归因分析
