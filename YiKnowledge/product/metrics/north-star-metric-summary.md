# 北极星指标（North Star Metric）

## 1. 指标定义

北极星指标：单一最能反映产品为客户创造价值的核心指标。Sean Ellis 与 Andrew Chen 推广。

作用：

- 全公司对齐"最重要的事"
- 减少指标碎片化（如同时追 5 个指标失焦）
- 区分"虚荣指标"（DAU、PV）与"价值指标"

## 2. 北极星指标的特征

| 特征 | 含义 |
|---|---|
| 衡量客户价值 | 不是衡量公司收入 |
| 反映战略 | 战略目标的具体化 |
| 可衡量 | 有数字与口径 |
| 可分解 | 能拆成子指标到团队 |
| 反映可持续增长 | 不是短期可刷的指标 |
| 不易被刷 | 刷量不能拉升它 |

## 3. 设计步骤

1. **明确战略**：长期看，我们要为客户创造什么价值？
2. **列出候选指标**：3-5 个候选
3. **过滤虚荣**：去掉 DAU / PV / 注册数等
4. **确认可分解**：能拆到子团队与执行项
5. **公开承诺**：全公司都知道这是北极星
6. **季度复审**：战略变了，北极星可能也要变

## 4. 候选模板（按业务类型）

| 业务类型 | 北极星候选 | 例 |
|---|---|---|
| 内容社区 | 人均内容消费时长 | Reddit: view time per user |
| 工具 | 成功完成任务数 | Calendly: meetings booked |
| SaaS | 高活跃客户数 | Atlassian: paid active accounts |
| Marketplace | GMV / 配对数 | Airbnb: nights booked |
| 订阅 | 留存付费用户 LTV | Netflix: monthly retention |
| AI 助手 | 人均成功任务数 | OpenAI: useful sessions per user |
| 教育 | 学习完成度 | Coursera: completed modules |

## 5. 北极星 → 输入指标

把北极星拆成可控的输入指标（leading indicators），分到团队：

```
北极星：人均成功任务数
  ├ 输入 1：任务成功率（Task Success rate）
  │   ├ 输入 1.1：faithfulness ≥ 95%
  │   └ 输入 1.2：工具调用成功率 ≥ 90%
  ├ 输入 2：人均发起任务数（人均 session × 任务/session）
  │   ├ 输入 2.1：首次成功率（Activation）
  │   └ 输入 2.2：每周活跃天数
  └ 输入 3：用户基数增长
```

每团队对齐 1-2 个输入指标作为本团队北极星。

## 6. 健康阈值

| 颜色 | 含义 | 处置 |
|---|---|---|
| 绿 | 达到目标 | 保持 |
| 黄 | 低于目标 10-20% | 分析归因 |
| 红 | 低于目标 > 20% | 暂停新功能，专攻北极星 |

## 7. 异常处置流程

1. 告警 → 数据校验（异常 vs 真实下降）
2. 分群拆解（按用户、按场景、按语言）
3. 归因（新功能 / 新模型 / 外部变化 / 数据问题）
4. 决策（修复 / 回滚 / 调整预期）
5. 验证（恢复后跟踪）

## 8. 关联指标

| 类型 | 含义 |
|---|---|
| 北极星 | 全公司对齐 |
| 输入指标 | 团队级目标 |
| 防护指标（护栏） | 防止"刷北极星"伤害其他价值，如 LTV / CAC、安全事件数 |
| 留存指标 | 北极星的上限天花板 |

**护栏指标**示例：

- 北极星：人均成功任务数
- 护栏：幻觉率 ≤ 5%、LTV/CAC ≥ 3、安全事件 0

护栏不达标 = 北极星达成也不能庆祝。

## 9. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 虚荣指标当北极星 | DAU 上升但用户没价值 | 改成价值指标 |
| 多个北极星 | 各团队选自己的 | 统一一个 |
| 不分解 | 北极星好看但不知怎么影响 | 拆输入指标 |
| 不变 | 战略变了指标没变 | 季度复审 |
| 无护栏 | 北极星涨但其他崩 | 必加护栏 |

## 10. 本团队落地案例

- YiAi BRD 智能体北极星：每周成功生成的 BRD 章节数
- 输入指标：faithfulness、首次接受率、人均 session 数
- 护栏：幻觉率 ≤ 5%、token 成本 / 客户 < 预算
- 季度复审：随业务变化调整
