# 异步协作原则

## 1. 是什么

异步协作：不依赖实时同步，以"文档先行 + PR 优先"为核心的工作方式。与会议驱动、同步对齐相反。

跨时区、远程、深度工作的团队尤其需要。

## 2. 核心原则

| 原则 | 含义 |
|---|---|
| 文档先行 | 决策、方案、问题先写文档，再讨论 |
| PR 优先 | 反馈以 PR review 为载体，不开会也能推进 |
| 默认异步 | 能不口语讨论就不口语讨论，留下记录 |
| 会议是昂贵品 | 必要时开会，开会必有议程与纪要 |
| 时区友好 | 不要求对方在自己工作时间内响应 |

## 3. 文档先行

### 何时写文档

- 提议新方案 → 先写 RFC / ADR
- 反馈设计 → 在文档 / PR 评论
- 报告问题 → 在 issue tracker
- 分享知识 → 在内部 wiki

### 文档质量要求

- 自包含：别人不读其他材料也能懂
- 结构化：背景 / 决策 / 选项 / 风险
- 明确建议：要别人做什么决定 / 何时给反馈
- 截止时间：反馈期限

## 4. PR 优先

### PR 文化要点

- PR 是讨论载体，不只是代码 review
- 评论永久留存，会议讨论无记录
- 异步 review：发起方不等即时反馈
- 评论要清晰、上下文齐全
- 反对方需给替代方案，不只说"不好"

### 反馈时效

- 24 小时内响应 PR（哪怕是"明天看"）
- 48 小时内 substantive review
- 超过 72 小时未响应 → 升级

## 5. 默认异步的工具集

| 用途 | 工具 |
|---|---|
| 决策记录 | ADR / RFC 文档 |
| 代码与方案 | Git / PR |
| 任务追踪 | Linear / JIRA / Asana |
| 长文讨论 | 文档评论 |
| 即时但非紧急 | Slack / 飞书（异步语义） |
| 紧急 | 电话 / 短信 |

## 6. 同步场景（仍需开会）

| 场景 | 为何同步 |
|---|---|
| 头脑风暴 | 实时互动效率高 |
| 紧急事件响应 | 决策要快 |
| 复杂争议 | 异步可能跑题 |
| 1on1 | 关系建立 |
| 跨文化误解 | 文本无语气 |

## 7. 时区协作约定

- 不要求对方在自己时区响应
- 会议时间轮流错峰（不要每次都让某时区早 / 晚）
- 会议录屏留档，缺席者可看
- 重要决定有书面总结

## 8. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 凡事开会 | 一天 6 小会 | 默认异步，会议是例外 |
| 文档没写就讨论 | 讨论无基础 | 必先有文档 |
| PR 不响应 | 卡住 3 天 | 24h 内必回应 |
| 同步讨论无纪要 | 决策丢失 | 必有纪要 + 同步到文档 |
| 即时消息期待即时回应 | 干扰深度工作 | 4h 内响应即可 |

## 9. 文化建设

- 高层以身作则：发 RFC 而非组织会议
- PR review 时间纳入工作时长
- 文档写得清楚被表扬
- 异步等待不被看作拖延
- 给反馈者留充足时间，不催

## 10. 与远程团队信任关系

- 远程团队信任建立更慢，但异步协作为其提供土壤
- 文档记录让贡献可被看见
- PR 评论让跨级别对话平等

## 11. 落地要点

- 团队约定工具与节奏
- PR 响应时效写进团队规范
- 会议预算：每周 X 小时上限
- 文档模板标准化
