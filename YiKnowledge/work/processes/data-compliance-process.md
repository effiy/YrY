# 数据合规与脱敏流程

## 1. 目的与适用范围

规范敏感数据的采集、存储、使用、共享、销毁动作；满足隐私法规（GDPR / 个人信息保护法）与公司合规要求，避免数据泄露与违规处罚。

适用于：所有涉及个人身份信息（PII）、财务、订单、健康等敏感数据的场景。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 数据 owner（R） | 识别敏感字段；执行脱敏；维护访问控制 |
| 技术负责人（A） | 审核脱敏方案；决策技术实现 |
| 安全 / 合规（C） | 评估合规风险；审核方案 |
| 业务方（I） | 业务必要性确认 |
| 法务（C，必要时） | 法规解释与方案背书 |

## 3. 步骤拆解

```
数据分类 → 脱敏方案 → 实施评审 → 上线 → 访问审计 → 销毁
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 数据分类 | 识别 PII / 敏感字段；标注敏感等级 | 分类清单产出 |
| 2. 脱敏方案 | 制定脱敏规则（掩码 / 哈希 / 加密 / 替换）；明确使用场景 | 方案文档完成 |
| 3. 实施评审 | 技术 + 安全 + 合规三方评审；记录结论 | 方案通过 |
| 4. 上线 | 实施脱敏；配置访问控制与审计日志；监控告警 | 上线完成 |
| 5. 访问审计 | 定期审计访问日志；异常访问告警 | 审计报告归档 |
| 6. 销毁 | 到期或业务停止后销毁数据；记录销毁动作 | 销毁记录归档 |

## 4. 脱敏规则参考

| 敏感类型 | 推荐策略 |
|---|---|
| 手机号 | 掩码（138****1234） |
| 身份证 | 掩码或哈希；仅在必要时还原 |
| 邮箱 | 掩码（a***@example.com） |
| 银行卡 / 支付 | 加密存储；展示掩码；禁止明文日志 |
| 地址 | 按需展示；导出脱敏 |
| 健康 / 种族 / 宗教 | 高敏；原则上不采集不存储 |

## 5. 度量指标

- 敏感字段覆盖率（已脱敏占比）
- 异常访问告警数与处理率
- 合规审计通过率
- 数据泄露事件数（目标 0）

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 明文泄露到日志 | 立即清理；修复代码；按 [事件响应流程](./incident-response-process.md) 升级 |
| 越权访问 | 立即收回权限；审计范围；安全通报 |
| 第三方索取敏感数据 | 必须法务 + 合规双签；最小化提供 |
| 业务方要求明文 | 拒绝；按需审批 + 操作审计 + 一次性 token |
| 法规变更 | 安全 / 合规牵头复审；调整脱敏规则 |
| 历史数据未脱敏 | 专项治理；分批迁移脱敏 |

## 7. 注意点

- **最小化采集原则**——能不采就不采；能少采就少采
- 脱敏必须在数据进入系统前完成；不要"先存明文后处理"
- 日志是泄露重灾区——禁止打印敏感字段
- 访问控制 + 审计日志必须配套；缺一不可
- 第三方数据共享必须有书面协议与最小化原则
- 与 [data-migration-process](./data-migration-process.md) 联动：迁移时敏感字段必须保持脱敏
