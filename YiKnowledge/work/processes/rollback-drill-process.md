# 紧急回滚演练流程

## 1. 目的与适用范围

通过定期演练验证回滚预案是否真的可执行；避免真实事故时才发现脚本失效、依赖缺失、人员不熟。

适用于：所有生产核心服务；高风险发布后 1 周内；季度例行演练。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 演练 owner（R） | 撰写演练剧本；执行；记录 |
| 技术负责人（A） | 决策演练范围；审核剧本 |
| 运维 / SRE（C） | 执行回滚动作；监控 |
| Oncall（C） | 模拟真实响应 |
| 迭代 PM（I） | 协调窗口与通报 |

## 3. 步骤拆解

```
剧本准备 → 预演 → 演练执行 → 验证 → 复盘 → 改进
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 剧本准备 | 选定服务；定义回滚触发条件、命令、验证点；评估演练对真实用户的影响 | 剧本通过审核 |
| 2. 预演 | 在影子环境或低峰窗口模拟一次；验证脚本可行 | 预演通过 |
| 3. 演练执行 | 按剧本在演练窗口执行；过程记录时序与耗时 | 演练完成 |
| 4. 验证 | 核心链路恢复；数据一致；无残留问题 | 验证通过 |
| 5. 复盘 | 记录 MTTR；对比真实事故预期；找出剧本漏洞 | 复盘报告归档 |
| 6. 改进 | 修复脚本、监控、人员技能 gap；列入 action | action 闭环 |

## 4. 输入 / 输出工件

- **输入**：回滚脚本、监控大盘、依赖清单、历史事故复盘
- **输出**：演练剧本、演练记录、复盘报告、改进 action 列表

## 5. 度量指标

- 演练 MTTR vs 预期 MTTR
- 演练通过率
- 剧本漏洞数
- 改进 action 闭环率

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 演练引发真实问题 | 立即中止；按 [事件响应流程](./incident-response-process.md) 处理 |
| 回滚失败 | 立即升级；评估是否需数据修复 |
| 脚本失效 | 暂停演练；修复后重跑 |
| 人员不熟 | 列入培训 action；加强 oncall 轮值 |
| 数据不一致 | 暂停；数据修复后再演练 |

## 7. 注意点

- **演练不是演习——必须有真实回滚动作**
- 优先选择低峰窗口；提前通报业务方
- 演练前必须备份；回滚 SQL 必须先验证
- 高风险发布后 1 周内必须演练一次
- 季度例行至少覆盖核心服务一次
- 演练结果与 [事件响应流程](./incident-response-process.md) 的 MTTR 度量联动
