# 数据迁移与回滚流程

## 1. 目的与适用范围

规范数据库结构变更与数据迁移的动作，保证可回滚、可验证、可追溯；避免锁表、数据丢失、不一致。

适用于：DDL 变更、大表数据迁移、跨库/跨系统数据同步、历史数据归档。

不适用于：业务侧 CRUD（由应用层保证）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| DBA / 后端 owner（R） | 撰写迁移脚本；执行；验证 |
| 技术负责人（A） | 评审方案；决策执行窗口 |
| 迭代 PM（C） | 协调窗口与依赖方 |
| 运维 / SRE（C） | 监控、扩容、应急预案 |
| 业务方（I） | 业务影响确认与停服窗口决策 |

## 3. 步骤拆解

```
方案评审 → 准备 → 预演 → 执行 → 验证 → 回滚预案 → 收尾
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 方案评审 | 表结构变更、数据量评估、锁影响、回滚 SQL、停服与否 | 方案通过 |
| 2. 准备 | 脚本 review；备份策略确认；监控大盘就位；告警阈值调整 | 全部就位 |
| 3. 预演 | 在预发/影子库执行；验证正确性与耗时 | 预演通过 |
| 4. 执行 | 按计划窗口执行；分批 commit；过程盯监控 | 脚本执行完成 |
| 5. 验证 | 行数核对、抽样比对、业务侧验证 | 数据一致 |
| 6. 回滚预案 | 若验证失败立即执行回滚 SQL；评估是否需要恢复备份 | 恢复到迁移前 |
| 7. 收尾 | 归档脚本与记录；清理临时表 | 归档完成 |

## 4. 输入 / 输出工件

- **输入**：表结构变更说明、数据映射规则、回滚 SQL
- **输出**：迁移脚本、执行记录、验证报告、回滚记录

## 5. 度量指标

- 迁移成功率
- 迁移平均耗时
- 迁移引发事故数（目标 0）
- 回滚执行次数

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 锁表超预期 | 暂停；评估是否中止迁移 |
| 数据不一致 | 立即停止；执行回滚预案 |
| 备份失败 | 中止迁移；先修复备份能力 |
| 停服窗口不够 | 拆分迁移；分批执行 |
| 跨系统同步失败 | 暂停下游消费；评估数据修复范围 |
| 涉及资金/订单 | 必须业务方 + 技术负责人双签 |

## 7. 注意点

- **永远假设迁移会失败——回滚 SQL 必须先写好并验证可行**
- 大表优先在线 DDL 工具（如 gh-ost / pt-osc）
- 不要在业务高峰执行；优先选择低峰窗口
- 备份是底线——没有备份不执行
- 数据迁移与代码发布解耦——避免一次性同时变更
- 涉及资金/订单/用户身份的迁移必须双签
