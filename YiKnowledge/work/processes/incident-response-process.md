# 事件响应流程（P0/P1/P2）

## 1. 目的与适用范围

规范线上事件的事中响应，缩短 MTTR；与 `lessons/failures/incident-postmortem-template.md` 互补——响应过程在事中，复盘在事后。

适用于：所有线上事件（P0/P1/P2）。

## 2. 严重等级定义

| 等级 | 定义 | 响应时效 | 升级 |
|---|---|---|---|
| P0 | 核心功能不可用；大面积用户受影响；资金/数据风险 | 5 分钟内响应 | 立即通报迭代 PM + 技术负责人 + 业务方 |
| P1 | 部分功能不可用；影响可绕过；中等范围用户 | 15 分钟内响应 | 通报迭代 PM + 技术负责人 |
| P2 | 体验问题；小范围用户；不影响主流程 | 1 小时内响应 | 知会迭代 PM |

## 3. 角色与职责

| 角色 | 职责 |
|---|---|
| Oncall（R） | 第一响应；初步定位；拉响应群 |
| 技术负责人（A） | 决策回滚/修复/扩容 |
| 迭代 PM（C） | 协调资源；对外通报 |
| 业务方（I） | 业务侧决策（是否止损） |
| 复盘 owner（R，事后） | 产出 postmortem |

## 4. 响应步骤

```
发现 → 响应群 → 定位 → 止损 → 恢复 → 通报 → 复盘
```

| 步骤 | 动作 | 时限 |
|---|---|---|
| 1. 发现 | 告警/用户反馈进入值班渠道 | — |
| 2. 响应群 | Oncall 拉群；命名"【事件-Px】XXX-YYYYMMDD"；@相关人 | P0 ≤ 5min |
| 3. 定位 | 排查变更、依赖、基础设施；明确影响面 | P0 ≤ 15min |
| 4. 止损 | 优先回滚、降级、开关、限流；不要原地修 bug | P0 ≤ 30min |
| 5. 恢复 | 验证核心链路恢复 | — |
| 6. 通报 | 群内通报恢复；外部通报按业务方决策 | — |
| 7. 复盘 | 24 小时内产出 postmortem | 见 incident-postmortem-template.md |

## 5. 度量指标

- MTTA：平均响应时长
- MTTI：平均定位时长
- MTTR：平均恢复时长
- 事件复发率：同一根因 30 天内复发次数

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| Oncall 无法定位 | 15 分钟内升级至技术负责人 |
| 影响扩大 | 等级上调；通报扩大 |
| 止损决策分歧 | 技术负责人决策；重大事件业务方共同决策 |
| 涉及第三方 | 启动紧急联络；同步业务方预期 |
| 复盘发现系统性问题 | 进入技术债清单；迭代 PM 排期治理 |

## 7. 注意点

- 事中只止损，不改 bug——bug 在事后修
- 群内信息要有时序：变更/影响/止损动作/恢复验证
- 通报要诚实，不要粉糖
- P0/P1 必须 24 小时内复盘
