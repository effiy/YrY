# 设计评审流程

## 1. 目的与适用范围

在研发进入开发前，确保各方对交互流程、视觉规范、边界状态、异常态达成共识，避免开发中返工或体验割裂。

适用于：所有有 UI 交互的需求；纯后端/数据需求可豁免。

## 2. 角色与职责（RACI）

| 角色 | 职责 |
|---|---|
| 设计师（R） | 输出设计稿（含交互流程、视觉规范、边界态、异常态）；召集评审 |
| 产品经理（A） | 确认设计满足需求与验收标准 |
| 迭代 PM（C） | 把控节奏；记录结论 |
| 前端负责人（C） | 评估实现可行性、复用组件、性能 |
| 后端负责人（C） | 评估数据结构对设计的影响 |
| 测试负责人（I） | 识别异常路径覆盖度 |

## 3. 步骤拆解

```
设计自审 → 设计评审 → 结论同步 → 设计验收（里程碑节点）
```

| 步骤 | 负责人 | 关键动作 | 退出标准 |
|---|---|---|---|
| 1. 设计自审 | 设计师 | 设计稿完成；边界态（空/错/加载/权限/超长文本）齐全；复用现有组件 | 自查清单通过 |
| 2. 设计评审 | 设计师 + 迭代 PM | 确保日程与在场；把控节奏；指定记录人；现场确认是否通过；结束前对齐纪要 | 结论明确：通过 / 再评审 |
| 3. 结论同步 | 设计师 | 纪要 @相关人同步项目群；action 列表带 owner 与截止日 | 纪要发出 |
| 4. 设计验收 | 设计负责人 + 迭代 PM | 里程碑节点验收；问题统一记录便于统计 | 验收报告归档 |

## 4. 输入 / 输出工件

- **输入**：PRD、设计稿（Figma/Sketch）、设计自查清单
- **输出**：评审纪要、设计验收报告、action 列表

## 5. 度量指标

- 设计一次通过率
- 设计到开发完成的偏差率
- 设计验收一次通过率

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 设计稿缺失边界态 | 退回补全后再审 |
| 实现可行性存疑 | 前端负责人现场评估，复杂度高的拆分迭代 |
| 与 PRD 冲突 | 暂停；产品确认 PRD 取舍后重审 |
| 设计验收不通过 | 列入必改项；迭代 PM 跟踪闭环 |

## 7. 注意点

- 里程碑节点很早定好，设计师需提前预留时间
- 验收问题统一记录便于统计
- 前端组件库已有的，优先复用，不要新增视觉差异
