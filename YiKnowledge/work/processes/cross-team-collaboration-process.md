# 跨团队协作流程

## 1. 目的与适用范围

规范跨团队（不同产品线、前后端、产研测、业务方与产研）协作动作；降低沟通损耗与责任真空。

适用于：跨团队需求、接口联调、共同发布、联合评审。

不适用于：单团队内部协作（由团队自管理）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 主导团队 PM（R） | 拉通协作方；输出联合计划 |
| 协作方 PM（A） | 内部协调；承诺交付 |
| 各方技术负责人（C） | 接口契约、依赖排序、联调 |
| 各方测试负责人（C) | 联合测试策略 |
| 业务方（I） | 业务节奏与优先级 |

## 3. 步骤拆解

```
识别 → 协作启动会 → 接口契约 → 联合计划 → 联调 → 联合测试 → 共同发布
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 识别 | 主导方识别关联团队；尽早联动 | 关联方已通知 |
| 2. 协作启动会 | 对齐背景/目标/范围/时间；指定各方 contact | 联合 brief 发出 |
| 3. 接口契约 | 各方技术负责人共同敲定；写入文档；不改口头 | 契约文档归档 |
| 4. 联合计划 | 拆分依赖路径；找最长路径；对齐里程碑 | 计划各方确认 |
| 5. 联调 | 联调环境就位；mock 与真实切换节奏明确 | 联调通过 |
| 6. 联合测试 | 共同制定用例；明确 bug 归属 | 测试通过 |
| 7. 共同发布 | 统一发布计划；明确各方动作与时序 | 发布成功 |

## 4. 输入 / 输出工件

- **输入**：PRD、各方技术方案、接口契约草案
- **输出**：联合 brief、接口契约文档、联合里程碑、发布计划、复盘记录

## 5. 度量指标

- 跨团队需求一次通过率
- 联调阶段 bug 漏出率
- 联合发布延期率
- 跨团队投诉/甩锅事件数

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 协作方未投入 | 主导方 PM 升级至对方 PM；必要时至上层 |
| 接口契约变更 | 必须书面通知；各方评估影响后再定 |
| 里程碑无法对齐 | 主导方 PM 拉会对齐；分歧上升 |
| 发布时序冲突 | 必须有书面发布计划；明确依赖顺序 |
| 责任甩锅 | 当场拉人；以接口契约为准；事后复盘 |
| 联合事故 | 主导方牵头按 [事件响应流程](./incident-response-process.md) 处理 |

## 7. 注意点

- **尽早联动关联方**——延期常因未识别清楚
- 接口契约是协作的"法律"——口头约定不算
- contact 必须明确到人；不要"我们组"
- 联合计划要找最长路径；不要被最短路径误导
- 共同发布必须有书面时序；禁止"顺手发一下"
- 复盘要联合开；不要各写各的
