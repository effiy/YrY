# 跨团队交接流程（项目移交）

## 1. 目的与适用范围

规范项目从一方移交另一方的动作；保证知识、责任、文档、权限、待办无遗漏；避免移交后的真空期与责任扯皮。

适用于：项目所有权转移（A 团队 → B 团队）、人员变动（owner 换人）、外包转自建、自建转 SaaS。

不适用于：临时支援（不转移所有权）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 移出方 owner（R） | 准备交接材料；执行移交 |
| 移入方 owner（R） | 接收并确认；后续负责 |
| 双方技术负责人（A） | 审核技术状态与遗留问题 |
| 双方迭代 PM（C） | 协调时序与通报 |
| 业务方（I） | 业务连续性确认 |

## 3. 步骤拆解

```
触发 → 交接准备 → 交接会议 → 接收验证 → 权限移交 → 正式切换 → 交接后支持
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 触发 | 确定移交原因与时点；双方 PM 对齐 | 移交计划发出 |
| 2. 交接准备 | 移出方整理文档、待办、遗留问题、依赖、联系人、权限清单 | 交接包完成 |
| 3. 交接会议 | 移出方讲解；移入方提问；记录 action | 会议纪要发出 |
| 4. 接收验证 | 移入方按文档独立操作；验证流程可行 | 验证通过 |
| 5. 权限移交 | 资源、代码库、监控、告警、密钥权限移交；收回旧权限 | 权限清单更新 |
| 6. 正式切换 | 业务方通报；切换后移出方进入支持期 | 切换完成 |
| 7. 交接后支持 | 移出方约定支持期（建议 2~4 周）；处理遗留问题 | 支持期结束 |

## 4. 交接包清单

- [ ] 项目 README 与架构文档
- [ ] 技术方案与接口契约
- [ ] 依赖方与关联方联系人
- [ ] 生产资源清单（应用/数据库/缓存/队列/存储）
- [ ] 权限清单（代码库/监控/告警/密钥/云资源）
- [ ] 待办与已知问题（含技术债）
- [ ] 关键流程与运维 SOP
- [ ] 监控大盘与告警阈值
- [ ] 备份与回滚方案
- [ ] 历史事件复盘

## 5. 度量指标

- 交接周期（触发到切换）
- 交接后 30 天事故数
- 移入方独立操作上手时间
- 支持期内遗留问题处理率

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 移出方拖延 | 双方 PM 升级；必要时至上层 |
| 交接包不完整 | 暂停切换；补全后再进 |
| 移入方验证失败 | 暂停切换；移出方修复后重验 |
| 业务连续性风险 | 业务方介入；必要时延长支持期 |
| 权限回收遗漏 | 安全通报；立即清理 |
| 移交后事故责任 | 支持期内移出方主责；支持期后移入方主责 |

## 7. 注意点

- **交接不是"丢过去"**——必须验证移入方能独立操作
- 权限移交要"先加后删"——避免真空期
- 支持期必须有时长约定；不要无限期拖着
- 业务方通报要早；避免业务方不知情
- 与 [knowledge-transfer-process](./knowledge-transfer-process.md) 联动：本文档关注所有权转移，知识沉淀关注经验传承
- 移交记录归档到 `projects/<项目>/handover.md`
