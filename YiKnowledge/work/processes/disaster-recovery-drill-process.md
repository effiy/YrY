# 灾备演练与切换流程

## 1. 目的与适用范围

验证灾备体系（多机房 / 多云 / 主备 / 异地容灾）真实可切换；避免"配置了却用不了"的虚假灾备。

适用于：所有声明具备灾备能力的核心服务；合规要求灾备的业务（金融/支付/订单等）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 演练 owner（R） | 撰写演练剧本；执行；复盘 |
| 技术负责人（A） | 审核剧本；决策演练范围 |
| 运维 / SRE（C） | 执行切换；监控 |
| 业务方（I） | 演练窗口与业务影响确认 |
| 合规（C，必要时） | 监督合规要求 |

## 3. 演练分级

| 级别 | 描述 | 频次 |
|---|---|---|
| L1 桌面推演 | 走流程不切换 | 每季度 |
| L2 单服务切换 | 真实切换一个服务到备机房 | 每半年 |
| L3 全链路切换 | 核心链路整体切换 | 每年 |
| L4 故障注入切换 | 模拟主机房故障，强制切换 | 每年 |

## 4. 步骤拆解

```
剧本准备 → 预演 → 演练窗口确认 → 切换执行 → 流量验证 → 回切 → 复盘
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 剧本准备 | 切换条件、命令、责任人、验证点、回切预案 | 剧本审核通过 |
| 2. 预演 | 影子环境或模拟环境预演 | 预演通过 |
| 3. 演练窗口确认 | 与业务方对齐；选择低峰窗口 | 窗口确定 |
| 4. 切换执行 | 按剧本切换流量/数据/缓存；过程记录时序 | 切换完成 |
| 5. 流量验证 | 核心链路可用；数据一致；延迟在预期 | 验证通过 |
| 6. 回切 | 演练后按计划回切到主机房；验证恢复 | 回切完成 |
| 7. 复盘 | 记录 RTO/RPO；找出剧本漏洞；改进 action | 复盘报告归档 |

## 5. 度量指标

- RTO（恢复时间目标）vs 预期
- RPO（恢复点目标）vs 预期
- 切换成功率
- 剧本漏洞数
- 数据一致性偏差

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 切换失败 | 立即回切；按 [事件响应流程](./incident-response-process.md) 升级 |
| 数据不一致 | 暂停；评估是否数据修复 |
| 切换后延迟劣化 | 评估是否回切；排查瓶颈 |
| 剧本漏洞 | 中止演练；修复剧本后重跑 |
| 演练引发真实事故 | 立即中止；事件响应 |

## 7. 注意点

- **配置不等于能力**——必须真实切换才算验证
- 演练前必须备份；回切预案必须先验证
- RTO/RPO 是承诺——演练不达标就是违约
- 切换要"能切也要能回"——回切必须演练
- 与 [rollback-drill-process](./rollback-drill-process.md) 互补：回滚演练关注单服务，灾备演练关注机房级
- 演练结果沉淀到 `projects/<项目>/` 与合规审计材料
