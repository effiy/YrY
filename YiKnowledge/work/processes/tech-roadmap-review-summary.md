# 技术路线图审查（Tech Roadmap Review）

> 本摘要说明该做什么、为什么做、如何评估；可填表单见 [tech-roadmap-review-template.md](./tech-roadmap-review-template.md)。

## 1. 是什么

季度对当前与未来 1-2 个季度的技术投资分布做一次结构化审查：

- 钱与人力花在了哪些域（平台 / 中间件 / 业务）
- 这些投资是否支撑当前最重要的里程碑
- 是否存在过度投资或被忽视的域
- Conway 定律是否被遵守（架构 = 组织结构）

## 2. 为什么做

技术投资有惯性：上一季度的项目继续拿资源、新需求不断塞进来、没人主动撤销旧投资。半年后回头看：钱花在 12 个方向、3 个项目已不再战略对齐、关键基础设施欠债没人还。

季度审查是强制性的"重新分配"机制：让一些项目自然结束、把资源挪到更重要的地方、把被忽视的基础设施补回。

## 3. 关键维度

### 3.1 投资分布

按域分桶：

| 域 | 当季投入 | 上季投入 | 趋势 | 是否战略对齐 |
|---|---|---|---|---|
| 平台（推理 / 网关 / 可观测） | X 人月 | Y | +Z% | 是 / 否 |
| 中间件（向量库 / 消息 / 缓存） | ... | ... | ... | ... |
| 业务（BRD / 对话 / aicr） | ... | ... | ... | ... |
| 基础设施（部署 / 监控 / 安全） | ... | ... | ... | ... |

### 3.2 里程碑对齐

列出当季关键里程碑，对照投资分布看：

- 是否每个里程碑都有对应投资？
- 是否有投资不在任何里程碑下？（"僵尸投资"）
- 哪些里程碑滞后？滞后是否因资源被挪走？

### 3.3 战略对齐评分

每投资项打分（1-5）：

- 5：直接支撑当季战略主题
- 3：支撑基础能力，但不直接对齐战略
- 1：与战略无关（应撤销或迁延）

### 3.4 组织与架构对齐（Conway）

- 团队结构是否匹配架构边界？
- 跨团队依赖是否清晰？
- 是否有"两个团队做类似的事"？

## 4. 评估方法

### 定量

- 人月分布（人力资本）
- 预算分布（金钱）
- PR / commit 分布（实际产出）
- 上线功能数与目标对照

### 定性

- 团队自评：当季最重要的 3 件事是什么？
- PM 反馈：业务侧最痛的 3 件事是什么？
- 跨团队对齐：依赖契约是否清晰？

### 输出

- 当季投资分布表
- 战略对齐评分表
- 下季投资建议（保留 / 调整 / 撤销）
- 里程碑风险清单

## 5. 执行节奏

| 时点 | 事项 |
|---|---|
| 季末前 3 周 | 启动，PM + TL 各自准备 |
| 季末前 2 周 | 联合评审会议（2 小时） |
| 季末前 1 周 | 输出文档，下季 OKR 对齐 |
| 季末 | 全员同步 |

## 6. 反模式

| 反模式 | 现象 | 修复 |
|---|---|---|
| 只列项目不评分 | 无法对比 | 强制战略对齐 1-5 分 |
| 全部"战略对齐" | 没人有勇气说撤销 | 强制至少 1 项撤销候选 |
| 评审走形式 | 季度会议变汇报 | 提前提交，会中只讨论分歧 |
| 不复盘上季 | 滞后项目无追踪 | 上季未完成项必查 |
| 只看投资不看回报 | 投了什么不重要，产出什么重要 | 加产出对照 |

## 7. 与其他流程关系

- 输入：OKR（战略目标）、上季复盘
- 输出：下季 OKR 草稿、技术债清单优先级
- 联动：[requirement-review-process](./requirement-review-process.md) / [tech-review-process](./tech-review-process.md) / [tech-debt-inventory-template](../../tech/infra/tech-debt-inventory-template.md)

## 8. 落地要点

- 模板填一遍只是手段，目的是"集体看到同一张图"
- 评审会前 24 小时把材料发给参与者，避免会上读材料
- 输出文档全员可查，决策可追溯
