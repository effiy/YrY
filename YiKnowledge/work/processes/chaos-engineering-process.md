# 故障演练（chaos engineering）流程

## 1. 目的与适用范围

通过主动注入故障（节点宕机、网络丢包、依赖慢、磁盘满）验证系统韧性；发现隐藏的单点与级联失败。

适用于：核心微服务、关键依赖链、有 SLA 承诺的服务。

不适用于：未稳定的 MVP、缺乏监控的服务（先补监控再做 chaos）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 演练 owner（R） | 设计故障用例；执行；复盘 |
| 技术负责人（A） | 审核故障范围；决策爆炸半径 |
| 运维 / SRE（C） | 执行故障注入；监控与应急 |
| Oncall（C） | 观测与判断是否升级 |
| 业务方（I） | 演练窗口确认 |

## 3. 故障用例库

| 类型 | 示例 |
|---|---|
| 节点 | Pod kill、CPU 打满、OOM |
| 网络 | 丢包、延迟、分区 |
| 依赖 | 下游慢、超时、错误率上升 |
| 数据 | DB 连接打满、缓存击穿、消息积压 |
| 资源 | 磁盘满、文件句柄耗尽 |
| 第三方 | API 限流、证书过期 |

## 4. 步骤拆解

```
用例设计 → 爆炸半径评估 → 预演 → 注入 → 观测 → 恢复 → 复盘
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 用例设计 | 选定故障与目标；明确假设（"系统应能 X"）；定义止损阈值 | 用例文档完成 |
| 2. 爆炸半径评估 | 评估影响范围；识别边界；制定中止条件 | 范围可控 |
| 3. 预演 | 在影子环境先跑一次 | 预演通过 |
| 4. 注入 | 按剧本注入故障；过程监控；触发中止条件立即停止 | 注入完成或中止 |
| 5. 观测 | 验证系统假设是否成立；记录指标 | 观测数据归档 |
| 6. 恢复 | 撤销注入；验证系统恢复 | 恢复正常 |
| 7. 复盘 | 假设是否被验证；发现韧性缺陷；改进 action | 复盘报告归档 |

## 5. 度量指标

- 假设验证率（系统按预期响应的占比）
- 隐藏缺陷发现数
- 故障恢复时间
- 演练中止率（触发止损的占比）

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 触发止损阈值 | 立即中止；按 [事件响应流程](./incident-response-process.md) 处理 |
| 影响超出爆炸半径 | 立即停止；评估是否升级 |
| 演练引发真实事故 | 中止 + 事件响应 |
| 故障无法撤销 | 升级至 SRE + 技术负责人；评估重启或切换 |
| 第三方受影响 | 立即停止；通报对方 |

## 7. 注意点

- **chaos 不是搞破坏**——是验证假设的科学方法
- 先有监控再做 chaos；没有观测的故障注入等于盲操作
- 爆炸半径必须明确；必须有自动中止机制
- 从小范围开始；逐步扩大（单实例 → 多实例 → 跨机房）
- 与 [rollback-drill-process](./rollback-drill-process.md) 与 [disaster-recovery-drill-process](./disaster-recovery-drill-process.md) 联动
- 发现的韧性缺陷进入技术债清单；迭代 PM 排期治理
