# 季度安全审计流程

## 1. 目的与适用范围

定期盘点代码、依赖、基础设施、数据访问的安全风险；早发现早治理；满足合规与监管要求。

适用于：所有生产项目与基础设施；合规要求覆盖的业务（金融/数据/隐私）。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 安全 owner（R） | 组织审计；汇总风险清单 |
| 技术负责人（A） | 决策治理优先级与排期 |
| 项目 owner（C） | 配合整改；修复项目内风险 |
| 迭代 PM（C） | 协调排期与跟踪闭环 |
| 合规 / 法务（I） | 法规解读与背书 |

## 3. 审计维度

| 维度 | 检查内容 |
|---|---|
| 代码 | 静态扫描（SAST）；密钥泄露；注入风险；权限校验 |
| 依赖 | CVE 扫描；过期依赖；license 合规 |
| 基础设施 | 暴露面；端口；权限；密钥管理；日志保留 |
| 数据 | 敏感数据访问审计；脱敏覆盖；越权 |
| 第三方 | API 鉴权；回调安全；供应链风险 |
| 运维 | SSH 访问；堡垒机；变更审计；应急访问 |

## 4. 步骤拆解

```
准备 → 扫描与检查 → 风险汇总 → 优先级评审 → 治理排期 → 闭环验证 → 归档
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 准备 | 确定审计范围；对齐工具与基线 | 范围清单完成 |
| 2. 扫描与检查 | SAST/SCA/渗透/配置扫描；人工抽查 | 扫描报告产出 |
| 3. 风险汇总 | 汇总风险项；分级（高/中/低）；关联修复方案 | 风险清单完成 |
| 4. 优先级评审 | 安全 + 技术负责人评审；高危立即治理 | 评审结论发出 |
| 5. 治理排期 | 高危 24 小时~1 周；中危 1 月内；低危季度内 | 排期表完成 |
| 6. 闭环验证 | 复扫验证修复；未闭环升级 | 闭环率达标 |
| 7. 归档 | 审计报告归档；通报业务方与合规 | 归档完成 |

## 5. 度量指标

- 风险发现数与分级分布
- 高危平均修复时长（目标 ≤ 7 天）
- 闭环率（目标 ≥ 95%）
- 复发风险数（同一问题季度复发）

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 发现高危在野利用 | 立即按 [hotfix 流程](./hotfix-release-process.md) 处理 |
| 项目 owner 拖延 | 迭代 PM 跟进；必要时升级至上层 |
| 治理影响业务节奏 | 业务方 + 安全 + 技术 三方决策取舍 |
| 涉及外部通报 | 合规牵头；按法规要求通报 |
| 治理方案不可行 | 升级至技术负责人；评估替代控制措施 |

## 7. 注意点

- **审计不是找茬**——是早治理避免事故
- 高危必须有截止日；不能"列入计划慢慢来"
- 扫描工具 + 人工抽查结合；不要只信工具
- 与 [dependency-upgrade-process](./dependency-upgrade-process.md) 与 [data-compliance-process](./data-compliance-process.md) 联动
- 审计报告作为合规证据归档；保留至少 1 年
- 治理完成后必须复扫验证；闭环才算完成
