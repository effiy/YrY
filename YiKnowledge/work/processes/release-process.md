# 上线发布流程与 checklist

## 1. 目的与适用范围

规范发布动作，降低线上事故概率；保证发布可回滚、可观测、可追溯。

适用于：所有生产环境发布，包含常规发布、紧急修复发布。

## 2. 角色与职责（RACI）

| 角色 | 职责 |
|---|---|
| 发布负责人（R） | 召集发布方案评审；执行发布；值守观察 |
| 迭代 PM（A） | 确保评审通过；跟踪 action |
| 技术负责人（C） | 评估回滚、灰度、依赖 |
| 测试负责人（C） | 线上回归与验收 |
| 产品（I） | 发布后业务验收 |
| 运维 / SRE（C） | 基础设施、权限、监控告警配置 |

## 3. 步骤拆解

```
发布方案评审 → 发布前准备 → 发布执行 → 线上观测 → 发布收尾
```

| 步骤 | 关键动作 | 退出标准 |
|---|---|---|
| 1. 发布方案评审 | 确保日程与在场；把控节奏；指定记录人；现场确认是否通过；结束前对齐纪要；纪要同步群 | 方案通过；简单发布可不开会，整理文档发群即可 |
| 2. 发布前准备 | 冒烟通过；发布窗口确认；依赖方通知；监控大盘就位；回滚脚本就位 | 所有 checklist 通过 |
| 3. 发布执行 | 按发布计划分步执行；每步有人盯；异常即暂停 | 所有步骤完成 |
| 4. 线上观测 | 核心指标观察 30 分钟以上；业务验收通过 | 无告警、无投诉 |
| 5. 发布收尾 | 改群名"【已发布】XXX"；归档发布记录；复盘（如有问题） | 归档完成 |

## 4. 发布前 checklist

- [ ] 发布方案评审已通过
- [ ] 冒烟测试通过（最低标准：阻塞主流程的问题不能有）
- [ ] 发布窗口已确认（避开业务高峰）
- [ ] 依赖方已通知
- [ ] 数据库变更已执行并验证
- [ ] 配置/开关已准备
- [ ] 回滚脚本已准备且验证可行
- [ ] 监控大盘与告警已配置
- [ ] 值守人员已就位
- [ ] 业务验收人已通知

## 5. 度量指标

- 发布成功率
- 发布导致事故数（目标 0）
- 发布到回滚的耗时
- 发布窗口遵守率

## 6. 异常处理与升级路径

| 场景 | 处理 |
|---|---|
| 冒烟不通过 | 视为开发延期；返回修复 |
| 发布过程异常 | 立即暂停；评估影响；必要时回滚 |
| 线上告警 | 15 分钟内决策是否回滚；上报迭代 PM |
| 业务验收不通过 | 列入必改项；评估是否回滚 |
| 紧急修复 | 走 hotfix 流程，简化评审但必须保留记录 |

## 7. 注意点

- **发布方案必须考虑回滚**
- 进入 UAT 当天必须完成发布计划评审
- 发布过程必须有记录，禁止"顺手发一下"
- 灰度发布见 [灰度发布流程](./canary-release-process.md)
