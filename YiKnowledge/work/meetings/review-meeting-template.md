# 评审会模板

## 使用场景

需求评审、设计评审、技术评审。共同目标：**会上做决定，不在会后再讨论**。

## 模板正文

```markdown
# {评审类型}：{项目/需求}

**日期**：YYYY-MM-DD
**主持**：{name}
**参与者**：{必填字段：PM / 设计 / 开发 / QA / 安全 / 法务}
**评审材料**：{提前 24h 发出的链接}
**时长**：60 分钟

## 1. 背景与目标（5 分钟）

- 业务目标：{OKR 关联}
- 用户痛点：{JTBD}
- 期望产出：{本次评审要决定什么}

## 2. 材料走查（15 分钟）

- PRD / 设计稿 / 技术方案 走查
- 主持引导：只看是否对齐目标，细节问题线下

## 3. 关键决策（30 分钟）

| # | 决策点 | 选项 | 决议 | 责任人 | 截止 |
|---|---|---|---|---|---|
| 1 | {key decision} | A/B/C | 选 B | {name} | YYYY-MM-DD |
| 2 | ... | ... | ... | ... | ... |

## 4. 风险与依赖（10 分钟）

| 风险 / 依赖 | 影响 | 处置 | 责任人 |
|---|---|---|---|
| ... | ... | ... | ... |

## 5. 未决议题（Parking Lot，5 分钟）

- 移至线下 / 下次会议
- 不在主会议强行决定

## 6. 行动项

| # | 行动 | 责任人 | 截止日 |
|---|---|---|---|
| 1 | ... | ... | YYYY-MM-DD |

## 7. 复审时间（如适用）

- 复审日期：YYYY-MM-DD
- 复审条件：{什么变更触发复审}
```

## 填写规范

| 字段 | 必填 | 规范 |
|---|---|---|
| 业务目标 | 是 | OKR 关联 |
| 关键决策 | 是 | 选项 + 决议 + 责任人 |
| 风险与依赖 | 是 | 含影响 |
| 行动项 | 是 | 责任人 + 截止 |
| 评审材料 | 是 | 提前 24h 发 |

## 评审类型差异

| 评审类型 | 重点 | 参与者 |
|---|---|---|
| 需求评审 | 价值与可行性 | PM + 开发 + QA + 设计 |
| 设计评审 | 体验与可用性 | 设计 + PM + 开发 |
| 技术评审 | 架构与风险 | 资深开发 + 架构师 + PM |
| 安全评审 | 安全与合规 | 安全 + 法务 + 开发 |
| 上线评审 | 风险与回滚 | PM + 开发 + QA + 运维 |

## 评审原则

1. **材料提前 24h 发**：会上不读材料
2. **只做决定**：纯讨论移至线下
3. **必出决策**：每决策点有结论
4. **未决移至 parking lot**：不强行决定
5. **必出行动项**：每条有责任人与截止
6. **60 分钟上限**：超时拆分

## 反模式

- 会上读材料 → 提前发
- 没决定 → 必出决议
- 没行动项 → 必出
- 离题 → 主持控场 + parking lot
- 全员参加 → 只请必要角色
