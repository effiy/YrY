# 复盘会模板

## 使用场景

迭代结束、项目里程碑、事件后。核心原则：**无指责、关注流程与系统、必出可执行行动**。

## 模板正文

```markdown
# {项目/迭代/事件} 复盘会

**日期**：YYYY-MM-DD
**主持**：{name}（负责流程，不评判）
**记录**：{name}
**参与者**：{on-call + 受影响方 + TL}
**时长**：60-90 分钟
**复盘类型**：迭代 / 项目 / 事件

## 会前准备（主持在会前 24h 发）

- 复盘背景文档（事件时间线 / 项目目标 vs 实际）
- 数据与证据（监控、PR 列表、用户反馈）
- 鼓励参与者先各自写下观点

## 1. 背景与时间线（10 分钟）

- 项目目标 / OKR
- 期望 vs 实际（量化）
- 关键时间线
- 影响范围

## 2. 做得好的（Keep）（10 分钟）

- {3-5 条，含数据与原因}
- 鼓励全员分享

## 3. 做得不好的（Problem）（15 分钟）

- {3-5 条，含影响与原因}
- **不指责个人**：问"系统为何允许这事发生"

## 4. 根因分析（20 分钟）

对每个 Problem 做 5-Why 或鱼骨图：

### Problem 1：{描述}

- Why 1：...
- Why 2：...
- Why 3：...
- Why 4：...
- Why 5：...

**根本原因**：{一句话}

### Problem 2：...

## 5. 改进措施（Action）（10 分钟）

| # | 改进项 | 优先级 | 责任人 | 截止日 | 验证方式 |
|---|---|---|---|---|---|
| 1 | {action} | P0 | {name} | YYYY-MM-DD | {metric / artifact} |
| 2 | ... | ... | ... | ... | ... |

## 6. 运气因素（5 分钟）

- {哪些环节靠运气才没出更大问题}
- 如何消除运气依赖

## 7. 下次承诺（5 分钟）

- {3-5 条，可量化}

## 8. 总结（1 句话）

## 会后

- 24h 内发复盘文档
- 全员可查
- 行动项进任务系统，每周追踪
- 季度看完成率
```

## 填写规范

| 字段 | 必填 | 规范 |
|---|---|---|
| 背景与时间线 | 是 | 量化 |
| Keep | 是 | 3-5 条 |
| Problem | 是 | 3-5 条 |
| 根因 | 是 | 5-Why |
| Action | 是 | 责任人 + 截止 + 验证 |
| 下次承诺 | 是 | 3-5 条 |

## 无指责原则

### 为何不指责个人

- 90% 事件根因在系统
- 指责后员工下次会掩盖问题
- 无指责让员工愿意主动报告

### 主持技巧

- 鼓励发言，不让一人主导
- 问"系统为何允许"而非"谁做的"
- 公开表扬好复盘
- 不与绩效挂钩

## 复盘原则

1. **会前发材料**：参与者先各自思考
2. **无指责**：关注流程与系统
3. **5-Why 必做**：不止步于"人为失误"
4. **必出行动项**：责任人 + 截止 + 验证
5. **必追踪**：进任务系统，每周看
6. **公开归档**：全员可查

## 反模式

- 复盘走形式 → 5-Why + 必出 Action
- 找替罪羊 → 无指责
- Action 无责任人 → 必填
- 写完不公开 → 全员可查
- 不追踪 → 每周追
- 不公开表扬好复盘 → 文化建设
