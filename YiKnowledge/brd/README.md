# BRD database export area

> **As a** knowledge-curator, **I want to** export BRD database content as .md grouped by role, **so that** RAG recall is stable and cross-role consumption does not require database access permission. 

> The BRD database (MongoDB) stores the business requirements source text; this directory is a static .md export area grouped by role, generated by the YiVad BRD sync tool. Not part of PARA Areas. 

## Summary

- 8 role subdirectories: `brd-ai-engineer/` / `brd-engineer/` / `brd-executive/` / `brd-knowledge-curator/` / `brd-new-hire/` / `brd-oncall-sre/` / `brd-product-manager/` / `brd-tech-lead/`
- 10 category subdirectories: `architecture-design/` / `build-deploy/` / `data-storage/` / `ai-ml/` / `sre-operations/` / `security-compliance/` / `product-strategy/` / `project-process/` / `testing-qa/` / `knowledge-reference/`
- Filenames like `brd_<role-or-category>_<id>.md`, generated from database keys by the sync tool
- Historical/legacy structure references (`brd/reference/countries.md` / `brd/scenarios/scn-unified-ticketing.md` / `brd/terminology/automotive.md` / `brd/domains/data.md`) point to tables/keys inside the DB and **do not correspond to static .md files** — they must be retrieved via the BRD database
- Sync process: [../knowledge-curator/templates/brd.md](../knowledge-curator/templates/brd.md)

## Core ideas

- **BRD content is managed by the database; static .md is only a RAG recall snapshot** — DB is the SSOT; this directory is the view layer
- **Legacy 14-category references (reference/scenarios/terminology/domains) no longer exist as static files** — for documentation referencing these paths, please change to reference the corresponding role subdirectories or query the DB directly
- **Role subdirectories not covered by the sync tool are empty** — to be filled by the BRD Agent later

## Key information

### Sync frequency
- YiVad BRD Agent triggers a sync task after each database update
- Static .md lands in the corresponding `brd-<role>/` subdirectories
- Failed syncs go to [../knowledge-curator/governance/tacit-knowledge-backlog.md](../knowledge-curator/governance/tacit-knowledge-backlog.md) for tracking

### Reference conventions
- Cross-role reference to BRD content: write relative path `brd/<role>/brd_<role>_<id>.md` or `brd/<category>/brd_<category>_<id>.md`
- Do not write legacy paths like `brd/reference/X.md` / `brd/scenarios/X.md` (these are DB table keys, no static file)
- To reference a row in a DB table: first sync to .md, then reference the .md

## Action recommendations

1. New documentation referencing BRD: point directly to `brd/<role>/brd_<role>_<id>.md` or `brd/<category>/brd_<category>_<id>.md`
2. Discover legacy path references (`brd/reference/` etc.): update to role/category subdirectory path or rewrite as a DB query explanation
3. Sync failure: record in [../knowledge-curator/governance/tacit-knowledge-backlog.md](../knowledge-curator/governance/tacit-knowledge-backlog.md)
4. Check coverage: `ls brd-<role>/` to see whether sync output exists

## Anti-patterns / common misuses

- **Writing `brd/reference/countries.md`** — DB table key is not a file path; the sync tool does not export to a `reference/` subdirectory (now merged into `knowledge-reference/`)
- **Manually editing `brd-<role>/*.md` or category `*.md`** — next sync will overwrite; to change content, go through the DB
- **Cross-role reference to a specific BRD row without a role/category prefix** — DB key is unique but .md path requires role or category subdirectory qualification
