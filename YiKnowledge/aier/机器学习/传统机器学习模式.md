# Traditional ML Patterns

> **When to use:** When an LLM is overkill — structured prediction, pattern matching, or statistical analysis where a smaller, faster, cheaper model works better.

## Traditional ML vs. LLM

| Use traditional ML when... | Use an LLM when... |
|---|---|
| Task is structured (classification, regression) | Task requires reasoning or natural language understanding |
| Training data is available and labeled | No training data; need zero-shot capability |
| Latency must be < 10ms | Latency can be > 100ms |
| Cost must be near-zero per prediction | Cost per prediction is acceptable |
| Explainability is required | Creative/nuanced output is the goal |
| Pattern is stable (doesn't need frequent retraining) | Task requires adapting to new patterns without retraining |

## Pattern 1: Text Classification

### Use Case: Auto-tagging YiKnowledge files

Classify markdown files into role directories based on content.

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression

# Train on existing tagged files
vectorizer = TfidfVectorizer(max_features=5000)
X = vectorizer.fit_transform(texts)  # file contents
y = labels  # role directories

model = LogisticRegression(multi_class='multinomial')
model.fit(X, y)

# Predict role for new file
new_vec = vectorizer.transform([new_file_content])
predicted_role = model.predict(new_vec)[0]
```

### When to use
- Classifying documents, tickets, or user feedback
- Routing support tickets to the right team
- Detecting spam or inappropriate content

## Pattern 2: Clustering

### Use Case: Discovering themes in user feedback

Group similar support tickets or user feedback to find common themes.

```python
from sklearn.cluster import KMeans
from sklearn.feature_extraction.text import TfidfVectorizer

# Vectorize and cluster
vectorizer = TfidfVectorizer(max_features=3000)
X = vectorizer.fit_transform(feedback_texts)

# Find optimal k with elbow method
kmeans = KMeans(n_clusters=5, random_state=42)
clusters = kmeans.fit_predict(X)

# Inspect top terms per cluster
for i in range(5):
    centroid = kmeans.cluster_centers_[i]
    top_terms = [vectorizer.get_feature_names_out()[j] 
                 for j in centroid.argsort()[-5:]]
    print(f"Cluster {i}: {top_terms}")
```

### When to use
- Discovering themes in user feedback
- Segmenting users by behavior
- Grouping similar error patterns in logs

## Pattern 3: Anomaly Detection

### Use Case: Detecting unusual API traffic patterns

```python
from sklearn.ensemble import IsolationForest
import numpy as np

# Features: requests per minute, error rate, avg latency
features = np.array([
    [rpm, error_rate, avg_latency]
    for timestamp, rpm, error_rate, avg_latency in metrics
])

model = IsolationForest(contamination=0.05, random_state=42)
predictions = model.fit_predict(features)

# -1 = anomaly, 1 = normal
anomalies = [i for i, p in enumerate(predictions) if p == -1]
```

### When to use
- Detecting traffic anomalies (DDoS, bot traffic)
- Finding unusual user behavior (account takeover)
- Identifying performance regressions

## Pattern 4: Regression

### Use Case: Predicting resource usage

```python
from sklearn.linear_model import LinearRegression
import numpy as np

# Features: active_users, concurrent_requests, model_size
# Target: gpu_memory_mb
X = np.array([[u, r, m] for u, r, m in historical_data])
y = np.array([mem for mem in memory_usage])

model = LinearRegression()
model.fit(X, y)

# Predict memory for new load
predicted_memory = model.predict([[100, 50, 7]])[0]
```

### When to use
- Predicting resource needs (memory, CPU, storage)
- Estimating task completion time
- Forecasting user growth

## Training vs. Inference

| Phase | Traditional ML | LLM |
|---|---|---|
| Training | Hours on CPU/GPU | Days-Weeks on GPU cluster |
| Inference | Microseconds on CPU | Seconds on GPU |
| Retraining | Needed when data drifts | Prompt engineering replaces retraining |
| Deployment | Pickle file + sklearn | Model server (Ollama, vLLM) |

## Anti-patterns

| Anti-pattern | Why it fails | What to do instead |
|---|---|---|
| Using an LLM for classification | 1000x slower and 1000x more expensive than sklearn | Use sklearn for structured prediction; LLM for reasoning |
| ML without evaluation | Model looks good on training data; fails in production | Hold out test set; measure precision/recall; monitor in production |
| Training on biased data | Model learns and amplifies the bias | Audit training data for representation; test on diverse inputs |
| Deploying without monitoring | Model degrades silently as data drifts | Track prediction distribution; alert on drift |
