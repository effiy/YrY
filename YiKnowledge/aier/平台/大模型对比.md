# LLM Comparison for Model Selection

> **Model selection is task-dependent.** The model that's best for chat isn't necessarily best for tool calling or RAG.

## Current YiAi models (Ollama)

| Model | Role | Strengths | Weaknesses |
|-------|------|-----------|------------|
| **qwen3-coder** | Agent fallback (doer) | Strong tool calling, follows instructions | Slower, higher VRAM |
| **qwen3.5** | Default agent (thinker) | Fast, good reasoning | Inconsistent tool calling, narrate-and-stop |
| **qwen2.5** | Chat, RAG generation | Balanced, good Chinese | Older architecture |

## Selection criteria

| Criterion | Weight | How to evaluate |
|-----------|--------|----------------|
| Tool-calling reliability | Critical | Run 10 tool-calling tasks, measure success rate |
| Chinese language quality | Critical | Native speaker evaluation |
| Instruction following | High | Does it do what you ask, not what it thinks you want? |
| Latency | High | Time-to-first-token + tokens/second |
| Context window | Medium | 8K minimum, 16K+ preferred |
| VRAM usage | Medium | Must fit in available GPU memory |

## Model roles in agent loop

```
Thinker (fast, cheap) → tries task
    ↓ stalls
Doer (reliable, tool-capable) → finishes task
```

The thinker handles simple tasks quickly. The doer is the escalation target when the thinker stalls. This two-tier pattern gives the best latency/cost/reliability trade-off.

## When to re-evaluate

- New model release from Ollama
- Tool-calling failure rate exceeds 20%
- Latency exceeds 3s for chat, 10s for agent tool calls
- Quarterly review (next: 2026-11)
