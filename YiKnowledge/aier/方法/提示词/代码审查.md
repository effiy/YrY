# Code Review Prompt

## Variant 1: Basic Code Review

```
You are a senior code reviewer. Review the following code for:

1. **Security** — SQL injection, XSS, auth bypass, secret exposure, unsafe deserialization
2. **Performance** — N+1 queries, unnecessary allocations, blocking operations, missing indexes
3. **Readability** — unclear names, missing edge-case handling, overly complex logic
4. **Correctness** — logic errors, off-by-one, null/undefined handling, race conditions

For each issue found:
- **Severity**: Critical / Major / Minor
- **Location**: line number or function name
- **Problem**: what's wrong
- **Fix**: concrete code suggestion

If the code looks correct, say so explicitly. Don't invent issues.

{{code}}
```
```

- **Temperature:** 0.0-0.2 (deterministic review)
- **Max tokens:** 2000

## Variant 2: PR Review

```
You are reviewing a pull request. The PR description:

> {{pr_description}}

## Changed files
{{diff}}

Review the changes for:
1. Does the change match the PR description?
2. Are there any unintended side effects?
3. Is the change minimal (no unrelated refactoring)?
4. Are there missing tests for the changed behavior?
5. Are there any security or performance concerns?

Output format:
- **Approve** / **Request changes** / **Comment**
- Summary (2-3 sentences)
- Issues (if any, with severity and fix)
```

### Variables

| Variable | Meaning | Example |
|---|---|---|
| `{{pr_description}}` | PR description text | "Fix parameter name mismatch: query → filter" |
| `{{diff}}` | Git diff output | `git diff main...feature-branch` |

## Variant 3: Enhancement Review

```
Review this code and suggest 3-5 concrete improvements. Prioritize by impact:
1. Highest impact, lowest effort first
2. Each suggestion must include: what to change, why, and the expected benefit

## Code
```{{language}}
{{code}}
```
```

## Anti-patterns

| Anti-pattern | Why it fails | Fix |
|---|---|---|
| Reviewing without context | AI flags "issues" that are intentional design choices | Include PR description or module context |
| Too much code at once | AI misses issues in long files | Review one file or function at a time |
| Temperature > 0.3 | Inconsistent reviews; same code gets different feedback | Use temperature 0.0-0.2 for reviews |
| Accepting all suggestions blindly | AI can suggest changes that break other parts of the system | Human review every suggestion before applying |
