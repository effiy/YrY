# Agent Evaluation Framework

> **When to use:** When building or modifying an AI agent (like YiAi's BRD agent). Agent evaluation is harder than LLM evaluation — agents take actions, not just generate text.

## Why Agent Evaluation is Different

| LLM evaluation | Agent evaluation |
|---|---|
| One input → one output | One input → sequence of actions + final output |
| Evaluate the text quality | Evaluate the trajectory + outcome |
| Stateless | Stateful (tool calls change state) |
| Deterministic-ish (same prompt → similar output) | Non-deterministic (agent may take different paths) |

## Evaluation Dimensions

### 1. Task Completion

Does the agent accomplish the task?

| Metric | Definition | Example |
|---|---|---|
| **Success rate** | % of tasks completed correctly | "Create a menu" → menu exists with correct fields |
| **Partial success** | % of tasks mostly correct but with minor issues | Menu created but wrong parent |
| **Failure rate** | % of tasks not completed | Agent stopped without creating the menu |

### 2. Tool Use Accuracy

Does the agent use the right tools with the right arguments?

| Metric | Definition |
|---|---|
| **Tool selection accuracy** | Did the agent pick the correct tool for each step? |
| **Argument accuracy** | Were the tool arguments correct? |
| **Tool call efficiency** | Did the agent make unnecessary or duplicate tool calls? |
| **Rejection respect** | Did the agent respect user rejections (not re-attempt rejected writes)? |

### 3. Safety

Does the agent avoid harmful actions?

| Metric | Definition |
|---|---|
| **No data loss** | Agent never deletes or corrupts data without confirmation |
| **No privilege escalation** | Agent doesn't attempt actions beyond its scope |
| **Confirmation respect** | Agent waits for confirmation on gated operations |
| **Stop on error** | Agent stops gracefully on errors instead of retrying destructively |

### 4. Efficiency

How many resources does the agent consume?

| Metric | Definition |
|---|---|
| **Turns to completion** | Number of LLM calls to finish the task |
| **Tokens consumed** | Total input + output tokens |
| **Wall time** | Total elapsed time |
| **Tool calls** | Number of tool invocations |

## Evaluation Harness Design

### Test Suite Structure

```
YiAi/tests/agent/
├── scenarios/           # Test scenarios organized by task type
│   ├── create_menu/     # "Create a menu with name X"
│   ├── update_menu/     # "Update the menu title to Y"
│   ├── delete_menu/     # "Delete the menu Z"
│   ├── list_menu/       # "List all menus" (read-only)
│   └── multi_step/      # "Create, update, then delete a menu"
├── expected/            # Expected outcomes per scenario
├── harness.py           # Evaluation runner
└── results/             # Historical results
```

### Scenario Definition

```python
# YiAi/tests/agent/scenarios/create_menu/simple_create.py

SCENARIO = {
    "name": "Create a single menu item",
    "task": "在管理菜单中创建一个名为'测试菜单'的子菜单",
    "expected": {
        "success": True,
        "tools_called": ["db_create"],
        "tools_not_called": ["db_delete"],
        "db_state": {
            "collection": "menus",
            "filter": {"name": "测试菜单"},
            "expected_count": 1,
        },
        "fields": {
            "name": "测试菜单",
            "parent": "管理",
        },
    },
    "max_turns": 10,
    "auto_approve": True,  # For deterministic testing
}
```

### Running the Harness

```python
# YiAi/tests/agent/harness.py

async def run_scenario(scenario, agent_config):
    """Run one scenario and return results."""
    start = time.time()
    
    result = await agent_chat_stream(
        task=scenario["task"],
        session_id=f"eval-{uuid4()}",
        max_turns=scenario["max_turns"],
        auto_approve=scenario.get("auto_approve", False),
    )
    
    elapsed = time.time() - start
    
    # Evaluate
    return {
        "scenario": scenario["name"],
        "success": evaluate_success(result, scenario["expected"]),
        "tools_called": extract_tools_called(result),
        "turns": result["turn_index"],
        "tokens": result.get("total_tokens", 0),
        "elapsed_ms": elapsed * 1000,
        "errors": extract_errors(result),
    }
```

## YiAi Agent Evaluation Patterns

### What to Test

Based on YiAi's agent architecture (see `CLAUDE.md` recent changes):

| Guard | What to test | How to test |
|---|---|---|
| **Narrate-and-stop** | Agent names a tool but doesn't call it | Give a task; stub LLM to return text naming `db_create` without a tool_call |
| **No-write nudge** | Agent completes without executing any write tool | Give a write task; stub LLM to describe the plan and stop |
| **Count-aware** | Agent creates fewer items than requested | "Create 2 menus" → stub LLM to create 1 and stop |
| **Rejection memory** | Agent re-attempts a rejected write | Reject `db_create`; verify the same call is auto-blocked |
| **Spin guard** | Agent repeats the same observation 3+ times | Stub LLM to return identical `db_list` results each turn |
| **Model escalation** | Weak model stalls; stronger model takes over | Use qwen3.5 (weak) for a write task; verify escalation to fallback |
| **Confirmation gate** | Write tools require confirmation | Verify `db_create` emits `confirmation_required`; executes only on `approved` |

### Regression Test Checklist

Before deploying agent changes, run:

- [ ] All single-step tasks pass (create, update, delete, list)
- [ ] Multi-step tasks pass (create → update → delete cycle)
- [ ] Read-only tasks never trigger write tools
- [ ] Rejected writes are never re-attempted
- [ ] Timeout and abort scenarios are handled gracefully
- [ ] No regression in task completion rate (> 90%)
- [ ] No regression in average turns to completion

## Anti-patterns

| Anti-pattern | Why it fails | What to do instead |
|---|---|---|
| Testing only the happy path | Agent fails on edge cases in production | Test rejection, timeout, abort, and error scenarios |
| "I tested it manually and it worked" | Manual testing is not reproducible; can't catch regressions | Build a scenario-based harness; run before every agent change |
| Evaluating only task completion | Agent "succeeds" but used 3x more turns after a change | Track turns, tokens, and tool calls per task |
| No baseline before changes | Can't tell if the change was an improvement | Run the full eval suite on the current version before making changes |
