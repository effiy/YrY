# 知识库分类处理队列

> **已分类但尚未精炼。** 此处的条目已分配角色目录，但需要补全 frontmatter、格式化内容、通过质量审查，才能提升为 `lifecycle: active`。队列上限 20 条。每周清空目标：所有条目 ≤ 14 天。

## 适用场景

收件箱的条目经过初步分类后进入此队列。这是知识从"原材料"变成"成品"的关键加工阶段。处于此阶段的文件：

- 已放置在正确的角色目录中
- 文件名基本符合规范
- 但 frontmatter 不完整（缺少 `benefit`、`acceptance_criteria` 等）
- 内容未经过格式化和质量审查

## 分类条目 vs 收件箱条目

| 属性 | 收件箱（inbox） | 分类队列（triage） |
|---|---|---|
| 位置 | inbox.md 表格中 | 已创建 stub 文件在角色目录中 |
| 角色归属 | 未确定 | 已确定 |
| 文件状态 | 无文件，仅记录 | 有 stub 文件，lifecycle: triage |
| 审查周期 | 每日 | 每周 |
| 滞留上限 | 7 天 | 14 天 |

### 字段说明

- **日期** — 从收件箱移至分类队列的时间
- **文件** — 在角色目录中的文件路径
- **角色** — 归属的角色目录名
- **审查者** — 负责审查该条目质量的领域专家（通常为该角色的 Reviewer）
- **状态** — `待精炼` / `审查中` / `已提升`

## 提升流程

对每条条目，完整执行[就绪检查清单](./readiness-checklist.md)：

1. **验证 frontmatter** — 所有必填字段齐全，`category` 与目录匹配
2. **验证命名** — kebab-case，无下划线或数字
3. **补充收益说明** — 添加 `benefit:` 和 `acceptance_criteria:`
4. **检查交叉引用** — 所有 `related:` 链接可解析
5. **设置生命周期** — `lifecycle: active`、`status: stable`、`review_cycle: quarterly`
6. **登记日志** — 将条目从本表移至 `review-log.md`，标记为"已提升"

### 提升前的质量信号

以下信号表明文件已准备好提升为 `active`：

- [ ] 不熟悉该领域的同事阅读后能理解核心观点
- [ ] 文件中有具体的例子/数据/代码支撑论点
- [ ] 文件中有反模式说明（错误用法及正确替代方案）
- [ ] 文件的 `benefit:` 字段能让目标读者在 5 秒内判断该文件是否与自己相关
- [ ] 所有 `{{placeholder}}` 已替换为实际内容

## 升级机制

超过 14 天的条目需升级处理，有三种路径：

- **立即提升** — 内容已就绪，只是被遗漏，直接完成提升流程
- **退回收件箱** — 当初分类有误，需重新归类
- **归档放弃** — 内容已失去时效性或不再相关，归档处理

### 升级决策树

```
条目超过 14 天
├── 内容是否仍有价值？
│   ├── 是 → 是否可在 1 小时内完成精炼？
│   │   ├── 是 → 立即提升
│   │   └── 否 → 排入本周优先级队列，不超过本周五
│   └── 否 → 归档（lifecycle: archive，注明废弃原因）
└── 角色归属是否正确？
    ├── 是 → 继续精炼
    └── 否 → 退回收件箱，重新分类
```

## 队列积压的预警机制

| 队列规模 | 状态 | 应对措施 |
|---|---|---|
| 0-10 条 | 健康 | 正常节奏，每周清空 |
| 11-20 条 | 关注 | 本周内清理至 10 条以下 |
| 21-30 条 | 警告 | 暂停收件箱新条目处理，全力清空分类队列 |
| > 30 条 | 严重 | 升级给 Curator，组织集中清空日 |

## 反模式

| 反模式 | 失效原因 | 正确做法 |
|---|---|---|
| 只分类不精炼 | 队列越积越长，"已分类"成为甩锅终点 | 每周至少完成 3 条提升（从 triage 到 active） |
| 精炼质量敷衍 | 文件只是格式上合规，内容没有实质性精炼 | 精炼意味着添加总结、提炼观点、补充反模式 |
| 反复退回同一个条目 | 在 inbox 和 triage 之间来回弹跳，消耗精力 | 第三次退回时直接归档或由 Curator 做最终裁决 |
| 分类队列为空 = 自满 | 队列为空可能不是好事——可能意味着没有新知识进入 | 检查收件箱是否也空；两者同时为空说明收集机制失效 |
