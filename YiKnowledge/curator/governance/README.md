# 治理子目录

> 知识库运营的指挥中心。7 个文件覆盖从内容进入到废弃的全生命周期。

## 文件清单

| 文件 | 用途 | 使用频率 |
|------|------|----------|
| [01-知识健康看板](./01-治理-知识健康看板.md) | 文件数量、成熟度、ADR 覆盖、已知缺口的量化快照 | 每月 |
| [02-治理规范](./02-治理-治理规范.md) | 4 角色、3 节奏、生命周期状态机——治理模型的核心定义 | 每季度 |
| [03-收件箱](./03-治理-收件箱.md) | 未分类内容的统一入口，24h 内分类 | 每日 |
| [04-就绪检查清单](./04-治理-就绪检查清单.md) | 10 题发布门禁——任何文件发布前必检 | 每次发布 |
| [05-审查日志](./05-治理-审查日志.md) | 审查操作记录——创建、提升、废弃、归档的审计线索 | 每周 |
| [06-隐性知识待办](./06-治理-隐性知识待办.md) | 仅存于人脑中的知识捕获队列 | 每月 |
| [07-分类处理](./07-治理-分类处理.md) | 已分类待精炼队列——从原材料到成品的加工站 | 每周 |
| [08-操作速查卡](./08-治理-操作速查卡.md) | 日/周/月/季度操作速查——可复制的命令和常见场景处置 | 每日 |

## 治理工作流

```
新内容进入 → [03-收件箱] → [07-分类处理] → [04-就绪检查清单] → 发布
                                   ↓
              过期内容 → [01-健康看板] 发现 → [05-审查日志] 记录 → 归档
                                   ↓
              人脑知识 → [06-隐性知识待办] → 捕获 → 发布
```

## 新人入口

1. 先读 [02-治理规范](./02-治理-治理规范.md) — 理解 4 角色 3 节奏模型
2. 再读 [04-就绪检查清单](./04-治理-就绪检查清单.md) — 掌握发布标准
3. 日常使用 [03-收件箱](./03-治理-收件箱.md) 和 [07-分类处理](./07-治理-分类处理.md)
