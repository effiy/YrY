## 二、质量指标

### 2.1 Frontmatter 合规率

> 检查必填字段（title, tags, category, created, updated, source, type, status）是否齐全。仅统计角色知识文件（排除 `projects/`、`skills/`、`static/`、`books/`），这些目录使用不同的 type schema。
>
> 刷新命令：
> ```bash
> cd YiKnowledge
> total=0; fail=0
> for f in $(find . -name "*.md" ! -path "./projects/*" ! -path "./skills/*" ! -path "./static/*" ! -path "./books/*"); do
>   total=$((total+1)); ok=true
>   for field in "title:" "tags:" "category:" "created:" "updated:" "source:" "type:" "status:"; do
>     grep -q "^$field" "$f" || { ok=false; break; }
>   done
>   [ "$ok" = false ] && { fail=$((fail+1)); echo "FAIL: $f"; }
> done
> echo "Total: $total, Failed: $fail, Compliance: $(( (total-fail)*100/total ))%"
> ```

| 指标 | 当前 | 目标 | 趋势 |
|------|------|------|------|
| Frontmatter 合规率 | 90%（406/447） | ≥ 95% | — |
| `benefit:` 覆盖率 | 82%（369/447） | ≥ 80% | — |
| `acceptance_criteria:` 覆盖率 | 53%（241/447） | ≥ 60% | — |

> **41 个不合规文件分布**：OKR 目录 38 个（缺 `tags:` 或 `category:`）、engineer/okr 3 个（缺 `created:`）。
> OKR 文件的 `type: okr-goal` 等专用 type 值缺少 `category:` 和 `tags:` 是普遍模式——需在 OKR 模板中强制这两个字段。

### 2.2 交叉引用健康

> 仅检查 `related:` 字段中的相对链接（`./path/to/file.md`），从文件所在目录解析目标路径。
>
> 刷新命令：
> ```bash
> cd YiKnowledge
> find . -name "*.md" ! -path "./projects/*" ! -path "./skills/*" ! -path "./static/*" ! -path "./books/*" -print0 | while IFS= read -r -d '' file; do
>   dir=$(dirname "$file")
>   grep "^  - \./" "$file" 2>/dev/null | sed -E 's/.*- (\.\/[^)]*).*/\1/' | while read -r link; do
>     target="${dir}/${link#./}"; target=$(echo "$target" | sed -E 's/#.*$//' | sed -E 's/\/$//')
>     [ ! -f "$target" ] && [ ! -d "$target" ] && [ ! -f "${target}.md" ] && echo "DEAD in $file: $link"
>   done
> done
> ```

| 指标 | 当前 | 目标 | 上次扫描 |
|------|------|------|----------|
| 死链数量 | 76 | 0 | 2026-10-07 |
| 总交叉引用数 | 719 | — | 2026-10-07 |
| 链接健康率 | 89% | 100% | 2026-10-07 |

> **76 个死链分类**：
> - `leader/roadmap/` 引用英文文件名（如 `manage-tech-debt.md`），实际文件为中文名 — **29 处**
> - `sre/observability/` 子目录缺少 README.md — **9 处**
> - `engineer/` 各子文件引用不存在的 `./README.md` — **18 处**
> - `leader/decisions/` 引用已重命名的 ADR 文件 — **4 处**
> - `aier/methods/` 引用不存在的 `./04-LLM评估.md` — **2 处**
> - 其他（模板占位链接、MEMORY.md/CLAUDE.md 中的示例路径） — **14 处**

### 2.3 命名规范合规

> 检查是否使用下划线、空格作为文件名（排除 README.md 和 INDEX.md）。OKR 目录的 `_templates/` 使用下划线前缀表示内部目录，属于例外。

> find . -name "*.md" | grep -vE '(README|INDEX)\.md$' | grep "_" | grep -v "_templates/"

> find . -name "* *.md"
> ```

| 指标 | 当前 | 目标 |

> 2 个违规均在 `skills/pretty-mermaid/references/`（`api_reference.md`、`DIAGRAM_TYPES.md`），为外部 skill 带入，非知识库自身问题。

## 四、时效性指标

### 4.1 内容新鲜度

> `updated` 字段超过 N 个月未更新的文件视为陈旧。
>
> 刷新命令：
> ```bash
> cd YiKnowledge
> cutoff_6m=$(date -v-6m +%Y-%m-%d)
> cutoff_12m=$(date -v-12m +%Y-%m-%d)
> stale_6m=$(grep -rl "^updated: " --include="*.md" . | while read f; do
>   d=$(grep "^updated:" "$f" | head -1 | sed 's/updated: *//')
>   [[ "$d" < "$cutoff_6m" ]] && echo "$f ($d)"
> done | wc -l)
> stale_12m=$(grep -rl "^updated: " --include="*.md" . | while read f; do
>   d=$(grep "^updated:" "$f" | head -1 | sed 's/updated: *//')
>   [[ "$d" < "$cutoff_12m" ]] && echo "$f ($d)"
> done | wc -l)
> echo "Stale >6mo: $stale_6m, Stale >12mo: $stale_12m"
> ```

| 指标 | 当前 | 目标 | 告警阈值 | 趋势 |

## 使用约定

- **月度刷新是强制动作。** 看板数据的价值与其新鲜度成正比。超过一个月的看板数据视为不可靠。
- **趋势箭头**：↑ = 较上月改善，↓ = 较上月恶化，→ = 持平，— = 无历史数据。
- **告警阈值触发时**，对应指标标记 ⚠️，并在风险登记册中新增条目，在下月刷新前解决。
- **首次建立基线**：标记 `—` 的指标在本次刷新时执行对应命令，记录初始值作为下月对比基准。
- **反模式警示**：
  - 看板数据长期不刷新 → 失去参考价值。月度刷新是 Curator 的核心职责之一，不可跳过。
  - 缺口列表只增不减 → 成为抱怨清单而非改进工具。每条风险必须有负责人和预计解决日期。
  - 只看数字不行动 → 每个 ⚠️ 指标必须配对至少一个具体改进举措。
