# 知识地图 — 存在哪些知识

> **目的：** 绘制知识全景图——我们知道什么、知识在哪里、谁持有、谁消费。每季度更新。这张图回答三个核心问题：我们的知识资产是什么？哪些资产是安全的（已文档化）、哪些是脆弱的（在人脑中）？谁在消费这些知识？

## 适用场景

- **风险识别** — 通过隐性知识地图发现单点故障（唯一持有人的知识）
- **知识建设规划** — 根据显性知识覆盖度和隐性知识风险决定下季度建设重点
- **RAG 优化** — 确认哪些领域知识已文档化，AI 可检索到
- **人员变动应对** — 即将离职或转岗的成员，其隐性知识需要紧急捕获

### 隐性知识风险评级

| 风险等级 | 条件 | 示例 |
|---|---|---|
| 🔴 极高 | 唯一持有 + 核心功能依赖 + 无文档 | YiAi RAG 引擎内部机制 |

## 知识流向图

```
隐性知识（人脑）
    │
    │ 文档化（知识捕获流程）
    ▼
显性知识（YiKnowledge 文件）
    │
    ├──→ YiAi RAG 引擎 ──→ AI Agent 回答
    ├──→ Claude Code ──→ AI 辅助开发
    └──→ 人类开发者 ──→ 直接查阅
```

## 反模式

| 反模式 | 失效原因 | 正确做法 |
|---|---|---|
| 隐性知识持续隐性 | 单点故障；人走了知识就没了 | 每季度识别前 3 项隐性知识并文档化 |
| 知识地图从不更新 | 地图老化；展示错误的知识全貌 | 每季度更新；验证文件计数和持有者 |
| 缺口只识别不填补 | 列表只增不减 | 每个缺口指定负责人和时间线 |
| 地图只画显性不画隐性 | 隐性知识才是最大的风险来源 | 知识地图必须同时包含显性和隐性两个维度 |
