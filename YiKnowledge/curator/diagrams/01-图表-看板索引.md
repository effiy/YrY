# 知识看板索引

> **目的：** 通过定量看板追踪知识库健康状况。每月审查一次。四个看板各自关注知识库的一个健康维度，组合起来提供全景视图。

## 适用场景

- **月度健康检查** — Curator 每月执行看板刷新，观察指标趋势
- **季度汇报** — 使用看板数据向团队汇报知识库建设进展
- **发现问题** — 当某个指标跌破阈值时，触发专项治理行动
- **资源规划** — 根据覆盖度缺口决定下阶段知识建设的重点方向

## 使用说明

1. 每月执行一次看板刷新：统计文件数、运行新鲜度审计脚本、运行质量审计脚本
2. 记录本月数据与上月数据的对比，关注趋势变化
3. 对 ⚠️ 状态标记的指标在下月周期内优先处理
4. 覆盖度看板中的缺口如连续两个季度未填补，升级为 P0

**状态：** 所有角色目录均高于最低阈值。增长态势健康。

### 体量指标的解读

- **趋势 ↑** — 自然增长，方向正确
- **趋势 ↑↑** — 快速增长，需关注质量是否同步跟进
- **趋势 →** — 停滞，可能意味着知识收集机制失效
- **趋势 ↓** — 萎缩，可能是归档过度或内容流失

## 看板 2：新鲜度 — 知识是否及时？

| 指标 | 当前值 | 阈值 | 状态 |
|---|---|---|---|
| 含 `last_verified` 字段的文件占比 | ~60% | > 80% | ⚠️ 低于目标 |
| 6 个月内验证过的文件占比 | ~50% | > 70% | ⚠️ 低于目标 |
| `status: deprecated` 文件占比 | < 5% | < 10% | ✓ 健康 |
| `lifecycle: active` 文件占比 | ~40% | > 50% | ⚠️ 低于目标 |

**行动：** 执行新鲜度审计。更新所有文件的 `last_verified`；将陈旧文件标记为废弃。

```bash
# 查找 6 个月以上未验证的文件
rg "^last_verified: 202[56]" YiKnowledge -l | while read f; do
  date=$(rg "^last_verified:" "$f" | head -1 | awk '{print $2}')
  # 检查是否超过 6 个月
done
```

### 新鲜度不足的后果

- RAG 检索可能召回过时信息，影响 AI 回答质量
- 团队成员引用过时文档导致决策失误
- 废弃内容与活跃内容混在一起，降低查找效率

## 看板 3：质量 — 知识结构是否良好？

| 指标 | 当前值 | 阈值 | 状态 |
|---|---|---|---|
| Frontmatter 完整文件占比（8 个必填字段） | ~70% | > 90% | ⚠️ 低于目标 |
| 含 `benefit:` 字段文件占比 | ~50% | > 80% | ⚠️ 低于目标 |
| 含 `acceptance_criteria:` 文件占比 | ~40% | > 70% | ⚠️ 低于目标 |
| 含 `roles:` 字段文件占比 | ~60% | > 80% | ⚠️ 低于目标 |
| `related:` 死链占比 | 未知 | < 5% | ⚠️ 未测量 |

**行动：** 在所有文件上运行就绪检查清单；优先补齐 `benefit:` 和 `acceptance_criteria:` 字段（对 RAG 检索至关重要）。

```bash
# 查找缺少 benefit 字段的文件
find YiKnowledge -name "*.md" -not -path "*/rss/*" | while read f; do
  if ! rg -q "^benefit:" "$f"; then
    echo "MISSING benefit: $f"
  fi
done
```

### 质量指标的重要性排序

| 优先级 | 字段 | 缺少的后果 |
|---|---|---|
| P0 | `benefit:` | AI 无法判断该文件是否与用户问题相关 |
| P0 | `acceptance_criteria:` | 读者无法判断文件内容是否完整 |
| P1 | `roles:` | 按角色过滤搜索失败 |
| P1 | `last_verified:` | 无法判断内容是否仍然准确 |
| P2 | `related:` 正确性 | 导航断裂，信任度下降 |

## 月度审查检查清单

- [ ] 更新各角色目录的文件计数
- [ ] 执行新鲜度审计：`last_verified` > 6 个月 → 标记
- [ ] 执行质量审计：缺少 `benefit:` 或 `acceptance_criteria:` → 标记
- [ ] 审查覆盖度缺口：是否有新主题需要文档化？
- [ ] 用当前数据更新本看板

## 看板数据采集脚本

```bash
#!/bin/bash
# 快速健康检查脚本 —— 在 YiKnowledge 根目录运行

echo "=== 体量 ==="
for role in engineer executiver leader aier producter srer curator; do
  count=$(find "./$role" -name "*.md" -not -name "README.md" | wc -l | tr -d ' ')
  echo "$role: $count files"
done

echo ""
echo "=== 新鲜度 ==="
total=$(find . -name "*.md" -not -path "*/rss/*" | wc -l | tr -d ' ')
verified=$(rg -l "^last_verified:" . --type md | wc -l | tr -d ' ')
echo "Files with last_verified: $verified / $total"

echo ""
echo "=== 质量 ==="
missing_benefit=$(find . -name "*.md" -not -path "*/rss/*" | while read f; do
  rg -q "^benefit:" "$f" || echo "$f"
done | wc -l | tr -d ' ')
echo "Files missing benefit: $missing_benefit / $total"
```

## 反模式

| 反模式 | 失效原因 | 正确做法 |
|---|---|---|
| 看板无阈值 | 无法判断数字好坏 | 每项指标必须有目标值或阈值 |
| 看板一年审查一次 | 问题恶化 12 个月才被发现 | 月度审查；能自动化的尽量自动化 |
| 覆盖度缺口只记不补 | 缺口列表只增不减 | 每个缺口指定负责人，纳入迭代跟踪 |
| 只看体量不看质量 | 文件数量上去了但全是占位符 | 体量 + 质量 + 新鲜度三维度同步关注 |
| 数据靠手动记忆 | 数据不准确，看板沦为形式 | 使用脚本采集基线数据，人工仅做判断 |
