# 架构成熟度评估 — 2026-08

> **YrY 单体仓库各项目架构成熟度基线评估。** 此评估以统一模型衡量 YiAi、YiVad、YiPet、YiKnowledge 四个子项目的架构纪律，识别差距并指导下一季度改进方向。

## 成熟度等级定义

| 等级 | 名称 | 标准 |
|-------|------|----------|
| 1 | 初始级 (Initial) | 临时性的、无文档化的架构 |
| 2 | 管理级 (Managed) | 架构已文档化，但未被强制执行 |
| 3 | 定义级 (Defined) | 架构已文档化，模式被强制执行 |
| 4 | 度量级 (Measured) | 采集架构指标，定期审查 |
| 5 | 优化级 (Optimizing) | 持续架构改进 |

### 各等级详细说明

**等级 1 — 初始级**：不做架构决策记录，代码结构无模式可循。适合原型和实验性项目，不适合生产系统。

**等级 2 — 管理级**：有架构图或文档，但实际代码不一定遵守。缺少自动化检查手段，依赖人工 Code Review 发现偏离。

**等级 3 — 定义级**：架构模式明确文档化（CLAUDE.md、ADR），分层边界被强制执行（目录结构、`__init__.py` 公共 API、模块导入规则）。Code Review 中有明确的架构检查项。

**等级 4 — 度量级**：设置架构适应性函数 (Architecture Fitness Functions)，CI 流水线检查层级违规、循环依赖、未授权的跨模块导入。定期生成架构健康报告。

**等级 5 — 优化级**：基于度量数据持续优化架构。每季度评估架构是否匹配业务增长需求。主动识别应拆分或合并的模块。

## 项目评估

| 项目 | 等级 | 证据 |
|---------|-------|----------|
| **YiAi** | 3 (定义级) | domain/services/server 三层分层强制执行；`__init__.py` 定义公共 API；关键决策有 ADR 记录；零测试覆盖是主要差距 |
| **YiVad** | 3 (定义级) | ProTable 规范模式；`v-auth` 指令；模块边界已文档化；零测试覆盖是主要差距 |
| **YiPet** | 3 (定义级) | 四层 API 架构；双世界边界；CDN 目录系统；零集成测试是主要差距 |
| **YiKnowledge** | 2 (管理级) | 7 个角色目录；强制要求 frontmatter；定义审查周期；交叉引用存在断链 |

### YiAi 详细评估

**优势**：
- 三层架构（domain/services/server）清晰分离关注点
- 通过 `__init__.py` 显式管理公共 API
- RPC 信封路由是单一的跨项目协议入口
- 已有 76 个 pytest 测试，shared 模块覆盖率 92%+

**改进方向**：
- 为 domain 层添加测试（当前覆盖率为 0%）
- 设置架构适应性函数检查层级依赖方向
- ADR 覆盖面需扩展到 agent 循环、知识监听器等领域

### YiVad 详细评估

**优势**：
- ProTable 作为规范数据展示模式
- `v-auth` 指令实现声明式按钮级权限
- Rsbuild 构建流水线定义清晰
- 模块边界在 CLAUDE.md 中文档化

**改进方向**：
- 零测试覆盖——任何重构都携带未知回归风险
- 引入 Vitest 后需建立 composable 测试覆盖基线
- RPC 参数名称契约需自动化验证

### YiPet 详细评估

**优势**：
- 四层 API 层（client → endpoints → types → services）职责分离清晰
- Chrome MV3 双世界边界明确，ISOLATED/MAIN 隔离规则文档化
- CDN 目录系统管理 80+ 厂商库

**改进方向**：
- 双世界边界的集成测试为零——边界违规在运行时才暴露
- 厂商库版本对齐是手动的——React 和 ReactDOM 版本不匹配会导致整个扩展崩溃

### YiKnowledge 详细评估

**优势**：
- 7 个角色目录覆盖所有知识类型
- frontmatter 规范强制执行
- 审查周期和生命周期状态定义

**改进方向**：
- 交叉引用存在断链（2026-08-21 修复了 15+ 处）
- 无自动化链接完整性检查
- 需定义文档覆盖率度量指标

## 关键差距

1. **无自动化架构适应性函数** —— CI 中无层级违规检查，所有架构合规依赖人工 Code Review
2. **YiVad 和 YiPet 零测试覆盖** —— YiAi 已有初步 pytest 覆盖（76 个测试），前端项目仍为空白
3. **跨项目契约测试缺失** —— RPC 参数名称契约（`filter`/`query`、`target_file`/`path`）无自动化验证，曾导致实际 bug
4. **YiKnowledge 交叉引用完整性** —— 2026-08-21 发现并修复 15+ 处断链，此后无持续检查机制

## 适用场景

- 季度架构审查时作为基线参考
- 向新成员阐述各项目的架构纪律水平
- 为技术债务优先级排序提供数据支持
- 评估引入自动化架构检查的投资回报率

## 反模式

- **为追求高等级而过度工程化。** 等级 3-4 对当前单人项目规模已足够，无需过早引入等级 5 的度量体系
- **仅评估而不改进。** 评估的价值在于驱动改进，不在于分数本身。每个季度的差异变化比绝对等级更重要
- **跨项目使用统一标准否决差异。** YiKnowledge 和 YiAi 的架构需求不同，不应用同一套指标评判
