## 关键数据流

### 聊天请求流（最高频路径）

```
用户输入 → YiVad/YiPet → RequestHttp/ApiClient
  → POST / {module:"services.ai.chat_service", method:"chat", params:{...}}
  → YiAi RPC Router → Chat Service → Ollama LLM
  → SSE 流式响应 → 前端逐 token 渲染
```

### RAG 查询流

```
用户提问 → YiVad/YiPet → RPC Envelope
  → YiAi RAG Engine → llama_index 混合检索（向量 + BM25）
  → 检索 YiKnowledge 文档 → LLM 生成回答
  → 返回带来源引用的回答
```

### 知识同步流

```
YiKnowledge 文件变更
  → YiAi Knowledge Watcher (apscheduler 60s 轮询)
  → 比对文件哈希 → 检测变更文件
  → 解析 frontmatter → upsert MongoDB knowledge_files
  → llama_index 更新向量索引
```

## 关键架构决策

| 决策 | 选择 | 理由 | ADR |
|---|---|---|---|
| 跨项目通信协议 | RPC 信封 `{module, method, params}` | 统一协议，避免 REST/GraphQL 混用 | — |
| LLM 接口 | llama_index.llms 统一抽象 | RAG 引擎已深度绑定，不引入额外抽象层 | [LLM 提供商](../decisions/yiai/02-决策-LLM多提供商上线.md) |
| LLM 容灾 | 多提供商路由 (Ollama + 云 API) | 消除 Ollama 单点故障 | [LLM 路由](../decisions/yiai/05-决策-LLM流量跨提供商路由.md) |
| 知识监听 | apscheduler 轮询 (5s) | macOS FSEvents 静默丢事件 | [Knowledge Watcher](../decisions/yiai/01-决策-Knowledge-Watcher部署.md) |
| 前端构建 | Vite → Rsbuild 迁移 | 更快的 HMR，更好的 Vue 3.5 支持 | [Rsbuild 迁移](../decisions/yivad/02-决策-Vite到Rsbuild迁移.md) |
| YiPet 架构 | MV3 双世界 + 四层 API | Content Script 和 Service Worker 隔离 | [双世界](../decisions/yipet/03-决策-Chrome-MV3双世界架构.md) |
| YiPet 代码质量 | ESLint → Biome 2.5 | 更快、更少配置、一次迁移 | [Biome](../decisions/yipet/02-决策-Biome代码检查与格式化.md) |
