# 配置管理策略

> 配置和代码必须分离。代码从仓库 clone 出来就能运行——不需要修改代码来适配环境。

## 核心原则

1. **代码和配置严格分离** — 环境差异（端口、密钥、连接字符串）不在代码中，在配置中
2. **配置 = 文件 + 环境变量** — 文件存默认值和结构，环境变量覆盖敏感或环境特定值
3. **绝不提交密钥** — `.env`、含密钥的 `config.yaml` 在 `.gitignore` 中
4. **配置有文档** — 每个配置项的含义、默认值、可选值都有说明
5. **配置有验证** — 启动时验证必需配置项——启动失败优于运行中崩溃

## YrY 按项目的配置策略

### YiAi (Python) — `config.yaml` + 环境变量

```yaml
# config.yaml — 提交到 git（不含密钥）
server:
  host: "0.0.0.0"
  port: 10086
  workers: 1

mongodb:
  uri: ${MONGODB_URI}           # 环境变量覆盖
  database: "yry"
  max_pool_size: 50

ollama:
  base_url: ${OLLAMA_BASE_URL:-http://localhost:11434}  # 默认值
  model: ${OLLAMA_MODEL:-qwen2.5}
  timeout: 30

llm:
  cloud_api_key: ${CLOUD_LLM_API_KEY}  # 密钥——仅环境变量
  cloud_model: ${CLOUD_LLM_MODEL}

knowledge:
  watcher_poll_seconds: 60
  root_path: "../YiKnowledge"

rag:
  hybrid_search: true
  top_k: 5
```

**规则**：
- `config.yaml` 提交到 git——包含所有非敏感配置和结构
- 敏感值（密钥、密码、连接字符串）使用 `${ENV_VAR}` 占位符
- 实际值通过 `.env` 文件或系统环境变量注入
- `.env` 和 `config.local.yaml` 在 `.gitignore` 中

**Python 加载模式**：
```python
# src/config.py
import os
import yaml

def load_config():
    with open("config.yaml") as f:
        config = yaml.safe_load(f)

    # 环境变量替换 ${VAR_NAME}
    config = resolve_env_vars(config)

    # 验证必需配置
    validate_config(config)

    return config

def validate_config(config):
    required = ["mongodb.uri"]
    for key in required:
        value = get_nested(config, key)
        if not value:
            raise ConfigError(f"缺少必需配置: {key}")
```

### YiVad (Vue 3) — `.env` 文件

Rsbuild 内置支持 `.env` 文件：

```bash
# .env.development — 提交到 git
RSBUILD_API_BASE=http://localhost:10086
APP_TITLE=YiVad (Dev)

# .env.production — 提交到 git
RSBUILD_API_BASE=https://api.example.com
APP_TITLE=YiVad

# .env.local — 不提交（开发者本地覆盖）
RSBUILD_API_BASE=http://192.168.1.100:10086
```

**规则**：
- `VITE_` 或 `RSBUILD_` 前缀的变量暴露给前端代码
- `.env.development` 和 `.env.production` 提交到 git
- `.env.local` 不提交——开发者本地覆盖
- 前端**绝不**存密钥——前端代码对用户完全可见

**使用**：
```typescript
// 构建时注入——不是运行时读取
const API_BASE = process.env.RSBUILD_API_BASE;
```

### YiPet (Chrome 扩展) — 构建时配置

Chrome 扩展没有传统的环境变量。使用构建时替换：

```javascript
// rsbuild.config.ts
export default {
  source: {
    define: {
      'process.env.API_BASE': JSON.stringify(
        process.env.RSBUILD_API_BASE || 'http://localhost:10086'
      ),
    },
  },
};
```

对于开发/生产切换，使用不同的构建命令：
```bash
npm run build:dev   # API_BASE=http://localhost:10086
npm run build:prod  # API_BASE=https://api.example.com
```

## 密钥管理

### 密钥存储层次

| 方法 | 安全性 | 适用场景 |
|---|---|---|
| **环境变量** | 中 | 开发环境、单机部署 |
| **密钥管理服务**（AWS Secrets Manager, Vault） | 高 | 生产环境、多机部署 |
| **`.env` 文件** | 低 | 仅本地开发（绝不到生产） |
| **代码中硬编码** | 最差 | 绝不 |

### YrY 密钥清单

| 密钥 | 位置 | 格式 |
|---|---|---|
| MongoDB URI | 环境变量 `MONGODB_URI` | `mongodb://user:pass@host:27017/db` |
| Ollama（本地） | 无需密钥 | — |
| 云 LLM API Key | 环境变量 `CLOUD_LLM_API_KEY` | `sk-xxx` |
| JWT Secret | 环境变量 `JWT_SECRET` | 随机字符串（`openssl rand -hex 32`） |

### 密钥轮换

- 云 API Key：每季度或怀疑泄露时轮换
- JWT Secret：泄露时立即轮换（轮换后所有已签发 Token 失效——需要用户重新登录）
- 数据库密码：每半年或人员离职时轮换

## 跨项目通用配置约定

| 参数 | YiAi | YiVad | YiPet | 说明 |
|---|---|---|---|---|
| API 地址 | `server.port: 10086` | `RSBUILD_API_BASE` | `API_BASE` | YiAi 是服务端，前端是客户端 |
| 开发端口 | `10086` | `8848` | — | 避免端口冲突 |
| MongoDB | `mongodb.uri` | — | — | 仅 YiAi 直接访问 |
| LLM 模型 | `ollama.model` | — | — | 可配置切换模型 |
| 日志级别 | — | — | — | 建议：dev=DEBUG, prod=INFO |

## 环境差异管理

```
开发环境 (dev)         生产环境 (prod)
─────────────          ─────────────
本地 MongoDB            MongoDB Atlas 或远程实例
Ollama 本地 GPU         云 LLM API（或自托管 Ollama）
DEBUG 日志              INFO 日志
CORS 宽松               CORS 严格（仅允许生产域名）
无认证/本地认证          认证启用
健康检查无告警           健康检查有告警
```

**切换规则**：一次 `config.yaml` 或环境变量的修改就能切换环境——不需要改代码。

## 配置变更流程

1. 新增配置项 → 在 `config.yaml` 中添加（含注释说明含义和默认值）
2. 修改默认值 → 评估对现有部署的影响
3. 删除配置项 → 确认无代码仍在读取
4. 所有变更 → 更新本文档中的配置清单

## 反模式

| 反模式 | 失败原因 | 正确做法 |
|---|---|---|
| `if (isDev) { ... } else { ... }` | 代码中有环境分支→环境和代码耦合 | 配置驱动——代码读配置，不判断环境 |
| 密钥提交到 git | 即使后续删除，git 历史中仍存在 | `.gitignore` + 提交前检查（git hook） |
| 默认配置不适合生产 | 生产环境忘记覆盖→用开发配置跑生产 | 生产环境显式设置所有关键配置；缺失时启动失败 |
| 配置散落各处 | 有的在 `config.yaml`，有的在代码常量，有的在数据库 | 单一配置入口——`config.yaml` + 环境变量 |
| 配置无文档 | "这个配置是什么意思？"——只有原作者知道 | 每个配置项有注释；关键配置列入本文件 |
