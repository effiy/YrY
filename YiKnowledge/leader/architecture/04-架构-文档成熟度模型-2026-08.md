# 文档成熟度评估 — 2026-08

> **YrY 单体仓库各项目文档成熟度基线评估。** 文档成熟度是团队知识传递效率的关键指标——好的文档让新人能独立上手，差的文档让每次交接都依赖口头传授。

## 成熟度等级定义

| 等级 | 名称 | 标准 |
|-------|------|----------|
| 1 | 初始级 | 除代码注释外无文档 |
| 2 | 管理级 | 每个项目有 README，存在入职指引 |
| 3 | 定义级 | CLAUDE.md + README + ADR + 知识库体系 |
| 4 | 度量级 | 文档覆盖率度量、时效性检查 |
| 5 | 优化级 | 自动文档生成、交叉引用完整性 CI 检查 |

### 各等级详细说明

**等级 1 — 初始级**：代码即文档。假设读者能通过阅读代码理解系统设计。团队知识的唯一来源是作者本人。

**等级 2 — 管理级**：有基础文档（README、简单的入职指引），但文档与实际代码可能脱节。文档更新靠个人自觉，无制度约束。

**等级 3 — 定义级**：建立文档体系（CLAUDE.md 定义项目约束、ADR 记录架构决策、知识库存储领域知识）。frontmatter 强制要求元信息。文档是开发流程的正式产出物。

**等级 4 — 度量级**：量化追踪文档质量。自动化检查文档与代码的一致性（如接口文档与 API 路由的对比）。跟踪文档时效性（超过 N 天未更新则告警）。

**等级 5 — 优化级**：从代码自动生成部分文档（API 文档、架构图）。持续优化信息架构，确保知识可在 2 次点击内找到。

### 各项目详细分析

**YiAi**：后端文档覆盖了架构分层、RPC 协议、MongoDB 集合设计、知识监听器等核心模块。主要差距在于缺少 API 端点文档（当前依赖阅读路由代码）。

**YiVad**：前端文档覆盖了 ProTable 模式、权限体系、动态路由、组件注册机制。主要差距在于缺少 composable 和 API 调用链的文档。

**YiPet**：扩展文档覆盖了 MV3 双世界架构、四层 API 层、CDN 目录系统、跨项目桥接。主要差距在于 content-script 与 service-worker 通信协议缺乏图示。

**YiKnowledge**：知识库文档覆盖了命名规范、流水线阶段、治理流程。主要差距在于交叉引用完整性无自动化保障。

## 关键差距

1. **无自动化时效性检查** —— 文档可能无声地过时，无法及时检测
2. **交叉引用完整性** —— 2026-08-21 发现并修复 15+ 处断链，此后无持续检查机制
3. **无文档覆盖率度量和指标** —— 无法量化哪些模块缺少文档
4. **入职指引文档** —— 三个项目各有一份，但未经新入职者验证其有效性
5. **无 API 端点文档** —— YiAi 的 RPC 端点和 REST 端点依赖阅读代码了解接口定义

## 改进建议

1. **添加 CI 检查，验证所有 `related` 链接可解析到实际文件**：优先级 P0，工作量约 1 天
2. **添加 `last_verified` 时效性检查**：对超过 90 天未验证的文档发出警告，优先级 P1，工作量约 2 天
3. **每次有新成员加入时执行入职指引文档**，收集反馈并修正，优先级 P1，随入职节奏进行
4. **为 YiAi 添加 API 端点文档**：使用 FastAPI 自带的 OpenAPI 生成，或编写手动文档，优先级 P2
5. **建立文档覆盖率基线**：统计每个模块/服务的文档条目数量，设定最低标准，优先级 P2

## 常见问题

**Q: CLADE.md 和 README 的区别是什么？**
A: README 面向人类读者（架构概述、快速开始），CLAUDE.md 同时面向 AI 助手和人类（包含详细的模块边界、约束、近期变更）。CLAUDE.md 内容更结构化，适合机器解析。两者互补而非替代。

**Q: 文档应该详细到什么程度？**
A: 能够支持一个新人在 1 天内独立完成一个小功能变更即为足够。如果每次小改动都需要询问作者，说明文档不够充分。

## 反模式

- **为写文档而写文档。** 无法支持实际决策或开发的文档是噪音。每份文档都应回答一个明确的问题（如"这个模块的边界在哪？"、"为什么当时选了这个技术？"）
- **一次性写完后永不更新。** 每月至少检查一次文档与代码的一致性。过时的文档比没有文档更危险（它提供错误的假设）
- **仅面向 AI 编写。** YrY 的 CLAUDE.md 和知识库同时服务人类和 AI，文档的可读性不能被忽略
