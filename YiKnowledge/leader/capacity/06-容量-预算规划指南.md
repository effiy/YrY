# 工程预算规划指南

> 预算是技术战略的数字表达。一个没有预算支持的技术战略只是愿望清单。

## 预算类别

| 类别 | 占比（典型） | 包含内容 |
|---|---|---|
| **人员** | 60-80% | 薪资、福利、 contractor、培训 |
| **基础设施** | 10-25% | 云服务、数据库、GPU/服务器、域名、CDN |
| **工具与服务** | 5-15% | SaaS 订阅、IDE 许可证、监控工具、API 按量付费 |
| **其他** | 2-5% | 差旅、会议、设备、书籍/学习 |

## 预算估算方法

### 人员预算

```
年度人员预算 = 人数 × 年均成本 × (1 + 间接成本率)

年均成本 = 薪资 + 奖金 + 福利（通常为薪资的 20-40%）
间接成本率 = 办公空间、设备、管理 overhead（通常为 15-25%）
```

**YrY 简化版**（单人项目，无正式薪资）：
- 人员成本 = 机会成本——如果这份工作的时间花在别处，收入是多少
- 不进入正式预算，但做决策时应意识到这个成本

## 常见遗漏项（最易超预算的原因）

| 遗漏项 | 为什么容易漏 | 估算方法 |
|---|---|---|
| **数据传输费** | 云服务 ingress 免费，egress 收费 | 估算月度出站流量 × $0.05-0.12/GB |
| **备份存储** | "我们有数据库就够了"——备份是额外的 | 主存储 × 1.5-2× |
| **预生产环境** | staging/dev 环境常被遗忘 | 生产环境的 30-50% |
| **SSL/域名续费** | 每年一次，平时不关注 | $10-100/年 |
| **税费** | 云服务账单通常不含税 | 加 5-15% 取决于地区 |
| **培训/学习** | "工程师自己会学" | $500-2000/人/年 |

## 预算时间线

### 年度预算规划

| 时间 | 活动 |
|---|---|
| **Q3 中** | 收集下一年需求——新项目、团队扩张、技术升级 |
| **Q3 末** | 提交预算初稿 |
| **Q4 初** | 预算审查和协商 |
| **Q4 末** | 预算定稿 |
| **Q1 初** | 预算生效 |

### 预算追踪

每月对比实际 vs. 预算：

| 类别 | 月度预算 | 本月实际 | 偏差 | 说明 |
|---|---|---|---|---|
| 基础设施 | $224 | $198 | -12% | 预留实例折扣生效 |
| 工具/服务 | $20 | $20 | 0% | |
| **合计** | $244 | $218 | -11% | |

偏差 > 15% 时需要分析原因。

## 预算削减场景

当被要求削减预算时，按此顺序回应：

| 选项 | 影响 | 建议 |
|---|---|---|
| **削减余量（20%→10%）** | 缓冲变薄——小波动可能超预算 | 可接受——余量本来就包含缓冲 |
| **推迟非关键项目** | 下季度启动，不影响当前服务 | 优先选项——用时间换预算 |
| **降配**（M10→M5, 4 核→2 核） | 性能下降，可能需要更多优化 | 可行——但需评估性能影响 |
| **取消备份/冗余** | 单点故障风险增加 | 不推荐——这是用可靠性换预算 |
| **砍人头** | 交付能力下降 | 最后选项——影响不可逆 |

## 反模式

| 反模式 | 失败原因 | 正确做法 |
|---|---|---|
| "去年预算 + 10%" | 不考虑实际需求变化——去年需要 2 台服务器不代表今年需要 3 台 | 零基预算——从需求出发，不从去年出发 |
| 不设余量 | 任何意外都导致超预算——预算变"错误"而非"参考" | 20-30% 余量 |
| 不追踪 | 年底才发现超预算 50%——无可挽回 | 每月对比实际 vs. 预算 |
| 把预算当目标花 | "预算没用完，年底突击花掉"——浪费 | 省下的预算 = 省下的钱，不是需要花掉的钱 |
| 预算只包含新增不包含维护 | 只算了新项目的人力，忘了现有系统需要维护 | 维护成本 = 基础设施 + 20% 人力用于维护现有系统 |
