# 路线图进度看板

> **作为**技术负责人，**我想要**一目了然地追踪路线图进展，**以便**及早发现问题、向利益相关者沟通状态、做出数据驱动的调整。
>
> 此看板是技术负责人每周检查路线图健康状况的核心工具。它不替代详细的项目管理工具，而是提供一个高层视角——哪些在轨道上，哪些偏离了。

## 看板布局

### 第一部分：容量与分配

| 指标 | 当前 | 目标 | 状态 |
|---|---|---|---|
| 净容量（人周）| | | |
| 产品功能占比 (%) | | 50–60% | |
| 技术投入占比 (%) | | 20–30% | |
| 运维占比 (%) | | 10–15% | |
| 探索占比 (%) | | 5–10% | |
| 缓冲消耗 (%) | | — | |

**说明**：
- **净容量**：团队在本季度实际可用于路线图工作的人周数（扣除假期、培训、会议等开销后）
- **产品功能占比**：直接对用户可见的功能开发工作所占比例
- **运维占比**：如果持续超过 15%，说明技术债或可靠性问题正在消耗过多开发资源
- **缓冲消耗**：本季度应付意外工作的缓冲余量——低于 5% 时需要警惕

## 如何使用此看板

### 每周检查（技术负责人，15 分钟）

1. 扫查容量：缓冲是否比预期更快被消耗？
2. 检查功能状态：自上周以来是否有项目变黄或变红？
3. 审查风险：是否有新风险？是否有已变为现实的风险？

### 每月检查（技术负责人 + 产品，30 分钟）

1. 审查功能交付与计划：本季度是否在按计划推进？
2. 检查容量分配：是否达到了目标比例分配？
3. 审查技术债务趋势：积压量在增加还是减少？

### 季度检查（技术负责人 + 工程领导层，1 小时）

1. 全面审查所有部分
2. 比较本季度的计划 vs 实际
3. 将发现的问题输入下一季度的[路线图规划](./plan-tech-roadmap.md)和[容量计划](./do-a-capacity-plan.md)

## 适用场景

- 每周技术负责人例行状态检查
- 向管理层汇报工程团队进展的数据来源
- 早期风险预警——在问题变成阻塞前识别
