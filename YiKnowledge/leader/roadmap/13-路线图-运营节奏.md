# 技术负责人运营节奏

> 技术负责人最大的时间管理陷阱是"救火模式"——持续被紧急但不重要的事打断。结构化的节奏让你从被动响应转向主动引导。

## 节奏总览

| 层级 | 频率 | 核心活动 | 产出物 |
|---|---|---|---|
| **周** | 每周 | 扫查看板、代码审查、技术决策 | 状态更新、ADR（如需要） |
| **月** | 每月 | 成本审查、技术债审查、风险登记册更新 | 月度简报、优化行动项 |
| **季度** | 每季度 | 路线图审查、OKR 评分、战略调整 | 季度汇报、下季度路线图 |

## 单人项目 vs 团队项目

| 活动 | 单人项目 (YrY 当前) | 团队项目 (未来) |
|---|---|---|
| 周站会 | 自我检查——本周计划 vs 实际 | 团队 15 分钟站会 |
| 1:1 会议 | 不需要 | 每周每人 30 分钟 |
| 代码审查 | 自我审查（检查清单） | 团队审查 |
| 回顾会议 | 月度自我回顾 | 团队双周回顾 |
| 技术讨论 | 写 ADR 自我辩论 | 团队 RFC 讨论 |

**单人项目的关键原则**：仪式感 > 形式感。独自走一遍流程（自问自答）比跳过流程好。

## 周节奏

### 周一：规划 (15 min)

```
任务：确定本周最重要的 3 件事
输入：上个周五的回顾 + 路线图优先级
输出：本周 3 个目标（写在看板上）
```

规则：3 件事就够了。如果列了 10 件，你一件都完成不了。

### 周三：深度工作检查 (5 min)

```
任务：检查周目标进展
问题：我在按计划推进吗？有什么意外消耗了时间？
行动：如果意外消耗 > 20% 时间，调整本周目标
```

### 周五：回顾 + 下周预览 (15 min)

```
任务：回顾本周 + 更新状态
检查清单：
  □ 本周 3 个目标达成了几个？
  □ 进度看板需要更新吗？
  □ 有新的技术债务需要登记吗？
  □ 有需要写的 ADR 吗？
  □ 下周的 3 个目标是什么？
```

### 每周固定时间块

| 时间块 | 时长 | 内容 | 不可侵犯性 |
|---|---|---|---|
| **深度工作时间** | 每天 3-4h 连续 | 编码、设计、写 ADR | 最高——关闭通知 |
| **代码审查** | 每天 30 min | 审查自己的代码（checklist） | 高 |
| **学习时间** | 每周 2-3h | 阅读技术文章、实验新工具 | 中——可在繁忙周缩减 |
| **行政/杂务** | 每周 2h | 邮件、许可证、依赖更新 | 低——碎片时间处理 |

## 月节奏

### 第一周：成本 + 数据回顾 (1h)

```
□ 填写月度成本追踪模板
□ 审查成本趋势：与上月对比，有异常吗？
□ 检查 DORA 指标（如果可测量）
□ 更新风险登记册——有新风险吗？状态变化？
```

产出：[成本追踪模板](../capacity/02-容量-成本追踪模板.md) 当月数据。

### 第二周：技术债 + 依赖审查 (1h)

```
□ 审查技术债务登记册前三项——有进展吗？
□ 运行依赖审计检查清单（pip audit / npm audit）
□ 检查是否有需要升级的关键依赖
□ 评估是否有新的技术债务产生
```

产出：[技术债管理](./08-路线图-管理技术债.md) 月度更新。

### 第三周：知识库维护 (1h)

```
□ 审查是否有超过 review_cycle 未审核的文档
□ 检查交叉引用完整性
□ 检查是否有应该归档或标记为 superseded 的文件
□ 审查 frontmatter 规范——新文件是否符合？
```

### 第四周：下月预览 (30 min)

```
□ 回顾本月 3 个目标达成情况
□ 对照季度路线图——我们在轨道上吗？
□ 确定下月 3 个重点
□ 预估下月容量（有假期/计划吗？）
```

## 季度节奏

详见 [11-路线图-季度审查流程](./11-路线图-季度审查流程.md)。

### 季度前 2 周：规划准备

```
□ 收集 Q3 数据（交付、事故、技术债、成本）
□ 阅读技术战略文档——方向需要调整吗？
□ 起草下季度 OKR
□ 估算下季度容量
```

### 季度第 1 周：规划 + 对齐

```
□ 完成季度路线图
□ 与产品对齐优先级
□ 确定下季度技术投入占比
□ 更新架构/文档成熟度评估
```

### 季度末：回顾 + 汇报

```
□ 执行季度审查流程
□ OKR 评分和复盘
□ 撰写高管一页纸汇报
□ 更新技术债务优先级
□ 审查并更新所有季度审查周期的文档
```

## 年度节奏

| 时间 | 活动 |
|---|---|
| 1 月 | 年度技术战略规划；去年回顾 |
| 4 月 | Q1 回顾；年度目标中期检查 |
| 7 月 | 半年回顾；下半年战略调整 |
| 10 月 | Q3 回顾；来年规划预研 |

## YrY 单人项目建议节奏

当前单人项目，节奏可以简化但不跳过核心环节：

| 必须保留 | 可以简化 |
|---|---|
| 周规划 (3 个目标) | 不需要站会 |
| 月成本检查 | 成本只有 ~$45，检查可以很快 |
| 季度路线图审查 | 不需要 1:1 会议 |
| 风险登记册月更 | 不需要团队回顾 |
| ADR 在重要决策时写 | 不需要 RFC 讨论 |

## 反模式

| 反模式 | 失败原因 | 正确做法 |
|---|---|---|
| "太忙没时间规划" | 不规划的时间会被紧急事务填满——永远"太忙" | 规划和深度工作放入日历，视为和会议一样不可侵犯 |
| 周目标列 10 项 | 永远完不成，失去对规划系统的信任 | 3 件就够了；完成 3 件 > 开始 10 件 |
| 孤立主义——不向外界同步 | 高管不知道你在做什么，你自己也不知道优先级是否正确 | 至少每季度有一次向上沟通（一页纸汇报） |
| 单人项目跳过所有仪式 | 无节奏 → 无方向 → 每个季度都在救火 | 最小仪式：周规划 + 月检查 + 季审查 |
| 仪式变成负担——走过场 | 填了表格但从不看、不行动——虚假的安全感 | 如果一项仪式连续 3 次不产生行动，就修改或删除它 |
