# 团队健康检查

> 等到正式回顾会议才发现问题，问题已经存在了 2 周。健康检查让你在问题还小时就发现它。

## 健康检查怎么用

1. 每季度（或每月）团队成员独立打分
2. 每个人对 10 个维度评 🟢🟡🔴
3. 匿名汇总后团队讨论——聚焦 🔴 和 🟢/🟡 差异大的维度
4. 选择 1-2 个改进项

**规则**：不讨论"谁评了什么"——讨论"我们看到什么模式、怎么改进"。

## 10 个健康维度

| # | 维度 | 🟢 健康 | 🟡 有些问题 | 🔴 需要改进 |
|---|---|---|---|---|
| **1** | **交付价值** | 我们持续交付用户关心的东西 | 交付节奏不稳定，有时快有时慢 | 我们不清楚自己交付的有没有价值 |
| **2** | **代码质量** | 代码容易修改，测试保护我们 | 有些地方碰不得，改了总出问题 | 代码质量在下降，每次修改都很危险 |
| **3** | **技术债务** | 我们有计划地偿还债务 | 债务在积压，但我们在追踪 | 债务不管控，交付速度明显下降 |
| **4** | **学习成长** | 我在学新东西，技能在提升 | 偶尔有新挑战，但大多是重复工作 | 我感觉技能停滞，没有成长机会 |
| **5** | **团队合作** | 我们互相信任，合作顺畅 | 偶尔有摩擦，但能解决 | 团队氛围有问题，我在避免某些互动 |
| **6** | **使命清晰** | 我知道我们为什么做这些事 | 大概知道方向，但不清楚优先级 | 我不知道我们在做什么，为什么做 |
| **7** | **发布安全** | 发布简单可靠，随时可以上线 | 发布有时会出问题 | 每次上线都紧张，经常需要回滚 |
| **8** | **技术方向** | 技术路线图清晰，决策有依据 | 大概有方向，但经常临时改 | 不知道架构要往哪走 |
| **9** | **工具和流程** | 工具得心应手，流程帮助我 | 有些工具/流程在拖慢我 | 被工具和流程阻碍，想做的东西做不了 |
| **10** | **工作负荷** | 工作负荷健康，有时间深度思考 | 偶尔加班但可控 | 持续高压，感觉 burnout |

## 讨论引导

健康检查的目的是**发现盲点**，不是打分排名。讨论时用这些问题引导：

- "哪个维度的结果最让你意外？"
- "🔴 的维度中，哪个如果修好了会有最大的杠杆效应？"
- "我们有没有看到一个模式？——是不是多个 🔴 有共同的根因？"
- "自上次健康检查以来，哪些维度有改善？哪些恶化了？"

## 根据结果行动

| 发现 | 行动 |
|---|---|
| **交付价值** 🔴 | 回顾最近交付的功能——用户真的在用吗？和产品经理对齐优先级 |
| **代码质量 + 技术债务** 同时 🔴 | 提高技术投入占比；下个迭代至少 20% 技术债削减 |
| **学习成长** 🔴 | 引入学习周五、内部技术分享、分配新类型的工作 |
| **使命清晰** 🔴 | 技术负责人需要更频繁地同步"为什么"——不只是"做什么" |
| **工作负荷** 🔴 | 检查在做什么——哪些可以不做、推迟或委托 |

## 单人项目的"健康检查"

单人项目没有团队可评，但自评仍然有价值——它强迫你诚实地审视现状：

```
日期：____年__月__日

维度                          自评    证据
1. 代码质量                   🟢/🟡/🔴  [我的代码改起来害怕吗？]
2. 技术债务                   🟢/🟡/🔴  [债务登记册在增长还是减少？]
3. 学习成长                   🟢/🟡/🔴  [这个月在学新东西吗？]
4. 使命清晰                   🟢/🟡/🔴  [我知道自己在做什么吗？为什么？]
5. 工作负荷                   🟢/🟡/🔴  [工作时间可控吗？有 burnout 前兆？]

本月需要改进的 1 件事：
```

## 趋势追踪

每次健康检查结果记录下来，看趋势：

| 日期 | 交付 | 质量 | 债务 | 成长 | 合作 | 使命 | 发布 | 方向 | 工具 | 负荷 | 热点 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| Q3 | 🟢 | 🟡 | 🟡 | 🟢 | — | 🟢 | 🟡 | 🟢 | 🟢 | 🟢 | 代码质量+债务 |
| Q4 | | | | | | | | | | | |

**趋势比单次评分更有价值**——一个维度从 🟢→🟡→🔴 比一直都是 🔴 更需要关注。

## 适用场景

- 团队建设——在问题变成冲突之前发现
- 季度回顾——和路线图审查一同进行
- 组织变革后——团队重组、新成员加入后的温度检查
