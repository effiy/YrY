# ADR: YiKnowledge 文件名序号采用三位零填充（001/012/108）统一格式

> **状态**：已接受 (2026-10-07)

---

## 上下文

当前 YiKnowledge 200+ 文件名序号格式混乱：
- 有的是 `1-.../2-...` 一位数无零填充（例 engineer/build/ 下 `04-构建-xxx` vs `0008-构建-实现SSE流式推送.md` 没序号）
- 有的是 `01-.../02-...` 两位零填充（curator/templates/ `01-模板-ADR模板` 等）
- 有的 `101-prd-xxx/105-prd-xxx` 三位但不是从 001 开始（projects/yiai/prds/2026-09/ 中跳号到 215 甚至 178、111）
- 还有完全无序号的自由命名（README、INDEX、COLLABORATION 这种索引类除外正常，但 engineer/ship/0007-构建-实现跨项目RPC调用.md 这种到底是没序号还是是特殊文件？）

带来问题：
1. **文件系统排序不稳定**：`ls` 按字典序排，`10-xx.md` 会排到 `2-xx.md` 前面（因为字典序 '1' < '2'，不管十位）——新人看文件顺序混乱，以为中间漏了 8 个文件
2. **AI RAG 读取困惑**：RAG 扫描目录时按文件系统返回顺序读文件，序号不一致会让 AI 认为"02 章和 101 章哪个是第一章？"——召回片段拼接时上下文顺序混乱
3. **序号跳号无规则**：PRD 序号从 01 跳到 105、111、115 再到 178、215（projects/yiai/prds/2026-09/）——新人看不懂为什么跳，不知道能不能用 100 以下的号，担心冲突
4. **重命名雪崩**：当文件从 9 到 10 时，`9-xx` → `09-xx` 要改文件名，同时所有 `related: ./9-xx.md` 链接也要改——如果是两位数到三位数（99→100），则 1-99 都要重命名（两位数变三位数），20-50 份文件大迁移

为什么现在必须定：
- Q3 新建 13 份本任务要求文档（本 ADR 就是其中之一），如果现在不定，新建文件沿用各自格式，未来迁移成本更高
- Curator OKR `cur-001` 第 6 条 `loop-retrievability` 要求查找体验改善，序号规范是最基础的查找优化

---

## 决策

**YiKnowledge 所有需要序号的文件命名统一采用「三位十进制整数+零填充前缀 + 短横线」格式：`001-xxx-主题.md`。序号在「同一父目录 + 同一类别池」内连续递增，不同类别池各自独立编号。禁止一位/两位/四位及以上序号。**

### 核心命名规范

```
文件名 = [序号前缀(可选)] + [中文类别标记(可选)] + [短横线连接的主题描述] + .md
序号前缀 = 3位数字，000 保留不用，从 001 开始递增
         ↑ 如果是索引类文件（README / INDEX / COLLABORATION / MEMORY 等全大写保留名），不需要序号前缀
类别标记 = 中文2-4字：基础/方法/平台/项目/架构/运行/交付/构建/治理/模板/战略/决策/路线图
         放在序号之后，主题之前，用短横线连接
主题描述 = 中文为主，可中英混合，2-20字，见名知意
```

合法示例：
```
leader/decisions/
  yiai-yiai-yiai-002-决策-LLM多提供商上线.md    ← 特殊：项目代号前缀（yiai），不是纯序号
  yipot-yipot-yipot-006-决策-托盘Accessory.md     ← 项目代号 + 序号 + 类别（本任务新建文件都是这个）

curator/templates/
  000-INDEX.md                        ← 00 是 INDEX 保留号（非内容序号），特殊情况接受
  0001-模板-ADR模板.md                 ← 3位？不，当前是01；决策后统一改 001
  0001-模板-ADR模板.md                ← 决策后的目标命名

engineer/run/
  0009-运行-Mentor一对一指南.md        ← 本任务新建：改 005（补到 3 位）
  0009-运行-Mentor一对一指南.md       ← 决策后的目标命名

executive/strategy/
  0001-战略-蓝海战略.md                ← 改 001
  0001-战略-蓝海战略.md               ← 目标
```

不合法示例（禁止）：
```
1-xxx.md              ❌ 一位数不零填充
01-xxx.md             ❌ 两位数不零填充（按本决策必须 001）
0001-xxx.md           ❌ 四位没必要
1001-xxx.md           ❌ 同目录超过 999 文档？先拆目录再加号
yiai-1-xxx.md         ❌ 项目代号后序号非三位
yiai-001-决策-xxx     ❌ 少 .md 后缀
```

### 类别序号池独立规则

序号不是整个知识库全局唯一——而是**同一父目录下同一类别池内唯一**：

| 示例 | 序号怎么算 |
|---|---|
| `curator/templates/` 下所有模板 | 共享一个池，从 `001-模板-...` 到 `012-模板-...` |
| `engineer/run/` 下所有 `xxx-运行-xxx` 和 `xxx-入职-xxx` | **共享一个池**（属于同一父目录 engineer/run 下一类：运行/入职都是运行模块子分类，不分池） |
| `leader/decisions/` 下按项目前缀独立 | `yiai-06...`、`yipot-06...`、`yiknowledge-06...`——**各项目的 ADR 序号独立池**，所以 yipot-06、yiknowledge-06 同时存在完全合法（不同项目池） |
| `projects/yiai/prds/2026-09/` 下的 PRD | 单独一个池（时间目录下），但号段建议从 001 起编，旧 101/105/111 号段维持不用改（历史遗留保持稳定） |
| README.md / INDEX.md / COLLABORATION.md / MEMORY.md | **无序号**，全大写保留名作为目录锚点文件，特殊命名不参与序号 |

### 重命名迁移策略（核心是"不雪崩"）

1. **新建文件一律按规范走**：本任务 13 份文件（虽然有些两位如 `05-运行-`）——写一个本 ADR 决定"**1 个月内**统一从两位迁移到三位，新建先按 05，然后在 1 个月内统一改到 005，相关链接 batch sed 改完"
2. **存量分批迁移**：`01-xxx.md` → `001-xxx.md`，curator/ → engineer/ → leader/ → ... 按目录分批，每批迁移用 bash `for f in ??-*; do mv ...; done` 批量改名 + `sed -i 's/\/01-/\/001-/g' **/*.md` 批量改 related 链接
3. **号段 100+ 的存量保持稳定**：projects/yiai/prds/2026-09/ 下 101/105/111/115/117/118/120/121/139/143... 都是三位数（虽然不是从 001 起但已经是三位零填充格式），**不改**——跳号没问题，只是不能续用低位避免冲突
4. **禁止为了序号连续而重命名所有文件**：删了 `005` 后 `006-020` 绝不改为 `005-019`——跳号是可接受的，重命名雪崩才是灾难

## 备选评估

| 替代方案 | 优点 | 缺点 | 否决原因 |
|---|---|---|---|
| **方案 A：两位数零填充（01-99），99 不够就加字母（01A 01B）** | 现有 curator/templates/ 已经是两位数，改动小 | 超 99 份同目录时搞出 01A 这种怪格式，AI 和 ls 排序都不自然；目前 executive/strategy/ 已经 52 份马上就到两位数上限 | 52→99 一年之内到；字母扩展方案极度不自然，不如直接 3 位 |
| **方案 B：无序号，全靠 created 日期 + 文件系统排序** | 命名最自由；零维护成本 | ls/rg 返回顺序和 created 不一致（跨平台 FS 差异）；AI 无法知道章节顺序；找文件要翻半天看日期 | 无序号等于放弃"找"的效率，新人查 1 个文件要 5 分钟而 30 秒 |
| **方案 C（已选择）：三位零填充（001-999）+ 同目录分类池独立 + 跳号接受不重排** | 999 同文件数上限足够（executive/strategy 52 份 ×20 倍冗余）；不触发雪崩；排序稳定；和现有 `yiai-001-01-xxx` 部分文件格式一致 | 短期改 50+ 文件工作量约 1 人天；新人有时会问"为什么 005 后面是 007？006 去哪了？"要解释"删了，不重排" | 999 上限足够；1 人天批量脚本 10 分钟完成大部分，剩余人工；跳号问题 README/INDEX 第一句写"序号允许跳号，不代表缺文件" |

## 后果

### 正面影响
- **排序稳定**：`ls` 按字典序排 001-002-...-010-011... 自然按数字顺序；AI/RAG 和人类看到的顺序完全一致
- **不雪崩**：3 位上限 999，52→999 足够 10 年；到 99 时不触发 01-99 全改 001-099 重命名；删除不重排，跳号永久保留
- **RAG 召回顺序可预测**：AI 按序号顺序拼接上下文片段，不会出现「10-运行」排在「2-入职」前面这种混乱
- **Curator 批量治理脚本简单**：`for f in $(ls | grep ^0[0-9]-); do`（两位）→ 批量改名 + 替换链接，10 行 bash 搞定

### 负面影响
- **一次性迁移 1 人天**：50+ 文件改名 + 改 hundreds of related 链接；虽然可用 bash 脚本，但人工 spot check 要 2 小时防止误改（比如 `01-模板` 和 `101-prd` 里同时出现 `/01-` 字符串）
- **历史文件名和内容里的引用不兼容**：如文档正文写"详见 `0001-构建-MongoDB模式设计.md`"——两位变三位后这种正文里的文字引用也要手工改，脚本无法完全覆盖（正则无法区分"正文提及 04-构建"和「related: ../../04-构建-」）
- **跳号心理负担**：新人问"为什么目录里 001、003、007？002/004-006 被删了？"——INDEX.md 表头加一行"序号允许跳号，不代表文件缺失"可解决 80%

### 中性影响
- **与 yiknowledge-08（双入口）协作**：INDEX.md 表格里通常有序号列——INDEX 列号和文件名前缀一致，不一致的立即标红提醒
- **leader/decisions/ 项目代号规则例外**：yiai-02-xxx、yipot-06-xxx、yiknowledge-06-xxx——这种项目+序号格式，项目代号算前缀，后面序号是 **3 位？（比如 yipot-006）还是当前 yipot-06（两位）**？→ 决策：**项目代号后的序号统一两位（xx-01 到 xx-99）**，因为单个项目不可能 ≥100 份 ADR，三位没必要；本规则和「纯序号 3 位」不冲突——纯序号和项目前缀序号是两套池
- **号段冲突处理**：如果同一目录（如 projects/yiai/prds/2026-09/）同时存在「01-prd、02-prd...」和「101-prd...」两套号段——**各自独立，继续维持，中间号段不用**，避免冲突
