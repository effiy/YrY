When working in `.claude/`:

1. **Skill boundaries are real.** Each `SKILL.md` is a user-invocable
   plugin with its own trigger surface. Editing a skill's body
   changes what Claude routes to it. Do not silently merge skills or
   rename trigger phrases — both will break evals.
2. **The shared substrate is shared.** The 12 `shared/components/*`
   web components and the `shared/vendor/*` libraries are consumed
   by every dashboard page. Touch them only via a single-file edit
   plus a regression sweep across every page that imports them.
3. **The pipeline is reproducible.** `rui-init` re-runs are
   deterministic from `profile.json` + `exploration.json`. If you
   change the catalog, change those two files (or rebuild them via
   `/rui-init`); do not hand-edit the generated `CLAUDE.md` /
   `README.md` / `docs/data.js` — they will be overwritten.

## Iron laws

1. **Simplicity First.** A new skill starts as a 30-line `SKILL.md`
   with a description and a single trigger. Add `agents/`,
   `references/`, `evals/`, `commands/` only when the trigger
   surface actually needs them. No speculative `rules/`, no
   placeholder `templates/`, no abstractions for one-time content.
2. **Surgical Changes.** Edit only the file(s) the user asked about.
   Do not "improve" sibling skills. Do not reformat SKILL.md
   frontmatter. Do not re-import shared components in skills that
   don't need them.
3. **The trigger phrase owns the skill.** The `description:` block
   in `SKILL.md` frontmatter is the only thing the dispatcher
   reads. Optimization is allowed; rewording without an eval
   pass is forbidden.
