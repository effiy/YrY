# .claude

> Claude skills catalog · 8 skill groups · 27 SKILL.md manifests · 12
> shared web components · 4 vendored libraries · 1 unified Vue 3 loader.
> Generated by the **rui-init** pipeline on 2026-07-15 15:20.

The `.claude/` directory is the Claude skills catalog for the YrY
project. It contains 8 top-level skill groups (each a plugin), 27
`SKILL.md` manifests, a shared UI substrate (12 web components + 4
vendored libraries + 1 unified loader), and a documentation dashboard
emitted by `rui-init`. The catalog is doc-only except for the
`rui-reports/diagram` sub-skill (an ESM package with vitest tests),
the vendored `rui-reports/diagram/engine/tree-sitter-dart-wasm`
sub-package, and `rui-tools/mermaid` (a small CLI).

## System view

The catalog is a **plugin-style** skills collection: each
`SKILL.md` is a self-contained user-invocable plugin with its own
trigger surface. The 12 `shared/components/*` widgets and the 4
`shared/vendor/*` libraries form the cross-skill UI substrate; the
`rui-tools/*` group is the meta-tooling layer (create / evaluate /
benchmark skills). `rui-init` orchestrates the end-to-end pipeline
(detect → explore → generate → arch → verify) that bootstraps every
new project, including this documentation dashboard.

## Command flow

There is no top-level build / lint pipeline for the catalog; the three
`package.json` files live inside the catalogued skills.

| To do this | Run this from the catalogued skill |
|------------|-------------------------------------|
| Run the vitest suite (only in `rui-reports/diagram`) | `cd skills/rui-reports/diagram && pnpm test` |
| Run a single vitest file | `cd skills/rui-reports/diagram && pnpm exec vitest run engine/core/src/<file>.test.js` |
| Render the pretty-mermaid CLI (only in `rui-tools/mermaid`) | `cd skills/rui-tools/mermaid && node scripts/render.mjs <input>` |
| Re-run the rui-init pipeline on a sub-skill | `cd <skill> && /rui-init` (manual trigger) |
| Open the dashboard | open `docs/index.html` in a browser (no build step) |

## Quick start

1. **Inspect the catalog layout**

   ```bash
   ls -la /Users/ruiyi/YrY/.claude/
   # docs/   shared/   skills/
   ```

2. **Open the dashboard**

   Open `/Users/ruiyi/YrY/.claude/docs/index.html` in a browser. The
   page mounts a Vue 3 app (CDN-loaded by `shared/loader.js`) that
   renders the 27 skills, the shared substrate, and links into the
   `docs/arch/` and `docs/self-test/` story trees.

3. **Read the project profile**

   `CLAUDE.md` (one level up) is the auto-generated baseline.

4. **Re-run the pipeline**

   Run `/rui-init` from the project root to rebuild the dashboard
   + the 11 scene files (5 in `docs/arch/`, 6 in `docs/self-test/`).

## Domain Language

The catalog uses its own vocabulary; understanding these terms is
required for any non-trivial edit.

### Term definitions

- **Skill** — A self-contained user-invocable plugin rooted at
  `SKILL.md`. Owns its own `agents/`, `references/`, `evals/`,
  `commands/`, `rules/`, `templates/` subdirectories. Always
  kebab-cased directory name; manifest is named exactly
  `SKILL.md` (not `skill.md` or `SKILL.MD`).
- **Skill group** — A top-level plugin under `skills/<group>/` that
  contains one or more skills. Used to bundle related skills (e.g.
  `rui-code/` contains 10 sub-skills). 8 groups total.
- **Trigger surface** — The `description:` block in `SKILL.md`
  frontmatter. The Claude dispatcher reads it to decide whether to
  route a user request to that skill. Optimization is allowed;
  rewording without an eval pass is forbidden.
- **Shared component** — A web-component widget in
  `shared/components/<name>/` that is auto-mounted by
  `shared/loader.js`. The 12 components are rui-back-top, rui-badge,
  rui-breadcrumb, rui-cross-nav, rui-loader, rui-panel-hub,
  rui-progress-bar, rui-scene-card, rui-score-bar, rui-stats-grid,
  rui-tag-chip, rui-toast.
- **Pipeline** — The 5-step rui-init flow: detect → explore →
  generate → arch → verify. Each step reads a `pipelineState`
  object and writes either files (generate, arch) or updated state
  (detect, explore, verify).
- **Story** — A directory under `docs/arch/` or `docs/self-test/`
  containing ≥ 1 scene (per-scene `index.md` with the §0–§4
  lifecycle). Two story trees ship with every rui-init run: the
  architecture story (5 scenes) and the self-test story (6 scenes).
- **Scene** — A single self-contained unit of documentation under
  a story directory. Ships as `scene-N-<slug>/index.md` and follows
  §0 (effect sketch) → §1 (test design) → §2 (output inventory) → §3
  (test report) → §4 (self-improvement).

### Relationships

- A **Skill** is owned by exactly one **Skill group** (parent /
  child).
- A **Skill** consumes 0..N **Shared components** (consumer /
  producer).
- A **Pipeline** produces 1..N **Stories** and verifies them in the
  same run (producer / consumer).
- A **Story** contains 1..N **Scenes** (parent / child).
- A **Scene**'s §0–§4 lifecycle causes / effects a single piece of
  guidance in the corresponding skill's `SKILL.md`.

### Example dialogue

> **User**: I want to add a new skill that teaches Claude about a
> particular kind of CLI tool.
>
> **System**: That is `rui-tools/skill`. Open
> `skills/rui-tools/skill/SKILL.md` and follow the "Create a skill
> from scratch" workflow. You will need: a new directory under
> `skills/<group>/<your-skill>/`, a `SKILL.md` with frontmatter
> (`name`, `description`, `lifecycle`, `user_invocable`), and an
> `evals/evals.json` with at least 3 graded test cases.
>
> **User**: I have a draft `SKILL.md`. How do I know it triggers
> correctly?
>
> **System**: Use `rui-tools/skill` again, this time the "Optimize
> skill description" workflow. It runs the eval harness
> (`evals/evals.json`) with parallel subagent execution and reports
> the variance between with-skill and without-skill pass rates.

### Disambiguation markers

- **Skill** is **not** a Python skill, a D&D skill, or a
  "competency" — it is a Claude plugin manifest. Do not confuse with
  the Anthropic "Skills" feature (which uses a different manifest
  format).
- **Skill group** is **not** an npm workspace, a Cargo crate, or a
  monorepo package — there is no top-level `package.json` and no
  shared dependency tree.
- **Trigger surface** is **not** a system prompt, a tool
  description, or a regex — it is the YAML frontmatter block
  inside `SKILL.md` consumed by the Claude dispatcher.
- **Shared component** is **not** a React component, a Vue SFC, or a
  custom element registered in user code — it is a vanilla
  web-component auto-mounted by the unified loader.
- **Pipeline** is **not** GitHub Actions, GitLab CI, or a build
  orchestrator — it is the rui-init 5-step flow that runs inside
  one Claude session.
- **Story** is **not** a Storybook story, a Jira ticket, or a
  user-story — it is a directory of scenes under `docs/arch/` or
  `docs/self-test/`.
- **Scene** is **not** a Three.js scene, a game scene, or a code
  snippet — it is a single self-contained `index.md` file under
  a story directory.
