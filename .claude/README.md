# .claude

> Claude 技能目录 · 5 个 skill group · 26 个 `SKILL.md` 清单 · 12 个共享组件 · 5 个 vendored 资源。
> Generated by the **rui-init** pipeline on 2026-07-19.

`.claude/` 是 YrY 项目里的 Claude 技能目录。它以 `skills/` 为主业务面，以
`shared/` 为跨页面 UI 基座，以 `docs/` 为 `rui-init` 生成的浏览入口和故事树。
当前仓库只有一个真正的包清单：`skills/rui-reports/diagram/package.json`。

## System view

这个目录是一个典型的 **plugin-style catalog**：每个 `SKILL.md` 都是一个可被 Claude
识别的技能入口；`rui-code`、`rui-reports`、`rui-tools` 负责聚合多种子技能，
`rui-init` 负责生成根级文档和文档中心，`rui-test` 则以 topics 目录组织测试知识。
`shared/loader.js` 与 `shared/components/*` 为 `docs/` 下的主页、依赖页、文件报告页、
日报页和故事页提供统一挂载能力。

## Command flow

这个目录没有顶层 `package.json`，所以常用命令都需要进入具体技能目录执行。

| To do this | Run this |
|------------|----------|
| 运行唯一的测试套件 | `cd /Users/yi/YrY/.claude/skills/rui-reports/diagram && pnpm test` |
| 运行单个 vitest 文件 | `cd /Users/yi/YrY/.claude/skills/rui-reports/diagram && pnpm exec vitest run engine/core/src/<file>.test.js` |

| 打开文档中心 | 在浏览器中打开 `docs/index.html` |

## Domain Language

`.claude` 的日常维护依赖一组固定术语；下面这部分是这个目录的领域语言基线。

**Skill** — A Claude-invocable capability rooted at a `SKILL.md` manifest.
**Skill Group** — A top-level directory under `skills/` that owns one or more related skills or topics.
**Trigger Surface** — The natural-language `description:` block that controls when Claude routes work to a skill.
**Shared Component** — A reusable UI unit under `shared/components/` that generated docs pages consume through the loader.
**Story** — A generated documentation tree under `docs/arch/` or `docs/test/` that groups scene documents.
**Scene** — A single `scene-N-<slug>/index.md` document that captures one focused architecture or verification narrative.

### Relationships

- A **Skill** belongs to exactly one **Skill Group**.
- A **Shared Component** is produced in `shared/` and consumed by `docs/` pages.
- A **Story** contains multiple **Scene** documents.
- The **Trigger Surface** determines when a **Skill** enters the workflow.

### Example dialogue

> User: 我想新增一个用于评估 skill 触发词效果的能力。
>
> System: 先看 `skills/rui-tools/skill/SKILL.md`，它负责 skill 创建、评估和优化工作流。
>
> User: 我想确认文档中心里这些故事页有没有缺失。
>
> System: 打开 `docs/test/scene-1-post-init-full-self-check/index.md`，再结合 `docs/.pipeline-state/verify-result.json` 查看基线结果。

### Disambiguation markers

- **Skill** 不是 npm package，也不是某个编程语言的模块系统概念。
- **Skill Group** 不是 monorepo workspace；这里只有目录分组，没有顶层包管理。
- **Trigger Surface** 不是 system prompt；它只指 `SKILL.md` frontmatter 里的描述文本。
- **Story** 不是 Storybook story；这里指的是文档树。
- **Scene** 不是 UI scene；这里指具体的 Markdown 场景文档。
