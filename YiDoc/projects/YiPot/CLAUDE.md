## Foundational Beliefs

- **Trust the model.** Default to reading the source before assuming; let the
  code be the authority when docs and code disagree. YiPot's two codebases
  (`src/` React frontend + `src-tauri/` Rust backend) are the ground truth.
- **Value attention.** A small surgical change beats a sprawling refactor;
  scope is a finite resource, spend it on the user's actual request. Each of
  the 21 translate engines is a self-contained directory — touch one, not all.
- **Verify reality.** After every change, run the smallest check that proves
  the change worked; never claim success without evidence. Tauri IPC bridges
  JS → Rust → OS — verify at each boundary.
- **Think Before Coding.** Don't assume — surface tradeoffs. If multiple
  translation engines can serve a request, present the options. If a simpler
  approach exists, say so. State assumptions explicitly before writing the
  first line.

## Iron Laws

1. **Simplicity First.** No features beyond what was asked; no abstractions
   for single-use code; no error handling for impossible scenes. The service
   plugin architecture (each engine is a self-contained directory with
   `Config.jsx` + `index.jsx` + `info.ts`) is already clean — reuse it, do
   not invent a new abstraction.
2. **Surgical Changes.** Don't "improve" adjacent code; match existing style
   (React 18 + JSX + camelCase for JS, snake_case for Rust modules, 2-space
   indent, double quotes). Every changed line traces to the user's request.
3. **No silent writes outside cwd.** The cwd is the docs catalog entry at
   `YiDoc/projects/YiPot/`. Source-tree writes go through the user; this file
   only orchestrates the docs catalog. The actual source tree at
   `/Users/ruiyi/Downloads/YrY/YiPot/` is read-only for this catalog.
4. **Tauri 1.8 API surface is frozen.** Do not migrate to Tauri 2.x in a
   surgical change; the plugin ecosystem (`tauri-plugin-sql-api`,
   `tauri-plugin-store-api`, `tauri-plugin-fs-watch-api`,
   `tauri-plugin-log-api`, `tauri-plugin-autostart-api`) is pinned to v1.

## Project Constraints

### Non-negotiable baselines

1. **Tauri 1.8 API surface.** The app pins `@tauri-apps/api@^1.6.0` and
   `@tauri-apps/cli@^1.6.3`; the 6 `tauri-plugin-*-api` packages are pinned
   to v1 GitHub revisions. Do not migrate to Tauri 2.x in a surgical change.
2. **Each engine is a directory.** `src/services/{translate,recognize,tts,collection}/<engine>/{Config.jsx,index.jsx,info.ts}`
   is the established contract. A new engine = a new directory with those
   three files; never inline an engine into the parent barrel.
3. **Window dispatch by `appWindow.label`.** Each Tauri window
   (`Translate`, `Recognize`, `Screenshot`, `Config`, `Updater`) has its own
   React subtree dispatched by `src/App.jsx`'s `windowMap`. Do not introduce
   a router — the label is the router.
4. **`config.json` is the single source of truth for settings.** Lives in
   Tauri's app config directory; accessed via `tauri-plugin-store-api`. Do
   not duplicate settings into Jotai atoms or `localStorage`.

### Degradation countermeasures

- Engine API error → the engine's `index.jsx` surfaces the error to toast;
  other engines remain selectable. One engine's failure must not cascade.
- `check_service_available()` runs at startup to prune engines whose API
  key is missing — invisible engines are not rendered.
- tiny_http bridge (`src-tauri/src/server.rs`, port 60828) fails → the
  clipboard-translate flow degrades to manual paste; the rest of the app
  keeps working.
- OCR pipeline: `tesseract.js` (in-browser) is the fallback when the
  Rust-side `system_ocr.rs` (system OCR via `lingua` + platform APIs)
  returns nothing.
- Tauri webview fails to load React → app shows a blank webview; the
  `updater.rs` + `Updater` window can still push a hotfix.

### Self-constraints

- This docs catalog entry (`YiDoc/projects/YiPot/`) is regenerated by
  `yry-init`. The dashboard `data.js`, `index.html`, `index.css`,
  `index.js` are the docs home 4-file set; `CLAUDE.md` and `README.md`
  sit beside them; `arch/` + `test/` are the two story directories.
- The actual YiPot source tree lives at
  `/Users/ruiyi/Downloads/YrY/YiPot/`; this catalog entry reads it but
  writes nothing there.
- Platform-gated code uses `#[cfg(target_os = "...")]` in Rust and
  `appWindow.label` in JS; do not collapse the platform branches.
