常见原因与解决：

  • 模型太大：在 config.yaml 中将 asr.model 从 large-v3 降为 medium
  • 批处理太多：降低 pipeline.batch_size（默认 10 → 5）
  • 其他进程占显存：运行 nvidia-smi 检查，必要时 kill 其他 Python 进程
  • 显存清理：重启 Python 进程释放显存（PyTorch 有时不释放）
Pipeline

提高 ASR 精度的方法：

  • 指定语言：在 config.yaml 中设置 asr.language，避免自动检测出错
  • 升级模型：使用 whisperx 的 large-v3 模型（1.5GB+）
  • 音频预处理：确保视频音质清晰，避免背景噪音
  • 切换后端：尝试不同的 ASR 后端（WhisperX / HuggingFace / Replicate）
  • 手动校正：修改 output/segments.json 中识别错误的片段后重跑后续步骤

YiviY 在步骤 11（_11_merge_audio.py）中合并原声与配音：

  • 默认策略：原声降低音量（-20dB）作为背景，配音为主音轨
  • 说话人分离：通过 PyAnnote 识别不同说话人，可为每个说话人分配不同的 TTS 声音
  • 时间对齐：配音时长与原语音片段对齐，通过 TTS 速度调整（步骤 10）

可在 config.yaml 中调整混合策略与音量比例。

使用批量处理工具：

  • Windows：运行 batch/OneKeyBatch.bat，按提示输入视频 URL 列表
  • Python：编写脚本循环调用 core/_1_ytdlp.py 至 core/_12_dub_to_vid.py
  • Colab：在 VideoLingo_colab.ipynb 中扩展为批量模式
  • Docker：挂载多个输入目录，用 --batch 参数启动
Translation

提高翻译质量的方法：

  • 升级模型：在 config.yaml 中使用更强的 LLM（如 gpt-4o）
  • 添加术语表：在 custom_terms.xlsx 中定义专业术语映射
  • 调整 Prompt：修改 core/prompts.py 中的翻译提示词
  • 检查源文本：NLP 句切分（步骤 3）的结果影响翻译质量，可手动检查 segments.json
  • 添加上下文：在 Prompt 中加入前后文作为上下文

字幕对齐由步骤 05（_5_split_sub.py）控制：

  • 检查 ASR 时间戳：确保 segments.json 中的 start/end 时间准确
  • 调整切分粒度：在 config.yaml 中设置 pipeline.subtitle_max_chars（默认 80）
  • 手动编辑：修改 output/subtitle.srt 中错误的时间戳
  • 重跑步骤 05-12：修改 subtitle.srt 后跳过前 4 步直接运行后续
Development

添加新后端需要修改 core/asr_backend/ 或 core/tts_backend/：

  1. 在对应目录下创建新后端的适配器文件
  2. 实现统一接口（recognize(audio) 或 synthesize(text)）
  3. 在 __init__.py 中注册后端
  4. 在 config.yaml 中切换到新后端

详见 Customization · Recipes。

调试步骤：

  1. 查看 Streamlit 控制台错误堆栈
  2. 在 config.yaml 中启用 debug: true 获得详细日志
  3. 检查 output/ 目录中失败步骤之前的 JSON 输出
  4. 单独运行失败步骤的 Python 文件：python -m core._6_gen_sub
  5. 对比 segments.json 的输入/输出是否合理

在 config.yaml 中配置 pipeline.skip_steps：

pipeline:
  skip_steps: [5]  # 跳过 Step 05 说话人分离

注意：跳过步骤可能导致后续步骤缺少依赖数据。建议先确认中间产物已存在于 output/ 目录。

Deployment

Docker 部署的硬件要求：

  • CPU 模式：4 核 CPU · 8GB RAM · 20GB 磁盘
  • GPU 模式：NVIDIA GPU · CUDA 12.4 · 8GB+ VRAM · 16GB RAM
  • 软件要求：Docker 20+ · nvidia-docker2（GPU 模式）

Dockerfile 基于 nvidia/cuda:12.4-runtime-ubuntu22.04，已预装所有依赖。详见 Setup · Docker。

生产环境部署建议：

  • Docker Compose：使用 docker-compose.yml 编排 YiviY + Redis + 对象存储
  • 反向代理：Nginx 配置 SSL，限制上传大小
  • 任务队列：集成 Celery + Redis 处理长时任务
  • 日志监控：挂载 logs/ 到宿主机，使用 Loki / Grafana 监控
  • 模型缓存：挂载 ~/.cache/huggingface/ 避免重复下载

Colab 会话断开后：

  • 中间产物：存储在 Google Drive（挂载 /content/drive/）可保留
  • 重启 Colab：重新运行前几个单元格挂载 Drive
  • 跳过前段：从断点处恢复（output/ 中已有中间 JSON）
  • 自动保存：使用 google.colab.drive.mount 挂载 Drive 后设置 output_dir 指向 Drive
