General 4

YiH5 支持 Vercel / Netlify / 自建 Node 服务器等主流部署方式。推荐生产环境使用 Docker 或 CI/CD 自动化部署。

查看 Changelog 了解版本变更，按迁移指南操作。建议先在开发环境验证后再部署生产。每次升级前请备份数据和配置。

Vanilla JS (ES2020+) · Bootstrap 5 · 共享 CDN 组件 · IIFE 模块化。

本项目遵循 MIT 许可证开源。你可以自由使用、修改和分发，但需保留原始版权声明。

Development 5

参考 Specifications 中的模块清单，在对应目录添加新文件并遵循现有架构模式。建议先创建 arch scene 记录设计决策，再编写代码。

推荐 VS Code + ESLint + Prettier。项目根目录已包含 .editorconfig 和 .gitignore。

npm run test 或 npm run test:watch 进入 watch 模式。

npm run lint — ESLint + Prettier 联合检查。建议在 CI 中集成 lint 步骤。

Fork → 创建 feature 分支 → 编写代码 + 测试 → 提交 PR。PR 需通过 CI 检查（lint + test + build）并由维护者 review。

Troubleshooting 4

查阅 Setup 的 Troubleshooting 章节，或查看 浏览器 DevTools Console 面板。常见问题已在下方列出。如果问题无法解决，请在 Git 仓库提 issue。

项目源码通过 Git 版本控制，定期 push 到远程仓库即可。配置文件建议独立备份。

轻量级架构，资源占用极低。如需进一步优化，可考虑 Service Worker 缓存策略。

检查 vite.config.js 中 server.watch 配置。部分文件变更可能需要重启 dev server。

Security 3

配置 CORS 白名单，仅允许信任的域名访问 API。使用 HTTPS 防止中间人攻击。

使用 .env 文件（已加入 .gitignore）管理环境变量。生产环境通过 CI/CD 注入。

部署到 Vercel/Netlify 自动获得 HTTPS。自建服务器推荐使用 Let's Encrypt + Caddy 自动证书。

Still stuck? 查阅 Setup Troubleshooting 或检查 Changelog 是否已知问题已在最新版本修复。也可以在 Git 仓库提 issue 获取帮助。
