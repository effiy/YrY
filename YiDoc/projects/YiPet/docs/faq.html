Installation

请检查以下步骤：

  • 确认在 chrome://extensions/ 中已启用"开发者模式"
  • 确认扩展已加载（无红色错误提示）
  • 点击 Chrome 工具栏的拼图图标，找到 YiPet 并点击📌固定
  • 如仍不显示，尝试重启 Chrome

原因与解决：

  • 路径错误：确认选择的目录直接包含 manifest.json（不是子目录）
  • JSON 语法错误：用 node -e "JSON.parse(require('fs').readFileSync('manifest.json'))" 验证
  • 权限问题：确保 Chrome 对该目录有读权限（macOS 下避免放在 ~/Downloads 等受保护位置）

支持。YiPet 基于 Manifest V3 规范，兼容所有 Chromium 内核浏览器：

  • Microsoft Edge：启用"开发者模式"后步骤与 Chrome 一致
  • Brave：需在 brave://extensions 启用开发者模式
  • Opera / Vivaldi：步骤类似，在各自扩展管理页加载
  • Firefox：暂不支持（需要 Manifest V2 适配）
Usage

常见原因与解决方案：

  • 网络问题：检查是否能正常访问 api.effiy.cn
  • 权限未授予：在 manifest.json 中确认 host_permissions 包含 <all_urls> 和 API 域名
  • Service Worker 错误：右键扩展图标 → "检查 Service Worker"，查看控制台日志
  • API 配置错误：检查 core/config.js 中的 baseUrl 是否正确
  • API Key 失效：在 Popup → Settings 中重新输入 Key

FAQ 模块通过 FaqService 从后端 API 动态获取内容：

  • 数据来源：调用 /faq/query 端点获取结构化 Q&A 数据
  • 本地缓存：首次加载后缓存到 chrome.storage，支持离线访问
  • 缓存策略：默认 TTL 为 3600 秒，可在 config.js 中调整
  • 渲染方式：使用 marked.js 解析 Markdown，mermaid.js 渲染图表

自定义 Pet 角色需要修改 modules/pet/ 目录：

  • 替换图片：修改 modules/pet/assets/ 下的图片资源（保持相同文件名）
  • 调整动画：编辑 modules/pet/config.js 中的动画参数
  • 扩展行为：在 modules/pet/content/ 中添加新的事件监听器

修改后需要重新加载扩展才能生效。详见 Customization。

Development

YiPet 采用 IIFE 模块化架构，无需构建步骤。修改代码后：

  1. 在 chrome://extensions/ 页面找到 YiPet 卡片
  2. 点击右下角的🔄刷新按钮
  3. 如果修改了 manifest.json，可能需要先点击"停用"再点击"启用"

注意：对于 content script 的修改，需要刷新目标页面才能生效。

Manifest V3 是 Chrome 扩展的最新规范，主要变化：

  • Background：从 persistent background page 改为事件驱动的 Service Worker
  • Content Script：支持动态注入（chrome.scripting.executeScript）
  • 权限模型：更细粒度的权限控制，支持可选权限请求
  • 安全限制：禁止远程代码执行，所有 JS 必须打包在扩展内

YiPet 完全遵循 MV3 规范，确保长期兼容性。详见 Changelog · v1.1.0。

MV3 Service Worker 30 秒无活动即被 Chrome 回收。解决方案：

  • 使用 chrome.alarms 周期性唤醒（最短 1 分钟）
  • 使用 chrome.storage.session 持久化瞬时状态
  • 避免在 SW 中持有大对象引用
  • 长耗时任务迁移到 offscreen document（MV3 新特性）

步骤：

  1. 在 cdn/components/ 创建新目录，命名 YrY<Name>/
  2. 主文件 YrY<Name>.js 实现 customElements.define()
  3. cdn/loader.js 会自动扫描并注册（无需手动添加）
  4. 使用：<yrY-name></yrY-name>
Security

YiPet 遵循最小权限原则，仅声明必要的权限：

权限 用途
storage 持久化用户配置、会话历史、FAQ 缓存
tabs 检测当前标签页状态，控制内容脚本注入
scripting 动态注入 content script（MV3 规范）
webRequest 拦截和修改网络请求（如 API 鉴权）

API Key 存储流程：

  1. 用户在 Popup → Settings 输入 Key
  2. Key 通过 AES-256-GCM 加密后存入 chrome.storage.local
  3. 加密密钥派生自设备指纹 + 用户 salt
  4. 读取时由 core/token.js 解密并注入请求头
  5. Key 永不离开本地，不上传任何服务器
