Setup

Note: YiPet 是一个 Chrome 扩展，需要通过 Chrome 的"加载已解压的扩展程序"方式安装。无需构建步骤，但需要确保 manifest.json 路径正确。整个安装过程约 2 分钟。

Prerequisites

安装前请确认你的环境满足以下要求：

Requirement Version Required Purpose
Google Chrome ≥ 116 Yes Manifest V3 运行时环境
Git ≥ 2.30 Optional 克隆 YiPet 仓库（或直接下载 ZIP）
Node.js ≥ 18 Optional 仅当需要运行 npm run lint / npm test
代码编辑器 任意 Optional 推荐 VS Code + Chrome Extension Snippets 插件

Installation Steps

1
获取 YiPet 源码

克隆仓库或下载 ZIP 到本地：

# 克隆仓库
git clone https://github.com/your-org/YiPet.git

# 或：从 Release 页下载 ZIP 并解压
2
打开 Chrome 扩展管理页

在地址栏输入：

chrome://extensions/
3
启用开发者模式

在扩展管理页右上角，开启"开发者模式"开关。

首次启用会弹出 Chrome 警告，点击"确定"即可。
4
加载已解压的扩展

点击"加载已解压的扩展程序"，选择 YiPet/ 目录（包含 manifest.json 的目录）。

5
固定扩展到工具栏

点击 Chrome 工具栏的拼图图标 🧩，找到 YiPet，点击 📌 图标将其固定。

6
验证安装成功

点击工具栏 YiPet 图标，应看到 Pet 主界面。如未出现，请检查下方故障排除。

Development Workflow

YiPet 采用 IIFE 模块化架构，无需构建步骤。修改代码后的工作流：

步骤 操作
修改代码 编辑 YiPet/ 目录下的文件（manifest.json, core/, modules/, cdn/）
重新加载扩展 在 chrome://extensions/ 页面点击 YiPet 卡片上的🔄刷新按钮
查看日志 右键点击扩展图标 → "检查弹出内容"（Popup）或 Service Worker 链接
运行测试（可选） npm run lint 与 npm test 确保代码质量
Content Script 注入顺序： manifest.json 中的 content_scripts.js 数组决定了脚本加载顺序，确保依赖关系正确（如 config.js 必须在 token.js 之前）。错误的顺序会导致运行时 ReferenceError。

Troubleshooting

错误信息：Could not load manifest

检查：① 选择的目录是否直接包含 manifest.json（不能是子目录）；② manifest.json 的 JSON 语法是否有效（可用 node -e "JSON.parse(require('fs').readFileSync('manifest.json'))" 验证）。

症状：Popup 打开但网页上 Pet 组件不显示。

检查：① manifest.json 的 content_scripts.matches 是否覆盖目标网站；② Service Worker 控制台是否有 chrome.scripting.executeScript 错误；③ 页面是否属于 chrome:// 或 chrome-extension:// 等受限 URL。

MV3 Service Worker 30 秒无活动即被 Chrome 回收。

解决方案：使用 chrome.alarms 周期性唤醒；使用 chrome.storage.session 持久化瞬时状态；避免在 SW 中持有大对象引用。详见 Modules。

常见原因：manifest.json 缺少 host_permissions，或 chrome.storage.local 中 API key 未初始化。

检查：① manifest.json 声明了 host_permissions: ["https://api.openai.com/*"]；② Popup → Settings 页面正确填写 API Key；③ Service Worker 控制台 chrome.storage.local.get('apiKey') 返回值非空。
